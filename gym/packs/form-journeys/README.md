# form-journeys — 서식 여정 (이름·순번·dry-run·재독)

## 왜 이 pack 인가

에이전트가 실제 서식을 채울 때 빠지는 길은 짧다. 첫 칸에 이름을 넣는
시연(core-cli T07, `fields[0].value == 홍길동`)은 그 길이 아니다.
이 pack 은 다른 표본·다른 좌표·다른 축만 둔다. T07 을 복제하지
않는다. 라이브 오라클이 채점한다. 기존 연산자만 고른다.

1. 이름 있는 칸을 지목한다 (`전화번호`·`작성자`·`부서명`·`이메일`·`제목`)
2. 같은 이름 다섯 칸은 `이름[N]` 순번으로 고른다
3. `--dry-run` 은 파일을 만들지 않고 봉투만 남긴다
4. 본문을 바꾼 뒤에는 `search` 로 옛 문구 0·새 문구 ≥1 을 닫는다
5. 제출본은 `sanitize` 한 뒤 한 번 더 돌려 `removedCount == 0` 을 본다

새 CLI 는 없다. `fields` · `edit` · `search` 만 쓴다.

## 이 확장이 지키는 규칙

1. **기존 명령만.** requires 는 `edit` · `fields` · `search`.
2. **기존 연산자만.** `value_eq` · `value_ge` · `answer_eq` ·
   `differs_from_input`. 전역 훑기(`deep_contains`)는 쓰지 않는다.
3. **기존 표본만.** `field-01` · `field-01-memo` · `form-01` · `form-02`.
4. **라이브 오라클.** 숫자는 박제하지 않는다.
5. **T07 을 복제하지 않는다.** `fields[0]` 에 홍길동을 쓰지 않는다.
6. **원본을 덮지 않는다.** 산출은 `-o` 뿐이다.

## 명령 레시피

```bash
rhwp fields samples/field-01.hwp --json
rhwp edit fill-fields in.hwp --data '{"전화번호":"02-720-8899"}' -o out.hwp --json
rhwp edit fill-fields in.hwp --data @row.json --dry-run --json
rhwp edit fill-fields in.hwp --data @row.json -o out.hwp --verify --json
rhwp edit replace-text in.hwp --find 마케팅 --replace 여정기획 -o out.hwp --json
rhwp edit sanitize filled.hwp -o submit.hwp --json
rhwp search out.hwp --json -- 여정기획
```

## 실패 모드

| 신호 | 원인 | 처방 |
|---|---|---|
| fields[0] 비지 않음 | T07 좌표 | 회사명을 데이터에서 뺀다 |
| 홍길동 본문 잔존 | T07 문자열 | 다른 작성자 값 |
| ambiguous 잔류 | 순번 없음 | 이름[N] |
| notFound 잔류 | 오타 | fields[].name 복사 |
| dryRun false | 실기록 | --dry-run |
| verify null | 플래그 생략 | --verify |
| 재 sanitize ≠0 | 정리 안 함 | sanitize 한 번 더 |
| differs_from_input 실패 | 원본 복사 | -o 새 파일 |
