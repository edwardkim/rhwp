# 판단 트리 — 요청에서 명령으로

에이전트가 받는 요청을 **일곱 갈래**로 나누면 명령 선택은 기계적이 된다.
각 갈래의 끝은 해당 장의 실측 표본으로 이어진다. 규칙 하나: **모르는
문서는 언제나 ①에서 시작**하라 — 문서를 모르고 편집부터 하는 것이 사고의
근원이다.

## ① "이 문서 뭐야?" — 파악

```text
쪽수·형식만            → info                      (10장)
한 봉투 전체 요약       → explain (표·누름틀 포함)    (10장)
요약·발췌(RAG 청킹)     → digest [--sections]        (10장)
목차/조문 구조          → export-structure           (10장)
특정 내용이 어디에?     → search  (쪽 주소 포함)      (10장)
본문 원문 필요          → export-text -p <쪽>        (10장, 문맥 절약)
서식인가? 채울 칸은?    → fields                     (10장)
```

긴 문서 함정: `export-text` 전문 덤프는 문맥 창을 태운다 —
`digest --max-chars` 나 쪽 지정이 먼저다.

## ② "데이터 뽑아 줘" — 수확

```text
표를 구조로            → export-tables (좌표·병합 보존)   (20장)
표를 엑셀/pandas 로    → table-to-csv --table <n>        (20장)
고친 CSV 를 되넣기     → csv-to-table (치수 계약·--verify) (20장)
날짜·금액·수량         → extract-data (원문 표기+주소)     (20장)
폴더에서 문서 발견      → scan (확장자↔매직 불일치 선별)    (20장)
```

## ③ "고쳐 줘 / 채워 줘" — 편집 (반드시 -o, 먼저 --dry-run)

```text
문구 치환              → edit replace-text --find --replace   (30장)
표 셀 값               → edit set-cell --table --row --col    (30장, 스타일 유지엔 --keep-style)
누름틀 채움            → edit fill-fields --data '{…}'        (30장, 반복 필드는 이름[N])
개인정보 마스킹        → edit redact --dry-run 먼저           (30장)
메타데이터 제거        → edit sanitize                        (30장)
여러 단계를 원자로     → run <계획.json> (선검증→단일 저장)    (30장)
```

함정 실측 2건: 눈에 보이는 격자 표가 표 0이 아닐 수 있다(제목을 감싼
무테두리 표가 흔함 — `export-tables` 좌표로 확인하고 지목하라). set-cell 은
`--keep-style` 없이는 기본 스타일로 들어간다.

## ④ "다른 형식으로" — 변환·렌더

```text
HWP → HWPX            → export-hwpx <입력> <출력.hwpx> --verify (40장)
HWPX/배포용 → HWP5     → convert <입력> <출력.hwp> --verify     (40장)
PDF 발행               → export-pdf                        (40장)
웹/LLM 소비            → export-markdown / export-doclang  (40장)
눈으로 확인            → export-svg → (외부) resvg 로 PNG   (40장)
전후 레이아웃 회귀      → render-diff (px 변위 판정)         (40장)
```

`--verify` 의 차이는 고장이 아니라 판정이다(exit 3) — `verify.identical`
을 읽고 `ir-diff` 로 범주를 좁혀라.

## ⑤ "증명해 줘 / 믿어도 돼?" — 검증 사다리

```text
조건 단언(쪽수·포함…)   → verify --expect-*                  (50장)
구조 같은가            → ir-diff (identical/diffCount)      (50장)
작업 하나 증명/재현      → replay [--expect-output-sha256]    (50장)
캡슐 쌓고 폴더 회계      → replay --capsule … / audit <폴더>  (50장)
작업 역사 무결          → lineage [--deep]                   (50장)
```

절차 전체는 `rhwp-work-receipt` 스킬이 정본이다.

## ⑥ "이 문서 안전해?" — 보안 (출처 불명 문서는 이것부터)

```text
프롬프트 주입 신호      → inspect injection    (60장)
숨긴 텍스트            → inspect hidden-text   (60장)
화면-바이트 불일치      → inspect unicode       (60장)
```

수신 문서를 LLM 프롬프트에 잇기 전에 ⑥을 돌리는 것이 규약이다 — 봉투의
출처 표지(서문 ③)와 한 몸인 방어선이다.

## ⑦ "수백 개야" — 대량·상주

```text
파일 목록 일괄          → batch <하위명령> --json (stdin 목록→NDJSON)  (80장)
반복 조회를 빠르게      → mcp-serve 세션 (hwp_open→hwp_doc_*)         (80장)
```

대량 규약(실패 행 격리·입력 N=성공+실패 게이트)은 `rhwp-bulk-pipeline`
스킬, 세션 통합은 `rhwp-mcp-session` 스킬이 정본이다.

## 갈래를 못 정하겠으면

`capabilities --search <키워드>` 가 명령 자기서술을 검색해 준다(70장).
그래도 없으면 그 일은 rhwp 의 표면 밖이다 — 없는 명령을 지어내지 말 것
(스킬 표류 가드가 잡는다).
