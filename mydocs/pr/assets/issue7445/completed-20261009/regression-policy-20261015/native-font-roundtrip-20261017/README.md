# 저장 후 원 글꼴 프로그램 출처와 검사 소유 보존

Issue: #7445

## 실제 결함과 구현

고정 devel `fe5725dc38`에서 `hwp3-sample.hwp`의 HWPX 자기 왕복은16쪽·기하 차이0px였다.
parent `6ef66438bb`에서는16쪽을 유지하지만13쪽에서 최대28px 차이가 났다.
원 파서가 전달한 한양신명조의 굵은0.05em 추가 전진 출처가 저장 시 사라졌기 때문이다.
표준 글꼴명·자간·원문은 바꾸지 않고 rhwp 전용 HWPX 보조 엔트리로 출처를 보존한다.
헤더 SHA256·언어별 글꼴 수가 일치할 때만 복원하며, 임베드 글꼴에는 적용하지 않는다.
이것은 rhwp 재열람의 보존 계약이며 외부 한컴 재저장 후의 보존을 주장하지 않는다.

생산자는 `native_font_program::encode`이고 HWPX writer가 실제 header bytes와 함께 기록한다.
parser의 `decode`가 공통 Font IR을 복원하고 기존 `select_native_programs` →
`bold_advance` → 공통 측정/배치·자연 글리프 원점 경로가 같은 출처를 소비한다.
렌더러에 포맷 판별이나 문서별 수치 예외를 추가하지 않았다.

기존 독립 Print12쪽의 제목 원점·기준선±2CSSpx와 원문 순서 검사를 저장 전후 모두 실행했다.
헤더 변경·보조 엔트리 제거·알 수 없는 버전에서 출처를 이름만으로 추정하지 않는 반례도
같은 검사에 포함했다. 기존 원본의 Native/fresh WASM 전16쪽 증거는
[굵은 제목 단계](../native-bold-tracking-20261016/README.md)에 있으며 새 산출물의 fresh 전쪽 검증과 구분한다.

## 검사 선택 보정

- #4961: fixed base의 같은 원문 구역·문단·문자 오프셋·중첩 경로·글자모양을 대조했다.
  missing-face의607문자·글꼴 결정은 같고 run만136→145로 분리됐다. 원문 문자 단일 소유,
  607문자/607record/누락0은 유지하고 run 집계를 실제 공개 text-layout과 대조한다.
  Native/Node WASM의 같은 manifest 소비자를 함께 바꿨다. 배치 hash 이관 범위는 바꾸지 않았다.
- #6172/#7418: 구두점 분리 후에도 같은 원문·셀·하이픈 소유를 찾는다. 전각 폭·비겹침·
  독립 구두점 전진 범위·face는 유지했다.
- 자산관리규정: 같은 제목의 한글 원점을 선택하며 독립 X/기준선±2와 저장 간격 관계는 유지했다.
- #6706: 바깥 글줄과 셀 내부 글줄을 혼동하지 않고 원본 셀 문단의 제목을 찾는다.
  전체 제목·각 paint run의 셀 소유·실제 자식 관계·표/그림 순서·쪽수는 유지했다.
  이 검사의 통과는 해당 WMF 그림의 시각 미달 해소를 의미하지 않는다.

## 검증과 미완료

기계 증적（로컬 중간 자료 `validation.json`）에 정확한 base·parent·소스 hash·명령·원문 식별자를 기록했다.
수정 전 CLI는 exit3/최대28px, 수정 후 exit0/0px다. 관련8개 case 집중41건은41PASS/0FAIL,
7.520초다. 첫 보정 진단40PASS/1FAIL은 바깥 글줄을 중복 세던 검사 선택 오류로 보존했고,
원본 셀 문단으로 정정한 최종41PASS만 판정에 사용했다.
기존 C85 패키지의 Node WASM 추적2건도 통과했으나 새 fresh WASM 빌드 증거는 아니다.

새 전체 nextest·필수 gate·fresh WASM/시각 검증은 아직 완료하지 않았다. WMF와 도로조명
배치 잔여를 해결한 뒤 최종 source/head로 재검증한다. 지침·사용자 초안·원본/PDF는 보존했다.
`.log`는 `validation.json`의 ignored output 경로에만 남긴다.
