# 부분 Print 환경과 원본 TrueType 선택의 구분

시행령 18쪽의 남은 6픽셀은 같은 한양중고딕의 하이픈 두 곳과 K-META 부근에 있다. 원본 PDF의 H2gtrM TrueType 하이픈은 853/1024em이며 설치된 H2GTRM.TTF의 hmtx와 윤곽 명령이 같다. 다른 글꼴로 맞출 대상이 아니다.

그런데 기존 HCI Poppy→Palatino Print 환경 JSON은 그 한 항목만 선언했고 다른 원본 프로그램의 자동 선택을 포함하지 않았다. Native 실제 출력은 한양중고딕의 같은 이름 CFF `HY Junggothic`을 선택했다. 원본 메트릭은 TTF HYGothic-Medium의853/1024em인 채 표시 프로그램만 달라 하이픈 잉크가 짧아졌다. 자동 환경에서는 같은 HY중고딕의 TTF HYGothic-Medium이 선택됨을 실제 관측했다.

기존 독립 Print로 확인한 HCI Poppy의 Palatino 대응과 원본 메트릭 보존은 유지한다. 집중 검사에서는 다른 face의 자동 선택까지 가져온 JSON을 대조했다. 그러나 이후 전쪽 검사에서 원본의 대체 글꼴 정보를 덮어쓰는 문제가 드러나 아래와 같이 공급 조건을 정정했다. Native와 WASM의 자원 신원 표현을 구분하며 각 경로의 base/head에는 같은 환경을 쓴다. 이전 부분 JSON의 결과는 당시 자료로 보존하고 새 환경 결과로 바꾸어 쓰지 않는다.

현재는 선택 원인의 진단이며 새 환경의 집중·전쪽 비교와 보호 검증 완료를 뜻하지 않는다.

## 실제 집중 결과

새 환경에서13·18쪽은 Native와fresh WASM 모두100.00000%·미대응0이다. Native18쪽의 같은 쪽 review·overlay를 직접 판독했다. 이 조건의 de467 이전 소스와120483b82f 소스 값도 각각 같아, 프로그램 선택 보완과 코드 효과를 구분한다.61쪽은 Native99.55732% / WASM99.55724%·각480픽셀로 남는다. 이 부분은 상단 문장의 ASCII 작은따옴표 줄 소속이 독립 Print와 달라 다음 단계에서 원인을 확인한다. 새 환경 전쪽 검증은 아직 완료하지 않았다.

## 전쪽 검사 후 공급 조건 정정

전체 자동 환경을 명시적으로 재주입하자 4쪽 90.84%, 24쪽 96.92%로 줄바꿈이 달라졌다. 4쪽의 실제 trace는 원본 한양신명조의 `documentSubstFont: HY신명조` 대신 새 전역 매핑 `HY Sinmyeongjo`가 먼저 적용되어, 방향성 큰따옴표 폭이 전각 1400HU에서 반각 700HU로 바뀌었음을 보여 준다. 단순한 잉크·래스터 차이가 아니며 이 조건의 결과를 수용하지 않는다.

독립 PDF로 공급자를 확인한 HCI Poppy→Palatino와 132개 사용 글리프의 원본 동일성을 확인한 한양중고딕 TTF 선택만 새 JSON에 넣는다. 다른 face의 원본 대체 정보를 유지한다. 이 조건으로 4쪽 99.89%, 24쪽 99.91%, 13·18·61쪽 100%다. 같은 조건의 fixed base와 후보 Native 전쪽을 다시 산출했으며 74쪽 최저 99.73508%, 65쪽 raw 100%다. 이것은 C4 소스 검증이며 이어지는 견고딕 결측점 보정의 최종 전쪽·WASM 결과를 대신하지 않는다.
