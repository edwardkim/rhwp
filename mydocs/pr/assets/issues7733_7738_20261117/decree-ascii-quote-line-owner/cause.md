# ASCII 작은따옴표의 줄 소속과 양쪽 정렬

시행령 61쪽은 독립 한컴 2020 Hancom PDF Print와 달리 작은따옴표가 둘째 줄 끝에서 셋째 줄 앞으로 이동했다. 글리프 모양만의 차이가 아니라 줄 소속과 양쪽 정렬 공백이 함께 바뀐 문제다. Native·fresh WASM의 수정 전 raw는 99.55732% / 99.55724%다. 원본 Print에서는 ASCII 작은따옴표 x=717.2799px·baseline116.48px, 다음 줄의 메타버스 시작x=268.8px·baseline140px로 서로 다른 줄이다.

원 수정 #8191의 `6097253468`은 ASCII 큰따옴표를 방향성 여는 따옴표와 구분했고, A'·AA'처럼 닫힌 apostrophe 뒤 한글 경계도 허용했다. 다만 여는 ASCII 작은따옴표는 계속 줄 끝 금칙으로 남겼다. 현재 함수는 문맥과 무관하게 작은따옴표를 금칙으로 분류해 다음 한글 앞의 break 기회를 없앤다. 기존 큰따옴표와 방향성 따옴표·괄호 검사는 유지한다.

원본을 고치기 전에 굴림·한컴바탕 두 글꼴에서 ASCII 작은/큰따옴표, 방향성 작은/큰따옴표, 괄호, 닫는 prime의 12조건을 별도 좁은 문단으로 만들었다. 독립 한컴2020 11.0.0.9136 Hancom PDF Print method0·전처리없음·1쪽이 실제13초에 성공했다. 모든 ASCII 여는 따옴표는 앞줄 끝에 남고, 방향성 따옴표와 괄호는 다음 한글과 함께 내려간다. 결과를 독립 줄 관찰 JSON으로 보존한다. 기준 시행령 PDF를 교체하지 않는다.

공통 line-break 계약의 보정과 최소 글꼴 회귀·같은 페이지 Native/fresh WASM 재검증을 진행한다. 이전 소스의 전체 PASS를 새 소스의 검증으로 쓰지 않는다.

## 공백 뒤 여는 문맥과 회귀

첫 12조건의 앞 글자 직후 apostrophe는 기존 닫는 문자 판별로 이미 허용돼 있었다. 원본과 같은 공백 뒤 여는 문맥은 별도 12조건으로 추가 대조했다. 두 글꼴 모두 공백 뒤 ASCII 작은따옴표가 첫 줄 끝에 남고 다음 한글이 다음 줄에 속한다. 방향성 따옴표·괄호는 다음 한글과 함께 내려간다. 별도 실제 2020 Print job `7e85d95a-71bf-44d7-8f3d-89abd5d1f293`도 13초에 성공했고, `with-leading-space/`에 입력·영수증·독립 줄 관찰을 보존한다. 두 제어 PDF 모두 정식 pdf 경로에 보관하며 원본 시행령 PDF는 보존한다.

최종 수정 전 3건은 1 PASS·2 FAIL(1.314초), 공통 보정 후 같은 3건은 3 PASS(1.310초)다. 방향성 기호와 기존 닫는 prime의 소속은 유지된다. ASCII 작은따옴표를 문자값만으로 줄 끝 금칙에 넣던 조건과 그에 의존한 닫는 apostrophe 전용 우회만 제거한다. 문서·쪽 번호 분기는 추가하지 않는다.

같은 61쪽의 독립 Print ASCII 원점(717.2799, 116.48)과 다음 줄 시작(268.8, 140)을 ±2px로 보호하는 별도 고정형 검사도 추가했다. 세 관계형과 이 고정형은 함수 주석에서 구분한다. 원점은 run 하나의 bbox로 추정하지 않고 실제 문자 경계에서 읽는다. 처음에는 작은따옴표가 별도 run이라고 잘못 가정해 실패했으나, 같은 style로 합쳐지는 정상 run의 문자 위치를 읽도록 검사만 수정했고 독립 기대 좌표는 유지했다. 최종 4건 모두 PASS(1.354초), 기존 큰따옴표·한글 금칙·HWP3·첨자·원본 기호까지 관련 37건 PASS(1.654초)다. 최소 글꼴 sandbox에서 실행했다.

## 실제 Native

Native nextest가 같은 native-skia release-test 경로에서 이미 CLI를 빌드했으므로 이를 source diff·SHA와 함께 동결해 불필요한 별도 Native 재빌드를 하지 않았다. 같은 개발 의존성 통합 조건의 수정 전 CLI도 링크 전에 보존했다. 61쪽은 99.55732%(480픽셀)→100.00000%(0)이고 13·18쪽도 100.00000%다. 동일 61쪽 review·overlay를 직접 판독해 작은따옴표 줄 소속·상단 두 줄 정렬과 본문·표의 보존을 확인했다. 최신 fresh WASM·전쪽·전체 회귀·정본 보호는 이후 단계이며 이전 소스 통과를 재사용했다고 주장하지 않는다.
