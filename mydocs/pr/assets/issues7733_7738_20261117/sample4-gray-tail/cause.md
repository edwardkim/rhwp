# sample4 26쪽 코드 배경의 하단 잘림

사용자 지적 영역은 회색 코드 배경 하단의 PDF 전용 빨간 띠다. 기준과 후보가 같다는 사실은 결함을 해소하지 않는다. 기존 #9157 검토도 이 차이를 남겼다고 기록했고, 제외된 과거 보정의 원 코드를 Ubuntu 저장소 Git 객체에서 직접 읽어 비교했다. 원본 HWP·독립 한컴 2020 Print PDF·글꼴·판정 문턱은 바꾸지 않는다.

96 DPI 원본 PNG에서 RHWP 회색 배경은 y=1008에서 끝나고 PDF는 y=1014까지 보인다. 실제 배치의 마지막 원문 문단 890은 y≈995.6, 줄 상자 높이≈13.3으로 본문 끝 y≈1009.1 안에 수용돼 있다. 원본 줄 높이와 줄간격이 생산한 채움 밴드는 20px인데, 최종 paint가 본문 단 끝으로 clamp해 약 13.5px만 남긴다. 독립 PDF의 마지막 회색 벡터 사각형도 96 DPI 환산 y≈994.592–1014.571로 후행 밴드를 포함한다. PDF 용지 척도와 glyph 농도 차이를 잘림 원인과 구분한다.

보정 방향은 본문에 실제 수용한 TextLine이 소유한 채움 밴드를 최종 paint까지 보존하는 것이다. 문단 흐름·페이지 소속·다음 쪽을 밀거나 px 상수를 더하지 않는다. 외곽 테두리의 물리 단 경계, 실제 넘친 글줄, 머리말·꼬리말·셀과 앵커 없는 영역의 기존 clip 계약은 유지한다. 과거 빈 문단 흡수 정책 변경은 함께 복원하지 않는다.

회귀는 단 중간 정상 글줄과 단 마지막 수용 글줄의 원본 높이+줄간격 포함 관계, 앞 쪽 줄의 중복 부재와 다음 문단 보존을 검사한다. 좌표 기대값을 렌더 결과에서 추출하거나 절대 px로 고정하지 않는다. 보정 전 집중 실패, 보정 뒤 집중 통과와 Native/fresh WASM의 같은 26쪽 raw·PDF·review·overlay로 실제 결과를 확인한 뒤 최종 검증을 잇는다.
