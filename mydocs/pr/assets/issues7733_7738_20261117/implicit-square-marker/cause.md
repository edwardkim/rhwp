# 암묵적 Wingdings 네모의 원 프로그램 보존

공식 파일 형식 문서 Section4의 변경 이력 마커 4개는 원본 글머리표 U+F0A7이다.
기존 경로는 이를 표시용 U+25AA로 바꾼 뒤 본문 글꼴의 폭과 잉크로 그렸다.
독립 공식 PDF의 Wingdings-Regular는 원점이 같은 별도 네모 프로그램으로 출력한다.
따라서 글자 원점을 옮기거나 PDF·폰트를 바꾸어 맞출 문제가 아니다.

기존 #8611 메인터너 보정 ce36292359의 암묵적 원 기호 전진·잉크 소유를 대조했다.
지정 공식 PDF 70쪽 xref372의 실제 glyph ID3을 읽어, UPEM2048·advance937,
경계 (173,444)..(765,1036)의 단일 네모임을 확인했다. 기존 U+F09F 원과 전진·상자가
같고 도형만 다르다. 서브셋에는 cmap이 없으므로 PDF 문자 추적의 glyph ID를 사용했다.
원점 차이와 glyph 내부 잉크 차이를 구분했다. 글꼴 바이너리나 추출 윤곽은 제출하지 않는다.

공통 암묵적 프로그램에 네모 도형을 추가하고 원 PUA 주소를 측정·paint까지 유지한다.
기존 원의 수치·예약 영역·본문 시작은 유지하며 리터럴 Unicode 네모에는 적용하지 않는다.
SVG의 일반·그림자·양각과 Native·Canvas 2D가 같은 도형 상자를 소비한다. 설치 Wingdings는
필요하지 않는다. 특정 문서·쪽번호의 px 오프셋을 넣지 않았다.

새 원 주소와 상대 전진 검사 2건은 보정 전 실제 FAIL, 기존 원·리터럴 대조 4건은 PASS였다.
이후 네모·원은 같은 상자에서 서로 다른 도형으로 그리며 리터럴은 글꼴로 남는 SVG 검사를
추가했다. 점 기호 공급·명시적 대체·HFT 프로그램 추적까지 최소 글꼴 집중 18 PASS다.
이 18건을 전체 회귀 완료로 세지 않는다.
