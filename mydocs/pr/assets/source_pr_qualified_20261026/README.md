# 원 PR 기존 재현본의 고정 base·후보 전쪽 증거

동결한 통합 검토에서 이미 사용한 62조건만 비교했다. 모든 조건은 한 쪽이며 각 backend의
후보 62쪽 모두 독립 한컴 Print와 쪽수가 같다. Native255·최적화 fresh WASM073 후보의
최저 raw는 각각 **99.98107%**다. 누락·측정 불가·90% 미만과 base 대비 **0.1%p 초과 하락은 0쪽**이다.

고정 devel은 `238de6de41a208648f4ade6b494fe433a81c1fce`, 실제 runtime은
`bbf3aed18dd82bbf344072b77b5ac590e7a71f3a`, 코드·검사는
`61528013511c87c732524f91c6f224286a055337`이다. 이후 문서·증거는 코드를 바꾸지 않았다.
[입력/PDF·실제 producer·명령·TSV/PNG 해시](provenance.json)를 파일별로 기록했다.
[공급 글꼴 1,317개](../inline_wrap_qualified_20261026/font_supply.tsv)는 모든 캡처에서 목록·해시가 같다.

## 재현 입력과 독립 기준

새 HWP/HWPX·Print PDF를 생성하지 않았다. 기존 자료를 그대로 사용하며 59~62번 공개 API
입력·PDF만 원래 바이트로 [정식 보존 경로](../computed_empty_host_line_20261020/public_api_originals/README.md)에
복사했다. 입력 생성 방식·원 source와 실제 MCP 또는 사용자 수동 Print 계약은 각 기존 주제의
provenance 및 개별 리뷰를 따른다. base의 90% 미달은 같은 입력의 수정 전 결함이며 후보의 미달로
바꾸어 쓰지 않는다. base/후보의 producer는 분리해 보존했다.

후보의 완료 캡처 124개를 재사용했다. base 중 디스크 부족 전에 완료된 41개는 동일 원본·PDF·
producer·쪽수와 실제 PNG를 확인한 뒤 정본 `--silhouette-only --png-pair`로 재측정했다.
나머지는 같은 정본 export로 산출했다. 원문 TSV 248개는 byte 단위로 복사했고 비교표만 별도 계산했다.
수치가 허용 범위라는 사실과 직접 판독·내용 소유의 의미 검사는 구별한다.

## 대표 PNG의 직접 판독과 재사용

현재 캡처와 직접 관련된 23조건의 Native/fresh PNG 46쌍에서 review·standalone overlay를
정본 `scripts/visual_sweep.py`의 `make_compares`, `make_overlay_page`, `make_review_panels`로 만들었다.
코드 불변·원 PNG 해시와 원 manifest를 확인했고 기존 캡처나 provenance를 덮어쓰지 않았다.
일반 CLI `--resume`이 문서 head 변경을 거절한 기록은 통과 증거로 쓰지 않았다.
새 캡처로 가장하지 않고 캡처 재사용과 이번 패널 합성을 구분한다.

서로 다른 실제 RGB 쌍 31개를 직접 열었다. 나머지 15개는 양쪽 원 PNG의 크기와 디코딩한
RGB byte가 모두 같음을 확인해 판독만 재사용했다. 다른 원본 파일의 동일성이나 의미 검사까지
대신한 것이 아니다. 도형 회전·겹침·필드 내용, 캡션 자동 번호·기준선, 빈 호스트·뒤 본문,
강조점·clip 및 양식 첫 줄을 같은 배율로 대조했다.

얇은 괘선의 농도와 글자 가장자리 잔차는 남는다. 도형 선의 33HU·Print 0.36pt 계약에 관한
[기존 별도 조사](../semanticist21_group_geometry_20261021/README.md#직접-판독과-의미-검사)를 유지하며
선을 임의 1px로 두껍게 만들지 않았다. raw 100%를 RGB 완전 일치로 설명하지 않는다.
