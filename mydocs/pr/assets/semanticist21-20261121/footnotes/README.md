# 다단 각주 본문의 줄바꿈과 저장 후 재열기

2026-11-21에 각 입력을 한컴 2020으로 직접 인쇄하고 같은 입력의 Native Skia와 최적화한 fresh WASM Canvas를 96 DPI에서 대조했다. 측정치는 색상 경계 보정 전 2px 실루엣 일치율이다. [전체 48행과 원본·PDF SHA-256](pages.tsv)

원본 `tests/fixtures/footnote_columns/c3u-eachColumn.hwp`는 첫째 단 본문이 ‘본문입니’에서, 둘째 단 본문이 ‘각주를’에서 첫 줄을 마친다. 보완 전 Native와 WASM은 원본의 저장 줄 시작점을 그대로 사용해 두 단에서 한컴보다 글자를 더 넣었다. 커밋 `f26e155ab6`은 본문 위 첨자 번호와 닫는 괄호의 표시 폭을 줄 채움과 그리기에 공유하고, 이 폭을 합산해 저장 줄의 재사용 여부를 판정한다. 원본을 처음 열 때 Native가 89.87%에서 99.26%, WASM이 89.59%에서 98.48%로 올랐다. [본문 확대](unequal-columns-body.png)

각주 1은 첫째 단 아래, 각주 2·3은 둘째 단 아래, 각주 4는 셋째 단 아래에 놓인다. 양쪽 출력에서 각주 경계선과 번호·본문을 확대해 줄 순서와 단 소속을 확인했다. [각주 확대](unequal-columns-notes.png)

Chromium에서 원 HWP를 연 직후, 세 단의 본문에 글자를 넣었다 지운 직후, HWP와 HWPX로 각각 내보내 다시 연 직후의 줄별 본문과 참조 위치를 비교했다. 네 상태에서 같은 줄에 같은 참조와 본문이 남았다. JSON 안의 `#`는 본문 안에 렌더된 각주 번호 위치를 표시한다. [브라우저의 네 상태](browser-body-rows.json) · [편집 후 저장본](saved/)

## 두 단의 마지막 각주와 주석 사이 간격

`c2-eachColumn.hwp`에는 왼쪽 단에 각주 1개, 오른쪽 단에 2개가 있다. 오른쪽의 두 각주 사이에 283 HWPUNIT의 간격을 두도록 저장되어 있다. 한컴 Print에서 오른쪽의 첫 각주 기준선은 741.7494pt, 마지막 기준선은 754.5754pt다. 왼쪽의 마지막 기준선도 754.5754pt다. [독립 인쇄본](../../../../../pdf/pr9234-footnote-columns/c2-eachColumn-2020.pdf)

이전 제품은 단 안에 다음 각주가 있는지 확인할 때 쪽 전체의 각주 번호를 사용했다. 그 결과 오른쪽 각주의 줄 상자가 맞닿았고 마지막 줄이 왼쪽보다 3.8px 위에 놓였다. `da7586cead`에서 단 안의 순번으로 다음 각주의 유무를 판단하도록 고쳤다. 같은 글꼴과 독립 PDF로 측정한 Native와 fresh WASM은 각각 97.47%에서 100.00%로 올랐다. 둘 다 오른쪽에만 3.8px 간격이 생겼고 마지막 두 줄의 위쪽 좌표가 995.8px로 일치한다.
