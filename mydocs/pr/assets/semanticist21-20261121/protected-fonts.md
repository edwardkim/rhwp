# 보호 문서 글꼴 재현 검증

11월 21일 검토한 통합 후보의 다단 각주 원본은 [원본·편집본 대조](footnotes/README.md)에 기록했다. 별도로 보호 문서 23종의 4,046개 Native·fresh WASM 측정값을 기존 정본과 대조한다.

## 독립 글머리표

별도 보관본이 없는 검증용 Hanyang·Poppy OTF의 해시는 선행 검증의 [공급 목록](../issues7733_7738_20261117/final-efe954/protected-font-conditions)에서 확인했다. 독립 HWPX 문자표의 한양중고딕 슬롯에 U+2022를 넣고 한컴 2020에서 PrintMethod 0으로 인쇄했다. 원래 글리프의 Type3 명령 SHA-256은 `2506433f6422778c6963a3dcbf11c311df80b06e75aad7a49a64e9be6c25a16a`이며 수평 전진은 1,000, 왼쪽 베어링은 316이다. 세 값이 [선행 글머리표 검증](../issues7733_7738_20261117/chemical-bullet-program-order/original-symbol-program-proof.json)과 일치했다.

독립 입력 SHA-256은 `5d11ca16005a631b110c748cbb182e2521f37868f0a516aee05ed09f77767cb1`, Print PDF는 `dff20e43f3b698161328c2378495bcacbdfb8251ec9ea512b9286de745006560`이다. 이 글리프만 담은 로컬 글꼴은 원본과 다른 이름으로 만들어 명시적으로 공급했다. 화학물질 표시 기준 72쪽에서 이 파일을 우선 공급한 첫 측정은 Native 99.91%, WASM 99.84%다. 해당 쪽의 기준은 각각 99.91%, 99.95%다.

## 실제 프로그램 대조

Native가 사용하는 식별 값은 파일 전체와 컬렉션 face index 4바이트를 연결한 SHA-256이다. 로컬 파일에서 한양중고딕·견고딕과 함초롬바탕·함초롬돋움의 식별 값이 선행 기록과 일치했다. Native가 한 번에 읽는 사용자 글꼴은 최대 256개다. 원본·독립 PDF에 쓰인 face와 선행 선택 프로그램으로 공급 목록을 좁혔다. 화학 문서 52개, 시행령 20개, 형식 사양서 18개다. 같은 조건에서 화학 문서 1쪽은 Native·WASM 모두 100.00%, 72쪽은 두 경로 모두 99.92%였다. 시행령 4·13·18·24·61쪽은 두 경로 모두 100.00%였다. 이 측정의 제품 소스는 `c6fb9159bf`다.

형식 사양서 Native 71쪽을 대조하면 기존 하한에 못 미친 쪽은 8·16·17쪽이다. 8쪽 제목의 한산뜻돋움 굵게는 Print의 사용 글리프 29개 모두 로컬 파일과 윤곽·수평 메트릭·힌팅 명령이 일치했다. 16쪽 Arial의 사용 글리프 29개는 로컬 7.05·7.07 모두 윤곽과 수평 메트릭이 일치했고, 개별 힌팅 명령 일치는 1개였다. 글꼴 파일을 전부 확보했다거나 잔여 차이가 모두 글꼴에서 비롯됐다고 판정할 근거는 없다.

HCI Poppy의 독립 한컴 2020 문자표는 글꼴 설명에 Gulim을 담은 CID TrueType으로 인쇄됐다. 이 출력은 원본 HFT 윤곽의 공급 근거에서 제외한다. 이 단계의 점수는 당시 보호 정본과 허용치로 평가했다.

## 독립 문자표의 복원 범위

한컴 2020에서 현대 한글 11,172자를 44개 독립 HWPX로 나눠 인쇄했다. 각 요청의 입력·PDF 해시와 PrintMethod 0, 추출된 문자 순서를 확인했다. 결합한 PDF의 SHA-256은 `21aaa13286e52b2aaf78fb6eb68c02f8dd57218d693b53b61ef42e1dceade01d`이다. 원래 윤곽과 전진폭을 보존해 만든 로컬 한양신명조 현대 한글 글꼴의 SHA-256은 `268c743cfa90e37ff5ce2dada01f21d8d19d458734022ad31a480c02ad932317`이다. 별도로 검증한 글머리표 1종과 이 한글 음절들이 독립적으로 확인된 공급 범위다.

별도로 인쇄한 Arial 문자표는 ASCII와 문장부호 102자를 포함하며, 공백을 정규화한 PDF 본문이 입력과 일치한다. 형식 사양서 16쪽에서 사용한 29개 글자의 힌팅 명령은 그중 한 글자만 일치하고 전역 힌트 세 테이블의 내용도 다르다.

형식 사양서 10쪽의 ‘ᄒᆞᆫ글의 문서’에서 첫 음절(`U+F53A`)이 초기 WASM 출력에서 빠졌다. 제품 소스 `143f804aef`의 같은 최적화 WASM에 Studio의 옛한글 글꼴 `assets/fonts/RHWPOldHangul-Regular.woff2`(SHA-256 `1a45a61e9a320c1bc62ca1401f7b23ceffffe8133dc2a9650ad4e12524f8dcab`)을 공급하자 음절이 복원됐다. 공식 PDF 대비 10쪽은 99.43%에서 100.00%, 11쪽은 99.74%에서 100.00%로 올랐다. [10쪽 본문 확대 비교](spec13-old-hangul.png)

시행령 17쪽에는 같은 이름의 HY헤드라인M 프로그램이 두 종류 있었다. Windows 공급본 `e50c7200…`은 독립 PDF에 사용된 글리프 13개의 윤곽·수평 메트릭·힌팅 명령과 전역 힌트 3개가 모두 일치했다. 한컴 추가 번들 `a3f57b4c…`은 윤곽·수평 메트릭이 8개에서 일치했다. 글꼴 공급 목록에 Windows 프로그램을 남기고 동일한 후보를 다시 인쇄했다. 17·41·58·73쪽의 fresh WASM은 각각 99.96%에서 99.98%로 올랐고, Native는 네 쪽 모두 99.98%였다.

화학 문서 91쪽은 본문의 글자 모양 205와 207을 사용하며 일반·굵은 글머리표를 구분한다. 독립 문자표를 한컴 2020으로 인쇄해 일반 U+2022·U+25CB와 굵은 U+2022의 전진폭·왼쪽 베어링·Type3 명령을 대조했다. 세 글리프의 명령과 메트릭이 원 문서의 독립 PDF와 모두 같았다. 굵은 글머리표에는 채우기와 함께 20단위의 획이 있었다. [글리프별 수치와 SHA-256](chemical-symbol-outlines.json)

독립 문자표의 SHA-256은 `3c6cdbd34ecf03238b236c86d03fe161401085261b5b94c7b520f23b31e361fb`, PrintMethod 0 PDF는 `67d8e9c78a1204577826077526e8f7921996f9df6d4afde50fb22bb8ff127175`이다. 이 표본에서 복원한 글리프를 같은 조건으로 103쪽 전체에 공급했다. 91쪽은 Native 99.73%에서 100.00%, fresh WASM 99.70%에서 99.99%로 올랐다. 1쪽은 양쪽 모두 100.00%, 72쪽은 모두 99.92%다. Native 103쪽 모두 정본 하한을 충족했고 fresh WASM에서는 39쪽의 기존 하한을 재현하지 못했다. [91쪽의 일반·굵은 글머리표 확대 비교](chemical-91-programs.png)

## 표 안에 저장된 아래아

형식 사양서 71쪽 표 안의 ‘ᄒᆞᆫ글 문서 파일 구조’는 원본에서 추출한 HWPX와 렌더 트리의 원문에 U+1112·U+119E·U+11AB를 담고 있다. 제품 소스 `da7586cead`에서는 최종 표시 문자열이 현대 음절 U+D55C로 바뀌었다. 독립 PDF의 HCRDotum은 이 위치를 U+F53A로 표현하며 확대하면 ㅎ 아래의 점이 보인다. 이전 #3486·#3563의 근거였던 HWP 97 안내문도 당초 Print와 한컴 2020 Print의 1·3·19쪽에서 같은 점을 확인했다. 한컴 2020 HWP3 Print와 2024 HWPX Print의 24쪽에서 U+F53A 뒤에 글 186회, 메일 6회, 팩스 16회, 소프트 2회가 나온다. 같은 인쇄본의 U+D55C 뒤에도 글 46회와 팩스 3회가 나온다. [두 인쇄본의 확대 대조](legacy-product-source-glyphs.png)

원인은 본문 조합 시점과 표·머리말을 포함한 렌더 트리 완성 시점에서 제품명 네 단어의 첫 음절을 현대 글자로 치환하는 규칙이다. 조합기는 PUA가 있는 런에서만 검증된 문자 매핑을 적용하고, 표·본문은 입력의 옛자모를 글꼴 조합 경로로 그대로 전달해야 한다. 쪽 번호나 낱말 목록과 무관하게 문자와 소유 오프셋을 보존한다.

문자 치환을 제거한 뒤 71쪽의 Native와 fresh WASM 실루엣은 모두 100.00%였다. 확대하면 WASM은 ‘ᄒᆞᆫ’만 옛한글 대체 글꼴로 그렸다. Canvas 호출에서도 이 음절의 첫 글꼴은 `RHWP Old Hangul`이었다. 공식 인쇄본의 함초롬돋움과 브라우저에 적재한 보통 굵기 함초롬돋움 두 버전은 U+F53A의 윤곽 명령, 전진폭 970, 왼쪽 베어링 168이 모두 같다. [인쇄본과 공급 프로그램의 글리프 대조](print-primary-source-font.json)

브라우저는 같은 스타일에 후보 파일이 둘이면 글꼴 전체의 글리프 목록을 등록하지 않는다. 대신 인쇄에 사용할 첫 프로그램은 실제 FontFace 선택 순서에 따라 등록한다. 인쇄 시 일반 자소 선택으로 원 글리프를 찾지 못하면 이 등록 정보에서 해당 글리프의 윤곽을 확인해 같은 프로그램으로 그린다. 첫 프로그램이 그 글자를 지원하지 않고 같은 글꼴 이름의 다른 후보가 미확인이면 기존 옛한글 조합을 사용한다.

### 행정업무운영 편람 43쪽의 한컴바탕

편람 HWP와 HWPX는 KoPub돋움체 Light 다음 대체 글꼴로 한컴바탕을 지정한다. 원문의 세 자모 U+1112·U+119E·U+11AB가 사용하는 옛한글 음절은 두 한컴 Print의 내장 글꼴에서 U+F53A의 윤곽으로 확인됐다. 두 PDF의 글리프와 한컴바탕 원본은 윤곽과 전진폭 1,024/1,024 em이 일치한다. 문서의 자간을 적용한 전진폭은 980 HWPUNIT이다. 현대 음절 ‘한’은 원래 글꼴의 전진폭을 사용한다.

브라우저에서 HWP는 U+F53A를 텍스트로 그렸고, HWPX는 윤곽을 직접 그렸다. 실제 Canvas에서 얻은 HWPX의 닫힌 윤곽 5개와 선분·곡선 84개를 PDF 내장 글리프와 대조했다. HWP에서 뒤의 ‘글’까지 거리는 11.40px에서 13.05px로 바뀌었고, HWPX에서도 보정 후 거리는 13.05px였다. 96 DPI에서 43쪽의 fresh WASM raw는 두 형식 모두 99.98515%에서 100.00000%가 됐고, Native는 두 형식 모두 100.00000%였다.
