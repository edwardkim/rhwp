## Direct PDF의 연결선 보존

#8394가 직접 PDF 출력을 지원한 원본 63쪽과 289쪽을 새 기준과 실제 후보에서 각각 출력했다.
`export-pdf --backend direct --profile print --compat 2024`에 0부터 시작하는 쪽 번호 62와 288을
사용했다. 두 결과는 각각 한 쪽이며, 독립 한컴 Print와 96 DPI로 대조할 때 raw 미대응 픽셀이
모두 0이다. 기준과 후보의 Direct PDF 래스터도 바이트 단위로 같다. 선·화살촉과 상자 배치를
직접 확인했으며 색상·외곽선에는 미세한 잔차가 있다. 이 확인은 편람 전체의 Direct PDF 지원을
뜻하지 않는다.

| 원본 쪽 | raw 미대응 / 합집합 | review | overlay |
| --- | ---: | --- | --- |
| 63 | 0 / 99,670 | [비교](direct-pdf-p063-review.png) | [겹침](direct-pdf-p063-overlay.png) |
| 289 | 0 / 203,464 | [비교](direct-pdf-p289-review.png) | [겹침](direct-pdf-p289-overlay.png) |

[fresh WASM 전쪽 대조](seo-wasm-exact.tsv)는 같은 입력·기준 PDF·글꼴로 비교한 388쪽에서
raw 하락이 없고 후보 최저는 94.651780708383%다. 하락은 표시 소수값이 아니라 정수 집계의
정확한 분수로 확인했다. 출력 PNG는 편람 29쪽에서 색상 픽셀이 달라 바이트 단위로 같지는 않다.
차이가 가장 많은 272쪽은 양쪽 raw 100%이며 본문 위치와 내용이 같음을 직접 대조했다.
Native 캐시·타일·Direct PDF 집중 검사는 별도로 완료해 기록한다.
기준 WASM 패키지는 직전 기준 `96ccd`에서 빌드했다. 이후 `55f40`까지 변경된 Rust 경로는
`native_host`, `renderer/pdf`, `renderer/skia`뿐이며 모두 WASM에서 제외된다. Cargo·의존성·
WASM 출력 스크립트도 변경되지 않아 이 기준 패키지를 재사용했다. 후보는 위에 기록한 fresh
WASM 패키지다. 편람은 기능 보존 대조군으로만 실행했다.

최소 글꼴 환경의 첫 Native Skia 집중 회귀는 416개 중 415개 통과·1개 실패였다. 실패한
`distinct_pages_keep_their_own_exact_full_page_crops_on_warm_round_trips`는 두 쪽을 텍스트로
구별했으나 시스템 글꼴이 없으면 양쪽이 흰색이 되어 서로 다르다는 전제에서 실패했다. 원 PR의
동일 검사도 같은 입력을 사용한다. 두 쪽에 서로 다른 합성 사각형을 넣고 기존 full-page crop·
캐시 재사용 assertion은 유지했으며, 보정한 검사는 같은 최소 글꼴 환경에서 개별 통과했다.
보정 후 같은 환경에서 #8389·#8394·#8371 관련 81개 모듈을 포함한 Native Skia 집중 회귀를
재실행해 416개가 모두 통과했다. 나머지 선택되지 않은 검사는 7,779개다.

이어 실행한 최소 글꼴 Native Skia 라이브러리 검사에서는 3,856개 통과, 2개 실패, 12개
무시였다. 제어 기호와 `atop` 수식의 잉크를 확인하는 합성 검사에서 글꼴을 명시적으로
공급하지 않은 상태로 잉크가 출력되지 않았다.
제어 기호는 시스템 face가 없을 때 명시 공급된 글꼴을 보조 후보로 사용하도록 했으며,
저장소의 라이선스 확인 글꼴을 명시한 집중 검사에서 통과했다. `atop`은 입력 `a`, `b`가
수학 이탤릭 `𝑎`, `𝑏`로 배치되는데 첫 시험의 Noto 글꼴은 이 글리프를 포함하지 않았다.
GUST Font License가 기록된 기존 Latin Modern Math 부분 글꼴은 두 글리프를 포함하며,
같은 최소 환경의 독립 진단에서 녹색 잉크 108픽셀이 출력됐다. 보정 후 최소 글꼴 Native
Skia 라이브러리 전체를 다시 실행해 3,858개 통과·실패 0개·12개 무시를 확인했다. 이전에
실패한 제어 기호와 `atop` 검사도 각각 통과했다.

## PR #8397 CI 보정

첫 code head `95ecc5971c2a684121643ba286caae8dc45b2b2b`의 Frontend package gates에서
undo-depth E2E가 6문단 대신 5문단으로 실패했다. 로컬에서도 재현했으며 새 빈 문서의 로컬
글꼴 선택창이 첫 입력을 가로막는 것을 확인했다. 빈 문서만 선택창을 생략하고 기존 파일 열기의
선택창은 유지했다. 보정 후 기존 undo-depth 110라운드 및 260회 undo와 파일 열기 선택·빈 문서
첫 입력을 브라우저에서 통과했다. 기존 CI E2E에 시딩된 6문단 검사를 추가했다.

같은 head의 CodeQL은 HWP3 파서의 조판 선택 `true`·`false` 인자 7곳을 하드코딩된 비밀번호로
분류했다. 실제 비밀번호 바이트와 복호화 경로는 변경하지 않고, 해당 논리값의 이름을 복호화된
원본의 조판 계약을 나타내는 이름으로 변경했다. 변경 전 파일에 동일한 식별자 치환을 적용한
결과가 변경 후 파일과 일치함을 확인했다. 그러나 `d63927b5bd6a1f408831a55bba906f8a5585cc56`의
CodeQL도 같은 7건을 보고했다. SARIF 데이터 흐름에서 실제 오탐 지점이 그림 주위 폭 계산 함수의
`password: bool` 매개변수임을 확인했고, 해당 매개변수도 조판 계약 이름으로 바꿨다. 실제 암호
처리 경로는 변경하지 않았다. 새 head의 CodeQL 판정은 CI 완료 후 확인한다.
