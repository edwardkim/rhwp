# #7910 어울림 표 뒤 빈 줄과 꼬리말 조판

공개 원본 HWP와 공개 대조 HWP는 한컴 Print에서 각각 2쪽이었고 기존 rhwp는 각각 1쪽이었다. 원본을 한컴 2020으로 저장한 HWPX는 두 엔진에서 2쪽이었다. 한컴 2020 11.0.0.9136의 `Hancom PDF` 한 쪽씩 인쇄를 기준으로 삼았다. 원본의 한컴 2024 13.0.0.3901 Print도 2쪽이다. [공개 재현 ZIP](https://github.com/user-attachments/files/32746158/repro_footer_picture.zip), [#7910](https://github.com/edwardkim/rhwp/issues/7910).

## 쪽수 차이가 생긴 위치

HWP 5.0 사양의 `HWPTAG_PARA_LINE_SEG`는 줄 배치 캐시다. 원본의 세 번째 본문 문단은 어울림 표와 글자를 담는다. 본문 글자는 실제로 폭 2,789 HWPUNIT의 오른쪽 공간에 14줄로 흐르지만 원본 캐시에는 전폭 줄 하나가 남아 있었다. 뒤의 빈 문단 일곱 개에는 재조판 전 위치가 남아 있었다. 마지막 빈 문단의 캐시 끝은 65,663 HWPUNIT이고 원본 본문 높이는 65,766 HWPUNIT이다. [HWP 5.0 rev 1.3 §4.3.4 표 62](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf), [한컴 표 속성 설명](https://help.hancom.com/hoffice/multi/ko_kr/hwp/table/tableattribute/table%28general%29.htm).

`plan_square_table_host`는 표와 같은 물리 프레임으로 호스트 줄을 다시 만들었다. `typeset_block_table`은 이 결과에서 호스트의 글줄만 누적하고 실제 표 상자는 배제 영역으로 등록했다. `wrap_flow`가 뒤의 저장 빈 문단을 표 높이에 이미 포함된 것으로 처리해 7개 문단이 자기 줄 높이와 간격을 소비하지 못했다. 이제 같은 페이지에 수용된 표 계획을 찾으면 뒤 문단을 일반 fit에 넘긴다. 출력도 이때 배정된 페이지와 문단 순서를 사용한다. 실제 표 하단을 지난 빈 줄에는 문단 전폭의 구성을 전달하면서 수용한 높이와 줄간격을 유지한다.

96 DPI에서 본문 높이는 876.88 px다. 표 뒤 첫 빈 줄의 본문 상대 위치는 617.60 px, 일곱째 빈 줄의 상단은 848.00 px, 점유 끝은 872.00 px다. 다음 줄을 시작할 위치는 886.40 px이므로 마지막 빈 문단은 둘째 쪽에 놓인다. 한컴이 저장한 HWPX도 표 옆 빈 문단 여섯 개, 표 아래 전폭 빈 문단 한 개, 둘째 쪽 첫 빈 문단 한 개를 기록한다. 이 HWPX에서 마지막 본문 문단 하나만 제거해 한컴으로 다시 인쇄했을 때 1쪽이 되었고, 남은 첫째 쪽의 96 DPI 픽셀은 제거 전과 같았다.

## 꼬리말

`84dee82a`가 재조판할 꼬리말에 검은 사각형의 점유 영역을 적용한다. 그림·사각형·자동 쪽번호가 있는 원본을 그대로 두었고, 삭제 실험에서는 요소를 하나씩 골라 제거했다. 자동 쪽번호 제거 뒤 문구와 띠가 유지되고, 그림 제거 뒤 띠와 번호가 유지된다. 검은 사각형을 제거하면 문구 기준선이 Native SVG에서 4.00 px, 한컴 Print에서 약 4.00 px 올라간다. 원본 문구의 96 DPI 기준선은 rhwp 1049.84 px, 한컴 2020·2024 Print 1048.77 px로 약 1.07 px 차이가 남는다.

## 입력과 대조 자료

- `hancom-original.hwpx`는 공개 원본 HWP를 한컴 2020으로 저장한 파일이다.
- `no-auto`, `no-picture`, `no-rect` HWPX는 이 파일에서 해당 꼬리말 개체와 그 문단의 저장 줄 캐시만 제거했다. 대응 HWP는 이 변형을 한컴 2020으로 저장한 파일이다. 각 입력을 독립적으로 인쇄했다.
- `no-final-body-paragraph.hwpx`는 한컴 저장 HWPX의 `Contents/section0.xml`에서 맨 끝의 본문 빈 `hp:p` 하나를 제거한 경계 대조다. 다른 ZIP 항목은 동일하다.
- #7909 공개 대조는 표·본문 쪽수의 별도 입력이다. 그 문구와 자동번호 API의 기존 회귀는 #8182에 있다. [#8182](https://github.com/edwardkim/rhwp/pull/8182).

본문 3~9번 빈 문단의 소속과 순서는 표 셀의 같은 번호와 구분해 본문 직속 렌더 트리에서 검사했다. 기존 WASM 커서 조회는 이 입력의 본문 번호 3~6에 대해 같은 번호인 셀 글줄을 반환한다. `84dee82a`의 한컴 저장 HWPX와 수정 후 HWP/HWPX에서 같은 좌표로 재현됐다. 이 변경의 WASM 커서 검사는 표 옆 마지막 줄, 표 아래의 전폭 줄, 둘째 쪽의 마지막 빈 문단을 확인했다.

기여자 공통 보호 검사는 4개 문서의 Native·fresh WASM 8건을 모두 통과했다. 두 자리 raw 표시값은 모두 100.00%였다. [공통 보호 결과와 TSV 원본](contributor-gate/results.json).
