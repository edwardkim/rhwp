# 누름틀 종료 표식이 있는 제어 전용 문단의 삽입점

## 확인한 계약과 반례

HWP5 FIELD_BEGIN과 FIELD_END는 각각 원시 문단 스트림의 8 UTF-16 유닛을 차지한다.
BEGIN은 `controls[]`에 있지만, 짝인 END는 `field_ranges`로 표현된다.
따라서 글자와 `char_offsets`가 비어 있어도 `control_idx * 8`이 항상 실제 삽입점은 아니다.

원 PR의 일반 제어 전용 문단 사례를 유지한 채, 원 여권 서식의 두 표 앞에 빈 누름틀
BEGIN/END를 더하는 합성 관계 검사를 `tests/cases`의 기존 파일에 추가했다.
뒤에 그림을 넣으면 앞선 줄 시작은 그대로여야 한다. 새 base에서 원 12개 PASS,
추가한 1개 FAIL로 확인했으며 실제 값은 `[0,48] → [0,56]`이었다.
이 값은 그림의 실물 px 좌표가 아니라 원본 스트림의 슬롯 길이와 줄 소유 관계다.

## 보정 범위

`shift_for_inline_control_insert`의 새 empty-paragraph 추정에
`field_ranges.is_empty()` 조건 하나를 더했다. 짝이 있는 누름틀 범위는 기존 문자 좌표
경로를 유지한다. 누름틀 번호의 공통 이동은 계속 수행한다. 일반 제어 전용 문단의 원 PR
수정은 유지하며, 고아 종료 표식·제목 차례·문서별 분기나 조판 상수는 추가하지 않는다.
누름틀 내부의 모든 편집 동작까지 새로 해결했다고 주장하지 않는다.

## 집중 검증 결과

최소 글꼴 격리에서 원 12개와 새 반례 1개가 모두 통과했다.
보정 전 12 PASS / 1 FAIL → 보정 후 13 PASS / 0 FAIL이다.
편집 직후와 HWP 저장 후 재열기에서 줄 시작을 보존한다.

이 결과는 집중 검사 결과다. 새 source의 전체 회귀·Native/fresh WASM·필수 게이트는
후속 검증에서 별도로 확인하며 이전 전체 통과 기록을 이 보정의 결과로 재인용하지 않는다.
