# 저장된 도형 호스트의 실제 프레임과 뒤 표 보존

코드 `5ad5d94b1d9e48f15e2e0b9c562794b513696163`을 Native047·최적화 fresh WASM021로
대조했다. #8064에서 수용한 원본·독립 한컴 Print PDF를 같은 바이트로 재사용했다.
이 자료는 이번 호스트 보정의 증거이며 통합 PR 전체의 완료 판정이 아니다.

## 원인과 생산·소비

원본 8쪽의 「제안서 작성목차 및 관련서식」 문단에는 자리차지 사각형이 있다.
Common 배치 높이는 1,300 HWPUNIT이고 내부 도형 좌표의 높이는 6,832다.
호스트의 저장 줄은 실제 프레임과 같은 높이여서 유효하다. 새 `inline_box_rows`가
흐름 높이의 상한을 저장 줄에 대입하면서 제목을 낮추고 뒤 표를 다음 쪽으로 밀었다.
두 형식 모두 기존 64쪽이 66쪽으로 후퇴했다.

원 해결 #4333·#4607과 공통화 커밋 `e7bc06c6e988`을 추적했다. 기존 흐름 높이 함수는
그 계약대로 유지한다. 저장 호스트의 유효성 판단은 실제 그리기에 전달하는 Common 프레임과
원본 여백을 소비한다. 내용 숨김·좌표 clamp·문서 ID 조건이나 기대 쪽수 완화는 추가하지 않았다.

`head/wasm/{hwp,hwpx}.tsv`에 보존한다. 같은 폴더의 8쪽 review·overlay를 직접 판독했다.

해결했다고 주장하지 않으며, devel 대비 보존과 이번 변경 영역의 판독을 구분한다.

해당 쪽은 Native/fresh WASM 모두 100%이고 같은 영역의 직접 판독도 완료했다.

## 새 이름의 정식 회귀

`tests/cases/stored_shape_host_physical_frame.rs`는 HWP5/HWPX 각각 관계 검사와
완료 페이지 좌표 검사, 총 4개 함수를 추가한다. 64쪽 일치와 함께 제목·표의 단일 소속,
표의 시작부터 종료까지 원본 셀 내용의 순서·보존·누락·중복을 검사한다. 좌표 검사에도
제목 다음 표라는 관계를 유지한다. 기존 검사를 삭제하거나 잘못된 출력을 새 기준으로 고정하지 않았다.

동일 원본·동일 검사로 수정 전 Native046은 4FAIL, 보정한 Native047은 4PASS였다.
양쪽 모두 `-D warnings` 컴파일에 성공했고 빌드 실패·0건 실행을 결함 검출로 세지 않았다.
표 전체의 추가·누락·중복까지 검사하도록 보완한 뒤에도 동일한 수정 전 4FAIL / 수정 후
4PASS를 확인했다. 독립 원본 셀 텍스트와 실제 표 텍스트 567자는 정규화 후 완전히 같다.

정식 Cargo 자동 수집에서는 이 파일 4건과 중첩 표 정상 대조군 2건, **총 6건 모두 통과**했다.
실행 전 suite manifest를 prepare·check한 뒤 case resolver가 지정한 실제 suite를 사용했다.
해당 실행의 target은 `regression_suite_025`이며, suite 번호를 고정된 등록 규칙으로 삼지 않는다.
공유 `target/pr-review`, `release-test`, `native-skia`, 빌드 잡 8개, 테스트 스레드 12개를
사용했다. 컴파일 12.74초, 실제 실행 0.644초이며 실행 누락은 없다. 이 결과는 전체 Rust
회귀·lint·Studio 검증이나 통합 PR 준비 완료를 뜻하지 않는다. 실행 로그는 ignored
`output/pr-review/semanticist21-20261019/logs/stored-shape-cargo-382.log`에 보존한다.
