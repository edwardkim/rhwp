# 글상자 안 제한 표와 자유 배치 표의 프레임

대상은 #9137의 저장 줄 없는 대조군 `textbox_nostored_header_front_tall.hwpx`이다.
통합 전 base와 첫 후보 모두 공식 한컴 2020 Hancom PDF Print와 33.03871%였다.
기존 검사는 웹한글기안기 화면 추정을 근거로 표 없는 대조군과 같은 제목 위치를 요구한다.
그 기대는 독립 데스크톱 Print의 배치와 맞지 않는다. 먼저 출력을 보정하며 검사 기대값은
새 Native/fresh WASM 시각 검증 전에는 바꾸지 않는다.

## 독립 대조 결과

원본의 표 위치는 문단 기준 위, `flowWithText=1`, 세로 오프셋 −388HU다.
한컴 재저장본은 표의 낡은 공통 높이 5983HU를 셀 높이 5669HU로 정리했다.
글상자의 원본 높이는 5940HU이고 두 안 여백은 각각 283HU다.
한컴이 저장한 뒤 본문 `BODY`의 시작은 6801HU로, 셀 높이 5669 + 표 바깥 위·아래
여백 566 + 글상자 안 위·아래 여백 566의 합과 같다.

동일 원본에서 속성 하나만 바꾼 세 대조군을 MCP engine 2020, Hancom PDF Print로 출력했다.
원본·오프셋 0·공통 높이 5669 대조군의 96dpi PDFium RGB 버퍼 SHA는 모두
`ce1beefec910194760975547ad1dddcb00014fe871719bcaf323529b232862a8`로 일치했다.
따라서 제한된 표의 음수 오프셋이나 낡은 공통 높이를 그대로 정렬 예산에 넣을 수 없다.

`flowWithText=0` 대조군은 다르다. 표는 가운데 정렬 전 문단 원점과 부호 있는 오프셋을
소유하며, 글줄 정렬과 표 바깥 여백을 따라 이동하지 않는다. 제목과 뒤 본문은 원래 글상자
높이를 사용한다. 상세 PDF 경계·글자 상자와 입력·출력 SHA 및 MCP 영수증은
`header-front-print-controls.json`에 기록했다. 세 HWPX와 Print PDF도 정식 경로에 보존한다.

## 보정 후보와 남은 검증

첫 빈 앵커의 한 행 제한 표는 원본 셀 높이·표 바깥 여백·글상자 안 여백으로 최소 프레임을
계산한다. 저장 줄·인라인·크기 보호·변환된 프레임에는 이 하한을 덮어쓰지 않는다.
본문 전진과 도형 paint가 같은 하한을 사용하고, 세로 정렬도 같은 제한 표 바닥을 쓴다.
저장 줄 없는 자유 배치 표는 글자 정렬 전 원점을 유지한다. 문서명·쪽 번호 예외는 없다.

이 기록은 독립 원인 분석과 보정 후보이며 최종 수용 판정이 아니다. 새 Native/fresh WASM
전쪽, 기존 저장 줄 대조군, 관련 회귀와 정본 보호 검증을 완료한 뒤 결과를 갱신한다.

첫 보정 Native에서 원본·오프셋 0·정리된 높이 대조군은 96.50%, 자유 배치·표 없는 대조군은
100.00%였다. 직접 판독에서는 원본의 뒤 본문 `BODY`가 늘어난 도형 아래로 이동하지 않아
흰 도형에 가려졌다. 조판 예약뿐 아니라 `layout_shape_item`의 본문 커서도 같은 파생 하한을
소비하도록 보완한다. 이 중간 96.50% 결과를 최종 완료로 수용하지 않는다.


## 최종 제품 보정의 집중 결과

제품 source `167921b3c5`의 Native와 fresh WASM에서 원본·세 속성 대조군·표 없는
대조군 5종은 모두 100.00%다. review와 overlay에서 TITLE·BOX·BODY가 각각 한 번 보이고
BODY가 늘어난 프레임 뒤로 이동한 것을 직접 확인했다. 최소 글꼴 회귀는 기존 저장 줄
대조군 3건과 새 관계형 2건·독립 Print 위치 고정형 1건을 포함해 6건 모두 통과했다.
자유 표의 부호 있는 이동은 오프셋만 0으로 바꾼 재저장 대조군과 비교한다.
보호 문서 전쪽 및 전체 회귀가 끝나기 전에는 PR 전체 완료로 확대하지 않는다.
