# 제목 뒤 사진 행의 높이 보정 원인

검토 대상은 원 PR #9022의 `samples/title_flow_photo/title-flow-photo-row.hwp`이다.
공식 기준은 같은 원본을 한컴 2020 데스크톱의 Hancom PDF Print로 출력한
`pdf/pr-review-all-open-20261116/title-flow-photo-row-hwp-2020.pdf` 3쪽이다.
웹한글기안기 PDF는 공식 대조 자료로 사용하지 않는다.

## 실제 반례와 공통 원인

통합 후보 `dadfc954`의 Native 전쪽 일치율은 43.29595%, 100%, 100%였다.
첫 쪽의 낮은 선언 행은 칸 높이 83.76px이지만 제목 뒤 사진의 바닥은 칸 밖으로 나간다.
두 번째 행과 후속 쪽은 맞으므로 전체 점수 평균으로 첫 쪽의 결함을 숨길 수 없다.

원 PR은 마지막 빈 그림 문단의 합성 자리 줄을 제거하는 처리를 여러 문단의 칸으로 넓혔다.
그러나 저장 줄 없는 갈래에서 계속 칸 전체 `text_height`를 빼므로 앞 제목 줄의 흐름까지
같이 사라졌다. 원본에서 계산한 안 여백 두 곳, 제목 줄 1600HU, 사진 높이 6000HU의
합은 약 105.09px이며, 기존 검사도 이 원본 관계를 요구한다.

`height_measurer.rs`는 마지막 문단의 인덱스를 유지하고, 그 문단의 실제
`para_flow_heights[pi]`에서 문단 앞 간격을 제외한 몫만 차감하도록 보정한다.
단일 문단 칸의 기존 계약과 앞 간격은 유지한다. 문서명·쪽 번호 예외는 추가하지 않는다.

## 검증 기록

최소 글꼴 macOS 격리 환경의 보정 전 집중 검사는 실제 3건 중 2 PASS, 1 FAIL이다.
`low_declared_title_photo_cell_grows_without_anchor_line`이 83.76px과 원본 계산
105.09px의 차이로 실패했다. 앞선 파생 suite 미갱신 실행의 0건 결과는 검증으로 세지 않는다.
보정 후 같은 최소 글꼴 검사 3건은 모두 PASS였다(검사 0.025초, 컴파일 3분 52초).
기대값과 쪽수 검사는 변경하지 않았다. 새 Native producer `d2bc18cb2b`의 전쪽 TSV는 3쪽 모두 100.00%였다. 첫 쪽 review와
overlay를 직접 판독해 제목·사진·칸 바닥과 뒤 행의 포함 관계를 확인했다. 최종 제품 source `167921b3c5`의 fresh WASM도 3쪽 모두 100.00%다.
최소 글꼴 환경의 기존 3개 회귀는 최종 재실행에서도 모두 통과했다.
