### 다단 각주 공통 소비 연결과 초기 확인

`FootnoteRef.column_index`는 Typeset의 `record_current_footnote_with_storage`와 Paginator의 실제 수용 지점에서 확정한다. 페이지를 복사하며 문단 번호를 옮기는 경로도 이 소유 단을 보존한다. `footnote_frames::FramePolicy`가 각 단·통단·오른쪽 단의 목표와 너비를 공통으로 정하며, 프레임별 `Reservation`은 구분선·각주 사이 간격을 누적한다. Typeset/Paginator의 현재 단 예산은 이 예약을 소비하고, 오른쪽 단에만 놓이는 각주는 앞 단의 본문 높이에서 차감하지 않는다. 목표 각주 프레임 자체의 초과는 기존 fit·분할·이월 경로로 전달한다.

### 91.36% 원본의 추가 개선 분석

작업지시자가 지적한 전체 최저 입력은 PR #8549의
`api-8549-moved-terminal-tab-hwp`다. 동일 API 작업의 HWPX는 99.92%다.

원 PR `560014d4554a6798f8524c00d1e261f89fcdca17`과 공식 사양의 PARA_LINE_SEG
bit 17·18(물리 행의 첫/끝 조각), bit 31(구현 편의 property)을 대조했다.
원 PR은 8유닛 개체·탭의 끝 뒤 줄 시작을 바로잡았고 현재 저장 경계 검사도 통과한다.
추가 차이는 저장 경계가 아니라 같은 물리 행을 소비하는 측정·배치에 있다.

원본 HWP의 세 번째 문단은 text_start `[0,24,32,54]`, vpos `[8000,8000,9600,9600]`,
column_start `[0,35750,0,35750]`이며, FIRST..LAST 두 조각이 두 물리 행을 이룬다.
각 행의 높이 1000HU·간격 600HU도 원본에서 확인했다.
`height_measurer::stored_seg_is_row_fragment`는 bit31이 있으면 조각 관계를 버려 측정에서
네 높이를 더한다. 배치의 `next_is_row_fragment`도 같은 술어를 소비해 그림 오른쪽 조각을
다음 줄로 쌓는다. HWP는 뒤 문단을 세 보이는 줄로 그리고, 독립 Print와 HWPX는 두 줄이다.

원본·PDF는 바꾸지 않고 output의 진단용 사본에서 세 번째 문단의 bit31만 분리하면,
현재 제품 그대로 99.92%가 나온다. 이는 원인 분리 실험이며 제품 개선·원본 검증 완료로
승격하지 않는다. 새 기준 PDF나 수정 사본으로 원본을 교체하지 않는다.

보정 방향은 단순히 bit31을 지우거나 같은 vpos를 무조건 합치는 것이 아니다.
공식 FIRST..LAST 소유·같은 vpos·양의 너비·비중첩 수평 구간이 완결된 행을 입증할 때
공통 측정·배치가 그 행을 소비하도록 한다. 서로 완결된 두 행·쪽/단 리셋·합성 자리표는
같은 높이라는 이유로 합치지 않는다. source cache의 일반 수용 기준은 유지한다.
기존 큰 측정 모듈은 현재 공통 술어의 연결만 바꾸고 새 판단 로직은 작은 공통 모듈에 둔다.

현재 제품 source는 전체 Rust 검증 중이므로 검증 종료 결과를 먼저 수집한다.
제품 보정 뒤 같은 원본·기존 독립 Print로 Native/fresh WASM을 다시 실행하고,
정상 줄·기존 조각 문서와 PR #8389·#8397의 보존 조건도 재확인한다.


R2 전체 nextest는 새 제품 보정이 필요해 컴파일 중 종료 코드 130으로 중단했다.
기록은 `final-full-rust-minimal-superseded.json`에 보존하며 전체 회귀 통과로 사용하지 않는다.
중단 뒤 남은 해당 실행의 rustc 두 개도 PID·인자를 확인해 종료했고 공유 target은 삭제하지 않았다.

공통 `stored_seg_is_row_fragment`는 기존 실저장 행 판정을 유지하고, bit31이 있는 행에는
`stored_line_ladder::has_declared_fragment_boundary`의 완결 FIRST..LAST·동일 vpos·양의 폭·
비중첩 수평 소유 증거를 요구한다. 측정의 높이 합산과 실제 배치의 전진 억제가 같은 판정을
소비한다. 연속 행·쪽/단 시작이나 모든 조각이 각자 완결된 합성 줄은 합치지 않는다.

R5 제품 `71e5e0ae2a72a6b8f51682d131077bd4df44994f`과 고정 base `170b886f167b705b6e630c5b34bb638d92fae0a9`의 Native 128입력·301쪽 대조를 완료했다. 2%p 초과 하락·후보 90% 미만·누락·오류는 모두 0이다. 같은 원본 WOFF를 SFNT로 재변환한 시간 메타데이터 차이 8건은 정확한 provenance 지문과 원시 테이블 대조에 근거해 조건을 수용했다. 다른 글꼴 조건을 자동 면제하지 않는다. 정밀 결과는 `validation-r5/native-new-base-comparison.json`에 보존한다.
