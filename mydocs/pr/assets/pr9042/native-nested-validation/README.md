## 독립 입력과 오류의 원인

`input-generation/`의 RHWP 합성 precursor를 한컴 2020 `11.0.0.9136`에서 실제 HWP로 SaveAs한 뒤,
그 저장본을 같은 제품의 method 0·one-up Print로 출력했다. 수정에서 신뢰하는 줄·칸·여백은
**실제 한컴이 재계산한 저장값**이다. 합성 precursor의 수동 LineSeg를 정상 저장 정보의 증거로 승격하지 않는다.

한 문단 사례의 자식 높이·칸 선언은 1,082 HU지만 저장 내용 하한은 `650 + 282 = 932 HU`다.
내용이 상자를 넘지 않는데도 기존 정확한 동등 비교가 정상 여백 150 HU를 거절했다.
두 문단은 줄 시작이 `0, 1038`, 줄 높이가 각각 650 HU, 여백 합이 282 HU여서 내용 끝은 1,970 HU다.
실제 자식 높이도 1,970 HU이고 칸의 최소 선언은 1,882 HU다. 최소 선언과 실제 닫힌 상자를 같은 높이라고
가정하거나 문단이 하나여야 한다고 제한하면 정상 경계를 처리하지 못한다.

## 공통 보완의 범위

- 자식의 선언 상자 안에 저장 내용이 포함되는지 확인한다. 빈 공간을 제거하거나 내용으로 채울 필요는 없다.
- 여러 문단은 같은 셀의 되감기·겹침 없는 저장 줄 사다리일 때 끝점을 공유한다. 문단별 지역 원점을
  무조건 최대값으로 합쳐 내용 하한으로 삼지 않는다.
- 자식 바깥 여백·칸 안 여백·저장 줄 폭까지 실제로 호스트 줄과 자식 칸에 포함되는 경우만 새 회수를 허용한다.
  합성 precursor의 과거 큰 셀에서 복사한 줄 폭 등 유효성이 없는 저장 정보는 거절한다.
- rowspan·분할·이어받기에는 이 전체 상자 규칙을 확장하지 않는다. 기존 rewind·span·미입증 경로는 유지하며
  기존 #8682의 대조군과 정본 보호 전쪽을 최종 head에서 검증한다.

제품 코드에 문서 ID·목표 px·보호 점수에 맞춘 상수는 추가하지 않았다. 세 문서의 내용·표 순서·부모 칸 안의
자식 표시와 후속 페이지도 Native/fresh WASM 확대 판독·관계형 회귀로 보호한다.
