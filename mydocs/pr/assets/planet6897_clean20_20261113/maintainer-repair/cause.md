# 원 PR이 고지한 악화 원본의 메인터너 보정

현재 기록은 Native 집중 검증 결과다. 새 후보의 fresh WASM·최종 전체 회귀와 보호 문서 재검증은 진행 중이며, 이 문서만으로 병합 승인하지 않는다.

## #8959 — 새 쪽으로 넘어간 TAC 줄의 앞 간격과 원점

원본 `3930000-201800017-health-report.hwp`의 문단 32는 저장된 첫 줄 원점이 이전 쪽에 있고, 새 쪽의 다음 원본 문단 33은 `4913HU`에서 시작한다. 이 값은 문단 위 간격 `1000HU` + 개체 소유 줄 높이 `3013HU` + 줄간격 `900HU`와 정수 단위로 정확히 같다. 독립 한컴 2020 Print의 6쪽도 같은 순서·배치를 보존한다.

기존 조기 `StoredTacPlan`은 이월된 개체 줄의 앞 간격을 버리고 줄간격의 절반만 소비했다. 일반 TAC 경로만 수정하면 이 조기 계획이 먼저 반환되어 실제 배치에는 적용되지 않는다. 또한 실제 배치 이후에도 이전 쪽 원점을 계속 전달해 다음 저장 줄을 거절했다.

공통 질의 `restarted_tac_opening_before`가 다음 원본 줄의 정확한 닫힘을 인증할 때만 앞 간격·전체 줄간격을 사용한다. 조기 계획과 일반 물리 TAC 경로가 같은 원점·끝점을 소비하고, 확정 배치와 일치할 때 후속 줄에 새 쪽의 0축을 전달한다. 문서 ID·특정 px 위치나 페이지별 예외를 사용하지 않는다. 편집된 저장 사다리·명시적 쪽 나눔·불완전한 다음 TAC 줄은 인증하지 않는다.

Native 6쪽: 원 devel 31.31734% → 통합 보정 전 20.75171% → 보정 후 **99.98623%**. 전 7쪽을 산출했고 1쪽은 원 devel 75.88644%·통합 후보 80.50731%로 기존 미달이다. 6쪽의 복구를 문서 전체 통과로 일반화하지 않는다.

## #9001 — 미래 조각의 각주를 원래 프레임 경계에서 차감한 오류

원본 `1543000-202100035-food-security-report.hwp`의 925번 표에는 각주 22가 있고, 독립 Print에서는 첫 조각이 있는 92쪽에는 기존 각주 21만, 이어지는 93쪽에 각주 22가 놓인다. 새 PR의 선언 높이 이월 판정은 아직 조각 소속이 정해지지 않은 표 각주 전체를 뺀 예산을 원래 프레임의 본문 경계로 사용했다. 원래 들어가는 첫 프레임을 넘침으로 오판해 추가 쪽이 생겼다.

원본 프레임의 포함 판정에는 이미 놓인 각주만 차감한 물리 본문 경계를 쓴다. 이후 실제 표 조각 수용·각주 예약은 기존의 예상 각주 예산과 공통 scanner가 그대로 검사한다. 각주 안전 검사를 제거하거나 수치 문턱을 완화하지 않는다.

Native 전체 쪽수: devel 143 / 보정 전 144 / 보정 후 **143** / 독립 Print 141. 집중 92~95쪽은 보정 후 34.23197 / 15.35483 / 19.39922 / 24.73274%. 기존 devel의 동일 쪽 대비 하락은 최대 0.06034%p다. 이미 등록된 #8997의 141↔143쪽 및 기존 미달을 해결했다고 주장하지 않는다.

0→0 원점 인증과 첫 프레임 수용 높이를 넓혔던 앞선 후보는 쪽수만 143으로 맞고 93·94쪽이 더 악화되어 기각·원복했다. 해당 후보를 최종 코드나 통과 근거로 포함하지 않는다.

수치·입력·프로듀서·직접 판독은 [집중 증거](native-focused-cause-evidence.json)에 연결한다. 원본·독립 Print의 커밋 경로와 해시는 [원본 증거](../counterexamples/inputs-and-print.json)에 있다.
