# 원본 HFT 글머리표의 전진 복원

원본 `report-628-original.hwp`의110쪽 표에서 기호 슬롯 한양신명조 HFT의 U+2022가
별도 프로그램의 부분 표에 없어서 반각으로 처리됐다. 원본 글자의 미수집은 반각 계약이 아니다.
독립 Print는 bullet 뒤 본문을13.12CSSpx 전진시키지만 수정 전은6.56px였다.
그림·각주·표 높이나 페이지별 예외를 바꾸지 않고 공통 원본 HFT 폭 표에 확인된1em을 연결했다.
paint 대체 Gulim 기호의 자연 폭0.375em을 원본의 전진 폭으로 쓰지 않는다.

## 실제 검증

| 항목 | Native | fresh WASM |
| --- | ---: | ---: |
| 110쪽 수정 전·같은 최소 글꼴 조건 | 93.35921% | 93.37018% |
| 110쪽 보정 후·같은 최소 글꼴 조건 | 99.79423% | 99.79424% |
| 전195쪽 최저·같은 최소 글꼴 조건 | 94.83952% (1쪽) | 94.84611% (1쪽) |
| 별도 원본 글꼴 공급 대조군110쪽 | 99.98846% | 99.98845% |

전195쪽씩 실제 산출했으며90% 미만·쪽수 누락은 없다. 같은 입력·PDF·글꼴 조건의
stage4 이력과 비교하면 각 backend에서194쪽은 PNG 바이트가 같고110쪽만 개선됐다.
이는 최신 고정 devel의 최종 PR 전쪽 게이트를 완료했다는 뜻이 아니다.

원본 글꼴 대조군은 설치된 원본 공급에서 실제 글리프·간격을 추가 판독한 조건이다.
기존 최소 글꼴 전쪽 조건을 이 조건으로 바꾸거나 미달을 숨기지 않았다. 원본과 공급
글꼴의 hash·명령·producer는 `original-font-control.json`에 있다. 폰트 바이너리는 커밋하지 않는다.
최소 글꼴 대체의 글리프 차이와95·96쪽 등 다른 잔여를 이 전진 복원으로 해결했다고 하지 않는다.

관계 검사에서 실제 수정 전1 FAIL → 수정 후1 PASS를 확인했다. 완료110쪽의 핵심 원점을
독립 PDF의±2CSSpx로 보호하는 고정형 검사도 추가해 최종 새2 PASS다. 함수 주석에서 두 종류를
구분하며 동일 셀·문단의 소속·순서·중복 검사도 유지한다. `pixel-before-contract.json`은
같은 좌표 조건을 실제 수정 전 CLI 트리에 적용하면 좌우 모두 실패함을 별도로 보여준다.
이 기록을 수정 전 Rust 좌표 검사 실행으로 표시하지 않는다.

기존 기호 슬롯3건·원본 HFT 제곱근1건·글꼴 프로그램 소유19건도 통과했다.
추가 좌표 검사의 첫 시도는 비공개 메서드를 써서 컴파일 오류가 났고 공식 실행에서 제외했다.
기존 공개 `build_page_render_tree`를 사용한 최종2건은 실제 통과했다.
Native/WASM Clippy·fmt·suite manifest·unit tier 검사도 통과했다.
Root pkg·Studio public·새 브라우저 초기 JS/WASM 응답 해시와 실제 첫 페이지 PNG도 일치했다.
Mac locked wrapper의 로컬 no-opt 결과이며 Docker 최적화 빌드가 아니다.

`validation.json`·`producer.json`에 전체 TSV·실행·소스를 연결한다. `before-*`와 `after-*`의
같은110쪽 raw/review/overlay를 대조한다. 원본 글꼴 대조군 이미지의 `original-font-*` 접두사는
별도 조건을 나타낸다. 관측한 다른 글리프 잔여·최종 전체 회귀·보호 TSV는 계속 처리한다.
