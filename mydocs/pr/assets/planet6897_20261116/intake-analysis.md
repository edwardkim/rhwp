## CJK 전진 결측의 메인터너 보정

win10-ted의 HBATANG.TTF를 output에 복사하고 SHA를 확인했다. 설치된 Mac 파일과는 해시가 다르지만, 이를 공급해도 일반 탐침 3쪽은 89.26→89.33%에 그쳤다. 원 PDF의 실제 기호 face는 Haansoft Batang이다. PDFium의 글자 원점을 같은 줄 한글 전각 전진으로 정규화하면 U+3001·3002·3004·3005·3006·3008·3010·3024는 1em인데, 기존 렌더 트리에서는 약0.5em이다. 따라서 파일 공급만으로 남은 간격 차이는 해결되지 않았다.

기존 unicode-width 의존성으로 U+3001–303F 중 폭2인 문자만 메트릭 결측 폴백에서 전각으로 처리했다. 실제 메트릭 hit·반각 형식·폭0인 결합 부호·중립 폭 U+303F는 이 조건에 포함하지 않는다. [Unicode 17 EastAsianWidth](https://www.unicode.org/Public/17.0.0/ucd/EastAsianWidth.txt)와 독립 Print 원점 관측을 근거로 하며 문서별 예외를 추가하지 않았다. 보정 뒤 Native/fresh WASM 전쪽 검증과 독립 원점 회귀2건을 완료했다. 실제 source·전체 수치·판독은 [최종 수용 기록](final/acceptance.json)에 연결한다.

초기 최소 글꼴 focused 검사는8PASS였다. 전체 검사에서는 허용 임시 fixture 경로의 TMPDIR 설정을 빠뜨려 임시 공개 테스트 글꼴까지 차단한 환경 오류를 확인하고 중단했다. 이 초기 환경 오류를 제품 회귀로 분류하거나 검사를 완화하지 않았다. 기존 프로필을 유지하고 TMPDIR를 허용 경로로 지정해 새 소스의 전체 검사를 다시 실행했으며, 최종13,634PASS·0FAIL을 확인했다.
