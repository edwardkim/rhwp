# #7749·#7750·#7753 조판과 한컴 Print 대조

생산 코드는 `ec8515f1d8d52353f1e5092eb080ab2619de55e7`이며 devel 기준은 `2480af27df441ffd199cc24602afddbd2d13dcfe`다. Native Skia와 Chromium의 최적화 fresh WASM Canvas로 96 DPI에서 전체 쪽을 만들었다. `silhouette_raw_match_percent`는 색 경계 보정 전 2px 실루엣이다. 페이지 전체를 대조했다. 입력 및 인쇄본의 SHA·엔진·MCP 작업 기록은 [인쇄본 목록](print-references.json)에 연결한다.

## 저장 표 이어받기와 제목 소속

80550 규제영향분석서의 두 경로는 원본 바이트가 같다. 한컴 2020과 2024 Print의 14·15쪽 벡터 괘선 중심은 부모 `77.5147px`, 자식 `83.1093px`다. 부모의 위 바깥여백 `141HU`를 현재 조각의 본문 상단에 더한 값이다. 자식 원점은 같은 바깥여백과 원래 셀 안여백·자식 바깥여백을 소비한다. `stored_nested_wrapper_cut_reopens_outer_top`이 저장한 자식 컷과 부모 상자를 확인하고, 조각 예산과 `layout_partial_table`이 같은 규칙을 사용한다. 부모 선언의 첫 상자를 만들 때에는 자식 선언 높이·오프셋·여백의 합이 원본과 일치해야 한다.

마지막 조각은 닫힌 자식 표의 실제 합과 뒤 빈 줄의 원본 `vpos=56894HU`가 같은지를 검증한다. `1400HU` 빈 줄 상자와 셀 위아래 여백을 물리 높이에 포함한다. 이 높이에서 사용한 안여백을 뺀 내용 높이를 세로 정렬도 소비한다. 자식 표 안의 제목 글줄을 소비한 쪽에 그 제목을 한 번 그리며, 아직 소비하지 않은 자식 표는 다음 쪽의 소유로 유지한다. 15쪽 확대 비교에서 빈 줄은 자식 뒤에 남고 뒤 표는 기존 원점에 자리한다. 30쪽 제목과 31쪽의 후속 표도 원래 순서에 있다.

30쪽의 저장 컷은 `[28, 57)`이며 제목은 유닛 56, 다음 표는 유닛 57부터다. `stored_carried_child_host`가 아직 자식 유닛을 소비하지 않은 문단을 확인하고 `layout_partial_table`의 표 배치가 이 결정을 사용한다. 29·30·31쪽의 제목 개수는 `0, 1, 0`이고 해당 표 개수는 `0, 0, 1`이다. 이 표를 용지 바깥까지 펼쳤던 30쪽의 셀 초과 줄은 73개에서 0개로 줄었다. [30·31쪽 원본 소유와 출력 트리](carried-child-ownership.json).

한컴 2024 Print가 영문과 기호의 `한양신명조` 두 원본 슬롯에서 굴림을 선택하는 것을 독립 글꼴 표본으로 확인했다. 해당 슬롯의 글꼴을 지정하고 원본의 글자 전진을 그대로 사용했다. [Native 글꼴 환경](regulatory-2024/font-environments/native.json) · [WASM 글꼴 환경](regulatory-2024/font-environments/wasm.json).

## 바탕쪽 그림과 표의 행 소유

ParameterSet의 Portrait 바탕쪽 그림은 용지의 원래 세로 원점에서 배치한다. 첫 장의 그림과 본문에 걸치는 부분을 두 한컴 Print에서 직접 비교했다. 저장 표의 줄·개체 범위가 조각에 포함될 때 같은 컷과 물리 높이를 예산에 반영한다. 44쪽의 코드 항목과 43·45쪽의 이웃 행을 함께 대조했다. 동일 HWP에 대한 74쪽 한컴 2022 인쇄본과 새 2024 인쇄본을 모두 측정했다.

## 보고서의 그림·각주와 RGB555

24쪽은 그림 23, 캡션, 사이의 EU 본문, 그림 24, 후속 캡션 순서다. 그림 흐름 높이와 저장 뒤 빈 줄을 포함한 동일한 닫는 위치를 측정과 실제 배치가 사용한다. 66·67쪽에서 표 행과 각주 76·78의 소속을 본문과 각주 영역별로 판독했다. 91쪽의 각주 문구와 번호가 이어지는 줄, 202쪽의 저장 왼쪽 탭 위치, 고정 글머리표 너비를 원본과 비교했다.

HWPX 11쪽의 그림 5 검사에서 캡션 윗변의 절대 좌표는 두 그림과 캡션의 셀 소속·포함·순서 검사로 교체했다. 그림 높이와 셀 안여백의 저장값은 행 높이의 독립 기대값으로 사용한다. #4068의 이월 표 여백, #4882의 왕복 쪽수 등식, #5174의 묶음 빈칸 표현, #7469의 각주 내어쓰기는 각 검사에서 원본과 렌더 관계를 확인한다. 보류했던 66·67쪽은 표의 앞뒤 행, 각주 본문, 중복 방지 계약을 회귀에 연결했다.

출력 크기가 잘린 정수 원본 창의 길이와 다른 불투명 비트맵은 재표본화한 결과를 공통 RGB555 표면으로 인코딩한다. 같은 크기의 원래 창은 기존 팔레트 계약을 사용한다. 독립 Print JPEG의 크기와 품질을 고정한 통제에서 정책연구 13쪽 두 그림의 평균 절대 RGB 오차가 `0.09332`, `0.01962`였다. 보호 편람 141쪽 그림은 `0.03142`로 대조군을 유지했다. 33/32 별도 RGB 변환과 RGB555를 함께 쓴 실험에서는 편람 그림의 오차가 `4.79624`였을 때 같은 서버의 편람 페이지 raw도 떨어졌다. 최종 RGB555 경로의 편람 HWP 141쪽은 기준과 PNG 해시까지 같다.

정책연구 HWP의 보관 Print는 두 그림 원자원 전체를 PDF에 싣고 잘랐다. 새 `13.0.0.3901`의 HWP·HWPX 각각 1-up Print는 잘린 자원과 별도 마스크를 출력하며 두 형식의 주요 그림 JPEG 해시가 같다. 원본 HWP의 두 Print 사이의 13쪽 raw는 `95.42735%`다. 생산 코드의 같은 쪽은 새 Print에 `99.78621%`, 보관 Print에 `95.47301%`였다. 전체 HWP 시각 비교는 새 Print로 수행했고, 보관 인쇄본은 쪽수 근거와 버전 대조에 사용했다. HWPX 보관·새 Print 대조는 215쪽 모두 raw `100.00%`여서 HWPX 전쪽 비교에 보관본을 이용했다. 새 HWP 인쇄 작업 반환의 `input_preprocess=scripts_disabled`를 기록했다. 원본 FileHeader 플래그는 `0x1`이며, 저장 스크립트 두 스트림에서는 `OnDocument_Open` 등 호출을 찾지 못했다.

새 기준에서 HWP 175쪽의 소제목은 Print보다 약 26.6px 위에 있다. 생산 코드와 고정 devel 기준의 출력 PNG SHA-256은 `f703626daedce7eabd05882d7ba62bd566db67f89516e218940cf7a6bad8cade`로 같다. 행의 원문과 앞뒤 순서·쪽 소속은 같다.
