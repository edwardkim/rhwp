# PR #8552의 실패한 셀 주소와 글꼴 등록 순서 보정

## 재현과 계약

고정 제품 `048f44da99`의 최적화 WASM 공개 API에서 본문·셀·중첩 셀·머리말·꼬리말의
정상 fontName 적용은 성공했다. HWP/HWPX 저장 뒤 재열기도 성공했다. 그러나 존재하지 않는
평면 셀, 중첩 경로의 없는 control, 빈 경로에서는 오류를 반환한 뒤에도 새 글꼴이 7개 언어
슬롯에 남았다. 본문·없는 머리말·fontIds 충돌은 오류 뒤 문서가 유지되는 정상 대조군이다.
실제 실행과 저장본은 `fontname-public-r11/`과 `fontname-invalid-cell-r11.json`에 있다.

실패가 반환된 편집은 글꼴 목록·글자 모양·저장 패스스루 상태를 바꾸지 않아야 한다.
사양의 화면 좌표나 시각 유사도를 기대값으로 사용하는 검사가 아니다. 이 상태 API 계약에는
다른 문서의 Visual Sweep 수치를 빌려 적지 않는다. 기존 조판 게이트는 그대로 유지한다.

## 공통 호출 경로와 원인

`applyCharFormatInCell` 및 by-path → DocumentCore의 셀 서식 명령 →
`resolve_font_name_mods` → 공통 `find_or_register_font_ids` → DocInfo dirty →
그 뒤에 셀 문단 주소 확인 순서다. 글꼴 등록 이후 주소 오류가 발생해 부분 변경이 남는다.
본문과 머리말/꼬리말은 주소를 먼저 검증하므로 같은 결함이 재현되지 않았다.

셀 명령의 기존 주소 해석 결과와 원본 글자 모양 ID 수집을 글꼴·테두리 등록 앞으로 옮긴다.
같은 문단을 별도 규칙으로 추측하거나 오류 뒤 rollback으로 숨기지 않는다. 실제 대상의
검증을 통과한 뒤에만 공통 등록 helper와 기존 재조판·저장 경로를 그대로 실행한다.

## 구현·검증 범위

- 기존 API 3종의 실패 전후 문서 관계를 정식 `tests/cases/` 검사에 포함한다. 정상 셀과
  중첩 셀은 이름을 실제로 적용하는 대조군으로 검증한다. 글꼴 파일은 공급하지 않는다.
- 기존 원 PR의 fontName 등록·재사용·충돌과 셀 서식 보존 검사를 함께 실행한다.
- 최소 공개 글꼴 환경, 고정 `target/pr-review`, 빌드 잡 8개를 쓴다.
- 현재 진행 중인 R11 시각 배치는 별도 보존된 바이너리·WASM package만 소비한다.
  그 입력·producer·루트 제품 소스와 HEAD는 바꾸지 않는다. 보정은 검증 worktree에서 준비한다.
- 새 API 보정 뒤 실제 공개 WASM으로 같은 11개 호출과 HWP/HWPX 저장·재열기를 다시 실행한다.
  이전 실패를 통과로 바꾸려고 기대값을 완화하지 않는다.

## 저장 참조의 실제 대조

정상 5개 경로(본문·평면 셀·중첩 셀·머리말·꼬리말)는 HWPX 저장과 HWP 저장 후 재열기
양쪽에서 적용 대상 run의 `charPrIDRef → fontRef → 언어별 fontface`를 따라갔다. 각 대상의
7개 언어 슬롯이 모두 요청한 이름을 참조함을 확인했다. 단순히 글꼴 목록에 이름이 추가된
것만으로 적용 성공을 판정하지 않았다. 설치 글꼴의 존재나 모양을 이 계약의 통과 근거로
사용하지 않았다.

본문 주소 오류, 없는 머리말, fontIds 충돌은 문서가 바뀌지 않았다. 평면 셀 주소 오류,
잘못된 중첩 경로, 빈 경로는 오류 뒤 각각 7개의 원치 않는 이름을 남겼다. 이 상태는
제품 보정 전의 결함 재현이며 최종 통과 결과가 아니다.

## 언어 슬롯별 등록 상한

정상 주소에서도 영문 슬롯만 기존 이름 256개로 채운 합성 상태 입력을 대조했다. 기존
helper는 한글 슬롯에 이름을 먼저 넣은 뒤 영문 슬롯의 상한 오류를 반환했다. 본문 공개
API에서 오류 뒤 HANGUL 2→3, LATIN 256 유지, 다른 슬롯 2 유지로 재현했다. XML 유효성을
확인한 `fontname-slot-limit-valid-v2` 입력만 이 근거에 사용한다. 초기 진단 사본의 XML 선언·
접두사 오류를 고쳤으며 그 잘못된 사본을 정식 근거로 사용하지 않는다.

공통 find_or_register_font_ids에서 모든 슬롯의 재사용 ID·새 등록 가능 여부를 먼저 확인해
하나라도 실패하면 아무 슬롯도 변경하지 않도록 보정한다. 상한에 도달한 슬롯도 같은
이름이 이미 있으면 재사용할 수 있어야 한다는 정상 대조군을 함께 검사한다. 상태 관계
검사는 총 5개다. 이 추가 결함을 보정한 뒤 검증하기 위해 R13 WASM 빌드는 초기에 종료했고,
완료한 Native producer와 시각 산출물은 그대로 보존했다.

## 최소 글꼴 환경의 집중 회귀 결과

R11 제품과 보정한 동일 테스트를 대조한 선행 실행에서 오류 후 문서 불변 검사 두 건은
실패했고 정상 적용 검사는 통과했다. 주소 해석 순서와 언어 슬롯 사전 검사를 보정한
R15에서는 새 상태 검사 5건이 모두 통과했다. 기존 본문·셀 서식과 글꼴 세션 계약을
포함한 집중 실행은 36건 모두 통과·exit 0이다. 프로그램 설치에 의존하지 않았다.
공개 최적화 WASM 11개 상태 호출과 등록 상한의 두 경계는 새 package 완료 후 검증한다.

## 최적화 WASM 공개 API의 보정 확인

R15 최적화 WASM 빌드는 exit 0이며 실제 API 11개 상태 호출과 등록 상한의 두 경계를
모두 통과했다. 오류 6종에서는 HWPX 저장 바이트가 호출 전후 같았고, 영문 슬롯만
상한에 도달한 입력도 오류 뒤 전체 저장 바이트가 같았다. 같은 이름이 이미 있는
상한 슬롯에서는 정상 재사용을 확인했다.

정상 본문·평면 셀·중첩 셀·머리말·꼬리말 5종은 저장된 HWPX와 HWP 재열기 양쪽에서
실제 대상 run의 글자 모양→7개 언어 슬롯→요청 이름을 모두 대조해 확인했다.
정식 `api-verification-r15.json`에 package·API·저장 참조 결과를 기록했다.
이 집중 통과와 별도로 통합 전체 회귀·lint·시각 게이트는 아직 완료하지 않았다.
