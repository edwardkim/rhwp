실제 배치가 달라진다. 구현 편의 태그 bit 31이 붙은 현재 구성과 원본 저장 줄을 구분한다.

표 뒤의 글줄 높이 300 HU와 간격 180 HU를 포함한 문단 끝은 5203 HU다.
그 뒤 TAC 문단의 첫 원점은 8831 HU다. 독립 한컴 저장 진단에서도 같은 원점을 확인했다.
진단 저장본을 새 입력이나 Print 정답지로 사용하지 않는다.

## 원인과 실제 소비 경로

R6는 문서 재구성에서 원래 줄 오프셋을 보존했지만 `post-text`는 여전히 두 줄의
높이·간격만 더했다. 뒤 표 진입이 흐름을 개체 끝 4723 HU까지 옮겨도 마지막 글줄의
480 HU가 빠졌다. 그 차이가 저장 쪽 기준의 역산에도 전파됐다.

| 생산 → 소비 | R7 보정 |
| --- | --- |
| 원본 줄과 개체 띠 | `float_placement/stored_float_rows.rs`가 같은 소유 판정과 범위별 점유·전진량을 제공 |
| 문서 사다리 재구성 | 같은 판정으로 줄별 오프셋을 보존하고 개체 높이의 중복 가산을 생략 |
| pre/post-text 측정·fit·분할 | `FormattedParagraph::host_text_bounds`의 동일 점유·전진량 사용 |
| 실제 조각과 다음 원점 | `record_host_text_fragment`가 동일 끝점과 `StoredColumnFrame`을 발행 |
| 재조판한 표 뒤 빈 줄 | `composed_object_tail` 범위 → 실제 `PartialParagraph` → 같은 줄 메트릭의 fit·전진 |

원본 줄이 개체 띠와 겹치거나 편집·합성·다른 줄 메트릭인 경우에는 저장 축을 적용하지 않는다.
별도 흐름을 소유하는 다른 개체의 줄도 앵커 꼬리로 중복 예약하지 않는다.
문서 번호·특정 높이·쪽수 임계로 분기하거나 출력 좌표를 clamp하지 않는다.

R7 실제 흐름 로그에서 문단 1 끝과 다음 표의 저장 원점이 모두 5203 HU,
`same_frame=true`, 저장 쪽 기준 0으로 일치했다. 두 TAC 뒤의 보통 앵커 줄도 실제로
방출돼 흐름 끝 856.6px를 소비하고, 하단 고정 표가 2쪽으로 이동했다.

## 검증 상태와 남은 결함

Cargo는 최소 OFL 글꼴 환경, 빌드 잡 8개, 공용 `target/pr-review`를 사용했다.
포맷 검사와 Native 빌드는 종료 코드 0이며 빌드 경고는 없었다. Native 시각 측정은
설치된 전체 시스템 글꼴을 사용한다. 글꼴 프로그램을 커밋하거나 새 배포물에 넣지 않는다.

R7 Native에서 `stored-band`는 R6의 56.67%에서 100.00%,
`36493460`은 53.72%에서 99.90%로 복구됐다. `36478532`의 2쪽 최저 99.90%,
기존 각주 100.00%, 법안 요약 10쪽 최저 99.95%, 표지 4쪽 최저 99.79%,
간판 2020·2022 각각 100.00%도 유지했다.

`36474334`는 독립 PDF와 같은 2쪽 및 2쪽 raw 100.00%를 복구했지만 1쪽 raw는
46.41%다. 실제 `review`·`overlay`에서 두 번째 TAC 표가 첫 표 높이만큼 더 내려간다.
이는 흐름 소비와 별개의 paint 원점 중복 가산이며 계속 보정해야 한다. 페이지 수만 맞았다고
완료로 판정하지 않는다. 보고서 전쪽 검증과 새 base의 PR #8658 보존 검증도 진행 중이다.

새 base의 PR #8658 입력 8개·10쪽은 Native raw 100.00%이며 관련 회귀 8건도 통과했다.
전체 집중 회귀는 24건 중 23건 통과·1건 실패다. 실패한 #8679 검사는 원본 ZIP에 저장된
4723/5203 HU를 과거 DocumentCore가 평탄화한 2200/4723 HU로 잘못 가정한다.
실제 표 간격·내용 보존 검사는 유지하며 원본 전제를 바로잡아야 한다.

Native 전체 측정은 20개 입력·341쪽 중 17개 입력 통과·3개 보류다.
`36474334`의 1쪽, `report-628`의 13쪽, `report-838`의 24쪽이 90% 미만이다.
원 실행 래퍼의 종료 상태와 글꼴 변환 시각 때문에 실패한 재개 확인은
[글꼴 캐시 신원 기록](native-font-cache-identity.md)에 분리했다.

Native/fresh WASM 최종 gate·전체 회귀·lint는 아직 완료하지 않았다.
따라서 새 실물 렌더링 회귀 등록과 PR 수용 판정은 보류한다.
