# 저장된 표 띠 경계의 회귀 검사 재검토

## 원본과 독립 근거

이슈 #8679의 기존 검사는 두 번째 저장 줄이 표 띠의 위끝을 가로지르고 다음 문단은
띠 끝에 저장돼 있다고 가정한다. 그러나 최초 입력 커밋
`636ff407ac0070ff01388de8d260946bb63c834f`, 초기 통합 head와 현재 head의 ZIP 원문은
모두 두 번째 줄 `4723`, 다음 문단 `5203`이다. 다운로드한 서울시 결재문서
36385506과 fixture의 SHA-256도
`fc6d6f27cb3767ebf57a302c6052a035db055042879e4e5165c173a950fd81b6`으로 같다.
검사에 적힌 `2200/4723`은 이 입력의 저장값이 아니다.

[원본·fixture 대조](rebase-a7feb849/stored-band-original-versus-fixture.json)와
[Git 원문 대조](rebase-a7feb849/stored-band-source-history.json)를 근거로 한다.
PDF는 기존 `pdf/issue8679_stored_band_crossing_line-2020.pdf`를 그대로 사용했다.
파일명의 2020과 달리 실제 Creator는 `Hwp 2022 12.0.0.4547`이며 2쪽이다.
Print를 다시 만들거나 입력을 수정하지 않았다.

## 검증과 보정 범위

제품 `9470fb026a8cd3b3d9594db55298b6f6c347bfda`의 실제 Native Skia와 최적화 포함
fresh WASM Canvas를 같은 Print 프로필·compat 2022·96dpi·설치된 시스템 글꼴로 비교했다.
두 경로 모두 전체 2쪽, 각 쪽 raw 100.00%, 미대응 내용 픽셀 0이다.
1쪽 제목 표·후속 표 간격과 내용 순서, 2쪽 표의 행·내용 보존을 review와 overlay에서
직접 확인했다. 시각 환경과 회귀의 최소 글꼴 환경은 별도로 유지한다.

기존 실패의 잘못된 선행 assertion만 실제 원본 관계로 바꾼다. 두 번째 줄이 띠 끝에 있고
후속 문단은 그 줄 높이·줄 간격만큼 뒤에 저장된다는 관계를 검사한다. 기존 출력의
표 사이 간격·앞뒤 순서·독립 PDF 2쪽 검사는 유지한다. 이미 유효한 저장 줄을 다시
밀지 않는 대조 검사임을 함수명과 첫머리에 명시한다. 이 입력으로 잘못 저장된 줄의
정규화 분기를 검출했다고 주장하지 않는다. 원 구현의 실패 여부를 입증하려면 그 전제를
실제로 갖는 별도 독립 입력이 필요하다.

현재 제품에서 기존 검사는 잘못된 원본 전제에서 실패했다. 보정 후 실제 자동 수집 suite의
최소 글꼴 집중 실행에서 19건이 통과했다. 처음 8건은 기존 머리말 API 검사이며, prepare 후
suite 재배치로 빠졌던 11건을 실제 수집 경로에서 추가 실행했다. 후자의 11건에 이 검사의
`valid_stored_band_and_successor_spacing_are_preserved`도 포함돼 통과했다. 필터 제외
1561건·1226건은 실행한 검사로 세지 않는다. 첫 컴파일 실행의 종료 143은 결과 없는 중단이며,
재실행의 종료 코드 0·실제 terminal summary만 통과 근거로 사용한다.

2026-11-07 R11의 도형 선·머리말 보정 후에도 두 경로 1·2쪽 PNG 4개가 기존 판독 이미지와
바이트 단위로 같다. 새 제품의 실제 빌드·package 해시와 실행한 검사 이름은
[재확인 증거](stored-band-contract/r11-provenance.json)에 기록했다. 다른 문서의 실패나
전체 검증 완료를 대신하지 않는다.

증적은 `stored-band-contract/` 아래 Native/fresh WASM TSV·대표 PNG·provenance로 보존한다.
