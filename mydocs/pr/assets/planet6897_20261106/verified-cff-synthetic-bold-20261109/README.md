# 실제 CFF 공급에 따른 Print 합성 굵기 보정

sample10 251쪽 제목의 원본 `#세나루`는 유형 값 0이며, 현재 환경은 실제 보통 CFF 프로그램을
선택한다. 기존 Canvas 경로는 메트릭 DB의 합성 굵기 표시만 확인하여 이 글꼴을 `fillText`로
그렸다. Native는 실제 선택한 보통 프로그램에 fill+stroke를 적용하므로 제목이 서로 달랐다.

## 기존 구현과 독립 근거

원 결함 #8430의 구현은 현재 브랜치의 체리픽 통합 커밋
`373ec6fa58e0ebac98be6a0435c716f87fee58cf`에서 확인했다. 커밋 메시지가 기록한 원 source는
`4f8570309e925468552036f4c20d099011d55a35`다. 최초 기록 시 원 source 객체는 이 Mac에 없었다. 후속 확인에서 원 PR #8605의 head
`5d37286267136c9978d7ac2f804913730ab6becf`를 fetch하여 원 source 객체도 확보했다. 기존 Native `text_replay`와 독립 Print의
`2 Tr`·`0.02em` 계약을 보존하며 같은 상수를 Canvas에 연결했다.

유형 미상 CFF는 원본 슬롯의 환경 선택과 실제 공급 프로그램 해시가 일치할 때만 윤곽을
등록한다. 이 paint 등록으로 원본 유형이나 저장 IR·조판 전진을 바꾸지 않는다.
새 합성 굵기 경로는 Print 프로필·실제 보통 CFF·스타일별 글리프 공급자의 `needs_faux_bold`
증거를 모두 요구한다. Screen·보통 글자·실제 Bold·신원 미확인 프로그램은 기존 경로를 쓴다.

## 실제 검사

- 최소 글꼴 Native 집중 검사: **19 PASS / 0 FAIL**. 공급 신원·조회 별칭·Unicode family·
  후보 순서·한도·원본 저장 보존을 확인했다. 이후 변경은 WASM 전용 조건과 포맷뿐이다.
- 공개 합성 CFF를 사용하는 실제 Chrome 반례: 보통 윤곽 등록이 남은 상태에서 실제 Bold를
  공급했을 때 기존 후보는 잘못 fill+stroke하여 **1 FAIL**이었다. 첫 다섯 진단의 입력 구성 오류는
  이 실패 증거로 세지 않는다. 수정 뒤 실제 Bold는 `fillText`를 유지한다.
- 최종 로컬 no-opt fresh WASM의 실제 Chrome 검사: **6 PASS / 0 FAIL**.
  2020·2024 Print의 합성 굵기, 실제 Bold·Screen·보통 글자 대조군을 포함한다.
- [집중 10쪽 TSV](focus-wasm.tsv): 같은 입력·글꼴·독립 PDF·DPI·문턱으로 다시 출력했다.
  sample10 251쪽 raw **99.84315%**, 공식 **99.84%**로 보호값 **99.83%**를 넘는다.
  기존 후보 99.80627%보다 개선됐으며 다른 9쪽의 공식 값은 유지된다.
- [review](sample10-wasm-p251-review.png)·[overlay](sample10-wasm-p251-overlay.png)를 직접
  대조했다. 제목의 굵기 개선과 본문·행 소속·쪽 번호 보존을 확인했으며 미세 래스터 차이는 남는다.
  [후보 raw](sample10-wasm-p251-raw.png)·[독립 PDF raw](sample10-p251-pdf-raw.png)를 함께 보존한다.

[실행·producer·hash](validation.json)에 실제 로그와 빌드 출처를 기록했다.
이 결과는 집중 10쪽과 해당 계약 검사이며 전체 회귀·전쪽 검증 완료가 아니다.
보호값보다 낮은 sample10 509쪽 및 sample16 HWP2024·HWPX 35쪽은 계속 보정해야 한다.
비공개 글꼴·윤곽 추출 표본·로그는 ignored output에만 보관한다.

## 후속 전체 검사에서 발견한 등록 분류 누락

`c524d1e918`의 실행 파일로 검사한 13,083건은 13,082 PASS·1 FAIL·45 skip이었다.
새 분할 등록 API가 패스스루 무효화 분류표에 없어 소스 가드가 실패했다. 이 API는 문서 IR이
아닌 paint 세션만 바꾸며 위 공개 계약 검사가 저장 보존을 확인한다. 따라서 원본 스트림을
불필요하게 무효화하거나 가드를 생략하지 않고, 기존 단일 API와 같은 `SessionState`로 분류했다.
분류 보정 뒤 같은 가드 원본 5건을 실제로 다시 컴파일·실행하여 5 PASS를 확인했다.
실행 중 별도의 WMF 후보가 작업 트리에 적용됐으므로 이 전체 결과를 그 새 후보의 통과로
인용하지 않는다. 최종 안정 소스에서 전체 회귀를 다시 완료해야 한다.

추가 [공통 Print 프레임 복원](../source-print-frame-preservation-20261109/README.md)의 집중
재출력에서는 이 문서의 나머지 3쪽도 보호값 이상으로 복원했다. 전체 검증은 후속 안정 소스로
계속 진행하며, 위 소스별 결과를 그 새 소스의 전쪽 통과로 바꾸어 기록하지 않는다.
