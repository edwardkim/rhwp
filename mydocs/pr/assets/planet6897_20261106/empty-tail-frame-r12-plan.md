# 각주 앞 저장 빈 문단의 점유와 이월 계획

## 독립 관측과 현재 원인 경로

기준 제품은 `048f44da99`다. 같은 report-628 원본과 기존 한컴 2020 Print 195쪽을
유지한다. Native/fresh WASM에서 124·125쪽 본문이 각각 27.6px·19.0933px 위에 있다.
이는 앞 쪽 마지막 빈 문단의 원본 `LineSeg`가 가진 높이+줄 간격
2070 HU·1432 HU와 같다. 이 일치만으로 화면 좌표를 보정하지 않는다.

실제 source frame과 호출 경로를 함께 확인했다. Section3 내부 page 91은 PDF 123쪽이다.
본문의 현재 pen은 817.8533px, 각주 예약은 32.1px이며 빈 문단 710에서 높이가 전진하지
않은 채 다음 저장 reset이 쪽을 연다. 원본의 빈 줄은 `61339 + 1150 + 920` HU로 전진한다.
`absorb_section_tail → prepare_saved_empty_run(..., |_| None) → 조기 빈 문단 흡수`가
뒤의 `paragraph/flow → 실제 각주 영역 측정 → fit·분할·발행`보다 먼저 실행된다.
뒤 helper를 추가로 호출하는 것만으로는 조기 반환에서 사라진 점유를 복구하지 못한다.

높이와 textHeight를 함께 바꾸거나 표시 표식을 넣은 진단 사본도 후속 위치를 개선하지
못했다. 진단은 정식 원본·독립 PDF·회귀 기대값으로 사용하지 않는다. 원본 사다리의
실제 범위와 현재 쪽의 동일한 물리 원점에서 판단하고, 계산상 fit·실제 전진·reset 소비를
같은 빈 줄 소유 계약으로 연결해야 한다.

## 공통 보정 방향

1. 조기 흡수 전에 기존 `BodyFootnoteMeasure`의 실제 선택 조각 높이를 전달한다.
   원본 저장 조각·번호·각주의 소속과 내용을 다시 구성하지 않는다.
2. 원본의 연속 빈 꼬리가 현재 흐름과 같은 저장 원점이며 원래 본문 안에 있는 경우,
   실제 각주 영역을 먼저 예약하고 빈 run의 소유를 유지한다. 실제 각주 영역 안에
   들어가지 않는다는 이유로 run을 감추는 쪽으로 되돌리지 않는다.
3. 이 run은 기존의 공통 전체 전진 fit 계약을 사용한다. 마지막 잉크 높이만으로 fit한 뒤
   실제로는 줄 간격까지 전진시키거나, 분할 재시도에서 저장 하단 pin으로 다시 수용하지 않는다.
   일반 본문의 마지막 잉크 fit과 표의 기존 hard flow 계약은 보존한다.
4. 이월한 빈 prefix와 뒤 저장 reset의 기존 공통 소비 경로를 사용한다. 다음 본문·표의
   좌표를 직접 이동하거나 문서 ID·고정 px·특정 문단 번호를 구현 조건으로 넣지 않는다.

## 검증 순서와 완료 경계

코드 변경을 고정한 뒤 같은 `target/pr-review`, 빌드 잡 8개로 Native를 먼저 빌드한다.
123~125쪽의 원본·Print·review·overlay와 실제 문단 소유·순서·줄 높이·각주 상자를 대조한다.
같은 각주·TAC 경계 대조군과 정상 body/no-note 경로도 확인하고, 개선 방향이 검증되면
전 195쪽·fresh WASM·보호 PR·최종 전체 검증을 진행한다. 현재 시각 미달의 회귀를
통과시키려고 기대값을 갱신하지 않는다.

수식 관련 16·18·120·122·123쪽과 143쪽 번호 간격은 계속 별도 원인 분석 대상이다.
이 계획의 완료나 일부 쪽 개선을 27개 PR의 최종 검증 완료로 판정하지 않는다.
