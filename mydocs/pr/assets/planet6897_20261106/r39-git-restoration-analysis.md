이 기록은 실제 종료한 집중 검증의 결과다. 전체 Rust·최종 Native/fresh WASM 전쪽·보호 TSV·최종 PR 승인을 대신하지 않는다.

## 원 해결과 공통 로직 보정

- [PR #8397](https://github.com/edwardkim/rhwp/pull/8397)의 `730759eb2c3820f061cb2cf4f86215c96cedc548`은 Native Skia의 분리 OTF 프로그램 선택을 보정했다. 그 로직은 유지돼 있으며, WASM 합성 굵기의 CFF 소비 누락과 구분한다.
- [PR #8605](https://github.com/edwardkim/rhwp/pull/8605) 원 커밋 `4f8570309e925468552036f4c20d099011d55a35`와 적용 `14ae66657f`는 실제 보통 face 윤곽에 fill+stroke를 적용한다. `3f2a7c96ee1ec86128b6ca1c3a6b700aa2eaeb3b`에서 실제 등록된 CFF 프로그램을 같은 경로에 연결했다. 유효한 원 TTF 별칭과 cmap 소유가 확인된 경우의 기존 우선권은 보존했다.
- 일반 구두점은 `9b1c31ec03`·`11cc64a443`의 원래 프로그램·메트릭 계약을 따른다. `5de92ecc46`에서 한자 뒤 괄호 보정을 모든 비어 있지 않은 영문 family로 넓힌 것은 잘못이었다.
- `09ada34bf1be3a3dcb60e36f2de016e8d35cfcd9`는 일반 구두점 정책을 복원하고 HWP3를 제외한 상속 한자→ASCII 구두점만 공통 측정·run 해소에서 영문 슬롯을 선택한다. HWP3는 실제 공급한 한글 프로그램에 글리프가 없고 원 영문 프로그램에 있을 때만 전환한다.
- `d753f31aa8`은 과도한 정책에 맞췄던 HWP3 제목 검사를 원래 기대값으로 복원했다. 자연 글리프를 원문 주소로 찾는 개선은 유지했다.
- 같은 커밋에서 `issue_7379_rowbreak_table_footnote_reservation` 합성 예산 반례의 본문 비교는 원문 주소가 있는 TextRun만 재귀 수집하도록 고쳤다. 자동 목록 기호는 `char_start=None`인 별도 paint 소유다. 원 PUA U+F09F를 보존한 기호를 원문 본문과 섞어 비교하던 검사의 범위를 바로잡았다. 원 IR의 15개 문단 본문, 분할·소유·캡션·후속 내용 기대값은 유지한다.
