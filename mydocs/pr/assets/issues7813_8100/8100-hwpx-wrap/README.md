# #8100 HWPX 줄바꿈과 글꼴 슬롯 진단

## #7679의 줄바꿈과 뒤 인라인 표

원본과 `hp:t`의 형제인 `hp:lineBreak`만 제거한 입력을 각각 한컴 2024에서 출력했다.
이 표식은 글줄을 끊지 않았다. 테스트용으로 표식을 제외한 rhwp Native 출력에서는 뒤 표에
붙어 마지막 글자도 다음 줄로 이동했다. 한컴 출력의 첫 글줄은 마지막 글자까지 담고 표만
다음 줄로 보냈다.

HWPX 파서는 `hp:t` 안의 실제 줄바꿈을 처리한다. 공통 인라인 흐름은 뒤 표가 현재 줄의
남은 너비에 들어가는지 확인한다. 표 앞에서 끊을 수 있고 남은 너비가 부족한 경우, 앞 글자를
그 줄에 유지한다. 기존 HWP 저장 줄의 소유와 표 앞에서 끊을 수 없는 어절도 대조한다.

## #7695의 영문 문장부호

한컴 2024에서 동일 원본을 다시 인쇄한 결과, 기존 Print PDF와 32쪽의 실루엣이 모두
100.00% 일치했다. 초기 Native는 32쪽 중 9쪽이 90% 미만이었고 최저는 71.37%였다.

첫 쪽의 `한/글이`에서 한컴의 빗금 전진은 4.32px이었다. 폭을 넓힌 왼쪽 정렬 대조 입력에서
rhwp는 빗금에 7.4px을 사용했다. 실제 문단 폭에서 마지막 글자가 뒤 줄로 밀리며 이후 줄
경계도 달라졌다. 원본에 한글 글꼴 슬롯만 있고 영문 슬롯 0의 보완 글꼴이 존재하는
문자 모양에 공통 문장부호 슬롯 선택을 적용한다. 이 선택을 행 구성의 폭 계산과 paint가
함께 소비한다.

두 원본과 대조 입력의 조판 위치를 확인했다. 수정 후 Native와 fresh WASM의 전쪽 비교는
최신 `upstream/devel` 리베이스 뒤 실시한다. 수치가 없는 부분은 검증 완료로 판정하지 않았다.
