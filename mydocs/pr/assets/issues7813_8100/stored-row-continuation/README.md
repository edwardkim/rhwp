# 저장 표의 이어받기에서 물리 행 상자 보존

## #7831 중첩 표 앞과 이어받기 종료

39쪽 원본의 25쪽에서 마지막 내용 컷을 소비한 뒤의 빈 행 높이를 저장 선언과 앞에서 수용한
상자로 계산했다. 96dpi 진단 Native에서 25쪽 raw가 14.21%에서 100.00%로 올랐다.
22쪽에서는 새 쪽의 중첩 표 앞에 있는 호스트 줄이 앞 프레임을 닫는다. 저장 빈 줄의 시작
62,480HU에 높이와 간격을 더하면 호스트 줄의 시작 64,680HU와 일치한다. 이 커밋은 그
줄의 하단 65,780HU까지를 앞 조각의 가운데 정렬에 전달한다.

23쪽은 자식 표가 소유한 새 쪽에서 별도로 확인한다. 그 쪽 마지막 빈 줄의 저장 위치 64,462HU는
자식 표 전체 높이 63,896HU와 위아래 여백 566HU의 합이다. 자식 표가 이전 프레임의 호스트
오프셋을 다시 소비하는 위치 차이가 남아 있다.

## #7834 병합 셀이 걸친 여러 조각

조각에서 각 병합 셀이 요구한 높이를 그 셀이 실제로 끝나는 행에 예약한다. 하나의 블록
총높이를 마지막 행에 몰아 주면 앞서 끝난 다른 병합 셀의 폭과 높이 관계를 잃는다. 스캔과
배치는 같은 행 높이 결과를 소비한다. 15쪽 진단 Native의 최저 raw는 43.28%에서
56.90%로 올랐다. 4·6·8쪽에는 병합 행 경계와 뒤 내용의 위치 차이가 남아 있다.

## #8100의 반복 머리행과 저장 본문 재시작

대조 원본 `22081993`의 90쪽 말미에서 일반 셀의 내용을 모두 소비해도 선언 행 높이 중
135.8px이 남았다. 이 높이에 반복 머리행 34.59px과 양끝 여백을 더한 값은 다음 원본

문단은 최신 기준으로 리베이스한 뒤 비교한다.

진단 측정은 2026-11-28 KST에 이전 기준 `ca96e9f342`, 독립 한컴 Print PDF,
96dpi, 색상 경계 보정 전 2px 실루엣으로 했다. 이 기록의 진단 수치는 리베이스 전
일부 코드에 대한 결과다. 새 코드의 전쪽 Native·fresh WASM과 보호 문서 검증을 이어간다.
