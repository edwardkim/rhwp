# CanvasKit 문서 사전 검사 작업 상한 100,000

사용자가 요청한 50,000→100,000 조정이다. 한 쪽당 예산이 아니라 문서 전체의 누적 작업 상한이며, 글줄·경로·그림 payload 등을 낮춤·분석하는 비용을 센다. 반복 숨김 문서의 앞3쪽은 기존 한도 안에 들지만 네 번째 쪽의 그림을 낮추기 전에 예산이 소진됐다. 글꼴이 없어서 생긴 오류로 판정하지 않았다.

[실물 측정](validation.json)에서 전체5쪽의 작업량은77,079다. 100,000 상한으로 네 가지 mode/profile 모두 complete·eligible이며, 실제 Studio compat/default 화면·인쇄4건도 CanvasKit으로 실행됐다. Canvas2D 대조2건을 함께 확인했다. 인쇄 CanvasKit 두 결과는 같은 독립 한컴 Print PNG 대비 기존2px raw100.00%이고 본문·그림·차트·아래 로고와 쪽 번호를 직접 판독했다. 이전50,000 측정과 실패한 strict report는 이전 source의 기록으로 보존하며 새 지원 결과와 혼동하지 않는다.

새 합성 회귀는7만5천 작업이 완료되는 경우와 누적10만을 넘는 후속 쪽에서 중단하는 경우를 검사한다. 두 건 모두 최소 글꼴 환경에서 통과했다. 기존 WASM API의 공개 상한 assertion도100,000으로 갱신했다. 새 검사는 tests/cases에만 추가했다. 128쪽·폰트256개·payload·깊이 한도와 중단 동작을 유지한다. 특정 문서명이나 페이지로 예외를 두지 않았다.

Node의 실제 사전 검사 시간은 새 상한에서 약0.06~0.45초였다. 동일4조합 측정 절차의 프로세스 최대RSS는 약498→689MiB다. 새 실행은 전체5쪽을 완료하고 이전 실행은3쪽에서 중단하므로 동일 작업량의 속도 비교로 해석하지 않는다. 모듈 로드와 생성자를 제외한 API 시간이며, RSS는 프로세스 전체 최대치다. 브라우저 전체 메모리를 측정한 값으로 표시하지 않는다. 전체 통합 회귀·보호 문서 검증은 별도 완료 후 PR에 반영한다.
