# 선행 공백 문단의 종료 글자 높이

PR #9064 입력의 1쪽 표 가로선 세 곳이 독립 한컴 Print보다 위에 놓인 원인은 선행 공백 문단의 줄 높이였다. 문단 0은 구역·단 정의와 공백·탭을 포함하며, 첫 run의 크기는 1100HU이고 마지막 빈 run의 크기는 1200HU다. 원본 XML의 종료 CharShapeRef는 원문 UTF-16 위치 55에 남아 있다. 원 PR의 직접 판독에도 전체가 약 1~2px 위에 있다는 차이가 기록돼 있어 그 공백 문단부터 추적했다. 실제 선택된 글꼴의 모양이 아니라 종료 글자 크기가 줄 메트릭에서 빠지는 것이 이번 잔여 위치 차이의 원인이었다.

같은 입력을 독립 한컴 2020 11.0.0.9136에서 재저장한 HWP를 rhwp 모델 없이 원시 CFB/레코드로 읽었다. 첫 줄의 높이·글자 높이는 1200HU, 기준선은 1020HU, 간격은 360HU다. 조판 프레임도 이 메트릭을 올바르게 발행했지만, `neutral_anchor_metrics`가 첫 공백 run의 크기로 다시 계산해 줄 높이·간격을 1100·330HU로 낮췄다. 전진량 차이는 130HU, 96DPI에서 1.7333px다. 뒤 제목과 표 전체가 이만큼 위로 당겨져 일부 가로선의 래스터 차이가 2px 관용을 넘었다.

기존 최초 글자 모양 선택은 `08cef43d24b`의 빈 부동 호스트 공통 메트릭에서 들어왔고, `5f6b3ac7bf`는 별도 NoLS 표 호스트의 공통 줄 결과를 보존했다. 이번에는 그 경로의 수용 조건을 넓히지 않고 종료 글자의 높이 참여만 보완한다.

공통 빈 호스트 줄 메트릭이 문단 종료 글자 크기도 포함하도록 고쳤다. 측정·페이지 예산·배치가 같은 함수를 소비하며, 문서 이름·문단 번호·세 개 가로선의 좌표로 분기하지 않는다. 원본 입력·기준 PDF·2px 관용·90% gate는 바꾸지 않았다. 실제 저장 줄과 HWP3 제한 등 기존 수용 조건도 유지한다.

새 관계 검사는 첫 공백 줄이 원본 종료 글자 크기를 포함하는지 확인한다. 수정 전 4통과·1실패에서 수정 후 5통과이며, 기존 2쪽수·제목/표 순서·2쪽 끝 글줄 검사도 함께 통과했다. [독립 원시 줄 근거](source-line-height.json)와 [검사 결과](regression.json)를 보존한다. 최종 코드 `836615963e`의 Native 재출력은 1쪽 raw 98.76%→100.00%, 2쪽 100.00% 유지다. 색상 경계 보정 픽셀은 0이며 기존 2px 관용 raw 판정이다. [TSV](native/silhouette.tsv)·[검증 출처](native-validation.json)·[1쪽 review](native/review-001.png)·[1쪽 overlay](native/overlay-001.png)를 확인했다. fresh WASM도 같은 코드에서 새로 빌드해 전2쪽 raw100.00%, raw 미일치·색상 경계 보정 각각0픽셀을 확인했다.
