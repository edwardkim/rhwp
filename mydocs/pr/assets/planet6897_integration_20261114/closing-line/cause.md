# 표 이어받기 뒤 끝 문단 간격 원인

- 지적한 입력은 PR #9064의 `ws-host-tac-above-offset-float.hwpx`다. Native와 fresh WASM 2쪽 잔여 raw 불일치167픽셀이 모두 「끝.」에 있고, 글리프는 같으나 ink 위끝이 Print1014px 대비1022px다.
- 기존 공통 계약은 `1f9554efe102be39f6d29ffe97ca595de9d2109a`와 `a69e43d7f25584ad9ad3f9ff7276cdc60e4dbf80`에서 추적했다. 조각 뒤 앞 간격은 무조건 0이 아니라 `max(단 원점 + 앞 간격, 조각 하단)`이며 큰 앞 간격200/700px의 독립 Print 대조군도 있다.
- 같은 원본의 독립 한컴2020 11.0.0.9136 재저장 HWP를 원시 CFB/레코드로 읽었다. 빈 문단3 vpos68224, 끝 문단4 vpos70404HU이며 본문 상단5668HU를 더하면 끝 줄 위끝1014.2933px다. 두 문단 간 전진2180HU는 현재 모델과 같고, 첫 빈 문단 앞 간격500HU가 추가되는 것이 실제 차이다.
- 원본 host는 공백2개·저장 줄 없음·양수 오프셋6198HU인 문단 기준 자리차지 표1개와 TAC 제목 표1개다. 이어받기 끝에서 원래 host의 공백/TAC 줄을 다시 열지 않고 기존 계산 빈 host의 단 원점 계약을 함께 소비해야 한다.
- 첫 연결 후보는 내부 `para_has_non_whitespace_text`가 공백 host를 재조판 텍스트로 분류한다는 사실을 놓쳐 적용되지 않았다. 최소 글꼴 실제 검사3PASS/1FAIL을 보존했으며 완성 근거로 쓰지 않는다. 임시 진단에서 projection=false·공백2개·합성 태그를 확인한 뒤 진단 출력을 제거했다. 글자 유무는 원문 문자만 검사하도록 바로잡았다.
- 구현은 문서명·문단 번호·8px 보정값을 사용하지 않는다. 기존 간격 producer와 현재 단 확정 원장을 공유하여 fit/전진/paint가 같은 값을 소비한다. 가시 본문·실제 저장 줄·둘 이상의 흐름 개체·음수 오프셋은 기존 경로다.
- 현재 재검증 완료 여부는 `after-test-result.json` 및 `../combined-final/state.json`을 확인한다. Native/fresh WASM 실제 출력 전에는 100%로 표시하지 않는다.
