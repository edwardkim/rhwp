# 여러 문단의 그림 셀: 공개 합성 재현 자료

저장 줄 정보가 없는 한 셀에 그림을 문단별로 넣은 수동 생성 문서다. 앞선 공개 합성 자료의 번호 그림만 재사용하고, 회사 문서의 본문·사진·파일명·원시 스트림은 포함하지 않는다. 입력 10개의 내장 PNG 40개를 번호 그림 원본 SHA-256과 대조했고 작성자·제목·회사 메타데이터가 비어 있음을 확인했다.

## 독립 기준과 코드

- 기준: [한컴 공식 WebHwp 데모](https://webhwpctrl-example.cloud.hancom.com/webhwp-example), `10.80.0.2862`, 2026-10-08 캡처.
- 수정 전: #7675와 당시 최신 devel `f0e7228f6`을 합친 `29426712e878389a14dbdf1af27ce07f83488c30`.
- 수정 후 코드: `aafa8bde01f200bfce81fba4463687831f8a7aed`.
- Native 바이너리 SHA-256: `0b0c1197f6a6dba96ab28b7a2a31ac446dd8da80ac8337f74ac89dd8e85464dc`.
- fresh WASM SHA-256: `19423ed87a4ae466c527f73384f26bdf23af5b53797730ec5e85048faf218cec` (`--dev --no-opt` 진단 빌드).
- `hancom-canvas-*.png`는 같은 입력의 독립 캔버스다. `*-before.png`, `*-after.png`, `*-wasm.png`는 RHWP의 전후 출력이다.

## 측정

| 입력 | 확인한 조건 | 수정 전 최대 그림 경계 차이 | 수정 후 |
| --- | --- | --- | --- |
| two-paras.hwp | 두 문단·그림 두 장이 꼭 맞는 셀 | 50px, 둘째 그림 잘림 | 1px |
| top.hwp | 위 정렬 정상 대조군 | 1px | 1px |
| center.hwp | 큰 셀의 가운데 정렬 | 50px | 1px |
| bottom.hwp | 큰 셀의 아래 정렬 | 100px, 둘째 그림 누락 | 1px |
| three-paras.hwp | 세 문단 | 100px, 셋째 그림 잘림 | 1px |
| para-spacing.hwp | 문단 앞뒤 간격 | 53px | 1px |
| unequal.hwp | 서로 다른 그림 높이 | 34px | 1px |
| compact.hwp | 80% 줄간격 | 45px | 1px |
| wrapped.hwp | 둘째 문단 안의 너비 부족 줄바꿈 | 162px | 1px |
| right.hwp | 오른쪽 정렬 | 50px | 1px |

10건 모두 Native/fresh WASM의 그림 데이터·좌표·쪽수가 같고, 모든 그림이 한 번씩 출력됐다. 뒤 문단의 위·아래 경계는 한컴 대비 최대 1px 차이이며 그림 아래에 있다. 전체 PNG는 글리프 차이가 있어 동일하지 않다. 이전 단일 문단 합성 12건도 최대 1px 차이를 유지했다.

추가 로컬 대조로 단일 문단의 앞 간격도 확인했다. 한컴 대비 그림 경계 차이가 2→1px로 줄어, 문단 간격 합산이 기존 단일 문단에 적용되는 경계도 확인했다.

데모에서 `GetTextFile`로 다시 받은 HWP 10건에는 여전히 `PARA_LINE_SEG` 레코드가 없다. PNG가 RGB에서 RGBA로 다시 인코딩되므로, 재열기 대조는 압축 바이트 대신 복원 RGBA 픽셀과 전체 SVG 배치·텍스트를 비교했다. 10건 모두 원래 입력과 같다. 이를 저장 LineSeg 경로의 검증이라고 부르지 않는다.

## 범위와 남은 검증

공통 문단 프레임은 기존 줄 나눔의 높이·간격을 소비하고, 셀 프레임이 문단별 원점·그림 소속을 합친다. 행 높이 측정, 세로 정렬, paint가 이 결과를 공유한다. 유효 저장 줄, 행 병합, 세로쓰기, 텍스트 혼합, 지원하지 않는 부동 그림 앵커는 이 경로의 대상이 아니다. 분할·이어받기 동작은 이번 10종으로 입증하지 않는다.

이 자료는 **WebHwp 화면이며 한컴 Print PDF가 아니다**. 독립 Print PDF Visual Sweep과 그 근거를 갖춘 새 정식 회귀 검사는 남아 있다. 이전 안내 후 사용자가 요청한 개선 시리즈의 WIP Draft 증적이며, 시각 게이트 통과·병합 준비 완료·회사 문서 전체 정상 출력을 주장하지 않는다.

회사 HWP 4,389개 중 해당 조건 후보는 5개 문서/5개 셀이었다. 3개 문서의 출력이 바뀌었고 5개 모두 쪽수·이미지 데이터별 개수를 유지했다. 1px 초과 그림 신호는 15→12개이며 최대 476.7px의 다른 잔여 신호는 그대로다. 원인 사례의 해당 셀은 47.8→0px, 다른 그림을 포함한 그 문서의 최대값은 47.8→3.4px다. 이는 bbox 진단이며 회사 원본의 한컴 일치 판정이 아니다. 회사 원본과 개별 식별 목록은 공개하지 않는다.
