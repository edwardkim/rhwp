## 원 주장과 최신 devel 재현

행 내용이 모두 소비됐고 이어받을 물리 공간도 없는 마지막 조각에서
`advance_column_or_new_page()`를 먼저 호출해 항목 없는 쪽이 남는 문제다.
최신 devel에서도 공개 재현물의 쪽수는 `2 / 3 / 3`이고 후보는 독립 기준의 `1 / 2 / 3`이다.
기준은 각 공개 합성 입력을 실제 웹한글기안기로 연 Print PDF이며 데스크톱 한컴 출력과
구분한다. 작성자의 비공개 실문서 코퍼스 결과는 참고 보고이며 메인테이너의 독립 실행으로
계상하지 않는다.

공개 경계는 같은 표·빈 문단에서 앞 표 뒤 잔여만 다른 두 입력이다. 글줄이 들어가는 경우의
불필요한 쪽은 제거하고, 글줄 자리가 없어 표와 함께 밀린 경우의 의도된 빈 쪽은 유지한다.
다른 분할·빈 띠·병합 칸·후속 본문 경계는 아래 최신 base 기능 보존과 보호 문서로 확인한다.
원본에 저장 줄이 없는 합성 입력이라는 사실을 명시하며 저장 LineSeg 수용 조건은 변경하지 않는다.

## 메인테이너 보완

원 기여의 종료·host 글줄 판정은 보존했다. 기존 회귀 3개에는 실제 모든 행 라벨과 두 표의
단일 소유·내용 순서·중복 방지를 보완했다. 쪽수는 독립 Print의 `1 / 2 / 3`을 유지한다.

작업지시자가 과거 보호 미재현 911행도 예외 없이 해결하도록 결정해, 실제 글꼴 공급의
256개 적재 상한·선택 메타데이터를 대조했다. 문서에 필요한 원 프로그램과 기존 명시 환경을 복원하고,
공통 원 PUA 지원 목록의 U+F02FB 누락, 구형 수식의 준비 도구 가족 이름 불일치, Native WMF에
사용자 snapshot이 전달되지 않는 세 지점을 보정했다. 글자 위치·폭·윤곽을 수치로 맞추지 않는다.

독립 문자 표본의 실제 한컴 Print로 `×`·`÷` 원 프로그램을 확인했고 준비 도구의 선택 옵션을 추가했다.
제공된 `HYHWPEQ.TTF`는 실제 공급하면서 구형 프로그램과의 전진 차이를 구분했다.
[원인·독립 hash·공급 환경](assets/pr8896/font-supply/README.md)을 따른다.
이 준비 폰트·비공개 원 프로그램은 저장소와 배포물에 넣지 않았다.

새 회귀는 원 PUA 등록·해제, 실제 구형 분수의 family 연결, WMF의 수동 등록 대조·미공급 음성 대조·
자동 공급·중복 억제·저장 원본 보존을 검사한다. 최소 글꼴 환경과 저장소 소유 MIT 합성 fixture를
사용하며 source-side unit test 수를 늘리지 않고 기존 integration suite로 자동 수집한다.
[현재 문서의 기존 검사 점검](assets/pr8896/regression-audit.md)에서 관계 검사·유효한 완료 쪽 좌표를
보존했다. 교체한 기존 px 핀·golden·baseline·허용치 변경은 없다.

## 2026-11-12 재개 시 원격 갱신

중단 직전의 모든 게이트는 source `3fdde2a216…`와 base `4c876654d8…`에서 완료했다.
재개 시 devel은 `eb84afc0364c51031bb07cbbb013476293367990`으로 갱신돼 있었다.

네 source 파일은 새 devel에서 변경되지 않았지만 표·각주·글꼴 환경의 소비 경로는 바뀌었다.

끝나기 전 이를 새 source의 완료로 계상하지 않는다. 원 PR head는 그대로이며 원격 쓰기는 수행하지 않았다.
