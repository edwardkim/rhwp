## 목표·범위

제목·본문 표 공동 앵커 개선을 수용할 수 있도록, 확인한 비본문 제어 경계와 부족한 검증을 한 단위로 보완한다.
다른 문서의 기존 조판 차이까지 수정 범위를 확장하지 않는다.

1. 공통 `stored_inline_host_has_separate_float_frame`의 Header/Footer 분류를
   `prepare_coanchored_first_line`과 일치시킨다. [한 파일 보정 초안](assets/pr9042/proposed-header-footer.patch)은
   승인 후 적용했다. Native 선행 검증에서 빈 머리말·꼬리말을 포함한 5종 모두 독립 PDF와 같은 2쪽이다.
   최종 fresh WASM·전체 검증은 계속한다. 문서 ID·특정 높이·px 보정은 추가하지 않는다.
2. 원 사례, 무변경 저장, 빈 머리말·꼬리말, 한컴 재저장 대조군에서 제목·본문·다음 표의 쪽 소속,
   순서·겹침·내용 보존을 실제 Native/fresh WASM과 저장·재열기로 확인한다.
3. 중첩 TAC tail 변경은 원 기여를 보존하며 실제 발동 입력·독립 한컴 Print와 비적용 대조군을 보강한다.
   기존 #8187 마지막 행 계약과 #8682 보호를 추적하고, 시작/끝 컷·요구 높이·예약·fit 실패 시 이월·배치를
   실제 관련 경로에서 확인한다. 자료 미확보를 완료로 처리하거나 임의로 기능을 제거하지 않는다.
   실제 한컴 저장본에서 내용과 칸·자식 상자 높이가 정확히 같아야 한다는 기존 가정의 오류를 확인했다.
   칸의 최소 선언과 실제 상자를 구분하고, 여백·저장 줄 폭·되감기 없는 문단 사다리의 포함 관계로 보완했다.
   한 문단·바깥 여백·두 문단의 실제 저장본 전 6쪽 Native가 모두 100.00%다.
   [입력·독립 Print·수정 전후 TSV](assets/pr9042/native-nested-validation/README.md)를 보존했다.
4. 검증한 경계는 정식 suite의 관계형 회귀에 반영한다. 기존 원 사례 검사의 유효한 내용 보호는 유지하고,
   신규 파일 첫머리는 최종 양쪽 전쪽 측정 뒤 실제 수치·시각·증거로 보완한다.

## 독립 근거·소비 지점

빈 머리말·꼬리말·무변경 직렬화의 Windows 한컴 Print는 모두 2쪽이고 두 쪽 RGB도 같다.
반면 후보 Native는 Header 또는 Footer가 있으면 3쪽이다.
공통 host 판정의 비본문 제어 수용 결과가 `from_stored_inline_host`의 frame 생성 여부를 바꾸며,
새 whole-fit 경로가 그 frame을 `record_paragraph_float_placement`와 `place_table_with_text`에 전달한다.
보정 후에도 후속 원점 선택·상한 적용과 실제 paint가 같은 결과를 소비하는지 추적한다.

## 완료 조건

- 모든 대상의 독립 PDF 쪽수와 Native/fresh 최적화 WASM 쪽수가 같고 전쪽 raw가 90% 이상이어야 한다.
  표 경계·마지막 내용·후속 표와 미세 차이는 직접 확대 판독한다. 부분 TSV를 전쪽 증거로 대신하지 않는다.
- 실제 발동·비적용 경계와 정상 대조군을 먼저 검증한 뒤 최종 제품 head의 전체 회귀,
  최소 글꼴 환경 검사·Native 공식 검사·필수 lint/build·편람 383쪽 gate·정본 보호 TSV의 하락 금지를 완료한다.
- 원 head와 latest upstream/devel을 재확인한다. 새 base를 반영하면 새 PR 기능 보존도 실제 검증한다.
- 실제 수치·최종 검토·첫 기여 댓글 초안을 로컬에 준비한 뒤 원격 제출·CI·merge 범위를 별도 승인받는다.
  이번 보완 담당 승인에는 remote push·공개 댓글·merge를 포함하지 않는다.

기여자 보완 경로를 선택하면 발견 사실과 재현 자료를 정리해 공개 문안·증거 게시 경로를 검토받는다.
담당 선택만으로 댓글이나 fork branch 변경을 실행하지 않는다.
