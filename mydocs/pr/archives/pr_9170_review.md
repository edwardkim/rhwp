# PR #9170 Studio 첫 렌더와 문서 교체 실패 재검토

## 최종 판정

**승인.** [PR #9170](https://github.com/edwardkim/rhwp/pull/9170)의 코드 커밋 `80295cb7e4089d8733445bb64630febdc0e79122`에서 P2를 수정했고 [코드 CI](https://github.com/edwardkim/rhwp/actions/runs/44227753996)와 [Canvas 비교](https://github.com/edwardkim/rhwp/actions/runs/44227753986)가 통과했다. 기준 devel은 `1695089d21fb5ff116eeba263e4935f04b4ac494`이다.

## 재현과 재검증

- 합성 HWP A의 첫 초기화를 보류한 사이 손상된 B를 열었다. 수정 전에는 A의 입력기가 비활성이었다. 수정 후에는 B의 오류 표시가 유지됐고 A의 내용이 보존됐다. 키보드로 입력한 `recovered-input`을 문서 모델에서 확인했다.
- 복구 도중 C를 열면 C가 활성 문서로 남았다. 코드에서 WASM 문서 세대와 중단 신호를 대조했고, 복구 경로가 상태 표시줄을 갱신하지 않고 공통 초기화로 도구 모음과 캐럿까지 연결하는 것을 확인했다.
- 빠른 교체·재열기·글꼴 준비 실패를 포함한 브라우저 회귀와 #9165 호스트 글꼴 경로를 통과했다. Firefox 배포용 확장이 31,744바이트 합성 HWP 다운로드를 감지해 Studio를 열었으며, 완료 시점과 2초 뒤 모두 첫 페이지 캔버스가 유지됐다. 완료 시점의 본문 잉크는 23,659픽셀이었다.
- TypeScript 검사, Studio 단위 검사 2,808건, E2E 목록 196건의 등록 검사를 통과했다. 회귀 코드는 [브라우저 테스트](../../../rhwp-studio/e2e/initial-page-render-issue9164.test.mjs)에 있다.
- 조판 원칙 검토 결과, 변경 범위는 첫 페이지 표시와 편집기 초기화의 실행 순서다. 문서 포맷 해석, 줄 배치, 좌표 계산에는 변경이 없다.
