## 축별 검토

### (a) 가드 등재 + 현상 동결 — 타당

- `scanFiles()` 에 `src/hwpctl` 추가 + `MUTATION_RECEIVERS = [wasm, wasmDoc, doc]`.
  **두 겹을 각각 다른 테스트가 못박은 것**이 좋다 — 한 겹만 고치면 스캔해도 0 으로
  보이는 것이 #3648 의 실패 양상이었다.
- BASELINE `src/hwpctl/**` 7키 합계 **23 — 검토자 재계산 일치**.
- `FROZEN_BY_POLICY` 로 이관 권고(`↓`)에서 제외한 판단이 정확하다. 동결된 현상에
  "줄이라"는 안내를 내면 의미가 반대로 전달된다.
- **미등재 수신자 트립와이어**가 이 PR 의 최대 가치다. 이름 기반 판정의 불완전함을
  없앨 수는 없으니 **빠뜨렸을 때 실패하게** 만들었다 — #3648 재발의 구조적 차단.

### (b) 명시적 미지원 응답 — 판정(b-2)과 정합

- `ActionDef.unsupported?: {code, message, reference}` — 사유가 실행 함수가 아니라
  **정의**에 붙는 설계가 옳다. 새 병렬 기제 없이 디스패처의 기존 상태 옆에 세 번째를
  뒀다.
- `Run`(action.ts:99)·`Execute`(:109)·`GetActionSupport`(index.ts:162) 모두 executor
  분기보다 **먼저** 판정 — 검토자 코드 확인 + 변이 재현으로 이중 확인.
- `GetActionSupport` 가 **미등록(`null`)** 을 분리한 것이 요점이다. 판정 코멘트에서
  지적한 "오타와 의도적 미지원이 구분되지 않는다"를 정확히 해소한다.
- `Undo`/`Redo` 등록 유지 + `'미구현 (향후 Phase 4에서 구현)'` 스텁 제거 — 그 메시지는
  사실이 아니었으므로(미지원이지 구현 대기가 아님) 제거가 맞다.

### (c) 층위 계약 문서화 — 위치 선택 타당

`mydocs/tech/edit_action_undo_redo_architecture.md` 를 고른 근거가 설득력 있다:
**원칙 1("문서 mutation 은 라우터를 통과한다")이 층위 없이 서술돼 결함의 원인을
담고 있었다.** 계약을 다른 문서에 적으면 원칙 1은 그대로 남아 같은 오인을 재생산한다.
원칙 1 자체에 적용 층위를 명시하고 예외에 hwpctl 을 추가한 것이 근본 처방이다.
