## 관련 이슈와 정적 검토

[이슈 #6769](https://github.com/edwardkim/rhwp/issues/6769)의 핵심은 mm 두 자리 표시값을
HWPUNIT으로 되돌리는 과정에서 생기는 손실을 사용자 편집으로 오인하지 않는 것이다.
이슈의 `samples/group-box.hwp` 가로선은 가로 오프셋 `8554`가 `30.18 mm`로 표시되고,
그 표시값을 역변환하면 `8555`가 된다. 원래 값의 변경은 도형 변환 지문과 원본 데이터 보존에 영향을 준다.

- `picture-props-dialog.ts`의 위치 입력 표시와 `picture-props-apply-model.ts`의 변경 판정이 같은 `displayedMm()`을 사용한다.
- `untouchedMm()`은 입력을 표시 정밀도로 정규화해 비교한다. 표시값이 같으면 원래 HWPUNIT을 패치에 넣지 않고 보존한다.
- 실제로 바뀐 위치 값은 `mmToHwp()`로 변환한다. 크기의 `Math.max(0, ...)`를 위치 오프셋에 복사하지 않았다.
- 공통 위치 패치는 도형뿐 아니라 그림 경로에도 전달된다. 현재 셀 그림 엔진은 위치 키의 존재 또는 `restrictInPage` 활성화에 따라 좌표 제한을 적용하므로, 미변경 키 생략과 실제 위치 변경을 함께 검증해야 한다.
- `treatAsChar`이면 공통 위치 처리에서 일찍 반환하는 기존 계약은 유지된다. 인라인 그림의 위치 정규화까지 해결했다고 주장하지 않는다.
- 이슈가 명시한 음수 오프셋의 unsigned getter 표시 문제는 별도 잔여 범위다. 이번 PR의 음수 클램프 미적용과 표시 문제 해결은 구분한다.
- 체리픽 텍스트 충돌은 없었다. 추가 경계값 검사에서 발견한 음의 0 결함은 아래와 같이 메인터너 보정했다.

## 메인터너 보정 완료

- 원 코드에서 `-1 HWPUNIT`의 표시값은 `-0.00`이지만 입력값을 다시 읽으면 `0.00`으로 정규화됐다. 문자열 비교가 이를 변경으로 판정해 무변경 확인에서도 `0`을 전송했다. 별도 경계값 검사에서 `image unchanged horizontal -1` 실패로 재현했다.
- `untouchedMm()`의 두 자리 표시 정밀도는 그대로 유지하고, 양쪽 반올림 표시값을 숫자로 비교해 음의 0과 양의 0을 동일하게 취급하도록 보정했다. 실제 음수 편집에 0 클램프를 추가하지 않았다.
- 그림·도형·선·그룹·OLE 각각에 음의 0 보존과 실제 음수 편집 회귀를 추가했다. 신규 회귀는 10개다.
- 보정 후 5종 개체 × 8개 오프셋의 40개 시나리오·160개 assertion이 모두 통과했다. 실제 셀 그림에 `-1 / -1`을 설정한 경계값에서도 속성창 `-0.00 / -0.00` 무변경 확인 후 `-1 / -1`이 유지됐다.
- 보정 대상은 `picture-props-apply-model.ts`와 `picture-props-apply-model.test.ts` 두 파일이다. 코드 SHA를 만들어 낸 것으로 기록하지 않으며, 현재 diff SHA-256은 `e00d6c035ce675020915a2c00a089e86792ba70a6a668d0c46589132ff74fd67`이다.

## 완료한 검증과 한계

1. 보정 후 `npm test`는 1,424 통과·1 건너뜀·실패 0이었다. TypeScript 검사, 최적화 WASM 빌드와 `npm run build`도 통과했다.
2. `samples/group-box.hwp`의 `s0p2c0` 가로선에서 실제 설정 버튼을 눌렀다. 위치 `8554 / 16620`, 너비 `17716`, 높이 `1`을 보존했고 전송 패치에 위치 키가 없었다.
3. 같은 선의 가로 입력을 `40.00 mm`로 변경하자 가로 `11339`가 적용되고 세로 `16620`은 유지됐다.
4. 원본, 최초 export, 무변경 확인 export 및 동일 좌표 재적용 대조군에서 대상 선의 SHAPE_COMPONENT 239바이트가 동일했다. 무변경 확인 파일 전체 8,704바이트는 동일 좌표 재적용 대조군과도 일치했다. 원본과 전체 파일이 바이트 동일하다는 주장은 하지 않는다.
5. 실제 셀 그림 `s0p31`, 경로 `[(0,0,0)]`, control `0`은 무변경 확인 후 `97 / -365`를 보존했다. 가로 `-1.00 mm` 편집은 패치에 `-283`을 전달하고 엔진 제한으로 `0`에 놓였으며, 미변경 세로 `-365`는 유지됐다. 영역 제한을 껐다 켜자 세로도 `0`으로 제한됐다.
6. 실제 셀 그림 경계값 주입 `-1 / -1`에서 보정 효과를 확인했다. 대표 속성창 PNG를 직접 열어 확인했고, 화면으로 알 수 없는 좌표·패치·저장 결과는 별도로 측정했다.

자세한 값과 직접 이미지는 [공통 시각 검증 기록](pr_6739_6770_visual_sweep.md)에 있다.
Rust 변경이 없어 전체 Rust 회귀와 새 기준 PDF 변환은 생략했다. 기존 그림 자르기 값의 표시 왕복이나
도형 getter의 unsigned 표시는 별도 범위다. 특히 다른 셀 그림에서 자르기 값 `1133→1134`, `1700→1701`의
기존 왕복을 관측했으므로 모든 속성이 무변경이라는 주장으로 확대하지 않는다.
