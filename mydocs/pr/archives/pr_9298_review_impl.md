원 PR의 최종 커밋은 `a5884818331908d5d6085aac3f9ca3430f27a098`, 대조할 devel은 `8a26c00869e5a15cc11efa715b3687b600a61c0b`이다. 두 이력을 로컬에서 병합했다.

규제영향분석서 37쪽의 표와 본문 배치는 10월에 #7778로 등록됐다. 11월 14일 #9007에서 같은 HWP를 한컴 2022 Print와 비교했을 때 이미 12·14·15·16·20·25·28·37쪽이 Native와 WASM에서 90% 미만이었다. 최저는 각각 38.340558%와 38.336022%였다. #9298은 11월 22일 등록됐다. 이번에는 최신 devel과 후보에서 사진이 들어 있는 8쪽 및 나머지 36쪽의 실제 출력을 대조한다. [#9007의 전쪽 검토](pr_9007_review.md) · [기존 이슈 #7778](https://github.com/edwardkim/rhwp/issues/7778)

## 사진 방향의 재현과 보완

공개 표본의 JPEG는 1321×2137화소이고 EXIF 방향은 6이다. 한컴은 인코딩된 세로 사진을 사용한다. Chromium 156에서 원 PR의 함수를 거친 사진은 1321×2137로 열렸다. 같은 사진의 APP1 앞에 JPEG에서 허용하는 채움 바이트 한 개를 넣으면 원 PR이 방향을 고치지 못했고 브라우저는 2137×1321로 열었다. 두 입력의 압축된 영상 데이터와 방향 값은 같다. 기존 JPEG 프레임 판독기는 이 마커 표기를 지원한다.

1. JPEG 헤더 마커를 읽는 기존 경로를 EXIF 검색과 공유한다. 이미지 저장에 쓰이는 원본은 보존하고 브라우저에 넘길 사본에서 유효한 TIFF 방향 값만 1로 바꾼다.
2. 양쪽 바이트 순서, 방향이 이미 1인 JPEG, 다른 APP1, 채움 바이트를 검사한다. 같은 원본 사진을 넣은 한 쪽 문서에서 실제 브라우저의 Canvas와 SVG를 확인하고, HWP·HWPX를 반복 저장한 뒤 사진 바이트를 비교한다.
3. 한컴에서 직접 인쇄한 한 쪽 사진 대조군과 37쪽 원본을 Native·fresh WASM으로 확인한다. 변경한 그림의 방향은 컬러 비교로 판독한다. 전체 회귀·Native 공식 검사·lint·정본 보호 결과를 최종 후보에 연결한다.

## Studio 화면의 이미지 경로

같은 사진을 담은 한 쪽 문서에서 최신 devel의 Chromium 156은 화면 SVG, 그림 키 조회, inline 레이어 모두 2137×1321로 디코딩했다. 인쇄 SVG는 1321×2137이었다. 원 기여는 SVG와 WebCanvas의 JPEG 처리를 고쳤으나, Studio가 그림 키에서 읽는 렌더링 바이트와 inline 레이어에 싣는 JPEG는 기존 경로를 사용했다. 두 API가 공유하는 `emitted_image_bytes`에서 원본 색상 JPEG를 내보낼 때도 방향을 정규화한다. 문서의 BinData 저장 경로와 그림 크기·프레임은 보존한다. 채움 바이트 대조군의 독립 한컴 2024 재인쇄는 96·192 DPI 모두 원래 사진 대조군과 전쪽 픽셀이 같았다.

## 두 사진이 있는 표의 조판 조사

8쪽의 7행 첫 칸을 분리하고 한컴 2024에서 HWP로 저장해 저장 줄까지 다시 만들었다. ‘어울림’에서 저장 `LineSeg`의 `column_start`는 첫 사진의 오른쪽 경계와 같은 10,119이고, ‘글 앞으로’에서는 0이다. 두 설정에서 생성된 `TextLine` 상자는 96 DPI 기준 각각 x=243.7·폭 157.6px와 x=108.8·폭 292.6px로 실제 줄의 영역을 구분했다. 폭 157.0px의 두 번째 사진은 양쪽 모두 x=176.6px에 배치됐다. 한컴 PDF의 해당 좌표는 각각 243.87px와 176.39px다. [두 설정의 8개 실측](../assets/pr9298/cell-wrap-controls.tsv)

일반 칸의 그림 대체 배치는 `table_layout.rs`에서 셀 전체를 기준으로 가운데 정렬한 `inline_x`를 구한다. 이미 출력한 소유 줄의 상자를 소비하는 분기는 저장 인라인 프레임·그림 안내 줄에 한정돼 있다. 분할 칸은 `table_partial.rs`의 `stored_inline_control_pen` 경로도 사용한다. 이웃 그림의 배치를 보완할 때에는 실제 소유 줄의 가용 영역과 해당 줄의 인라인 요소 순서를 두 경로에서 재사용한다. 사진 크기나 특정 문서의 위치로 판정하는 보정값은 필요하지 않다. ‘글 앞으로’ 대조군은 겹치는 인쇄 결과를 보존해야 한다.

## 승인된 셀 안 그림 보완

기준은 `0fbee2c04e`, 원 기여는 `a588481833`이다. 한컴에서 직접 저장하고 인쇄한 두 대조군을 사용한다. 어울림에서는 둘째 그림이 첫 그림의 오른쪽에 놓인다. 글 앞으로에서는 둘째 그림이 셀 가운데에 놓이고 첫 그림이 겹친 부분을 덮는다. HWP 5.0 개체 공통 속성의 본문 배치와 z 순서가 각각 가로 위치와 그리기 순서의 근거다.

빈 글줄의 인라인 그림은 줄 조판기가 결정한 가로 위치와 셀의 그림 출력 경로가 결정하는 세로 위치·자르기를 함께 사용한다. 글 앞으로 그림은 셀 내부의 기존 전경 정렬에 참여시킨다. 두 형식의 배치·색상·개체 소유와 저장 재열기를 검사한 뒤 원본 37쪽, 정본 보호 문서와 전체 회귀를 대조한다.
