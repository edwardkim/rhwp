| 입력 | base 셀 수 | 후보 셀 수 | 후보에서 사라진 내용 |

| 2행×2열 | 4 | 4 | 없음 |
| 2,048행×2열 | 4,096 | 4,096 | 없음 |

## 제안하는 제한 보정과 완료 조건

1. HWP3의 공통 이웃 탐색만 보정한다. 축별 시작 좌표와 반대 축 구간을 index로 구성해 실제 겹치는 이웃을 찾는다. 선형 탐색 상한을 단순 제거해 O(n²)로 바꾸거나 2048 뒤를 None으로 처리하지 않는다. 좌표군의 구간 합집합을 가진 검색 tree 등으로 O(n log n) 구성·O(log² n) 질의를 사용하고 메모리/연산 경계를 기록한다. 두 축이 같은 구현을 사용하게 한다.
2. 원 기여의 시작 변 기반 격자·한컴 네 표 개선을 보존하며 기존 parsing·Storage 자원 한도·동일 입력의 내용 순서를 유지한다. 데이터 손실을 숨기거나 문서 ID·행 수 전용 예외를 넣지 않는다.
3. 작은 정상·2048 경계·연산량 대조를 실제 parser에서 먼저 확인한다. 셀의 내용 보존·소유·겹침 관계를 검사하고 helper만 통과한 것으로 끝내지 않는다.
4. 두 테스트 파일의 현행 증거 주석·검증 근거를 실제 측정 후 보완한다. SO-SUEOP 46쪽·sample16 64쪽·table-cell-order 1쪽의 Native/fresh WASM 전쪽 TSV, 독립 Print·원 글꼴 공급, 직접 확대 판독과 base 대비 하락을 확인한다. 미달·쪽수 불일치는 완료로 처리하지 않는다.
5. 새 source/test 보정에는 Rust lint 전체·집중·release-test 전체·Native 공식·최적화 fresh WASM과 편람 gate 등 적용 필수 검증을 수행한다. 기존 녹색 원 CI를 새 보정 head의 검증으로 재사용하지 않는다. 원 head의 기여 이력은 보존한다.

이번 제안은 **로컬 보정·필수 검증** 범위다. GitHub push·공개 댓글·새 PR·merge·CI 재실행은 포함하지 않는다. 승인 전에는 원 source를 바꾸지 않고 기존 기여의 독립 검토를 계속한다.
