# PR #4584 · #4590 · #4594 · #4597 통합 검토 실행 기록

이 문서는 네 원 PR의 누적 체리픽·메인터너 보정·검증 순서만 기록한다. 수용 판단과 원 PR별
범위·한계는 각 [#4584](pr_4584_review.md), [#4590](pr_4590_review.md),
[#4594](pr_4594_review.md), [#4597](pr_4597_review.md) 검토 문서를 기준으로 한다.

## 기준선과 적용 순서

| 단계 | 원 PR / source head | 누적 branch commit | 처리 |
| --- | --- | --- | --- |
| 기준선 | `upstream/devel` `4f9e4ae6` | - | clean branch `review/humdrum00001010-20260811` 생성 후 rebase |
| 1 | #4584 / `692c546c` | `beec1758d` ~ `497011131` | 파생 상태 전면 재구성 |
| 2 | #4590 / `764bcd64` | `72e7473d1` ~ `2d60cb008` | 실패 진단·플랫폼 경계 |
| 3 | #4594 / `1b7acf0c` | `081954d42` ~ `a44dcaa83` | 감시 수명·재연결 회복 |
| 4 | #4597 / `758d40ae` | `a78def626` ~ `33f92a494` | 편집 중 재도색 경계 |
| 보정 | 누적 검토 발견 | `ed8e0387a` | Node test에서 브라우저 전역 기본 진단을 보호 |

#4597은 #4584가 `src/wasm_api.rs`에서 넓힌 `&mut self` 무효화 경로를 선행 조건으로 삼으므로
반드시 마지막에 적용했다. #4590과 #4594는 그 사이의 Studio runtime 계층을 보완하며, 원 기여자
commit을 재작성하거나 source branch에 force-push하지 않았다.

## 보정 범위

`ed8e0387a`는 `subsecond-runtime.ts`의 기본 오류 listener가 Node test runtime의 `window`을 직접
참조하던 문제만 고친다. 브라우저에서는 기존 `window` listener와 개발자 콘솔 보고를 유지하고,
Node에서는 기본 reporter와 listener를 비활성화한다. patch dispatch·오류 분류·브라우저 동작은
변경하지 않는다.

## 완료한 검증

아래 검증은 최초 기준선 `a70797db` 위 rebase 전 누적 후보 `a08be5d10`에서 완료했다. 이후
`4f9e4ae6`으로의 rebase는 충돌 없이 끝났고, 작업지시자 지시에 따라 전체 검증을 중복 실행하지 않았다.
현재 rebase 후보 `ed8e0387a`는 통합 PR의 GitHub CI에서 다시 검증한다.

- 전체 nextest: `cargo nextest run --cargo-profile release-test --target-dir target/pr-review --tests
  --test-threads 12 --no-fail-fast` - 5,764건 통과, slow 7건, 정책 skip 36건.
- Rust 품질·배포 검증: `cargo fmt --check`, `cargo clippy --all-targets --target-dir target/pr-review --
  -D warnings`, `cargo build --release --target-dir target/pr-review`, release lib test 3,498건 통과.
- renderer/WASM: Native Skia 3종 58/2/4건 통과, `wasm-pack build --target web --out-dir pkg` 통과.
- Studio: `npx tsc --noEmit`, `npm --prefix rhwp-studio test` 847건 통과.
- #4576 focused regression 1건 통과, `git diff --check` 통과.

## 다음 게이트

1. 이 기록과 원 PR별 archive review 문서를 통합 PR에 포함한다.
2. 통합 PR 최신 code head의 GitHub CI·CodeQL·필요한 Render Diff를 확인한다.
3. 작업지시자 승인 뒤 통합 PR을 merge하고, 원 PR별 후속 comment·close·branch 정리는
   `post_merge.md` 순서를 따른다.

실제 브라우저 hot-patch 적용의 end-to-end 증명은 현재 누적 검증의 범위 밖이다. Dioxus endpoint,
Vite, Vite WASM proxy의 HTTP `200`은 확인했지만 patch instantiate 성공의 증거로 기록하지 않는다.
