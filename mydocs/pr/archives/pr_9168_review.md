# PR #9168 표 셀 편집 시 호스트 글꼴 재조회 검토

[PR #9168](https://github.com/edwardkim/rhwp/pull/9168)은 [이슈 #9165](https://github.com/edwardkim/rhwp/issues/9165)의 Canvas2D 입력 지연을 다룬다. 기준 커밋은 `fbf8081db57c0c6abc9bad418290c5018193e24f`, 검토한 코드 커밋은 `083726fb7738a6e370576a69da2432c16599283e`다.

- 셀 입력 경로에서 페이지네이션이 안정된 경우 전달하는 쪽 번호를 확인했다. 넘침으로 전체 페이지네이션이 필요하거나 앞선 렌더 준비가 끝나지 않은 경우 전체 요청을 수집한다. 문서·공급자·글꼴 세대, 쪽수와 메트릭 종류가 일치할 때만 다른 쪽의 요청을 재사용한다.
- 빈 카탈로그에서도 독립적인 PUA 준비가 실행된다. 일반 텍스트 요청의 중복 제거 키는 기존 face 선택에 쓰이는 family, bold, italic을 포함한다. 조판·페이지 분할 알고리즘은 변경하지 않았다.
- 3쪽 합성 문서 첫 셀에 20회 입력한 최종 측정에서 빈 공급자의 페이지 트리 조회는 60회에서 0회, 글꼴 공급 시 60회에서 20회로 줄었다. Chrome의 글꼴 공급 조건에서 두 번째 프레임까지 중앙값은 66.6ms에서 33.3ms로 줄었다. 세 브라우저와 세 공급자 조건에서 조합·붙여넣기·실행 취소·다시 실행 후 전후 기하 해시가 일치했다. [측정 및 재현 기록](../../plans/issue_9165_host_font_input.md)
- 타입 검사, Studio 단위 검사 2,808건, production build, 기존 #7403과 신규 #9165 E2E를 통과했다. 코드 커밋에서 Frontend package gates, Build & Test, Canvas visual diff와 CodeQL 언어별 분석이 성공했다. [GitHub Actions](https://github.com/edwardkim/rhwp/actions/runs/44215150479)
- 격리 WKWebView의 실제 두벌식 키 입력에서 자모 분리는 기준과 후보에 공통으로 남았다. 설치된 알한글 앱의 입력 지연은 이번 수치에 포함되지 않는다.

검토 결과 병합을 막을 결함은 발견하지 못했다. 리뷰 기록을 추가한 최종 커밋의 CI와 병합 가능 상태를 확인한 뒤 병합한다.
