# PR #9071 바탕쪽 좌표 경계 보완 계획

## 독립 재현

공개 한컴 저장본 `samples/pr9071/issue9046/hancom/02-both.hwpx`와 `09-both-odd.hwpx`를 원격 한컴 2020 11.0.0.9136에서 one-up Print한 PDF와 대조했다. 각각 전 3쪽이며, 후보 `a1975f149e`의 Native 결과는 1·3쪽 100.00%, 2쪽 47.76471%다. 실제 CLI로 HWP 변환한 뒤에도 동일하다. 양쪽 바탕쪽이 적용되는 짝수 쪽의 검은 막대가 독립 Print보다 오른쪽으로 길게 표시된다. 단순 글꼴 차이가 아니다.

원본의 좌우 여백은 11338·5669 HWPUNIT로 다르고 바탕쪽 도형은 `PAPER/LEFT`, 가로 오프셋 0·너비 6000 HWPUNIT다. 독립 Print에서는 2쪽에 막대의 끝 일부만 표시되고 후보는 전체 너비를 표시한다. 원본과 저장본의 바탕쪽 종류·내용·도형 속성은 같아 serializer의 슬롯 보존 검증만으로 실제 배치 완료를 판정할 수 없다.

## 제한 보완 범위

1. #9046·#8906과 기존 바탕쪽/맞쪽 여백 해결 이력, 사양, 독립 Print를 먼저 대조한다. `MasterPage`의 적용 종류와 기준 프레임 생성부터 `layout_master_page_with_section`의 실제 도형·문단 원점 소비까지 추적한다.
2. 정상 생성된 원본에서 양쪽·홀수·짝수 바탕쪽과 대칭/비대칭 여백의 계약을 확인한다. 원본 수치에 맞춘 상수·문서별 분기·출력 clipping으로 가리지 않는다.
3. 확인한 계약의 공통 좌표 소비를 보완하고, 원 기여의 종류·내용·속성 보존을 유지한다.
4. 원 11조합의 HWPX·HWP 전쪽 Native/fresh WASM, 원래 짝수 전용 정상 대조군, 저장 재열기와 직접 확대 판독을 완료한다. 관련 모든 페이지가 90% 이상이 된 뒤 실제 배치 관계 회귀를 등록한다.
5. 최종 변경에서 필수 회귀·lint·Native·편람·보호 TSV 검증을 다시 완료한다. 이 계획은 로컬 보완·검증이며 원격 push·댓글·PR·merge는 포함하지 않는다.

## 현재 판정

`머지 보류`. 사용자가 메인테이너 보완·필수 재검증을 승인해 아래 공통 프레임 보완을 진행한다. 나머지 PR과 기존 승인 범위의 검증은 계속한다. Windows 호스트의 Hwp.exe·COM·자동 인쇄는 실행하지 않는다.

## 선행 해결 추적과 실제 프레임 근거

- 기존 맞쪽 여백 교대는 #1196의 `a53ba046d1`에서 `PageAreas::from_page_def_for_page`와 최종 쪽번호 적용으로 도입됐다. 바탕쪽 슬롯 보존은 #3930의 호환 복제 → #8906의 실제 종류 bit 저장 → 이번 PR의 복제 제거 순서다. 별개의 물리 Print 화면 처리는 #7751의 `bd5207aa02`·`8291d5cdd2`로, 그 그림 배율·clip 계약은 변경하지 않는다.
- 독립 한컴 2020에서 원 한컴 HWP, 원 HWPX의 대칭 여백 변형, 좌우 여백 반전 변형을 추가 Print했다. 원 HWP의 짝수 쪽은 200px 막대의 11px만 남고, 대칭 변형은 전쪽 전체 막대, 반전 변형은 2쪽에서 막대가 +56.729pt로 이동했다. 실제 PDF 이미지 좌표이며 Native 출력에서 얻은 기대값이 아니다. 임시 변형·PDF·job 영수증·이미지 bbox는 ignored `resume/remote-master-frame-probe/`에 보존한다.
- 원본 여백 차이는 `(5669 - 11338) / 100 = -56.69pt`이며, 반전은 +56.69pt다. 독립 PDF의 raster 배치 반올림과 대응한다. 0으로 clamp하거나 끝의 일부만 그리도록 조건을 추가하지 않는다.

값의 생산·소비는 `PageAreas`의 홀수 쪽 본문 원점 → `PageLayoutInfo.unmirrored_body_x`의 보존/최종 여백 갱신 → `master_page_paper_frame`의 현재 본문 원점과의 차이 → `build_master_page`의 공통 용지 프레임이다. 도형·그림은 `ObjectPlacementFrame.paper`로, 표는 같은 프레임 원점으로 소비한다. 물리 페이지 bbox와 본문/문단 기준은 이동시키지 않고, 바탕쪽 작업 뒤 본문의 물리 용지 원점을 복원한다. backend별 보정·저장 IR 변경·수치 보정은 추가하지 않는다. 실제 전쪽 검증은 보완 뒤 실행하며 현재 통과로 판정하지 않는다.


## 저장 검사 경로 정정

새 배치 회귀의 최초 HWP 저장 검사는 HWPX IR을 `DocumentCore::export_hwp_native`에 직접 넘겨 형식 어댑터를 생략했다. 실제 CLI는 `src/cli/commands/conversion.rs`의 `export_hwp_with_adapter`, Studio도 같은 형식 lowering의 snapshot 경로를 쓴다. `commands/document.rs`는 이를 HWPX → HWP 저장의 단일 진입점으로 명시한다. 실제 검증된 CLI 경로와 검사의 경로가 달랐으며 원 기여의 슬롯 회귀로 분류하지 않는다. 원 HWPX/대조군 5개는 모두 통과했고 직접 native 저장 후의 1쪽에서만 개체가 빠짐을 실행 로그로 확인했다. 검사는 기존 배치 assertion을 유지하면서 실제 형식 변환 API를 호출하도록 정정한다.
