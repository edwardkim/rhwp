## 메인터너 보정

### #6080 — 「」 반각 판정의 측정·페인트 발산 (확정 결함, `136a94677`)

원 PR은 폭 측정을 **메트릭** 기준(`is_monospace_metric`)으로 바꾸면서 페인트는 폰트 **이름 목록**
(`돋움체`/`DotumChe`/`굴림체`/`GulimChe`) 기준으로 나눴다. 두 기준이 달라 양방향으로 갈린다.

- **이름 목록 밖 고정폭**: 메트릭 DB 전수 조사 결과 monospace이면서 `U+300C` 폭이 `em_size`인
  글꼴은 11종인데 이름 목록이 덮는 것은 `DotumChe`·`GulimChe` 둘뿐이다. `BatangChe`(바탕체),
  `GungsuhChe`(궁서체), `D2Coding` 계열 5종은 advance만 반각으로 줄고 글리프는 전각으로 그려져
  다음 글자와 겹친다. 별칭 표에 `"바탕체" => "BatangChe"`, `"궁서체" => "GungsuhChe"`가 있어
  문서의 한글 폰트명에서 그대로 도달한다.
- **이름만 닮은 메트릭 DB 밖 글꼴**: `KoPub돋움체`는 전용 폭 표(`kopub_char_width`)를 쓰고 메트릭
  DB에 없다. `U+300C`에서 그 표는 어느 분기에도 걸리지 않아 `None`을 반환하므로 측정은 반각
  오버레이를 적용하지 않는데, 이름에 `돋움체`가 들어 있어 페인트만 0.5×로 눌렀다.

`devel`에서는 두 경로가 모두 반각이라 정합했으므로 이 발산은 #6080이 새로 만든다. SVG 경로는
`svg_text_length_attrs`가 `textLength`+`lengthAdjust="spacingAndGlyphs"`로 글리프를 advance에 맞춰
누르기 때문에 발산이 가려진다 — 원 PR 증적이 SVG라 여기서는 보이지 않고, skia(PDF/PNG)와 WASM
브라우저에서만 나타난다.

보정은 페인트가 **측정 결정을 그대로 되묻게** 바꾼다.

- `src/renderer/layout/text_measurement.rs`: 반각 오버레이의 `width_source`를 상수
  `HALFWIDTH_PUNCTUATION_WIDTH_SOURCE`로 고정하고, `forces_halfwidth_cjk_quote`를
  `measure_char_width_embedded_decision`의 결정 비교로 재작성했다. 시그니처에 `bold`·`italic`·
  `font_size`를 추가해 측정과 같은 메트릭 변형을 고른다.
- `src/renderer/layout.rs`: 통합 테스트에서 직접 검증하기 위해 `pub use`로 노출했다
  (`map_pua_bullet_char` 선례와 같은 방식).
- `src/renderer/skia/text_replay.rs`, `src/renderer/web_canvas.rs`: 호출부에서 스타일의
  `bold`·`italic`·`font_size`를 넘긴다.
- `tests/cases/issue_6060_cjk_quote_paint_measure_parity.rs`: #2020 돋움체 반각, #6060 휴먼명조·
  HY헤드라인M 전폭, 이름 목록 밖 고정폭 반각, 메트릭 DB 밖 `KoPub돋움체` 비강제, CSS 체인 첫 face
  판정, 낫표 외 문자 비대상을 고정한다.

기대값은 추측이 아니라 `font_metrics_generated.rs`의 실제 폭 데이터로 확인했다.
`DotumChe`/`GulimChe`/`BatangChe`/`GungsuhChe`는 em_size 1024·Latin 폭 전부 512·`U+300C` 1024,
`D2Coding`은 em_size 1000·`U+300C` 1000이다. `Dotum`/`Batang`/`HYHeadLine-Medium`/`휴먼명조`는
비례 글꼴이라 반각 오버레이 대상이 아니다.

보정 전 구현으로 되돌려 같은 시험을 돌리면 회귀 시험 2건
(`monospace_faces_outside_name_list_match_measurement`,
`name_lookalike_outside_metric_db_is_not_forced`)만 실패하고 #2020·#6060 앵커 2건은 통과한다.
시험이 실제 결함을 잡고 기존 계약은 바꾸지 않음을 이 대조로 확인했다.

### Docker 표준 WASM 경로 부재

`docker compose --env-file .env.docker run --rm wasm`은 이 호스트에서 실행할 수 없었다. Docker
Desktop 데몬이 꺼져 있어 `/var/run/docker.sock`과 `~/.docker/run/docker.sock` 모두 연결되지 않는다.
[local_validation](../../manual/pr_review/local_validation.md)이 정한 대로 대체 경로를 사용하고 그
사실을 여기 남긴다. `scripts/wasm-pack-locked.sh --no-opt`는 `wasm32-unknown-unknown` 컴파일까지
성공한 뒤 `wasm-bindgen` 설치 단계에서 로컬 도구 오류로 멈췄으므로, WASM 판정 근거는 위 표의
CI 동일 명령(`cargo clippy … --target wasm32-unknown-unknown`, `cargo check --target
wasm32-unknown-unknown --lib`)이다. 이 두 명령이 이번 보정이 건드린 wasm 전용 경로
(`src/renderer/web_canvas.rs`)를 실제로 컴파일한다.

## 보정하지 않고 기록만 남긴 관찰

- **#6077 표-그림 간격**: 표 상단 괘선이 그림 페인트 bbox 바닥과 정확히 `0.00px` 일치한다. 표의
  바깥 위 여백은 1.0mm(283 HU ≈ 3.8px)인데, 코드 주석이 주장한 "표가 그림 바닥에 붙지 않음"이 이
  fixture에서 관측되지 않는다. 이 fixture에는 한컴 기준 PDF가 없어 정답을 확정할 수 없으므로 원
  저자 확인 대상으로 남긴다.
- **#6084 CENTER 분기의 방향**: `direct_hwpx_cell_has_declared_stored_frame`의 CENTER 분기가 기존
  `sum_fits_declared`를 대체한다. `preceding = 0.9h`, `trailing = 0.9h`이면 합이 `1.8h`라 종전
  판정은 거짓인데 새 판정은 참이다. #6035 해소에 필요한 방향은 좁히기이므로 교집합
  (`sum_fits_declared && preceding …`) 형태가 더 안전하다.
- **#6075 시뮬 비용**: `page_offcanvas_sim`이 참이면 미주 문단마다 scratch `LayoutEngine`으로 단
  전체를 재렌더한다. `column_had_compact_endnote_rewind`는 단 전환까지 유지되므로 되감김 이후 그
  단의 문단 수에 대해 제곱으로 늘어난다. 종전에 이 경로는 `ssot_level >= A3`(비기본) 전용이었다.
- **#6075 잔여**: 통합 head에서 대상 쪽의 최대 text baseline은 `1141.56`, 용지 높이는 `1122.51`로
  `+19.05px`가 남는다. 원 PR이 보고한 수정 전 ~1290px보다 크게 줄었지만 `56.0px` 가드 임계 아래
  잔여는 설계상 남는다.
- **U+2018–U+2027 의 선행 발산**: 페인트는 이 범위를 글꼴·글리프 폭과 무관하게 0.5×로 누르는데
  측정은 `glyph_w >= em_size`일 때만 반각으로 잡는다. `devel`에도 있는 선행 상태라 이번 보정
  범위에 넣지 않았다.
- **overflow-cell 원장의 플랫폼 의존**: 검토 환경(macOS)에서 `devel`을 재산출하면 커밋된 원장과
  4개 행이 이미 다르다(편람 `.hwp` 35→32, `issue1891_external_bindata_link.hwpx` 50→48,
  `table_giant_cell_overfill.hwpx` 94→76, `task1718/table_giant_cell_overfill.hwp` 행 소멸).
  원장에 기준 플랫폼 표기가 없어 로컬 재산출이 회귀처럼 보인다. 별도 이슈 후보다.
