## 메인터너 보정: 저장 글줄 사이 부동 개체 띠와 후행 빈 줄

`36474334-original.hwpx`는 원래 문단 1의 저장 글줄이 440·4723 HU,
문단 2가 5203 HU이고, 저장 줄 없는 문단 3 앞의 실제 끝은 8831 HU다.
같은 원본을 한컴이 HWP로 저장한 진단본도 문단 3을 8831 HU에 둔다.
원본 PDF는 변경하지 않으며 진단 저장본을 Print 기준으로 사용하지 않는다.

앞서 R5는 문단 3의 말미 부동 앵커 줄 1100 HU를 복원했지만 1쪽/PDF 2쪽 문제는 남았다.
추가 추적에서 DocumentCore의 혼합 구역 vpos 재구성이 원래 문단 1의 둘째 줄을
2200 HU로 당긴 뒤 부동 표 끝 4723 HU까지만 점유했다. 둘째 줄의 300+180 HU를
잃어 후속 문단 전체가 480 HU 위로 갔다. 구현이 아니라 원본에서 읽은 저장값이다.

공통 생산 위치는 `commands/document.rs`의 저장/합성 혼합 줄 사다리다. 유효한 원본
글줄 사이에 PARA 기준 자리차지 개체 띠가 있고 뒤 글줄이 그 띠 끝 이후에 있으면,
줄별 저장 오프셋과 마지막 줄의 전진을 함께 보존한다. 후속 문단·typeset 측정·paint는
이 사다리를 소비한다. 개체 띠를 이미 포함한 줄 사다리에 개체 높이를 다시 더하지 않는다.
합성·편집·되감긴 사다리와 글줄에 개체 높이가 포함된 별도 계약에는 적용하지 않는다.
문서 ID·특정 높이나 쪽수 임계로 분기하지 않는다. 실제 Print 재대조와 정상 대조군 검증이
완료될 때까지 수용 판정과 새 회귀 등록은 보류한다.
## 리베이스 후 공통 흐름 보정 분석

2026-11-06, 새 base `45684640be5eddcf5972b063260250345b34d928`에서 이어간다.
[HWP5 사양 설명본 4.3.4·표 62](../../tech/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.md#434-문단의-레이아웃)는
줄의 세로 위치·줄 높이·텍스트 높이·줄간격을 별도 저장값으로 구분한다.
구현 편의 태그 bit 31과 원래 저장 줄을 구분하며, 유효한 저장 줄 사이의 개체 공간을
단순한 `줄 높이 + 간격` 합으로 다시 만들지 않는다.
R6의 원본 줄 보존만으로는 `36474334`의 첫 표 뒤 300 HU 글줄과 180 HU 간격이
실제 흐름에서 소실된다. 원본 줄 440→4723은 표의 문단 오프셋 2001 HU와 높이
2282 HU를 포함하지만 `post-text`는 두 줄의 높이·간격만 더했다. 이후 표 진입이
흐름을 개체 하단 4723 HU까지 옮겨도 뒤 글줄의 끝 5203 HU가 소비되지 않는다.

보정 연결은 `stored_float_row_span_hu`의 저장 줄 범위 →
`FormattedParagraph::host_text_bounds`의 점유·전진량 → pre/post-text의 수용·분할·배치와
`record_host_text_fragment`의 동일 끝점이다. 같은 판정이 문서 재구성의 원본 줄 오프셋
보존과 배치의 `StoredColumnFrame` 발행에도 쓰인다. 형상과 겹치는 줄, 편집·합성 줄,
달라진 줄 메트릭에는 이 저장 축을 적용하지 않는다.

두 TAC 표 뒤의 비흐름 도형 앵커는 현재 재조판이 만든 세 번째 보통 줄이다. 이전 상한은
그 줄을 셌지만 실제 PageItem과 전진량은 없었다. 현재 구성의 마지막 TAC 소유 줄 뒤를
공통 범위로 정해 수용 예산·실제 `PartialParagraph`·뒤 간격을 한 번만 소비한다.
원래 저장 줄의 쪽 재시작이나 별도 흐름 개체의 높이를 이 경로에 섞지 않는다.

현재는 원인·호출 경로와 구현을 보정한 단계다. 새 base 기능 보존, 기존 100% 대조군,
원본 두 쪽과 Native/fresh WASM 직접 대조는 아직 완료하지 않았다.
