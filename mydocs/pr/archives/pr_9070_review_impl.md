# PR #9070 괘선 매핑 보완 계획

현재 판정은 원 기여의 기호 소실 개선과 상호 참조 절단 방어를 유지하면서, 새 괘선 매핑의 독립 근거를 보완해야 한다는 것이다. 메인테이너 보완 승인을 받아 제품 보정과 소규모 독립 시각 검증을 진행했다. 최종 전체 검증은 아직 완료하지 않았다.

## 확인한 반례와 선행 해결 이력

원 head `8669ec6dc4b91a57d6af8e6b82dd391dff0832af`, 최신 devel `88170fd75f9d0ce156fe49d79aeabea9bb3a4bcc`를 대조한다. #5860의 원 해결 `3c6199ab44`, #6380의 `ce8015138f`는 한컴 저장본과 실제 문자·횟수·문맥이 일치한 집합을 보존한다. 기존 공통 표시 매핑은 `src/renderer/hancom_pua.rs`에 독립 PDF 근거를 기록했다.

공개 #8912 첨부의 77개 괘선 코드를 실제 한컴 2020으로 HWPX 변환했다. 이는 파일을 한컴이 정상 생성했다는 뜻이 아니다. 원 HWP3는 제보자가 바이트를 조립한 합성 입력이다. 변환 job `125b8593-c1cf-470e-ab30-8bb833a40079`와 원본·반환 바이트 해시는 ignored 검토 로그에 보존했다. 변환본은 [공식 경로](../../../samples/pr9070/hancom-reference/hwp3-linechars-symbols-2020.hwpx)에 두었다.

| HWP3 코드 | 원 후보의 새 디코딩 | 독립 한컴 변환 | 기존 검증된 표시 근거 |
| --- | --- | --- | --- |
| `0x3032` | `U+2550` 이중 실선 `═` | `U+F081C` | 한컴 PDF에서 작은 사각 점이 반복되는 점선 `┈` |
| `0x305E` | `U+2500` 가는 실선 `─` | `U+F0848` | 편람 독립 PDF에서 굵은 가로 막대 `━` |

LibreOffice `hwpfilter/source/hcode.cxx`의 `LINEBASE`·`LineCharDir`는 77개 코드의 연결 방향만 구분하고 실제 문자 변환에서는 `+`, `-`, `|`로 단순화한다. 이것만으로 이번 후보의 7개 줄 모양·굵기 집합을 입증할 수 없다. [공식 소스](https://github.com/LibreOffice/core/blob/master/hwpfilter/source/hcode.cxx)를 직접 확인했다.

7개 별도 기호는 독립 한컴 변환본과 모두 일치한다. 위 문제를 그 기호의 오답이나 기존 실측 PUA override의 변경으로 확대하지 않는다. 최신 후보가 추가한 원래 검사를 통과하더라도 새 기대 문자열 자체가 점선·굵기를 고정하므로 독립 근거와 대조해야 한다.

## 제안하는 제한 보완 범위

1. 원 기여 SHA와 7개 기호·상호 참조 절단 방어를 보존한다.
2. 77개 괘선의 HWP3→문서 문자 매핑을 실제 한컴 저장값과 대조한다. 기존 실측 PUA는 유지하고 새 코드를 임의의 연속 오프셋 또는 7종 굵기 가정으로 채우지 않는다. 한컴은 세 번째 집합의 일부를 `U+F0308`–`U+F0310`으로 저장하므로 단순 연속 오프셋도 맞지 않는다.
3. 보존한 문자를 표시하는 공통 경로에서 실제 점선·굵기·연결 방향을 확인한다. 저장용 코드와 텍스트 표면의 의미 보존을 분리하고 backend별 임시 매핑을 반복하지 않는다.
4. 같은 합성 원본과 기존 공개 HWP3 정상 대조군을 한컴 Print·Native/fresh WASM 전쪽 TSV·확대 판독으로 검증한다. 아직 Print/최종 시각 검증은 완료하지 않았으며, 코드 변환 성공을 인쇄 일치로 표시하지 않는다.
5. 근거를 확보한 새 기대값과 관계형 회귀, 필수 gate를 새 보정 head에서 완료한다. 보정 전 FAIL/후 PASS도 남긴다.

현재 승인은 reviewer 지정과 검토 착수다. 이 계획은 메인터너가 기여자의 제품 보정을 맡는 추가 범위이며, GitHub 댓글·push·새 PR·merge는 포함하지 않는다. `AGENTS.md` 339–340행에 따라 보정 담당의 결정을 기다린다. 다른 두 PR 검토는 계속한다.

## 승인 후 실제 보완

사용자가 메인테이너 보완·필수 검증을 승인했다. 저장 문자 77개와 공통 원 PUA 공급 경로를 보완했고, [수동 Print·Native/fresh WASM 근거](../assets/pr9070/README.md)를 확보했다. 최소 글꼴 환경에서 실제 manifest의 현재 suite를 다시 해석해 집중 63개를 모두 실행·통과했다. 초기 stale suite 선택의 58개 결과는 전체 63개 통과로 바꾸지 않고 구분한다. 원본의 문자 순서와 HWP/HWPX 반복 저장도 새 검사에서 통과했다. 원격 승인은 reviewer 지정까지이며 PR·push·댓글·merge는 수행하지 않았다.
