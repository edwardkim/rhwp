## 전체 회귀의 중첩 캡션 카운터 panic 분석

R26 전체 nextest에서 overflow_cell_baseline partition15와 off_canvas_baseline partition15가
같은 `table_layout.rs`의 `auto_counter.borrow_mut()`에서 panic했다. 기대값 비교 실패가 아니며
원장 baseline을 늘리거나 회귀를 제거해 해결할 문제가 아니다.

기존 #3528 파싱·#5875 캡션 출력과 이번 R8의 캡션 TAC 소유 보정을 선행 경로로 확인했다.
`layout_caption`은 `_auto_counter` 인수를 실제로 쓰지 않고 현재 원본 자동 번호를
`project_caption_auto_numbers`로 표시 문자열에 투영한다. 그런데8개 호출 지점이 RefMut를
캡션 전체에 걸쳐 유지해 중첩 표의 캡션 진입에서 같은 RefCell을 다시 빌린다.
필요하지 않은 인수와8개 호출의 장기 borrow를 제거하는 공통 보정으로 준비한다.
새 카운터를 만들거나 번호 상태를 초기화하지 않고, 실제 번호 투영·소비 경로는 유지한다.

현재 source는 R26 전체 nextest 종료까지 고정한다. 이후 이 panic과 평가결과서의 원본 글머리표
전진을 같은 후속 후보에 보정해 검증한다. 기존 두 원장 검사는 유지한다. 아직 후속 코드에
반영하거나 통과로 판정한 상태가 아니다.


### R26 전체 검증 종료와 보정 범위

전체 Rust 검사는 12,824건 중 12,813건 통과·11건 실패·기존 skip 45건, exit 100으로 종료했다.
실패 6건은 같은 중첩 캡션의 불필요한 RefMut 수명, 2건은 #7872 중첩 표의 바깥 셀 포함,
1건은 #8160 HWPX 53쪽 기준선, 2건은 #3234 같은 문단의 홀수 머리말 우선순위다.
검사·baseline은 완화하지 않고 원 해결 및 통합 보정과 대조한다.

R27에서는 먼저 쓰지 않는 캡션 카운터 인수와 8개 호출 지점의 borrow를 제거한다.
원본 자동 번호 투영은 유지하며 카운터를 새로 만들거나 재진입을 건너뛰지 않는다.
같은 문단의 양쪽·홀짝 선언에는 구체성을 유지하고, 뒤 문단의 양쪽 재정의는 보존한다.
평가결과서 원형 기호는 독립 Print로 확인한 원본 HFT의 개별 전진만 표시 OTF와 구분한다.
이 보정의 집중 실행과 남은 중첩 표·기준선 실패 분석 뒤 최종 검증을 계속한다.


### 원본과 현재 프레임을 이중 투영한 소비 지점 확인

#7872의 이전 R11과 R25/R26 실제 트리를 대조했다. 바깥 칸과 두 중첩 표의 높이는
같지만, R25부터 두 중첩 표만 아래로 8px 이동했다. 현재 줄 프레임으로 만든 셀을
실제 배치 함수에 원본처럼 다시 넘겨, 저장 host의 선언과 현재 높이 구분이 사라졌다.
정렬·extent는 현재 프레임을 소비하되, 실제 배치에는 원본 셀을 넘겨 각 문단에서
같은 프레임을 한 번만 투영한다. 원본 컨트롤 주소에 기반한 캐시와 초과분 판정도 유지한다.

#8160 HWPX 53쪽은 앞쪽의 빈 문단825가 새 쪽에 추가돼 양식3 기준선이 25.6px 밀렸다.
R11/R26의 문단822~824 커서는 같다. 현재 본문959px는 프레임 안인데, 뒤 빈 줄이
들어가지 않는다는 이유로 dirty 사다리 전체의 저장 reset을 무효화한 R25 조건이 원인이다.
대조군 report-628 문단705는 빈 줄 이전 본문 커서883.2px 자체가876.8px 프레임 밖이다.
단순 dirty 또는 다음 빈 줄의 fit 실패와 이미 수용한 본문의 프레임 넘침을 구분한다.
기존 독립 PDF·64쪽 기준선 검사와 보고서 전체 소속 검사를 그대로 재실행한다.


### R27 집중 결과와 남은 실제 소비 지점

R27 집중 검사는 공개 글꼴 5개 환경에서 27건 중 25건 통과·2건 실패, exit100이다.
캡션 패닉 6건·홀짝 머리말 2건·sample16 세 원본의 전쪽 계약, 새 원형 기호 공급 검사가 통과했다.
#7872 두 검사는 이전과 같은 바깥 칸 포함 실패다. 원본 셀을 실제 배치에 넘기는 보정만으로는
해결되지 않았으며, 이를 완료로 판정하지 않는다. 검사와 독립 기대값은 그대로 유지했다.

보존된 Native 실행 파일 11개를 같은 원본에 실행해 시점을 좁혔다. R11/R15/R16~R22는
중첩 표 원점119.3/218.6px이고 R23c/R25부터127.3/226.6px다. 바깥 칸 높이는147.9px로 같다.
R23c는 실제 셀 배치 앞에서 현재 줄 프레임을 셀 전체에 투영했다. 배치 함수에는 원본을
되돌렸지만 그 앞의 정렬 계산은 여전히 투영본을 `calc_nested_controls_bottom_height`에 넘긴다.
이 helper와 실제 배치의 `sequential_nested_cell_layout`이 서로 다른 저장 선언을 받아
다른 점유 하단을 생산하는 것이 남은 소비 지점이다. 현재 프레임의 글줄 높이는 유지하고,
원본 컨트롤·저장 선언과 같은 composed 결과를 두 경로에 함께 넘기는 보정을 이어 간다.


### R28 공통 중첩 점유 하단 소비 일치

정렬 계산의 `calc_nested_controls_bottom_height`도 실제 배치와 같은 원본 셀 문단과
현재 composed 결과를 받게 변경한다. 글줄 프레임의 높이·줄 소속은 보존한다.
높이를 다시 키우거나 좌표를 옮기는 보정이 아니라, 같은 helper에 들어가는 원본 선언의
소유를 일치시킨다. #7872 두 원본·sample16 전쪽 계약·보고서 소속·캡션·머리말·글꼴 공급의
동일 집중 검사를 함께 실행한 뒤 새 Native/fresh WASM을 만든다.


### R28 집중 검증 완료

공개 글꼴 5개 최소 환경에서 동일 집중 검사27건이 모두 통과했다(exit0, 실행4.782초).
R26 전체 검사에서 실패했던11건을 모두 포함하며 #7872 두 원본의 포함·독립 기준선,
sample16 세 원본의64쪽 내용·원점, 캡션·원장 패닉과 머리말 우선순위가 통과했다.
새 수식 소속2건·자동 분할 경계3건·표시 프로그램 공급 반례도 함께 통과했다.
검사·baseline·PDF·오차는 변경하지 않았다. 나머지2419건은 이 집중 실행의 통과로 합산하지 않는다.
같은 source의 Native·최적화 fresh WASM과 최종 전쪽 비교·전체 회귀·lint는 계속 진행한다.
