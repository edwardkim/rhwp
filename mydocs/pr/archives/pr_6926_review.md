## 실행한 검증

원본을 찾아 새 한컴 engine 2020 PDF 17쪽을 비동기로 생성했다. 5·7·9쪽을 재대조했다. 현재 render tree의 그림 x는 7쪽 481.3/483.4, 9쪽 489.2/481.2로 작성자와 일치한다. 전체 17쪽 roundtrip은 PASS, maxDisp=0, overPages=0, structPages=0이다.

동일 HEAD에서 #6926의 적용 커밋 `46ff3a5a8`만 제거한 대조본을 별도로 빌드했다. 동일 원본·환경의 전체 17쪽, 3,090개 렌더 노드를 비교한 결과 180개의 x만 18.8~18.9px 바뀌었고 x를 제외한 속성은 전부 동일했다. 세로 좌표·크기·본문 구조는 변하지 않았다. 1쪽을 포함한 비대상 페이지도 동일했다.

전용 회귀 3개와 #6910의 2개를 합친 focused 5개 모두 통과했다. 최종 전체 회귀는 8 threads, 9,327개 통과·실패 0·별도 skipped 46개, 316.582초, exit 0이다.

최종 메인터너 보정 후 공통 전체 회귀는 9,327개 통과·실패 0·별도 건너뜀 46개다. focused 5개, fmt, native/WASM/workspace all-targets Clippy, workspace 빌드와 manifest 검사도 통과했다. 제품 소스가 같아 기존 Native Skia·WASM package·Studio·TypeScript·Chrome·시각 결과를 재사용했으며, 이전 실패와 재실행 범위는 공통 기록에 구분했다.

## 잔여 사항과 수용 범위

roundtrip PASS는 같은 렌더러 왕복 간 동일성이지 한컴 일치나 페이지 넘침 부재가 아니다. 실제 9쪽(0-based page=8) para=91에서 본문 하단 대비 82.5px 넘침이 출력됐다. 5·7·9쪽의 잉크 일치율은 약 32.00/27.15/19.75%이며 자동 합격 기준으로 쓰지 않았다.

이 넘침은 #6926 적용 전후에 동일하다. 이번 수용은 선언 가로 여백의 반영에 한정하며 기존 본문 흐름·글꼴 문제의 해결을 뜻하지 않는다. 제품 소스를 추가 변경하지 않았으므로 기존 PNG를 유지했다.

## 보류 해소를 위해 완료한 보정

- 기존 issue4090 공개 최소본을 발견해 재사용했다. 새 23.2MB 원본 중복 추가나 기존 baseline 완화는 하지 않았다.
- [전용 회귀](../../../tests/cases/issue_6887_para_float_outer_margin.rs)는 원본 `pi=44, ci=1` 표의 PARA / LEFT / Square / 비-TAC / 여백 1417HU 선언을 먼저 확인한다.
- Left·Inside에서는 1417HU(18.8933px)가 한 번만 적용되고, Center·Right·Outside에서는 왼쪽 여백이 추가되지 않으며 음수 여백도 이동을 만들지 않음을 검사한다.
- 크기 비교는 `280.2933333333333` 대 `280.29333333333335`의 f64 반올림 때문에 처음 실패했다. 사용자 승인으로 크기에만 `1e-9px` 허용을 적용했다. 가로 이동량·비대상 정렬 검사는 그대로 유지했다.
- 초기 import 컴파일 오류와 위 엄밀 비교 실패는 메인터너 테스트의 문제였으며, 수정 후 focused·전체 회귀를 다시 실행해 통과했다.
- 비대상 TAC를 포함한 원본 전체 구조의 보존은 동일 조건 대조본으로 확인했다. 새 자동 회귀가 TAC의 모든 변형까지 검사한다고 주장하지 않는다.

## 원 PR·이슈 코멘트 계획

원격 통합·CI gate 완료 후 댓글에는 목표 x 재현, 17쪽 변경 귀속 대조, 전용 회귀 성공을 기록한다. 원본 9쪽의 넘침과 글꼴 차이는 기존 잔여로 함께 공개한다. 가로 여백 범위를 넘어 전체 문서가 해결됐다고 주장하지 않는다.

- 지금은 원격 댓글·review·close를 수행하지 않았다.
- 모든 통합 gate와 merge 후 devel CI 완료 뒤 실제 merge SHA·PR/devel CI URL을 기록한다.
- 증적은 공통 기록의 댓글 템플릿처럼 commit 고정 raw 이미지로 본문에 직접 표시한다. `/tmp` 경로·로그 링크를 공개 증적으로 사용하지 않는다.
- 기존 수용 댓글이 있으면 본문을 수정하고 중복 등록하지 않는다. UTF-8 body-file 방식으로 게시한 뒤 API로 실제 본문을 재조회한다.
- 연결 이슈의 실제 범위가 남으면 전체 해결로 닫지 않는다. 기여자 fork 브랜치는 보존한다.
