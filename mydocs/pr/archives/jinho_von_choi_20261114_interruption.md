- Hancom PDF 큐에는 이 작업에서 만든 `hwp3-linechar-specimen.hwp` 기록 2개(ID 2·3, 조회 시 상태값 128)가 남았다. 다른 문서 이름이면 중단하도록 확인한 뒤 해당 2개만 제거했다. 이후 큐 0개·`Hwp.exe` 0개다. 상태값 128을 임의로 대기·오류로 해석하지 않았다.
- 직접 작성한 `print-specimen.ps1`·`window-probe.ps1`을 `.ps1.disabled`로 이름을 바꾸어 일반 실행 경로를 비활성화했다. 원본 바이트 해시는 ignored `reboot-containment.json`에 남겼다. 시스템 실행 정책·레지스트리·다른 사용자의 프린터 작업을 바꾸지 않았다.
- 조회 가능한 원격 변환 5건은 모두 terminal 상태다. 새 요청은 보내지 않았다. 초기 원본 Print 호출 중 job ID 기록이 실패한 1건은 직접 재조회하지 못했으므로 이 목록의 건수에 포함하지 않는다.
- 기본 작업공간 `devel`은 `88170fd75f`이고 clean이다. 전용 worktree의 제품 수정 2개 파일과 공개 입력, 실행 로그·빌드 산출물은 보존했다. 검토 완료 후 정리는 실행하지 않았다.

앞선 실행에서도 `Quit()` 이후 이 작업이 만든 `Hwp.exe`가 남았다. 당시 기록한 PID·실행 경로·시작 시각을 확인해 그 PID만 종료한 뒤 재시도했지만, 프린터 드라이버의 정상 복구를 확인하지 못했다. 반복 오류 메시지의 직접 발생 지점은 아직 확정하지 않았다. 입력의 잘못된 용지 값만을 이번 호스트 오류의 확정 원인으로 돌리지 않는다. 호스트 인쇄 실패 뒤 추가 자동화를 진행한 대응은 중단하며, 로컬 한컴 호출은 다시 시작하지 않는다.

## 메인테이너의 수동 열기·직접 인쇄 확인

사용자가 같은 HWP를 한컴에서 정상적으로 열고 직접 PDF로 인쇄했다고 확인했다. 제공한 폴더의 실제 유일한 PDF는 `E:\tmp\rhwp-jinho-20261114\hwp3-linechar-specimen-2020.pdf`이며, 대화에서 처음 언급한 `-direct.pdf` 접미사는 없다. 이 파일명 차이는 사용자에게 알렸다.

Windows의 인쇄 입력 HWP와 검토 worktree 원본은 SHA-256 `a20917ea3e4b0d27f3b041078dfae3a2050d0606058bada6fe48fc6a876061a2`로 일치한다. PDF는 한컴 2020 `11.0.0.9166`·Hancom PDF `1.3.0.550`, 1쪽, 18,695바이트이고 생성 시각은 2026-11-14 18:30:56 KST다. 앞선 자동 인쇄 실패 뒤 사용자가 직접 제공한 결과이며 자동화 성공으로 소급하지 않는다.

[수동 Print PDF](../../../pdf/pr9070/hwp3-linechar-specimen-2020.pdf)와 [출처·해시](../assets/pr9070/manual-print-provenance.json)를 보존했다. 새 한컴 실행이나 인쇄 요청 없이 기존 파일만 읽고 복사했다. 이 결과로 해당 합성 HWP 자체를 손상 또는 반복 오류의 원인으로 단정하지 않으며, 자동 인쇄·출력 파일 지정·종료 처리 경로를 우선 조사한다. 장애의 직접 원인 확정 및 Native/fresh WASM 전쪽 시각 판정은 별도이며 아직 완료하지 않았다. 호스트 한컴 자동화의 비활성 상태는 유지한다.
