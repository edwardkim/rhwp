## R29 선행 분석 — 한자 뒤 중립 괄호의 원본 소유

`sungeo.hwp`는 base와 후보 모두 독립 Print와 같은 94쪽이다. 현재 Native는 1쪽을
제외한 여러 쪽에서 0.1%p를 넘게 낮다. 원본 구역1·문단63은 글자 모양10 하나로
`江湖煙波(강호연파)`를 저장하며, 한글·영문은 궁서, 한자는 한양해서를 선언한다.
한컴 Print 전94쪽에서 HYhaeseo 한자 뒤 여는 괄호 947건은 모두 Gungsuh로 출력됐다.
현재는 앞 한자의 언어를 그대로 넘겨 괄호까지 한양해서의 실제 전진으로 측정한다.
그 결과 뒤 `강호연파`의 원점이 base보다 약1.3px 앞당겨진다.

원본·PDF·글꼴 공급 환경과 임계값은 동일하다. 설치된 한양해서를 제외하거나
메트릭 수치를 역으로 맞추지 않는다. 같은 본문과 보호 문서의 독립 괄호 소유를
교차 확인한 뒤, 측정과 실제 글줄 분할이 공유하는 언어 소유 규칙에서 보정한다.

같은 크기의 궁서/굴림/바탕, 궁서/궁서/바탕, 맑은 고딕/Arial/바탕을 각각 6가지 문자
순서로 둔 합성 HWPX를 한컴 2020 `11.0.0.9136`과 2024 `13.0.0.3901`의 MCP Print로
출력했다. 두 버전 모두 18개 사례의 괄호는 영문 슬롯이며, 한글·영문 face가 같거나
영문 프로그램에 한글이 수록되어 있어도 이 계약은 바뀌지 않는다. 원본 `sungeo.hwp`의
독립 Print 947건과 일치한다. 공백의 상속 언어는 그대로 유지한다.

기존 `uses_latin_slot`의 프로그램 종류·한글 수록 여부 조건을 제거하고, 선언된 영문 슬롯을
기존 공통 분할·측정·paint 경로가 함께 소비하게 했다. 새 관계 검사는 제품 수정 전
`江湖煙波(`가 한 run에 묶이는 것을 실제로 검출했다. 합성 대조군은 원 주장 문서를
대체하지 않으며 원본 전 94쪽의 새 Native/fresh WASM 결과와 직접 판독을 별도로 확인한다.
R29의 실제 종료 전에는 최종 무하락이나 승인으로 판정하지 않는다.

R29 최소 글꼴 집중 회귀는 관련 기존 검사와 함께 **33건 모두 PASS / exit 0**이다.
새 원본 관계 검사의 수정 전 FAIL과 수정 후 PASS를 확인했다. Native/fresh WASM 전쪽
재측정과 전체 회귀·필수 lint는 별도 게이트이며 아직 완료 판정하지 않는다.


## R30 선행 분석 — 유효한 0번 머리 글자 모양 참조

R29는 괄호의 영문 슬롯 소유를 고쳤지만 전 94쪽의 Native/fresh WASM 최저가 모두
98.93%이며, 고정 base 대비 93쪽에서 이 작업의 0.1%p 조건을 넘겨 낮다. 90% 하한을
넘었다는 이유로 수용하지 않고 고비용 전체 회귀·편람 후속 실행을 중지했다.

원본 바이트의 BULLET은 `attr=0x8`, 거리 20%, `char_shape_id=0`, 문자 U+F09F다.
0번 글자 모양은 1400HU·#000080·양각이며 본문 10번 모양은 1300HU·#000099다.
구역 1 문단 63의 PARA_CHAR_SHAPE는 `(0,10)` 한 항목뿐이다. 끝 글자 모양을
상속한 결과가 14pt라는 해석도 성립하지 않는다. 독립 Print는 약 14.04pt의
#000080·흰색·회색 층을 가진 마커를 출력한다.

기존 `marker_char_style`과 `nominal_marker_size`는 ID 0을 참조 없음으로 취급해
마커·예약 영역·거리 기준을 모두 본문의 13pt에서 얻는다. 이 조건은 통합 PR #7568의
`731de9e1b4bb946d76f35108ed7e186ebe4ebecb`에서 들어왔으며, 당시 별도 글자 모양을
참조하는 마커의 크기 분리는 맞지만 0번과 본문 모양이 다를 수 없다는 가정은 틀리다.
사양 표 39는 글자 모양 ID 참조를 정의하며 0을 예약값으로 정하지 않는다.

같은 0번 모양을 새 ID로 복제해 참조 주소만 바꾼 진단 HWPX 쌍에서도 본문 시작이
1.6 CSSpx 달라졌다. 독립 Print 5쪽과의 진단 값은 99.96933% → 100%다. 이는 rhwp가
직렬화한 진단 쌍이므로 원본 HWP의 최종 측정으로 바꾸지 않는다. 실제 원본은 그대로
새 Native/fresh WASM으로 다시 측정한다.

보정은 0번을 포함한 유효 참조를 공통 마커 스타일·예약 영역에서 함께 소비하는 것이다.
참조가 없는 합성 HWP3 개요와 편집 API의 기본 목록은 생성 단계에서 기존 센티널
`u32::MAX`를 명시해 본문 추종을 보존한다. 파일의 실제 0번 참조와 합성 기본값을
소비 지점의 휴리스틱으로 구분하지 않는다. 같은 모양의 ID 별칭 불변성·원본 크기와
꾸밈·명시적 참조 없음 반례를 글꼴 설치와 무관한 관계 검사로 보호한다.

수정 전 최소 글꼴 Rust 회귀 3건은 **2 FAIL / 정상 대조 1 PASS / exit 100**이다.
0번 참조의 크기·색·양각과 동일 모양 ID 별칭의 배치를 실제로 검출했고, 명시적 참조 없음
대조군은 통과했다. 보정본의 집중 검사·실제 영향 쪽·전쪽 및 필수 전체 검증은 별도로 진행한다.


### R30 실제 선행 결과와 최신 base 반영

수정 후 최소 공개 글꼴 집중 회귀는 **57건 모두 PASS / exit 0 / 실행 9.077초**다.
실제 원본 고사성어 5쪽은 같은 조건에서 Native **98.93% → 100.00%**로 개선했고,
고정 base 99.95%보다 높다. [같은 원본 5쪽 TSV·review·overlay·확대 및 출처](assets/planet6897_20261106/pr8611/r30-native-p005/README.md)를 보존했다.
수정 후 전 94쪽과 fresh WASM은 별도로 완료해야 하므로 최종 승인으로 표시하지 않는다.

새 base `13775409e57a9550cfb31866d40bdf319ab54bac`의 PR #8725를 반영해
110개 커밋을 충돌 없이 리베이스했다. 리베이스 직후 head는
`ff240479b03c6ff0697d2fb5e09fbe03c4d009de`다. 전체 파일 트리가 새 base와 기존
변경의 사전 합성 트리 `534c365cab083809848ba7f7387db3d2592b8275`와 정확히 같아,
충돌 해소 과정의 누락은 없다. 이것을 실행 검증으로 대신하지 않는다. 새 셀 그림 삽입·이동과
편집 후 세로 기준선·글 옆 그림 높이, 기존 원본 및 보호 TSV를 같은 새 후보에서 확인한다.
