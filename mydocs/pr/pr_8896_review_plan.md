2026-11-11 작업지시자가 “8896 PR 은 메인테이너쪽에서 완료 처리로 진행합니다”라고 지시했다.
기존 원 head `51a960e392a3d79a4d28f78fa90a2aa88ad8c0d7`와 공개 3개 입력·독립 Print PDF를 보존한다.

## 남은 처리와 완료 기준

1. 기존 검토의 보류 사유와 실제 source·테스트·독립 Print를 대조한다.
2. 최신 devel 병합 결과에서 Native/fresh 최적화 WASM의 3개 입력 전 6쪽과 실제 빈 host 글줄 대조군을 검증한다.
   #8945의 8쪽 첫 조각·아래 여백 계약도 같은 후보에서 유지되는지 확인한다.
3. 정본 보호 18개 문서·Native/WASM 36개 데이터셋과 필수 편람 gate를 완료한다.
   직전 #8945에서 정합한 글꼴·연결 이미지·source-metrics 환경을 재사용하고, 현재 devel의 기록된 PNG 해시와 후보 실제 출력을 비교한다.
   과거 정본 미재현을 새 회귀와 구분하며 이전 PR 한정 예외를 자동 적용하지 않는다.
4. 집중 회귀와 변경 범위의 필수 검증을 완료한다. source/test/fixture 보정이 없으면 원 exact-head 녹색 Full CI의 광범위 회귀 재사용 조건을 확인한다.
   보정하면 새 head의 로컬 필수 묶음과 CI를 완료한다.
5. 최종 승인·병합 및 #8693의 실제 해결 범위를 확인하고 기록·댓글·동기화·전용 산출물 정리를 수행한다.
   fork `kidsnote/rhwp`는 push 권한이 없으므로 보정 commit이 필요한 경우 원 기여 SHA를 보존한 upstream 수용 PR을 사용한다.

## 기존 근거

### 2026-11-11 수용 범위 변경

Native/WASM 보호 3,542쪽이 현재 devel과 모두 같지만 과거 정본 공식 값 미재현 911행이 남았다.
작업지시자는 “예외 없이 기존 차이도 먼저 해결”을 선택했다. 따라서 기존 #8945 예외를 재사용하거나
이번 PR에 새 예외를 적용하지 않는다. 공급 글꼴·원 프로그램·측정 조건과 최초 수용 source를 대조하고,
필요한 공통 보정을 수행해 원래 보호값을 충족한 뒤 PR을 제출한다. 정본 TSV·허용치는 변경하지 않는다.
작은 미달 쪽의 진단을 먼저 수행하고 실제 보정 뒤 영향 범위 전쪽과 원 #8693 개선을 재검증한다.

첫 확인 사항은 Native 적재 상한 256개다. 기존 5개 글꼴 경로의 첫 HFT 폴더만 387개이므로 뒤의
한컴·Windows 글꼴이 적재되지 않는 경고가 있었다. 실제 문서의 선언 가족·기존 환경의 명시된 대체
가족만 공급한 작은 대조군으로 공급 문제와 제품 문제를 구분한다. 이 진단은 전쪽 검증을 대체하지 않는다.

중첩 표 8·9쪽에는 `U+F02FB`의 원 글리프가 공급돼도 Unicode `▸`로 투영되는 잔여가 있었다.
기존 #4224 → PR #4228(`30bad7c1d4c3799d2e4df4027c465a972dc9559d`)은 글꼴이 없는 경우의
tofu를 표시 대체로 해결했다. 이후 `774d414cd9`·`17225375ff`가 실제 SFNT의 원 PUA 표시·전진을
공통 소비하게 했지만 지원 목록에 이 기호가 빠져 있었다. 독립 Print가 사용한 Haansoft Batang의
작은 삼각형과 공급 프로그램을 대조하고, 원 글리프 공급 시 보존되는 공통 목록에 추가한다.
원 프로그램 부재·결측에서는 기존 #4228 대체를 유지한다. 문서별 좌표나 glyph 크기를 맞추지 않는다.
보정 후 중첩 표 전 17쪽과 정상 대조군의 Native/fresh WASM을 먼저 확인한 뒤 관계형 회귀를 보강한다.
