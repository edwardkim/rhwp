# pblsketch의 중첩 문단 편집과 글상자 클릭 보완 검토

검토 기준은 `devel` `48a6783990`, 두 원 기여를 함께 적용한 제품 소스는 `2647cad077`이다. 아래 두 동작은 무관한 파일에서 각각 재현된다. 원 기여 둘의 개선을 보존하면서 담당자가 보완할 범위를 제안한다.

## #9401에서 Backspace를 실행 취소하면 문단 경계가 달라진다

1. [수식이 든 HWPX](../../tests/fixtures/group_textbox_cell/table-inline-equation.hwpx)를 열면 글상자 속 표 칸에서 수식 `x+1` 다음에 `BOX`가 보인다. 입력은 공개 표 문서와 #9424의 공개 수식으로 구성했고 rhwp로 HWPX에 저장·재열기했다. 수식과 `B`가 앞 문단에 남는 위치에 커서를 놓는다.
2. Enter를 누르면 앞 문단은 수식과 `B`, 뒤 문단은 `OX`가 된다. 뒤 문단 맨 앞에서 Backspace로 합친 뒤 Ctrl+Z를 누르면 앞 문단에는 수식만 남고 뒤 문단이 `BOX`가 된다. 수식이 없는 대조본은 같은 조작에서 `B`와 `OX`가 복원된다.
3. Native는 원 입력과 HWP·HWPX로 재저장한 두 입력 모두에서 나눈 위치 2에 대해 병합 위치 1을 반환했다. Studio는 앞 문단의 글자 수 1을 따로 읽은 뒤 실행 취소에 쓴다. [Native 여섯 대조](assets/pblsketch-20261126/native-undo.tsv) · [브라우저 조작별 결과](assets/pblsketch-20261126/studio-reproduction.tsv)

문단을 나눌 때 사용하는 인라인 개체의 논리 위치와 합칠 때 반환하고 기록하는 위치를 통일한다. 병합 커맨드와 후속 실행 취소가 같은 결과를 받게 하고, 일반 문자열과 수식의 앞·뒤, Enter·Backspace·실행 취소·다시 실행, HWP/HWPX 재열기를 검증한다. 최신 기준에서는 글상자 단계에서 나누기 자체를 거부했다.

## #9403에서 커서 조회는 맞지만 Studio가 묶음 전체를 선택한다

1. 저장소의 `tests/fixtures/group_textbox_cell/cell-group-textbox.hwp`를 Studio에서 연다. 표 칸에 있는 둘째 글상자의 `둘째 상자` 끝 오른쪽 5px를 클릭한다.
2. 후보의 좌표 조회는 둘째 글상자 5번째 위치를 반환한다. 실제 마우스를 한 번 클릭하면 두 글상자를 둘러싼 묶음 선택 손잡이가 나타난다. `K`를 입력해도 해당 글상자의 글이 바뀌지 않는다. 같은 곳을 다시 누른 경우에도 묶음 선택이 남는다. 최신 기준에서도 묶음 객체 선택이 재현된다. [클릭 직후 화면](assets/pblsketch-20261126/group-click.png)
3. 본문의 일반 글상자에서는 같은 동작으로 누른 줄 끝에 `K`가 추가된다. 후보는 Native의 11개 좌표에서 경로와 위치를 모두 맞춘다. Studio의 포인터 처리에서는 바깥 편집 주인이 표인 경우 안쪽 글상자 경로보다 묶음 객체 선택이 앞선다.

안쪽 글상자 텍스트나 여백과 묶음 테두리의 조작을 구분하고, 커서 조회가 선택한 안쪽 글상자·문단 경로를 실제 입력까지 전달한다. 형제 글상자의 글자와 여백, 묶음 테두리의 객체 선택과 이동, 글상자 안 표 칸, 본문 글상자, 실제 입력과 실행 취소를 함께 검증한다. 원 PR 각각의 기록은 [#9401](pr_9401_review.md)과 [#9403](pr_9403_review.md)에 있다.
