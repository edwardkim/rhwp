# #8975 표 뒤 문단 간격 — 승인된 메인테이너 보정

2026-11-13. 사용자가 기존 차이 예외 대신 간격 보정·재검증을 선택했다. 원격 처리는 별도다.

## 독립 기대값과 원인

e·f 생성 대조군의 실제 HWP LineSeg는 빈 문단 31에서 높이 1000HU·줄간격 600HU이고,
다음 문단 32의 저장 vpos 차이는 1600HU다. 문단 서식도 10pt·줄간격 160%다.
따라서 빈 줄은 1600HU(96dpi 21.3333px)를 한 번 소비해야 한다. 같은 입력의 Desktop
Hancom 2020 Print에서 표 뒤 문단 위치를 확인했다. Native는 8px, WASM은 7px 아래다.

실제 호출 연결:

1. `typeset/paragraph/format.rs`가 줄 높이 13.3333px·후행 간격 8px를 구성한다.
2. `typeset/paragraph.rs`는 `flow_advance_height` 결과 21.3333px를 수용하고
   `paragraph_fragment_content_bottoms`에 실제 줄 하단을 기록한다.
3. `typeset/section/vpos.rs`는 그 하단을 공통 `HeightCursor.prev_item_flow_line_bottom_y`로 전달한다.
   paint의 `layout.rs`도 실제 배치한 줄 상자의 하단을 같은 커서에 넘긴다.
4. `height_cursor.rs::vpos_adjust`의 lazy 역산이 기존 단 원점이 없다는 이유로 실제 소비 증거를
   배제하고 `trailing_ls_hu=600`을 다시 빼 기준을 세운다. 뒤 문단의 스냅이 600HU 아래가 된다.

실제 진단에서 빈 문단 진입 255.067px → 정상 전진 21.3333px인데 다음 문단 진입은
284.4px다. lazy base는 29870HU이며, 실제 소비를 한 번만 반영하면 30470HU여야 한다.
픽셀 목표 상수를 코드에 넣지 않는다.

## 선행 보정과 제한 범위

`e12d99b91a92bb20c1eccc2550acf1201719d42e`(#7382 통합 이력)는 실제 빈 줄의 소비된
후행 간격을 보존했고 `694dccffb1e79d5f1bc488b0f90b51fef06561c2`는 누적 RowBreak
프레임과 뒤 문단 원점을 연결했다. 이 보정을 되돌리거나 저장 줄의 실제 빈 슬롯을 없애지 않는다.

보정은 공통 커서의 상대 기준 역산에 한정한다. 기존 단 원점이 있으면 그 원점과 실제 소비가
맞는지 확인하는 조건을 유지한다. 원점이 없을 때도 권위 있는 연속 저장 줄·편집되지 않은 경로와
실제 수용한 줄 하단/후행 간격이 일치하면 그 상대 기준을 사용할 수 있게 한다.
소비 하단 누락·불일치, 비연속 줄, 합성 줄, 편집 경로, 모순되는 기존 단 원점은 기존 bridge를 유지한다.

## 검증 순서

1. 작은 실제 e·f의 Native 전 4쪽과 간격을 먼저 확인한다. 정상 대조군으로 #7620 기존
   RowBreak·None, #7288 TAC, #7382의 실제 빈 줄/단 원점 반례를 포함한다.
2. fresh 최적화 WASM에서 같은 입력·Desktop Print를 재검증한 뒤 관계형 회귀와 독립 근거를 보완한다.
3. 기존 단위 검사의 원점 부재 반례는 실제 줄 소비 증거와 논리적으로 맞는지 재검토한다.
   다른 부정 대조군은 유지한다. 구현값을 그대로 기대값으로 복사하지 않는다.
4. 최종 head에서 Rust lint 묶음·전체 release-test·Native 공식 3종, 편람 383쪽 gate와
   정본 보호 TSV 전체의 공식값 하락 금지를 검증한다. 기존 PR별 기능과 #8951의 0건을 함께 확인한다.
5. 실패는 기존 해결 PR·보정·독립 근거를 먼저 추적한다. 기존 기대값이나 보호값을 통과 목적으로 낮추지 않는다.
