# #8153: 같은 런의 명시적 오른쪽 탭

[계획](../plans/issue_8153_inline_right_tab_20261026.md)의 원본·공식 TabDef 계약과
실제 소비 경로를 따른다. 채움이 있는 같은 런의 RIGHT 탭도 기존 공통 정지 선택을
사용하도록 측정과 문자 위치를 연결했다. 명시적 정지가 없으면 원본 저장 전진을
소비하며 자동 우측 탭과 다음 런을 기다리는 경로는 각각의 계약을 유지한다.
원본·글꼴·PDF·페이지/문서별 보정 좌표를 수정하지 않았다.

정식 검사 `tests/cases/issue_8153_intrarun_right_tab.rs`의 SHA-256은
`2dd7e448cef7edd4d00a76cc46af2e1e3781605da45b678d61847ba5da4618fb`다.
고정 source `c3b88a07df`에서 빌드 exit 0·실행 exit 101이며 두 원본 모두
명시적 정지 대신 셀 우단에 맞추는 관계 위반으로 실패했다. 쪽번호의 소유·순서·
누락/중복과 원본 정지에 대한 끝점 관계를 보호하며 과거의 잘못된 위치를 고정하지 않는다.

실제 Native 진단에서 원본 정지를 소비하면 280쪽 미대응 164→0픽셀이다.
저장 전진 폭을 그대로 소비한 별도 진단도 같은 결과다. 임시 분기 변경의 첫 후보는
canonical TabLeader와 불일치해 재생 검증에서 거부됐으며, 그 오류는 output에 보존했다.
수정한 진단은 TextRun과 대응 TabLeader를 함께 다루고 원본 파일을 바꾸지 않았다.
이 진단을 제품 변경의 수정 후 통과로 계산하지 않는다.

기존 PR #1021과 Task #874, 공통 통합 `b9075217cc`를 확인했고
정오표 30절과 기존 문제 해결 문서의 일괄 셀 우단 설명도 반례에 맞게 정정했다.
공식 사양의 오류라고 주장하거나 원문 사양을 바꾸지 않았다.

수정 source `8244f3455bc431b791a42ebb94763611bac53b2d`의 Native 빌드는
잡 8개·고정 `target/pr-review`에서 exit 0·368.24초였다. 같은 SHA의 정식 2건이
통과했고, 기존 대조군과 intrarun bbox·중간 탭·자리표·HWP3 저장 탭 폭·TAC 정렬을
포함한 **124건 모두 통과**했다. 실제 실행 목록과 최종 summary를 보존했다.

Native 영향 84조건과 전쪽 766쪽을 실제 재출력했다. 두 원본의 280쪽만
미대응 **164→0픽셀·raw100**으로 바뀌었고 다른 764쪽의 미대응 수는 같다.
766쪽의 텍스트·소유·순서도 같으며 원본/PDF/PNG 해시를 검증했다.
두 형식의 실제 review PNG를 열어 쪽번호와 리더·본문·표 외곽을 직접 대조했다.

| Native 입력 | 100%·미대응 0인 쪽 | 최저 raw | 전체 미대응 픽셀 |
| --- | ---: | ---: | ---: |
| HWPX | 345/383 | 99.46283% | 1,437 |
| HWP | 342/383 | 99.46283% | 1,453 |

현재 source의 표준 최적화 fresh WASM 검증은 진행 중이다. 마지막으로 양쪽 backend의
전쪽을 모두 확인한 source는 `c3b88a07df`이며 그 source는 1,532조건 중
1,368조건이 raw100·미대응 0이다. 서로 다른 source의 수치를 합쳐 현재 source의
완료 건수로 보고하지 않는다. 전체 목표와 필수 전체 테스트·PR 준비는 아직 완료 전이다.
작업 로그와 원문은 ignored
`handbook-intrarun-right-tab-candidate/` 및 `remaining-raw100-diagnostic/remaining-direct-current/`다.

전체 서식 검사는 생성 harness의 삭제된 검사 참조 때문에 실패했다. 정본 생성기로
현재 원본 목록을 준비했으나 integration target 예산 50>48에서 harness 재생성이
거부됐다. 변경한 코드의 별도 rustfmt 검사는 통과했지만 전체 서식·suite 정책 검사를
통과했다고 계산하지 않는다. 삭제한 검사를 복원하거나 정책 한도를 늘려 우회하지 않으며
최종 전체 검증 전 수집 경로와 실제 target 구성을 확인해 해결해야 한다.

첫 제품 빌드 `b64342407e`는 helper 호출의 `tab_w` 스코프 오류로 exit 101이었다.
이 오류를 보존하고 helper가 기존 `style_params`에서 같은 기본 탭 폭을 직접
소비하도록 수정했다. 컴파일 실패를 검사 실행이나 제품 통과로 계산하지 않는다.
