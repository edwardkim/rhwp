# `text_overlap` 래칫 조이기 — 원장 4,322 → 3,543 (#7226 곁가지)

`tests/cases/text_overlap_baseline.rs` 가 스스로 선언한 절차를 실행한 기록이다.

> 0 이 아닌 문서만 `상대경로\t건수` 로 사전순 기록한다. **감소는 통과**이므로,
> 결함을 고쳤으면 dump 로 확인한 뒤 래칫을 조인다.

`#6976`(PR #7252)이 형제 래칫 `body_overflow` 에서 같은 일을 하며 *"같은 모양을 형제
래칫에서도 의심하라"* 고 남겼다. `text_overlap` 도 열린 뒤 조인 적이 없어 원장의 5분의 1이
실측보다 컸다 — 그만큼이 새 회귀를 조용히 흡수하는 여유로 남아 있었다.

`4.3.1` 의 조건 *"리베이스 없이 감소분으로 래칫을 조이지 않는다"* 를 충족한다 — 측정과
제출의 base 가 같은 커밋이다.

원장 168행 **전부 렌더에 성공**했다. 게이트의 `missing` 검사(baseline 행의 문서가 선택된
partition 에 있는데 결과에 없으면 실패)가 통과했으므로, dump 에 없는 행은 "못 읽어서 빠진 것"
이 아니라 **실측 0** 이다. `count_doc` 도 렌더 실패를 `None` 으로 돌려 0 으로 위장하지 않는다.

⚠ 처음 `cargo test --test regression_suite_025` 로 돌렸을 때 **0건 실행·exit 0** 이 나왔다 —
`--sync` 뒤 이 게이트의 배정이 `regression_suite_004` 로 바뀌어 있었다. 위 표의 이름 필터
(`-E 'test(...)'`)가 배정과 무관하게 도는 형태다.

## 유보 2행 — 로컬 실측을 상한으로 쓸 수 없는 문서

`2025 행정업무운영 편람(최종).hwp` / `.hwpx` 는 **조이지 않고 기존 21 을 유지한다**(실측 각 20).

`#6325` 가 이 문서에서 환경 분기를 실측했다 — 같은 커밋·같은 피처인데 69쪽 표 높이가
로컬(Windows) 248.547 vs CI 352.013 으로 **+103.47px** 벌어지고, 같은 쪽 `overflow` 가
로컬 2 vs CI 4 였다. 페이지·본문 상자는 비트 동일이라 부동소수 잡음이 아니며, 원인 규명
없이 닫혔다. 이 문서에서는 로컬이 CI 보다 **적게** 세므로 로컬값을 상한으로 쓰면 CI 를 깬다.
`#7252` 도 같은 이유로 이 2행을 유보했다.

나머지 114행의 환경 분기는 로컬에서 알 수 없다 — **PR 의 CI 가 검증이다.** CI 가 더 크게
재면 그 값으로 올려 적는다(게이트가 실패 시 현재값 전체 TSV 를 찍어 두는 것이 그 용도다).

## 왜 완화가 아닌가

이 변경은 baseline 의 모든 행을 **내리기만** 한다. 올린 행·새로 실은 행은 0 이다.
래칫의 판정(신규 발생·증가만 실패)은 그대로이고, 천장이 실측에 붙으면서 지금까지
여유 안으로 숨을 수 있던 회귀가 **다음 PR 부터 즉시 실패**한다.
