# #8153: 그림 저장 행의 활성 셀 여백

[계획](../plans/issue_8153_inline_picture_row_frame_20261026.md)의 원본 HU와
독립 Print를 근거로 기존 닫힌 행 생산자의 컨트롤 검증을 확장했다.
글자처럼 그림은 기존 줄 구성의 점유 높이를 재사용하고, 실제 저장 UTF-16 소속 줄에서
최대 점유 높이가 저장 줄 높이와 같아야 한다. 단 정의는 비흐름 상태로 구분하고
캡션·부동 개체·다른 종류의 컨트롤은 이 인증에서 제외한다. 기존 편집·합성 줄 거부,
행/열 덮임과 정수 HU 전체 프레임의 정확한 닫힘 조건을 유지한다.
측정과 실제 배치는 기존 공통 행 결과를 소비하며 폴백 공차를 바꾸지 않았다.

정식 원본 검사는 `tests/cases/issue_8153_inline_picture_row_frame.rs`의 2건이다.
원문 SHA-256은 `61ed98edf3330212787f574713ecd9bb551a0c892fc77aba56b5897a5655afe5`다.
수정 전 e496770a7d의 실제 라이브러리에서 빌드 exit 0·실행 exit 101이며,
두 형식 모두 수신 baseline 311.713333px가 독립 기준 315.359985px ±2px를 벗어나
실패했다. 최초 작성 때 셀 내부 문단 인덱스를 바깥 문단 인덱스로 오인한 검사를
실제 CellContext의 전체 경로로 바로잡은 뒤, 같은 원문의 실제 baseline 실패를 확보했다.
새 코드의 수정 후 실행·영향 페이지·전쪽 검증은 아직 완료 전이다.

첫 후보 ca25c70861은 Native 빌드 6분 8초·exit 0이지만 정식 2건은 같은 baseline에서
여전히 실패했다. 후속 단계는 이 실패를 감지해 실행하지 않았다. 실제 원본 IR을 덤프하니
로고 문단은 `ColumnDef(column_count=1)`와 함께 `column_type=MultiColumn`이었다.
원본 XML의 명시적 `columnBreak=0`과 한 단 정의, 기존 한 단 프레임 소비 로직도 대조했다.
모든 단 정의를 실제 단 나눔으로 보는 기존 진입 조건이 인증을 먼저 거부한 것이다.
한 단 정의와 실제 다단/쪽 나눔을 구분하도록 같은 검증 함수에 통합하고, 다단 정의는
계속 거부한다. 원본 저장 줄의 단조성·정확한 전체 프레임 닫힘은 그대로 확인한다.
원본 검사 원문은 변경하지 않았고 새 후보에서 다시 실행한다.

검사는 실제 쪽의 중첩 표·그림·활성 여백·원본 전체 높이, 수신/경유의 원본 셀 소유,
글줄의 셀 포함·순서·누락·중복·후속 제목을 함께 보호한다. 기존 110건과 닫힌 텍스트
행·그림 소유 대조도 다시 실행한다. 임시 proof·로그·PNG는 ignored 작업 루트의
`handbook-inline-picture-row-candidate/`에 둔다. 전쪽 100%·최종 검증·PR 준비 완료를
이 구현 커밋의 성공으로 대신하지 않는다. upstream 동기화와 원격 쓰기는 하지 않는다.
