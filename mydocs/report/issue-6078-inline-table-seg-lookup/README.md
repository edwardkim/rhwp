## 근인 — 하드코딩된 seg 순서 가정

인라인 표 문단 레이아웃이 `line_segs[0] = 표 줄`, `[1] = 텍스트 줄` 을 **가정**한다
(코드 주석에도 그렇게 적혀 있다). HWP3 국세청 서식은 반대로 저장한다.

```
pi=0  ls[0] vpos=0     lh=1300   ← 제목 텍스트 줄 [별지 제96호의2서식]
      ls[1] vpos=1300  lh=67616  ← 표 줄 (표 h=65484)
```

그래서 `￼` 자리표시 조각이 **표 줄의 baseline**(`bl=57473HU = 766.3px`)을 텍스트 줄
높이로 받아 문단 바닥을 표 높이만큼 한 번 더 밀었다.

## 판별은 기하로

표가 실제로 속한 seg 를 **줄 높이로** 고른다 — `line_height >= 표 선언 높이` 인 첫 seg.

`control_line_seg_index` 를 먼저 써 봤으나 **선행 컨트롤에서 0 대신 1** 을 돌려준다:
컨트롤이 문자 0 이고 첫 글자 offset 이 8 이면 `p >= start_txt` 가 `0 >= 0` 으로 참이
된다. 그 오답으로 `정책연구용역사업 중간진도보고서`(pi=428, 표 h=13956 이 ls[0]
lh=16086 에 담김)가 되레 2줄 밖으로 나갔다. 그 함수는 다른 계약(#4531·#4622)이 쓰므로
건드리지 않고 이 자리의 선택만 기하로 바꿨다.
