## 근인

`layout_table_item` 의 TAC 재등록 분기는 "앞선 TAC 가 흐름을 진행시켰으면 글줄을 그
자리로 옮긴다"는 규칙이다. 그런데 이 문단에서 흐름을 진행시킨 것은 TAC 가 아니라
**양수 세로 오프셋을 가진 자리차지 그림**이다.

```
문단 43  ls[0] vpos=0  lh=2831(37.7px)      ← 글줄은 문단 상단
  [0] 그림  tac=false wrap=자리차지 vert=Para(off=3518 = 46.9px)
  [1] 표 1×3 "붙임2 | 행사 포스터"  treat_as_char=true   ← 그 글줄에 놓인다
```

오프셋(46.9px)이 글줄 높이(37.7px)보다 크므로 한글은 그림을 그만큼 내려 그리고 그
위에 글줄을 그대로 둔다. rhwp 는 그림이 밀어 올린 흐름으로 TAC 글줄을 재등록해
글줄을 그림 아래(용지 밖)로 보냈다.

## 판별과 범위

판별은 기하로 둔다 — **앞선 자리차지 float 의 양수 세로 오프셋 ≥ host 글줄 높이**일
때만 글줄을 문단 상단에 남긴다. 저장 사다리도 같은 말을 한다(`vpos=0`).

오프셋이 글줄 높이보다 작으면(개체가 글줄과 겹치도록 놓이면) 종전대로 글줄이 개체
뒤로 간다 — #2813 이 다루는 "앵커 줄이 스택 아래를 인코딩" 형상이 그쪽이다.

글줄만 위로 올리고 **흐름 커서는 그림 아래를 유지**한다(호출 뒤 복원) — 뒤따르는
내용이 그림 위로 딸려 올라오지 않게.
