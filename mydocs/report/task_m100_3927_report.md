한컴 2020 PDF의 물리 쪽 경계를 잘못 읽은 결과이므로 폐기한다. PDF p287에는 첫 문단 12줄,

## 진단 경로 — 정정 2회

착수 가설이 두 번 뒤집혔다. 기록해 둘 가치가 있다.

1. **"한컴이 분할했는데 rhwp 가 통짜 이월"** → ✗. 저장 하단 719.1px < 가용 740.8px 이라
   한컴은 통째로 넣었다. pi=24 의 되감김은 24 자신의 쪽 시작일 뿐인데 23 의 분할
   증거로 오독했다.
2. **"선언 394.4px 가 정답, rhwp 가 1.41배 과대"** → ✗. 저장 셀 h·행 높이는 **편집기
   저장 시점 스냅샷**이다(셀[11] 선언 39.3px 에 16줄 392px 이 들어 있다). 한컴은 조판
   때 내용에 맞춰 재계산한다.
3. **PDF 실물 bbox 측정** → ✓. 한컴 표 389.1px / 답변 본문 301.2px, 줄 수 16.

**교훈: 저장값은 오라클이 아니라 스냅샷일 수 있다.** 내용 재계산 대상(셀 내부)에서는
저장 높이 대조가 무효이고, 정답지 PDF 의 실물 bbox 만이 오라클이다. 시각(p287 육안)이
"한컴도 행을 키운다"를 확인해 준 것이 2차 정정의 결정타였다.

## 가설 — 160% 이중 적용

셀 문단 저장: `lh=1150HU(15.3px)`, `vpos` 간격 `1838HU(24.5px)`. rhwp 는 vpos 간격을
줄 높이로 쓰고, `24.5 = 15.3 × 1.60`(셀 문단 `line=160/Percent`). 한컴 실측
18.8 ≈ `15.3 × 1.23`. → 이미 반영된 값에 160% 를 다시 적용하는 형태.
