## 2. 조사 경과 및 검증

### 2.1 SVG 출력 (rhwp export-svg)
- 대상 문단: `P(X̄=11/4)=(8+72+24)×(1/6)⁴=104/6⁴=13/162` → 다음 줄 `따라서 p=162, q=13이므로`
- **HWPX·HWP 양쪽**, 고해상도(z3) 렌더에서 `13/162` 분수와 `따라서` 줄이 **정상 분리**. 겹침 없음.
- 한글 2022 PDF 정답지(`pdf/3-09월_교육_통합_2022.pdf` 17쪽)와 정합.

### 2.2 코드 분석 (SVG ↔ 캔버스 동등성)
- 수식 배치 정책: `svg.rs:476`과 `web_canvas.rs:848` **모두 `scale_y = 1.0`** (식을 bbox 높이에 세로 압축하지 않고 EqLayout 자연 높이로 배치).
- 글리프 배치: `render_equation_canvas`(canvas_render.rs)는 `fill_text(text, x, y+baseline)`로 `render_equation_svg`와 **동기화**(코드 주석상 Issue #900 동기화 명시).
- 렌더 트리(bbox)는 두 백엔드가 **공유** → 동일 좌표. 따라서 SVG가 정상이면 캔버스도 정상이어야 함.

### 2.3 studio 캔버스 실측 (재현 시도)
- WASM 재빌드(`docker compose run --rm wasm`, v0.7.14) 후, vite + headless Chrome로 studio 구동.
- 문서 로드 23페이지, 상태표시줄 "17 / 23 쪽" 확인.
- 페이지 17 [다른 풀이] 전체 캡처 → `P(X̄=11/4)=…=13/162` 와 `따라서 p=162` **정상 분리**. **겹침 재현 안 됨.**

### 2.4 버전 교차 확인
- `local/devel`이 devel보다 크게 뒤처짐(local/devel=**v0.7.9**, devel=**v0.7.14**). 작업 브랜치를 devel 기반으로 rebase.
- v0.7.9로 빌드 시 본 문서는 **9페이지**로만 파싱됨(미주 페이지네이션 미구현) → 17쪽 자체가 없음. 즉 사용자가 본 화면은 v0.7.9가 아닌, 그 이후~수정 이전 시점의 빌드.
