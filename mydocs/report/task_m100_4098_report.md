## 1. 한 줄

레거시 `VtDataGrid` 를 **값이 아니라 구조로** 읽게 바꿔, 소수 값을 못 읽던 결함과 그리드
순서를 고정 가정하던 결함을 없앴다. 실측 중 **이슈에 없던 세 번째 결함**(라벨 digit
휴리스틱)이 단독으로 코퍼스 전건을 차단하고 있어 함께 고쳤다.

## 2. 이슈 대비 달라진 전제

이슈와 `task_m100_4055_stage1.md` §2 는 그리드 구조를 **행 pitch 로 추론**해야 한다고 봤다
(117 vs 141, "전역 stride 를 가정하면 안 된다"). 실측해 보니 추론할 필요가 없다 —
`VtDataGrid` 프롤로그의 `VtObject` 가 `<u16 ROWS> <u16 COLS>` 를 명시하고, 셀마다 1-based
행우선 인덱스를 싣는다. 대조군에서 `(5,4)` 를 읽고 index 6 → `(r1,c1)` = 적립금/2010년 =
`328.0` 으로 교차 검증했다. 코퍼스 28종 전건에서 `(R-1)×(C-1) == f64 개수` 가 성립한다.

`task_m100_4055_stage1.md` §2 의 pitch 관찰은 여전히 사실이지만 더 이상 판정 근거가 아니다.

## 4. 설계 — 모양 권위의 역전

**① `VtObject` 치수가 모양 → ② 셀 인덱스가 배치 → ③ 라벨은 이름일 뿐.**

예전에는 라벨 분류가 `expected_values` 를 정했기 때문에 라벨을 잘못 가르면 값 탐색까지 같이
틀렸다. 이제 라벨은 개수에 관여하지 않는다. 라벨이 없어도 파싱은 실패하지 않는다 —
계열명은 `None`, 카테고리는 1-based 서수로 채워 `categories.len()` 이 데이터 치수와
어긋나지 않게 한다(렌더러가 카테고리 개수로 축을 잡는다).

- `src/ole_chart/grid.rs` (신규) — 구조 스캐너. 수치는 `FF FF 06 00 00 00` 구분자로, 문자는
  형상으로 찾고 **양쪽 다 12바이트 헤더를 되읽어 `typeId` 로 확인**한다.
  `GridValue::Number { value, offset }` 이 8바이트 in-place 패치 주소를 보존한다 —
  레거시 값 쓰기(#4100 후속)의 선행 조건이다.
- `src/ole_chart/orientation.rs` (신규) — `decide_series_axis`.

## 5. 방향 판정 — 오라클 없이 29/29

#4055 의 `classify()` 는 OOXML 정답지와 대조하는 오라클이라 레거시 단독 문서에 쓸 수 없다.
대신 그리드 창 **뒤**의 계열·범례 구간에 계열 이름 `VtString` 레코드가 바이트 그대로
재등장하는 성질을 쓴다(카테고리는 재등장하지 않는다).

`한 축 라벨 전부 재등장 && 반대 축 불완전` → 그 축이 계열 축.
**가납 조건: 데이터 행·열이 둘 다 2 이상.**

두 세부 규칙은 실측이 강제했다.

- **가납 조건은 필수다.** 원형 5건은 범례가 슬라이스(=열)를 나열해 `열 4/4 · 행 0/1` 이다.
  가납 조건이 없으면 이 10건(2포맷)을 **정확히 반대로** 판정한다.
- **"반대 축 0" 이 아니라 "불완전"** 이어야 한다. 대조군은 카테고리 `2040년` 이 오탐으로
  재등장해 행 echo 가 1/4 다.

정사각 그리드(`시가고가저가종가`, 데이터 4×4)도 `행 4/4 · 열 0/4` 로 모호하지 않게 풀린다.

### 가납 실패 시 fail-closed 를 쓰지 않은 이유

관례(행=계열)로 접고 `SeriesAxisEvidence::Inconclusive` 를 IR 에 실어 **추정임을 밝힌다.**
저장소 선례가 fail-closed 를 지지하지 않는다.

1. INV-05 · `detection_policy.md` ④ — 금지되는 것은 *추정을 추정이라 밝히지 않는 것*이지
   추정 자체가 아니다.
2. [`task_m100_4100_report.md` §3-3](task_m100_4100_report.md) — 메인테이너 자기정정:
   > 보수적 선택 자체는 맞지만 **범위가 틀렸다** — 거부는 그 점의 *쓰기*에 걸려야지 문서
   > 전체의 *읽기*에 걸리면 안 된다.
3. `src/ooxml_chart/data.rs` — "스캐너는 표지만 세우고 판단하지 않는다".

방향 모호는 **값이 아니라 이름·묶음**의 문제다. 값은 어느 쪽이든 같다. 게다가
`shape_layout.rs` 의 `Err` 갈래도 `rendered = true` 를 세워 하류 EMF·WMF 폴백을
단락시키므로, 파서가 거부를 넓히면 지금 렌더되는 문서가 주황 placeholder 로 떨어진다 —
수용 기준 4 위반이다.

모양 자체를 못 믿는 경우(프롤로그 불일치·인덱스 중복/범위 밖·수치 개수 불일치)는 그대로
`Err` 로 닫는다. 그건 이름이 아니라 모양의 문제이고, 오늘도 이미 placeholder 로 가는 입력이다.

### 육안 증거

결함은 **정상 문서에서 보이지 않는다** — 렌더러가 OOXML 을 먼저 이기고, 레거시 단독 대조군은
결과가 바뀌면 안 되는 문서다. 중첩 CFB 에서 `OOXMLChartContents` 만 걷어내 레거시 경로를
강제한 변종으로 대조했다(`generate_legacy_only_variant`, 산출물 `output/issue-4098/`).

| | 결과 |
|---|---|
| 변경 전 | 주황 placeholder — `OLE 차트 미지원: legacy HWP chart data grid labels are incomplete (BinData #1)` |
| 변경 후 | 3계열 × 4카테고리 막대차트, 막대 높이가 값에 정확히 비례(계수 37.6) |

변경 전 실패 사유가 `labels are incomplete` 라는 점이 3번째 결함이 선행 차단 요인이었다는
직접 증거다.

## 7. 중복 제거

`OBJECT_MARKERS` 가 3벌이었다. `grid.rs` 단일 사본으로 접고 `parser.rs` 는 위임한다.
`tests/support/issue_4055_chart_probe.rs` 의 `locate_grid_values` 도 프로덕션에 위임해서,
**#4055 의 코퍼스 테스트가 자동으로 프로덕션 게이트가 됐다**(56/56).

단 `VALUE_TRAILER`·`DOUBLE_MARKER` 와 `Orientation`/`classify`/`ground_truth` 는 남겼다 —
의도적으로 무제한인 대조 스캔과 OOXML 오라클은 **독립 채점자**이고, 채점자를 피채점자에게
위임하면 판정이 동어반복이 된다(`root_clsid` 가 세운 관례).

## 8. 알려진 한계 (범위 밖)

- `OleChartType` 은 여전히 `Unknown` 고정이다. 종류 판별은 별건이고 #1251 골든과
  `svg_renderer` 의 `Line` 분기가 여기 걸려 있다.
- 음수 값은 렌더러에서 높이 0 막대가 된다(`svg_renderer.rs` 의 `value.max(0.0)`). 기존
  한계이고, 파서가 값을 정확히 싣게 된 것이 이 문제를 다루기 위한 선행 조건이다.
- 결측 셀 그리드는 `NumberCellCountMismatch` 로 닫는다. 코퍼스 실측 0건. 실제 사례가 나오면
  `0.0` 채움 + 표지가 대안이지만, 레거시 쓰기가 모양을 잘못 읽은 그리드를 지목하면 안 되므로
  지금은 열지 않는다.
- 레거시 단독 문서의 한컴 렌더 대조는 여전히 미실시다(#4055 보고서 §7과 동일). 이 PR 은
  레거시를 **읽기** 정확도만 다룬다.
