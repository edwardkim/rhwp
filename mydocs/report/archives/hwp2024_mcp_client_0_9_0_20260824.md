# Windows HWP MCP client 0.9.0 생성 결과

## 목적

`hwp-convert-2024`의 통합 Windows 변환 service가 지원하는 engine `2020`·`2024`와 암호 문서 계약을
rhwp 작업 PC에서 사용할 수 있도록 dependency-free HTTP MCP client artifact를 갱신한다. client는 변환
엔진이나 한컴 DLL을 포함하지 않고 local input blob 업로드, 비동기 job 호출, result blob 검증과 local
저장만 담당한다.

작업 기준은 `hwp-convert-2024@c18f2d2`와 `rhwp upstream/devel@4e070c632`다. 실제 server URL과 token,
문서 암호는 artifact, 문서, 명령 출력과 Git 변경에 포함하지 않았다.

## 기존 artifact 분석

기존 `0.8.0` client는 Node.js 표준 라이브러리만 사용하는 경량 구현이며 SDK·Zod·`node_modules`가 없었다.
동기 변환과 비동기 `start → status → download`, byte 수·SHA-256 검증은 이미 지원했다. 그러나 모든 요청을
2024 기본 파일명으로 만들었고 다음 현재 server 입력을 노출하지 않았다.

- `engine: 2020|2024`
- 선택적 문서 `password`
- engine `2020`의 기본 `-hwp2020` 파일명

## 변경 계약

- package version을 `0.9.0`으로 올렸다.
- MCP tool 4개의 변환 schema에 `engine`과 `password`를 추가했다.
- 기본 engine은 `2024`이며 `2020`을 선택하면 기본 출력 파일명에 `-hwp2020`을 사용한다.
- CLI에 `--engine 2020|2024`를 추가했다.
- CLI 암호는 command line 값이 아니라 현재 사용자만 읽을 수 있는 단일 행 `--password-file`에서 읽는다.
- 암호는 변환 시작 remote argument에만 포함하며 client 결과 JSON과 job 상태에는 넣지 않는다.
- MCP transport, Base64 blob, atomic publish와 SHA-256 검증은 기존 경량 구현을 유지했다.
- 외부 npm runtime dependency와 `node_modules`는 추가하지 않았다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| 세 `.mjs`의 `node --check` | 모두 exit code 0 |
| archive를 지정한 `npx ... hwp2024-mcp-convert --help` | exit code 0, `--engine`·`--password-file` 노출 |
| stdio initialize / `tools/list` | version `0.9.0`, tool 4개 |
| tool schema | engine enum `2020,2024`, 선택적 password 존재 |
| 외부 import / dependency / `node_modules` | 모두 0개 |
| engine `2020` request 준비 | remote engine `2020`, 기본 `-hwp2020.pdf` 확인 |
| 실제 archive CLI → local mock HTTP MCP 비동기 시작 | `queued`, 유효 UUID, engine `2020` |
| 비공개 암호 파일 전달 | mock server에서 일치 확인, result key는 `engine,job_id,status`만 존재 |
| 변경 Markdown 링크 검사 | exit code 0, 이상 없음 |
| 변경 장기 문서 6개의 metadata 검사 | 오류 0건 |
| Rust suite manifest prepare/check | exit code 0 |
| `cargo fmt --all` / `cargo fmt --all -- --check` | 모두 exit code 0 |

local mock은 실제 MCP initialize, initialized notification, `tools/call`, session DELETE 순서를 처리했다.
이 검증은 client의 wire contract와 비노출을 확인하지만 배포 server의 새 source 반영 여부까지 증명하지는
않는다. 배포 후에는 비공개 환경 파일로 engine별 실제 동기 smoke와 비동기 start/status/download를 각각
실행하고 client/server byte 수·SHA-256, `engine_profile`, `hancom_version`을 추가 확인해야 한다.

전체 저장소 metadata 검사는 이번 변경과 무관하게 최신 `upstream/devel`에 이미 있던 `mydocs/tech` 4개
문서의 front matter 누락 16건을 보고했다. 변경한 장기 문서 6개를 같은 validator로 별도 검사한 결과는
오류 0건이다. 기존 누락 문서는 이 client 작업에서 수정하지 않았다.

## 문서 전환

신규 변환은 단일 `hwp-convert-2024` client를 사용한다. 마지막 저장 제품이 2022 이하이면 engine `2020`,
2024이면 engine `2024`를 선택한다. 별도 Linux HWP 2020 beta client 문서는 `superseded`로 전환하되 이전
운영 이력 재현을 위해 파일과 구형 artifact는 보존한다.
