## 6. 80쪽+ 코호트 해부

실패 619건의 구조를 분석했다.

### 6.1 실패는 대형 문서에 몰린다

| 문서 규모 | 문서 수 | 실패 | 실패율 |
|---|---|---|---|
| 1–5쪽 | 8,367 | 174 | 2.1% |
| 6–20쪽 | 1,022 | 141 | 13.8% |
| 21–80쪽 | 317 | 130 | 41.0% |
| **80쪽+** | **199** | **174** | **87.4%** |

델타의 75%가 ±1쪽(+1 214건, −1 79건).

### 6.2 누적 드리프트가 아니다

80쪽+ 실패 174건의 **첫 어긋남 위치**:

| 총쪽 대비 위치 | 건수 |
|---|---|
| **0–20%** | **117 (67%)** |
| 20–40% | 32 |
| 40–60% | 12 |
| 60–80% | 6 |
| 80–100% | 7 |

중앙값 13% — 문서 앞부분에서 이미 갈린다. 오차가 쌓여야 나타나는 드리프트라면 중후반에
첫 어긋남이 나야 한다. 다만 |델타|는 길이에 비례해 커진다(81–150쪽 1.29 → 151–300쪽 1.61
→ 300쪽+ 3.12), 즉 **앞에서 갈린 뒤 뒤에서 추가로 더 갈린다.**

### 6.3 오차는 서로 상쇄된다

대표 문서(166 vs 165쪽) 실측:

```
pi19   rhwp_p1  hwp_p2   delta -1
pi447  rhwp_p31 hwp_p32  delta -1
pi496  rhwp_p37 hwp_p38  delta -1
pi534  rhwp_p44 hwp_p43  delta +1   ← 방향 전환
pi541  rhwp_p45 hwp_p44  delta +1
```

문단 762개가 어긋나는데 최종 쪽수 차이는 +1이다. **앞에서 당기고(−1) 뒤에서 밀려(+1)
대부분 상쇄된다.** 첫 어긋남 방향은 전체적으로 당김 우세(114 : 60).

쪽 1–4는 한글 정답지와 내용이 일치하며, 초반 어긋남은 **쪽 경계의 빈 문단** 문제다.

### 6.4 수치 향상 관점의 함의

- 80쪽+ 199건을 전부 고쳐도 **+1.8pp 가 상한**이다(93.75 → 95.5).
- 1–5쪽 문서 8,367건은 이미 97.9%로 짜낼 여지가 거의 없다.
- 실패가 **여러 국소 오차의 잔차**라, 하나를 고치면 상쇄 균형이 바뀌어 다른 문서가
  나빠질 수 있다. 이는 [#2279 캠페인]이 "전 축 knife-edge" 로 종료된 구조와 같다.

**결론: 국소 레버로는 접근이 어렵다.** 유의미한 향상은 세로 공간 계산 전반을 다시 세우는
수준이어야 하고, 그 경우 3중 게이트(92셋 + 10k + 시각)가 필수다.

## 7. 하니스 운영 기록

같은 실수를 반복하지 않도록 남긴다.

| 증상 | 실제 원인 |
|---|---|
| 4,601행 전부 STALL | `verify_combined.py` 미복사. 러너가 "파일 없음"이 아니라 **watchdog STALL 로 보고**해 원인이 가려졌다 |
| `--start 0 --end 0` 즉시 완료 | `--end` 는 **배타적**(`start <= idx < end`) |
| ERR 140건 | Bash 10분 상한에 걸려 죽인 실행의 부산물. 단독 재현 시 rc=0 |
| ERR 84건(본 실행) | 미지원 포맷 코호트. **r25 바이너리도 동일하게 실패** — 회귀 아님 |
| "PI 정합 계속 하락" | 기준선과 **다른 공식**을 씀(분모에 ERR·STALL 포함, 분자에서 CARET 제외). 기준선 정의를 역산해 확인했어야 했다 |
| "표지 쪽 누락" | `export-svg -p` 가 **0 기준**. rhwp 2쪽을 한글 1쪽과 비교한 허상 |

착수 전 **청크 1개를 완주시켜 분포를 확인**한 것이 위 문제들을 본 실행 전에 걸러 냈다.
