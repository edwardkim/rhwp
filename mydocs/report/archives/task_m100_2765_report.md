# 최종 결과 보고서 — Task M100 #2765

## 이슈

HWP3 파서가 특수문자 코드 **25(제목/표/그림차례 표시, 한글문서파일구조3.0 §10.19)** 를 코드
**24(하이픈, §10.18)** 와 동일한 match arm 으로 처리하여, 비가시(invisible) 차례(TOC) 항목
표식 자리에 하이픈 글리프 `'-'` 를 잘못 삽입. 차례 표식이 붙은 제목 문단의 본문 텍스트가 오염됨.

- Issue: https://github.com/edwardkim/rhwp/issues/2765
- PR: (본 보고서 하단 참조)

## 결론

`parse_simple_control_char()` 의 `24 | 25 =>` arm 을 **코드 24 전용**과 **코드 25 전용**으로
분리했다. 두 arm 모두 6바이트(3 hchar)를 동일하게 소비하되, 코드 24는 하이픈 글리프 `'-'` 를
방출하고 코드 25는 비가시 표식이므로 **아무 글리프도 방출하지 않는다**. 바이트/hchar 소비량이
불변이라 후속 문자 정렬·char_shape 위치가 유지되며, `char_offsets.len() == text.chars().count()`
불변식도 보존된다.

이는 추론이 아니라 **한컴 HWP5 변환본 정답지 대조로 실측된 손실**이다. `hwp3-sample10.hwp` 에서
이 결함 하나로 289개 제목 문단이 정답지와 어긋났고, 수정 후 소거되었다.

## 결함 상세

### 결함 위치 — `src/parser/hwp3/mod.rs` `parse_simple_control_char()` (수정 전 라인 1740)

```rust
24 | 25 => {
    let mut buf = [0u8; 4];
    ...
    i += 2;
    char_offsets.push(utf16_len);
    utf16_len += 1;
    text_string.push('-');   // ← 코드 25(차례 표식)에도 하이픈이 삽입됨
}
```

- **코드 24 (§10.18 표 59, 하이픈):** 실제 하이픈 글리프. `'-'` 방출이 **정당**.
- **코드 25 (§10.19 표 60, 제목/표/그림차례 표시):** 비가시 표식. offset 2 의 hunit
  (0=제목차례/1=표차례/2=그림차례)만 갖는 마크로, 글리프가 없다. `buf` 는 읽기만 하고
  해석되지 않으며(종류 필드 폐기), 없어야 할 하이픈을 방출.

### 대조 (형제 arm)

같은 함수의 코드 26(찾아보기 표식)·28(개요)은 비가시 표식으로서 `'-'` 가 아닌 `'\u{FFFC}'` 를
방출하고 `Field` 컨트롤을 남긴다. 코드 25만 하이픈 arm 에 잘못 묶여 형제 처리와 어긋나 있었다.
이 `'-'` 방출은 초기 구현(`675354e8`, Task #417) 이래 한 번도 분리되지 않았다.
