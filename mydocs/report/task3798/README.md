# #3798 쪽 끝 말미 줄간격 스필 — 한도 형태 반증 증적

**결론: 수정을 제출하지 않는다.** 근인 기술은 유효하지만, 한글 정답지를 지키는 한도
창(12~18px) 안에서 순이득이 음수다. 이 문서는 다음에 이 축을 여는 사람이 처음부터
다시 재지 않도록 측정과 반증을 남긴다.

- 측정 기준 devel: `0889974a0`
- 표본·계약: `samples/issue3798/page_end_trailing_spill.hwpx`,
  `tests/issue_3798_page_end_trailing_spill.rs`(계약 테스트는 `#[ignore]`),
  생성기 `tools/make_issue3798_fixture.py`
- 게이트 하니스: `tools/gate_3798_page_end_spill.py`
- 실험 패치: `trimcap_experiment.patch` (아래 §4 의 판별자까지 반영된 최종형)
- 측정 원자료: `data/`


## 1. 근인 (유효)

쪽 마지막 문단의 적합 판정은 말미 줄간격을 뺀 높이(`height_for_fit`)로 한다
[Task #359]. 한글도 쪽 하단을 조금 넘겨 채우므로 방향은 맞다. 그런데 그 트림에
**한도가 없다** — `src/renderer/typeset.rs::paragraph_page_end_fit_height`.

```rust
if require_full_advance { total_height.max(height_for_fit) } else { height_for_fit }
```

그래서 rhwp 는 말미 줄간격 전량(모집단 실측 최대 33.7px)을 쪽 밖으로 흘려보내고,
한글이 다음 쪽으로 넘긴 문단을 현재 쪽에 얹는다. 넘치는 것이 글리프 없는 간격이라
쪽수·텍스트 추출·IR diff·쪽 밖 글자 어느 판별자로도 **침묵한다**. 한글 per-PI 오라클만
잡는다.


## 2. COM 없는 게이트 (재사용 가능)

r29 서베이(`output/poc/survey10k_r29_20260802/results/*.tsv`)의 `detail` 컬럼이 문서마다
어긋난 문단을 `piN rhwp_pX|hwp_pY` 로 적어 뒀다. 그 기록을 정답지로 삼으면 **한글 COM
없이** 이 축을 잴 수 있다.

```
python tools/gate_3798_page_end_spill.py --mode pi    --cap 12
python tools/gate_3798_page_end_spill.py --mode pages --cap 12 --limit 1200
```

- `--mode pi` — `n=1` 코호트(문단 하나만 어긋난 문서) 66건. 그 한 문단을 뺀 나머지 pi 는
  r29 에서 전부 한글과 맞았으므로, 기준선 대비 **다른 pi 가 움직이면 회귀**다.
- `--mode pages` — 쪽 총수. r29 의 `hwp_pages` 가 정답지다.

기준선은 같은 바이너리에 `RHWP_EXP_TRIMCAP` 을 아주 크게 줘 만든다(현행 동작과 동치).
기준선 쪽수가 r29 기록과 다른 문서는 `drift` 로 빼서 devel 이동을 격리한다(이번 측정은
drift 0).

r29 결과물은 `output/`(gitignore) 아래에 있으므로, 저장소만 받은 사람은 서베이 결과
디렉터리를 따로 갖춰야 이 하니스를 돌릴 수 있다.


## 3. 첫 형태(한 줄 문단 한정)가 깨뜨린 것

한도 6px · 한 줄 문단 한정 — 92셋 통제셋은 92/92 로 초록인데 **한글 정답지 테스트
3건이 깨졌다.**

| 테스트 | 정답지 | 실측 |
|---|---|---|
| `issue_2158 … hwp3_sample16_hwpx_matches_hwp5_and_hangul` | 한글 2022 = 64쪽 | 65쪽 |
| `issue_2430_cell_rewrap_threshold_no_oversplit` | 한글 = 39쪽 | 40쪽 |
| `issue_3236 … single_cell_table_content_splits_to_next_page` | 한컴 2020 PDF = 2쪽 | 3쪽 |

**92셋 통제셋은 이 축을 보지 못한다** — 기준선과 한도 6px 모두 92/92 다. 이 축에서
유일한 검출기는 nextest 안의 정답지 테스트들이다. 조판 fit 규칙을 건드리는 수정은
nextest 를 게이트 순서 맨 앞에 두어야 한다.


## 4. 회귀의 실체 — 말미 간격이 스필 폭이 아닌 문단

회귀 문서를 열어 보면 한도가 밀어낸 것은 글월 문단이 아니었다.

```
148719004 10월 재난종합상황 분석 및 전망   기준선 54쪽(한글 54) -> 한도 6px 59쪽
  pi=173  "(빈)"  ls=14.4    빈 문단
  pi=348  그림     ls=88.1    개체 문단
  pi=713  그림     ls=78.4    개체 문단
  pi=714  그림     ls=78.4    개체 문단
```

**개체를 담은 문단의 말미 줄간격은 개체 높이가 부풀린 값이라 스필 폭으로 읽으면 안
된다.** 빈 문단은 넘치는 것이 잉크가 아니라 간격뿐이라 한글도 그대로 둔다.

그래서 판별자를 **개체 없는·글월 있는 한 줄 문단**으로 좁혔다.

```rust
para.controls.is_empty() && para.text.chars().any(|c| c > '\u{001F}')
```

이 하나로 `issue_2430` 이 살아나고(3건 → 2건), 59043 쪽수 핀도 초록을 유지한다.


## 5. 좁힌 판별자의 한도 창과 이득

| 한도 | `issue_3236` | `issue_2158` | #3798 계약 | PI 66건 (해소/회귀) |
|---|---|---|---|---|
| 6 · 8 | FAIL | FAIL | PASS | 8 / 2 |
| 10 | PASS | FAIL | PASS | 5 / 1 |
| **12** | PASS | PASS | PASS | **2 / 0** |
| **14** | PASS | PASS | PASS | **2 / 0** |
| **16** | PASS | PASS | PASS | **0 / 0** |
| 20 | PASS | PASS | **FAIL** | 0 / 0 |

표본이 요구하는 상한은 18.4px(§계약), 정답지가 요구하는 하한은 12px. **창은 12~18px**
이고 그 안에서 문단 배치 이득은 2건까지 줄어든다.

쪽수 축은 더 나쁘다 — 모집단 1200건(한도 12px):

```
해소 0 · 회귀 1 · drift 0
  21221777 …합의체 규칙            2쪽 -> 3쪽   (한글 2)
  3780000-202300008 안전관리 보고서 117 -> 118  (한글 116, 더 멀어짐)
```

**순이득이 음수다.** 문단 배치 +2 를 얻자고 쪽수 −1~−2 를 내주는 거래라 제출하지 않는다.


## 6. 남은 갈래

상수 한도는 닫혔다. 한글이 유지한 스필(14.4·15.0·15.9px)과 넘긴 스필(9.6~14.9px)이
절대값으로 겹치므로, **스필 폭 자체는 지배 변수가 아니다.** 다음에 열 사람이 볼 곳은
문맥 판별자다 — 예를 들어 다음 문단의 첫 줄이 들어갈 자리가 있는지, 또는 그 쪽의
누적 오차(`cur`)가 이미 한글과 벌어졌는지. 이번 이득 문서들이 누적 `cur` 오차를 전량
높이 강요로 우연히 상쇄한 것일 가능성은 여전히 남아 있다
(`typeset-layout-opposite-errors-cancel` 계열).
