# 한글 버전 오라클 r1 정합성 기계 검증 — 2020 기준 정합 확인

- **대상**: [PR #4136](https://github.com/edwardkim/rhwp/pull/4136)의 10k 전수 산출물 전체 —
  [r1 보고서](hangul_version_oracle_r1_20260807.md)(확정 247건 목록·3자 대조·집계 수치),
  [재현 가이드](../manual/verification/hangul_version_oracle.md), 하니스 스크립트 7종.
- **방법**: 사람 눈이 아니라 **기계 검증기**
  [`verify_r1_report_consistency.py`](../../tools/hangul_version_oracle/verify_r1_report_consistency.py)로
  보고서가 스스로 수록한 행 단위 데이터(121+123+3+7+5행)에서 유도 가능한 수치 전부를 재계산해
  본문 주장·가이드·스크립트 계약과 한 번에 대조했다. 한글 설치·코퍼스 없이 돌아간다.
- **결과**: 41건 검사 — 기여자 변경에서 정합 오류 3건을 수정했고(2절), 최신 `devel`의
  §4·§8 정정을 반영한 재검증과 검증기 보정 뒤 **41 PASS · 0 FAIL · 0 CONTRADICTION**이다(4절).
- **2020 기준 정합**: 세 원시 대조(5 / 254 / 258)가 집합 관계가 강제하는 예측 구간과 정확히
  일치한다 — **(254−1) + 4 + 1 = 258** (3절). 확정 247건 목록은 2020 기준으로도 무손실로 쓸 수 있다.

## 1. 왜 기계 검증인가

r1 보고서는 확정 목록 전량(247행)과 3자 대조 데이터를 본문에 수록했다. 즉 본문 요약 수치의
대부분은 **보고서 안의 행 데이터에서 다시 계산할 수 있고**, 사람이 옮겨 적다 생기는 정합 오류를
기계가 전수로 잡을 수 있다. 검증기는 다음을 재계산·대조한다(수치 하드코딩 없이 §4·§5.4·§5.5·§8
표와 본문을 직접 파싱한다).

| 축 | 내용 |
| --- | --- |
| 행 수 | 5.1=121, 5.2=123, 5.3=3, 합 247, 6절=7, 8절=5 |
| 행 단위 산술 | 5.1 전 행 `차이 == 2024−2022`, 5.2/5.3 전 행 좌우 상이 여부 |
| 집계 | 방향(81/40), ±1쪽(87건·72%), 상위 사례(−77/+48/+33/−15), 출처 분포 재집계·본문 대조 |
| 5.5 분포 | HWPX 7행 합=3,418·행별 백분율 전수·70.7%·98.4%(3,362), HWP5 6행 합=6,582·백분율 전수 |
| 검증 산술 | 254=247+2+4+1, 98.8%=247/250, 9,746=10,000−254, 2.47%·0.05% |
| 교차 | 6절↔확정 목록·8절↔6절 비겹침, 8절↔5.1 겹침 문서 값 일치, 8절 재계산 254↔4절 원시 254, CLSID 단일성 |
| 스크립트 계약 | ASCII 전수, `-Workers 1`·`-StallSeconds 300`·`-WarmupDocs 5`·`-HideWindow` 옵트인, `FileShare`, `exit 3`, 두 레지스트리 뷰, 판정 5종(주석 아닌 코드), 워커 TSV 실제 출력 행의 컬럼 순서 |
| 2020 정합 | 3자 대조 집합 경계 검사(3절) |

판정 어휘: **PASS** / **FAIL**(여기서 고칠 수 있는 오류) / **CONTRADICTION**(두 서술의 모순은
저장소 안에서 증명되나 옳은 쪽 판정에 원자료 필요) / QUESTION(저장소 데이터로 판정 불가).

재현:

```bash
python tools/hangul_version_oracle/verify_r1_report_consistency.py
```

종료코드: FAIL 있으면 1, CONTRADICTION만 있으면 2, 전부 PASS면 0.

## 2. 발견하고 수정한 3건

1. **§5.4 본문의 prism 건수 오기 — 141 → 138.** 확정 목록 247행을 출처별로 재집계하면
   `prism_downloads`는 138건이고 §5.4의 표도 138로 맞다. 본문 문장만 141이었다.
   141은 재현 검증 전 원시 254건 기준 수치가 남은 것으로 보인다.
   **PR #4136 본문과 Discussion #4137 본문에도 같은 141이 있어 저자 수정이 필요하다**
   (저장소 밖 텍스트라 이 PR로는 못 고친다).
2. **§5.2 표의 백틱 포함 파일명 렌더 깨짐.** ``…[최종보고서] `20~`21년 업종…`` 행은 파일명 안의
   백틱이 코드스팬을 끊어 GitHub 렌더가 어긋나고, 표를 기계 파싱할 때도 이 행만 이탈한다.
   더블 백틱 스팬으로 감쌌다. 데이터 값은 그대로다.
3. **`scan_appversion.ps1`의 UTF-8 BOM 제거.** 가이드 8절은 "이 폴더의 스크립트는 전부 ASCII"라고
   계약했는데 이 파일만 선두 BOM 3바이트가 있었다(내용은 전부 ASCII). BOM은 PowerShell 5.1
   동작에는 무해하지만 계약과 어긋나므로 제거해 7종 전부 바이트 단위 ASCII로 맞췄다.

## 3. 2020 기준 정합 — 세 원시 대조는 집합 관계대로 맞물린다

8절의 세 원시 대조(2020↔2022 = 5, 2022↔2024 = 254, 2020↔2024 = 258)에는 집합 관계가 강제하는
경계가 있다. `MATCH`는 (Pages, Paras, Fp) 튜플의 완전 일치이고 non-OK는 ERR/MISSING 행으로 diff에
그대로 남으므로(`compare_passes.ps1`), **원시 diff(2022,2024) = 254건 목록에 없는 문서는 2022와
2024 결과가 완전히 같다.** 따라서:

- 2020↔2022 5건 중 **4건은 원시 254(확정 247 + 미확정 7) 밖** → 2022=2024이므로 2020≠2022이면
  곧 2020≠2024. 전부 2020↔2024에 합류한다. (4건이 미확정 7건과도 겹치지 않음은 검증기 R42가 확인.)
- **1건은 겹침** — `korea_policy_downloads\148719004_….hwp`. §5.1(2022=58, 2024=55)과
  §8(2020=59, 2022=58)의 **2022값이 정확히 일치**하고, 2020=59 ≠ 2024=55 이므로 차이가 유지된다.
- 254건 중 겹침 아닌 253건은 2020=2022이므로 2020↔2024 판정이 2022↔2024와 동일 → 전부 유지.
- 예측 |2020↔2024| = 253 + 4 + 1 = **258 = 실측 258.**

정직하게 적어 둘 한계: 위 경계는 5·254·겹침 1이 주어지면 257~258로 이미 강제되므로, 실측 258이
추가로 결정하는 것은 **겹침 1건의 잔류 여부뿐**이다. 또 개수 대조라 "엉뚱한 문서가 뒤바뀌어 있는"
오류에는 무감각하다. 하니스 재현성의 실질 근거는 이 검사가 아니라 **8절의 2022↔2024 재계산이 r1
원시값 254와 문서 단위 재실행 없이도 정확히 재일치한 것**(검증기 R19b)이다.

결론: **2020을 기준으로 삼아도 확정 247건 목록은 그대로 유효하다.** 247건의 2020측 값은 2022값과
동일하고(유일한 예외 148719004는 2020=59p), 여기에 §8의 2020 전용 후보 4건(재현 검증 미완)을 더하면
2020 기준 후보 목록이 완성된다. r1의 "2022 기준선 유지 + 2020≈2022" 결론을 데이터 정합 측면에서
기계적으로 뒷받침하는 결과다.

## 4. 최신 기준 재검증 — 모순 2건 해소

기여자 검증기가 작성될 때의 보고서는 §4에 "재실행 동일 3건·재실행 실패 4건"을, §8에
"합집합 263건"을 적고 있었다. 최신 `devel`의 r1 보고서는 둘을 다음처럼 정정했다.

1. **§4와 §6의 분할이 일치한다.** §4는 재실행 다름 247건, 재실행 동일 2건, 재실행 실패 4건,
   전체 실행 ERR 1건으로 구분한다. §6의 7행도 `rerun=MATCH` 2건, 재실행 ERR 4건, 전체 실행 ERR
   1건이므로 `254 = 247 + 2 + 4 + 1`로 정확히 맞는다. 최초 실행 ERR은 재실행 실패와 다른 열이므로
   검증기도 둘을 분리해 계산한다.
2. **§8의 합집합은 258건으로 명시됐다.** 2020↔2022와 2022↔2024의 교집합 1건을 빼면
   `5 + 254 - 1 = 258`이고, 보고서도 같은 값을 쓴다. 대조군 100건을 합친 검증 목록은 358건이다.
3. **문서 경로 표기 차이를 함께 처리한다.** Markdown 백틱, 이중 백틱, `<code>` 경로 표기는 모두
   같은 행 데이터다. 검증기는 HTML entity까지 원래 경로로 복원해 세 표현을 동등하게 재집계한다.

따라서 현재 기준에서 검증기는 exit 0으로 끝난다. 이는 보고서가 수록한 표·행·스크립트 계약의 내부
정합 검증이며, 원자료를 다시 실행해 한컴 측정을 재현했다는 뜻은 아니다.
