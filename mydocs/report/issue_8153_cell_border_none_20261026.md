# #8153: 명시적 NONE과 cellzone 테두리 보존

[계획](../plans/issue_8153_cell_border_none_20261026.md)의 원 해결 PR #6420과 후속
이슈 #6619·실제 통합 `950300ea7b`를 대조했다. #6311의 실물에서 빠졌던 회색
프레임은 표 기본 테두리의 검은 선이 아니라 명시적 cellzone 38·39였다.
해당 영역 처리는 현재 공통 로직에 이미 반영되어 있다.

편람 148쪽 중첩 표는 cellzone이 없고 화살표 칸 윗변·아랫행 바깥 칸의 좌우가
명시적 NONE이다. 독립 Print에도 해당 선이 없다. 주변 선의 모양으로 프레임을
추정하는 `is_callout_partial_frame`이 그 NONE까지 채우므로, 그 추정을 제거했다.
칸 자체의 테두리·명시적 cellzone 덮어쓰기·칸이 없는 외곽 슬롯의 기본값은 유지한다.

생산·소비 경로는 `칸 BorderFill → edge 점유 → cellzone 덮어쓰기 →
점유되지 않은 바깥 슬롯의 표 기본값 → render_edge_borders의 Line`이다.
측정·배치·분할 높이를 바꾸지 않으며 Native·WASM 공통 paint 경로를 수정했다.
특정 문서·쪽번호·표 모양·좌표 예외를 추가하지 않았다.

두 원본 148쪽의 기존 Native·표준 최적화 fresh WASM은 각각 raw 99.85259%다.
동일 독립 PDF·96 DPI에서 전쪽 최저 90% 이상인 앞선 검증을 확인했다.
새 `tests/cases/issue_8153_cell_none_border.rs`는 칸 소유와 원본 NONE, 선의
비중첩 관계, 처리 흐름 내용의 누락·중복·순서 및 당사자 문구를 보호한다.
고정 source `8244f3455b`에 같은 검사 소스를 연결해 실제 **2건 FAIL**을 확인했다.
컴파일은 exit 0이며, 두 실패는 모두 명시적 NONE에 바깥 선이 추가된 관계 위반이다.
검사 SHA-256은 `203021be624d17aca1cbfa37d01492ddb74150495fd4d82de3958224c4f97f44`다.

기존 #6619의 명시적 zone·색 덮어쓰기·병합 끝 주소 검사는 유지한다.
과거 #6311 합성 검사는 실제 원본의 zone을 생략한 채 표 기본값만으로 프레임을
요구한다. 같은 합성 입력의 독립 한컴 2020 Print는 제목 칸 네 변만 출력하며,
기존 Native는 raw 34.35374%·미대응 386픽셀이다. 제품 출력을 먼저 보정하고
Native/fresh WASM 90% 이상과 직접 판독을 마친 뒤 그 잘못된 기대값을 수정한다.
이 초기 분석 단계에서는 해당 검사 변경 또는 수정 후 통과를 주장하지 않았다.

실제 원본 `156745900`은 정상 대조군의 기능 보존만 확인하며 보정 대상을 확장하지 않는다.
이 자료에 대한 현재 전체 Print 일치를 주장하지 않는다. 비공개 원본과 합성 진단·
독립 PDF·실행 로그는 ignored `remaining-raw100-diagnostic/p148-callout-rule/`에 보존한다.

## 시각 검증 후 기존 합성 기대값 정정

기존과 바이트가 같은 합성 원본도 표준 fresh WASM에서 raw100·미대응 0이다.

`issue_6311_table_border_fill_emits_left_bottom_and_title_left`를

입력·출처·SHA는 [fixture 설명](../../tests/fixtures/issue_8153_cell_none_border/README.md)에 있다.

`1ac6b58709552dcd69cd4878a2025acb45f48d9f0bdfe3385a5a4e5dbc866a0d`다.
같은 보정 제품 source에서 이전 검사는 실제 1 FAIL, 정정 검사는 실제 1 PASS다.

첫 정정 초안은 중심선이 칸 경계와 정확히 같다고 잘못 가정해 용지 clip의 안쪽 이동에서
실패했다. 독립 Print에서도 위쪽 획이 용지 안에 있는 것을 다시 확인하고, 임의 상수나
제품의 inset 계산값을 복사하지 않고 실제 획 너비의 영역과 제목 칸의 소유 관계로 바로잡았다.
실패 기록도 보존했다. 기존 #6619의 올바른 zone 검사는 그대로 유지한다.

같은 제품 source `be1b4f2ddb`의 전쪽 양쪽 검증 결과는 **1,376/1,532조건 raw100·
미대응 0, 잔여 156조건**이다. 잔여는 41개 쪽 번호에 분포한다. 직전 `8244f3455b`의
