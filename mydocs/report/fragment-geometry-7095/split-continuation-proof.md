## 1. 적용 술어 — 예산과 배치의 단일 출처

`native_single_cell_rowbreak_page_fragment`(`src/renderer/float_placement.rs:1360`) 하나를
페이지네이터(`typeset.rs:27026`)와 렌더러(`table_partial.rs:3415`)가 **같이** 소비한다.
네 조건은 native HWP5 저장본 · `row_count == 1 && col_count == 1` · `!treat_as_char` ·

## 2. 경로 대조 — 시작·끝 컷 → 요구 높이 → 누적 예약 → 컷·이월 → 배치

체인은 `page_avail`(27179) → `avail_for_rows`(27402) → 행 스캔
`scan_block_table_split_rows`(22529) → `end_cut`·`split_end_limit` →
`end_row_height_override` → 렌더러 `row_heights` 다.

### ① 쪽 상단 조각 — 7062 `pi=8` (1×1 RowBreak, 본문 전체를 담은 표)

| 조각 | start_cut | `outer_bottom` | `page_avail` | `consumed` | fits | 끝 컷·이월 |
| --- | --- | ---: | ---: | ---: | --- | --- |
| 1쪽 첫 조각(쪽 중간 `cur_h=484.3`) — 분기 ② | `[]` | **0.0** | 508.1 | 397.1 | true | `[21]` 로 이월 |
| 2쪽 이어짐 | `[21]` | **3.2** | 996.5 | 980.4 | true | `[27]` |
| 3쪽 이어짐 | `[27]` | 3.2 | 996.5 | 961.1 | true | `[67]` |
| … (9개 조각 동일) | | 3.2 | 996.5 | | | |
| 10쪽 끝 조각 — 분기 ③ | `[296]` | 3.2 | 996.5 | 238.7 | true | `split_end_limit=0` |

`3.2 = outer_margin_bottom 1.88 + 100HU 1.33` 이다. 수정 전 같은 조각의
`host_before=0.0 · outer_bottom=0.0 · page_avail=1001.6` 과 정확히 이 두 성분만큼 다르다.

수정 전/후 컷 열: `[21] [27] [67] [88] [131] [162] [199] **[254] [297]**` →
`[21] [27] [67] [88] [131] [162] [199] **[253] [296]**`. 앞 일곱 조각의 컷은 **같고**,
예산이 5.1px 줄어든 결과가 마지막 두 조각에서 유닛 하나로 나타난다. 쪽수는 10 으로 같다
(정본 10).

### ② 예산 실패 → 컷·이월 — 30269 `pi=136` (10쪽, 표의 **첫** 조각인데 쪽 상단)

```
AVAIL : cont=false cur_h=0.0 table_avail=933.5 host_before=3.8 outer_bottom=5.1
        page_avail=924.6 avail_for_rows=924.6
RESULT: end_row=1 consumed=933.5 partial_h=933.5 split_end_limit=929.8 fits=false
        → start_cut=[29] 로 이월
AVAIL : cont=true  start_cut=[29] page_avail=924.6
RESULT: consumed=482.4 split_end_limit=0.0 (끝 조각)
```

`5.1 = 3.77 + 1.33`. 요구 높이 933.5 가 예산 924.6 을 넘어 **컷이 실제로 발동**하고
유닛 29 부터 다음 쪽으로 넘어간다. 수정 전에는 `outer_bottom=0.0 · page_avail=933.5` 라
같은 조각이 컷 없이 들어갔고, 상자가 내용 높이로 1028.30 까지 내려가 본문 아래(1028.00)를
0.3px 넘었다.

## 3. 소비한 내용과 물리 공간의 구분

- **빈 밴드는 상자 쪽에서 계상한다.** 7062 2쪽 조각의 마지막 내용은 1025.8 에서 끝나고
  상자는 1043.9 까지 간다. 이 18.1px 는 내용이 소비한 높이가 아니라 쪽이 정한 물리 상자이며,
  `row_heights[0] = pinned_height`(`table_partial.rs:4115`) 한 곳에서만 들어간다.
  흐름 전진(`st.current_height`)에는 들어가지 않는다 — 비끝 조각은 쪽을 닫기 때문이다.
- **줄간격은 반대 방향으로 나타난다.** 30269 10쪽의 내용 행 높이에는 조각 마지막 줄 뒤
  줄간격이 들어 있어 `split_end_limit=929.8` 이지만, 한/글은 그 줄간격을 그리지 않는다.
  상자 고정은 이 값을 **줄이는** 쪽으로도 작동해 924.64(=1022.91−98.27)가 된다. 예산이 같은
  상자로 잘랐으므로 보이는 줄은 상자 안에 남는다(내용 최하단 1023.20).
- **끝 조각의 두 값은 다르다.** 예산에서는 ①과 같이 3.2px 를 보수적으로 빼지만
  (7062 10쪽 `outer_bottom=3.2`), 흐름 전진에는 바깥 아래 여백만 넣는다
  (`terminal_outer_bottom_overhead`). 렌더러가 끝 조각 뒤에 여백을 두지 않으므로 그 자리를
  예산이 먹으면 다음 내용이 밀린다(rowbreak-problem-pages 14쪽 pi13→pi16 0.2px, hwpctl
  73쪽 pi1750→pi1760). 예산이 흐름보다 1.33px 보수적인 것은 의도이며, 부족이 아니라
  여유 방향이다.

## 4. 경계 실행 증거

| 경계 | 결과 |
| --- | --- |
| 원래 높이만 fit 하는 예산 | 30269 p10 — `consumed 933.5 > avail 924.6` 로 컷 발동(위 §2) |
| 시작 컷이 있는 조각 | 7062 `[21]`…`[296]` 9개 조각 전부 |
| 끝 컷이 있는 조각 | 같은 9개 — `end_cut.iter().any(>0)` 이 4102 의 게이트다 |
| 마지막 유닛 소비 후 종료 | 7062 p10 `split_end_limit=0.0` · 상자 286.10 에서 끝남 · 쪽수 10 |
| 쪽 중간 시작 첫 조각(반례) | 7062 1쪽 `outer_bottom=0.0` — 술어가 걸리지 않음 |
| 같은 조각에서 여러 rowspan 종료 | **구조상 비해당.** `straddle_continuation_demand`(`table_layout.rs:15631`)는 `row_span > 1` 셀만 본다. 이 술어는 1×1 표에만 걸리므로 해당 조합이 존재할 수 없다. |
| 앞 조각 끝 ↔ 다음 조각 시작의 유닛 누락·중복 | 컷 열이 `[21] [27] [67] …` 로 단조 증가하고 마지막 조각이 `split_end_limit=0` 으로 끝난다. 수정 전과 같은 유닛 집합을 9개 조각이 나눠 갖는다. |

## 6. 미해결·미검증

- **칸 내용의 `valign` 축은 이 PR 이 닫지 않았다.** 쪽 경계로 잘리는 칸은
  `effective_align = Top`(`table_partial.rs:1522`, #4042)이라 고정한 상자 아래에 빈 밴드가
  남는다(7062 2쪽 내용 49.10..1025.80, 상자 47.20..1043.90). 정본은 같은 칸을
  `valign=Center` 로 채워 57.06..1032.63 이다. 상자만 맞고 내용 위치는 아직 정본과 다르다.
- **그 결과로 기존 이탈이 1.88px 커진 자리가 있다.** 7062 3쪽의 칸 안 중첩 표가 본문 아래를
  넘는 양이 1.2 → 3.1px, 6쪽 off-canvas 표가 30.15 → 32.03px 로 늘었다. 둘 다 조각 전체가
  바깥 위 여백만큼 내려간 결과이고 **정본도 같은 만큼 내린다**. 남은 차이는 위 valign 축이다.
  `off_canvas_baseline` 은 건수 래칫이라(문서당 1건 유지) 이 크기 변화를 잡지 않는다 —
  숨기지 않기 위해 여기 적는다.
- **미보유 자료:** 156645214(쪽 중간 시작 반례)와 42065 11·15쪽 이중 여백은 이 저장소
  samples 에 없다. 두 값은 PR #7098·#7095 진행 중 실측 기록을 인용한 것이고 이번 A/B 에서는
  재측정하지 않았다.
- **overfill 문서의 쪽수 차이**(47 vs 정본 48)는 이 PR 범위 밖이며 #7140(중첩 표 행 유닛
  높이 과소 측정)이다.
