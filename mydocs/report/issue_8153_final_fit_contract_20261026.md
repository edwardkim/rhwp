# #8153 가운데 정렬·마지막 가시 줄의 fit 보정

[계획](../plans/issue_8153_final_fit_contract_20261026.md)의 같은 원본·독립 Print·사양·
고정 producer 비교를 따른다. 원본과 PDF·측정 임계값은 그대로 사용한다.

## 독립 재현

46쪽의 CENTER·condense70에 공백 전용 압축을 적용한 현재 `7620cc75`의 한글 전진은
10.506667px다. 독립 Print의 약 9.44~9.60px와 달라 두 원본의 새 검사 모두 실제 FAIL이다.
최종 검사 SHA-256은 `6242da01b422c9acf6bfd2d2c2e3ef48446c161d33cc5db945d3578bd1c3553c`다.
같은 검사 원문은 원래 `5bcb654516`의 라이브러리에서 두 건 모두 PASS다.

373쪽의 현재 마지막 점과 첫 글자 원점 차이는 독립 Print의 290.88px보다 약 4.9px 작다.
이 위치 관계를 ±2px로 보호하는 최종 검사 SHA-256은
`786ffde5c9623cd11a48241e85829f5a8e366cf1142b509f20ef72ec0b709a95`다.
고정 `7620cc75`에서 두 원본 모두 이 누적 원점 차이로 FAIL을 확인했다. 같은 줄의 원문·
run 순서·표 셀/문단 소유와 글자·공백 전진도 함께 검사한다.

첫 초안은 PDF의 600dpi 양자화 좌표를 1HU 정밀도만으로 비교했다. 이 초안은 원래 정상
producer에서도 공백 전진 4.95244px를 FAIL로 판정했다. 최종 초안은 두 원점 차이에 대한
600dpi 한 장치 픽셀과 HU 오차를 반영했다. 373쪽의 누적 배치 오류는 별도의 실제 원점
관계로 보호한다. 초안과 최초 FAIL 로그는 ignored 작업 자료의
`initial-too-precise-draft/`에 보존했다. 유효한 기존 활성 검사를 낮추거나 제거한 것이 아니다.

## 공통 구현

CENTER를 공백 전용 `CondensePlan`에서 제외하고 이미 있던 실제 glyph fit을 유지한다.
LEFT의 확인된 공백 예산과 RIGHT의 현재 계약은 유지한다. 46쪽·문서 ID·원문 문자열이나
특정 수치를 조건으로 쓰지 않는다.

이미 존재하던 가시 줄 끝 측정은 장식 없는 말미 공백을 각 run의 실제 style로 제외하고,
마지막 signed 자간의 잉크 끝을 복원한다. 밑줄·취소선·음영·실제 글자 테두리가 있는
말미 공백은 보이는 내용으로 유지한다. 이 결과를 순수 가운데 정렬뿐 아니라 간격을
분배하지 않는 JUSTIFY 글줄의 fallback fit에도 사용한다. 동일 구현을 나타내도록
`VisibleTextLineMeasure`로 이름을 바꿨고 backend별 계산이나 보정 상수를 추가하지 않았다.
탭·겹침·각주 마커·줄 소유 인라인 개체의 기존 경로는 유지한다.

## 현재 상태와 다음 검증

최종 테스트 원문은 정식 `tests/cases/` 경로로 준비했다. 수정 후 Native 빌드·집중 검사와
실제 Visual Sweep은 이어서 실행하며 아직 PASS나 보정 완료로 판정하지 않는다. 기존
76건과 새 네 건, TAC 앞 공백·오른쪽/가운데 말미 공백·합성 soft-wrap의 정상 대조를
함께 확인한다. 추가 정상 대조군 네 건은 고정 `7620cc75`에서 먼저 모두 PASS했다.
새 후보에서는 기존 76건·새 네 건·정상 대조 네 건을 합친 84건을 실행한다.
46·373쪽의 직접 Native/fresh WASM 비교와 전쪽 TSV를 새 producer로 검증한 뒤
최종 회귀·lint·Skia·Studio 등 필수 게이트를 수행한다.

이번 보정 이전 `7620cc75`의 Native 전 766쪽은 완료됐다. raw 100%·미대응 0은 HWP
320쪽, HWPX 317쪽이고 양쪽 최저 99.45644%다. 표준 release fresh WASM 빌드·최적화도
완료됐고 집중 104조건의 최저는 각각 99.25584%다. 전쪽 WASM 실행은 진행 중이다.
이 결과를 새 로컬 구현의 검증으로 표시하지 않는다. 입력·기준 PDF·글꼴·producer와
실행 로그는 같은 ignored 작업 루트의 관련 candidate 폴더에 고정한다.

모든 1,532조건 raw 100%·미대응 0과 최종 테스트를 완료한 뒤 PR 준비까지만 하고
대기한다. upstream/devel 동기화·원격 게시·push·PR 생성은 하지 않는다.
