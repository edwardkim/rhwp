## 실측 (px @96dpi, 원본 인쇄 10쪽)

한글과 **0.9px 이내**로 일치한다.

## 저장 사다리가 정답을 말한다

```
pi=324  ls[0] vpos=71604  lh=1200        ← 71604+1200 = 72804 ≤ 본문 72847
pi=325  ls[0] vpos=6863                  ← 리셋(다음 쪽)
```

즉 한글은 그 줄을 **이 쪽 마지막 줄**로 두고 표만 넘긴다. 한글 실측이 본문 하단
(1046.9)을 0.3px 넘겨 놓는 것도 같은 말이다 — 말미 줄간격을 요구하지 않는다.

## 근인 세 겹

1. **음수 오프셋에서 pre-emit 자체를 안 했다.** `prefill_before_deferred_table` 이
   `signed vertical_offset < 0` 이면 통째로 빠져나간다. 이 표는 `vertOffset = -1700`.
   → 저장 사다리가 "줄이 본문 안에서 끝나고 다음 문단이 리셋된다"고 증언할 때만 허용.

2. **fit 을 말미 줄간격까지 포함해 쟀다.** `line_advances_sum` 은 24.0px 를 주어
   잔여 16.6px 를 넘겨 탈락했다. 바로 아래 후속 문단 루프는 이미 `height_for_fit`
   (말미 ls 제외)를 쓴다 — 같은 규약(#359)을 host 줄에도 적용한다. 누적은 종전대로 전량.

3. **중복 방지 가드가 "현재 쪽"만 봤다.** 조판·페인트 양쪽의 가드가
   `current_items` / `page_content.column_contents` 를 훑는데, 쪽을 넘긴 뒤에는 그것이
   **새 쪽**의 목록이라 앞 쪽의 pre-emit 을 못 본다 → 같은 줄이 두 쪽에 그려졌다.
   쪽을 넘어 남는 `pre_emitted_host_paras` 기록을 함께 보게 했다. 분할 표 경로에는
   이미 그 가드(`host_pre_emitted`)가 있었고 **통짜 표 경로에만 빠져 있었다.**
