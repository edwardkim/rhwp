# #6186 — 꼬리말 `vertAlign=BOTTOM` 미적용

재현물 `samples/issue6186/156755659_footer_vertalign_bottom.hwpx`(원본 그대로, 91KB).

## 실측 (px @96dpi, 2쪽)

| 요소 | 수정 전 | 수정 후 | 한글 2020 |
|---|---:|---:|---:|
| 꼬리말 줄 위끝 | **1028.0** | **1051.2** | **1049.9** |
| 겹쳐 놓인 글상자 | 1045.9 | 1045.9 | 1045.8 |

수정 전에는 꼬리말이 21.8px 위에 붙어 같은 자리 글상자와 **두 줄로 갈라져** 보였다.
수정 후 한글과 1.3px 이내로 포개진다.

## 근인 — 값은 오는데 두 곳이 안 쓴다

파서는 HWPX `<hp:subList vertAlign="BOTTOM" textHeight="2834">` 를 이미 `list_attr`
비트 21~22 로 싣고 모델(`Header`/`Footer.list_attr`)까지 온전히 전달한다. 그런데

- **레이아웃**이 그 값을 읽지 않아 늘 밴드 맨 위에 놓았고,
- **직렬화기**가 `vertAlign` 을 항상 `"TOP"` 으로 굳혀 저장해 왕복에서 유실됐다.

## 게이트를 세 번 좁혔다

| 시도 | 결과 |
|---|---|
| `footer_area.bottom` 을 `margin_bottom` 기준으로 정정 | **핀 8건 붕괴** — 그 rect 는 쪽 계산에도 쓰인다(`issue_1733` 246 vs 242) |
| 공유 rect 는 두고 **선언 밴드 높이**로 정렬 | 8 → 2건 |
| 내용 높이가 참값인 **텍스트 전용 꼬리말**로 한정 | `exam_kor` 골든 복구 |
| 직렬화기 `vertAlign` 보존 | 왕복 정합 3문서 복구 |

`exam_kor` 는 한글 오라클을 새로 떠서 갈랐다 — 저장소 PDF 가 다른 판형이라 COM 으로
재측정했고, **한글 A4 기준 꼬리말 상자가 쪽 하단에서 82.1px 위**(A3 렌더 환산 116.2px)
라 종전 골든(118.5)이 맞고 변경값(100.6)이 틀렸다. 두 문서 모두 `vert_align=2` 로
같았으므로 차이는 정렬 여부가 아니라 **내용 높이 계산**이었다 — `exam_kor` 꼬리말에는
상자가 들어 있어 "줄 높이 합"이 과소평가된다.

## 별건 — 이 문서의 꼬리말이 SVG 산출에 없다

렌더 트리에는 `Footer > TextLine > TextRun "2 -"` 가 있는데 `export-svg` 의 텍스트는
본문 범위(125.8~975.1)뿐이다. 머리말도 같다. 이 축과 별개라 이슈에 따로 보고했다.
