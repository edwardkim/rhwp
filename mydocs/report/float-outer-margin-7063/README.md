## 1. 규칙 — `hwpx_sample2` 29쪽 전수 28건

`outMargin.left`** 다. 여백 0 인 표는 −0.06px(괘선 stroke/2)로 붙는다.

**14쪽이 반례를 죽인다** — `horzOffset` 이 0 이 아닌데도 정본이 `outMargin.left` 를
그대로 더한다(37.80 + 158HU 2.11 + 283HU 3.77 = 43.68 ≈ 정본 43.66). "오프셋이 있으면
여백을 안 싣는다" 는 좁힘은 기각이고, `horzRelTo` 는 `PARA`·`COLUMN` 이 같은 규칙이다.

## 2. 좁은 술어 셋은 이 규칙의 부분집합이었다

같은 여백을 저장소가 세 곳에서 따로 싣고 있었다. 전부 이 일반 규칙의 **진부분집합**이라,
일반 규칙을 켜면서 뒤 둘의 **가로 몫을 제거**했다(가드 추가가 아니라 제거다).

| 술어 | 조건 | 처리 |
| --- | --- | --- |
| `#6378` `original_hwpx_column_rowbreak_equal_outer_margin_hu` | 원본 HWPX · COLUMN · RowBreak · 사방 균등 | 그대로 둠(체인 앞쪽, 같은 값) |
| `#3820 Stage 120` `stored_reset_paint_geometry.outer_left_hu` | 저장 되감김 조각 · COLUMN · LEFT · 오프셋 0 | **가로 제거**(세로는 유지) |
| `native_empty_host_physical_outer_box_paint_inset` | 빈 host · 1열 RowBreak · COLUMN · LEFT | **가로 제거**(세로는 유지) |

제거 근거는 실측이다 — `tac-img-02.hwp` 1쪽 표가 본문 75.6 에서 79.4(= +283HU)가
아니라 83.1(= +2×283HU)로 갔고, `#3820` p167 pi=1775 가 94.49 에서 98.27 이 아니라
102.04 로 갔다.

정본도 같이 넘는다 — `hwpx_sample2` 본문 오른끝은 755.92px 인데 정본 표 우단은

```text

```

이고 수정 후 rhwp 는 757.67 이다(정본 대비 0.32px = 괘선 stroke/2). 수정 전 755.79 는
정본보다 1.56px 짧았다. 곧 이 지표 증가는 **회귀가 아니라 정본 재현**이며, 판정식이
본문 상자를 넘는 것만 세기 때문에 올라간다.
