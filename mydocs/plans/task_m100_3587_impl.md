## 1. 목표와 완료 범위

템플릿의 표·문단·글상자 블록을 데이터 건수에 맞게 반복하고 채운 뒤, 앞뒤 기존 문단과
원형을 훼손하지 않고 저장·재편집할 수 있는 공통 API를 만든다. 이미지와 중첩 표를 포함한
복합 블록도 구조·참조 관점에서 다룬다. 특정 연구노트의 크기·페이지 수·표 모양을 조건으로 삼지 않는다.

기존 필드/셀 채우기·문서별 batch fill·계획 실행·외부 DocInfo 이식을 재사용한다.
새 템플릿 언어, 독립 자동화 서비스, Gym 의존성은 추가하지 않는다.
메인테이너에게 매 함수마다 판단을 요구하지 않도록 다음 네 묶음의 의존 관계를 제시한다.

| 순서 | 묶음 | 목적·완료 증거 |

**이번 승인 요청은 전체 순서와 A의 구현 진입**이다. A 완료는 #3587 완료가 아니다.

## 2. 공통 계약

### 2.1 원형·대상·반복의 의미

- 처음에는 같은 구역의 **완전한 문단 범위 `[start, end)`**를 블록 단위로 한다.
  한 문단의 텍스트와 컨트롤을 함께 복제하며 시작/끝 문단을 주변과 merge하지 않는다.
  단일 표·글상자만 복사하는 기존 API와 혼동하지 않는다.
- 목적지는 기존 문단 **앞의 경계** 또는 구역 끝이다. 빈 기존 문단도 편집자의 구조로 보존한다.
  삽입 편의를 위해 새 빈 문단을 자동 추가하지 않는다. 명시적으로 포함한 빈 문단은 반복한다.
- 원형은 편집 전 snapshot에서 먼저 고정한다. 같은 문서 안 삽입으로 원형의 인덱스가 이동해도
  다음 반복의 원형이 바뀌지 않는다. 목적지가 원형 내부인 요청은 초기 계약에서 거부한다.
- `count=0`은 삽입 무변경이며 원형/기존 출력 삭제를 의미하지 않는다. 기존 생성분을 교체하려면
  별도 명시적 생성 범위가 필요하다. 공백/표 모양으로 과거 생성분을 추정하지 않는다.
- 같은 append 요청을 다시 실행하면 추가 생성된다. 멱등이라고 부르지 않는다. 재시도는
  입력 지문·실행 결과 확인으로 구별한다. 기존 CAS는 파일 변경을 검출하는 수단이지 영구 요청 ID 저장소가 아니다.

### 2.2 데이터와 생성 결과

- 생성 결과마다 원형의 상대 문단/컨트롤 경로 → 결과 경로 대응표를 반환한다.
  같은 이름의 필드는 반복 항목 내부의 상대 경로/순번으로 지정한다. 문서 전역의 첫 이름 일치에 쓰지 않는다.
- 기존 셀 쓰기·필드 채우기·문구 치환과 같은 값 의미를 사용한다. 누락 값·빈 문자열·추가 키를 구별한다.
  strict 자동화 요청은 해결되지 않은 대상이나 모호한 바인딩이 있으면 적용 전에 오류로 보고한다.
- 그림 바이트 삽입과 그림 배경/글상자 내부 그림은 서로 다른 경로다. 기존 그림 API를 사용하며
  엔진이 내용의 60% 크기 등 업무 정책을 자동 결정하지 않는다.
- 빈 행 추가는 기존 `insertTableRow` 재사용 대상이다. 여러 문단·내부 컨트롤·병합 셀을 가진
  원형 행 반복은 별도 구조 복제 계약이 필요하다. 행 경계를 넘는 병합은 자동 축소/분할하지 않고
  초기에는 명시적 오류로 한다. 단순 행·전체 표·문단 블록 반복을 동일 기능이라고 보고하지 않는다.

### 2.3 원자성·자원·참조

- 요청 전체를 검사한 후 staged 구조에서 ID/참조·데이터 바인딩을 완료한다. 실패 시 원본 Document,
  raw 상태, clipboard/cascade, 이벤트·batch 상태까지 변경 여부를 검사한다.
  `beginBatch/endBatch`만 호출하고 rollback이 된다고 주장하지 않는다.
- 성공 시 편집 캐시 무효화·재조판을 한 경로에서 적용한다. Studio undo 스냅샷 계약은 유지한다.
  새로운 장기 snapshot 저장소를 추가하지 않는다.
- 반복 수×블록 노드 수·텍스트/리소스 크기는 checked arithmetic으로 사전 계산한다.
  기존 `MAX_TABLE_GRID_CELLS`는 표 격자 한도일 뿐 문서 전체 반복 예산을 대신하지 않는다.
  B 착수 전에 요청 예산의 항목·기본값·상한을 기존 보안 정책 및 측정 근거와 함께 확정한다.
  무제한 반복이나 u32→u16 묵시적 축소는 허용하지 않는다.
- 같은 문서에서는 스타일·BinData를 공유할 수 있다. 다른 문서에서는 목적 문서에 매핑한다.
  지원하지 않는 참조를 삭제하거나 임의 스타일 0으로 바꿔 성공시키지 않는다.
- 원본의 기존 중복 ID를 문서 전체 재채번으로 정리하지 않는다. 복제 범위 안에서 참조가 모호하면
  strict 연산은 오류로 알리고, 비대상 원본의 편집/시각 결과를 변경하지 않는다.

### 3.2 구현 순서

1. §4 fixture로 기존 ID 중복, common/raw 불일치, 원본 불변 검사를 먼저 고정한다.
   현재 probe의 XML 관찰을 Rust의 직접 IR·HWP raw 검사로 보강한다.
2. 종류 ID와 신원 ID를 나누고, 문서 사용 ID 집합을 수집한다. 할당은 같은 입력/순서에 대해
   결정적이며 충돌을 검사한다. 크기 해시·시각·난수만으로 유일성을 주장하지 않는다.
3. 블록 clone의 모든 개체를 먼저 매핑하고 두 번째 순회에서 참조를 재작성한다.
   표 셀·글상자·그룹·캡션·내부 그림·필드 등 소유 트리를 방문한다.
   연결선의 drawing ID와 common ID, field begin/end를 구분한다.
4. 같은 복제 블록 내부 참조는 새 개체로 연결한다. 외부 참조·불명 raw 컨트롤을 만났을 때의
   보존 가능성을 검증하지 못하면 strict 블록 API 지원 완료로 보고하지 않는다.
   기존 clipboard의 허용 동작을 줄이는 변경이 필요하면 그 호환 영향부터 보고한다.
5. table의 common/raw 신원을 함께 갱신하고 seal/dirty 처리에 맞춰 저장 경로가 같은 값을 쓰게 한다.
   HWPX 문단 전체 재채번은 기존 serializer 책임으로 두며 그것을 복제 개체 ID allocator로 대체하지 않는다.
6. 내부 copyControl/pasteControl과 표 생성·split이 같은 ID 계약을 소비하도록 연결한다.
   copy만으로 원본을 변경하지 않고 paste의 실제 생성 시 새 ID를 발급한다.
7. 원본+복제본 두 개 중 하나만 텍스트·서식 편집 및 삭제하고 남은 개체/참조를 검증한다.
   두 형식 저장·재열기와 관련 시각 확인을 통과한 뒤 A 결과를 보고한다.

5. 동일 source에서 반복 실행한 결과의 구조·ID 대응표 결정성 확인. 앞뒤 문단 불변과 정상 reflow 구별.

기존 긴 검사 성공을 새 구현의 통과로 재사용하지 않는다. Stage 1 probe는 실패 조건을 찾은 조사이지
PR 검증이 아니다. 공유 빌드 캐시와 7700 개발 서버는 유지한다.

기존 clipboard 전역 상태와 커서 빈 문단 정책에 의존하지 않는다. 반환에는 생성 범위와
상대 경로 대응표를 포함한다. §2의 구조/자원 사전검증과 staged 적용이 선행돼야 한다.
문단에 SectionDef/ColumnDef 등 구역 전용 컨트롤이 있으면 초기에는 거부하고 이유를 보고한다.
원형의 헤더/푸터를 조용히 떼어내 정상 복제라고 보고하지 않는다.

### C — 반복·채우기 실행

B의 대응표에 기존 셀/필드/텍스트 편집을 결합한다. 표 행 반복은 기존 빈 행 추가와 구별해
전체 셀 문단 복제의 지원 조건을 별도로 확정한다. native/WASM의 동일 core 연산을
`run` 계획에 연결하고 `plan_schema.rs`, capabilities/MCP 설명과 테스트를 함께 갱신한다.
새 DSL을 만들지 않으며 현 `run` 4 action의 호환성·dry-run/선검증 결과를 유지한다.
구조 변경 후 기존 field/checkbox occurrence가 이동할 수 있으므로 입력 기준 선택과
생성 결과 기준 선택을 분리하지 않고 action 이름만 추가하는 구현은 하지 않는다.

### D — 외부 원형과 최종 레시피

기존 `foreign_paste`의 style/BinData 매핑을 재사용하되 커서 merge·구역 평탄화와 분리한다.
다른 스타일표에서 같은 숫자 ID를 쓰는 반례, 같은 자원 반복 이식, 잘못된 참조, 실패 시
목적 DocInfo가 남지 않는지를 먼저 확인한다. 대상의 용지·구역 속성은 기본적으로 보존하며
원본 전체 설정 복제는 문서 생성 동작으로 명시한다.
마지막에는 고정 양식·행 반복·표/복합 블록 반복·다중 영역·다른 문서 가져오기의 실행 레시피를 제공한다.

## 6. 원 제안과 제외 범위 승인 요청

- orphan/마지막 표 뒤 trim: 자동 전체 탐색 삭제 대신 생성 경계 보존으로 대체한다.
  이미 생성된 범위의 제거는 명시적 범위 계약이 있어야 한다.
- compactLeadingParasBeforeTables의 2pt 변형은 이식하지 않는다.
- mergeSectionIntoPrevious는 일반 구역 편집 기능이므로 이번 반복 자동화의 후처리에서 제외한다.
- 한컴에서 열지 못하는 합성 샘플로 시각 정답을 정의하지 않는다.
- 일반 구역 병합, 임의 문단 중간 범위 복제, 모호한 외부 참조를 가진 모든 컨트롤 지원은
  이번 초기 계약의 완료 조건으로 약속하지 않는다. 지원 거부·제한을 API/보고서에 명시한다.

**승인 요청:** 이 순서와 제외/대체 방향, 첫 묶음 A의 구현·focused 검증 진입.
제품 전체 자동화 완료 판정은 A만이 아니라 승인된 B/C/D의 사용 흐름과 최종 검증으로 한다.
원격 push·게시·PR 생성은 현재 요청에 포함하지 않는다.
