# #7642 어울림 호스트의 확정 줄과 저장 원점 공유

Issue: #7642.

0e7f112db0의 직접 전쪽 검증에서 국어 14쪽은 99.79769%지만 17쪽은
44.87939%로 후퇴했다. 문자 분할만 같다는 이유로 공통 plan을 생략한 보정은
부적합하다. 17쪽에는 개체 높이를 포함한 저장 한 줄과 실제 본문 줄이 있고,
같은 문자 분할이 같은 물리 행·높이를 뜻하지 않는다.

독립 Print와 대조한 17쪽 호스트의 저장 원점은 단 상단 +19715HU이며,
기존 공통 plan 출력 첫 줄 474.5px와 일치한다. plan을 생략한 legacy 출력은
440.9px였다. 반면 14쪽의 plan은 유효 저장 원점 450.6px 대신 누적 커서
407.7px를 고정했다. plan을 선택적으로 생략하는 방식 대신 실제 원점을 공유한다.

실제 단의 첫 소유자에서 시작하는 정상 저장 사다리와 이미 수용한 이전 plan의
문자 분할·줄 높이·간격을 확인한다. 저장 세로 축이 보존됐으면 fit 전에 그 단의
저장 원점으로 호스트를 정렬하고 동일 plan의 행·끝점을 fit과 paint가 소비한다.
원점이 입증되지 않거나 앞선 재조판으로 세로 구성이 바뀌었으면 기존 흐름을 유지한다.
문서 ID·페이지 번호·관측 px 값을 구현 조건으로 쓰지 않는다.

14·17쪽, 원본 세 문서 전쪽, 온새미로 두 형식과 NO_LS, 전체 102문서 및
#7969·#7970 보존 검증을 유지한다. 앞 후보의 결과를 새 후보 통과로 승격하지 않는다.
