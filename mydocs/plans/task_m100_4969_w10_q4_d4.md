## 2. 기능 탐지 계약

버전·User-Agent·CanvasKit package 번호로 분기하지 않는다. candidate 자체와 현재 backend 객체가 아래 기능을
온전히 제공하는지 판정한다.

### 2.1 candidate capability

다음 조건을 전부 만족한 `GlyphRun`만 bounded vertical candidate다.

1. `diagnostics.reason == boundedVerticalHwp5TableCellV1`
2. `variant.variantId == verticalGlyphRun`, `variantKind == glyphRun`
3. run과 shape key의 writing mode가 모두 `vertical-rl`
4. orientation은 `vertical-upright`, per-glyph transform은 없음
5. direction은 양쪽 모두 `ltr`, bidi level은 0
6. exact·strict·portable 진단, missing/cluster/fallback-font count 0
7. synthetic style·variation·효과 없음, portable exact face 검증 성공
8. glyph/position/advance/cluster 수와 finite·resource 상한 통과

조건 일부만 맞는 candidate를 일반 horizontal 허용 규칙으로 우회시키지 않는다. bounded provenance가 붙은 run은
전체 tuple이 맞지 않으면 fail-closed한다.

### 2.2 backend capability

- Rust `CanvasKit`·`CanvasKitBrowser`: 위 bounded tuple이면 vertical pending 두 reason만 해제한다.
- Native Skia·SVG·Canvas2D: 계속 `TextRun` fallback을 선택한다.
- Studio: 실제 render surface의 Canvas 객체에서 `drawGlyphs`가 함수인지 leaf variant 선택 **전에** 탐지한다.
- font blob 검증·face 생성·Font 생성이 실패하면 candidate를 선택하지 않고 fallback을 남긴다.
- draw helper도 `drawGlyphs` 존재를 다시 방어적으로 검사한다.

선택 뒤 draw 실패는 fallback을 이미 제거해 빈 화면을 만들 수 있다. 따라서 “일단 선택하고 catch에서 실패”는
기능 탐지가 아니며 허용하지 않는다.

1. D3-C가 게시한 glyph id·position·advance·cluster·font resource를 backend가 다시 shape하지 않는다.
2. exact bounded provenance가 없는 vertical run은 선택하지 않는다.

4. vertical-sideways·mixed·punctuation·Latin·HWPX·multi-line/run/column target은 확대하지 않는다.
5. capability나 font 생성 실패 시 fallback이 사라지지 않는다.
6. horizontal Q2/Q3 selector·font replay 계약을 변경하지 않는다.
7. package version·UA·문서 format build number를 판정 조건으로 쓰지 않는다.
8. private corpus·Hyper-V·GitHub mutation은 사용하지 않는다.

## 6. 중단 조건

- 실제 Canvas capability를 variant 선택 전에 알 수 없으면 selector를 열지 않고 구조를 재설계한다.
- vertical target을 허용하려고 generic writing-mode/orientation guard를 전역 해제해야 하면 중단한다.
- D3 glyph 위치를 CanvasKit에서 다시 측정·reshape해야만 맞으면 D3/D4 권위 분리가 깨지므로 중단한다.
- actual Noto face pixel이 D3 bbox/origin 허용오차를 벗어나면 보정 상수를 넣지 않고 원인을 조사한다.
- public schema나 D2 target 확대가 필요하면 수정 수행계획을 다시 제출한다.
