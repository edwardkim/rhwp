## 1. 배경과 판단

#5511은 `src/main.rs`의 렌더 출력 adapter를 `src/cli/outputs/`로 옮겼지만, root에는 아직
`test-caption`의 직접 SVG 렌더 호출과 구조 query 공유 helper가 남아 있다. 이 상태에서 #5776은 실제
workflow consumer를 기준으로 PDF/shared adapter와 raster adapter의 누락된 CI 영향을 복구했고, #6001의
`13ae331db`로 `devel`에 통합되었다.

따라서 #3789는 더 이상 “누락된 adapter를 CI에 추가”하는 작업이 아니다. 선행 작업이 고정한 positive
mapping을 보존하면서 다음 두 책임을 분리한 뒤, `src/main.rs` 전체에 남은 Render Diff fail-closed 경계만
안전하게 제거하는 작업으로 진행한다.

1. `test-caption`의 문서 변형·SVG 렌더 책임을 전용 CLI 모듈로 이동한다.
2. `export-structure`와 공유 JSON 변환 helper를 비렌더 query 소유 모듈로 이동한다.

## 3. 목표와 불변식

- `src/main.rs`에는 renderer 호출·렌더 결과 가공·구조 JSON 생성 구현을 남기지 않는다.
- root는 인자 해석과 전용 모듈 dispatch 같은 composition 책임만 가진다.
- `test-caption`의 stdout/stderr, SVG 출력, 기본 출력 경로와 exit code를 바꾸지 않는다.
- `export-structure`와 batch query의 JSON schema, key 순서·값, provenance와 exit code를 바꾸지 않는다.
- #5776이 고정한 PDF/shared/raster/vector 실제 consumer mapping과 adapter 전수 검사를 약화하지 않는다.
- Render Diff workflow, trusted classifier, policy mirror는 같은 source 경계를 추적한다.
- 단순 파일명이 아니라 실제 workflow consumer 근거로 CI 영향 범위를 결정한다.

## 4. 범위

### 4.1 범위 안

- `test-caption` 구현을 응집도 있는 전용 CLI 모듈로 move-only 분리
- `export-structure`와 `structure_json_value`를 비렌더 query 모듈로 분리
- root와 기존 output/batch module의 import·dispatch 정리
- 새 렌더 소유 경로를 Render Diff workflow·classifier·policy mirror에 반영
- `src/main.rs` blanket Render Diff trigger와 `main-render-boundary` 예외 제거
- 기존 CLI·CI contract test 보강과 변경 범위별 로컬 검증

### 4.2 범위 밖

- renderer 알고리즘, PDF/SVG/raster 출력 의미나 golden baseline 변경
- #5511 Stage 3의 service layer·DIP 또는 `src/main.rs` 전면 재설계
- #3790의 broader test axis·CI architecture 변경
- cache, runner, branch protection, release·publish 설정 변경
- 새로운 사용자 CLI, option, JSON schema 추가

## 5. 단계별 수행계획

### Stage 1 — 계약과 소유 경계 고정

1. `test-caption`, `export-structure`, batch structure query의 호출·출력 계약을 목록화한다.
2. 전용 caption 모듈과 structure query 모듈의 dependency 방향을 확정한다.
3. 현행 focused CLI tests와 CI classifier/workflow tests를 기준선으로 실행한다.

**종료 게이트**: 이동 전후를 비교할 CLI 계약과 CI path matrix가 문서·테스트로 식별된다.

### Stage 2 — source 책임 이동

1. `test-caption` 구현을 전용 모듈로 옮기고 root에는 dispatch만 남긴다.
2. `export-structure`와 구조 JSON helper를 query 소유 모듈로 옮겨 vector output과 root에서 제거한다.
3. 기존 CLI contract와 대표 SVG·JSON 결과가 이동 전후 동일한지 확인한다.
4. source 이동을 독립 local commit으로 고정한다.

**종료 게이트**: `src/main.rs`에 직접 렌더 호출과 구조 JSON 구현이 없고 공개 CLI 결과가 동일하다.

### Stage 3 — CI false-positive 경계 제거

1. 새 caption 렌더 경로를 workflow·classifier·policy mirror의 같은 의미 위치에 등록한다.
2. 세 목록에서 `src/main.rs`를 제거하고 일반 Rust source로 분류되는 계약을 추가한다.
3. #5776 adapter inventory와 render-workflow 추적 불변식이 계속 통과하는지 확인한다.
4. CI 운영 변경과 test를 별도 local commit으로 고정한다.

**종료 게이트**: root-only 변경은 Render Diff를 요구하지 않고, 실제 렌더 경로 변경은 계속 Render Diff를
요구하며 세 경로 목록이 일치한다.

### Stage 4 — 전체 검증과 제출 준비

1. Rust source 변경 게이트와 CI workflow O2 게이트를 실행한다.
2. 포맷·lint·문서 link·diff 검사를 실행하고 파생 test suite는 제출 대상에서 제외한다.
3. 단계 보고와 최종 보고를 작성한 뒤 push·PR 생성을 별도 승인 게이트로 남긴다.
