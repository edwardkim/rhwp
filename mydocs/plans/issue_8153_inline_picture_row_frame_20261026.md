# #8153: 글자처럼 그림의 저장 행과 셀 안 여백

## 원본·독립 근거와 기존 해결

두 편람 원본의 86쪽 중첩 표는 6행 3열이며 전체 높이는 11849HU다.
HWPX section2의 원본 표 1670013916에서 행 선언은
1080·3673·880·1964·1964·1964HU다. 둘째 행의 글자처럼 그림은
실제 저장 줄 높이와 개체 높이가 모두 3717HU이고 활성 셀 여백은 위·아래 140HU다.
따라서 해당 행의 하한은 3997HU이며, 다른 행의 선언을 보존한 합은 정확히 11849HU다.
현재는 둘째 행을 3717HU까지만 늘리고 나머지 280HU를 마지막 행에 붙인다.

독립 한컴 2024 Print의 수신·경유 baseline은 각각 315.359985·341.599976px다.
현재 실제 출력은 311.713333·337.9px로 약 3.7px 위에 있다.
원본 HU로 유도한 이동량은 280/75px다. PDF의 600dpi 텍스트 원점 양자화는
확인했지만 그 차이를 맞추는 별도 수치를 추가하지 않는다.

기존 해결은 `issue_8153_nested_row_minimum_20261025.md`와 `0bdcdbf92d`의
닫힌 저장 행 프레임이다. 셀 내용·물리 공간·여백의 분리는 PR #7877의 통합 기록도
확인했다. 그 PR의 본문과 댓글(0건), 원본 XML·PDF 관측은 ignored
`output/pr-review/issue8153-handbook-raw100-20261022/remaining-raw100-diagnostic/p086-print-geometry/`
아래에 보존한다. noAdjust나 1.5px 텍스트 폴백 공차를 전역 변경하지 않는다.

## 생산·소비와 반례

`float_placement::stored_complete_row_frame_heights`는 저장 줄·활성 여백·행 선언의
정수 합이 원래 개체 프레임을 정확히 닫을 때만 행 결과를 반환한다. 현재 모든 컨트롤을
거부한다. 실제 저장 UTF-16 줄 소속으로 확인한 글자처럼 그림의 점유 높이가 해당
LineSeg 높이를 증명하면 같은 생산 결과에 포함한다. 비흐름 ColumnDef는 별도로 구분한다.
그림 캡션·부동 개체·다른 종류의 컨트롤·편집/합성 줄·미완성 프레임은 기존 경로를 유지한다.

이 결과는 `LayoutEngine::resolve_row_heights_with_common_fit`의 조기 반환과
`HeightMeasurer`의 최종 저장 행 결과에서 함께 소비된다. 마지막 행 재분배 전에 같은
행 상자를 결정하며 paint 이동·clamp를 추가하지 않는다. 같은 줄의 그림은 최댓값,
다른 줄은 실제 저장 소속을 사용하고 `treat_as_char`만으로 같은 줄이라고 가정하지 않는다.

## 실제 검증 계획

원본 HWP/HWPX의 86쪽 수신·경유·제목·로고 행·전체 표·내용 보존을 정식
`tests/cases/issue_8153_inline_picture_row_frame.rs`에서 검사한다. 독립 Print 좌표는
±2px로 확인하며 셀 포함·순서·누락·중복 관계도 유지한다. 동일 소스 검사를 수정 전
실제 e496770a7d 라이브러리에서 실패시킨 뒤 수정 후 다시 실행한다.
이전 Native/fresh WASM의 해당 페이지는 양쪽 98% 이상이며 직접 확대 판독했다.
기존 닫힌 텍스트 행·안 여백·정상 반례를 실행하고 영향 페이지부터 실제 PNG/TSV를 대조한다.
최종 전쪽 1532조건 raw100·미대응 0과 필수 전체 검증을 완료하기 전 PR을 생성하지 않는다.
사용자의 지시 전 upstream 동기화·원격 쓰기는 하지 않는다.
