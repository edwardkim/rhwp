## 2. 사전 조사 결과 (정합 항목 + 부정 항목)

### 정합 (정상 동작)
1. **ColumnDef 파싱**: `count=2 same_width spacing=850` 정상 (paragraph 0 control 1)
2. **column area 계산**: `col[0]: x=34.0 w=357.2 / col[1]: x=402.5 w=357.2` 정상
3. **머리말 표 구조**: 2x4 table (`수능 모의고사` + DCT 로고 + `22-09 교육`) 정상 파싱
4. **2-column 분배**: 단 0/단 1 양쪽 items 배치
5. **paragraph height 측정**: per-paragraph `total_height = sb + (lh+ls) + sa` IR 정확 일치 (DIFF=0)

### 부정된 가설
- ~~line_spacing 누락 (paragraph_layout)~~ — **부정**. measurement 코드 정합. dump-pages 표시 형식 함정 (display 만 line_heights 합산, total_height 는 line_spacings 포함).

### 본질 (재조사 필요)
column 의 `cc.used_height` (typeset 누적) vs `compute_hwp_used_height` (IR vpos 기반) 의 250px 차이가 어디서 오는지 미확정. 추정 후보:
- Shape items (수식, 그림) 의 차지 공간 차이
- 머리말/꼬리말/미주 영역 보정 차이
- 표 (table) 높이 측정 차이
- vpos-reset 처리 차이
- TAC (treat-as-char) 인라인 객체 height 차이

## 4. Stage 1 진단 항목 (구체)

`compute_hwp_used_height` 의 IR 기반 계산 (= 907.1px) 과 `cc.used_height` 의 typeset 누적 (= 653.9px) 의 250px 차이를 다음 카테고리로 분리:

1. **per-item 기여 누적**: PageItem 별 (FullParagraph / PartialParagraph / Shape / Table / 미주) 누적 height 와 IR 의 (vertical_pos + line_height + line_spacing) 누적 비교
2. **Shape (수식 등) 측정**: TAC 인라인 수식의 측정 height vs IR 기대 height
3. **빈 paragraph**: 81 items 중 다수가 (빈) paragraph (h=18px) — 누적 합산 대비 IR vpos 진행 비교
4. **머리말 영역 영향**: 머리말 표 height 가 본문 paragraph 측정에 영향 미치는지 확인 (in 같은 column 시)
5. **vpos-reset 트리거**: page break / column break 시 vpos reset 처리 정합
