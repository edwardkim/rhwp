# #7642 RowBreak 격자 조각의 바깥 원점

Issue: #7642.

## 독립 근거와 원인

법령 원본의 위 바깥여백 141 HU를 세 표에서만 0 또는 282 HU로 바꾸고 다른
스트림·줄·셀·글자 속성은 보존했다. MCP engine 2020, 한컴 11.0.0.9136의 Print
method 0 결과는 두 진단본 모두 74쪽이다. 3·44·61쪽의 위 괘선은 선언 여백에
따라 이동한다. 후보 6f36e14b는 세 진단본의 이어받기 위 괘선을 모두 같은
본문 위에 둔다. 원본은 수정하지 않았고 진단 자료는 output에 둔다.

기존 native_terminal_multirow_rowbreak_reopens_outer_top은 다열 RowBreak 격자의
마지막 행 내부 컷만 위 여백을 연다. 중간 행의 실제 새 조각도 바깥 프레임을
갖는데 이 제한이 이를 누락한다. 문서 번호·실측 px로 출력을 맞추지 않는다.

## 변경과 소비 경로

기존 다행·다열·비 TAC 자리차지 RowBreak 및 오프셋 계약을 보존하고 마지막 행
제한을 제거한다. 한 열의 거대 셀은 이번 독립 근거 범위와 구별한다.
공통 판정 → 조각 예산의 host_before_overhead → 수용 컷/높이와 PageItem의
fragment_placement → layout의 resolved_table_top → 최종 표·셀 원점으로 연결한다.
기존의 더 구체적인 저장 프레임 원점을 먼저 적용하고, 같은 여백을 paint에서
중복 가산하지 않는다. 기존 반례의 실제 호출 경로와 후속 본문도 대조한다.

## 검증과 완료 조건

진단 0·141·282 HU의 영향 쪽과 원본 전체 74쪽을 Native/fresh WASM으로 비교한다.
기존 한 열 거대 셀·양수 오프셋·마지막 행 컷·현재 102개 문서·반영 #7969의
기능과 13개 시각 입력을 함께 검증한다. 90%·쪽수·직접 판독·고정 devel 대비
하락 gate를 모두 유지한다. 기준을 충족한 뒤 새 이름의 관계 회귀와 조건을
충족한 중요 페이지의 ±2px 검사를 추가한다. 실행 중인 6f36e14b 검증은 중단하지
않으며 그 결과를 이번 새 코드의 완료 증거로 표시하지 않는다.
