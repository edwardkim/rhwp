## 3. 설계

### 3-1. 행렬 = 목표 상태, 치수 diff 는 위치 기반 꼬리 증감

`ChartEdits`(`chart.rs:242`)에 `"structure": bool`(`#[serde(default)]`) 하나만 더하고 **행렬 표현은
유지**한다. 행렬은 편집 후 차트의 목표 상태다. 행 수가 늘면 각 블록(`c:cat`/`c:val`/`c:xVal`/`c:yVal`
캐시) 꼬리에 `<c:pt idx="n"><c:v>…</c:v></c:pt>` 를 붙이고, 줄면 꼬리 `c:pt` 요소를 지운다. 계열도
같다 — 늘면 마지막 `c:ser` 를 복제해 뒤에 붙이고(`c:idx`/`c:order` = 새 위치), 줄면 꼬리 `c:ser` 를
지운다. 겹치는 칸은 B1 그대로 텍스트 치환.

따라서 **`c:pt idx`·`c:idx`/`c:order` 재번호가 필요 없다**(항상 `0..n-1` 유지) — idx 속성 span 도
필요 없고, `ptCount` 재계산만 남는다. 중간 행/계열 삭제는 "뒤를 앞으로 당겨 쓰기 + 꼬리 삭제"로
표현되며, 코퍼스 형상에서는 #5447 수술 헬퍼(`b2_remove_point`·`b2_remove_series`)의 산출과 **바이트
동일**하다(`c:pt` 가 `idx` 와 `c:v` 만 가진 요소라 위치 치환 결과가 같다). 이 동일성을 S2 의 독립
오라클 테스트로 고정한다.

대안(명시 op 목록 `ops:[{deleteSeries:1}]`)은 중간 계열 삭제 시 `c:spPr` 승계를 표현할 수 있으나 CSV
동형성이 깨지고 범위가 두 배다. 코퍼스에 계열별 `spPr` 이 거의 없어 시각 차이도 없다. 필요해지면
후속에 additive 로 연다.

### 3-2. 스캐너가 구조 좌표를 한 번에 기록한다 (S1, `data.rs`)

같은 이터레이션에서 기록한다(2패스 금지 — 같은 바이트를 두 번 읽으면 두 좌표계가 어긋날 수 있다).
전부 additive 필드라 기존 코드는 무수정으로 컴파일된다(외부 리터럴 생성자 0건).

```rust
pub struct ChartPoint { idx, span, text, element_span: Option<Range<usize>> }   // <c:pt …>…</c:pt>
pub enum PlotKind { Bar, Line, Area, Pie, OfPie, Doughnut, Radar, Scatter, Bubble, Stock, Other }
pub struct BlockShape {
    pub element_span: Range<usize>,             // <c:val>…</c:val> 전체
    pub pt_count: Option<PtCount>,              // PtCount{span, value} — ptCount val 속성값 텍스트 구간 + 선언값
    pub insert_at: Option<usize>,               // 점 삽입 앵커 = 마지막 c:pt 요소 끝 → 없으면 캐시 닫는 태그 직전
}
pub struct ChartSeries {
    name, axis, labels, values, labels_multi_level,
    plot: PlotKind, prefix: String,             // 둘러싼 *Chart 요소 / c:ser qname 접두어("c:")
    element_span: Range<usize>,                 // <c:ser>…</c:ser>
    name_span: Option<Range<usize>>,            // c:tx 캐시 텍스트 구간
    idx_span: Option<Range<usize>>, order_span: Option<Range<usize>>,  // c:idx / c:order val 구간
    labels_shape: Option<BlockShape>, values_shape: Option<BlockShape>,
}
```

- `ptCount`·`idx`·`order` 의 속성값 구간은 quick_xml 이 속성 오프셋을 주지 않으므로 **그 태그 하나의
  raw 구간 `&text[pos_before..buffer_position()]` 안에서** `val` 속성을 수동 파싱해 얻는다. 재슬라이스가
  선언값과 다르면 `None`(fail-closed — 그 블록의 구조 편집만 거부된다).
- `in_cache` 게이트로 `multiLvlStrCache` 안 ptCount 오염을 막고, `c:tx` 의 `ptCount val="1"` 은 섹션
  게이트(`Cat|Val|XVal|YVal`)로 거른다. `SKIPPED_SUBTREES` 에 `dPt` 를 더해 `c:dPt/c:idx` 가 계열
  `c:idx` 를 덮지 않게 한다(first-wins).
- 차트 종류는 손실 파서 `OoxmlChart::parse` 를 두 번째로 부르지 않고 스캐너가 `PlotKind` 로 계열마다
  기록한다(콤보 안전). `chart.rs:49 same_chart_data` 에 `plot` 비교를 더한다(span 류는 비교하지 않음).
- 기존 검증(`NoSeries`, 비순차 fail-closed)·기존 크레이트 테스트 17개 무변경.

### 3-3. 패처는 구간→바이트열 splice 다 (S2, `patch.rs`)

`Planned`(`:122`)를 `Splice { span, bytes, seq }` 로 일반화한다. 정렬 키 `(start, end, seq)` — 같은
앵커의 길이 0 삽입은 입력 순서, 겹침 검사 `start < cursor`(`:209`)·단일 패스 복사(`:204-219`)는
그대로. 빈 구간 삽입과 빈 바이트 삭제가 같은 코드로 돈다. **재직렬화는 하지 않는다.**

공개 면: `enum ChartEdit { Value(ValueEdit), SeriesName{series,text}, AppendPoints{series,target,texts},
TruncatePoints{series,target,keep}, AppendSeries{name,labels,values}, TruncateSeries{keep} }` +
`apply_chart_edits(xml, data, &[ChartEdit])`. `apply_value_edits` 는 시그니처를 유지하고
`ChartEdit::Value` 로 위임한다(통합 테스트 40건·`chart.rs` 호출부 무수정). `EditTarget::Label` 이
카테고리 라벨에도 유효해진다(`LabelNotEditable` 제거). 계열 신설은 템플릿(`series.last()`)의
`element_span` 바이트 조각에 **같은 splice 를 상대 오프셋으로** 적용해 복제본을 만들고
`template.element_span.end` 에 삽입한다. 이스케이프는 도입하지 않는다(`is_safe_text` 유지 — `<>&`
포함 이름·라벨은 거부).

### 3-4. 코어는 의도가 있을 때만 구조를 바꾸고, 쓰기 전에 자기 산출을 다시 읽는다 (S3, `chart.rs`)

- `structure=false` → B1 의 네 거부(`seriesCountMismatch`·`valueCountMismatch`·`seriesNameMismatch`·
  `categoryMismatch`) 그대로. 메시지에 "구조 편집은 `structure:true` 로" 안내만 더한다.
- `structure=true` → `validate_structure()`: `rowCountMismatch`(계열 간 행 수 불일치) →
  `lastPointDeleteRefused`/`lastSeriesDeleteRefused` → **종류별 가드** → 라벨 규칙(`labelsRequired`·
  `labelCountMismatch`·기존 `sharedCategoryRequired/sharedXRequired`) → 값(`notANumber`·
  `valueNotPatchable`) → 이름(`seriesNameNotPatchable`·`seriesNameRequired`·`unsafeText`) →
  `pointsNotInsertable`/`seriesNotClonable`. None≡"" 동일시(`:302-304`)는 "무편집"으로 유지.
- 종류별 가드(신규 reason): `pieSeriesCountFixed`(pie/pie3D/ofPie 계열 수 변경), `stockSeriesCountFixed`
  (HLC=3/OHLC=4 — 변경은 B3), `scatterXYMismatch`(분산형 행 수 변화에 X 누락/길이 불일치),
  `multiLevelLabelsUnsupported`(다층 카테고리 구조 편집). 마지막 1점·1계열 삭제 거부는 위 하한.
- `plan_edits()` 는 `Vec<ChartEdit>` 를 만든다. 라벨 텍스트 변경은 라벨 보유 **전 계열 동기**(스파이크
  `b2_relabel_category` 정책). `changed[]` 에 `{"op": …}` 항목을 더한다(기존 값 항목 형상 유지).
- 패치 직후 **self-check**: ①② 각각 `scan_chart_values(&patched)` Ok + 목표 행렬 일치, 둘 다 있으면
  `same_chart_data(rescan①, rescan②)`. 아니면 `selfCheckFailed` 로 **한 바이트도 쓰지 않는다**
  (수용 기준 2 를 코드로 강제). 무변경 조기 반환·dry-run·원자 대입·캐시 무효화는 B1 그대로.

### 3-5. CLI/MCP 는 옵트인으로 연다 (S4)

`csv-to-chart --structure` 가 있을 때만 `structure:true` 를 코어에 넘긴다. 기본은 현행 fail-closed —
"의도 없이 개수가 어긋난 CSV 는 여전히 사고"(이슈 §3). `edit set-chart-data` 는 `--data` JSON 에
`structure` 가 실리고, `--dry-run` 이 코어 검증을 거치도록 고친다. MCP `hwp_csv_to_chart` 에
`structure` 인자, `hwp_set_chart_data` 스키마 문구, 프로필 recipe, `cli_commands.md`·
`agent_knowledge_map.md`·codex 생성물을 갱신한다. 검증기는 코어 한 곳(CLI 복제 금지).
