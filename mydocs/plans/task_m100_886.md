# Task #886 수행 계획서

## 이슈

- 이슈 번호: #886
- 제목: rhwp-studio(extension): 웹 창 닫기 전 저장 여부 확인
- 마일스톤: v1.0.0 (M100)

## 배경

현재 rhwp-studio extension에서 문서를 수정한 상태로 웹 창/탭을 닫거나 새로고침하면 별도 확인 없이 페이지가 종료될 수 있다. 이 경우 저장되지 않은 변경사항이 유실될 수 있으므로, 저장 보호 흐름을 추가한다.

브라우저 보안 정책상 창/탭 닫기와 새로고침 시에는 앱 커스텀 HTML 모달을 안정적으로 표시할 수 없다. 따라서 브라우저 이탈 계열은 `beforeunload` 기반 기본 확인창을 사용하고, 앱 내부 문서 전환 계열은 기존 모달 UI를 확장하여 저장 여부를 묻는 흐름으로 분리한다.

## 필수 참조 문서 확인

- `mydocs/manual/browser_extension_dev_guide.md`: MV3 CSP, 확장 페이지 제약, 보안 규칙 확인
- `mydocs/report/browser_extension_security_audit.md`: 확장 환경 보안 위협 모델 및 DOM API 사용 원칙 확인
- `mydocs/tech/font_fallback_strategy.md`: 본 작업의 직접 수정 범위는 아니나 필수 참조 문서로 확인

## 현황 확인

- `rhwp-studio/src/main.ts`
  - 문서 로드, 새 문서 생성, URL 파라미터 로드, `open-document-bytes` 이벤트 처리의 중심이다.
  - 현재 문서 dirty state 추적과 `beforeunload` 처리는 확인되지 않았다.
- `rhwp-studio/src/command/commands/file.ts`
  - `file:new-doc`, `file:open`, `file:save` 명령이 존재한다.
  - `file:new-doc`는 문서가 있으면 기존 `showConfirm()`으로 닫기 확인을 하지만, 실제 저장 여부와 무관하게 항상 같은 메시지를 사용한다.
  - `file:open`은 새 파일을 바로 로드하므로 저장되지 않은 변경사항 보호가 필요하다.
- `rhwp-studio/src/ui/confirm-dialog.ts`
  - 확인/취소 2버튼 모달만 제공한다.
  - `저장`, `저장 안 함`, `취소` 3선택 모달은 별도 유틸 또는 확장이 필요하다.
- `rhwp-studio/e2e/`
  - Puppeteer 기반 E2E가 있으며, 모달 확인 패턴은 `footnote-delete-confirm.test.mjs`에서 참고 가능하다.

## 목표

1. 문서 변경 후 저장되지 않은 상태를 dirty state로 추적한다.
2. dirty 상태에서 브라우저 창/탭 닫기 또는 새로고침 시 브라우저 기본 이탈 확인창이 표시되도록 한다.
3. dirty 상태에서 앱 내부 새 문서/파일 열기/문서 전환 흐름을 실행하면 `저장`, `저장 안 함`, `취소` 선택지를 제공한다.
4. 저장이 성공하면 dirty 상태를 해제하여 이후 창/탭 닫기 확인창이 표시되지 않도록 한다.
5. dirty 상태가 아닌 경우에는 불필요한 확인창을 표시하지 않는다.

## 구현 방향

1. dirty state 소유 위치를 정한다.
   - 우선 후보: `main.ts` 또는 별도 `core/document-dirty-state.ts`
   - 이벤트 기반으로 input/edit 명령 실행 후 dirty 표시, 문서 로드/새 문서 생성/저장 성공 후 clean 표시
2. 변경 감지 지점을 좁게 연결한다.
   - `InputHandler.executeOperation()` 계열 또는 편집 명령 실행 완료 지점이 1차 후보이다.
   - 직접 WASM 변경을 수행하는 명령(`insert`, `table`, `page`, `format` 일부)은 누락되지 않도록 검토한다.
3. 저장 보호 유틸을 만든다.
   - dirty가 아니면 즉시 통과
   - dirty이면 앱 내부 모달에서 `저장`, `저장 안 함`, `취소`를 선택
   - `저장` 선택 시 기존 `file:save` 흐름을 재사용하고 저장 성공 여부에 따라 다음 동작 진행
4. 브라우저 이탈 보호를 추가한다.
   - dirty 상태일 때만 `beforeunload`에서 `preventDefault()`와 `returnValue` 설정
   - clean 상태에서는 이탈 확인이 발생하지 않도록 한다.
5. 검증을 추가한다.
   - 단위 테스트 또는 E2E로 dirty 상태 전환, 저장 후 clean 상태, 내부 문서 전환 취소/진행을 확인한다.
   - 브라우저 기본 `beforeunload`는 자동화 한계가 있으므로 가능한 범위에서 이벤트 핸들러 동작을 검증하고 수동 검증 절차를 남긴다.

## 수용 기준

1. 새 문서 또는 기존 문서 편집 후 창/탭 닫기 또는 새로고침 시 브라우저 기본 확인창이 표시된다.
2. 저장 완료 후 창/탭 닫기 또는 새로고침 시 확인창이 표시되지 않는다.
3. dirty 상태에서 새 문서/파일 열기 등 앱 내부 문서 교체 동작을 시도하면 저장 여부 선택 모달이 표시된다.
4. 앱 내부 모달에서 `취소`를 선택하면 기존 문서가 유지된다.
5. 앱 내부 모달에서 `저장 안 함`을 선택하면 기존 동작이 계속 진행된다.
6. 앱 내부 모달에서 `저장`을 선택하면 저장 성공 후 기존 동작이 계속 진행된다.
7. HWPX 출처 저장 비활성화 정책이 깨지지 않는다.
8. `npm run build` 및 관련 E2E 또는 수동 검증 절차가 통과/기록된다.

## 리스크와 대응

| 리스크 | 대응 |
|------|------|
| 브라우저가 `beforeunload` 문구를 무시함 | 기본 확인창 표시 여부만 보장하고 문구 커스텀은 수용 기준에서 제외 |
| dirty state 누락 | 편집 명령 경로와 직접 WASM 변경 경로를 구현 계획서 단계에서 명확히 열거 |
| 저장 취소와 저장 실패 구분이 불명확함 | `file:save` 결과를 반환 가능한 구조로 정리하거나 저장 보호 유틸에서 실패/취소를 보수적으로 취소 처리 |
| HWPX 저장 비활성화 문서에서 `저장` 선택 시 혼란 | HWPX는 저장 불가 안내 후 문서 교체를 중단하는 정책을 우선 검토 |
