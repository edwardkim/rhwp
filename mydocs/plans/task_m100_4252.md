## 1. 목표

페이지 분할로 재귀 조판되는 중첩 표의 `TextRun.cell_context`가 실제 문서 IR 경로를 끝까지
보존하게 한다. rhwp-studio에서 해당 셀의 자식 표 객체 선택과 다중 페이지 bbox 조회가 예외 없이
성공해야 한다.

## 2. 확인된 원인

- 최상위 부분 표는 `layout_partial_table()`에 실제 본문 `para_index`와 `control_index`를 전달한다.
- 재귀 분할 자식 표는 자식 표 하나만 담은 합성 `Paragraph`를 만들어 `(para=0, control=0)`으로 같은
  함수를 다시 호출한다.
- 이 재귀 호출에는 외부 `CellContext` 인자가 없다. 셀 방출부가 합성 좌표로 새 루트 경로를 만들어
  화면은 정상 조판되지만 원본 IR 탐색과 선택 API는 실패한다.
- 실제 fixture의 물리 5쪽 `구 분` 런은 현재 `parentPara=0`,
  `(control=0, cell=0, cellPara=12) → (control=0, ...)`로 기록된다. 실제 문서에서
  `paragraph[0].controls[0]`은 `SectionDef`다.

## 3. 변경 경계

- 레이아웃 geometry, 페이지 컷, 표 높이와 테두리 paint는 변경하지 않는다.
- 부분 표 함수가 선택적인 enclosing `CellContext`를 받아 재귀 호출에서만 원본 경로를 연장하게 한다.
- 합성 문단의 `(0, 0)`은 자식 표 데이터 조회에만 사용하고 렌더 트리의 선택 메타데이터로 방출하지
  않는다.
- 최상위 부분 표와 비분할 중첩 표의 기존 경로 생성 규칙을 유지한다.
- renderer가 유효 경로를 방출하는 것을 우선 해결한다. Studio의 예외 후 선택 상태 정리는 본 수정에
  필요하다고 검증될 때만 최소 범위로 다룬다.

## 4. 브라우저 성능 불변 계약

- 커서 이동, 키 입력, `requestIdleCallback`과 Studio 이벤트 핸들러에 새 작업을 추가하지 않는다.
- 선택 때마다 별도의 전 페이지 경로 검증이나 렌더 트리 순회를 추가하지 않는다. 기존
  `get_table_cell_bboxes_by_path()` 호출 횟수와 탐색 범위를 늘리지 않는다.
- 실제 경로는 이미 진행 중인 부분 표 조판에서 enclosing context를 전달해 만든다. 함수 경계에서는
  가능한 한 `Option<&CellContext>`로 빌려 전달하고, RenderNode에 소유 metadata를 넣을 때만 기존과
  같은 수준으로 복제한다.
- 수정 전·후 같은 환경과 release WASM에서 fixture 17쪽 로드 완료 시간과 대표 자식 표 객체 선택
  시간을 여러 번 계측해 중앙값을 기록한다. 브라우저 시간은 환경 잡음이 있으므로 단일 수치를 hard
  assertion으로 만들지 않고, 구조적 추가 순회 여부와 함께 판정한다.
- 기존 `probe-input-perf-issue3137.mjs`의 문서·cursor·focused repaint·long-task 계약을 재실행해
  입력 경로에 새 long task나 전체 repaint가 생기지 않았는지 확인한다.

## 5. 래칫과 검증

1. 실제 fixture 물리 5쪽 `구 분` 런의 경로가 원본 IR에 resolve되지 않는 RED를 먼저 고정한다.
2. 수정 후 경로가 실제 `paragraph[7].controls[1]` 외부 표에서 시작해 래퍼와
   `cellPara=12.controls[0]` 자식 표까지 이어지는지 검증한다.
3. 전 17쪽의 길이 2 이상 `cell_context.path`를 원본 IR에 재적용해 마지막 컨트롤이 모두
   `Table`인지 검사한다.
4. Studio가 사용하는 `get_table_cell_bboxes_by_path()`로 물리 5쪽 자식 표 bbox를 조회해 오류 없이
   셀 목록을 반환하는지 검증한다.
5. 기존 #2007·#4069·#4159 focused 페이지네이션/테두리 핀과 17쪽 계약을 재실행한다.
6. 변경 범위에 맞는 fmt·diff·Clippy와 release WASM 계약을 확인한다. 시각 geometry가 바뀌지 않아야
   하므로 전후 render tree bbox 차이가 0인지 확인한다.
7. 브라우저 성능 불변 계약을 수정 전·후 비교하고 `output/4252/`에 성능 JSON과 필요한 Studio 증적을
   둔다. 경로 정확성을 위해 사용자 hot path에 추가 스캔이 필요해지면 구현을 중단하고 재설계한다.

## 7. 재검증에 따른 범위 정제

초기 renderer 정정 뒤 작업지시자의 Studio 로그에서 유효한 raw context를 같은 깊이의 합성 traversal
context가 덮는 hit-test 결함, 표-only 부모 문단 caret 실패, 동일 `Esc` 이벤트의 선택 렌더 중복이
확인됐다. 승인된 성능 불변 계약 안에서 다음 최소 보정을 포함한다.

- raw context를 우선하고 traversal context는 더 깊을 때만 보완한다.
- 기존 cursor fallback 순회에 표 또는 유효 자손 run anchor를 추가하며 새 전 페이지 탐색은 만들지 않는다.
- 이벤트 발행 후의 직접 선택 렌더 한 번을 제거해 기존 구독자 한 곳에서만 렌더한다.
- bbox API가 이미 캐시된 page tree를 사용하게 하되 조회 페이지 범위와 반환 계약은 바꾸지 않는다.

변경하지 않은 `requestIdleCallback` prefetch와 `requestAnimationFrame` visible-page 렌더 경고는 이
이슈의 성공 조건에 섞지 않고 별도 성능 결함으로 분리한다.
