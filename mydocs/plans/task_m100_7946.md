## 1. 목표와 범위

PDF 기능을 포함한 Docker WASM으로 Studio에서 로컬 PDF를 직접 열고, 공통 IR의 실제
조판 결과를 확인한다. 임시 버튼 주입이나 HWP/HWPX 사전 변환을 사용자 절차로 요구하지 않는다.

#7911의 CLI/WASM·Worker 기반과 #7913의 병합 결과를 재사용한다.
[기존 B08 백로그](task_m100_7911_backlog.md)의 Studio UI 채택 부분만 별도 작업으로 분리한다.
패키지 배포·보안 감사·B10-1 저장본 한컴 재조판까지 함께 완료했다고 표시하지 않는다.

Studio 빌드 도구의 의존성 보정 #7855·#7856을 같은 브랜치와 통합 PR에서 처리한다.
각 이슈의 변경은 구분 가능한 commit으로 남기고 완료 조건·검증 결과도 이슈별로 판정한다.

## 2. 현재 관측과 독립 기대

- `rhwp-studio/index.html`의 input, `file-system-access.ts`의 확장자 판별·picker와
  `main.ts`의 input/drop 경로는 PDF를 거절한다.
- 제품 `HwpDocument` 생성자와 `importPdf()`는 PDF를 공통 IR로 가져온다.
  default-off에서도 JS 메서드가 존재하므로 export 유무는 지원 여부의 증거가 아니다.
- 기존 `loadBytes` → `WasmBridge.loadDocumentAtomically` → `initializeDocument` →
  `CanvasView.loadDocument`를 재사용한다. POC나 다른 PDF 뷰어로 조판을 대신하지 않는다.
- 기능 계약의 독립 기대는 사용자 요청과 기존 공개 API의 feature-on/off·원자적 문서 교체다.
  배치 기대는 원본 `pdf/issue5875/nested_table_text_caption-2020.pdf` 12쪽이다.
- 같은 기준 SHA의 lockfile에서 Studio의 `brace-expansion` 5.0.6/2.1.0과 `fast-uri` 3.1.2,
  metrics의 `brace-expansion` 5.0.7, VS Code의 `fast-uri` 3.1.5가 남아 있음을 확인했다.
  Studio의 minimatch 5.1.9와 Ajv 8.20.0은 각각 2.x·3.x 의존 범위를 선언한다.
  두 기존 이슈 모두 열려 있고 담당자는 `edwardkim`이며 별도 댓글은 없다.

## 3. 작업 순서

1. #7855·#7856의 전체 설치 그래프·상위 버전·호출부를 대조하고 필요한 소스 호환성 보정과
   manifest/lockfile 갱신을 수행한다. 정상 glob 선택·스키마 검증과 깨끗한 재설치를 먼저 확인한다.
2. 실제 WASM capability와 Studio 파일 입력·형식/저장 상태의 연결을 구현한다.
   파일 열기·fallback input·드롭이 같은 지원 형식 계약을 소비하게 한다.
3. 갱신 의존성 위에서 Studio/PWA·metrics·VS Code를 검증한다. Docker PDF-on 빌드와
   실제 CDP Studio에서 직접 PDF 열기, 전쪽 탐색·그림 표시,
   실패 복구·기존 형식 대조군 및 전쪽 Native/fresh WASM 비교를 수행한다.
4. 단계 결과를 보고하고 세 이슈의 통합 PR 준비·검토·CI·병합 절차로 진행한다.

상세 변경·검증은 [구현계획](task_m100_7946_impl.md)을 따른다.
범위 확장 없이 먼저 실행 가능한 Studio 연결을 완성하고 추가 보완은 기존 백로그에 연결한다.

## 4. 완료 조건

- PDF-on의 정식 열기/드롭에서 PDF를 직접 열고 실제 Studio Canvas로 12쪽을 확인한다.
- feature-off의 기존 형식 열기와 PDF 미지원 안내, 취소·손상/한도 오류 뒤 현재 문서 보존과
  다음 정상 입력 복구를 검증한다. PDF 원본을 HWP/HWPX 바이트로 덮어쓰지 않는다.
- 입력·source SHA, 실제 fetch WASM 및 루트 pkg/public SHA 일치와 실행 명령을 기록한다.
- 같은 원본 PDF 대비 전쪽 Native/fresh WASM 각각 90% 이상·쪽수 일치·직접 판독을 확인한다.
  기존 #7913 증거만으로 새 UI 경로의 성공을 선언하지 않는다.
- 코드 범위에 맞는 로컬 검사와 승인된 CI를 실행한다. 시각 gate 미달은 기존 예외로 자동 면제하지 않는다.
- #7855의 두 패키지 clean install/`npm ls`에서 5.0.12만 남고 invalid가 없어야 한다.
  확장 패턴과 파일 선택 결과, metrics 출력 차이를 확인한다.
- #7856의 모든 사용 경로 clean install/`npm ls`에서 확정 목표 버전을 확인한다.
  Ajv `$id`/`$ref`·URI 계약, VS Code compile·package를 검증한다.
- 세 패키지의 개발 의존성 포함 audit 결과와 실행 Node/npm 버전·남은 발견을 기록한다.
  기존 알려진 문제와 새로 유입된 문제를 구분하고 두 이슈의 대상 권고 해소를 확인한다.
