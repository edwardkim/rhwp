## 재현과 범위

#6961 검증에서 Firefox 155.0.1의 다운로드 1건이 실제 탭 ID 2개를 만들었다.
filename launcher를 기준본으로 되돌린 패키지도 동일했다. 편집 후 저장과 다른 이름으로
저장에서도 자체 moz-extension Blob 출력이 각각 뷰어 탭 2개를 추가했다.

Firefox adapter의 같은 ID 이벤트를 수신 순서로 직렬화한다. 수신 시간을 보존해 큐 대기가
새 다운로드를 과거 항목으로 바꾸지 않게 하고, 실패 후 다음 이벤트와 다른 ID는 진행한다.
공통 순수 상태 머신의 freshness/TTL/terminal 정책은 유지한다.
Chrome/Firefox adapter에서 자신의 runtime origin에 속한 Blob 출력만 자동 열기에서 제외한다.
외부 웹 Blob과 다른 확장의 Blob을 일괄 제외하지 않는다. 저장 자체는 취소하지 않는다.

## 단계와 검증

1. 계획 커밋 후 중첩 생성/변경/완료 이벤트와 자체 Blob 재오픈을 실패 테스트로 고정한다.
2. adapter 큐와 정확한 자체 Blob 판별을 구현한다.
3. 기존 과거 다운로드·재시작·비-HWP·설정 보호와 새 테스트, 두 production build,
   dist 계약, 실제 Chrome/Firefox 다운로드 및 Firefox 편집/저장/다른 이름 저장을 검증한다.
4. #6961과 결합한 패키지에서도 탭 1개 유지, 정상 이름, 편집 데이터 보존을 확인한다.
5. 결과 보고와 PR 초안까지 로컬 커밋한다.

Rust/WASM/Studio source 변경은 없으며 기존 WASM을 재사용한다. 렌더링 변화는 범위 밖이다.
실제 브라우저 검증은 임시 프로필과 loopback fixture를 사용한다.
