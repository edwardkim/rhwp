## 목표

파서·편집 명령이 소유하는 `Document`와 렌더러가 계산한 projection/cache, 저장 포맷 lowering의
생명주기를 분리한다. 새 범용 IR 계층을 먼저 만들지 않고 현재 결함을 만든 생산자와 소비자 사이에
최소 경계를 둔다.

## 확인된 경계

1. `floating_image_stack_extents`는 세로 offset만 보고 #2004 projection을 허용한다. 이 함수가 같은
   좌표계에서 실제 2D overlap을 증명해야 한다.
2. `layout_only_fill_lines`는 `Paragraph.line_segs`의 suffix provenance인데 HWP5와 HWPX 저장기가
   서로 다른 판정을 쓴다. `Paragraph::serializable_line_segs`를 단일 source view로 둔다.
3. `Table.dirty`와 `single_line_overflow_memo`는 renderer가 소유해야 할 상태를 source model에 넣고
   mutation site마다 수동 무효화를 요구한다. section/paragraph revision과 현재 frame 입력으로
   재측정하거나, correctness에 불필요한 memo는 제거한다.
4. `Table.local_resize_*`는 파일에 없는 Studio projection이다. transient marker 및 과거 편집
   morphology 추론을 제거하고, 포맷이 보존할 수 없는 독립 행·열 경계 편집은 mutation 전에
   명시적으로 거부한다.
5. `export_hwp_with_adapter*`의 lowering은 live `Document`가 아니라 snapshot에서만 수행한다.

## 단계

1. source/derived LineSeg view와 red regression을 만든다.
2. #2004 admission을 2D frame geometry로 제한하고 기존 fixture의 그림 identity/bounds를 고정한다.
3. 표·문단 renderer cache owner와 invalidation을 `DocumentCore` 경계로 옮기거나 제거한다.
4. source `Table`의 local resize marker와 morphology 추론을 제거한다. HWP/HWPX가 편집 의도를
   표현하지 못하는 `localResize` 요청은 source mutation 전에 오류로 반환하고 일반 grid resize의
   저장 geometry는 유지한다.
5. 모든 HWP lowering API를 snapshot-only로 만들고 live IR 구조 동일성을 검증한다.
6. focused, 전체 release-test, lint/WASM/Native Skia, OVR·발동 페이지 시각 검증 뒤 Draft PR을 연다.

## 범위 확장 중단 조건

- HWP/HWPX가 표현하지 못하는 local resize geometry를 무손실 저장하려면 새 파일 확장이 필요한 경우
- source 공개 API 또는 파일 포맷을 비호환으로 바꿔야 하는 경우
- 정합성을 위해 일반 문서 전체의 저장 LineSeg를 폐기해야 하는 경우

이 경우 임의 확장하지 않는다. 이번 구현은 첫 조건을 확인했으므로 요청을 mutation 전에 명시적으로
거부하는 완료 조건의 두 번째 선택지를 적용한다.
