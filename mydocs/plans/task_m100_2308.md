## 유효성 판단

이 이슈는 현재도 유효하다. `DocumentCore.render_normalized`는 원본 섹션과 조판 결과를 복제한
`Vec<Option<(Vec<Paragraph>, Vec<ComposedParagraph>)>>`를 유지하고, deferred edit 뒤에는
논리 경로를 따라 복제본을 직접 갱신한다. 이 구조에는 다음 문제가 남아 있다.

- 원본 변경과 렌더링 전용 복제 상태 사이의 동기화 책임이 분산돼 있다.
- 경로 불일치 시 기존 갱신 함수가 조용히 반환하여 stale 상태를 감지하기 어렵다.
- 작은 변경도 섹션 전체 복제 또는 복제 트리의 부분 수정으로 이어질 수 있다.
- #2004 이미지 스택 보정과 #2195 중첩 표 너비 보정이 같은 복제 트리에 결합돼 있다.
- 렌더 정규화 상태의 유효성을 판정할 구조·경로별 revision이 없다.

최신 `devel`에서는 #2430으로 레이아웃 경계가 조정됐지만, 위 소유권·무효화 문제는 해소되지
않았다. 따라서 기존 목표를 유지하되, 단순 revision 래핑이 아니라 희소 overlay 기반 derived
state로 구체화한다.

2026-07-23 구현 착수 전 재확인에서도 이슈는 OPEN, assignee는 `postmelee`, 경쟁 PR은
없었다. 최신 `devel@29b5547e`에서도 섹션 clone, `compute_render_normalized()`,
`refresh_render_normalized_cell_paragraph_after_edit()`가 유지돼 있어 계획 범위는 여전히
유효하다. 기준선 이후 renderer 변경은 새 derived-state 계약을 대체하지 않는다.

## 목표

1. 렌더링 정규화 상태를 원본 IR의 소유 복제본이 아닌 재생성 가능한 derived state로 만든다.
2. 구조 변경, 페이지 기하 변경, 안정적인 논리 경로 변경을 revision으로 구분한다.
3. 경로가 일치하고 revision이 유효하면 기존 `Arc` 결과를 재사용한다.
4. 경로 또는 구조 불일치를 stale 결과 재사용이 아닌 재파생·섹션 fallback·명시적 오류로 처리한다.
5. #2004와 #2195 동작 및 기존 편집·캐시 회귀를 보존한다.
6. 기존 clone/mirror 경로를 제거하고 새 무효화 계약을 문서화한다.

## 단계별 수행 계획

### Stage 1 — 현행 계약 특성화

- `render_normalized` 생성·소비·갱신 지점을 테스트로 고정한다.
- 표 셀, 표 caption, 도형 textbox, 그림 caption 경로의 성공·불일치 동작을 기록한다.
- #2004와 #2195에서 실제로 달라지는 값만 식별한다.
- 현재 전체 섹션 복제량과 반복 렌더 시 재사용 기준을 측정한다.

### Stage 2 — revision 및 overlay 기반 도입

- 문서 epoch, 섹션 구조/페이지 기하 revision, 경로 revision을 추가한다.
- 명시적 variant를 가진 `RenderPathEntry`와 논리 `RenderPath`를 정의한다.
- `RenderNormalizationOverlay` 캐시와 revision 검증 규칙을 구현한다.
- 기존 `mark_section_dirty`는 안전한 섹션 범위 무효화를 유지한다.

### Stage 3 — #2004 이미지 스택 정규화 이전

- TAC 유효 control index와 합성 line projection만 overlay에 저장한다.
- 원본 paragraph/control은 source IR에서 읽는다.
- 기존 clone 기반 이미지 스택 보정 경로를 제거한다.

### Stage 4 — #2195 중첩 표 너비 정규화 이전

- 논리 경로별 effective nested-table width만 overlay에 저장한다.
- `LayoutEngine` 소비부가 `RenderNormalizationView`를 통해 유효 값을 조회하게 한다.
- clone/mirror 갱신 함수와 sentinel caption 경로를 제거한다.

### Stage 5 — 무효화·재사용·회귀 검증

- 안정 경로 변경은 해당 entry만 재파생되는지 확인한다.
- 구조 변경은 섹션 overlay를 폐기하고 재생성하는지 확인한다.
- 경로 불일치에서 stale 값이 사용되지 않는지 확인한다.
- 영향받지 않은 sibling entry와 레이아웃 캐시의 `Arc` identity 재사용을 확인한다.

### Stage 6 — 통합·시각 검증·문서화

- focused Rust test와 source guard를 실행한다.
- OVR(no-HWP) 및 Hancom 기준 OVL 시각 검증 근거를 남긴다.
- 기술 문서와 완료 보고서에 새 소유권·revision·fallback 계약을 반영한다.
- focused 검증 결과를 공유한 뒤 전체 release test, clippy, WASM, Studio/E2E 실행 여부를 별도 승인받는다.
