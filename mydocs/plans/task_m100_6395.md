## 1. 목표

rhwp-studio에서 현재 화면 밖에 새 쪽이 생기는 배율로 `Command+Enter` 쪽 나누기를 실행해도 다음 계약을
만족한다.

1. 문서 커서는 새 쪽의 새 문단 첫 위치로 이동한다.
2. DOM 캐럿은 갱신된 `VirtualScroll`의 새 쪽 offset으로 다시 배치된다.
3. 편집 영역은 캐럿이 viewport 안에 들어오도록 즉시 스크롤된다.
4. 같은 비동기 레이아웃 경계를 쓰는 단 나누기와 쪽/단 나누기 undo·redo도 같은 재표시 정책을 쓴다.

## 2. 원인 가설과 확인 결과

쪽 나누기 편집 결과와 커서 위치는 WASM에서 즉시 갱신되지만, `CanvasView`의 mutation 렌더 선택과
`VirtualScroll` 페이지 재계산은 비동기로 끝난다. `InputHandler.afterEdit()` 직후 첫 캐럿 계산은 이전 페이지
배치를 사용하므로 아직 없는 새 page index의 offset이 0으로 해석된다. 이후 페이지가 갱신되어도 해당 명령의
캐럿 좌표 재계산과 viewport reveal이 자동으로 이어지지 않는 것이 증상의 직접 원인이다.

## 3. 범위

### 범위 안

- mutation 레이아웃 완료 경계를 `CanvasView`에서 알리는 내부 이벤트
- 쪽/단 나누기와 그 history snapshot만 다음 완료 이벤트에서 한 번 reveal하는 정책
- 완료 시 커서 rect 재계산, DOM 캐럿 갱신, 기존 scroll-into-view 재사용
- 순수 정책 unit test와 150% 실제 Chrome `Meta+Enter` E2E
- E2E manifest와 npm 실행 진입점

### 범위 밖

- Rust/WASM 편집 명령이나 문서 pagination 알고리즘 변경
- 일반 텍스트 입력마다 강제 스크롤하는 전역 정책
- 한글 2024 자체의 자동화·정량 비교
- 모바일 키보드 shortcut과 플랫폼별 modifier 정책 변경

## 4. 단계

### Stage 0 — 이슈·계획 정식화

- 동일 증상 열린/닫힌 이슈를 검색하고 #6395를 등록한다.
- assignee, `v1.0.0`, `bug`·`rhwp-studio`·`typescript` metadata를 고정한다.
- 수행 계획과 파일 단위 구현 계획을 별도 계획 commit으로 남긴다.

**종료 게이트**: 계획 commit이 최신 `upstream/devel` 기반 작업 branch에 존재한다.

### Stage 1 — 레이아웃 완료 뒤 1회 reveal

- `pageBreak`, `columnBreak`와 `snapshot:*` history type을 인식하는 one-shot 정책을 추가한다.
- `CanvasView.refreshPagesForMutation()`이 현재 revision의 page refresh를 끝낸 뒤 완료 이벤트를 보낸다.
- `InputHandler`가 예약된 경우에만 cursor rect와 DOM 캐럿을 다시 계산해 viewport reveal을 수행한다.

**종료 게이트**: 일반 편집에는 영향이 없고 경계 명령은 완료 이벤트 한 번만 소비한다.

### Stage 2 — 회귀 검증

- TypeScript 검사, rhwp-studio 전체 unit test, production build를 통과시킨다.
- 실제 Chrome에서 150% 배율의 한 쪽 문서에 `Meta+Enter`를 입력한다.
- 새 문단 위치, page index/offset, DOM 캐럿 좌표, `scrollTop`, viewport 여백을 함께 단언한다.
- E2E manifest 정합성과 `git diff --check`를 확인한다.

**종료 게이트**: 이슈 #6395 수용 기준이 자동 검증으로 고정되고 검증 결과가 stage·최종 보고서에 남는다.

### Stage 3 — Open PR과 self-review 기록

- 검증한 code candidate를 원본 저장소의 작업 branch에 push하고 Open PR을 생성한다.
- PR 번호가 발급된 뒤 archive self-review 문서와 오늘할일을 trailing 문서 commit으로 같은 PR에 포함한다.
- 최신 PR head의 GitHub Actions와 mergeability는 merge 전 별도로 재확인한다.

**종료 게이트**: PR diff에 구현·테스트·계획·보고·self-review 기록이 포함되고 CI가 최신 head에서 시작한다.

## 5. 위험과 rollback

- 오래된 mutation 완료 이벤트가 예약을 먼저 소비하지 않도록 `CanvasView`가 current revision을 확인한 뒤에만
  이벤트를 보낸다.
- 일반 편집의 스크롤 동작 변화는 operation type allowlist와 one-shot consume으로 차단한다.
- 회귀 시 `CaretLayoutReveal`, 완료 이벤트, 세 호출부를 함께 revert하면 기존 동작으로 복원된다.
