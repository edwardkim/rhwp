# #7998 PDF 표 추론 후속 일감

- Issue: [#7998](https://github.com/edwardkim/rhwp/issues/7998)
- 구현 기준: `1d54f8a09d3242d17a54df4d6b5b3a8a7859b4e4`
- [승인 계획](task_m100_7998_impl.md)의 제품 경로를 먼저 연결한 뒤, 다음 세부 항목을 보완한다.
- 아래 미완료 범위 때문에 전체 PDF 표 인식이나 작성 객체 복원을 완료했다고 표시하지 않는다.

| 일감 | 현재 상태와 다음 완료 조건 |
|---|---|
| B01 모호한 셀의 추가 근거와 판정 | paint 부재와 셀 연결을 분리했고 분리/연결 대안을 남긴다. 보류를 없애기 위해 조건을 덧붙이지 않는다. 독립적인 내용·구역·경계 증거로 해석을 좁힐 수 있는 사례부터 구현하고, PDF만으로 구분 불가능한 경우는 계속 보류한다. |
| B02 점선·혼합 괘선의 편집 가능한 표 생성 | 짧은 원본 선분, 점선 carrier, raw/복원 coverage는 보존된다. 기존 TableBuilder가 paint를 보존할 수 없는 후보는 positional 상태를 유지한다. 실제 dash·선폭·색·원본 순서를 보존하는 공통 IR 소비 계약을 검증한 뒤 표로 승격한다. |
| B03 지역 격자의 선택과 공유 경계 | 포함·경계 공유의 평면/지역 대안과 축 출처를 출력한다. 새 clip·문자 간격·전역 후보와 T0/T1은 현재 진단 가설이며 실제 Builder 입력은 paint 기반 검출이다. 선택한 새 해석의 셀 소속·단일 내용 소유·최종 IR/저장을 연결하고 대안/선택 근거를 보존한다. 현재 공간 포함 기록은 자식 표 확정이 아니다. Excel 샘플의 작성 당시 셀 수는 정답으로 가정하지 않는다. |
| B04 후보 생성의 범위 | 기본 문자 간격·클립 인접·paint·전역 비교를 연결했다. 단독 1×1 구역, 복잡한 클립 교차, 다중 문단·세로/회전 문자 등은 관측 가능 여부와 frontend 지원 범위를 구분해 확장한다. 기존 회전 페이지 거절을 이번에 해결했다고 보고하지 않는다. |
| B05 설정·가시성·진단 보존 | 현재 규칙 버전·기본 설정·선택 상세 진단·각 단계 제한을 출력한다. 문자 ID는 backend Unicode span/character의 식별자이며 원본 font GID/operator 전체 보존이 아니다. 의미 공백·근사 box의 생성 출처, 문서별 설정 전달, 상세 근거의 문서 단위 보존 정책과 clip 교차/occlusion을 세분화한다. 흰색만으로 문자를 삭제하지 않는 계약은 유지한다. |
| B06 실제 구조 평가 집합 | 실험 JSON은 가설 비교 자료다. 공개 가능한 정상/반례와 사용자 합의 구조를 별도 관리하고, 동일 source·설정에서 축/소속/보류의 결정성과 의미 보존 변형을 검증한다. 픽셀 일치가 작성 객체 복원의 정답이라는 주장을 하지 않는다. |
| B07 기존 시각 차이의 판정 | 원래 PDF 3쪽 Native 및 견적서의 현행 기준 미달을 추적한다. 견적서는 0.12pt 괘선의 `thinlinemode=shape`/`none` 차이가 확인됐다. 진단용 `none` 점수를 정식 gate로 바꾸거나 소스 두께를 늘려 점수를 맞추지 않는다. 독립 PDF·실제 공급 글꼴·원본/변환본 직접 판독에 따라 처리 범위를 결정한다. |

첫 절편에서 정상 2×2 합성 대조군은 공통 IR의 의미 표 1개로 생성됐다. 사용자 원본의
불확실한 후보는 원래 문자·그림·paint를 유지한다. 후보 검출 수, 의미 표 생성 수,
시각 gate, 작성 당시 구조의 검증 여부는 각각 별도로 기록한다.

## 검증 자료의 사용 경계

- 원본 PDF와 기존 실험 묶음, 견적서 연락처·주소, 로컬 글꼴은 저장소 밖의 검증 자료로 보존한다.
- 1차 새 검사 중 4건은 PDF 관측/API 계약이며 렌더링 golden이나 실물 조판의 절대 좌표 검사가 아니다.
- 정상 대조군의 추가 1건은 선행 시각 조건 확인 후 HWP/HWPX 저장의 단일 내용 소유를 검사한다.
- 실제 배치 회귀는 Native/fresh Docker WASM의 선행 시각 조건을 충족한 입력에만 등록한다.
- 기존 검증과 캐시는 그대로 재사용한다. 상세 항목을 진행할 때 영향받은 증거만 갱신하며,
  같은 소스의 빌드나 이미 확인한 무관한 검사를 반복하지 않는다.
