# #7998 PDF 표 추론 후속 일감

- Issue: [#7998](https://github.com/edwardkim/rhwp/issues/7998)
- 구현 기준: `1d54f8a09d3242d17a54df4d6b5b3a8a7859b4e4`
- [승인 계획](task_m100_7998_impl.md)의 제품 경로를 먼저 연결한 뒤, 다음 세부 항목을 보완한다.
- 아래 미완료 범위 때문에 전체 PDF 표 인식이나 작성 객체 복원을 완료했다고 표시하지 않는다.
- 2026-10-18 지시의 **문자 덩어리·글줄·문단 복원(B10–B13)은 이번 #7998의 구현 범위**다.
  이름이 백로그라는 이유로 후속 이슈로 넘기지 않는다. [계획 4.1절](task_m100_7998_impl.md#41-이번-범위의-글줄문단-복원과-실제-ir-연결)을 따른다.
- 실행 순서는 [계획 4.3절의 P1–P5](task_m100_7998_impl.md#43-분할정복-실행-순서와-절편별-완료-조건)를
  따른다. B10–B13을 모듈별로 따로 끝내지 않고 P1 셀 다중 글줄 → P2 혼합 run/공백 →
  P3 본문 지역 → P4 표/문단 합성으로 실제 IR·편집·저장을 연결한다. 각 행은 상세 일감이며
  실행 우선순위를 대신하지 않는다. P1의 영문 메트릭·시각 보류는 해소됐고 메인테이너가 직접 판정했다. 현재 미완료 절편은 P2다. 수평 전진폭·공백과 탭의 저장 stream 축을 보정했으며 최종 저장본 자동 검증을 통과했다. 7쪽도 메인테이너의 직접 시각 판정을 통과했다. 혼합 baseline·위첨자까지 통과했다고 보고하지 않는다.

| 일감 | 현재 상태와 다음 완료 조건 |
|---|---|
| B01 모호한 셀의 추가 근거와 판정 | paint 부재와 셀 연결을 분리했고 분리/연결 대안을 남긴다. 보류를 없애기 위해 조건을 덧붙이지 않는다. 독립적인 내용·구역·경계 증거로 해석을 좁힐 수 있는 사례부터 구현하고, PDF만으로 구분 불가능한 경우는 계속 보류한다. |
| B02 점선·혼합 괘선의 편집 가능한 표 생성 | 짧은 원본 선분, 점선 carrier, raw/복원 coverage는 보존된다. [3차 구현](../working/task_m100_7998_stage3.md)에서 native paint 경계의 보고서 7개·견적서 내부 1개를 실제 셀 본문으로 승격했다. 비표준 경계는 셀 drawing이며 border 스타일의 편집 계약은 남는다. compound 경계 picture는 손상이 확인돼 원래 paint와 positional 상태를 유지한다. P2에서 수평 advance와 탭 저장 축을 보완했다. border 스타일과 나머지 편집 계약의 미완료가 있어 이 항목 전체의 완료는 아니다. |
| B03 지역 격자의 선택과 공유 경계 | 포함·경계 공유의 평면/지역 대안과 축 출처를 출력한다. 새 clip·문자 간격·전역 후보와 T0/T1은 현재 진단 가설이며 실제 Builder 입력은 paint 기반 검출이다. 선택한 새 해석의 셀 소속·단일 내용 소유·최종 IR/저장을 연결하고 대안/선택 근거를 보존한다. 현재 공간 포함 기록은 자식 표 확정이 아니다. Excel 샘플의 작성 당시 셀 수는 정답으로 가정하지 않는다. |
| B04 후보 생성의 범위 | 기본 문자 간격·클립 인접·paint·전역 비교를 연결했다. 다중 문단은 B10–B13으로 이번 처리에 포함한다. 단독 1×1 구역, 복잡한 클립 교차, 세로/회전 문자는 관측 가능 여부와 frontend 지원 범위를 구분한다. 기존 회전 페이지 거절을 이번에 해결했다고 보고하지 않는다. |
| B05 설정·가시성·진단 보존 | 현재 규칙 버전·기본 설정·선택 상세 진단·각 단계 제한을 출력한다. 문자 ID는 backend Unicode span/character의 식별자이며 원본 font GID/operator 전체 보존이 아니다. 의미 공백·근사 box의 생성 출처, 문서별 설정 전달, 상세 근거의 문서 단위 보존 정책과 clip 교차/occlusion을 세분화한다. 흰색만으로 문자를 삭제하지 않는 계약은 유지한다. |
| B06 실제 구조 평가 집합 | 실험 JSON은 가설 비교 자료다. 공개 가능한 정상/반례와 사용자 합의 구조를 별도 관리하고, 동일 source·설정에서 축/소속/보류의 결정성과 의미 보존 변형을 검증한다. 픽셀 일치가 작성 객체 복원의 정답이라는 주장을 하지 않는다. |
| B07 기존 시각 차이의 판정 | 2026-10-18 지시로 이번 보정 범위에 포함했다. Batang의 실제 공급·선택을 확인했고, fill이 stroke 상태에 따라 사라지는 독립 PDF 검사로 reference 향상 모드의 결함을 수정했다. 원래 shape 결과를 보존하며 같은 보정 조건의 새 base/후보를 전쪽 비교했다. 후보 Native/fresh WASM 최저는 operators 91.04017/90.62487%, 견적서 99.85062/99.74444%이며 하락·쪽수 차이가 없다. 전체 로컬 검증을 통과했고 메인테이너 직접 시각 판정은 대기 중이다. [2차 기록](../working/task_m100_7998_stage2.md)을 따른다. |
| B08 글꼴 공급 제한의 가시화 | 큰 디렉터리를 공급하면 기존 64MiB 예산 때문에 뒤의 필요한 face가 빠질 수 있다. 이번 검증은 필요한 Batang만 든 디렉터리와 실제 Native trace로 해결했다. 예산을 무조건 늘리지 않고 누락 이유·문서 요청 face의 공급 여부를 사용자에게 보이는 후속 진단 계약을 검토한다. |
| B09 Docker 공유 cache의 소스 신원 | 서로 다른 checkout을 동일한 /app에 mount하면 더 오래된 mtime의 수정 source가 기준 backend artifact를 재사용할 수 있었다. 이번에는 소스 SHA를 확인하고 변경된 backend 네 파일의 mtime만 갱신해 재컴파일했다. 공유 target 초기화 없이 source-content 신원을 검증하는 재사용 절차를 후속 보완한다. |
| B10 공통 문자·글줄과 지역화 | 이번 범위. P1에서 `ObservedText`/`SourceTextRange`/`TextLine`을 도입해 T0와 소유 구역의 recognition이 같은 글줄 결과를 소비한다. 상세 glyph 예산 이후의 coarse source 범위도 유지한다. source 문자/UTF-16·geometry quality를 보존하고, 같은 높이의 두 단·다른 셀·위첨자·span 분할 반례에서 줄 소속과 결정성을 검증한다. |
| B11 문단 경계와 읽기 순서 | 이번 범위. P1의 두 주석 대조군에서 여러 줄 한 문단/별도 문단, 내어쓰기·가운데 정렬의 typed 제안과 실제 소비를 연결했다. 실물의 원래 문단 수를 검증했다는 주장은 아니다. 지역의 줄 간격·정렬·들여쓰기/목록·장애물 근거를 보완한다. 시각 줄바꿈과 문단 끝을 구분하며, 한 모호한 줄 뒤의 정상 내용을 일괄 보류하지 않는다. 두 줄 한 문단/두 문단의 독립 대조와 본문/셀 원문자 소유를 확인한다. |
| B12 실제 Paragraph/LineSeg 소비 | 이번 범위. P1의 확정된 셀 제안은 여러 `LineSeg`를 가진 한 `Paragraph`로 생성한다. 표현 불가·보류 제안은 줄 frame을 유지하고 의미 복원 미검증으로 남긴다. 본문의 한 span 한 TextBox는 P3 미완료다. Helvetica는 독립 Adobe AFM 전진폭을 실제 공통 측정에 연결해 P1 시각 보류를 해소했다. PDF 글줄의 source 원점/전진폭을 공통 장평·자간으로 표현했고 5쪽 끝 글자 표시를 확인했다. 생성한 탭의 내용→stream 축도 문자·글자모양·LineSeg에 함께 반영했다. 혼합 기준선과 표현 불가 줄은 아직 미완료다. 진단과 실제 셀/본문이 공통 문단 결과를 소비하며, 줄 폭·advance·정렬·원점이 측정과 최종 배치에서 같은 계약을 갖도록 한다. 위첨자 2가 원본보다 내려가는 외부 반례는 source baseline의 공통 소비를 추적해 이 경계에서 보완한다. |
| B13 편집·저장과 문단 검토 화면 | 이번 범위. P1의 두 대조군은 실제 Studio에서 삽입/삭제·문단 split/merge·양 저장 형식 재열기의 정확한 문자열·문단 소속을 통과했다. Native 저장/재열기 PNG도 직접 PDF import 결과와 같다. 견적서의 삽입 공백은 trim된 기대값 때문에 잘못 진단했으며, 과거/현재 저장본의 정확한 접두어+원문 보존을 확인했다. 혼합 run·baseline은 여전히 미완료다. 글줄 box와 문단 묶음·읽기 순서·실제 IR을 구분해 검토 화면에 제공한다. 보고서 7쪽은 탭을 1유닛으로 만든 IR의 저장 축 때문에 양 형식 재열기에서 실패했고, 8유닛 stream 매핑으로 보정한 뒤 최종 Native/fresh WASM·양 저장 형식 자동 검증을 통과했다. 7쪽도 메인테이너의 직접 시각 판정을 통과했다. |

첫 절편에서 정상 2×2 합성 대조군은 공통 IR의 의미 표 1개로 생성됐다. 사용자 원본의
불확실한 후보는 원래 문자·그림·paint를 유지한다. 후보 검출 수, 의미 표 생성 수,
시각 gate, 작성 당시 구조의 검증 여부는 각각 별도로 기록한다.

## 검증 자료의 사용 경계

- 원본 PDF와 기존 실험 묶음, 견적서 연락처·주소, 로컬 글꼴은 저장소 밖의 검증 자료로 보존한다.
- 1차 새 검사 중 4건은 PDF 관측/API 계약이며 렌더링 golden이나 실물 조판의 절대 좌표 검사가 아니다.
- 정상 대조군의 추가 1건은 선행 시각 조건 확인 후 HWP/HWPX 저장의 단일 내용 소유를 검사한다.
- 실제 배치 회귀는 Native/fresh Docker WASM의 선행 시각 조건을 충족한 입력에만 등록한다.
- 기존 검증과 캐시는 그대로 재사용한다. 상세 항목을 진행할 때 영향받은 증거만 갱신하며,
  같은 소스의 빌드나 이미 확인한 무관한 검사를 반복하지 않는다.
