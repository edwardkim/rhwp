# #7998 PDF 표 추론 후속 일감

- Issue: [#7998](https://github.com/edwardkim/rhwp/issues/7998)
- 구현 기준: `1d54f8a09d3242d17a54df4d6b5b3a8a7859b4e4`
- [승인 계획](task_m100_7998_impl.md)의 제품 경로를 먼저 연결한 뒤, 다음 세부 항목을 보완한다.
- 아래 미완료 범위 때문에 전체 PDF 표 인식이나 작성 객체 복원을 완료했다고 표시하지 않는다.
- 2026-10-18 지시의 **문자 덩어리·글줄·문단 복원(B10–B13)은 이번 #7998의 구현 범위**다.
  이름이 백로그라는 이유로 후속 이슈로 넘기지 않는다. [계획 4.1절](task_m100_7998_impl.md#41-이번-범위의-글줄문단-복원과-실제-ir-연결)을 따른다.
- 실행 순서는 [계획 4.3절의 P1–P5](task_m100_7998_impl.md#43-분할정복-실행-순서와-절편별-완료-조건)를
  따른다. B10–B13을 모듈별로 따로 끝내지 않고 P1 셀 다중 글줄 → P2 혼합 run/공백 →
  P3 본문 지역 → P4 표/문단 합성으로 실제 IR·편집·저장을 연결한다. 각 행은 상세 일감이며
  실행 우선순위를 대신하지 않는다. P1과 P2의 수평 전진폭·공백·탭 저장 축, 혼합 baseline
  절편은 실제 셀 편집과 양 저장 형식까지 연결했다. 7쪽과 혼합 기준선 대조군은 메인테이너의
  직접 시각 판정을 통과했다. P2의 모든 원본 글꼴 메트릭 복원이 완료된 것은 아니다.
  P3 첫 본문 절편의 실제 문단·편집/저장 경계를 연결했다. 보고서의 수평 보류는 현재 15줄이며,
  본문 표현 보류와 P4의 표/문단 합성을 B12에 유지한다. P3 절편의 시각·문단 구조는
  2026-10-18 메인테이너 직접 판정을 통과했다(code checkpoint `b923b179a`).
  P4 첫 합성 절편도 2026-10-18 **“시각·중첩 구조 통과”**로 수용됐다.
  [stage4](../working/task_m100_7998_stage4.md)의 실제 중첩 소유·자식 편집·양 저장 형식
  증거를 재사용한다. 두 번째 절편의 compound 경계 원본 7개와 변형 4개도
  **“시각·중첩 구조 통과”**로 수용됐다. 세 번째 절편 B14와 네 번째 연속 실선 경계·행열 편집(B15)도 **“시각·편집 구조 통과”**로 수용됐다. 다섯 번째 B16의 보존 paint 저장·재소비도 **“시각·편집 구조 통과”**로 수용됐다. 비표준 paint 경계의 일반 편집·병합/지역 격자와 P5는 남는다.

| 일감 | 현재 상태와 다음 완료 조건 |
|---|---|
| B01 모호한 셀의 추가 근거와 판정 | paint 부재와 셀 연결을 분리했고 분리/연결 대안을 남긴다. 보류를 없애기 위해 조건을 덧붙이지 않는다. 독립적인 내용·구역·경계 증거로 해석을 좁힐 수 있는 사례부터 구현하고, PDF만으로 구분 불가능한 경우는 계속 보류한다. |
| B02 점선·혼합 괘선의 편집 가능한 표 생성 | 짧은 원본 선분, 점선 carrier, raw/복원 coverage는 보존된다. [3차 구현](../working/task_m100_7998_stage3.md)에서 native paint 경계의 보고서 7개·견적서 내부 1개를 실제 셀 본문으로 승격했다. P4 첫 절편은 periodic 경계 family의 실제 중첩 Table·부모/자식 배경 소유를 연결했고 직접 시각·구조 판정을 통과했다. 비표준 경계는 셀 drawing이며 border 스타일의 편집 계약은 남는다. 두 번째 절편은 같은 PDF dash 원본 7개와 phase/alpha·clip·곡선 배경/전경 4개의 source 이미지 범위·물리 셀 소유를 검증했다. 10개는 실제 중첩 표와 자식 편집·양 저장 형식으로 연결했고, 글자를 나중에 덮는 전경 1개는 원래 positional 소유·순서를 유지한다. 반투명 래스터 농도 차이와 점수 하락을 기록한 직접 수용이며 border 스타일·행열 편집은 남는다. |
| B03 지역 격자의 선택과 공유 경계 | 포함·경계 공유의 평면/지역 대안과 축 출처를 출력한다. B18은 정상 paint 격자 안에서 실제 text-show의 활성 clip·공통 glyph 근거가 완전한 tiling을 이루는 해석을 Builder·편집·양 저장에 연결했다. 일반 clip 인접/문자 간격/전역 후보 전체를 채택한 것은 아니다. P4 다음 절편은 닫힌 paint 외곽 안의 실제 내용 clip 축과 사방 선이 확인되는 빈 단일 tile를 구현했다. L자 paint를 의미 병합으로 오인하지 않고 한 행/한 열 표도 같은 소비로 연결했다. 전쪽 Native/fresh WASM 각 318쪽과 정식 집중 51건을 검증했으며 2026-10-19 직접 시각 판정을 통과했다. [stage9](../working/task_m100_7998_stage9.md)의 source·판정 범위를 따른다. 빈 병합 구역/숨긴 변의 빈 셀은 미확정으로 보존하고, 일반 무외곽·부분 격자는 남는다. 대안과 작성 객체 미확정 상태를 보존하며 Excel의 작성 당시 셀 수를 정답으로 가정하지 않는다. |
| B04 후보 생성의 범위 | 기본 문자 간격·클립 인접·paint·전역 비교를 연결했다. 다중 문단은 B10–B13으로 이번 처리에 포함한다. 단독 1×1 구역, 복잡한 클립 교차, 세로/회전 문자는 관측 가능 여부와 frontend 지원 범위를 구분한다. 기존 회전 페이지 거절을 이번에 해결했다고 보고하지 않는다. |
| B05 설정·가시성·진단 보존 | 현재 규칙 버전·기본 설정·선택 상세 진단·각 단계 제한을 출력한다. 문자 ID는 backend Unicode span/character의 식별자이며 원본 font GID/operator 전체 보존이 아니다. 의미 공백·근사 box의 생성 출처, 문서별 설정 전달, 상세 근거의 문서 단위 보존 정책과 clip 교차/occlusion을 세분화한다. 흰색만으로 문자를 삭제하지 않는 계약은 유지한다. |
| B06 실제 구조 평가 집합 | 실험 JSON은 가설 비교 자료다. 공개 가능한 정상/반례와 사용자 합의 구조를 별도 관리하고, 동일 source·설정에서 축/소속/보류의 결정성과 의미 보존 변형을 검증한다. 픽셀 일치가 작성 객체 복원의 정답이라는 주장을 하지 않는다. |
| B07 기존 시각 차이의 판정 | 2026-10-18 지시로 이번 보정 범위에 포함했다. Batang의 실제 공급·선택을 확인했고, fill이 stroke 상태에 따라 사라지는 독립 PDF 검사로 reference 향상 모드의 결함을 수정했다. 원래 shape 결과를 보존하며 같은 보정 조건의 새 base/후보를 전쪽 비교했다. 후보 Native/fresh WASM 최저는 operators 91.04017/90.62487%, 견적서 99.85062/99.74444%이며 하락·쪽수 차이가 없다. 전체 로컬 검증을 통과했고 메인테이너 직접 시각 판정은 대기 중이다. [2차 기록](../working/task_m100_7998_stage2.md)을 따른다. |
| B08 글꼴 공급 제한의 가시화 | 큰 디렉터리를 공급하면 기존 64MiB 예산 때문에 뒤의 필요한 face가 빠질 수 있다. 이번 검증은 필요한 Batang만 든 디렉터리와 실제 Native trace로 해결했다. 예산을 무조건 늘리지 않고 누락 이유·문서 요청 face의 공급 여부를 사용자에게 보이는 후속 진단 계약을 검토한다. B14의 원래 Helvetica를 한컴 2020이 Haansoft Batang으로 대체한 long-suffix는 Native 88.50536%다. 명시적 Arial 대조군의 통과와 구분하며 P5 글꼴·출력 판정 대상으로 남긴다. |
| B09 Docker 공유 cache의 소스 신원 | 서로 다른 checkout을 동일한 /app에 mount하면 더 오래된 mtime의 수정 source가 기준 backend artifact를 재사용할 수 있었다. 이번에는 소스 SHA를 확인하고 변경된 backend 네 파일의 mtime만 갱신해 재컴파일했다. 공유 target 초기화 없이 source-content 신원을 검증하는 재사용 절차를 후속 보완한다. |
| B10 공통 문자·글줄과 지역화 | 이번 범위. P1에서 `ObservedText`/`SourceTextRange`/`TextLine`을 도입해 T0와 소유 구역의 recognition이 같은 글줄 결과를 소비한다. 상세 glyph 예산 이후의 coarse source 범위도 유지한다. P2에서는 painted 문자와 span의 Ts/Tm/CTM 원점을 일치시켜 원래 문자·크기를 보존했고, 작은 첨자·혼합 크기·선두 첨자·분리되어야 할 작은 줄을 대조했다. owner-local 추론이며 모든 drop-cap·본문 지역의 작성 구조를 입증한 것은 아니다. P3에서는 반복 baseline의 gutter 근거로 두 단·넓은 제목의 owner를 분리하고, 가용 폭을 ink 합집합과 구분했다. drop-cap 일반 복원은 미검증이다. |
| B11 문단 경계와 읽기 순서 | 이번 범위. P1의 두 주석 대조군에서 여러 줄 한 문단/별도 문단, 내어쓰기·가운데 정렬의 typed 제안과 실제 소비를 연결했다. 실물의 원래 문단 수를 검증했다는 주장은 아니다. 지역의 줄 간격·정렬·들여쓰기/목록·장애물 근거를 보완한다. 시각 줄바꿈과 문단 끝을 구분하며, 한 모호한 줄 뒤의 정상 내용을 일괄 보류하지 않는다. P3 독립 대조에서 두 줄 한 문단/두 문단·양방향 첫 들여쓰기·목록·가까운 제목을 실제 문단과 연결했고, 모호한 구역/수평 표현 보류 뒤의 정상 문단을 유지한다. 실물의 작성 당시 문단 경계를 전수 확정했다는 뜻은 아니다. |
| B12 실제 Paragraph/LineSeg 소비 | 이번 범위. P1의 확정된 셀 제안은 여러 `LineSeg`를 가진 한 `Paragraph`로 생성한다. P3는 표현 가능한 본문 제안을 복수 Paragraph/LineSeg의 실제 TextBox로 발행하고 동일 adapter를 소비한다. 실패 시 스타일·진단과 source 소유를 원자적으로 보존한다. Helvetica는 독립 Adobe AFM 전진폭을 공통 측정에 연결했다. P2의 source 원점/전진폭은 공통 장평·자간, 탭은 내용→stream 축, baseline은 일반 `CharShape.char_offsets`와 공통 draw 결과로 연결했다. 작은 PDF 글자에 script flag를 덧붙이지 않는다. 무편집 source 줄과 편집 후 재조판을 구분한다. P3 보고서에는 실제 본문 문단 26개를 발행했고, 셀/본문을 합친 typography 기록은 관측 메트릭 218개/legacy frame 15개다. 정수 반올림 폭 대신 실제 배치와 같은 소수 폭으로 비교해 일부 거짓 보류를 해소했다. 본문에는 별도로 장평/자간 표현·판정 보류가 남는다. 이 줄도 baseline은 보존하나 수평 메트릭 복원은 미검증이다. 표현 범위를 넓히거나 clamp하지 않고 B12·P4 통합에서 원래 font/advance 근거와 대조한다. |
| B13 편집·저장과 문단 검토 화면 | 이번 범위. P1의 실제 Studio 삽입/삭제·문단 split/merge·양 저장 형식 재열기를 P2 혼합 run·baseline 대조군에도 연결했다. 원문과 이웃 셀 소유·실제 크기/기준선 관계를 검사한다. 무편집 저장본의 PNG 동일성과 편집 후 재조판을 별도 판정한다. 견적서의 삽입 공백은 trim된 기대값의 오인이었고 원문 보존을 확인했다. 보고서 7쪽의 탭 stream 축은 보정 후 메인테이너 직접 시각 판정을 통과했다. 혼합 기준선도 직접 통과했으며 같은 출력의 판정을 반복 요청하지 않는다. P3 본문 13개 대조군은 실제 Native/Studio WASM의 삽입·삭제·split/merge와 HWP/HWPX 재열기를 통과했다. 원본 위 인식 제안과 실제 IR 줄/문단을 검토 화면에서 구분한다. P3 직접 판정에 이어 P4 중첩 family 8개도 자식 셀 삽입·삭제·양 저장 형식과 실제 Studio 경로를 통과했다. 두 번째 P4 절편은 compound 10개 family의 실제 Native/Studio WASM 자식 편집·저장·재열기도 통과했다. B14의 긴 그림 host도 실제 Native/Studio WASM 삽입·삭제·HWP/HWPX 재열기와 직접 시각·편집 구조 판정을 통과했다. 테두리/행열 편집과 P5 최신 devel 검증은 남는다. |

- P2 기준선 owner 탐색은 기존 line group들을 비교한다. frontend의 페이지당 span 20,000개
