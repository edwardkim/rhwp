## 1. 배경 및 문제 정의

기존 `hwpx-roundtrip` baseline 게이트(Task #1315)는 **IR 뼈대(구조) 보존만** 검증한다.
`roundtrip_ir_diff` 가 0 이어도 라운드트립(parse→serialize→reparse)이 **렌더 결과를
바꾸는** 경우 — 페이지 수 변화, 렌더 노드 삽입/삭제, bbox 좌표 변위 — 를 검출하지 못한다.
`hwpx_roundtrip_baseline.md` 에도 "통과 = 구조 보존이며 시각 충실도 보장이 아니다"로
명시되어 있다. 이 공백을 메우는 **렌더 기하 회귀 게이트**가 필요하다.

### 현재 코드 자산 (조사 결과)

| 자산 | 위치 | 역할 |
|------|------|------|
| 렌더 트리 생성 | `document_core/queries/rendering.rs:237` `build_page_render_tree(page) -> PageRenderTree` | 페이지별 `RenderNode` 트리 |
| 렌더 노드 모델 | `renderer/render_tree.rs` `RenderNode{ node_type, bbox, children }`, `RenderNodeType`(24종), `BoundingBox{x,y,w,h}` | 비교 대상 |

| 배치 게이트 선례 | `diagnostics/hwpx_roundtrip_batch.rs` (577줄), `tests/hwpx_roundtrip_baseline.rs` (XFAIL/EXCLUDED 등급제) | 신설 게이트의 구조적 본보기 |

### 참고 (P1 분리 — 본 타스크 범위 밖)

## 2. 목표 (이슈 범위 1:1 매핑)

1. **렌더 기하 비교 코어**: 두 문서의 페이지별 `RenderNode` bbox 를 **타입 LCS 매칭**으로
   비교한다. 삽입/삭제가 있어도 대응 노드의 변위(displacement)를 측정하고, 구조
   불일치(페이지 수·매칭 실패)는 별도 분류한다. 폰트 래스터화에 의존하지 않는다.
2. **`render-diff` CLI**: 아래 3개 모드.
   - 자기 라운드트립: `rhwp render-diff <a.hwpx>` (원본 IR 렌더 vs 직렬화→재parse IR 렌더)
   - 두 파일 비교: `rhwp render-diff <a.hwpx> <b.hwpx>`
   - 배치: `rhwp render-diff --batch samples/hwpx -o <out>` → `geom_inventory.tsv`
3. **회귀 baseline 테스트** `tests/visual_roundtrip_baseline.rs`: `samples/hwpx` 전수에 대해
   페이지 수 보존 + 구조 불일치 없음 + 최대 변위 ≤ 임계(실측 0.0px → 임계 0.5px).
   기존 baseline 과 동일한 XFAIL/EXCLUDED 등급제·신규 샘플 자동 포함을 따른다.

### 비목표 (명시)

- 한컴 정답지(PDF) 시각 충실도 검증 — 자기 roundtrip 통과 ≠ 한컴 호환. **내부 회귀 방지만** 보장.
- 픽셀/SSIM 래스터 비교 — P1 후속.
- 텍스트/글자모양 등 비기하 속성 비교 — 그것은 기존 `ir-diff`/`hwpx-roundtrip` 담당.

## 3. 비교 알고리즘 설계 (코어)

페이지별로 `RenderNode` 트리를 **전위순회 평탄화**하여 `(node_type_tag, bbox)` 시퀀스를
만든 뒤 두 시퀀스를 비교한다.

1. **페이지 수 비교**: `page_count(a) != page_count(b)` → `PageCountMismatch` (구조 불일치, 하드).
2. **노드 시퀀스 정렬**: 페이지별 평탄 시퀀스를 **타입 태그 LCS**로 정렬.
   - 매칭쌍(공통 부분수열): bbox 변위 측정.
   - LCS 밖(한쪽에만 존재): 삽입/삭제로 분류·카운트.
3. **변위 지표**:
   - 매칭쌍별 변위 = `max(|Δx|, |Δy|, |Δw|, |Δh|)` (px).
   - 페이지/문서 단위 **max displacement**, 삽입/삭제 카운트 집계.
4. **판정 등급** (baseline 게이트 기준):
   - PASS: 페이지 수 일치 ∧ 삽입/삭제 0 ∧ max_disp ≤ 0.5px.
   - STRUCT_MISMATCH: 페이지 수 불일치 또는 삽입/삭제 > 0 (하드 실패).
   - DISP_OVER: max_disp > 임계 (하드 실패).

> 태그 LCS 의 키는 `RenderNodeType` 의 variant 판별자(텍스트 내용·스타일 무시)만 사용한다.
> 텍스트 변경은 `ir-diff` 담당이며, 본 게이트는 **렌더 기하 회귀**에 집중한다.

## 6. 리스크 / 결정 필요 사항

1. **임계 0.5px 적정성**: 이슈가 실측 0.0px → 0.5px 를 제시. 전수 측정에서 부동소수
   재계산 잡음으로 0 초과가 나오면 임계 상향 또는 해당 샘플 XFAIL — 단계 4에서 실측 확정.
2. **자기 라운드트립의 비결정성**: `serialize_hwpx` 가 노드 순서/좌표를 바꾸는 샘플은
   STRUCT_MISMATCH 로 드러남 — 이는 게이트의 의도된 검출이며, 다수면 XFAIL 등급으로 흡수.
3. **`samples/hwpx` 의 HWP3/HWP5 무관**: 게이트는 HWPX 전수만 대상(이슈 범위). HWP5/HWP3
   라운드트립은 범위 밖.
4. **공통 모듈 오염 금지**: 신규 비교 로직은 `diagnostics/` 안에만 둔다. `renderer/`,
   `document_core/` 등 공통 모듈에 게이트 전용 분기를 넣지 않는다.
