# #8153: Print 래스터의 가는 실선 소비

## 원인과 독립 근거

원본 편람 177쪽은 Native의 미대응 1,710픽셀이 회색 가로 표선 5개 행에만 있다.
독립 한컴 Print PDF의 해당 선은 0.24pt, 불투명 회색이며 원본에서 해소한 선폭
0.32 CSS px와 같다. 저장 좌표나 선언 선폭을 바꿀 근거가 아니다.

공개 [PDFium SetupStrokePaint](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/core/fxge/skia/fx_skia_device.cpp)는
출력 변환의 역행렬로 한 디바이스 픽셀을 구한 뒤 원본 선폭과 비교한다.
인쇄 래스터 재생에서 이 최소 폭을 소비하며, 문서 좌표·사양의 선폭과 분리한다.
임의의 문서별 밝기·위치·선폭 상수로 대신하지 않는다.

독립 PDF 벡터 대조군 7종 선폭을 96/192dpi에서 실제 출력했다.
한 디바이스 픽셀보다 가는 선은 최소 폭으로 재생했을 때 PDFium과 같은 두께를 보였다.
192dpi의 해당 세 대조군은 RGB도 전부 같았다. 다른 선폭의 안티앨리어싱 차이까지
해결했다고 판정하지 않는다. 이 대조군은 PDF 래스터 계약이며 한컴 문서 일치의 증거는
원본 HWP/HWPX와 독립 한컴 Print로 따로 검증한다.

## 값의 소비 경로

`원본 선언 폭 → 공통 LineStyle/PaintOp의 논리 폭 → 최종 출력 변환의 역행렬 →
공통 최소 디바이스 폭 → Native/Canvas의 실제 실선 stroke` 순서다.
Native와 Canvas는 같은 역변환 계산을 소비한다. 표·문단 배치, 선의 원점·끝점,
dash 구간과 화살표의 원본 계산은 유지한다. Screen, 벡터 출력과 이중·삼중선은
이번 변경에서 최소 실선 폭을 적용하지 않는다.

## 검증 순서

1. 원본 편람 177쪽과 인접 표·그림 경계의 Native/fresh WASM을 먼저 직접 대조한다.
2. 같은 producer로 초점 52쪽과 정상 대조군을 확인한다.
3. 전쪽 TSV·정확한 미대응 마스크와 PR #8148 대조 범위를 확인한다.
4. 완료 페이지의 독립 기대값으로 회귀 검사를 등록하면서 잘못된 기존 검사를 함께 정리한다.

구현 전의 공개 근거와 대조군을 기록한 계획이며, 새 head의 실제 검증을 완료 처리하지 않는다.
SO/DLL 분석 코드·바이너리·주소·실행 기록은 이 문서에 포함하지 않는다.
