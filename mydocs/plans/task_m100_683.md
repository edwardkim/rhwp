# 수행계획서 — Task #683

## 이슈

**제목**: pr-149.hwp: 그림 wrap=TopAndBottom 빈 문단 레이아웃 — 그림 다음 line height 누락
**이슈**: [edwardkim/rhwp#683](https://github.com/edwardkim/rhwp/issues/683)
**브랜치**: `local/task683`

## 배경

`samples/pr-149.hwp` (이미지 흑백/그레이스케일 테스트 문서)를 SVG로 출력하면, 한글 2022 PDF 변환본 대비 그림과 다음 텍스트 사이 간격이 좁다. 매 그림 cluster 마다 약 **1600 HU (한 줄 line height)** 가 누락된다.

## 측정 사실 (150dpi 기준)

| 항목 | 한글 2022 PDF (정답지) | rhwp SVG | 차이 |
|------|---------------------|---------|------|
| 그림1 top | 273 px | 273 px | 0 |
| 그림2 top | 666 px | 633 px | -33 px |
| 그림3 top | 1059 px | 994 px | -65 px |
| 그림 간 거리 | 393 px = **18864 HU** | 360 px = **17280 HU** | **-1584 HU** |

파일에 저장된 LINE_SEG vpos 값 (참조용):
- p1("원본:") vpos=1600
- p2(그림1+빈문단) vpos=3200
- p3("회색조:") vpos=18896
- p4(그림2+빈문단) vpos=20496
- p5("흑백:") vpos=36192
- p6(그림3+빈문단) vpos=37792
- p7("입니다.") vpos=53488

→ 파일 자체는 cluster 당 17296 HU (line 1600 + image 15696) 로 저장. 그러나 한글 2022는 18864 HU (≈ +1600 HU) 로 렌더.

## 가설

`wrap=TopAndBottom` 그림을 가진 **빈 문단**(텍스트 없음)의 paragraph 높이 계산 시:
- 현재 rhwp: `max(line_height, image_height)` = image_height
- 한글 2022 추정 동작: `line_height + image_height` (그림 아래에 빈 baseline 한 줄 추가 확보)

이 가설은 다음을 통해 추가 검증 필요:
1. 동일 패턴(빈 문단 + TopAndBottom 그림)을 가진 다른 샘플에서도 동일한 1600 HU 차이가 나타나는지
2. 텍스트가 있는 문단에 TopAndBottom 그림이 들어간 경우는 어떻게 처리되는지
3. HWP 스펙 또는 PDF 저장본의 line spacing 처리 규약 문서

- **1차 정답지**: `pdf/pr-149-2022.pdf` (한글 2022 PDF)

- 컨트리뷰터 환경: macOS/Linux → `pdf/` PDF 가 1차 정답지 (한컴 편집기 미보유 시)

### 제외 (별개 이슈로 분리)
