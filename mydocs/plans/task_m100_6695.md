# #6695 PDF 오라클 단일 경로·Git LFS 폐지 수행계획

## 1. 목적과 기준선

- **이슈**: [#6695](https://github.com/edwardkim/rhwp/issues/6695)
- **브랜치**: `task_m100_6695_pdf_oracle_consolidation`
- **기준선**: `upstream/devel@2b2646f4051dd1ecefc296e2e032308bd0f25bd7`
- **연계 이력**: #5345(세 경로 편입), #1109(runner 저장공간)

한컴 PDF 오라클의 버전·크기별 최상위 폴더 분리를 폐지하고 모든 현행 PDF를 `pdf/**`에서
일반 Git blob으로 관리한다. clone·fork·Actions 다운로드가 저장소 소유자의 Git LFS bandwidth를
계속 소비하는 구조를 끝내되, PDF bytes와 오라클 provenance를 훼손하지 않는다.

2026-09-03 기준 실측은 다음과 같다.

| 경로 | PDF 수 | 작업트리 byte | 상태 |
| --- | ---: | ---: | --- |
| `pdf/` | 1,161 | 1,023,785,532 | 일반 Git |
| `pdf-2020/` | 1 | 860,225 | 일반 Git |
| `pdf-large/` | 18 | 57,189,369 | LFS pointer 17 + 일반 Git blob 1 |

`pdf-large/hwpx/issue_1133.pdf`의 작업트리는 131-byte pointer지만, 선언된 SHA-256
`ca066fdc5cda9fd8c47c9a29ba9a546e70c6acdaa96df4d6c66e0b8e02cdbc45`와 일치하는
110,523-byte PDF가 로컬 LFS object store에 있어 네트워크 재다운로드 없이 복원 가능하다.
최대 파일은 50,228,784 bytes이며 50 MiB(52,428,800 bytes) 미만이다.

## 2. 결정과 보호 불변식

1. **단일 현행 경로**: PDF 오라클은 `pdf/**` 아래에서만 관리한다.
2. **LFS 비사용**: 현재 트리와 신규 PDF에 Git LFS pointer를 사용하지 않는다.
3. **50 MiB 상한**: 일반 Git의 성능 경고 경계를 넘지 않도록 PDF 한 파일은
   52,428,800 bytes 미만이어야 한다. 초과 파일은 커밋하지 않고 별도 이슈에서 축소·발췌·외부
   증적 중 provenance를 보존하는 방식을 승인받는다.
4. **byte 보존**: 이동 전후 SHA-256과 크기, `%PDF-` magic, 한컴 engine suffix를 보존한다.
5. **충돌 fail-closed**: 목적지 충돌은 hash 일치 때만 중복 제거한다. 불일치는 덮어쓰지 않는다.
6. **pointer 커밋 금지**: LFS 실제 객체를 복원·검산하지 못하면 자산 이동을 시작하지 않는다.
7. **공개 이력 보존**: `git lfs migrate`, `filter-repo`, force-push, 저장소 재생성을 하지 않는다.
8. **역사 기록 보존**: 과거 CHANGELOG·완료 보고서의 당시 경로는 고치지 않는다. 현행 지침과
   실행 소비자만 단일 경로로 바꾼다.
9. **원격 저장량 정직성**: LFS 추적을 끝내도 과거 원격 LFS 객체가 자동 삭제되지는 않는다.
   purge는 GitHub Support가 필요한 별도 O4 운영 판단으로 남긴다.
10. **검증 비용 보존**: PDF-only 변경의 fast-pass 의미를 유지하고 경로 목록만 `pdf/**`로
    축소한다. 이 작업을 이유로 renderer 전체 CI를 PDF-only PR에 새로 부과하지 않는다.

## 3. 단계별 수행

### Stage 1 — 전환 원장과 소비자 지도 고정

1. `pdf-2020/**`, `pdf-large/**`의 old/new path, index 형식, working byte, SHA-256을 기록한다.
2. 17개 LFS 대상의 pointer OID·선언 크기와 실제 object를 대조하고 전부 `%PDF-`인지 확인한다.
3. 목적지 충돌을 상대경로·basename·SHA-256 세 축으로 검사한다.
4. workflow, CI classifier/policy, oracle-public, LLM verifier, 테스트, 현행 매뉴얼의 경로 소비자를
   생성물과 수기 정본으로 구분한다.
5. 결과를 `mydocs/working/task_m100_6695_stage1.md`에 기록한다.

**종료 게이트**: 18개 `pdf-large` PDF와 1개 `pdf-2020` PDF의 손실 없는 목적지가 확정되고,
복원 불가능 pointer와 hash 불일치 충돌이 0이다.

### Stage 2 — 단일 경로 원자 전환

1. LFS object store의 실제 bytes로 `issue_1133.pdf`를 복원하고 OID·크기·PDF magic을 재검산한다.
2. `pdf-2020/pr-1674-2020.pdf`를 `pdf/pr-1674-2020.pdf`로 이동한다.
3. `pdf-large/hwpx/**`, `pdf-large/issue2006/**`는 상대 구조를 보존해 `pdf/**`로 이동한다.
4. `pdf/`에 이미 있는 byte-identical 최상단 2개는 목적지 파일을 보존하고 중복 source만 제거한다.
5. `pdf-large/README.md`의 현행 규칙은 `pdf/README.md`로 통합하고 두 폐기 디렉터리를 제거한다.
6. `.gitattributes`의 PDF LFS rule을 제거하고 `CONTRIBUTING.md`에 단일 경로·suffix·50 MiB
   fail-closed 규칙을 명시한다.
7. 신규 PDF 경로·크기·pointer 위반을 검사하는 가벼운 정책 검사기와 단위 테스트를 추가한다.

**종료 게이트**: 입력 1,180개에서 byte-identical 중복 2개를 제외한 `pdf/**` 1,178개가 있고,
운영 PDF LFS pointer와 폐기 디렉터리가 0이다.

### Stage 3 — 활성 소비자와 CI 계약 현행화

1. CI, CodeQL, Render Diff, Adapter, Proptest, Pages의 경로 목록을 `pdf/**` 하나로 축소한다.
2. `ci-impact-classifier`·`ci-impact-policy`·trusted post-merge 재사용기와 mirror test를 갱신한다.
3. Oracle Public Advisory의 `include_large`, checkout LFS, 세 root 분기를 제거하고 `pdf/`만 읽게 한다.
4. `tools/oracle_public/**`의 catalog·pair index·coverage 산출물은 정본 생성기로 재생성한다.
5. LLM verifier의 oracle corpus·fixture·resolver에서 폐기 경로를 제거하고 관련 테스트를 실행한다.
6. GitHub 운영, PR review 시각 증적, publish, PDF README 등 현행 문서를 갱신한다. historical
   memory에는 새 정본으로 연결되는 superseded 안내만 추가한다.

**종료 게이트**: 실행 코드·workflow·생성물이 `pdf-2020/` 또는 `pdf-large/`를 현행 입력으로
사용하지 않으며, PDF-only fast-pass와 기존 PDF rename/delete의 full fallback 의미가 유지된다.

### Stage 4 — clean-clone·크기·회귀 검증과 최종 보고

1. LFS smudge를 건너뛴 clean clone/worktree에서 `pdf/**`가 모두 실제 PDF인지 확인한다.
2. `git lfs ls-files`가 비어 있고 `git check-attr filter`가 `pdf/**`에 LFS를 반환하지 않는지 본다.
3. 전환 원장의 old OID/SHA-256과 새 Git blob SHA-256을 전수 대조한다.
4. 정책·workflow mirror·oracle-public·LLM verifier·문서 검사를 실행한다.
5. Rust test source의 PDF 경로를 바꾼 경우 AGENTS.md의 native/WASM/workspace Clippy 묶음을
   순서대로 모두 실행한다.
6. 새 commit의 raw blob 합과 packed object delta를 측정해 LFS bandwidth 제거와 일반 clone 증가의
   교환 비용을 `mydocs/report/task_m100_6695_report.md`에 기록한다.

**종료 게이트**: clean clone 재현, 1,178개 PDF byte 보존, 모든 정책 테스트, 문서 검사와 필요한
Rust gate가 통과하고 메인테이너가 최종 보고를 승인한다.

## 7. 비범위와 rollback

- 공개 Git history rewrite, force-push, 저장소 삭제·재생성은 비범위다.
- 원격 LFS storage purge와 GitHub billing 설정 변경은 비범위다.
- PDF 오라클의 시각 내용 재생성, renderer 수정, 새로운 배포 채널은 비범위다.
- merge 전 rollback은 task branch 폐기다. merge 뒤에는 전환 commit을 revert한다. 원격 LFS purge는
  이 rollback으로 복원할 수 없으므로 이 이슈에서 실행하지 않는다.
