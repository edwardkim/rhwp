# #7642 저장 자동 줄의 무효화 근거와 원본 들여쓰기 보존

Issue: #7642.

## 위반한 계약과 독립 근거

`21_언어_기출_편집가능본.hwp`의 0.132 문단은 정상 저장본의 두 줄과
독립 한컴 Print의 두 줄이 일치한다. 현재 측정으로 한 줄에 들어간다는
사실은 이 저장 줄을 무효화할 근거가 아니다. b86의 본문 정규화는 후속
원점까지 당겨 6·7·8·10쪽을 후퇴시켰다. 실제 원본·Print 좌표·대조 TSV는
`stage2774-common-soft-wrap-counterexample/`에 보존했다.

온새미로 질문은 본문 문자열에 없는 자동 번호를 현재 문서 순서에서 계산한다.
저장 LineSeg에는 그때 사용한 번호 문자열·마커 프로그램의 기하가 없다.
실제 해소된 마커의 가시 영역은 줄 채움과 높이에 참여해야 한다. 같은 원본의
독립 Print는 15쪽 질문과 `[3점]`을 한 줄에 놓는다. 최신 747 Native에서 이를
재현했지만, 유효한 일반 본문도 함께 압축하는 적용 근거는 잘못됐다.

## 공통 수정

- 더 적은 줄이라는 결과를 캐시 무효화 사유로 사용하지 않는다. 본문 정규화는
  실제로 해소되어 그려질 목록 마커의 현재 기하를 갱신하는 계약으로 적용한다.
  번호·글머리표는 같은 `list_marker_geometry` 결과를 사용한다. 문서 ID·페이지·
  질문 문자열·글꼴 이름으로 대상을 정하지 않는다.
- 단순 재측정에 불과한 일반 본문은 기존 저장 줄 수용 경로를 유지한다.
  별도의 명시 편집·폭/개체 변화의 무효화 경로를 막는 변경은 아니다.
- fresh 줄 채움은 저장 줄을 재사용하는 함수가 아니다. 입력의 줄을 지우지
  않고 전달해, 기존 `reflow_indentation_pattern`이 원본의 줄별 들여쓰기 기록을
  읽도록 한다. 새 줄·공백·후속 원점은 기존 공통 파생 문단 경로로 발행한다.
  원본 문서와 저장용 LineSeg는 변경하지 않는다.

## 검증 범위와 한계

온새미로 두 형식의 전체 46쪽·실제 질문 경계와 일반 본문 대조군의 두 줄 및
후속 문단 위치를 함께 확인한다. 음수/양수 들여쓰기와 자동 번호가 있는 정상
다중 줄도 전체 102개 문서에서 확인하며, #7969·#7970 기능 보존 검증을 유지한다.
747 빌드/전체 Rust 검증은 고정 worktree에서 계속 실행한다. 새 source의 빌드는
그 작업들의 최종 상태와 공유 target의 실제 idle을 확인한 뒤 순차 실행한다.

이 수정의 완료는 아직 입증되지 않았다. 전쪽 Native/fresh WASM·직접 판독·
기준 대비 무회귀 전에 새로운 실물 회귀나 baseline을 추가/갱신하지 않는다.
