## 1. 문제

`samples/76076_regulatory_analysis.hwp`는 HWP 2024 기준 PDF와 같은 82쪽을 만들지만, 수정 전 34쪽의
첫 continuation 표가 약 60px 더 길어져 뒤따르는 `직접편익` 표까지 아래로 밀렸다. PR #4763은
페이지 소유권과 전체 쪽수를 정합했으나 #3128의 셀 내부 재조판과 terminal host tail 높이는 해결하지
않았다.

[#4764](https://github.com/edwardkim/rhwp/issues/4764)는 문서 전반의 raster·font·paint 차이를 추적하는
상위 영역이다. 이번 작업은 #3128의 34쪽 continuation geometry와 줄바꿈만 다루며 #4764의 전역
폰트·래스터 정합을 섞지 않는다.

## 2. 목표

1. 76076 문서의 82쪽 페이지 수와 p33→p34 continuation 소유권을 유지한다.
2. 34쪽 첫 continuation 외곽을 한컴 PDF raster의 y=77..463px에 맞춘다.
3. 뒤따르는 `직접편익` 표를 PDF의 y=512px 부근에서 시작한다.
4. 첫 들여쓰기 줄의 `연동시스템 등` 줄바꿈을 한컴과 동일하게 유지한다.
5. p81→p82 short RowBreak child와 기존 중첩 표·overflow 회귀를 바꾸지 않는다.

## 3. 범위

### 포함

- 저장 `LINE_SEG`가 없는 literal-space 들여쓰기 문단의 제한적 tracking 복원

- terminal native RowBreak child의 빈 host tail 중복 예약 제거
- #3128 전용 geometry·줄바꿈 회귀 테스트
- 연관된 #1891, #2308, 중첩 표, overflow 회귀 검증
- 기준 PDF와 96dpi 시각 비교

### 제외

- #4764의 전역 폰트 fallback·glyph paint·raster 일치율 개선
- HWP 파서나 Document IR 스키마 변경
- unrelated pagination 휴리스틱 변경

## 6. 구현 중 실제로 바뀐 판단

- 처음에는 `CharShapeRef` tracking을 모든 셀 fallback에 복원했으나 80168 문서가 157쪽에서
  156쪽으로 바뀌었다. 적용 대상을 둘 이상의 literal ASCII 공백, 동일 font metric, 구간별 tracking
  차이가 함께 있는 native HWP5 장문 1×1 child로 좁혔다.
- 기존 #2308 회귀는 p34에서 저장 cell margin을 유지한다고 가정했으나, 원본 속성
  `applyInnerMargin=false`와 PDF 우측 paint edge를 다시 대조해 table content box가 권위임을 확인했다.
- tracking과 content-box만으로 본문 높이는 맞았지만 후속 표가 19.2px 더 내려갔다. terminal child가
  이미 source cursor를 소유하는데 generic first-unit reservation이 빈 host Enter를 다시 예약한 별도
  원인을 분리했다.
