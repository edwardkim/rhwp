# #8153: 인라인 표 문단의 공통 글자 전진 결과

## 원본·독립 출력과 실제 원인

편람 271쪽의 HWP/HWPX는 본문 section 9 / paragraph 203에 공백 8개 뒤 TAC 표를 저장한다.
HWPX 원본은 charPr 138의 1000HU 크기·한글 98% 장평·영문 0 자간, 표의 좌우 바깥여백
각 140HU를 갖는다. 독립 Print의 표 세로 경계는 114.356 / 193.830 / 318.496pt다.
Native의 첫 경계 156.133px는 독립 152.475px보다 약 3.7px 오른쪽이다.

검증한 이전 producer `2cb8223029`의 공통 paint에서 공백 문자 경계는
`0, 6.506667, …, 52.053333px`인데, 같은 TextRun bbox는 56px이고 뒤 표는 그 56px를
소비한다. 문자당 정수 px 반올림으로 8×7px를 만든 별도 배치와 실제 glyph 전진이 갈린다.
이 진단은 보관된 Native PNG·입력 SHA·WASM SHA를 구분해 기록했다.

선행 구현은 인라인 표 문단의 초기 문자별 반올림 경로, 탭·말미 공백의 `82479c6463b`
(#7344), 언어 슬롯의 `155bec27ee7`(#7702), 중립 공백 원점의 `9636eebe9d`다.
앞선 보정에서 마련한 저장 탭 폭·소유 언어·장평·원본 여백은 유지한다. 새 메트릭이나
문서별 좌표를 도입하지 않고 기존 공통 `char_width_decision`의 HU 장치 전진을 사용한다.

## 생산과 소비의 연결

원본 문자·char-shape·중립 언어 소유 → 기존 `ParagraphMetricScope`의 동일한 스타일 →
공통 문자/클러스터 전진과 저장 탭 → 문단당 한 번 만든 전진 계획 → 세그먼트 폭·정렬 폭·
말미 공백 제외·줄바꿈·실제 cursor·TextRun의 명시적 문자 경계 → 다음 TAC 표의 원점으로
연결한다. bbox와 glyph 끝을 따로 재측정하지 않는다. 표·backend에 픽셀 예외를 넣지 않는다.

- 문단의 기존 세그먼트와 저장 줄 소속은 유지한다. 줄의 실제 원점/높이 정책은 바꾸지 않는다.
- 문자마다 정수 px로 반올림하지 않는다. 공식 원본 HU·언어별 속성과 기존 장치 단위를 소비한다.
- 합성·저장 탭, 바깥여백, 스타일/언어 변경, 각주 marker의 소속을 구분한다.
  전체 문자열의 클러스터 경계는 공통 측정 helper에서 얻으며 조합 문자를 독립 글자로 세지 않는다.
- 측정과 배치가 동일한 원본 문자별 전진을 소비하고, 최종 TextRun도 같은 경계를 게시한다.

## 검증 순서

1. 기존 producer의 공백 끝과 뒤 표 원점 불일치를 진단 실패로 보존한다.
2. 공유 Cargo 작업 종료 후 새 후보를 Native로 빌드한다. 271쪽과 원본의 저장 탭·
   가운데/오른쪽 정렬·표 앞뒤 공백·서로 다른 언어 슬롯·정상 표 문서의 영향 페이지를 확인한다.
3. 독립 Print와 Native/fresh WASM의 관련 쪽 90%·직접 판독 후 관계 검사와 독립 ±2px
   회귀를 등록한다. 기존의 잘못된 정수 기대값은 원 해결 근거와 새 출력으로 재검토한다.
4. 두 편람 전쪽·PR8148 corpus를 같은 PDF 물리 DPI에서 base와 대조한다. 현재 후보의
   하락을 기준값으로 숨기지 않는다. 이후 최종 회귀·lint·Skia·Studio·WASM과 PR 절차를 마친다.

현재 원인 추적과 구현 계획 단계이며, 후보 구현·최종 시각·정식 회귀는 아직 완료되지 않았다.
