## 1. 목표와 우선순위

W9는 exact font source의 GPOS `kern` pair adjustment를 공통 layout에서 계산해 native·WASM·backend가 같은
위치를 재생하도록 연결했다. 그러나 GSUB로 glyph identity가 달라지는 문자열, non-LTR direction, vertical
writing과 variation instance는 의도적으로 fail-closed했다.

W10의 목표는 이 미지원 입력을 한꺼번에 허용하는 것이 아니다. exact font bytes·face index·script·language·
feature·axis를 기능 탐지하고, 공통 shaping owner가 glyph id·cluster·advance·offset을 한 번 결정한 뒤 backend가
같은 결과를 재생할 수 있는 축만 단계적으로 연다.

우선순위는 다음과 같다.

1. 기존 horizontal K0·K1 보호 계약과 현재 structured rejection을 기준선으로 동결한다.
2. GSUB/GPOS horizontal shaping을 먼저 연결해 W9의 nominal-glyph 제한을 제거한다.
3. 같은 shaping owner에 bounded variation instance를 연결한다.
4. GSUB `vert`/`vrt2`, `vhea`·`vmtx`와 필요 시 `VORG`를 사용하는 vertical shaping을 마지막에 연다.

vertical부터 backend별 회전으로 근사하거나 variable font를 family 이름만으로 생성하지 않는다. 두 경로 모두
공통 glyph shaping과 exact source provenance가 선행돼야 하기 때문이다.

## 2. 현행 구조와 원인 계보

이미 존재하는 schema·보호 경계는 다음과 같다.

- `ShapeKey`: font instance, direction, writing mode, script, language, OpenType feature, shaping engine,
  fallback policy를 보존한다.
- `FontInstanceKey`: exact face key, size, variation axes, synthetic style을 보존한다.
- portable GlyphRun: glyph id, position, advance, cluster와 replay eligibility를 표현한다.
- CanvasKit·native Skia·text-v2: non-LTR, vertical writing, variation instance를 현재 구조화된 reason으로
  fail-closed한다.
- W9 `renderer/kerning.rs`: exact source와 rustybuzz를 사용하지만 nominal glyph·cluster identity가 유지되는
  pair positioning만 layout에 투영한다.

따라서 핵심 결손은 schema 필드가 아니라 다음 연결이다.

```text
HWP/HWPX 문서 의도 또는 명시적 API 요청
  -> script·language·direction·writing mode·axis의 권위 판정
  -> exact font bytes + face index
  -> bounded common shaping decision
  -> measurement·line break·glyph positions의 단일 소비
  -> SVG·Canvas2D·CanvasKit·native Skia portable replay
```

backend가 독립적으로 shaping하면 measurement와 paint가 발산한다. 반대로 shape metadata만 채우고 실제 layout
advance를 기존 문자별 hmtx 합으로 남겨도 줄바꿈과 paint가 달라진다. 공통 shaping decision이 measurement와
replay 양쪽의 단일 권위여야 한다.

## 6. 보호 불변식

1. 기존 horizontal kerning-off와 W9 K1 fixture의 measurement·line break·paint output은 byte 또는 canonical
   identity를 유지한다.
2. exact font bytes·face index와 glyph coverage를 증명하지 못하면 기존 TextRun 또는 K0로 fail-closed한다.
3. shaping은 공통 layout owner가 한 번 수행하고 backend는 published glyph result만 재생한다.
4. GSUB glyph 수 변화와 cluster mapping을 원문 char index로 억지 1:1 투영하지 않는다.
5. direction·script·language·feature·writing mode·variation instance는 cache key와 trace에서 누락되지 않는다.
6. axis tag 중복, NaN·Infinity, range 밖 값은 canonical clamp로 숨기지 않고 정책에 따른 구조화 reason으로
   거부한다. 지원하기로 승인한 축만 명시적 범위 검증 뒤 적용한다.
7. vertical advance·origin이 없으면 horizontal advance를 무조건 회전해 대체하지 않는다.
8. stored LineSeg의 존재나 HWP/HWPX version을 capability로 사용하지 않고 현재 객체·table·glyph 결과를
   feature detection한다.
9. font 32 MiB, text/glyph/position 4,096, cluster·feature·axis 수에 bounded 상한을 유지하고 새 무제한 clone·
   serialization을 만들지 않는다.
10. source font bytes·개인 font 경로·private corpus identity를 render tree·trace·artifact에 넣지 않는다.

### Stage W10-Q3 — variable font instance

1. `HappinessSansVF`의 `wght`·`opsz` default/boundary/interior instance를 exact source에서 shaping한다.
