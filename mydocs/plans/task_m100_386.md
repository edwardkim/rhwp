## 배경

`samples/exam_eng.hwp` 1페이지 SVG 출력에서 한컴 PDF 출력과 1페이지 구성이 어긋난다.

| 출력 | 1페이지 단 1 마지막 항목 |
|------|--------------------------|
| 한컴 PDF | 12번 ⑤ (1페이지에 1~12번 모두 포함) |
| rhwp SVG | 11번 ③ (11번 ④⑤ + 12번이 2페이지로 밀림) |

LAYOUT_OVERFLOW 경고는 발생하지 않으므로 Task #356에서 도입한 검증 기반(detect_inter_paragraph_vpos_reset)으로는 잡히지 않는 별개 결함이다.

## 현상

`dump-pages -p 0` 결과:

```
페이지 1
  단 0: items=38, used=1114.4px, hwp_used≈1205.8px, diff=-91.4px
  단 1: items=25, used=1186.2px, hwp_used≈ 969.1px, diff=+217.1px
```

- 단 1에서 rhwp가 HWP 권위값보다 +217.1px 더 길게 누적
- body_area h = 1209.4px, 단 1 used 1186.2px → 11번 ④ 이후 항목이 들어갈 자리 부족 판정
- HWP 권위값 기준으로는 단 1에 1~12번 모든 항목(33~66) 누적 약 1109.8px → 100px 여유

**개별 높이는 일치하나 누적 단계에서 +217px 부풀림** 발생.

## 원인 가설

`src/renderer/pagination/engine.rs:245-285`의 vpos 기반 `current_height` 보정 로직에 **컬럼 경계 가드 부재**.

```rust
if let Some(prev_pi) = prev_pagination_para {        // 함수 레벨 변수, 컬럼 전환 시 리셋 X
    if para_idx != prev_pi && st.page_has_block_table {
        // ... prev_pi의 last seg vpos_end 기반으로 vpos_h 계산
        if vpos_h > st.current_height && vpos_h > 0.0 {
            let avail = st.available_height();
            if vpos_h <= avail {
                st.current_height = vpos_h;          // ← 강제 상향
            }
        }
    }
}
```

문제 시나리오:
1. 단 0 마지막 문단 처리 후 `current_height` ≈ 1100px
2. `advance_column_or_new_page()` 호출 → `current_height = 0.0` 리셋 (state.rs:120)
3. 단 1 첫 문단(pi=33) 진입, `prev_pagination_para`는 여전히 단 0 마지막 pi
4. 보정 로직이 **단 0 마지막 vpos_end - page_vpos_base** 기준으로 vpos_h 계산하여 current_height 상향
5. 단 1 첫 문단부터 잘못된 누적 시작점 → 단 1 끝부분 5개 항목이 밀려남

가설 검증 항목:
- 단 1 첫 문단 처리 시점에 보정 로직이 실제로 발동하는지 (`page_has_block_table` 플래그 상태)
- 컬럼 경계에서 `prev_para.column_start != cur_para.column_start` 가드 추가 시 회귀 영향 범위
