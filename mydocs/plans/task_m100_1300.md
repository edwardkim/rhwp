## 목표

괄호 분수처럼 **키 큰 base**에 붙는 위첨자(지수)가 base 우상단에 단정히 붙도록 상승량을 보정한다. 현재는 지수가 과도하게 높아 **윗줄을 침범**한다.

## 현상 (정밀 확인 완료)

- 샘플: `samples/3-09월_교육_통합_2022.hwpx` 17쪽 [다른 풀이]
- 식 `2×4!/3!×(1/6)⁴ = 8×(1/6)⁴` 등에서, `(1/6)⁴`의 지수 `4`가 **한 줄 위 텍스트("의 2가지 경우이므로")까지 떠올라** "2가지₄", "이므₄로"처럼 보임.
- 한글 2022 PDF(`pdf/3-09월_교육_통합_2022.pdf` 17쪽): 지수 `4`는 **괄호 우상단**에 붙고 윗줄 침범 없음. → rhwp 위첨자 상승량 과다.

## 원인 (코드 확인)

`src/renderer/equation/layout.rs` `layout_superscript`(`:456-474`):
```rust
let sup_shift = b.baseline - s.height * 0.7;   // base baseline 비례
if sup_shift >= 0.0 {
    sup_y = 0.0;                                // 위첨자를 항상 박스 최상단
    base_y = sup_shift.max(s.height - b.height).max(0.0);
    ...
}
```
키 큰 base는 `b.baseline`이 커서 `sup_shift`(=base를 아래로 미는 양)가 과대 → 합성 박스 baseline이 base.baseline의 약 2배가 되며 위첨자가 텍스트 baseline 위로 한 줄 이상 치솟음. 짧은 base(`x²`)는 영향 적음.

## 의존성 / 위험

- **회귀 위험(중)**: 위첨자 y는 모든 수식에 영향. 짧은 base(`x²`, `a^n`)와 분수 base 양쪽이 동시에 맞아야 함. 한쪽만 맞추면 다른 쪽 회귀.
- 기존 수식 핀/스냅샷 테스트가 있으면 baseline 고정 후 진행.
