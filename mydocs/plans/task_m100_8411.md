## 요청과 재현

사용자가 제공한 화면은 「PDF 가져오기」의 고급 설정을 펼친 상태다.
현재 구현의 고급 설정은 기본적으로 접혀 있다. 기본 화면부터 JSON이 항상 노출된다고
설명하지 않는다. 펼친 화면에서는 시간 입력, JSON 편집기와 내부 정책 전체가 간격 없이
배치되며 프로필과 입력란에 Studio 공통 스타일이 적용되지 않는다.

2026-10-31 실제 Chromium에서 공개 `pdf/issue8403/image-patterns.pdf`를
`open-document-bytes`로 열어 확인했다. 변환은 시작하지 않고 선택 단계에서 조사했다.

- select·숫자 입력·textarea의 class가 모두 비어 있다. 기본 크기·배치로 표시된다.
- 고급 설정에 `JSON.stringify(policy, null, 2)`로 내부 필드까지 894자를 표시한다.
- 프로필에서 ArrowDown을 눌러도 `standard`가 유지된다. 고급 설정 summary에서
  Space를 눌러도 열리지 않지만 마우스로는 열린다.
- 420×320 화면에서 고급 내용을 펼치면 가져오기·취소 버튼이 최초 화면에 보이지 않는다.
- `rhwp-busy`는 false다. 이전에 해결한 대기 커서 문제와 구분한다.
- 증거: `output/pdf-import-dialog-20261031/{initial,expanded,short-viewport}.png`,
  `result.json`, `inspect.mjs`. 전용 Vite·Chromium을 실행한 뒤 종료했다.

## 선행 분석

대화창은 #8174의 통합 [PR #8360](https://github.com/edwardkim/rhwp/pull/8360),
`f125c735c7`에서 도입됐다. `rhwp-studio/src/ui/pdf-import-dialog.ts`는 대부분
기본 DOM과 inline style로 구성되고, `dialog-pdf-import` 전용 스타일은 없다.
기존 `dialog-row`, `dialog-label`, `dialog-input`, `dialog-select`도 사용하지 않는다.

[이슈 #8398](https://github.com/edwardkim/rhwp/issues/8398)의 해결
[PR #8401](https://github.com/edwardkim/rhwp/pull/8401), `3c01421e89`는 main.ts의
선택 대기/실제 작업 수명을 수정했으며 이번 대화창 구성은 변경하지 않았다.
기존 PDF 가져오기 이슈를 검색했고 같은 화면 구성 증상의 열린 이슈는 찾지 못했다.
#5852의 전역 다국어화와 PDF 조판 관련 열린 이슈는 이번 작업과 별개다.

키보드 문제는 공통 `ModalDialog.show()`의 capture handler가 input·textarea·button
이외 요소의 기본 키 동작을 막는 경로에서 발생한다. select와 summary의 실제 동작을
보호하되 편집기로 키가 전파되는 문제를 다시 만들지 않아야 한다.

## 한 단위의 개선 범위

1. 파일명·가져오기 설명, 처리 설정, 진행/오류, 하단 조작을 구분한다. 공통 테마 토큰과
   입력 스타일을 사용하고 긴 파일명, 밝은/어두운 테마에서 가독성을 확인한다.
2. 기본 선택은 표준을 유지한다. 표준/자원 절약의 차이는 현재 정책의 입력 크기·쪽수 등
   사용자에게 필요한 정보로 설명한다. 기본값과 실제 자원 한도는 바꾸지 않는다.
3. 고급 설정은 접힌 상태를 유지한다. 제한 시간은 명확한 라벨·단위·범위 안내와 함께
   배치한다. 적용 한도는 읽기 쉬운 이름·단위로 요약한다. 전체 정책 JSON과 맞춤 JSON
   입력은 별도의 전문가용 상세 영역으로 묶어 일반 선택 흐름을 차지하지 않게 한다.
   기존 한도 조정 기능과 검증은 유지한다.
4. 진행·실패·재시도 안내를 분리하고 오류가 난 입력을 식별할 수 있게 한다. 처리 중에는
   설정 변경을 막되 취소는 유지한다. #8398의 일반 커서·문서 보존 계약도 유지한다.
5. 좁거나 낮은 화면에서는 내용 영역이 스크롤되고 하단 버튼은 조작 가능하게 한다.
   Tab·방향키·Space·Enter·Escape의 실제 동작과 포커스를 검증한다. 공통 모달 키 처리
   보정은 select/summary 등 확인된 원인 범위만 수정하고 다른 대화창도 대조한다.

Rust·WASM 엔진, PDF 변환·조판·저장 결과, 프로필의 상한·기본 시간, CI는 변경하지 않는다.
이번 범위는 Studio UI이며 문서 렌더링 피델리티 수치 보정 작업이 아니다.

## 완료 기준과 검증

- 기본/고급/전문가 상세와 진행·오류·재시도 화면을 실제 브라우저에서 확인한다.
- 두 테마, 긴 파일명, 데스크톱·작은 화면에서 입력 라벨과 하단 버튼의 가시성을 확인한다.
- 키보드로 프로필 변경·고급 영역 펼치기가 되고, 입력 조작이 가져오기를 잘못 시작하지 않는다.
- 기존 프로필·JSON 검증·제한 시간·취소·재시도의 실제 결과와 Worker 전달 값을 보존한다.
- #8398의 실제 열기·취소·오류·재시도 회귀와 일반 문서 열기를 대조한다.
- 기존 자동 수집 구조에 맞춰 필요한 UI 회귀를 보완하고 TypeScript, Studio 전체 npm test,
  실제 브라우저 검증을 완료한다. 화면 변경 전후를 캡처해 직접 판독한다.
- UI 전용 변경이므로 기존 최신 최적화 WASM을 재사용하며 불필요한 Rust 재빌드는 하지 않는다.

승인에 따라 최신 upstream/devel 기준
`task/8411-pdf-import-dialog-ui`에서 구현·검증을 한 번에 진행한다.
PR 생성·push·merge는 이번 계획 승인 범위에 포함하지 않는다.
