# Task #937 수행계획서 — 복학원서 서명란 '(인)' 기호 렌더링 불일치

## 이슈

[Issue #937](https://github.com/edwardkim/rhwp/issues/937) — 복학원서 서명란 '(인)' 기호 렌더링 불일치

## 배경

대상 문서는 `samples/복학원서.hwp`이고, 기준 문서는 `pdf/복학원서-2022.pdf`이다. 한컴/PDF 기준의 1페이지 서명란에는 `(인)` 기호가 표시되지만, 현재 rhwp-studio 렌더에서는 같은 위치가 다른 기호처럼 보인다.

코드 수정 전 진단으로 `rhwp dump samples/복학원서.hwp`를 실행한 결과, 문제 위치는 `s0:pi=12` 안의 4×4 표 `cell[1]` 문단이다.

```text
셀[1] r=0,c=1 text="                          󰄫 (S"
```

해당 PUA 문자의 코드포인트는 `U+F012B`로 확인했다. 기존 렌더 경로에는 `map_pua_bullet_char()`를 통한 여러 PUA 치환이 있으나, 현재 `U+F012B`는 매핑되어 있지 않아 SVG/Canvas 출력 시 원본 PUA 글리프가 그대로 남는다.

## 목표

1. `U+F012B`가 한컴 기준처럼 `(인)`으로 표시되도록 한다.
2. IR의 원문 PUA 문자는 보존하고 렌더링 시점 치환만 적용한다.
3. 기존 PUA 매핑 및 복학원서 golden SVG 회귀를 깨지 않는다.

## 구현 방향

기존 PUA 처리 패턴을 재사용한다.

- 렌더 시점 치환: `src/renderer/layout/paragraph_layout.rs::map_pua_bullet_char`
- SVG/Canvas/HTML 경로는 이미 이 헬퍼를 호출하는 구조가 존재한다.
- `U+F012B -> (인)`은 1글자에서 3글자로 확장되므로, 단순 `char -> char` 매핑만으로는 부족할 수 있다.

따라서 Stage 1에서 실제 적용 지점을 좁히고, Stage 2에서 필요한 경우 문자열 치환 헬퍼를 별도로 추가한다. 단일 문자 매핑 함수에 무리하게 다문자 문자열을 끼워 넣지 않고, 기존 `display_text`/렌더 시점 치환 패턴과 정합되는 쪽을 우선한다.

## 영향 범위

| 영역 | 예상 영향 | 비고 |
|---|---:|---|
| PUA 렌더 매핑 | 중간 | `U+F012B` 단일 코드포인트 추가가 핵심 |
| 텍스트 폭 측정 | 중간 | `(인)`은 3글자라 bbox/line width 보정 필요 |
| SVG golden | 중간 | `tests/golden_svg/issue-677/bokhakwonseo-page1.svg` 갱신 가능 |
| WASM/Canvas | 중간 | rhwp-studio 재현 대상 |
