## 1. 이번 절편의 결정과 목표

이번 절편은 W4 action rank 7 `KoPubWorld돋움체 Light`를 같은 KoPubWorld family의 rank 8 결과로
추정하지 않고 독립적으로 심사한다.

핵심 질문은 다음과 같다.

> 현재 rhwp가 `KoPubWorld돋움체 Light`의 실제 layout advance를 선택하지 못하고 있다면, 공식 exact
> TTF의 `hmtx`를 사용한 한 decision-plane 교정이 실제 HWP 편집 습관의 장평·자간·fixed frame 조판을
> 개선하면서 비대상 문서와 native·WASM·브라우저 backend를 안전하게 보존하는가?

그 답에 따라 이번 절편의 산출은 다음 셋 중 하나다.

1. **qualified**: 현재 동작과 기대 동작의 첫 divergence, 한 decision plane, 실제 영향 cohort와
   비회귀 조건을 고정하고 별도 product-correction 자식 이슈 초안을 준비한다.
2. **no-change**: exact metric 후보가 실제 fixed frame을 개선하지 않거나 회귀를 만들거나, 현행 동작이
   이미 동등한 metric을 사용하면 제품 규칙을 바꾸지 않는다.
3. **blocked**: exact·CDN artifact identity, 같은 snapshot의 실제 geometry 또는 portable 정책을 판정할
   근거가 부족하면 재개 조건만 기록하고 제품 규칙을 바꾸지 않는다.

qualification 통과 자체는 metric DB·registry·fallback·paint·font supply 변경이나 GitHub 자식 이슈 등록을
승인하지 않는다.

### Stage W8-R7-Q1 — 공개 fixture와 current runtime boundary

1. W5 generator로 rank 7 HWPX를 복원해 W5 fixture SHA-256과 일치하는지 확인한다. 불일치하면 fixture를
   새 정답지로 사용하지 않고 중단한다.
2. HWPX에서 결정적 HWP 짝을 만들고 IR·page count·반복 변환 hash를 고정한다.
3. raw document face, parser normalization, layout-name, layout-metric lookup, heuristic와 paint 요청을 각각
   기록한다.
4. HWP/HWPX와 native/Docker WASM trace를 독립 비교한다.
5. 실제 render line bbox·run membership·stored/fresh admission을 같은 snapshot에서 관찰한다.

**종료 게이트**: current miss 여부와 첫 divergence가 한 decision plane으로 좁혀지고 native/WASM parity가
성립하거나, 증거 불일치로 `blocked`가 된다.

**실행 결과 (2026-08-26)**: W5 generator로 rank 7 HWPX를 재생성해 봉인 SHA-256
`1cc8062c…36f9e`와 byte-exact함을 확인했다. `rhwp convert --verify --verify-pages`를 두 번 실행한 HWP5는
동일 SHA-256 `3a844e05…ee7f`, IR 차이 없음, 1쪽 동치를 유지했다. 새 release native와 Docker WASM에서
HWPX·HWP5 각 1,556건의 trace가 형식별 byte-exact했고 metric entry는 전건 `null`, match kind는 전건
`none`이었다. HWPX는 document `substFont`를 paint 후보 체인에 보존하고 HWP5는 보존하지 않지만,
두 형식의 source+layoutMetric projection, fontFamily를 제외한 actual layout run과 fixed geometry는 모두
byte-equivalent했다. 그러므로 substitution metadata 차이는 paint-plane 경계이고 current layout의 첫
divergence는 `layout-metric`으로 확정했다. Q2는 제품 mutation 없이 exact TTF와 CDN OTF·WOFF2의 metric
identity 및 current heuristic 대비 누적 advance만 비교한다.

## 6. 자원·보안·개인정보 보호 불변식

- trace query는 `maxCharacters <= 4096`을 강제하고 0·음수·초과 값을 거부한다.
- 입력은 크기 상한이 있는 regular non-symlink file만 허용한다. journal은 1회 streaming하며 line 크기와
  중복 index를 제한한다.
- 외부 child 실행은 60초 timeout과 64 MiB 출력 상한을 적용한다.
- local-only cohort 출력은 mode `0600`, tracked public projection은 `0644`로 분리하고 기존 출력 symlink는
  거부한다.
- private corpus의 절대 경로·문서명·본문·문서 hash·font bytes는 공개 JSON·Markdown·Git diff에 넣지 않는다.
- CDN 다운로드 파일은 계측 cache일 뿐 tracked asset이 아니며, license 판정 없이 재배포하지 않는다.
- version/build 분기가 아니라 현재 face resolution·metric lookup·LineSeg admission 상태를 기능 탐지한다.
- layout metric, glyph/paint identity와 supply availability를 서로 독립 판정한다.
- actual fixed geometry의 한 줄 회귀도 평균 폭·page count 개선으로 상쇄하지 않는다.

다음 중 하나면 해당 stage에서 중단한다.

- W3/W4/W5/W7.5 입력 hash 또는 exact SFNT identity 불일치
- W5 rank 7 fixture hash를 결정적으로 복원할 수 없음
- HWP/HWPX의 첫 divergence를 한 decision plane으로 좁힐 수 없음
- CDN artifact의 byte·metric identity가 불명인데 supply를 layout truth로 사용해야만 후보가 성립함
- same-snapshot actual frame 또는 stored-row admission을 판정할 수 없음
- modelled cohort에서 신규 overflow·line-boundary 회귀 발생

- Q0은 기존 W3 journal의 decision만 읽으며 10k 원문을 다시 열지 않는다.
- Q1·Q2는 공개 fixture와 이미 확보한 exact source를 먼저 사용한다. 여기서 후보가 사라지면 private cohort,
  브라우저 시각 검증과 제품 구현에 진입하지 않는다.
- Q3도 Q0에서 동결한 문서만 제한 재실행한다. 기존 증거가 drift했을 때만 drift한 입력 범위를 다시 만든다.
- Hyper-V는 exact/subst/missing ladder나 source identity가 충돌한 경우에만 별도 계획·승인을 받아 제한 재실행한다.
- 각 stage는 focused contract test와 `git diff --check`를 통과한 뒤 결과를 보고한다. commit은 메인테이너의
  별도 승인 뒤 수행한다.

## 8. 승인 게이트

본 수행계획 승인 전에는 Stage W8-R7-Q0 실행, 새 계측 script·fixture 작성, CDN artifact 다운로드,
private cohort 조회, 제품 source 수정, commit, GitHub comment·push·PR·자식 이슈 생성을 하지 않는다.
계획 승인 뒤에도 각 stage 결과를 보고하고 다음 단계 승인을 받아 진행한다.
