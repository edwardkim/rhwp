## crates.io 배포의 주 사용 대상 (검토안)

**주 대상은 rhwp를 자신의 애플리케이션에 문서 처리 엔진으로 포함하려는 Rust 개발자다.**
HWP/HWPX를 열고 구조와 내용을 읽거나, 편집·저장·렌더링 기능을 자기 제품과 처리 흐름에
연결하는 사용자를 우선한다. 아래 순위는 현재 코드와 배포 목적에 따른 제안이며,
실제 이용 통계나 메인테이너가 확정한 지원 계약을 뜻하지 않는다.

| 우선순위 | 예상 사용자 | 주요 사용 목적 | crates.io에서 제공할 가치 |
| --- | --- | --- | --- |
| 1 — 주 대상 | Rust로 업무 도구·문서 처리 서비스·데스크톱 앱을 만드는 개발자 | HWP/HWPX의 텍스트·표·문서 구조를 읽어 검색·색인·RAG 입력으로 사용하거나, 문서를 편집·저장하고 지원 출력으로 렌더링 | 저장소를 직접 checkout하지 않고 Cargo 의존성으로 엔진을 가져와 자신의 코드에서 호출 |
| 2 — 보조 대상 | CLI·배치 처리·AI 에이전트 자동화를 운영하는 사용자 | 문서 정보 조회·추출·변환을 명령과 JSON 출력으로 연결하고, 필요하면 MCP 서버로 사용 | Cargo로 CLI를 빌드·설치하는 경로. Rust API를 직접 사용하지 않아도 이용 가능 |
| 3 — 추가 소비 경로 | Rust 기반 WASM 애플리케이션 개발자 | 자기 앱의 진입점과 실행 환경을 유지하면서 rhwp의 문서 처리 기능을 포함 | Rust 의존성으로 연결하고 필요한 feature를 선택하는 경로 |

이 구분의 코드 근거는 [Cargo manifest](../../Cargo.toml)의 `rlib`·`cdylib`와 CLI bin,
[공개 진입점](../../src/lib.rs)의 `parse_document`·`model::Document`·`DocumentCore`·
`serialize_document`, [에이전트 진입 문서](../../llms.txt)의 JSON·MCP 소비 경로다.
[1단계 소비 계약](../working/task_m100_8174_stage1.md#rust-소비-계약-초안)에서
각 경로의 feature·검증 대상을 구분한다.

Cargo 공식 문서도 [라이브러리를 프로젝트 의존성으로 추가하는 경로](https://doc.rust-lang.org/cargo/guide/dependencies.html)와
[`cargo install`로 실행 파일을 설치하는 경로](https://doc.rust-lang.org/cargo/commands/cargo-install.html)를
구분한다. CLI 설치는 패키지의 소스를 빌드하는 경로이므로, 기존 GitHub Release의 실행 파일
배포와 함께 제공할 수 있다. 일반 문서 열람 사용자의 Studio·확장 프로그램 이용 경로와
JavaScript 사용자의 npm 경로는 [기존 배포 채널](../manual/publish_guide.md)에 정리되어 있다.

이 대상을 채택한다면 준비 작업의 우선순위는 **저장소 밖 Rust 프로젝트에서 문서 열기 →
구조·내용 확인 → 편집·저장 왕복을 재현하는 것**이다. 선택한 feature의 렌더링과 CLI 설치·실행도
각 소비 경로에서 검증하며, source 후보 압축 성공만으로 이 사용성을 입증하지 않는다.
구체적인 공식 API·호환성·MSRV·target은 MD03·MD04에서 결정한다. 서비스 활용 사례를
제시한 사실만으로 비신뢰 업로드의 보안 지원을 약속하지 않으며, 그 범위는 MD05·MD07에서 정한다.
이 검토안으로 MD01–MD09의 상태나 현재 구현 범위를 변경하지 않는다.

[현재 구조 재조사](../tech/investigations/issue-8174/README.md)에서 독립 workspace의 소비와
CLI 설치를 실행하고 수정 후보 A01–A07을 구분했다. 기존 `service` 진입점, `HwpError`의
표준 오류 연동 실패, CLI facade 의존과 최소 feature의 범위도 아래 API·빌드 결정에 반영해 검토한다.

### MD01 — 제품 릴리즈와 crates.io 게시 시점

  인증 방식과 실제 적용 시점. 지원되는 최신 registry 인증 절차는 구현 시 공식 문서로 확인한다.
- **구현 영향:** A는 수동 명령·preflight·단계별 확인과 실패 복구, B는 workflow·권한·집계 검사가
  추가된다. 모두 exact SHA/version/digest와 자식→부모 등록 확인을 보존한다.
