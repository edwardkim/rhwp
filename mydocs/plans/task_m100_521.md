# Task #521: 그림(BehindText) vertical extent 가 paragraph height 에 미반영 — 수행계획서

## 배경

`samples/exam_eng.hwp` 페이지 2 column 1 의 18번 문제 답안지 ① ~ ⑤ 가 PDF 대비 약 3~4mm (~20px) 위로 올라가 있음. 이메일 안내문 표 박스의 하단 보더와 ① 사이 시각 여백이 PDF 의 ~5mm 대비 SVG 는 ~1.4mm 로 좁음.

## 측정 (1684×2382 동일 스케일)

| 항목 | PDF y | SVG y | 차이 |
|------|-------|-------|------|
| 박스 하단 보더 | 798 | ~791 | -7 |
| ① 첫 답안 | 826 | **806** | **-20** |
| ⑤ 마지막 답안 | 946 | ~919 | -27 |

## 본질 (가설)

pi=104 는 3개 컨트롤의 복합 구조:

| ctrl | 종류 | wrap | vert | 크기 |
|------|------|------|------|------|
| 0 | 그림 (브라우저 프레임 윗) | BehindText (글뒤로) | Para offset=0 | 108.0×67.8mm |
| 1 | 그림 (브라우저 프레임 아래) | BehindText (글뒤로) | Para offset=58.1mm | 108.0×18.5mm |
| 2 | 표 1×1 | TopAndBottom + tac=true | (인라인) | 108.0×76.2mm |

라인 height = 22207 HU = 셀 21607 + outer_margin_bottom 600. 다음 문단 pi=105 (①) IR vpos = 24805. SVG 측정 line_top ≈ 525.6 → IR 기대 544.2 대비 **약 1395 HU (18.6 px) 위로 올라감**.

**핵심 가설**: 한컴은 BehindText 그림이라도 paragraph 의 vertical extent (offset + height) 를 차지하면 다음 paragraph 시작 위치를 그림 하단까지 push down. rhwp 는 표(ctrl[2])의 line_height 만 기준으로 다음 line 시작 위치를 결정 → ctrl[1] 그림이 차지하는 vertical space 76.6mm 를 반영하지 못함.

부수 증상:
- 박스 내부 — Race Manager 와 박스 하단 사이 여백이 IR 기대 12.96 px 대비 SVG ~8.8 px (4 px 부족)
- ctrl[1] 그림 위치 자체는 IR 정합 (vert=Para offset=58.1mm 정확히 적용됨)

## 작업 단계

### Stage 1: 정밀 진단 + 가설 검증 + 분포 조사

1. `RHWP_LAYOUT_DEBUG=1` 으로 pi=104 layout 추적 (paragraph_layout.rs 의 logging 활용)
2. 가설 검증 — typeset.rs / pagination 의 paragraph 끝 y 계산 위치 식별, BehindText 그림이 어떻게 처리되는지 추적
3. 분포 조사 — 전체 샘플에서 "BehindText 그림 + 다음 문단" 패턴이 미반영되는 케이스 스캔 (회귀 위험 평가)
4. exam_eng p2 18번 베이스라인 캡처 (PDF / SVG-before)

### Stage 2: 수정 (가설 확정 후)

가설이 맞으면:
- BehindText 그림의 vertical extent (offset + height) 를 paragraph height 계산에 반영
- 다음 paragraph 시작 y = max(line_height-기반 y, behind_text_image_bottom)

회귀 위험을 최소화하기 위해 작은 변경부터 시도, 분포 조사에서 확인된 영향 케이스 모두 검증.

### Stage 3: 회귀 검증 + 최종 보고서
