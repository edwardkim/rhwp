# #7642 기준 PDF 래스터의 색·가는 Type3 획 보존

Issue: #7642. 렌더 source21cdd179bf의 출력과 독립 한컴 Print를 사용해 진단했다.
현재 공통 Cairo 정책은 실행 중 큐가 끝날 때까지 보존한다. 후보 helper와 검사는
ignored stage2468에 준비했으며 아직 기본 경로에 적용하지 않았다.

## 독립 계약과 원인

기준 PDF 래스터는 페이지·물리 크기와 함께 원본의 내부 RGB와 실제 잉크를
보존해야 한다.96/144DPI에서 다음 세 계약을 동시에 지켜야 한다.

1. 상수 DeviceRGB 이미지를 분수 좌표에서 축소해도 내부 RGB가 같아야 한다.
   잉크 임계값232 근처의 색도1 낮추지 않는다.
2. 같은 RGB로 빈틈없이 이어진 얇은 면과 하나의 큰 면은 같은 내부 색이어야 한다.
   각각의 면을 antialias해 생기는 흰 이음매를 기준 출력에 추가하지 않는다.
3. Type3 글꼴의 실제 가는 획을 전체 소실시키지 않는다. PDF 좌표로 정의한
   폭0.2pt·높이7.2pt 세로 획은 두 DPI에서 모두 실제 잉크를 갖는다.

Cairo None은1·2를 지키지만3의 잉크가0이다. Cairo 기본값은3을 지키지만2를
어긴다. Splash는2를 지키지만96DPI에서1의 비영 RGB를1 낮춘다. MuPDF 기본값도
2의 인접 면에 이음매가 생긴다. PDFium 기본값은 세 계약을 모두 만족했다.
이 판정은 문서 점수를 높이기 위한 renderer 선택이 아니라 독립 PDF 보존 계약이다.

## 구현과 증거 재계산 계획

후보 PDFium helper는 전체/선택 쪽에 같은 명령과 원본 쪽 번호를 사용한다.
글자·이미지·경로 antialias를 유지하고 후처리 색 보정이나 fallback을 하지 않는다.
Python·실제 PDFium 라이브러리·버전·wrapper·helper 해시를 기록한다. 범위 밖
쪽과 잘못된 DPI는 실패하며 다른 쪽이나 renderer로 대체하지 않는다.

기존 균일색·인접 면·실제 한컴 Print의 파랑 그라데이션 검사는 독립 기대값을
그대로 재사용한다. Type3 소실 검사와 선택 쪽·실패·실행 신원 검사까지8건이
후보에서 통과했다. 최초 PdfPage context-manager 호출 오류는 문서 객체와
다르게 page/bitmap에 명시적 close가 필요해 후보 helper에서 고쳤고 재실행했다.

공통 정책 전환 시에는 Python 검사 CI에 필요한 pypdfium2 의존성을 함께 반영하고
기존 명령 계약 검사·가이드를 새 공통 경로와 맞춘다. 기존 검사 호출을 중복 추가하지
않는다. 로컬 설치만으로 CI 의존성이 충족됐다고 판단하지 않는다. 현재 실행 중
Cairo 큐는 도구 해시를 고정했으므로 도중에 공통 helper를 바꾸지 않는다.

전환 뒤에는 devel9415b920c8과 최신 후보의 전체 Native/fresh WASM을 같은
새 PDF 정책으로 재측정한다. 동일 source·입력·글꼴·compat·DPI의 PNG를
해시와 producer manifest로 확인할 수 있으면 해당 렌더 출력만 재사용하고,
PDF PNG·TSV·review·overlay는 새로 산출한다. 다른 정책의 base/head TSV를
섞지 않는다. 문서별 renderer·antialias 선택은 하지 않는다. 전체90%·쪽수·직접
확대 판독·devel 대비0.01%p 하락 판정은 유지한다.

## 공통 경로 적용 결과

단계2473에서 Type3 검사의 수정 전 두 DPI 실패를 확인한 뒤 공통 경로를
PDFium으로 바꾸었다. 기존 Python 자동 수집172건과 CI 영향 분류·정책95건이
통과했다. 실행 중이던 옛 정책 시각 큐는 소유 프로세스만 확인해 종료하고
완료 캡처를 보존했다. Rust 빌드는 유지했다. 위 후보 준비 시점 기록과 구분하며,
새 정책의 전쪽 base/head TSV·직접 판독이 완료됐다는 뜻은 아니다.
