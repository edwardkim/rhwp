## 1. 목표와 핵심 질문

`ResolvedCharStyle`은 HWP/HWPX의 kerning flag를 보존하지만 `TextStyle` 변환에서 이를 잃는다. 현행
measurement는 glyph별 advance를 합산하고, SVG·Canvas2D·native Skia는 그 결과로 만든 cluster별 위치를
재생한다. portable GlyphRun도 `ttf-parser-nominal-v1` 명목 glyph와 기존 advance만 기록하므로 어느 경로도
문서가 요청한 pair positioning을 적용하지 않는다.

이번 작업의 질문은 다음과 같다.

> 문서의 kerning flag를 손실 없이 전달하고, 실제 font가 지원하는 GPOS `kern` 또는 legacy `kern` 능력을
> 기능 탐지해 pair adjustment를 적용할 때 어떤 glyph pair와 줄·프레임 경계가 달라지며, native·WASM·
> Canvas2D·CanvasKit이 같은 결정을 재생하는가?

목표는 모든 폰트에 임의의 kerning 값을 추정하는 것이 아니다. 정확한 source와 지원 table을 확인할 수 있는
경우만 적용하고, 나머지는 구조화된 `unsupported` 진단과 현행 advance를 유지하는 fail-closed 경로를 만든다.

## 3. 현행 손실 계보와 설계 제약

```text
HWP/HWPX CharShape.kerning
  -> ResolvedCharStyle.kerning               [보존]
  -> resolved_to_text_style / TextStyle      [현재 손실]
  -> EmbeddedTextMeasurer                    [문자별 hmtx·metric 합산]
  -> compute_char_positions                  [pair context 없음]
  -> TextRun / PaintTextStyle                [capability·source trace 없음]
  -> SVG·Canvas2D·native Skia                [cluster별 고정 좌표 재생]
  -> portable GlyphRun                       [nominal glyph, pair shaping 없음]
```

따라서 `TextStyle`에 bool 하나를 추가하는 것만으로는 완료되지 않는다. 다음 세 책임을 분리한다.

1. **문서 의도**: kerning on/off가 style resolution부터 layout·paint까지 손실 없이 전달되는가.
2. **font capability**: 실제 선택된 face source가 GPOS `kern`, legacy `kern` 또는 어느 것도 지원하지 않는가.
3. **결정 결과**: 어느 pair에 얼마의 adjustment를 적용했고 line/frame crossing이 어떻게 달라졌는가.

현행 `FontMetric`은 단일 glyph advance만 보존하고 pair table이나 source bytes provenance를 갖지 않는다.
historical metric 이름만으로 pair 값을 추정하거나 backend에게 다시 shaping을 맡기면 native/WASM 또는
layout/paint가 발산한다. pair adjustment는 공통 layout에서 한 번 결정하고 backend가 동일 위치를 재생해야 한다.

## 5. 보호 불변식

1. `kerning=false` 문서의 layout position·줄바꿈·paint JSON·SVG 출력은 기존과 동일해야 한다.
2. `kerning=true`라도 exact pair capability를 증명하지 못하면 adjustment를 적용하지 않는다.
3. font face 선택·single-glyph metric 변화와 pair positioning 변화를 같은 candidate에 섞지 않는다.
4. pair adjustment는 공통 결정값이고 backend가 독자적으로 다시 shaping하지 않는다.
5. GPOS `kern`, legacy `kern`, unsupported와 disabled를 서로 다른 진단으로 남긴다.
6. 장평·자간·justification·script scale 적용 순서를 fixture와 trace로 고정한다.
7. stored LineSeg 존재를 validity로 간주하지 않고 현행 feature-detection disposition을 사용한다.
8. 공개 산출물은 aggregate와 공개 fixture만 포함하며 private identity는 fail-closed한다.
9. parser·serializer의 기존 kerning round-trip과 문서 편집 명령을 깨뜨리지 않는다.
10. pair 또는 glyph 처리량에는 명시적 상한을 두고 비정상 입력에서 무제한 shaping을 하지 않는다.

**종료 게이트**: OpenType source에서 계산한 kerning on/off의 기대 pair 차이, 비대상 무변화, table 우선순위와
fail-closed reason이 공개 fixture에서 결정적으로 재현된다. 특정 한컴 버전의 출력이 on/off 차이를 만들지

메인테이너에게 승인받는다.

**실행 결과 (2026-08-26)**: 공개 HWPX 1쪽에 body 18개(run: ratio 100/90/80 × spacing 0/-5/-10 ×
K0/K1), table-cell 2개, text-box 2개를 고정했다. body의 K0/K1은 같은 stored/fresh lane에 배치했다. 현행
rhwp native·Docker WASM은 18개 body position과 SVG가 일치했고, 제품은 K0/K1을 모두 같은 좌표로 처리했다.

추적된 Noto Sans KR은 GPOS-only이며 unitsPerEm 1,000, `AV=-18`, `To=-76`, `WA=0`, `HH=0` design unit다.

없고 적용 순서도 측정할 수 없다.

개선이며, K0 현행 출력 불변을 별도 호환성 게이트로 유지한다. 공개 adjudication canonical SHA-256은

`8ad6b8562bfb19fc9c751d1d74012c334d821028640a1459e27a0b0b6bbbbda1`이다.

### Stage W9-Q3 — end-to-end 공통 pair positioning 구현

1. K0는 현행 호환성, K1은 OpenType capability 기반 기능 개선으로 분리하고 HWP 2020 PDF byte parity를 K1
   acceptance criterion으로 사용하지 않는다.
2. kerning flag를 `ResolvedCharStyle`에서 `TextStyle`과 measurement decision까지 전달한다.
3. exact source capability를 받은 공통 pair-positioning provider를 도입한다.
4. pair adjustment를 line measurement와 `compute_char_positions`가 같은 값으로 소비하게 한다.
5. 장평·자간·추가 spacing과 결합 순서를 단일 함수와 trace로 고정한다.
6. paint replay에는 이미 결정된 positions와 capability metadata만 전달하고 backend 재-shaping을 금지한다.
7. source 없음·미지원·malformed·상한 초과는 현행 advance를 유지하고 구조화된 reason을 남긴다.
8. `kerning=false` fast path가 기존 계산과 직렬화를 그대로 유지하는지 회귀로 고정한다.

**종료 게이트**: 공개 pair fixture의 measurement·line break·positions가 일치하고 off-baseline은 불변이며,
모든 미지원 상태가 fail-closed한다.

### Stage W9-Q4 — backend parity와 bounded 실제 cohort 판정

1. native와 Docker WASM에서 같은 public fixture의 pair decision과 positions를 canonical 비교한다.
2. SVG·Canvas2D·CanvasKit·native Skia가 공통 positions를 재생하고 독자적인 pair shaping을 추가하지 않는지
   확인한다.
3. Q0에서 동결한 동일 157문서만 bounded read-only 판정한다. 10k 전체를 다시 순회하지 않는다.
4. stored-valid/admitted, stored-rejected·unmodelled, fresh layout을 합치지 않고 별도 집계한다.
5. format, face, ratio, spacing, context별 적용·무조정·미지원과 첫 line/frame crossing을 집계한다.
6. 문서별 identity와 본문을 제거한 aggregate만 tracked evidence로 투영한다.

**종료 게이트**: backend parity mismatch 0, off-cohort 변화 0, 157문서 전건 disposition 회계와
stored/fresh 분리 결과가 확보된다. 실제 회귀가 있으면 평균 개선으로 상쇄하지 않고 원인을 좁혀 재계획한다.

### Stage W9-Q5 — 최종 판정과 W10 전달 계약

1. `qualified`, `no-change`, `blocked` 중 하나로 제품 결과를 판정한다.
2. flag 전달, capability, pair decision, backend replay의 계보와 보호 불변식 전항을 감사한다.
3. 공개 fixture·aggregate·검증 명령과 제한 사항을 최종 보고서에 기록한다.
4. W10에는 이번 작업에서 실제 지원한 shaping 경계와 미지원 table/script/axis만 전달한다.
5. commit·push·PR·self-review·merge·issue close는 각각 프로젝트 승인 게이트에 따라 별도로 진행한다.

**종료 게이트**: 메인테이너가 최종 보고서와 PR 후보 범위를 승인해야 원격 절차로 진입한다.

## 9. 중단·재계획 조건

다음 중 하나가 발생하면 구현을 밀어붙이지 않고 해당 Stage에서 중단해 수정 계획 승인을 받는다.

- kerning-off baseline이 style field 또는 JSON schema 추가만으로 바뀜
- exact font source 없이 historical metric name에서 pair 값을 추정해야만 구현 가능함
- native·WASM에서 동일 shaping engine이나 source provenance를 확보할 수 없음
- browser/Skia가 공통 positions 위에 kerning을 중복 적용함
- actual stored-valid lane에서 신규 overflow·line/frame crossing 회귀가 확인됨
- private identity 또는 font bytes가 tracked output에 포함됨
- shaping 상한을 우회하는 입력이나 유의미한 WASM size·시간 회귀가 확인됨
