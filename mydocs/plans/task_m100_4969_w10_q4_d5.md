## 2. 계측 원칙

### 2.1 A/B/A wall-time

동일한 공개 synthetic HWP5 code-2 표 셀과 동일 Noto source를 사용한다.

- **A1**: exact source를 등록하지 않아 기존 legacy vertical layout·TextRun으로 원자 fallback한 fresh core
- **B**: exact source를 등록해 bounded layout·GlyphRun·CanvasKit replay가 모두 활성화된 fresh core
- **A2**: A1과 같은 별도 fresh core를 B 뒤에 다시 실행한 drift control

source 등록과 fixture 생성은 timed region 밖에 둔다. 한 process에서 A1→B→A2 순서로 실행하고, Q3-E5와 같은
release 계측 관행을 재사용해 process 9개, warm-up 20회, 본 측정 64회로 고정한다. 각 process의 raw JSON을
보존하고 p50·p95, `B - mean(A1,A2)`, `A2 - A1` drift를 함께 보고한다.

측정 축은 서로 섞지 않는다.

1. render-tree/layout cold 1회와 warm 64회
2. 이미 만든 render tree의 layer build 64회
3. layer JSON serialization과 Rust CanvasKit replay-plan 분석 64회
4. actual CanvasKit surface의 legacy TextRun A1/A2와 bounded `drawGlyphs` B replay 64회

font blob/typeface/font 생성 비용은 cold와 warm cache hit을 분리한다. actual draw warm 측정은 검증된 face/font를
미리 준비하고 draw만 재며, cold 준비 비용은 별도 필드로 기록한다. backend가 다시 shape하거나 위치를 재측정하지
않는다.

### 2.2 판정 방식

새 절대 wall-time SLA나 측정 뒤 만든 임계치를 적용하지 않는다. A1/A2 drift가 bracket한 noise와 effect size를
있는 그대로 공개한다. 재현 가능한 B slowdown은 숨기지 않고 결과 승인에서 메인테이너가 수용·정정 여부를
판단한다.

hard gate는 구조적이다.

- A1/A2: vertical GlyphRun·font blob/face 0, legacy tree/hash 서로 일치
- B: fallback TextRun 2, vertical GlyphRun 2, unique font blob/face 각 1
- 반복 64회에도 source/resource/payload 개수가 반복 횟수에 비례해 증가하지 않음
- B glyph id·position·origin·pixel bounds와 canonical mismatch 0
- unsupported backend·malformed tuple은 fallback 100%, blank·partial publication 0

## 3. causal WASM size 대조

D4-D의 9,883,530 bytes는 이전 측정 사이에 upstream 23커밋이 들어가 Q4-D 인과 delta가 아니다. D5는 같은 최신
B tree에서 Q4-D 제품 커밋만 역적용한 disposable A worktree를 만든다.

역적용 대상은 다음 여섯 제품 checkpoint다.

1. `b1a33b6fc` — Studio actual CanvasKit replay
2. `c9b551909` — Rust CanvasKit selector
3. `d49400aad` — vertical GlyphRun publication
4. `bb334756b` — source/leaf shadow mapping
5. `992fe4acaf92` — bounded vertical HWP5 table layout
6. `d0948166a` — exact-source-bound dormant owner

임시 A와 B는 같은 upstream·toolchain·Docker image를 사용하고 별도 target/pkg 디렉터리에서 표준 Docker WASM을
각각 한 번 빌드한다. 최적화 WASM bytes·SHA-256과 delta bytes·percent를 기록한다. build wall time은 cache·열 상태가
달라 성능 결론으로 쓰지 않는다.

역적용은 disposable worktree에서만 수행하고 current branch를 바꾸지 않는다. reverse patch conflict가 나거나
A↔B diff가 위 여섯 checkpoint의 source/test allowlist 밖을 건드리면 강제로 맞추지 않고 `causal-size-unavailable`로
중단한다. 이 경우 과거 절대값으로 delta를 대신하지 않으며 최종 판정은 `blocked` 후보로 올린다.
