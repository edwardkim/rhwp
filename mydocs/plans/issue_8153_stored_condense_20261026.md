# #8153: 저장 줄의 공백 압축과 원 글자 전진 보존

## 원본·독립 근거

두 편람의 200쪽, 구역 7 문단 71의 표 셀 문단 3은 LEFT, 공백 최소값 30%,
장평 98%, 자간 −3%, 10pt다. 유효한 저장 줄 두 개의 시작은 0·54다.
독립 2024 Print에서 첫 줄의 `예외적으로 … 운영`과 다음 짧은 줄의 `및 관리 현황 보고`는
같은 KoPub 원 글자 전진을 사용한다. 첫 줄의 내부 ASCII 공백이 줄어들고 선두 공백과
`nbSpace`는 자연 폭을 유지한다. 현재 Native는 첫 줄에 추가 음수 자간을 주어 글자와
들여쓰기까지 줄인다. 글머리표 복구 후 남은 14픽셀의 원인을 이 경로에서 확인한다.

사양은 `한글문서파일형식_5.0_revision1.3.md` 표 44의 attr1 bit 9~15(공백 최소값
0~75%)와 HWPX paraPr.condense다. 줄 수용의 공백 예산·선두 공백 제외는 기존
`composer/line_breaking.rs`의 #7418 계약과 독립 한컴 재저장 자료를 재사용한다.
원 해결 기록은 #7568의 `731de9e1b4`, 후속 #7702 및 현재 base에 통합한
`6097253468`(#8191)과 대조한다. 줄을 끊는 계약과 끊은 줄을 실제 그리는 계약을 구분한다.

## 공통 원인과 구현 범위

현재 `compute_line_extra_spacing_with_dash_plan`은 비분배 정렬의 초과 폭을
모든 글자의 음수 자간으로 나눈다. 원본 공백 최소값을 이 판단에 전달하지 않는다.
또한 이 경로의 LeadingSpacePlan은 선두 공백을 배분 대상에서 제외하지 않는다.
Justify/Split의 별도 배분 규칙과 기존 독립 출력 근거는 유지한다.

1. 같은 저장/재조판 줄의 공백 최소값 예산으로 비분배 줄이 수용되는지 먼저 계산한다.
   원 글자·자간·줄 소속을 바꾸지 않고 내부 ASCII 공백의 원 폭에서만 예산을 소비한다.
   선두 들여쓰기·말미·nbSpace·원자적 필드/개체 내부는 공백 기회로 추측하지 않는다.
2. 공백 크기가 다른 run은 같은 원본 비율의 예산을 나눠 쓴다. source HU와 DPI를
   보존하며 임의의 문서 ID·고정 px·추가 fit 여유를 도입하지 않는다.
3. 줄의 공통 압축 결과를 TextStyle의 세션 한정 공백 결과로 전달한다. 문자 폭 측정,
   실제 run/인라인 개체 조각과 최종 positions가 같은 결과를 소비한다. 원래 글자의
   최소 전진 방어를 공백 압축으로 재적용해 결과를 되늘리지 않는다.
4. 실제 압축 positions를 게시해 PaintTextStyle 변환이나 backend의 재측정으로
   원점이 바뀌지 않게 한다. 문서 IR·사양 값·글꼴 프로그램은 수정하지 않는다.
5. 측정의 소비 경로는 `원본 condense·run 공백 폭 → 공통 run별 공백 결과 →
   정렬 기준 폭 → TextStyle 조각 → glyph 위치/다음 개체 pen → Native/Canvas positions`다.
   이 뒤의 마지막 글자/말미 공백 처리도 같은 결과와 함께 확인한다.

공백 예산으로 수용되지 않는 줄이나 소유를 확인할 수 없는 투영을 이 계획의 성공으로
보고하지 않는다. 원자적 표시 필드와 원문 scalar가 다른 투영은 기존 계약을 보존하고
현재 두 문서의 남는 차이는 계속 조사한다. 이 제한으로 전체 100% 목표를 축소하지 않는다.

## 검증

`tests/cases/issue_8153_condense_keeps_glyph_advances.rs`는 같은 문서·같은 글자모양의
짧은 정상 줄을 독립 대조로 사용한다. 두 줄의 같은 글자 전진과 선두/nbSpace 자연 전진,
내부 공백 압축·원문/쪽 소속을 확인한다. 기대 위치를 수정 함수에서 다시 계산하거나
전체 페이지 좌표를 고정하지 않는다. 테스트의 실제 소유 범위를 먼저 확인한 뒤
기존 frozen `5bcb654516`에서 결함 FAIL, 새 구현에서 PASS를 확인한다.

기존 #7418/#7702 줄 소유·경계 검사와 #8153 핵심 검사를 함께 실행한다. 200쪽·다른
공백 최소값 문단과 정상 경계의 Native/fresh WASM 직접 비교를 먼저 하고, 하락이 없으면
두 원본 전쪽 TSV·직접 확대 판독·최종 Rust/lint/Skia/Studio 게이트를 완료한다.
기준 PDF는 기존 독립 Print를 재사용한다. 진단·SO 자료와 임시 산출물은 output에만 둔다.
upstream/devel 동기화·원격 게시·PR 생성은 하지 않는다.

## 후속: 마지막 줄의 양쪽 정렬 압축 계약

`7e8e5e9e02`의 집중 검사 60건은 통과했다. 두 원본 116·200쪽은 Native 미대응
0픽셀로 개선됐으나, 집중 102조건 중 양쪽 형식의 148·327쪽은 각각 18·15픽셀 늘었다.
전쪽 확대 전에 이 차이부터 보정한다. 원본·PDF·측정 조건은 유지한다.

원인은 `needs_justify`가 거짓인 마지막 줄을 문단 자체가 LEFT인 줄과 같은 계약으로
취급한 것이다. 원본 148쪽 paraPr913은 JUSTIFY·condense50, 327쪽의 해당 셀 문단은
paraPr142·JUSTIFY·condense70이다. LEFT인 200쪽의 condense30과 구별한다.
독립 Print의 148쪽 한글 전진은 약13.60~13.76px, 내부 공백은 약5.76~5.92px이며,
327쪽 한글은 약11.52~11.68px, 내부 공백은 약5.28px다. 공백만 원본 condense까지
줄인 현재 구현은 각각 공백4.76px·2.37px로 지나치게 줄이고 글자 전진을 남긴다.

기존 정정 `848df0676f`와 [#7642 독립 Print 관측](../working/task_m100_7642_stage3720.md)의
양쪽 정렬 20% 공백 한계·잔여 글자 사이 압축을 재사용한다. 새로운 비율을 맞추지 않는다.
이 계약은 마지막 줄의 양수 여백을 늘린다는 뜻이 아니다. 자연 폭이 가용 폭을 넘을 때의
음수 여백 압축에서만 재사용하고, Split·탭·양수 여백·억제 셀 계약은 보존한다.

1. 문단 정렬과 줄의 실제 여백 부호를 구분한다. LEFT/RIGHT/CENTER의 공백 최소값과
   Justify의 음수 여백을 분리하며, 마지막 줄도 기존 Justify 압축 helper를 소비한다.
2. 말미 공백·마지막 signed 자간을 반영한 같은 여백 측정을 계약 선택과 helper에서 공유한다.
   실제 run 분할을 확정한 뒤 선두 공백/필드 소유 배열을 생성하는 앞선 정정도 유지한다.
3. `issue_8153_justified_final_line_compression.rs`에서 두 원본 148·327쪽의 같은 문단·
   글자모양·내용 관계와 독립 Print의 글자/공백 전진 구간을 검사한다. 전체 쪽의 절대
   좌표 핀이 아니라 실제 글자 메트릭 계약이며, Print의600dpi 격자와1HU 오차만 반영한다.
4. 고정된 `7e8e5e9e02`에서 실제 FAIL을 확인하고 새 source에서 PASS와 연결한다.
   기존 60건과 집중 Native/fresh WASM을 다시 확인한 뒤 두 문서 전쪽 검증을 계속한다.

진단 원문은 ignored `remaining-raw100-diagnostic/p148-p327-*`,
`condense-changed-lines-before/`와 `condense-changed-lines-after/`에 있다.
중간 source의 하락을 완료 판정으로 수용하거나 문서별 예외로 감추지 않는다.
