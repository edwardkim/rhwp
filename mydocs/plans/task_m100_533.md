## 1. 본질

`samples/exam_kor.hwp` 14페이지 우측 단에서 Square wrap 인라인 3×2 표 호스트 (pi=50) 직후 문단 (pi=51) 부터 SVG y 좌표가 baseline (~13.04 px ≈ 978 HU) 만큼 위로 시프트되어 렌더링되어 시각적으로 줄간격이 좁아 보이는 결함.

좌측 단의 pi=33/37/40/47 직후 문단도 동일 패턴 — Square wrap host 다음의 일반 문단 path 전반에서 발생.

→ 결함은 **Square wrap host → 일반 문단 경계 한 군데**. 후속 문단끼리는 일관 시프트만 누적되지 않음.

## 3. 가설 본질 분석

### 3-1. 코드 경로 비교

| paragraph 종류 | 함수 경로 | y 계산 |
|---------------|----------|-------|
| Square wrap host (pi=50) | `layout_wrap_around_paras` → `layout_partial_paragraph` | `para_y = table_y_start + ls.vpos/75` (top), 내부에서 baseline 추가 ✓ |
| 일반 문단 (pi=51+) | vpos 보정 (Task #412) → `layout_paragraph` → `layout_composed_paragraph` | `y_offset = col_area.y + (vpos_end - base)/75` (top), baseline 추가 누락 ✗ |

### 3-2. 추정 root cause

`src/renderer/layout.rs` 의 vpos 보정 (line 1490-1539, Task #412/#332 영역) 이 `y_offset = col_area.y + (vpos_end - base) / 75` 로 보정 — 이는 "다음 문단 첫 줄의 top" 위치.

`layout_composed_paragraph` 가 이 y_offset 을 받아 line 별 텍스트 SVG y 를 산출할 때 baseline 추가 경로가 누락된 것으로 추정.

대조 — wrap_around 경로 (line 3162) 는 동일하게 top 좌표를 `para_y` 로 전달하고 `layout_partial_paragraph` 내부에서 baseline 보강.
