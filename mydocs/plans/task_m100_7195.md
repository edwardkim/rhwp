## 3. 1단계 — 통과 2건의 상시 검사 복귀

### 최소 변경안

1. `src/renderer/layout/integration_tests.rs`의
   `test_552_passage_box_top_gap_p2_4_6`에서 `#[ignore]`를 제거한다.
   이 테스트에 한정하여 파일 읽기와 `DocumentCore::from_bytes` 실패를 명시적으로 실패시킨다.
   공용 `load_document` 전체 계약을 바꾸어 다른 테스트에 영향을 주지 않는다.
2. `src/wasm_api/tests.rs`의 `test_task77_image_cell_no_intra_row_split`에서 ignore를 제거한다.
   파일 부재 시 return을 없애고 기존 엄격한 읽기/파싱 경로를 사용한다.
   과거 ignore 이유는 과거 기록임을 분명히 하고 현재 assertion 통과와 새 시각 판정을 구분한다.
3. 기존 간격 임계값, 행 경계, cut 및 그림 소유 assertion은 그대로 유지한다.

### 검증

- 커밋된 샘플과 실제 실행 입력의 일치, 실제 읽기·파싱·assertion 도달을 확인한다.
- 일반 nextest 필터로 두 테스트를 실행한다. `--run-ignored only`를 쓰지 않아도 선택되는지 목록을 확인한다.
- 입력이 없거나 잘못됐을 때 실패하는 경로를 검증한다. 원본 샘플을 삭제·변조하지 않고 격리된 실행 환경을 사용한다.
- `cargo fmt --all -- --check`, `node scripts/rust-unit-test-tiers.mjs --check --base-ref 8d45f242baa1a565357aaa38e9f459595b1e756c`와 집중 테스트를 수행한다.
- 기대 결과는 기본 검사 2건 복귀다. 전체 제외 수는 실행 범위·동일 SHA의 목록을 확인한 뒤 보고하며
  예전 51에서 산술로 뺀 값을 최신 전체 실행 결과로 쓰지 않는다.

단계 결과를 `mydocs/working/task_m100_7195_stage1.md`에 기록하고 커밋한 뒤 다음 단계로 진행한다.

## 4. 2단계 — 실패 3건의 정밀 조사

세 건은 제품 수정이 아니라 원인·계약 조사부터 한다. 기존 이슈 #2279, #2308, #3798은 등록 시점
모두 CLOSED다. 과거 종료 근거와 ignore 도입 근거를 대조하되 임의 재개하지 않는다.

| 대상 | 입력 | 중점 확인 |
| --- | --- | --- |
| #2279 | `samples/86712_regulatory_analysis.hwp` | 중첩 행 유닛·가용 예산·첫 조각/이어지는 조각의 측정과 paint 일치, p27~29 줄 소유 |
| #2308 | `samples/76076_regulatory_analysis.hwp` | content box·폰트 환경·저장 줄 정보·줄바꿈 결과와 p81~82 실제 출력 |
| #3798 | `samples/issue3798/page_end_trailing_spill.hwpx` | fit 높이와 소비 높이, 마지막 줄의 글자 영역과 trailing 간격, 합성 기대값의 독립 근거 |

공통 조사 순서:

1. 원본·IR·테스트 계약·ignore 도입/후속 이력과 한컴 기준 출력의 입력/페이지/환경을 식별한다.
2. 첫 실패 뒤 검사도 독립적인 진단으로 수집하여 첫 오류 하나로 전체 상태를 추정하지 않는다.
3. 측정 → 분할 → 배치 → paint의 동일 객체·줄·경계 좌표를 추적한다. PDF 물리 페이지를 기준으로
   인쇄 쪽번호 또는 섹션별 리셋과 구분한다.
4. 기준 출력이 유효하면 같은 내용·영역의 PDF/SVG/PNG 비교와 디버깅 레이아웃을 준비한다.
   자료가 없으면 미검증으로 남기고 새 정답을 합성하지 않는다.
5. 반례와 환경 차이를 분리하여 아래 판정 후보를 제시하고 애매한 사례는 메인테이너의 시각 판정을 받는다.

판정은 **조판 규칙 위반 / 규칙상 유효하나 한컴과 다른 배치 / 테스트 계약·기준 자료 문제 / 증거 부족**으로 구분한다.
현재 devel의 시각 검증 문서뿐 아니라, #7090에서 사용자가 정한 “한컴이 무조건 정답은 아니며
애매하면 메인테이너가 트리아지한다”는 결정을 이 조사에도 적용한다.

열린 PR #7184가 중첩 행 높이와 분할 예산을 변경하므로 #2279 조사와의 교차 영향을 확인한다.
다른 담당자의 PR을 임의 변경하거나 이 브랜치로 통합하지 않는다.
