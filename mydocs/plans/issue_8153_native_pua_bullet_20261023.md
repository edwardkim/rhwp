# #8153: 원 글머리표의 실제 glyph 전진 공유

## 원인과 독립 근거

편람 228쪽 표에서 원문 `U+F02EF` 뒤의 첫 글자는 현재 200.52px,
독립 한컴 Print에서는 207.04px에 있다. 원 글머리표를 표시 대체용 가운데점의
반각 폭으로 재서 약 6.5px 당겨진다. 뒤따르는 일반 본문 글꼴의 독립 PDF 윤곽
450개는 설치된 원 프로그램과 같으므로 글꼴 파일 교체로 해결할 문제가 아니다.

독립 Print의 글머리표 17개는 실제 공급 SFNT의 `U+F02EF` 윤곽과 같고,
그 프로그램의 `hmtx` 전진은 1024/1024em이다. 표시 문자열 `·`의 전진과 다르다.
다른 공급 프로그램의 전진까지 1em으로 가정하지 않는다. 사양의 글꼴 슬롯·문자
보존과 실제 공급자의 cmap/hmtx를 근거로 처리한다.

## 기존 해결의 보존

- #5599 후속 `04ac745496`의 의미상 표시 대체와 #5800의 HWP5/평면-15 키 정규화를 유지한다.
- 실제 공급 SFNT의 원 PUA 표시·전진을 함께 쓰는 `d98df211d9`와 최종 소비 보정
  `774d414cd9`의 공통 경로를 사용한다.
- `764071d473`의 명시 exact 글꼴 소유권·호스트 세션 교체 계약을 유지한다.
- 실제 glyph 공급이 없거나 해당 cmap에 glyph가 없으면 종전 가운데점 fallback을 유지한다.
  일반 Unicode `·`를 원 PUA로 다시 분류하지 않는다.

## 생산과 소비

`원본 PUA → 공통 지원 기호 판정 → 실제 glyph를 가진 기존 호스트 공급 프로그램 →
cmap/hmtx 전진 snapshot → 측정·줄 구성 → 원 glyph 표시·Native/Canvas 재생` 순서다.
기호 코드의 지원 범위를 추가하며 backend별 폭 보정·문서별 분기는 넣지 않는다.
문서의 문자·font family·원본 바이트를 바꾸거나 글꼴 파일을 추가하지 않는다.

## 검증

기존 MIT 합성 글꼴의 cmap을 메모리에서 구성한 프로토콜로 수정 전 실패를 먼저 확인한다.
기대 전진은 해당 합성 원본의 hmtx 900/1000으로 정해 1em 하드코딩도 검출한다.
현재 원본 228쪽을 먼저 출력하고, 기존 화살표·괄호 및 정상 대조군을 확인한 뒤
초점 52쪽·fresh WASM과 전쪽 검증을 진행한다. 세션 프로토콜 통과를 한컴 출력의
피델리티 증거로 대신하지 않으며, 원래 목표인 1,532건 raw100과 페이지별 중요 영역
±2px 회귀 구축도 별도로 완료한다.
