## 1. 배경

Task #741 (PR #753) 에서 HWP3 외부 file path 그림 처리를 위해 `external_path` 필드 셋팅 로직을 추가했다. 이 때 HWP3 spec의 그림 종류 구분 (offset 74) 을 누락하여, **외부 파일/OLE/Embedded Image 3종 모두에 동일하게 `external_path` 를 설정**하는 결함이 발견되었다.

`hwp3-sample11.hwp` 의 임베디드 그림이 한컴오피스 2022 에서는 "문서에 포함" 으로 정상 표시되지만, rhwp-studio 에서는 외부 파일 (`E$$00000.jpg`) 로 잘못 표시된다.

## 2. 결함 상세

### 위치
[src/parser/hwp3/mod.rs:935-952](src/parser/hwp3/mod.rs#L935-L952)

```rust
let pic_type = info_buf[74];
if pic_type == 0 || pic_type == 1 || pic_type == 2 {  // ← 3종 동일 처리
    let pic_name_buf = &info_buf[83..83+256];
    let mut pic_name = decode_hwp3_string(pic_name_buf);
    pic_name = pic_name.trim_end_matches('\0').to_string();
    ...
    if !pic_name.is_empty() {
        // [Task #741] 외부 file path IR 전달 (Renderer placeholder 처리용).
        // HWP3 spec offset 74 그림 종류 0=외부 파일, 1=OLE, 2=Embedded Image
        pic.image_attr.external_path = Some(pic_name.clone());  // ← 모든 type에 적용 (오류)
        let next_id = (pic_name_to_id.len() + 1) as u16;
        let id = *pic_name_to_id.entry(pic_name).or_insert(next_id);
        pic.image_attr.bin_data_id = id;
    }
}
```

### HWP3 spec
- `pic_type == 0`: 외부 파일 — `pic_name` 은 file path
- `pic_type == 1`: OLE — `pic_name` 은 OLE 객체명
- `pic_type == 2`: Embedded Image — `pic_name` 은 임베디드 image 내부 참조명 (`E$$NNNNN.ext` 형식)

### 비교
| 항목 | rhwp-studio | 한컴오피스 2022 |
|---|---|---|
| 파일 이름 | `E$$00000.jpg` | (빈 값) |
| 문서에 포함 | ☐ (해제) | ☑ (체크) |

## 3. 영향 범위

| 컴포넌트 | 영향 |
|---|---|
| `picture-props-dialog.ts` | `externalPath` 우선 표시 → 임베디드 그림 오표시 |
| `web_canvas.rs` placeholder 분기 | `data.is_none() && external_path.is_some()` → 임베디드 그림 placeholder 오발현 가능 |
| WASM `getExternalImageBasenames` | 임베디드 그림 basename 도 반환 → 무의미한 fetch 시도 |
| `getExternalImageBasenames` 결과의 dev 서버 fetch | 매칭 파일 없어 404 응답 → log 노이즈 |

`bin_data_id` 매핑 자체는 `pic_name_to_id` HashMap 기반으로 모든 type에 필요하므로 유지한다.

## 4. 해결 방향

### 핵심 수정
`pic_type` 별 분기:
- `pic_type == 0` (외부 파일): `external_path = Some(pic_name)` 설정 (현행 유지)
- `pic_type == 1` (OLE): `external_path = None` (현재 OLE 전용 처리는 별도)
- `pic_type == 2` (Embedded): `external_path = None`

`bin_data_id` 할당은 type 무관하게 유지 (`pic_name_to_id` HashMap 매핑).

### 비채택 방안
- WASM 측 (`getExternalImageBasenames`) 에서 필터링: 결함 본질은 parser 레이어이므로 IR 자체를 정합하게 한다.
