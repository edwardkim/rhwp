## 1. 배경

Task #321 v6 작업 중 발견된 잔여 drift. 모든 문단의 마지막 줄 뒤에 붙는 `line_spacing`(약 9.5px)이 typeset advance 에 매번 누적되어, col 1+ 본문이 HWP/PDF 보다 일찍 다음 페이지/단으로 넘어감.

### 재현 (확인 완료)

```
RHWP_TYPESET_DRIFT=1 ./target/release/rhwp export-svg samples/21_언어_기출_편집가능본.hwp -p 0
```

- 모든 문단에 일관되게 `diff=+9.5` 보고됨 (= `trail_ls`)
- 페이지 0 끝에서 `LAYOUT_OVERFLOW: page=0, col=0, para=9, overflow=7.7px` 발생 → 누적 drift 의 가시화
- PDF page 1 col 1 마지막 문단(pi=26 + 보기 ①②③) 이 우리 SVG 에서는 page 2 로 밀림

## 2. 원인 분석 (코드)

`src/renderer/typeset.rs`:

```rust
// 521~525: 포맷 단계에서 fit 용 보정값은 이미 계산되어 있음
let total_height = spacing_before + lines_total + spacing_after;
let trailing_ls = line_spacings.last().copied().unwrap_or(0.0);
let height_for_fit = (total_height - trailing_ls).max(0.0);

// 607: fit 검사는 보정된 값 사용 — 정상
if st.current_height + fmt.height_for_fit <= available { ... }

// 612, 622: 그러나 advance 는 보정 없는 total_height 누적 — 버그
st.current_height += fmt.total_height;
```

`vpos_h`(LINE_SEG 실측) 와 `fmt.total_height` 의 차이 = `trail_ls`. HWP 는 마지막 줄 뒤 line_spacing 을 advance 에 포함하지 않음을 확인.

분할 경로(line 671~700) 도 동일 구조: `part_line_height = fmt.line_advances_sum(...)` 이 마지막 줄에 대해서도 `lh + ls` 를 더함 → 같은 drift.

## 3. 수정 방향 (확정 제안)

**후보 2** (이슈 본문) — `current_height` 누적값을 fit 기준과 일치시킴.

### 변경 지점

| 위치 | 현재 | 변경 후 |
|------|------|---------|
| `typeset.rs:612` | `st.current_height += fmt.total_height;` (FullParagraph fits) | `st.current_height += fmt.height_for_fit;` |
| `typeset.rs:622` | `st.current_height += fmt.total_height;` (line_count=0 path) | `st.current_height += fmt.height_for_fit;` |
| `typeset.rs:671~673,700` | 분할 마지막 partial 의 `part_line_height` 가 trailing_ls 포함 | 마지막 partial(`end_line >= line_count`) 일 때만 trailing_ls 빼기 |

### 변경하지 않는 것

- `paragraph_layout` 의 줄 내부 위치 계산 — 동일 문단 내부 줄 위치는 무영향 (advance 만 보정)
- `FormattedParagraph::total_height` 자체 — 다른 곳 영향 회피, 보정은 advance 시점에서만
- 표/footnote/zone 관련 height 계산 — 본 task 범위 외

### 후보 1·3 비교

| 후보 | 회귀 비용 | 정확도 | 채택 |
|------|----------|--------|------|
| 1. paragraph_layout 의 마지막 줄 y 보정 | 동일 문단 내 모든 줄 y 변동 가능 | 중 | ✗ |
| **2. typeset advance 보정** | advance 만 변경, layout 무영향 | 고 (HWP `vpos_h` 일치) | **✓** |
| 3. fit 만 너그럽게 | 이미 적용된 상태와 동일 (효과 0) | - | ✗ (이미 반영) |
