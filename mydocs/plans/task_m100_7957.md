## 목표와 범위

현재 Studio가 거절하는 정상 PDF의 처리 범위를 제품 PDF frontend·backend·WASM·Worker로
확장한다. 각 오류는 개별 이슈로 추적하며 공통 요청 정책·진단·검증은 한 작업 브랜치에서
통합한다. #7911·#7953의 공통 IR 기반을 이어 사용한다.

| 이슈 | 범위 | 현재 입력·재현 |
| --- | --- | --- |
| #7957 | 128쪽 초과 원본과 전체·선택 쪽 처리 | `reousrce_limit.pdf`, 162쪽, `PDF_RESOURCE_LIMIT: PDF must have 1 to 128 pages` |
| #7958 | content operator의 중복 해석·계상과 예산 | `content_operators.pdf`, 12쪽, `PDF_RESOURCE_LIMIT: content operators` |
| #7959 | bounded image의 실제 미지원 조합 | `bounded_import_path.pdf`, 4쪽, `PDF_IMAGE_UNSUPPORTED` |
| #7960 | 개별·문서 누적 path operation 처리 | `budget_exceeded.pdf`, 107쪽, `PDF_RESOURCE_LIMIT: document path operation budget exceeded` |
| #7961 | container/extraction 실제 실패 원인과 호환 | `extraction_error.pdf`, 14쪽, `PDF_PARSE_FAILED` |
| #7962 | 16 MiB 입력 한도와 호스트별 정책 일치 | 별도 실물 없이 생성 입력으로 검증. 16 MiB+1바이트 선행 거절 재현 |
| #7963 | decoded/copy/predictor/codec 누적 예산 | `decoded_bytes.pdf`, 14쪽, `PDF_RESOURCE_LIMIT: document decoded bytes` |

모든 실물 PDF는 `/mnt/e/tmp/`에 있으며 업로드하지 않았다. 원본은 읽기 전용 검증 입력으로
취급한다. #7962는 사용자 지시로 별도 샘플 제공을 착수 조건으로 삼지 않는다.

## 수행 순서와 판정

1. [공동 구현계획](task_m100_7957_impl.md)의 요청 정책·원인 관측 경계를 먼저 구현한다.
2. 입력/쪽 선택, operator/decoded 재사용, path 및 image/parse 호환을 절편별로 보정한다.
   각 절편은 작은 경계·영향 출력으로 방향을 확인하고 다음 절편으로 진행한다.
3. 일곱 유형의 개별 완료 조건과 정상 대조군을 확인한 최종 소스에서 Native·Docker WASM을
   만들고 전쪽 시각·실제 Studio·Worker와 정식 회귀를 통합 검증한다.
4. 최신 devel 변경을 필요한 시점에 한 번 통합해 영향 범위를 재검증하고 한국어 공동 PR을
   준비한다. 동일 실행 입력의 증거는 source/graph/profile 동일성을 확인해 재사용한다.

원인별 미지원은 해결·미해결을 구분한다. 첫 오류가 사라진 뒤 다른 한도에 도달하면 그 후속
경계까지 기록하며 해당 문서를 정상 처리했다고 보고하지 않는다. 일반 PDF 기능 전체나
오래된 보안·의미 복원 백로그를 완성하는 것을 이번 작업의 전제 조건으로 확대하지 않는다.
상수 일괄 상향·무제한 decoder·내용 생략·전체 쪽 raster 치환으로 오류를 숨기지 않는다.
