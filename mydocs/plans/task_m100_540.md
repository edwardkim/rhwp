## 1. 문제 정의

## 2. 사전 분석 결과 (Stage 0)

### 2.1 9곳 IR 구조 통일성

모든 9곳이 동일 패턴:

| pi | text | ParaShape | line | lh | ls |
|----|------|-----------|------|----|----|
| pi=44/80/110/143/174/206/232/264/294 | "[X~Y] 다음 글..." | ps_id=10 | **165%** | 1100 | **716** |
| 다음 pi (빈/공백) | (빈 또는 " ") | ps_id=25/35/39 | **60% or 65% or 95%** | 1100 | **음수 (-440 / -384 / -56)** |

빈/공백 paragraph 의 음수 ls 분포:
- ls=−440 (60% line): 3건 (pi=45, 207, 265)
- ls=−384 (65% line): 1건 (pi=111)
- ls=−56 (95% line): 5건 (pi=81, 144, 175, 233, 295)

### 2.2 페이지 2 [4~6] 측정

- pi=44 vpos=0, pi=45 (빈, 60% ls=-440) vpos=1816, pi=46 (지문) vpos=2476
- gap pi=44→pi=46 = 2476 HU = **33.01 px (IR 정확)**
- rhwp SVG 측정: 33.01 px ✓

→ rhwp 는 IR vpos 정확 따름. 한컴이 더 넓다면 한컴은 음수 ls 를 다르게 처리.

### 2.3 광범위 영향 사전 평가 (음수 ls 사례 카운트)

| 샘플 | 음수 ls 횟수 | line<100% 횟수 |
|------|------------|---------------|
| `synam-001.hwp` | **57** | 3 |
| `21_언어_기출_편집가능본.hwp` | 15 | 10 |
| `exam_math.hwp` | 13 | 9 |
| `exam_science.hwp` | 2 | 0 |

`synam-001.hwp` 에 57건으로 가장 광범위. 음수 ls 처리 변경 시 회귀 위험 매우 큼.

### 2.4 의심 본질 (한컴 환경 검증 필요)

1. **한컴 60% line spacing + 음수 ls 빈 paragraph 동작**: 한컴이 빈 paragraph 의 visual height 를 lh 그대로 사용 (음수 ls 무시) 또는 minimum advance 룰 적용 가능성.
2. **HWP 명세상 음수 ls 의 정의**: ls 는 "extra spacing" 인지 raw advance 인지에 따라 해석 차이.
3. **paragraph 사이 minimum spacing**: 한컴이 paragraph 간 최소 간격 룰을 추가 적용할 가능성.

## 4. 수정 방향 (3안 비교, 사전 검증 후 결정)

### A안: 빈 paragraph 의 음수 ls floor (text_len=0 한정)
빈 paragraph (cc=0 or text_len=0) + 음수 ls 인 경우 advance = lh 로 강제. 영향 범위: 빈 paragraph 만.

```rust
// paragraph_layout 또는 height_measurer 의 line advance 식
let advance_hu = if para.text.is_empty() && line_spacing < 0 {
    line_height  // 빈 paragraph 의 음수 ls 는 무시
} else {
    line_height + line_spacing
};
```

### B안: minimum line advance 룰 (전체 paragraph)
paragraph 종류 무관 advance ≥ lh 강제. 한컴 명세에 부합하면 단일 룰.

### C안: line spacing percent 의 한컴 동작 추정
% line spacing 의 한컴 advance 식 = max(lh, lh × percent / 100). 음수 ls 의 raw 값 무시하고 percent 재계산.
