# PDF 가져오기 선택 대기 중 모래시계 커서 개선

상태: 2026-10-31 승인한 구현·로컬 검증 완료. [완료 기록](../working/task_m100_8398_completion.md).
이슈: [#8398](https://github.com/edwardkim/rhwp/issues/8398), 담당: edwardkim.
기준: `devel` / `8fbed1a9c89798f925279e42fed6cbeba26b9c71`.

## 문제와 재현

사용자는 PDF 가져오기 대화창에서 선택해야 하는 동안 뒷쪽 모래시계 진행 상태 때문에
조작하기 어렵다고 보고했다. 2026-10-31 실제 Chromium의 Studio 열기 경로에서 재현했다.

- `open-document-bytes`로 PDF를 열고 「PDF 가져오기」의 설정 선택 단계에서 관측했다.
- `document.documentElement`에 `rhwp-busy`가 붙어 있다.
- 프로필 선택과 가져오기 버튼의 computed cursor가 모두 `wait`다.
- 상태 표시줄은 `파일 로딩 25% - 문서 파싱 및 쪽 계산 중...`이다.
- PDF Worker 생성은 0회다. 이 단계는 실제 변환이 아니라 사용자 입력 대기다.
- Escape 취소 뒤에는 busy가 해제되고 취소 문구가 표시된다.
- 화면·측정: `output/pdf-import-busy-20261031/dialog.png`, `result.json`, `browser.log`.
  스크린샷에는 커서 모양이 포함되지 않으므로 커서 판정은 computed style 실측에 근거한다.

## 선행 이슈와 원인

[기존 #5740](https://github.com/edwardkim/rhwp/issues/5740)은 실제 문서 로딩 중 대기 커서를
추가했다. [통합 #5768](https://github.com/edwardkim/rhwp/pull/5768), `c1acbf97c8`에 반영됐다.
그 완료 조건에도 사용자 입력을 기다리는 모달에서는 평소 커서를 사용하도록 명시되어 있다.
PDF 선택 대화창은 이후 [#8360](https://github.com/edwardkim/rhwp/pull/8360), `f125c735c7`에
들어왔다. 검색한 기존 이슈 중 이번 PDF 선택 대기의 증상과 같은 열린 이슈는 찾지 못했다.

`main.ts`의 `loadFile → loadBytes → loadDocumentForOpen → showPdfImportDialog`에서
바깥 `withBusyCursor`의 수명이 대화창의 전체 Promise 수명까지 포함한다. `loadBytes`는
선택 전에 25% 문구까지 게시한다. `style.css`의 `:root.rhwp-busy *`는 대화창 자식의
커서까지 강제한다. 실제 Worker 준비와 변환은 대화창 `onConfirm`에서 시작한다.

## 한 단위의 구현 범위

1. 문서 열기의 사용자 선택 대기와 실제 처리 단계를 구분한다. PDF 설정 선택과 실패 후
   재시도 대기에는 전역 busy 및 파싱 중 진행 문구를 유지하지 않는다.
2. 실제 읽기·변환은 기존 PDF 대화창의 단계 표시를 사용한다. 취소 버튼은 계속 조작 가능하게
   유지한다. 완료된 후보의 문서 교체·뷰 초기화에는 실제 작업 구간의 진행 표시를 적용한다.
3. `loadFile`과 `loadBytes`의 중첩 busy 소유권을 함께 다룬다. CSS만으로 대화창 커서를
   가리는 방식이나 전역 클래스 강제 제거로 다른 작업의 busy 상태를 훼손하지 않는다.
4. 공통 경로를 쓰는 파일 열기·드롭·바이트/호스트 열기를 보호한다. PDF 취소·오류·재시도 시
   기존 문서·최근 문서·저장 핸들·복구본 보존을 유지한다. 기존 HWP/HWPX 로딩과 새 문서의
   실제 작업 중 대기 표시도 유지한다.

Rust·PDF 변환 결과·조판·자원 한도는 변경 범위가 아니다. 현재 최신 devel의 최적화 WASM을
사용한다. 구현 중 이 경계를 넘길 필요가 발견되면 근거를 먼저 정리한다.

## 완료 기준과 검증

- 선택 단계: 프로필·고급 설정·확인·취소가 일반 커서로 조작 가능하고 가짜 파싱 진행 표시 없음.
- 변환 단계: 단계 표시·취소 가능, 실패 후 설정 수정·재시도 대기에 busy 잔류 없음.
