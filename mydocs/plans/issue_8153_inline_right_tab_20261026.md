# #8153: 같은 런의 오른쪽 탭과 명시적 정지

## 원 해결과 독립 근거

PR #1021·Task #874의 보정과 공통 측정 통합 `b9075217cc`를 추적했다.
기존 분기는 같은 런의 RIGHT+leader를 항상 셀 우단으로 정렬한다.
HWP5 §4.2.7 표 36은 탭 위치·종류·채움을 구분하고 표 37은 자동 우측 탭을 별도로
정의한다. 채움이 있다는 이유로 명시적 탭 위치를 무시할 근거는 없다.

편람 280쪽의 두 실제 런은 자동 우측 탭이 꺼져 있고 명시적 정지는 38,272 HU다.
원본 저장 전진 폭은 각각 1,106·1,162 HU다. 실제 스타일에서 명시적 정지는
510.29333px, 현재 셀 우단은 520px이며 현재 문자 배치는 후자를 강제한다.
독립 Print의 두 쪽번호는 앞의 명시적 정지에 대응한다. 이 수치는 원인 증거이며
제품에 페이지·문서 ID·보정 좌표로 추가하지 않는다.

고정 source `c3b88a07df`의 실제 Native paint를 사용한 진단에서 수정 전 PNG는
정식 전쪽 출력과 RGB 전픽셀이 같았다. 원본에서 읽은 명시적 정지를 적용한 진단과
저장 전진 폭을 보존한 진단 모두 **미대응 164→0픽셀·raw 100%**다.
원본·PDF·글꼴·텍스트·소유·측정 기준을 바꾸지 않았다. 별도 source-free offset을
맞춘 결과가 아니며 제품 수정 뒤의 재검증을 대신하지 않는다.

## 공통 수정과 반례

`TabDef와 유효한 inline tab → 공통 정지 선택 → 측정 폭과 문자 위치 →
intrarun bbox·canonical TabLeader·Native/Canvas`의 실제 경로를 연결한다.
기존 `find_next_tab_stop`의 명시적 정지와 가용 프레임 계약을 재사용한다.
단 안의 정지는 보존하고, 더 좁은 셀 밖에 저장된 정지는 기존 프레임 계약을 유지한다.
명시적 RIGHT 정지가 없으면 유효한 저장 전진을 소비한다. 자동 우측 탭과
교차 런 정렬은 기존의 정렬 단위·문자 순서 계약을 함께 확인한다.
리더 채움만으로 셀 우단을 선택하는 잘못된 가정을 제거한다.

정식 두 원본의 `tests/cases/issue_8153_*` 검사에서 같은 런의 숫자 끝이 원본의
명시적 정지와 일치하는 관계·소유·순서를 보호한다. 같은 검사 원문으로 수정 전
실패와 수정 후 통과를 확인한다. 기존 intrarun bbox·자동 탭·교차 런·중간 탭·
명시적 LEFT·가용폭 밖의 정지 대조도 실행한다. 관련 매뉴얼의 과도한 일반화를
실제 검증 결과와 함께 정정한다.

새 Native 영향 페이지와 직접 판독을 먼저 확인하고 표준 최적화 fresh WASM 및
전쪽을 같은 원본/PDF로 검증한다. 현재 source의 전쪽 1,532조건은 모두 90% 이상이나
최종 목표인 전쪽 raw 100%·미대응 0과 필수 전체 테스트는 아직 완료되지 않았다.
작업 증적은 ignored `remaining-raw100-diagnostic/remaining-direct-current/`다.
upstream 동기화와 원격 GitHub 쓰기 없이 PR 준비까지만 진행한다.
