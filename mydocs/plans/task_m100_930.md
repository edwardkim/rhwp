# Task #930 수행 계획서

## 1. 이슈 요약

**Issue #930**: 글상자 내부 텍스트에 도형 행렬변환(matrix) 세로 스케일 미적용 — `table-in-tbox.hwp` 2페이지

**목표**: 세로 스케일 행렬이 걸린 글상자 내부 본문 텍스트가 정상 크기로 렌더링되도록 정정한다. PDF(한글 2022) 정답지와 시각 정합을 달성한다.

## 2. 배경

`samples/table-in-tbox.hwp` 2페이지 본문은 사각형 도형(글상자, `글자처럼=true`) 안에 21개 문단으로 들어 있다.

`rhwp dump -s 0 -p 4` 결과:

```
요소: orig=43725×7950, curr=46691×65166, M=[1.068,0,0; 0,8.197,0]
```

도형이 세로로 8.197배 확대된 구조다. 현재 렌더 결과 글상자 본문 텍스트가 `font-size≈2.44`로 출력되어 거의 보이지 않는다 (정상 헤더 배너는 `22.67`). `2.44 × 8.197 ≈ 20` 으로, 본문 글꼴이 약 1/8.2로 축소되어 있다.

## 3. 원인 분석

`src/renderer/layout/shape_layout.rs:1196~1227` `layout_textbox_content()` 에 #874(commit `a466e2ea`, closes #866) 에서 추가된 글꼴 축소 로직이 존재한다.

```rust
let sw_ratio = current_width / original_width;   // 1.068
let sh_ratio = current_height / original_height; // 8.197
let max_ratio = sw_ratio.max(sh_ratio);          // 8.197
if max_ratio > 1.5 {
    let inv = (1.0 / max_ratio).min(1.0);        // 0.122
    cs.font_size *= inv;   // 글꼴이 1/8.2 로 축소됨
}
```

이 로직은 `shortcut.hwp` 1페이지 마스터 페이지 자동번호("1") 글상자를 위해 도입되었다. 자동번호 글상자는 거대한 글꼴(254pt)이 좌표계에서 그대로 그려져 본문과 겹치는 문제를 막기 위해, 도형이 원본 대비 확대된 경우 글꼴을 `original/current` 비율로 축소한다.

그러나 이 휴리스틱은 너무 광범위하다. `table-in-tbox.hwp`처럼 글상자 내부 문단이 **최종(current) 박스 크기 기준으로 이미 LINE_SEG 가 산출된** 일반 본문 텍스트에도 동일하게 적용되어 글꼴을 잘못 축소한다.

근거: `table-in-tbox.hwp` 글상자 내부 문단의 LINE_SEG 는 최종 박스 기준으로 배치되어 있다.
- LINE_SEG `sw`(세그먼트 폭) ≈ 45868 HU → current 박스 내부 폭(46691 − 좌우 margin 283×2 ≈ 46125)에 일치
- 마지막 문단 `vpos` ≈ 63101 HU → current 박스 높이(65166)에 근접

즉 글상자 본문은 확대된 박스 크기로 이미 조판이 끝나 있으므로 추가 글꼴 축소가 불필요하다. 반면 `shortcut.hwp` 자동번호는 그렇지 않아 축소가 필요하다 — 두 케이스를 구분하는 판별자가 필요하다.

## 4. 해결 방향

#874 글꼴 축소 로직의 발동 조건을 좁혀, **`shortcut.hwp` 자동번호 케이스에는 계속 적용되고 `table-in-tbox.hwp` 일반 본문에는 적용되지 않도록** 판별자를 도입한다.

판별자 후보(Stage 1 에서 검증 후 확정):

- **(A) LINE_SEG 정합 기반**: 글상자 내부 문단의 LINE_SEG `sw`/`vpos` 범위가 current 박스 크기에 정합하면 "이미 최종 조판됨"으로 보고 축소를 건너뛴다.
- **(B) 등방/이방 스케일 기반**: `sw_ratio`와 `sh_ratio`가 모두 1.5 초과인 등방 확대일 때만 축소(`min(sw_ratio, sh_ratio) > 1.5`). `table-in-tbox`는 `sw_ratio=1.068`로 한 축이 거의 1.0인 이방 확대이므로 제외된다.
- **(C) 콘텐츠 성격 기반**: 자동번호 단독 글상자 등 특정 패턴에 한정.

`shortcut.hwp`의 자동번호 글상자 스케일 등방/이방 여부를 Stage 1 에서 확인하여 (A)·(B) 중 더 견고한 쪽으로 확정한다.
