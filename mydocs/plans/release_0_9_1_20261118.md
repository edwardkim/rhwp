# v0.9.1 릴리즈 준비 — 2026-11-18

## 지시와 기준

작업지시자의 “0.9.1 릴리즈 작업을 해야 겠습니다”에 따라 로컬 릴리즈 준비를 시작한다.
기준은 최신 원격 devel `fbf8081db57c0c6abc9bad418290c5018193e24f`, 현재 main은
`7213ed1f96266b95e22cd5645a07851c9c18298e`다. 이전 정식 배포는 `v0.9.0`이다.
별도 작업공간 `release/0.9.1-preparation-20261118`을 사용하며 기본 devel과 다른 작업은 보존한다.

현재 devel에는 v0.9.0 이후 1,224개 commit이 있다. 이 기능 기준과 이미 승인·검증한
deprecated Atomic 보정 `9a0e2ced2bba4b21b8a0560884851dbe5efa0e6e`를 준비 범위로 고정한다.
다른 PR을 임의로 추가하지 않는다. 준비 중 원격이 전진하면 실제 차이·충돌과 필요한 재검증을
보고하며, 실행 증거를 다른 SHA의 성공으로 바꾸지 않는다.

이번 지시는 로컬 구현·문서·검증 준비 범위다. 원격 push·PR 생성·workflow dispatch·main 승격·
태그·registry 게시·스토어 제출은 구체적인 후보와 실행안을 준비한 뒤 해당 단계에서 확인한다.
지난 0.9.0의 원격 승인·예외를 새 릴리즈에 이월하지 않는다.

## 한 단위의 준비

1. deprecated 보정을 원 이력 그대로 통합하고 실제 MSRV 1.93.1을 유지한다. 기존 Fuzz 메모리
   보정은 devel에 포함돼 있으며 main 승격 뒤 정기 실행에도 적용될 변경으로 안내한다.
2. 제품 manifest·lock·확장 manifest를 0.9.1로 동기화한다. 공개 crates.io archive와 현재 source를
   대조해 변경된 내부·vendor 패키지 및 의존 부모의 새 버전·정확한 의존성을 확정한다.
   이미 게시된 버전의 내용이나 checksum을 바꾸지 않는다.
3. v0.9.0 이후 저자·공동 저자·원 PR·통합 이력을 기존 감사 도구로 대조한다. 새 기여자 원장과
   국·영문 CHANGELOG·릴리즈 노트를 만들고 이전 버전 기록은 보존한다. 원시 이메일은 ignored
   `output/release-v0.9.1/`에만 두며 공개 원장에는 넣지 않는다.
4. README·PDF/Native 안내·확장별 변경 이력·스토어 심사 문서·게시 매뉴얼을 현재 배포 계약에
   맞춘다. 검증하지 않은 macOS 지원이나 전체 PDF 충실도를 완성됐다고 설명하지 않는다.
5. 최종 source의 필수 Rust lint·전체 회귀, 실제 Native·최적화 fresh WASM·브라우저 소비,
   npm/VSIX·Chrome/Edge/Firefox 포장과 AMO source 재빌드, crates source/포장·의존성·소비를
   점검한다. 제품 조판 규칙은 새로 바꾸지 않고 이미 통합된 개선과 이번 준비 변경을 구분한다.
6. exact main/devel의 workflow 승격 inventory와 required 실행안을 준비한다. 최종 devel
   통합 뒤 같은 SHA의 승격 검증을 완료하고 main PR을 연다. 과거 실행·skip·미실행을 새 head의
   통과로 대신하지 않는다. registry·스토어 게시 후에는 공개 설치·checksum·실제 소비를 확인한다.

## 절차와 기록

배포 정본은 `mydocs/manual/publish_guide.md`, `crates_io_guide.md`,
`github_operations.md`와 `codex/docs_and_git_workflow.md`다. PR 기본 경로는
`collaborator_self_merge`, 보조 경로는 `local_validation`이며 code head CI 성공 전에는
PR review·오늘할일을 미리 작성하지 않는다. CI 실행 정의·판정 정책을 변경하면 옵션 2를 적용한다.

공용 Cargo target은 기본 작업공간의 `target/pr-review`이며 Cargo 계열 명령은 순차 실행한다.
공개 registry 소비 환경은 기존 Git 제외 키트 `local/crates-io-consumption/`를 재사용하되,
미게시 0.9.1의 공개 소비 성공을 주장하지 않는다. 모든 완료·미실행 단계는 실제 SHA·명령·
결과를 [준비 보고서](../report/release_0_9_1_preparation_report.md)에 구분해 남긴다.

## 준비 중 기준 갱신

2026-11-18 11:49 KST 원격 확인에서 devel에 #9168 한 건이 추가된 것을 확인했다.
최신 기준 `1695089d21fb5ff116eeba263e4935f04b4ac494`를 충돌 없이 병합했다.
수정은 Studio의 쪽별 호스트 글꼴 요청과 검사이며 Rust·Cargo 입력은 이전 후보와 같다.
원 기여 개선은 Studio 전체 검사와 `host-font-input-issue9165.test.mjs`로 다시 확인한다.
기여자 원장은 v0.9.0 이후 1,225개 commit으로 갱신했으며 사람 19명은 그대로다.
새 원격 후보를 임의로 추가한 것이 아니라 최신 devel의 통합 상태를 반영한 갱신이다.

최종 fetch에서 #9170이 추가된 devel `8612752c0e`를 확인해 로컬에 병합했다.
첫 페이지 표시 완료의 Studio 변경이며 Rust·Cargo·runtime 자원 입력은 앞서 실제 검증한
`8a01b6529c`와 같다. 기여자 원장을 1,226개 commit으로 갱신했다.
새 초기 렌더 E2E와 Studio·패키지·브라우저를 재검증한다. source ZIP은 실제 냉 재컴파일한
8a01b6529c의 Rust 입력과 새 ZIP 입력의 내용이 같을 때만 그 컴파일 증거·캐시를 재사용하며,
새 프런트엔드는 ZIP에서 실제로 다시 빌드한다. 다른 Rust 입력이 발견되면 전체 재컴파일한다.

## 릴리즈 검사에서 발견한 Chrome 설정 응답 경계

최신 source의 worker 강제 종료 E2E에서 get-settings 채널이 닫힐 때 초기 콜백이
runtime.lastError를 읽지 않고 기본 배지·호버를 켜는 기존 결함을 확인했다. 관련 callback은
Task #76 `a6ae8c28de`에서 시작했고, lifecycle 검사는 #7283·#8178에 이어진 기존 경로다.
#9170의 Studio 코드가 실행되기 전 worker-stop 단계의 오류이며, 8a01b6529c 이후 해당
content-script·background·lifecycle 테스트 소스는 같다.
Chrome 공식 runtime 계약에 따라 콜백 안에서 오류를 확인하고, 설정을 확보하기 전 선택적 UI를
활성화하지 않도록 릴리즈 보정한다. 실제 content script를 실행하는 VM 대조군에서 수정 전
오류 사례 FAIL·정상/비활성 사례 PASS를 확인했다. 기존 CI 자동 수집 options.test.mjs에
세 사례를 포함해 source 수정 뒤 전부 재검증한다. lifecycle의 오류 assertion은 유지한다.
근거: https://developer.chrome.com/docs/extensions/reference/api/runtime/#property-lastError

보정 검증: 기존 content callback 반례는 수정 전 FAIL, 수정 후 options 7개 PASS다. 실제 Chrome의 `wake-download-hwp`를 재시도 없이 3회 실행해 모두 PASS를 확인했다. 전체 확장 E2E와 최종 포장 검증을 이어간다.
