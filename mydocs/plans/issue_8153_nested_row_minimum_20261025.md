# #8153: 중첩 표의 저장 행 하한과 닫힌 전체 프레임

## 원본과 독립 근거

편람 HWP/HWPX 149쪽의 신청서 안내 두 줄과 아래 회색 행이 약 3.76px 위에 있다.
원본 HWPX section4의 표 `1517942118`은 4행이며 개체 높이는 5628HU다.
행별 선언은 982·882·2103·1261HU다. 제목 행은 실제 저장 글줄 높이 1000HU와
활성 위·아래 여백 141+141HU를 갖는다. 따라서 882HU의 선언은 제목을 담지 못한다.
소스 LineSeg·셀 크기·안 여백은 HWPUNIT으로 읽으며 문서별 픽셀 보정값을 넣지 않는다.

독립 Print의 제목 baseline은 814.72px이며 안내 두 줄은 829.76·841.92px다.
현재 실제 layer의 제목은 원래 위치에 있지만 안내 두 줄의 논리 baseline은
826.093333·838.253333px다. 아래 회색 행의 독립 경계는 846.477376px다.
이전 회귀의 글자 크기·baseline만 바꾸어 맞추지 않고 실제 행 원점을 추적한다.

| 행 | 선언 HU | 저장 줄·실효 안 여백에 필요한 최소 HU | 적용할 하한 HU |
| --- | ---: | ---: | ---: |
| 첫 행 | 982 | 982 | 982 |
| 제목 | 882 | 1282 | 1282 |
| 안내·쪽 번호 | 2103 | 1820 | 2103 |
| 회색 접수란 | 1261 | 1024 | 1261 |

각 행의 `max(선언, 내용+활성 여백)` 합이 원래 개체 높이 5628HU와 정확히 같다.
현재는 제목을 1000HU로만 성장시키고 남은 282HU를 마지막 행으로 보내어, 표 전체
높이가 같아도 제목 뒤의 안내·회색 행 위치가 잘못된다. 원본 자료와 PDF 좌표는 ignored
`handbook-{owned,exact}-table-fill-candidate/source-diagnostic/`에 보존했다.

## 원 해결과 보존할 반례

`stored_hwpx_no_adjust_cell_content_end`의 원 도입은 `b586290aeb9d`이며
통합 PR #7505의 PR #7382 보정56에서 #1658 하단 고정틀의 행 성장 중복을 막았다.
`mydocs/pr/archives/pr_7382_review.md`의 보정56·59는 제목 원점 보존과 본문 표의
안 여백 계약을 명시한다. noAdjust만으로 여백을 없애는 전제는 일반화할 수 없다.
이 helper를 전역 제거하거나 다른 입력에 같은 여백을 무조건 더하지 않는다.

## 공통 생산·소비와 검증

기존 `stored_complete_row_frame_heights`에서 저장 줄의 소유·단조 순서·양수 높이·
활성 여백·행/열 덮임을 확인한다. 기존의 닫힌 내용 프레임 판정은 유지하고,
그 판정이 성립하지 않을 때 행별 선언과 실제 내용 하한의 최댓값이 원래 개체 높이를
정확히 닫는 경우에만 같은 원본 행 결과를 반환한다. 마지막 줄의 후행 spacing은
다음 흐름의 전진이며 닫힌 셀 잉크의 높이와 구분한다. 임의 비율·공차로 성립시키지 않는다.

이 결과는 HeightMeasurer의 최종 행 결과와 LayoutEngine의 일반/중첩 fallback이
이미 소비한다. 별도 paint 좌표 이동·마지막 행 clamp·본문 숨김을 추가하지 않는다.
실제 149쪽의 안내/쪽 번호/회색 행·전체 높이·앞뒤 내용과 정상 #1658·#3386을 먼저
검증하고, 이후 편람 전쪽 Native/fresh WASM에서 하락 여부를 확인한다. 현재는 구현
전 원인·검증 계획이며 새 후보의 통과나 전쪽 100% 완료를 뜻하지 않는다.
