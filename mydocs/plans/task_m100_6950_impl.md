## 1. 목표와 선택하지 않는 방법

문단 끝의 자리차지 표가 해당 앵커 줄 아래에 배치되고, 실제 배치와 조판 공간 예약이 일치하도록
한다. 표가 들어갈 여유가 없는 본문 줄에 표를 겹치지 않는 것이 목표다. 샘플 전체의 모든 간격과
폰트를 일괄 수정하는 작업이 아니다.

기존 TAC 전용 제한을 삭제하면 #6718이 악화되므로 삭제하지 않는다. 호스트 저장 줄이 단조
증가한다는 조건만 더하는 것도 두 사례를 구분하지 못한다. 형식/한컴 버전, 문서명, 문단 번호,
샘플 좌표를 정책 키로 삼지 않는다. 이번 문제 표를 TAC로 바꾸거나 원본 LineSeg를 수정하지 않는다.

## 2. Stage 2의 실행 순서

### A. 좌표 기준 확인 — 이번 구현의 선행 조건

새 전수 계측 대신 이번 fixture와 #6718, #6879 세 건에서 다음 값만 확인한다.

- 원본 첫 줄·앵커 줄, 현재 쪽 원점 및 continuation 시작 줄.
- typeset의 `para_start_height`, 현재 흐름 높이와 예약한 표 상하단.
- layout의 `para_start_y`, `para_y_for_table`, 실제 호스트 줄과 표 상하단.
- 위 기준값이 어느 PageItem 처리에서 설정·재설정되는지.

기존 진단 수단을 먼저 쓰며, 부족한 값만 임시 진단으로 기록한다. 진단 출력을 제품의 무조건 로그로
남기지 않는다. #6718에서 빈 호스트 전용 스냅이 실행됐다는 과거 설명은 전제로 삼지 않는다.

확인할 설계는 **이미 조정된 표 기준점에 저장된 첫 줄-끝 줄 거리를 다시 더하지 않고, 같은 쪽
좌표계에서 아직 반영되지 않은 앵커 진행만 반영**하는 것이다. 단순 `max()`나 임의 간격 보정으로
대체하지 않는다. 구체적인 기준점 대응은 세 사례의 기록으로 검증한 후 코드에 고정한다.

이 확인으로 일반 규칙을 도출할 수 없거나 PageItem/IR의 광범위한 구조 변경이 필요하면,
샘플 예외를 추가하지 않고 발견 내용과 수정 계획을 먼저 보고한다.

### B. 최소 구현과 회귀 테스트

| 대상 | 계획 |
| --- | --- |
| `src/renderer/layout.rs` | 저장 앵커와 현재 문단/쪽 기준을 해석하는 최소 공통 판단을 추가·사용. 기존 TAC·분할 보호 경로 유지 |
| `src/renderer/typeset.rs` | 일반 표의 공간 예약에도 같은 기준을 적용. 실제 표만 내려 후속 본문과 겹치게 하는 수정 금지 |
| `tests/cases/issue_6950_paragraph_end_topbottom_anchor.rs` (신규 예정) | 실제 fixture로 본문 끝-표-후속 본문 순서, 표 개수·내용 보존, 쪽 넘침을 검사 |
| `mydocs/working/task_m100_6950_stage2.md` | A의 기준점 기록, 수정 전 실패/후 성공, 보호 사례 결과와 한계를 정리 |

공통 판단의 위치는 기존 앵커 helper 인근을 우선한다. renderer 전체 리팩토링이나 관련 없는
개체 배치 경로의 이동은 하지 않는다. 원본 fixture와 PDF는 이미 확보했으므로 추가 생성하지 않는다.

신규 테스트는 `603.8px`를 한컴 정답 좌표라고 고정하는 방식이 아니라 실제 텍스트와 표의
비겹침·순서를 먼저 검증한다. 쪽수 변화는 무조건 승인하지 않고 후속 배치와 정답 PDF로 확인한다.
원본에서 읽은 위치의 설명용 계산과 테스트가 보호할 의미를 구분한다.

workspace build → all-targets Clippy → manifest 검사 묶음을 순차 수행한다. generated suite·manifest는
검증 증적이지 제출 소스가 아니다. 전체 회귀 범위와 실제 명령·시간은 Stage 3 보고서에 남긴다.

현재 단계에서 CI 정책 변경, 원격 push·PR 생성, GitHub comment·병합·close는 하지 않는다.
최종 보고서와 결과 승인 후 각 후속 승인 절차를 따른다.
