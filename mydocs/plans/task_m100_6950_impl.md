## 1. 목표와 선택하지 않는 방법

문단 내 텍스트와 표를 **원본 컨트롤 순서·앵커·본문배치 속성·가용 영역에 따라 결정**하고,
확정한 동일 배치 결과를 공간 예약과 실제 출력이 소비하도록 한다. 이번 샘플의 겹침만 없애는
좌표 보정은 완료 기준이 아니다. 같은 의미의 HWP/HWPX 입력에는 같은 공통 IR 배치 규칙을 적용한다.
같은 입력·폰트/측정 결과·조판 설정에 대해 같은 결과가 나오는 것이 여기서 말하는 결정론이다.
이는 모든 한컴 버전의 출력이 동일하다는 주장과 다르다.

기존 TAC 전용 제한의 **단순 삭제**는 #6718을 악화시키므로 채택하지 않는다. 그러나 이 조건문
자체를 영구 보존하는 것도 목표가 아니다. 일반 규칙으로 역할이 대체되면 제한을 교체·제거한다.
보호 대상은 기존 정상 조판이지 과거 분기문이나 테스트의 절대 좌표 그 자체가 아니다.
호스트 저장 줄의 증가 여부만으로 사례를 구분하지 않으며, 형식/한컴 버전, 문서명, 문단 번호,
샘플 좌표를 정책 키로 삼지 않는다. 이번 문제 표를 TAC로 바꾸거나 원본 LineSeg를 수정하지 않는다.

### 1.1 확정할 조판 계약

다음은 구현·검증할 계약이며, 이미 구현됐다는 설명이나 공개 스펙의 직접 인용이 아니다.
속성의 기본 의미는 [표 배치 규칙](../tech/table_layout_rules.md), 저장 줄의 의미와 source 경계는
[Document IR LineSeg 표준](../tech/document_ir_lineseg_standard.md)을 따른다.

1. **논리 순서**: 문단의 텍스트 위치와 컨트롤 앵커를 동일 문자 축으로 대응한다. control 배열
   순서나 이미 그려진 노드 순서만으로 문단 내 배치 순서를 추정하지 않는다.
2. **배치 방식**: TAC는 텍스트와 같은 줄 흐름에서 여백 포함 상자의 가용 폭을 판단한다.
   들어가지 않으면 현재 줄을 닫고 다음 가용 줄로 진행한다. 비-TAC의 TopAndBottom은 위치 속성으로
   정한 점유 구간에서 본문을 위/아래로 흐르게 하며, 단순 인라인 폭 비교로 치환하지 않는다.
   Square의 좌우 어울림, 글앞/글뒤의 겹침 의미도 혼동하지 않는다.
3. **원점**: Paper/Page/Column/Para의 기준, 앵커가 속한 실제 줄과 쪽/단의 조각을 명시적으로
   구분한다. 현재 흐름의 y를 문단 첫 줄 또는 앵커 줄이라고 암묵적으로 간주하지 않는다.
4. **저장 줄과 재조판**: 현재 문단/조각에 유효한 저장 LineSeg인지 먼저 판정한다. 유효한 source
   좌표는 그 좌표계에서 해석하고, 없거나 편집으로 무효가 된 경우 계산된 줄 배치를 사용한다.
   저장 좌표와 재조판 높이를 근거 없이 더하지 않는다. 파일 확장자·버전으로 경로를 선택하지 않는다.
5. **공통 배치 결과**: 앵커 기준·표 상자·점유 구간·다음 흐름 위치를 한 결정의 결과로 묶는다.
   typeset이 예약한 뒤 layout이 다른 원점에서 다시 보정하지 않도록 결과를 전달한다.
   ‘같은 helper를 호출한다’만으로 서로 다른 입력 원점의 불일치를 해결했다고 인정하지 않는다.
6. **쪽 경계**: 현재 영역에 배치할 수 없으면 문서의 표 나눔 정책과 기존 페이지 조판 계약에 따라
   분할/이월한다. 겹침을 감추기 위해 표를 쪽 안에 강제로 끌어올리지 않는다. 탐색은 줄/영역의
   유한한 경계를 따라 전진하고 배치 불가능한 크기에서 같은 위치를 무한 재시도하지 않는다.

이번 샘플의 ‘본문 아래 표’는 이 계약에서 도출되어야 한다. `87.36px` 추가 또는 `603.8px` 배치를
성공 규칙으로 사용하지 않는다. #6718을 지키기 위한 continuation 전용 제외 분기도 자동 채택하지 않는다.

### 1.2 구현 책임 경계

- 파서는 구조·속성을 공통 IR로 보존한다. renderer에 포맷별 임시 판별을 추가하지 않는다.
- 배치 결정은 측정된 줄/표와 현재 frame을 입력으로 받으며 RenderNode를 읽어 역산하지 않는다.
- 공간 예약과 렌더링은 확정 결과의 소비자다. 좌표계 변환은 명시하되 배치 판단을 반복하지 않는다.
- 기존 `ObjectPlacementFrame`, `InlineFlowPlan`의 원점·확정 결과 전달 구조를 우선 재사용한다.
  현재 `InlineFlowPlan::supports`는 비-TAC 표를 지원하지 않으므로 이번 표를 억지로 TAC 경로에
  통과시키지 않는다. 필요한 일반 표 배치 결과는 해당 책임 경계에서 연결한다.
- 문단·표의 계약상 필요한 결과 전달을 ‘최소 줄 수’를 이유로 생략하지 않는다. 반대로 폰트 엔진·
  전체 IR·관련 없는 모든 renderer 경로의 일괄 재작성으로 확대하지 않는다.

## 2. Stage 2의 실행 순서

### A. 좌표 기준 확인 — 이번 구현의 선행 조건

새 전수 계측 대신 이번 fixture와 #6718, #6879 세 건에서 다음 값만 확인한다.

- 원본 첫 줄·앵커 줄, 현재 쪽 원점 및 continuation 시작 줄.
- typeset의 `para_start_height`, 현재 흐름 높이와 예약한 표 상하단.
- layout의 `para_start_y`, `para_y_for_table`, 실제 호스트 줄과 표 상하단.
- 위 기준값이 어느 PageItem 처리에서 설정·재설정되는지.

기존 진단 수단을 먼저 쓰며, 부족한 값만 임시 진단으로 기록한다. 진단 출력을 제품의 무조건 로그로
남기지 않는다. #6718에서 빈 호스트 전용 스냅이 실행됐다는 과거 설명은 전제로 삼지 않는다.

이 기록은 사례별 제외 조건을 찾는 작업이 아니다. **현재 원점이 어떤 논리 줄/물리 조각을
가리키는지 밝혀 앵커와 점유 영역을 직접 결정**하기 위한 것이다. 이미 반영된 거리를 다시 더하지
않는 것은 그 결과의 불변식이다. 단순 `max()`나 임의 간격 보정으로 대체하지 않는다.
기준점 대응은 실제 입력과 조판 계약 테스트로 검증한 후 코드에 고정한다.

이 확인으로 일반 규칙을 도출할 수 없거나 PageItem/IR의 광범위한 구조 변경이 필요하면,
샘플 예외를 추가하지 않고 발견 내용과 수정 계획을 먼저 보고한다.

### B. 조판 계약 구현과 회귀 테스트

| 대상 | 계획 |
| --- | --- |

기존 앵커 helper의 의미를 공통 배치 결정과 정합시킨다. renderer 전체 리팩토링이나 관련 없는
개체 배치 경로의 이동은 하지 않는다. 원본 fixture와 PDF는 이미 확보했으므로 추가 생성하지 않는다.

신규 테스트는 `603.8px`를 한컴 정답 좌표라고 고정하는 방식이 아니라 실제 텍스트와 표의
비겹침·순서를 먼저 검증한다. 쪽수 변화는 무조건 승인하지 않고 후속 배치와 정답 PDF로 확인한다.
원본에서 읽은 위치의 설명용 계산과 테스트가 보호할 의미를 구분한다.

추가로 조판 계약의 경계를 테스트한다: 앵커가 첫 줄/뒤 줄에 있는 경우, 가용 폭의 안/밖,
원점 이동, 같은 문단의 여러 컨트롤 순서, continuation, 유효한 저장 줄/계산된 줄의 구분이다.
직접 구성한 IR의 테스트는 알고리즘 불변식 검증으로 명시하고, 한컴에서 정상 저장된 문서나
독립 정답지라고 주장하지 않는다. 실제 HWP/HWPX fixture와 한컴 PDF 검증은 별도로 유지한다.
기존 테스트와 한컴 근거가 충돌하면 기대값을 기계적으로 보존/갱신하지 말고 원인을 보고한다.

## 3. Stage 3 — 영향 검증과 PR 준비

Stage 2 결과 승인 후 별도 진행한다. 변경 범위에 맞게 [로컬 검증 4.3](../manual/pr_review/local_validation.md)을
적용하고 Docker WASM을 빌드한다. Rust 본문에 새 테스트를 넣지 않고 `tests/cases/` 원본만 제출한다.

PR 준비 시에는 `AGENTS.md`의 파생 suite 준비 → fmt → native Clippy → WASM Clippy →
workspace build → all-targets Clippy → manifest 검사 묶음을 순차 수행한다. generated suite·manifest는
검증 증적이지 제출 소스가 아니다. 전체 회귀 범위와 실제 명령·시간은 Stage 3 보고서에 남긴다.

현재 단계에서 CI 정책 변경, 원격 push·PR 생성, GitHub comment·병합·close는 하지 않는다.

  현재 종료점을 별개로 전달한다. `ParagraphFloatPlacement`가 존재한다는 사실 자체는
  표 아래까지 본문 흐름을 소비했다는 증거가 아니다.
- 텍스트와 같은 줄에서 너비 부족으로 밀려난 표의 줄 점유와, 별도 세로 위치를 가진
  floating 표의 배제 구간을 구분한다. 구분 근거는 실제 줄/개체 배치 결과에 두며
  파일명·표 수·59.96mm 임계값·포맷 이름으로 선택하지 않는다.
- 일반 floating 표는 기존 `visible_float_exclusions`의 순차 흐름을 유지한다.
  표 위에 들어가는 본문은 그대로 배치하고, 표 영역과 충돌하는 시점에만 아래로 진행한다.
  표의 배치 정보만으로 `current_height`·`min_flow_floor`를 선행 상승시키지 않는다.
- 줄 끝 표의 줄 점유를 실제로 소비한 #6950은 승인된 문단 종료·pi=2 빈 줄·pi=3 시작을
  유지한다. 빈 문단 예외를 전역 삭제하거나 표/셀의 페인트만 옮기지 않는다.
- 집중 검증은 #1510 기존7검사와 정답지 쪽수 partition14, 기존 #6950·#6025·#6312·
  #2439·#6797·#6718 보호 검사를 포함한다. 기존 기대값을 완화하지 않는다.
- 두 #1510 샘플의 수정 후 SVG와 #6950 승인 위치 보존 증적을 제시해 시각 판정을 받는다.
  이후 전체 회귀를 진행한다. WASM 교체는 SVG 재판정 이후 별도로 진행한다.
