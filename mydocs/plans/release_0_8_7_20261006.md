## 선행 WMF fuzz 실패

[실패 run 37406380433](https://github.com/edwardkim/rhwp/actions/runs/37406380433)은 main 680111ec7의 WMF 텍스트 간격 뺄셈 overflow다.
원래 main debug에서 같은 패닉을 재현했다. devel에는 #7263의 saturating 방어가 이미 존재한다.
devel debug 및 CI형 ASAN/overflow 활성화 재실행은 패닉 없이 정상 parse error로 종료했다.
잘못된 WMF가 정상 렌더링된다고 주장하지 않는다. 기존 정식 WMF 회귀 검사 2개 통과.
60초 smoke는 61초·91,116 units·peak RSS 636 MB·exit 0으로 완료됐고, 입력 SHA와 원시 로그는 로컬 보안 기록에 남긴다. 새 source/test/기준값 수정은 없다.

## 순서와 남은 작업

1. 로컬 코드/문서 검증, fresh WASM, npm/VSIX dry package, Chrome·Firefox 최종 패키지 및 source 재빌드.
2. 검증 결과와 정확한 head를 제시하고 push·준비 PR 생성 승인. devel에 merge commit 통합 후 source SHA 재고정.
3. main→devel ancestry 및 workflow promotion inventory 확인. 승인된 exact-develop SHA에서 필요한 workflow와 Release Binary tag=test, npm publish=false를 실행한다.
4. 모든 preflight evidence가 같은 SHA로 성공하면 devel→main PR을 준비하고 필수 CI를 확인한다.
5. O4 승인을 받은 exact main release SHA에 v0.8.7 태그를 push한다. CD가 Release와 npm·VS Code·VSX를 게시한다.
6. 자동 Release에 승인된 한국어 notes를 적용하고 채널별 exact version을 조회한다. Chrome·Edge·Firefox는 준비한 파일을 기존 스토어 항목에 제출한다.

0.8.7 배포 준비 통과와 실제 배포 완료를 구분한다. 비공개 advisory/CVE 공개·종료는 별도 절차이며 이 릴리스로 자동 처리하지 않는다.

## 추가로 발견한 릴리스 운영 차단점

로컬 publish 계약 검사에서 현재 버전을 0.8.6으로 고정한 테스트가 실패했다. 버전 형식과 Cargo 원본 대비 모든 manifest·lockfile·현재 사용자 안내의 일치 검사를 유지하며 고정값을 제거했다. 서드파티 라이선스 기준 버전도 갱신했다.

main 대비 inventory에는 5개 workflow 정책 누락과 변경된 CodeQL init의 비고정 action ref가 있었다. CodeQL init/analyze를 GitHub v4 tag의 실제 commit `2892aa5e19bbd11bc0cff5427e3b750a04d9e3c2`로 고정했다. Nextest build/run reusable은 실제 CI의 네 archive build/worker 성공을 요구한다. issue-form-labels·refresh-nextest-duration·trusted-postmerge-ci-reuse는 새 read-only dispatch adapter에서 기존 shipped script와 API 실패 계약을 실행한다. 실제 label/metrics 쓰기 성공은 미검증이며 원격 승인 후에도 adapter는 쓰기를 하지 않는다.

여러 파일이 같은 caller run을 공유하면 collector가 마지막 파일 hash만 보존하던 결함도 재현했다. 두 source hash/mode를 같은 exact run에 연결한 신규 회귀 검사는 수정 전 `1 != 2`로 실패했고, 수정 후 각 hash·mode·verdict를 별도로 보존해 통과했다. gate의 SHA·workflow hash·actor·pagination·필수 job·artifact 요구를 완화하지 않는다.
