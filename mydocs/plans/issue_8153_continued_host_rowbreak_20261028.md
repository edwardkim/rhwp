# 이어받은 앞 문단 뒤 저장 표 원점 검증

`rowbreak-problem-pages.hwpx`의 독립 한컴 PDF는 18쪽이다. 현재 후보는
19쪽이며 8쪽에 짧은 표 조각만 배치한다. `c5383665af` 빌드에서 18쪽,
`68dbcdc78f` 빌드에서 19쪽으로 바뀌며, 두 빌드의 입력과 바이너리 해시를
검증했다. 후자의 편람 314쪽 저장 띠 보정은 유지해야 한다.

앞 문단 20은 7쪽에서 1번 줄부터 이어지지만, 뒤 표의 저장 vpos는 이어받기
전 좌표계를 사용한다. 공통 저장 프레임 조회가 이를 새 쪽의 절대 원점으로
인증하면 96px 흐름 원점이 508.4px로 이동한다. 준비된 원점은
`first_fragment_saved_offset → align_flow_to → 첫 조각 예산 → 배치`에 전달된다.
예산은 약 834px에서 400px로 줄고, 다음 쪽에 18.4px짜리 조각이 추가된다.

같은 표 진입 경로의 기존 방어처럼 현재 쪽의 직전 문단이 이전 쪽에서 이어진
부분 문단이면 저장 좌표를 새 쪽 절대 원점의 증거로 쓰지 않는다. 수용된
부분 문단의 실제 흐름을 사용한다. 이 조건은 문서명이나 특정 수치가 아니라
쪽과 문단 소유에 따른 것이다. 일반 저장 원점과 편람 314·315쪽의 저장 행
프레임은 계속 적용되어야 한다.

현재 기록은 수정 전 분석과 보정 방향이다. 수정 후 `#1488`, `#7902` 및
편람 314·315쪽의 HWP/HWPX 회귀, 정상 대조군, Native/fresh WASM 전쪽과
독립 PDF의 실제 출력 비교는 아직 실행하지 않았다. 검증 전에는 완료로
판정하지 않는다. 실행 로그와 임시 비교는 `output/pr-review/issue8153-handbook-raw100-20261022/`에 둔다.

## 조판과 출력의 원점 공유 후보

집중 검사에서 HWPX가 18쪽이어도 7쪽의 셀 일부를 8쪽으로 넘겼다. 독립
Print에는 해당 셀이 7쪽에 있으며 HWP도 같은 쪽에 배치한다. 출력 경로는
`native_text_frame_first_fragment_saved_top`을 독립 호출해 조판이 거부한 원점을
다시 적용했다. `FragmentBudget`이 실제 수용한 원점을 `PartialTable`에 전달하고
출력은 이를 소비하도록 후보를 작성했다. 이전 생성 경로와 이어받기는 별도로 보존한다.

영어 공백 원본 반각 보정 및 이 원점 공유 후보의 집중 검사·독립 PDF와 Native/fresh
WASM 전쪽 결과는 별도로 확인해야 한다. 아직 수정 후 시각 통과로 판정하지 않는다.

`5dfb2b41` 집중 실행은 중첩 셀 원본 소유·쪽수·기존 완료 페이지·편람 HWP/HWPX
물리 띠를 포함해 35건 PASS다. 저장된 첫 표 프레임이 이어진 앞 문단의 현재 쪽
흐름과 다른 좌표계인 경우 그 저장 프레임으로 첫 조각 컷을 앞당기지 않고,
확정된 원점을 조판과 출력이 함께 소비한다. 이어받기 조각의 저장 프레임은 유지한다.
독립 PDF와 두 출력 경로 전쪽 비교는 미실행이며 회귀 보호와 시각 일치는 구분한다.
