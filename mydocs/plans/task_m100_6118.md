## 1. 배경과 결정

현재 데스크톱의 서식 도구 모음 `#style-bar`는 `글꼴 및 간격`, `글자 모양`, `색`, `문단` 그룹을
제목이 있는 68px 리본으로 표시한다. 이 구조는 좁은 화면을 위한 그룹형 반응형 작업에서 도입됐지만,
넓은 데스크톱에서도 같은 높이가 적용돼 문서 작업 영역을 불필요하게 줄인다.

이 작업은 기존 그룹형 DOM을 과거 마크업으로 되돌리거나 새 밀도 설정을 추가하지 않는다. 대신 현재
자산을 그대로 보존하면서 `1280px` 이상에서만 한컴 2024와 유사한 한 줄 압축형으로 배치한다.

```text
viewport >= 1280px
  현재 DOM·ID·아이콘·명령 연결
    -> 그룹 제목은 시각적으로 감춤
    -> 필드와 명령을 한 줄로 정렬
    -> 서식 바 높이 36px 이하

viewport <= 1279px
  현재 태블릿·모바일 그룹형 반응형 레이아웃 유지
```

따라서 사용자가 선택하는 새 토글은 만들지 않는다. 화면 폭에 따라 자동으로 밀도를 바꾸는 것이 이번
회귀 수정의 제품 계약이다. `#icon-toolbar`의 접기/펴기와 단축키 `Ctrl+F1`은 #6112·PR #6115의 범위로
남기며 이 작업에서는 변경하지 않는다.

## 2. 원인과 기존 자산 재사용

회귀의 기점은 2026-07-24의 `625f7667f` 계열 변경이다. 당시 좁은 화면 개선을 위해 서식 바가
28px 한 줄 구조에서 최소 68px의 제목 포함 그룹 구조로 바뀌었고, 그 기본 규칙이 넓은 데스크톱에도
적용됐다. 선행 계획 #3249가 의도한 데스크톱 한 줄 밀도와 현재 결과가 어긋난다.

## 3. 범위

### 3.1 범위 안

- `1280px` 이상 데스크톱에서 서식 바를 한 줄, 무줄바꿈, 36px 이하로 압축
- 그룹 제목과 필드 제목은 DOM·접근성 연결을 보존한 채 데스크톱에서 시각적으로만 감춤
- 1280px에서도 모든 기존 서식 컨트롤과 드롭다운 진입점 표시
- 현재 그룹 경계를 얇은 구분선과 간격으로 유지
- 1279/1280px 경계와 데스크톱·태블릿·모바일의 자동 회귀 테스트
- 기본·플랫·올드스쿨 스킨 및 라이트·다크 모드의 시각 확인
- 단계 보고서, 최종 보고서와 PR용 대표 스크린샷 근거

### 3.2 범위 밖

- 새 압축/확장 토글, 사용자 설정, 저장소 스키마 또는 테마 설정 변경
- `#icon-toolbar` 접기/펴기, `Ctrl+F1`, #6112·PR #6115 구현 변경
- 메뉴 바·상태 바·문서 렌더러·WASM·HWP/HWPX 파서 변경
- 태블릿·모바일 그룹 순서 또는 터치 크기 재설계
- 현재 DOM을 과거 flat DOM으로 교체하거나 명령 ID를 변경하는 작업
- 한컴 2024의 그래픽 자산 복제

## 4. 단계별 수행계획

### Stage 1 — 회귀 계약과 기준선 고정

1. `625f7667f` 전후의 넓은 데스크톱 높이·배치 차이를 기록한다.
2. 1279px와 1280px에서 현재 서식 바의 높이, 줄 수, overflow, 그룹 제목 표시 상태를 계측한다.
3. 현재 컨트롤 ID·접근성 연결·이벤트 진입점의 보존 목록을 만든다.
4. 결과를 `mydocs/working/task_m100_6118_stage1.md`에 기록하고 다음 단계의 수치 계약을 확정한다.

**종료 게이트**: 넓은 화면 회귀와 좁은 화면 비회귀 조건이 동일한 측정식으로 재현되고, 제품 source는
변경되지 않은 상태다.

### Stage 2 — 데스크톱 압축형 CSS와 회귀 테스트

1. `@media (min-width: 1280px)` 데스크톱 규칙으로 현재 그룹 DOM을 한 줄로 재배치한다.
2. 입력·버튼의 기존 27px 계열 크기를 재사용하고 불필요한 세로 padding·최소 높이만 해제한다.
3. 제목은 시각적으로 감추되 DOM과 label 연결을 유지한다.
4. 정적 계약 테스트를 데스크톱 압축형과 태블릿·모바일 그룹형의 두 계약으로 갱신한다.
5. 기존 반응형 E2E에 1279/1280 경계, 한 줄 여부, 높이, overflow, 컨트롤 가시성 검사를 추가한다.
6. 결과를 `mydocs/working/task_m100_6118_stage2.md`에 기록한다.

**종료 게이트**: 1280px 이상에서 한 줄·36px 이하·무 overflow가 자동 검증되고, 기존 1279px 이하
레이아웃 및 모든 서식 명령 진입점이 유지된다.

### Stage 3 — 브라우저·테마 시각 검증과 제출 준비

1. 1920, 1280, 1279, 1024, 768, 412px의 대표 뷰포트에서 실제 브라우저 동작을 확인한다.
2. 기본·플랫·올드스쿨 스킨의 라이트·다크 데스크톱 조합을 확인한다.
3. 1280px 이상에서 글꼴, 크기, 줄 간격, 글자 모양, 색, 문단 명령이 모두 보이고 클릭 가능한지 확인한다.
4. TypeScript, Studio unit test, build, 반응형 E2E, 포맷·문서 검증을 실행한다.
5. `mydocs/working/task_m100_6118_stage3.md`와 `mydocs/report/task_m100_6118_report.md`에 결과와
   대표 스크린샷을 기록한다.

**종료 게이트**: 기능·반응형·테마 게이트가 모두 통과하고 PR 본문에서 재현 가능한 명령과 근거를
제시할 수 있다.

- [ ] #6112·PR #6115의 `#icon-toolbar` 동작과 `Ctrl+F1` 계약을 변경하지 않는다.
