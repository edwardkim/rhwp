# 수행계획서 — Task #1355: 해설(미주) 세로 여백 누적 → 콘텐츠 오버플로

## 1. 증상 (확인 완료)

해설(미주) 영역에서 문제 헤딩(문30 등) 직전 세로 여백이 한 줄 분량(~30~40px) 과하게
적용되어, 긴 해설 구간에서 **여백이 누적**되며 콘텐츠가 점진적으로 아래로 밀린다.

| 페이지 | 증상 | 측정 (네이티브 SVG vs 한글 2022 PDF) |
|--------|------|--------------------------------------|
| p18 | 문30 헤딩 앞 여백 과다 | `p+q=175` 줄까지 정렬됨 → 문30 앞 여백 PDF 45px **vs 우리 85px (+40px)** |
| p18 | 문24 답안 본문 초과 | +30px 드리프트 누적 → 문24 마지막 줄 본문 하단 ~14px **초과** |
| p21→p22 | 줄 페이지 넘어감 | `(ⅰ)~(ⅲ)에서` 한 줄이 p21→**p22 최상단으로 넘어감** |

- 네이티브 SVG에서 재현 → **공유 레이아웃 문제** (studio 한정 아님)
- **task #1347(단 구분선 sep_y_end)와 무관** — 기존 버그

## 2. 원인 분석 (1차 추정)

`src/renderer/layout.rs`에 미주 문제-제목 앞 "20mm급 미주 사이 간격"을 조건부로 압축하는
로직이 이미 존재한다:

- `endnote_question_number(para)` — 문NN 제목 감지
- `compact_endnote_title_gap_after_single_equation_tail(...)` (line 252~) — 직전 미주 내용이
  **단일 수식 tail**일 때만 20mm 간격을 압축

문30은 직전 내용이 단일 수식이 아니라 텍스트 줄(`p+q=162+13=175`)이므로 이 압축 조건에
걸리지 않아 20mm급 간격이 부분적으로만 줄고 +40px가 남는 것으로 추정된다.

> 미주 trailing/간격은 회귀가 잦은 영역([[tech_trailing_model_no_ssot]],
> [[tech_endnote_tail_backtrack_atomic_vs_text]]). SSOT 부재로 전면 통일은 금지, **조건부 게이트**로 접근.

## 3. 접근 (조사 우선)

1. **근본원인 확정**: 문30 직전 미주 문단(빈 문단/제목)의 vpos·spacing·gap을 계측하여
   한컴 정합 gap(PDF 45px) 대비 우리 gap(85px)의 초과분이 어디서 생기는지 코드 경로로 특정
2. **한컴 정합 기준 수립**: PDF 픽셀 측정으로 정답 gap 산출 (단일 수식 tail이 아닌 일반
   텍스트 tail 뒤 제목 gap)
3. **조건부 보정**: 기존 `compact_endnote_title_gap_*` 게이트를 일반 tail에도 안전하게
   확장하거나 별도 게이트 추가. 전면 통일 금지.
4. **회귀 가드**: p18/p21 외 다른 미주 샘플(단일 수식 tail 케이스 #1302 등) 무영향 확인

## 4. 검증

- p18 문30 앞 gap PDF 45px ±5px 정합, 문24 본문 내 수용
- p21 `(ⅰ)~(ⅲ)에서` p21 잔류 (p22 넘어가지 않음)
- 기존 미주 회귀 테스트 + `cargo test` 전체 통과
- 다른 해설 샘플 시각 회귀 없음

## 5. 위험도

중. 미주 간격은 회귀 빈발 영역. 조건부 게이트 + 다중 샘플 회귀 가드로 관리.
