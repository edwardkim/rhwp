## 조사 결과

### 사용자 배율 입력

- `ZoomDialog.onConfirm()`은 언제나 callback을 실행하고 `void`를 반환한다.
- 빈 문자열은 `Number('') === 0`이 되어 10%로, 유한하지 않은 값은 100%로, 범위 밖 값은 10~500%로
  `clampCustomZoomPercent()`에서 조용히 보정된다.
- 공용 `ModalDialog`는 `onConfirm() === false`이면 창을 유지하는 계약을 이미 제공하며, 문서 저장 암호
  대화상자는 이 계약과 `role="alert"`를 사용하는 선례다.
- 공용 모달의 편집 입력 Enter는 제출하지 않으므로, 입력 안에서 Enter 제출을 검증하려면 대화상자 전용
  capture listener가 필요하다. 같은 패턴은 암호 대화상자에 이미 있다.

### 보기 설정 적용

- 현재 확인 callback은 쪽 이동·쪽 배치를 저장하고 `page-view-settings-changed`를 먼저 발행한 뒤
  `ViewportManager.setZoom()`을 호출한다.
- 첫 이벤트에서 `CanvasView.setPageViewSettings()`가 이전 배율로 `recalcLayout()`과 visible page render를
  시작하고, 뒤의 `zoom-changed`에서 `onZoomChanged()`가 최종 배율로 다시 레이아웃·Canvas 해제·렌더한다.
- `zoom-changed`는 CanvasView뿐 아니라 입력기의 커서·선택 핸들과 눈금자도 소비하므로 이벤트 자체를
  없애거나 최종 레이아웃 뒤에 임의로 미루면 별도 회귀가 생길 수 있다.
- `EventBus.emit()`은 동기 배달이다. 따라서 한 `page-view-settings-changed` transaction 안에서 표준
  `zoom-changed`는 한 번 전달하되, CanvasView 자신의 중첩 zoom handler만 억제하고 transaction method가
  최종 배치·배율로 레이아웃과 렌더를 한 번 수행할 수 있다.
- 사용자 설정은 현재 쪽 이동과 쪽 배치를 각각 저장한다. 두 값을 먼저 정규화해 한 번에 기록하는 API가
  있으면 localStorage에도 중간 조합을 남기지 않는다.

## 목표

1. 사용자 정의 배율을 제출 전에 검증하고 잘못된 입력을 대화상자 안에서 설명한다.
2. invalid 입력에서는 callback·설정 저장·보기 이벤트를 실행하지 않고 대화상자와 입력값을 유지한다.
3. 쪽 배치·쪽 이동·최종 배율·맞춤 모드를 하나의 보기 설정 transaction으로 전달한다.
4. 표준 zoom 이벤트 소비자는 유지하면서 CanvasView의 중간 이전-배율 레이아웃·렌더를 제거한다.
5. 마우스와 키보드 확인·취소, 오류 포커스와 접근성 상태를 실제 브라우저에서 검증한다.

## 범위

### 포함

- 사용자 정의 배율의 빈 값·비숫자·10% 미만·500% 초과 제출 차단
- 정수 백분율 10~500의 정확한 적용과 기존 preset·폭 맞춤·쪽 맞춤 유지
- 오류 메시지, `role="alert"`, `aria-invalid`, `aria-describedby`, 오류 입력 focus/select
- 유효한 값으로 고친 뒤 오류 상태 해제
- 사용자 정의 입력 안의 Enter 제출, Escape·취소 버튼의 무변경 종료
- 쪽 배치·쪽 이동을 한 번 정규화하고 localStorage에 한 번 저장하는 사용자 설정 API
- `page-view-settings-changed` payload에 최종 zoom·fit mode·anchor를 포함하는 transaction 계약
- transaction 중 표준 `zoom-changed`를 한 번 발행하면서 CanvasView의 중첩 zoom layout만 억제
- 최종 배치·배율 기준 `recalcLayout()`·앵커 복원·Canvas 해제·visible render 각 한 경로

## 위험과 완화

| 위험 | 완화 |
| --- | --- |
| 표준 `zoom-changed`를 억제해 눈금자·커서가 갱신되지 않음 | 이벤트는 한 번 그대로 발행하고 CanvasView 자신의 중첩 handler만 동기 guard로 건너뛴다. |
| 배치만 바꾸는 기존 이벤트가 깨짐 | zoom fields를 선택적으로 해석하고 기존 payload는 기존 배치 전환 계약으로 유지한다. |
| transaction 중 예외로 guard가 남음 | guard 설정과 해제를 `try/finally`로 묶고 이후 독립 zoom이 항상 정상 경로를 타게 테스트한다. |
| 같은 배율인데도 Canvas를 불필요하게 해제 | 숫자 배율·토폴로지 변화 여부를 분리하고 실제 해상도 변화 또는 토폴로지 변화일 때만 해제한다. |
| 오류를 고친 뒤에도 스크린리더가 이전 오류를 읽음 | 유효 입력 시 `aria-invalid`와 alert 내용을 함께 초기화하고 연결 ID는 안정적으로 유지한다. |
| Enter handler가 편집기 단축키로 샘 | ModalDialog와 같은 document capture 경계에서 처리하고 hide 시 반드시 제거한다. |
| #6108 범위를 top PR에서 중복 수정 | 맞춤 수학은 건드리지 않고 #6108 resolver의 최종 결과를 transaction payload로 전달한다. |
