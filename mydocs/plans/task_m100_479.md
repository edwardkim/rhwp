## 1. 증상

`samples/21_언어_기출_편집가능본.hwp` 페이지 12 단 0의 23번 paragraph(`pi=251`)가 한컴 PDF 기준 위치보다 약 **200px 아래**(y≈1182px baseline)에 그려짐. 이전 task에서 분석된 layout drift 누적 결과.

## 2. 근본 원인 (재확인)

`RHWP_TYPESET_DRIFT=1` 출력으로 모든 paragraph에서 동일 패턴:

| 케이스 | fmt_total - vpos_h | 원인 |
|--------|---------------------|------|
| 일반 paragraph | **+9.5px** (= trailing_ls) | 마지막 라인의 line_spacing 포함 |
| spacing_after 있는 paragraph | +18.8px (= trailing_ls + sa) | trailing_ls + sa 함께 포함 |

핵심 코드 (`src/renderer/typeset.rs:802`):

```rust
let lines_total: f64 = line_heights.iter().zip(line_spacings.iter())
    .map(|(h, s)| h + s)        // 마지막 line의 ls 까지 포함
    .sum();
let total_height = spacing_before + lines_total + spacing_after;
```

HWP의 vpos 기준은 `(last_vpos + last_lh) - first_vpos = lh_sum + (n-1)*ls` — **trailing line_spacing 미포함**.

각 paragraph가 trailing_ls만큼 부풀려져, 페이지 12 단 0의 17개 paragraph 누적 ≈ **200px drift** → 23번 paragraph 위치 어긋남.

## 3. 이전 작업 컨텍스트 (회귀 이력)

`src/renderer/layout/paragraph_layout.rs:2553` 주석:
> Task #452: 이전 #332 의 layout-only trailing 제외 → pagination 과 1 ls drift 발생 → 회복

**과거에 layout에서만 trailing 제외 시도 → typeset/pagination과 drift → 회귀로 복원**. 따라서 이번 정정은 **typeset과 layout 모두 동시에** 정정해야 한다.

## 4. 수정 방향 비교

| 옵션 | 내용 | 영향 / 리스크 |
|------|------|---------------|
| **A** | typeset + layout 모두 trailing_ls 제외. paragraph height = `lh_sum + (n-1)*ls + sb + sa` (정확한 vpos 기반) | 모든 paragraph 누적 변경. 광범위 회귀 위험. 정답에 가장 가까움 |
| **B** | 단 마지막 paragraph만 trailing_ls 제외 (Task #483 패턴 일반화) | 작은 표면적. 단 중간 paragraph drift는 그대로 |
| **C** | env var opt-in (`RHWP_HANCOM_VPOS=1`) | 안전. 기본 동작 유지. 본 이슈 미해결 |

### 추천: **옵션 A — typeset + layout 동시 정정**

회귀 이력(Task #452)을 고려해 두 모듈을 동기화. 메모리 가이드 [본질 정정 회귀 위험] 따라 광범위 검증 필수.
