# Task #520 수행계획서 — exam_science.hwp 문제7 inline 도형 위치 오류

## 1. 배경

`samples/exam_science.hwp` 페이지 3, 문제 7번의 1×1 표(pi=33) 셀 내부 두 번째 문단(p[1])에 들어 있는 inline 도형(㉠ 사각형, `tac=true`, `wrap=TopAndBottom`)이 자기가 속한 line_seg(`ls[1]`, vpos=3220)이 아니라 **다음 문단 `[탐구 과정 및 결과]`(p[2], vpos=5396) 라인**에 그려져 텍스트와 시각적으로 겹친다.

PDF 정답에서는 `이다.` 줄에 ㉠ 박스가 함께 있고 `[탐구 과정 및 결과]`는 별도 라인이다.

## 2. 목표

inline 도형(`tac=true`)이 자기가 포함된 line_seg 의 baseline 에 정확히 그려지도록 렌더러 좌표 산출을 수정한다. 결과 SVG 가 PDF 와 시각적으로 일치하도록 한다.

## 3. 진행 절차 (간략)

1. 코드 위치 식별: `src/renderer/` 내 inline shape(`treat_as_char=true`) 좌표 산출 루틴, 특히 `wrap=TopAndBottom` 분기 처리 로직.
2. 재현 케이스의 IR 데이터 확인 (`rhwp dump`/`dump-pages`로 line_seg 별 vpos·lh, shape의 anchor 정보 점검).
3. 좌표 계산 수정 — 인라인 shape 의 y 좌표를 자기가 속한 line_seg.vpos + baseline 기반으로 산출.
4. 회귀 테스트: `samples/tac-img-02.hwpx` 등 다른 inline shape 샘플로 회귀 없는지 확인.
5. 빌드/테스트/clippy + SVG 재출력 후 PDF 와 비교.

- 단계별 보고서: `working/task_m100_520_stage{N}.md`

## 5. 영향 범위

- `src/renderer/` 내 inline shape 좌표 산출 코드 (정확한 파일은 구현 계획서에서 확정).
- 다른 inline 도형(수식, 그림 등) 렌더링에 회귀 가능성 있음 → 회귀 샘플 확인 필요.

## 6. 위험 / 미해결 사항

- HWP 의 `tac=true` + `wrap=TopAndBottom` 조합 자체가 모순적인 속성 조합이며, 현재 렌더러가 이 둘 중 어느 쪽을 우선 해석하는지 코드 분기 조사 결과에 따라 수정 방향이 갈린다.
- HWPX 동등 파일이 없어 `ir-diff` 사용 불가 → 시각적 비교(PDF vs SVG)로만 검증.
