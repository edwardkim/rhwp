## 1. 이번 결과물과 경계

**원형을 복사한 뒤 복사본마다 다른 데이터를 채우고, 같은 연산을 native·WASM·CLI·MCP로
호출할 수 있게 한다.** 연구노트의 제목·본문·확인란은 첫 실물 검증 대상이지 하드코딩 조건이 아니다.
고정 양식 채우기, 문단/표 블록 반복, 표 내부 행 반복을 구분해 지원한다.

B의 복사·저장 결과와 원형 보존 계약은 유지한다. Studio에서 Enter 입력 중 뒤 표가
되돌아와 겹치는 [#7065](https://github.com/edwardkim/rhwp/issues/7065)는 이번에도 수정하지 않는다.
다른 문서의 스타일·BinData를 가져오는 D, Gym 시나리오, 원격 push·PR은 C 구현 승인과 별개다.
Gym은 제품 의존성이 아니라 구현 후 사용하는 선택적 검증 도구로 유지한다.

## 3. 채우기 계약

### 3.1. 대상을 먼저 고정한다

- 고정 양식: 요청 시작 시 문서의 소유 경로를 지정한다.
- 복사본: B의 원형 상대 경로와 복사본 번호로 지정한다. 페이지 번호·화면 위치·문서 전체
  표 순번을 식별자로 사용하지 않는다. 경로는 해당 요청의 좌표이지 영구 ID가 아니다.
- 채우기 target은 문단의 명시한 텍스트 범위 또는 닫힌 ClickHere 필드다. 셀은
  `표 경로 + 행/열 앵커 + 셀 문단`을 문단 경로로 해석하는 편의 주소로 제공한다.
  셀 전체를 하나의 문자열로 평탄화하는 것을 기본값으로 하지 않는다.
- 필드 이름 편의 선택은 지정 블록/복사본 범위에서만 해석한다. 동명 필드가 여러 개면
  해당 범위의 명시 occurrence 또는 정확한 경로가 필요하다. 첫 매치 자동 선택 금지.
- 중첩 셀·글상자는 B의 소유 경로로 도달하고 기존 편집 의미를 보존할 수 있는 경우만 허용한다.
  unsupported 경로는 무변경 오류이며 바깥 문단/첫 셀로 fallback하지 않는다.
- 한 요청의 target은 변경 전 구조에서 모두 해석한다. 동일/겹치는 텍스트 범위,
  필드 전체와 내부 텍스트를 동시에 지정한 충돌, 경로 타입 불일치는 적용 전 거부한다.
  길이 변경 때문에 뒤 target이 이동하지 않도록 준비 단계의 대응표를 사용한다.

### 3.2. 데이터와 구조 보존

- 데이터는 JSON 문자열 값의 record 배열과 명시적인 `binding(key → target)`으로 받는다.
  표현식 평가, 임의 script 실행, 파일 경로를 통한 묵시적 데이터 로딩은 추가하지 않는다.
- 누락 key, 빈 문자열, 여분 key를 구분한다. 누락/여분/중복 binding은 기본 오류이며,
  빈 문자열은 **지정 범위의 텍스트만 비우는 명시적 값**이다. 원형 문단 삭제가 아니다.
- 복사+채우기의 record 수가 생성 복사본 수다. 복사만 하는 기존 B `count` API는 유지한다.
  빈 record 배열은 유효 주소·옵션 검사를 거친 무변경 성공이며 기존 내용은 지우지 않는다.
- 문단/글자 서식은 대상 템플릿에서 상속한다. 검정색 강제, 2pt 축소, 줄간격 축소,
  표 크기 고정, 빈 문단 삭제로 산출물을 맞추지 않는다.
  대체 문자열은 지정 범위 시작점의 글자 서식을 상속하며, 범위 밖의 오른쪽 서식을 보존한다.
- 텍스트 offset 단위와 run/field/control anchor 갱신은 기존 편집 의미를 재사용한다.
  한글·보조 평면 문자·결합문자와 줄바꿈을 계약 테스트로 고정한다. 기존 엔진이
  처리하는 줄바꿈 의미를 그대로 사용하고 `\n`을 임의 빈 문단 제거 규칙으로 바꾸지 않는다.
- 표·그림·필드 경계를 가로질러 지우는 범위는 거부한다. 바꾸지 않은 내부 컨트롤,
  원형, 앞뒤 문단, 의도적인 빈 Enter를 보존한다. 형식/참조 보존과 재조판에 따른 위치 이동은 구분한다.
- 이미지 삽입/교체 자체는 C 신규 기능으로 넣지 않는다. 원형의 배경/본문 그림과
  BinData 참조는 복사 과정에서 보존하며, 텍스트만 채우기 위해 그림을 제거하지 않는다.

### 3.3. 원자성과 예산

내부 처리는 `선검증 → 변경 대상만 staging → 채우기·identity/참조 검증 → 단일 반영`이다.
기존 B staging을 재사용하고, 문서 전체 deep clone·JSON 직렬화 왕복이나 clipboard를
트랜잭션 대용으로 쓰지 않는다. 복사 결과 삽입 후 기존 setter를 호출하다 실패하는 방식도 금지한다.

문단 편집의 모델 변경 부분과 reflow/이벤트 부분이 결합된 곳은 최소 helper 추출로 재사용한다.
기존 호출부의 조판 정책을 함께 바꾸지 않는다. 마지막 반영 전 결과/이벤트/소유 데이터의
필요 용량 확보와 모든 복구 가능한 오류 검사를 끝낸다. 실패 시 IR·DocInfo·raw cache·
렌더링 provenance·이벤트·clipboard·커서 상태를 전후 대조한다. OOM/process abort의 복구를 보증하지 않는다.

B 상한(복사 1,000, 추가 문단 10,000, 추가 node 100,000, 깊이 64,
구조 32 MiB, 대응표 8 MiB, 원본 검사 node 1,000,000)을 유지한다.
채운 후 문자열/문단/참조 증가분도 구조 예산에 포함한다. public 요청 JSON은 8 MiB,
binding과 확장 후 편집 target은 각각 최대 10,000으로 제안하며 호출자는 낮출 수만 있다.
native typed 입력도 같은 실제 작업량 상한을 적용한다. 곱셈·덧셈 overflow를 복제 전에 거부한다.
이 상한은 요청 비용의 제한이지 파일 형식 제한이나 process RSS 상한이 아니다.

## 4. 표 내부 행 반복

표 전체 반복과 다른 연산으로 구현한다. 원형의 연속 행 `[startRow,endRow)`을 지정한
행 경계에 복제하며, 각 셀의 모든 문단·서식·내부 컨트롤을 보존하고 새 identity를 부여한다.
행 좌표/row count/cell zone 등 행 구조 참조를 함께 재매핑한다. 기존 표 전체 identity는 유지한다.

- 처음에는 본문 최상위 표에서 완결된 행 묶음만 허용한다. 원형 내부에서 닫힌 가로/세로
  병합은 보존하지만 source 또는 삽입 경계를 가로지르는 병합은 선검증에서 거부한다.
- 제목 행/제목 셀을 데이터 행으로 늘리는 요청과 원형 밖에 걸친 cell zone은 초기 거부한다.
  제목 반복 속성을 지워서 통과시키지 않는다. 지원 제한과 대상 경로를 오류에 표시한다.
- 원형 내부 삽입은 거부하고 앞/뒤 경계는 허용한다. 원형 행과 앞뒤 행의 내용은 보존한다.
- 행 수의 파일 형식 상한, B의 소유 트리·필드/connector 폐쇄성·자원 예산을 검사한다.
  빈 행 생성 API와 identity 갱신을 겹쳐 호출하지 않도록 원형 셀 staging에서 처리한다.
- 중첩 표 내부의 행 증가, 경계 교차 병합의 자동 분해는 이번 초기 공개 계약에서 제외한다.
  블록 안에 중첩 표를 통째로 복사하는 기존 B 지원은 축소하지 않는다.

## 5. 공개 API와 기존 `run` 호환성

- native typed 요청/결과를 정본으로 한다. 명칭안은 `fill_template_native`,
  `repeat_and_fill_paragraph_block_native`, `repeat_and_fill_table_rows_native`다.
  B의 기존 `repeat_paragraph_block_native`는 source/API 호환을 유지한다.
- WASM은 같은 core를 호출하는 options JSON의 얇은 어댑터만 둔다. 요청 해석·예산·오류를
  core와 공유하고 반환에 적용 건수·생성 경로 대응표를 포함한다. native 예외와 JS 예외의
  의미가 다르지 않도록 테스트한다. 새 wrapper의 이름·타입은 소비자 문서와 함께 고정한다.
- `run`에 위 세 동작의 action을 추가하고 기존 `hwp_run_plan`으로 그대로 노출한다.
  기존 네 action·`planVersion:1.0`·조건절·입력 해시 선조건·저장 검증의 계약은 바꾸지 않는다.
  계획 스키마 판번호는 추가 변경에 맞춰 minor 증가시키되 봉투 버전과 혼동하지 않는다.
- **초기 구조 action은 계획 안에서 단독 step으로만 허용한다.** 복사와 모든 record 채우기는
  그 한 step 안에서 원자 수행한다. 기존 네 action과 섞어서 occurrence가 밀리는 계획이나
  복수 구조 step은 `invalid[]`로 거부하고 단독 복합 action 또는 저장 결과를 입력으로 하는
  다음 계획을 안내한다. 기존 네 action만 있는 다중 step 계획은 그대로 지원한다.
  이는 주소 재해석을 추측하지 않기 위한 명시적 제한이며, 범용 다중 영역 레시피는 D에서 검토한다.
- 새 `fill_template` 역시 초기에는 단독 step으로 제공한다. 고정 양식의 여러 target은
  한 요청 안에서 함께 채운다. 기존 `fill_fields` 등의 기본값/모호성 의미를 몰래 strict로 바꾸지 않는다.
- 새 action의 dry-run은 core의 동일 준비/검증 경로를 실행하되 반영·저장은 하지 않는다.
  복사 예정 대상과 비용을 보고하며 실물 조판 통과라고 쓰지 않는다. 잘못된 target들은
  가능한 범위에서 함께 보고하고 의존 실패는 파생 오류로 구분한다.
- 정상/실패/dry-run 봉투, `untrustedContent` 출처 표지, `changedPages` 미확정 시 null,
  capabilities·MCP 설명·schema를 함께 갱신한다. MCP 세션 전용 복제 엔진은 추가하지 않는다.
- 반복은 멱등 연산이 아니다. 같은 요청 재호출은 다시 추가한다. 입력 SHA 선조건으로
  다른 입력을 막는 것과 영구 request ID 중복 실행 방지를 구분해 문서화한다.
