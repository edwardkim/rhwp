# #7642 직접 논리 기호와 붙은 명시적 공간의 항 소유

## 독립 근거와 반례

15cb5e6f60의 원본 11월 15쪽은 Native 99.40525%로 개선됐지만, 직접 Unicode
∴는 Text 토큰으로 남아 명령형과 다른 폭을 쓴다. 명령형/Unicode를 함께 넣은
독립 Print 대조군의 해당 행에서 차이를 확인했다. 인용 문자열은 일반 문자로
유지하며 기호 앞뒤의 한글·그리스 문자를 기호에 흡수하지 않아야 한다.

원래 대조군의 중괄호 없는 연속 분수도 여전히 다르다. ∴가 분자 밖에 남아
Native 최저 82.72387%다. 원본과 실패 증거를 보존했다. 분수를 각각 묶은
다른 대조군의 95.50959%를 이 원본의 해결로 보고하지 않는다.

별도 48개 입력을 두 face·두 크기로 생성하고 한컴 2024에서 정상 저장·Print했다.
생성 입력과 한컴 저장본을 구분한다. `explicit-space-terms`의 Save job은
`8c84a89e-2564-4f64-94c3-147a97750211`이다. 상태·Print job·원본 해시는 ignored
stage2227, 정상 저장 속성과 독립 PDF의 글리프 원점은 stage2228에 기록했다.

| 입력 경계 | 독립 Print의 앞 항 소유 |
|---|---|
| `THEREFORE~q over p`, `a~b over c` | 앞 기호/변수와 뒤 변수가 같은 분자 |
| `THEREFORE ~ q`, `THEREFORE ~q`, `THEREFORE~ q` | 앞 기호는 분수 밖 |
| 붙은 얇은 공백 또는 띄운 얇은 공백 | 앞 기호는 분수 밖 |
| `THEREFORE~{q} over {p}`, `a~{b} over {c}` | 명시한 중괄호가 분자 경계 |
| 선행 `~q over p`, `~ q over p` | 선행 공간은 분수 밖 |

붙은 normal `~`까지 무조건 항 종료로 취급한 가정이 틀렸다. 한컴의 일반 공백
경계·얇은 공백·행/칸 구분·명시적 그룹을 합쳐 없애는 보정도 이 반례와 맞지 않는다.

## 생산·소비와 검증

직접 ∴·∵를 명령형과 같은 MathSymbol로 전달하고 인접 문자를 보존한다.
`parser_terms::has_term_continuation`은 앞 항에 붙은 `~`를 그 항 안에 포함한다.
기존 일반 공백/그룹 경계와 선행 공간·얇은 공간·행/칸 경계는 유지한다.
토큰 → document 항 Row → OVER 분자 소유 → 공통 수식 레이아웃 → 최종 paint를
대조한다. LaTeX 호환 파서의 기존 항 수집 계약은 바꾸지 않는다.

두 원래 기호 대조군과 항 경계 48식, 원본 시험지의 Native/fresh WASM 전체
쪽을 같은 PDF로 비교한다. 직접 기호·인용 문자열·인접 문자·명시적 공백·분자
소유와 나머지 항 보존을 확인한다. 정상 대조군과 현재 93개 항목의 검증도
유지한다. 새 정식 렌더링 회귀는 양쪽 전쪽 90%와 확대 판독 뒤 새 이름으로
추가한다. 기존 실패를 통과시키기 위해 golden이나 좌표 핀을 먼저 바꾸지 않는다.
