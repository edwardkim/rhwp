# #7642 본문 수식 정렬 검사의 유효 입력 보정

Issue: #7642

## 독립 근거와 변경 범위

기존 `issue_5583_body_equation_alignment.rs`는 기본 Section의 0×0 용지와
임의의 19094×4333 HWPUNIT 수식 상자를 사용했다. 한컴 정상 저장본도 용지가
0×0이고 원본 Print는 실패한다. 이 입력의 비정상 상태를 보존하며 renderer의
저장 줄 수용 조건을 완화하지 않는다.

A4 용지·본문 너비를 명시한 대조군에 한컴 정상 저장으로 확인한 HYhwpEQ,
Equation Version 60, 1376×2340 HWPUNIT 크기와 줄 메트릭을 반영했다.
수식 내용·가운데 정렬·원래 column_start 0/6000·segment_width는 유지했다.
둘을 각각 MCP engine 2020의 실제 Print로 출력했다. 두 PDF의 분수 원점이
동일하며, 원래 검사처럼 column_start가 양수라는 이유만으로 비가운데 정렬을
요구할 수 없다. 이 대조는 정상 저장 LineSeg 전체의 권위를 부정하지 않는다.

## 선행 검증과 구현

code cc4255a58d8112c07013e89eda1b1a065c824fea의 stage2291 Native와
stage2292 fresh WASM에서 두 대조군은 각각 전쪽 raw 100%, 1쪽 일치다.
stage2294의 같은 영역 review·overlay에서 가운데 배치, 숫자 모양·순서와
분수선을 확인했다. 분수선 끝·분모 래스터 경계 차이는 남아 있으며 RGB 동일을
주장하지 않는다.

기존 잘못된 합성 검사 대신 새 파일·새 함수 이름으로 검증한 fixture를 읽는다.
원본 수식 소유·쪽수·분자/분모 보존, 본문 내 포함과 가운데 관계를 확인한다.
독립 PDF 숫자 원점을 ±2px로 추가 보호한다. 소유 대상을 좌표로 검색하지 않는다.
기존 원본·변경 절차와 Print 메타데이터는 fixture 설명에 연결한다.

실행 중인 논리 기호 수정 전/후 검사가 공용 target을 반환하면 이 정렬 검사를
같은 target에서 순차 실행한다. 실제 결과를 기록하기 전에는 통과로 보고하지 않는다.
