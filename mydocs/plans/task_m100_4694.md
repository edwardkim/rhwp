## 1. 배경

B1 엔진(#4100)으로 rhwp 는 차트를 **고칠** 수 있게 됐지만 그 표면은 코어 JSON API 와 CLI CSV
왕복뿐이다. studio 사용자는 차트를 선택·이동·복붙할 수 있어도(#3682) **값을 바꿀 수 없다** —
`src/wasm_api.rs`(export 432곳)에 chart export 는 0건이고, studio 는 ole 개체를
`PicturePropsDialog` 의 "도형"으로만 다룬다(`picture-props-dialog.ts:46` `OLE_TAB_NAMES`).

이 작업은 그 간극을 4층으로 배선한다. **편집 로직·검증·캐시 무효화는 전부 코어에 이미 있으므로
(`chart.rs:627-636`), 이 작업은 로직을 새로 만들지 않고 통로만 만든다.**

```
wasm_api export 5종 → wasm-bridge 위임 → 신규 ChartDataDialog → 커맨드/컨텍스트 메뉴/더블클릭
```

v1.0.0 의 서사("한컴 없이 한글 문서를 편집하세요", `branding_strategy.md:140`)에서 엔진만 있고
UI 가 없는 차트 편집은 미완이다 — 이 작업이 그 간극을 닫는다.

## 4. 설계

### 4-1. 주소 — 정본(by_index) 단일 경로

studio 는 항상 `listCharts()` 열거 → 선택 ref 대조 → `get/setChartDataByIndex(index)`.
3인자 export 도 함께 내되(코어·CLI 와 표면 대칭, embed 소비자용) studio 는 쓰지 않는다.

- 근거: (a) 코어가 by_index 를 정본으로 명시, (b) 본문 직속/표 셀/글상자/머리말을 컨테이너별
  분기 없이 한 매칭 함수로 처리, (c) 3인자도 내부에서 전수 열거라 비용 동일
- `matchChartRef(charts, ref)` — studio 순수 함수(신규 `src/core/chart-data-target.ts`):
  - 본문 직속: `container` 없음 ∧ `section===sec ∧ paragraph===ppi ∧ control===ci`
  - 표 셀: `ref.cellPath[k] ↔ container[k]{kind:'tableCell', control, cell, paragraph}` 전
    원소 일치 ∧ 말단 `paragraph===ppi ∧ control===ci`
  - 머리말/꼬리말: `container===[{kind, control: headerFooter.outerControlIdx,
    paragraph: headerFooter.outerParaIdx}]` ∧ 말단 일치
  - **매칭 실패 = 메뉴 미노출**(안전 축소). 오매칭으로 다른 차트를 고치는 것이 최악이다
- index 드리프트: 다이얼로그가 열려 있는 동안 문서가 바뀔 수 있으므로 **쓰기 직전 operation
  클로저 안에서 재열거·재대조**한다. 재대조 실패 시 무기록 + 사용자 안내

### 4-2. WASM — 캐스팅+위임만, 테스트할 것이 없게

코어에 `list_charts_native() -> Result<String, HwpError>` 를 추가해 **열거 계약을 cargo
테스트로 고정**하고, wasm 층은 얇게 둔다(picture 선례 관례 그대로). wasm 층 검증은
`wasm-pack build`(컴파일 게이트) + e2e 실브라우저.

Export 5종: `listCharts()` · `getChartData(sec,para,ci)` · `setChartData(sec,para,ci,editsJson)`
· `getChartDataByIndex(index)` · `setChartDataByIndex(index,editsJson)`

### 4-3. ChartDataDialog — 코어 검증기를 단일 진실로 하는 3층 검증

`ChartDataDialog extends ModalDialog`(`field-edit-dialog.ts` 최단순 패턴). 그리드는 HTML
table: 헤더행 = 라벨 열 제목 + **계열명(비활성, title="계열 이름 변경은 다음 단계(B2)에서
지원")**, 행 = 포인트, 셀 = `<input inputmode="decimal">`. **행·열 추가/삭제 버튼 없음**(부재
자체가 B2 경계 표시) + 하단 안내문 1줄.

- 라벨 열: `axis==='scatter' ∧ labelsShared ∧ !labelsMultiLevel` 일 때만 편집 가능(코어가
  분산형에서만 labels 를 기록·비공유는 `sharedXRequired` 거부 — 계약과 동형). category 는
  read-only + 툴팁
- 빈 값 셀(원본 `""`, `<c:v/>`): disabled + 툴팁 — 코어 `valueNotPatchable` 거부의 선제 반영
- 검증 3층:
  1. **입력시**: 숫자 검사(비어 있지 않은 유한 float) — 위반 셀 표시 + [확인] 비활성
  2. **[확인] 시 dryRun**: `setChartDataByIndex(index, {…, dryRun:true})` — `ok:false` 면
     `invalid[]` 표시하고 **닫지 않음**(코어 검증기가 단일 진실, UI 검증은 UX 용 선제일 뿐).
     `changedCount===0` 이면 **쓰기·undo 기록 없이** 닫음(무편집 무흔적)
  3. **실쓰기**: `executeOperation({kind:'snapshot', operationType:'objectProps', operation})`
     안에서 재열거→`setChartDataByIndex`
- **페이로드 규칙**: 전 셀의 현재 문자열을 **원본 그대로**(trim·normalize 금지) 전송 — 코어가
  문자열 diff 로 미변경 셀을 무기록 처리하므로 표기(`4.3` vs `4.30`)가 보존된다.
  `series[].name` 은 **보내지 않는다**(대조 스킵 — `c:tx` 부재/빈 문자열 함정 회피). labels 는
  분산형에서 실제 편집됐을 때만 포함
- CSS: `src/styles/chart-data-dialog.css` 신규, 접두어 `chart-data-` →
  `mydocs/manual/rhwp_studio_ui_conventions.md` 접두어 표 갱신(**규칙 문서 `:32-33` 의 의무**)

### 4-4. 배선

- 커맨드 `insert:chart-data-edit`(`insert.ts`, `insert:equation-edit` 선례): `opensDialog:
  true`, `canExecute` = 차트 ole 선택 상태
- 컨텍스트 메뉴(`input-handler.ts:1736-1742` equation 분기 옆): `ref?.type==='ole'` ∧
  `listCharts()`+매칭 성공 → "차트 데이터 편집...". 판정은 우클릭당 1회, 캐시 없음(차트 수 소수)
- 더블클릭: 차트 ole 더블클릭 → `insert:chart-data-edit` dispatch(수식 더블클릭 선례).
  **한컴 UX(차트 더블클릭 → 데이터 편집)와 동형이라 포함하되, 범위 이견이 있으면 승인 시점에
  제외 지시를 따른다**
- 하지 않는 것: 전용 단축키(한컴에도 없음), `PicturePropsDialog` 진입 버튼(수식과 달리 별도
  속성 다이얼로그가 없어 구조가 다름 — 필요 시 후속)

### 4-5. 한컴 판정 — 재판정 불필요

쓰기 경로가 엔진 `set_chart_data_*` 와 동일 바이트(①② 동시 기록, 이 작업의 재포장 로직 추가
0줄)이고 #4603 에서 7종 전건 판정 완료. e2e 산출물 1건을 한컴에서 수동 오픈하는 스팟체크만
선택 항목으로 남긴다(작업지시자 판단).
