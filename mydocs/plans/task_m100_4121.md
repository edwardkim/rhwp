## 2. 문제 요약

머리말/꼬리말 편집 모드에는 캐럿과 단일 문자 삽입·삭제가 있지만 텍스트 선택 계약이
없다. 마우스 드래그와 `Shift+방향키`가 선택 범위를 만들지 못하고, 선택 강조 표시·범위
삭제·부분 글자 서식·복사/잘라내기 경로도 머리말/꼬리말 문맥으로 라우팅되지 않는다.

이슈에서 지목한 `getSelectionRectsInHeaderFooter` 부재는 첫 결손이 맞지만, 최신 `devel`
코드를 대조한 결과 API 하나만 추가해서는 이슈를 닫을 수 없다.

```text
코어/WASM: 머리말/꼬리말 선택 사각형·범위 글자 서식·범위 복사 API 없음
Cursor:     hfAnchor 및 정렬된 HF 선택 범위 없음
Mouse:      HF 클릭이 선택 드래그 수명주기를 시작하지 않음
Keyboard:   HF 이동 분기가 Shift 선택을 처리하지 않음
Consumer:   선택 렌더·삭제·입력 치환·서식·copy/cut이 본문/각주 경로로만 연결됨
```

따라서 이번 작업은 “선택이 보인다”에 그치지 않고 선택을 실제 편집 동작이 소비하는
상태까지 완성해야 한다.

## 3. 확인된 기존 자산

- `get_cursor_rect_in_header_footer_native`와 `hit_test_in_header_footer_native`가
  머리말/꼬리말 문단 마커(`usize::MAX - hf_para_idx`)를 이미 해석한다.
- `get_selection_rects_in_footnote_native`가 다문단 선택 사각형 계산의 가까운 기준이다.
- `insertTextInHeaderFooter`, `deleteTextInHeaderFooter`, 문단 분할·병합 API와 각각의
  undo/redo 커맨드가 있다.
- 머리말/꼬리말 문단 서식은 `applyParaFormatInHf`와 서브모드 스냅샷 경로가 이미 있다.
- 본문/셀 선택에는 다문단 복사, 범위 서식, 삭제 및 undo/redo 선례가 있다.

기존 단일 문단 삭제 API는 선택의 한 조각을 지울 수 있지만, 문단 경계를 넘는 선택을
원자적으로 삭제·복원하지는 못한다. 부분 글자 서식과 선택 복사 역시 머리말/꼬리말 전용
코어 경로가 현재 없다.

## 4. 설계 결정

### 4.1 선택은 HF 정의에 귀속되고, 사각형은 페이지별로 조회한다

2026-08-28 한글 2024 VDI 실측에서 다음 동작을 확인했다.

```text
1. 마우스·Shift 선택 직후에는 편집 중인 페이지에만 강조가 보였다.
2. 선택을 유지한 채 화면 밖 페이지로 스크롤하면 새로 보이는 같은 머리말에도 강조가 생겼다.
3. 다시 원래 페이지로 돌아오면 이전에 강조되지 않았던 반복 페이지도 강조됐다.
4. 네 페이지를 계속 한 화면에 둔 경우에는 다른 페이지가 다시 그려지지 않아 활성 페이지만
   강조된 것처럼 남았다.
5. 글자 서식 적용 또는 Ctrl+Z처럼 페이지를 다시 그리는 동작 뒤에는 같은 HF 정의가 보이는
   다른 페이지에도 동일한 선택 강조가 나타났다.
6. 짝수 쪽 머리말은 편집 표면과 같은 짝수 쪽 반복 인스턴스에 같은 선택·편집 결과가 적용됐다.
```

따라서 선택 상태는 `preferred_page` 한 쪽에 귀속되지 않고
`sectionIdx + isHeader + applyTo + HF control identity + range`에 귀속된다. 각 페이지는 같은
논리 선택을 자기 `Header`/`Footer` 렌더 노드에 투영한다.

강조 표시 후보는 `preferred_page` 편집 표면과, 현재 렌더 페이지 중 resolved HF target이
같은 페이지의 합집합이다. 따라서 홀짝 전용 HF도 현재 편집 표면에는 표시되고, 실제 적용
대상인 같은 홀짝 페이지들에도 같은 선택이 투영된다.

코어 API는 문서 전체 페이지를 한꺼번에 강제 레이아웃하지 않고 `page_num` 하나의 사각형을
반환하는 페이지 지역 primitive로 둔다. Studio가 현재 렌더된 페이지 중 활성 HF 정의가
일치하는 페이지마다 이를 호출하고, 스크롤로 새 페이지가 렌더될 때도 유지 중인 선택을
다시 투영한다.

### 4.2 상호작용 표면은 페이지 사이를 이동하고, 선택 의미는 HF 정의 전체다

`preferred_page`는 현재 캐럿·hit-test·마우스 드래그를 받는 편집 표면을 나타낸다. 사용자가
다른 페이지에 투영된 같은 HF 정의를 클릭하면 일반 텍스트 클릭처럼 기존 선택을 해제하고
그 페이지를 새 `preferred_page`로 삼아 같은 논리 HF 정의를 계속 편집한다.

본문 클릭은 현재 동작대로 HF 선택과 편집 모드를 끝내고 해당 본문 위치로 이동한다. 일반
`Esc`는 선택이 있으면 선택만 해제하고 HF 모드를 유지하며, 선택이 없으면 HF 모드를
종료한다. 상단 도구의 닫기 버튼과 `Shift+Esc`는 선택 유무와 관계없이 HF 모드를 종료한다.
한글 2024의 클릭 차단과 고정 포커스는 rhwp의 필수 호환 계약으로 채택하지 않는다.

앵커와 캐럿은 같은 `sectionIdx`, `isHeader`, `applyTo`, HF control identity 안에서만
유효하다. 본문↔머리말, 머리말↔꼬리말, 서로 다른 적용 범위 사이의 교차 선택은 만들지
않는다.

### 4.3 문단 경계 선택도 1급 동작으로 처리한다

단일 문단만 지원하면 마우스 드래그가 다음 문단에서 깨지고 표준 편집 동작이 서로
달라진다. 같은 머리말/꼬리말 안의 다문단 범위에 대해 강조 표시, 삭제, 입력/붙여넣기
치환, 부분 글자 서식, 복사/잘라내기와 undo/redo를 함께 검증한다.

### 4.4 한글 2024의 지연 다시 그리기 현상은 복제하지 않는다

한글 2024에서 이미 화면에 보이는 다른 반복 페이지가 선택 직후 갱신되지 않는 현상은
선택 의미가 아니라 페이지별 invalidation 시점의 차이다. rhwp는 같은 논리 선택을 가진
현재 렌더 페이지를 즉시 함께 갱신하고, 화면 밖 페이지는 화면에 들어올 때 선택을 그린다.
즉 관찰된 선택 범위·대상·스크롤 후 지속성은 맞추되 stale highlight를 의도적으로 재현하지
않는다.

## 5. 작업 범위

이번 이슈의 필수 범위:

- 페이지별 머리말/꼬리말 선택 사각형 native/WASM/Studio API 추가
- `hfAnchor`, 정렬된 HF 선택 범위, 선택 초기화·문맥 전환 규칙 추가
- 반복 페이지 클릭 시 `preferred_page` 전환과 `Esc`의 선택 취소/모드 종료 2단계 처리
- 마우스 클릭-드래그-해제와 드래그 자동 스크롤을 HF hit-test에 연결
- `Shift+Left/Right/Home/End` 및 지원되는 수직 이동의 선택 확장/축소 연결
- 편집 표면과 같은 HF 정의가 렌더된 페이지의 단일/다문단 선택 강조 표시
- 스크롤·확대/축소·undo/redo·서식 변경 뒤에도 반복 페이지에 선택 재투영
- 선택 범위 삭제, 입력·붙여넣기 치환, 복사·잘라내기
- 선택 범위 부분 글자 서식과 캐럿 글자 속성 조회
- 모든 변경 동작의 undo/redo, HF 편집 문맥·캐럿·선택 정합성
- `Both`/`Odd`/`Even`, 머리말/꼬리말 양쪽의 회귀 검증

이번 이슈의 비범위:

- 본문과 머리말/꼬리말 사이의 교차 선택
- 서로 다른 머리말/꼬리말 또는 적용 범위 사이의 교차 선택
- 머리말/꼬리말 내부 표·그림·개체의 블록 선택 확장
- 화면 밖 모든 페이지의 렌더 트리를 선택 때문에 선행 생성하는 eager 전수 레이아웃
- 각주 선택 동작의 독립적인 기능 확장(공유 로직 회귀가 확인되면 별도 이슈로 분리)
- OS별 서식 보존 클립보드 전체 재설계
- 한글 2024의 머리말/꼬리말 생성·편집 대화상자와 모양 갤러리 UI 복제

## 7. 구현 방향 후보

### 후보 A — 이슈에 적힌 최소 미러링

선택 사각형 API와 `hfAnchor`, 마우스·키보드 배선만 추가하고 기존 단일 문단 삭제를
연결한다.

장점은 변경량이 작다는 점이지만 다문단 삭제, 부분 서식, copy/cut, 입력 치환이 남아
선택은 보여도 정상 편집이 되지 않는다. 이 상태로는 이슈의 증상과 확인하지 못한 항목을
모두 해소했다고 판단하기 어렵다.

### 후보 B — 머리말/꼬리말 선택 계약 완성(기본안)

선택 상태와 기하부터 모든 표준 소비자까지 한 수직 경로로 구현한다. 다문단 범위 편집은
전용 코어 연산 또는 HF 문맥을 보존하는 원자적 커맨드로 묶고, undo/redo까지 같은 PR에서
고정한다.

변경 표면은 더 넓지만 테스트 가능한 완료 경계가 분명하고, 후속 PR에서 선택 상태 계약을
다시 바꾸는 중복을 피할 수 있다.

### 후보 C — 코어가 모든 반복 페이지의 사각형을 한 번에 반환

선택 API가 적용 대상인 문서 전체 페이지의 사각형을 반환하고 Studio가 필터링한다.

한글 2024 실측처럼 반복 페이지에 같은 선택을 표시할 수는 있지만 화면 밖 페이지까지
선택 때문에 강제 레이아웃할 수 있다. 페이지 지역 API를 현재 렌더 페이지별로 호출하는
후보 B가 같은 의미를 더 낮은 비용으로 만족하므로 채택하지 않는다.

## 8. 기본 수행 순서

Hyper-Waterfall 구현계획은 승인 후 4단계로 구체화한다.

```text
Stage 1: RED 계약 + 페이지 지역 HF 선택 기하 API
Stage 2: Cursor 앵커 + 마우스/키보드 선택 + 반복 페이지 강조 표시
Stage 3: 삭제·입력 치환·부분 서식·copy/cut + undo/redo
Stage 4: Rust/Studio/WASM/실브라우저 회귀 검증과 최종 보고
```

각 Stage는 다음 Stage 전에 코드·테스트·완료보고서를 함께 검토하고 커밋한다. 구현 중
공개 API 또는 완료 범위를 바꿔야 하면 수행계획/구현계획을 먼저 갱신해 재승인받는다.

```text
   렌더 페이지에 강조가 보인다.
2. Shift+방향키/Home/End가 선택을 확장·축소하고 Shift 없이 이동하면 선택이 해제된다.
3. Backspace/Delete/typing/paste가 선택 범위를 정확히 한 번 치환한다.
4. 부분 글자 서식이 선택 범위에만 적용되고 레이아웃이 즉시 갱신된다.
5. copy/cut의 평문과 내부 클립보드 내용이 선택 범위와 일치한다.
6. undo/redo 후에도 HF 대상, 캐럿, 선택, 내용, 문단·글자 서식이 왕복한다.
7. 화면 밖 반복 페이지는 스크롤로 렌더되는 즉시 같은 선택을 표시한다.
8. 다른 HF 정의와 적용 대상이 다른 홀짝 페이지에는 선택 강조가 생기지 않는다.
9. 같은 HF 정의가 투영된 다른 페이지를 클릭하면 기존 선택이 해제되고 그 페이지가 새
   편집 표면이 되며, 본문 클릭은 HF 모드를 종료하고 클릭한 본문 위치로 이동한다.
10. 선택이 있는 상태의 Esc는 선택만 해제하고, 선택이 없는 상태의 Esc와 Shift+Esc·상단
    닫기 버튼은 HF 모드를 종료한다.
```
