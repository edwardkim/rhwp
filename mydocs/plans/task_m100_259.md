# Task #259 수행 계획서 — HY 계열 한글 폰트명 → 메트릭 DB 영문명 매핑 누락

- 브랜치: `local/task259`

- 재현 샘플: `samples/text-align.hwp` 4번 문단(s0:pi=4)

## 1. 배경 및 문제 정의

웹 에디터에서 `text-align.hwp` 4번 문단의 HY중고딕 텍스트가 **글자 폭 오류로 겹쳐 보임**. 작업지시자 시각 확인으로 식별 (2026-04-23).

### 현상

- 문단 예: "또점고창시춘시창시대전천시이산시전주시목포시경주시창시제주시제주하"
- 글자 폭이 기본값(fallback)으로 계산되어 후속 글자가 앞 글자와 겹침

### 원인 (2단 정규화 경로의 중간 끊어짐)

HWP 폰트명 → 메트릭 DB 조회는 두 단계를 거친다:

1. **한국어 별칭 → 한국어 정규명**: `src/renderer/style_resolver.rs`
   - 예: `한양중고딕`, `신명 중고딕` → `HY중고딕` (line 467, 478)
   - HY 계열 정규명 7종 사용: `HY중고딕`, `HY견고딕`, `HY헤드라인M`, `HY견명조`, `HY신명조`, `HY그래픽`, `HY궁서`

2. **한국어 정규명 → 메트릭 DB 영문명**: `src/renderer/font_metrics_data.rs::resolve_metric_alias` (line 72-96)
   - 함초롬/나눔/맑은고딕 등은 매핑 존재
   - **HY 계열 매핑 전무** → 정규명이 그대로 `"HY중고딕"` 반환
   - `FONT_METRICS` 배열은 영문명(`HYGothic-Medium` 등)으로 저장 → 미스매치
   - `find_metric` 이 `None` 반환 → 호출부가 기본 폭 적용 → 겹침

## 2. 목표

`style_resolver.rs` 가 출력하는 HY 한글 정규명 7종 모두를 `resolve_metric_alias` 가 메트릭 DB의 영문명으로 매핑하여, **HY 계열 폰트의 글자 폭이 DB 메트릭 기반으로 계산**되도록 한다.

## 3. 범위

### 포함

- `resolve_metric_alias` 에 HY 한글 정규명 → 영문 매핑 7종 추가
- 단위 테스트 (각 HY 정규명에 대해 `find_metric` 이 `Some` 반환)
- `text-align.hwp` 회귀 검증 (SVG 스냅샷 + 웹 에디터 시각 확인)
- 타 HY 계열 샘플 스모크 검증

### 제외

- 메트릭 DB 추가/수정 (기존 엔트리 재사용만)
- `style_resolver.rs` 수정 (이미 정상)
- Fault tolerance / Bold variant 폴백 구조 변경

## 4. 매핑안 (Stage 1 에서 확정)

| HWP 한글 정규명 | 메트릭 DB 영문명 (잠정) | 근거 |
|---|---|---|
| `HY중고딕` | `HYGothic-Medium` | 한컴 PostScript name 관례 (Gothic-Medium = 중고딕) |
| `HY견고딕` | `HYGothic-Extra` | Extra = 견 (굵은) |
| `HY헤드라인M` | `HYHeadLine-Medium` | 직역 |
| `HY견명조` | `HYMyeongJo-Extra` | Extra = 견 |
| `HY신명조` | `HYSinMyeongJo-Medium` | 직역 |
| `HY그래픽` | `HYGraphic-Medium` | 직역 |
| `HY궁서` | `HYGungSo-Bold` | 한컴 궁서는 Bold weight 단일 |

> Stage 1 에서 원본 TTF PostScript name 또는 실측 비교로 최종 확정.
