## 1단계: 선언 잔여 중복과 행 합산 경계 보정

확정된 일반 셀의 연결 구간에서 선언·내용 요구를 함께 풀도록 공통 helper를 보정했다.
측정기와 fallback이 같은 helper를 호출한다. 미지 행, 독립 저장 reset, 세로쓰기·개체가
있는 구간은 이 새 계산의 근거로 사용하지 않는다. 19쪽의 실제 측정 구간은
414.72→396.08px, 끝 행은 47.093333→28.453333px가 됐고 Native raw는
72.89079→100%다. review/overlay에서 병합 라벨·내부 괘선·입찰계약의 하단을 직접 확인했다.

25쪽의 마지막 행은 누적 합 888.00000000000045475px와 예산 888px를 비교해 밀리고 있었다.
이미 블록 스캔에서 사용하는 방식대로 행 스캔도 누적 연산 규모의 f64 오차만 구분한다.
이 사례의 오차 상한은 0.00000000001301359px이며 HU/px 여유나 시각 문턱을 늘리지 않았다.
실제 저장 행 소속은 25쪽 끝 30→31, 26쪽 끝 57→58로 바뀌었다(끝 행은 exclusive).
Native 26쪽은 65.74957→96.64273%, 27쪽은 62.91973→98.40958%로 개선됐다.

첫 보정과 합산 경계 보정을 각각 포함한 기존 Native 집중 검사 43건을 최소 글꼴 환경에서
실행해 두 번 모두 43 PASS를 확인했다. 새 검사는 아직 추가하지 않았다. 현재 Native 집중
11쪽 중 19·25·26·27·29·75쪽은 90% 이상이지만 30·31·32·33·76쪽은 미달이다.
같은 새 source의 fresh WASM·전103쪽·전체 회귀와 필수 3종은 아직 재실행 전이며,
과거 #7642의 전체 통과를 이 후보의 결과로 재인용하지 않는다.

76쪽에서는 원문 문단 131의 부동 표만 다음 쪽으로 이월되는데, 뒤 inline 표 앞의 호스트 줄
32px까지 이월돼 다음 표가 앞당겨지는 현상을 확인했다. 저장 줄 사다리는 문단 131의

나머지 30–33쪽의 측정·조각 행 상자 차이도 계속 추적한다.

## 2단계 진행: 빈 호스트 줄과 조각 내용 하한

저장 사다리로 뒤 inline 표의 시작이 호스트 줄 다음임을 인증한 이월 계획에서도,
빈 호스트 줄을 현재 쪽에서 한 번 소비하도록 보정했다. Native 전103쪽을 끝까지

367.7→399.7px가 됐고, 문단 131의 부동 표는 77쪽을 유지한다. 호스트 줄의 중복은 없다.
이 중간 후보의 남은 미달은 30·31·32·33쪽 네 개다.

같은 전103쪽 render tree에서 원문 일반 셀 14,166개의 source-owner별 텍스트를
대조해 모두 일치함을 확인했다. 반복 제목은 쪽별 원문 소유를 따로 검사했다.
컨트롤이 있는 다섯 셀은 별도 범위이며, 이 텍스트 노드 감사로 실제 clip 밖 잉크나

실제 측정→조각→paint를 계측한 결과 문단 70의 행 60은 측정기에서 53.333333px인데,
이어받기 행 원장을 다시 푼 뒤 28.453333px로 줄었다. 같은 행에서 끝나는 새 셀 (59,2)의
다섯 줄 66.666667px와 안여백 15.12px가 선언 56.906667px보다 크지만, 다른 걸침 셀의
앞 상자 변화 때문에 재계산할 때 선언만 사용해 내용 성장 24.88px를 버린 것이 원인이다.
단순 글꼴 차이나 선언 잔여 감소로 분류하지 않는다.

같은 종료 행의 모든 소유자에 대해 선언과 공통 내용 컷 API의 전체 물리 요구 중 큰 값을
확정된 앞 행 상자에서 차감하도록 보정 중이다. 내부 유닛 배열을 다른 모듈에 노출하지 않고,
기존 전체 끝 범위 계약을 사용한다. 새 Native 집중·전103쪽과 fresh WASM은 이 후보로
검증하며, 끝나기 전에 중간 후보의 통과를 최종 결과로 대체하지 않는다.

현재 단계를 전체 이슈 완료나 PR 제출 적격으로 판정하지 않는다.

## 2단계 Native/fresh WASM 선행 조건 완료

v5 fresh WASM도 전103쪽 90% 이상·쪽수 일치·누락0으로 완료됐다. 최저는 51쪽
94.75587%이며, Native 최저는 같은 쪽94.75432%다. 19쪽은 양쪽100%, 30쪽은
Native99.36627/WASM99.36595%, 76쪽은99.57115/99.57141%다. 고정base WASM
전103쪽은 같은 readonly package와 canonical capture lock 아래 산출 중이다.
그 결과의 0.1%p 대조를 확인하기 전 무회귀 완료라고 표시하지 않는다.

등록 전 임시 회귀6건에서 보정 전2PASS4FAIL→현재6PASS를 실제 확인했다.
조각 내용 하한만 빠진 중간v3에서는 해당 검사1건이 의도한24.88px 차이로 실패했다.
첫 초안의 (58,2) 소유 가정은 원문 두 행 병합과 달라 잘못됐으므로, 온전한 행을
소유하는 원문 단일행 열7을 검사하도록 정정한 뒤 수정 전후를 다시 실행했다.
초기5PASS1FAIL 초안을 최종 결과로 사용하지 않는다.

증적은 `mydocs/pr/assets/issue7700/repair-20261106/phase2/`에 정리한다.
활성 원본/PDF·기존 비시각 IR 수집·정식 회귀를 다음 단계에서 복원한다. 새 지침의
중요 쪽98% 조건을 충족한19·30·76쪽에는 독립 Print ±2px 검사를 보조로 추가하되,
이슈가 요구하는 원문 소유·포함·겹침·내용 보존 관계와 기존 말미 공백 검출 의미를 유지한다.
