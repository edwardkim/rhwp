## 공통 구현과 검증 순서

1. 진행 중인 #7642 전체 회귀의 종료와 source 불변을 확인하고 검사 helper 보정을 먼저
   커밋한다. 검증 중인 source나 HEAD를 바꾸지 않는다.
2. 선언과 내용 요구가 같은 행 높이 원장을 소비하도록 보정한다. 이미 확정된 행 구간의
   작은 병합 셀 성장으로 큰 병합 셀의 잔여가 중복 남는 순서 효과를 제거한다.
   미지 행의 기존 앞 행 우선 해법, 명시적 저장 프레임, 셀 간격·여백과 실제 내용 하한은
   보존한다. 측정 경로와 fallback 배치 경로는 같은 공통 계산을 사용한다.
3. 문서명·문단 번호·행 번호에 따른 예외나 출력 좌표 이동을 넣지 않는다. 순수한 최소 제약
   관계를 임시 진단으로 먼저 확인하고, 실제 Native 19·26·27쪽 및 나머지 미달 쪽을 출력한다.
4. 같은 원본의 Native/fresh WASM 전103쪽을 새 source로 산출한다. 전쪽 90% 이상,
   쪽수·내용 소속·누락/중복, base 대비 페이지별 raw 하락 0.1%p 이내를 모두 확인한다.
   모든 미달 쪽의 review/overlay를 직접 판독하고 추가 원인이 있으면 계속 보정한다.
5. 시각 선행 조건을 충족한 뒤 적합한 정식 회귀를 복원한다. 원문 단위와 내용 소유 관계를

6. #7375·#7640·#7642와 새 devel 이어받기 행의 정상 대조군을 보존한다. 관련 집중 검사,

   fresh WASM 실제 소비 경로를 검증한다. 최종 제출 head의 편람 Native gate도 완료한다.

## 1단계: 선언 잔여 중복과 행 합산 경계 보정

확정된 일반 셀의 연결 구간에서 선언·내용 요구를 함께 풀도록 공통 helper를 보정했다.
측정기와 fallback이 같은 helper를 호출한다. 미지 행, 독립 저장 reset, 세로쓰기·개체가
있는 구간은 이 새 계산의 근거로 사용하지 않는다. 19쪽의 실제 측정 구간은
414.72→396.08px, 끝 행은 47.093333→28.453333px가 됐고 Native raw는
72.89079→100%다. review/overlay에서 병합 라벨·내부 괘선·입찰계약의 하단을 직접 확인했다.

25쪽의 마지막 행은 누적 합 888.00000000000045475px와 예산 888px를 비교해 밀리고 있었다.
이미 블록 스캔에서 사용하는 방식대로 행 스캔도 누적 연산 규모의 f64 오차만 구분한다.
이 사례의 오차 상한은 0.00000000001301359px이며 HU/px 여유나 시각 문턱을 늘리지 않았다.
실제 저장 행 소속은 25쪽 끝 30→31, 26쪽 끝 57→58로 바뀌었다(끝 행은 exclusive).
Native 26쪽은 65.74957→96.64273%, 27쪽은 62.91973→98.40958%로 개선됐다.

첫 보정과 합산 경계 보정을 각각 포함한 기존 Native 집중 검사 43건을 최소 글꼴 환경에서
실행해 두 번 모두 43 PASS를 확인했다. 새 검사는 아직 추가하지 않았다. 현재 Native 집중
11쪽 중 19·25·26·27·29·75쪽은 90% 이상이지만 30·31·32·33·76쪽은 미달이다.
같은 새 source의 fresh WASM·전103쪽·전체 회귀와 필수 3종은 아직 재실행 전이며,
과거 #7642의 전체 통과를 이 후보의 결과로 재인용하지 않는다.

76쪽에서는 원문 문단 131의 부동 표만 다음 쪽으로 이월되는데, 뒤 inline 표 앞의 호스트 줄
32px까지 이월돼 다음 표가 앞당겨지는 현상을 확인했다. 저장 줄 사다리는 문단 131의
20347HU + 줄 1500HU + 뒤 간격 900HU = 문단 132의 22747HU로 정확히 이어진다.
부동 개체의 이월과 이 호스트 줄의 소유를 분리하는 다음 단계 보정이 필요하다.
나머지 30–33쪽의 측정·조각 행 상자 차이도 계속 추적한다.
