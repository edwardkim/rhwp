## 보정 전 전체 측정과 원인

고정 base `170b886f167b705b6e630c5b34bb638d92fae0a9`와 #7642 후보 runtime의
Native 전103쪽을 정본 Visual Sweep으로 각각 출력했다. 쪽수 일치·누락0이며,
19·26·27·30·31·32·33·76쪽이 양쪽 모두 90% 미만이다. 최저는 32쪽 53.57664%다.
100쪽은 실제 Native PNG도 동일하며, 나머지 36·65·66쪽은 후보에서 소폭 개선됐다.
0.1%p 초과 하락은 없다. 기존 미달이라는 사실로 이번 해결 범위에서 제외하지 않는다.

19쪽의 원문 표 문단 67, 행 30–42에서 공개 HeightMeasurer API의 실제 내용 요구와
현재 행 벡터를 대조했다. 작은 병합 셀 세 개의 내용이 각각 6.213333px 늘어난 뒤,
큰 병합 셀의 선언 잔여가 끝 행에 그대로 남는다. 현행 계산을 3.7e-9px 이내로 재현했고,
같은 선언·내용 최소 제약을 함께 풀면 중복 잔여 18.64px가 사라진다.
이 구간의 합은 현재 414.72px, 원본 선언과 공동 제약은 396.08px다.
독립 Print의 내부 괘선도 이 차이를 확인한다. 이는 19쪽의 원인 증거이며,
나머지 미달 쪽까지 해결됐다는 증거가 아니다.

27쪽의 첫 `주요통계관리`는 원문 표 문단 68의 행 57이다. Print에서는 26쪽에 있지만
Native에서는 27쪽으로 넘어간다. 전체 미달 표의 원문 소유는 문단 67·68·70·128·132로
확인했다. 글꼴 차이로 면제하지 않고 각 행의 실제 높이와 쪽 소속을 추적한다.

## 공통 구현과 검증 순서

1. 진행 중인 #7642 전체 회귀의 종료와 source 불변을 확인하고 검사 helper 보정을 먼저
   커밋한다. 검증 중인 source나 HEAD를 바꾸지 않는다.
2. 선언과 내용 요구가 같은 행 높이 원장을 소비하도록 보정한다. 이미 확정된 행 구간의
   작은 병합 셀 성장으로 큰 병합 셀의 잔여가 중복 남는 순서 효과를 제거한다.
   미지 행의 기존 앞 행 우선 해법, 명시적 저장 프레임, 셀 간격·여백과 실제 내용 하한은
   보존한다. 측정 경로와 fallback 배치 경로는 같은 공통 계산을 사용한다.
3. 문서명·문단 번호·행 번호에 따른 예외나 출력 좌표 이동을 넣지 않는다. 순수한 최소 제약
   관계를 임시 진단으로 먼저 확인하고, 실제 Native 19·26·27쪽 및 나머지 미달 쪽을 출력한다.
4. 같은 원본의 Native/fresh WASM 전103쪽을 새 source로 산출한다. 전쪽 90% 이상,
   쪽수·내용 소속·누락/중복, base 대비 페이지별 raw 하락 0.1%p 이내를 모두 확인한다.
   모든 미달 쪽의 review/overlay를 직접 판독하고 추가 원인이 있으면 계속 보정한다.
5. 시각 선행 조건을 충족한 뒤 적합한 정식 회귀를 복원한다. 원문 단위와 내용 소유 관계를
   검사하고, 해당 페이지 Native/fresh WASM 양쪽 raw 98% 이상일 때만 독립 Print ±2px의
   절대 좌표 검사를 추가한다. 이전 부적합 기대값을 현재 출력에 맞추지 않는다.
6. #7375·#7640·#7642와 새 devel 이어받기 행의 정상 대조군을 보존한다. 관련 집중 검사,
   Native Skia 필수 3종, 최소 글꼴 전체 nextest, lint/build·manifest/unit tier 및
   fresh WASM 실제 소비 경로를 검증한다. 최종 제출 head의 편람 Native gate도 완료한다.

빌드 jobs8·테스트 threads8·총 capture8, Cargo 순차 실행을 유지한다. Mac fresh WASM은
