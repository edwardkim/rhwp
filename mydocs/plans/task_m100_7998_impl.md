## 작업의 우선순위: 정확한 PDF → IR 변환

2026-10-18 메인테이너 지시: **PDF를 rhwp IR로 옮기는 과정은 속도보다 정확성이 우선이며,
이것이 rhwp의 차별점이다.** 정확성은 원문·공백·읽기 순서의 보존, 표/셀/문단/글줄의 올바른
소속과 관계, 원본에 대응하는 배치, 편집·저장·재열기 후의 보존을 포함한다. 구조 검증과
시각 검증을 모두 충족한 범위에서 성능을 개선한다. 처리 속도나 높은 픽셀 일치율을 의미 구조의
정확성 대신 수용 근거로 사용하지 않는다.

알고리즘 선택은 독립 기대 구조와 반례에서의 정확성을 먼저 비교하고, 실행 시간·메모리는
별도로 기록한다. 최적화는 동일 입력의 문자 소속·줄/문단 경계·셀 구조·보류 판정과 실제 출력을
보존해야 한다. 요청 자원 제한은 유지하되, 제한에 도달한 구역은 미완료와 근거를 전달한다.
속도를 위해 임의의 병합·분리·문단 확정을 하거나 미처리를 ‘구조 없음’으로 보고하지 않는다.

## 3. 원인 계층과 실제 소비 경로

| 확인한 조건 | 코드 위치 | 이번 변경의 계약 |
|---|---|---|
| stroke가 없거나 matrix가 있으면 경계 추출에서 제외 | `src/parser/pdf/table_detection.rs::edges` | stroke·얇은 fill·clip·변환 좌표의 근거를 구분해 관측한다. clip을 곧바로 셀 테두리로 채택하지 않는다. |
| 공유 변의 paint가 없으면 이웃 Tile을 연결 | 같은 파일 `grid`의 `covered <= EPS` 분기 | paint 부재와 셀 연결을 분리하고 추가 근거가 없는 병합·분리 대안을 보류한다. |
| 고정 512 edge 초과를 빈 검출 입력으로 낮춤 | 같은 파일 `MAX_EDGES`, `detect_ruled_tables` | 비용 제한을 유지하되 미완료 구역과 사유를 노출한다. 상수만 크게 올리는 해결은 하지 않는다. |
| 공유 경계에 닿은 자식 후보를 보류 | `table_hierarchy.rs::strict`, `compose` | 경계 공유를 표현하고 평면·지역·포함 해석을 비교한다. 접촉이나 선폭만으로 계층을 결정하지 않는다. |
| 구조 증거 snapshot이 페이지 lowering 뒤 폐기됨 | `extract.rs::extract` → `mod.rs::ExtractedPage` | 요약 진단과 opt-in 상세 진단을 연결해 후보 탈락·보류·소속의 이유를 확인할 수 있게 한다. |

실제 경로는 backend `extract_paths`·문자/그림 추출 → `extract.rs`의 검출·recognition →
`ExtractedPage.snapshot` → `structured_lowering.rs`의 `TableBuilder`와 positional fallback →
공통 Document IR → Native/WASM paint 및 저장이다. `mod.rs`의 요청 예산도 검출된 셀을 소비한다.
검출 helper만 바꾸고 별도의 lowering 조건·원점·제거 집합이 이전 가정을 사용하는 상태를
완료로 간주하지 않는다. 새 후보의 내용 소유와 paint 순서가 최종 IR까지 이어지는지 확인한다.

backend에는 이미 path의 source-order 경로·dash·matrix·clip/clip path·alpha와 문자 폭/offset
정보가 있다. 이를 제품 adapter에서 소비한다. 다만 clip 필드는 직렬화에서 생략되며 paint 없는
clip 연산이 현재 path 목록에 충분히 남는지는 추가 확인이 필요하다. 별도 PDF parser를 새로
작성하지 않고 필요한 관측 지점을 기존 backend에 연결한다. 문자 위치가 근사인 경우 실제
glyph 좌표로 가장하지 않고 품질·미확정 상태를 기록한다.

## 4. 구현 범위와 연결된 첫 절편

피드백의 M0–M5를 제품 경로에서 연결한다. 관측 장부만 만드는 데 머물지 않고, 후보 생성·
판정·lowering·진단까지 최소 한 번 끝까지 통과시킨 뒤 세부 알고리즘을 보완한다.
`tools/pdf-ir-poc`는 비교 자료로 유지하며 Python 실험이나 POC에 별도 제품 엔진을 만들지 않는다.

1. **관측과 정규화:** 원본 문자·path·clip·fill·그림의 source ID, 원본 좌표/CTM과 정규화 좌표,
   visibility 상태를 보존한다. 원본/유도/가설/사용자 확인을 구분한다. 규칙·설정 버전과 ID는
   같은 입력과 설정에서 결정적이어야 한다. 흰 글자를 색상만으로 삭제하지 않는다.
2. **T/S/G 후보:** T0 내용 묶음, S 구역/paint 근거, G 후보별 지역·비교용 전역 축을 별도로
   생성한다. 클립·경계·내용 기반 축의 출처와 충돌을 남긴다. 한 행/한 열이라는 이유만으로
   후보를 버리지 않는다. 원본을 덮지 않고 경계 기반 T1 보정을 참조로 연결한다.
3. **공유 변과 셀:** `paintPresence`와 `separatorRole`을 분리한다. 중복 stroke 구간은 합집합으로
   계산하고 점선의 raw 지지율과 복원 지지율을 구분한다. 무paint→병합을 자동 확정하지 않는다.
   직사각 Tile 덮임과 문자·그림의 단일 소유를 검증하며 L자 영역을 bbox로 바꾸어 셀을 만들지 않는다.
4. **지역·계층 대안:** 공유 경계를 참조로 표현하고 `H_flat`/`H_nested`를 보존한다. 다른 지역의
   축이 내용을 가로지르는 현상은 충돌 증거이며 한 해석의 자동 탈락 조건이 아니다. 순환·깊이·
   계산량 제한을 유지한다. 작성 프로그램을 분류해 특정 샘플만 처리하는 분기를 넣지 않는다.
5. **제품 소비와 검토 화면:** 확정 가능한 후보만 공통 IR의 편집 가능한 표로 승격한다. 보류 후보는
   기존 위치·paint·내용을 보존하고 이유와 경쟁 가설을 조회하게 한다. 기존 PDF 진단 API에 호환되는
   요약을 두고 상세 근거는 요청 시에만 제한된 양으로 전달한다. 로컬 review에는 원본/문자 묶음/
   clip/실제 경계/복원 경계/가상 축을 구분하는 overlay와 후보별 근거를 제공한다.

요청 예산과 실패 복구는 모든 단계에 적용한다. 한 후보의 예산 초과를 페이지 전체의 ‘표 없음’으로
바꾸지 않는다. 원본 paint를 보존할 수도 없는 경우와 추론만 미완료인 경우를 구분한다.
완전한 PDF 가시성 엔진·OCR·원본 Excel 객체 복원·모든 표의 자동 확정은 이번 완료 주장이 아니다.
새로 확인한 미지원 유형은 현재 연결된 구현의 완료 조건과 구분해 후속 백로그에 기록한다.

### 4.1. 이번 범위의 글줄·문단 복원과 실제 IR 연결

2026-10-18 메인테이너가 현재 문단/줄 인식과 IR 매핑의 취약성을 지적하고 범위 확장을
지시했다. 아래 항목은 구현할 일이며, 현재 구현 완료나 기존 시각 판정으로 보고하지 않는다.

**확인한 생산·소비 경로와 결함:** `extract.rs::extract`가 같은 span을 두 경로로 보낸다.
`table_inference.rs::Ledger::observe`는 문자별 T0를 만들지만, `recognition.rs::make_lines`는
그 T0를 소비하지 않고 span baseline을 다시 묶는다. `ParagraphMachine`은 정렬·글자 크기·
고정 상대 간격으로 문단을 제안한다. `TableBuilder::build_inner`는 `fixed_lines` 경로에서
그 제안을 다시 줄별 `Paragraph`로 쪼갠다. 본문 `bodyRegions`의 문단 제안은
`lowering.rs`에서 소비하지 않고 원래 span마다 TextBox 하나를 만든다. `paragraph()`의
줄 사이 `\n`과 `text_with_tabs()`의 span 간 탭도 원본의 명시적 개행/탭을 입증한 결과가 아니다.
현재 pass5 저장본의 보고서 7개 표에서 셀 문단 210개, 다중 글줄 문단 0개를 확인했다.
이 수치는 현 상태 관측이며 기대 문단 수가 아니다.

**참고한 일차 자료와 적용 판단** — 2026-10-18 문서·실제 구현을 대조했다.

| 자료 | 참고할 방식과 적용 경계 |
|---|---|
| [pdfminer.six의 layout analysis](https://pdfminersix.readthedocs.io/en/latest/topic/converting_pdf_to_text.html), [group_objects/group_textlines](https://github.com/pdfminer/pdfminer.six/blob/master/pdfminer/layout.py) | 문자 box의 세로 겹침과 상대 가로 간격으로 글줄을 구성하고 가까운 줄을 묶는다. 문자 결합과 줄 결합의 서로 다른 척도를 참고한다. text box를 곧바로 작성 문단으로 단정하지 않는다. |
| [pdfplumber의 WordExtractor](https://github.com/jsvine/pdfplumber/blob/stable/pdfplumber/utils/text.py) | 진행 방향에 따른 줄 군집·줄 안 정렬, 문자 간격과 원본 문자 참조를 분리한다. PDF 연산 순서나 span 분할을 읽기 순서·단어 경계로 가정하지 않는다. |
| [PdfPig의 XY Cut·Docstrum·reading order](https://github.com/UglyToad/PdfPig/wiki/Document-Layout-Analysis) | 여백에 의한 지역 분할과 이웃 거리에서 얻는 줄/블록 간격을 비교한다. 같은 높이의 두 단·서로 다른 셀을 합치지 않는 지역화와 국소 간격 추정의 근거로 쓴다. 블록 검출과 문단 경계·읽기 순서 판정은 구분한다. |

별도 Python/C# 엔진이나 OCR을 제품 의존성으로 추가하지 않는다. 기존 backend가 제공하는
문자 원점·advance·방향·source order·geometry quality를 사용한다. 비교 알고리즘의 상수나
실험 문단 수를 그대로 정답으로 채택하지 않으며, 이번 두 실물과 독립 반례에서 선택 근거를 남긴다.

1. **공통 문자·글줄 결과:** 원본 span/문자의 ID와 UTF-16 대응, 원본 공백과 추론 공백,
   진행 방향·baseline·box·측정 품질을 보존하는 공통 결과를 만든다. 진단 T0와 실제 인식이
   같은 결과를 참조한다. 먼저 글줄 후보를 구성하고 여백·지지되는 셀 경계·그림 구역과 대조해
   지역별 줄을 확정한다. 큰 가로 간격은 분할 후보로 처리하고, 같은 baseline만으로 다른 단이나
   다른 셀을 한 줄로 합치지 않는다. 단어 간격과 단 사이 여백을 동일한 탭 규칙으로 처리하지 않는다.
2. **문단과 읽기 순서:** 지역 안의 줄 사이 간격 분포, 좌우/중앙 정렬, 첫 줄·내어쓰기,
   목록 시작과 이어지는 줄, 제목의 크기 변화, 그림·표 경계를 함께 평가한다. 내용 블록 하나에
   여러 문단을 허용한다. 문장 부호 하나, 동일 글꼴, 고정 `1.8em`만으로 경계를 확정하지 않는다.
   글줄 끝의 시각적 줄바꿈, 명시적 개행, 문단 끝을 구분하고 원본 근거와 추론 상태를 남긴다.
   기하만으로 확정할 수 없는 경계는 국소적으로 보류하며, 한 모호한 줄 때문에 뒤의 정상 지역
   전체를 하나의 Deferred 덩어리로 흡수하지 않는다.
3. **실제 IR 소비:** 확정한 한 문단은 여러 줄을 가진 하나의 `Paragraph`로 매핑한다.
   `text`·`char_offsets`·글자모양 범위·`LineSeg`·문단모양의 단위와 원점을 공통 IR 표준에
   맞춘다. 셀 안에서는 `Cell.paragraphs`, 본문에서는 지역의 문단 목록이 같은 인식 결과를
   소비한다. 위치 보존에 필요한 글상자 프레임과 그 안의 의미 문단을 구분한다. 글줄·문단 경계,
   추론 공백과 source 문자 범위의 연결은 진단과 저장 어댑터가 각각 재추측하지 않는다.
4. **측정·편집·저장:** span bbox와 실제 glyph advance를 구분해 줄의 가용 폭·탭/정렬·기준선을
   구성한다. renderer의 source 줄 수용/재조판 분기와 최종 배치까지 추적하고, 현재 탭 뒤 잘림을
   같은 경계에서 보정한다. 편집 후에는 공통 무효화·재조판 계약을 따른다. 문자 삽입/삭제,
   문단 split/merge와 HWP/HWPX 저장·재열기에서 문단 소속·읽기 순서·원문/공백의 보존을 검사한다.
   원래 없는 문단 끝이나 hard break를 추가해 화면만 유지하지 않는다.

구현은 **공통 문자/줄·지역 결과 → 문단 판정 → 셀·본문 IR 소비 → 편집·양 저장 형식** 순서로
연결한다. 현재 stage3 안의 세부 일감으로 기록하고, 인식 모듈만 통과한 상태를 완료로 표시하지
않는다. 회전/세로·OCR·완전한 Tagged PDF 복원은 별도 범위지만 지원하지 않은 내용을 삭제하지 않는다.

수용 검증에는 독립적으로 정한 두 줄 한 문단/두 문단, 첫 줄 들여쓰기·목록의 이어지는 줄,
같은 baseline의 두 단·인접 셀, 혼합 크기의 위첨자, 한글/영문과 TJ 공백·명시적 공백을 포함한다.
span 분할·병합과 연산 순서 변경으로 같은 원문/배치의 문단 소속이 바뀌지 않아야 한다.
원문자 단일 소유·누락/중복, UTF-16 범위와 실제 최종 줄/문단 소속을 검사한다. 실물에서 작성 당시
경계가 불명확한 곳은 수동 확인한 경계와 미확정 경계를 구분한다. 검토 화면은 원본 위의 글줄 box,
문단 묶음과 읽기 순서, 실제 저장 IR의 소속을 따로 제공한다. 픽셀 점수와 구조 판정은 별도로 유지한다.

### 4.2. 수정 설계: 공통 관측과 소유 범위별 문단 구성

2026-10-18 분할정복 지시에 따라 4.1절을 아래 설계와 절편으로 구체화한다. **아래 타입명과
모듈명은 구현할 내부 설계명**이며 현재 코드에 이미 존재하는 필드·검증 결과가 아니다.
공통 Document 모델 전체를 재작성하지 않고 PDF frontend 내부에서 공통 결과를 발행한다.

| 내부 결과 | 책임과 불변 조건 | 실제 소비자 |
|---|---|---|
| `ObservedText` / `SourceTextRange` | 원본 span/문자 식별자, Unicode scalar와 UTF-16 대응, 원문 공백, 원점·advance·box·방향·스타일 참조와 geometry quality. 원본 문자열은 수정하지 않는다. | T0 진단, 지역/셀 소속 판정, 실제 줄 구성 |
| `TextLine` | 소유 지역, 순서 있는 source 범위, 줄 안 run과 기준선·점유 영역. 관측된 간격과 추론 공백/정렬을 구분한다. | 문단 판정, 줄 검토 화면, IR adapter |
| `ParagraphProposal` | 소유 지역과 line 참조, 읽기 순서, 줄 사이 연결/문단 경계의 근거와 확정/보류 상태. 한 줄도 문단일 수 있고 여러 줄도 한 문단일 수 있다. | 셀/본문의 동일한 문단 adapter, 진단 |
| `TextRegion` / `TextAnalysis` | 표 셀·본문 구역·보류 영역의 소유 관계, 원본/수정 후보의 연결과 불완료 사유. 확정 범위에서 원문자 소유는 정확히 하나다. | TableBuilder, 본문 lowering, 요청 결과 진단 |

`extract.rs`에서 backend의 문자 관측을 한 번 정규화하고, `table_inference::Ledger`의
T0와 `recognition`이 이를 참조한다. 구체적인 내부 배치는 `text_analysis.rs` 등 PDF 전용
모듈로 좁히며, 현 JSON 장부는 공통 결과의 진단 직렬화로 만든다. lowerer가 JSON의
preview 문자열이나 별도로 추측한 경계를 의미 구조의 원본으로 삼지 않도록 이행한다.
source ID는 같은 입력 안의 추적 수단이다. span 분할·연산 순서 변형 대조에서는 ID 자체의
일치를 요구하지 않고 원문자 대응·줄/문단 소속·읽기 순서를 비교한다.

결정 경로는 `원본 관측 → 경계에 독립적인 T0/줄 후보 → S/G 후보와 소유 대안 →
채택된 지역 안의 T1/줄 → 문단 → 실제 IR`이다. T0는 불변으로 남기고, 채택된 셀 경계로
줄을 나눈 경우에는 T1의 원본 참조와 분할 이유를 남긴다. 줄 후보를 먼저 만들었다는 이유로
표/단 경계를 가로지르는 소속을 확정하지 않으며, 문단 제안이 자신의 근거가 된 셀 가설을
다시 독립 증거로 보증하는 순환을 만들지 않는다. 이후 판정이 달라지면 영향받은 지역만
재구성하고 원문과 이전 후보를 보존한다.

공백과 줄 연결은 source 범위와 함께 표현한다. 원문 공백, 기하에서 추론한 단어 공백,
시각적 줄바꿈, 근거가 있는 hard break와 문단 끝을 구분한다. `Paragraph.text`에는 선택한
연결 정책을 한 번 적용하고 그 UTF-16 범위를 `char_shapes`와 `LineSeg.text_start`가
공유한다. 모든 span 간격을 탭으로 바꾸거나 모든 시각 줄 끝에 newline을 넣지 않는다.
하이픈·결합 문자·공백을 삭제/정규화하는 새 정책은 독립 근거 없이 추가하지 않는다.

문단 adapter는 셀/본문에서 같은 의미 결과를 소비하되, 페이지·지역·셀·문단의 원점과
가용 폭은 명시적으로 전달받는다. [공통 LineSeg 표준](../tech/document_ir_lineseg_standard.md)의
단위·source publication 계약을 따르고, renderer의 source 줄 수용/재조판과 실제 최종
원점 소비까지 대조한다. 기존 소비 경로가 표현할 수 없는 메트릭이 확인되면 그 계약을
먼저 보완하며, PDF 전용 paint 위치 덮어쓰기로 구조와 화면을 분리하지 않는다.

소유 전환은 한 선택 후보의 내용을 모두 검증한 뒤 적용한다. 확정 문단에 소비된 source
범위만 positional fallback에서 제거하고, 미확정 내용은 단일 fallback 소유로 남긴다.
중간 실패에서 glyph 누락·중복이나 반쯤 적용된 셀/본문을 발행하지 않는다. 셀 그림과
경계 paint는 문자와 별도 source 종류로 유지하되 표/본문 소유·z-order를 함께 검증한다.

기존 backend의 `TextSpan`/`to_chars`는 원점·advance·방향을 얻는 adapter로 재사용한다.
`layout/clustering.rs`는 `ml` feature 아래 단순 거리 군집이고,
`converters/layout_lines.rs`는 converter 전용 span→한 줄 프레임 구성이다. 이름만으로
문단/소유 계약을 충족한다고 판단하거나 다른 converter 경로를 제품 frontend에 통째로
활성화하지 않는다. 해당 구현과 4.1절의 외부 알고리즘은 필요한 규칙·반례를 비교하는 자료다.

### 4.3. 분할정복 실행 순서와 절편별 완료 조건

모듈별 구현을 모두 끝낸 뒤 마지막에 연결하는 대신, **각 절편이 좁은 입력 범위에서
관측·인식 → 실제 IR → 편집·저장·재열기까지 통과**하도록 한다. 기반 공통 타입도 첫 절편의
실제 소비에 필요한 만큼부터 도입한다. 절편 수용과 #7998 전체 완료는 구분한다.

| 순서 | 해결 범위와 연결 일감 | 독립 기준·반례 / 절편 완료 조건 |
|---|---|---|
| P1 셀 안의 다중 글줄 문단 | B10–B13의 첫 연결. 수평 텍스트·확정된 단순 셀에서 공통 문자/줄 결과와 문단 adapter를 도입하고 `fixed_lines`의 줄별 문단 분리를 보완한다. | 작성/주석 근거가 있는 ‘두 줄 한 문단’과 ‘두 문단’ 대조군을 먼저 정한다. 실제 Cell 안의 Paragraph/LineSeg 소속, 원문·공백·순서, 문자 편집 후 양 저장 형식 재열기를 확인한다. 같은 줄의 다른 셀을 합치지 않는다. 영향 실물 셀과 독립 대조군의 Native/fresh WASM 직접 판독까지 끝내야 통과다. |
