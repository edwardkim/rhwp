줄로 내려가야 하는 관계**를 올바르게 처리하는 것이다. 먼저 회귀 여부와 원인 계보를
확인하고, 폭이 충분한 경우까지 표를 무조건 내리는 보정은 배제한다.

TAC는 Treat As Character(글자처럼 취급), LineSeg는 저장된 줄 배치 정보다. 이 사례에서
그림은 non-TAC, 표는 TAC다. 개행은 새 문단·문자 삽입이 아니라 자동 줄 배치다.

미해결인지**다. 기존 devel에서 재현된다고 과거 회귀 가능성까지 배제하지 않는다.

## 3. 범위와 보호 불변식

1. 그림의 실제 위치·바깥 여백과 줄 영역의 교차로 가용 폭을 판단한다. 종이 기준 좌표를
   본문 회피와 무관한 것으로 취급하지 않는다.
2. TAC 표가 들어갈 폭이 부족하면 다음 배치 가능한 줄을 선택하고, 충분하면 옆 배치를
   유지한다. 두 개체의 선언 폭 합이나 고정 px 문턱만으로 판정하지 않는다.
3. 같은 문단이라도 현재 개체 자신의 밴드와 선행 형제 개체의 밴드를 구분한다.
   owner 조건 제거만으로 모든 자기 문단 개체를 회피시키지 않는다.
4. 줄/host/표 경로에서 세로 이동을 중복 계상하지 않는다. 표의 존재, 페이지 귀속,
   후속 문단 흐름을 보호한다.
5. 저장 LineSeg는 유효성 검증 후 활용하며, 누락·합성·범위 밖 입력에서 무한 전진,
   무한 반복이나 off-canvas를 만들지 않는다. 한컴 제품 버전별 경험 분기는 추가하지 않는다.
6. 원본 문서와 기준 PDF를 수정하지 않는다. 기대값 완화·golden 일괄 갱신으로 시험을 통과시키지 않는다.

범위 밖: #6798의 7쪽 수정 보정, 전체 float 엔진 리팩터링, 코퍼스 전수 재계측,
CI·릴리즈 정책 변경. #6798의 기여자 작업과 이번 수정은 별도 관리한다.

## 4. 단계별 진행

### Stage 1 — 재현·회귀 분류와 원인 계보

- 기존 render tree·PDF·CLI dump를 우선 읽고, 누락된 대조만 생성한다. 동일 원본,
  폰트 source, DPI, feature/profile, 옵션을 고정하고 binary/source SHA를 함께 기록한다.
- 우선 고정 최신 devel과 이미 검토한 PR 결합 후보의 1쪽 `pi=0 ci=3/4` 및 후속 표·본문
  geometry를 비교한다. 이번 최신 devel과 이전 검토 devel은 같은 SHA이므로 중복 빌드하지 않는다.
- PR 고유 변경과 base 변화가 섞이면 PR 분기점·단독 head 또는 hunk 유무 대조로 분리한다.
  그림 옆 줄 배치의 다른 축인 #6754와 기존 #4639 이력을 우선 확인하되 원인으로 단정하지 않는다.
- 과거 정상 증적이 발견되면 그 경계를 대상으로 bisect한다. 정상 기준을 못 찾으면 무제한
  과거 빌드를 하지 않고 최초 발생 미확정으로 보고한다. 최초 과거 후보는 최대 3개로
  한정하고 추가 확대는 근거와 비용을 제시해 승인받는다.
- 분류가 원 PR 회귀인지와 별도로, 현재 객체의 flow·가용 폭·TAC 분류·LineSeg 소비 경로를
  추적해 최소 수정 위치를 도출한다.
- 산출: `mydocs/working/task_m100_6812_stage1.md`와
  `mydocs/plans/task_m100_6812_impl.md`. 결과·구현계획 승인 후 다음 단계로 간다.

### Stage 2 — 판별력 있는 회귀 시험과 최소 구현

- 공개 API로 대상 그림·표의 pi/ci, 존재·1쪽 귀속·상대 geometry·후속 흐름을 고정하는
  RED 시험을 `tests/cases/`에 추가한다. 실제 교집합과 필요한 clearance는 이름·식을 구분한다.
- 반대 방향은 폭 충분/이미 회피/비어울림/다른 문단/LineSeg 비정상 중 실제 변경 분기를
  보호하는 작은 집합으로 선정한다. 합성 IR을 쓰면 캐시를 재구축해 대조가 실제 반영되게 한다.
- 승인한 구조적 조건으로만 수정하고 RED→GREEN 및 수정 제거 음성 대조를 확인한다.
- #6754(그림과 표가 나란히 있어야 하는 TAC 조합), #4639 관련 경로와 실제 변경 함수의
  인접 핀을 함께 검사한다. #6754의 그림은 TAC이므로 이번 non-TAC 그림과 구분한다.
- 제품 `src/**`에 신규 테스트·test support를 넣지 않는다. generated suite·manifest 및
  Cargo 파생물은 검증 전용이며 제출하지 않는다.
- 산출: `mydocs/working/task_m100_6812_stage2.md`.

### Stage 3 — 영향 검증·Docker WASM·메인테이너 시각 판정

- 테스트 원본을 커밋한 뒤 분리된 review 환경에서 suite를 준비해 검증한다. 기존 다른 PR의
  review worktree는 덮어쓰지 않는다. 이 시점에만 필요한 검증 worktree를 준비하고 기록한다.
- AGENTS.md와 `local_validation.md` 4.3의 순차 Rust lint 묶음(native/WASM32/workspace
  all-target, fmt, locked workspace build, suite check)을 모두 수행한다. 전체 CI 성격의
  광범위 회귀는 관련 결과를 보고한 뒤 별도 명시 승인을 받아 실행한다.
- 기존 한컴 PDF와 1쪽 수정 결과를 비교하고 같은 문서의 후속 페이지 및 선정한 반대 사례를
  확인한다. 전체 11쪽 유지나 overlap 0만으로 조판 통과를 선언하지 않는다.
- Docker로 최적화 WASM을 빌드한다. 이전 네트워크 주소 풀 소진이 재발하면 기존 network를
  삭제하지 않고 환경 실패와 제품 실패를 구분해 처리한다.
- 기존 7708 PR 검토 서버는 보존한다. 수정 후보 Studio를 별도 식별 가능한 URL로 준비하여
  메인테이너의 직접 시각 판정을 받는다.
- 성능은 동일 fixture의 동일 조건 전후 반복 측정으로 국소 영향만 보고한다. 공개 결정적
  성능 회귀는 보호하되, 이번 문제를 이유로 10k 전수 계측을 새로 시작하지 않는다.
- 산출: `mydocs/working/task_m100_6812_stage3.md`, 필요한 대표 시각 증적.
