## 3. 근본 원인 분석

### 차트 그림(pi=172, ci=0) 메타데이터
- 종류: Picture (그림)
- 크기: 170.0mm × 111.0mm (HU 48190 × 31470)
- `text_wrap = TopAndBottom`
- `vert_rel_to = Para` (문단 상대)
- `treat_as_char = false`

### vpos 흐름 (한컴 기록)
| 문단 | vpos (HU) | 비고 |
|------|----------|------|
| pi=172 line[0] | 1275685 | 차트 anchor 문단, 텍스트 라인 |
| pi=173 line[0] | 1307155 | 차트 다음, vpos 차이 31470 = 차트 높이 |
| pi=174 line[0] (2x1 표) | 1308915 | |

한컴은 **TopAndBottom + vert=Para** 그림이 anchor 문단 다음 문단의 vpos를 그림 높이만큼 밀어 기록한다.

### 우리 레이아웃 처리 흐름

`src/renderer/layout.rs` 컬럼 아이템 루프:

| 단계 | 처리 | y_offset (px) |
|------|------|---------------|
| ① | `FullParagraph pi=172` 배치 (h=14.7) | 94.5 → 109.2 |
| ② | `Shape pi=172` (차트) — `layout_body_picture` 가 `y_offset + total_height` 반환 (`picture_footnote.rs:356`) | 109.2 → **528.8** |
| ③ | Shape 처리 후 `vpos_page_base = None; vpos_lazy_base = None` (line 1490-1491) | — |
| ④ | `FullParagraph pi=173` — vpos 보정 진입 (line 1387-1400) | — |

### vpos 보정 lazy_base 산출 결함

`src/renderer/layout.rs:1387-1400`:
```rust
let y_delta_hu = ((y_offset - col_area.y) / self.dpi * 7200.0).round() as i32;
let lazy_base = vpos_end - y_delta_hu;
```

- `y_offset = 528.8` (차트 바닥) → `y_delta_hu = (528.8 - 94.5) × 75 = 32574 HU`
- `vpos_end_172 = 1275685 + lh(1100) + ls(660) = 1277445` (pi=172 텍스트 라인 끝)
- `lazy_base = 1277445 - 32574 = 1244871`

**문제**: `vpos_end_172`는 pi=172 **텍스트 라인** 의 끝이지만 `y_delta_hu`는 차트 바닥까지의 거리 → lazy_base가 차트 높이만큼 낮게 잡힘.

이후 pi=174 (2x1 표) vpos 보정:
- `vpos_end_173 = 1307155 + 1100 + 660 = 1308915`
- `end_y = 94.5 + (1308915 - 1244871) × 96/7200 = 94.5 + 853.92 = 948.4`
- `y_offset 528.8 → 948.4` 강제 점프 (차트 높이 31470 HU ≈ 419.6px 이중 반영)

표 자체 높이 103.5px 추가 → `pi=174 종료 y ≈ 1052` → LAYOUT_OVERFLOW 일치.

### 기존 bypass 가드의 한계

`src/renderer/layout.rs:1366-1370`:
```rust
let prev_has_overlay_shape = paragraphs.get(prev_pi).map(|p| {
    p.controls.iter().any(|c|
        matches!(c, Control::Shape(s) if matches!(s.common().text_wrap,
            TextWrap::InFrontOfText | TextWrap::BehindText)))
}).unwrap_or(false);
```

- `Control::Shape`만 검사 → `Control::Picture` 미처리
- `InFrontOfText|BehindText`만 우회 → `TopAndBottom` (vert=Para) 미처리

→ pi=172의 그림(Picture, TopAndBottom)이 가드에 걸리지 않아 vpos 보정 진입 + 잘못된 lazy_base 산출.

## 4. 수정 방향

`prev_has_overlay_shape` 가드를 다음 케이스로 확장:

1. **Control::Picture (non-TAC)** 포함
   - 그림이 텍스트 흐름에 영향을 주는 모든 경우
2. **TopAndBottom + vert_rel_to=Para** 추가
   - 그림 높이가 후속 문단 vpos 차이에 반영되어 있어 vpos 보정 시 이중 점프 발생

확장 후 가드 식 (개략):
```rust
let prev_has_overlay_shape = paragraphs.get(prev_pi).map(|p| {
    p.controls.iter().any(|c| match c {
        Control::Shape(s) => {
            let cm = s.common();
            matches!(cm.text_wrap,
                TextWrap::InFrontOfText | TextWrap::BehindText)
            || (matches!(cm.text_wrap, TextWrap::TopAndBottom)
                && matches!(cm.vert_rel_to, VertRelTo::Para))
        }
        Control::Picture(p) if !p.common.treat_as_char => {
            matches!(p.common.text_wrap,
                TextWrap::InFrontOfText | TextWrap::BehindText)
            || (matches!(p.common.text_wrap, TextWrap::TopAndBottom)
                && matches!(p.common.vert_rel_to, VertRelTo::Para))
        }
        _ => false,
    })
}).unwrap_or(false);
```
