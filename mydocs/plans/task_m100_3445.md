## 5. v0.8.1 에서 얻은 운영 교훈 적용

이번 릴리즈에서 반복하지 않을 것들이다.

- **기준선은 고정 대상이 아니다.** v0.8.1 에서 세 차례 이동했다(dependabot 통합 → #3400 →
  #3409·#3402). 각 단계 전 `git fetch` 로 재확인하고, 바뀌면 이전 검증 결과를 재사용하지
  않고 재실행한다.
- **CHANGELOG 작성 후 유입 확인.** v0.8.1 에서 release PR CI 대기 중 #3402 가 merge 돼
  릴리즈 노트에서 누락될 뻔했다. main 통합 직전 `v0.8.1..devel` 을 다시 훑어 CHANGELOG 에
  빠진 사용자 체감 변경이 없는지 확인한다.
- **main 통합은 merge commit.** squash 시 ancestry 소실로 다음 릴리즈에서 문서 충돌이
  재발한다(v0.8.0 이력). 사전에 merge-base 이후 main 독자 변경 0 을 확인하고, 사후 트리
  동일성과 ancestry 보존을 검증한다.
- **publish step success ≠ 배포 완료.** v0.8.1 에서 마켓플레이스 2곳이 인덱싱 지연으로
  0.8.0 으로 조회됐다. 레지스트리를 실측할 때까지 완료로 보고하지 않는다.
- **릴리즈 이슈에 `Closes` 를 쓰지 않는다.** v0.8.1 에서 devel merge 시 자동 close 돼
  재개방해야 했다. PR 본문에는 `관련: #3445` 로만 적는다.
