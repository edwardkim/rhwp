# Task #523 수행계획서 — exam_science p1→p2 누적 vpos drift

## 1. 배경

`samples/exam_science.hwp` page 1 우측 단 하단에 들어가야 할 문제 6번 `<보기>` 표(pi=30, 3×3, 107.1 px) 와 답안 표(pi=31, 1×10, 19.1 px) 가 page 2 로 밀린다.

핵심 수치:
- page 1 단 1 누적 used = 1112.6 px (잔여 102.5 px)
- 표 pi=30 = 107.1 px → 잔여 보다 4.6 px 부족 → break
- HWP 원본 vpos: 78952 HU + 8033 HU = 86985 HU < column 91136 HU → 본래 fit
- 누적 오버슈트 ≈ 61 px (4570 HU)

본질: `paragraph_layout` 의 누적 y 가 HWP 가 인코딩한 vpos 보다 점진적으로 커진다. `#496` / Layout Phase 3 가 다루는 baseline/vpos drift family.

## 2. 목표

`exam_science.hwp` page 1 안에 문제 6 `<보기>` + 답안이 정상적으로 들어가도록 누적 drift 의 발원지를 식별하고 정정한다. 회귀 0 이 우선.

## 3. 진행 절차

1. 진단: page 1 단 1 의 pi 별 누적 y 와 HWP vpos 의 차이를 추적 (RHWP_DEBUG 로깅 또는 임시 print). drift 가 어느 pi 구간에서 누적되는지 식별.
2. 발원지에 따라 분기:
   - **(가)** `has_tac_shape` 분기의 line_height 폰트 보정 (`paragraph_layout.rs:798-806`) 가 문제 1-5 의 인라인 수식 다발 문단(pi=13/16/18/22/27) 에서 과대 적용 → 보정식 정밀화.
   - **(나)** 빈 문단(pi=20/25/26) 의 line_height 가 HWP 기록값보다 큼 → 빈 문단 처리 분기 정정.
   - **(다)** spacing_before/after 와 HWP vpos 의 중복 가산 → 이중 적용 차단.
3. 수정 적용. 단발 fix 보다 가능한 한 좁은 분기로 한정.
4. 회귀 검증: `scripts/svg_regression_diff.sh build HEAD~1 HEAD` 7 샘플 / 170+ 페이지 byte-diff. exam_science 기대 변경 페이지(p1, p2) 외 회귀 0.
5. 시각 검증: page 1 안에 `<보기>`+답안 정상 수용, page 2 가 문제 7 부터 시작 (PDF 일치).
