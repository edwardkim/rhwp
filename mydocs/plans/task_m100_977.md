# 수행 계획서 — Skia replay 경로 개요번호 x 우측 밀림 (M100 #977)

- 이슈: edwardkim/rhwp#977
- 브랜치: `local/task977` (← `upstream/devel`)
- 마일스톤: M100 (v1.0.0)

## 1. 배경

목차(개요번호 포함) 페이지를 rhwp-studio(CanvasKit/Skia 렌더)로 열면 일부 개요번호만 우측으로 ~9~10px 밀려, 같은 수준의 형제 항목과 정렬이 어긋난다.

- `export-svg`(네이티브 SVG 렌더러) 출력은 **정상** — 모든 개요번호 정렬
- rhwp-studio(Skia replay) 화면에서만 어긋남 → **Skia replay 경로 전용 버그**

## 2. 재현 조건 (조사 완료)

같은 `ParaShape`(ps_id 동일)를 쓰는 인접 목차 문단 중, **선두 공백 글자의 CharShape가 본문과 다른 문단**에서 발생한다.

- 정상 문단: 선두 공백 CharShape = 본문과 같은 폰트, 장평 100%
- 어긋난 문단: 선두 공백 CharShape = 다른 폰트 + 장평 95%

## 3. 조사 현황 (완료)

| 항목 | 결과 |
|------|------|
| 렌더 경로 | rhwp-studio → `getCanvasKitReplayPlan()` → CanvasKit(Skia) replay |
| 텍스트 그리기 코드 | `src/renderer/skia/text_replay.rs` |
| 밀림 폭 | 캔버스 픽셀 측정 +9~10px (선두 공백 2칸 폭과 일치) |
| `compute_char_positions()` | 장평 정상 반영, 레이아웃/SVG/Skia 공유 → 분기점 아님 |
| SVG 경로(`svg.rs`) | 정상 |

추정 분기점: 선두 공백 런(다른 폰트 + 장평 95%)의 폭 산출, 또는 후속 런 원점 `bbox.x`가 Skia replay 경로에서 어긋남. 읽기 전용 조사로는 `bbox.x` 오류인지 글리프 배치 오류인지 미확정.

## 4. 수행 범위

1. **진단** — `text_replay.rs`와 `svg.rs`에서 동일 문단의 `bbox.x` + `char_positions`를 덤프해 두 경로 비교 → 분기점 확정
   - `bbox.x` 상이 → render tree 구성 단계 버그
   - `bbox.x` 동일 → Skia 글리프 배치 버그
2. **수정** — 확정된 분기점에 대한 정정. 장평/폰트 차이가 후속 런 x에 미치는 영향을 정상화.
3. **검증** — 어긋난 케이스 정렬 회복 + SVG·Skia 양 경로 출력 일치. 광범위 샘플로 회귀 없음 확인.

## 5. 단계 개요 (구현 계획서에서 상세화)
