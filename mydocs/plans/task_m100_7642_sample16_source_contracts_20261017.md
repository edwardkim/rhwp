# #7642 sample16 회귀의 원본 소유·저장 줄 계약 검토

Issue: #7642

## 원인과 독립 근거

source cc4255a58d의 sample16 HWP3/HWP5/HWPX는 각각 전쪽64쪽의
Native/fresh WASM raw 최저90% 이상이며 독립 Print와 쪽수도 일치한다.
기존 #6527의 HWP3 검사만 TextLine 조상이 없어야 한다고 고정해 실패한다.
현재 원본 두 수식은 문단155/158의 글줄 흐름 참여 제어이고, 두 형식의
독립 Print6쪽은 제목→첫 설명→첫 수식→둘째 설명→둘째 수식→후속 주의문의
순서를 보존한다. 단독 수식이라는 분류와 내부 wrapper 유무를 혼동하지 않는다.

기존 #3518은 원본 제목의 공백과 U+FFFC 제어 자리를 무시한 문자열을 요구해
serializer 검사에 도달하기 전에 실패한다. 실제 원본은 `1. 추진목적` 뒤에
책갈피·새번호·쪽번호위치의 제어 자리3개가 있다. 원본 문단과 제어 소유를
확인한 뒤 저장 LineSeg와 원래 왕복 계약을 검사해야 한다.

## 실행 순서

1. 전쪽 TSV·독립 Print6쪽의 Native/fresh WASM review·overlay를 직접 판독한다.
2. #6527은 새 이름의 파일/함수로 원본 소유·TAC 줄 참여·본문 포함과 내용
   순서·누락/중복을 검사한다. 단순 wrapper 종류로 standalone을 판정하지 않는다.
3. #3518의 현재 HWPX 내보내기와 기존 Print 입력의 바이트를 확인한다. 동일하지
   않으면 새 출력 자체를 MCP Print하고 전쪽 Native/fresh WASM을 확인한 뒤
   필요한 검사 변경을 판단한다. source와 왕복본의 통과를 서로 대신하지 않는다.
4. 진행 중인 공용 target의 lint가 끝난 뒤 새 검사들을 한 번에 준비·실행하고,
   변경한 Rust test를 포함한 필수 lint를 같은 target에서 순차 확인한다.

이 단계는 현재 브랜치 전체 완료·PR 준비 완료를 뜻하지 않는다. devel 대비
하락과 나머지 미달·회귀 실패도 해결한다. 검사 기대를 맞추려고 원본의 제어
자리·저장 줄·source provenance를 제거하지 않는다.
