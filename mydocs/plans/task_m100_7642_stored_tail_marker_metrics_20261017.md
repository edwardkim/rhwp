# #7642 자동 줄 끝과 첫 줄 번호의 공통 점유 보정

Issue: #7642.

## 원본·독립 출력과 반례

#1440의 원본 HWP/HWPX와 독립 한컴 Print PDF는 전체 46쪽이다. af71은
쪽수를 복원했지만 6·15·36쪽이 각각 raw 42.99858%, 62.15351%, 61.14367%다.
세 쪽의 공통점은 같은 토큰의 끝(`은?`, `점]`, `?`)만 마지막 저장 줄에
남은 질문이다. 독립 PDF에서는 해당 질문이 모두 한 줄이다.

내용·스타일을 바꾸지 않고 p19의 LineSeg만 제거한 진단 저장본은 같은
af71에서 한 줄로 배치된다. 진단은 원본 또는 Print 기준을 대체하지 않는다.
다만 그 새 줄 높이는 본문 1000HU이고, 실제 번호는 독립 글자 모양의
1200HU다. PDF와 원본 첫 줄도 1200HU여서 번호를 포함하면 다음 문단
원점 차이 4.8px를 설명한다. 이를 상수로 보정하지 않고 실제 번호 스타일을 사용한다.

## 규칙과 소비 경로

- 저장 기하 miss 정책과 문자 분할의 유효성은 별개다. 기존의 같은 토큰
  꼬리 재결합 검증을 본문 Reflow 경로에서도 적용한다. 실제 같은 frame의
  채움이 더 적은 줄을 만들 때만 stale로 판정한다.
- 토큰 끝은 한글뿐 아니라 영숫자와 닫는 문장부호를 포함한다. 완결된 새
  어절, 명시적 개행, 쪽·단 경계, 외부 배제 영역과 독립 개체는 기존대로 보존한다.
- 마커 기하가 실제 paint와 같은 스타일의 글자 크기를 제공하고, frame은
  첫 물리 줄의 최대 글자 크기에 포함한다. 뒤 줄과 중간부터 재조판하는
  조각에는 마커를 중복 계상하지 않는다. 확정 행을 fit·paint가 함께 소비한다.
- 큰 기존 frame·배치 파일에는 작은 연결만 추가한다. 공통 토큰 판정은
  1000줄 미만인 `stored_word_tail.rs`에서 유지하며 전체 엔진 분할은 하지 않는다.

이 변경과 국어 저장 원점의 실제 점유 검증, PostScript 프로그램 식별을
한 후보로 묶어 빌드한다. 원본 전쪽 Native/fresh WASM, 같은 base, 정상
질문·번호·명시 개행 대조군과 전체 102문서를 확인한 뒤 회귀·완료를 판정한다.
