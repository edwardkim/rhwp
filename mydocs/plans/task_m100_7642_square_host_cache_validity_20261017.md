# #7642 어울림 호스트 저장 줄의 프레임 유효성

Issue: #7642.

## 입력과 독립 기준

[2027] 온새미로1 본교재의 원본 HWP/HWPX와 한컴2024 Print46쪽을 보존한다.
HWPX의 version.xml은 Hancom Office Hangul13.0.0.3622가 저장한 정상 입력이다.
수동 생성 캐시로 추정하지 않는다. 원본102문단은 다섯 저장 줄이지만 Print는
같은 내용179자를43/46/45/45자의 네 줄로 출력한다. 저장 줄만 지운 진단본도
독립 Print46쪽이며 같은 네 줄을 보였다. 원본을 수정하거나 진단본으로 대체하지 않는다.

기존 Native의 원본은 다섯 줄, 저장 줄 제거 진단은 네 줄이다. 진단도47쪽이다.
115문단은 fit85.33px로 잔여93.83px에 들어가지만 anchored/internal reset3 때문에
마지막 줄이 이월된다. source 줄은 일반 자동 reset이며 명시적 page-start bit는 없다.
본문 재조판 뒤 ladder dirty=true인데도 같은 사다리로 다음 쪽을 강제한 결과다.
위 px는 관측값이며 구현 조건으로 쓰지 않는다.

## 원인과 소비 경로

plan_square_table_host는 저장 줄 없는 호스트만 측정한 표의 배제 영역으로 채운다.
원본 저장 호스트는 이 프레임을 보지 않아 실제 줄 수·구간이 현재 프레임과 달라도
기존 캐시를 사용한다. 같은 단일 어울림 표의 실제 배제 영역으로 저장 줄의
수·가로 구간을 확인한다. 동일하면 기존 저장 소유를 유지하고, 다르면 공통
채움이 만든 줄과 끝점을 fmt·fit·배치가 함께 소비한다. 실제 쪽/단을 넘는
저장 사다리는 한 프레임이 소유하지 않으므로 기존 분할 소유자에게 남긴다.

저장 reset을 현재 본문 흐름의 증거로 쓰는 helper는 앞선 재조판으로 무효화된
사다리를 거절한다. 독립적인 명시적 page-start는 별도 기존 소유를 유지한다.
새 페이지 수를 정답으로 고정하거나 줄을 숨기지 않는다. 예산으로 수용할 범위와
이월을 결정하며 원문 순서·누락·중복을 검증한다.

## 반례와 검증

유효 저장 어울림 호스트의 같은 row key, 명시적 page-start, 실제 쪽/단 횡단,
다중 개체·다른 개체 소유, NO_LS와 정상 본문을 구분한다. 국어 세 문서의
마지막 간격 보정과 함께 다음 배치로 빌드한다. 원본 두 형식의 전쪽·Print쪽수,
관계·경계·확대 판독과102문서, #7969·#7970을 검증한다. 결과 전에는 해결이나
PR 준비 완료로 판정하지 않으며 새로운 실물 회귀는 전쪽90% 확인 후 추가한다.
