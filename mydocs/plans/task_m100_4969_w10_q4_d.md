## 1. 재검토 결론

Q4-C는 exact vertical shaping과 bbox·inline/column next origin을 한 `Arc`로 묶었지만 제품 module에
등록하지 않았고 caller·sidecar·paint publication도 0이다. 이 상태에서 `layout_vertical_cell_text`에
바로 호출을 추가하면 다음 네 권위를 한 번에 열게 된다.

1. `(charShapeId, languageIndex)` exact source를 vertical transaction에 인증하는 권위
2. legacy per-character column 대신 shaped run geometry를 commit하는 레이아웃 권위
3. `TextRun` fallback과 vertical `GlyphRun`을 같은 source로 게시하는 publication 권위
4. CanvasKit이 vertical-upright glyph positions를 선택하는 backend 권위

각 경계는 독립적으로 fail-closed해야 한다. 따라서 Q4-D를 D0~D5로 나누고, 각 결과 승인과
checkpoint 뒤에만 다음 절편으로 이동한다.

## 2. 현재 경로 감사

### 2.1 문서 의도

- HWP5 표 셀은 `Cell.text_direction`의 0/1/2를 보존한다. 최초 target은 code 2, 즉
  `vertical-rl + Latin upright` 의미를 가진 표 셀만 허용한다.
- HWPX 표 셀 parser·serializer는 현재 `HORIZONTAL`/`VERTICAL`만 code 0/1로 다루고
  `VERTICALALL`을 code 2로 보존하지 않는다. 따라서 HWPX 표 셀은 Q4-D target이 아니다.
- format version 번호로 분기하지 않는다. 현재 `Document` provenance와 실제 cell field, exact slot,
  run geometry를 feature detection한다.

### 2.2 레이아웃

`layout_vertical_cell_text`는 composed run을 문자 단위로 분해하고 font size 또는 반칸 휴리스틱으로
advance를 정한 뒤, 문자마다 `TextLine`과 `TextRun`을 만든다. Q4-C transaction과 page-local
sidecar는 아직 연결되지 않았다. 실패 뒤 legacy로 돌아갈 때 node id·bbox·children 순서까지 같아야 하므로,
`next_id()` 또는 tree mutation 전에 target 전체를 검증하고 한 commit 함수만 최종 mutation을 수행해야 한다.

### 2.3 publication·backend

- horizontal sidecar lowerer는 vertical y-position을 `VerticalPositioningAuthorityPending`으로 계속 거부해야 한다.
- nominal font lowerer, Rust layer selector, `text_v2`, Native Skia와 Studio CanvasKit replay는 현재 vertical
  orientation/writing mode를 각각 거부한다.
- 최초 backend는 explicit glyph positions를 재생할 수 있는 CanvasKit Browser/Studio와 Rust CanvasKit policy만
  연다. Native Skia·SVG·Canvas2D는 Q4-D에서 `TextRun` fallback을 유지한다.
- pure CJK upright만 대상이므로 `glyphTransforms`는 만들지 않는다. Latin sideways·mixed-per-glyph는 열지 않는다.

## 3. 최초 activation surface

다음 조건을 모두 만족할 때만 `boundedVerticalHwp5TableCellV1` 후보가 된다.

1. 현재 provenance가 HWP5 의미 계보이고 표 셀 `text_direction == 2`다.
2. one cell·one paragraph·one composed line·one text run·one column이다.
3. visible text가 pure CJK upright이며 공백·Latin·문장부호·mixed class가 없다.
4. run 전체가 같은 `char_shape_id`, language category, font size, 장평 1.0, 자간 0인 exact slot이다.
5. slot에 host가 등록한 공개 Noto Sans KR exact bytes와 face index가 있고 generation·SHA-256·길이가 일치한다.
6. bold/italic·합성 스타일·테두리/배경·겹침·field/note·tab·inline control·display projection·variation이 없다.
7. 한 열의 shaped bbox와 next inline/column origin이 cell inner area 안에서 유효하고 모든 glyph/cluster/resource
   상한을 만족한다.
8. request→shape→layout commit→sidecar→font resource→GlyphRun→CanvasKit 선택이 모두 성공한다.

한 조건이라도 실패하면 run 일부를 게시하지 않고 기존 per-character `TextRun` tree를 byte/canonical 동일하게
생성한다. parser나 font name이 exact source를 자동 등록하지 않으며 public API mode를 새로 추가하지 않는다.

## 4. target과 control

### target

기존 integration source 안에서 공개 Noto Sans KR를 exact slot에 등록한 HWP5-provenance synthetic document를
만든다. 한 셀·한 문단·한 run의 pure CJK 문자열과 `text_direction=2`를 사용하고, Q4-C oracle에서 계산한
glyph id·cluster·origin·bbox·next origin을 layer JSON까지 고정한다. binary fixture를 새로 위장 생성하거나
font name fallback을 사용하지 않는다.

### non-target control

- `samples/table-004.hwp`: code 2 의미·legacy output control. exact slot 미등록 상태에서는 활성화 0.
- `samples/issue6029/3200477_icao_procedure.hwpx`: code 1, 문자 보존·한 열 구조·roundtrip control.
- horizontal cell, HWPX cell, code 1, unknown raw, no exact source, stale/mismatched source
- multi paragraph/run/column, mixed CJK+Latin, punctuation, Latin sideways/upright, variation
- resource limit, cell overflow, sidecar duplicate/limit, unsupported backend

두 기존 sample의 canonical SVG/layer tree와 HWP/HWPX roundtrip은 Q4-D 전후 mismatch 0이어야 한다.

### Q4-D3 — atomic vertical GlyphRun publication

상세 정정 계획은
[`task_m100_4969_w10_q4_d3_revised.md`](task_m100_4969_w10_q4_d3_revised.md)를 따른다.
D2 target은 문자별 fallback leaf와 `TextSourceId`를 가지므로 줄 전체를 한 equivalence group으로 묶지 않는다.
대신 line 전체 publication을 한 transaction으로 준비하고 각 fallback leaf에 고유 `text-N` group과 한 glyph
candidate를 게시한다. 모든 leaf와 한 portable source가 준비된 경우에만 함께 commit한다.

1. D2 line sidecar와 exact source certificate를 한 번 대사해 portable font resource와 모든 leaf의
   vertical-upright `GlyphRun`을 mutation 없이 준비한다.
2. staged line subtree가 leaf/source/cluster/variant 검증을 통과한 뒤에만 subtree와 resource delta를 게시한다.
3. 각 `TextRun` fallback은 그대로 남고 equivalence group은 leaf를 가로지르지 않는다.
4. 성공한 line의 source id만 nominal lowerer slot에서 claim한다. 실패하면 resource·variant·claim 0이다.
5. horizontal lowerer와 Rust·Studio backend selector의 vertical authority pending은 변경하지 않는다.

**종료 게이트**: target `N TextRun + N GlyphRun`, leaf별 equivalence group `N`, portable resource 1,
resource mismatch 0, failed publication residue 0, horizontal publication mismatch 0, backend false selection 0.

상세 절차는 [`task_m100_4969_w10_q4_d4.md`](task_m100_4969_w10_q4_d4.md)를 따른다.

1. Rust CanvasKit policy와 Studio replay는 진단 provenance가 `boundedVerticalHwp5TableCellV1`이고
   `vertical-rl + vertical-upright + no transforms`인 candidate만 선택한다.
2. glyph ids·positions·font resource를 그대로 재생하고 backend에서 reshape하지 않는다.
3. Native Skia·SVG·Canvas2D와 vertical-sideways/mixed candidate는 기존 reason으로 `TextRun` fallback한다.
4. Node WASM layer JSON과 Studio CanvasKit pixel E2E에서 target exact position·bbox를 대사한다.

**종료 게이트**: target CanvasKit selection/pixel mismatch 0, unsupported backend false selection 0,
fallback disappearance 0.

## 6. 보호 불변식

1. no exact source·horizontal·HWPX·code 1·unknown intent output은 바뀌지 않는다.
2. format build number가 아니라 현재 provenance·field·source capability·geometry를 판정한다.
3. parser/font name/fallback matrix는 activation authority가 아니다.
4. layout과 paint가 서로 다시 측정하거나 backend가 reshape하지 않는다.
5. run 일부, glyph 일부, resource 일부를 게시하지 않는다.
6. horizontal `VerticalPositioningAuthorityPending`을 전역 해제하지 않는다.
7. private corpus·Hyper-V는 사용하지 않는다. 공개 synthetic와 추적 sample만 사용한다.
8. commit·push·GitHub comment·PR은 각각 별도 승인 전에는 수행하지 않는다.
