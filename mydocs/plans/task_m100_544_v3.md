## 본질 가설 (1차)

**박스 안 sequential paragraph 의 prev 마지막 줄 trailing-ls 가 누락**.

근거:
1. **p11 의 14.66 px = 정확히 line_height 1100 HU** (`lh=1100`, `ls=716` 중 line_height 만 적용, ls 완전 제외)
2. Task #479 의 trailing-ls 제외 메커니즘이 `is_full_paragraph_end && cell_ctx.is_none() && !next_starts_border` 분기에서 작동
3. 박스 안 sequential paragraph 사이는 prev/next 둘 다 같은 박스 outline → next 가 "border 시작" 이 아님 → `next_starts_border = false` → trailing ls 제외 발동

p2/5 는 -5~6 px (부분 제외):
- 가설 A: `lazy_base` (Task #537 영역) 가 일부 보정
- 가설 B: prev paragraph 의 마지막 줄 line_spacing 값이 다른 paragraph 의 평균과 다름
- → Stage 1 정밀 진단으로 확정

## 수정 방향

### Phase A — 박스 안 sequential paragraph 의 trailing-ls 보존

paragraph_layout.rs 의 `is_full_paragraph_end && cell_ctx.is_none() && !next_starts_border` 분기에 추가 가드:

```rust
// [Task #544 v3] 박스 안 sequential paragraph 사이는 trailing-ls 보존.
// next_starts_border 는 border 가 새로 시작될 때만 true (Task #552). 이미
// border 진행 중인 sequential paragraph 는 false 라 본 가드에서 trailing-ls
// 제외됨 → 시각적 line spacing 부족. 추가 가드 next_para_continues_border 도입.
```

방법 1: layout.rs 에 새 Cell `next_para_continues_visible_border` 도입. paragraph 가 prev paragraph 와 같은 border_fill_id + 같은 box outline 이면 set.

방법 2: `next_starts_border` 의 정의 확장 — "border 가 새로 시작" → "다음 paragraph 가 border 가짐 (시작 + 진행 중 모두)".
