## 1. 증상

`samples/pic2.hwp` (HWP5, 2 페이지) 의 페이지 1 layout 이 한컴 viewer (pic2.pdf) 와 매우 다름.

| 항목 | rhwp 결과 | 한컴 PDF (정답지) |
|------|----------|------------------|
| 페이지 수 | 2 | 2 |
| paragraph 0 ("우리나라") 위치 | 위쪽 가로 ("라/대한민국" 식 잘못된 layout) | 우측 세로 (한 char 1 line) |
| 의자 그림 2개 배치 | 위쪽 가로 (둘 다 위쪽) | 좌측 큰 + 우측 위 작은 (분리) |
| paragraph 22 ("SK하이닉스 성과급이...") | 페이지 1 끝 (LAYOUT_OVERFLOW 88.8 px) | 페이지 2 시작 (정상) |
| 페이지 2 layout | 거의 정합 | (정상) |

## 2. 1차 진단 결과

### 2.1 paragraph 0 정밀 정보

```
--- 문단 0.0 --- cc=38, text_len=5, controls=4 [구역나누기]
  텍스트: " 우리나라"
  [CS] pos=0 id=0 (공백) + pos=33 id=7 (한글)
  [PS] ps_id=0 align=Justify line=160/Percent
       margins: left=0 right=0 indent=0 border_fill_id=2
  ls[0~7]: 8 line_segs (ts=0/33/34/34/35/35/36/36, cs/sw=24470/2570 또는 39123/3397)
  [0] 구역정의 (SectionDef)
  [1] 단정의 (ColumnDef)
  [2] 그림 82.5×104.4mm Square wrap, 용지(33.8mm, 34.9mm), z=1
  [3] 그림 42.6×53.9mm Square wrap, 용지(125.4mm, 34.9mm), z=0
```

paragraph 0 의 line_seg 8개 — wrap zone 분할 (그림 옆 좁은 영역).

### 2.2 ROOT CAUSE 후보

| 후보 | 영역 | 우선순위 |
|------|------|---------|
| H1 | Square wrap 그림 옆 wrap zone 의 layout 처리 (column_start / segment_width) | 높 |
| H2 | paragraph 0 의 line_seg ts 가 같은 char 반복 (ts=34/34, 35/35, 36/36) — 8 line wrap 처리 | 높 |
| H3 | paragraph 별 누적 height 계산 차이 → paragraph 22 LAYOUT_OVERFLOW | 중 |
| H4 | 그림 2개 (큰 + 작은) 의 paper 좌표 layout | 중 |

paragraph 0 의 layout 본질 = "그림 2개 사이/주위에 텍스트 wrap" 처리. 한컴 의 layout 결과:
- 의자 그림 (큰): 좌상단, 의자 그림 (작은): 우상단
- 두 그림 사이/위: "우리나라" 첫 char 단위 세로 정렬 ("우/리/나/라")
- 두 그림 아래: paragraph 1 "대한민국"
- 이후 paragraph 2~ "서울 경기도..." 본문

rhwp 의 layout 결과:
- 의자 그림 2개 위쪽 가로 배치
- "라/대한민국" 식 잘못된 텍스트 위치
- 본문 가운데 (paragraph 7~ "SK하이닉스가..." 정합)
- 무용수 그림 우측 아래 (paragraph 7 의 그림)

핵심: paragraph 0 의 wrap zone 처리 + paragraph 0 본문 텍스트 위치 차이.

## 3. 진행 전략

### 3.1 진단 절차

1. **paragraph 0 의 정확한 layout 흐름 추적**:
   - rhwp 의 line_seg ts=0/33/34/34/35/35/36/36 의 SVG x/y 좌표 계산
   - 한컴 PDF 의 "우/리/나/라" 세로 배치 좌표 추출 (pdftohtml)
   - rhwp 가 어떤 위치에 paragraph 0 의 char 들을 배치하는지 정량 측정
2. **paragraph 0 의 wrap zone (cs/sw) 의 의미 분석**:
   - cs=24470, sw=2570 → x=24470, width=2570 hwpu = 좁은 영역
   - cs=39123, sw=3397 → x=39123, width=3397 hwpu
   - 그림 2개의 외곽 영역과 어떻게 매칭되는지
3. **그림 2개의 layout 좌표 vs paragraph 0 의 wrap zone 의 관계 분석**
4. **paragraph 22 LAYOUT_OVERFLOW root cause 추적**

### 3.2 가설 검증

| 가설 | 검증 방법 |
|------|----------|
| H1: Square wrap 의 cs/sw 처리 부정확 | line_seg cs/sw 와 그림 외곽 영역 비교 |
| H2: line_seg ts 의 같은 char 반복 처리 부정확 | composer 의 wrap zone 분할 코드 추적 |
| H3: 누적 height 계산 | dump-pages 의 vpos 값과 한컴 정합 비교 |
