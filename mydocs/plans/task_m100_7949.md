## 1. 목표와 통합 범위

기본 빌드로 PDF를 가져오고, 한컴에서 생성한 명시적 1비트 이미지 마스크를 포함한 PDF를
투명 영역까지 보존해 표시한다. 두 이슈는 한 작업 브랜치·통합 PR로 처리하며 이슈별 변경과
완료 조건을 구분한다. #7911의 기반과 #7946 / #7947의 Studio 직접 열기를 재사용한다.

| 이슈 | 변경 범위 | 완료 판정 |
| --- | --- | --- |
| #7949 | Cargo 기본 feature, 기본 Native·Docker WASM·패키징 소비 경로, 명시적 feature-off와 안내·검사 | 추가 feature 지정 없이 PDF 지원. 명시적 제외 빌드와 기존 HWP/HWPX 계약 보존 |
| #7950 | 요청 예산을 사용하는 명시적 1비트 Mask와 추가 승인된 이미지 SMask·Matte 합성 | 두 재현 PDF 정상 열기, 투명 영역·그림 배치 보존, 손상·자원 한도·미지원 범위의 명시적 오류 |

기본 활성화만으로 마스크 오류가 해결됐다고 판정하지 않는다. 반대로 마스크 보정만 한
feature-on 검증으로 기본 빌드의 PDF 지원을 주장하지 않는다.

## 2. 현재 관측과 기준

- 같은 증상의 열린 이슈·PR을 검색한 뒤 #7949·#7950을 각각 등록하고 양쪽 본문을 연결했다.
  assignee·milestone·label·한글 본문을 API로 재조회해 확인했다.
- 기본 `Cargo.toml`의 `default`에는 `console_error_panic_hook`만 포함된다.
  `--features pdf-import`를 지정한 Docker WASM에서는 실제 capability가 true이고 Studio가
  공개 PDF `pdf/issue5875/nested_table_text_caption-2020.pdf`를 12쪽으로 연다.
- 사용자 PDF `/mnt/e/tmp/261016-mof-69009.pdf`는 같은 PDF-on WASM에서도
  `PDF_IMAGE_UNSUPPORTED`로 실패한다. 1쪽·194,530바이트이며 SHA-256은
  `b8927f6c493b5c4f276a52a847726aa1be1ec3848547ace78bf06ae876daf765`다.
- 그 PDF의 RGB JPEG 객체 12·16·196·199는 `/Mask`로 11·15·195·198을 참조한다.
  마스크는 같은 크기의 `/ImageMask true`, `/BitsPerComponent 1`, `/FlateDecode` 스트림이다.
  독립 Poppler 출력에서는 정상 표시된다. 전체 PDF 원본을 배치·투명 영역의 독립 기준으로 쓴다.
- `PdfImageHandle::decode()`가 요청 예산이 있는 경로에서 비어 있지 않은 `/Mask`를 거절한다.
  제품 extract가 이를 일반 codec/mask 미지원 메시지로 바꾼다. 제한 해제나 마스크 무시는 해결이 아니다.

기존 진단은 기본 작업공간의 ignored `output/pr-review/pdf-image-mof-69009-20261016/`,
7700 PDF-on 빌드 확인은 `output/pr-review/issue7946/studio-7700-20261016/`,
이슈 등록·API 재확인은 `output/pr-review/pdf-default-mask-20261016/`에 보존한다.
원본 PDF의 공개 출처·재배포 권한은 확인되지 않았으므로 자동 업로드하지 않는다.

## 3. 진행 순서

1. 통합 계획의 승인을 받은 뒤 #7950의 마스크 해석·합성을 먼저 보정한다. 요청 예산과
   Decode·행 패딩·오류 경계를 작은 실행으로 확인하고 변경 영역의 Native 출력을 대조한다.
2. #7949의 기본 feature와 실제 소비 경로·안내를 갱신한다. 명시적 feature-off 검증 입력은
   기본 빌드와 구분한다. 이슈별 변경을 추적 가능한 commit으로 남긴다.
3. 최종 통합 소스에서 기본 Native와 기본 Docker WASM을 만들고 실제 Studio 열기·드롭을
   검증한다. source·실제 fetch WASM·루트 pkg/public SHA를 연결한다.
4. 두 PDF 대조군의 전쪽 Native/fresh WASM TSV와 직접 판독을 완료한 뒤 필요한 정식 회귀를
   추가하고 변경 범위별 필수 검사·보고·승인된 PR 제출 절차를 진행한다.

상세 경계·소비 경로·반례는 [공동 구현계획](task_m100_7949_impl.md)을 따른다.

## 4. 통합 완료 조건과 경계

- 사용자 재현 PDF 1쪽과 공개 대조 PDF 12쪽이 기본 Native/Docker WASM에서 열리고,
  전쪽 각각 90% 이상·쪽수 일치·누락 없음과 로고·투명 영역·crop 직접 판독을 확인한다.
- feature-off의 미지원 안내·HWP/HWPX 열기와 실패 뒤 현재 문서 보존·다음 정상 입력 복구를 확인한다.
- 마스크 참조·길이·Decode·자원 초과는 지원 여부와 구분해 오류를 유지한다.
  새로운 렌더링 회귀는 시각 선행 조건 충족 후 추가하며 기존 기준을 완화하지 않는다.
- `parserAllocationBoundsProven=false`와 미완료 할당 감사는 유지한다.
  색상 키 Mask 배열·graphics-state SMask·독립 stencil·OCR·의미 복원·Worker 편집기 전환은 별도 범위다.
- 패키징 소비 경로의 빌드 검증과 실제 npm/스토어 배포는 구분한다. 현재 승인은 이슈 등록과
  공동 처리 준비이며 원격 push·PR 생성·배포·merge 승인을 대신하지 않는다.
- 기존 #7911 작업공간, 실행 중인 기본 Studio 7700과 공유 `target/pr-review`를 보존한다.
