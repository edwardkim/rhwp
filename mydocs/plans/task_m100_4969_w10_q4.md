## 1. 수정 이유

상위 계획은 Q4에서 vertical table을 읽고 `vert`/`vrt2`를 적용한 뒤 제품 좌표를 검증하는
순서였다. 인수 감사 결과, capability 검증은 있지만 exact top-to-bottom output oracle은 없고,
HWP5·HWPX·표 셀·글상자·구역의 vertical 의도가 서로 다른 표현으로 저장되며 일부는
현재 IR/layout 경계에서 합쳐진다.

따라서 "vertical table이 있으면 기존 세로쓰기를 exact shaping으로 교체"하지 않는다. output oracle을
먼저 고정하고, 문서 의도와 OpenType writing mode를 typed contract으로 연결한 뒤, dormant
transaction에서 geometry 전체를 검증한다. 최초 제품 activation은 증명된 한 subset만 열고
나머지는 기존 결과로 atomic fallback한다.

## 2. 보호 불변식

1. no-request·horizontal Q2/Q3 output, line break, bbox, backend selection을 바꾸지 않는다.
2. `vhea`+`vmtx`가 없으면 vertical request를 구조화 reason으로 거부한다.
3. CFF vertical origin에 `VORG`가 필요한 경우 추정 origin으로 조용히 대체하지 않는다.
4. HWP/HWPX version이 아니라 현재 필드·table·glyph 결과를 feature detection한다.
5. `Cell.text_direction` 또는 `TextBox.list_attr`의 raw 숫자를 바로 OpenType writing mode로 해석하지 않는다.
6. `VERTICAL`·`VERTICALALL`, 영문 눕힘·세움, RL·LR column progression을 서로 합치지 않는다.
7. `vert`/`vrt2` GSUB glyph identity와 vertical GPOS·vmtx position을 Unicode 치환·font-size advance가
   정확하다고 간주하지 않는다.
8. shaping owner가 결정한 glyph·cluster·advance·offset·origin을 layout·bbox·hit-test·backend가
   같이 소비한다.
9. font 32 MiB, text/glyph/position 4,096, feature·cache·trace의 현재 bounded 상한을 유지한다.
10. 추적 공개 font·fixture만 PR 증적에 사용하고 private corpus identity를 기록하지 않는다.

## 3. 실행 절편

### Q4-A — exact vertical output oracle contract

1. Noto Sans KR TTF와 Source Han Serif K OTF의 top-to-bottom 결과를 native oracle로 고정한다.
2. pure CJK, Latin, CJK punctuation을 분리해 glyph id, cluster, x/y advance, x/y offset을 기록한다.
3. default feature와 explicit `vert`/`vrt2` on/off를 분리해 자동 적용을 추정하지 않는다.
4. Noto의 no-VORG 경로와 Source Han의 VORG 경로를 분리한다.
5. Happiness Sans VF의 `VerticalMetricsUnavailable`과 malformed/mismatch/bounded rejection을 control로 유지한다.
6. Q0 face inventory의 현재 TTF/OTF source readiness를 추가하되 historical WOFF2 판정은 보존한다.

**종료 게이트**: 같은 exact source·request의 native 재실행 output mismatch 0, 음성 거부 변화 0,
제품 caller·layout·paint 변경 0. 이 결과 승인 전에 Q4-B를 시작하지 않는다.

**결과**: [Q4-A 결과 보고서](../working/task_m100_4969_w10_q4_a.md)의 native 19/19·Node WASM
3/3·음성 control·source readiness 현행화를 근거로 `qualified-standalone-vertical-oracle`로
판정했다. product caller·layout·paint 변경은 0이다.

### Q4-B — 표면별 typed vertical intent

1. 표 셀, 글상자, 구역, 바탕쪽의 raw 값을 서로 다른 source intent로 inventory한다.
2. HWP5 0/1/2와 HWPX `HORIZONTAL`/`VERTICAL`/`VERTICALALL`의 roundtrip·layout 의미를 분리한 typed
   adapter 계약을 red fixture로 고정한다.
3. `samples/table-004.hwp`, `samples/hwpx/tbox-v-flow-01.hwpx`, 변환 HWP, 추적 PDF,
   `samples/issue6029/3200477_icao_procedure.hwpx`를 각각 semantic·roundtrip·legacy regression control로
   분류한다.
4. 공식 스키마와 추적 쌍으로 VERTICALALL 의미를 판정할 수 없을 때만 Hyper-V
   한컴을 사용할 최소 adjudication 계획을 별도 승인받는다.
5. 지원하지 못한 raw 값은 horizontal로 바꾸지 않고 typed unsupported로 유지한다.

**종료 게이트**: 표면별 source intent→writing mode→Latin orientation mapping이 하나의 표와 음성
fixture로 고정되고, HWP/HWPX roundtrip regression 0. 이 단계에서도 product activation 0.

**결과**: [Q4-B 결과 보고서](../working/task_m100_4969_w10_q4_b.md)에서 OWPML 스키마와
한컴 HWPX↔HWP5 쌍으로 `VERTICALALL == HWP5 code 2 == Latin upright`를 판정했다. typed
contract 3건을 포함한 focused 22/22, 표 셀·글상자 왕복 regression 0, legacy HWPX/HWP SVG mismatch
0을 확인했다. 제품 parser·IR·layout activation은 0이며 기존 의미 손실은 Q4-C 이후의 표면별
변경 대상으로 남겼다.

### Q4-C — dormant vertical layout transaction

1. Q4-A glyph result와 Q4-B typed intent를 vertical 전용 transaction에 연결한다.
2. RL/LR column progression, vertical advance/origin, glyph bbox, next origin, cluster source range를 한 번에
   결정한다.
3. CJK upright, Latin sideways/upright, punctuation substitution을 별도 homogeneous run으로 먼저 검증한다.
4. mixed run은 경계·fallback이 증명될 때까지 unsupported로 닫는다.
5. horizontal lowerer의 `VerticalPositioningAuthorityPending`을 전역 제거하지 않고 vertical transaction이
   소유한 payload에만 전용 lowering을 허용한다.

**종료 게이트**: dormant output의 measurement·bbox·next origin mismatch 0, product consumer 0,
horizontal control byte/canonical mismatch 0.

**결과**: [Q4-C 결과 보고서](../working/task_m100_4969_w10_q4_c.md)의 단일 geometry owner가
old Hangul·Latin sideways/upright·punctuation의 glyph origin·bbox·inline/column next origin을
결정한다. native 27/27, 격리 Node WASM 4/4, focused Clippy를 통과했으며 mixed run·missing vertical
metrics·variation bbox는 pristine fallback으로 원자 거부한다. 제품 module 등록·consumer·publication은 0이다.
메인테이너가 `qualified-dormant` 판정을 승인했으며 이 commit을 Q4-C checkpoint으로 고정한다.

### Q4-D — 한 표면 bounded atomic activation

> 구현 전 감사에서 exact source 인증·layout commit·vertical publication·CanvasKit 선택이 서로 다른
> 실패 경계임을 확인했다. HWPX 표 셀은 `VERTICALALL` 의미를 아직 보존하지 않으므로 최초 target에서
> 제외하고, [Q4-D 수정 수행계획](task_m100_4969_w10_q4_d.md)의 D0~D5로 나눈다.

1. exact source와 typed intent가 둘 다 있는 공개 synthetic fixture에서 한 표면만 선택한다.
2. 권고 순서는 표 셀 one-cell·one-paragraph·one-run·one-column homogeneous CJK이다. exact source
   결속을 증명하지 못하면 activation 대상으로 승격하지 않는다.
3. request·shape·layout·publish·backend 선택이 모두 성공할 때만 새 output을 원자적으로 게시한다.
4. 일부만 성공하거나 source·intent·backend proof가 없으면 런 전체를 기존 legacy output으로 돌린다.
5. #6029 공개 fixture와 table-004 HWP의 문자 보존·열 구조·roundtrip을 non-target control로 둔다.

**종료 게이트**: target fixture exact vertical position mismatch 0, partial publication 0, 기존 세로쓰기
fixture regression 0. 표 셀 activation이 증명되지 않으면 Q4를 dormant/bounded-subset으로 판정한다.

**진행**: D0 red baseline 승인·checkpoint 뒤 D1은 exact source snapshot·handle·generation·bytes `Arc`를
인증하는 dormant context를 제품 module에 등록했다. [D1 결과 후보](../working/task_m100_4969_w10_q4_d1.md)는
native 30/30·격리 wasm32+Node 1/1·표준 Docker WASM build를 통과했으며 제품 caller/publication은 0이다.
D2~D4의 세 activation 경계는 red로 유지된다. 메인테이너가 D1 결과와 checkpoint 진행을 승인했으며,
새 `upstream/devel@7592e9c99` 동기화·재검증 뒤 D2 착수를 별도로 승인받는다.

### Q4-E — 확장 판정·에디터 좌표 분리

1. text box, section, master page, Latin, punctuation, mixed run을 각각 독립 변경 이유로 판정한다.
2. caret·selection·hit-test·cursor navigation은 renderer bbox 정합과 분리한 editor 계약으로 검증한다.
3. 한 항목이 별도 사용자 여정·oracle·rollback을 필요로 하면 #4969 후속 issue로 분리한다.
4. Q4-D의 지원 subset을 확장하지 않고도 Q4 판정과 Q5 인계가 가능하게 한다.

**종료 게이트**: 각 표면이 `qualified`, `bounded-subset`, `dormant`, `blocked`, `follow-up`로
분류되고 분리 근거가 남는다.

### Q4-F — Q5 인계 checkpoint

1. supported/unsupported vertical matrix와 source·intent·backend reason을 전건 회계한다.
2. 최종 공개 fixture digest, canonical glyph/position, legacy controls을 기계 판독 증적으로 고정한다.
3. Q5에서 측정할 backend parity·wall time·WASM size·resource 상한을 Q4 실제 지원 subset으로 재정의한다.
4. 결과 승인과 checkpoint 승인을 분리한다.

## 5. 검증 계획

각 절편은 focused test·native/Node WASM canonical output·negative reason을 먼저 검증한다. renderer/layout
변경 이후에는 실제 변경 범위에 따라 native Skia, Docker WASM, Studio CanvasKit, SVG/Canvas2D,
hit-test 게이트를 선택한다. 전체 PR gate는 Q4 결과 승인 뒤 PR 준비 승인을 별도로 받아
실행한다.

모든 commit·push 직전에는 다음을 실행한다.

```bash
cargo fmt --all
cargo fmt --all -- --check
```

`src/**` `#[cfg(test)]` 변경 시 `node scripts/rust-unit-test-tiers.mjs --check`를 추가한다. 새 integration
source는 `tests/cases/` 원본만 제출하고 generated suite·manifest·Cargo marker를 stage하지 않는다.

## 7. 최종 판정

Q4 완료는 "모든 세로쓰기 지원"을 의미하지 않는다. exact source·typed intent·vertical table·geometry·
backend proof가 모두 있는 subset만 `qualified` 또는 `bounded-subset`으로 선언한다. 의미·source·
좌표 계약 중 하나라도 없으면 `dormant`/`blocked`/`follow-up`으로 남겨 Q5가 허위의
backend parity를 측정하지 않게 한다.
