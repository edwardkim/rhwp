# #8153: 일반 행의 이어받은 물리 상자와 쪽 끝 빈 띠

## 선행 해결과 현재 원본

원 해결 이슈 [#7764](https://github.com/edwardkim/rhwp/issues/7764)의 본문·전체 댓글,
통합 PR [#7882](https://github.com/edwardkim/rhwp/pull/7882)와 후속
[#8191](https://github.com/edwardkim/rhwp/pull/8191)의 본문·전체 댓글을 확인했다.
원 구현 `5d22772bf168396806e44bd41e567bd81a316445`의 통합 검토 진행 95·97과
현재 `stored_ordinary_row_frame.rs`를 대조했다. 원 계약은 내용 컷·선언 최소·실제 수용
상자를 구분하고, 이미 받은 상자를 뺀 잔여와 같은 컷의 내용 요구를 함께 보존하는 것이다.
이 조사로 다른 문서의 활성 제외를 되돌리거나 새 보정 대상으로 늘리지 않는다.

현재 두 편람 원본의 312쪽은 section 11, para 3의 103행×2열 표 안에서 같은 5행을
이어받는다. HWPX의 `pageBreak="CELL"`은 현 parser의 원래 RowBreak 계약이다.
두 칸은 TOP 정렬, 높이 90,787HU이며 왼쪽 56줄·오른쪽 빈 줄 1개를 가진다.
왼쪽 저장 줄의 10·33번째 유닛은 실제 원점 0으로 재시작한다. 수동 합성 메타데이터가 아니다.
원본·독립 PDF·측정 임계값을 바꾸지 않는다.

고정 `b8ca19e50d`의 실제 dump와 Native PNG에서 다음을 확인했다.

- 311쪽은 내용 컷 `[]→[10,1]`을 소유하고 다음 쪽에 물리 잔여 986.64px를 전달한다.
- 312쪽은 `[10,1]→[33,1]`, 행 상자 483.106667px를 받는다. 반복 머리행 60.64px를
  더한 실제 점유 543.746667px가 Native tree와 일치한다. 다음 잔여는 503.533333px다.
- 해당 세로선의 Native paint 끝은 637.524px, 독립 2024 Print는 644.264px다.
  6.74px 부족하며 같은 내용 컷의 빈 물리 밴드가 문제다. 첫 조각과 마지막 내용 소유,
  뒤 행·꼬리말을 함께 확인해야 한다. 점수만으로 종료하지 않는다.

## 공통 생산·소비와 보정 방향

`원본 일반 행·저장 컷 → scan의 physical available 및 끝 행 상자 → consumed/
end_row_height_override/split_end_reserved → emit의 PageItem과 실제 수용 원장 →
다음 start_row_height_override → 부분 표 paint`를 실제 호출 위치로 추적했다.

`scan_table_fragment`의 refit 뒤 호출하는 `stored_ordinary_row_end_frame`은 일반 행의
첫 조각에만 물리 공간을 배정한다. 원본 컷·수용 잔여가 있어도 `start`가 비어 있지 않으면
거절한다. 아래 emit의 잔여 계산은 이미 전달된 같은 행의 상자에서 현재 실제 상자를
차감하므로, 별도 좌표 보정 대신 스캔이 그 잔여를 소비하게 하는 방향을 검증한다.

첫 조각은 기존 독립 선언·남은 프레임 검증을 유지한다. 이어받은 조각은 원본 일반 행과
유효한 저장 컷, 같은 행이 이미 수용한 물리 잔여를 함께 확인한 뒤 같은 상자 선택을
소비한다. 원본 전체 높이로 되돌아가 앞 상자를 다시 예약하지 않는다. 세 쪽 이상을
차지하는 행도 같은 원장 계약으로 다룬다. 새로 들어온 행은 앞 행의 잔여를 쓰지 않는다.
편집·재조판·합성 저장 줄·중첩 개체·rowspan의 기존 별도 계약을 넓히지 않는다.

본문 하단·반복 머리행·각주·캡션·바깥 여백은 이미 계산한 같은 available을 사용한다.
PDF에서 읽은 644.264나 페이지·행 번호를 제품 조건에 넣지 않고, source 최소와 현재
물리 예산의 결과를 스캔·예약·배치가 공유하게 한다. 세로선만 늘리는 paint 보정이나
clamp는 하지 않는다. HWP의 셀 높이는 최소 점유라는 기존 설명·실측을 따르며, 사양의
이름에 없는 임의의 페이지별 여유 수치를 추가하지 않는다.

## 재현과 검증

1. 정식 테스트 초안은 ignored 작업 자료에서 준비한다. 고정 `b8ca19e50d` 라이브러리로
   두 원본의 실제 312쪽 세로선 끝에서 FAIL을 확보한 뒤 같은 원문으로 후보를 확인한다.
   저장 컷·셀 소유·중복/누락, 독립 Print의 ±2px 끝점과 앞뒤 내용 관계를 함께 보호한다.
2. 312·316~320·326~327·344~345·352~354쪽 및 각 앞뒤 종료·후속 쪽을 먼저 Native로
   비교한다. 쪽수와 내용 컷을 함께 대조하고, 새 빈 쪽·누락·중복·변경 외 쪽의 하락을
   확인한다. 기존 일반 행·병합 종료·작은 줄간격 꼬리·큰 빈 최소 공간 검사도 대조한다.
3. 같은 code head의 표준 fresh WASM과 전쪽 TSV·대표 review/overlay를 확인한다.
   현재 source의 두 문서 전쪽 Native/fresh WASM 90% 이상과 해당 쪽 98% 이상을 유지한다.
   기존 유효한 회귀의 기대값·허용치·baseline을 낮추지 않는다.
4. 전 1,532조건 raw 100%·정수 미대응 0 및 필수 최종 테스트까지 계속한다. 원격 게시·
   push·PR 생성·upstream/devel 동기화 없이 PR 준비까지만 마친 뒤 대기한다.

현재 표준 WASM은 별도 검증 worktree의 고정 `b8ca19e50d`에서 최적화 중이다. 해당
worktree와 공용 target은 보존하며 Cargo/rustc/wasm-opt를 겹쳐 실행하지 않는다.
