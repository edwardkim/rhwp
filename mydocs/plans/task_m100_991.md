# 수행계획서 — 글자처럼 취급 인라인 표가 빈 문단에 단독 앵커 시 렌더링 누락

- 타스크: 로컬 task991 (GitHub 이슈 미발행 — 비공개 문서 검증 사안이라 로컬 번호로 진행)
- 브랜치: `local/task991` (`local/devel`에서 분기)
- 마일스톤: M100 (v1.0.0)
- 작성일: 2026-05-19

## 1. 배경

비공개 샘플 HWPX 문서(공공기관 제안요청서)를 SVG로 내보낸 결과와 한컴 2022 PDF 권위 자료를 비교하던 중 두 가지 불일치를 발견했다.

1. **본문 표 블록 누락** — `treat_as_char=true`(글자처럼 취급) 표 1개가 SVG 결과 전체(180쪽)에서 통째로 사라짐.
2. **페이지 수 누적 드리프트** — SVG 180쪽 vs PDF 179쪽. 표 셀/줄 높이 정밀도 차이가 문서 전반에 ±1쪽씩 누적된 결과로, 거의 상쇄되어 순 +1쪽.

본 타스크는 **(1) 표 누락 버그만** 다룬다. (2)는 성격이 다른 정밀도 사안이므로 별도 타스크로 분리한다.

## 2. 문제 정의

`treat_as_char=true` 표가 **본문 텍스트가 없는 빈 문단**(`text_len=0`, 컨트롤은 표 1개뿐)에 단독 앵커된 경우, SVG 렌더 결과에서 표의 **테두리와 셀 내용이 모두 그려지지 않는다**.

해당 표: 섹션 0 문단 103, 1행×1열, 156.0×44.2mm, 셀 안에 5개 문단(불릿 목록).

## 3. 현재까지의 원인 분석

각 단계를 `rhwp dump` / `dump-pages` 로 추적한 결과:

| 단계 | 상태 | 근거 |
|------|------|------|
| 파서(IR) | **정상** | `dump`: 1행×1열 표 + 셀 5개 문단 텍스트 모두 존재 |
| 페이지네이션/레이아웃 | **정상** | `dump-pages`: 표가 6→7쪽에 `PartialTable`로 분할 배치됨. 6쪽 `split_end=41.0`, 7쪽 `cont=true split_start=41.0`. 세로 공간도 정상 예약 |
| 렌더러(SVG 출력) | **버그** | 분할 배치된 표의 테두리·셀 문단이 SVG 노드로 방출되지 않음. 셀 텍스트가 180쪽 어디에도 없음 |

원인 가설: 렌더러가 `PartialTable`(쪽 분할된 표)을 렌더 노드로 변환하는 경로에서, `treat_as_char=true` 표(특히 빈 문단 단독 앵커 케이스)를 누락한다. `is_tac_table_inline`은 이 표를 인라인이 아닌 블록으로 판정하므로(텍스트 없음 + TAC 표 1개 → `false`), 블록 표 경로를 타야 하지만 분할 렌더 경로에서 빠지는 것으로 보인다.

정확한 누락 지점(typeset.rs / layout/table_layout.rs 중)은 구현계획서 1단계에서 코드 추적으로 확정한다.

## 4. 검증 방법

- 코드 수정 없이 재현·검증 가능: `rhwp export-svg` → 셀 텍스트("☞"로 시작하는 5개 불릿)와 표 테두리가 SVG에 나타나는지 확인.
- `dump-pages`로 레이아웃 항목이 수정 전후 동일한지 확인(레이아웃 회귀 없음 보장).
- 기존 골든 SVG 테스트(`tests/golden_svg/`)·`cargo test` 전체 통과.
- 다른 TAC 표/분할 표 케이스에 회귀가 없는지 기존 샘플로 교차 확인.

## 5. 작업 범위

- 포함: `treat_as_char` 표가 빈 문단 단독 앵커 + 쪽 분할된 경우의 렌더링 누락 수정.
- 제외: 페이지 수 ±1 누적 드리프트(별도 타스크), HWP3 경로.
- 수정 대상 예상 모듈: `src/renderer/` (typeset.rs 또는 layout/table_layout.rs). 공통 문서 모델·파서는 정상이므로 손대지 않는다.

## 6. 단계 개요 (상세는 구현계획서에서 확정)

1. 렌더러의 `PartialTable` / `treat_as_char` 표 렌더 경로 코드 추적 → 누락 지점 확정.
2. 누락 수정 구현.
3. 검증(SVG 재현·골든 테스트·교차 회귀) + 최종 보고서.

## 7. 비공개 문서 처리

재현에 쓰는 HWPX/PDF는 **비공개 문서**다. git에 커밋하지 않는다. 테스트 픽스처가 필요하면 공개 가능한 대체 샘플을 찾거나, 불가 시 픽스처를 비커밋 처리하고 보고서에 명시한다. 본 계획서 등 문서에는 파일명·기관명 등 식별 정보를 적지 않는다.
