# #7065 셀 문단 편집 중 형제 표 겹침 보완

2026년 11월 28일. 작업 브랜치 `task/7065-cell-edit-table-pagination`, 구현 기준 `upstream/devel` `ea9f0bb7a044a9cdb537d3c3a13502bece2d0e2c`.

## 문제와 범위

[#7065](https://github.com/edwardkim/rhwp/issues/7065)는 [#7101](https://github.com/edwardkim/rhwp/pull/7101)의 문단 복사·저장 작업에서 분리됐다. [당시 진단](../working/task_m100_3587_stage7.md#enter-6회-경계-재검증--후속-7065로-분리)의 후행 표 되돌림은 기준 소스에서 재현되지 않는다. 같은 셀을 편집할 때 두 번째 표의 윗변이 2쪽의 첫 번째 표를 침범한다. 연구노트 원본 HWP, 한컴 복사본 두 개, 블록을 다시 복제해 저장한 HWP·HWPX 모두 Enter 6~9회와 역방향 삭제에서 겹친다. 9회째 세로 겹침은 66.1px이다.

쪽 나눔이 허용된 자리차지 표에서 인접 표의 실제 점유를 보존하는 계약을 고친다. 저장된 개체 공통 속성과 셀 편집이 만든 현재 행·줄 높이를 구분한다. 한컴 2020 인쇄로 원본과 같은 편집을 넣어 저장한 HWP·HWPX를 대조한다. [HWP 5 개체와 표 사양](../tech/한글문서파일형식_5.0_revision1.3.md)을 따른다.

메인테이너가 지적한 제목·서명 표의 2쪽 집중은 편집 Print에서 재현된 결함이다. 합격 판정은 미편집 문서와 기존 #3587 회귀가 확인한 `제목 → 본문 조각 전체 → 서명 → 다음 묶음`의 순서 및 표의 실제 비겹침을 기준으로 한다. 문제가 있는 편집 Print의 쪽수나 저장 앵커에 맞춰 순서를 바꾸지 않는다. [수정한 판정과 근거](../report/task_m100_7065_report.md#검증-기준-정정)

## 승인된 수정 계획

1. 두 HWPX에서 읽은 저장 높이와 앵커 값, 문단·개체 순서, 셀 줄 소유를 대조한다. 직접 한컴 저장본과 rhwp 저장본은 값이 달라도 같은 본문·서명 순서 역전을 재현한다. 저장값을 현재 배치에 적용하기 전에 실제 표 상자가 그 저장 프레임을 뒷받침하는지 확인한다.
2. 이전 후보의 후행 표 선배치를 제거한다. 같은 가로 범위에서 흐름과 함께 움직이고 겹침이 금지된 표는 앞 표의 통째 상자 또는 마지막 조각의 점유 끝을 후행 표 배치의 하한으로 사용한다. 남은 단에 서명 표 상자가 들어가지 않으면 다음 단이나 쪽에서 공간을 다시 구한다. 배치 원점과 예약한 높이, 이전 단에서 적용한 앵커 오프셋의 소진 여부를 그리기에도 전달한다. 미편집 저장 상자와 #2813의 유효한 저장 스택, 가로로 나란히 놓일 수 있는 표는 제약의 유효성을 따로 확인한다.
3. Enter 6~9회의 앞 표 겹침 및 Enter 7회의 8.31px 뒤 표 겹침을 먼저 대조한다. 통째 표와 분할이 이어지는 표에서 제목·본문 행 전체·서명·다음 묶음의 소속, 순서, 누락·중복, 겹침을 확인한다. 기존 #3587 회귀 세 건의 기대값을 보존한다.
4. 원본과 복사본, 기존 rhwp HWP·HWPX 및 한컴 직접 저장 HWPX를 Native와 fresh WASM에서 열어 비교한다. 실제 Studio에서 Enter 1~15회, Backspace, 실행 취소, 두 형식 저장·재열기를 확인한다. 저장 단계를 보완할 필요가 있으면 조판을 복원한 뒤 생기는 저장 전후 차이를 근거로 판단한다. 한컴 Print에서 몰린 화면은 진단에 사용하고 쪽수와 한컴의 개체 순서를 합격 기대값으로 삼지 않는다.
5. CI와 같은 Native Skia 검사, 전체 Rust 회귀, 필수 lint와 최신 devel 병합 검증을 실행한다. 편람·정본 보호 문서의 유효한 독립 Print 및 현재 기준에 대조하고, 미달 범위를 해소한 뒤 제출 가능 여부를 판정한다.
