## 3. 본질 가설

### 3.1 박스 top y (9.4 px 쏠림)

**가설 T1**: pi=80 `line_spacing=716 HU` (9.55 px) 이 trailing-ls 로
sequential advance 에서 제외 (Task #479). paragraph border 의 `bg_y_start`
(paragraph_layout.rs:786) 가 sequential y_offset 을 사용하므로 trailing-ls
만큼 위로 쏠림. PDF 는 IR vpos (pi=81 시작 = pi=80 vpos + lh + ls) 기준.

**검증 방법**:
- pi=80 line_spacing 값 확인
- box top y 가 IR vpos 기준 산출되도록 변경 시 PDF 일치 여부

### 3.2 박스 left x / width (11.5 px / 83.6 px 차이)

**가설 G1**: `paragraph_layout.rs:2683-2684` 의 box_x/box_w 산식이 PDF 와
다름. PDF 는 box_x = col_area.x (margin_left 미적용) 또는 다른 기준.

**가설 G2**: paragraph margin_left (1704 HU) 가 11.5 px 만 적용됨 — 일부 분리
적용 또는 산식 오류. width 차이 83.6 px = ~6300 HU 는 right margin 추가 차감
누락 또는 다른 산식 문제.

**검증 방법**:
- pi=82 PS margin_left/right 정확한 값 확인
- box_x / box_w 산식과 PDF 좌표 직접 비교

### 3.3 passage 텍스트 x (11.5 px 쏠림)

**가설 X1**: 박스 left 와 동일 시프트. 박스 좌표 산식 변경 시 텍스트도 자동
일치할 가능성 (effective_margin_left 산식 동일 기반).

## 6. 메모리 룰 준수

- **[feedback_pdf_not_authoritative]**: PDF 보조 ref 로만 사용. 한컴 2010 PDF 외에
  한컴 2020 환경도 가능하면 비교.
- **[feedback_essential_fix_regression_risk]**: paragraph border 좌표 변경은 본질
  정정 회귀 위험 큼. 다단/단일 단/표 분할 / 셀 내부 case 광범위 검증.
- **[feedback_rule_not_heuristic]**: HWP 표준 명세에 따른 룰 적용. 분기/허용오차/fallback
  도입 전 \"휴리스틱 vs 룰\" 자문.
