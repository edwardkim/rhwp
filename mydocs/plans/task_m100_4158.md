## 1. 문제

`samples/basic/issue2007_nested_cell_pagination_42065.hwp` 물리 10쪽의
`공정거래위원회` 앞 표식은 render tree에서 raw `U+F02B1`,
`charOverlap={borderType: 0, innerCharSize: 0}`인 실제 `CharOverlap`이다.

같은 PUA가 일반 `TextRun`인 물리 2쪽은 #4139에서 Canvas2D bounded vector fallback으로
교정했지만, 실제 `CharOverlap` 경로는 여전히 raw PUA를 브라우저 글꼴에 전달한다. 그 결과
해당 글꼴의 PUA glyph 유무에 따라 tofu가 나타난다. SVG와 Native Skia도 같은 의미 규칙을
공유하지 않아 backend parity가 보장되지 않는다.

## 2. 의미 규칙

단일 글자인 `CharOverlap`의 문자가 `U+F02B1..U+F02C4`이면 한컴 사각 안 숫자 1..20으로
해석한다.

```
display text     = code point - U+F02B0
raw border 0     = effective border 3 (사각형)
raw border 1..4  = 작성된 border를 보존
```

다중 문자 PUA 겹침 숫자 디코더와 표준 Unicode 원문자, 이 범위 밖 PUA는 기존 동작을
유지한다. IR의 raw 문자와 `CharOverlapInfo`도 바꾸지 않고 렌더링 의미만 결정적으로
해석한다.

## 4. 회귀 계약

- render tree는 물리 10쪽의 raw `U+F02B1`과 `borderType=0`을 그대로 보존한다.
- Canvas2D 호출에서 raw `U+F02B1`을 `fillText`하지 않고 숫자 `1`과 사각 테두리를 그린다.
- 실제 문서 페이지 수는 17쪽을 유지한다.
- #536/#4139의 물리 2쪽 일반 `TextRun` 사각 숫자 래칫도 계속 통과한다.
- SVG는 raw PUA 없이 `<rect>`와 숫자 `1`을 출력한다.
- 공통 단위 테스트는 1·20 경계, 범위 밖 문자, 다중 문자 제외, 명시적 border 보존을 고정한다.
