## 1. 제품 계약

### 사용자 흐름

1. 사용자가 파일 메뉴에서 `PDF로 저장…`을 선택한다.
2. Studio가 `PDF 준비 중…` 진행 상태와
   `브라우저 인쇄 창에서 ‘대상 → PDF로 저장’을 선택합니다.` 안내를 표시한다.
3. SVG·폰트·레이아웃 준비가 끝나면 브라우저 인쇄 창을 자동 호출한다.
4. 사용자가 브라우저에서 대상을 `PDF로 저장`으로 선택해 저장한다.

기존 `인쇄…`은 실제 프린터 출력 진입점으로 유지하고 두 명령은 같은 print pipeline을 사용한다.

### 상태 불변 계약

- PDF는 HWP/HWPX/HML `SaveFormat`에 추가하지 않는다.
- 실행 전후 `currentFileHandle`, 파일명, dirty/save 상태를 변경하지 않는다.
- 브라우저가 저장·취소 결과를 노출하지 않으므로 저장 성공 메시지를 표시하지 않는다.
- 직접 PDF bytes 생성과 native PDF backend의 WASM 이식은 비목표다.

## 2. 설계 방향

### surface 선택

1. **우선안: same-origin 전용 인쇄 iframe**
   - 정적 `print.html`을 같은 origin에서 로드하고 부모 Studio가 DOM API로 인쇄 문서를 구성한다.
   - popup과 `about:blank`를 모두 제거한다.
   - 준비 완료 후 `iframe.contentWindow.print()`를 자동 호출한다.
2. **대안: same-origin 전용 인쇄 창**
   - iframe에서 혼합 용지, 폰트 또는 Chrome/Edge 동작 차이가 확인될 때만 채택한다.
   - 사용자 클릭 동기 구간에서 창을 먼저 확보하고 같은 print pipeline을 사용한다.

두 surface는 기존 페이지별 named `@page`, 혼합 용지 크기·방향, SVG id namespace 처리를 재사용한다.

### 공통 pipeline

- 출력 의도만 `print | pdf`로 구분한다.
- 페이지 생성·print profile·문서 구성·폰트/레이아웃 준비·자동 `print()` 호출은 공유한다.
- 진행 문구와 사용자 안내만 출력 의도에 따라 달리한다.
- print surface의 생성·정리와 준비 대기는 별도 모듈로 격리해 단위 테스트할 수 있게 한다.

### 명시적 print profile

- WASM에 `renderPageSvgWithProfile(page, profile)`을 추가한다.
- 기존 `renderPageSvg(page)` 계약은 바꾸지 않는다.
- Studio print pipeline만 `profile = "print"`를 명시해 편집용 표시를 배제한다.
- profile 문자열은 기존 `RenderProfile::parse` 규약을 재사용한다.

## 3. 단계

### Stage 0 — 현행 계약과 surface 비교

- 현행 호출 순서와 popup activation 손실을 코드·브라우저에서 재현한다.
- iframe과 전용 창의 same-origin, 혼합 `@page`, 자동 `print()` 가능 여부를 비교한다.
- file handle·파일명·dirty 상태 불변을 관찰할 수 있는 검증 포인트를 확정한다.
- 선택 근거를 `mydocs/working/task_m100_3126_stage0.md`에 기록한다.

### Stage 1 — 발견 가능한 UX와 iframe print pipeline

- 파일 메뉴에 별도 `PDF로 저장…` 명령을 추가한다.
- 기존 `인쇄…`과 공유하는 pipeline을 도입한다.
- same-origin `print.html` iframe에 인쇄 DOM을 구성한다.
- SVG·`document.fonts.ready`·레이아웃 준비 후 `print()`를 자동 호출한다.
- 준비 진행률, PDF 대상 선택 안내, 오류와 surface 정리를 구현한다.
- rhwp 자체 인쇄 버튼 재클릭과 `about:blank` 경로를 제거한다.

### Stage 2 — print profile과 focused 회귀

- Rust/WASM `renderPageSvgWithProfile` API와 TypeScript bridge를 추가한다.
- print pipeline을 명시적인 `print` profile에 연결한다.
- profile parsing, 편집 표시 억제, 혼합 용지, SVG id namespace, 상태 불변을 focused test로 고정한다.
- 기존 `renderPageSvg` 소비자는 변경하지 않는다.

### Stage 3 — Chrome/Edge 및 PDF 결과 검증

- #2524/#2525를 포함한 다중·혼합 용지 fixture로 Chrome/Edge 동작을 비교한다.
- 한 번 클릭 → 준비 상태 → 자동 인쇄 창 호출을 검증한다.
- CDP `printToPDF` 또는 동등한 재현 절차로 페이지 수·크기·검색 가능한 텍스트를 확인한다.
- 취소 후 파일명·handle·dirty 상태 불변을 확인한다.
- 자동화할 수 없는 시스템 인쇄 대화상자 단계와 환경 차이를 수동 절차로 남긴다.
