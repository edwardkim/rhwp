## 1. 배경

본 task 는 rhwp-studio 의 file 저장 흐름 관련 **2건 통합 정정**:

### (A) "다른 이름으로 저장" 기능 부재
rhwp-studio 에 Save As 기능 부재. 현행 `file:save` (Ctrl+S) 만 존재하며 `currentFileHandle` 이 있으면 자동 overwrite 되어 새 파일명으로 저장할 방법이 없음.

한컴오피스 2022 표준 동작:
- 파일 > 저장 (Ctrl+S) — 기존 파일 overwrite
- 파일 > 다른 이름으로 저장 (Ctrl+Shift+S) — 새 파일명 + 위치 + 포맷 선택

### (B) 저장 권한 프롬프트 취소 시 fallback download 오발현 (범위 확장)
사용자가 Ctrl+S → Chrome "변경사항을 저장하시겠습니까?" 권한 프롬프트에서 "취소" 클릭 시, 의도와 달리 blob URL fallback download 가 발현되어 파일이 Downloads 폴더에 저장되고 chrome-extension viewer 가 자동 연결됨. 본질: `try/catch` 의 catch 가 `AbortError` 만 swallow 하고 `NotAllowedError` 등 다른 cancel 에러는 fallback path 진입.

## 3. 해결 방향

### (A) Save As 핵심 변경
1. **`saveDocumentToFileSystem` 시그니처 확장** — `forceSaveAs: boolean` 옵션 추가. true 시 `currentHandle` 무시하고 항상 `showSaveFilePicker` 호출
2. **`file:save-as` command 신규** — `file:save` 와 동일하나 `forceSaveAs: true` 전달 + `services.wasm.currentFileHandle` / `services.wasm.fileName` 갱신
3. **메뉴 항목 추가** — `index.html` 파일 메뉴에 "다른 이름으로 저장(A)..." 추가 (저장 항목 아래)
4. **단축키 등록** — `shortcut-map.ts` 에 `Ctrl+Shift+S` → `file:save-as` 추가 (한글 IME 대응 `ㄴ` 도 함께)

### (B) 권한 cancel fallback download 오발현 정정
[file.ts:172-177](../../rhwp-studio/src/command/commands/file.ts#L172-L177) 의 catch 블록에 `NotAllowedError` 도 swallow 추가. 동시에 `file:save` + `file:save-as` 양쪽 동일 패턴 적용 (코드 중복 회피 위해 helper 함수 분리).

```typescript
// 사용자 명시 cancel 에러: AbortError (피커 취소) + NotAllowedError (권한 거부)
// 모두 fallback download 우회 — 의도하지 않은 download 차단.
function isUserCancelError(e: unknown): boolean {
  return e instanceof DOMException
      && (e.name === 'AbortError' || e.name === 'NotAllowedError');
}
```

### 폴백 동작 (정상 case)
- File System Access API 미지원 브라우저 (Safari 등): API 자체 부재 → `showSaveAs` dialog → 파일명 입력 → blob download (기존 fallback 재사용)
- 사용자 cancel 은 fallback 진입 안 함 (위 helper 로 분기)

### 비채택 방안
- 새 command 없이 `file:save` 에 `forceSaveAs` 파라미터만 추가: dispatch 시 파라미터 전달 복잡, 메뉴/단축키 표현 불편
