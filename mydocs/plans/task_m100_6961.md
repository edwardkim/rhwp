## 원인과 범위

Firefox 최초 #156 / PR #169부터 DownloadItem.filename 절대 경로를 표시 이름으로 전달했다.
#1498 / PR #1513의 과거 다운로드 재오픈 회귀와 #1515/#1516 상태 머신 보호를 유지한다.
뷰어 URL을 조립하는 최종 경계에서 basename만 추출하는 공통 순수 함수를 사용한다.
Chrome/Firefox의 새 탭·빈 탭 재사용 모두 같은 경계를 거친다. DownloadItem, 분류 함수,
신선도, 중복 처리, 저장 상태, URL, Studio 저장 로직은 수정하지 않는다.
한글·공백·괄호·퍼센트 문자열·밑줄을 보존하며 URL 디코딩을 추가하지 않는다.

## 단계

1. 계획과 수정 전 회귀 증적을 확정한다.
2. 공통 이름 함수와 두 launcher에 적용하고 실제 절대 경로 adapter 테스트를 보강한다.
3. 다운로드 전체 관련 테스트, 두 확장 build/dist 계약, 실제 Firefox 저장 및 탭 수를 확인한다.
4. 결과보고와 PR 본문 초안을 준비하고 commit한다.

## 검증

- POSIX/Windows/UNC 경로, 경로 없는 이름, 빈 이름 fallback, URLSearchParams 인코딩 왕복.
- 한글(조합형 포함)·괄호·공백·밑줄·퍼센트·HWP/HWPX/HML 이름 보존.
- onCreated/onChanged에서 실제 absolute filename을 사용하고 탭 1개와 이름을 함께 확인.
- 과거 항목, background 재시작, terminal 중복, autoOpen=false와 비-HWP 보호 테스트 유지.
- 실제 패키지에서 자동 열기 → 편집 → 저장/다른 이름 → 재열기 및 저장 다운로드 추가 탭 확인.
- Rust/WASM/Studio source 무변경: Rust lint/전체 테스트는 대상 밖. 기존 WASM 재사용 사실을 기록.
