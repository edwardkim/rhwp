# Task M100 #6672 수행 계획

## 목적

full renderer의 실제 제품 호출 그래프에 들어오지 않는 Rust 함수들을 제거한다.
한 번의 표본 실행에서 호출되지 않았다는 사실만으로 삭제하지 않고, native·WASM·
native-skia 제품 library의 rustc liveness 판정과 저장소 전체 호출자 검색을 함께
삭제 게이트로 사용한다.

## 기준

- Issue: #6672
- 기준 branch: `origin/devel` `b6b9384ed`
- 작업 branch: `renderer/full-render-dead-code`
- 인접 작업: PR #6668은 아직 `devel`에 병합되지 않았으므로 본 변경의 선행 조건으로
  삼지 않는다.

## 범위

첫 제거 단위는 paragraph composer의 고아 callable 폐쇄 집합이다.

- `inject_footnote_markers`
- `split_composed_line_by_width`
- `estimate_regenerated_line_text_width`
- `missing_lineseg_legacy_bullet_requires_regenerated_space_metric`
- `tokenize_paragraph`
- `is_line_end_forbidden`

이 중 `split_composed_line_by_width`, `tokenize_paragraph`,
`is_line_end_forbidden`은 단위 테스트가 직접 호출한다. 이 셋과 전용 폭 helper는
`#[cfg(test)]`로 제품 graph에서 제외해 기존 회귀 계약을 보존한다. 어떤 테스트도
호출하지 않는 나머지는 삭제한다. target별로만 쓰이는 SVG font lookup이나
native-skia 함수, public compatibility API는 이번 범위가 아니다.

작업 중 이슈 피드백에 따라 같은 판정을 renderer 전체로 확대한다. native,
wasm32, native-skia 세 제품 구성에서 모두 `dead_code`인 함수·메서드는 전부
test-only 경계로 이동한다. 이 교집합에서 test 호출도 없는 두 composer 함수는
삭제한다. target 한 곳에서 쓰이는 callable과 함수가 아닌 dormant field/type/constant는
제외한다.

## 단계

1. LLDB command로 full render가 frame-aware line-breaking owner에서 멈추는지 확인한다.
2. 세 제품 구성에서 동일하게 죽은 callable과 저장소 호출자 0건을 고정한다.
3. renderer 전체의 제품-dead callable을 test-only로 제한하고, test 호출도 없는
   함수는 삭제한다.
4. LLDB replay, focused test, Rust lint 묶음, 전체 release-test, WASM·renderer 검증을
   실행한다.
5. 결과 보고서를 커밋하고 Draft PR을 연다.

## 비범위

- 공개 WASM legacy Canvas API 제거
- PR #6668의 SVG ownership 변경
- field/type/constant까지 포함하는 저장소 전역 dead-code 정책 전환
- 렌더링 의미, 줄 나눔 결과, golden SVG 변경

## 완료 조건

- LLDB가 실제 `export-svg` 실행에서 production line-breaking owner에 정지한다.
- renderer callable이 native·WASM·native-skia의 공통 `dead_code` 진단에서 0건이다.
- test 호출도 없는 함수는 source에서도 사라진다.
- 필수 로컬 검증이 모두 통과하고 Draft PR이 `devel`을 base로 열린다.
