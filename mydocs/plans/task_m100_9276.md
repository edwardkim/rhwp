# #9276 Windows에서 직접 PDF 내보내기 성능 복구

Issue: #9276

## 기준과 완료 조건

작업 기준은 `upstream/devel`의 `bd3cd171331e80e79881dc8e9ed37f837ef6be77`이다. 2026년 11월 22일 이슈와 연결된 해결 PR이 없는 것을 확인했다. 원본은 신고자가 지정한 조달청 공고의 HWPX 첨부 세 개다. [이슈와 원본 출처](https://github.com/edwardkim/rhwp/issues/9276)

동일한 Windows x64 호스트의 로컬 디스크에서 웹폰트 캐시를 예열한 뒤 `rhwp export-pdf 입력.hwpx -o 결과.pdf --backend direct --json`으로 측정했다.

| 조달청 첨부 키와 순번 | 쪽수 | v0.8.7 시간 / 바이트 | devel 시간 / 바이트 |
|---|---:|---:|---:|
| 202604300039 / 1, 공고문 | 11 | 0.86초 / 605,028 | 24.11초 / 10,933,271 |
| 202610080012 / 2, 모집 안내 | 7 | 1.37초 / 526,802 | 29.52초 / 798,387 |
| 202610080012 / 1, 추천서 | 1 | 0.10초 / 143,179 | 3.31초 / 49,636 |

공고문의 최신 devel 결과에서 압축한 글꼴 스트림은 10,615,665바이트였다. 사용된 굴림체 컬렉션과 한양 글꼴 스트림은 Windows 설치 파일 전체와 SHA-256이 같았다. 같은 11쪽을 SVG로 출력하면 4.03초, Native PNG로 출력하면 23.99초가 걸렸다. 자동 글꼴 준비 결과를 명시적으로 재사용해도 같은 PDF가 22.56초에 생성됐다.

목표는 세 원본의 실제 Windows 실행 시간을 수 초 수준으로 돌리고, 큰 글꼴 전체가 불필요하게 들어간 PDF를 작게 만드는 것이다. 각 원본의 쪽수, 실제 글꼴·글리프·폭, 페이지별 표시, 검색·복사할 수 있는 텍스트와 기존 direct 그라데이션을 보존한다. Windows 설치 글꼴은 로컬 비교에만 사용한다. [구현·검증 계획](task_m100_9276_impl.md)
