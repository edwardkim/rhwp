## 수정 전 관측

배포된 Studio v0.9.1에서 바탕글 10pt인 두 줄 이상의 문단을 편집했다. 둘째 줄의 시작점은 브라우저가 출력한 페이지 SVG에서 읽었고, 같은 문단을 HWP와 HWPX로 각각 저장한 뒤 새 문서로 열어 문단 모양의 `Indentation`을 확인했다. 배포 커밋은 `981ce66b4183b13c1a3b5907e04a8969c8c42034`다.

| 입력 또는 동작 | 실제 결과 |
| --- | --- |
| 문단 모양에서 내어쓰기 1.005pt / 1.015pt | 저장값 −201 / −203, 둘째 줄 5.05pt / 5.10pt |
| 같은 설정창에서 1.00pt / 1.01pt / 1.10pt | 세 입력 모두 해당 길이대로 표시 |
| 본문 첫 줄에서 `AB` 뒤의 커서로 Shift+Tab | 커서 거리 17.50px, 둘째 줄 이동 87.53px, 저장값 −2625 |
| 설정창에서 기존 `CHAR` 내어쓰기 −203을 변경하지 않고 설정 | HWP와 HWPX 모두 −200으로 바뀜 |
| 원본의 첫 줄 들여쓰기 +202를 다른 문단으로 모양 복사 | 원본은 +202, 대상 문단은 두 저장 형식 모두 +195 |

최신 `devel`의 눈금자 드롭 함수에서도 재현했다. 확대율 200%에서 문서 기준 17.0px·17.5px·18.0px를 지정했을 때 각각 2550·2625·2700이 생성됐다. 가운데 값의 최하위 비트는 상대 길이를 뜻한다. [눈금자 드롭 처리](../../rhwp-studio/src/view/ruler-pin-geometry.ts)

## 완료 조건

절대 길이로 입력한 들여쓰기와 내어쓰기는 HWPUNIT 단위로 저장하고, 정상 `CHAR` 문서의 상대 길이는 기본 글자 크기를 따라야 한다. 원본과 비교할 때는 최초 편집값, 실행 취소·다시 실행, 두 형식에서의 반복 저장을 각각 확인한다. [구현·검증 계획](task_m100_8860_impl.md) · [기존 CHAR 저장 검토](../pr/archives/pr_7319_review.md) · [한컴 인쇄로 확인한 상대 길이 해석](../pr/archives/pr_7825_review.md)
