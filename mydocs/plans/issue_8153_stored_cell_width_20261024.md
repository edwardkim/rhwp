# #8153: 저장 셀 폭과 행 경계의 소유

## 원본과 독립 출력

대상은 편람 HWP/HWPX 64쪽이다. 원본 HWPX section2 문단 417에 중첩된 표의
9·10·11행 가운데 셀은 폭 29,412HU, colSpan 10이다. 같은 행 양옆 셀은 4,405HU와
3,988HU다. 행 합 37,805HU와 공통 표 폭 38,001HU는 같지 않다. 문서 ID로 분기하거나
이 196HU 차이를 보정 상수로 사용하지 않는다.

현재 실제 cell bbox의 가운데 폭은 394.773333…px이고 원본 폭은 392.16px다. 현재
오른쪽 회색 선은 x=580.106666…px, 독립 Print는 약 576.816px다. 우선 저장 폭을
전역 grid의 잔여 폭으로 바꾸는 생산 경로와 선이 그 경계를 소비하는 경로를 추적한다.
paint에서 특정 선만 옮겨 셀 본문과 다른 폭을 사용하게 하지 않는다.

HWP 5.0 revision 1.3 표 80의 셀 폭은 HWPUNIT이다. `noAdjust`라는 이름만으로 행 폭을
정규화하거나 보존해야 한다고 추정하지 않는다. 해당 속성을 분리한 실제 출력으로 확인했다.

## 속성을 분리한 실제 한컴 Print

원본 첫 문단의 secPr와 ctrl/colPr, 문단 417, 스타일·리소스를 보존한 한 구역 축약 입력을
만들었다. 원본 383쪽의 pagination 통과 자료가 아니라 폭 계약을 확인하는 별도 대조군이다.
대조군은 다음 두 속성만 교차 변경했다.

- 대상 표의 `noAdjust`: 원래 1 또는 0.
- 9·10·11행 가운데 셀 폭: 원래 29,412HU 또는 29,608HU.

한컴 2024 13.0.0.3901, PrintMethod 0, input_preprocess none에서 네 입력 모두
1쪽·555×754pt다. 원본 독립 Print 64쪽도 같은 물리 용지다.

| 가운데 셀 폭 | noAdjust | 양쪽 회색 선의 거리 |
| ---: | ---: | ---: |
| 29,412HU | 1 | 391.737325px |
| 29,412HU | 0 | 391.737325px |
| 29,608HU | 1 | 394.454651px |
| 29,608HU | 0 | 394.454651px |

`noAdjust`만 다른 두 출력의 회색 선 위치·높이·폭은 정확히 같다. 가운데 셀 폭을 바꾸면
왼쪽 선은 그대로이고 오른쪽 선만 달라진다. 원본 64쪽의 두 선 거리는 391.736003px로,
원래 폭 대조군과 차이가 약 0.001322px다. 이 실제 결과는 원본 셀 폭을 그대로 소비해야
한다는 근거이며 `noAdjust`로만 대상을 좁힐 근거가 아니다.

ignored 작업 루트의 `row-width-controls-v2/`에 입력·생성 코드·PDF SHA, 네 Print
job 영수증과 `print-width-observations.json`을 보존했다. 첫 시도 `row-width-controls/`는
colPr를 ctrl 없이 run에 직접 넣어 Print가 A4로 출력됐다. 그 출력은 원본 좌표 확정 근거에서
제외하고, 원래 XML prefix와 첫 문단의 전체 계층을 보존한 v2로 다시 검증했다.

## 원 해결 PR과 보존할 반례

이슈 #5590의 원 PR #5646 head `98e929188dab898990cff72eb311631f09bfba15`는
통합 PR #5669, merge `14e4d01af64a897d93f81f3bd6be0a3ad66c563f`에 반영됐다.
원 해결 기록과 `task_5590_per_row_column_widths.md`, 기존 회귀를 읽었다. 원래 변경은
행별 선언 구획을 도입했지만, form-002의 부분 가로선이 짧아지는 반례 때문에 전역 grid가
표 폭과 이미 맞으면 행별 구획을 사용하지 않았다. 이 보호 목적을 삭제하지 않는다.

현재 `render_edge_borders`의 수평선은 경계 아래 행의 `row_col_x`를 사용한다.
form-002 원본에는 위 행이 colSpan 3·폭 13,684HU인 셀을 가지고, 아래 행이 colSpan
27·표 전폭인 셀을 가지는 경계가 있다. 아래 행의 span 내부를 균등 분할한 좌표는 위 셀의
실제 끝점이 아니다. 이것이 과거 부분 선 길이 문제의 원인인지 실제 소유·실행 경로로
확인한다. 수치의 유사성만으로 원인이 확정됐다고 기록하지 않는다.

기존 #5590의 정상 행 구획, `pdf/hwpx/form-002-2022.pdf`의 부분 가로선,
행 합의 비례 정규화를 도입한 #5720의 원 해결 근거도 함께 확인한다. 알려진 반례를
피하려고 noAdjust·문서 ID·1% 같은 조건을 새로 추가하지 않는다.

## 구현 전 추적과 검증 순서

1. `build_row_col_x`/`RowColumnGeometry`의 폭 생산 → 일반·부분 표의 셀 원점과 폭 소비 →
   실제 가로·세로선의 경계 선택을 추적한다. 측정의 `resolve_column_widths` 소비도 대조한다.
2. 셀의 저장 폭과 표 전체 폭을 구분하고, 경계의 선이 어느 셀/행의 끝점을 소유하는지
   확인한다. grid 번호가 같다는 이유로 다른 행의 물리 좌표를 대신 사용하지 않는다.
3. 같은 결과를 셀 본문과 테두리가 소비하도록 공통 원인을 보정한다. 격자 밖으로 선을
   숨기거나 paint에서 x 좌표만 clamp하는 방식으로 해결하지 않는다.
4. 원본 64쪽과 위 정상 반례를 먼저 실제 재검증하고 직접 판독한다. 이후 양쪽 형식의
   전쪽 Native/fresh WASM, 기존 corpus와 필수 회귀 gate를 완료한다. 현재 문서는 독립
   원인 조사이며 아직 이 폭 보정의 구현·통과 또는 1,532개 raw100의 완료가 아니다.

## 추가 독립 대조: 행의 마지막 셀과 내부 경계

원본 구획을 유지하면서 64쪽 축약 대조군의 9·10·11행 마지막 셀 배경만 녹색으로
바꿨다. 폭·텍스트·LineSeg·margin·span은 바꾸지 않았다. 한컴 2024 Print job
`9c8074ff-8241-4eb4-bf7a-b18fcc7bbcfc`는 PrintMethod 0, input_preprocess none,
13.0.0.3901로 완료됐다. 녹색 실제 폭은 세 행 모두 55.779989px다. 원본 마지막 셀
폭은 3,988HU=53.173333px이고 행의 부족 폭을 마지막 셀에 더하면 55.786667px다.
내부 가운데 셀을 늘린 현재 전역 grid와 달리, 독립 출력은 마지막 셀의 물리 폭에서
행을 닫는 동작을 보인다. 임의로 196HU를 상수로 넣지 않고 원본 구획·표 외곽의 소유로
설명해야 한다. 입력 SHA-256은
`8663242aee91ae3f942707c253549135353511ac1e70332de0ecdfa1d7e3001e`,
PDF SHA-256은 `fb85478e558daf0f9ae0a7ca871f51c889a18514bcc0ee9ea37abcbf9e2fb310`다.

다른 대조군에서 첫 행의 셀 폭만 2% 늘려도 아래 행의 회색 선 거리는 정확히 같았다.
따라서 첫 행 폭 합으로 다른 행을 일괄 정규화한다는 가설은 기각했다. 이 대조군으로
새 배율이나 예외를 구현하지 않는다. `row-width-first-row-controls/`의 입력·Print·
`independent-width-comparison.json`에 실제 값을 보존한다.

서명 표의 80쪽 날짜 줄도 원본 누적 폭과 현재 셀 시작의 차이가 283HU다. 날짜의 글자
전진은 독립 Print와 맞아졌으므로 문자열을 조건으로 되돌리지 않는다. 29개 가상 열에
걸친 원본 셀 경계와 마지막 셀의 물리 닫힘을 확인하는 같은 공통 원인 조사에 포함한다.

#5720의 제목 전폭 셀 배경 실측은 표 외곽 폭을 유지한다. 이것만으로 내부 경계를 비례
정규화해야 한다고 단정할 수는 없다. 기존 원본 첫 데이터 행의 네 셀 배경만 구별한
독립 Print로 내부 경계를 추가 확인한다. 첫 시도는 원본 BorderFill ID 21개 뒤에
900번을 추가해 한컴이 배경을 소비하지 않았으므로 폭 근거에서 제외했다. 22~25번으로
연속 추가한 새 대조군을 사용한다. 기존 #5720의 표 외곽 보존과 form-002의 부분 가로선
보호 목적은 유지하고, 실제 경계의 소유를 확인한 뒤 구현 범위를 정한다.

## 구현 단계의 생산·소비 계약

연속 ID를 사용한 #5720 네 셀 대조군은 Print job
`c7782d56-2dac-4ad0-b0ad-29c6403f0b1f`로 완료됐다. 네 배경의 물리 폭은 각각
94.34934·222.92000·94.34932·226.75732px다. 원본 앞 세 셀 폭
94.48·222.98667·94.48px와 대응하며 비례 정규화한 95.04347·224.31653·95.04347px와
다르다. 마지막 셀은 행 부족 폭을 수용한다. 이 결과는 표 외곽 보존을 없애는 근거가
아니라 내부 셀의 폭을 비례 확대할 근거가 없다는 뜻이다.

공통 모델에서 유효한 원본 셀이 열 주소를 빈틈없이 덮는 행의 물리 프레임을 HU로
생산한다. 앞 셀들의 원본 폭을 누적하고, 마지막 셀은 같은 표 외곽에서 행을 닫는다.
부족 폭은 모든 앞 셀에 배분하지 않는다. 과다 폭·구멍·중복·잘못된 span은 이 계약으로
확정하지 않고 기존 해석을 보존하며, 해당 원본의 독립 근거를 별도로 확인한다.

이 결과를 측정의 문단 프레임 폭, 일반·부분 표의 셀 원점/폭, 테두리의 행별 경계가
함께 사용한다. 가상 열 내부 보간은 논리 주소를 표현하는 수단이며 실제 셀 전체 폭을
보간 폭의 부동소수 합으로 다시 정하지 않는다. 수평선은 그 선의 상·하 소유를 따라
경계 행을 고르며, 아래 행의 전폭 셀 내부 가상 열로 위 셀 끝점을 대체하지 않는다.

최초 실행은 원본 64·80·83·85~87쪽과 #5590/#5720/form-002를 포함한 집중 검증이다.
새 실패나 하락은 기대값을 바꾸지 않고 원본·독립 출력으로 조사한다. 이 모델 계약과
기존 보조 폭 복구가 충돌하는 원본도 집중 검사로 확인한 뒤 범위를 확대한다.
