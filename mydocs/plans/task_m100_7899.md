## 확인한 결함과 근거

HWP5 명세는 각 구역 끝의 확장 바탕쪽과 마지막 구역 끝의 메모 목록을 별도 저장 범위로 정의한다. 현재 HWP parser는 그 범위를 편집 후 보존할 독립 소유 영역으로 유지하지 않는다. 모델에서 구역을 다시 쓰면 일부 바탕쪽이 `is_extension` 분류에 의해 제외되고, HWP 메모 본문은 모델로 복원되지 않아 저장 목록이 비게 된다.

- 최신 devel과 같은 저장 코드의 Native에서 공개 입력 10개를 확인했다. 8개는 목록을 잃고 2개는 정상 대조군이다.
- npm `@rhwp/core 0.8.7`에서 Native와 같은 유실 3건·정상 대조 1건을 재현했다. 손실 저장본도 자기 재열기는 성공한다.
- 독립 한컴 2020에서 `exam_math_8.hwp` 원본 재저장은 성공했고, 유실된 저장본은 600초 타임아웃으로 실패했다. 신고자의 한컴 2024 `Open=False`와 구분한다.
- 열린 PR 54건을 조사했다. 같은 원인 파일을 수정하는 6건에서도 핵심 함수는 devel과 같아, 직접 해결 중인 PR은 없다.
- 원문·명령·해시·레코드 비교는 기본 작업공간의 ignored `output/pr-review/issue7899-20261014/`에 보존한다. 조사 보고서 `diagnosis-ko.md`, PR 조사 `related-prs/report-ko.md`를 재사용한다.

## 목표와 범위

본문에 한 글자를 입력하는 등 구역의 재직렬화를 유발하는 편집 후에도 구역 끝 바탕쪽·메모 목록의 소속, 원본 내용, 순서와 필요한 참조를 보존한다. 저장된 파일의 실제 레코드와 독립 한컴 열기·저장을 대조한다.

이번 범위는 HWP5 입력 → 구역 끝 소유·보존 계약 → HWP5 저장이다. 본문 편집의 원본 스트림 무효화는 유지한다. 확장 바탕쪽의 적용 의미·렌더링 플래그를 저장 위치의 대용으로 사용하지 않는다. HWPX에서 생성하는 기존 바탕쪽·메모 저장 경로와 상호작용을 검증한다. 신규 메모 편집 UI, 조판 알고리즘 변경, 형식 외부 취약성 개선은 이 계획의 목표가 아니다.

## 입력과 검증 계약

기존 커밋된 샘플은 그대로 재사용한다. 교육과정 샘플은 현재 devel에 없고 공개 main에서만 확보됐으므로 검증에 사용하면 입력 SHA와 공개 출처를 유지하며, 제출 시 검토 commit에 포함할 위치를 명시한다. 임시 입력을 기존 devel 샘플로 보고하지 않는다.

순수 레코드·참조 보존 검사는 원본과 명세로 기대값을 정한다. 렌더링 검사·fixture/golden의 추가·변경은 관련 범위의 90% 선행 조건을 따른다. 모든 시각 게이트·쪽수 불일치·미검증 범위는 별도로 기록하며 기존 #7639의 문서별 수용을 이 이슈에 적용하지 않는다.

## 절차와 승인 범위

현재 승인 범위는 수행·구현 계획에 따른 구현과 집중 검증이다. [Issue Workflow](../manual/codex/docs_and_git_workflow.md#issue-workflow)의 계획 승인 뒤 구현을 시작한다. 긴 전체 CI 성격의 로컬 검증은 focused·시각 결과 공유 후 승인받는다. 원격 push·댓글·PR 생성·merge·이슈 종료는 별도 승인이다.

후속 자체 PR은 [collaborator self 경로](../manual/pr_review/collaborator_self_merge.md)를 적용한다. 오늘할일과 번호 기반 PR review는 해당 PR의 code head CI 성공 뒤 작성한다. 계획 단계에서 PR 번호를 예측하거나 다른 작업의 오늘할일을 바꾸지 않는다.

구체적인 소유·저장 변경과 파일별 검증은 [구현 계획](task_m100_7899_impl.md)에 연결한다.
