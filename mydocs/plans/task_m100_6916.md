# #6916 수행계획서 — 제품과 선택적 Gym 평가 도구의 의존 경계

- 이슈: https://github.com/edwardkim/rhwp/issues/6916
- 담당: edwardkim / milestone v1.0.0
- 작성일: 2026-09-09
- 브랜치: `task_m100_6916`
- 기준: fetch 후 최신 `upstream/devel` `c72ad805cc60e4a5cf5689c18b44e7214cec68fe`
- 상태: 2026-09-09 Stage 1 조사 완료, A안 구현계획 승인 대기. 제품 구현은 시작하지 않았다.
- 역할: Gym 참가자가 아닌 메인테이너 감사·개발. 평가 자산 열람은 가능하나 채점 기준을 완화하지 않는다.

## 1. 목표와 메인테이너 결정

**rhwp 제품은 Gym 없이 빌드·실행·배포할 수 있어야 한다. Gym은 rhwp CLI/API를
선택적으로 사용하는 평가 도구로 유지한다.** 의존 방향은 Gym → rhwp다.

Gym 폴더를 삭제하거나 별도 저장소로 이전하는 작업이 아니다. Gym을 계기로 개발한 일반
CLI/API 기능도 보존한다. 사용자 제품과 평가 도구의 책임을 분리하는 것이 완료 기준이다.

## 2. 확인된 출발점과 조사 한계

- `src/mcp_serve.rs`의 `rhwp://docs/gym` 리소스가
  `include_str!("../gym/README.md")`로 Gym 문서를 컴파일 시 포함한다.
  `src/main.rs`는 해당 모듈을 사용한다. 이 결합의 도입 목적·소비자·호환성은 Stage 1에서 추적한다.
- 네이티브 release 패키징은 바이너리·LICENSE·README를 복사한다. Gym 과제·채점기 전체가
  제품 바이너리 패키지에 들어간다고 주장하지 않는다. 모든 게시 패키지의 내부를 검사한 상태도 아니다.
- `gym` 문자열이나 과거 개발 주석만으로 필수 의존을 판단하지 않는다.
  빌드 입력, 런타임 호출, 공개 리소스, 테스트, 선택적 안내를 구분한다.
- #6628의 완료된 운영 경계는 보존한다. #6684의 열린 온보딩 개선은 별도 범위이며 흡수하지 않는다.

## 3. 범위와 보호 불변식

1. 제품 source·build script·package manifest·CLI/MCP resource·CI/release의 실제 Gym 소비 경로를 조사한다.
2. 제품이 Gym 파일이나 실행 도구를 요구하는 결합만 최소한으로 제거한다.
3. MCP URI·목록·응답 계약은 조사 후 보존안을 우선 검토한다. 제품 소유의 가벼운 안내 또는
   외부 안내 등 대안을 비교하고 구현계획 승인 전에 해법을 확정하지 않는다.
4. Gym 과제·기준풀이·채점기·증적과 일반 문서 처리 API는 보존한다.
5. Gym 결과를 일반 제품 PR·devel/main push·tag·Release·게시의 승인 조건으로 사용하지 않는다.
   Gym 자체 변경의 계약 검사와 제품 릴리스 게이트를 구분한다.
6. 새 상시 heavy CI lane, 신규 배포 채널, 별도 저장소, 평가 의미·리더보드 변경,
   온보딩 전면 개편, parser/renderer 변경은 제외한다.
7. 주 checkout의 Gym·WIP·output을 삭제하지 않는다. Gym 부재 검증은 격리된 복사본에서만 수행한다.

## 4. 수행 순서와 승인 지점

| 단계 | 수행 내용 | 결과와 승인 지점 |
| --- | --- | --- |
| Stage 1 — 의존 조사·설계 | 도입 이력과 현재 소비자를 확인하고 필수 의존/선택적 안내/Gym 자체 검사/역사적 언급으로 분류한다. 제거·보존 목록, MCP 호환성 대안, 배포별 영향과 검증 명령을 확정한다. | `working/task_m100_6916_stage1.md`, `plans/task_m100_6916_impl.md`. 구현계획 승인 후 Stage 2 진입. |
| Stage 2 — 최소 분리 구현 | 승인된 필수 결합만 수정한다. 공개 계약 회귀 검사와 제품/Gym 권위 문서의 운영 경계를 보완한다. | `working/task_m100_6916_stage2.md`. focused 검증 결과 승인 후 Stage 3 진입. |
| Stage 3 — 독립성 검증·완료 보고 | Gym 없는 격리 source의 빌드·실행·패키징 및 외부 rhwp 바이너리를 사용하는 선택적 Gym 경로를 확인한다. 영향 범위별 필수 검증을 마무리한다. | `working/task_m100_6916_stage3.md`, `report/task_m100_6916_report.md`. 결과 승인 후 commit/push·PR·self-review·merge·close는 해당 승인 절차로 진행. |

단계 전환 전 현재 단계 변경을 커밋한다. 새 자식 이슈를 연속 생성하지 않고 본 이슈의 3단계로 관리한다.
추가 공개 인터페이스 변경이나 제품 기능 제거가 필요하다면 범위를 확대하지 말고 계획 수정 승인을 요청한다.

## 5. 검증 전략

- Stage 1에서 Gym 직접 의존을 제거한 소스와 기존 소스의 비교 조건을 고정한다.
  동일 SHA·feature·도구 버전을 기록하고 기존 캐시 때문에 소스 의존 누락을 놓치지 않도록
  격리 target과 Gym 없는 소스 구성을 사용한다.
- 네이티브 CLI 빌드와 기본 실행, MCP resource 목록·읽기, 영향받는 일반 CLI/API 계약을 확인한다.
  MCP 안내 내용 변경과 URI 호환성은 별도 항목으로 판정한다.
- native package, WASM 및 npm/확장 배포의 소비 경로를 먼저 조사한다. 영향받는 경로는 로컬
  빌드·포장까지 확인하고, 영향 없는 경로의 실행 생략은 근거를 남긴다. 실제 WASM 빌드는 Docker를 사용한다.
- 패키징 검증은 게시하지 않는 로컬 검사다. remote dispatch·스토어 게시·릴리스 발행은 포함하지 않는다.
- Gym은 운영 매뉴얼의 외부 바이너리 지정 경로로 대표 과제 smoke 검사를 수행한다.
  경계 변경에 필요하지 않은 전체 과제 재계측이나 채점기 개편은 하지 않는다.
- Rust source/test를 변경하면 PR 제출 전 review 환경에서 root `AGENTS.md`와
  [로컬 검증 4.3](../manual/pr_review/local_validation.md)의 fmt·native Clippy·WASM Clippy·
  workspace build·all-targets Clippy·manifest 검사 순서를 모두 통과한다.
  새 integration 원본은 `tests/cases/`에 두고 파생 suite·manifest는 제출하지 않는다.
- 문서와 운영 경계의 참조는 확인하되 일반 Markdown 수정 때문에 별도 CI를 만들지 않는다.
  렌더링 구현은 변경하지 않으므로 조판 전수 시각 검증은 기본 범위가 아니다.

## 6. 완료·복구 기준

- 필수 의존 목록과 보존/제거 결정이 source·이력 근거로 설명된다.
- Gym이 없는 격리 소스에서 관련 제품 빌드·실행·패키징 성공 증적이 있다.
- 선택적 Gym 실행과 기존 일반 CLI/API 계약이 유지된다.
- 제품/Gym 운영 경계가 실제 구현과 권위 문서에서 일치한다.
- 최종 보고서는 exact SHA, 명령, 성공·실패·미확인 범위, 패키지 포함물과 복구 경로를 구분한다.

복구는 본 이슈에서 변경한 코드·문서 커밋의 되돌림으로 한정한다. Gym 자산이나 사용자 문서를
삭제하는 방식으로 복구하지 않는다. 격리 검증 공간은 정확한 경로와 내용 확인 후 정리하며
재현에 필요한 최소 증적은 `output/6916/`과 보고서에 남긴다.
