## 1. 배경

`samples/hwp3-sample19.hwp` (HWP3 원본, 25,471 B) 를 rhwp HWP3 파서로 열면 파싱 실패한다.

```
$ rhwp dump samples/hwp3-sample19.hwp
오류: HWP 파싱 실패 - 유효하지 않은 파일: HWP 3.0 오류:
입출력 오류가 발생했습니다: failed to fill whole buffer
```

동일 원본을 한글 편집기에서 HWP5/HWPX 로 변환한 fixture 두 개는 정상 동작한다.

| 파일 | 크기 | 결과 |
|------|------|------|
| `samples/hwp3-sample19.hwp` | 25,471 B | ❌ 파싱 실패 |
| `samples/hwp3-sample19-hwp5.hwp` | 29,184 B | ✅ 정상 |
| `samples/hwp3-sample19-hwpx.hwpx` | 29,016 B | ✅ 정상 |

시그니처는 정상 (`HWP Document File V3.00 \x1a\x01\x02\x03\x04\x05`), 헤더 직후 바이트 패턴도 기존 hwp3 샘플과 동일.

## 2. 원인 가설

`failed to fill whole buffer` 는 `std::io::Read::read_exact` 가 EOF 에 닿았을 때 표준 라이브러리가 내는 메시지다. HWP3 파서 어느 지점에서 선언된 레코드/세그먼트 길이만큼 읽지 못한 채 파일 끝을 만났다는 뜻.

`src/parser/hwp3/` 내 `read_exact` 호출 후보 (1차 스캔):

- `records.rs` — DocInfo·StyleList·ParaShape·CharShape·TabDef 등 헤더 직후 레코드
- `paragraph.rs` — 문단 내부 데이터/링크 정보
- `drawing.rs` — 도형/링크/매크로/그림 객체
- `ole.rs` — OLE 매입 객체
- `mod.rs` — 본문 cursor 의 6개 지점은 `read_exact` 실패를 `break` 로 흡수하므로 EOF 가 통과될 수 있음. 즉 이 6곳은 용의자가 아니고, 그 외 모든 `?` 전파 지점이 후보.

가장 의심: hwp3-sample19 에만 등장하는 특정 컨트롤(도형·OLE·매크로 등) 의 길이 필드 해석 오프바이원 또는 한컴 사양 외 변형.
