## 1. 배경과 기준선

현재 `#icon-toolbar`는 #3243·PR #3255 이후 `.tb-group` 단위 줄바꿈을 허용하고, 1023px 이하에서는
label을 숨기고 버튼 폭을 44px에서 36px로 줄인다. 이 방식은 모든 명령을 즉시 노출하지만 창 너비에
따라 높이·밀도·명령 위치가 달라진다.

2026-08-26 로컬 Chrome에서 기본 모드의 가시 group을 실측한 결과는 다음과 같다.

| viewport | 현행 높이 | group 행 | 버튼 밀도 | 콘텐츠 폭 |
| ---: | ---: | ---: | --- | ---: |
| 1920, 1280px | 56px | 1행 | label 포함 44px | track 1219px |
| 1024px | 99px | 2행 | label 포함 44px | 1172px |
| 976, 883, 768px | 53px | 2행 | icon-only 36px | 988px |
| 412, 375px | 77px | 3행 | icon-only 36px | 988px |

1024px에서 높이가 거의 두 배가 되고, 1023px 경계를 넘으면 다시 작은 버튼으로 바뀐다. 따라서 device
breakpoint보다 한 줄 scroll viewport가 편집 영역의 위치와 명령의 공간 기억을 안정적으로 보존한다.

## 2. 제품 결정

- `#icon-toolbar`는 지원하는 모든 너비에서 56px 한 줄을 유지한다.
- 1023px 이하에서도 기존 데스크톱의 label 포함 44px 버튼 밀도를 유지한다.
- 콘텐츠가 들어가면 이동 버튼을 숨기고 현재 전체 도구를 그대로 표시한다.
- 콘텐츠가 넘치면 좌우 이동 버튼과 한 줄 scroll viewport를 표시한다.
- 버튼 클릭은 다음·이전의 **가시 `.tb-group` 시작 경계**로 이동한다.
- trackpad 수평 wheel과 touch pan은 native horizontal scroll을 사용한다.
- 첫·끝에서는 해당 이동 버튼을 disabled 처리한다.
- mode group이 바뀌면 시작 위치로 복귀하고 overflow·disabled 상태를 다시 계산한다.
- 기존 명령 DOM, 순서, ID, listener, active/disabled 상태를 복제하지 않는다.

```text
#icon-toolbar
├─ [이전 그룹]
├─ .tb-scroll-viewport
│  └─ .tb-scroll-track
│     ├─ 기존 .tb-group / .tb-sep 순서
│     └─ 기존 mode 전용 group
└─ [다음 그룹]
```

## 3. 기존 자산 재사용

- 현재 `.tb-group`, `.tb-btn`, `.tb-label`, sprite·text icon과 command wiring
- `#icon-toolbar`의 theme background, border와 `--ui-*` 상태 token
- #6115의 `#icon-toolbar` ID 기반 visibility와 `Ctrl+F1` focus 계약
- 머리말/꼬리말, 주석, 개체 선택 시 기존 inline `display` 전환
- [기존 구조 계약 테스트](../../rhwp-studio/tests/responsive-toolbar-layout.test.ts)와
  [반응형 E2E](../../rhwp-studio/e2e/responsive.test.mjs)

좌우 이동 기호는 별도 그래픽 자산을 복제하지 않고 현재 글꼴·theme token으로 그리는 이중 꺾쇠를 사용한다.

## 4. 범위

### 4.1 범위 안

- 기존 group을 담는 scroll viewport·track과 좌우 이동 버튼
- 한 줄·56px 고정, desktop label·button 밀도 보존
- group 경계 이동, native horizontal wheel·touch pan, focus 가시성
- resize와 mode group 변경 시 overflow 재계산
- 시작·끝 disabled, accessible label과 hidden 상태
- 1920~375px, 세 skin × light/dark, toolbox 접기/펴기 통합 검증

### 4.2 범위 밖

- `#style-bar`의 #6118 반응형 정책 재변경
- 최상단 `#menu-bar`, 상태 표시줄, renderer·WASM 변경
- 명령 순서·동작·단축키 또는 user setting schema 변경
- 명령 우선순위 기반 자동 숨김이나 더보기 메뉴
- 한글 2024 그래픽 자산 복제

## 5. 단계별 수행계획

### Stage 1 — 기준선과 구조 계약 고정

1. 1920~375px의 높이·행 수·버튼 밀도와 기본 mode 콘텐츠 폭을 실측한다.
2. 외부 ID, 명령 DOM·순서, mode·visibility 계약을 목록화한다.
3. 한 줄 viewport, 이동 버튼, group 경계 이동과 접근성 계약을 문서화한다.

**완료 결과(2026-08-26)**: [Stage 1 보고서](../working/task_m100_6138_stage1.md)에 현행 1~3행과
1219px desktop track 기준선을 고정했다. 제품 source 변경은 0건이다.

### Stage 2 — DOM·CSS·controller 구현

2. device breakpoint의 wrap·label 숨김·버튼 축소 규칙을 제거한다.
3. ResizeObserver·MutationObserver 기반 controller와 group 경계 이동을 구현한다.
4. source 계약과 controller 테스트, responsive E2E를 갱신한다.
5. `mydocs/working/task_m100_6138_stage2.md`에 결과를 기록한다.

**종료 게이트**: 1920~375px에서 한 줄·56px이며 첫 group부터 마지막 group까지 버튼·wheel·touch·focus로

**완료 결과(2026-08-26)**: [Stage 2 보고서](../working/task_m100_6138_stage2.md)에 single track DOM,
