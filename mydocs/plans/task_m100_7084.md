## 1. 목표와 비범위

`실물😀\n본문`의 `😀`(U+1F600)가 rhwp-studio에서 가로로 압축되어 보이는 현상을
실제 선택된 폰트·문자 서식·폭 측정·그리기 경로에 따라 설명하고 원인 계층에서 수정한다.
특정 이모티콘의 너비를 고정하거나 모든 이모티콘을 정사각형으로 만드는 보정은 하지 않는다.
문서의 의도적인 장평과 자간을 보존한다. 잘못 좁은 진행폭을 바로잡아 뒤 글자 위치·줄 나눔이
달라질 수 있으므로, 기존 좌표를 무조건 유지하는 대신 동일 입력의 한컴 출력과 정상 조판 계약으로
판정한다. 영향 없는 문자·문단의 메트릭과 배치는 유지한다.

수정 방향은 **대체 글리프 선택 → 해당 폰트/조형 결과의 메트릭으로 배치 → 같은 선택으로 그리기**다.
이모티콘의 실제 너비/높이 비율을 유지하되, 진행폭·그림 경계·줄 높이를 구별한다.
폰트 DB에 이름이나 문자 폭을 추가하는 것만으로 작업 완료를 선언하지 않는다.

파일은 한컴과 Studio에서 정상 열렸다는 메인테이너 판정이 있다. 이는 파일 열림 판정이지
현재 devel의 시각 재현 또는 파싱·서식·메트릭의 무결성 확인을 대신하지 않는다.
Stage 1 실행 조사에서는 문자 보존과 측정/그리기 불일치를 확인했다. 현재 증상을 #3587의
복사·채우기/저장 결함 또는 UTF-16 문자 누락 때문으로 분류하지 않는다.

표 페이지네이션 #7065, 표 간격 #7090, Gym 확장, 전역 커닝 정책 및 전체 폰트 DB 재계측은
이번 범위가 아니다. 수정에 꼭 필요한 확장이 발견되면 근거와 함께 계획 변경을 요청한다.
모든 이모지 결합열을 새로 지원하는 조형 엔진 도입이나 폰트 배포채널 추가도 이번 계획에 포함하지 않는다.

### 3.1 남은 조사 — 실행 경로와 독립 정답지 연결

다음 연결을 동일 문자/cluster에 대해 계측한다.

`원본 문자·서식 → Document IR → 폰트 선택/폭 측정 → layout advance → backend 글리프·가로 배율`

1. **환경과 선택 고정**: 완료한 DB 조사를 재계측하지 않고, 실제 Studio backend, 브라우저,
   로드된 WASM/JS hash, 폰트 감지 세대·권한, CSS chain 또는 Typeface와 파일 식별을 기록한다.
   디스크의 새 WASM이 브라우저에 로드됐다고 추정하지 않는다. 실제 대체 face를 직접 식별할 수
   없으면 폭 일치만으로 특정하지 않고 `ambiguous`로 남기며 통제된 폰트 입력과 구분한다.
2. **문자·서식 대조**: 두 형식에서 U+1F600의 보조 평면 문자 보존, UTF-16 길이와 Unicode
   문자/cluster 단위, 글자 크기·언어 슬롯·장평·자간·첨자·정렬 및 저장/재열기를 확인한다.
3. **폭과 그리기 대조**: 지정 폰트, 실제 fallback 글리프 폰트, advance(다음 글자 시작까지의 폭),
   ink bounds(실제 그림 영역), 장평과 fit 배율을 각각 기록한다. 이 값들을 같은 개념으로 섞지 않는다.
   측정과 paint가 서로 다른 폰트나 단위를 사용하는지, 간격을 글리프 크기에 포함하는지 확인한다.
   최소 한 레코드에 원본/IR 서식, 선택 메트릭과 출처, glyph/cluster, 크기·단위, 자연 advance,
   최종 layout advance, 가로·세로 배율, 실제 그림 경계의 확인 여부를 연결한다.
   Canvas2D·CanvasKit·native의 미실행 경로는 미검증으로 표시한다.
4. **계보 판정**: 먼저 동일 입력의 현행 devel과 관련 변경 이력을 대조한다. 확인 가능한 이전
   배포/코드 기준에서 같은 환경으로 필요한 소수 비교만 실행해 회귀·기존 미해결·환경 차이를 구분한다.
   새로 추가된 샘플이라는 사실만으로 회귀라고 판정하지 않는다.
5. **한컴 기준 대조**: 확보된 두 저장본과 대응하는 유효한 PDF를 우선 재사용한다. 없을 때만
   새로 생성하며 한컴 버전·입력/PDF/font hash·producer를 남긴다. 같은 영역의 이모티콘 비율,
   앞뒤 문자 위치, 줄바꿈·줄 높이를 비교한다. 컬러 glyph의 base outline과 최종 그림 경계를
   혼동하지 않는다. 다른 워드프로세서와의 전체 성능·시각 비교는 필수 게이트로 추가하지 않는다.

현재 코드에서 폭 맞춤 관련 공통 경로 `src/renderer/mod.rs::glyph_fit_advance`,
`src/renderer/layout/text_measurement.rs`, `src/renderer/svg.rs`, `src/renderer/web_canvas.rs`,
`rhwp-studio/src/view/canvaskit-renderer.ts`를 탐색 시작점으로 확인했다.
이는 원인 확정이나 해당 파일 전부를 수정하겠다는 목록이 아니다.

### 3.2 구현계획에서 확정할 계약

Stage 1 이후 아래 항목을 [구현계획](task_m100_7084_impl.md)에 구체화했다.
실제 선택·메트릭/조형 결과의 재사용 제약과 backend별 증거 수준을 해당 계획에서 구분한다.

- **선택의 소유 계층**: 지정 폰트가 글리프를 갖는 경우와 없는 경우를 구별한다.
  없는 경우에는 실제 사용 가능한 대체 폰트와 glyph/cluster를 결정하는 계층을 특정한다.
  문자마다 paint가 별개 폰트를 추측하는 상태로 측정만 보정하지 않는다.
- **메트릭의 출처**: 단독 글리프는 실제 face의 메트릭, 조합열은 지원되는 조형 결과의 advance를
  근거로 한다. 정적 DB 보완이 필요하면 승인된 원본·수록 범위·생성기/overlay 소유권을 특정한다.
  historical generated 영역이나 generated projection을 임의 수정하지 않는다.
- **배치와 그리기의 일치**: 선택된 face·glyph/cluster·크기·진행폭·출처를 공통 결과로 소비한다.
  잘못된 fallback 폭에 맞추는 추가 압축은 원인과 함께 해소하고, 의도된 장평·자간·정렬은 보존한다.
- **자연 비율과 크기 조정의 분리**: 대체 폰트의 크기 조정이 필요하면 독립 근거를 갖춰 배치와
  그리기에 동일 적용한다. “1em 정사각형” 또는 glyph 그림 너비=advance라는 가정은 금지한다.
  줄 높이·기준선은 기존 조판 계약에서 검증하며 이모지 그림 높이로 일괄 교체하지 않는다.
- **사용 불가 상태**: 폰트 bytes 미확보, 지원 glyph 없음, 선택 불명확 상태의 처리와 제한을 명시한다.
  미확인 폭을 exact 메트릭으로 보고하지 않는다. native/WASM의 서로 다른 환경에서도 동일 입력과
  동일 폰트 자원·정책이면 결정이 재현되어야 한다.
- **자원·비용**: 기존 캐시·폰트 감지 세대를 재사용한다. 글자별 hot path에 파일 읽기·네트워크·
  폰트 전수 열거를 넣지 않는다. bytes 파싱과 조합열 처리는 기존 자원 상한을 유지한다.

Stage 1에서 실행 경로가 예상과 다르면 이 계약을 실제 원인 계층에 맞춰 조정한다.
일괄 emoji 폭 상수, paint fit 전역 해제, 전체 shaping 엔진 재작성으로 우회하지 않는다.

단계 전환 전 해당 단계 변경을 커밋한다. 오늘할일·PR review는 제출 시점의 역할별 절차로 처리하며

별도 구현계획 승인 후 진행한다.

## 5. 보호 불변식과 비례 검증

### 5.1 완료 판정에 필요한 최소 검증표

| 대상 | 확인할 계약 |
| --- | --- |
| 기존 HWP/HWPX 두 입력 | 원본 서식·문자 보존, 실제 fallback 선택과 advance 출처 확인, 한컴 대비 비율·주변 배치 판정 |
| 지원 폰트의 단독 `😀` / 지정 폰트에 glyph 없는 `😀` | exact와 fallback 각각 실제 메트릭 사용, 0.5em 추정 폭의 무근거 강제 적용 없음 |
| 이모지 뒤에 문자가 있는 줄·가용 폭 경계 | 그림 비율뿐 아니라 뒤 문자 겹침·줄바꿈의 정합 확인 |
| 장평 100%·비100%, 자간 0·양수·음수 | 문서 지정은 보존하고 배율/간격 이중 적용 없음 |
| 주변 한글·영문·숫자·기호·비이모지 보조 평면 문자 | 새 선택 규칙의 적용/비적용 경계, 기존 정상 메트릭 보존 |
| VS16·ZWJ 대표 입력 | 기존 cluster 계약 손상 및 코드 단위별 폭 단순 합산 여부 확인; 새 지원 범위 확대는 별도 판단 |
| 폰트 사용 불가·모호한 선택 | 실패/대체 상태와 제한이 드러나고 환경 차이를 숨기지 않음 |

제품 수정은 위 표의 필요한 최소 반례로 먼저 검증한다. 현재 backend 이외의 출력은 변경 영향에 따라
범위를 정하되, 공통 경로 수정 시 Canvas2D의 성공을 CanvasKit/native의 성공으로 대체하지 않는다.
실물 시각 판정은 작업지시자가 한다. 합성 테스트나 외부 API 계약만으로 한컴 일치를 선언하지 않는다.

### 5.2 불변식과 제출 검증

- 문서가 지정한 장평/자간은 유효한 의미로 적용하고, 동일 배율을 측정과 paint에서 이중 적용하지 않는다.
- 동일 문자·서식·폰트의 측정 결과를 배치와 그리기에서 일관되게 소비한다. glyph 폭과 다음 시작점의
  advance를 구별하되 두 값을 임의 상수로 맞추지 않는다.
- 핵심 실물 대조군은 위 HWP/HWPX 두 개다. 한글·영문·숫자·일반 기호, 비이모지 보조 평면 문자,
  명시 장평/자간을 관련 반례로 고른다. VS16/ZWJ 등 cluster 문제가 원인에 관련되면 필요한 사례만 추가한다.
- 폰트 미설치/대체 상황은 실제 폰트 파일과 선택 결과로 분리한다. 환경을 몰래 변경하거나 모든 환경에서
  동일 이모티콘 모양을 보장한다고 주장하지 않는다.
- 원본·한컴 기준·수정 전후는 같은 영역을 표준 compare/overlay/review 방식으로 대조한다.
  픽셀 점수만으로 비율 정상·주변 위치 보존을 판정하지 않는다. 측정치와 메인테이너 판정을 구분한다.
- 새 Rust 회귀는 `tests/cases/`에 작성하고 generated suite/manifest를 PR에 포함하지 않는다.
  소스·테스트 변경 시 현행 Rust lint 묶음, frontend 변경 시 해당 Node 검사, 렌더러 변경 시
  전체 회귀 및 Native Skia/Render Diff 등 [범위별 게이트](../manual/pr_review/local_validation.md)를 적용한다.
- golden/baseline/래칫 허용치를 테스트 통과 목적으로 완화하지 않는다. 불가피한 정상 출력 변화는
  독립 정답지·전후 위치·영향 범위를 먼저 제출한다.
- 폰트 선택·측정 경로가 바뀌면 동일 문서의 cold/warm 처리 비용과 probe/cache 횟수를 전후 비교한다.
  DB/자원이 추가되면 WASM 크기·메모리 영향도 기록한다. 전수 코퍼스 재계측은 기본 단계로 넣지 않는다.
- 완료 조건은 두 형식의 메인테이너 시각 통과, 원인 경로/반례 검사 통과, 변경 범위별 게이트 통과,
  알려진 제한 공개다. 계획 승인·DB 항목 증가·파일 열림만으로 완료 처리하지 않는다.

## 용어

- IR (Intermediate Representation): 포맷을 파싱한 뒤 엔진이 공통으로 사용하는 문서 표현.
- advance: 다음 문자/cluster의 시작 위치까지 진행하는 폭. 글리프가 칠해진 실제 영역의 너비와 다를 수 있다.
- fallback: 지정 폰트가 해당 글리프를 제공하지 않을 때 다른 폰트에서 선택하는 처리.
- glyph / cluster: 그려지는 글자 모양 / 함께 조형·배치되는 문자 묶음.
- UTF-16 surrogate pair: 보조 평면 문자 한 개를 16비트 코드 단위 두 개로 표현하는 방법.
- fit 배율: 배치된 폭과 실제 글리프 폭을 맞출 때 적용하는 배율. 문서의 장평과 같은 것으로 가정하지 않는다.
- em / unitsPerEm: 폰트 설계 좌표의 기준 단위 / em 하나를 구성하는 설계 단위 수. 그림 높이와 다르다.
- shaping(조형): 문자열·폰트·서식에서 실제 glyph와 진행폭·위치를 구하는 과정.
- SFNT: TrueType/OpenType 등이 사용하는 폰트 테이블 컨테이너 형식. 이름 탐지만으로 bytes 확보가 보장되지 않는다.
- Typeface: 그리기 엔진에서 사용하는 실제 폰트 face 객체.
- VS16 (Variation Selector-16) / ZWJ (Zero Width Joiner): 이모지 표현 선택자 / 결합열 연결 문자.
- ascent/descent: 기준선 위/아래 폰트 메트릭. 실제 그림 경계나 문단 줄간격과 동일하지 않다.
