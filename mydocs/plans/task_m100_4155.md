## 1. 문제

HWP3 문서를 `rhwp convert` 로 HWP5 변환한 뒤 한컴으로 열면 **본문 전체가 검정 막대**로 덮인다.
글자는 제 위치·제 크기로 그려지고 그 위에 순검정 사각형이 칠해진다(`samples/SO-SUEOP.hwp`
변환본 한컴 PDF 3쪽 실측: 줄 크기 검정 fill 65개, 원본은 글리프 크기 35개).

`convert_char_shape` 가 HWP3 글자 음영의 **음영 비율(offset 25)을 무시**하고 팔레트
인덱스(offset 23)만 읽었다. 비율 0 은 음영 없음이고 실문서 다수인데 — SO-SUEOP 은 2,511건
전건이 0 — 인덱스 0(검정)만 보고 `0x00000000` 을 썼다.

`rhwp export-svg` 는 정상이라 자체 검증으로는 안 보인다. 렌더러가 검정을 "음영 없음"
sentinel 로 쓰기 때문이다. HWPX 축도 라이터 반창고(`shade_color == 0 → "none"`)로 가려져
있었고 **HWP5 바이너리 축만** 깨졌다.

## 2. 이슈 원안에서 조정한 두 지점

실측 근거는 [stage1](../working/task_m100_4155_stage1.md) §3·§4.

1. **합성 공식** — 이슈는 표 셀용 `hwp3_table_cell_shade_color` 재사용을 제안했으나, 그 함수의
   정수 반올림이 이슈 본문의 한컴 실측과 15%/6% 에서 1씩 어긋난다. 실측 정합 helper 를
   신설하고 셀 helper 는 손대지 않는다(셀 축은 대응 실측 없음).
2. **sentinel** — 이슈는 HWP5 라이터가 `0 → 0xFFFFFFFF` 로 번역할 것을 제안했으나, IR 의
   "음영 없음"은 이미 `0xFFFFFFFF` 로 수렴해 있고 HWP3 변환부만 이단이었다. IR sentinel 을
   통일하면 라이터 3종이 무수정으로 정합한다. IR `0` 은 "진짜 검정 음영"으로 남아 의미가
   깨끗해진다.

## 3. 범위 — L1 + L2 한 PR, 커밋 분리

**L1 (커밋 1·2)**: 결함 수정과 회귀 고정.

| 파일 | 변경 |
| --- | --- |
| `src/model/color.rs` (신설) | `NONE` sentinel 상수 |
| `src/model/mod.rs` | `pub mod color;` |
| `src/model/style.rs` | `CharShape::default().shade_color` → `color::NONE` |
| `src/parser/hwp3/mod.rs` | `hwp3_char_shade_color` 신설 + `convert_char_shape` 배선 |
| `src/parser/hml/reader.rs` | `ShadeColor` 속성 부재 → sentinel |
| `src/document_core/builders/exam_paper.rs` | 명시 `shade_color: 0` 제거 |
| `tests/issue_4155_hwp3_char_shade_contract.rs` (신설) | 저장 바이트/XML 계약 6종 |

**L2 (커밋 3)**: "음영 없음" 판정이 7곳에 4종으로 흩어지고 그중 둘이 렌더러와 어긋난 것을
`model::color` 한 곳으로 접는다([stage1](../working/task_m100_4155_stage1.md) §5).

L1 만 해도 IR 값이 `0 → 0xFFFFFFFF` 로 바뀌어 `paint_op.rs` `is_fill_only_glyph_replay` 가
HWP3 에서 뒤집히므로 시각 검증 레인은 어차피 필요하다. 같은 레인에서 한 번에 끝내되 커밋을
분리해 리뷰어가 따로 거부할 수 있게 한다.

**손대지 않는 것**: `serializer/char_shape.rs`·`serializer/hwpx/header.rs`·
`serializer/hml/head.rs`. 라이터는 "값을 보존하는가"를, 렌더러는 "그려지는가"를 묻는 다른
질문이다 — 흰색 음영(`0x00FFFFFF`)은 한컴 코퍼스에 49건 실재하고 저장에선 보존돼야 한다.

## 4. 검증

`mydocs/manual/pr_review/local_validation.md` §4.3 의 renderer 행을 적용한다
(`paint`·`renderer` 변경 포함). 결과는 [stage3](../working/task_m100_4155_stage3.md)·
[report](../report/task_m100_4155_report.md).

계약 테스트는 **변이 검증**으로 red 를 먼저 확인한다 — 수정 커밋을 되돌려 실행하고, 실패
분포가 이슈 본문("HWPX 축은 정상, HWP5 축만 깨짐")과 일치하는지 본다. 일치하지 않으면 진단이
틀린 것이므로 멈추고 다시 잰다.

최종 시각 판정 권위는 작업지시자(한컴)다. 자체 SVG 는 무회귀 증적일 뿐이다.

## 5. 후속으로 넘기는 것

- `hwp3_table_cell_shade_color` 의 절상 반올림. 셀 음영이 있는 HWP3 표본을 한컴으로 저장해
  실측한 뒤 별도 이슈로 글자용과 통일한다.
- `shade_color: Option<ColorRef>` IR 리팩터링. sentinel 을 아예 없애는 게 정답이지만
  소비처가 많아 독립 이슈다.
