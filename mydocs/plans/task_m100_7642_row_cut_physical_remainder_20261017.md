# #7642 일반 행 잔여 높이와 병합 블록 컷의 소유 구분

Issue: #7642.

## 독립 근거와 원인

법령 원본과 기존 한컴 Print PDF의 61쪽을 같은 글꼴 공급·PDFium·96 DPI로
비교했다. 후보9b61cda0ed의 Native raw 일치율은40.97681%다. review와
standalone overlay에서 이어받은 첫 본문 앞에 빈 띠가 생겼다. 가로 폭 보정은
유효하지만 이 세로 차이를 면제하지 않는다.

실제 실행의 `NESTED_FRAME`에서24×14 표의 시작 컷은8행부터의 병합 블록
슬롯10개다. 298211faf7에서는 시작 override가 없고8·9행의 소비된 내용 높이는
0이었다. 새 후보는 같은 컷에 `start_override=29.44`를 전달했다.

`emit_table_fragment`의 일반 재조판 행 잔여 산식이 종료 블록 컷까지 읽는다.
`end_row - 1`의 일반 칸 최소와 블록 슬롯의 내용 높이를 빼서 만든 차액을
블록 시작행의 상자로 전달한다. 서로 다른 컷의 소유자와 높이를 혼용한 것이다.

## 수정과 소비 경로

일반 행 최소 높이의 잔여 산식은 일반 행 종료 컷만 소비한다. 병합 블록의
종료 컷은 기존 블록 잔여와 걸침 칸 장부가 계속 소유한다. 일반 칸의 독립
최소를 삭제하거나 병합 칸이 있다는 이유로 배제하지 않는다.

생산자는 `continuation/fragment/emit.rs`의 next 시작 높이다. 이 값은
continuation cursor와 다음 scan, `PageItem::PartialTable`,
`table_partial.rs`의 시작 행 실제 높이에 전달된다. paint에서 clamp하거나
빈 띠만 숨기지 않고, 잘못된 소유자의 잔여를 발행하는 원인을 고친다.

## 검증과 반례

같은 source에서 법령 전74쪽 Native/fresh WASM을 재산출한다. 61쪽의 잘못된
29.44px 잔여 제거와 본문 순서·표 외곽을 직접 판독한다. 일반 행 컷인43·44쪽은
최소 높이 보정이 유지되는지 대조한다. 19쪽 종료 간격과60쪽 가로 폭도 확인한다.
전쪽90%·쪽수·확대 판독 전에는 새 실물 회귀를 추가하지 않는다. 전체102문서와
고정 devel 대비 하락, 필수 Rust/lint/UI는 별도 최종 gate로 유지한다.
