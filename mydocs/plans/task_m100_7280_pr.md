   base가 바뀌면 영향·충돌을 먼저 확인하고 정책 검사와 영향 검증을 갱신한다.

   제품이 바뀌면 해당 회귀·fresh WASM·시각 증거를 갱신한다. baseline/ignore 완화는 하지 않는다.
3. 커밋 완료 후 아래 본문의 `@HEAD@`를 실제 `git rev-parse HEAD`로 치환하여
   `output/7280/pr-body.md`로 준비한다. 이 계획 파일 전체를 PR 본문으로 게시하지 않는다.
   이후 commit이 추가되면 raw URL과 본문도 다시 생성한다.
4. 승인된 경우에만 다음 명령을 실행한다. 생성 전 동일 head의 기존 PR 유무를 확인한다.

```bash
git push origin task_m100_7280
gh pr create --repo edwardkim/rhwp --base devel --head task_m100_7280 \
  --title 'refactor(layout): separate typeset responsibilities and document rule ownership' \
  --body-file output/7280/pr-body.md
```

생성 뒤 API로 base/head/body와 SHA 고정 asset의 존재를 확인하고 PR 화면의 이미지 표시를 확인한다.
PR 번호는 그때 받아 역할에 맞는 review 절차로 이어간다. CI·review·merge 승인을 미리 선언하지 않는다.
