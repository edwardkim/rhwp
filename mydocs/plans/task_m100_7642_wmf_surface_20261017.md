# #7642 WMF Print surface와 실제 글꼴 공급의 공통 경로

## 독립 근거와 위반된 계약

[bitmap 계획](task_m100_7642_bitmap_tone_20261017.md), stage2101·2127·2132를 이어간다.
정상 저장본 `samples/hwp3-sample16-hwp5.hwpx` 18·35쪽이 원본에 대응하는 독립
2024 Print PDF와 Native/fresh WASM에서 모두 90% 미만이다. 단순 SVG fill 목록은
clip·덮어쓰기·DIB 보간 뒤의 실제 색 수가 아니며, SVG 이미지의 텍스트는 Canvas
FontFace 등록만으로 공급되었다고 판단할 수 없다. 원본/PDF를 고쳐 맞추지 않는다.

독립 Print의 WMF 자원은 600DPI raster이며 source RGB와 흑백 예약색을 합친
visible palette의 경계를 따른다. 작성 대조군은 별도 입력이며 정상 저장본의
완료 증거를 대신하지 않는다. 잘못 작성한 0x8008 선택은 원본/실패 증거를 보존하고
명시적 PS_NULL 생성 대조군으로 분리했다. 정상 35쪽의 원인과 혼동하지 않는다.

## 생산·소비 경로

현재 WMF → image_resolver → SVGPlayer → backend별 SVG painter를,
Print 2024·RealPic·밝기/명암 0에서만 공통 source surface로 연결한다.
원본 WMF의 SVG → 전체 자원/crop/fill/변환의 장치 크기 → 실제 공급 font database →
600DPI 최종 합성 → 흑백 예약색 포함 visible RGB 판정 → 기존 전달색 보정 →
OutputDevice PNG를 동일한 PageLayerTree가 소비한다. 측정·문단·쪽 배치는 바꾸지 않는다.

장치 의존 payload는 원본 bin key로 재조회하지 않는다. 기존 OutputDevice 계약을
따라 실제 PNG를 싣고 host는 내용 기반 image key를 사용한다. surface cache는
원본 내용·장치 가로/세로·font source fingerprint를 포함하고 메모리 상한을 둔다.

Native는 실제 시스템/설정 경로와 문서의 내장 font를 사용한다. WASM은 별도 paint
font API로 실제 host font bytes·TTC face·alias를 공급하며 기존 HFT·exact layout
slot API의 의미를 넓히지 않는다. 공급 세대 변경 뒤 layer/JSON cache를 무효화한다.
필요한 글꼴을 확보하지 못하면 텍스트를 지운 PNG를 정상 결과로 캐시하지 않는다.

## 적용·비적용 경계와 검증

- 2024 Print 원본색 WMF의 clip·겹침·palette 경계·DIB 보간·글꼴을 같은 결과로 확인한다.
- 2020·Screen·WMFC의 enhanced content와 기존 EMF 장치는 각각 기존 계약을 보존해 대조한다.
- 크기 상한·비정상 입력·지원하지 않는 효과는 기존 실패/fallback과 구분하며 정상으로 보고하지 않는다.
- 공통 raster 의존성은 Native 기능 없이 WASM에도 빌드되도록 fs·mmap 기능을 분리한다.
- Native 먼저 방향을 확인하되 최종 수용은 fresh WASM 및 실제 Studio 준비 경로까지 확인한다.
  같은 source·PDF·96DPI의 전쪽 TSV와 확대 판독, 최신 devel 대비 무하락을 모두 적용한다.
- 새 회귀는 원본 출력 보정·관련 전쪽 양쪽 90%·직접 판독 후 새 이름으로 추가한다.
  기존 hash·baseline을 먼저 갱신하지 않는다. 합성 null-pen 격자의 알려진 차이도 남긴다.

코드 변경 뒤 Native/fresh WASM을 새로 빌드한다. 진행 중인 이전 source의 queue는
그 producer SHA의 결과로만 기록하며 새 엔진의 완료 증거로 재표기하지 않는다.
공용 target 작업 트리 전환 시 source 해시뿐 아니라 crate 재빌드도 확인한다.

## 내부 자원의 종횡비와 최종 배치의 분리

stage2158의 정상 저장본 35쪽은 최종 그림 크기는 독립 PDF와 거의 같지만 내부 PNG가
3898×2853이고 독립 PDF 자원은 4561×2853이다. 원본 WMF viewport는 6377×3989다.
같은 정사각형 WMF를 가로형·세로형으로 배치한 별도 stage2159 입력을 한컴 2024의
Print로 출력했다(stage2160). PDF는 서로 다른 배치 사각형에 **동일한 1500×1500 자원**을
재사용한다. 원본 비율과 장치 표본 수를 보존하고 최종 배치에서 늘리는 독립 근거다.

따라서 crop·fill·변환으로 구한 전체 표시 크기에서 가로·세로 요구 배율의 최댓값을
고르고, 그 단일 배율로 원본 viewport를 raster한다. 최종 ImageNode 위치·크기와 crop은
변경하지 않는다. 가로·세로 중 한 방향에 고정한 배율이나 문서별 보정을 쓰지 않는다.
이 대조군과 정상 18·35쪽을 새 Native/fresh WASM에서 비교하고, 대조군 전쪽 검증과
직접 판독 전에는 관련 정식 회귀를 추가하지 않는다.
