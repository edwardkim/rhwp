## 1. 결정과 목표

W4는 선언 빈도가 높은 font를 나열하는 작업이 아니다. 실제 renderer에서 metric이 해소되지 않은 문자가
장평 축소·음수 자간·고정 frame 성격의 문맥·LineSeg 상태와 **같은 usage row에서 동시에 나타난 양**을
계산해, W5에서 어떤 document face부터 exact/missing oracle로 조사할지 정한다.

결과는 두 층으로 분리한다.

1. **실측 조판 위험 순위**: W3의 문자별 decision과 실제 교차 노출만 사용한다.
2. **W5 실행 준비도**: 정부·법정 서식 근거, exact source 확보 상태, backend 선택 불일치처럼 조사
   효율과 공공 중요도를 높이는 증거를 별도 flag로 기록한다.

준비도 flag는 실측 risk mass를 바꾸지 않는다. 최종 W5 queue에서도 다른 위험 band를 건너뛰는
숨은 가중치로 쓰지 않고, 같은 band 안의 조사 순서와 후보별 질문을 구체화하는 데만 사용한다.

## 3. 필드 compatibility 감사

### 3.1 그대로 사용할 수 있는 축

| W4 질문 | W3 필드와 판정 |
| --- | --- |
| 실제 metric 위험 문자 | `coverageCategory`가 `face-miss`·`char-miss`·`heuristic`인 `charCount` |
| 장평 축소 | `ratio < 100`; 극단 축은 historical POC와 같은 `ratio <= 90` |
| 음수 자간 | `spacing < 0`; 극단 축은 historical POC와 같은 `spacing <= -5` |
| 압축 노출 | `ratio < 100 || spacing < 0`, 실제 같은 행의 교집합 |
| 포맷·언어·style | `format`, `language`, `bold`, `italic`, `kerning` |
| 문맥 proxy | `context` |
| LineSeg lane | `storedLineSeg` boolean |
| resolver 원인 | normalized/requested/resolved face, match·relation·width source 계보 |

W3에서 위험 category 세 개의 합은 2,061,732자다. 그중 압축 노출 1,380,970자, historical fixed-frame
proxy 1,038,224자, 두 조건의 교집합 779,851자다. stored LineSeg lane은 1,985,948자이고
missing/placeholder lane은 75,784자다. 이는 ranker 구현 가능성을 확인한 착수 수치이지 W4 최종 순위가
아니다.

### 3.2 이름을 정확히 제한할 축

#### fixed-frame proxy

POC의 `fixedFrame`은 실제 bbox·column boundary·남은 slack을 계산한 geometry 판정이 아니다. historical
generator는 다음 context bit 가운데 하나라도 있으면 fixed frame으로 셌다.

```text
table-cell | text-box | caption | header | footer | master-page
```

W4는 이 정의를 byte-for-byte 재사용하되 출력 이름을 `fixedFrameContextProxy`로 한다. 실제 fixed frame,
overflow 또는 한 줄 틀이라고 승격하지 않는다. 문서별 `riskDocuments`에는 face 연결 key가 없으므로 이를
W3 row에 추정 join하지 않는다.

#### LineSeg lane

W3의 `storedLineSeg=true`는 `line_segs`가 비어 있지 않고 전부 missing placeholder가 아니라는 뜻이다.
정상 범위, 경계 slack, 최신성 또는 한컴이 실제로 신뢰할지를 보증하지 않는다. 따라서 W4는 다음 두 lane을
독립 집계한다.

- `stored-line-lane`: 저장 줄 정보가 존재하는 문자의 clipping·line-boundary 조사 후보
- `fresh-candidate-lane`: LineSeg가 없거나 placeholder인 문자의 reflow·page-drift 조사 후보

W4 결과에서 둘을 “유효/무효 LineSeg”로 부르지 않는다. 실제 feature validity와 fresh layout 비교는
W5 controlled ladder의 질문으로 넘긴다.

### 3.3 직접 join하지 않을 축

- 기존 POC는 9,948건, W3는 9,909건 성공이므로 두 aggregate의 usage row를 같은 모집단으로 간주하지
  않는다.
- W3 finalizer가 만든 `legacyUsage`와 `decisionUsage`만 같은 9,909건의 호환 projection으로 사용한다.
- usage row의 `documentCount`를 face별로 합하면 같은 문서를 중복 계상할 수 있으므로 문서 영향도로
  사용하지 않는다.
- POC `fonts[].usedDocumentCount`와 jsDelivr 사용 문서 수는 historical 보조 빈도로만 표시하고 risk
  score나 완료 분모에 넣지 않는다.

## 4. 후보 identity와 중복 방지

기본 후보 key는 원문에 실제 지정된 exact `font` 문자열인 **document face**다. W5 exact/missing
oracle의 입력도 이 이름이기 때문이다. format·language·style은 후보를 쪼개지 않고 하위 분포로 보존한다.

동시에 `metricRequestedFace`·`normalizedFace`별 원인 cluster를 만든다. 여러 document face가 같은
requested metric face로 모이더라도 이를 font identity로 합치지 않는다. W1에서 bytes나 oracle로 검증된
relation이 없는 이름은 별도 후보로 유지하고, 같은 원인 cluster라는 진단만 제공한다.

최종 산출물은 다음 두 순위를 모두 제공한다.

- document-face risk rank: W5 조사 대상 선정용
- metric-request cluster rank: 하나의 metric 결손이 여러 이름에 미치는 영향 설명용

## 5. 실측 risk mass 계약

### 5.1 포함·제외

기본 위험 문자에는 `face-miss`, `char-miss`, `heuristic`만 포함한다. `exact-hit`, verified overlay,
identity alias와 metric surrogate는 coverage 성공 계열이므로 기본 risk mass에 섞지 않고 별도 관찰 열로
남긴다. non-applicable·excluded·layout-only·backend 미관찰도 위험 문자로 승격하지 않는다.

### 5.2 같은 행의 교차 노출만 계산

row의 위험 문자 수를 `n`이라 할 때 다음 투명한 계수를 사용한다.

```text
compressionFactor = 1
  + I(ratio < 100)
  + I(ratio <= 90)
  + I(spacing < 0)
  + I(spacing <= -5)

frameFactor = fixedFrameContextProxy ? 2 : 1

rowRiskMass = n * compressionFactor * frameFactor
```

이 식은 face의 전체 miss 양과 별도 marginal 비율을 곱하지 않는다. 실제 같은 row에서 동시에 관찰된
문자에만 가중한다. category별 주관 가중치는 두지 않고 `face-miss`·`char-miss`·`heuristic` 구성 자체를
함께 보고한다.

LineSeg는 어느 lane이 본질적으로 더 위험한지 W4 자료만으로 확정할 수 없으므로 multiplier로 쓰지 않는다.
각 face에 `storedRiskMass`, `freshCandidateRiskMass`, 합계 `baseRiskMass`를 모두 남긴다.

### 5.3 순위와 안정성

기본 정렬은 다음과 같다.

1. `baseRiskMass` 내림차순
2. compressed fixed-context miss 문자 내림차순
3. 전체 miss 문자 내림차순
4. 전체 실제 사용 문자 내림차순
5. UTF-8 document face 이름 오름차순

계수 하나의 우연으로 순위가 굳지 않도록 다음 민감도 표를 함께 계산한다.

- 가중치 없는 miss 문자 순위
- frame factor를 1로 둔 순위
- extreme 압축 추가 가중치를 제거한 순위
- stored/fresh lane 각각의 독립 순위

상위 후보의 순위가 변형마다 크게 바뀌면 단일 정밀 순위를 주장하지 않고 cumulative risk mass 기준의
band로 공표한다. ranker는 band 경계와 변형별 rank 범위를 결과에 남긴다.

## 6. 상승 조건과 W5 실행 준비도

다음 조건은 `baseRiskMass`에 더하지 않고 evidence가 있는 flag로 남긴다.

| flag | 승인할 근거 | 금지할 추정 |
| --- | --- | --- |
| `government-or-legal-core` | 공개 정부·법정 서식, #4739 정부상징 matrix 등 직접 anchor | 이름에 `정부`가 있다는 이유 |
| `exact-source-verified` | font bytes를 열어 name/face index를 확인한 상태 | 파일명·설치 여부만으로 exact 판정 |
| `exact-source-available` | 공식 조달 경로는 있으나 bytes 미검증 | jsDelivr 검색 성공을 metric exact로 승격 |
| `backend-selection-divergence` | W1 ledger 또는 #4739/#4741의 profile별 관찰 | Canvas2D 가능을 CanvasKit SFNT 가능으로 간주 |
| `unknown-relation` | W1의 명시적 unknown | 비슷한 이름으로 successor 추정 |

W5 action queue는 empirical risk band를 먼저 지키고, 같은 band 안에서 verified source·공공 핵심·backend
불일치 증거가 있는 후보를 앞세운다. base rank와 action queue rank, 이동 이유를 모두 표시한다.

### Stage W4-2 — 결정론적 ranker와 local 실행

1. read-only streaming ranker를 구현한다. 110MB JSON을 복제하거나 raw row를 출력하지 않는다.
2. current W3 final aggregate 한 건만 읽어 document-face와 metric-request cluster를 집계한다.
3. counts·category·stored/fresh lane·risk mass를 독립 재대사한다.
4. 입력 row 순서를 바꾼 fixture에서 canonical output hash가 같음을 검증한다.
5. local-only 전체 실행을 두 번 수행해 공개 projection bytes와 hash가 exact인지 확인한다.

**종료 게이트:** 위험 문자 2,061,732자가 후보별·category별·lane별로 손실 없이 대사되고 privacy 오류가
0이어야 한다. 실제 W5 후보 선정은 아직 하지 않는다.

### Stage W4-3 — 증거 상승 조건과 민감도 판정

1. W1 ledger, government matrix, KoPub·정부상징 기록, supply survey를 face 이름으로만 join한다.

3. 기본·무가중·frame-neutral·non-extreme·lane별 순위를 비교해 안정 band를 만든다.
4. base rank와 action queue rank가 다른 모든 후보에 이동 사유를 기계 판독 가능하게 남긴다.

**종료 게이트:** 근거 없는 promotion 0, identity 추정 0, 다른 empirical band를 flag만으로 건너뛴 후보 0.

### Stage W4-4 — 최종 보고와 W5 인계

1. 전체 aggregate와 상위 후보의 miss 양, 압축·fixed-context·LineSeg lane 근거를 보고한다.
2. 단순 선언 빈도·jsDelivr 공급 여부를 보조 열로만 표시한다.
3. 상위 후보마다 W5의 exact 설치, missing, document `substFont`, official successor, 모두 미설치 질문을

4. #4960·#4962 체크 후보와 #4963 입력 후보를 준비하되 GitHub 본문은 별도 승인 전 수정하지 않는다.

## 9. 보호 불변식과 중단 조건

W4는 원인 계보 보고서의 FI-01~FI-14를 모두 유지하며 특히 다음을 hard gate로 둔다.

- FI-03: layout metric과 paint face 차이를 자동 결함으로 보지 않는다.
- FI-04·FI-05: identity, successor, surrogate, substitute와 heuristic을 섞지 않는다.
- FI-06: Canvas2D·Local Font Access·CanvasKit capability를 분리한다.
- FI-09·FI-12: version이 아니라 LineSeg 상태를 탐지하고 stored/fresh lane을 분리한다.
- FI-10: private corpus 식별 자료를 게시하지 않는다.
- FI-13: 웹 공급 가능성과 metric compatibility를 분리한다.
- FI-14: 평균 장평 단문이 아니라 실제 압축·고정 문맥 교차 노출을 사용한다.

다음 상황에서는 해당 stage를 중단하고 계획을 다시 승인받는다.

- W3 final aggregate에 계약에 없는 category·dimension이 나타남
- 위험 문자나 lane 합이 원본 count와 대사되지 않음
- fixed-frame geometry 또는 LineSeg validity를 새 10k pass 없이 확정해야만 완료할 수 있음
- public promotion evidence가 face identity를 추정해야만 연결됨
- ranking 구현이 제품 renderer, metric DB, fallback, font asset을 변경해야 함
- 공개 projection에서 path·문서 identity·raw character가 검출됨

## 11. 계획 self-review

- **중복 계측 방지**: W3 final aggregate의 동일 행 교차축으로 답할 수 있으므로 새 10k pass를 금지했다.
- **모집단 정직성**: POC 9,948건과 W3 9,909건을 직접 join하지 않는다.
- **고정 frame 정직성**: historical context mask를 geometry로 과장하지 않고 proxy로 이름 붙였다.
- **LineSeg 정직성**: boolean 존재 상태를 validity로 승격하지 않고 stored/fresh-candidate lane으로 나눴다.
- **점수 설명성**: marginal 비율을 곱하지 않고 같은 usage row의 실제 교차 노출만 가중한다.
- **정책 분리**: 실측 위험과 정부 중요도·source 준비도·backend 불일치를 별도 층으로 유지한다.
- **identity 보호**: requested metric cluster를 font identity 병합으로 사용하지 않는다.
- **privacy**: corpus 식별자와 local font 경로를 tracked 산출물에서 금지한다.
- **제품 0-delta**: W4는 read-only 분석이며 metric·fallback·paint·font asset을 변경하지 않는다.
- **승인 분리**: 계약, ranker 실행, evidence promotion, 최종 W5 인계를 독립 승인 게이트로 둔다.
