## 2. 문제 정의

`samples/hwp3-sample16-hwp5.hwp` (HWP3 → HWP5 변환본) 의 페이지 분할이 한컴 viewer 와 다름:

| 구분 | 한컴 | rhwp |
|------|------|------|
| Page 1 (cover) | "세계 3대..." 표지 | 동일 |
| Page 2 (목차) | 동일 | 동일 |
| **Page 3 (사업개요)** | Section 1 (Ⅰ. 사업개요) 만 | **Section 1 + Section 2 시작 까지** packed |
| **Page 4** | "(2) 주전산센터 서버통합..." 시작 | (rhwp 에서는 다른 위치) |

**rhwp 가 한컴 보다 paragraph 누적이 compact** — section 2 시작이 page 1 에 들어감.

## 3. 진단 결과

### 3-1. HWP5 binary 명시적 page break 정보 부재
- `paragraph.raw_break_type=0x00` (no 쪽나누기 flag)
- `ParaShape.page_break_before=false` (attr1 bit 19 미설정)

### 3-2. 한컴 layout 자체 알고리즘
한컴 viewer 가 paragraph 누적 + page-fill heuristic 으로 자동 page break. rhwp 도 같은 방식이지만, paragraph 간격 누적이 한컴 보다 작아 더 많은 content 가 page 에 fit.

## 4. 수행 계획 (5 stage)

### Stage 1 — 정밀 진단
- HWP5 변환본 vs 한컴 viewer 의 paragraph 간격 정확 측정
- rhwp 의 layout 누적 공식 vs 한컴 추정 공식 비교
- 어느 paragraph type / 어느 영역에서 간격 격차 발생하는지 식별
- 격차의 양 (px) 정확 측정

### Stage 2 — Fix 후보 평가
- 후보 A: ParaShape 누적 spacing 추가 buffer (변환본 specific)
- 후보 B: page-fill heuristic 정밀화 (paragraph 간 minimum gap 강제)
- 후보 C: Empty paragraph 자동 page break 감지 (pi=87 같은 빈 paragraph 후 section 시작 시)
- 후보 D: ParaShape spacing /4 보정 추가 정밀화 (HwpUnitChar 가설 확장)

### Stage 3 — Fix 적용
- 선정 후보 구현
- 단위 검증: sample16-hwp5 page 3-4 한컴 정합

### Stage 4 — 회귀 검증
- `cargo test --release --lib` 전체
- `cargo clippy --release -- -D warnings`
- SVG sweep (sample16 + 일반 HWP5 + 시험지 + HWPX 변환본)
- WASM 빌드 검증

### Stage 5 — 작업지시자 시각 판정 + 최종 보고서
- rhwp-studio 시각 판정
- 한컴 정합 확인
- 최종 보고서
