## 1. 이번 절편의 결정과 목표

#4967은 여러 font face를 한 PR에서 일괄 수정하는 구현 이슈가 아니라 face별 교정을 통제하는 tracker다.
이번 절편은 첫 process canary인 rank 8 `KoPubWorld바탕체 Light`가 실제 제품 교정 자식 이슈의 진입 조건을
충족하는지 판정한다.

핵심 질문은 다음과 같다.

> 현재 rhwp의 정확히 어느 decision plane이 `KoPubWorld바탕체 Light` 사용 문서의 조판을 잘못 결정하며,
> exact metric 교정이 실제 사용자 문서의 첫 줄 경계 divergence를 개선하면서 비대상 cohort와 backend를
> 그대로 유지하는가?

이번 절편의 산출은 다음 둘 중 하나다.

1. **qualified**: 공개·비공개 증거 경계를 지킨 correction hypothesis와 정확히 한 decision plane을 고정하고,
   별도 product-correction 자식 이슈 초안을 준비한다.
2. **no-change / blocked**: 실제 오류, portable 목표 또는 재배포·backend 조건을 증명하지 못한 이유를 기록하고
   제품 규칙을 바꾸지 않는다.

qualification 통과 자체는 registry change set 작성, 제품 source 수정, 원격 자식 이슈 등록을 승인하지 않는다.

## 3. 현행 제품 상태와 작업 가설

v2 registry에서 `KoPubWorld바탕체 Light`가 소유한 active rule은 다음 `supply` 두 개뿐이다.

| projection | 현행 동작 |
| --- | --- |
| `canvas2d-webfont` | jsDelivr WOFF2 exact family 공급 |
| `canvaskit-sfnt` | online OTF exact source plan, offline unavailable |

`rust-layout-name`, `rust-layout-metric`, `canvas2d-paint`에는 이 face의 규칙이 없다. source에서도
`KoPubWorld바탕체 Light`는 기존 KoPub 전용 폭 표의 이름 탐지와 metric DB 모두에 걸리지 않아
`heuristicFullwidth`, `heuristicHalfwidth`, `heuristicNarrow`로 측정된다. 기존 generator로 임시 생성한
rank 8 fixture를 기존 local release binary로 조회한 1,024자도 metric entry 0, `matchKind=none`이었다.
이 trace는 current HEAD build의 정식 증적이 아니므로 Stage W8-Q1에서 다시 고정한다.

작업 가설은 다음과 같다.

```text
correctionHypothesis:
  exact webfont를 paint에 공급하면서 Rust layout은 heuristic advance를 쓰므로
  장평·자간과 fixed frame에서 layout/paint 누적 advance가 벌어진다.

provisional targetDecisionPlane:
  layout-metric
```

다음 사실이 확인되기 전에는 이 가설을 제품 결정으로 승격하지 않는다.

- exact TTF와 현행 Canvas2D WOFF2·CanvasKit OTF의 glyph/advance identity 또는 허용 가능한 차이
- 실제 6문서 cohort에서 heuristic → exact metric이 만드는 최초 줄 경계·overflow 변화
- stored LineSeg가 유효한 문단과 fresh 재조판이 필요한 문단의 기능 탐지 결과
- portable default에서 font bytes를 내장하지 않고도 exact-derived metric을 사용할 근거
- offline paint가 exact font를 조달하지 못할 때 layout exact metric을 유지해도 되는지에 대한 명시적 정책

5. trace 상한으로 일부 문자가 잘리면 fixture를 숨겨 줄이는 대신 bounded page/paragraph query 또는 테스트

**종료 게이트**: 공개 fixture bytes·semantic hash, 전건 current trace와 actual geometry 기준선이 고정된다.

### Stage W8-Q3 — 실사용 6문서 bounded qualification

1. local-only 6문서에 current와 candidate metric을 read-only 비교한다. 새 corpus 전수 pass는 하지 않는다.
2. document별 최초 divergence를 paragraph/run의 비식별 좌표와 원인만 기록한다.
3. actual table/header/body geometry, 장평·자간, stored LineSeg validity와 overflow/line boundary를 판정한다.
4. exact metric으로 개선되는 문서, 변화 없는 문서, 악화되는 문서를 분리한다.
5. 문서 identity를 제거한 aggregate만 tracked evidence로 투영한다.

**종료 게이트**: 최소 한 실제 문서의 설명 가능한 개선과 모든 비대상 문서의 비악화가 있거나,
그렇지 않으면 제품 변경 없이 종료한다.

**실행 결과 (2026-08-25)**: Q0의 6문서만 읽어 source usage 43,432자와 실제 페이지 render observation
44,117자를 별도 회계로 유지했다. exact metric 적용 가능 43,735자, cmap miss 보존 213자, 특수 advance

있었던 문서는 개선 3·악화 1이었으며, 표 셀 한 줄에서 target 9자의 합계가 +144 HWPUNIT 넓어져 1.92px

W8-Q4에 진입하지 않는다. 재개하려면 같은 snapshot에서 TextLine frame·context와 stored-row admission을 함께
내는 읽기 전용 query 계약을 별도 계획·승인으로 마련한 뒤 동일 6문서만 다시 비교해야 한다.

### Stage W8-Q3R — same-snapshot evidence query 보강과 제한 재판정

Q3의 차단 원인은 metric 후보가 아니라 서로 다른 tree build를 소비한 독립 query의 run set 불일치다. 따라서
Q3R은 제품 font 정책을 바꾸지 않고 다음 읽기 전용 증거 계약만 보강한다.

1. 기존 Font Decision Trace 계산을 이미 만들어진 `PageRenderTree`를 받는 내부 경로로 분리한다. 기존 공개
   API의 출력·상한·해시는 바꾸지 않는다.
2. 새 결합 query는 쪽당 `build_page_tree`를 정확히 한 번 호출하고, 그 snapshot에서 trace record와
   `TextLine` bbox/context 및 동일 순회의 run index 대응표를 함께 낸다.
3. stored-row 상태는 원본 `LineSeg` 존재만으로 추정하지 않는다. 동일 snapshot에서 확인한 source paragraph,
   actual frame과 현행 cache-key 술어를 사용해 `admitted`·`rejected`·`unmodelled`·`notApplicable`을 구분한다.
   외부 wrap geometry나 source mapping을 온전히 재구성할 수 없으면 fail-closed `unmodelled`이다.
4. 문서를 바꾸는 command, metric DB·registry·fallback·paint·supply 및 pagination 결과에는 손대지 않는다.
   query는 `maxCharacters <= 4096` 상한과 page 범위를 그대로 강제한다.
5. 공개 합성 fixture로 단일 tree build, trace 기존 출력 불변, line↔run 전건 join, cache disposition의
   admitted/rejected/unmodelled 경계를 검증한다. 새 integration 원본은 `tests/cases/`에만 두고 generated
   suite·manifest는 제출하지 않는다.
6. 구현 검증 뒤 Q0의 동일 6문서만 다시 읽어 4,397자 미조인을 해소하고 table-cell +1.92px 사례를
   actual disposition과 함께 재판정한다. 10k 전수·Hyper-V는 실행하지 않는다.

**종료 게이트**: snapshot build count가 쪽당 1이고 trace↔line↔run join 누락이 0이며, 모든 target line에
cache disposition 또는 명시적 `unmodelled` 사유가 있다. 이 게이트를 통과해도 Q4 진입은 재판정 결과 승인
뒤에만 가능하다.

**실행 결과 (2026-08-25)**: 공개 fixture에서 쪽당 tree build 1, 기존 trace 불변, line/run join 누락 0과
`admitted`·`rejected`·`unmodelled` 경계를 검증했다. 같은 6문서의 44,117자를 재판정해 이전 미조인 4,397자를
0으로 만들었다. cache disposition은 admitted 15,788자, rejected 10,187자, unmodelled 18,142자였다.
metric-capacity 회귀 5줄 가운데 4줄은 admitted, 1줄은 rejected였고 표 셀 +1.92px 신규 overflow도 admitted로
확인됐다. 따라서 미해석 문자를 더 풀지 않아도 일괄 exact metric 후보는 `no-change`이며 Q4에 진입하지 않는다.

### Stage W8-Q4 — backend·portable 정책과 FI-01~FI-14 판정

1. native, WASM layout parity를 확인한다.
2. Canvas2D WOFF2, CanvasKit online OTF, CanvasKit offline unavailable을 서로 다른 capability로 판정한다.
3. stored-valid, stored-invalid/obsolete, fresh-candidate를 버전이 아닌 feature detection으로 나눈다.
4. FI-01~FI-14를 전항 표로 판정하고 특히 다음 불변식을 hard gate로 둔다.
   - layout metric과 paint identity를 자동으로 합치지 않는다.
   - identity, document substitution, successor, surrogate와 missing-font를 섞지 않는다.
   - web supply 가능성과 metric compatibility를 분리한다.
   - private corpus와 font bytes를 공개하지 않는다.
   - 실제 압축·fixed geometry를 평균 폭이나 page count 하나로 대체하지 않는다.
5. portable default, installed exact-font opt-in과 offline no-supply의 예상 결과를 문장으로 고정한다.

**종료 게이트**: backend별 적용·비대상·미지원 이유와 portable policy가 모순 없이 설명된다.

### Stage W8-Q5 — qualification 판정과 후속 이슈 제안

1. `qualified`, `no-change`, `blocked` 중 하나를 최종 판정한다.
2. qualified일 때만 correction hypothesis, exact one decision plane, affected cohort, registry operation 후보,
   acceptance matrix를 포함한 product-correction 자식 이슈 초안을 작성한다.
3. 실제 자식 이슈 등록은 메인테이너의 별도 승인을 받는다.
4. #4967 tracker는 rank 1·7 및 evidence-reopen lane이 남으므로 rank 8 판정만으로 close하지 않는다.

**종료 게이트**: qualification 보고서 승인. 제품 구현·registry change set은 후속 이슈의 새 계획과 승인 뒤 시작한다.

## 6. 재계측·재실행 정책

다음 조건이 아니면 10k 또는 Hyper-V를 다시 실행하지 않는다.

- 동결 W3/W4/W5 입력 hash가 불일치한다.
- exact font bytes 또는 대상 supply bytes가 기존 source identity와 다르다.
- 기존 W5 profile이 필요한 문자·advance·state를 포함하지 않아 correction hypothesis를 판정할 수 없다.
- comparator canonicalization 결함으로 기존 projection을 신뢰할 수 없다는 재현 증거가 생긴다.

이 경우에도 전체 재실행부터 하지 않고 해당 6문서 또는 필요한 physical state 하나만 제한 재실행하며,
사유와 비용을 먼저 보고해 계획 변경 승인을 받는다.

## 7. 보호 불변식

- W4 ranking과 W5 Oracle profile을 다시 쓰거나 현재 환경 결과와 혼합하지 않는다.
- exact font가 없을 때 한컴의 `HCRBatang-Bold` 선택을 rhwp의 portable identity로 오인하지 않는다.
- document `substFont=KoPubWorld돋움체 Light`를 실제 사용된 fallback으로 승격하지 않는다.
- stored LineSeg 존재를 validity로 부르지 않고 문단별 기능 탐지 결과를 남긴다.
- current v2 registry, schema 1.0, metric DB와 generated source는 qualification 동안 0-delta다.
- private 10k source, 문서명·경로·본문·식별 hash와 local font bytes는 commit·PR·log에 넣지 않는다.
- 출력 파일을 저장할 때 host absolute path를 public JSON에 복사하지 않는다.
- rank 8 결과를 같은 KoPub family의 rank 7이나 다른 weight에 추정 적용하지 않는다.

## 8. 중단 조건

- W4/W5/W7.5 parent hash 또는 의미가 현재 정본과 충돌한다.
- exact TTF와 현재 공급 OTF/WOFF2의 metric identity를 설명할 수 없다.
- source provenance·license·redistribution 경계가 불명확하다.
- page count만 같고 glyph position·line boundary가 발산한다.
- 실제 6문서에서 개선 없이 회귀만 생기거나, 개선을 stored LineSeg 강제 신뢰로만 만들 수 있다.
- 두 decision plane을 함께 바꿔야만 가설이 성립한다.
- private 문서 identity를 공개해야만 acceptance를 설명할 수 있다.

중단 시 제품 변경 없이 원인과 재개 조건을 보고하고 다음 계획 승인을 기다린다.
