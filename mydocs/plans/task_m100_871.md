# Task #871 수행 계획서

## 1. 이슈 요약

**Issue #871**: rhwp-studio에서 외부 앱 클립보드 값이 내부 클립보드에 가려져 붙여넣기되지 않음

**이슈 링크**: https://github.com/edwardkim/rhwp/issues/871

**브랜치**: `local/task871`

## 2. 현상

macOS rhwp-studio web에서 rhwp-studio 내부 복사/붙여넣기는 동작하지만, 다른 프로그램에서 새로 복사한 값이 rhwp-studio 붙여넣기에 반영되지 않는다.

재현 흐름:

1. rhwp-studio에서 텍스트 A를 복사한다.
2. 다른 macOS 앱에서 텍스트 B를 복사한다.
3. rhwp-studio 편집 영역에서 Cmd+V를 누른다.
4. 기대: B가 붙여넣기된다.
5. 실제: 이전 rhwp-studio 내부 클립보드 값 A가 붙여넣기된다.

## 3. 현재 코드 분석

### 핵심 원인 후보

`rhwp-studio/src/engine/input-handler-keyboard.ts`의 `onPaste()`가 외부 클립보드 데이터보다 내부 WASM 클립보드를 먼저 사용한다.

현재 흐름:

1. `onPaste(e)` 진입 후 `e.preventDefault()`
2. `this.wasm.hasInternalClipboard()` 검사
3. 내부 클립보드가 있으면 `pasteControl` 또는 `pasteInternal` 실행 후 `return`
4. 외부 클립보드의 이미지, `text/html`, `text/plain` 처리는 그 이후에만 도달

따라서 rhwp-studio 내부 복사 후 내부 클립보드가 남아 있으면, 시스템 클립보드가 외부 앱에서 갱신되어도 rhwp-studio는 그 사실을 구분하지 못한다.

### 관련 파일

| 파일 | 역할 | 분석 포인트 |
|------|------|-------------|
| `rhwp-studio/src/engine/input-handler-keyboard.ts` | copy/cut/paste 이벤트 처리 | `onPaste()`의 내부 클립보드 우선순위 |
| `rhwp-studio/src/core/wasm-bridge.ts` | WASM 클립보드 API 래퍼 | `hasInternalClipboard`, `pasteInternal`, `pasteHtml` 노출 |
| `src/wasm_api.rs` | 내부 클립보드 네이티브 구현 | `clearClipboard` 바인딩 존재 |
| `rhwp-studio/src/command/commands/edit.ts` | 편집 메뉴/도구 상자 명령 | `document.execCommand('paste')` 의존 |
| `rhwp-studio/e2e/copy-paste.test.mjs` | 기존 복사/붙여넣기 회귀 테스트 | 내부 복사 후 내부 붙여넣기만 검증 |

## 4. 수정 방향

### 원칙

- rhwp-studio 내부 복사 직후 내부 붙여넣기는 서식 보존 경로를 유지한다.
- 외부 앱에서 시스템 클립보드가 갱신된 경우에는 외부 값을 우선한다.
- 외부 `text/html`, 이미지, plain text 붙여넣기 경로를 퇴화시키지 않는다.
- 브라우저 보안 정책상 임의 `navigator.clipboard.read()` 의존을 최소화하고, paste 이벤트의 `e.clipboardData`를 우선 활용한다.

### 후보 설계

1. 내부 복사 시 시스템 클립보드에 rhwp 전용 식별자를 함께 기록한다.
   - 예: `text/html`에 `data-rhwp-clipboard-id` 또는 HTML comment marker 삽입
   - plain text만 가능한 fallback에서도 내부 클립보드 오판 가능성을 낮출 보조 상태 검토
2. 붙여넣기 시 `e.clipboardData`를 먼저 읽어 현재 시스템 클립보드가 rhwp 내부 복사 결과인지 판별한다.
3. rhwp marker가 현재 내부 클립보드와 일치하면 `pasteInternal`을 사용한다.
4. marker가 없거나 외부 데이터로 판단되면 이미지, HTML, plain text 순서로 외부 붙여넣기를 수행한다.
5. 필요 시 `WasmBridge`에 `clearClipboard()`를 노출하여 외부 붙여넣기 후 stale 내부 클립보드 영향을 제거한다.
6. 메뉴/도구 상자 붙이기 경로의 `document.execCommand('paste')` 동작 한계를 확인하고, 가능한 범위에서 키보드 paste 경로와 일관되게 정리한다.

## 5. 검증 기준

### 필수 시나리오

1. rhwp-studio 내부 텍스트 복사 후 바로 붙여넣기
   - 기대: 내부 클립보드 경로 사용, 서식 보존
2. rhwp-studio 내부 텍스트 복사 후 외부 앱 텍스트 복사 후 붙여넣기
   - 기대: 외부 앱 텍스트가 붙여넣기됨
3. 외부 HTML/표 복사 후 붙여넣기
   - 기대: 기존 `pasteHtml` 경로 유지
4. 외부 plain text 복사 후 붙여넣기
   - 기대: 줄바꿈 포함 텍스트 삽입 유지
5. 이미지 클립보드 붙여넣기
   - 기대: 기존 이미지 삽입 경로 유지

### 자동 검증 후보

- `rhwp-studio/e2e/copy-paste.test.mjs` 확장 또는 신규 e2e 추가
- 내부 복사 후 Playwright clipboard에 외부 텍스트를 주입하고 Cmd+V 결과 확인
- `npm run build` 또는 `npx tsc --noEmit`로 TypeScript 검증
