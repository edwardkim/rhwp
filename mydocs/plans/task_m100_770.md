## 1. 문제 정의

### 증상

`samples/basic/shortcut.hwp` 페이지 2~7 의 헤더 zone (1x1 TAC 표 + 후속 PartialParagraph) 이 PDF 권위(한글 2022) 대비 **40 px 압축**. 본문이 위쪽으로 끌어올려져 PDF 정합 미달.

### 베이스라인 측정

`dump-pages` 단 0 (헤더 zone) used vs hwp_used diff:

| 페이지 | items | rhwp used | hwp_used | diff |
|--------|-------|----------|---------|------|
| 1 | 1 (FullParagraph pi=0) | 69.1 | 53.1 | +16.0 (헤더 paragraph 자체) |
| **2** | 2 (Table + PartialParagraph) | **27.3** | **47.1** | **-19.8** |
| **3** | 2 | **30.5** | **53.5** | **-23.0** |
| **4** | 1 | **20.0** | **53.3** | **-33.3** |
| **5** | 3 | **40.0** | **53.3** | **-13.3** |
| **7** | 1 | **20.0** | **53.3** | **-33.3** |

PDF 페이지 2: 헤더 ('파일') ~ 본문 ('새 문서') 거리 ≈ **60 px**
rhwp 페이지 2: 동일 거리 ≈ **21 px**
→ rhwp **40 px 압축**

## 2. IR 분석

### pi=36 (페이지 2 "파일" 헤더)

```
[PS] ps_id=2 line=100/Percent
ls[0]: vpos=0,    lh=1200, ls=0      (16.0 px, 표 line 0)
ls[1]: vpos=1200, lh=2332, ls=0      (31.1 px, 표 본체 + 후속)
[0] 단정의: 1단
[1] 표: 1x1, RowBreak, treat_as_char=true, wrap=TopAndBottom
```

vpos_end = 1200 + 2332 + 0 = 3532 HU = **47.1 px** ✓ (hwp_used 47.1 일치)

### pi=81 (페이지 3 "보기" 헤더)

```
[PS] ps_id=10 line=140/Percent
ls[0]: vpos=0,    lh=1200, ls=480    (16.0 px + 6.4 px ls)
ls[1]: vpos=1680, lh=2332, ls=480    (31.1 px + 6.4 px ls)
```

vpos_end = 1680 + 2332 + 480 = 4012 HU = **53.5 px** ✓ (hwp_used 53.5 일치)

### dump-pages 분리

```
단 0 (items=2):
  Table pi=36 ci=1 1x1 926.0x23.5px wrap=TopAndBottom tac=true vpos=0..1200
  PartialParagraph pi=36 lines=1..2 vpos=1200
```

paragraph pi=36 이 두 PageItem 으로 분리:
- Table PageItem: 표 자체 (vpos 0..1200 = line 0)
- PartialParagraph PageItem: line 1..2 (vpos=1200 부터)

## 3. Root cause 가설 (정적 분석)

### 가설 H1 — PartialParagraph y advance 누락

`PartialParagraph (line 1..2)` 의 layout 시 line 1 의 `lh + ls` 가산이 누락 또는 부족.
- 정상: y += 31.1 px (lh[1]=2332 HU)
- 결함: y += 4 px (또는 누락)

### 가설 H2 — Table PageItem 이 paragraph height 전체 점유

Table PageItem 처리 시 paragraph 의 모든 line 높이를 표 자체 height (23.5 px) 로 대체하여 후속 spacing 사라짐.

### 가설 H3 — TAC 표 + ColumnDef 동반 paragraph 의 특수 처리

pi=36 의 controls 에 ColumnDef + Table 동시 존재. layout.rs 의 ColumnDef 처리에서 paragraph height 산출이 변경되어 line 1 의 lh 가 적용되지 않을 가능성.

### 우선 검증

H1/H2/H3 중 어느 영역인지 instrument 로 확인 (Stage 2). 가설별 정정 위치:
- H1: `paragraph_layout.rs::layout_partial_paragraph`
- H2: `layout.rs::layout_column_item PageItem::Table`
- H3: `layout.rs` ColumnDef 처리 분기
