# #8153: 저장 높이가 없는 셀의 글줄과 안 여백

## 원본·독립 출력과 위반한 규칙

편람 두 형식 117쪽의 `관인인쇄용지 관리대장`은 5행 표다. 세 번째 행은
문자가 없는 저장 문단이며 셀 높이는 0HU, 저장 글줄 높이는 100HU,
위·아래 실효 안 여백은 각각 141HU다. 글자가 없어도 유효한 줄 상자와
382HU의 최소 점유를 갖는다. 독립 한컴 Print의 해당 띠는 약 5.12 CSS px다.

현재 계산은 100HU = 약 1.333px의 줄만 예약한다. 뒤 행의 가로선은 독립 Print보다
약 3.7px 위에 있다. 선 굵기 보정으로 이 선이 선명해지면서 미대응이 1,780→2,150픽셀로
늘었지만, 두 출력의 조판 트리는 동일하다. 선을 다시 흐리게 해 차이를 숨기지 않는다.

## 기존 해결과 원인 계층

원 커밋 `429dee416e64`의 공통 `stored_text_cell_required_height`는 통합 PR #7877에서
도입됐다. 원 PR #7704 자체는 반복 순회 성능 개선이며 셀 여백의 독립 근거가 아니다.
실제 통합 PR의 저장 줄·물리 프레임 소유 계약과 #2211 계보의 패딩 이중 계상 방지를
함께 확인했다. 유효한 양수 셀 프레임이 이미 여백을 소유하는 계약은 유지한다.

높이 0인 선언에는 실제 글줄과 여백을 담은 물리 프레임이 없다. 종전 1.5px 허용치로
이를 양수 프레임과 같은 상태로 분류한 것이 잘못이다. 여백을 결정하려고 문서·쪽 번호나
작은 글꼴 크기를 판정하지 않으며, 허용치의 숫자를 조정하지 않는다.

## 공통 생산·소비

`저장 글줄과 실효 안 여백 → 공통 셀 요구 높이 → HeightMeasurer의 행 하한 →
분할 예산과 행 높이 → LayoutEngine fallback의 동일 요구 높이 → 실제 괘선·글자 배치`다.
공통 helper가 높이 없는 선언에서 내용과 여백을 함께 반환하게 한다.
측정과 배치에 별도 보정을 추가하거나 뒤 행 좌표를 이동시키지 않는다.

## 실제 검증 계획

- 원본의 높이 0 빈 행이 저장 글줄·실효 여백을 포함하는지 수정 전 실패/수정 후 통과를 확인한다.
- 117쪽 및 도형 획 보정 253쪽을 같은 Native/fresh WASM producer로 독립 Print와 대조한다.
- 선언 프레임이 있는 빈 셀·내용 셀, 패딩 없는 셀과 기존 마지막 행 흡수 계약을 정상 대조한다.
- PR #7877의 원 해결 문서와 #8148 검증 입력, 편람 전쪽에서 새 영향과 하락을 확인한다.
- 관련 시각 선행 조건과 직접 판독 후 정식 관계형 검사를 등록한다. 잘못된 기존 기대값을
  복사하거나 일반 회귀의 허용치를 넓히지 않는다.
