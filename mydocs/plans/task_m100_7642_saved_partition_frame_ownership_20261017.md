# #7642 저장 문자 분할과 실제 프레임 소유

Issue: #7642.

## 독립 근거와 현재 관측

원본 `samples/exam_kor.hwp`와 대응 한컴 Print PDF의 14쪽은 같은 대화문을
같은 네 줄로 나눈다. a80c33624a의 Native 출력도 33문단을 36/31/29/6자로
나누며, 원본의 control 포함 textStart 0/44/75/104와 일치한다. 그런데
저장 구간과 들여쓰기를 적용한 새 구간의 가로 좌표 표현을 직접 비교해
재구성을 선택하고, 다단의 누적 커서를 새 절대 원점으로 고정했다.
실제 첫 줄은 407.7px, 저장 줄에 따른 정상 원점은 약 450.6px다.
이는 독립 PDF에 없는 겹침이며 raw 73.30267%로 남았다.

원본 온새미로 HWP/HWPX의 한컴 2024 Print는 46쪽이다. a80의 41쪽은
115문단 전체를 수용하지만, 다음 실제 페이지는 저장 페이지의 두 번째 줄인
116문단부터 시작한다. 저장 첫 줄인 115문단 끝줄(vpos=0)은 이전 실제
페이지가 이미 소비했다. 138문단의 옛 자동 reset을 그대로 적용하면 Print가
42쪽 끝에 둔 첫 줄을 43쪽으로 넘기고, 168번 빈 문단만 든 추가 쪽이 생긴다.
원본과 PDF를 고치거나 빈 줄을 숨기지 않는다.

## 규칙과 소비 경로

- 저장 LineSeg와 새 프레임이 같은 문자 분할을 확정하면 기존 줄 소유를 유지한다.
  hanging indent 적용 전후의 구간 좌표를 같은 의미의 캐시 key로 취급하지 않는다.
  실제 문자 분할이 다른 경우에는 기존 공통 plan의 fit·paint 공유를 유지한다.
- 자동 저장 경계를 수용하기 전에 이전 실제 페이지의 끝 항목과 현재 페이지의
  첫 항목을 대조한다. 같은 저장 프레임의 prefix를 이전 실제 페이지가 이미
  소비했다면 그 저장 경계는 현재 페이지 배분의 독립 증거가 아니다.
  일반 줄 예산이 수용·분할을 결정한다. 추정한 숫자 공차나 문서 ID로 판정하지 않는다.
- 명시적인 쪽·단 나누기와 first-line-of-page 비트, 서로 다른 구역,
  표·도형 소유, 편집·합성 줄 및 정상 저장 페이지 시작은 기존 경로에 남긴다.

## 검증

원본 두 형식과 NO_LS 진단을 구분해 쪽 소속·첫 줄·끝 줄을 확인한다.
국어 3개 입력, 현재 전체 102문서 1,704쪽, #7969와 #7970의 기능 보존 검증은
유지한다. 새 Native/fresh WASM 전쪽 TSV와 같은 영역의 review·overlay를 확인한다.
전체 관련 페이지 90% 이상과 확대 판독 전에는 새 실물 회귀를 추가하지 않는다.
