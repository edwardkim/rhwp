# #8860 Studio 문단 길이 변환과 원래 서식 보존 계획

Issue: #8860

1. Studio가 pt·px를 문서에 쓸 때 가장 가까운 정수 HWPUNIT으로 먼저 반올림하고 최하위 비트를 0으로 기록한다. 1pt는 100 HWPUNIT, 96dpi의 1px는 75 HWPUNIT이다. 정확히 절반인 소수 입력은 크기가 큰 쪽으로 반올림한다. 예를 들어 1.005pt는 1.01pt로, 17.50px는 1313 HWPUNIT으로 저장한다. 들여쓰기와 내어쓰기는 방향만 반대다. 문단 설정창의 명시적인 편집, 본문의 Shift+Tab과 같은 절대 길이를 쓰는 눈금자 핀에서 이 규칙을 공유하는 안이다. [단위 사양](../tech/한글문서파일형식_5.0_revision1.3.md) · [기존 문단 간격 변환](../../rhwp-studio/src/core/paragraph-spacing.ts)
2. 기존 서식을 유지하거나 복사할 때는 원래 단위를 보존한다. 설정창에서 입력값이나 방향을 바꾸지 않았으면 해당 필드를 쓰지 않는다. 모양 복사에서는 화면용 px에서 단위를 역산하는 경로를 대조하고 기존 API의 문단 원시값을 우선 사용한다. 같은 변환을 쓰는 좌우 문단 여백도 대조한다. 구역의 쪽 여백과 탭 위치에는 별도 저장 규칙이 있다. [문단 설정창](../../rhwp-studio/src/ui/para-shape-dialog.ts) · [모양 복사와 내어쓰기](../../rhwp-studio/src/engine/input-handler.ts)
3. 바탕글 10pt와 20pt에서 같은 절대 입력을 비교하고, 기존 상대 단위는 양수·음수 원본으로 대조한다. 소수 경계 양옆, 0, 기존 정수·0.1pt 입력, 다른 항목만 바꾼 설정창, 모양 복사와 눈금자 드롭의 실제 저장값을 검사한다. 일반 표 셀에서 Shift+Tab은 이전 셀 이동이므로 셀 문단 편집은 실제 문단 설정창을 사용하며 단축키 이동도 검증한다. 기존 독립 대조 입력과 한컴 Print를 재사용한다. [원본](../../samples/issue7816/odd_indent_ladder.hwpx) · [한컴 2020 인쇄본](../../pdf/issue7816/odd_indent_ladder-2020.pdf)
4. 최신 기준과 후보의 Studio에서 실제 입력·둘째 줄 위치·실행 취소·다시 실행을 확인한다. HWP와 HWPX 각각 편집 → 저장 → 재열기 → 재저장 → 재열기 후 원래 단위·문단 내용·다른 속성을 대조한다. TypeScript, Studio 전체 테스트와 빌드, 관련 편집 E2E를 실행한다. 제출 직전 기준 브랜치와 본인 열린 PR을 다시 확인한다. [변경 범위별 검증](../manual/pr_review/local_validation.md#43-변경-범위별-기본-검증)
