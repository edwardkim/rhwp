## 절차 기록과 보정

작업지시자는 대화와 #6041 본문에서 다음 설계를 승인한 뒤 구현 진행을 지시했다.

- 외부 PR #6440을 기반으로 보정하지 않고 #6040 Stage 1 head에서 독립 구현한다.
- 3열 이상 같은 열 수 규칙이 아니라 실제 Canvas surface pixel 예산을 모든 배치에 적용한다.
- raw DPR을 기본값으로 유지하고 예산을 실제로 넘을 때만 안정된 단계로 낮춘다.
- 화면 밖 retained/prefetch, 포커스에서 먼 페이지 순으로 낮추며 편집 페이지와 출력 경로는 보존한다.

다만 이 승인 내용을 저장소 계획 파일로 먼저 외부화하는 절차를 누락해 최초 source commit과 Draft PR
생성 뒤 이 문서를 작성했다. 이 문서는 파일이 구현 전에 존재했다고 소급 주장하지 않는다. 대화·이슈의
사전 승인 범위를 정본 계획 형식으로 옮기고, 이후 발견한 고정 4-layer 과대 추정을 페이지별 실제 plane
구성으로 바로잡은 경위를 함께 기록하는 절차 보정이다.

## 목표

1. 일반 문서는 가능한 최대 화면 해상도(raw DPR)로 렌더한다.
2. retained Canvas surface 총비용이 예산을 넘을 때만 비포커스 페이지를 DPR 2→1.5→1 순으로 조정한다.
3. visible 품질보다 화면 밖 prefetch를 먼저 낮추고, 같은 단계에서는 포커스에서 먼 페이지를 우선한다.
4. 포커스 페이지, `print`, `highQuality`, CanvasKit의 기존 계약을 보존한다.
5. 열 수나 자동 쪽 배치 임계값과 분리해 #6040 토폴로지 동작에 회귀를 만들지 않는다.

## 범위

### 포함

- 전역 visible/retained surface pixel 예산과 hysteresis
- 페이지별 width×height×zoom²×effectiveDpr²×Canvas layer count 비용
- Canvas2D 페이지 plane 구성에 따른 layer count 상한과 문서/revision 수명 캐시
- DPR tier 결정, 포커스 전환 시 즉시 raw 복원, DOM 진단 dataset
- planner 단위 테스트, 실제 Canvas2D/CanvasKit 문서와 4-layer fixture 검증

### 제외

- 자동 열 수·중앙 정렬·줌 좌표: #6040
- 행 가상화, page LRU, eviction, prefetch scheduler: #6042
- 포인터/캐럿 앵커를 새로 정의하는 줌 동작
- print/PDF/SVG/highQuality 출력 해상도 변경
- 외부 PR #6440 코드의 cherry-pick 또는 수정
- 예산 이내 저배율 overview의 화질·절감량 기반 DPR ceiling: #6521에서 실험 후 비채택
