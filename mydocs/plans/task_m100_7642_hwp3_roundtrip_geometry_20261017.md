# #7642 HWP3 왕복 저장의 도형과 자연 페이지 소유 보존

## 독립 근거와 위반된 계약

원본 `samples/hwp3-sample16.hwp`과 한컴 저장본은 전쪽 Native/fresh WASM
90% 이상이다. RHWP HWPX 왕복 저장본을 그대로 한컴2020 Print한 독립 PDF는
64쪽이지만 Native/fresh WASM 8쪽이 미달이다. 원본과 왕복본의 typed IR을
대조했고, bold 불리언은 보존됐다. raw attr 비트 차이를 굵기 소실로 오판하지 않는다.

`src/parser/hwp3/drawing/shape_mapping.rs`는 사각형·글상자와 타원을 default
기하로 만든 뒤 크기·선·채움만 채운다. 기존 layout은 그 크기로 외곽을 표시하지만
`src/serializer/hwpx/shape.rs::write_rect_pts`와
`section.rs`의 ellipse geom_tail은 0 좌표를 그대로 쓴다. 한컴 저장본의 실제
꼭짓점·중심·축과 다르다. HWP3의 암묵 도형 상자를 parser 경계에서 공통 IR 기하로
정규화하고 serializer와 renderer가 같은 기하를 받도록 하는 것이 보정 후보이다.
원래 HWPX에서 명시된 퇴화 도형을 전역 크기 fallback으로 덮어쓰지 않는다.

원본의 자연 페이지 경계62개는 `page_break_synthesized=true`로만 IR에 남고
HWPX 저장에서 사라진다. 경계를 표준 강제 개행으로 모두 방출하면 다른 정상
문서가 빈 페이지를 만들므로 적용하지 않는다. 내용에 종속된 원본 소유 정보의
보존·재사용 조건을 먼저 확인하며 편집 후 낡은 정보는 수용하지 않는다.

## 배치 원인과 검증 순서

1. typed IR과 독립 한컴 저장본의 기하를 대조한다. 크기·변환·회전과 논리 좌표를
   구분하고 실제 원점·paint 소비를 추적한다.
2. 기존 실패 파일을 보존하고 기하만 바꾼 반례를 독립 Print한다. 진단 대조군
   통과를 원래 저장본 통과로 보고하지 않는다.
3. 일반 규칙의 parser/저장 보정을 모아 적용한 뒤 한 번의 Native/fresh WASM
   빌드로 검증한다. 원본·왕복 저장본과 HWP3 정상 대조군의 전체 쪽수·내용 순서·
   소유 및 전쪽 TSV를 대조한다. 전체 페이지 양쪽90%·확대 판독 전에는 정식
   렌더링 회귀를 추가하거나 기존 실패 기대값을 바꾸지 않는다.
4. 사용자 지시대로 새 이름의 정식 회귀를 만든다. 도형 외곽·텍스트 포함과
   자연 경계의 문단/표 앞뒤 순서·보존을 보호한다. 페이지별 양쪽98% 이상과
   직접 판독을 충족하는 핵심 쪽에만 독립 ±2px 좌표를 병행한다.

증거는 기존 stage2331~2349와 이어 기록한다. 원본·실패 입력·기준 PDF는
바꾸지 않고, TSV/로그/중간 JSON은 ignored output에 둔다.

## 진단 결과와 보정 후보의 소비 경로

기하만 복원한 `hwp3-sample16-geometry-counter.hwpx`의 원본 SHA-256은
`b584d034d48519d43e1bfdea24681da6744cb0d0820a8a05f497dec1af3a7ab2`다.
Print job `a4dd11a3-c3e8-42ec-a3c2-bb652aaa1690`는 engine2020 /
한컴11.0.0.9136 / Print0 / `hancom2020_pdf_driver_one_up`로64쪽을 출력했다.
PDF SHA-256은 `a9561557c0644ab9d8b0a1bfdb8c63ff8945a22cddb2c7651d6051c0c98a630f`다.
동일 producer cc4255의 stage2352 Native / stage2353 fresh WASM 전쪽 비교에서
1·3·5·18·19·39쪽의 미달이 해소됐고20·37쪽은 남았다. 전쪽 완료는 아니다.

20쪽은 원본 문단414의 첫 저장 원점1416HU가 원본 layout에는 반영되지만 왕복본
배치에서 사라진다. 원본의 `ColumnBreakType::Page`와
`page_break_synthesized=true`는 표준 강제 Page와 의미가 다르므로, 앞서 명시
pageBreak를 복원한 진단의 결과로 합성 경계 복원의 결과를 추정하지 않는다.

기하 보정은 HWP3 표68의 개체 크기에서 공통 IR의 사각형 꼭짓점·보통 타원
중심/축을 생산한다. renderer의 사각형·타원 paint는 기존 common 크기 경로를
유지하며 serializer가 같은 IR의 비퇴화 기하를 소비한다. HWPX의 명시적0좌표와
변형 타원의 별도 정보를 이 규칙으로 덮어쓰지 않는다.

자연 경계 보정 후보는 기존 HWP3 출처 마커의 버전2 payload에 구역별 자연 경계
문단 소유를 기록한다. header/구역 XML의 SHA-256·문단 수가 일치할 때만 파서가
공통 Page+합성 상태로 복원한다. 표준 XML의 pageBreak는 계속 생략한다.
낡은 header·구역·잘못된 인덱스/순서·명시적 다른 경계·변경 추적의 표시 투영은
복원 대상이 아니다. 옛 b"1" 마커와 HWP5-origin 저장본의 경로는 유지한다.
구역 파서 → 공통 Paragraph 상태 → 기존 pagination의 합성 경계 분기가 실제
소비 경로이며 renderer에 HWP3 전용 새 분기를 추가하지 않는다.

현재 코드는 보정 후보이며 새 producer의 빌드·재수출·독립 Print·전쪽 TSV·확대
판독은 아직 미실행이다. 기존 결과를 새 코드의 완료 증거로 사용하지 않는다.

## 새 Native의 실행 결과와 남은 표 진입 간격

`9654a0f7489cab6043c3cec4d3198cfec315a5ea` Native 빌드는 exit0,
264.963초, source hash 유지 true다. 첫 후보의 sha2 포맷 API 컴파일 오류는
9654a0f748에서 수정했다. 새 저장본 Print job
`0c0af302-f2ce-4071-92a6-c0144d2a546d`는 같은2020/11.0.0.9136/Print0 모드로
64쪽을 출력했다. 자연 경계62개와 header/구역 해시의 일치를 직접 확인했다.
Native 전쪽 결과에서37쪽은99.98906%로 보정됐고20쪽81.81229%는 남았다.

stage2367 실행 추적에서 원본 문단414는 `FullParagraph`, 왕복본은 `Table`로
분기한다. 원본의 제어 자리문자는 왕복 파서에서 제어 슬롯으로 표현되므로 빈
문자열이 된다. 문단 속성의 앞간격2832(half-HU)=1416HU와 저장 원점1416HU,
줄높이2528HU, 후속 원점3944HU는 모두 같다. 원본 경로는0 쪽 원점과52.6px
전진을 보존하지만 표 경로는 앞간격을0으로 취급하고 뒤 높이 상한에서33.7px로
되감는다. 그림과 뒤 본문도 같은18.88px만큼 위로 이동한다.

추가 원인은 HWPX 왕복에서 원본 IR의 제어 자리문자와 문자 축을 잃는 것이다.
같은 저장 줄·문단 간격인데 `text` 표현만 바뀌어 문단 흐름 경로가 바뀐다.
따라서 보정은 원본 제어 자리문자의 character 위치와 UTF-16 offset 축을 기존
출처 마커에 함께 보존하고, hash가 일치하는 같은 저장본을 읽을 때 파서에서
복원하는 것으로 정한다. 별도의 앞간격 paint 규칙을 추가하는 후보는 채택하지
않았다. 원본의 보이는 텍스트 hash·자리문자 수/순서·제어 개수·offset/char_count
정합도 함께 확인한다. 원문 텍스트 전체를 보조 엔트리에 중복 저장하지 않는다.
원본 IR → HWPX 보존 마커/표준 내용 → 검증된 파서 복원 → 기존 문단 흐름이
실제 소비 경로다. 이미 원본에서 직접 확인한 동일 IR의 경로를 유지한다.
정상 대조군을 함께 재검증하며 실패 검사나 baseline은 아직 변경하지 않는다.

## 표지 날짜의 HFT 전진폭 보정

제어 문자 축 보정 소스 9cbe10a8ce의 왕복본·원본·한컴 HWPX/HWP5는 전쪽
Native/fresh WASM 90% 이상이지만, 표지 날짜 폭은 직접 판독에서 미달이다.
날짜의 원본은 한양신명조 HFT, 28pt, 굵게, 장평100%, 자간0이며 독립 Type3의
intrinsic 숫자 폭은500/1000em이다. 같은 한컴의 정상 저장·Print 대조군에서
12/20/28pt 숫자는 정체 약0.50em, 굵게 약0.55em으로 전진한다. HY신명조 TTF
대조군은 같은 굵기 증가가 없다. 음수·양수 자간도 따로 대조했다.

추가로 전체 ASCII95자와 한글 정체·굵게를 정상 저장·Print했다. 두 Type3
프로그램의 intrinsic ASCII 폭은 모두 같고, 한글은1000/1000em이다.
job·PDF 해시·폭 표는 ignored stage2386~2394에 있다. 확인하지 않은 HFT
전체로 전진 보정을 확대하지 않는다.

기존 검증된 HFT 메트릭 표에 한양신명조의 독립 intrinsic 폭을 추가하고,
원본이 HFT로 선언된 슬롯에만 그 표를 선택한다. TTF 선언은 기존 표를 유지한다.
추가 굵기 전진은 glyph 폭 확대와 분리하며, 같은 문자 측정 결과의 장평·자간·
장치 격자 처리를 거쳐 실제 원점으로 전달한다. glyph-fit 경계는 intrinsic 폭을
유지한다. 기존 신명 HFT 두 프로그램도 같은 규칙을 소비하므로 그 독립 Print와
시험지 대조군을 함께 재검증한다. formal 회귀 추가는 새 source의 전쪽 검증과
확대 판독 뒤에 진행한다.

## 법령 표의 명시된 TTF 대체 프로그램

법령 원본의 실제 형식은 확장자와 달리 HWP5다. FACE_NAME 레코드는
한양중고딕 TTF와 대체 HY중고딕 TTF를 함께 저장한다. 독립 Print는 H2gtrM
TrueType을 사용하며 괄호의 실제 전진이 약0.416em이다. 설치된 H2GTRM.TTF도
426/1024em이다. 현재 측정의 한양 HFT 표는 괄호가 약0.29em이어서 표의 첫 셀이
한 줄에 들어가고 실제 두 줄 높이와 뒤 행이 사라진다. 저장 LineSeg는 없는 입력이다.

반례로 대체 프로그램을 명시하지 않은 한양중고딕의 TTF 선언을 정상 저장·Print했다.
선언은 TTF여도 실제 출력은 Type3 HFT였다. 따라서 TTF 플래그나 이름 하나만으로
모든 한양 글꼴을 HY TrueType으로 바꾸지 않는다. 확인된 한양/HY 쌍의 명시된
대체 정보와 실제 출력 프로그램을 근거로 선택하며, HFT·임베드·명시적 환경 선택을
보존한다. 측정과 paint가 같은 대체 글꼴을 소비하는지 확인하고, 원본과 대체 정보가
없는 대조군을 함께 검증한다. 표 행 높이·줄바꿈을 px로 고정하지 않는다.

추가 반례에서 명시적 HY 대체 정보가 있는 TTF 선언도 정상 저장 후 Type3로
Print됐다. 위 메타데이터 두 조건만으로 TTF 프로그램을 선택한 후보는 폐기했다.
후보 diff는 ignored stage2407에 보존했고 실제 소스에서는 되돌렸다. 같은 원본
바이트의 `.hwp` 별칭을 다시 Print하여 기존 PDF와 실제 프로그램 선택의 차이를
확인한다. 기존 PDF나 정상 기대값은 이 진단으로 교체하지 않는다.

## 부분 HFT 표의 미수집 문자 보존

8aaa2ee705의 같은 원본·독립 Print PDF·새 공통 PDF 정책에서 왕복본41쪽은
수정 전97.31251%에서82.81763%로 하락했다. 표지 날짜는99.12446%에서
99.87011%로 개선됐지만 미달 쪽을 상쇄하지 않는다. 원본 Type3의 `【` 다음
한글 원점은14.04pt 글자 크기에13.92pt 전진이며 전각이다. 새 ASCII 전용
HFT 표는 이 문자를 수집하지 않았는데, 미수집을 일반 반각 휴리스틱으로
보내18.7px 대신9.3px만 전진했다. 본문이 괄호와 겹치고 뒤 내용도 이동한다.

미수집은 글리프 부재와 다르다. 등록된 부분 HFT 표에서 폭을 확인하지 못한
문자는 새 표 적용 전의 표시 face 메트릭으로 보충한다. 확인된 ASCII 고유
폭은 그대로 우선하며, HFT 굵기 전진은 대체 표의 이름이 아니라 원본 측정
프로그램의 선택으로 판단한다. 일반 TTF의 결측 글리프 선택과 구별한다.
공통 문자 측정 결과를 줄 폭·배치·glyph-fit이 함께 소비하도록 보정한다.

같은 원본과 대조군 전체 Native/fresh WASM 검증·확대 판독은 다시 수행한다.
41쪽만 통과하거나 표지 점수만 높아지는 것으로 완료 처리하지 않는다.
진단 기록은 ignored stage2417~2418에 보존하고, 회귀 검사는 전쪽 선행
조건을 충족한 뒤 새로운 이름으로 추가한다.

## 법령의 줄 없는 단독 TAC 표와 공백 선행 줄

명시적 TrueType 환경의 법령46쪽은 문단424~440의 텍스트·원점이 독립 PDF와
일치하지만 문단442의 표부터34px 아래로 이동한다. 이 문단은 공백 두 개와
글자처럼 취급되는3행 표를 저장하며 LineSeg는 없다. 표 본체613.85px와
좌우 바깥여백3.76px, 선행 공백20px는 본문642.53px 안에 함께 들어간다.
독립 PDF는 같은 줄에서 표를 배치한다. 기존 경로는 폭90%의 인라인 분류와
단독 RowBreak 표 예외 때문에 물리 줄 계획을 사용하지 않고 공백 줄34px를
먼저 소비했다. 이후 빈 문단이 넘어가47쪽20px,48쪽16px의 이동을 일으켰다.
따라서 빈 문단을 숨기지 않고 원래 표·공백의 물리 줄 소속을 보정한다.

저장 줄이 없고 기존 물리 줄 계획이 지원하는 단독 RowBreak 표도 전체 계획이
현재 단에 수용될 때 그 결과를 측정·배치에 함께 사용한다. 공백·명시적 개행·
문자/객체 순서·현재 가용 너비·여백은 기존 plan 계산으로 결정한다. 실제 분할이
필요하면 페이지 상태를 바꾸기 전에 기존 분할 소유자에게 반환한다. 이 경로에서
전체 표를 임의로 다음 쪽으로 넘기거나 빈 줄 높이를0으로 만들지 않는다.

생산은 inline_flow::plan, 예산 확인은 try_place_reflowed_table_rows의 plan.end,
실제 배치는 commit_inline_flow에 저장한 같은 계획을 최종 renderer가 소비한다.
기존 저장 줄 경로와 분할 경로는 별도로 유지한다. 수용 가능한 전체 표·수용
불가능한 분할·개행/너비 부족·정상 대조군을 확인하며 전쪽90%·직접 판독 전에는
관련 formal 회귀를 바꾸거나 새로 추가하지 않는다.

## #1440의 KoPubWorld 프로그램 폭 누락

46쪽 독립 Print와47쪽 Native의 첫 다른 내용 소속은 원본 구역3 문단102에서
시작한다. 앞 문단99~101까지의 원점은 맞지만, 해당 Square 표 호스트의
본문은 Native 다섯 줄·PDF 네 줄로 갈려 뒤 본문이24px씩 밀린다. 현재
KoPubFamily 판별은 KoPubWorld 이름을 인식하지 않아 한글 전진을 일반
1em 휴리스틱으로 처리한다. 독립 PDF에는 실제 KoPubWorld Batang/
Dotum TrueType 프로그램이 내장되어 있다.

설치된 공식 Light 글꼴과 PDF 서브셋의 바탕855개·돋움82개 글리프가 윤곽과
전진 모두 일치했다. 여섯 굵기의 ASCII95자는 기존 KoPub 각 계열 표와
동일하다. 바탕의 현대 한글11172자는936/1000em, 돋움 Light/Medium은
872/1000em이다. 돋움 Bold는 두 음절만1000/1000em이고 나머지는872다.
이 반례도 실제 프로그램 값으로 보존한다.

World 계열의 이름과 확인된 ASCII/현대 한글 폭만 공통 측정에 연결한다.
미확인 다른 CJK·기호에 한글 폭을 확대하지 않으며, 종전 KoPub 계열의
근삿값과 폰트 파일은 바꾸지 않는다. 원본 저장 줄을 임의로 삭제하거나
46쪽 기대값을47쪽으로 갱신하지 않는다. 실제 새 페이지/줄 결과는 전체
Native/fresh WASM과 독립 Print로 확인한다. 원본 저장 줄의 재사용이
별도 문제로 남으면 그 유효성도 독립 근거로 확인하고 추가 보정한다.
