# Task #526 수행 계획서 — exam_science 12번 문제 인라인 수식 stack 결함

## 1. 배경

`pi=61` (12번 문제 후속) 의 9개 인라인 수식이 본문 텍스트 흐름이 아닌 한 점(`gx=534.8, gy=1206.91`)에 모두 stack 되어 글자가 겹쳐 unreadable.

페이지 1의 `pi=18` (4번 문제 후속, 7개 수식) 은 정상 인라인 배치. 차이는 pi=61의 **첫 줄에 인라인 2×1 표(tac=true)** 가 있다는 점.

## 2. 가설

`paragraph_layout.rs` 의 인라인 수식 배치 경로가 인라인 표를 처리한 줄 이후의 수식들에 대해 `inline_shape_position` 을 등록하지 못함. 결과적으로 `shape_layout.rs:140-152` fallback 경로 (정렬 기반 단독 배치) 로 떨어져 모든 수식이 동일 좌표 받음.

가설 검증 포인트:
- A. `composer.tac_controls` 가 9개 수식 + 1 표를 모두 포함하는가
- B. `tac_offsets_px` 의 수식 위치들이 후속 줄의 run 범위 안에 있는가
- C. `run_tacs` 필터가 수식들을 잡는가
- D. `set_inline_shape_position` 호출이 실제 일어나는가

## 3. 단계 (4단계)

### Stage 1 — 진단

(a) RHWP_LAYOUT_DEBUG 또는 임시 eprintln 으로 pi=61 의 다음 값 추적:
   - `composed.tac_controls` (위치, 폭, ci)
   - `tac_offsets_px` (위치, 폭, ci)
   - 각 line 의 `comp_line.runs` 와 `run_tacs` 필터 결과
   - `set_inline_shape_position` 호출 여부

(b) 표 처리 코드 (`paragraph_layout.rs:1899, 1919` 등) 가 표 본체만 등록하고 수식들은 별도 처리되지 않는 케이스 식별.

(c) `mydocs/working/task_m100_526_stage1.md` 에 진단 결과 + 수정 후보 정리.

**완료 기준**: 9개 수식이 fallback 으로 떨어지는 정확한 코드 경로/조건 식별.

### Stage 2 — 정정

진단 결과에 따라 한 가지 또는 여러 분기 수정:
- A안: `run_tacs` 필터 조건 보정 (인라인 표 뒤 수식 위치 매칭 누락)
- B안: 인라인 표 처리 후 후속 수식들에 대한 `set_inline_shape_position` 명시적 호출 추가
- C안: `composer.tac_controls` 빌드 시 인라인 표와 수식의 위치 충돌 해소

회귀 위험 최소화 — 변경 범위 최소.

**완료 기준**: pi=61 9개 수식이 distinct x 위치에 인라인 배치 (gy=1169, 1191 라인).
