# Task #927 수행 계획서 — HWP5 rhwp-studio 페이지 수 오버 (98p vs 62p)

## 이슈

[#927](https://github.com/edwardkim/rhwp/issues/927) — `samples/hwp3-sample16-hwp5.hwp` (HWP5) 가 rhwp-studio 에서 98p 표시되나 CLI/메타 62p (36 페이지 오버).

## 페이지 수 매트릭스

| 파일 | rhwp CLI | rhwp-studio | 한컴 PDF |
|------|---------|-------------|----------|
| `hwp3-sample16.hwp` (HWP3 원본) | 64 p | 정상 | — |
| `hwp3-sample16-hwp5.hwp` (HWP5) | 62 p | **98 p** ❌ | 64 p |

HWP3 원본은 정상. HWP5 변환본 + rhwp-studio 조합만 오버.

## 가설

1. **lineseg 자동 보정** ("비표준 lineseg 163건 자동 보정됨" — studio 상태줄) 로직이 페이지 분할 동작에 영향
2. CLI 와 studio 의 페이지네이션 호출 경로 차이
3. WASM 환경의 font fallback / metric 차이 → line height ↑ → 페이지 break ↑
4. studio 의 page break 결정 시 사용하는 default font metric 이 CLI 와 불일치

## 작업 범위

대상 모듈:
- `src/wasm_api/` — studio entry point, paginate API
- `src/renderer/pagination.rs` / `layout.rs` — 페이지 분할 로직
- `src/renderer/line_breaking.rs` — line_seg 처리 + 비표준 보정
- lineseg 보정 로직 위치 (메시지 출처)

## 절차 (waterfall)

**Stage 1 — 진단 심화**
- "비표준 lineseg ... 자동 보정됨" 메시지 출처 식별
- CLI 와 studio 의 paginate 호출 경로 비교
- 보정 후 line height 가 페이지 break 에 미치는 영향 측정
- studio 환경 폰트 metric 의 CLI 대비 차이 측정 (페이지 1~5 에서 line vpos 비교)

**Stage 2 — Root cause 수정**
- Stage 1 에서 식별된 가장 큰 원인 수정
- (예상) lineseg 보정 후 page break 위치가 CLI 와 다르게 결정되는 로직 정합

**Stage 3 — 보조 원인 + 회귀 점검**
- 다른 HWP5/HWPX sample 페이지 수 회귀 없음 확인
- HWP3 원본 페이지 수 변화 없음 (현재 정상 상태 유지)

**Stage 4 — 최종 보고서 + PR**

각 단계 완료 후 단계별 완료 보고서 + 승인 요청.
