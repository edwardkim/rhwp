## 1. 목표

특정 문자의 폭과 glyph가 왜 그렇게 선택됐는지를 한 개의 versioned trace로 설명한다. trace는 다음
세 질문에 답해야 한다.

1. 문서가 선언한 face와 언어 slot, `altType`, `substFont`가 어떤 layout name으로 정규화됐는가?
2. 그 문자의 advance는 어느 metric entry·overlay·surrogate·heuristic에서 결정됐는가?
3. native·Canvas2D·CanvasKit은 어떤 후보와 font resource를 사용할 수 있었고, 선택 또는 실패 이유는
   무엇인가?

이 작업은 font 정책을 고치는 단계가 아니다. 현재 resolver의 결정을 읽기 전용으로 설명하고, trace를
요청하지 않은 경로의 layout·paint·serialization 결과와 비용을 그대로 유지한다.

## 2. 왜 현재 구조에서 바로 로그만 추가하면 안 되는가

현재 font 결정은 한 함수에 모여 있지 않다.

```text
HWP/HWPX DocInfo
  → Rust style_resolver: 7개 언어 slot·altType·문서 substFont
  → Rust text_measurement: KoPub 표·metric alias·FONT_METRICS·overlay·heuristic
  → RenderTree/TextRun: 이미 정규화된 CSS family chain
  ├─ SVG/Canvas2D: 브라우저 CSS·local/web font 상태
  ├─ CanvasKit: SFNT font plan·substitution·glyph resource
  └─ native Skia: custom → system → bundled → legacy typeface와 문자별 glyph 보유 검사
```

- `ResolvedCharStyle`과 `TextStyle`에는 원래 document face·`altType`·`substFont`가 남지 않는다.
- `measure_char_width_embedded`, `compute_char_positions`, `estimate_text_width_unrounded`에는 같은 폭
  fallback 사다리가 나뉘어 있고 현재 반환값은 숫자뿐이다.
- `font_metrics_data::find_metric`은 최종 metric과 `bold_fallback`만 반환하므로 exact·bold-only·name-first,
  alias와 문자별 glyph miss를 구분할 수 없다.
- Studio의 `getRendererDiagnostics` v1은 renderer 선택과 페이지별 CanvasKit 상태만 설명한다.
- Canvas2D의 CSS family chain, Local Font Access 열거, raw Canvas probe와 실제 glyph 선택은 서로 다른
  증거다. 브라우저가 노출하지 않은 실제 선택 face를 추정으로 기록하면 안 된다.

따라서 별도 로그 문구를 여러 곳에 복제하지 않는다. 기존 선택 사다리를 결과와 reason을 함께 반환하는
순수 결정 함수로 추출하고, 기존 호출부는 그 결과의 숫자·face만 사용한다. opt-in query만 같은 결정
객체를 직렬화한다.

## 3. 보호 불변식

[원인 계보 보고서](../report/font_metrics_fallback_causal_lineage_20260816.md)의 FI-01~FI-14를 전부
적용하며, 특히 다음을 hard gate로 둔다.

- native/WASM 기본 SVG는 byte-identical이어야 한다.
- 호스트에 설치된 font 상태가 portable default layout을 조용히 바꾸지 않는다.
- layout metric face와 paint face가 다를 수 있음을 오류로 합치지 않는다.
- identity alias, document substitution, official successor, metric surrogate, paint substitute,
  supply source와 capability detection을 같은 `fallback` 문자열로 축약하지 않는다.
- metric의 exact → bold-only → name-first 물리 순서와 first-match 계약을 유지한다.
- KoPub 전용 폭, 한컴 PDF space overlay, 구두점·`.notdef` 보정, area-dot과 일반 heuristic의 적용
  순서를 바꾸지 않는다.
- CSS 사용 가능성, Local Font Access 열거, raw probe와 CanvasKit SFNT 조달을 별도 capability로 둔다.
- HWP/HWPX 형식 또는 한컴 build 번호로 분기하지 않고 현재 객체·문단 상태를 feature detection한다.
- 저장 LineSeg와 fresh layout을 혼합하지 않는다.
- private 10k corpus 원문·식별 목록·절대 경로와 재배포 불가 font bytes를 저장소 산출물에 넣지 않는다.

## 5. 공개 계약 — 별도 `FontDecisionTrace` v1

기존 renderer diagnostics에 optional field를 덧붙이지 않고 별도 query를 둔다.

```text
Rust native: get_font_decision_trace_native(page, options) -> JSON
WASM:        getFontDecisionTrace(page, optionsJson) -> JSON string
Studio RPC:  getFontDecisionTrace({ page, limits? }) -> EmbedFontDecisionTraceV1
```

초기 options는 page 단위와 상한만 허용한다. 임의 section/paragraph 선택이나 비결정적 sampling은 v1에
넣지 않는다. 유효하지 않은 page·상한·backend 값은 기본값으로 조용히 바꾸지 않고 오류로 거부한다.

### 5.1 최상위 봉투

```text
schemaVersion: 1
status: complete | truncated | unsupported | failed
scope: { pageIndex, requestedLimits, appliedLimits }
counts: { runsSeen, charactersSeen, recordsEmitted, recordsOmitted }
records[]
backendSummary: { layout, native, canvas2d, canvaskit }
reasons[]
normalizedHash: { algorithm: sha256, value }
```

- `reasons[]`는 안정 enum code와 사람이 읽는 detail을 분리한다.
- stack trace, wall-clock, elapsed time, 절대 path, 사용자명과 browser 객체 순서는 hash 대상에서 뺀다.
- `recordsOmitted`를 계산할 수 없으면 `null`과 reason을 함께 두며 0으로 가장하지 않는다.
- backend가 빌드되지 않았거나 관찰 API가 없으면 빈 성공이 아니라 `unsupported` 또는
  `notObserved`를 기록한다.

### 5.2 문자 record

각 record는 source 순서로 다음 층을 분리한다.

```text
source
  sectionIndex, paragraphIndex, nestedPath?, runIndex, charOffset
  character, codePoint, charShapeId
document
  languageSlot, inheritedLanguageSlot?
  face, altType, embedded, substFont
layoutName
  requestedFace, normalizedFace, cssFamilyChain, steps[]
layoutMetric
  requestedFace, aliasResolvedFace
  matchKind: exact | boldOnly | nameFirst | none
  metricEntry?, characterMatch: hit | miss | notApplicable
  widthSource, baseAdvanceHwpunit, transforms[] , finalAdvanceHwpunit
paint
  native, canvas2d, canvaskit
provenance[]
  candidateId, ruleId, evidenceAnchor, sourceOwner, relationType, evidenceStatus
oracle
  status, profileId?, knownLimitations[]
```

`paint`의 backend별 항목은 `requested`, `candidates`, `resolved`, `source`, `capabilities`, `failures`와
`certainty`를 갖는다. `certainty`는 최소 `observed`, `resolved`, `planned`, `notObserved`, `unsupported`를
구분한다. Canvas2D가 실제 선택 glyph face를 공개하지 않으면 CSS chain과 확인된 supply 상태만 기록하고
`resolved`로 승격하지 않는다.

`oracle`은 W5보다 먼저 임의 profile을 만들지 않는다. 현재 입력에 검증된 profile이 없으면
`status: notProvided`, `profileId: null`과 알려진 제한을 명시한다.

### 5.3 폭 계산 계보

폭은 최종 실수 하나만 기록하지 않는다. 최소한 다음 순서를 분리한다.

1. zero-width control 또는 object placeholder
2. U+318D area-dot policy
3. KoPub 전용 character table
4. metric alias와 exact·bold-only·name-first entry 선택
5. space overlay, narrow punctuation, halfwidth quote, `.notdef` artifact 보정
6. metric character miss 뒤 cluster/CJK/fullwidth, narrow punctuation, generic halfwidth heuristic
7. dash leader 제한
8. 장평 비율, glyph-relative 자간, extra char/word/dash spacing
9. HWPUNIT 양자화와 최종 advance

기존 측정 함수가 위 사다리의 같은 순수 `CharWidthDecision`을 사용하도록 하여 trace와 실제 layout이
서로 다른 답을 만들지 못하게 한다.

## 6. W1 `ruleId`와 evidence 연결 방식

W1 원장의 1,507행을 Rust/TypeScript 선택 표로 생성하거나 제품 source에 복사하지 않는다. 대신 실제
결정 지점이 이미 알고 있는 다음 W1 candidate identity를 trace 전용 값으로 만든다.

```text
sourceBoundaryId
candidateKind
sourceFace
targetOrPolicy
conditions
order
```

W1의 canonical key ordering·UTF-8·trailing newline·SHA-256 규약으로 identity hash를 계산해
`candidate.<20hex>`와 `rule.<sourceOwner>.<20hex>`를 만든다. evidence anchor는 해당 candidate ID를
가리킨다.

- 이 계산은 이미 선택된 결과에 provenance를 붙일 뿐 target 선택에는 참여하지 않는다.
- Rust와 TypeScript golden vector가 byte-for-byte 같은 ID를 만들어야 한다.
- local validator는 trace fixture의 모든 `ruleId`가 W1 ledger에 존재하고 source owner·relation type이
  일치하는지 검사한다.
- 대응 행이 없으면 임의 ID를 만들지 않고 `ruleId: null`, `reason: ledgerRuleMissing`으로 fail-closed한다.
- `evidenceStatus: unknown`은 그대로 노출하며 추정으로 `verified`에 올리지 않는다.
- ledger의 source digest가 현재 source와 달라도 selection을 중단시키지는 않는다. trace status에
  `ledgerSourceDrift`를 명시하고 W1 collector 재실행이 필요함을 알린다.

이 구조는 ledger를 runtime authority로 만들지 않으면서도 W1과 W2 사이의 기계 검증 가능한 링크를
유지한다.

## 8. 상한·성능·오류 계약

- v1은 page 한 개만 처리한다.
- 기본 문자 상한은 1,024, hard maximum은 4,096으로 고정한다. `0`, 음수, 비정수와 maximum 초과는
  거부하며 자동 clamp하지 않는다.
- 문자당 provenance step과 failure reason에도 고정 상한을 두고 중복을 stable dedupe한다.
- source order로 앞에서부터 수집하고 상한에 닿으면 `status: truncated`와 최초 누락 source 좌표를 남긴다.
- trace query 안에서 네트워크 font fetch, Local Font Access 권한 요청, 문서 reload와 repaint를 시작하지
  않는다. 현재 snapshot만 읽는다.
- default layout/render 호출에는 collector, allocation, hashing과 browser capability query를 추가하지
  않는다.
- serialization 실패, source 좌표 불일치, backend join 불일치와 hash 기능 부재는 빈 배열 성공으로
  바꾸지 않는다.
- 오류 detail에는 font filename 외의 host path, 원문 파일명, 사용자명과 browser exception stack을
  넣지 않는다.

## 9. 결정론적 hash 계약

`normalizedHash`는 다음 규칙으로 만든다.

- JSON object key는 code-point order로 정렬하고 array는 source/decision 순서를 보존한다.
- browser enumeration, set과 map에서 온 후보는 의미 있는 우선순위가 없을 때 normalized family와 source로
  정렬한다. 선택 순서 자체가 정책인 chain은 절대 정렬하지 않는다.
- 폭은 부동소수점 문자열이 아니라 HWPUNIT 정수와 schema가 정한 유리 변환 값으로 기록한다.
- timestamp, elapsed time, 절대 path, error stack과 hash 자신은 projection에서 제외한다.
- capability snapshot과 backend 선택 결과는 포함하므로 동일 hash의 의미는 같은 문서·page·options·현재
  capability 상태다. portable layout 부분은 별도 `layoutHash`로 분리해 호스트 font 상태와 무관함을 검증한다.
- Rust와 TypeScript가 같은 golden trace에서 같은 canonical bytes와 SHA-256을 만들어야 한다.

### Stage 2 — Rust layout decision trace

1. style resolution을 기존 문자열 wrapper와 provenance decision으로 분리한다.
2. metric lookup이 alias, match rung, entry와 `bold_fallback`을 설명하게 하되 기존 `find_metric` 결과를
   전수 비교한다.
3. 문자 폭 사다리를 단일 `CharWidthDecision`으로 추출하고 두 기존 측정 경로가 이를 사용하게 한다.
4. page source 좌표·DocInfo·문자 결정 record를 결합하는 bounded native query를 구현한다.
5. WASM binding과 canonical `layoutHash`를 추가한다.
6. 대표 exact, alias, surrogate, overlay, metric miss, CJK/narrow/generic heuristic, document substFont와
   7개 언어 slot 회귀를 추가한다.

**종료 게이트:** legacy metric projection과 기존 폭 함수가 전수·대표 입력에서 동일하고, native/WASM
layout trace JSON과 `layoutHash`가 일치하며 기본 renderer output delta가 0이다.

### Stage 3 — backend capability와 paint trace

1. native Skia 후보 chain과 문자별 glyph 보유 검사를 실제 render helper와 공유하고 feature-gated trace로
   노출한다.
2. Studio에 별도 `getFontDecisionTrace` RPC와 엄격한 parameter validation을 추가한다.
3. Canvas2D substitution, local/web/generic source와 certainty를 현재 snapshot에서 읽는다.
4. CanvasKit SFNT plan, local/bundled/glyph resource, substitution과 failure reason을 source record에 결합한다.
5. CSS 실제 glyph face 미관찰, API 미지원, 권한 거부, 부분 열거, SFNT 부재와 backend join 실패를 서로
   다른 reason으로 검증한다.

**종료 게이트:** 같은 record가 세 backend의 서로 다른 결과를 한 schema에서 설명하고, trace 호출이
font load·repaint·layout·backend 선택을 발생시키지 않는다.

### Stage 4 — 공개 HWP/HWPX end-to-end와 결정론 검증

1. 공개 HWP와 HWPX에서 document face → layout name → metric/heuristic → paint/backend 계보가 끊기지
   않는 fixture를 만든다.
2. exact face, missing face와 document substitute profile을 섞지 않고 각각 실행한다.
3. native, WASM, Canvas2D와 CanvasKit의 normalized trace 차이를 reason 단위로 판정한다.
4. 같은 입력을 반복하고 object key·font enumeration 순서를 변이해 hash 결정론을 검증한다.
5. 상한 초과와 unsupported backend가 explicit status로 끝나는지 확인한다.

**종료 게이트:** Issue #4961의 대표 HWP/HWPX, backend 차이, deterministic hash와 fail-closed 완료 조건이
모두 자동 test evidence를 가진다.

### Stage 5 — 불변식 감사·문서·최종 보고

1. W1 ledger validator와 trace `ruleId` join을 재실행한다.
2. focused Rust·Studio·WASM test, native/WASM 공개 SVG parity와 `native-skia` gate를 실행한다.
3. trace disabled 상태의 API·renderer·serialization output과 frontend 초기화 동작이 이전과 같은지
   확인한다.
4. FI-01~FI-14와 #4961 완료 조건을 전항 disposition한다.
5. API 문서, Stage 보고서, 최종 보고서와 오늘할일을 현행화하고 W3·W4 입력을 명시한다.

**종료 게이트:** 제품 선택·출력 0-delta, 모든 trace 계약 통과, private 자료 비포함, 알려진 한계와
후속 issue disposition이 확인된다.

## 12. 중단 조건과 잔여 위험

다음 중 하나가 발생하면 성공으로 기록하지 않고 해당 Stage에서 중단한다.

- trace를 만들기 위해 fallback order, metric 값 또는 backend 선택 결과가 바뀜
- default render 경로에 collector·hash·browser font query 비용이 생김
- trace용 폭 계산이 실제 layout의 함수와 분리되어 같은 문자에 다른 advance를 반환함
- W1 ledger를 selection authority로 import하거나 W7 registry projection을 선행함
- 대응하지 않는 `ruleId`를 추정으로 생성하거나 44개 `unknown`을 숨김
- Canvas2D 실제 glyph face를 CSS chain만으로 `observed`라고 주장함
- backend 미지원·부분 열거·join 실패·상한 초과를 빈 성공으로 반환함
- hash에 timestamp·절대 path·비결정적 enumeration order가 들어감
- private corpus 식별 정보 또는 재배포 불가 font bytes가 diff에 포함됨
- native/WASM parity 또는 기존 font contract가 깨짐

W2 완료 뒤에도 실제 10k renderer coverage, 장평·자간·고정 frame 위험 순위는 #4962에서 수행한다.
oracle profile schema는 #4963, generated metric과 manual overlay 계보 분리는 #4964, canonical registry는
#4966 이후의 별도 승인 대상이다.

## 13. 완료 기준

- 대표 공개 HWP/HWPX에서 document face부터 최종 fallback reason까지 문자별 trace가 이어진다.
- document face, language slot, `altType`, `substFont`, normalized face, metric hit/miss와 width reason이
  보존된다.
- Rust layout, native, Canvas2D와 CanvasKit의 다른 결정·capability·failure가 같은 schema로 설명된다.
- candidate evidence anchor와 `ruleId`가 W1 ledger에 기계적으로 연결되며 unknown은 그대로 남는다.
- 같은 입력·options·capability snapshot의 normalized hash와 portable `layoutHash`가 결정론적이다.
- page·문자·reason 상한, unsupported backend와 source join 실패가 명시적으로 fail-closed한다.
- trace 미호출 시 기존 font 계약, native/WASM renderer output과 Studio 초기화 결과가 변하지 않는다.
- private corpus와 허가되지 않은 font bytes가 산출물에 포함되지 않는다.
- API 문서, Stage 보고서, 최종 보고서와 W3·W4 인계가 완료된다.
