| 환경 | 출력 |

- **포맷**: HWP3 한정 (HWP5 / HWPX 동일 현상 미확인). 본 타스크는 HWP3 경로에서만 재현되는 회귀로 한정한다.
- **기존 회귀**: `upstream/devel d4a32ab2` 시점에서도 동일 발생. PR #918 (Task #902 WMF) 와 **무관**.
- **영향 모듈 후보**:
  1. **HWP3 파서** — `src/parser/hwp3/` 에서 표 셀 paragraph 의 inline shape (tac=true wrap=TopAndBottom) 텍스트/오프셋 산출 단계
  2. **공통 렌더러 TAC 분할** — `src/renderer/composer.rs`, `src/renderer/layout/paragraph_layout.rs` 의 `run_tacs` / `tac_offsets_px` 계산 단계
  3. **공통 컨트롤 위치 산출** — `src/model/paragraph.rs::control_text_positions()` 의 `\u{FFFC}` fallback 경로

> CLAUDE.md 규칙에 따라 HWP3 전용 분기는 `src/parser/hwp3/` 안에서만 추가한다. 공통 모듈에 HWP3 분기 추가 금지.

## 4. 1차 분석 (사전 정찰)

- `src/parser/hwp3/mod.rs` 의 control 루프 (≈384-457) 가 컨트롤마다 `\u{FFFC}` 마커를 `text_string` 에 삽입하고, 813-847 의 표 셀 paragraph 경로도 같은 마커를 쓴다. wrap=TopAndBottom 과 Square 가 구분 없이 삽입된다.
- `src/model/paragraph.rs::control_text_positions()` (≈773-867) 는 char_offsets gap 분석으로 컨트롤 위치를 결정하며, gap 분석 실패 시 `\u{FFFC}` 검색 fallback (≈840-863) 으로 대체한다. 최근 183c5d08 에서 "그림 3개 중복 emit" 을 잡기 위해 fallback 이 강화되었다.
- `src/renderer/layout/paragraph_layout.rs` (≈1920-2110) 의 TAC 분할이 `run_tacs` 와 `tac_offsets_px` 로 shape marker 전/후 RUN 을 분리한다. 마커 위치가 2회 잡히면 RUN 도 2회 분리되어 양쪽에 동일 텍스트가 emit 될 수 있다.
- 가장 가능성 높은 1차 가설: **HWP3 표 셀 paragraph 의 `\u{FFFC}` 마커 또는 `char_offsets` 가 중복 삽입되어, 후단 TAC 분할이 동일 segment 를 2회 emit** 한다. 또는 char_offsets 가 정확해도 shape 가 본문 paragraph 와 셀 paragraph 양쪽에 등록되어 wrap-around sub-paragraph 가 본문 위에 덧그려질 수 있다.

- `control_text_positions()` 는 HWP5/HWPX 공용이다. 여기서 수정하면 PR #877, #902 등에서 통과한 회귀가 깨질 수 있다. 가능하면 HWP3 파서 단계에서 IR 산출을 정정하는 방향을 우선한다.
