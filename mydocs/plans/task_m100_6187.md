## 1. 목표와 사용자 결정

눈금자 표시·입력 정책과 resize 깜빡임의 원인을 각각 해결하되, #6187 전체 수용 기준을 만족하는
**새 PR 하나**로 제출한다. stacked PR이나 표시 정책만 먼저 병합하는 별도 PR은 만들지 않는다.

사용자가 대화에서 확정한 제품 방향은 다음과 같다.

1. 편집 화면의 가로·세로 눈금자와 교차 코너는 화면 너비와 무관하게 항상 표시한다.
2. 모바일의 손가락 입력은 눈금자 읽기 전용으로 다룬다. 좁은 데스크톱 창이나 태블릿에 연결한
   마우스까지 비활성화하지 않도록, 화면 너비·UA가 아니라 실제 입력 종류로 조작 여부를 판단한다.
3. 읽기 전용이어도 눈금·숫자·현재 문맥의 여백/들여쓰기 표시는 유지한다. 기존 문단 모양·편집 용지
   대화상자를 통한 수치 변경 경로와 문서 스크롤·확대 제스처를 막지 않는다.
4. 창 드래그 resize 중 눈금자가 비는 현상은 표시 정책과 독립된 결함으로 재현·수정·검증한다.
5. 구현 뒤 로컬 서버에서 작업지시자가 직접 확인한다. 그 확인과 별도 승인을 받기 전에는
   remote push나 PR 생성을 수행하지 않는다.

인쇄 시 눈금자를 숨기는 기존 계약과 문서 미로드 상태의 빈 눈금자 배경은 유지한다.
‘항상 표시’는 모든 문맥에서 존재하지 않는 핀이나 화면 밖 용지의 눈금까지 만들어 낸다는 뜻이 아니다.

## 5. 수용 기준

- 375px 등 모바일 크기, 767/768, 807/808, 961/962, 1023/1024px와 넓은 화면에서 눈금자 grid 유지.
- `max-height: 500px` 모바일 조건에서도 눈금자가 사라지거나 잘못된 flex 자식으로 배치되지 않음.
- 마우스·트랙패드는 좁은 화면에서도 기존 핀 조작 가능. 손가락 입력은 핀 드래그와 문서 commit을
  발생시키지 않음. 같은 장치에서 입력 수단을 바꿔도 페이지 새로고침 불필요.
- 클릭만으로 commit하지 않는 기존 규칙과 실제 마우스 drag의 commit/undo 경로 유지.
- 10/50/100% × 세로/가로 쪽 이동의 각 조합에서 1023↔1024 왕복 10회 이상과 연속 너비 변경 중
  눈금자 공백 프레임, 중복 표시, 오래된 좌표 잔류가 없음.
- 767/768, 807/808, 961/962 경계에서도 resize 전 마지막 편집 focus·눈금 기준 쪽·배율·쪽 이동
  설정을 유지하고 page-level 가로 overflow나 서식 도구 모음 회귀가 없음.
- 문서 교체, 테마 변경, dispose 후 예약 callback·전역 입력 listener 정리에 회귀가 없음.
- 정적 visibility, bitmap 갱신 동작 검사, 실제 화면 증거를 서로 구분해 보고하고 작업지시자가
  로컬 서버에서 창 드래그로 최종 확인함.
