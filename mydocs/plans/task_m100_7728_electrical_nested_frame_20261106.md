## 1단계 — 닫힌 TAC 원본 프레임의 기본 줄 중복 제거

`unstored_tac_wrapper_shares_anchor_line`은 단일 셀·단일 빈 문단의 TAC 자식과 폭 없는
마커만 있는 원본을 판별한다. 부모 선언 높이가 자식 본체·자식 바깥 여백·부모 안 여백의
합과 정확히 닫힐 때만 기본 글자 줄과 자식 상자의 합집합을 사용한다. 실제 저장 줄,
본문, 다른 개체, 독립 세로 정렬 공간은 기존 계약을 유지한다. 성장한 내용도 자르지 않는다.
행 높이와 상세 컷 원장에 같은 판별을 적용하고 부모의 가로 프레임·테두리는 보존한다.

- 독립 원본 프레임 관계를 검사하는 ignored 진단: 보정 전 실제 실패(exit101,
  430.0133px), 보정 후 통과(exit0, 400.0133px). 새 정식 회귀 테스트는 아직 추가하지 않았다.
- 후보 Native 전 18쪽: 누락 0, 최저 49.35093%, 미달 5·6·7·9쪽. 9쪽은
  57.11636→63.64442%, 10쪽은 16.84183→99.57724%다. 남은 쪽을 수용으로 바꾸지 않는다.
- 새 소스에서 Mac 최소 글꼴 Native Skia 3종: 전체 lib 4,039 PASS/0 FAIL/12 ignore,
  누락 그림 PNG 2 PASS, 직접 PDF 22 PASS. 세 종료 코드 모두 0이다.

- #2195의 86712·80168 공개 측정 API 대조 222행은 전후 동일했다. 이것은 해당 두 문서의

## 2단계 — 저장 빈 행·짧은 재시작과 부동 표의 본문 소속

단일 저장 글줄이 있는 큰 빈 행을 첫 물리 프레임과 빈 꼬리로 나눠 부모·자식이 같은 유닛을
소비하게 했다. 빈 꼬리는 글줄을 복제하거나 안여백을 한 번 더 예약하지 않는다. 한 단 정의는
기존 공용 메타데이터 판정을 쓰며, 원본 문단의 인접 `0→0` 저장 재시작은 실제 행 원점과
선언 첫 프레임을 함께 확인한다. 이 경계의 부모 예약과 부분 표 배치는 같은 컷 높이를 쓴다.

9쪽의 실제 원인은 빈 문단 높이 0이 아니다. 독립 재저장본에 문단42의 문자 `x`만 넣으면
8쪽 하단에 인쇄되며 표는 9쪽에 남는다. 42·43을 둘 다 제거한 위치는 하나만 제거한 경우와
같다. 부동 표가 실제로 이월되는 공통 경로에서 현재 쪽에 들어가는 호스트·후속 본문을
기존 prefill로 남기도록 보정했다. 원본 문단42 소속, 빈 행 시작, 문단 내부 계속 문구의
ignored 진단은 각각 실제 FAIL→PASS다. 원본과 새 정식 회귀 검사는 바꾸지 않았다.

- 후보 Native 전 18쪽, 누락 0: 5쪽 54.39305→96.74611%, 9쪽 63.64442→97.70433%.
- 미달은 6쪽 59.22973%, 7쪽 48.62869%다. 7쪽은 fixed devel 49.35093%보다
  0.72224%p 하락했으므로 수용하지 않는다. 전체 최저의 후퇴를 숨기지 않는다.
- 현재 후보 Mac 최소 글꼴 Native Skia 전체 lib 4,039 PASS/0 FAIL/12 ignore,
  PNG 2 PASS·직접 PDF 22 PASS. 이전 단계의 결과를 새 후보 통과로 재인용하지 않았다.
- 6쪽의 `(생략)` 행과 7쪽 앞 제목의 잘못된 쪽 소속이 남는다. 앞 네 행의 실제 합은
  왼쪽 448.8px·오른쪽 448.0px로 선언 첫 프레임과 정확히 닫히지만 다음 행의 부모 유닛에는
  물리 쪽 경계가 없다. 원시 높이만 보는 판정·재조판 출처·부모 전달 소비를 계속 추적한다.
  완결 행 소속 진단은 여전히 FAIL이다.

부분 보정의 파일 hash·전쪽 원 수치·미달/하락·Native 3종 명령과 로그 hash·전후 review/overlay는

## 3단계 — 완결 행 프레임의 최종 컷 권한

실제 앞 네 행의 합과 원본 개체 높이가 정확히 닫히는 경계를 공통 행 계획으로 인증했다.
행별 정수 역변환에서 1HU를 잃던 후보를 누적 물리 합 비교로 바로잡았으며 공차는 추가하지
않았다. 뒤 행 재조판과 앞 원본 행의 소유를 구분하고 일반·세분 행 모두 같은 표식을 전달한다.
