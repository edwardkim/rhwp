# Task M100 #3514 수행계획서 — Chrome 실제 패키지 핵심 surface smoke

- 이슈: #3514
- 상위 이슈: #3512
- 마일스톤: M100 (v1.0.0)
- 브랜치: `codex/issue-3514-extension-smoke` (`upstream/devel@00da1ab35` 분기)
- 작성일: 2026-08-20
- 현재 게이트: Stage 2 승인 완료, Stage 3 준비

## 1. 배경

확장 프로그램은 Studio 단위·E2E와 정적 dist 검사가 통과해도 실제 MV3 패키지에서 CSP,
정적 자산 경로, service worker, content script 배선이 깨질 수 있다. options CSP(PR #168),
viewer CSP·다크 아이콘 404(#1444), `print.html` 누락(#3433)이 실제 배포에서 반복됐다.

현재 `scripts/frontend-extension-dist.test.mjs`와 `rhwp-chrome` Node 테스트는 파일 존재,
인라인 스크립트, 설정·다운로드·fetch 정책을 검증한다. 하지만 `rhwp-chrome/dist`를 실제 Chrome에
설치해 extension origin의 page/service worker/content script가 함께 초기화되는지는 검증하지 않는다.

## 2. 목표

Puppeteer가 동반하는 Chrome for Testing에 최종 `rhwp-chrome/dist`를 unpacked extension으로
설치하고, 사용자 프로필·외부 네트워크에 의존하지 않는 단일 smoke 명령을 제공한다.

## 3. 범위

1. 실제 패키지 설치와 런타임 extension ID 탐지
2. MV3 service worker target 및 시작 오류 검증
3. viewer의 실제 HWP fixture 로드와 Canvas 준비
4. 다크 모드 viewer의 CSP·정적 자산 요청 검증
5. options 설정 hydration 뒤 입력 활성화 검증
6. viewer와 같은 origin의 print surface 로드·DOM 접근 검증
7. loopback 페이지 content script 주입과 HWP 배지 1개 검증
8. 격리 프로필·다운로드 디렉터리, 탭 예산, 외부망 차단, 실패 진단과 정리

## 4. 비범위

- 설정·다운로드 수명주기 상세 시나리오(#3513)
- provider 분류·동적 DOM·hover·context menu·`file://` 전수 E2E
- OS 인쇄 대화상자와 인쇄물 시각 비교
- CI 경로 분류·브라우저 캐시(#3515)
- Web Store 업데이트와 계정 동기화

## 5. 단계

| Stage | 범위 | 산출물 | 승인 뒤 동작 | 상태 |
|---|---|---|---|---|
| 1 | 과거 확장 오류 조사, #3514 범위 확정, 수행·구현계획, 절차 복구 | 오늘할일, 두 계획서, recovery feedback, Stage 1 보고 | Stage 1 문서 커밋 | 승인 완료 |

## 6. 절차 복구

초기 진행에서는 위 범위를 모두 단일 Stage 1로 묶어 구현·검증한 뒤 한 번에 stage했다. 이는
단계별 승인 게이트를 지키지 못한 것이다. 작업지시자의 지시에 따라 전체 index를 비우고,
`mydocs/feedback/task_m100_3514_hyper_waterfall_recovery.md`에 이 이탈을 기록했다.

이미 작성된 Stage 2·3 후보 변경은 작업트리에 보존하되 해당 Stage 승인 절차 전에는 stage하지
않는다. Stage 3에서는 Stage 2 커밋을 기준으로 전체 검증을 다시 실행해 순차 게이트 증적을 새로 만든다.

## 7. 완료 조건

- #3514의 확장된 체크리스트를 충족한다.
- `npm --prefix rhwp-chrome run test:e2e:smoke`가 한 명령으로 build와 smoke를 실행한다.
- smoke는 사용자 Chrome, Web Store, 외부 네트워크를 사용하지 않는다.
- 프로덕션 권한·CSP·테스트 전용 hook을 추가하지 않는다.
- retry 없이 로컬 10회 연속 통과한다.

## 8. 위험과 대응

| 위험 | 대응 |
|------|------|
| Chrome/Puppeteer 버전 드리프트 | `puppeteer`가 동반하는 Chrome for Testing을 같은 package lock으로 고정 |
| worker가 빠르게 유휴 종료 | 설치 직후 service worker target을 bounded timeout으로 탐지하고 진단 로그 수집 |
| 브라우저 배경 요청이 외부망에 의존 | loopback 차단 proxy와 Chrome background-networking 비활성화 사용 |
| 시작 탭·자동 탭으로 false positive | harness가 소유한 page만 명시하고 전체 page budget을 즉시 검사 |
| 정상 console 경고를 오류로 오판 | error/pageerror/HTTP 실패를 차단하고 알려진 비오류 console은 진단으로만 보존 |
| 실패 시 프로필·Chrome 누수 | 모든 자원을 `finally`에서 역순 정리하고 정리 실패도 진단에 포함 |
