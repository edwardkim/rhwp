# 수행계획서 — #3486 HWP3 암호 문서 한컴 기준 PDF 렌더링 정합

  `samples/HWP5-password-123456.hwpx`

## 목표와 판정권

암호 해제 성공 자체가 아니라, 같은 문서를 한컴에서 출력한 기준 PDF와 rhwp의 parser → 공통 IR →
layout → renderer 결과를 대조하여 **구조·기하 결함**을 수정한다. 픽셀 지표와 visual sweep은 차이를
찾고 범위를 좁히는 보조 수단이며, 최종 시각 수용 판정은 한컴 기준을 확인하는 작업지시자에게 있다.

암호 HWPX의 최신 배포 MCP 변환은 정상 동작을 다시 확인했다. 이 결과는 원본과 기준 PDF를 얻는
수단의 정상성만 보장하며, rhwp의 렌더링 정합을 증명하지는 않는다.

## 이미 완료한 기준선과 정정 사항

- Stage 1은 HWP3 아래아 누락을 재현 fixture로 고정하고 제목을 복원했다.
- Stage 1 당시의 "쪽 배경 이미지를 표시하지 않는다"는 가설은 최신 한컴 기준 PDF의 1쪽 중앙 그림과
  작업지시자가 제공한 대조 화면에 맞지 않았다. 따라서 이후 단계에서는 HWP3 추가 정보 블록 #6의
  실제 이미지·효과값을 공통 `BorderFill` 이미지 채우기로 보존하는 쪽으로 재조사한다.
- 이 계획서는 초기 Stage 1 뒤에 누락된 수행·구현 계획을 보완하는 기록이다. 이미 존재하는 코드 변경은
  Stage 2 보고와 커밋 `b775832f4`에 정확히 연결하며, 과거 순서를 문서로 꾸며내지 않는다.

## 구현 범위

1. HWP3 추가 정보와 문단/문자 stream 값을 HWP5/HWPX 공통 IR 계약에 맞춰 보존한다.
2. 확인된 한컴 PUA만 별도 표에서 의미가 있는 표준 문자로 paint 경로에 투영한다. 원문 IR은 보존하며,
   연속 PUA 범위를 추측으로 치환하지 않는다.
3. HWP3와 HWPX의 공통 renderer 차이는 공통 경로에서만 조정하되, HWP3 고유 의미를 일반 문서에
   넓게 적용하지 않는다.
4. renderer 변경에는 fixture 회귀 테스트와 한컴 PDF 기준 시각 자료를 함께 남긴다.

### Stage 3에서 확인한 표현 계약

- HWP5 계열 `ImageFill`의 두 8-bit 필드는 저장 순서가 화면 의미와 반대다. HWPX의
  `bright="50" contrast="-15"`는 공통 raw IR에서 `(brightness=-15, contrast=50)`으로 보존한다.
  이 raw 계약은 parser·IR diff·round-trip의 기준이며, 여기서 의미 순서로 뒤집지 않는다.
- 반면 화면 출력 경계에서는 위 raw 값을 그대로 `brightness=-15, contrast=50`으로 해석하면 안 된다.
  HWP3와 HWPX 양쪽이 SVG에 `rhwp-img-bc-b-15c50`을 내보내는 것을 재현했다. Stage 3의 다음 변경은
  쪽 배경의 renderer 경계에서만 display 값 `(50, -15)`으로 투영하고, 일반 그림의 별도 속성과
  legacy REAL_PIC watermark preset은 분리해 보존한다.
- 새 HWP5 평문 비교 fixture는 24쪽·365문단이고 HWPX 두 비교 fixture는 23쪽이다. 동일한 한컴
  원본 계열이라는 사실만으로 쪽 번호를 맞춰 대조하지 않으며, HWPX는 자체 기준 PDF를 확보한 뒤
  별도 시각 비교한다.

## 범위 제외와 제약

- 한컴/HY 전용 폰트·HFT를 저장소 또는 증적에 포함하지 않는다. 해당 폰트 메트릭 차이는 남은 차이로
  구분해 기록한다.
- HWP3 비밀번호 알고리즘의 추가 변경, 암호 UI/저장 정책, HWPX 복호화 구현은 #3486의 렌더 정합
  변경 범위가 아니다.
- PUA pictogram의 실제 키캡·도형 조판을 일반 문자 치환으로 가장하지 않는다. 현재 가능한 의미 보존
  fallback과 별도 object/pictogram 지원의 경계를 보고한다.
- 전체 CI 성격의 긴 검증은 focused 결과와 시각 자료를 먼저 공유하고 작업지시자가 승인한 뒤에만
  실행한다.

## 단계 3 구현계획

1. HWP3 원본의 추가 정보 블록 #6과 HWPX 비교 문서의 이미지 효과(밝기·대비·effect·fill mode)를
   추출해 공통 IR 값을 대조한다.
2. SVG와 Web Canvas의 이미지 효과 적용 순서를 동일 입력으로 확인한다. 중앙 그림의 색조 차이는
   effect 해석, opacity/워터마크 preset, 색상 보정 중 어느 경로인지 분리한다.
3. 한 원인만 수정하고 HWP3 및 HWPX의 1쪽을 다시 sweep한다. 페이지 수, 그림 위치, 본문 line flow를
   별도 지표로 기록한다.
4. 수정을 뒷받침하는 최소 회귀 테스트를 추가한다. HFT 부재로 설명되는 차이는 코드 수정 대상에서
   제외하고 수용 판단 자료로 남긴다.
