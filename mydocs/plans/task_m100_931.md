# Task #931 수행 계획서

## 1. 이슈 요약

**Issue #931**: rhwp-studio 축소 시 BehindText 워터마크 overlay가 줌 배율을 따르지 않음

**대상 파일**: `samples/복학원서.hwp`

**마일스톤**: v1.0.0 (M100)

## 2. 증상

rhwp-studio에서 `samples/복학원서.hwp`를 연 뒤 하단 상태 표시줄의 축소 버튼으로 25% 수준까지 줄이면, 문서 페이지 뒤쪽 회색 작업 영역에 고려대 워터마크 이미지가 원본 크기처럼 크게 노출된다.

화면상으로는 같은 워터마크가 두 장 보인다. 문서 페이지 안의 워터마크는 문서 내용으로 유지되어야 하지만, 뒤쪽에 크게 남는 이미지는 overlay 배치가 줌 배율을 따르지 않아 발생한 렌더링 결함으로 판단한다.

## 3. 사전 분석

`복학원서.hwp`의 PageLayerTree를 확인한 결과 `behindText` 이미지가 2개 존재한다.

| 항목 | wrap | bbox | 비고 |
|------|------|------|------|
| 로고 | `behindText` | `x=65.493, y=49.013, w=77.013, h=87.893` | 상단 학교 로고 |
| 워터마크 | `behindText` | `x=137.707, y=270.24, w=495.04, h=495.733` | 고려대 마크, watermark preset |

25% 줌에서는 워터마크 폭이 약 124px로 줄어야 하지만, 현재는 약 495px 수준으로 남아 페이지 밖 회색 배경에 노출된다.

## 4. 결함 후보

### 후보 A — overlay bbox에 zoom 미적용

`rhwp-studio/src/view/page-renderer.ts`의 `applyOverlays()`는 `scale = zoom * dpr` 값을 `dpr`처럼 사용한다.

현재 구조:

```ts
const dpr = scale;
const cssWidth = canvas.width / dpr;
```

이 계산은 `canvas.width = pageWidth * zoom * dpr`일 때 `pageWidth`로 돌아가므로, overlay layer가 줌된 페이지 크기(`pageWidth * zoom`)가 아니라 원본 페이지 크기로 잡힌다.

또한 `createOverlayLayer()`는 `img.bbox.x/y/width/height`를 그대로 CSS px에 넣는다. 결과적으로 overlay 이미지는 줌 배율을 따르지 않는다.

### 후보 B — 지연 재렌더가 layer filter를 깨뜨림

초기 렌더는 `renderPageToCanvasFiltered(pageIdx, canvas, scale, 'flow')`로 BehindText/InFrontOfText 그림을 본문 canvas에서 제외한다.

하지만 `scheduleReRender()`는 200ms/600ms 뒤 `renderPageToCanvas(pageIdx, canvas, scale)`를 호출한다. 이 호출은 필터 없는 전체 렌더이므로 BehindText 그림이 canvas 안에도 다시 들어갈 수 있다.

### 후보 C — overlay page clipping 부재

overlay layer가 페이지 경계 기준으로 clip되지 않으면, 좌표/크기 계산이 어긋나는 순간 회색 작업 영역으로 이미지가 노출된다. 줌 계산을 고친 뒤에도 페이지 경계 기준 `overflow: hidden`을 적용해 회귀를 줄여야 한다.

## 5. 수정 방향

1. `CanvasView.renderPage()`에서 `zoom`, 실제 `dpr`, `renderScale`의 책임을 분리해 `PageRenderer`에 전달한다.
2. overlay layer의 표시 크기를 `pageSize * zoom` 기준으로 맞춘다.
3. overlay 이미지 bbox에 `zoom`을 곱하거나, 페이지 좌표계 wrapper에 `transform: scale(zoom)`을 적용한다.
4. overlay layer에 페이지 경계 기준 clipping을 적용한다.
5. `scheduleReRender()`의 지연 렌더도 `flow` 필터를 유지하게 바꾼다.
6. 필요 시 테스트/검증용 e2e 또는 렌더링 회귀 가드를 추가한다.

## 6. 수용 기준

1. `samples/복학원서.hwp` 25% 줌에서 고려대 워터마크가 페이지 안에서 약 124px 수준으로 축소되어 보인다.
2. 회색 작업 영역에 원본 크기 워터마크가 노출되지 않는다.
3. 85%/100% 줌에서 문서 내용상 BehindText 워터마크는 사라지지 않는다.
4. 지연 재렌더 후에도 BehindText/InFrontOfText 분리 렌더링이 유지된다.
5. `npm run build` 또는 TypeScript 빌드가 통과한다.
6. rhwp-studio 브라우저 검증에서 줌 변경 전후 DOM 크기와 스크린샷이 수용 기준에 부합한다.

## 8. 검증 계획

1. `samples/복학원서.hwp` PageLayerTree의 overlay bbox를 재확인한다.
2. rhwp-studio dev 서버에서 문서를 로드하고 100%/85%/25% 줌을 비교한다.
3. DOM에서 page canvas와 overlay layer의 `width/height/top/left`, overlay image bbox를 측정한다.
4. 25% 줌에서 overlay 이미지 폭이 원본 495px이 아니라 약 124px인지 확인한다.
5. 지연 재렌더 후 canvas가 `flow` 필터를 유지하는지 스크린샷/DOM으로 확인한다.
6. `npm run build`를 실행한다.
7. 변경 범위가 TypeScript UI 렌더링에 한정되므로 cargo 전체 테스트는 필요 시 보조 검증으로 수행한다.
