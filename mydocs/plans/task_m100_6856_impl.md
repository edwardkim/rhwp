## 1. 변경 이유와 완료 목표

메인테이너는 최소 수정의 5쪽 시각 판정을 통과시켰다. 그러나 일반 도형의 선을 지우던 B 분기를
제거한 것만으로는 글상자 구조 보존과 렌더러의 내용 의존적인 선 억제 문제까지 해결되지 않는다.

후속 #6856의 목표는 **원본의 컨트롤 구조를 파서에서 공통 IR로 보존하고, 조판은 그 구조와 명시된 선 속성을
소비하도록 만드는 것**이다. 글자 유무·채우기 색·선 굵기를 조합해 글상자나 비인쇄 도형을 추정하지 않는다.
이미 수용된 5쪽 선 복원은 유지하며, 이를 별도 대규모 도형 엔진 개편으로 확대하지 않는다.

## 2. 확인된 사실과 아직 확인할 사항

| 영역 | 현재 확인된 사실 | 이번 처리 |

| 렌더러 | A 조건에 `textbox_has_visible_text()`가 남아 선 억제 여부에 내용이 관여 | 원래 도입 문서의 증거를 확인하고 내용 의존 억제 제거 |

HWP의 문단 목록 검사는 문자열 검사와 다르다. 그림 컨트롤만 든 문단도 목록에 남을 수 있으므로,
현재 모든 이미지 전용 글상자가 일반 도형으로 오분류된다고 단정하지 않는다.
반대로 원본에 글상자 구조가 있지만 추출 문단이 없는 경우의 구조 손실은 별도로 시험해야 한다.
유효한 빈 구조와 손상되어 읽지 못한 구조를 같은 정상 입력으로 취급하지 않는다.

근거 문서는 [공통 IR 경계](../tech/parser_architecture.md)와
[HWP 5.0 스펙](../tech/한글문서파일형식_5.0_revision1.3.md)의 표 67·81·86·87·89·90·93·94다.

## 3. 구현 계약

### 3.1 기하·내부 구조·선 스타일의 분리

1. `Rectangle`은 사각형 기하를 나타낸다. `match shape` 자체를 제거하는 것이 목표가 아니다.
2. 해당 도형에 속한 글상자 구조의 존재는 파서에서 확정한다. 내부 글자 수나 그림 수는 판별 근거가 아니다.
3. 선 유무·종류·굵기·색은 원본 선 속성에서 가져온다. 글상자라는 사실만으로 선을 지우지 않는다.

기존 `Option<TextBox>`를 구조의 단일 저장 근거로 유지하고, 모델에 공통 구조 질의를 둔다.
호출자가 일반 도형과 글상자를 명시적으로 구분하도록 참조를 포함한 타입화된 결과를 사용하는 방향이다.
별도 저장 boolean이나 중복 enum 필드를 추가해 `text_box`와 불일치하는 상태를 만들지 않는다.
정확한 타입명은 구현 때 기존 모델 명명법에 맞춘다. 공개 직렬화 필드나 API 스키마 변경은 목표가 아니다.

| 원본의 소유 구조 | IR 계약 | 선 처리 계약 |
| --- | --- | --- |
| 글상자 구조 없음 | 일반 그리기 객체, `None` | 원본 선 속성 사용 |
| 글상자 구조 있음, 글자 없음 | 글상자, `Some(TextBox)` | 비어 있다는 이유로 선 변경 금지 |
| 글상자 구조 있음, 그림만 있음 | 글상자, 그림을 포함한 문단·컨트롤 보존 | 그림만 있다는 이유로 선 변경 금지 |
| 글상자 구조 있음, 글자 또는 글자·그림 혼합 | 글상자, 내용 보존 | 글자가 있다는 이유로 선 변경 금지 |

위 모든 경우에 명시적 ‘선 없음’은 유지한다. ‘실선 복구’를 모든 객체에 실선을 강제하는 처리로 만들지 않는다.

### 3.2 파서의 책임

- HWP의 LIST_HEADER가 **현재 도형의 글상자 소유인지** 레코드 계층과 범위로 확인한다.
  캡션·표·중첩 그룹 자식의 리스트를 현재 도형의 글상자로 가져오지 않는다.
- 일반 도형과 그룹 자식 경로에서 동일한 구조 계약을 적용한다. 기존 인라인 글상자 속성 경로도
  도달 가능성과 소유 관계를 확인한다. 단순히 `LIST_HEADER`를 발견하면 `Some`으로 바꾸지 않는다.
- 유효한 소유 구조는 내용과 독립적으로 보존한다. 레코드 부족·손상 처리는 기존 오류 정책을 유지하며,
  실패한 파싱을 정상 빈 글상자로 위장하지 않는다.
- HWPX의 `drawText`·`subList`와 HWP 레코드 차이는 파서 내부에서 처리한다.
  렌더러에 원본 태그·파일 버전·파일명 분기를 넘기지 않는다.

### 3.3 A 경험적 선 억제의 처리

기존 A는 텍스트가 있는 무채움 그룹 글상자의 얇은 검정 실선을 지운다. 이는 글상자 구조 판별도,
공식 비인쇄 규칙도 아니다. 이번에는 이 휴리스틱을 IR로 옮겨 이름만 바꾸는 방식도 채택하지 않는다.

먼저 #1681의 원래 편람 사례에서 A가 실제 실행되는 객체를 찾고, 원본 선 속성·수정 전후 SVG·
사용 가능한 한컴 정답지를 대조한다. 기존 편람 전체 SVG가 최소 수정 전후 동일했다는 결과는
A 자체의 정당성을 증명하지 않는다. 이미 가진 자료를 우선 사용하며 전수 코퍼스 재계측은 하지 않는다.

- 구현 방향은 A와 가시 텍스트에 의존하는 선 억제 제거다.
- 원본에 별도의 유효한 선 표시 속성이 확인되면 그 의미를 파서/IR에 보존해 공통 스타일 처리에서 소비한다.
  스펙이나 실제 구조의 증거 없이 `nonPrinting` 같은 속성을 신설하지 않는다.
- 제거가 원래 사례와 충돌하고 원본 근거를 확정하지 못하면 해당 차이와 미확정 원인을 보고한다.
  색·내용 기반의 대체 조건을 추가하거나 한컴 정답지를 임의 수정하지 않는다. 새 정책은 재승인을 받는다.

## 5. 세 작업 묶음과 검증 순서

### R1 — 구조 계약과 재현 시험

- 기존 공개 샘플·원래 편람·현재 두 원본을 우선 조사해 구조별 대표 객체를 확보한다.
- 일반/그룹 경로의 파싱 전 구조 → IR → 저장 → 재파싱 결과를 대조한다.
- 구조 소유권, 빈 글상자, 이미지 전용 글상자, 명시적 선 없음의 시험을 먼저 추가한다.
  기존 시험에서 A 보존을 요구한 항목은 역사적 관측 시험임을 표시하고 변경할 계약을 설명한다.
- 이 묶음의 산출물은 정확한 손실 지점, 원래 A의 적용 객체, 수정 전 실패 또는 보존 결과다.
  수정 전부터 통과한 계약을 버그 재현이라고 보고하지 않는다.

### R2 — 파서/IR 보존과 렌더러 정정

- R1로 확인한 구조 손실을 고치고 공통 구조 질의를 적용한다. 선 속성을 구조 분류와 분리한다.
- A를 정정하고 focused 시험을 통과시킨다. 기존 기대값을 조용히 바꾸지 않고 계약 변경 이유를 남긴다.
- 같은 글상자의 내용을 빈 상태·그림만·글자만·혼합으로 바꿔도 동일한 선 속성을 소비하는지 검사한다.
- 내부 계약용 변형은 메모리 내 시험으로 한정한다. 인위적으로 변형한 파일을 한컴 정답지로 제시하지 않는다.
- 현재 원본 5쪽, 1·7쪽 배치와 그림자, 원래 A 사례를 비교해 `output/6856/` 아래 SVG를 제시한다.
  기존 5쪽 승인은 보존하되 새 코드의 출력에도 재확인이 필요하다.

### R3 — 전체 검증·최종 보고

- 변경 범위가 고정된 뒤 전체 검증을 한 번 모아 수행한다. 실패 시 관련 수정과 필요한 재검증을 한다.
- `AGENTS.md`의 Rust lint 묶음을 **순차** 통과시키고,
  [local_validation 4.3](../manual/pr_review/local_validation.md)의 release-test 전체·Native Skia 3종을 수행한다.
- 신규 HWPX의 4.3.1 래칫·보안 검사를 적용한다. 기존 비영 계측값은 원인 비교 없이 완화하지 않는다.
- Docker 최적화 WASM을 빌드해 Studio에 준비한다. 현재 Studio의 이전 WASM을 새 구현 증거로 쓰지 않는다.
- focused·전체 시험, 구조/그림 보존, 선 복원, 한컴 대조, 미확정 사항을 구분한 최종 보고서를 제출한다.

review worktree에서 준비하고 source PR에 포함하지 않는다. 실제 한컴 대조용 대표 입력이 부족하면
기존 자료로 입증한 범위와 부족한 구조를 특정해 메인테이너에게 요청한다.

## 6. 보호 불변식과 완료 조건

1. 일반 도형은 글상자 전용 처리로 진입하지 않고, 글상자는 내용이 비거나 그림만 있어도 구조를 유지한다.
2. 파싱·저장·재파싱에서 글상자 소유 관계, 내부 그림 참조, 선 속성이 보존된다.
3. 명시적 실선과 ‘선 없음’은 내용 유무에 의해 바뀌지 않는다.
4. 수용된 5쪽 앞쪽 실선·뒤쪽 그림자와 기존 1·7쪽 배치를 보존한다. 다른 출력 변화는 이유와 증거를 제시한다.
5. 원래 A 사례의 정합을 별도로 판정한다. 근거 없는 억제를 남긴 채 구조 개선 전체 완료로 보고하지 않는다.
6. 새 조건을 renderer에 누적하거나 외형 휴리스틱을 IR로 옮겨 문제를 숨기지 않는다.

현재 승인된 행위는 #6852에서의 범위 분리와 별도 이슈 등록이다. 위 구현은 아직 승인·착수하지 않았다.
착수 시 최신 상태로 계획을 재검토하고 승인받는다. 단계 변경 전 변경분을 커밋하고 결과를 보고하는
기존 승인 절차를 따른다. push, PR 생성, merge, close는 각각 승인받는다.

## 7. 용어

- **IR (Intermediate Representation, 중간 표현)**: 포맷별 파싱 결과를 조판·편집이 공통으로 사용하는 모델.
- **구조 소유권**: 리스트나 문단이 어느 도형·캡션·표에 속하는지 레코드 계층/XML 중첩으로 정하는 관계.
- **기하**: 사각형·타원 등의 외곽 형태. 내부 글상자 구조나 글자의 존재와 별개다.
- **라운드트립(round trip)**: 읽은 문서를 저장한 뒤 다시 읽어 의미·구조의 보존을 확인하는 검사.
- **A/B**: #1681에서 도입된 경험적 선 억제의 두 분기. A는 글상자, B는 일반 흰 사각형에 적용됐던 조건이다.
- **보호 불변식**: 이번 수정 중에도 깨져서는 안 되는 구조·출력 계약.
