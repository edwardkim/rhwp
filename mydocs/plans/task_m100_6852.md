## 1. 앞선 작업의 정정과 이번 목표

앞선 `task_m100_6852@07188b9f7`의 API·UI 확장은 원본의 실선 렌더 누락을 해결하지 못했다.
그 브랜치에 구현·계획·보고서를 보존하고 **이번 브랜치에는 가져오지 않는다**.
‘기존 SVG와 동일’은 결함까지 유지했다는 뜻이며 본 이슈의 해결 근거로 사용하지 않는다.
기존 테스트 통과 기록도 재착수 구현의 검증 결과로 재사용하지 않는다.

이번 수용 대상은 원본 5쪽 ‘기존 선발 방식의 문제점’ 앞 작은 묶음이다.
앞쪽 흰 사각형에 명시된 검정 실선을 실제로 그려 위·왼쪽 선 누락을 해결하고,
뒤쪽 그림자 사각형과 도형 배치·치수·변환을 보존한다.
그룹 선 조회·일괄 편집·혼합값 UI 등은 이번 재착수 범위에 포함하지 않는다.

현재 GitHub 이슈 본문은 앞선 API 바인딩 진단을 담고 있어 이번 범위와 다르다.
수정 계획 승인 뒤 별도 원격 게시 승인을 받아 본문·수용 조건을 정정한다.
이 불일치를 남겨 둔 채 이슈 전체 해결 또는 close를 선언하지 않는다.

### 원인 계보와 남은 증명

`should_suppress_group_child_construction_stroke`는 `c279f7d93c0`에서 추가됐다.
원 PR [#1681](https://github.com/edwardkim/rhwp/pull/1681)의 `7f9a10263908`을 체리픽했고,
통합 PR [#1704](https://github.com/edwardkim/rhwp/pull/1704)로 반영됐다.
주석은 편람의 글상자 보조선 억제를 목적으로 설명하지만 실제 함수는 다음 두 대상을 처리한다.

1. A: 눈에 보이는 텍스트가 있고 채우기가 없는 글상자.
2. B: **글상자가 없고 흰색 단색으로 채운 일반 도형**.

공통 조건은 캡션 없음, 그룹 소속, 회전·전단 없음, 검정 실선, 굵기 `0 < width <= 40`이다.
Rectangle 처리에서 true이면 선 색상을 `None`, 선 굵기를 `0`으로 만든다.
현재 증거는 B의 오탐을 가리킨다. 수정 전 RED와 B 제거 후 GREEN으로 인과를 최종 고정한다.
[당시 검토 기록](../pr/archives/pr_1681_review.md)은 재조판·라운드트립 검증을 담지만,
일반 흰 사각형 선 보존의 독립 검증은 명시하지 않는다. 테스트 부재와 모든 검증 부재는 구분한다.

## 3. 최소 수정안과 보호 범위

- 메인테이너 추가 지시(2026-09-08): **글상자와 일반 그리기 객체의 처리 경계를 엄격히 구분한다.**
  `Rectangle`은 기하 종류이고 `text_box`는 내부 텍스트 구조다. 모델에 배타적인 새 개체 종류를
  만들지 않고, 렌더링 보정의 진입 경계에서 이 구조를 먼저 판정한다.

| 구조 | 분류 | 이번 선 처리 계약 |
| --- | --- | --- |
| `text_box: None` | 일반 그리기 객체 | 글상자 보정 경로에 진입하지 않음. 원본 선 스타일 사용 |
| `text_box: Some`, 내용이 비거나 공백뿐 | 빈 글상자 | 일반 도형으로 재분류하지 않음. 기존 A의 텍스트 조건에 해당하지 않으므로 억제하지 않음 |
| `text_box: Some`, 가시 텍스트 있음 | 텍스트가 있는 글상자 | 글상자 전용 경로에서만 기존 A의 나머지 조건을 평가 |

- **B 분기를 제거**하고, `text_box`가 없으면 보정 대상에서 즉시 제외되는 구조를 명시한다.
  글상자 전용 판정은 확인된 `TextBox` 참조를 사용한다. 색·선 굵기·그룹 여부로 일반 도형을
  글상자나 마스크로 추정하는 우회 경로를 두지 않는다.
- 분류와 비인쇄 판정은 별개다. `Some(TextBox)`라는 이유만으로 선을 지우지 않는다.
- 함수 이름·주석은 실제로 남는 글상자 대상에 맞게 고친다. ‘모든 그룹 도형’ 또는 ‘HWPX 전용’으로
  오해하게 두지 않는다. HWP/HWPX 버전·파일명·색상별 예외를 새로 추가하지 않는다.
- A는 정당성이 증명됐다는 뜻이 아니라 이번에 동작을 바꾸지 않는 경계로 유지한다.
  텍스트가 있다고 비인쇄라는 가정을 새 계약으로 정당화하지 않는다.
- 모델·파서·그룹 API·Studio UI를 변경하지 않는다. 그리기 순서·그림자 스타일·좌표·행렬을 보존한다.
- 사각형의 명시적 ‘선 없음’은 계속 선 없음이어야 한다. 선을 강제로 실선으로 덮어쓰지 않는다.
- 기존 편람에서 B에 걸리던 도형의 변화는 별도 비교해 보고한다. 해당 변화의 한컴 정답지 판정이
  불분명하면 추측으로 PASS 처리하거나 새 억제 조건을 만들지 않고 메인테이너에게 제시한다.

## 4. 수행 순서와 승인 경계

### Stage 1 — 조사·수정 계획 (완료)

위 원인 계보, 실제 HWPX XML, 공식 스펙, baseline 재현을 근거로 이 계획을 승인받는다.
기존 조사를 다시 전수 수행하지 않는다. 승인 후 현재 계획·추가 샘플을 단계 커밋으로 보존한다.

### Stage 2 — 최소 수정·5쪽 우선 수용

1. 별도 review worktree에서 baseline 제품과 새 fixture를 준비하고,
   `tests/cases/`에 실제 HWP/HWPX의 해당 도형 선 존재를 검사하는 공개 API 회귀를 추가한다.
   수정 전 실패를 확인한 뒤 B 분기를 제거한다. source 본문에 새 회귀를 넣지 않는다.
2. 수정 후 두 문서의 실선·그림자·좌표를 검사한다. 같은 기하·선 스타일에서 `None`, 빈/공백
   `Some`, 가시 텍스트 `Some`의 세 경계를 시험한다. 일반 도형은 흰색·투명 채우기 및 그룹 소속에도
   글상자 보정으로 선을 잃지 않아야 한다. 명시적 선 없음은 보존한다. 내부 계약용 변형은
   한컴 정답지로 제시하지 않으며 A의 관측 동작 보호와 포맷상 정당성 증명을 구분한다.
3. 기존 편람의 영향 도형을 식별해 수정 전후 스타일·출력 차이를 기록한다.
   원본 11쪽 및 1쪽·7쪽 배치 불변과 구분해 판정한다.
4. 수정한 코드의 CLI로 **5쪽 SVG를 먼저** `output/6852/restart/` 아래 내보내 메인테이너에게 제시한다.
   전체 페이지 SVG byte 동일성을 목표로 삼지 않는다. 선 복원으로 필요한 차이는 발생해야 한다.
5. 결과 보고 후, 시각 판정과 광범위 검증 승인을 받는다. 실패하면 원인을 수정하며
   API·UI 확장이나 다른 조판 문제로 작업 범위를 넓히지 않는다.

### Stage 3 — 최종 검증·보고·통합 준비

- 승인된 focused 수정 뒤에만 `AGENTS.md` Rust lint 묶음과 release-test 전체,
  [local_validation 4.3](../manual/pr_review/local_validation.md)의 Native Skia 3종을 수행한다.
- 새 HWPX는 같은 매뉴얼 4.3.1의 여섯 래칫 적용 범위를 확인하고, 신규 sample 보안 검사에
  실제 파일 경로를 전달한다. 신규 비영 계측값은 수정 전 같은 파일과 대조하며 무조건 baseline으로
  수용하지 않는다. 기존 실패를 숨기는 원장 완화는 하지 않는다.
- Docker 최적화 WASM을 빌드하여 Studio에서도 실제 선 복원을 확인한다.
- 최종 보고서에는 대상 선의 복원, 그림자·배치 보존, 편람 영향, 남겨 둔 A의 검증 한계를 구분한다.
- 원격 push·이슈 본문 정정·PR 생성·merge·close는 각 승인 경계를 지킨다.
  source PR에는 검증용 generated suite·manifest·Cargo 파생물을 넣지 않는다.
