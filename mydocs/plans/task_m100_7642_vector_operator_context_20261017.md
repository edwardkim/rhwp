# #7642 벡터 뒤 명시적 간격과 정체 글자의 공통 전진

## 원인과 독립 근거

고정 devel 대비 11월 9쪽의 작은 하락은 머리말이 아니라 글상자 안 벡터 식에
집중한다. 같은 raw 마스크의 위치와 실제 SVG/PDF의 글리프 원점을 대조했다.
첫 AC의 글자 원점은 맞지만 등호부터 약 2.52px, 다음 AD 뒤 더하기부터 추가
간격과 정체 D의 전진 차이가 누적된다. 이 값들을 문서 좌표 보정으로 쓰지 않는다.

두 face·6/9/12/18pt·12종의 정상 저장/Print 96식을 새로 만들었다. Save job은
`af38a491-02b6-42bd-b643-f71c0c53358a`, Print job은
`9ecc52f7-548a-4842-a0ea-492bd626f1f3`이며 한컴 13.0.0.3901의 PrintMethod=0이다.
원본 XML 입력과 정상 저장본, 독립 12쪽 PDF를 구분해 보존한다. 실제 glyph
원점과 정상 저장 속성은 ignored stage2241에 있다.

붙은 `vec{rm AC it}=2`는 앞 장식의 끝 여유를 재사용한다. 명시적 얇은/normal
공간을 넣으면 그 공간과 등호의 앞 간격이 별도로 남는다. 현재
`before_operator_gap`은 인접하지 않은 경우에도 장식의 여유를 재사용해 앞
연산자 간격을 지운다. 분수 뒤 명시적 공간도 같은 경계로 대조했다.

HyhwpEQ의 정체 D는 9pt에서 기존의 독립 GDI 전진 표가 9를 게시하지만
`hancom_glyphs::measure`는 hmtx 비율을 반올림해 8을 게시한다. 실제 Print의
AD 뒤 M 원점은 앞의 독립 전진 표와 맞는다. HancomEQN은 이미 별도 GDI 표를
소비하므로 반례로 유지한다. 같은 원본 face의 측정과 실제 GlyphRun이 서로
다른 전진을 갖는 가정을 제거한다.

## 수정과 검증

- 장식·분수의 자동 여유 재사용은 실제로 인접한 경계에서만 수행한다. 명시적
  공간을 제거하거나 자동 여유에 합치지 않는다. 여는 괄호/인접 연산자의 다른
  문맥 규칙은 그대로 유지한다.
- HyhwpEQ 정체 ASCII GlyphRun도 기존 독립 정체 전진 helper를 소비한다.
  미측정 크기는 기존 fallback을 유지하고 HancomEQN·이탤릭·다른 face는 바꾸지 않는다.
- `토큰/명시적 공간 → Row 경계의 인접 상태 → GlyphRun 전진/positions →
  장식·연산자 배치 → 공통 painter`를 같은 입력에서 확인한다. x 좌표 clamp,
  특정 문서·색상·글자 크기의 예외는 추가하지 않는다.
- 원래 11월 9쪽과 96식, 논리 기호/항 경계 대조군을 함께 Native/fresh WASM으로
  재검증한다. 이전 source의 Native는 그 source로 보존한다. 큰 WASM 빌드 전에
  Native 경계와 실제 확대 판독을 확인하고 새 source에서 필수 gate를 수행한다.
- 전쪽 90%와 직접 판독 뒤 새 이름의 정식 회귀를 추가한다. 같은 핵심 동작의
  완료 페이지 중 양쪽 100→99→98% 순으로 독립 ±2px 핀을 선정하고 관계도 유지한다.
