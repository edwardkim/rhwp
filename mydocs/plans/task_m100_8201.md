## 현상과 원인

`samples/issue8201/seal-delegation-form.hwp`(인감증명법 시행령 별지 제13호서식) 1쪽 동의 칸
`인감 \u{F012B} 또는 서명` 줄에서 rhwp는 기호를 `(인)` 세 글자로 그린다. 기호 하나가 약
17.3px를 차지해 같은 줄 끝 `명`이 셀 clip 오른쪽 경계(612.72px)에 닿는다.

원인 계층은 표시 투영이다. `src/renderer/hancom_pua.rs`의 `(0xF012B, "(인)")`가 1글자를
3글자로 확장하고, 측정(`effective_text_for_metrics`)과 paint(`expand_pua_render_text`)가 모두
이 결과를 소비한다. 둘은 서로 일관되지만 한컴 출력과 다르다. 파서·레이아웃 계층의 결함이 아니다.

## 독립 기준

| 근거 | 관측 |
| --- | --- |
| `samples/issue8201/seal-delegation-form-2020.pdf` (law.go.kr 공개, Hwp 2020) | 기호 = 내장 Haansoft Batang GID 3, `/W` 1000/1000 = 1em. 전진 57 device unit ≈ 같은 줄 한글 58 unit |
| 같은 문단 글자모양(charPr 49) | 10pt, 장평 100, 자간 −31%(symbol·user 슬롯 포함) → 한글과 기호 모두 0.69em 전진 |
| `pdf/복학원서-2022.pdf` (Hwp 2022) | 서명란 같은 자리에 같은 GID 3 글리프. `(인)`이 아니라 타원 안 '인' 한 글자 |
| 두 PDF의 내장 GID 3 윤곽 경계(UPM 1024) | 바깥 타원 (50,−76)–(979,842), 안쪽 타원 (77,−50)–(952,817), 안쪽 '인' (181,34)–(801,757). 두 출력에서 동일 |
| 6개 독립 한컴 PDF의 Haansoft Batang 일반 '인'(U+C778) | 경계 (116,−69)–(912,842), 전진 1024. 2010·2020·2024 출력에서 동일 |

seal 안쪽 '인'은 일반 '인'의 투영 사본이다. 각 획의 점 개수가 같고(33/32, 16/16, 45/45,
28/28) 경계 투영 오차는 최대 32 unit(13.3px 글자에서 약 0.4px)이다. 바깥 테두리는 on-curve 점의
타원 잔차가 최대 2%인 타원이다. 이는 #6127/#7642의 네모 숫자 메트릭
(`assets/fonts/boxed-digit-metrics.json`, 같은 UPM 1024의 frame + source→target 투영)과 같은 모델이다.

**#937의 기대값 재검토.** [PR #947](https://github.com/edwardkim/rhwp/pull/947)은 복학원서 서명란을
`(인)`으로 고정했다(`tests/issue_937.rs`, `tests/issue_948.rs`, golden
`tests/golden_svg/issue-677/bokhakwonseo-page1.svg`). 같은 문서의 한컴 PDF는 타원 안 '인' 한 글자다.
따라서 이 검사들은 독립 기준과 맞지 않는 기대값을 고정했다. 수정 전 복학원서 1쪽 Native 실루엣은
95.40706%로 90% 이상이므로 [기대값 재검토](../manual/pr_review/visual_fixture_evidence.md#기존-회귀-테스트의-기대값-재검토)
절차로 교정한다.

## 범위

| 구분 | 이번 범위 |
| --- | --- |
| 평문 U+F012B (HWPX 평면 15, HWP5 `0xA12B`, HWP3 johab `0x2BCE`) | 1em 전진(자간·장평은 일반 경로) + 타원 테두리와 안쪽 '인' 합성 |
| 출력 경로 | SVG, Canvas2D(WebCanvas), Native Skia, CanvasKit(Studio) |
| 실제 공급 원 PUA 글꼴 | 기존 우선순위 유지 — 원 glyph가 있으면 합성하지 않는다 |
| 텍스트 추출·검색 표면 | 종전 `(인)` 유지 |
| 글자겹침(CharOverlap) 안의 F012B | 종전 동작 유지(독립 근거 없음) |
| HTML DOM 렌더러 | 네모 숫자와 같은 원문 유지 계약(합성 없음) |
| HWP5 `0xA2B*` 네모 숫자 정규화 | 비범위(별도 결함 후보로 기록) |

## 적용하지 않아야 할 반례

- 인접 PUA(U+F012A, U+F012C)와 미등록 PUA는 합성하지 않는다.
- 실제 공급 원 프로그램(`native_pua_metrics`)이 F012B를 가지면 원 glyph를 쓴다.
- F012B가 접수증 TAC 채움줄의 날인선 판정(#4384)에 쓰이는 존재 검사는 그대로다.
- 네모 숫자의 기존 출력은 일반화 refactor 뒤에도 같아야 한다.
