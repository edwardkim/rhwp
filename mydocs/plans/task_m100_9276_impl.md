# #9276 Native 글꼴 처리와 direct PDF 검증 계획

Issue: #9276

1. Windows에서 같은 공고문으로 글꼴 환경 준비, 페이지 구성, Skia 글꼴 선택·그리기, PDF 닫기를 계측한다. 선택한 face와 collection index, 실제 사용 glyph ID와 PDF font stream을 대조한다. 원본 폰트 선택 순위를 보정한 `fcf2e11b17`, 설치 글리프 선택을 보강한 `7b1c7f21c3`, 웹폰트 공급을 추가한 [#8565](https://github.com/edwardkim/rhwp/pull/8565)와 대조한다.
2. 확인된 반복 작업을 그 값을 생산하는 공통 코드에서 줄인다. 같은 프로그램을 재사용할 때는 얼굴 번호와 style·variation·실제 글리프를 구분하고 사용자 공급 순서와 기존 메모리 한도를 지킨다. PDF에서 전체 프로그램으로 대체되는 이유를 실제 사용 글리프로 재현한다. 부분 임베딩이 허용된 경우 glyph ID 매핑, 윤곽·복합 글리프·전진폭과 ToUnicode를 함께 보존한다. 원본이 부분 임베딩을 금지하거나 안전하게 표현할 수 없는 글꼴에는 기존 보존 경로를 적용한다.
3. 동일 PC에서 기준과 수정본을 같은 빌드 조건으로 반복 실행해 세 원본별 경과 시간·CPU 시간·PDF 및 글꼴 바이트를 기록한다. 전쪽 PDF를 같은 도구로 래스터화하여 문자, 기호, 표, 쪽 나눔과 텍스트 추출을 비교하고 PNG 재생도 확인한다. 공고문·모집 안내문의 발행기관 PDF, 기존 직접 출력 그라데이션 및 글꼴 대조군을 함께 확인한다. 해당 코드 경로의 회귀·lint와 저장소의 변경 범위별 필수 검증까지 진행한다.
