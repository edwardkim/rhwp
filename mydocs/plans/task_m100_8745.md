# 암호 문서 보안 경고의 반복 원인 제거 계획

## 목표와 현재 상태

작업지시자는 암호 문서 해제 테스트 주변에서 반복되는 보안 경고의 처리를 요청했다.
기준은 `upstream/devel@e4ffabea38062e716f6c333cc950fa31b42b4dd7`이다.
2026-11-07 작업지시자가 “이슈로 등록한 후 구현을 진행하세요”로 이슈 등록과 구현을 승인했다.
[#8745](https://github.com/edwardkim/rhwp/issues/8745)를 등록하고 edwardkim에게 할당했다.
작업 브랜치는 `task/8745-password-document-security`다.

[조사 기록](../tech/investigations/issue-8745/README.md)에 실제 SARIF,
기존 해결 PR·보정 patch·검증 이력, 공개 타입의 Debug 노출 재현을 보존했다.
이 작업은 경고별 반복 dismiss를 줄이면서 실제 암호 유출 탐지를 유지하는 것이 목표다.

## 하나의 작업 단위

1. **실제 출력 경계 보강:** `service::OpenOptions`의 자동 Debug를 명시적 redaction으로 바꾸고
   일반·pretty·중첩 출력에서 합성 암호가 노출되지 않는 회귀를 추가한다. 현재 PDF 옵션과 Native
   command의 가림 규약을 재사용한다. 모든 메모리 복제의 zeroization을 보장하는 작업으로 확대하지 않는다.
2. **반복 source 경계 수정:** #6731의 command/query 분리를 Rust에서 먼저 작은 분석 실험으로
   검증한다. 암호를 소비하는 open command는 성공·실패를 표현하고, 완성 문서는 별도 조회·소유권
   이전 경로에서 취득하는 안을 우선한다. 성공 전 상태를 공개하지 않고 실패 시 기존 문서를 보존한다.
   Native host뿐 아니라 Core·서비스·CLI·WASM의 같은 반환 경계를 함께 대조한다.
3. **호환성과 출력 계약:** 기존 공개 constructor·WASM API는 호환 wrapper로 유지할 수 있는지
   확인한다. wrapper가 다시 같은 source를 만들면 미해결로 기록하고 구조를 재검토한다.
   암호 저장 결과와 CLI의 완료 정보도 분리해 #190을 함께 확인한다. CLI JSON 스키마·종료 코드와
   실제 문서 저장은 보존한다. 암호 값·본문·암호화 payload가 진단 출력으로 넘어가지 않게 한다.
4. **테스트 경고의 구분:** 16개 하드코딩 결과를 공개 벡터·테스트 암호·제품 작업 버퍼로 개별
   대조한다. 필요한 고정 벡터와 형식의 키 유도 규칙은 유지한다. 불필요한 명명·버퍼 패턴의 보정은
   실제 동작과 분석 효과를 함께 입증할 때만 반영한다. 테스트 경로 제외나 비밀처럼 보이지 않게
   상수를 인코딩하는 방식으로 처리하지 않는다.
5. **재발 방지와 검증:** 알려진 로그 marker 목록만 검사하는 기존 회귀를 넘어, 합성 암호의
   stdout·stderr·오류·Debug 비노출과 실제 열기·저장 계약을 함께 검사한다. 정상 실패 메시지와
   사용자 요청 문서 출력은 진단 채널과 구분한다. 전체 테스트·필수 lint·영향 표면 검증까지 한 단위로 끝낸다.

선호안이 Rust CodeQL에서 실패하면 같은 목적의 이름 변경·helper 추가를 반복하지 않는다.
실제 새 flow를 근거로 대안을 정리하고, 분석 설정·공개 API의 파괴적 변경이 필요하면 그 변경만
추가 결정 대상으로 올린다. Studio의 과거 성공을 Rust에서 이미 검증한 결과로 간주하지 않는다.

## 변경 제한

- 조판 계산, 글꼴 선택, 원본 문서 의미, 암호화 형식·알고리즘, 기존 페이지·baseline을 바꾸지 않는다.
- CodeQL query·language·path·severity·required check를 줄이거나 넓은 sanitizer를 추가하지 않는다.
- 기존 dismissed 경고를 재분류하거나 새로운 경고를 자동 dismiss하지 않는다.
- 기존 로그를 전부 삭제하지 않는다. 실제 출력 인자와 목적을 대조한 경계만 수정한다.
- 운영 암호·토큰은 사용하지 않는다. 기존 공개 fixture와 공개/합성 테스트 값만 사용한다.
- 열린 다른 작업 PR과 worktree는 보존한다.

## 검증과 완료 조건

| 검증 | 완료 조건 |
| --- | --- |
| 타입 출력 | 실제 `service::OpenOptions`의 Debug·pretty·중첩 출력에 암호가 없고 비밀이 아닌 옵션은 확인 가능 |
| 열기 | HWP3·HWP5·HWPX·지원 PDF의 정상 암호·오암호·암호 없음·일반 문서 동작 보존 |
| 실패·재시도 | 실패 시 이전 문서·세션 보존, 올바른 암호로 재시도 성공, 암호가 오류에 포함되지 않음 |
| 저장 | 기존 암호화/평문 Save As와 재열기, CLI JSON·종료 코드 계약 유지 |
| 분석 음성 대조 | 같은 CodeQL 2.27.4·query pack의 분석 전후에서 목표 반환값 기반 flow가 제거됨. check 색이나 dismissed 감소로 대체하지 않음 |
| 분석 양성 대조 | 격리된 합성 코드의 실제 암호 변수→로그, 하드코딩 운영 키가 계속 검출됨. 제품에 고의 취약 코드를 넣지 않음 |
| 남은 진단 | 16개 하드코딩 및 2개 형식 관련 결과를 개별 근거로 설명. 필요한 공개 벡터 보존과 미해결 실제 결함을 구분 |
| 제품 검증 | [로컬 검증 4.3](../manual/pr_review/local_validation.md#43-변경-범위별-기본-검증)의 전체 회귀·Native 해당 검사·Rust lint 묶음. 변경된 WASM/Studio 표면의 fresh WASM·브라우저 암호 열기·저장 검증 |
| 출력 보존 | 같은 공개 암호/평문 입력의 기존 경로와 후보 렌더·저장 결과 비교. 실제 조판 변경이 필요하면 시각 검증 규칙 적용 후 범위를 재판정 |

착수 당시 로컬 CodeQL 실행기가 없어 분석 도구 확보와 고정 버전 재현도 작업에 포함했다.
구현 중 로컬 분석으로 원인 제거를 확인한 후 제출 준비한다. 승인받아 PR을 연 뒤에는 실제 해당
PR merge ref의 SARIF로 최종 확인한다. 전체 저장소 기준 분석도 PR 제출 전 로컬에서 수행해
테스트 파일에서의 재발을 확인한다. 이를 GitHub protected branch full scan이라고 표시하지 않는다.

[GitHub 운영 규칙](../manual/github_operations.md)의 9.4에는 이슈 종료 전 protected branch full
scan 조건이 있다. 같은 문서의 병합 후 자동 실행 금지 정책에 따라 merge 뒤 검증 CI를 자동 실행하지
않으며, 필요한 독립 보안 분석의 실행·종료 판정은 PR 후속 승인 시 명시한다. 과거 #6731의
devel push 자동 분석 절차를 그대로 재사용하지 않는다.
