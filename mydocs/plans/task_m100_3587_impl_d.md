## 1. 메인테이너가 판단할 목표

**문서 A의 제목·표·글상자 묶음을 문서 B의 지정 문단 앞에 가져오고, B의 기존 내용과 용지 설정은 유지한다.**
같은 숫자의 글꼴·테두리·그림 번호라도 문서마다 의미가 다르므로, A의 실제 서식·자원을 B의 번호로
연결해야 한다. 가져온 블록은 C의 공개 채우기 API로 편집하고 HWP/HWPX로 저장할 수 있어야 한다.

단순 커서 붙여넣기, 문서 전체 합치기, 렌더러 간격 수정은 이번 D의 목적이 아니다.
기존 대화형 붙여넣기 동작은 보존한다. #7065·#7084·#7090 수정은 포함하지 않는다.

## 3. 요청·결과 계약

제안 core 연산: `import_paragraph_block_native(source: &Document, request)`.
요청은 `sourceSection`, `sourceStart`, `sourceEnd`, `targetSection`, `insertBefore`, `count`, `limits`다.
모든 인덱스는 호출 전 snapshot 기준이며 source는 불변 참조다. 목적지는 대상 문단 앞 경계 또는 구역 끝이다.

- 완전한 문단 범위 `[start,end)`만 허용한다. 원본에 포함된 빈 Enter는 보존하며 새 빈 문단은 만들지 않는다.
- source 문서의 구역/용지·머리말/꼬리말은 자동 가져오지 않는다. 선택 블록에 구역 전용 컨트롤이 있으면
  B의 strict 지원 검사로 거부한다. 원본의 첫 문단을 조용히 잘라내 성공시키지 않는다.
- 대상이 빈 문서라도 대상 용지 설정을 유지한다. 원본 설정까지 필요한 문서 생성은 원본을 열어 시작하는 기존 레시피다.
- `count=0`은 주소·옵션 검사 후 자원 추가·이벤트·캐시 변경 없는 no-op이다. A/B의 지원 범위는 넓히지 않는다.
- 결과에는 대상 구역/삽입 범위, 복사본별 상대→대상 경로, 서식·바이너리의 추가/재사용 수를 반환한다.
  source는 다른 문서이므로 같은 문서용 `sourceAfter`를 억지로 채우지 않는다.
- 복사본 개체 ID는 대상의 사용 중 ID 및 다른 복사본과 충돌하지 않아야 한다. 블록 내부 참조는 새 ID로,
  블록 밖 참조는 근거 없는 재연결 대신 기존 strict 정책에 따라 거부한다.
- 가져오기 후 내용 채우기는 반환 경로로 C 연산을 호출한다. 별도의 업무용 템플릿 언어는 추가하지 않는다.

## 4. 서식·자원 준비와 실패 원자성

1. 원본 범위·대상 경계·지원 컨트롤·소유 트리 및 양쪽 참조 예산을 검사한다.
2. 선택 블록에서 필요한 서식·바이너리의 도달 집합을 구한다. 미사용 source 자원 때문에 대상이 커지지 않아야 한다.
3. 목적 서식표의 기존 항목은 변경하지 않고 동일 의미는 재사용한다. 의존 참조를 매핑한 다음 값 비교한다.
   `next_style_id` 자기/상호 참조는 2단계 예약·연결로 처리한다. 순환 참조를 오류로 뭉뚱그리거나 기존 스타일을 고치지 않는다.
4. 그림·그림 채우기·지원되는 내장 글꼴은 참조 의미별로 해석한다. 동일 바이트와 호환 metadata의 자원은 재사용한다.
   해시만 같다는 이유로 다른 의미의 자원을 합치지 않는다. 외부 링크는 네트워크/로컬 경로를 자동으로 열지 않고 거부한다.
5. 대상에 넣지 않은 블록 사본에 서식/자원 참조와 A의 신원 매핑을 적용한다. HWP raw와 HWPX typed 참조를
   함께 검증하며, 모르는 raw 참조를 지우고 성공으로 보고하지 않는다.
6. 응답 직렬화·용량 확보 등 복구 가능한 실패를 commit 전 끝낸다. 준비된 서식·BinData·블록을 반영하고
   DocInfo raw dirty, BinData epoch, resolved styles, 문단 raw, 조판 캐시·이벤트를 한 경로에서 갱신한다.
7. 실패·dry-run에서는 양쪽 문서, 대상 DocInfo/BinData, clipboard·이벤트·batch 상태가 유지돼야 한다.
   원본 소유의 lazy byte cache가 읽기로 채워지는 것과 문서 의미 변경은 구별해 보고한다.

일반 OOM/프로세스 중단까지 rollback 보장이라고 표현하지 않는다. 목적 문서 전체를 무조건 clone하는
방법으로 원자성을 대체하지 않는다. 기존 대화형 paste의 허용 정책은 별도 wrapper에서 유지한다.

### 자원 상한 제안

B의 상한(1,000복제/10,000문단/100,000노드/깊이64/구조32MiB/대응표8MiB/문서순회1,000,000노드)을 유지한다.
추가로 요청당 **자원 metadata 준비 32MiB, 읽어 비교·가져오는 바이너리 합계 64MiB**를 hard ceiling으로 제안한다.
이 수치는 포맷 한도나 성능 측정 결과가 아니라 초기 운영 안전 한도이며 호출자는 낮출 수만 있다.

기존 단일 BinData 256MiB 한도를 그대로 합계 한도로 오인하지 않는다. 중복 비교에 읽은 바이트도 예산에 포함하고,
lazy 자원은 제한 해제 API를 사용한다. 제한 읽기를 보장하지 않는 resolver는 명시적으로 거부한다.
u8 스타일/u16 참조·storage ID 등의 저장 가능 범위를 checked conversion으로 사전 검사한다.

### D2의 공개 입력 경계

- WASM: 불변 source 문서 핸들 + options JSON을 받아 같은 core를 호출한다. JSON 안에 문서 바이트를 넣지 않는다.
- CLI: 단독 `import_paragraph_block` action에 source 파일과 SHA-256을 명시한다. 입력 파일을 한 번 읽은 바이트로
  지문 검사·파싱·실행한다. 기존 대상 파일 CAS 및 출력 실패 계약을 유지한다. dry-run은 파일을 쓰지 않는다.
- MCP: 기존 로컬 `hwp_run_plan` 경유. 새 서버/서비스·제품의 Gym 의존성은 추가하지 않는다.
- 가져오기→채우기 및 다중 영역은 결과 문서/반환 경로를 다음 호출에 명시적으로 전달하는 순차 레시피다.
  기존 단독 구조 action 제한을 몰래 없애지 않으며, 여러 호출 전체의 rollback까지 보장한다고 하지 않는다.
- 기존 C3 계약 누락 8건을 재발시키지 않도록 schema·property 생성기·provenance fixture·실물 레시피·raw 무효화
  경로·envelope 버전·지식지도 필드 사전을 기능 연결과 같은 묶음에서 갱신한다.

실제로 확인한다. 추가 실물 샘플은 필요한 구조가 없을 때만 요청한다. 합성 계약 입력은 한컴 시각 정답이 아니다.
