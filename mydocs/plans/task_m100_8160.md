## 기준 PDF와 선행 근거

새 MCP에서 세 입력을 각각 Print 0 / 1-up으로 재산출해 기존 PDF 경로를 교체했다.
입력/PDF SHA, job ID, 실제 한컴 빌드와 192쪽의 96 DPI raster 검증은
`mydocs/pr/assets/issue_8160/mcp-reference-refresh.json` 및 `pdf-pages-96dpi.jsonl`에 보존한다.
HWPX·2024 HWP는 engine 2024, 2022 HWP는 같은 새 MCP의 실제 HOffice110 engine 2020이다.
파일명·Creator만으로 출력 경로를 추정하지 않는다.

#7721·#7722·#7724·#7642의 원 해결 PR, 실제 통합/보정 commit과 독립 근거를 추적한다.
특히 기존 `verified_sample16_2024_print_boundaries.rs`는 기본 HWP5 이름을 읽으므로
이번 별도 `-2024.hwp` 입력과 같다고 가정하지 않는다. 새 기준 PDF에서 기존 관측값을 다시 측정한다.

## 단계와 완료 근거

1. **착수·baseline**: 최신 devel 고정, 실제 소스로 Native/fresh WASM을 빌드·동결한다.
   실제 글꼴·compat·print profile·96 DPI를 고정하고 세 문서 전쪽 TSV와 미대응 픽셀 수를 확보한다.
   페이지별 차이의 원인과 기존 정식 회귀의 실제 입력·보호 범위를 목록화한다.
2. **공통 원인 보정**: 중요한 미달/차이 영역부터 독립 PDF·확대 review/overlay를 읽고,
   값의 생산 → 측정 → 실제 배치 → paint 소비를 추적해 공통 조판·렌더링 규칙을 고친다.
   문서 ID·우연한 수치 보정, 입력 변경, 측정 조건·baseline·공차 완화로 점수를 맞추지 않는다.
   변경 경계와 정상 대조군을 먼저 실행하고 전쪽에서 개선·무회귀를 확인한다.
3. **전 페이지 회귀 보호**: 사용자 추가 지시에 따라 세 문서 모든 페이지의 Native/fresh WASM
   **384개 결과가 모두 raw 100%이고 미대응 픽셀이 0인 것을 먼저 확인한 뒤에만**
   회귀 테스트를 추가·변경한다. 정본의 90%·98% 최소 조건보다 강한 이번 작업의 순서다.
   각 쪽의 독립 기대 좌표·확대 판독도 확보한다.
   세 문서 모든 쪽의 중요 영역, 원본 소유 식별자, 독립 좌표, 검사명을 연결하고
   소유·순서·누락·중복·포함·비겹침을 함께 보호한다. 빈 쪽은 별도 의미 계약으로 검사한다.
   기존 검사별 입력·소유·경계·내용 보호 범위를 대조해 중복은 병합·제거하고 필요한 보호를 보존한다.
   사용자 추가 지시에 따라 기존의 잘못된 검사·기대값도 독립 원본/Print 근거로 수정하거나 제거한다.
   올바른 기대값의 실패는 구현을 고치며, 현재 출력을 그대로 기대값에 복사해 통과시키지 않는다.
   최종 전쪽 raw 100%와 미대응 픽셀 0을 확인하며 반올림된 표시값만으로 판정하지 않는다.
4. **최종 검증·PR**: 동일 최종 code head에서 Rust lint 묶음·workspace build·정책 검사,
   전체 nextest·Native Skia·최적화 fresh WASM, 전쪽 TSV·확대 판독과 영향 대조군을 완료한다.
   전쪽 raw 100%·정수 미대응 0과 필수 검증을 충족한 후보의 결과를 보고하고, 이미 받은
   조건부 승인에 따라 upstream 작업 브랜치에 push해 Open PR을 만든다. 정확한 code head CI를 확인한다.
   이후 PR review·오늘할일을 문서 trailing commit으로 반영하고 새 head의 필수 CI를 확인한다.
5. **머지·후속 처리**: 최신 head·mergeability·필수 검증을 대조해 머지한다.
   merge SHA·devel 포함, 문서/증적, 이슈·PR 후속 코멘트, 관련 workflow와 안전한 전용 branch 정리를
   `post_merge.md`에 따라 확인한다. PDF·TSV·대표 PNG는 SHA가 고정된 정식 증적으로 연결한다.
