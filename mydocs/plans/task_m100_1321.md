# 수행 계획서 — Task M100 #1321

## 개요

**이슈**: #1321 — #1298 후속 — HWPX 시리얼라이저: 빈 문단(text 없음)의 0-length field fieldEnd가 fieldBegin보다 먼저 방출됨  
**브랜치**: `local/task1321`  
**마일스톤**: M100

## 배경

#1298에서 0-length field range(`start_char_idx == end_char_idx`)의 fieldBegin/fieldEnd 인터리빙 오류를 수정했다. 수정 내용은 메인 문자 루프 내에 pre-char 검사를 추가하는 방식이었다.

그러나 **`para.text`가 완전히 비어있는 빈 문단** 케이스는 수정 대상에서 누락되었다. `#1298` 구현 계획서(task_m100_1298_impl.md)에도 "빈 문단(text == "") + 0-length 필드는 별도 이슈로 처리한다"고 명시되어 있다. 본 이슈 #1321이 그 후속 작업이다.

## 문제 요약

`src/serializer/hwpx/section.rs`의 `render_run_content` 함수에서, `para.text == ""`인 빈 문단에 0-length field가 있을 때 방출 순서가 역전된다.

### 실행 흐름 (버그 재현)

```
para.text = ""
para.field_ranges = [{ start: 0, end: 0, control_idx: 0 }]
para.controls = [Field { field_id: 55, ... }]
```

1. 메인 루프 `for (idx, c) in para.text.chars().enumerate()` → **0회 실행**  
   - `#1298`의 pre-char 0-length 검사도 함께 건너뜀
2. 루프 후 처리 (line 329~339): `!field_end_emitted[0]` → **`<hp:fieldEnd>` 방출** ← 먼저
3. 남은 slots 처리 (line 341~344): slot_idx=0 < slots.len()=1 → **`<hp:fieldBegin>` 방출** ← 나중

**결과**: `<hp:fieldEnd>` → `<hp:fieldBegin>` (순서 역전, HWPX 스펙 위반)

## 수행 범위

- `src/serializer/hwpx/section.rs` — `render_run_content` 함수 내 빈 문단 처리 추가
- 신규 단위 테스트 추가: `para.text == ""`인 빈 문단에 0-length field가 있는 케이스

## 수행 방법

루프 후 처리(line 329~339)와 남은 slots 처리(line 341~344)의 **순서 교체**가 가장 단순한 수정이지만, slots와 field_end의 상대 순서가 깨질 수 있어 위험하다.

안전한 방법: **메인 루프 진입 전에 빈 문단 전용 처리 블록 추가**

```rust
// 빈 문단(text == "")에서 0-length field: 루프가 실행되지 않아
// pre-char 검사를 통과하지 못하므로, 루프 전에 별도 처리
if para.text.is_empty() {
    for (i, fr) in para.field_ranges.iter().enumerate() {
        if fr.start_char_idx == fr.end_char_idx && !field_end_emitted[i] {
            // remaining slots에서 fieldBegin이 먼저 방출된 뒤
            // fieldEnd를 방출해야 하므로, 여기서는 emitted 플래그만 세팅하지 않고
            // → slots 방출 후 처리 순서를 재구성
        }
    }
}
```

실제 수정 전략은 구현 계획서에서 구체화한다.
