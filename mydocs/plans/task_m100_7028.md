## 1. 목표와 범위

여러 페이지에 걸친 표에서도 원본 셀의 대각선 테두리를 표시한다. 특히 제목 셀로 지정된
상단 행이 이후 페이지에 반복될 때, 기존 반복 조판 규칙과 해당 페이지의 표시 좌표에 맞게
대각선을 생성한다. 첫 페이지에만 선을 추가하거나 샘플별 조건으로 해결하지 않는다.

기존 페이지 분할·반복 제목행 선택은 보호 대상이다. 실제로 잘린 셀의 기하와 온전하게
복제되는 제목 셀의 기하를 구분한다. 일반 표 페이지네이션 전면 재설계, #3645 재개,
새로운 표 속성 UI 구현은 범위 밖이다.

## 2. 확인된 출발점

- 입력: `samples/task2146/21761835_jeonjik_exemption_table.hwp`.
- SHA-256: `d8e7e38b206f6e53b7d2d260115396f8a0dd94bd8b712bbc4428dc11bf66e5dc`.

  header flag `0x0004`, rowspan=1이다. 단순 UI 추정이 아니라 HWP 레코드 실측이다.
- r0c0 BF=13: attr `0x0040`, backslash bits=2, diagonal type=1(실선), 검정.
- 최신 native 조판 6쪽, 첫 페이지 pi=4 ci=0은 `partialTable`이며 r0c0 자체는 잘리지 않는다.

  없다. 첫 페이지 RenderTree/SVG에도 해당 선이 없다. 파서 속성 누락이나 Studio만의 문제는 아니다.
- `v0.8.6` 소스에서도 호출 누락을 확인했다. 최초 유입 시점과 과거 실행 결과는 미확정이다.
- #2146의 기존 회귀는 셀 높이만 검사하므로 선 누락을 검출하지 못한다.
- 기존 로컬 증적: `output/diagnostics/21761835-diagonal/README.md`, `pages.json`,
  `tree/render_tree_001.json`, `svg/21761835_jeonjik_exemption_table_001.svg`.
  CLI 페이지 옵션은 0-based; `_002`는 첫 페이지가 아닌 두 번째 페이지 보조 증적이다.

## 3. 현재 제목 셀 조판 규칙과 보호 불변식

`src/model/table.rs`의 `Table::leading_header_rows()`는 header 셀의 rowspan까지 반영해
표 상단에서 연속되는 제목행 블록만 선택한다. 중간에 흩어진 제목 셀을 모두 반복하지 않는다.
`typeset.rs`의 반복 높이 예약과 `table_partial.rs`의 표시 행 구성이 같은 함수를 사용한다.

분할 레이아웃은 continuation이고 repeat_header이며 start_row>0인 경우에만,
start_row보다 앞선 제목행을 본문 조각의 행 앞에 붙인다. 표시 행 순서로 y를 계산한다.
따라서 원본 행 번호를 그대로 페이지 y로 사용하는 구현은 허용하지 않는다.

보호할 값과 동작:

1. 제목행 선택 범위·반복 활성 조건·높이 예약과 실제 표시 높이의 일치.
2. 원본의 대각선 종류·방향·굵기·색. 선 없음은 선 없음으로 유지.
3. 일반 셀, 반복된 제목 셀, 실제로 잘린 셀을 구분한 좌표·clip·중복 방출 정책.
4. 기존 페이지 수·행 분할·셀 높이·본문 위치·가로/세로 테두리.
5. 영역(cell zone) 대각선과 셀 대각선의 기존 중복 억제, 중심선 및 세로쓰기 의미.

## 5. 검증 설계

- 실물: 현재 샘플의 첫·후속·마지막 페이지에서 제목 셀 인스턴스와 대각선 존재/끝점 검사.
  첫 셀 높이 약 52.4px 및 기존 6쪽 조판을 함께 보호한다.
- 대조군: 제목행 비반복, 일반 비분할 표, 대각선 없음, rowspan과 실제 분할 셀,
  셀/영역 대각선 중복 및 세로쓰기. 기존 테스트를 우선 재사용하고 필요한 최소 사례만 추가한다.
- 새 integration source는 `tests/cases/`에만 추가하며 generated suite·manifest는 PR에서 제외한다.
- Rust 변경 후 순차 fmt·native Clippy·WASM lib Clippy·workspace build·all-target Clippy와
  suite 정합성을 검증한다. 세부 명령은 AGENTS.md와 local_validation.md §4.3을 따른다.
- 최종 Docker WASM을 Studio에 제공하고 메인테이너가 한컴과 시각 판정한다.
  RenderTree/SVG 선 존재만으로 최종 시각 통과를 선언하지 않는다.

기존 PDF 후보는 `pdf/task2146/21761835_jeonjik_exemption_table-hwp-2020.pdf`다.
실제 메타데이터는 Hwp 2022 / Hancom PDF, 6쪽이다. 파일명으로 버전을 판정하지 않는다.
다른 `21761835_jeonjik_exemption_table-2020.pdf`는 cairo producer이므로 그 이름만으로
한컴 정답지로 채택하지 않는다. 기존 증적이 유효하면 새 PDF 변환·전수 계측을 반복하지 않는다.

## 6. 완료 요건

첫 페이지와 반복 제목 셀의 대각선이 한컴에 맞게 표시되고, 위 보호 불변식과 회귀 검사가
통과해야 한다. 실제 잘린 셀을 조각 크기에 맞춰 임의로 새 사선으로 바꾸지 않아야 한다.
완료 판정은 코드 연결 여부가 아니라 렌더 결과·회귀·메인테이너 시각 확인을 근거로 한다.
