## 2. 문제 정의

Linux/macOS 환경에 한컴 전용 폰트(HY헤드라인M, HY수평선B, 휴먼명조, HY울릉도M 등)가 미설치되어 있으므로, rhwp 는 메트릭 폴백(Noto Serif/Sans CJK KR, Pretendard 등)을 사용한다. 폴백 폰트의 글리프 폭/높이/베이스라인이 원본과 다르기 때문에:

1. 셀 안 텍스트 정렬 어긋남
2. 표 행 높이 누적 오차
3. PDF 시각 비교 RMSE 가 폰트 차이로 ~20%+ 가산되어, 본질적 레이아웃 결함을 가린다.

## 3. 현황 분석

### 3.1 현재 `resolve_metric_alias` (src/renderer/font_metrics_data.rs:83)

HY 계열 7종만 메트릭 별칭 등록되어 있다:
- HY중고딕 → HYGothic-Medium
- HY견고딕 → HYGothic-Extra
- HY헤드라인M → HYHeadLine-Medium
- HY견명조 → HYMyeongJo-Extra
- HY신명조 → HYSinMyeongJo-Medium
- HY그래픽 → HYGraphic-Medium
- HY궁서 → HYGungSo-Bold

**누락**: HY수평선B, HY울릉도M, HY백송B 등 다수. 휴먼명조 등 휴먼 계열은 별칭 없이 직접 DB 등록되어 있음 (font_metrics_data.rs:10280).

### 3.2 메트릭 DB 규모

폰트 메트릭 DB는 595 엔트리 (FONT_0 ~ FONT_594) 보유. HY/휴먼 계열 메트릭은 이미 다수 등록되어 있으나, 한국어 표시 이름(예: "HY수평선B")과 영문 패밀리명(예: "HYSuPyungSun-Bold") 간 별칭 매핑이 미흡한 것이 핵심 문제.

### 3.3 이슈 본문 3개 옵션

| 옵션 | 핵심 | 효과 | 비용 |
|------|------|------|------|
| 1) 폴백 메트릭 보정 | `resolve_metric_alias` 확장 + 누락 HY/한글 폰트 → 기존 DB 매핑 | 폰트 미설치 환경에서 폭/높이 근사 → 표 정렬·행 높이 개선 | 별칭 테이블 확장만, 코드 변경 최소 |
| 2) 자동 임베딩 | `--embed-fonts --font-path` 자동화 + OFL 호환 폰트 번들 | 오프라인 정확 렌더링 | OFL 호환 폰트 후보 조사·번들 사이즈 증가 |
| 3) RMSE 측정 마스크 | 시각 비교 시 폰트 차이 영역 가중치 보정 | 본질 결함 가시화 | 측정 메소드 개선 도구만, 런타임 영향 없음 |

## 4. 권장 접근

옵션 1 + 옵션 3 **병행**.

- **옵션 1 (런타임 개선)**: 이슈의 직접 목표인 "폴백 메트릭 보정"이며, `resolve_metric_alias` 확장만으로 즉시 효과. Memory rule `feedback_font_metrics_alias_sync`에 따라 메트릭 DB와 동기.
- **옵션 3 (검증 도구)**: 폰트 차이 RMSE 가산 문제는 측정 방법론 이슈. 별도 보조 도구로 본질 결함만 측정 가능.
- **옵션 2 (자동 임베딩)**: 라이선스/번들 사이즈 큰 검토가 필요하므로 본 타스크 범위에서 분리, 별도 이슈로 후속.
