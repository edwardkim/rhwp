## 1. 배경과 현재 상태

현재 `.github/workflows/release-binary.yml`은 다음 네 자산을 만든다.

1. Linux x86_64
2. macOS x86_64
3. macOS AArch64
4. Windows x86_64

Linux AArch64 사용자는 소스 빌드 또는 x86_64 원격 호스트를 사용해야 한다. #5949 제안자는
DGX Spark Ubuntu 24.04 AArch64에서 release CLI를 직접 빌드하고 `info`, `convert`,
`export-tables`, `mcp-serve`를 검증했지만, 현재 GitHub Release에는 해당 산출물이 없다.

GitHub의 현재 공식 표준 runner 문서는 public repository에서 `ubuntu-24.04-arm`을 지원한다.
따라서 크로스 컴파일이나 self-hosted runner를 추가하지 않고 native AArch64 runner에서
`aarch64-unknown-linux-gnu` 바이너리를 빌드·실행할 수 있다.

- runner 정본: <https://docs.github.com/en/actions/reference/runners/github-hosted-runners>
- GA 공지: <https://github.blog/changelog/2025-08-07-arm64-hosted-runners-for-public-repositories-are-now-generally-available/>

## 2. 목표와 완료 조건

### 목표

- release matrix에 Linux AArch64를 독립 target으로 추가한다.
- native runner에서 산출 바이너리의 `--version` 실행까지 확인한다.
- `rhwp-{tag}-linux-aarch64.tar.gz`와 그 SHA-256을 기존 release job이 수집하게 한다.
- 기존 네 플랫폼, tag/release 조건, 권한과 배포 채널을 바꾸지 않는다.

### 구현 완료 조건

1. workflow 계약 테스트가 target, runner, suffix, binary 이름과 matrix 유일성을 고정한다.
2. exact PR head의 `workflow_dispatch(tag=test)`에서 Linux AArch64 build job이 성공한다.
3. `rhwp-test-linux-aarch64.tar.gz`를 내려받아 다음을 확인한다.
   - archive 안에 `rhwp/rhwp`, `LICENSE`, `README.md`, `README_EN.md`가 있다.
   - 실행 파일은 ELF 64-bit AArch64다.
   - workflow의 native runner에서 `rhwp --version`이 성공했다.
4. PR의 required CI가 성공하고 변경이 `devel`에 정상 병합된다.

### 이슈 최종 완료 조건

구현 merge만으로 #5949를 닫지 않는다. v0.8.6 태그의 GitHub Release에
`rhwp-v0.8.6-linux-aarch64.tar.gz`와 해당 `SHA256SUMS.txt` 행이 실제로 게시되고,
archive 구조·architecture·version을 재확인한 뒤 close한다. 제안자의 DGX Spark 실측은 유용한
추가 증적이지만 메인테이너가 통제할 수 없는 외부 응답을 필수 close 조건으로 두지는 않는다.

## 4. 보호 불변식

1. 기존 네 target의 target·runner·archive suffix·binary 이름을 바꾸지 않는다.
2. `push.tags: v*`와 `workflow_dispatch` trigger를 유지한다.
3. `contents: write`보다 권한을 넓히지 않고 privileged event를 추가하지 않는다.
4. `tag=test` 수동 실행은 build·artifact만 만들며 GitHub Release를 생성하거나 수정하지 않는다.
5. `v*` 실행에서 다섯 build job이 모두 성공해야 release job이 시작되는 기존 `needs: build`를 유지한다.
6. checksum은 다섯 archive 전체를 포함하며 파일명 충돌이나 누락을 허용하지 않는다.
7. 철회된 배포 채널·설치 자산을 되살리지 않는다.
8. runner label이나 action 호환성을 추정으로 완료 처리하지 않고 exact head의 실제 Actions run으로 확인한다.

### Stage O3-3 — 로컬 비례 검증

다음을 순차 실행한다.


**종료 게이트**: 모든 계약과 형식 검사가 통과하고 rollback diff가 matrix 항목·문서·테스트 제거로 제한된다.

## 6. 위험과 rollback

| 위험 | 탐지 | 대응 |
| --- | --- | --- |
| runner label 미지원·queue 실패 | exact head Actions job | merge 보류, 공식 label 재확인 |
| ARM linker 또는 dependency 실패 | native build log | 누락 system dependency를 최소 추가하거나 범위 재승인 |
| official Action의 ARM 비호환 | step별 log | action pin·지원 범위를 조사하고 임의 권한 확대 금지 |
| archive 이름·checksum 누락 | artifact 다운로드·release job | matrix suffix/수집 glob 계약 수정 |
| 기존 플랫폼 회귀 | 다섯 matrix job | fail-fast=false 결과를 분리하고 원인 target만 보정 |
| tag=test가 release를 게시 | release job 조건 검토·run 관찰 | 즉시 중단하고 조건 revert |

devel rollback은 #5949 구현 merge commit을 revert해 Linux AArch64 matrix·계약·문서만 제거한다.
이미 v0.8.6 Release가 게시된 뒤 산출물 자체에 결함이 확인되면 자산을 조용히 교체하지 않고,
영향과 checksum 불일치를 기록한 뒤 메인테이너 승인에 따라 새 patch release를 사용한다.
