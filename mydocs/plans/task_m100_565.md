## 5. 근본 원인

1차 가설은 일반 `layout_paragraph` 의 run 후처리 분기였지만, 실제 #565 문단은 선행 TAC 표 때문에 `layout_inline_table_paragraph` 경로로 진입한다.

해당 경로는 `char_offsets` gap 으로 텍스트 세그먼트를 나눈 뒤 `segment → table → segment` 순서만 지원하고 있었다. `composed.tac_controls` 에는 표와 수식이 모두 들어 있지만, 배치 단계에서는 `inline_tables` 만 순회하므로 `rmX` 등 수식 9개가 인라인 위치에 렌더링되지 않는다.

그 결과 수식은 `inline_shape_position` 이 등록되지 않은 채 shape/layout fallback 경로로 넘어가고, 모두 같은 fallback 좌표에 겹쳐 렌더링된다.

추가 리뷰에서 19번 답문항처럼 같은 text position 에 TAC 수식과 TAC 표가 연속 저장된 경우도 확인했다. 기존 단일 `segment → object` 순회는 같은 gap 의 두 번째 개체를 다음 텍스트 뒤로 밀어 텍스트 줄바꿈을 깨뜨릴 수 있으므로, 같은 position 의 TAC 개체를 모두 현재 gap 에서 처리해야 한다.
