## 2. 목표와 보존 조건

화질을 더 낮추지 않고 **화면 판정 중복, 왕복 스크롤의 재래스터, 입력을 막는 연속 작업**을 줄인다.
캐시는 메모리를 일부 더 보존해 CPU 작업을 줄이는 교환이다. 메모리 감소와 줌 시간 개선을 미리
약속하지 않는다. 이 작업의 주 성과 지표는 스크롤 응답·cache hit·중복 raster 감소다.

포함:

1. 이미 계산된 페이지 geometry의 행 인덱스와 공유 visibility snapshot
2. visible / 제한된 방향 prefetch / 최근 사용 retention 분리
3. main·overlay를 함께 다루는 페이지 표면 LRU와 실제 할당 비용 추적
4. 일반 스크롤의 visible 우선 작업 분할, bounded idle prefetch, stale 작업 차단
5. 실제 문서의 성능·화질·줌·수명 회귀 검증과 재현 가능한 증거

보존:

- #6467의 DPR 결정·32M visible / 40M retained surface pixel 예산·보호 쪽·출력 profile을 유지한다.
  #6521의 DPR 1.5 ceiling이나 열 수 기반 화질 gate를 추가하지 않는다.
- #6040에서 승인한 자동 2열·실제 점유 중앙 정렬과 기존 줌 앵커·매 프레임 geometry 갱신을 유지한다.
  [Stage 1 재구성 기록](../working/task_m100_6040_stage1.md)의 폐기된 Canvas 전용 preview,
  topology 고정/정착 commit 설계를 재도입하지 않는다.
- 눈금자·캐럿·선택·hit-test가 사용하는 좌표와 갱신 시점을 바꾸지 않는다.
- 초기 문서 표시, 편집/undo/redo, document-agent strict render, 줌 정착의 동기 visible 경로는
  우선 보존한다. 새 visible 분할은 **일반 스크롤 경로**부터 연결한다. 다른 경로로의 확대는 재승인한다.
- zoom/resize의 기존 전체 release 경계를 없애지 않는다. 첫 LRU의 이득 범위는 동일 배율·revision의
  스크롤 왕복이며, 배율을 넘어 bitmap을 재사용해 흐리게 보이게 하지 않는다.

범위 외: 페이지 설정 UI, 파서·조판·Rust/WASM 변경, renderScale 정책 변경, 새로운 줌 기준,
worker/OffscreenCanvas 이관, raster 내부 선점, 무조건 큰 overscan, 다른 PR의 merge/close.

## 6. 수용 기준과 증거

### 정확성·수명

- 행 인덱스는 기존 AABB visible 결과와 일치한다. 같은 geometry/viewport query의 전체 판정은 한 번이며
  getPageAtPoint 등 보조 조회도 전체 페이지 반복으로 되돌아가지 않는다.
- 표시 완료로 보고한 쪽에 빈 내용/누락 layer가 없어야 한다. 분할 중인 나머지 쪽을 완료로 세지 않고,
  전체 visible-stable 지연도 별도로 판정한다. 캐시에서 다시 붙인 결과는 직접 렌더와 동일해야 한다.
- 동일 revision/backend/정확한 render scale의 완료된 bundle이 예산 안에서 보존된 왕복은 재래스터 0.
- 무효화된 timer/idle/rAF/decode callback의 화면·zoom 변경 0. 순수 wheel의 zoom 분류 0.
- 사용자 검증으로 눈금자 지연, 좌우/상하 점프, 캐럿·선택·hit-test·페이지 상태 표시 회귀가 없어야 한다.
- 추가 LRU는 예산 여유 내에서만 존재한다. 보호된 mandatory visible 자체가 기존 예산을 넘으면 예외를
  숨기지 않고 cache=0으로 기록한다. 기존 baseline 예외를 '항상 총량 40M 이하'라고 주장하지 않는다.

### 성능

- 핵심 카운터: visibility 계산/조사 rows·pages, 실제 main/overlay raster, release, cache hit/miss/eviction,
  stale 취소, queue 길이, planner·scheduler 비용, active/prefetch/LRU/pool Canvas 수·정수 pixel 합.
- 입력→첫 visible 표시, 전체 visible 안정화, prefetch 완료를 별도 측정한다. long task 수/총시간,
  frame p50/p95/max, refresh rate 기준 frame 누락 추정도 기록한다. rAF 간격을 compositor 실측 dropped
  frames로 부르지 않는다. 미지원 지표는 N/A로 남긴다.
- 주 시나리오는 조건별 warm-up 뒤 최소 20회 A/B·B/A 교대 표본, cold는 별도 수집한다. sample 수,
  중앙값·p95·분산과 실패/취소 표본을 남긴다. n=4 탐색 자료로 속도 개선을 주장하지 않는다.
- 작은 1·2쪽 initial visible의 동기 호출 수를 늘리거나 첫 표시를 의도적으로 다음 frame으로 미루지 않는다.
  시간 비회귀 판정의 오차 범위는 Stage 1 반복 잡음 측정 후 **최적화 결과를 보기 전에** 승인받는다.
- 네 zoom 지표(input→preview / focused-sharp / visible-stable / retained-complete)는 회귀 대조로
  사용한다. 이 PR에서 전체 줌 완료 시간 개선을 필수 성과처럼 약속하지 않는다.
