## 1. 배경

Task #634 종료 시점에 페이지 2, 3 미표시 메커니즘이 미해결로 남아 본 issue 로 분리됨.

`samples/aift.pdf` (한컴 출력) vs rhwp 비교 결과:

| rhwp 페이지 | 한컴 표시 | 메커니즘 |
|------------|----------|---------|
| 1 (cover disclaimer) | 표시 | PageNumberPos 등록 후 표시 (정상) |
| **2 (사업계획서 표지, 35×27 표)** | **미표시** | **메커니즘 미확인** |
| **3 (요약문, 14×17 표)**          | **미표시** | **메커니즘 미확인** |
| 4 (목차)             | 미표시 | PageHide on para 2.34 ✓ |
| 5 (별첨 목차)         | 미표시 | PageHide on para 2.54 ✓ |
| 6 (본문 시작)         | 표시 | NewNumber 무관 정상 |
| 7+ (NewNumber 발화 후) | 표시 | 정상 |

페이지 2, 3 두 페이지 모두 PageHide page_num=true 컨트롤은 **없음** (Task #634 에서 검증).
즉 rhwp 는 정상 처리 후 표시하지만 한컴은 미표시 → 별도 메커니즘 존재.

## 4. 단계별 계획

### Stage 0: 사전 데이터 수집 (read-only)

**목표**: 가설 검증에 필요한 모든 raw 데이터 수집.

수집 항목:
1. `rhwp dump-pages samples/aift.hwp -p 1` (페이지 2 = 0-based 1) — 페이지 구조
2. `rhwp dump-pages samples/aift.hwp -p 2` (페이지 3) — 페이지 구조
3. `rhwp dump samples/aift.hwp -s 0 -p {표 paragraph}` — 페이지 2 표의 paragraph header / ParaShape / 표 attr
4. `rhwp dump samples/aift.hwp -s 0 -p {표 paragraph}` — 페이지 3 표의 paragraph header / ParaShape / 표 attr
5. 페이지 4, 5 (PageHide 표시) 표 비교 데이터 (대조군)
6. 페이지 1, 6 (정상 표시) paragraph 비교 데이터 (대조군)
7. 한컴 PDF 페이지 2, 3 footer 영역 raw text op 측정 (실제 footer 누락 확인)

산출물: `mydocs/working/task_m100_637_stage0.md` (raw data 요약)

### Stage 1: 5가지 가설 체계적 검증

**목표**: Stage 0 raw data 로 각 가설 채택/기각.

각 가설별 검증:
- **H1 (cover-style 휴리스틱)**: 페이지 2/3 표가 본문 영역 전체 차지하는지 측정 (body_area vs table size). 페이지 4, 5 표 (미표시이지만 PageHide 가 진짜 원인) 와 비교.
- **H2 (셀 내부 PageHide)**: 표 셀 내부 paragraphs 재귀 dump 로 PageHide page_num 컨트롤 직접 검색.
- **H3 (paragraph header 비트)**: 페이지 2/3 표 host paragraph 의 paragraph header property 32비트 풀 dump → 페이지 4, 5 (PageHide 표시) 와 페이지 1, 6 (정상 표시) 의 비트 비교.
- **H4 (표 attr 비트)**: 표 ctrl_header attr (0x0600000e vs 0x0400000e) 비트 의미 분석. HWP 스펙 (관련 비트가 page-number-related 인지) 확인.
- **H5 (한컴 휴리스틱)**: H1~H4 모두 기각 시 잠정 채택. 단 휴리스틱은 룰 아님 → close-as-no-fix 권고.

산출물: `mydocs/working/task_m100_637_stage1.md` (가설별 판정표)
