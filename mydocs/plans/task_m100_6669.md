# #6669 Gym JSON 증적 시각화 수행계획

## 1. 목적과 기준선

- **이슈**: [#6669](https://github.com/edwardkim/rhwp/issues/6669)
- **부모**: [#6628](https://github.com/edwardkim/rhwp/issues/6628)
- **브랜치**: `task_m100_6669`
- **기준선**: `upstream/devel@d770ef80ed5ccc82a834558355b6786213ca2e05`
- **기준 PR**: #6677 merge commit `d770ef80ed5ccc82a834558355b6786213ca2e05`

저장된 Gym 실행 증적을 다시 실행하지 않고 사람이 판독할 수 있는 정적 보고서로 변환한다.
JSON 봉투는 계속 유일한 기계 판독 정본이며, 보고서는 판정을 새로 만들지 않는 파생 뷰다.

#6628에서는 이미 exact runner·제품 후보와 binary SHA-256을 고정해 positive 1,035/1,035,
discrimination false-pass 0, trajectory 239/239를 전수 확인했다. #6669는 Gym의 판정 의미를
바꾸지 않으므로 이 전수 실행을 반복하지 않는다. 고정된 소형 공개 fixture와 기존 봉투 검증기를
사용해 변환 계약을 검증한다.

## 2. 보호 불변식

1. **JSON 정본 유지**: HTML의 색·수치·문장은 JSON을 해석한 결과일 뿐 승인 권위가 아니다.
2. **fail-closed**: 필수 파일·kind·schema·필드·종료 코드·집계가 깨지거나 실행 신원이 섞이면
   보고서를 성공 상태로 만들지 않는다. 불완전 입력은 출력 파일을 원자적으로 남기지 않고 종료 2다.
3. **상태 비축약**: `ok`, process exit, `trusted`, tool 오류, 예외, skip을 각각 보존한다.
   하나만 참이라는 이유로 녹색 성공으로 접지 않는다.
4. **결정성·오프라인**: 같은 입력 바이트와 같은 생성기 버전은 byte-identical HTML을 만든다.
   시각 보고서는 외부 CDN, 네트워크, 웹폰트, JavaScript 실행에 의존하지 않는다.
5. **계보 고정**: runner head/tree, product source head, binary version·SHA-256, 실행 환경·시각,
   축별 종료 코드·경과 시간, 입력 파일별 SHA-256과 생성기 버전을 표시한다.
6. **혼합 실행 거부**: 세 실행 축의 `binPath`, positive agent/run id, 증적 디렉터리의 실행 신원,
   manifest의 파일 hash가 서로 맞지 않으면 생성하지 않는다. 실행 직후 `--seal`이 입력 집합을
   고정하고, `--out`은 seal 이후 한 바이트라도 달라진 입력을 거부한다.
7. **민감정보 최소화**: 절대경로·사용자 홈·사설 코퍼스 경로·파일명·본문은 출력하지 않는다.
   알려진 공개 pack/task id만 표시하고 자유 형식 오류 문자열은 HTML escape·경로 마스킹·길이 상한을
   적용한다.
8. **운영 비결합**: 일반 PR, `devel`/`main`, tag, release, npm·extension 게시 게이트에 연결하지 않는다.
9. **외부 변경 승인**: GitHub comment, push, PR 생성, merge는 각각 승인 뒤 수행한다.

## 3. 출력 형식 결정

최소 정본 출력은 **단일 self-contained HTML**로 한다.

- HTML은 표·상태 배지·접을 수 있는 실패 상세를 한 파일에서 제공해 SVG 한 장보다 1,000개 이상
  task의 drill-down에 적합하다.
- 차트는 inline SVG 또는 CSS 막대로만 만들고, 모든 수치는 같은 문서의 표와 텍스트로도 제공한다.
- 정적 HTML이므로 로컬 `file://` 열람과 PR artifact 보존이 가능하다.
- 원문 JSON을 HTML에 통째로 복제하지 않는다. 입력 이름·kind·schema·SHA-256과 판정에 필요한
  최소 구조화 필드만 파생한다.
- 생성은 두 단계다. `--seal`이 검증된 입력의 실행 신원과 SHA-256 목록을
  `evidence-manifest.json`에 원자적으로 고정하고, `--out`이 그 manifest를 재검산한 뒤 HTML을 쓴다.
  manifest는 Gym 판정 결과가 아니라 원문 파일 집합의 영수증이다.

## 4. 단계별 수행

### Stage 0 — 입력 계약과 위협 모델 고정

1. 수동 운영 매뉴얼이 만드는 metadata, `.exit`, `.seconds`, 일곱 JSON 봉투를 목록화한다.
2. 필수 입력, 허용 schema, 역할별 정직 집계와 실행 신원 fingerprint를 기계 표로 고정한다.
3. `scoreErrors`를 결과 행의 의도된 음성 거부와 대응되는 항목, 대응되지 않는 미설명 오류로
   구분하는 규칙을 고정한다.
4. 경로·본문 누출, HTML injection, 과대 오류 문자열, 입력 교체와 실행 혼합을 위협 모델에 포함한다.

**종료 게이트**: 어떤 입력이 성공·실패·미완료·skip으로 보이는지와 생성 거부 조건이 모호하지 않다.

### Stage 1 — fail-closed 증적 로더와 정규화 모델

1. `gym/tools/evidence_report.py`에 표준 라이브러리만 사용하는 로더를 추가한다.
2. `audit.json`, 두 oracle probe, `authority-ledger.json`, `positive.json`,
   `discrimination.json`, `trajectory.json`과 각 종료 코드·경과 시간 및 실행 metadata를
   역할별로 검증한다.
3. 기존 audit/discrimination/trajectory의 정직 계약을 재사용하고, positive와 oracle은 같은 수준의
   집계 재계산을 추가한다.
4. `--seal`에서 입력 파일 hash와 실행 identity fingerprint를 계산한 deterministic
   `evidence-manifest.json`을 원자적으로 쓰고, `--out`에서 manifest와 현재 입력을 다시 대조한다.
5. 사람 출력용 모델에는 allowlist 필드만 옮기고 자유 문자열을 안전하게 정규화한다.

**종료 게이트**: 깨진 JSON, 필수 봉투 부재, 잘못된 kind/schema/count/exit, 섞인 binary/run 신원이
각각 구조화된 오류와 종료 2를 내며 성공 HTML이 남지 않는다.

### Stage 2 — 결정론적 self-contained HTML renderer

1. 실행 계보와 일곱 입력의 hash 표를 만든다.
2. 구조 감사, oracle structural/selftest, authority ledger, positive, discrimination,
   trajectory의 상태 카드를 만든다.
3. pack별 task/control/load-bearing 분포를 표와 inline 막대로 표현한다.
4. false-pass, positive 실패·누락·skip, 의도된/미설명 score error, theater, trajectory 예외·tool 오류를
   별도 `<details>` 구간으로 제공한다.
5. `trajectory.ok`와 `trajectory.trusted`를 다른 칸에 표시하고, 미판정·skip을 성공색으로 쓰지 않는다.
6. 생성 시각 대신 입력의 실행 시각만 사용하고 정렬·숫자·문자열 직렬화를 고정한다.

**종료 게이트**: 같은 fixture를 두 번 생성한 SHA-256이 같고, 네트워크 없이 브라우저에서 열린다.

### Stage 3 — 계약 시험과 공개 샘플

1. 작은 합성 fixture에 정상, 실패, skip, 의도된 score error, 미설명 오류, `ok=true/trusted=false`를
   모두 포함한다.
2. 성공 상태, 비녹색 실패·미완료, 원문 hash 역추적, path redaction, HTML escape를 시험한다.
3. 필수 파일 누락·깨진 JSON·schema 불일치·집계 위조·실행 혼합·manifest hash 변경을 음성 시험한다.
4. fixture에서 결정적으로 생성한 작은 샘플 HTML과 정확한 재생성 명령을 저장한다.

**종료 게이트**: byte-identical 생성과 fail-closed 음성 계약이 단위 시험으로 고정된다.

### Stage 4 — 운영 문서와 에이전트 지침 연결

1. `gym/docs/evidence_report.md`에 입력·출력·상태 색·계보·오류·보안 계약을 정본화한다.
2. `mydocs/manual/gym_benchmark_operations.md`에 전수 실행이 끝난 뒤 manifest 고정과 HTML 생성·검산
   명령을 추가한다.
3. `gym/AGENTS.md`에 JSON 정본, 비권위 파생 보고서, 민감정보와 fail-closed 규칙을 연결한다.
4. Gym 도구/문서 진입점에서 새 규약을 찾을 수 있게 최소 링크만 추가한다.

**종료 게이트**: 인간 메인테이너와 AI 에이전트가 같은 명령·같은 판정 경계를 따라 재현한다.

### Stage 5 — 검증·시각 판정·최종 보고

1. focused evidence-report 시험과 `test_gym_*.py` 전체 빠른 계약을 실행한다.
2. audit, oracle structural/selftest, authority ledger를 실행한다.
3. 샘플 HTML을 로컬 브라우저에서 열어 상태색·overflow·접힘·모바일 폭·offline 요청 0을 확인한다.
4. 문서 metadata·링크와 `git diff --check`를 검사한다.
5. 최신 `upstream/devel`과의 충돌·변경 범위를 재확인하고 최종 보고서를 작성한다.

**종료 게이트**: 코드·문서·샘플이 같은 입력 계약을 가리키며, 메인테이너 시각 판정과 최종 결과
승인을 받은 뒤에만 push·PR 단계로 넘어간다.
