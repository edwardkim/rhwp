## 1. 문제 정의

### 증상

`samples/basic/shortcut.hwp` 페이지 3 끝에 PDF 권위 자료 (한글 2022) 가 보여주는 "<편집 화면 분할에서>" + "화면 이동 Ctrl+W,N" 행이 페이지 4 첫 줄로 밀림.

### 베이스라인 (stream/devel)

```
=== 페이지 3 ===
  단 0: 보기 표 (pi=81)
  단 1: pi=82~87 (좌단 6, used=80px)
  단 2: pi=88~93 (우단 6, used=80px)
  ── 페이지 break ──
=== 페이지 4 ===
  단 0: pi=94, pi=95 ("<편집 화면 분할에서>", "화면 이동")
  단 1: pi=96 (입력 표)
  단 2/3: 좌우 단 (pi=97~115)
```

페이지 3 잔여 공간 = body_height(701.7) − used(139.9) ≈ **561.8 px** (10배 이상 여유).

### PDF 권위 (한글 2022)

페이지 3 다단 영역 좌단=7행, 우단=7행:
- 좌단: pi=82..87 + **pi=94 ("<편집 화면 분할에서>")**
- 우단: pi=88..93 + **pi=95 ("화면 이동 Ctrl+W,N")**

페이지 4 시작은 pi=96 (입력 표) 의 [다단나누기].

## 2. 표 명세 (IR)

`src/model/paragraph.rs::ColumnBreakType`:

```rust
pub enum ColumnBreakType {
    None,         // 0 — 일반
    Page,         // 0x0010 — 쪽 나누기
    Column,       // 0x0008 — 단 나누기
    Section,      // 0x0080 — 구역 나누기
    MultiColumn,  // 0x0100 — 다단 나누기
}
```

본 결함 paragraph: `pi=94 column_type=Column` (단 나누기), `pi=96 column_type=MultiColumn` (다단 나누기).

## 3. Root cause (사전 정적 분석)

### 핵심 분기 — `src/renderer/typeset.rs:417-424`

```rust
if para.column_type == ColumnBreakType::Column {
    if has_diff_col_def {
        self.process_multicolumn_break(...);  // ColumnDef 동반 → zone 재정의
    } else if !st.current_items.is_empty() {
        st.advance_column_or_new_page();      // 일반 column-break
    }
}
```

`advance_column_or_new_page` (`typeset.rs:261-273`):

```rust
fn advance_column_or_new_page(&mut self) {
    self.flush_column();
    if self.current_column + 1 < self.col_count {
        self.current_column += 1;       // 다음 단으로
        self.current_height = self.pending_body_wide_top_reserve;
    } else {
        self.push_new_page();            // 마지막 단이면 새 페이지 ← 결함
    }
}
```

### 결함 메커니즘

1. 다단 영역 (col_count=2) 좌단(pi=82..87) + 우단(pi=88..93) 자동 분배 완료 → `current_column=1`
2. pi=94 [단나누기] 만남 → `advance_column_or_new_page` 호출
3. `current_column + 1 = 2 = col_count` → `push_new_page` 호출
4. **페이지 3 잔여 공간 무시하고 페이지 break 강제**

### 한컴 정합 동작

- column-break 가 마지막 단에서 발생 시 `col 0` 으로 **wrap-around**
- 같은 다단 영역에 paragraph 추가 (좌단/우단 행 추가)
- 페이지 잔여 공간 있는 한 wrap-around 가능, 없으면 새 페이지

## 4. 정정 방향 (가설)

### 가설 H1 — column-break wrap-around (마지막 단에서 col 0 으로 회귀)

`advance_column_or_new_page` 의 마지막 단 분기에서:
```rust
} else {
    // [Task #768] column-break 가 마지막 단에서 발생 + 페이지 잔여 공간 있음
    // → col 0 으로 wrap-around (같은 다단 영역에 행 추가)
    if /* 다단 영역 + 잔여 공간 충분 */ {
        self.current_column = 0;
        self.current_height = /* 적절한 다음 행 위치 */;
    } else {
        self.push_new_page();
    }
}
```

**도전 과제**:
- "다단 영역 안" 판단 (col_count > 1)
- "잔여 공간 충분" 판단 (다음 paragraph 의 height 가 column 잔여 공간 안에 들어가는지)
- col 0 의 다음 행 위치 산출 (현재 col 0 의 마지막 paragraph 의 vpos + height)

### 대안 H2 — column-break 자체를 자동 분배에서 무시

다단 영역 안에서 column-break 마커를 분배에 영향 주지 않도록. 자동 분배 알고리즘이 14 paragraphs (pi=82..95) 를 균등 분배 → 좌단 7, 우단 7.

**문제**: 명시적 마커를 무시하면 다른 column-break 케이스 회귀 가능.

### 가설 H3 — column-break 가 paragraph 분배 분기점 (col 0 ↔ col 1 토글)

column-break 가 있는 paragraph 를 만나면:
- 좌단 (col=0) → 우단 (col=1) 이동
- 우단 (col=1) → 좌단 (col=0) wrap-around (같은 다단 영역)

→ H1 의 일반화. 가장 간결.

### 우선 순위

H1 > H3 > H2 (H1 부터 시도, RED FAIL 잔존 시 H3 → H2)

### 엣지 케이스

- 페이지 잔여 공간 부족 시: 새 페이지로 가는 게 정확
- column-break 가 첫 단(col=0)에서 발생: 기존 동작 유지 (col 1 으로)
- column-break + ColumnDef 동반: 기존 process_multicolumn_break 유지
