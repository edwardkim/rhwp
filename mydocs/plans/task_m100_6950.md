## 1. 목표

문단 텍스트 끝의 자리차지 표가 텍스트 아래에 배치되어야 하는데 같은 문단과 겹치는 결함을
해결한다. 샘플 이름·문단 번호·고정 위치를 조건으로 삼지 않고 원본 앵커와 문단 흐름에 근거한
조판 규칙으로 구현한다. 관련된 모든 표 문제를 한꺼번에 해결하는 작업은 아니다.

2026-09-09 메인테이너 요구로 목표를 명확히 한다. 임시 엣지 케이스 처리나 과거 조건문 보존이 아니라
**HWP/HWPX의 문단 텍스트·표 배치 원리를 공통 IR의 결정론적 조판 계약으로 구현**한다.
사례는 규칙을 검증하는 자료다. 확정 배치와 점유 영역을 함께 결정해 예약·출력에 전달하며,
수정된 책임 경계와 검증 기준은 [구현계획 1절](task_m100_6950_impl.md#1-목표와-선택하지-않는-방법)에 둔다.

## 3. 원인 조사와 보호 불변식

현재 일반 배치의 `tac_sibling_float_anchor_offset_px`는 같은 문단에 선행 TAC(글자처럼 취급)
컨트롤이 없으면 보정량을 0으로 만든다. 그 결과 이번 표에는 첫 줄 기준점과 세로 오프셋이 적용된다.
다만 이 조건은 `980c80203` / #6879에서 #6718의 저장 vpos 되감김 사례를 보호하려고 좁혀졌다.

따라서 다음을 함께 지킨다.

1. 선행 TAC가 없다는 이유만으로 유효한 문단 끝 앵커를 잃지 않는다.
2. 저장 줄의 vpos 되감김·재조판 사례에 앵커 간격을 무조건 더하지 않는다. 기존 guard를 단순 삭제하지 않는다.
3. 실제 표 배치와 조판 공간 예약이 같은 기준점을 사용한다. 표만 내려서 뒤 문단과 겹치게 하지 않는다.
4. 앞선 표 3개, 호스트 텍스트, 후속 문단의 흐름과 기존 정상 쪽 분할을 보존한다.
5. #6879의 TAC 형제 사례와 #6860의 분할 경로를 보호한다. 문단 밖 선행 표를 같은 문단의 TAC로 취급하지 않는다.
6. 입력 문서는 읽기 전용으로 보존한다. 실제 한컴 확인이 없는 합성 문서를 정답지로 사용하지 않는다.

## 5. 검증 전략과 비용 제한

- 이미 확보한 원본 구조·현재 WASM 재현을 재사용한다. 처음부터 코퍼스 전수 계측을 하지 않는다.
- 역사 A/B는 우선 `980c80203` 전후와 현재 기준의 같은 입력을 비교한다. 결과가 회귀를 가리킬 때만
  필요한 구간을 좁혀 추적한다. 실행 엔진·폰트·입력·빌드 조건을 맞추고 소스 이력만으로 회귀를 단정하지 않는다.
- #6718/#6879/#6860의 기존 fixture·증적을 우선 사용한다. 확보되지 않은 자료나 빌드 제약은
  미확인으로 보고하며, 정답을 추정하여 통과 처리하지 않는다.
- 이번 표의 텍스트 겹침 제거뿐 아니라 선행 표·후속 문단과 쪽수 변화의 이유를 확인한다.
  위치 후보 계산과 한컴 시각 판정은 구분한다. SVG는 `output/6950/` 아래에 내보낸다.
- 새 회귀 테스트는 `tests/cases/` 원본으로 작성한다. Rust 본문에 테스트를 추가하지 않는다.
  메인테이너 지시로 편입한 원본 fixture를 우선 사용하며, 추가 최소 fixture가 필요하면 Stage 1
  구현계획에서 확정한다. 원본은 변경하지 않는다.
- Rust source/test 변경의 PR 제출 전에는 review 환경에서 `AGENTS.md` 및
  [로컬 검증 4.3](../manual/pr_review/local_validation.md)에 따라 파생 suite 준비, fmt,
  native Clippy, WASM Clippy, workspace build, all-targets Clippy, manifest 검사를 순차 수행한다.
  generated suite·manifest는 source PR에 포함하지 않는다. 전체 검증은 해당 단계 승인 범위에서 실행한다.
- 광범위 회귀 계측이 필요해지면 기존 증적으로 부족한 이유와 예상 비용을 먼저 제시한다.
  CI 정책·폰트 정책·다른 열린 표 이슈의 전면 수정은 범위 밖이다.
