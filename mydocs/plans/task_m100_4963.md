## 1. 결정과 목표

W5의 목적은 W4 상위 후보에 임의 fallback을 추가하는 것이 아니다. 같은 입력을 한컴의 정확한 폰트가
있는 상태부터 관련 폰트가 모두 없는 상태까지 통제해서 출력하고, **폰트 선택·글립·advance·줄·페이지 중
어디에서 최초 조판 차이가 생기는지** 재현 가능한 Oracle Profile로 고정하는 것이다.

이번 작업은 다음 질문에 답한다.

1. 문서가 요구한 exact face가 설치되었을 때 한컴은 실제로 어떤 font/glyph/advance를 쓰는가?
2. exact face가 없을 때 문서의 `substFont`, 공식 successor, 한컴 자체 missing-font 선택은 각각 어떤
   결과를 만드는가?
3. 서로 다른 관계를 이름 유사성이나 metric 근사치로 합치지 않고 증명할 수 있는가?
4. 다음 font incident에서 동일한 ladder를 다시 쓸 수 있는가?

### 범위 안

- W4 A·B band 17개 face의 readiness와 조사 상태를 명시한다.
- Oracle Profile schema, 관계 enum, 상태 enum, deterministic fixture와 비교기를 만든다.
- 이미 존재하는 W3·W4·한컴 2022 계측은 hash가 일치하면 재사용한다.
- 승인된 통제 환경에서 exact·missing ladder를 canary부터 단계적으로 실행한다.
- 완료할 수 없는 face도 `unknown` 또는 `blocked` 근거를 남겨 분모에서 숨기지 않는다.

### 범위 밖

- 제품 font metric DB, fallback 순서, paint/backend 정책 변경
- 이름이 비슷하다는 이유만으로 exact·alias·successor 관계 강제
- 351개 전체 face 전수 조사
- 비재배포 font bytes·subset PDF·private corpus 식별 정보 공개
- HWP/HWPX 또는 한컴 빌드 번호만으로 정책을 분기하는 구현

## 4. Oracle Profile 계약

각 실행은 하나의 profile JSON이며, 다음 identity와 observation을 함께 가져야 한다.

### 4.1 identity

- issue, candidate rank, exact document face, ladder state, question id
- input HWP/HWPX SHA-256, fixture contract/version, generator source commit
- OS, locale, Hancom full version/build, PDF producer, export route
- 설치 font의 name table·face index·SHA-256과 전체 ambient font manifest digest
- 실행 시작·종료 시각, process reset/reboot 여부, 반복 번호

### 4.2 observation

- requested face, Hancom readback face와 `FontType`
- PDF subset/base font name, font type, encoding/CID 정보
- `pdfObservedAdvance`: PDF text/glyph positioning에서 관찰한 advance
- `hmtxAdvance`: 확인된 SFNT face의 `hmtx` advance와 units-per-em
- 대표 glyph outline의 canonical digest
- line count·line boundary·page count·대표 anchor 위치
- 최초 divergence plane과 최초 다른 character/line/page
- relation evidence와 직접 anchor

`hmtxAdvance`와 `pdfObservedAdvance`는 같은 값으로 간주하지 않는다. PDF CID width, Type3 glyph,
Hancom HFT처럼 원본 SFNT `hmtx`를 검증할 수 없는 경우 `hmtxAdvance`를 만들어내지 않고 상태와 사유를
기록한다.

### 4.3 필드 상태

모든 필수 관찰 필드는 값과 함께 다음 상태 중 하나를 갖는다. 설명 없는 `null`은 허용하지 않는다.

- `observed`: 도구와 원본 evidence로 실제 관찰
- `unavailable`: 현재 source/tool로 관찰 불가
- `not-applicable`: 해당 format/profile에는 개념이 적용되지 않음
- `blocked`: 안전·라이선스·immutable bundle 등 명시적 장애가 있음

### 4.4 relation enum

- `identity-exact`
- `identity-alias`
- `official-successor`
- `document-substitution`
- `metric-surrogate`
- `hancom-missing-font`
- `unknown`

각 relation은 별도 evidence anchor가 있어야 한다. `official-successor`는 제작·배포 주체의 직접 문서나
bytes/name-table 계보 없이 지정하지 않는다. `metric-surrogate`는 폭 유사성일 뿐 identity나 공식
successor가 아니다.

## 5. controlled ladder

같은 input bytes와 fixture를 다음 순서로 실행한다.

1. `exact-installed`: exact font가 설치된 기준 profile
2. `exact-removed`: exact font만 제거하고 일반 ambient 환경은 유지
3. `document-subst-font-only`: 관련 후보군에서는 문서의 `substFont`만 남김
4. `curated-official-successor-only`: 직접 증명된 공식 successor만 남김
5. `all-related-fonts-missing`: exact·subst·successor·known alias를 모두 제거

여기서 `only`는 Windows 필수 font까지 제거한다는 뜻이 아니다. **대상 face와 증명된 관련 face set**만
통제하고, 나머지 ambient font manifest는 모든 profile에서 동일하게 유지한다. 각 전환 뒤 한컴 process를
완전히 종료하고 font cache 상태를 기록한다. 필요하면 snapshot을 복원해 순서 효과를 제거한다.

bundled HFT처럼 안전하게 제거할 수 없는 font는 `blocked-immutable-bundle`로 남긴다. exact가 실제로
남아 있는 상태를 missing profile이라고 이름 붙이는 것은 금지한다.

## 6. deterministic fixture

private corpus 문서를 Oracle 입력으로 공개하지 않는다. W4가 드러낸 HWP 편집 습관을 재현하는 공개
synthetic fixture를 face별로 같은 template에서 생성한다.

- 한글, 라틴, 숫자, 문장부호, 전각 공백과 대표 혼합 문자열
- 장평 100/90/80, 자간 0/-5/-10, kerning on/off
- 본문, 고정 폭 표 셀, 글상자, 머리말/꼬리말 문맥
- 동일 문자열 반복과 line/page boundary anchor
- stored LineSeg lane과 fresh candidate lane을 구분하되 LineSeg 유효성을 미리 가정하지 않음
- 생성 후 canonical input hash와 semantic manifest를 기록

모든 ladder state에서 input bytes는 동일해야 한다. font 이름이나 문서 내용을 state마다 다시 생성하면
비교 실행으로 인정하지 않는다.

### Stage W5-3 — 무변경 evidence import·read-only canary

**상태: 완료 (2026-08-22)**

- 기존 한컴 2022 `한양신명조`·`휴먼명조` HFT evidence를 hash 고정해 profile로 투영
- 현재 설치 상태를 바꾸지 않는 exact-installed 관찰만 제한 실행

- 기존 PDF와 새 PDF를 서로 다른 환경이면 golden pair로 비교하지 않음

실행 결과는 다음과 같다.

- 공식 보안 DLL의 `RegisterModule=true` 뒤 reference HWPX와 W5 rank 1 fixture가 모두 실제로 열렸다.
- 6개 queue face와 음성 대조군을 readback한 결과 현재 exact TTF는 rank 9 `맑은 고딕`, rank 13
  `휴먼명조`, rank 16 `한컴 윤고딕 230`이었다. rank 1과 KoPubWorld 2종 및 음성 대조군은
  `함초롬바탕`으로 해소되어 exact가 아님을 fail-closed로 기록했다.
- rank 9는 설치된 `malgun.ttf` SHA-256이 W5-2 local source와 일치하므로 입력 face만 바꾼 동일
  deterministic fixture로 read-only canary를 실행했다. HWP 2020 build `11.0.0.9136`, PDF producer
  `Hancom PDF 1.3.0.550`, 914개 Windows/Hancom font manifest digest와 process reset을 고정했다.
- 출력은 `INPILL+MalgunGothic` CID TrueType subset 1종, 1,556 glyph observation, 30개 visual line,
  1쪽이었다. 대표 U+AC00은 source SFNT `hmtx` 2048/2048과 PDF user-space advance 8.120862를 서로
  다른 envelope에 기록했다.
- exact-installed 한 상태만 관찰했으므로 first divergence를 주장하지 않았다. font 설치·제거,
  remote 변환·업로드, private corpus 접근과 제품 metric/fallback/paint 변경은 모두 0건이다.

이 단계의 runner는 font 설치·제거를 하지 않으며 다른 HWP process를 강제 종료하지 않는다. raw
ambient manifest·PDF·관측 JSON은 저장소 밖 owner-only 보관소에 있고 공개 profile에는 digest와
path-free aggregate만 남긴다.

**게이트**: remote 변환·파일 업로드가 필요하면 별도 승인을 받는다.

### Stage W5-4 — disposable 환경 controlled canary

- `KoPubWorld돋움체 Light` 또는 `KoPubWorld바탕체 Light`: 공식 bytes 검증 성공 때만 포함

각 상태 전후 설치 목록/hash를 기록하고 snapshot 복원 뒤 재실행한다. first divergence가 안정적으로
재현되지 않으면 17개 확대를 중단하고 계약·환경부터 교정한다.

W5-4A에서 5개 질문은 세 고유 물리 상태로 정규화했다. `exact-installed`는 exact-only,
`document-subst-font-only`는 fixture-declared subst-only, `exact-removed`와
`all-related-fonts-missing`은 managed related font가 하나도 없는 동일 실행을 공유한다. 직접 근거가
없는 `curated-official-successor-only`는 실행하지 않는다. 각 고유 상태는 외부 control plane이 baseline
snapshot을 복구한 뒤 실행하고, 종료 후 같은 baseline ambient manifest로 돌아왔음을 재검증해야 한다.

메인테이너가 승인한 외부 Hyper-V control plane에서 updated-base Standard checkpoint를 각 상태 전후로
복원했다. rank 1과 rank 7은 `exact-only`, `subst-only`, `none-related`를 완료했고, baseline manifest와
대상 두 font를 제외한 projection이 매번 복구됐다. rank 13은 managed TTF가 없는 상태에서도 exact
readback이 남아 bundled HFT 또는 unmanaged source를 손상시키지 않는 원칙에 따라
`blocked-immutable-or-unmanaged-font`로 중단했다.

rank 1·7의 세 물리 실행은 8개 semantic profile로 분리했다. 특히 `문체부 바탕체` exact SFNT의 영문
name `MBatang`과 fixture의 `KoPubWorld바탕체 Light` substitution을 identity로 혼동하지 않는다.
subst-only와 none-related는 모두 HCR fallback을 사용해 조판 projection이 같았고, exact-only는 U+AC00
glyph observation index 18의 selection·advance에서 먼저 갈라졌다. 공개 산출물은 VM/checkpoint 이름,
절대 경로, font bytes, private corpus identity를 포함하지 않는다.

**게이트 결과**: 메인테이너 판정 뒤 W5-5A의 17개 queue로 확대했다. 추가 mutable 실행은 승인된
disposable snapshot·복원 절차 안에서만 수행했다.

### Stage W5-5 — 17개 queue 확대·공개 projection

- 기존 readiness·profile·blocked 증거를 먼저 결합해 17개 후보를 재사용·terminal·actionable로 분류
- canary를 통과한 동일 계약으로 actionable 후보만 실행
- source-unavailable·immutable HFT는 증거 있는 `unknown`/`blocked`로 완료 상태를 기록
- profile 간 selection/glyph/advance/line/page 최초 divergence를 집계
- W1 Font Rule Ledger와 incident response 문서에 재사용 가능한 evidence anchor 연결
- 최종 보고서와 다음 제품 변경 이슈 후보를 분리 제안

## 8. 보호 불변식

1. **입력 동일성**: ladder 사이에서 HWP/HWPX bytes를 바꾸지 않는다.
2. **환경 동일성**: 대상 related font set 외 ambient manifest가 다르면 같은 ladder로 비교하지 않는다.
3. **관계 분리**: exact, alias, successor, subst, surrogate, Hancom missing을 합치지 않는다.
4. **advance 분리**: source SFNT `hmtx`와 PDF 관찰 advance를 분리한다.
5. **최초 차이 보존**: 최종 페이지 차이만 보지 않고 selection→glyph→advance→line→page 계보를 남긴다.
6. **feature detection**: HWPX/한컴 version 분기가 아니라 해당 문단·font evidence의 실제 유효성을 본다.
7. **fail-closed**: source·관계·환경이 확인되지 않으면 `unknown`이지 자동 fallback 성공이 아니다.
8. **제품 무변경**: W5 evidence만으로 metric DB/fallback/paint를 바로 고치지 않는다.
9. **복구 가능성**: system font mutation은 disposable snapshot과 복원 검증 없이는 하지 않는다.
10. **비공개 경계**: font bytes·private corpus·문서 식별자는 tracked/public 산출물에 넣지 않는다.

## 9. 보안·저작권·자원 한계

- local font inventory 원문은 권한 `0600`의 local-only 산출물로 둔다.
- 공개 profile에는 승인된 family/full/PostScript name, digest, license/embedding 상태만 남긴다.
- OS/2 `fsType`과 배포 조건을 확인하지 않은 subset PDF나 font bytes는 커밋하지 않는다.
- 입력·출력은 지정 root 아래 regular file만 허용하고 path traversal·symlink를 거부한다.
- PDF page·object·glyph·파일 크기 상한, child-process timeout, 임시 폴더 정리를 둔다.
- malformed PDF/font 한 건이 batch 전체를 무한 대기시키지 않도록 per-item 실패로 격리한다.
- private corpus의 path, filename, document hash, 원문, 개별 결과를 공개하지 않는다.
