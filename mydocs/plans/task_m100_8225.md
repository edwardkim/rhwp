# #8225 그림 개체의 HWP5 CTRL_DATA 보존

## 착수 근거

[#8233](https://github.com/edwardkim/rhwp/pull/8233)은 그룹 자식의 데이터를 보존했고 [#8395](https://github.com/edwardkim/rhwp/pull/8395)로 통합됐다. [당시 검토](../pr/archives/pr_8233_review.md)에도 `sungeo.hwp`의 전체 레코드가 60개에서 48개로 줄어드는 현상이 남았다. 2026년 11월 22일 열린 PR 19건과 이슈 이력을 대조했다. 잔여 손실을 처리하는 PR이 없어 [#8225의 추가 재현](https://github.com/edwardkim/rhwp/issues/8225#issuecomment-7041613421)을 기준으로 구현한다.

## 기준과 수정 범위

기준은 `upstream/devel`의 `5235b4d131`이다. CLI로 첫 문단에 글자를 넣고 저장한 뒤 CFB 구역의 레코드를 읽어 소유자 경로와 원문 바이트를 대조했다. `sungeo.hwp`에서는 그림 그룹 헤더 12개가 사라졌다. `20250130-hongbo.hwp`, `156618554_petfood_press.hwp`, `156636617_240617 2024년 5월 월간 수출입 현황(확정치).hwp`에서는 중첩 그림 헤더가 각각 1개씩 사라졌다. 각 헤더와 맨 위 도형 구성 요소에는 내용이 같은 독립 레코드가 있었다.

1. HWP 5.0 사양 4.3.8 표 66과 원래 레코드 트리에 따라 그림 개체 헤더와 구성 요소에 직속된 ParameterSet을 각각 읽고 원래 소유자 아래에 쓴다.
2. 그룹 자식·캡션의 독립적인 데이터, 첫 글자 장식의 편집·제거, 그림 하이퍼링크 변환을 함께 검증한다.
3. 실제 HWP 편집·저장·재열기를 두 차례 수행한다. 네 원본과 정상 대조군에서 구역별 소유 경로·순서·전체 바이트를 비교한다. Native CLI와 새로 빌드한 WASM, 집중 회귀·전체 Rust 회귀·lint로 확인한다.
