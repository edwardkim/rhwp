## 1. 목표

빈 host 문단의 다행 RowBreak 표에서 저장 선언 높이의 근소 초과가 실제 행 분할 검토보다 먼저
통짜 이월을 결정하는 문제를 고친다. 다만 과거 #3674 실험이 보여 준 것처럼, 표 셀의 줄높이가
과대측정된 상태에서 분할 진입만 넓히면 다른 문서의 행·각주 소유권이 깨진다.

따라서 다음 선후 관계를 지킨다.

1. 셀 콘텐츠와 행높이 측정을 한컴 PDF 실물과 정합시킨다.
2. 측정 정합 뒤에도 남는 declared 선이월만 분할 스캔으로 보낸다.
3. HWP 저장 증거가 없는 HWPX에도 동일한 구조 규칙을 적용하되, 1×1 개체 표와 첫 조각을
   안전하게 구성할 수 없는 표는 기존 이월을 유지한다.

페이지 수만 383으로 맞추는 상수·관용치 조절은 하지 않는다. 표의 실제 높이와 각 물리 페이지의
콘텐츠 소유권이 한컴 PDF와 맞는지를 완료 기준으로 삼는다.

## 4. 가설과 판정 순서

### H1 — 셀 줄높이 측정 정합

현재 문제 셀은 저장 LINE_SEG의 줄높이와 줄간격을 합산해 약 24.5px pitch를 만들며 16줄을
392.3px로 측정한다. PDF 실물은 같은 16줄을 약 301.2px, 줄당 약 18.8px로 배치한다.

Stage 1에서 해당 셀을 `section/paragraph/table/row/cell` 좌표로 식별하도록 진단을 보강하고,
각 줄의 `line_height`, `line_spacing`, `vpos` 간격, 최대 글자 크기, 문단 줄간격 종류를 함께 기록한다.
저장값 자체를 정답으로 간주하지 않고 PDF bbox와 대조해 어떤 성분이 중복 또는 과대 소비되는지
확정한다.

### H2 — 측정 수정 뒤 declared gate 재판정

`pi=23`처럼 한컴이 통째 배치한 표는 측정 높이가 정상화되면 declared 선이월 조건을 우회하기 위한
특례 없이 현재 쪽에 들어가야 한다. Stage 2 결과를 적용한 뒤 `pi=14`와 `pi=23`의 분기 로그를 다시
수집해 문턱 문제만 남겼는지 확인한다.

### H3 — 분할 가능성을 먼저 확인하는 일반 규칙

측정 정합 뒤에도 `pi=14`처럼 현재 쪽에서 첫 조각을 만들 수 있는 다행 RowBreak 표가 남으면,
`declared_overflows_current` 하나로 즉시 이월하지 않는다. 실제 fragment scan이 의미 있는 첫 조각을
만들 수 있는지 확인하고, 가능할 때만 현재 쪽에서 분할을 시작한다.

- `row_count > 1`, RowBreak, 빈 host, 자리차지 표라는 구조 경계를 유지한다.
- 첫 블록/행 내부 컷과 각주 예약을 기존 scanner가 안전하게 계산하지 못하면 기존 이월을 유지한다.
- 1×1 개체 표(#874·#2439), 단일행 선언 신뢰(#3236), 표 각주·reset 경계(#3738)는 제외한다.
- 전역 tolerance 확대나 특정 `pi`·파일명·쪽수 조건은 사용하지 않는다.

## 5. 단계

### Stage 1 — 식별 가능한 RED 계약과 기준선 고정

1. `RHWP_DIAG_ROWH`에 이슈 좌표를 식별할 최소 문맥을 추가하거나 동등한 테스트 전용 계측을 만든다.
2. `pi=23`의 줄 수는 16으로 유지되지만 높이 성분이 PDF와 어긋나는 RED를 고정한다.
3. `pi=14`가 fragment scan 전에 `DIAG_ADVC`로 이월되는 RED를 고정한다.
4. HWP/HWPX 페이지 수와 문제 구간의 텍스트 소유 순서를 기준선으로 기록한다.

Stage 1은 동작 변경 없이 진단과 RED 계약만 추가한다.

### Stage 2 — 셀 높이 측정 정합

1. `height_measurer`, `table_layout`, 조판/렌더 공용 줄높이 경로에서 실제 중복 성분을 제거한다.
2. 저장 LINE_SEG가 있는 셀과 없는 셀, CellBreak/RowBreak, 마지막 줄 trailing 간격의 기존 계약을
   분리해 유지한다.
3. 측정과 실제 렌더의 행높이 공식이 다시 갈라지지 않도록 공용 helper 또는 동일 테스트 계약으로
   묶는다.
4. `pi=23`의 같은 쪽 배치와 관련 실제 표 bbox를 재확인한다.

### Stage 3 — declared 선이월 일반화

Stage 2 뒤 남은 사례에만 적용한다.

1. declared 초과 시 즉시 이월하는 분기와 기존 fragment scan 사이의 판정을 구조화한다.
2. `pi=14`가 현재 쪽에서 첫 조각을 만들고 다음 쪽으로 이어지는지 고정한다.
3. 저장 LineSeg가 없는 HWPX에서도 같은 구조가 같은 결과를 내는지 확인한다.
4. 수정 전환을 제거하면 RED가 재발하는 red-check를 수행한다.

### Stage 4 — 광범위 회귀와 시각 판정

1. 편람 HWP/HWPX의 전체 페이지 수, 문제 구간 텍스트 소유 순서와 PDF 대응 페이지를 재측정한다.
2. 관련 focused 회귀와 `release-test` 전체를 실행한다.
3. 비공개 10k 코퍼스는 기준 head와 후보 head의 실패·쪽수·overflow 변화를 비식별 집계로 비교한다.
   원본이나 파일 식별 목록은 커밋·push·이슈·PR에 포함하지 않는다.
4. Native Skia 3종과 WASM 빌드를 수행한다.
5. PDF/SVG 시각 근거와 검토용 이미지는 Git 제외 경로 `output/3931/`에 생성해 작업지시자의
   시각 판정을 받는다.

## 8. 완료 조건

1. `pi=23`의 16줄과 줄바꿈은 유지하면서 셀·행 높이가 PDF 실물 방향으로 정합되고, 표가 한컴처럼
   현재 쪽에 배치된다.
2. `pi=14`는 declared 근소 초과만으로 새 쪽에 선이월되지 않고, 현재 쪽 첫 조각과 다음 쪽 꼬리를
   기존 fragment 계약으로 배치한다.
3. HWPX에서도 저장 되감김 증거 없이 같은 구조 규칙이 작동한다.
4. 편람 HWP 393쪽·HWPX 386쪽이 PDF 383쪽 방향으로 이동하며, 줄·표 소유권을 바꾸어 만든 숫자
   상쇄가 아니다.
5. #3738 33건을 포함한 focused·전체 회귀가 통과하고 신규 overflow-cell 악화가 없다.
6. 비공개 10k 비교에서 신규 parse/render 실패와 기존 오라클 정합 문서의 악화가 0건이다.
7. 작업지시자가 `output/3931/` 시각 증적을 판정한다.
