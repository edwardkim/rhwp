## 1. 목표

빈 host 문단의 다행 RowBreak 표에서 저장된 내부 `vpos` reset이 다음 물리 조각을 가리키는데도,
flow anchor가 약간 아래로 밀린 상태에서 declared 선이월이 실제 fragment scan보다 먼저 표 전체를
다음 쪽으로 보내는 문제를 고친다.

한컴 2020 PDF를 문단 단위로 다시 대조한 결과, 과거 #3927의 "16줄을 한 쪽에 18.8px pitch로
배치한다"는 판정은 잘못이었다. 실제로는 앞 문단 12줄과 뒤 문단 4줄이 서로 인접한 두 물리 쪽에
나뉘며, 줄 pitch는 저장값과 같은 약 24.5px이다. 따라서 전역 셀 줄높이를 줄이지 않는다.

다음 선후 관계를 지킨다.

1. 현재 저장 줄높이와 잘못된 통짜 이월을 동작 불변 래칫으로 고정한다.
2. HWP의 내부 reset·저장 span·다음 문단 되감김을 함께 충족하는 경우 flow anchor를 저장 anchor로
   재동기화해 기존 fragment scanner가 12+4 조각을 구성하게 한다.
3. `pi=14`의 declared 선이월과 HWPX 무증거 구조는 별도 단계에서 일반화한다.

페이지 수만 383으로 맞추는 상수·관용치 조절은 하지 않는다. 표의 실제 높이와 각 물리 페이지의
콘텐츠 소유권이 한컴 PDF와 맞는지를 완료 기준으로 삼는다.

## 4. 가설과 판정 순서

### H1 — 셀 줄높이 과대측정 가설: 기각

현재 문제 셀은 저장 LINE_SEG의 줄높이와 줄간격을 합산해 약 24.51px pitch를 만들며 16줄을
392.3px로 측정한다. PDF 직접 측정도 약 24.48px pitch이고, 16줄은 한 쪽이 아니라 12+4줄로
나뉜다. Stage 1 진단은 이 값을 보존해야 할 계약으로 고정한다.

### H2 — 내부 reset 표의 flow anchor 재동기화

`pi=23`은 저장 span 하단이 현재 쪽에 들어가지만 flow anchor가 저장 상단보다 약 27.5px 아래로
밀려 `saved_object_bottom_fits_current` 판정을 통과하지 못한다. 다행 RowBreak, 빈 host,
내부 저장 `vpos` reset, 다음 문단 되감김, 저장 span이 현재 쪽에 들어감이라는 구조 증거를 모두
요구한 뒤 저장 상단으로 anchor를 재동기화하고 기존 fragment scan으로 보낸다.

### H3 — 분할 가능성을 먼저 확인하는 일반 규칙

`pi=14`처럼 현재 쪽에서 첫 조각을 만들 수 있는 다행 RowBreak 표가 남으면,
`declared_overflows_current` 하나로 즉시 이월하지 않는다. 실제 fragment scan이 의미 있는 첫 조각을
만들 수 있는지 확인하고, 가능할 때만 현재 쪽에서 분할을 시작한다.

- `row_count > 1`, RowBreak, 빈 host, 자리차지 표라는 구조 경계를 유지한다.
- 첫 블록/행 내부 컷과 각주 예약을 기존 scanner가 안전하게 계산하지 못하면 기존 이월을 유지한다.
- 1×1 개체 표(#874·#2439), 단일행 선언 신뢰(#3236), 표 각주·reset 경계(#3738)는 제외한다.
- 전역 tolerance 확대나 특정 `pi`·파일명·쪽수 조건은 사용하지 않는다.

## 5. 단계

### Stage 1 — 식별 가능한 RED 계약과 기준선 고정

1. `RHWP_DIAG_ROWH`에 이슈 좌표를 식별할 최소 문맥을 추가하거나 동등한 테스트 전용 계측을 만든다.
2. `pi=23`의 16줄과 24.5px pitch가 PDF와 일치함을 고정한다.
3. 현재 두 셀 문단이 같은 page index 291을 소유하는 실패와, 정답인 인접 쪽 소유를 RED로 고정한다.
4. HWP 393쪽 기준선과 한컴 2020 PDF 383쪽 계약을 각각 고정한다.

Stage 1은 동작 변경 없이 진단과 RED 계약만 추가한다.

### Stage 2 — HWP 내부 reset의 저장 anchor 복원

1. `typeset.rs`의 declared 이월 직전에서 다행 RowBreak·빈 host·내부 저장 reset·다음 문단
   되감김·현재 쪽에 들어가는 저장 span을 함께 검사한다.
2. 구조 증거가 완결된 경우에만 flow anchor를 저장 상단으로 재동기화하고 기존 fragment scanner가
   물리 조각을 만들게 한다.
3. `pi=23`의 첫 문단과 둘째 문단이 인접한 서로 다른 쪽을 소유하는지 확인한다.
4. 저장 24.5px pitch와 16줄 전체 높이는 변경하지 않는다.

### Stage 3 — declared 선이월 일반화

Stage 2 뒤 남은 `pi=14`와 HWPX 사례에만 적용한다.

1. declared 초과 시 즉시 이월하는 분기와 기존 fragment scan 사이의 판정을 구조화한다.
2. `pi=14`가 현재 쪽에서 첫 조각을 만들고 다음 쪽으로 이어지는지 고정한다.
3. 저장 LineSeg가 없는 HWPX에서도 같은 구조가 같은 결과를 내는지 확인한다.
4. 수정 전환을 제거하면 RED가 재발하는 red-check를 수행한다.

### Stage 4 — 광범위 회귀와 시각 판정

1. 편람 HWP/HWPX의 전체 페이지 수, 문제 구간 텍스트 소유 순서와 PDF 대응 페이지를 재측정한다.
2. 관련 focused 회귀와 `release-test` 전체를 실행한다.
3. 비공개 10k 코퍼스는 기준 head와 후보 head의 실패·쪽수·overflow 변화를 비식별 집계로 비교한다.
   원본이나 파일 식별 목록은 커밋·push·이슈·PR에 포함하지 않는다.
4. Native Skia 3종과 WASM 빌드를 수행한다.
5. PDF/SVG 시각 근거와 검토용 이미지는 Git 제외 경로 `output/3931/`에 생성해 작업지시자의
   시각 판정을 받는다.
