- 상태: 메인테이너가 2가지 일반 사각형 / 16가지 글상자 구조의 식별 구현 착수를 승인함.

  바탕쪽 fallback·선 억제 A 제거·다른 페이지 조판 정정을 함께 수행하지 않는다.

## 1. 먼저 정할 검증 공간

사각형 기하를 고정하고 **직접 소유한 내부 문단 구조**를 검사한다. 개체 수·글자 수·이미지 수가
몇 개인지에 따른 모든 문서 배열은 무한하므로, 아래 수는 판정에 필요한 유무 동치류의 수다.
도형 종류 전체나 손상 입력 전체를 망라한 수라고 주장하지 않는다.

- S: 유효한 내부 문단 영역의 소유 구조 유무. 빈 문단도 영역 존재에 포함한다.
- B: 배경 채움 이미지 유무. 단색·패턴·그라데이션은 이번 축에서 '배경 이미지 없음'에 속한다.
- T: 해당 영역의 직접 소유 문단에 글자 데이터 유무. 공백을 trim해서 구조를 판단하지 않는다.
- I: 해당 문단에 직접 삽입한 그림 컨트롤 유무. 배경 이미지는 세지 않는다.
- O: 해당 문단에 그림 이외의 컨트롤 유무. 표·수식·도형·필드 등을 포함한다.

S가 없으면 T/I/O는 모두 없음이어야 한다. S가 있으면 T/I/O는 각각 독립적인 유무 3축이다.
따라서 `(영역 없음 1 + 영역 있음 2³) × 배경 이미지 2 = 18가지`다.

| 구조 | 글자 T | 삽입 그림 I | 기타 컨트롤 O | B 없음/있음 | 기대 구조 판정 |
| --- | --- | --- | --- | --- | --- |
| 영역 없음 | 없음 | 없음 | 없음 | 2가지 | 내부 문단 영역 없는 도형 |
| 영역 있음 | 없음 | 없음 | 없음 | 2가지 | 빈 내부 문단 영역 보존 |
| 영역 있음 | 있음 | 없음 | 없음 | 2가지 | 글자 포함 영역 보존 |
| 영역 있음 | 없음 | 있음 | 없음 | 2가지 | 그림 전용 영역 보존 |
| 영역 있음 | 있음 | 있음 | 없음 | 2가지 | 글자·그림 혼합 영역 보존 |
| 영역 있음 | 없음 | 없음 | 있음 | 2가지 | 기타 컨트롤 전용 영역 보존 |
| 영역 있음 | 있음 | 없음 | 있음 | 2가지 | 글자·기타 컨트롤 영역 보존 |
| 영역 있음 | 없음 | 있음 | 있음 | 2가지 | 그림·기타 컨트롤 영역 보존 |
| 영역 있음 | 있음 | 있음 | 있음 | 2가지 | 세 종류 혼합 영역 보존 |

글자·그림만 고려한 핵심 조합은 앞의 5행인 10가지다. 기타 컨트롤 때문에 나머지 8가지를 추가한다.
18가지는 의미상 조합이지 18개의 정상 한컴 fixture가 확보되었다는 뜻이 아니다.
표 안 그림처럼 중첩된 내용은 현재 소유자의 O에 속하고, 중첩 소유자의 구조를 별도로 검사한다.
O를 한 축으로 묶는 것은 분류 계약용이다. 표·수식 등 각각의 파서 경로를 모두 검증했다는 뜻은 아니다.

## 2. 정상 조합과 별도로 검사할 경계

다음은 18가지에 억지로 포함시키지 않고 별도 경계 시험으로 관리한다.

1. 영역 없음과 '빈 문단 하나가 있는 영역'은 다르다.
2. 영역 선언은 있지만 문단이 0개인 입력: 포맷상 유효성을 확인하고, 정상 빈 문단과 구분해 보존 여부를 정한다.
3. 영역 레코드 잘림·파싱 실패: 정상 빈 글상자로 간주하지 않는다. 기존 오류/진단 정책을 유지한다.
4. 캡션·그룹 자식·표 셀의 리스트: 현재 도형이 소유하지 않으면 현재 도형의 영역으로 가져오지 않는다.
5. 실선/선 없음 변경은 구조 판정에 영향을 주지 않는다. 이번 샘플의 실선 지정은 제품 기본값 변경이 아니다.

## 3. 구현 순서와 판정 원칙

1. **원본 → 파서 → IR 대조가 먼저다.** 기존 편람 HWP/HWPX와 메인테이너가 요청한 A4 샘플을 사용한다.
   기존 자료로 각 행의 확보/미확보를 표시하며, 전수 코퍼스 조사나 18개 파일 자동 생성을 먼저 하지 않는다.
2. HWP는 해당 도형 소유의 리스트 레코드와 경계를, HWPX는 해당 도형 소유의 drawText/subList를 확인한다.
   문단 파싱 결과가 없다는 이유만으로 원본 구조도 없었다고 판정하지 않는다.
3. IR 구조 계약을 확정한 후 하나의 공통 판정 경로를 구현한다. 기하 Rectangle은 유지하고
   내부 영역의 존재를 별도 의미로 보존한다. 중복 boolean이나 종류 필드를 추가해 기존 구조와 모순시키지 않는다.
4. 내용(T/I/O)·배경(B)은 판정 입력으로 사용하지 않는다. 시험 행을 선택하고 보존 결과를 검사하는 데만 쓴다.
5. 기존 `Option<TextBox>`를 감싸는 함수만 추가하고 문제가 해결됐다고 하지 않는다.
   잘못된 판정이 있으면 원본 해석/소유권/소비 지점 중 실제 원인을 수정하고 수정 전 실패를 증명한다.
6. 조판부호는 내부 레이아웃 노드 이름이 아니라 확정된 원본 컨트롤 의미를 사용하도록 검토한다.
   표시 문구 변경은 한컴에서 확인된 기대 판정이 있어야 진행한다. 렌더링 편의를 위한 TextBox 노드와
   한컴 UI의 개체 종류가 일치한다고 전제하지 않는다.

판정 순서 초안:

```text
현재 도형의 소유 구조를 정상적으로 읽을 수 있는가?
  아니오 → 기존 파싱 오류/진단 경로 (정상 일반 도형으로 위장 금지)
  예 → 소유 내부 문단 영역이 존재하는가?
        없음 → 내부 영역 없는 도형
        있음 → 내부 영역 있는 도형 (비어 있어도 보존)
```

메인테이너 승인으로 이번 rhwp 식별 계약은 사각형 기하 + 내부 영역 없음이면 일반 사각형,
내부 영역 있음이면 글상자로 확정한다. 한컴 COM UserDesc와 동일한 값이라고 주장하지 않는다.
첫 절편은 IR 공통 식별과 조판부호 소비를 연결하고, 파서 변경은 구조 손실이 재현된 지점에 한정한다.

## 4. 현재 증거와 한계

- A4 v3 HWP/HWPX는 한컴 직접 저장·재열기 성공, 같은 문단의 도형 3개다.
- baseline 파싱 결과: 글자 포함 내부 영역 1개, 내부 영역 없음 1개, 빈 내부 영역 1개.
  배경 이미지 없음 조건에서 서로 다른 3행만 확인됐다. 나머지 15행은 이 샘플로 검증되지 않았다.
- 배경 이미지와 그림 전용 글상자 조합은 추가 근거 확인이 필요하다.
- 한컴 COM UserDesc는 3개 모두 사각형이다. 가로 글상자 생성 액션과 내부 편집 성공을
  한컴 UI의 별도 종류 식별 성공으로 과장하지 않는다.
- 현재 코드의 TextBox 렌더 노드 → `[글상자]` 경로는 확인했다. Studio에서 세 개 모두
  표시된다는 관찰은 실행 WASM/열린 파일을 확인한 재현이 아직 필요하다.

## 5. 승인 후 절편의 완료 기준

- 18가지 검증 행과 추가 경계의 기대 결과, 실제 근거 유무를 구분한다.
- 구조 판정의 입력에 글자 수·이미지 유무·배경·선 스타일이 들어가지 않는다.
- 실제 잘못된 판정 또는 구조 손실의 실패 시험을 확보한 지점만 제품 변경한다.
- 새 회귀는 `tests/cases/`에 추가하고 source 본문에 넣지 않는다.
- 내부 모델 시험, 한컴 파일 유효성, 한컴 UI 판정, Studio 표시 결과를 별도로 보고한다.
- PR 전체 검증·WASM 갱신·원격 게시·commit/push는 이번 산정 단계에서 수행하지 않는다.

이 변형 공간과 판정 계약에 대한 구현 착수 승인을 받았다. 기존 baseline과 보존 브랜치는 유지한다.
