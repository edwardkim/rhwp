## 한 단위의 준비 작업

1. 배포 대상 manifest·lockfile의 0.9.0 일치, main ancestry와 릴리즈 채널 계약을 확인한다. 내부 0.1 패키지와 upstream 기반 fork 버전은 각 패키지 계약을 유지한다.
2. v0.8.7 이후 4,852개 커밋의 저자·공동 저자·PR 및 cherry-pick 출처를 대조한다. 이메일을 포함한 원시 자료는 ignored `output/release-v0.9.0/`에 두고 공개 원장에는 계정·hash·출처만 남긴다. 합쳐진 원 PR과 별칭을 누락하지 않으며 미확인 항목은 명시적으로 해결한다.
3. 한국어·영어 CHANGELOG와 릴리즈 노트, npm core/editor 및 확장 프로그램 안내를 준비한다. PDF 기본 지원·암호·선택 쪽·두 배치 모드·자원 정책·Worker·실제 지원 경계와 오류 대응을 현재 코드로 확인한다.
4. 배포 manifest, 기여자 원장, 문서 링크와 릴리즈 계약 검사를 실행한다. Native와 fresh WASM의 실제 PDF 예제 및 npm/VSIX·브라우저 패키지 구성을 확인한다. 제품 조판 코드를 바꾸지 않는 한 전체 조판 회귀를 중복 수행하지 않는다.
5. 로컬 결과와 남은 원격 검증을 보고한다. macOS·Windows·ARM 등 5개 공식 바이너리와 게시 채널은 정확한 후보의 승인된 verify-only CI로 확인한 뒤 배포 판단한다.

## 배포 직전 재확인

준비 후보에는 파일 차이가 없는 v0.8.7 main 이력을 merge commit `2f95b7d757`으로 연결했다.
준비 PR도 **merge commit**으로 통합해야 이 ancestry가 보존된다. squash/rebase merge로 대체하지 않는다.

승격 inventory의 6개 미등록 실행 표면을 정책에 연결한다. 기존 composite는 실제 package caller,
write 권한이 있는 CI Impact controller는 read-only 실행 계약, 나머지는 실제 manual run을 요구한다.
Layout advisory는 skip도 green이 될 수 있어 실제 완료 verdict와 누락된 sparse build 자원을 보강한다.
원격 dispatch·권한·검사 기준 완화는 하지 않는다. 이 준비에는 CI 실행 증거 정책 변경이 포함되므로
후속 기록은 `post_merge.md`의 **옵션 2**로 별도 기록 PR에 남긴다. 원 준비 PR에 문서-only trailing
commit을 추가해 Full CI를 반복하지 않는다.

추가 source archive 점검에서 `rhwp-jpeg-encoder`의 중복 후보를 발견했다. #8360의 정리 이후
#8389(`c417310cab`)에서 원래 후보를 남긴 채 `Cargo.toml.orig` 포함 후보가 다시 추가된 이력을
확인했다. 두 include 목록의 합집합과 모든 의존성을 보존해 후보를 하나로 정리한다. 제품 codec이나
Cargo 버전은 바꾸지 않는다. crates.io 일정은 아래 2026-11-08 추가 지시에 따라 0.9.0에 포함한다.

준비 중 devel에 새 기능이 통합되면 최종 승격 SHA로 기여자·변경 목록을 다시 산출한다. 릴리즈 날짜는 실제 게시 시 확정한다. #8745의 보호 브랜치 전체 보안 분석은 아직 별도 후속 조건이며, 이번 준비만으로 완료했다고 기록하지 않는다.
