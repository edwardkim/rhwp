## 2. 문제 요약

`3-10월_교육_통합_2022.hwp` 11쪽 문18) 해설의 시그마(∑)에서 하한 `k=1`의 `=1`이 본문으로 밀리고, 상한 `6`이 `1`의 위첨자로 붙어 깨진다.
사용자 신고: "시그마에서 인자가 안보임 k만 보임. 시작/끝(범위가) 표시 안됨 - 위치가 달라요".

같은 문서 안에서도 본문 수식과 미주(해설) 내부 수식의 스크립트 표기가 다른 것이 직접 원인이다.

| 위치 | 스크립트 | 결과 |
|------|----------|------|
| 본문 (para 0.161 control[1]) | `sum _{k=1} ^{6} (k+1) ^{2}` (브레이스) | 정상 |
| 미주 5개 문단 내부 | `sum_k=1 ^6 (k+1)^2` (브레이스 없음, 공백 구분) | 깨짐 |

페이지 11은 해설(미주) 영역이라 깨진 미주 수식이 표시된다.

## 3. 재현 구조

```text
원본 HWP: samples/3-10월_교육_통합_2022.hwp
정답 PDF: pdf/3-10월_교육_통합_2022-2022.pdf (있을 경우)
페이지:   11쪽 (인덱스 10), 문18) 해설
```

미주 내부 수식 스크립트 (export-svg 경로 계측으로 확인):

```text
sum_k=1 ^6 (k+1)^2 - sum_k=1 ^5 (k-1)^2
= 7^2 + sum_k=1 ^5 (k+1)^2 - sum_k=1 ^5 (k-1)^2
= 49 + sum_k=1 ^5 left { (k+1)^2 - (k-1)^2 right}
= 49 + 4 sum_k=1 ^5 k = 49 + 4 times { 5 times 6 } over 2 = 109
```

`sum_k=1 ^6` 파싱 결과 (현재):

```text
BigOp{ ∑, sub: Text("k"), sup: None }, Symbol("="), Superscript{ base:1, sup:6 }, ...
```

기대 결과:

```text
BigOp{ ∑, sub: Row[k,=,1], sup: 6 }, Paren(k+1)^2, ...
```

## 4. 근본 원인

HWP 수식 스크립트에서 일반 공백은 시각적으로는 무의미하지만 구문적으로는 **무브레이스 인자(피연산자)의 경계 구분자**다.
`sum_k=1 ^6` 은 ∑(하한 `k=1`, 상한 `6`) 을 의미하며, `1` 뒤의 공백이 하한 인자의 끝을 표시한다.

그러나 현재 구현은 다음 두 지점에서 이 규칙을 무시한다.

1. `src/renderer/equation/tokenizer.rs` `skip_spaces` 가 일반 공백(` `, `\t`, `\n`, `\r`)을 토큰으로 남기지 않고 버린다 (#505: 개행을 의미 없는 포맷팅으로 간주). 가시 공백(`~`, `` ` ``, `#`, `&`)만 Whitespace 토큰으로 보존된다.
2. `src/renderer/equation/parser.rs` `parse_single_or_group` 가 무브레이스 인자를 **단일 토큰 하나만** 취한다 (LaTeX식). `sum_k=1` 에서 `_` 뒤의 첫 토큰 `k` 만 하한으로 잡고, `=1` 은 본문으로 흘려보낸다.

두 요인이 겹쳐, 공백으로 끝나는 무브레이스 첨자 인자가 단일 토큰으로 잘린다.

> #505 는 공백의 **시각적 무의미성**과 **구문적 무의미성**을 혼동해 일반 공백을 완전히 버렸다. 이것이 회귀의 뿌리다.

## 5. 작업 범위

- 무브레이스 `_`/`^` 첨자 인자가 공백 경계까지 토큰 run 을 취하도록 수정
- 대상 미주 수식(시그마 상·하한) 정상 렌더 확인
- 기존 브레이스 표기(`sum _{k=1} ^{6}`), 가시 공백(`~`), 단일 토큰 첨자(`x^2`, `a_n`) 회귀 방지
- 단위 테스트(파서 AST 고정) 추가

이번 이슈의 비범위:

## 7. 구현 방향 후보

### 후보 A: 토크나이저가 일반 공백을 경계 토큰으로 보존

`skip_spaces` 가 공백을 버리는 대신, 일반 공백 run 을 하나의 경계 토큰(예: `TokenType::Boundary` 또는 기존 Whitespace 의 비가시 변형)으로 emit 한다.
파서는 이 경계 토큰을 (1) 무브레이스 인자 종료 신호로 사용하고 (2) 그 외 위치에서는 시각 폭 0 으로 무시한다.

- 장점: HWP 문법(공백 = 토큰 구분자)에 가장 정직하게 대응. 첨자뿐 아니라 다른 무브레이스 인자에도 일관 적용 가능.
- 위험: 공백 토큰이 늘어나면서 기존 파서 루프 곳곳에서 공백 skip 처리를 추가해야 함. 누락 시 회귀 가능.

### 후보 B: 파서의 무브레이스 첨자 인자만 greedy run 으로 변경

토크나이저는 그대로 두고, `parse_single_or_group`(또는 첨자 전용 분기)에서 무브레이스일 때 `^`/`_`/구조 명령/괄호/`{`/EOF 등 자연 경계를 만날 때까지 단순 토큰(Command/Number/Symbol/Text)을 run 으로 묶는다.

- 장점: 변경 범위가 파서 한 곳으로 좁다. 토크나이저 영향 없음.
- 위험: 일반 공백 토큰이 없으므로 `sum_k=1 ^6` 과 `sum_k (k+1)` 같이 "공백으로 의도적으로 끊은" 경우를 구분 못 함. 자연 경계(괄호/`^`)에만 의존하면 과소·과대 소비 위험.

### 후보 C: A + B 결합 (기본안)

토크나이저가 일반 공백을 비가시 경계 토큰으로 보존(A)하고, 파서의 무브레이스 첨자 인자가 "경계 토큰 또는 `^`/`_`/구조 경계" 를 만날 때까지 run 소비(B)한다.

- 장점: 공백 의도(`sum_k=1 ^6`)와 자연 경계(`sum_k=1(k+1)`)를 모두 정확히 처리. 정답에 가장 가깝다.
- 위험: 변경 2개 모듈. 회귀 검증 범위가 가장 넓다 — 기존 수식 테스트 전수 통과 필요.

## 8. 기본안

후보 C 를 기본으로 한다. 단, 토크나이저 공백 보존은 **비가시(폭 0) 경계 토큰**으로 한정해 #505 의 "공백은 시각적으로 무의미" 의도를 유지하고, 파서의 무브레이스 인자 소비 규칙만 경계 기준으로 확장한다.

```text
1. 현재 깨짐을 파서 AST 단위 테스트로 고정한다 (sum_k=1 ^6 → 현재 잘못된 AST).
2. 토크나이저가 일반 공백을 비가시 경계 토큰으로 emit 하도록 보강한다.
3. 파서가 경계 토큰을 무브레이스 인자 종료로 인식하고, 그 외 위치에서 무시하도록 보강한다.
4. 무브레이스 첨자 인자가 경계까지 run 을 묶도록 한다.
5. 기존 수식 테스트(브레이스/가시공백/단일첨자) 전수 회귀 확인.
6. 대상 미주 시그마 시각 렌더 확인.
```
