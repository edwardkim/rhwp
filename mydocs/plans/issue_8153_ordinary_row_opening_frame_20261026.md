# #8153: 여러 저장 프레임을 가진 일반 행의 첫 물리 상자

[이어받기 선행 분석](issue_8153_ordinary_row_continuation_frame_20261026.md)의
원 해결 이슈·통합 PR·메인터너 보정과 같은 계약을 계속 확인한다. 원본 두 편람,
독립 2024 Print PDF와 임계값은 유지한다. upstream/devel 동기화와 원격 변경은 하지 않는다.

## 실제 원인과 독립 기대

고정 `9a910f98e463b65b23978612165c3461584ff8ff`의 전쪽 Native에서
316·326·344·352쪽에 세로선 끝의 미대응 픽셀이 남았다. 양쪽 형식 모두 같은
법령 대조표 section 11 / para 3 / 103행×2열의 새 행을 쪽 중간에서 연다.
독립 PDF의 세 세로선은 모두 y=94.298665에서 644.263997px까지다.
수정 전 원본 HWPX 12·22·54·71행의 양쪽 칸은 각각
157036·68028·53411·102320HU이며 실제 저장 줄은 다음 여러 쪽의 경계를 가진다.

`stored_ordinary_row_end_frame`은 첫 컷 뒤에 한 저장 프레임만 남았는지를 확인한다.
여러 프레임이 남으면 현재 컷·물리 예산·원본 일반 셀의 유효성과 관계없이 거절한다.
실제 316쪽은 현재 앞 행의 점유 381.64px 뒤 새 행의 내용 74.88px와 패딩을 받고
종료하지만, 같은 원본의 독립 세로선은 현재 쪽의 물리 상자 끝까지 이어진다.
남은 **내용 컷 수**로 현재의 **수용 물리 공간**을 거절하는 가정을 점검한다.

## 공통 생산·소비와 검증 순서

`원본 일반 행과 유효한 컷 → scan의 동일 physical available/앞 행 점유 →
stored_ordinary_row_end_frame → consumed/end_row_height_override/split_end_reserved →
emit 수용 원장/다음 잔여 → 실제 부분 표`를 따른다. 첫 조각도 여러 쪽으로 이어받는
원본 최소를 사용하되 현재 예산 안에서 수용한다. 다음 내용·물리 잔여는 기존 원장을
소비한다. 뒤 내용 컷 검증이나 잔여 생산자의 다른 종료 계약을 무작정 완화하지 않는다.
문서·쪽 번호·독립 PDF 좌표를 제품 조건에 넣거나 paint 선만 늘리지 않는다.

먼저 같은 정식 테스트 원문으로 고정 Native의 실제 종료선 FAIL을 확인한다.
앞뒤 컷·행/셀 소유·원본 HU·세 열 경계와 독립 ±2px 종료선을 함께 보호한다.
해당 쪽의 기존 Native/fresh WASM raw는 모두 98% 이상이다. 구현 후 동일 원문과
기존 97건, 영향·앞뒤 종료, 직접 overlay와 전쪽 Native를 대조해 하락·빈 쪽·
내용 누락·중복을 확인한다. 이어서 같은 코드의 표준 fresh WASM을 검증한다.
현재 계획은 수정 후 PASS 또는 전쪽 100% 달성 기록이 아니다.

진단 원문·실제 실행·독립 PDF 추출·producer 해시는 ignored 작업 루트의
`remaining-raw100-diagnostic/p316-current-pagination/`와
`handbook-ordinary-row-opening-candidate/`에 보존한다.
