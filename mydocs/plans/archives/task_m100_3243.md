# rhwp-studio 도구 상자 너비 맞춤 설계

- 대상: `rhwp-studio` 도구 상자 `#icon-toolbar`
- 승인: 좁은 너비에서 가로 스크롤이나 버튼 축소 대신 여러 행으로 줄바꿈

## 목표

도구 상자의 명령을 숨기거나 축소하지 않고 현재 컨테이너 너비 안에 모두 배치한다.
데스크톱에서 내용이 들어가면 기존 한 행을 유지하고, 너비가 부족할 때만 논리 그룹 단위로
다음 행으로 줄바꿈한다.

## 확인된 원인

실제 브라우저의 현재 Studio viewport에서 `#icon-toolbar`의 `clientWidth`는 883px이고
`scrollWidth`는 1039px다. 1023px 이하 반응형 규칙은 라벨과 버튼 너비만 줄이며 tablet
구간의 `#icon-toolbar`에 wrap 또는 overflow 처리를 지정하지 않는다. 기본
`overflow: visible`이 유지되어 156px가 컨테이너 밖으로 넘친다.

## 선택한 설계

- `#icon-toolbar`는 너비가 부족할 때 `flex-wrap: wrap`으로 여러 행을 만든다.
- 각 `.tb-group`은 하나의 flex item으로 유지하여 그룹 내부 버튼은 서로 다른 행으로
  나뉘지 않는다.
- wrap 구간에서는 고정 `height`를 제거하고 `min-height`만 유지하여 실제 행 수만큼
  도구 상자 높이가 늘어나게 한다.
- 모바일에서도 동일한 wrap 정책을 사용하며 기존 horizontal scroll 정책은 제거한다.
- top-level의 직접 자식 `.tb-sep`는 wrap 구간에서 숨긴다. separator가 행의 처음이나
  끝에 홀로 배치되는 현상을 막기 위해서다.
- 머리말/꼬리말, 주석, 회전 등 mode 전용 group과 group 내부 separator는 기존 동작을
  유지한다.

## 보존 계약

- 버튼 순서, 문구, 아이콘, command wiring을 변경하지 않는다.
- 데스크톱에서 내용이 한 행에 들어가면 기존 높이와 라벨 표시를 유지한다.
- 1023px 이하에서 적용되는 라벨 숨김과 축소 버튼 정책을 유지한다.
- 도구 상자의 표시/숨기기 command와 편집 영역 focus 보존 listener를 변경하지 않는다.
- 새 UI component, JavaScript layout 측정, ResizeObserver를 추가하지 않는다.

## 검증

1. 반응형 E2E가 desktop, tablet, mobile, mobile-landscape의
   `toolbar.scrollWidth <= toolbar.clientWidth`를 확인한다.
2. 내용이 한 행에 들어가지 않는 viewport에서는 서로 다른 button `offsetTop`이 존재해
   실제 줄바꿈이 발생했는지 확인한다.
3. 기존 Studio Node test와 TypeScript/Vite production build를 실행한다.
4. 실제 브라우저의 실제 883px viewport에서 screenshot으로 두 행 배치, 잘림 없음, 버튼 순서
   유지를 확인한다.
