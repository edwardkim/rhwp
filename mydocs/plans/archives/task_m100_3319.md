# Task M100 #3319 — SO-SUEOP HWPX OLE 개체 선택

- Issue: [#3319](https://github.com/edwardkim/rhwp/issues/3319)
- Branch: `task/3319-hwpx-ole-selection`
- 기준: `upstream/devel` `84523993329690c820147dcc255839daeb88826c`

## 목표

`samples/SO-SUEOP.hwpx` 1쪽에서 렌더된 그림형 OLE를 클릭하면 rhwp-studio가 텍스트 caret 또는
무반응으로 끝나지 않고 해당 OLE 개체를 선택한다.

## 범위와 완료 기준

1. 실제 fixture를 여는 browser E2E가 OLE control layout과 클릭 좌표를 확보한다.
2. 클릭 뒤 선택 ref가 `type: 'ole'`이고 문서상 `(sec, para, control)` 참조가 layout control과
   일치한다.
3. 기존 `한셀OLE` 선택·캡션·caret 회귀를 유지한다.

다음은 이번 작업에서 변경하지 않는다.

- HWP3 `Picture`와 HWPX `OLE`의 IR 타입 통일
- OLE 컨테이너 내부 콘텐츠 편집 또는 새 OLE 기능
- 외부 연결 그림의 적재·fallback 정책(#3302, #3313)

## 단계

1. `SO-SUEOP.hwpx`로 Studio 선택 E2E를 재현하고 layout·선택 상태를 기록한다.
2. RawSvg/이미지형 OLE가 page control layout에서 원본 control 메타를 보존하는지 확인하고 최소
   보정을 적용한다.
3. focused browser E2E와 영향을 받은 Rust/WASM 검증을 실행하고 결과를 단계 보고서에 기록한다.

## 위험과 판정

같은 화면 좌표에 여러 개체가 겹치면 화면 최상단 렌더 정렬키가 선택 대상과 같아야 한다. 따라서
문제 해결을 위해 일반 텍스트 hit-test보다 OLE를 무조건 우선시키는 전역 우회는 적용하지 않는다.
fixture 기반 E2E가 실제 원본 control ref까지 검사해 선택 대상 혼동을 막는다.
