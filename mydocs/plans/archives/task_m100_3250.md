# rhwp-studio 문서 복구 대화상자 화면 내 배치 설계

- 대상: `rhwp-studio` 문서 복구 대화상자
- 승인: 복구 후보 목록만 화면 안에 묶어 세로 스크롤

## 목표

복구 후보가 많거나 파일명이 길어도 문서 복구 대화상자가 viewport 밖으로 나가지 않게 한다.
제목, 안내 문구, `복구`·`삭제`·`나중에` 동작은 항상 보이며 복구 후보 목록만 세로로
스크롤한다.

## 확인된 원인

실제 브라우저의 현재 `882 × 758` viewport에서 복구 후보 10개가 표시될 때 대화상자 높이는
846px이다. 대화상자 위쪽은 `-44px`, 아래쪽은 `802px`까지 놓이며 본문과 하단 버튼이
화면 밖으로 나간다.

공통 `.dialog-wrap`과 `.dialog-body`에는 데스크톱 viewport 높이 제한이 없다. 복구 UI도
후보 목록을 일반 block으로 생성해 후보 수만큼 본문이 계속 늘어난다.

## 선택한 설계

- 복구 대화상자에 전용 class를 부여해 다른 대화상자와 레이아웃 계약을 분리한다.
- 전용 대화상자는 viewport 여백을 남긴 최대 높이를 갖는 세로 flex container로 만든다.
- 제목과 하단 버튼은 축소하지 않고 고정 영역으로 유지한다.
- 본문은 안내 문구와 후보 목록을 세로로 배치하고, 후보 목록에만 남은 높이를 할당한다.
- 후보 목록은 `overflow-y: auto`와 touch momentum scrolling을 사용한다.
- 긴 파일명은 후보 항목 너비 안에서 줄바꿈해 가로 overflow를 만들지 않는다.
- 기존 색상, 간격, 버튼 순서, 복구 선택 동작과 모바일 bottom-sheet 표현은 유지한다.

## 보존 계약

- 후보 정렬, 기본 선택 후보, `복구`·`삭제`·`나중에` 의미를 변경하지 않는다.
- 자동 복구 정책이나 draft 삭제 정책을 변경하지 않는다.
- 공통 `ModalDialog`의 다른 소비자에게 viewport 또는 scroll 정책을 강제하지 않는다.
- 새 JavaScript 높이 측정이나 resize listener를 추가하지 않고 CSS layout으로 해결한다.
- 후보가 적을 때 기존 대화상자 크기보다 불필요하게 커지지 않는다.

## 검증

1. 회귀 테스트가 복구 전용 class, viewport 최대 높이, 후보 목록 전용 scroll 계약을 확인한다.
2. 테스트를 먼저 추가해 현행 코드에서 실패한 뒤 최소 구현으로 통과시킨다.
3. 복구 UI 집중 테스트, TypeScript 검사, Vite production build를 실행한다.
4. 현재 실제 브라우저 viewport에서 다음 runtime 조건을 확인한다.
   - 대화상자 위·아래가 viewport 안에 있음
   - 제목, 안내 문구, 하단 버튼이 동시에 보임
   - 후보 목록의 `scrollHeight`가 `clientHeight`보다 크며 실제로 스크롤됨
   - 긴 파일명이 대화상자 가로 폭을 넘지 않음
