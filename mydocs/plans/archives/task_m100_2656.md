# 수행계획서 — Chrome/Edge 확장 설정 보존과 저장 실패 처리 (M050 #2656)

- **이슈**: [edwardkim/rhwp#2656](https://github.com/edwardkim/rhwp/issues/2656)
- **브랜치**: `codex/issue-2656-extension-settings` (`upstream/devel` a803f079 기준)
- **작성일**: 2026-07-21
- **승인**: 2026-07-21 사용자가 이슈 등록 후 작업 진행을 지시함

## 1. 목표

Chrome/Edge 확장에서 사용자가 저장한 `autoOpen=false`를 설정 페이지 재진입, Service Worker
재시작, Chrome 재실행, 확장 업데이트/Reload와 설정 키 부분 누락 이후에도 보존한다. 저장에
실패했는데도 성공으로 표시하는 옵션 UI와 비동기 초기 로딩 전에 DOM 기본값을 다시 저장할 수 있는
경쟁 조건을 함께 제거한다.

정상 Chrome 업데이트가 설정을 직접 초기화한다는 사실은 현재 확인되지 않았다. 따라서 외부 원인을
추정으로 고정하지 않고, 정적으로 확인한 결함과 저장소 수명주기 공백을 재현 가능한 계약과 테스트로
고정한다.

## 2. 기준선과 확인된 문제

`upstream/devel` a803f079의 Chrome 확장에는 다음 문제가 있다.

1. `background.js`가 `onInstalled.reason === "install"`에서 모든 기본 설정을
   `storage.sync`에 기록한다.
2. `options.html`의 세 체크박스가 storage 로드 전에 `checked` 상태로 렌더링된다.
3. `options.js`가 비동기 로드 완료 전에 change listener를 열고, 한 항목 변경 때 네 설정을
   모두 저장한다.
4. `storage.sync.set` callback의 `runtime.lastError`를 무시하고 항상 저장 성공을 표시한다.
5. options, message router, download interceptor가 각각 기본값과 storage 읽기를 중복한다.
6. `autoOpen` 키가 없으면 각 소비자가 곧바로 기본값 `true`를 적용하며 local 복구 경로가 없다.
7. 기존 테스트는 저장된 `autoOpen=false`가 다운로드 자동 열기를 막는지만 검증한다.

## 3. 설계 계약

### 3.1 공통 settings-store

- `rhwp-chrome/sw/settings-store.js`를 Chrome/Edge 설정의 단일 진입점으로 둔다.
- 기존 flat sync key인 `autoOpen`, `showBadges`, `hoverPreview`,
  `disableExternalWebFonts`는 호환성을 위해 유지한다.
- `storage.sync`가 key별 권위 저장소다. 유효한 boolean sync 값이 있으면 이를 사용한다.
- `storage.local`에는 스키마 버전, 갱신 시각, 전체 설정을 포함한 snapshot을 저장한다.
- sync key가 없거나 sync 읽기가 실패한 항목만 local snapshot으로 복구한다.
- 두 저장소 모두 값이 없을 때만 기존 기본값을 적용한다.
- 사용자 저장은 권위 저장소인 sync를 먼저 갱신하고 성공 여부를 UI에 반영한다. local snapshot은
  best-effort 백업으로 갱신하며, local만 실패하면 sync에 저장된 사용자 선택은 유지한다.
- sync 읽기 실패 중에는 옵션 UI가 local snapshot을 복구 표시할 수 있지만, 다운로드 자동 열기는
  local의 `true`만으로 허용하지 않고 fail-closed 처리한다.

### 3.2 설치·업데이트 수명주기

- `onInstalled`는 컨텍스트 메뉴와 최소 로컬 진단 메타데이터만 갱신한다.
- `install`, `update`, `chrome_update` 어느 reason에서도 사용자 설정을 기본값으로
  덮어쓰지 않는다.
- 진단 메타데이터는 reason, 이전/현재 확장 버전, 기록 시각만 포함하며 문서 URL이나 개인정보를
  저장하지 않는다.

### 3.3 옵션 UI

- HTML의 초기 `checked`를 제거하고 입력을 disabled로 시작한다.
- storage 로드와 DOM 반영이 끝난 뒤에만 change listener와 입력을 활성화한다.
- 저장 중에는 중복 입력을 막고, 실패하면 성공 메시지를 표시하지 않는다.
- 성공·로드 실패·저장 실패 메시지를 한국어/영어 locale에 추가한다.
- options script를 ES module로 전환하되 MV3 CSP의 외부 스크립트 원칙을 유지한다.

## 4. 단계

### Stage 1 — 저장소와 수명주기 회귀 가드

- settings-store의 clean install 기본값, legacy flat key, sync/local key별 복구,
  저장 성공/실패 테스트를 작성한다.
- `install`, `update`, `chrome_update`가 sync 설정을 쓰지 않는 수명주기 테스트를 작성한다.
- 최소 로컬 진단 메타데이터의 필드와 비개인정보 계약을 검증한다.

### Stage 2 — 설정 저장소와 소비자 통합

- settings-store와 extension lifecycle helper를 구현한다.
- background, message router, download interceptor가 공통 loader를 사용하도록 전환한다.
- 기존 다운로드 interceptor mock에 sync/local storage 계약을 추가한다.

### Stage 3 — 옵션 UI 경쟁·오류 처리

- options HTML의 초기 checked를 제거하고 loading disabled 상태를 적용한다.
- options 초기화와 저장 handler를 테스트 가능한 ES module 함수로 분리한다.
- 지연된 get, 저장 rejection, 저장 성공, 단일 항목 변경 보존 테스트를 작성한다.
- locale과 오류 상태 스타일을 추가한다.

### Stage 4 — 패키지·focused 검증

- 변경 JS의 `node --check`와 신규/기존 Node test를 실행한다.
- `npm --prefix rhwp-chrome run build`로 실제 dist를 생성한다.
- dist 계약 테스트에서 settings-store 복사, options module, inline script 부재를 확인한다.
- Rust/WASM 소스는 변경하지 않으므로 Rust 전체 CI는 수행하지 않는다.

### Stage 5 — 수동 검증 인계와 보고

- 자동화할 수 없는 Chrome 프로필 재실행, 비활성화/재활성화, 동일 ID Reload, 실제 다운로드
  시나리오를 별도 테스트 프로필용 체크리스트로 남긴다.
- 이 환경에서 UI를 직접 조작할 수 있으면 압축해제 확장 수동 확인까지 수행한다.
- 수행하지 못한 실제 Chrome/스토어 업데이트는 merge 차단이 아닌 배포 후 인수 항목으로 명시한다.
- 단계 보고서와 최종 보고서를 작성하고 오늘할일 상태를 갱신한다.

### Stage 6 — 탭 안전성 사후 보강

- #1498/#1515의 과거 다운로드 탭 다발 맥락을 재검토한다.
- 동일 download id의 `filename`/`finalUrl` 동시 이벤트를 강제해 중복 탭 경쟁을 재현한다.
- 설정 storage await 전에 id별 in-flight 선점을 적용하고 terminal 기록이 최신 handled state를
  보존하도록 Chrome adapter를 보정한다.
- sync read 실패 중 local `autoOpen=true`는 자동 열기 권한으로 사용하지 않는다.
- local backup 저장 실패가 성공한 sync 저장을 무효화하지 않도록 sync 권위 계약을 강화한다.

### Stage 7 — PR review partial-sync 보강

- `update`와 `chrome_update`에서 현재 유효한 sync 설정을 local snapshot으로 선보존한다.
- 기존 sync key 또는 schema metadata는 남아 있지만 `autoOpen`과 local snapshot이 없는 상태를
  clean install과 구분한다.
- 위 partial sync의 자동 동작은 fail-closed 처리하고, 근거 없는 default `true`를 local snapshot으로
  굳히지 않는다.
- 깨끗한 최초 설치와 유효한 local snapshot 복구 계약은 별도 회귀 테스트로 유지한다.
- reviewer 재현 순서 전체를 lifecycle + key 누락 통합 테스트로 고정한다.

## 6. 수동 검증 체크리스트

- 별도 Chrome 프로필에서 `rhwp-chrome/dist` 압축해제 확장 로드
- 자동 열기 해제 후 sync/local snapshot 모두 `false` 확인
- 설정 페이지 재진입, Service Worker 재시작, 확장 비활성화/재활성화, Chrome 재실행 뒤 유지
- 동일 경로 확장 Reload 뒤 유지
- HWP/HWPX 다운로드 때 뷰어가 자동으로 열리지 않음
- sync의 `autoOpen` key만 제거한 뒤 local snapshot에서 `false` 복구
- 저장 실패 주입 시 성공 문구 대신 실패 문구 표시

## 7. 위험과 완화

- **sync/local 충돌**: key별 sync 우선, sync 누락/실패 시 local fallback으로 규칙을 고정하고
  테스트한다.
- **구버전 호환**: 기존 flat sync key를 유지해 이미 배포된 content/background 계약을 깨지 않는다.
- **부분 저장**: 실패 시 UI를 실제 재로드 값으로 되돌리고 성공을 표시하지 않는다.
- **원치 않는 자동 열기**: sync read 실패 시 local `true`로 탭을 열지 않고 fail-closed 처리한다.
- **기존 설치 partial sync**: legacy key/schema metadata만 남은 상태는 clean install로 보지 않고,
  유효한 `autoOpen` 근거가 생길 때까지 자동 열기와 default snapshot 생성을 막는다.
- **동시 다운로드 이벤트**: download id별 in-flight 선점과 최신 handled/terminal state 유지 테스트로
  탭 1개 불변식을 고정한다.
- **과도한 storage write**: local snapshot이 실제 resolved 설정과 다를 때만 보강한다.
- **dist 누락**: settings-store는 기존 `sw/` 복사 경로에 두고 dist 계약 테스트를 추가한다.
- **Firefox/Safari 드리프트**: 이번 변경은 Chrome/Edge 패키지로 한정한다. 공통 계약을 바꾸지 않으며
  타 플랫폼 확대는 별도 이슈로 분리한다.

## 8. 완료 조건

- 이슈 #2656의 자동 검증 항목이 focused test로 재현·통과한다.
- clean install의 기본 동작과 기존 `autoOpen=false` 다운로드 회귀가 유지된다.
- update 직후 sync의 `autoOpen`만 누락되어도 effective/local snapshot의 `false`가 유지된다.
- local snapshot 없는 partial sync에서는 자동 열기가 fail-closed되고 default `true`가 백업으로 굳지 않는다.
- options UI가 로드 전 입력과 저장 실패를 성공 상태로 노출하지 않는다.
- Chrome/Edge dist에 새 설정 모듈과 locale이 포함되고 MV3 CSP 계약이 유지된다.
- 수동 검증 수행 범위와 배포 후 확인 항목이 보고서에 명시된다.
