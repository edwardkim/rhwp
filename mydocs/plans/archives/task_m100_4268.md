## 문제

현재 기여 가이드는 정확성 테스트와 CI 통과를 요구하지만, 환경 의존적인 절대 성능 수치와
메인테이너 전용 검증에 대한 책임 경계를 명시하지 않는다. 컨트리뷰터가 특정 하드웨어, 비공개
코퍼스 또는 메인테이너 브라우저 환경의 성능 임계치까지 재현해야 하는 것으로 오해할 수 있다.

반대로 단순히 “성능 기준을 요구하지 않는다”고 쓰면 결정적 성능 회귀 테스트와 GitHub required
checks까지 면제하는 것으로 읽힐 수 있다. PR 제출 자격과 merge gate를 분리해 명문화해야 한다.

## 정책 원칙

1. 컨트리뷰터에게 로컬 절대 시간, 비공개 코퍼스, 메인테이너 전용 벤치마크 통과를 PR 제출 조건으로
   요구하지 않는다.
2. 성능 영향 PR의 컨트리뷰터는 재현 절차와 가능한 범위의 전후 관측값을 제공한다.
3. 통제된 환경의 최종 성능 판정은 메인테이너가 수행한다.
4. 공개된 결정적 성능 회귀 테스트와 GitHub required checks는 기존과 같이 merge gate다.
5. 성능 회귀로 merge를 막을 때는 메인테이너가 공개 가능한 재현 근거를 제공하거나 공개 fixture·
   래칫을 함께 마련한다.

## 변경 범위

| 파일 | 변경 |
| --- | --- |
| `CONTRIBUTING.md` | PR 전 체크리스트 다음에 성능 검증 책임 경계 추가 |
| `.github/pull_request_template.md` | 선택형 `성능 영향 및 측정 결과` 입력란 추가 |
| `mydocs/manual/pr_review/local_validation.md` | 메인테이너의 환경 의존 성능 판정과 blocking 근거 규칙 추가 |

CI workflow, timeout, 성능 임계치, required check, 비공개 코퍼스의 공개 범위는 변경하지 않는다.

- `python3 scripts/check_markdown_links.py CONTRIBUTING.md .github/pull_request_template.md mydocs/manual/pr_review/local_validation.md mydocs/plans/task_m100_4268.md mydocs/orders/20260809.md`

  한정되는지 확인
- CONTRIBUTING의 공개 정책과 maintainer 검증 문서가 서로 모순되지 않는지 문구 대조

일반 Markdown 정책 변경이므로 Cargo, WASM, renderer와 시각 검증은 수행하지 않는다.

## 완료 조건

- PR 제출 조건과 merge 성능 gate가 구분된다.
- 비공개 자료나 특정 하드웨어 수치가 컨트리뷰터 의무가 아님을 명시한다.
- 결정적 공개 성능 회귀 테스트와 required checks가 유지된다.
- 메인테이너의 재검증 책임과 blocking 근거 제공 의무가 명시된다.
- 문서 링크와 diff 검사가 통과한다.
