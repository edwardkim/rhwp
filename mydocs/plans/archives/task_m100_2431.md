## 단계

### 1단계 — C: Native Skia cache writer 정합성 복구

- Native Skia job의 `actions/cache/restore` 기반 `Linux-cargo-*` reader를 제거한다.
- 별도 `shared-key`를 사용하는 `Swatinem/rust-cache`로 통합한다.
- PR은 restore-only, `devel/main` push만 save하는 현행 신뢰 경계를 유지한다.
- C 병합 후 devel save와 후속 PR warm restore를 관측한 뒤 legacy `Linux-cargo-*` cleanup을 판단한다.

### 2단계 — D: third-party action SHA pinning

- C와 기존 두 job의 `Swatinem/rust-cache@v2`를 검증한 full commit SHA로 고정한다.
- action 버전 갱신 정책과 주석을 정리한다.

### 3단계 — A: 닫힌 PR merge-ref cleanup

- fork PR까지 처리할 수 있도록 `pull_request_target.closed` 보정을 메인테이너에게 확인 중이다.
- checkout이나 PR code 실행 없이 해당 `refs/pull/<number>/merge` cache만 삭제한다.
- 삭제 대상과 정리 후 잔여 총량을 run log에 남긴다.
- 현재 남은 닫힌 PR ref 13개는 별도 일회성 cleanup 승인을 받은 뒤에만 삭제한다.

### 4단계 — B: frontend npm cache 비활성화

- frontend gate의 npm cache 입력을 제거하고 `package-manager-cache: false`를 명시한다.
- PR별 npm cache가 새로 생성되지 않는지 API와 run log로 확인한다.

## 게이트

| 항목 | 기준 |
|------|------|
| 범위 분리 | C, D, A, B를 각각 별도 PR과 커밋으로 유지 |
| 신뢰 경계 | PR은 restore-only, trusted branch만 save |
| required check | `CI / Build & Test` 표면과 Native Skia 테스트 명령 불변 |
| cache 정합성 | C merge 후 devel save, 후속 PR에서 `native-skia` shared-key restore 확인 |
| 삭제 안전성 | exact PR merge-ref만 삭제, active branch/cache 무접촉 |

## 승인 게이트

- C와 D는 기존 메인테이너 결정에 따라 진행한다.
- A 이벤트 보정과 기존 stale PR cache 일회성 삭제는 메인테이너 답변 전 실행하지 않는다.
- 작업지시자는 2026-07-23 C 구현의 push와 Draft PR 생성을 승인했다.
- cache 삭제는 메인테이너 답변과 작업지시자의 별도 승인을 받기 전 실행하지 않는다.
