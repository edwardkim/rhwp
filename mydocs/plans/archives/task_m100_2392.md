## 1. 목적

`PicturePropsDialog.handleOk`는 하나의 함수에서 다음 변경 이유를 함께 소유한다.

1. DOM control의 현재 값을 읽고 HWPUNIT/ColorRef 등 저장 형식으로 변환한다.
2. 기존 image/shape properties와 비교해 최소 patch를 만든다.
3. image/shape/line/group/OLE별 적용 규칙과 기본값을 선택한다.
4. header/footer, cell path, 일반 본문에 맞는 WASM setter를 선택한다.
5. `CommandServices` 유무에 따라 snapshot undo 또는 직접 적용 fallback을 수행한다.
6. 적용 여부와 무관하게 dialog를 닫는다.

이번 작업의 목적은 이 책임들을 검증 가능한 경계로 분리하면서 기존 patch와 side effect를 그대로 보존하는
것이다. 함수 수나 파일 수 증가 자체가 목적이 아니며, 전체 Total CC와 고복잡도 합의 순감소를 함께
증명해야 한다.

## 3. 현재 apply 계약

### 3.1 patch 책임군

Stage 1에서 아래 항목을 field 단위 characterization table로 확정한다.

| 책임군 | 현재 동작 |
|--------|-----------|
| 공통 | size protection, width/height, treat-as-char, wrap/position, overlap/restrict, description |
| shape 공통 | text-box margin, vertical align, rotation/flip, line, corner, fill, shadow |
| OLE | outer margin, caption과 제한된 line 저장. transform/fill/shadow 범위 제한 |
| image | rotation/flip, outer margin, caption, border, scale, crop, padding, effect, transparency |
| 변환 | mm/HWPUNIT, ColorRef/hex, percentage/alpha, integer/float default 처리 |
| patch 정책 | 기존 값과 다른 field만 전송하는 항목과 의도적으로 항상 전송하는 항목이 혼재 |

`parseInt`/`parseFloat`와 `||` fallback, clamp, `TakePlace`/`TopAndBottom` 변환, `Through` 보존 같은 세부
규칙도 동작 계약이다. 보기 좋은 정리라는 이유로 기본값 의미를 바꾸지 않는다.

### 3.2 setter target 계약

| object/target | 현재 setter |
|---------------|-------------|
| shape/line/group/OLE + cell path | `setCellShapePropertiesByPath` |
| shape/line/group/OLE + 일반 본문 | `setShapeProperties` |
| image + header/footer | `setHeaderFooterPictureProperties` |
| image + cell path | `setCellPicturePropertiesByPath` |
| image + 일반 본문 | `setPictureProperties` |

image는 header/footer를 cell path보다 먼저 판정한다. shape 계열은 cell path 우선이다. 이 우선순위와 setter
인자 순서는 변경하지 않는다.

### 3.3 undo와 fallback 계약

- `services.getInputHandler()`가 있으면 `kind: 'snapshot'`, `operationType: 'objectProps'`로 라우팅한다.
- snapshot operation은 patch setter 실행 후 현재 cursor position을 반환한다.
- InputHandler가 없으면 setter를 직접 호출하고 `document-changed`를 emit한다.
- patch가 비어 있으면 setter와 event를 실행하지 않는다.
- 성공·무변경 여부와 관계없이 마지막에 dialog를 닫는다.

## 4. 수행 범위

### 4.1 characterization

- `handleOk`의 field, 변환, default, diff/always-send 정책을 object type별로 분류한다.
- setter target과 undo/fallback matrix를 고정한다.
- 기존 source-oriented test와 headless E2E가 실제로 보장하는 범위와 공백을 분리한다.
- 새로운 계산 경계의 data-driven unit test 입력을 먼저 설계한다.

### 4.2 patch 계산 책임 분리

- DOM control 값 수집과 기존 properties 비교를 구분한다.
- 공통, shape/OLE, image patch 계산이 독립적으로 검토되도록 경계를 만든다.
- 계산 경계는 가능한 한 plain data를 받고 DOM, `WasmBridge`, `EventBus`에 직접 의존하지 않게 한다.
- helper가 기존 클래스보다 넓은 거대 context를 요구하면 추출을 강행하지 않고 경계를 다시 설계한다.

### 4.3 side-effect orchestration 분리

- patch 생성과 setter target 선택을 분리한다.
- target 선택, setter 인자, snapshot undo와 fallback을 독립적으로 검증한다.
- `handleOk`는 입력 수집, patch 계산 호출, 적용 orchestration과 종료를 조정하는 얇은 진입점으로 축소한다.

### 4.4 metrics와 회귀 검증

- 동일 base pre/post snapshot으로 aggregate와 stable function diff를 만든다.
- 대상 파일과 frontend 전체의 Total CC, Top 20, threshold 합·개수, Max를 모두 기록한다.
- Studio unit/build와 그림 속성 undo/Through headless E2E를 재실행한다.
- 변경 allowlist와 public/WASM/runtime dependency 무변동을 확인한다.

## 5. 범위 제외와 금지 목록

### 5.1 범위 제외

- `populateFromProps` 해체 또는 dialog 초기화 pipeline 변경

- React/Vue/Svelte 등 runtime UI framework 도입
- package runtime dependency 추가
- public npm/embed 계약 또는 WASM JSON/byte schema 변경
- source refactor와 기능·보안·UI 변경 혼합
- 기존 diff-only field를 always-send로 바꾸거나 그 반대 방향으로 변경
- object type 또는 target 분기를 합치면서 setter 우선순위·인자 의미 변경

- 조건을 새 helper로 이동한 뒤 Total CC·stable diff 없이 개선으로 주장
- frontend 전체 SOLID 예비 점수를 공식 기준선으로 사용

## 11. SOLID·복잡도 적용 방식

평가 단위는 frontend 전체가 아니라 `picture-props-dialog` apply pipeline과 #2392 diff다.

| 원칙 | 이번 작업의 review 질문 |
|------|-------------------------|
| SRP | DOM 입력, patch 계산, target routing, undo orchestration의 변경 이유가 경계로 구분되는가 |
| DIP | 계산 정책이 `HTMLElement`, `WasmBridge`, `EventBus` concrete detail 없이 검증 가능한가 |
| OCP | object type별 규칙 추가가 기존 전체 pipeline 재작성 대신 제한된 계산 경계에서 가능한가 |
| LSP | 명시된 substitute가 없으면 점수를 추론하지 않고 setter target 계약만 검토하는가 |
| ISP | 새 context/type이 사용하지 않는 모든 DOM/WASM detail을 강제하지 않는가 |

`solid_scoring_guide.md`의 공식 점수는 maintainer/collaborator가 같은 평가 단위에 근거를 남기고 조정한
경우에만 기록한다. CC·LOC 감소를 SOLID 점수로 자동 변환하지 않는다.

복잡도 판정은 #1904/#2130의 최신 교훈을 따른다. Max와 threshold 개수만 보지 않고 Total CC, global Top 20,
CC>25 합과 stable function diff를 함께 사용해 복잡도를 다른 함수로 옮긴 결과를 차단한다.
