## 1. 문제

`CharShape.ratios` 기본값이 `[0; 7]` 이다(`src/model/style.rs:213`). OWPML `ratio` 는
`default="100"`, `xs:positiveInteger` 에 [50, 200] 제약이라
(`mydocs/manual/OWPML SCHEMA/Header XML schema.xml:590-611`) 0 은 타입 수준에서 이미 불법이다.

`relative_sizes`(#4141)와 두 가지가 다르다.

1. **렌더러가 소비한다** — `src/renderer/style_resolver.rs:355` 가
   `cs.ratios[lang] as f64 / 100.0` 으로 나눠 `ResolvedCharStyle.ratio` 를 만든다.
   장평 0 = 글자 폭 0.
2. **HML 은 렌더 경로다** — `export-svg`/`export-pdf` 가 `.hml` 을 받는다.

재현(배포 CLI):

```bash
rhwp export-hml tests/fixtures/hml/exambank_math_equations_min.hml -o /tmp/rt.hml
# → <RATIO Hangul="0" Latin="0" Hanja="0" Japanese="0" Other="0" Symbol="0" User="0"/>
```

입력 fixture 의 `<CHARSHAPE>` 는 `FONTID` 만 갖고 `RATIO` 자식이 없다.

### 왜 기존 게이트로 안 잡히나

- HWPX 라운드트립 검증기(`src/serializer/hwpx/roundtrip.rs`)는 char_shapes 를 개수만
  비교한다 — `ratios` 필드 비교 0건.
- HML preflight(`src/serializer/hml/preflight.rs:175-197`)의 비교 목록에 `ratios` 가 없다.
- HML 왕복 동등성 테스트(`tests/hml_serializer.rs:385`)는 before==after 만 본다 —
  0→"0"→0 도 통과.
- 골든 SVG 7건은 전부 ratio 명시 표본이라 기본값 경로를 타지 않는다.

## 2. 근본 원인 — 미채움 경로 전부가 `CharShape::default()` 를 통과한다

`ratios=[0;7]` 를 실제로 만드는 프로덕션 경로 5계열:

| 경로 | 위치 | 형태 |
| --- | --- | --- |
| HWPX charPr `<hh:ratio>` 자식 부재 | `src/parser/hwpx/header.rs:611` (`:664` 대입 안 됨) | `CharShape::default()` |
| HWPX charPr id 갭 filler | `src/parser/hwpx/header.rs:36` `set_indexed` | `T::default` |
| HML `RATIO` 자식 부재 | `src/parser/hml/reader.rs:608` (`:639` 대입 안 됨) | `..Default::default()` |
| HTML import | `src/document_core/commands/html_import.rs:845`, `src/document_core/html_table_import.rs:635` | `CharShape::default()` |
| HWP3 인덱스 0 placeholder | `src/parser/hwp3/mod.rs:3763` | `CharShape::default()` |

HWP3 `convert_char_shape`(`src/parser/hwp3/mod.rs:595`)는 레코드에서 `ratios` 를 채우므로
안전하고, placeholder 는 전 15표본에서 참조 0건이다(#4141 stage1 §3 실측). HWP5 는
`raw_data` 우선이라 HWP5→HWP5 무손실.

**파서/모델 불일치**: HWP5 CHAR_SHAPE 파서(`src/parser/doc_info.rs:528-532`)는 이미
`[100u8; 7]` + `unwrap_or(100)` 폴백이다. 모델 `Default` 만 0 이다 — #4141 보고서가
`relative_sizes` 에 대해 기록한 것과 정확히 같은 불일치.

## 3. 수정 — `impl Default for CharShape` 의 `ratios` 한 줄

`src/model/style.rs:213` `ratios: [0; 7]` → `[100; 7]`. 근거는 OWPML 스키마
default=100 / [50,200], 그리고 HWP5 파서 폴백과의 정합.

### 렌더 영향 — 산출이 달라지는 곳은 4곳뿐이고 전부 "버그의 정상화"

폭/자간 경로 5곳(`renderer/layout/text_measurement.rs:71`, `renderer/svg.rs:2780`,
`renderer/web_canvas.rs:2246`, `renderer/html.rs:378`, `renderer/skia/text_replay.rs:315`)은
전부 `ratio > 0.0 ? ratio : 1.0` 가드라 0→100 변경 시 산출 동일(0→1.0 폴백 == 100→1.0).

| 위치 | 종전(ratio=0) | 변경 후(ratio=1.0) |
| --- | --- | --- |
| `renderer/svg.rs:3107`, `renderer/web_canvas.rs:2525` | 강조점이 글자 왼쪽 모서리에 붙음 | 글리프 중앙 — 정상화 |
| `renderer/canvaskit_policy.rs:808` | 기본형 run 을 invalidGeometry 로 오판 | 유효 판정 |
| `renderer/canvaskit_policy.rs:2061` | 기본형 run 을 장평 paint effect 있음으로 오판 | 효과 없음 |

가드 통일·제거는 하지 않는다 — 손상 바이트가 0 을 실어올 수 있어 방어선으로 유효하다.

### 함께 바꾸지 않는(보류) 필드 — `base_size`

이슈의 "함께 검토" 요건에 따라 Stage 1 에서 계측을 깊게 수행한 뒤 포함 여부를 결정한다
(작업지시자 지시, 2026-08-18). 쟁점 3가지:

1. `src/doclang/adapter/inline.rs:421` 이 `cs.base_size != 0` 을 "폰트 정보 없음"
   센티널로 사용 — 기본값이 1000 이 되면 손실 보고 위양성 가능.
2. `src/document_core/queries/hidden_text.rs:255-257` 실효 pt = `base_size.max(0)/100.0` —
   기본형 문자의 은닉 판정이 0pt→10pt 로 반전 가능.
3. `ratios` 와 달리 무가드 레이아웃 소비(`style_resolver.rs:341` 이 폰트 크기의 유일한
   원천)라 줄높이가 실제로 움직인다.

결정 기준: 위양성·판정 반전이 실표본에서 0건이고 센티널 재작성 없이 안전하면 포함,
아니면 검토 결과를 잠금 테스트 주석·보고서에 기록하고 후속 이슈로 분리 제안.

### 기각한 대안

- **라이터에서 가드(0 이면 100 으로 치환)**: 증상 은폐. IR 이 틀린 값을 들고 있는 것이
  원인이고, #4141 이 확립한 "기본값 원천 수정" 철학과 어긋난다.
- **파서별 폴백 추가(4곳+)**: 수정 면적만 넓어지고 새 미채움 경로가 생길 때마다 재발.
- **폭 경로 가드 제거(단순화)**: 이득 없이 회귀면만 넓어진다.

### 테스트 5건

1. `hwp3_convert_emits_valid_ratios_for_every_sample` — 표본 전수 스윕(`MIN_SWEPT_SAMPLES=10` 가드)
2. `so_sueop_convert_ratios_within_valid_range` — 재현 표본 고정, 개수 하한 >1000
3. `public_document_core_export_also_emits_valid_ratios` — `export_hwp_with_adapter` 공개 경로
4. `hwp3_export_hwpx_emits_valid_hh_ratio` — `Contents/header.xml` `hh:ratio`
5. `hml_roundtrip_without_ratio_child_emits_valid_ratio` — RATIO 부재 사전단언 후 왕복

**단언 형태가 #4141 과 다르다**: relative_sizes 는 HWP3 레코드에 필드가 없어 `==100`
전수 단언이 가능했지만, ratios 는 레코드 실데이터가 있다(SO-SUEOP 실측 95/90/100/97).
따라서 범위 [50,200] 소속 단언으로 간다. Stage 1 계측에서 정상 표본에 범위 밖 실값이
발견되면 `!=0` + 범위 위반 보고로 좁히고 사유를 파일 doc 주석에 기록(컨틴전시).

HWPX ratio-자식-부재 유닛 케이스는 추가하지 않는다 — 잠금 유닛 테스트가 기본값을 고정하고,
테스트 4가 idx0 placeholder 경유로 방출 경로를 관통하며, 유닛 추가는 unit-test-tiers
기준선 재계산을 유발한다. 생략 사유는 파일 doc 주석에 남긴다.

### 갱신·유지할 기존 단언

- **갱신**: `src/model/style.rs:1154-1195`
  `char_shape_default_matches_spec_only_for_relative_sizes_and_shade` —
  `ratios == [0;7]` 잠금(:1167-1171)을 `[100;7]` 로 뒤집고 doc 주석(:187-191, :1147-1153)을
  새 계약으로 교체. `base_size == 0`(:1172-1175)은 Stage 1 결정에 따라 유지+사유 교체 또는 갱신.
- **유지**: `src/parser/hwpx/header.rs:3361`(`[95;7]` 명시값 보존),
  `tests/issue_hml_shape_child_attribution.rs:37,38,61`. 왕복 동등성 테스트는 양쪽 동시
  변경이라 통과 예상.
