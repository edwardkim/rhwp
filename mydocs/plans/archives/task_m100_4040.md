## 1. 문제

`native-skia` feature 로 제한된 integration test 가 CI 의 어떤 job 에서도 실행되지 않는다.

- default-feature archive/worker 는 `native-skia` 없이 빌드하므로 해당 파일이 통째로 cfg-out 된다.
- `Native Skia tests` job 은 `--lib skia` 와 integration target **2개**만 명시적으로 실행한다.

따라서 그 테스트가 보호하는 회귀는 CI 에서 재발해도 차단되지 않는다.

## 2. 조사 결과 — 이슈보다 범위가 넓다

이슈는 `issue_2293_chart_png_text.rs` 한 건만 지목했다. 전수 조사하니 **파일 전체가 `#![cfg(feature = "native-skia")]` 인 test 3개 모두** 같은 상태다.

| 파일 | Native job | classifier 소유 | 보호 대상 |
| --- | --- | --- | --- |
| `tests/issue_2083_hide_fill_page_background.rs` | ✗ | ✗ | #2083 쪽 배경 감추기 PNG |
| `tests/issue_2292_chart_png_clip.rs` | ✗ | ✗ | #2292 차트 PNG 잘림 |
| `tests/issue_2293_chart_png_text.rs` | ✗ | ✗ | #2293 차트 PNG 텍스트 소실 |
| `tests/issue_2225_missing_picture_placeholder.rs` | ✓ | ✓ | (정상) |
| `tests/render_p37_direct_pdf_export.rs` | ✓ | ✓ | (정상) |

각 파일은 `#[test]` 1건씩이다. 즉 **회귀 가드 3건이 죽어 있다.**

### 2.1 두 번째 결함 — 분류가 어긋난다

`tests/issue_2293_chart_png_text.rs` 를 classifier 에 넣어 보면 이렇다.

```
tests/issue_2293_chart_png_text.rs  →  rust=true  native=false  reason=classified:rust
```

`native_skia_required=false` 라 **그 테스트를 실행할 job 자체가 skip 된다.** job 에 target 만 추가하고 classifier 를 고치지 않으면, 정작 그 파일을 고치는 PR 에서 검증이 돌지 않는다. 두 변경은 짝이어야 한다.

### 2.2 세 번째 결함 — 계약 테스트가 이 부류를 못 잡는다

기존 `test_native_skia_integration_targets_are_classifier_inputs` 는 **workflow target ⊆ classifier 목록** 한 방향만 단언한다.

```python
targets = set(re.findall(r"--test ([A-Za-z0-9_]+)", native_step))
for target in targets:
    self.assertIn(f"'tests/{target}.rs'", classifier)
```

양쪽 **어디에도 없는** 파일은 순회 대상이 아니라 조용히 빠진다. #2083·#2292·#2293 이 정확히 그 경로로 새어 나갔다.

### 2.3 별개 축 — 함수 단위 cfg

`tests/cli_exit_codes.rs` 는 파일 게이트가 없어 default worker 에서 돌지만, 그 안의
`export_png_follows_the_same_contract` 는 `#[cfg(feature = "native-skia")]` 함수라 default 실행에서
cfg-out 되고 Native job 에도 없다. 파일 단위 해법으로는 잡히지 않는 별개 축이다.

## 3. 목표와 범위

| 항목 | 포함 |
| --- | --- |
| 고아 integration test 3건을 Native Skia job 에 추가 | 포함 |
| 그 3건을 classifier 의 native-skia 소유 목록에 추가 | 포함 |
| 부류 자체를 강제하는 계약 테스트 | 포함 |
| classifier fixture 로 분류 고정 | 포함 |
| 함수 단위 cfg (2.3) | **제외** — 4절 |

Stage 4 의 Rust·Native Skia 조건화 **의미는 바꾸지 않는다.** 누락된 기존 검증만 회복한다.

## 4. 이번에 하지 않는 것

**함수 단위 `#[cfg(feature = "native-skia")]` 테스트**는 제외한다. 해법이 다르다 — 파일을 Native job 에
추가해도 그 파일의 나머지 테스트가 default worker 와 중복 실행된다. 중복 실행을 받아들일지, 파일을
분리할지, 별도 job 을 둘지 판단이 필요하고 이는 #3790 의 진리표에 영향을 준다. 별도 이슈로 분리한다.

## 5. 예상 단계

1. 고아 목록을 계약 테스트로 먼저 고정한다 (RED 재현).
2. workflow 와 classifier 를 함께 고쳐 GREEN 으로 만든다.
3. classifier fixture 와 뮤테이션으로 실효성을 확인한다.
4. 원격 CI 에서 세 target 이 실제로 실행·통과하는지 로그로 확인한다.

## 6. 완료 조건

- `Native Skia tests` job 로그에 `issue_2083`·`issue_2292`·`issue_2293` target 실행과 통과가 남는다.
- 세 파일 중 하나만 바꾸는 PR 이 `native_skia_required=true` 로 분류된다.
- `native-skia` 파일 게이트 test 를 새로 추가하고 job·classifier 배선을 잊으면 계약 테스트가 실패한다.
- Stage 4 조건화의 다른 판정은 변하지 않는다 (기존 계약 테스트 무회귀).

## 7. 검증 제약

`native-skia` 빌드는 `libfontconfig1-dev`·`libfreetype6-dev` 등 시스템 패키지를 요구한다(workflow 의
`Install native Skia runtime packages`). 로컬에서 세 테스트를 직접 실행할 수 있는지는 착수 시 확인하고,
불가하면 **원격 CI 로그를 1차 증적으로 삼는다.** 로컬에서 가능한 검증(계약 테스트, classifier, actionlint)은
모두 수행한다.
