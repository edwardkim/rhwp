## 1. 목표

이슈 첨부 `jubo_20260104.hwp`의 예배 순서 표에서 반복되는 `다 같 이`, `인 도 자`
같은 짧은 라벨이 한컴과 동일하게 셀 글 영역 전체에 분산되도록 정정한다.

## 2. 구현 전 조사 결과

- 이슈에서는 배분정렬로 표현했지만, 첨부 HWP의 문제 문단은 HWP5 정렬 값 `5`, 즉
  `Split`이다. HWPX로는 `DISTRIBUTE_SPACE`, 한컴 UI 의미로는 공백 기준 나눔
  정렬이며 파서는 이를 `Alignment::Split`으로 정확히 보존한다.
- 현재 SVG에서 문제 라벨의 셀 clip 폭은 약 `95.39px`이나 `다/같/이` x 좌표는
  `417.53 / 439.93 / 462.33px` 또는 `416.25 / 427.45 / 438.65px`에 머문다.
- 동일 입력의 HWP 2020 PDF에서는 세 글자가 셀의 오른쪽 경계까지 고르게 분산된다.
- 문제 문단의 좌우 여백과 들여쓰기는 모두 0이며 셀 inner 폭도 `91.63~92.91px`로
  정상 계산된다. 가용폭 또는 파서가 원인이 아니다.
- 현재 코드는 `Split`을 일반 `Justify`와 같은 활성 조건으로 묶어 마지막 줄에서는
  공백 분배를 끈다. 한 줄짜리 셀 라벨은 곧 마지막 줄이므로
  `extra_word_spacing=0`이 되는 것이 근본 원인이다.

## 3. 작업 단계

### Stage 0 — 재현·계측 고정

- 첨부 HWP의 `ParaShape`/`LINE_SEG`/표 셀 inner 폭과 실제 `available_width`를
  확인한다.
- HWP 2020 PDF와 rhwp SVG의 문자 x 좌표 및 셀 clip 경계를 기록한다.
- 이슈 첨부 원본은 재배포 조건을 확인하지 않았으므로 저장소 fixture로 추가하지 않는다.

### Stage 1 — Split 마지막 줄 계약 정정

- `Justify`는 기존처럼 일반 본문 마지막 줄과 강제 줄바꿈 줄에서 분배하지 않는다.
- `Split`은 마지막 줄에서도 내부 공백에 남은 폭을 분배한다.
- 일반 좌·중·우 정렬, `Distribute`, 탭 및 줄바꿈 산식은 변경하지 않는다.

### Stage 2 — 회귀 차단

- 단일 마지막 줄에서 `Split=true`, `Justify=false`인 판정 계약을 단위 테스트로 고정한다.
- `다 같 이` 형태의 두 내부 공백에 양의 slack이 동일하게 들어가는지 검증한다.
- 기존 배분·정렬·표 셀 관련 테스트를 함께 실행한다.

### Stage 3 — 시각·전체 검증과 보고

- HWP 2020 기준 PDF와 수정 후 SVG 2쪽을 동일 배율로 대조한다.
- macOS 로컬 검증 절차에 따라 `CARGO_INCREMENTAL=0`으로 Rust 검사와 clippy를
  실행하고 결과를 최종 보고서에 기록한다.

## 4. 수용 기준

1. 첨부 문단의 HWP5 `Split`/HWPX `DISTRIBUTE_SPACE`가 파싱부터 SVG까지 유지된다.
2. 문제 라벨이 셀 글 영역의 좌·우 경계에 맞춰 분산되고 큰 잔여 폭이 남지 않는다.
3. `Split`을 `Justify`의 마지막 줄 규칙으로 억제하는 회귀가 테스트로 막힌다.
4. 기존 정렬·표 셀·SVG 회귀가 통과하고 HWP 2020 기준과 의미 있는 차이가 남지 않는다.

## 5. 범위 밖

- `Justify`의 마지막 줄 정책 및 공백 분배 산식 변경
- 원본 예배 주보 문서를 샘플로 영구 추가하는 작업
- 폰트 대체 또는 문서 전체 줄바꿈 재조정
