# Task #3674 수행계획서 — 편람 쪽수 편차 (rhwp 386 vs 한컴 383)

- Issue: [#3674](https://github.com/edwardkim/rhwp/issues/3674) (M100)
- 브랜치: `local/task3674` / 착수: 2026-08-04

## 1. 착수 재계측 — 기준선이 안정돼 있다

오늘 devel(`976ed264b` 계열) release 빌드로 재계측한 결과가 8/1 등록 시점과 동일하다.

| 산출 | 쪽수 | 검증 |
|---|---|---|
| 한컴 2020 PDF (정답지) | **383** | `pdfinfo` 383쪽 · 19,287,456B · SHA `aba8d5a4b5c21dff` 일치 |
| rhwp — 저장본 HWP | **386** | export-text 386파일 (`pyeonram_3565_rhwp_saved.hwp`, 9,083,904B) |
| rhwp — 원본 HWPX | **387** | export-text 387파일 |

그 사이 조판 PR 다수(#3771 표 셀 등)가 merge 됐는데도 이 문서는 움직이지 않았다 —
편차가 특정 축에 고정돼 있다는 신호다.

주: 이슈의 `pyeonram_3589.hwp`(SHA `4caff289…`)는 로컬에 없다.
`pyeonram_3565_rhwp_saved.hwp` 가 같은 크기(9,083,904B)·같은 쪽수(386)의 동일 계열
산출물이므로 이것을 저장본 축의 기준으로 쓴다.

## 2. 겹치는 열린 PR — 계획에 반영

착수 점검에서 같은 축의 열린 PR 2건을 확인했다.

- **[#3900](https://github.com/edwardkim/rhwp/pull/3900)** (planet6897) — 저장 `LINE_SEG`
  `vpos` 되돌아감을 쪽 경계로 인정. **저장 HWP 의 쪽 경계 판정 자체를 바꾸므로 이
  문서(저장본 축)의 쪽수를 움직일 수 있다.** Stage 1 에서 이 브랜치로도 계측해 영향을
  정량화한다(merge 대기와 무관하게 데이터 확보).
- [#3916](https://github.com/edwardkim/rhwp/pull/3916) (kevin9327) — 쪽수 검증 도구
  개선. 조판 로직 무변경이라 충돌 없음, 참고만.

## 3. 조사 설계

### Stage 1 — 발산 지점 좌표화 (진단, 코드 무변경)

총량 비교(386 vs 383)가 아니라 **어긋나는 문서 위치**를 찾는다.

1. 정답지 PDF 를 쪽별 텍스트로 추출(`pdftotext -f N -l N`)하고, rhwp 쪽별
   export-text(이미 확보)와 **쪽 시작 앵커**(선행 텍스트 정규화 후 일치)로 정렬한다.
2. rhwp쪽↔한컴쪽 매핑에서 **오프셋이 0→+1→+2→+3 으로 증가하는 전이 지점**을 전부
   찾는다. 편차 3쪽이면 전이는 최대 3곳 안팎이다 — 각각이 독립 결함 후보다.
3. 각 전이 지점 주변을 rhwp SVG 렌더 + PDF 해당 쪽과 대조해 **결함 축을 분류**한다
   (표 분할·줄높이·간격·vpos·개체 배치 …). 트러블슈팅 폴더 사전 검색 규칙을 따른다.
4. **#3900 브랜치 계측**: 같은 두 입력의 쪽수를 #3900 head 로도 재고, 전이 지점이
   어떻게 움직이는지 기록한다.
5. HWPX(387) vs HWP(386) 1쪽 차이도 같은 방법으로 그 한 지점을 좌표화한다.

산출: 전이 지점 목록(쪽 번호·주변 내용·결함 축 분류·스크린샷) — **Stage 1 보고 후
어느 축을 고칠지 작업지시자 결정**을 받는다.

### Stage 2+ — 원인 수정 (Stage 1 결과에 따라 별도 승인)

거버넌스 준수: 샘플명·쪽번호·임의계수 분기 금지, 근거는 문서 속성/스펙 필드만.
수정 시 red-check + 보호 코호트(10k 서베이 원칙: 문서 단위 이동만 권위) 확인.

## 4. 검증 기준 (Stage 1)

1. 전이 지점이 **쪽 좌표로 특정**된다(±1쪽 이내).
2. 각 지점의 결함 축 분류에 시각 증거(rhwp 렌더 vs PDF 쪽)가 붙는다.
3. #3900 영향이 수치로 기록된다.
4. 진단 단계는 코드를 바꾸지 않는다.

## 5. 위험과 제약

- **PDF 텍스트 추출 순서**가 rhwp 와 다를 수 있다(표·머리말 등) — 앵커 매칭은 정규화
  (공백 제거·선행 N자)와 이웃 쪽 재동기화로 보강하고, 매칭 실패 구간은 수동 확인으로
  남긴다.
- 386쪽 문서라 렌더·비교 비용이 크다 — 전이 지점 주변만 렌더한다.
- 편차 3쪽이 **한 원인의 누적**일 수도, **세 원인**일 수도 있다. 전이 지점 수가 곧
  답이므로 예단하지 않는다.
- 시각 판정 권위는 작업지시자에게 있다 — Claude 는 정량 측정과 증거 수집까지만.
