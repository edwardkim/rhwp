# Task #3377 수행계획서 — 확장 첫 로딩 1·2쪽 세로축 어긋남

- Issue: [#3377](https://github.com/edwardkim/rhwp/issues/3377) (M100)
- 브랜치: `local/task3377` / 착수: 2026-07-30 (wasm 재빌드 후 작업지시자 재현 확인)
- 성격: studio/확장 첫 페인트 과도 상태 — 재렌더 시 소멸, dev 서버 headless 미재현

## 1. 문제 요약

확장 viewer.html(프로덕션 빌드) 첫 로딩에서 SO-SUEOP.hwp 1쪽이 2쪽과 다른 폭/정렬로
그려진다. 42쪽 이동 후 복귀하면 소멸 → 첫 페인트가 확정 전 상태로 남는 stale 캔버스
또는 배치 계산 경합으로 추정. dev 서버(7700) headless 시계열에서는 완전 정렬(x=313/w=793).

## 2. 조사 가설 (우선순위순)

- **H1. 웹뷰 내 문서 위치/배치 계산** (작업지시자 지시로 추가): 캔버스 픽셀이 아니라
  페이지 컨테이너의 CSS 배치(폭 확정·가운데 정렬·스크롤 컨테이너 초기 크기)가 첫
  로딩 시점에 미확정 값으로 계산됐다가 갱신 누락되는 경로. 확장 환경에서만 재현되는
  점(뷰포트 크기 확정 타이밍이 dev 와 다름)과 부합 가능성.
- **H2. 줌/뷰포트 확정 vs 페이지별 페인트 순서 경합**: fit-width 등 줌 확정 이후 이미
  그려진 1쪽만 재페인트 누락.
- **H3. #3363 WMF/OLE preview 비동기 디코드 연관**: 이슈 기록상 후순위 — 배제 확인용.

| Stage 2 | 근인 확정: H1~H3 중 계측으로 특정, 소스 경로(zoom 계산·컨테이너 배치·페인트 스케줄) 지목 | stage2 보고 — 근인 코드 위치·수정 방향 |
