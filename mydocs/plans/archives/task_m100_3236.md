## 1. 확정된 사실 (착수 전 실측)

**첫 페이지에서 시작된 표가 페이지 높이에 도달하면 다음 페이지로 분할되어야 하는데,
분할 조각이 생성되지 않고 잘린다.** 전체 문서의 63%가 소실된다.

| 층 | 측정 | 판정 |
|---|---|---|
| 한컴 정답지 (권위) | 총 **6,651자** (p1 3,018 / p2 **3,633**) | 기준 |
| rhwp SVG | 총 **2,450자** (p1 2,067 / p2 383) | **−4,201자 (−63%)** |
| IR(파서) | `export-tables`: table0 = 1행 1열 단일 셀에 **1,471자** | 정상 — 읽기는 됨 |
| render tree p1 | `Table` 1 + `Cell` 1(자식 44) | 분할 조각 없음 |
| render tree p2 | `Cell` 6 — 이는 **다른 표**(table1, 3×2) | 이어짐 아님 |
| studio Canvas p2 | 하단 33% 잉크 **0.02%** (p1 하단 17.72% 대비) | 백지 |

즉 **파서는 읽었고 레이아웃이 버렸다.** SVG·Canvas·확장 등 백엔드 차이가 아니라
공통 상류(레이아웃)의 결함이다.

### 조사 오판 기록 (재발 방지)

초기에 "재현 안 됨"(SVG·wasm 정상) → "Canvas 백엔드 결함"(p2 384자를 정상으로 오인)으로
두 번 오판했다. 원인은 **정답지 없이 자기 산출물끼리만 비교**한 것이다. p2 에 384자가
있다는 사실만 보고, 있어야 할 3,633자와 대조하지 않았다. 정답지 PDF 를 먼저 만들었다면
첫 측정에서 잡혔다.

## 2. 유력 가설

`layout_partial_table_item`(`renderer/layout.rs:7668`)은 **행 범위**(`start_row`/`end_row`)
기반으로 분할 조각을 만든다. 이 fixture 의 문제 표는 **1행 1열 단일 셀**이라 나눌 행이
없어 분할 대상이 되지 못하는 것으로 보인다. 즉 "행 단위 분할"만 지원하고 **"셀 내부
문단 단위 분할"이 없다.**

Stage 1 에서 이 가설을 확정하거나 기각한다. 기각되면 다른 축(높이 측정, 페이지 잔여
높이 판정, `is_block_split` 경로)을 순차 확인한다.

## 4. 검증 기준

> 갱신(2026-08-01, 추적 2차): "텍스트 총량 일치" 기준은 폐기한다 — SVG `<text>` 노드
> 추출과 pdftotext 는 집계 방식이 달라 총량 비교가 성립하지 않는다(clip 된 텍스트도
> SVG 에는 방출됨). 분포·경계 텍스트 기준으로 대체.

1. **쪽별 텍스트 분포가 한컴 정답지(45%/55%)와 일치** — 통짜 배치 시 84%/16% 로 쏠린다.
2. **p2 시작 텍스트가 정답지와 일치** ("경과되지 않은 외국인투자기업인…") — 분할점 검증.
3. 분할 조각(`PartialTable`)이 p1·p2 양쪽에 생성될 것. `LAYOUT_OVERFLOW_CELL` 0건.
4. studio Canvas p2 하단 잉크가 백지(0.02%)가 아닐 것.
5. **정답지 PDF 이미지 스왑 대조** 통과.
6. 회귀: release-test 전체(92셋 포함)·issue_1891 쪽수 fixture·samples 전수 쪽수 A/B.
7. 최종: 작업지시자 시각 판정.
