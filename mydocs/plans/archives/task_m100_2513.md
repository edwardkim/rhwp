## 2. 문제와 실제 활동

`@rhwp/editor` 사용자는 cross-origin iframe 내부 UI를 직접 제어하지 않고
`editor.loadFile(bytes, name)`의 Promise 완료를 문서 준비 신호로 사용한다. 현재 기본 호출은
로드 후 글꼴/검증 안내창을 기다리므로, iframe이 로딩 overlay 아래 있거나 사용자가 버튼을 누르지
않으면 문서는 렌더돼도 RPC가 60초 timeout된다.

#2389는 `{ suppressDialogs: true }` opt-in을 추가했지만 public SDK의 기본값과 첫 사용 예제는
여전히 대화형이다. embed 전용 SDK의 zero-option 경로가 결정적으로 완료되지 않는 것이 남은 결함이다.

## 3. 목표와 비목표

### 목표

- `@rhwp/editor.loadFile()`에서 `suppressDialogs` 생략 시 비대화형 로드를 기본 적용한다.
- `{ suppressDialogs: false }`를 명시하면 기존 안내창 동작을 유지한다.
- top-level Studio와 raw embed protocol의 기존 기본값은 유지한다.
- modal click 없는 fresh iframe 회귀 테스트로 Promise settle을 증명한다.

### 비목표

- Studio 전체 dialog 정책 변경
- font detection/validation UI 제거
- MessageChannel protocol version 변경
- legacy transport 제거 및 배포 인프라 변경

## 4. 선택지와 결정

1. **SDK 생략 기본값만 `true`로 변경 (권장).** embed API의 일반 호출을 안전하게 만들고
   explicit `false`로 호환 경로를 남긴다. 변경 범위가 `npm/editor`와 embed E2E에 한정된다.
2. `createEditor()` 전역 옵션 추가. 인스턴스별 정책은 명확하지만 API surface와 상태 전달이 늘어난다.
3. 현 opt-in 유지 + 문서만 강조. 이미 README가 권장하고도 실제 consumer가 timeout했으므로
   root cause를 제거하지 못한다.

결정: 1번. direct protocol은 기존 `false`를 유지해 SDK 외 consumer의 계약을 바꾸지 않는다.
