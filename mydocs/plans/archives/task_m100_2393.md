# 수행계획서 — #2393 CI 기본 테스트 job 병렬화 (nextest archive + 8샤드)

- 이슈: #2393 / 브랜치: local/task2393 / 마일스톤: M100
- 실측 기준: devel run 29646668098 — job 17분 (테스트 8.4 + 빌드 5 + 부대 ~3)
- 작업지시자 결정: 8샤드

## 단계

### 1단계 — CI 재구성 (ci.yml)

1. `Build default-feature tests` job 을 분해:
   - **build-test-archive**: cargo-nextest 설치 → `cargo nextest archive
     --profile release-test --archive-file tests.tar.zst` → 아티팩트 업로드
     (release/release-test 프로필 분기는 현행 조건 유지)
   - **test-shard (matrix 1..8)**: 아티팩트 다운로드 → `cargo nextest run
     --archive-file tests.tar.zst --partition hash:{i}/8` — 컴파일 없음
   - **lint job (병렬)**: fmt check + clippy + WASM check 를 테스트 임계
     경로에서 분리 (기존 단일 job 의 부대 단계 이전)
2. 캐시: 수동 cargo 캐시 → `Swatinem/rust-cache@v2` 교체 (빌드 job 한정,
   저장 조건 현행 devel/main 정책 유지)
3. 브랜치 보호 required check 명이 바뀌므로 — job 명은 기존 "Build & Test"
   게이트(집계 job)가 8샤드 + lint 를 needs 로 묶어 **단일 required check
   의미 보존** (ruleset 변경 불요가 목표, 불가피 시 작업지시자 보고)
4. native-skia job·frontend 게이트·CodeQL 은 불변

### 2단계 — 공허 통과 방지 게이트 (#2353 교훈)

- 각 샤드가 실행 테스트 수를 로그로 남기고, 집계 job 이 **8샤드 합계 =
  전체 기대치(±0)** 를 대조 — 샤드 누락·파티션 중복이 green 으로 위장하는
  것을 차단
- nextest `--partition hash:i/8` 는 순열 안정 — 전체 커버 보장은 합계 대조로
  실증

### 3단계 — 실측 검증

- 브랜치 push → CI 실행 → before(17분)/after wall-clock 실측 기록
- 전 샤드 green + 테스트 수 합계 일치 + lint job green
- devel 반영 후 다음 PR 1건에서 재확인

## 게이트 요약

| 게이트 | 기준 |
|--------|------|
| 테스트 보존 | 샤드 합계 = 현행 전체 수 (누락/중복 0) |
| required check | "Build & Test" 의미 보존 (ruleset 무변경 목표) |
| wall-clock | 17분 → 10분 이내 (작업지시자 조정 2026-07-19; 5분대 한정 아님) |
| 무회귀 | native-skia·frontend·CodeQL 불변 |
