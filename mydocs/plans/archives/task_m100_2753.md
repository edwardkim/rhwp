# 타스크 수행계획서 — #2753 mydocs/report 파일명 규칙 정리

- 이슈: [#2753](https://github.com/edwardkim/rhwp/issues/2753)
- 브랜치: `task/2753-report-naming`
- base: `devel` @ `bd442b2a`
- 담당: edwardkim

## 1. 배경과 문제

`mydocs/report/` 의 보고서 파일명 규칙은 `docs_and_git_workflow.md` 가 정한
`task_m100_{issue}_report.md` 다. 2026-07-21 전수 조사에서 규칙 밖 명명 22건을 확인했고,
그중 **21건이 07-20~21 이틀 사이에 유입**됐다. 통합 PR 검토에서 코드 게이트는 돌렸으나
문서 파일명이 점검 항목에 없었던 것이 원인이다.

## 2. 조사 결과 (구현 전 확정)

| 분류 | 건수 | 조치 |
|---|---:|---|
| 정규 `task_m100_{issue}_report.md` | 302 | 없음 |
| `task_m100_` 접두 파생문서 (`_pr_body`/`_measurement`/`_pr_draft`) | 25 | **없음** — 이슈 번호 규칙 준수, 최종 보고서가 아님 |
| `PR-*` / `pr-*` | **22** | rename |
| `survey_10k_r*` (12) / `survey_pipage` (1) / `hwpx_lossless_3axis_*` (3) | 15 | rename 안 함, 예외 명문화 |

### 사전 안전성 확인 (완료)

- **rename 충돌 0건** — 대상 22건의 목표 파일명이 `report/` 에 이미 존재하는 경우 없음
- **외부 참조 0건** — `git grep -F <구파일명> -- ':!mydocs/report/'` 결과 없음. 다른 문서·코드가
  구 파일명을 가리키지 않으므로 rename 이 링크를 깨지 않는다

### 기계적 rename 금지 근거

`PR-2607-*.md` 의 `2607` 은 **PR 번호**이고 실제 이슈는 본문의 `#2606` 이다.
`PR-` 접두 8건이 **전부 1씩 어긋난다**. 파일명 숫자를 쓰면 8건이 틀린 번호로 고정된다.
GitHub 는 이슈와 PR 이 번호 공간을 공유해 `gh issue view` 로 종류를 판별할 수 없으므로,
**본문의 `Issue: #NNNN` 줄만을 근거로 삼는다**(22건 전부 확보 완료).

## 3. 작업 단계

### 1단계 — rename 22건

- `git mv` 로만 수행. **파일 내용은 한 줄도 수정하지 않는다**
- 매핑은 이슈 #2753 본문의 확정표를 그대로 따른다
- 수행 후 검증:
  - `git status` 가 22건 전부 `R`(rename) 로 인식하는지 — `A`+`D` 로 잡히면 내용이 바뀐 것
  - `ls mydocs/report/ | grep -cE "^(PR-|pr-)"` → 0
  - `git grep -F` 로 구 파일명 잔여 참조 재확인 → 0

### 2단계 — 예외 조항 명문화

`mydocs/manual/codex/docs_and_git_workflow.md` 의 `Working Document Naming` 절에 추가:

> 회차형 측정 기록(서베이·벤치마크 등 동일 축을 반복 측정해 시계열로 비교하는 문서)은
> `{주제}_{회차}_{YYYYMMDD}.md` 를 쓴다. 이슈 1:1 대응이 아니므로
> `task_m100_{issue}_report.md` 규칙을 적용하지 않는다.

근거: `survey_10k_r5`~`r18` 은 하나의 연속 측정 시리즈이고 회차·날짜가 식별자다.
`task_m100_2279_report.md` 로 몰면 12개 회차가 한 이름을 두고 충돌하며 시계열 비교라는
문서의 목적이 사라진다.

### 3단계 — 재발 방지 체크리스트

`mydocs/manual/pr_review_workflow.md` 의 `2.2 기본 메타` 절에 항목 추가:

> - [ ] **문서 파일명**: `mydocs/report/` 신규 파일이 `task_m100_{issue}_report.md` 규칙을
>   따르는지. 파일명의 숫자가 PR 번호일 수 있으므로 본문의 `Issue: #N` 과 대조한다.
>   회차형 측정 기록은 예외(`docs_and_git_workflow.md` 참조)

CI 기계 검사는 **이번 범위에서 제외**한다 — 2단계 예외 조항 때문에 단순 정규식은 오탐이 난다.
필요하다면 별도 이슈로 분리한다.

## 4. 검증 계획

문서·파일명 변경만이라 코드 게이트는 해당 없으나, 저장소 정합을 위해 다음을 수행한다.

- `git status` rename 인식(`R`) 22건 확인
- 구 파일명 잔여 참조 0 확인
- 링크 검사: 변경한 두 매뉴얼 문서의 상대 링크 유효성
- `cargo fmt --all --check` — 코드 무변경 확인 목적
