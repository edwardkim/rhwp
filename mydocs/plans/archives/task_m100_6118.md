## 1. 배경과 실측

현재 `#style-bar`는 화면 폭보다 1024/768px의 device breakpoint를 우선해 레이아웃을 바꾼다. 그 결과
실제 콘텐츠가 들어가는 화면에서도 불필요하게 행이 늘어난다.

2026-08-26 로컬 브라우저에서 현재 코드를 계측한 결과는 다음과 같다.

| viewport | 현재 결과 | 확인된 여유·제약 |
| --- | --- | --- |
| 1024px | 69px 높이의 caption 포함 한 행 | 전체 그룹이 오른쪽 약 1016px까지 들어감 |
| 1023px | field 1행 + command 1행, 86px | CSS grid가 약 500px씩만 사용하고 나머지 폭을 비움 |
| 768px | field 1행 + command 1행, 86px | 첫 번째 참고 이미지와 같은 안정된 2행 |
| 767px 이하 | field + character/color + paragraph 3행, 123px | `flex-direction: column`과 paragraph `width:100%`가 강제 |
| command | 모바일 버튼 기준 약 447px | bar padding을 포함해 약 460px부터 command 한 행 가능 |
| field | grid 최소 약 378px | 375px에서 `scrollWidth 384 > clientWidth 375` 관측 |

따라서 `1280px 이상`이라는 고정 조건이나 `767px 이하 3행`은 실제 콘텐츠 폭을 설명하지 못한다.

## 2. 제품 결정

서식 도구 모음은 두 가지 시각 구조만 사용한다.

### 2.1 전체 압축 1행

필드와 명령 전체가 들어가는 너비에서는 다음을 적용한다.

- field와 command를 모두 한 줄에 표시
- group caption과 field label은 접근성 연결을 보존한 채 시각적으로 감춤
- 높이 36px 이하
- 줄바꿈·page-level 가로 overflow 없음
- 적용 경계는 device 이름이 아니라 압축 후 intrinsic width와 안전 여백을 측정해 결정

### 2.2 압축 2행

전체가 한 줄에 들어가지 않으면 첨부 참고 이미지와 같은 구조를 사용한다.

1. 첫째 줄: 스타일, 언어, 글꼴, 크기, 줄 간격
2. 둘째 줄: 글자 모양, 색, 문단 명령

외부 `#style-bar`의 배경과 경계는 화면 전체 너비를 유지한다. 내부 field/command track은 고유 콘텐츠
폭까지만 차지하고 왼쪽 정렬해 화면이 넓어져도 불필요하게 늘어나지 않는다.

command 한 행까지 들어가지 않는 좁은 너비에서는 세 번째 행을 만들지 않는다. paragraph처럼 낮은
우선순위의 후행 command group을 둘째 줄 마지막의 더보기 패널로 이동해 동일한 2행 구조를 유지한다.
field 행은 글꼴 칸을 우선 유연하게 축소해 지원 최소 375px에서도 page-level overflow를 만들지 않는다.

```text
충분한 폭       field + character + color + paragraph                  1행
제한된 폭       field                                                    1행
                character + color + paragraph                            2행
아주 좁은 폭    field                                                    1행
                character + color + [더보기: paragraph]                  2행
```

- 내부 track의 intrinsic/max width 제한과 왼쪽 정렬

## 5. 단계별 수행계획

### Stage 1 — 기준선과 콘텐츠 경계 고정

1. 현행 1920~375px의 field/group geometry, 행 수, 높이와 overflow를 같은 식으로 계측한다.
2. caption을 감추고 padding을 압축한 전체 1행의 intrinsic width와 안전 여백을 산정한다.
3. 2행 command track과 paragraph 제외 command track의 최소 폭을 각각 고정한다.
4. 모든 control ID·label·command·active state 보존 목록을 만든다.
5. `mydocs/working/task_m100_6118_stage1.md`에 breakpoint 근거를 기록한다.

**종료 게이트**: 전체 1행 전환점, command 더보기 전환점과 375px field 최소 계약이 수치로 고정되고
제품 source는 아직 변경되지 않은 상태다.

**완료 결과(2026-08-26)**: [Stage 1 보고서](../../working/task_m100_6118_stage1.md)에
`FULL_ROW_MIN=976px`, `COMMAND_INLINE_MIN=460px`, `FIELD_MIN=375px`의 실측 근거와 보존할 control
목록을 고정했다. 제품 source 변경은 0건이다. 이후 사용자 시각 검토에서 데스크톱 첫 콤보를 메뉴
텍스트 축은 border가 아니라 select 내부 option 텍스트를 기준으로 다시 보정했다. 사용자 검토에서 한 줄
compact 단계를 추가한 최종 경계는 962/961px, 808/807px, 460/459px이다.

### Stage 2 — 1·2행 CSS와 더보기 구현

1. 전체 1행과 압축 2행을 하나의 콘텐츠 기반 breakpoint로 전환한다.
2. field/command track을 `max-content` 계열 폭과 `max-width:100%`로 제한한다.
3. 375px에서 field의 글꼴 칸과 gap을 축소하되 입력 높이와 접근성 이름은 유지한다.
4. 좁은 화면에서는 paragraph group을 더보기 panel로 표시하고 세 번째 행을 금지한다.
5. 더보기 panel의 focus, Escape, 외부 click, active/disabled 동기화를 구현한다.
6. 정적 계약 테스트와 기존 responsive E2E를 갱신한다.
7. `mydocs/working/task_m100_6118_stage2.md`에 구현 결과를 기록한다.

**종료 게이트**: 모든 지원 viewport에서 1행 또는 최대 2행이며, 모든 명령에 inline 또는 더보기로
도달하고 page-level 가로 overflow가 없다.

**완료 결과(2026-08-26)**: [Stage 2 보고서](../../working/task_m100_6118_stage2.md)에 DOM/CSS/controller와
정적·E2E 계약을 고정했다. 최종 보정 기준으로 962px 이상은 36px 전체 단일 행, 961~808px은 paragraph를
접은 단일 행, 807~460px은 2행 inline, 459~375px은 2행과 paragraph 더보기로 동작한다.

### Stage 3 — 브라우저·테마 검증과 제출 준비

1. 1920, 1280, 1024, 962, 961, 883, 808, 807, 768, 460, 459, 412, 390, 375px을 검증한다.
2. default/flat/oldschool × light/dark의 높이·행·경계·focus를 확인한다.
3. field 입력, character/color dropdown, paragraph 더보기 명령을 실제로 조작한다.
4. TypeScript, Studio test/build, responsive E2E와 포맷·문서 검증을 실행한다.
5. `mydocs/working/task_m100_6118_stage3.md`와 `mydocs/report/task_m100_6118_report.md`에 결과와
   대표 screenshot을 기록한다.

**종료 게이트**: 기능·반응형·접근성·테마 검증이 모두 통과하고 PR에 재현 가능한 근거를 제시할 수 있다.

**완료 결과(2026-08-27)**: [Stage 3 보고서](../../working/task_m100_6118_stage3.md)에 14개 viewport,
default/flat/oldschool × light/dark 24개 조합, 실제 field·dropdown·더보기 상호작용을 고정했다.
최종 통합 responsive/theme E2E 821건이 통과했고 oldschool 단일 행의 37px 경계를 36px로 보정했다.
