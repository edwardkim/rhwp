# 수행계획서 — 웹한글기안기 제품규격서 V1.1 4페이지 서버 구성도 좌표 복구 (M100 #3257)

- **이슈**: [edwardkim/rhwp#3257](https://github.com/edwardkim/rhwp/issues/3257)
- **브랜치**: `task/3257-webhangul-product-spec-page4` (`upstream/devel@4b5514457` 기준)
- **작성일**: 2026-07-24

## 1. 목표

사용자 제공 HWP `웹한글기안기 제품규격서_V1.1`의 4페이지에서 `용도별 서버 구성` 그림이
오른쪽으로 밀려 잘리는 회귀를 고친다. HWP 2020 기준 PDF의 배치와 rhwp SVG/render tree를
대조하여, 하단 서버 구성도가 본문 폭 안에서 온전히 보이도록 한다.

## 2. 재현 자료와 관측 근거

| 항목 | 값 |
|---|---|
| 회귀 fixture | `samples/issue3257/webhangul_product_spec_v1.1.hwp` |
| 원본 HWP SHA-256 | `40c7dfb901acb834cd2acb1726b15d2cb95d49e1e745d50e3cb95b2c37162fd6` |
| 기준 PDF | `pdf/issue3257/webhangul_product_spec_v1.1-2020.pdf` (6쪽, HWP 2020 변환 `run_status=0`, `validation=ok`) |
| 문제 위치 | 4페이지, section 0 / paragraph 75 / control 0 (`Picture`, `treat_as_char=true`) |
| 현재 rhwp | 그림 bbox `x=416.9`, `w=574.1`; 페이지 우측 밖으로 잘림 |
| 기준 위치 | 기준 PDF의 그림 좌측은 약 `x=129`; 그림 전체가 본문 안에 있음 |

`pi=75`는 Center 문단의 공백 6자 뒤(문단 끝 위치)에 TAC 그림이 놓인 구조다. render tree는
그림을 실제로 방출하지만, 정렬 폭의 `line_tac_offsets_for_width`에는 해당 끝 위치 그림이
들어가지 않는다. 따라서 40px짜리 공백만 가운데 정렬한 `x=376.9` 뒤에 그림을 붙인다.

이슈의 상단 그림(`pi=72`)은 Justify 문단이라 같은 구조여도 가운데 정렬 오차가 드러나지
않는다. 따라서 일반적인 그림 좌표/크롭 문제가 아니라 **끝 위치 TAC와 가운데 정렬 폭 계산의
불일치**다.

## 3. 범위와 안전 조건

| 포함 | 제외 |
|---|---|
| 본문 최종 run 또는 명시 줄바꿈의 끝 위치 TAC를 실제 방출과 같은 조건으로 정렬 폭에 포함 | parser, 이미지 크기/크롭, HWP 파일 원본 변경 |
| 다음 줄이 같은 문자 위치에서 시작하면 해당 TAC를 앞 줄 폭에서 제외 | 다음 줄 선두 TAC를 앞 줄에 중복 포함하는 #1219 회귀 복원 |
| #3257 HWP fixture와 기준 PDF 보존, render tree/시각 회귀 근거 | 전 문서군의 임의 좌표 보정 또는 page-4 전용 하드코딩 |

## 4. 구현 설계

1. `paragraph_layout.rs`에 정렬 폭 전용 TAC 집합 helper를 둔다.
   - 기존의 엄격한 줄 범위(`start <= pos < next line start`)를 기본으로 유지한다.
   - 마지막 run의 끝 위치 TAC는 renderer의 `allow_end_tac`과 같은 조건일 때만 추가한다.
   - 다음 composed line이 같은 run 끝 위치에서 시작하면 추가하지 않는다. 이 규칙은 #1219의
     줄 경계 수식 오포함 방지를 그대로 보존한다.
2. 해당 helper를 `line_tac_offsets_for_width` 생성에 사용한다. 기존의 우측 정렬 셀 TAC 표
   보정은 새 일반 규칙에 중복되지 않는지 확인하고 필요한 좁은 예외만 보존한다.
3. 실 방출과 같은 폭을 `estimate_line_run_widths`, `total_tac_width_in_line`,
   `non_cell_tac_only_line`에 전달해 Center/Right/Distribute 정렬 기준을 통일한다.

## 5. 검증 계획

1. 순수 helper 단위 테스트
   - 최종 줄의 공백 뒤 TAC는 폭 집합에 포함한다.
   - 다음 줄이 같은 문자 위치에서 시작하면 앞 줄 폭 집합에는 포함하지 않는다.
   - 명시 줄바꿈 끝 위치의 TAC도 renderer와 같은 줄에만 포함한다.
2. fixture render-tree 회귀 테스트
   - #3257 fixture의 4페이지 `pi=75, ci=0` image bbox 좌측이 약 `129px`임을 검증한다.
   - 이전 결함값 `416.9px`와 구별되는 범위를 사용한다.
3. focused Rust 검증: formatter, 해당 renderer unit/integration test, SVG 및 render-tree export.
4. 시각 검증: HWP 2020 PDF 4페이지와 수정 후 rhwp 4페이지를 같은 해상도로 렌더하여 실제
   이미지가 보이는 비교 자료(원본·rhwp·차이/주석 패널)를 `mydocs/pr/assets/`에 남긴다.
   최종 한컴 실물 판정은 작업지시자가 확인한다.
