# 문서 확대/축소 반응성 조정 설계

- 대상: `rhwp-studio`
- 승인: 휠 민감도와 완화 시간을 함께 조정한 뒤 민감도를 20% 추가 조정

## 목표

현재 부드러운 확대/축소 구조를 유지하면서 입력을 따라오는 속도와 이동량을 높인다.
Ctrl/Cmd+휠 입력 뒤에 남는 완화 꼬리를 줄여 사용자가 즉시 반응한다고 느끼게 한다.

## 선택한 설계

`ViewportManager`의 두 입력 조정값만 변경한다.

- 정규화된 휠 민감도를 `0.002`에서 `0.0035`로 높인 뒤 실제 사용 피드백에 따라
  `0.0042`로 20% 추가 조정한다.
- 지수 완화 시간 상수를 `45ms`에서 `22ms`로 줄인다.

첫 조정에서는 민감도와 완화 시간을 함께 변경해 이동량과 지연감을 동시에 개선했다.
두 번째 조정은 완화 시간과 렌더링 구조를 유지하고 민감도만 20% 높여 사용자가 요청한
추가 이동량을 제공한다.

## 보존 계약

- 버튼과 키보드 확대/축소 단계는 `0.1`을 유지한다.
- 연속 입력을 하나의 animation frame 흐름으로 합치는 구조를 유지한다.
- 확대/축소 중 기존 페이지를 CSS로 미리보기하고 완료 후 다시 렌더링하는 구조를 유지한다.
- 현재 페이지 중심점의 상대 위치를 보존하는 스크롤 보정을 유지한다.
- 최소·최대 확대 배율과 즉시 적용하는 `setZoom` 계약을 변경하지 않는다.
- 관련 없는 UI, CSS, 문서 렌더러 변경은 포함하지 않는다.

## 검증

1. 기존 확대/축소 회귀 테스트의 이동량 계약을 `0.0042`에 맞게 조정한다.
2. 테스트가 `0.0035`에서 실패하는 것을 확인한 뒤 민감도 상수만 변경한다.
3. 확대/축소 집중 테스트와 전체 Node 테스트를 실행한다.
4. TypeScript/Vite production build와 `git diff --check`를 실행한다.
5. 실제 브라우저의 실제 6쪽 문서에서 같은 미세 휠 입력을 보내 다음을 확인한다.
   - 최종 배율 변화량이 기존보다 커졌는지
   - 확대/축소가 정착하는 시간이 짧아졌는지
   - 애니메이션 중 페이지 재렌더링이 없는지
   - 페이지 중심점의 상대 위치가 유지되는지
