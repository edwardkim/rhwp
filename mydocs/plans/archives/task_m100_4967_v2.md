## 1. 이번 절편의 결정과 목표

이번 절편은 W4 action rank 1 `문체부 바탕체`의 높은 위험량을 곧바로 제품 결함으로 간주하지 않고,
현재 rhwp의 실제 face-name 정규화와 metric 선택을 먼저 판정한다.

핵심 질문은 다음과 같다.

> W4가 `문체부 바탕체`를 face miss로 센 원인이 실제 제품 runtime의 metric miss인가, 아니면 문서의
> localized face를 `MBatang`으로 정규화하기 전 이름을 계측한 관찰 경계의 차이인가?

그 답에 따라 이번 절편의 산출은 다음 셋 중 하나다.

1. **qualified**: 현재 동작과 기대 동작의 첫 divergence, 정확히 한 decision plane, 실제 영향 cohort와
   비회귀 조건을 고정하고 별도 product-correction 자식 이슈 초안을 준비한다.
2. **no-change**: runtime이 이미 exact `MBatang` metric을 사용하거나 후보 변경이 actual fixed frame을
   악화시키므로 제품 규칙을 바꾸지 않는다. W4 계측 경계가 원인이면 계측 계보의 정정 필요성만 분리한다.
3. **blocked**: source provenance·재배포 또는 동일 snapshot의 실제 geometry를 판정할 증거가 부족하면
   그 재개 조건만 기록하고 제품 규칙을 바꾸지 않는다.

qualification 통과 자체는 metric DB·registry·fallback·paint·font supply 변경이나 GitHub 자식 이슈 등록을
승인하지 않는다.

## 3. 착수 가설

현재 source에는 다음처럼 서로 다른 관찰 경계가 공존한다.

- serializer name table에는 `문체부 바탕체` → `MBatang` 매핑이 있다.
- generated metric DB에는 `MBatang` regular metric이 있다.
- W4 공개 ranking은 raw document face `문체부 바탕체`의 208,949자를 `face-miss`로 집계했다.
- v2 registry에는 rank 1의 명시적 layout-name·layout-metric·paint·supply rule이 없다.

따라서 첫 가설은 제품 metric을 추가해야 한다는 것이 아니라 다음과 같다.

```text
provisional hypothesis:
  W4 계측은 localized document face를 runtime canonical name으로 정규화하기 전 경계에서 metric coverage를
  판정했을 수 있다. 실제 runtime trace가 MBatang metric을 선택한다면 W4 face-miss는 제품 결함이 아니다.

provisional targetDecisionPlane:
  미확정 — layout-name, layout-metric, paint, supply 중 Q1에서 하나만 선택하거나 no-change로 종료
```

HWP와 HWPX가 서로 다른 parser/name-normalization 경로를 거치므로 format을 합쳐 추정하지 않는다. 또한
stored LineSeg 존재는 metric 교정 적용 근거가 아니다. admission validity를 같은 snapshot에서 기능 탐지한다.

### Stage W8-R1-Q0 — 증거 호환성·source 경계 고정

1. W4 ranking, W5 ladder/profile, W7.5 registry의 digest와 semantic parent를 검사한다.
2. `MT.TTF`의 name table, unitsPerEm, cmap, `hmtx`와 face index를 재확인하되 bytes를 외부로 복제하지 않는다.
3. 공개 배포·license anchor를 기존 조사와 공식 출처 증거로 구분한다. 확인되지 않은 재배포·successor 관계는

4. W3 checkpoint에서 rank 1 문서 집합을 재파싱 없이 결정적으로 선택하고 identity는 local-only 원장에 둔다.

**종료 게이트**: 동결 digest가 일치하고 exact source identity와 공개 가능 범위가 분리되며, 새 전수 계측 없이

**실행 결과 (2026-08-25)**: W3 journal을 새 corpus parse 없이 1회 streaming 조회해 rank 1 실제 22문서
(HWP 15, HWPX 7)를 재선정했다. target 209,066자 중 W4 위험 208,986자와 category·format·compressed
fixed-context 수치가 모두 일치했고 위험 문자는 전부 stored lane이었다. exact `MT.TTF`는 SHA-256과
localized/English family pair, unitsPerEm 1000, cmap·hmtx를 재확인했다. 현행 metric projection에는
`MBatang` entry 370이 있지만 v2 registry의 `문체부 바탕체`/`MBatang` explicit rule은 0이다. 공식 안내의
이용조건과 local bytes의 동일성은 증명되지 않았고 `OS/2.fsType=2`이므로 portable font supply는
qualification하지 않았다. 10k·Hyper-V·제품 mutation은 모두 0이다.

### Stage W8-R1-Q1 — runtime name·metric 관찰 경계 판정

1. 공개 fixture에서 raw document face, parser normalization, layout-name, layout-metric lookup과 paint family를
   각각 기록한다.
2. HWP와 HWPX를 독립 판정하고 native와 Docker WASM의 canonical trace가 같은지 확인한다.
3. `문체부 바탕체`가 `MBatang` metric에 도달하면 W4 face-miss와 runtime hit의 관찰 경계 차이를 증명한다.
4. 도달하지 않으면 첫 divergence가 parser normalization인지 registry alias인지 metric lookup인지 한 plane으로
   좁힌다.

**종료 게이트**: W4 위험량이 제품 miss인지 계측 projection 차이인지 판정되고, target decision plane이
하나로 확정되거나 `no-change`로 종료된다.

**실행 결과 (2026-08-25)**: 공개 HWPX fixture와 그로부터 결정적으로 변환한 HWP fixture를 같은
Font Decision Trace로 비교했다. 두 형식 모두 target 1,556건에서 requested·normalized·alias-resolved
face가 `문체부 바탕체`, layout-name step 0, metric entry `null`, match kind `none`이었고 native와 현행
WASM의 canonical trace가 byte-exact했다. 따라서 W4 face miss는 raw-name 계측 projection의 오탐이 아니라
현재 HWP/HWPX runtime의 실제 unresolved 경계다. 기존 `MBatang` metric anchor에 도달하기 전에 갈라지는
첫 decision plane은 `layout-name`으로 확정했다. Q2는 제품 mutation 없이 가상 name relation을 적용해
현행 generated `MBatang` metric과 exact `MT.TTF hmtx`의 호환성을 제한 비교한다. 10k·Hyper-V 재실행은
모두 0이다.

### Stage W8-R1-Q2 — exact SFNT와 현행 metric의 제한 비교

1. fixture와 bounded cohort의 실제 사용 문자만 대상으로 generated `MBatang` metric과 exact `MT.TTF hmtx`를
   비교한다.
2. current transform의 장평·자간 적용 순서를 그대로 재생하고 run 누적 advance와 첫 frame crossing을 계산한다.
3. name match와 metric compatibility, glyph/paint identity, font supply 가능성을 서로 독립 판정한다.
4. 이미 exact-derived metric이 사용된다면 중복 rule을 만들지 않고 `no-change` 후보로 회수한다.

**종료 게이트**: 제품 후보가 정확히 한 plane에서 current→candidate 차이로 설명되거나 변경 없이 종료된다.

**실행 결과 (2026-08-26)**: 현행 historical generated `MBatang` entry 370과 exact `MT.TTF hmtx`를
source에서 직접 읽고 Q1 trace의 transform을 재생했다. 가상 `문체부 바탕체 -> MBatang` relation은
Hangul 1,000 HWPUNIT, space 500 HWPUNIT을 선택하고 그 밖의 문자는 기존 heuristic을 보존한다. exact
source가 보유한 layout-bearing 2,351 codepoint의 advance mismatch는 0이며 source가 보유하지 않은 문자는
가상 relation 결과를 그대로 보존한다. 이 base 동치는 장평·자간·justification·clamp 뒤에도 유지됐다.
공개 fixture 1,556건과 fixed-frame 6축의 total advance·첫 crossing 변화는 모두 0이다. 특정 cohort 문자
목록보다 강한 전체 layout-bearing domain 동치를 증명했으므로 private 22문서를 다시 parse하지 않았다.
제품 alias가 layout 이득을 만들지 않고 metric entry의 exact source 계보도 `unknown`이므로 rank 1은
`no-change`로 종료하며 Q3에 진입하지 않는다.

**종료 게이트**: backend별 적용·비대상·미지원 이유와 portable 정책이 모순 없이 설명된다.

## 6. 보호 불변식과 중단 조건

- version/build 분기가 아니라 현재 face resolution·metric lookup·LineSeg admission 상태를 기능 탐지한다.
- localized name, identity, document substitution, official successor, surrogate, missing-font를 섞지 않는다.
- layout metric과 glyph/paint identity, web supply 가능성을 각각 분리한다.
- actual fixed geometry의 한 줄 회귀도 평균 폭·page count 개선으로 상쇄하지 않는다.
- 기존 계측 자료가 유효한 동안 전수 재계측·Hyper-V 재실행을 반복하지 않는다.
- source provenance·재배포 조건이 불명한 font bytes를 저장소나 web backend에 넣지 않는다.
- private corpus identity·본문·hash를 공개하지 않는다.

다음 중 하나면 해당 stage에서 중단한다.

- W4/W5/W7.5 입력 hash 또는 exact SFNT identity 불일치
- HWP/HWPX의 첫 divergence를 한 decision plane으로 좁힐 수 없음
- same-snapshot actual frame 또는 stored-row admission을 판정할 수 없음
- source bytes 공급을 identity나 metric correctness의 전제로 오인해야만 후보가 성립함
- modelled cohort에서 신규 overflow·line-boundary 회귀 발생
