## 문제

거대 표 셀의 양쪽·배분 정렬 줄에서 영문·숫자 glyph 윤곽 자체가 가로로 확대된다.
레이아웃이 다음 cluster의 시작 위치에 배분한 extra_char_spacing을 Canvas2D와 SVG가
현재 glyph의 목표 폭으로도 사용한 것이 원인이다.

이 문제는 #3815와 #3822 통합 검증 중 발견됐지만 두 작업이 도입한 회귀는 아니다.
#3815는 Studio scheduler, #3822는 composer 줄바꿈을 변경하며 이 renderer 경로는
그 이전부터 존재했다.

## 설계

1. 문자 origin·줄바꿈·pagination에 사용하는 layout advance는 유지한다.
2. Canvas2D/SVG의 glyph-fit 단계에서만 양수 extra_char_spacing을 제외한다.
3. 음수 간격은 #2189 셀 오버플로우 보정의 기존 browser glyph-fit 대상을 유지한다.
   measurement clamp 때문에 intrinsic advance를 새로 역산하지 않는다.
4. 명시적 장평, 첨자 배율, ASCII pinning, 반각 CJK 인용부호 계약을 유지한다.
5. Canvas와 SVG가 같은 TextStyle glyph-fit helper를 사용하도록 한다.

## 검증

- 양수·음수 spacing과 Canvas glyph-fit focused unit
- SVG renderer 전체
- wasm32-unknown-unknown library check
- HWP/HWPX 연속 IME→숫자 통합 E2E
- 사용자 브라우저 시각 판정
- formatting 및 diff gate

전체 release-test와 Native Skia 3종은 제한 검증과 시각 근거를 먼저 공유한 뒤
Draft PR 검토에서 추가 실행 여부를 결정한다.

## 완료 기준

- 문자 origin과 line/page count는 유지된다.
- 양수 배분 간격 전후 영문·숫자 glyph 폭이 같다.
- 음수 셀 보정은 기존 Canvas/SVG glyph-fit 폭을 유지한다.
- Canvas2D와 SVG의 동작이 일치한다.
- 실제 HWP/HWPX에서 가로 확대가 재현되지 않는다.
