## 1. 배경과 결함

`test-caption`은 고정 fixture 좌표 `(0,2)`, `(0,3)`, `(1,0)`, `(1,1)`의 그림 네 개에
Bottom/Top/Left/Right 캡션을 설정하고 그 상태를 확인한 뒤 SVG를 출력하는 내부 진단 명령이다.

현재 구현은 그림 속성 변경이 전부 실패하거나 확인 대상이 없어도 오류를 stdout에만 기록하고 계속 진행한다.
그 결과 원본 문서를 렌더한 SVG와 `완료`를 남기면서 exit 0을 반환한다. 이는 “캡션 라운드트립 검증”이라는
명령 의미와 공통 CLI exit code 계약을 어기는 false-pass다. #3789는 move-only 범위였으므로 이 제품 결함을
분리했고, #6381에서 해결한다.

## 2. 목표와 불변식

- 네 대상의 mutation과 verification이 모두 성공한 경우에만 SVG를 만들고 exit 0을 반환한다.
- 한 대상이라도 mutation 또는 verification에 실패하면 원인을 stderr에 기록하고 exit 1을 반환한다.
- 실패 실행은 성공을 뜻하는 `완료`와 SVG 산출물을 남기지 않는다.
- 범위를 벗어난 임의 문서에서도 panic(exit 101) 없이 제어된 exit 1을 반환한다.
- 성공 경로의 대상 좌표, 방향, 세로 정렬, 캡션 폭·간격, SVG 파일명은 유지한다.
- renderer·layout·document model과 `test-caption` 대상 선택 전략은 바꾸지 않는다.

## 3. 범위

### 3.1 범위 안

- mutation 실패 집계와 stderr 진단
- 대상 부재·비그림 control·캡션 속성 불일치 검증
- 실패 시 렌더·저장 전에 exit 1로 종료
- all-fail, partial-fail, all-pass CLI 회귀 계약
- 내부 CLI 문서의 성공·실패 조건 보정

### 3.2 범위 밖

- 고정 좌표를 자동 그림 탐색으로 일반화
- 캡션 setter, renderer, pagination 또는 SVG 의미 변경
- 새 공개 command·option·JSON schema 추가
- #3789의 Render Diff path 정책 재조정

## 4. 단계별 수행계획

### Stage 1 — 계약과 재현 고정

1. 기존 임의 문서 회귀를 all-fail exit 1 계약으로 바꾼다.
2. 테스트가 생성한 HWP fixture로 partial-fail과 all-pass를 재현한다.
3. 성공·실패의 stdout, stderr, 산출물 조건을 명시한다.

**종료 게이트**: 구현 전 실패하는 세 회귀 시나리오가 서로 다른 결함 경계를 고정한다.

### Stage 2 — fail-closed 구현

1. mutation 결과를 누적하고 실패를 stderr에 기록한다.
2. 네 대상의 control 종류와 캡션 속성을 정확히 확인한다.
3. 어느 단계에서든 실패가 있으면 SVG 출력 전 exit 1을 반환한다.
4. 성공 경로만 기존 page SVG 출력과 `완료`를 수행한다.

**종료 게이트**: all-fail·partial-fail은 exit 1, all-pass는 exit 0이며 panic이 없다.

### Stage 3 — 문서와 전체 검증

1. 내부 CLI 문서에 성공과 runtime/validation failure 조건을 반영한다.
2. focused test, Rust 정책 게이트, format, clippy와 전체 회귀를 순서대로 실행한다.
3. 파생 suite·manifest는 검증 증적으로만 사용하고 stage하지 않는다.

**종료 게이트**: 변경 범위별 필수 게이트가 통과하고 제출 diff가 source 원본만 포함한다.

### Stage 4 — review 보정

1. setter와 같은 `Shape(Picture)`·Endnote 가상 문단 해석 범위로 verification을 맞춘다.
2. 성공 테스트가 실제 verification 증적 네 건을 요구하도록 강화하고 setter 필드 계약을 고정한다.
3. help·capabilities·CLI 정본에서 고정 fixture 전용 명령임을 명시한다.
4. 최신 devel을 반영하고 새 Rust lint 묶음과 전체 회귀를 다시 통과한다.

**종료 게이트**: review 지적의 실제 결함과 회귀 공백이 닫히고 보정 head의 CI만 merge 조건으로 남는다.
