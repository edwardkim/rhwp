# 수행계획서 — Frontend package gates·Lint 병렬화 (M100 #3268)

- **이슈**: [edwardkim/rhwp#3268](https://github.com/edwardkim/rhwp/issues/3268)
- **브랜치**: `task/3268-frontend-lint-parallel` (`upstream/devel@204c56528` 기준)
- **작성일**: 2026-07-24

## 1. 목표

frontend 영향 PR에서 `Frontend package gates`가 Lint의 산출물을 기다리지 않고, 두 job이
`preflight` 완료 뒤에 병렬 시작하도록 한다. `Native Skia tests`와 `Build test archive`는 Lint와
Frontend가 모두 성공했을 때만 시작하도록 유지한다.

## 2. 근거

[CI run 30098091156](https://github.com/edwardkim/rhwp/actions/runs/30098091156)에서 Lint는
13:45:08–13:46:39 UTC, Frontend는 13:46:43–13:48:33 UTC에 실행됐다. 둘 사이에 작업 산출물
의존성은 없으나 `frontend-package-gates`의 `needs: [preflight, lint]` 선언 때문에 Native/archive
시작이 약 1분 35초 늦어진다.

## 3. 범위와 안전 조건

| 포함 | 제외 |
| --- | --- |
| Frontend의 선행 job을 `preflight`로 축소 | Lint fast-pass 제거 또는 문서-only PR의 불필요한 Lint 실행 |
| downstream Native/archive의 Lint·Frontend dual-success gate 유지 | Rust/TypeScript 제품 코드와 테스트 변경 |
| cache·workspace 격리와 Cargo lock 안전성 검증 | cache key·writer 정책 변경 |
| actionlint·YAML·DAG 계약 검사 및 원격 CI 확인 | Cargo 전체 회귀를 로컬에서 동시 실행 |

Lint와 Frontend는 각각 `ubuntu-latest`의 독립 runner에서 실행한다. 두 job은 작업 디렉터리와
`target/`을 공유하지 않으며, PR에서는 cache save도 하지 않는다. 따라서 이 병렬화는 Cargo 파일
lock을 만들지 않는다. Lint 실패 시 이미 시작된 Frontend가 끝날 수 있는 runner 비용은 허용하되,
Native/archive/shard는 시작하지 않게 한다.

## 4. 구현 설계

1. `frontend-package-gates.needs`를 `preflight`만 남긴다.
2. Frontend의 `if`는 preflight 성공, non-fast-pass, frontend-required 조건을 그대로 둔다.
3. Native Skia와 archive의 `needs` 및 조건은 그대로 두어 두 gate의 성공을 요구한다.
4. workflow 주석을 새 병렬 경로와 의도된 실패 비용에 맞춘다.

## 5. 검증 계획

1. `actionlint .github/workflows/ci.yml`, Ruby YAML parse, `git diff --check`를 실행한다.
2. 정적 DAG 계약 검사로 다음을 확인한다.
   - Frontend는 preflight만 필요로 하고 fast-pass·frontend-required 조건을 유지한다.
   - Lint와 Frontend는 모두 preflight 뒤 독립 job이다.
   - Native/archive는 Lint와 Frontend의 성공을 계속 요구한다.
   - shard는 archive와 Native Skia가 모두 성공해야 시작하며 aggregate를 보존한다.
   - Lint·Frontend는 별도 hosted runner·cache key를 사용하고 공유 `target/`을 만들지 않는다.
3. 원격 PR CI에서 Frontend 영향 run의 실제 시작 시각과 모든 required check를 확인한다.

## 6. 완료 기준

- Frontend 영향 PR에서 Lint·Frontend가 preflight 뒤 병렬 시작한다.
- Lint 또는 Frontend 실패 시 Native/archive/shard가 시작하지 않는다.
- fast-pass, frontend 비대상 skip, `Build & Test` 집계를 보존한다.
- Cargo lock을 유발하는 공유 workspace·`target/`·cache write가 없다.
- 구현·검증·보고서를 작업 브랜치에 커밋하고, 작업지시자 승인 후에만 PR을 생성한다.
- `mydocs/orders/20260724.md`는 PR 생성 승인 직전의 최종 준비 단계에서만 갱신한다.
