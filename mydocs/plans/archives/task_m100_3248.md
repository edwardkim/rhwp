# rhwp-studio 본문 입력 지연 개선 설계

- 대상: `rhwp-studio` 본문 텍스트 입력과 한글 IME 조합
- 승인: 즉시 로컬 표시 + 전체 문서 pagination 병합(A), IME 교체 입력 최적화 필수

## 목표

43쪽 HWP 문서의 실제 브라우저 측정에서 본문 한 글자 입력은 첫 화면 반영까지 약
83~89ms, 한글 IME 중간 글자 교체는 약 98ms가 걸렸다. 텍스트 자체의 변경·문단
reflow·recompose는 약 0.3ms였고, 동기 전체 pagination이 평균 38.5ms를 차지했다.

본문의 짧고 안정적인 텍스트 편집은 텍스트 변경, 문단 reflow, 현재 쪽 렌더를 즉시
수행한다. 사용자가 보는 글자와 현재 쪽 표시는 미루지 않는다. 현재 쪽 밖의 전체 문서
pagination만 120ms 입력 유휴 시점까지 병합한다. 줄·쪽 흐름이 바뀌거나 전역 기하가
필요한 경계에서는 현재 쪽을 그리기 전에 전체 pagination을 즉시 한 번 수행한다.

## 선택한 설계

### 즉시 로컬 본문 텍스트 교체 primitive

Rust `DocumentCore`에 본문 문단용 local replace primitive를 둔다. 이 API는
`delete_count`와 `text`를 한 호출에서 받아 다음을 한 번 수행한다.

1. 편집 전 문단 흐름 advance와 쪽 위치를 보존한다.
2. 기존 텍스트 삭제와 새 텍스트 삽입을 적용한다.
3. 해당 문단만 reflow하고 구역 vpos와 composed paragraph를 갱신한다.
4. render-normalized/page-tree 파생 캐시를 편집 결과와 일치시킨다.
5. 편집 전후 흐름 advance를 비교해 `flowChanged`를 반환한다.
6. `flowChanged`가 `false`이면 현재 쪽을 즉시 그릴 수 있도록 local 결과를 공개하고,
   전체 문서 pagination 필요 상태만 남긴다.

일반 insert는 `delete_count = 0`, 일반 delete는 빈 `text`, IME 교체는 이전 조합 길이와
새 조합 문자열을 함께 넘긴다. 이 경계 덕분에 IME 중간 상태의 delete와 insert가 각각
전체 pagination을 실행하지 않으며, 최종 교체 결과만 흐름 경계를 판정한다. 새 조합
글자는 local reflow 직후 현재 쪽의 다음 animation frame에 표시된다.

### Studio 입력 라우팅

`WasmBridge`는 local body replace 결과를 검증해
`documentPaginationPending`, `flowChanged`, `charOffset`을 반환한다. 지원 대상은 줄바꿈·탭이
없는 최대 8자의 동일 본문 문단 insert/delete/replace다. 구조 편집, 선택 범위 삭제,
붙여넣기, 머리말·꼬리말·각주, 중첩 표는 기존 즉시 경로를 유지한다.

`InsertTextCommand`와 `DeleteTextCommand`는 지원 대상 본문 편집에서 local primitive를
사용하고 mutation effect를 history에 전달한다. undo/redo는 전역 기하 복원을 위해 기존
즉시 경로를 유지한다.

IME와 iOS raw 입력은 기존의 개별 `deleteTextAt` + `insertTextAtRaw` 조합 대신 한 번의
`replaceTextAtRaw`를 사용한다. 조합 중간 글자 교체마다 history를 쌓지 않고,
`compositionend`에서 최종 텍스트를 기존처럼 한 command로 기록한다.

### pagination과 화면 갱신

- `flowChanged = false`: 같은 input 처리에서 현재 페이지에
  `document-page-invalidated`를 보내고 Canvas2D 한 페이지만 다음 animation frame에
  다시 그린다. 글자 표시는 120ms timer를 기다리지 않는다.
- `flowChanged = true`: cursor 위치 조회와 현재 페이지 paint 전에 전체 pagination을
  한 번 수행해 줄바꿈·쪽 이동까지 즉시 정확하게 표시한다.
- 안정 입력 후 120ms 동안 새 입력이 없으면 현재 쪽 밖의 pending document pagination을
  한 번 수행한다. 글자마다 timer를 재설정해 연속 타이핑 중 off-screen 계산이 현재 쪽
  표시를 막지 않게 한다.
- 방향키·Home/End·PageUp/PageDown, Enter/Tab, 구조·서식 명령, undo/redo,
  save/export, blur, deactivate 전에 pending pagination을 먼저 flush한다.
- flush 실패 시 pending 상태를 유지하고 기존 full-refresh 경로로 복구한다.

## 보존 계약

- 저장되는 HWP/HWPX 내용과 undo/redo 결과는 변경하지 않는다.
- 입력한 글자, IME 중간 글자, caret, 현재 문단 reflow는 즉시 표시한다.
- 120ms 유휴 timer는 보이는 텍스트나 현재 쪽 paint의 선행 조건이 아니다.
- 조합 중간 상태는 undo history에 노출하지 않는다.
- 줄 또는 페이지 흐름이 달라진 편집은 stale pagination으로 cursor를 조회하지 않는다.
- 짧은 안정 입력만 page-local 대상으로 삼고, 판단할 수 없는 결과는 즉시 pagination한다.
- 현재 사용자가 작업 중인 toolbar, zoom, 접근성 변경은 수정하거나 되돌리지 않는다.

## 테스트

1. Rust local replace가 insert/delete/IME replace를 현재 문단에 즉시 적용하고
   `flowChanged`를 정확히 반환하는 단위 테스트
2. flow가 바뀐 replace가 한 번의 명시적 flush 뒤 즉시 pagination되는 단위 테스트
3. `WasmBridge` local 결과 검증과 구형/누락 API의 보수적 즉시 fallback 테스트
4. `InsertTextCommand`·`DeleteTextCommand` mutation effect와 undo/redo 회귀 테스트
5. IME 중간 교체가 개별 delete/insert 대신 local replace를 한 번 호출하고 같은 frame에
   page invalidation을 예약하는 테스트
6. 120ms idle flush 재설정과 navigation/save/deactivate 경계 flush 테스트
7. page-local invalidation이 현재 페이지만 렌더하고 flow 경계에서는 full refresh하는 테스트
8. WASM 재빌드, Studio TypeScript 테스트와 production build
9. 실제 43쪽 HWP 브라우저에서 일반 입력과 `ㅎ → 하` IME 교체를 다시 측정

## 완료 기준

- 안정적인 일반 입력과 IME 교체 중 whole-document pagination 호출이 0회다.
- IME 교체 한 번은 WASM local replace 호출 1회만 수행한다.
- 안정 입력의 동기 input handler 시간이 16ms 미만이다.
- 현재 페이지의 첫 화면 반영이 50ms 미만이다.
- 현재 페이지 paint는 120ms 유휴 timer보다 먼저 실행된다.
- 120ms 유휴 또는 명시적 경계 뒤 off-screen pagination이 정확히 한 번 실행된다.
- 줄바꿈이 생기는 입력, save/export, undo/redo 뒤 페이지 수·cursor·저장 결과가 기존과 같다.
