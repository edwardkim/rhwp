# rhwp-studio 서식 도구 모음 grouped ribbon 설계

- 대상: `rhwp-studio` 서식 도구 모음 `#style-bar`
- 승인: 모든 명령을 숨기지 않고 유지하되, 모바일에서는 임의 줄바꿈 대신 역할별 grouped ribbon으로 배치

## 목표

412px 모바일 viewport에서 서식 도구 모음의 모든 컨트롤을 보이게 유지하면서도 각 행의
역할과 명령 의미를 즉시 알아볼 수 있게 한다. 현재의 큰 빈 버튼, 임의 줄바꿈, 서로 같은
`가 + ▼` 아이콘, 바코드처럼 보이는 문단 정렬 아이콘을 제거한다.

## 확인된 문제

- 기존 모바일 규칙은 `.sb-btn`을 큰 touch target으로 확장하면서 `.sb-ga`를 숨겨 빈 버튼과
  화살표만 남긴다.
- `#style-bar`의 직접 자식이 역할별 wrapper 없이 섞여 있어 flex wrap 지점이 명령 그룹과
  무관하게 결정된다.
- 스타일·언어·글꼴·크기와 줄 간격이 서로 다른 행/크기 규칙을 사용한다.
- 취소선, 글자 효과, 글자색은 모두 `가 + ▼` 형태라 기능을 구분하기 어렵다.
- 취소선은 `format:strikethrough` 직접 toggle이지만 실제 선택지가 없는 화살표를 표시한다.
- 여섯 문단 정렬 아이콘은 14×12 rectangle data URI로 그려져 배분·나눔 정렬이 바코드처럼
  보인다.

## 선택한 구조

### 필드 grid

모바일에서 스타일, 언어, 글꼴, 크기, 줄 간격을 하나의 `.sb-field-grid`에 배치한다.

- 각 실제 `<label>`은 컨트롤 위에 표시하여 접근 가능한 visible label 계약을 보존한다.
- 412px에서 다섯 필드가 한 행에 맞도록 열 너비를 조정하되 글꼴 필드가 남는 너비를
  우선 사용한다.
- 필드 높이는 27px, radius는 기존 `var(--radius-sm)`을 사용한다.
- 줄 간격은 더 이상 문단 아이콘 뒤의 독립적인 큰 필드가 아니며 같은 grid의 다섯 번째
  필드가 된다.
- 기존 select/input ID와 이벤트 wiring은 변경하지 않는다.

### 명령 band

필드 grid 아래에 두 개의 명령 band를 둔다.

1. 글자 band
   - 굵게, 기울임, 밑줄, 취소선, 글자 효과
   - 얇은 separator 뒤에 글자색, 형광펜
2. 문단 band
   - 왼쪽, 가운데, 오른쪽, 양쪽, 배분, 나눔 정렬

각 band와 내부 group은 하나의 wrap item으로 유지한다. 버튼은 모바일에서 29px 정사각형,
dropdown 버튼만 화살표 공간을 포함해 38px을 사용한다. 배경은 기본 상태에서 투명하고,
hover/active/focus 상태만 기존 theme token으로 구분한다.

## 명령 아이콘 계약

- 굵게·기울임·밑줄은 현재 `가` glyph를 유지한다.
- 취소선은 glyph 중앙을 명확히 가로지르는 선을 사용하고 화살표를 제거한다.
- 글자 효과는 `가` 우상단에 작은 effect sparkle을 표시하며 실제 menu 화살표를 유지한다.
- 글자색은 `가` 아래에 현재 선택 색 swatch를 항상 표시한다.
- 형광펜은 marker glyph와 현재 선택 highlight swatch를 표시한다.
- 문단 정렬 여섯 개는 동일한 18×18 stroke weight와 line cap을 사용한다.
  - 왼쪽·가운데·오른쪽·양쪽은 line origin/length로 의미를 표현한다.
  - 배분은 양쪽 boundary와 그 사이에 배분된 line을 사용한다.
  - 나눔은 중앙 divider와 양쪽 line group을 사용한다.
- 아이콘은 theme의 `currentColor`를 사용하고 별도 새 색상 체계를 도입하지 않는다.
- 모든 버튼의 기존 `title`, command ID, active-state 갱신은 유지한다.

## 반응형 동작

- 모바일 `max-width: 767px`
  - field grid와 두 command band를 순서대로 표시한다.
  - 모든 필드와 명령을 유지한다.
  - `.sb-ga`를 숨기지 않는다.
  - 큰 `var(--touch-target-min)` 강제 대신 29px ribbon density를 사용한다.
- 태블릿 `768px..1023px`
  - 역할별 group을 atomic flex item으로 유지하고 필요한 경우 group 단위로 wrap한다.
- 넓은 데스크톱
  - 내용이 들어가면 기존 한 행 밀도를 유지한다.
  - 기존 표시/숨기기 command와 편집 영역 focus 보존 listener를 변경하지 않는다.

## 접근성과 상호작용

- 모든 select/input의 실제 visible `<label for>` 연결을 보존한다.
- 버튼의 `title`과 기존 command wiring을 보존한다.
- dropdown이 있는 컨트롤만 화살표를 표시한다.
- 취소선 클릭은 기존과 같이 `format:strikethrough`를 즉시 toggle한다.
- focus-visible 상태는 기존 focus color token으로 식별 가능해야 한다.
- 숨겨진 명령이나 새 “더 보기” menu를 만들지 않는다.

## 비목표

- 서식 command 동작, WASM API, history 동작 변경
- toolbar 색상 체계 또는 dark/light theme 재설계
- font picker와 highlight palette 내부 UI 재설계
- icon toolbar `#icon-toolbar` 재설계
- JavaScript viewport 측정이나 `ResizeObserver` 추가

## 검증

1. source contract test가 field/grid/group wrapper, mobile density, visible glyph, direct strike toggle,
   dropdown 보존, 새 alignment icon 계약을 확인한다.
2. 기존 accessibility shell test가 visible label 계약을 계속 통과한다.
3. 실제 412px viewport에서:
   - `styleBar.scrollWidth <= styleBar.clientWidth`
   - field grid, 글자 band, 문단 band의 순서와 행 경계가 안정적
   - 모든 명령이 보이고 빈 버튼이 없음
   - 취소선에는 화살표가 없고 글자 효과·글자색·형광펜에는 화살표가 있음
4. 883px와 1024px에서 overflow와 command 순서 회귀가 없다.
5. Node test 전체와 TypeScript/Vite production build를 실행한다.
