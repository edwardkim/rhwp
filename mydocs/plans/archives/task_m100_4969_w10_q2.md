## 1. 왜 W9 경로를 단순 확장하면 안 되는가

W9의 `KerningParagraphMeasurement`와 `TextRunNode.layout_positions`는 N개 Unicode scalar에 N+1개 문자 경계를
보존한다. nominal glyph identity가 유지되는 pair adjustment에는 정확하지만, Q1 오라클처럼 `office`가 6 scalar
에서 4 glyph가 되거나 옛한글 여러 glyph가 한 cluster를 공유하면 다음 가정이 깨진다.

1. 문자 하나마다 독립 advance가 있다.
2. 임의의 문자 경계에서 폭을 뺄 수 있다.
3. layout 뒤 nominal glyph를 다시 찾아도 같은 결과가 나온다.
4. W9 pair delta를 적용한 뒤 rustybuzz GPOS를 더해도 된다.

따라서 W9 position map에 가상 중간 좌표를 채우거나 `lower_font_native_glyph_sidecars`가 paint 단계에서 다시
shaping하는 안은 기각한다. 전자는 cluster 의미를 파괴하고, 후자는 measurement와 paint의 owner를 둘로 만든다.
Q2는 cluster 기반 common shaping 결과를 line break·최종 run·paint가 함께 소비하고, 적용된 run에는 W9 GPOS를
다시 적용하지 않는 구조로 진행한다.

## 2. 권고 구조

작업명 기준 구조는 다음과 같다. 실제 이름은 구현 절편에서 Rust naming과 충돌을 확인한 뒤 확정한다.

```text
ExactFontSourceRegistry (W9 source generation·bytes·face index 재사용)
  -> HorizontalShapingContext
       -> bounded attempt decision (성공·실패 모두 소유)
       -> Arc<ShapedRun> (성공일 때만 glyph·cluster·font-unit result)
       -> cluster-aware paragraph/break measurement cache
  -> final emitted TextRunNode의 internal shaping sidecar
  -> LayerBuilder
       -> TextRun fallback
       -> exact GlyphRun / 필요 시 GlyphOutline
       -> TextSource-linked shaping decision trace
  -> backend는 published variant만 재생
```

### 2.1 attempt 결과

`Option<GlyphRun>` 대신 terminal attempt를 항상 반환한다.

- bounded run 식별자 또는 paint 단계에서 결합되는 `TextSourceSpan`
- `disposition`과 typed `reason`
- canonicalization 성공 시에만 `settingsSha256`·`fontSourceSha256`
- glyph count와 applied output의 bounded 참조
- trace에는 원문·font bytes·로컬 경로·private corpus identity 없음

source unavailable처럼 identity 이전에 닫힌 요청에는 hash를 만들지 않는다. 페이지 공개 attempt는 최대 4,096
records로 제한하고 초과분은 `truncated`와 omitted count로 회계한다.

### 2.2 cache와 수명

W9 `KerningMeasurementContext`처럼 한 pagination/edit transaction의 HeightMeasurer·Typeset·page layout·edit
reflow가 같은 immutable source generation과 owned result를 공유한다. cache key에는 원문 전체와 다음 값을
메모리 안에서만 포함한다.

- exact source handle·registry generation
- font size·장평 bit identity
- direction·writing mode·script·language
- ordered feature와 canonical variation vector(Q2에서는 empty만 applied)
- hard boundary와 display projection 상태

cache 결과는 `Arc`로 공유하고 font face는 source별 한 번만 parse한다. cache entry·text/glyph·attempt count에
상한을 두며 상한 초과는 기존 layout으로 전체 rollback한다. hash 충돌만으로 결과를 재사용하지 않고 key equality를
다시 확인한다.

### 2.3 render-tree 인계

최종 line/run shaping 결과를 다시 계산하지 않도록 `TextRunNode`에는 직렬화되지 않는 optional internal sidecar를
둔다. `Arc`를 사용해 glyph vector 복제를 피하고, `layout_positions`는 W9 전용 scalar contract로 유지한다. Q2
shaping 적용 run에 가짜 N+1 문자 positions를 넣지 않는다.

LayerBuilder가 sidecar를 소비해 기존 `LayerGlyphRunPaint`와 `GlyphCluster`를 생성한다. rejected attempt도
TextRun fallback과 연결된 source annotation 또는 동등한 bounded sidecar로 보존한다. 실제 값을 공개 JSON에
연결하는 절편에서만 schema minor를 올린다.

## 3. 최초 activation 범위

첫 활성 lane은 다음 조건을 모두 만족해야 한다.

- `horizontal-tb`, LTR, bidi level 0
- exact portable source와 유효 face index
- variation empty, synthetic bold/italic 없음
- 한 exact face·style·script로 구성된 homogeneous segment
- rotation·vertical·char overlap·display text 치환 없음
- tab·inline control·note marker는 hard boundary 밖으로 분리
- text·glyph·cluster 각 4,096 이하
- 모든 채택 line boundary가 shaping cluster boundary와 일치

common shaper는 RTL oracle도 계산하지만 제품 적용은 기존 bidi ordering owner가 source range·visual order를
증명할 때까지 `unsupported/bidi-authority-pending`으로 닫는다. variation과 vertical은 각각 Q3·Q4까지 닫는다.

첫 제품 권고안은 **complex-required LTR subset**이다. 옛한글 Jamo·combining mark처럼 nominal replay로 의미가
깨지는 run을 먼저 열고, Latin 기본 `liga`의 전면 적용은 shadow delta가 기존 줄바꿈·bbox에 미치는 영향을 보고
별도 승인한다. `office` ligature oracle은 엔진 계약으로 유지하되 승인 전 모든 일반 Latin run의 기본 출력을
바꾸는 근거로 사용하지 않는다.

HWP kerning flag는 `kern` feature 값으로 명시적으로 반영한다. shaping이 `applied`이면 그 결과가 GSUB와 GPOS의
단일 owner이며 W9 pair adjustment를 건너뛴다. shaping이 미요청·미지원·실패이면 W9 K1 또는 기존 K0가 그대로
소유한다. 한 run에 두 경로를 섞지 않는다.

## 4. 단계별 절편과 승인 게이트

### Q2-A — attempt owner·sidecar 계약

1. Q1 request validator·canonical identity·output을 terminal attempt API로 감싼다.
2. source unavailable부터 applied까지 같은 disposition vocabulary를 사용한다.
3. hash optionality, trace 4,096 record 상한과 privacy 음성 검사를 추가한다.
4. render/layout에는 아직 연결하지 않는다.

**종료 게이트**: malformed·unsupported·bounded·applied가 원문 없이 결정적으로 직렬화되고 제품 출력 변화 0.

### Q2-B — horizontal shaping context·shadow measurement

1. W9 exact source registry를 재사용하는 transaction context와 parse/result cache를 만든다.
2. font-unit glyph output을 size·장평에 따라 px position·advance로 한 번 변환한다.
3. cluster index와 cluster-aligned `range_width`를 만들고 LTR 공개 fixture로 검증한다.
4. 현행 layout과 나란히 계산하되 bbox·line break·paint에는 적용하지 않는다.
5. K0·W9 K1·old Hangul·Latin liga의 delta와 비용을 공개 fixture aggregate로 보고한다.

**종료 게이트**: native/WASM shadow result parity mismatch 0, cache collision 0, 제품 출력 변화 0. activation matrix를
메인테이너가 별도 승인한다.

### Q2-C — cluster-aware line-break transaction — qualified

1. `composer/line_breaking.rs`의 scalar `range_width`와 별도로 cluster range 측정을 연결한다.
2. hard boundary·style/source split을 넘는 shaping을 금지한다.
3. line candidate가 cluster 내부를 자르면 shaping paragraph 전체를 W9/K0로 rollback한다.
4. W9 `KerningParagraphBreakSession`과 같은 bounded final-line 재측정으로 boundary context를 반영한다.
5. re-shape 결과가 선택한 line fit을 바꾸면 제한 횟수 안에서 재결정하고, 수렴하지 않으면 전체 rollback한다.

**종료 게이트**: measurement·line selection·최종 run width가 한 owner 결과를 소비하고, 부분 적용·비수렴·cluster
절단은 silent approximation 없이 rollback한다.

Q2-C0~C2는 제품 소비자 0인 dormant transaction으로 구현·검증됐다. 옛한글 `0..3` cluster 내부의 scalar
candidate는 제거되고, final line range를 다시 shape한 `Arc`와 line width를 함께 보존한다. later segment 실패,
source 부재, 후보·폭·attempt 상한은 앞선 성공을 게시하지 않고 pristine W9 K1 또는 K0 결과로 문단 전체를
rollback한다. native·Node WASM 공개 fixture 8건의 결과 불일치는 0이며, 제품 게시 flag는 모든 경로에서 false다.
세부 결과는
[`task_m100_4969_w10_q2_c.md`](../../working/archives/task_m100_4969_w10_q2_c.md)에 고정한다.

#### Q2-B 종료 뒤 owner 재감사에 따른 활성 순서 정정

현행 live cursor는 `BreakToken.width`가 아니라 K0 `base_width`와 W9 boundary pair delta를 소비한다. 또한
`LineBreakResult`는 최종 문자 범위만 남기고 shaped measurement를 emitted run에 전달하지 않는다. 그러므로 Q2-C에서
줄 경계만 제품에 먼저 적용하면 Q2-D 전까지 line selection과 bbox·paint owner가 달라진다.

Q2-C 구현은 cluster-aware paragraph/break transaction을 **dormant** 상태로 완성하고 공개 fixture에서 candidate를
검증하되, live product output은 바꾸지 않는다. Q2-D가 final emitted run `Arc` sidecar와 rejected-attempt handoff를
완성할 때 Q2-C line decision과 함께 원자적으로 활성화한다. 이 정정은 기능 범위를 줄이는 것이 아니라 보호 불변식
4번을 단계 사이에서도 지키기 위한 순서 변경이다. 상세 gate는
[`task_m100_4969_w10_q2_c_activation_matrix.md`](../../working/archives/task_m100_4969_w10_q2_c_activation_matrix.md)에 고정한다.

### Q2-D — emitted run·rejected-attempt trace 인계

1. final emitted run에 internal `Arc` sidecar를 붙이고 W9 `layout_positions`와 상호 배타로 만든다.
2. footnote·control·run split 뒤의 최종 문자열을 권위 source range로 사용한다.
3. LayerBuilder가 sidecar에서 GlyphRun position·advance와 direction-aware cluster range를 만든다.
4. 성공·실패 attempt를 TextSource와 결합하고 실제 public field가 생길 때 schema minor를 올린다.
5. raw text·font bytes·host path가 diagnostics에 중복되지 않는지 검사한다.

**종료 게이트**: line width, TextRun bbox, GlyphRun total advance와 다음 run origin이 일치하고 rejected attempt도 typed
disposition을 잃지 않는다.

Q2-C 이후 owner 재감사에서 `TextRunNode` 새 field보다 `ComposedParagraph` internal `Arc`와
`PageRenderTree`의 bounded `NodeId` sidecar table이 더 작은 변경임을 확인했다. `TextRunNode.layout_positions`는 W9
scalar 계약 그대로 두고, `LayerNode.source_node_id`로 existing GlyphRun lowerer까지 연결한다. 일반 edit reflow가
LineSeg만 남기고 Arc를 잃는 경로는 최초 activation에서 제외한다. 수정된 절편과 승인 경계는
[`task_m100_4969_w10_q2_d.md`](task_m100_4969_w10_q2_d.md)를 따른다.

### Q2-E — backend replay

1. CanvasKit·native Skia는 exact font blob·face index를 검증한 뒤 published glyph ID·position만 재생한다.
2. SVG·Canvas2D처럼 glyph-ID API가 없는 backend는 common glyph result에서 만든 exact outline variant를 재생한다.
3. outline 지원이 안 되는 glyph format은 TextRun fallback과 structured reason으로 닫는다.
4. backend에서 원문을 다시 shaping하는 호출을 계약 테스트로 금지한다.
5. variation·RTL·vertical·synthetic style은 현 단계에서 계속 fail-closed한다.

**종료 게이트**: 지원 subset의 SVG·Canvas2D·CanvasKit·native Skia가 같은 glyph decision을 재생하고 backend
reshaping 0. 미지원 backend는 fallback reason을 보존한다.

### Q2-F — 회귀·성능·최종 판정

1. 기존 K0 fixture, W9 K1 fixture와 현행 non-target render hash를 다시 고정한다.
2. native·Docker WASM glyph·cluster·position·line break parity를 확인한다.
3. shaping call, cache hit, parse count, layout wall time, page-tree bytes와 WASM size를 W9 기준선과 비교한다.
4. malformed·oversized·cache/attempt exhaustion과 non-convergent line break를 adversarial test한다.
5. 결과를 `qualified`, `bounded-subset`, `blocked`로 판정하고 Q3 인계를 제시한다.

**종료 게이트**: 기존 보호 fixture 회귀 0, 지원 subset parity mismatch 0, 상한·fallback 회계 누락 0. Latin default
liga 확대는 별도 결과 승인 없이는 포함하지 않는다.

Q2-E backend replay와 Q2-F 회귀·성능 판정은 Q2-D4·D5의 수정 수행계획에 흡수해 완료했다. 최종 지원 범위는
[`task_m100_4969_w10_q2_final_classification.md`](../../working/archives/task_m100_4969_w10_q2_final_classification.md)의
`bounded-subset`이 정본이다. 두 active lane 밖의 입력은 structured reject 또는 기존 TextRun/W9/K0 fallback으로
닫으며, Q3 variation과 Q4 vertical을 Q2 완료로 오인하지 않는다.

## 5. 보호 불변식

1. common shaping 적용 run에는 W9 kerning을 중복 적용하지 않는다.
2. shaping 실패는 run 일부가 아니라 승인된 transaction 경계 전체를 기존 W9/K0로 되돌린다.
3. glyph 수 변화와 cluster를 문자별 가상 advance로 분해하지 않는다.
4. line-break candidate와 emitted run이 다른 shaping 결과를 소비하지 않는다.
5. exact source bytes·face index·registry generation이 cache lineage에서 빠지지 않는다.
6. feature 순서는 보존하고 variation axis는 canonical 정렬한다.
7. raw text는 cache key 메모리에만 존재하며 attempt trace에 직렬화하지 않는다.
8. font bytes는 기존 portable resource table 이외의 diagnostics에 복제하지 않는다.
9. backend는 published glyph/outline만 재생하고 독자적으로 shaping하지 않는다.
10. unsupported RTL·variation·vertical·glyph format을 기존 TextRun fallback으로 조용히 위장하지 않고 reason을 남긴다.
11. text/glyph/cluster/trace/cache와 final-line 재시도에 bounded 상한을 둔다.
12. K0·W9 K1 보호 fixture는 각 절편 종료 때 다시 확인한다.

## 7. 검증과 커밋 경계

Q2-A부터 Q2-F까지 각 절편은 독립 commit·승인·rollback 경계다. 새 integration source는 `tests/cases/` 원본만
추가하고 generated suite·manifest·Cargo target은 source PR에 포함하지 않는다. 각 절편 focused test 뒤 최소
native lib check·clippy·WASM check를 수행하며, activation 이후에는 K0/K1·composer·layout·paint JSON·backend
replay를 함께 검증한다.

PR 준비 승인 전에는 review worktree에서 generated integration suite를 준비해 전체 gate를 실행한다. Hyper-V
한컴 오라클은 공개 fixture만으로 feature 적용 결과를 판정할 수 없는 좁은 경우에 별도 승인 뒤 사용하며, Q2
계획 자체에는 필요하지 않다.

## 8. 승인 요청 범위

Q2-A~D5와 최종 classification을 완료하고 결과·checkpoint commit 승인을 받았다. Q3는 별도 수정 수행계획 승인
전 자동으로 열리지 않는다. remote push·PR·issue comment는 기존 거버넌스 승인 경계를 유지한다.
