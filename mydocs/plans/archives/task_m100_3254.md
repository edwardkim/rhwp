# rhwp-studio 한글 IME 셀 교체 입력 지연 개선 설계

- 대상: 1단계 표 셀 안의 빠른 연속 한글 IME 조합과 조합 확정
- 승인: atomic deferred cell replace(V1)

## 문제와 실측 기준선

43쪽 HWP 계약서의 실제 편집 위치인 1단계 표 셀
`section=0, parentPara=6, control=0, cell=0, cellPara=1, offset=246`에서 한글 IME를
계측했다.

- 첫 조합 입력 `ㅎ`: 8.0ms
- 조합 교체 `ㅎ → 하`: 41.4ms
- 조합 확정: 1.4ms

교체 입력 중 `deleteTextInCellByPath`가 37.5ms 동안 동기 전체 pagination을 수행했고,
뒤따르는 `insertTextInCellDeferredPagination`은 0.2ms였다. 즉 IME 이벤트 자체나 확정
기록이 아니라, 이전 조합 문자열을 지우는 셀 삭제 경로가 병목이다.

현재 `replaceTextAtRaw`는 본문에서는 atomic local replace를 사용하지만 셀에서는
`deleteTextAt`과 `insertTextAtRaw`를 순서대로 호출한다. 실제 위치에는 깊이 1의
`cellPath`가 있으므로 삭제가 `deleteTextInCellByPath`로 라우팅되고, 조합 갱신마다
전체 문서 pagination이 실행된다.

## 목표

빠른 연속 한글 입력에서 각 조합 갱신과 음절 확정이 누적 지연 없이 현재 페이지에
표시되게 한다. 문서 모델 변경은 미루지 않고 같은 input 처리에서 완료하되, 안정적인
셀 흐름에서는 현재 페이지 밖의 전체 pagination만 기존 120ms 유휴 경계로 병합한다.

실제 43쪽 문서에서 다음을 완료 기준으로 삼는다.

- `ㅎ → 하` 같은 조합 교체의 동기 input 시간 중앙값 8ms 미만
- 빠른 연속 조합 교체 20회의 95백분위가 16ms 미만
- 안정 조합 교체 한 번당 셀 replace WASM 호출 1회, 동기 전체 pagination 0회
- 조합 확정, 저장 텍스트, caret, undo 결과가 기존과 동일

## 선택한 설계

### atomic deferred cell replace

Rust `DocumentCore`에 깊이 1 셀 문단용 atomic replace primitive를 추가한다. 이 API는
`delete_count`와 새 `text`를 한 번에 받아 다음 순서로 처리한다.

1. 대상 셀 문단과 편집 범위를 검증한다.
2. 편집 전 문단 flow advance와 로컬 layout 기여 상태를 보존한다.
3. 이전 조합 문자열 삭제와 새 조합 문자열 삽입을 같은 mutable access에서 적용한다.
4. inactive ClickHere 필드의 시작·끝 범위를 기존 insert 규칙대로 보존한다.
5. 부모 컨트롤을 dirty로 표시하고 셀 문단 reflow와 vpos 재계산을 각각 한 번 수행한다.
6. 편집 후 flow advance와 로컬 layout 기여 상태를 계산한다.
7. `render_normalized`의 동일 셀 문단과 관련 cell-unit cache만 현재 결과에 맞춘다.
8. page-tree cache를 무효화하되, 안정 흐름에서는 pagination을 실행하지 않는다.
9. 최종 `charOffset`과 `cellFlowChanged`를 반환한다. bridge는 atomic API 사용 여부로
   `paginationDeferred`를 부여한다.

삭제와 삽입을 별도 deferred 호출로 나누지 않는다. 별도 호출은 reflow를 두 번 수행하고
중간의 빈 조합 상태를 파생 캐시와 이벤트에 노출한다. atomic replace는 최종 상태만 한 번
관찰되게 한다.

### WASM과 Studio 라우팅

`wasm-bindgen`에는 `replaceTextInCellDeferredPagination`을 노출하고 `WasmBridge`는 결과를
typed object로 검증한다. 구형 WASM처럼 API가 없으면 mutation을 일부 적용하지 않은 상태에서
기존 즉시 delete+insert 경로로 보수적으로 fallback한다.

Studio에는 depth-1 셀과 짧은 단일 조합 문자열만 허용하는 판정 helper를 둔다. 지원 범위는
줄바꿈·탭 없는 최대 8자 replace이며, 다음은 기존 경로를 유지한다.

- 본문: 기존 `replaceBodyTextLocal`
- 깊이 2 이상 중첩 셀: 기존 ByPath 즉시 경로
- 머리말·꼬리말·각주
- 선택 범위, 구조 편집, 일반 붙여넣기
- 일반 Backspace/Delete

IME `replaceTextAtRaw`는 지원 가능한 깊이 1 셀에서 새 atomic API를 한 번 호출하고 mutation
effect를 반환한다. 첫 조합 입력은 기존 deferred cell insert를 그대로 사용한다.
`compositionend`는 이미 적용된 최종 문자열을 history에 한 번 기록하는 현재 계약을 유지한다.

### pagination과 화면 갱신

- `cellFlowChanged = false`: 현재 input 처리에서 문서 모델, 셀 reflow, caret 좌표를 갱신하고
  현재 페이지 invalidation을 다음 animation frame에 예약한다. 전체 pagination은 pending으로
  남겨 120ms 유휴 또는 명시 경계에서 한 번 flush한다.
- `cellFlowChanged = true`: 기존 `prepareTextMutationBeforeCursor`가 caret 조회 전에 pending
  pagination을 즉시 flush한다. 줄 수, 셀 높이, 페이지 컷이 달라지는 실제 경계만 동기 비용을
  부담한다.
- flush 실패: pending 상태를 보존하고 기존 full-refresh 복구 경로를 사용한다.

DOM IME composition overlay는 유지한다. 이 설계는 화면만 먼저 보여 주고 문서 모델을 나중에
맞추는 optimistic overlay가 아니다. 모델 변경과 local reflow는 input 처리 안에서 즉시
끝나며, overlay는 Canvas paint 전 동일 frame의 조합 피드백만 담당한다.

## 보존 계약

- 빠른 조합 중간 상태는 undo history에 기록하지 않는다.
- 조합 확정은 최종 문자열 하나만 기존 `InsertTextCommand`로 기록한다.
- field range, char offset, caret DocProperties, event log는 최종 replace 상태와 일치한다.
- 안정 흐름에서 보이는 텍스트와 caret는 120ms pagination timer를 기다리지 않는다.
- 실제 셀 흐름 변화는 stale pagination으로 caret를 조회하지 않는다.
- API 누락과 지원 범위 밖 입력은 mutation 전에 기존 즉시 경로로 fallback한다.
- atomic API가 mutation 뒤 잘못된 결과를 반환하면 중복 편집을 피하기 위해 오류로 처리하고
  같은 이벤트에서 즉시 경로를 재시도하지 않는다.
- 현재 worktree의 toolbar, zoom, 접근성, Subsecond 변경은 수정하거나 되돌리지 않는다.

## 오류 처리

- 인덱스, 범위, 길이 또는 개행 조건이 잘못되면 mutation 전에 오류를 반환한다.
- bridge는 `ok`, `charOffset`, `cellFlowChanged`를 검증하고, feature detection 결과로
  `paginationDeferred`를 부여한다. `cellFlowChanged`가 누락된 구형 결과는 기존 insert
  계약처럼 보수적인 boundary flush로 처리한다.
- feature detection은 atomic API 호출 전에 수행해, API 누락 fallback에서 delete만 적용되는
  부분 상태를 만들지 않는다.
- Rust replace가 실패하면 Studio는 같은 이벤트에서 다시 delete+insert를 시도하지 않는다.
  중복 mutation을 피하고 기존 입력 오류 처리로 전달한다.

## 테스트와 검증

구현은 테스트 우선으로 진행한다.

1. TypeScript 실패 테스트
   - depth-1 셀 IME replace가 atomic bridge 호출 한 번만 사용한다.
   - stable 결과가 pending page-local mutation effect가 된다.
   - flow 변경 결과가 기존 boundary flush effect로 전달된다.
   - depth-2 셀과 API 누락은 기존 즉시 경로를 유지한다.
2. Rust 실패 테스트
   - `ㅎ`을 `하`로 교체한 직후 텍스트와 offset이 정확하다.
   - delete+insert가 reflow/event를 최종 상태 기준으로 한 번만 적용한다.
   - 안정 replace는 pagination을 defer하고 warm page tree에서 새 텍스트가 보인다.
   - flow 변경 replace는 올바른 `cellFlowChanged`를 반환한다.
   - ClickHere field range와 char offsets가 insert 규칙을 보존한다.
3. focused Rust/Studio 테스트와 WASM 재빌드
4. production build
5. 실제 43쪽 문서의 같은 셀에서 `ㅎ → 하`와 빠른 20회 연속 조합을 브라우저로 재측정
6. 조합 확정 뒤 텍스트, caret, undo 1회 복원, 페이지 수를 확인

## 제외 범위

- 일반 Backspace/Delete의 deferred cell deletion
- 깊이 2 이상 중첩 셀 최적화
- 본문 local replace 추가 변경
- Canvas renderer 또는 120ms idle 정책의 재설계
- DOM-only optimistic composition 모델
