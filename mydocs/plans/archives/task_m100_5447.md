# #5447 계획서 — B2 스파이크: 행·열·라벨 구조 편집 실현성 실측

## 1. 배경

B1 축이 닫혔다 — #4055 스파이크 → #4100 엔진(PR #4603) → #4694 UI(PR #4717,
2026-08-13 merge). #3683 의 B2 착수 판정 코멘트(2026-08-18, 2차 재검증 반영 patch)가
코퍼스 28종 실측으로 구현 정책 3종을 정했고, 이 스파이크는 "정해달라"가 아니라
**"정한 것이 한컴에서 통하는가"** 를 확인한다.

| 정책 | 내용 | 근거 |
|---|---|---|
| `c:f` | **무갱신** (원본 바이트 그대로) | `c:externalData` 0/28 — 캐시가 유일한 진실 원천, 한컴 스스로 깨진 범위 사용(분산형 ser0 `Sheet1!$B$2:$A$4`) |
| `c:ptCount` | **항상 재계산** | 28/28 실제 점 개수와 일치하는 한컴 불변식 |
| `c:pt idx` | 삭제·삽입 후 **0..n-1 전수 재번호** | rhwp 스캐너 fail-closed(`crates/rhwp-ooxml-chart/src/data.rs:363-398`) — 희소 idx 산출물은 rhwp 자신이 못 읽음 |

B1 은 개수를 안 바꿔 `c:f` 가 계속 정합이었다. B2 는 **범위 길이와 실제 개수가 어긋난
파일을 처음으로 내보낸다** — 그 어긋남을 한컴 렌더러와 **차트 데이터 편집기**가 어떻게
다루는지가 판정 대상이다.

## 2. 질문

| # | 질문 | 판정 |

| S1 | `c:f` 무갱신 상태에서 개수가 바뀐 차트를 한컴이 정상 개봉·렌더하는가 | 144DPI 래스터 |

| S3 | 계열 신설(`c:ser`+채번+이름·값)·삭제(잔여 재번호)가 통하는가 — 누적·3D 포함 | 144DPI 래스터 |
| S4 | 거부해야 할 경계(원형 계열 추가, 주식형 계열 개수 변경)가 실제로 깨지는가 | 작업지시자 육안 |

**S2 가 `c:f` 무갱신 정책이 뒤집힐 수 있는 유일한 지점이다** (#4100 판정에서 편집기
적재까지 확인한 선례를 따른다).

## 3. 방법 — 바이트 수술 + 기존 주입 경로

구조 변종은 `set_chart_data_native` 로 만들 수 없다(fail-closed:
seriesCountMismatch/valueCountMismatch/categoryMismatch). 스파이크는 코퍼스 XML 을
**바이트 문자열 수술**(한컴 단일 라인 기계 생성이라 균일 — 28종 실측)로 가공해
기존 주입 경로로 넣는다:

- HWPX — `replace_chart_representations`(`tests/issue_4100_chart_data_edit.rs:761`):
  ①②에 **같은** 변종 XML 동시 주입 (다르면 representationMismatch 로 재독 거부)
- HWP5 — `replace_chart_nested_only`(신규, ②만): `replace_ole_stream` 경유
  (루트 CLSID·③④ 보존 — #4097 계약)
- 산출마다 자기검증: `scan_chart_values` 재통과 → export → `from_bytes` 재개방 →
  봉투 구조 확인(계열 수·라벨·값) → ①==②==변종 XML, ③④ 바이트 불변

`.hwp` ② 추출은 `chart_streams` 경유 — DocInfo BIN_DATA **참조 해석**을 거친다
(코퍼스 유일의 다중 BinData 파일 `분산형/곡선이있는분산형.hwp` 에 미참조 잔류 BIN 이
있어 첫 스트림을 집으면 오판한다. 착수 판정 코멘트 §5 실측).
