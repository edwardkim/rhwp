## 1. 수정 이유

Q3-D는 exact `(charShapeId, languageIndex)` slot에 canonical instance request를 소유하고 source/request generation을
cache provenance에 넣었지만, 제품 composer는 여전히 기본 transaction만 사용한다. 기존 Q3-E 초안은 이 다음을
한 절편으로 묶어 다음 세 위험을 충분히 분리하지 못했다.

1. 공개 caller를 열면 malformed 요청뿐 아니라 정상 요청을 해제해 기존 Q2 출력으로 돌아가는 역방향 command도
   필요하다.
2. paragraph transaction은 `HorizontalShapingTransaction` 구체 타입만 받으므로 explicit transaction을 억지로
   끼우면 default lane까지 바꾸기 쉽다.
3. backend capability가 같지 않다. CanvasKit Browser는 producer-resolved monochrome `GlyphOutline`을 재생할 수
   있지만 Native Skia variable `GlyphRun` selector와 SVG·Canvas2D outline replay는 아직 열리지 않았다.

따라서 Q3-E는 **public request**, **composer activation**, **portable publication**, **backend selection**을 서로 다른
승인·checkpoint로 나눈다. 모든 backend를 동시에 여는 것이 아니라 기능 탐지 결과에 따라 지원되는 replay만
선택하고 나머지는 기존 `TextRun`으로 결정론적으로 닫는다.

### 1.1 Q3-E0 사전 감사에서 확인한 계획 정정

현행 Q2 product gate는 `is_bounded_horizontal_shaping_candidate_text()`에서 옛한글 자모가 있는 문자열만 통과시키고,
`eligible_segments()`도 옛한글 자모를 포함한 Hangul scalar 구간만 measurement 대상으로 만든다. 따라서 Q3의 공식
Happiness Sans fixture인 modern Hangul `가변`과 Latin `Typography`는 exact instance request가 있어도 기존 Q2
transaction에 진입하지 않는다.

이를 모르고 공통 gate를 modern Hangul·Latin까지 넓히면 request가 없는 기존 문서도 더 넓은 projection·transaction
경로를 타므로 Q2 무회귀 불변식을 훼손한다. Q3-E는 기존 Q2 old-Hangul gate와 `eligible_segments()`를 그대로 두고,
**exact request 존재 확인 뒤에만** 평가되는 `boundedHorizontalLtrV1` explicit-only single-run policy를 별도로 둔다.
이 정정은 메인테이너 승인을 받았으며 Q3-E0 source test·baseline에 반영한다.

## 2. 고정 결정

### 2.1 명시 요청 API와 권위

최초 public authority는 host가 exact font source를 이미 등록한 뒤 호출하는 다음 두 command다.

- native: `set_exact_font_instance_native`, `clear_exact_font_instance_native`
- WASM: `setExactFontInstance(optionsJson)`, `clearExactFontInstance(optionsJson)`

`setExactFontInstance`의 strict options schema는 다음과 같다.

```json
{
  "charShapeId": 7,
  "languageIndex": 0,
  "mode": "boundedHorizontalLtrV1",
  "axes": [
    { "tag": "wght", "value": 650.0 },
    { "tag": "opsz", "value": 400.0 }
  ]
}
```

`clearExactFontInstance`는 `charShapeId`, `languageIndex`, `mode`만 받는다. JSON은 16 KiB, axis는 16개,
language index는 0..6으로 제한하고 unknown field·unknown mode·중복 tag·비유한 값·실제 `fvar` 범위 밖 값은 snapshot
변경 전에 거절한다. font bytes는 JSON에 넣지 않고 기존 `registerExactFontSource`가 소유한다. 빈 axis와 explicit
default는 유효한 default instance 요청이며 **clear와 같지 않다**.

두 command는 상태·canonical axis·source/request generation만 JSON으로 반환한다. raw font bytes, raw text, host path,
private corpus identity는 반환하거나 trace에 기록하지 않는다. HWP/HWPX parser, 문서 버전, font name, bold,
장평·자간은 이 API를 자동 호출할 권위가 없다.

### 2.2 되돌릴 수 있는 request owner

Q3-D registry에 exact slot 단위 remove를 추가한다. 존재하지 않는 slot clear는 멱등이고 generation을 올리지 않는다.
실제 remove만 request generation을 올리고 measurement context·composition·pagination·page tree를 같은 CQRS command에서
무효화한다. exact source 전체 clear가 request 전체를 비우는 기존 계약도 유지한다.

### 2.3 default lane과 explicit-only candidate lane의 분리

Q2의 old-Hangul candidate predicate와 segment selector는 변경하지 않는다. Q3는 composer가 exact slot request의
존재를 먼저 확인한 경우에만 별도 explicit-only predicate를 평가한다. 이 predicate는 아래 activation surface의 전체
한 run을 하나의 target range로 만들며, 기존 Q2 segment discovery를 일반 script로 확대하지 않는다.

line convergence가 공통으로 소비하는 좁은 measurement session 계약을 만들고 Q2 default transaction과 Q3 explicit
transaction이 각각 구현한다. explicit-only line transaction은 전체 run measurement와 기존 candidate boundary·
available width 검증을 재사용하되, Q2의 `NoComplexRequiredText`/old-Hangul segment 판정은 호출하지 않는다. exact
request가 없거나 preflight가 실패하면 지금과 같은 Q2/default path만 사용한다.

default transaction이 registry를 몰래 조회해 variation을 주입하는 방식은 금지한다. 이 분리로 요청이 없는 모든
문서는 Q2 cache identity·geometry·layer JSON을 그대로 유지한다.

### 2.4 최초 activation surface

다음 조건을 **모두** 만족하는 paragraph만 `boundedHorizontalLtrV1` 후보가 된다.

1. 최종 composed paragraph가 한 줄·한 text run이며 model text와 display text가 같다.
2. 모든 scalar가 같은 exact `(charShapeId, languageIndex)` slot과 같은 shaping style을 사용한다.
3. pure modern Hangul 또는 pure Latin non-ligature이고 language category가 하나다.
4. horizontal LTR, bidi level 0이며 vertical·RTL·rotation·glyph transform이 없다.
5. inline control·tab·field/note split·char overlap·border/background·decoration이 없다.
6. synthetic bold/italic, super/subscript, letter/word/extra spacing, display projection이 없다.
7. 글꼴 크기·장평과 glyph/cluster/run/resource 상한이 기존 Q2/Q3 bounded limit 안이다.
8. exact source, request generation, canonical instance와 replay certificate가 모두 같은 snapshot이다.

한 조건이라도 어긋나거나 line decision이 수렴하지 않으면 paragraph 전체를 Q2/default `TextRun` 결과로 되돌린다.
부분 run만 variable instance로 게시하지 않는다.

### 2.5 publication과 backend 기능 탐지

eligible explicit instance는 같은 measurement `Arc`에서 다음 세 동등 variant를 만든다.

- 기존 `TextRun`: 항상 남는 default fallback
- canonical instance `GlyphRun`: glyph/cluster/geometry와 instance identity 증적
- producer-resolved monochrome `GlyphOutline`: backend reshaping 없는 portable visual replay

모든 validation과 outline 생성은 resource·variant mutation 전에 끝낸다. `GlyphRun`과 `GlyphOutline`이 모두 완전할 때만
같은 equivalence group에 원자적으로 붙이고 nominal lowerer claim을 얻는다. 하나라도 실패하면 둘 다 게시하지 않고
`TextRun`만 남긴다.

최초 backend matrix는 다음처럼 제한한다.

| backend | non-default instance 선택 | Q3-E 동작 |
| --- | --- | --- |
| CanvasKit Browser/Studio | `GlyphOutline` | 활성화 대상 |
| CanvasKit policy analysis | `GlyphOutline` | 선택·음성 계약 검증 |
| Native Skia | 미지원 | variable `GlyphRun` 거절 후 `TextRun` fallback |
| SVG layer | 미지원 | `TextRun` fallback |
| Canvas2D | 미지원 | `TextRun` fallback |

Q3-C의 Native Skia coordinate proof는 capability 증거이지 product selector 승인으로 확대하지 않는다. variable
typeface cache key·construction을 여는 변경과 SVG/Canvas2D outline replay는 후속 작업으로 남긴다.

### Q3-E3 — bounded explicit composer activation

1. default/explicit measurement session 계약을 도입하되 기존 Q2 old-Hangul predicate·segment selector는 보존한다.
2. exact request 확인 뒤에만 modern Hangul·Latin single-run 전체 범위를 만드는 explicit-only policy를 평가한다.
3. 한 줄·한 run·한 slot preflight를 통과한 경우에만 explicit session으로 line transaction을 실행한다.
4. line width·selection·bbox·next origin·sidecar가 같은 request provenance measurement를 소비하도록 고정한다.
5. negative matrix는 paragraph 전체를 기존 Q2 결과로 rollback한다.

**종료 게이트**: default/no-request canonical output delta 0, eligible instance geometry 변화 증명, 부분 activation 0.
결과 승인·checkpoint 뒤 E4로 간다.

### Q3-E4 — atomic portable publication·backend matrix

1. variable `GlyphRun`과 `GlyphOutline`을 같은 source/equivalence group에 원자적으로 게시한다.
2. CanvasKit Browser/Studio는 outline을 선택하고 malformed/incomplete outline은 `TextRun`으로 되돌린다.
3. Native Skia·SVG·Canvas2D는 non-default instance를 선택하지 않는 음성 계약을 고정한다.
4. explicit default는 Q2와 pixel/geometry가 같고 provenance만 분리되는지 검증한다.

**종료 게이트**: CanvasKit만 non-default visual delta를 보이며 다른 backend는 default fallback과 동일하다. resource·cache
부분 mutation 0. 결과 승인·checkpoint 뒤 E5로 간다.

### Q3-E5 — 성능·크기·전체 회귀·최종 판정

1. default/no-request와 explicit default/interior/max를 같은 환경에서 각각 warm-up 뒤 9회 측정한다.
2. `1/2/8 instance × 1/2/8 run`의 parse/cache/resource/outline count와 payload bytes를 기록한다.
3. native full, all-target Clippy, Native Skia fallback, Node WASM, Docker WASM, Studio full/build와 실제 CanvasKit E2E를
   수행한다.
4. 결과를 `qualified`, `bounded-subset`, `blocked` 중 하나로 판정하고 Q4에 인계한다.

성능·크기 hard gate는 다음과 같다.

- no-request p50 <= baseline +3%, p95 <= baseline +5%
- explicit activation p50 <= default exact-source baseline +25%, p95 <= +40%
- 위 64-build receipt의 default baseline p50이 `1,000,000ns` 미만인 측정 noise 구간에서는 상대비율만으로
  판정하지 않는다. 이때 activation의 default 대비 절대 증가량은 p50 `1,000,000ns` 이하,
  p95 `2,000,000ns` 이하(호출당 각각 15.625us·31.25us 이하)여야 한다.
- page render tree 준비 시간과 warm cache 수치 사이에서 cold first-layer-build p50·p95를 분리해 공개한다.
  기존 영수증은 warm-up 뒤 64-build 합계만 기록해 비교 가능한 cold baseline이 없으므로 cold 수치에는
  사후 hard gate를 만들지 않는다. Q3-E5 결과를 이후 cold 회귀의 최초 기준으로 고정한다.
- release WASM raw delta <= 65,536 bytes이면서 baseline의 0.75% 이하
- font blob은 unique source당 1개, instance face/result/outline cache는 canonical instance 수에 선형이며 상한을 넘지 않음

동일 환경 9회 측정에서도 gate를 넘으면 원인을 최적화하고 재측정하기 전에는 `qualified`로 판정하지 않는다.
