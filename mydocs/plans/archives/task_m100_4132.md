## 1. 문제

`tests/cli_exit_codes.rs`의 `export_png_follows_the_same_contract`는 함수 단위
`#[cfg(feature = "native-skia")]`라 default-feature worker에서 cfg-out된다. RED 전수 검사에서는
`tests/issue_1144.rs`의 `issue_1144_skia_png_export_entrypoint_does_not_freeze_filename_context`도 같은
상태임을 추가로 발견했다. `Native Skia tests` job은 두 integration target을 실행하지 않아 CLI 종료 코드와
Skia PNG filename cache 무효화 계약이 CI 어디에서도 검증되지 않는다.

PR #4170은 파일 전체가 native-skia로 게이트된 integration test를 저장소에서 발견해 Native job과
classifier 양쪽 배선을 강제하는 계약을 `devel`에 반영했다. #4132는 혼합 파일의 함수 게이트를 이 파일
게이트 규약으로 정규화한다.

## 2. 결정 — 선택지 B

native 전용 테스트를 `tests/cli_exit_codes_native.rs`와 `tests/issue_1144_native.rs`로 분리한다.

- 원래 `cli_exit_codes.rs`의 default-feature 테스트를 Native job에서 10건 중복 실행하지 않는다.
- #4170의 “파일 게이트 test = Native job + classifier 소유” 단일 규약을 재사용한다.
- 새 파일을 job 또는 classifier 한쪽에만 추가하거나 둘 다 빠뜨리면 기존 양방향 계약이 실패한다.
- 이미 Native job·classifier에 배선된 `issue_2225` 한 건만 명시적 예외로 두고, 함수 단위 native-skia
  test가 혼합 파일에 새로 생기는 경우를 별도 계약 테스트로 차단한다.

공용 실행 helper는 `tests/support/cli_exit_code_support.rs`와 `tests/support/issue_1144_support.rs`로
추출한다. 각 default/native integration crate 쌍이 같은 fixture·실행 함수를 사용하며 구현을 복제하지 않는다.
