# 수행계획서 — #2353 e2e 스크립트 인벤토리·관리 체계 설계

- 이슈: [#2353](https://github.com/edwardkim/rhwp/issues/2353)
- 마일스톤: M100 (v1.0.0) / 브랜치: `local/task2353`
- 유형: 설계+문서+도구 — 구현계획서는 생략하고 **2단계 설계안이 그 역할을 대신**
  (설계안 승인 후 구현 착수)

## 1. 배경 (실측)

`rhwp-studio/e2e/` 76개 파일 vs 매뉴얼 등재 18개 — 4배 드리프트. 명명 혼재
(도메인/issue-N/pr-N/debug-/.check/.probe/gen-), 생명주기·계층(CI vs 로컬 vs
수동 디버그) 무구분.

## 2. 단계

1. **전수 인벤토리 조사**: 76개 파일 각각 — 용도(1줄)·대상 기능·의존 샘플·
   실행 모드(host/headless)·assertion 유무·상태 분류(상시 회귀 / 일회성
   프로브 / 폐기 후보 / 유틸). 산출: 조사 결과 표 (`working/` 단계 보고).
   파일 내용 직접 정독 기반 — 파일명 추정 금지.
2. **관리 방안 설계** (승인 게이트):
   - **manifest 단일 권위 목록**: 위치·형식 확정 — 후보: `rhwp-studio/e2e/
     MANIFEST.md` (파일 옆 배치로 갱신 근접성) vs `mydocs/manual/` (문서
     거버넌스 front matter 정합). 트레이드오프 비교 후 권고안 제시
   - **명명 규칙**: 유형 접두/접미 체계 (예: 상시 `*.test.mjs`, 일회성
     `probe-*.mjs`, 유틸 구분) + 기존 파일 적용 방침 (일괄 개명 vs 신규부터)
   - **생명주기 절차**: 추가(=manifest 등재 의무)/변경/폐기(일회성 프로브
     보존·삭제 기준 — git history archive 원칙)
   - **드리프트 방지 장치**: 파일 목록 ↔ manifest 대조 검사 스크립트 설계
     (#2329 원장 트립와이어 선례 — 미등재 신규 파일 = FAIL)
   - e2e-cdp.md 는 실행 가이드로 존치, 목록 절은 manifest 참조로 대체
3. **구현**: manifest 작성(전수) + 대조 검사 스크립트 + e2e-cdp.md 현행화 +
   승인된 범위의 파일 정리(개명/폐기). 검사 스크립트는 링크·메타데이터 검사와
   같은 로컬 실행 원칙 (CI 미편입 — 필요 시 실행).
4. **게이트 + 최종보고**: 대조 검사 green + `check_markdown_links`/
   `check_document_metadata` green + 대표 e2e 3종 실행 확인(관리 변경이 실행에
   무영향 증명) → 최종보고.

## 3. 위험

- 폐기/개명은 외부 기여자 워크플로(문서·PR 본문의 기존 파일명 참조)에 영향 —
  2단계에서 영향 범위 조사 포함, 개명은 보수적으로 (참조 0건 확인 시에만)
- 히스토리 파일명 참조(과거 PR/이슈 본문)는 불변 기록이므로 redirect 불필요
  — manifest 에 구명 병기로 해결

## 4. 완료 기준

- 76개 전수 인벤토리 + 승인된 관리 체계 + manifest·검사 도구 반영
- 드리프트 0 상태로 시작 (검사 green), 이후 추가는 절차를 따르면 자동 유지
