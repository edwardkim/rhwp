## 3. 설계

### 3-1. 그리드 상태 모델을 DOM 에서 분리한다

B1 은 `valueInputs: (HTMLInputElement|null)[][]` 가 곧 상태였다. 행·열 수가 원본에 고정됐고
(`:109`,`:188`), `null` 하나가 "원본에 칸 없음"(`:157`)과 "원본이 빈 값"(`:167`)을 겸했다. 셋 다
**DOM 이 진실**이라는 한 병의 증상이다.

신규 순수 모듈 `src/core/chart-grid-model.ts` 가 **불변 모델을 진실로, DOM 을 투영으로** 세운다.
`CellOrigin` 4종(`value`/`empty`/`absent`/`new`)이 겸용하던 두 뜻을 가른다. 구조 연산 4종은 전부
`(GridModel, …) => GridModel` 이다. 새 칸 기본값은 `'0'` — 빈 문자열은 코어 `is_number` 가 거부한다.

미변경 문자열 보존(`4.30`)은 모델이 원본 문자열을 그대로 담고 손대지 않는 것으로 유지된다.
`trim()`·`Number()` 왕복이 이 경로에 한 번도 없다.

> **`src/core/` 의 값 import 는 상대경로 + `.ts` 확장자여야 한다.** `npm test` 는 `node --test` 로
> 타입 스트리핑만 하므로 `@/` alias 를 값 import 에 쓰면 그 모듈을 읽는 단위 시험이
> `ERR_MODULE_NOT_FOUND` 로 죽는다(선례 `font-substitution.ts:13`).

### 3-2. `structure` 는 페이로드에서 유도한다

`needsStructure(data, values, labels, names)` 를 새로 두되 규칙을 발명하지 않는다 — 코어
`validate_values` 의 네 거부(`seriesCountMismatch`·`valueCountMismatch`·`seriesNameMismatch`·
`categoryMismatch`)가 하나라도 설 페이로드면 true, **그 넷의 부정으로만** 정의한다.

항상 켜면 안 되는 이유: `structure: true` 는 개수 불일치를 "의도"로 해석하므로, 그리드 조립에
버그가 생기면 엔진이 거부하지 않고 **조용히 계열을 잘라내는 문서 변형**이 된다. B1 의 네 거부가
그 사고를 막는 마지막 그물이고 UI 가 재현할 수 없다. 부수 효과로 무편집 왕복이 자동 보장된다 —
아무것도 안 건드리면 `structure` 키조차 실리지 않아 페이로드가 B1 과 글자 단위로 같다.

### 3-3. 다이얼로그 전용 우클릭 메뉴

기존 `ContextMenu` 는 `registry.get(cmdId)` 가 없으면 항목을 버리는 커맨드 레지스트리 구동이라
그리드 조작 6종의 전역 커맨드 등재가 필요하고, `row.dataset.cmd`(`context-menu.ts:50`)가
automation e2e 의 `[data-cmd]` 드리프트 스캔 표면에 올라탄다. 그리드 조작은 다이얼로그 밖에서
뜻이 없으므로 신규 `src/ui/local-context-menu.ts` 를 두고 **CSS 만 재사용**한다 — 신규 CSS 0줄
(`.context-menu` z-index 20000 > `.modal-overlay` 10000).

**키 처리가 이 모듈의 핵심이다.** `ModalDialog` 는 `document` capture 에서 모든 키를
`stopPropagation()` 하고(`dialog.ts:113`) ESC 를 닫기로, **비-입력 요소의 Enter 를 `.dialog-btn-primary`
클릭으로** 바꾼다(`:105-110`). 메뉴 항목은 `<div>` 라, 막지 않으면 메뉴에서 누른 Enter 가
다이얼로그를 확인해 버린다. 그래서 `window` capture 에 달고(capture 는 `window → document` 순)
ESC·Enter 둘 다 전파를 끊는다. **이슈에 없던 실측이다.**

### 3-4. 사전 비활성은 봉투에서 유도되는 것만

| 조건 | 비활성 | 코어 대응 |
|---|---|---|
| `labelsMultiLevel === true` | 행 3항목 | `multiLevelLabelsUnsupported` |
| `labelsShared === false` | 행 3항목 | `sharedCategoryRequired`/`sharedXRequired` |
| 행 1개 / 계열 1개 | 행 삭제 / 계열 삭제 | `lastPointDeleteRefused`/`lastSeriesDeleteRefused` |
| `hasUpDownBars` 이고 대상이 첫·끝 계열 | 그 계열 삭제 + 양끝 **바깥** 삽입 | `candleAnchorBroken`(계열 수가 바뀔 때만 발화 → 중간 삽입·삭제는 통과) |

`plot === 'pie' | 'ofPie'` 는 **막지 않고** 안내한다 — #6037 이 파손이 아니라 무효과로 확정했다.
주식형 계열 수는 **아무것도 막지 않는다** — 처음에는 3·4로 묶었으나 한컴 실측이 그 근거를
반증했다(§3-5).

그 밖의 거부(중간 삽입 시 빈 값 자리 이동, `c:tx` 부재 등)는 **막지 않고 코어 dryRun 이 판정한다.**
코어 규칙을 UI 가 재현하기 시작하면 둘이 어긋나고, 과잉 차단이 미달 차단보다 나쁘다. 다만
`seriesNameRequired` 만은 UI 가 예방한다 — 신설 계열에 기본 이름을 채워 보내면 이 거부가 서지 않는다.

### 3-5. 주식형 렌더러의 계열 역할을 일반화한다 (사후 추가)

수동 테스트에서 `시가고가저가종가`에 계열을 더하면 캔들·고저선이 사라지고 꺾은선이 됐다.
**문서는 정상이고 렌더러가 어긋났다** — `render_stock`
(`crates/rhwp-ooxml-chart/src/renderer.rs`)이 계열 역할을 **위치로 고정**하고 있었다
(3계열=고·저·종, 4계열=시·고·저·종, 그 밖은 `render_line` 폴백).

한컴 실측이 그 규약을 반증한다. 참인 규칙은 OOXML 본래 의미다 —
**고저선 = 카테고리별 전 계열 최소↔최대**, **캔들 = 첫 계열↔끝 계열**(`upDownBars` 가 있으면
계열 수와 무관). 근거는 §8-1에 모았다.

변경면은 함수 머리의 인덱스 유도 한 곳뿐이다. 마커 루프는 이미 전 계열을 돌고 있고
(`marker_symbol` 이 `Auto|Named` 인 계열마다), 축도 `raw_value_bounds(chart.series.iter())` 라
이미 전 계열 기준이다.

**기존 3·4계열 렌더는 바뀌지 않는다** — 코퍼스 두 픽스처의 전 카테고리에서 두 규칙이 같은 값을
낸다(§8-1 표). 기존 stock 시험 6종이 무수정 통과하는 것으로 확인했다.

## 10. 확장 계획 — 구조 편집의 계열 정체 보존 (검증 완료판, #6053 후속 축)

보고서 §6-3 이 별건으로 접수했던 "새 계열의 스타일"을 코드 전수 실측으로 재검증한 확정
설계다. 결론 — **명시 표지(3면 계약 확장)는 기각, 추론이 계약을 한 글자도 안 바꾼다.**

### 10-1. 검증으로 확정된 사실

- `plan_edits` 는 순수 위치 기반(짝짓기는 `zip`, 증감은 꼬리 슬롯/꼬리 절단)이고, 정체
  추론기는 `ends_kept`(이름 일치 ∨ 값 벡터 일치, 양끝 전용) 하나뿐이다 — **이 이중 술어를
  전 위치로 확장하는 것이 정공법**이다.
- 임의 위치 삽입·삭제·재번호의 좌표(`element_span`·`idx_span`/`order_span`)는 이미 다
  있다. 없는 것은 그것을 쓰는 `ChartEdit` 변형과 계획부뿐.
- 코어 JSON 은 `deny_unknown_fields` 가 없어 미지 키가 조용히 버려지고, CSV 는 순수
  행렬이라 표지를 구조적으로 표현할 수 없다 — 명시 채널은 3면 동형을 깬다.
- v1 경계 문서(`chart_ole_v1_boundary.md` §4)와 충돌하지 않는다 — 그 조항은 렌더/퍼즈
  골든 잠금의 범위 선언이고, 편집 트랙은 #3683 go 결정을 따른다(#5652 가 이미 `patch.rs`
  를 열었다). WMF/EMF/`Contents`/`OlePres` 는 계속 안 건드린다.

### 10-2. 확정 스코프 — 비꼬리만

꼬리 삽입·꼬리 삭제·제자리 개명 = 기존 `AppendSeries`/`TruncateSeries`/`renameSeries`
그대로(바이트·op 불변 — CSV 계약 3시나리오·바이트 고정 계약·원형/막대 원장 SHA 무수정
통과가 증거). **비꼬리 삽입·삭제만** 정체 경로를 탄다. 주식형 OHLC 는 캔들 가드 때문에
허용되는 삽입이 전부 중간이라, 사용자가 본 결함이 정확히 이 경로다.

### 10-3. 설계

1. **정체 추론(`chart.rs`)** — 원본↔목표 대응이 단사이고 상대 순서가 보존되며 결과가
   "삽입만" 또는 "삭제만"일 때만 정체 경로. 그 외 전부(중복 이름·값, 동시 삽입·삭제,
   순서 역전) 현행 위치 기반 폴백 — 모호하면 무조건 폴백(R1). 전부 제자리 대응이면
   꼬리뿐이므로 레거시로 합류(바이트 불변).
2. **새 연산(`patch.rs`)** — `InsertSeries{at(최종 자리),…}`·`RemoveSeries{at(원본 자리)}`.
   복제 기계는 `append_series` 에서 추출한 `clone_series` 공유, `strip_style` 로 복제본의
   `sp_pr_span`·`symbol_span` 을 들어내 기본 스타일(Auto 마커·기본 선)로 되돌린다.
   앵커·재번호는 `finish()` 일괄 패스. 레거시 꼬리 연산과 상호 배제.
3. **스캐너(`data.rs`)** — `sp_pr_span`(계열 최상위)·`symbol_span`(marker 안) 스캔.
   깊이 카운터로 marker 하위 spPr 구분, `dPt`/`dLbls` 는 SKIPPED_SUBTREES 가 이미 차단.
4. **봉투** — `changed[]` op 2종 추가(`insertSeries{at,name}`·`removeSeries{at,name}`).
   기존 op 단언은 존재 단언이라 추가만으로 안 깨진다.

### 10-4. 판정 기준 (한컴 불호출)

OHLC 위치 1 삽입 후: 시가/고가/저가 = `symbol none`+`a:ln noFill`, **새 계열 = 미지정
(Auto)·`a:ln` 없음**, 종가 = Auto·noFill, idx/order 0..4. Rust 시험으로 단언한다
(`tests/cases/issue_6053_chart_series_identity_contract.rs`).

### 10-5. 원장 파급 (전수 실측)

중간계열삭제 × 2포맷, issue5652 {묶은,누적}세로막대형-계열삭제 × 2포맷. MANIFEST 2종
