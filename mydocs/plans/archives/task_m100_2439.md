## 1. 목표

공개 이슈 첨부 HWP의 6페이지(0-based page 5)에서 두 번째 일일 점검표 행과 글자가
겹치고 후속 빈 문단이 본문 하단을 3.8px 넘는 문제를 수정한다. 같은 문단에 묶인
자리차지 표를 fresh 페이지로 통째 이월할 때 typeset과 layout의 페이지-local 좌표를
다시 일치시키고, 기존 co-anchored float·RowBreak 동작은 보존한다.

정상 Microsoft Print to PDF 정답지의 10쪽이 빈 페이지라는 1차 판정은 이후 정밀
비교에서 잘못으로 확인됐다. 표 분할 흐름, 같은 visible host의 두 표 뒤 flow, 저장
LineSeg 기반 번호 줄글 들여쓰기를 함께 교정해 정답지와 같은 10쪽 흐름을 복원한다.

## 2. 최신 기준 재현

`upstream/devel` 28331531에서 다음 명령으로 동일 재현을 확인했다.

```sh
cargo run --quiet --bin rhwp -- export-svg \
  "/Users/melee/Downloads/고위험의료기기 일별 점검표(버그 제보용).hwp" \
  -o /private/tmp/rhwp-issue2439-20260719-baseline
```

- 현재 rhwp 출력: 8쪽
- 한컴 2024 편집 화면과 Microsoft Print to PDF 기준: 10쪽
  - PDF 10쪽에는 `5.응급 및 긴급한 상황시 7920으로 연락한다.` 한 줄이 있다.
- 진단: `LAYOUT_OVERFLOW: page=5, sec=0, col=0, para=53, type=FullParagraph, first=false, y=759.7, bottom=755.9, overflow=3.8px`
- page 6의 `pi=52`에는 8×17 RowBreak 표 두 개가 있다.
  - `ci=0`: `vertical_offset=0`, 실측 높이 191.6px
  - `ci=1`: `vertical_offset=6950HU`(약 92.7px), 실측 높이 191.6px
- layout 계측에서 `ci=0`은 y=519.5..714.8에 정상 배치되지만, `ci=1`은
  y=718.6에서 시작해 본문 하단 755.9까지만 37.3px로 잘린다. 8개 행이 이 좁은
  조각에 그려져 라벨과 경계가 겹친다.

## 3. 근본 원인

문제의 시작점은 page 5의 `pi=39`에 같은 host로 묶인 두 번째 표(`ci=1`)가
co-anchored RowBreak orphan 가드에 의해 page 6으로 통째 이월되는 경로다.

1. `typeset_table_paragraph`가 원래 page 5의 문단 시작 높이
   `para_start_height≈425.2px`를 잡는다.
2. `typeset_block_table`의 fits-fresh orphan 가드가 page 5의 남은 공간이 부족하므로
   `advance_column_or_new_page()`를 호출해 `ci=1`을 page 6으로 이동한다.
3. 새 페이지의 `current_height`는 0으로 초기화되지만, 뒤의
   `place_table_with_text`에는 이전 페이지의 `para_start_height≈425.2px`가 그대로
   전달된다.
4. 양수 offset visible float의 배타 영역이 page 6 기준 약 96px가 아니라 이전 페이지
   기준 약 522px에서 시작한다고 기록된다. 후속 문단은 실제 표 영역을 건너뛰지 못한다.
5. typeset은 page 6의 `pi=40`을 21.3px에서 시작하지만 layout은 이월된 표 하단
   325.8px 뒤에서 시작한다. 약 288px 좌표 차이가 누적되어 뒤의 `pi=52 ci=1`을
   typeset은 전체 fit으로 오판하고 layout은 페이지 하단에서 잘라 그린다.

이는 표 행 높이 측정 자체가 아니라 **페이지 이월 뒤에도 이전 페이지의 렌더/배타영역
기준점이 남는 stale `para_start_height` 결함**이다.

추가로 재현 문서의 반복 양식은 같은 visible host에 `vertical_offset=0`인 첫 표와
양수 offset인 두 번째 표를 둔다. 첫 표가 후행 co-anchored float를 위한 exclusion을
남기지 않아 두 번째 표가 첫 표 안에서 시작하고, 표 그룹 뒤에 emit되는 같은 host의
서명 텍스트도 자기 exclusion을 건너뛰었다. 따라서 첫 표의 전체 높이와 후행 표/서명
흐름이 함께 보존되지 않았다.

후속 10쪽 정답지 비교에서는 두 원인이 더 확인됐다.

1. 단일 positive-offset 빈 host RowBreak 표가 실제로 그려진 하단, outer bottom, 저장
   LineSeg 진행량을 다음 일반 문단 fit에 모두 전달하지 않아 표의 마지막 행과 서명문이
   한컴보다 앞쪽 페이지에 남았다.
2. native HWP5 일반 본문 줄의 저장 `LineSeg.column_start`를 무시해 번호 줄글이 문단
   margin 위치에서 시작했다. full-width 저장 LineSeg의 시작점을 권위 좌표로 적용해야
   한컴의 들여쓰기와 일치한다.

## 4. 수정 범위

| 포함 | 제외 |
|---|---|
| fits-fresh co-anchored RowBreak 표가 실제 새 페이지/단으로 이동한 경우 placement 기준점 재설정 | 전역 표 높이·행 높이 상수 변경 |
| 단일 positive-offset 빈 host RowBreak 표의 painted flow와 strict fit | 일반 문단 전체의 fit 정책 변경 |
| native HWP5 visible host의 두 표 outer margin·LineSeg flow와 post-text 배치 | 모든 float 좌표 재계산 |
| native HWP5 full-width 저장 LineSeg의 `column_start` 들여쓰기 | 표 셀·wrap/control·합성 LineSeg·HWP3·HWPX 적용 |
| #2439 end-to-end 회귀 테스트와 관련 focused 교차 회귀 | HWP 파서·직렬화 변경 |
| before/after SVG·PDF 또는 PNG 시각 확인 | 한컴 PDF의 가로 위치를 픽셀 단위 정답으로 간주 |

## 5. 단계

### Stage 1 — 회귀 가드 작성

- 공개 첨부 원본은 로컬 재현·시각 기준으로 유지한다.
- 저장소 fixture는 `ai_sample_document_authoring_guide.md`에 따라 개인정보·재배포
  가능성을 먼저 확인한다. 원본을 그대로 커밋하지 않고, 가능한 경우 기존
  `issue1663`/`issue1535` fixture를 Clone and Narrow하여 다음 구조만 남긴다.
  - 앞 페이지 중간에서 시작하는 visible host
  - 같은 host의 RowBreak 표 A/B
  - B가 fresh 페이지로 통째 이월되는 양수 offset 표
  - B 이후 문단이 B의 실제 하단 뒤에서 시작해야 하는 조건
- end-to-end 단언: 이월된 B와 후속 문단 비겹침, 문제 페이지의 표 bbox/행 bbox 양수,
  `LAYOUT_OVERFLOW`를 유발하던 후속 흐름이 본문 안에 머묾.

### Stage 2 — page-local placement 기준점 교정

- `src/renderer/typeset.rs::typeset_block_table`의 co-anchored fits-fresh orphan 가드에서
  실제 `advance_column_or_new_page()`가 발생했음을 기록한다.
- 해당 표의 **placement/exclusion 기준점만** 새 페이지의 `st.current_height`로 재설정한다.
- #1860에서 분리한 `budget_para_start_height`는 그대로 유지한다. 예산 기준과 렌더 위치
  기준을 다시 합치지 않는다.
- 같은 host에서 선행 co-anchored float가 있으면 양수 offset 표의 저장 상단과 현재 flow
  중 더 아래쪽을 exclusion 상단으로 사용해 표 전체 높이를 보존한다.
- zero-offset 선행 표도 후행 co-anchored float가 있을 때만 exclusion을 남긴다.
- 같은 host의 텍스트가 표 그룹 뒤에 emit되면 자기 exclusion을 소비하되, #1549의
  표 앞 제목은 기존처럼 표 위에 남긴다.

### Stage 3 — 1차 focused·시각 검증

- 신규 #2439 테스트 red→green.
- 관련 테스트: `issue_1510`, `issue_1535`, `issue_1549`, `issue_1663`, `issue_1860`,
  `issue_2322_fullpage_form_table_pair`.
- 재현 HWP `dump-pages`/`export-svg`:
  - `LAYOUT_OVERFLOW` 제거
  - page 6 반복 표 행/라벨 겹침 제거
  - 이월된 `pi=39 ci=1` 뒤 흐름과 `pi=52` 배치 정합
- 이 단계의 9쪽 출력은 1차 중간 결과다. Stage 4의 “PDF 10쪽은 빈 페이지” 판정은
  Stage 5에서 철회했으며, Stage 6에서 저장 flow 의미를 복원해 하드코딩 없이 10쪽을
  만들었다.
- 한컴 2024 PDF는 페이지 수, 내용 순서, 표 비겹침의 보조 오라클로 사용한다.
- 자동 raster 일치율은 폰트·anti-aliasing·전체 위치 차이의 영향을 받으므로 사람의
  페이지별 review와 함께 판정한다.

### Stage 4 — 최초 정답지 비교와 판정 철회

- 최초에는 양식 코드 순서만 보고 9쪽 출력과 PDF의 내용이 일치한다고 판정했다.
- PDF 10쪽의 텍스트를 끝까지 다시 확인해 blank-page 판정과 당시 완료 결론을 철회한다.
- Stage 4 문서는 당시 측정값은 보존하되 현재 결론으로 사용할 수 없음을 명시한다.

### Stage 5 — 정답지 오라클 정정과 잔여 차이 분석

- PDF 10쪽의 텍스트 레이어와 raster를 다시 확인해 마지막 5번 문장 한 줄을 식별한다.
- 9쪽 출력을 완료로 판정했던 Stage 4 결론을 명시적으로 철회한다.
- 페이지별 표 fragment, 표 하단과 서명문, 번호 줄글 시작 좌표를 정답지와 대조한다.

### Stage 6 — 잔여 flow·들여쓰기 구현과 최종 검증

- 단일 positive-offset 빈 host RowBreak painted flow와 strict fit을 구현한다.
- native HWP5 두 표 visible host의 outer margin·LineSeg flow를 typeset/layout 양쪽에
  반영한다.
- native HWP5 full-width 저장 LineSeg의 `column_start`를 일반 본문 줄에 적용한다.
- 최종 `dump-pages` 10쪽, focused 16개 대상 60/60, `cargo fmt` 검사, WASM build,
  PDF 1~10쪽 visual sweep과 사람 직접 review를 완료한다.
- 단계 보고서와 최종 보고서를 현행화한다. 전체 CI 성격 검증과 PR 생성·push는 별도
  승인 전에는 수행하지 않는다.

## 6. 위험과 완화

- **#1663 orphan control 회귀**: 후속 표 통째 이월 자체는 유지하고, 이월 후의 page-local
  placement 기준점만 교정한다.
- **#1860 재발**: `budget_para_start_height`와 placement 기준을 분리한 기존 계약을 유지한다.
- **다른 visible float 페이지수 변화**: `has_preceding_coanchored_float` + RowBreak +
  fits-fresh + 실제 advance가 모두 성립한 좁은 경로로 한정한다.
- **fixture 공개성**: 사용자가 제공한 HWP 원본은 명시적 동의 없이 그대로 커밋하지 않는다.
