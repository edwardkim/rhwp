## 목표

`samples/복학원서.hwp`의 표 셀을 편집해 Section 전체를 재직렬화했을 때 SectionDef 아래의
동일한 `CTRL_DATA`가 두 번 출력되는 결함을 제거한다. 저장본은 셀 편집 내용과 알 수 없는
SectionDef 자식 레코드를 보존하면서 한컴의 control child record 계약을 만족해야 한다.

## 확정 원인

HWP5 파서는 SectionDef에서 첫 중첩 `CTRL_HEADER` 전에 나타나는 첫 직접 자식 `CTRL_DATA`를
`Paragraph.ctrl_data_records`와 `SectionDef.extra_child_records`에 동시에 보존한다. 저장 시
일반 control serializer가 첫 사본을 `CTRL_HEADER` 직후에 쓰고, SectionDef serializer가
`extra_child_records`의 같은 payload를 다시 써서 한컴이 파일 손상으로 거부한다.

## 구현 범위

1. SectionDef에서 첫 중첩 `CTRL_HEADER` 전에 나타나는 첫 직접 자식 `CTRL_DATA`는
   `Paragraph.ctrl_data_records`만 소유하도록 파서의 canonical ownership을 고정한다.
2. 추가 직접 자식, 중첩 control의 `CTRL_DATA`, 중첩 `CTRL_HEADER` 뒤의 직접 자식
   `CTRL_DATA`는 알 수 없는 원본 레코드로 계속 보존한다.
3. 과거 또는 외부에서 만든 이중 소유 IR도 안전하게 저장하도록, SectionDef serializer는
   문단이 전달한 것과 level·payload가 모두 같은 exact duplicate만 건너뛴다.
4. parser ownership과 serializer 방어를 각각 고정하는 회귀 테스트를 추가한다.
5. `samples/복학원서.hwp`를 실제 `edit set-cell` 경로로 저장하고 record trace와 재독 결과를
   검증한다.
6. HWP5 저장·CTRL_DATA 기술 문서에 SectionDef의 선택적 레코드와 canonical owner를 반영한다.

## 범위 제외

- 서로 다른 payload를 가진 복수 `CTRL_DATA`의 의미 해석 또는 정규화
- SectionDef 이외 control의 배치 규칙 변경
- renderer·layout·Studio UI 변경
- Windows 한글 2024 자동화

## 위험과 대응

- **중첩 CTRL_DATA 손실**: tag만 보고 모두 제거하지 않고 첫 중첩 `CTRL_HEADER` 전,
  SectionDef header의 바로 아래 level에 있는 첫 레코드만 문단 소유로 이동한다.
  중첩 레코드와 중첩 header 뒤의 직접 자식 보존을 별도 테스트한다.
- **legacy IR 중복 재발**: parser 수정에만 의존하지 않고 serializer에서 동일 level·payload의
  exact duplicate를 방어한다.
- **baseline 감소**: 기존 IR field sweep에 중복 직렬화로 등록된
  `section_def.extra_child_records.len` 발산이 해소될 수 있다. 실측 dump와 baseline을 대조하고
  원인을 확인한 감소분만 갱신한다.
