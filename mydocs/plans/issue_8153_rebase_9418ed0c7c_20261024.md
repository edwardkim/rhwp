## 글꼴 관측의 원인 계층과 보정 방향

38쪽 후보의 host 관측은 원본 `한양신명조`의 명시 대체 `HY신명조`를 실제 `HCR Batang`으로

`HY신명조`의 실제 프로그램 부재와 다른 호환 프로그램의 존재를 같은 상태로 소비한 것이다.
기존 `FontEnvironment::document_requests`는 같은 프로그램의 이름만 제공하는
`installed_font_program_aliases`를 이미 사용한다.

HWP 표 19·21 및 원본의 TTF 대체 선언에 따라 공급 관측도 이 공통 프로그램 이름을 사용한다.
화면의 정상 fallback 순서는 유지하고, 명시 대체의 실제 프로그램이 확인된 경우에만 공통
측정·paint 환경을 확정한다. 문서 ID·페이지·점수·글꼴별 허용치를 분기 조건으로 넣지 않는다.
원 face 존재, 실제 명시 대체 존재, 호환 face만 존재, 주소별/명시적 전역 선택 우선권을

## WASM 전쪽 실행의 준비 오류와 남은 검증

고정 최적화 package로 전쪽 WASM 실행도 시작했다. 기준 exporter의 인자 수 차이와
Native가 실제 선택한 시스템 글꼴의 브라우저 공급 누락은 각각 별도 실패 로그에 보존했다.
Native receipt의 원본·선택 환경·프로그램 SHA·collection face를 검증해 동일 프로그램을
공급한다. 프로그램이 다르면 검사를 끄거나 다른 글꼴을 같은 것으로 간주하지 않는다.
동일 family의 서로 다른 설치 파일도 실제 SHA로 구분한다.

기존 회귀의 최종 Print 소비 검사와 글꼴 선택 계약의 통과는 전쪽 시각 검증의 대체가 아니다.
원래 HWP/HWPX 각 383쪽 × Native/fresh WASM의 raw 100%·정확한 미대응 0,
직접 확대 판독·중요 영역 회귀·최종 전체 게이트를 계속 수행한다.
