# Task M100-1330 수행계획서 — 빈 글머리표 줄 입력 후 marker/caret 크기 변동 보정

## 이슈

- GitHub Issue: #1330 `rhwp-studio: 빈 글머리표 줄에 입력 시 marker와 caret 크기가 커짐`
- 브랜치: `issue-1330-bullet-marker-caret-size`
- 마일스톤: M100 / v1.0.0 편집 기반
- 후속 관계: #1329 `글머리표 Enter 직후 빈 줄 caret이 글머리표 앞에 표시됨`

## 배경

#1329 작업 중 글머리표 문단에서 Enter를 눌러 새 빈 글머리표 줄을 만든 뒤 텍스트를 입력하면
글머리표 marker와 caret/입력 글자 크기가 커져 보이는 현상이 확인됐다.

#1329는 빈 list 문단의 caret x 좌표가 marker 앞쪽에 보이는 문제를 다룬다. #1330은 입력 전후의
marker/caret 스타일 기준이 달라지는 렌더링/스타일 문제로 분리한다.

관찰된 흐름은 다음과 같다.

1. 글머리표 문단에서 Enter를 눌러 같은 글머리표가 유지된 빈 줄을 만든다.
2. Enter 직후 빈 줄에는 marker만 있고 본문 TextRun은 없다.
3. 해당 줄에 텍스트를 입력하면 첫 본문 TextRun이 생긴다.
4. 입력 직후 marker와 caret/입력 글자 크기가 입력 전보다 커져 보인다.

## 목표

빈 글머리표/번호 문단에서 입력 전후의 marker와 caret 크기를 일관되게 유지한다.

사용자 경험 기준:

- Enter 직후 빈 list 문단의 marker 크기가 실제 입력 후 marker 크기와 달라지지 않는다.
- 입력 전 caret 높이가 입력 후 caret/문자 높이와 불연속적으로 바뀌지 않는다.
- 글머리표/번호 문단의 본문 시작 위치, hanging indent, 기존 list 배치는 회귀하지 않는다.

기술 기준:

- 빈 list 문단의 marker 스타일 산정 기준을 기본 스타일이 아니라 해당 문단의 활성 글자 모양으로 맞춘다.
- caret height 계산도 빈 list 문단에서 실제 삽입 예정 글자 스타일과 같은 기준을 사용하도록 확인한다.
- #1329의 caret x 보정과 충돌하지 않도록 좌표 문제와 스타일 문제를 분리해 구현한다.

## 비목표

이번 이슈에서 다음 범위는 다루지 않는다.

- 문단 번호/글머리표 정의 테이블 전체 구조 개편
- 모든 numbering/bullet level의 서식 재설계
- HWP/HWPX serializer 변경
- #1329 PR의 caret x 좌표 보정 재구현 또는 이슈 클로즈
- 한컴과 완전히 동일한 list marker glyph 선택 정책 보장

## 현재 가설

초기 가설은 다음과 같다.

- list marker는 문서 문자 좌표에 포함되지 않는 별도 TextRun으로 렌더링된다.
- 빈 list 문단에는 본문 TextRun이 없어 marker 생성 시 기본 글자 스타일 또는 fallback 스타일이 사용될 수 있다.
- 텍스트 입력 후에는 첫 본문 TextRun 또는 문단 char shape 기준으로 marker가 다시 산정되어 크기가 바뀔 수 있다.
- caret height도 빈 문단 fallback과 본문 run 기반 계산이 서로 다른 font size를 사용할 가능성이 있다.

Stage 1에서 실제 코드 경로와 데이터 차이를 확인한 뒤 가설을 조정한다.

## 성공 기준

1. 빈 글머리표/번호 줄에서 입력 전 marker 크기와 입력 후 marker 크기가 일관된다.
2. 빈 줄 caret height와 입력 후 caret/문자 height가 불연속적으로 커지지 않는다.
3. 기존 list 문단의 marker 위치와 본문 들여쓰기가 회귀하지 않는다.
4. 일반 빈 문단의 caret 동작이 회귀하지 않는다.
5. 자동 테스트와 rhwp-studio 수동 검증으로 확인된다.

## 리스크

- #1329 PR이 아직 upstream/devel에 병합되지 않았다. #1330 수정이 #1329와 같은 코드 경로를 건드리면
  PR 간 충돌 가능성이 있다.
- marker style은 렌더러, 문단 char shape, list definition이 함께 관여할 수 있어 원인이 단일 파일에
  한정되지 않을 수 있다.
- caret x 좌표와 caret height 계산이 같은 fallback 경로에 있으면 두 문제를 분리해 테스트해야 한다.
- 실제 한컴 동작과 비교가 필요한 경우 macOS/Windows 한컴 접근 가능 여부에 따라 수동 확인 범위가 제한될 수 있다.
