# #7642 저장 줄 끝의 재조판과 후속 원점을 같은 파생 프레임으로 공유

Issue: #7642.

## 확인된 결함과 독립 근거

0f58 Native의 #1440 원본은 46쪽이다. 질문 p19는 독립 한컴 Print와 같은
한 줄로 바뀌었지만 다음 p20은 여전히 옛 두 줄 사다리의 원점으로 이동한다.
실행 로그는 p19의 `total=35.5`, 저장 복원을 전제로 한 `adv=22.7`,
p20의 `cur_h=59.5`를 보여 준다. 새 높이를 계산한 사실만으로 후속 소비가
갱신된 것은 아니다. 6·15·36쪽의 raw 미달은 계속 blocker다.

## 공통 결과와 소비 지점

`project_stored_word_tail`이 실제 본문 frame에서 발행한 줄·공백 메트릭을
렌더 전용 정규화 문단으로 보존한다. 기존 `compute_render_normalized`의
파생 문단/구성 경로를 사용하므로 측정·pagination·paint가 같은 줄을 읽는다.
원본 document와 저장용 캐시는 변경하지 않는다.

줄 수가 바뀐 문단의 원본·새 프레임 전진 차이를 계산하고 같은 원본 물리
프레임의 뒤 문단 좌표에 전달한다. 명시적 쪽/단 전환, 단 정의 변경,
원본 VPOS 되감김과 줄의 쪽/단 시작에서 누적 보정을 종료한다. 저장 좌표를
clamp하거나 내용을 숨기지 않는다. 실제 단 폭을 PageLayoutInfo로 구하며,
너비가 다른 단처럼 현재 소유 단을 입증하지 못한 경우에는 투영하지 않는다.
좁은 어울림 띠를 전폭 본문으로 오인하지 않도록 원본 줄의 물리 구간도 확인한다.

기존 셀·그림의 검증된 줄 끝 재결합 계약은 보존한다. 일반 본문은 파생
정규화본을 먼저 발행한 뒤 사용하며, paint에서만 재결합하고 옛 후속 축을
남기는 임시 경로를 일반 본문 해결책으로 사용하지 않는다.

## 검증 범위

원본 두 형식의 전쪽, NO_LS 대조군, 국어 두 형식의 14·17쪽과 전체 문서,
전체 102문서 및 #7969·#7970의 Native/fresh WASM과 같은 base를 대조한다.
명시 개행·정상 두 줄·실제 단 경계·어울림·번호 없는 본문의 보존도 확인한다.
전쪽 90%와 직접 판독 전에는 새 실물 회귀나 baseline을 추가·변경하지 않는다.
