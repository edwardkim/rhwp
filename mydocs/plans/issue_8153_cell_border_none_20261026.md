# #8153: 명시적 NONE과 cellzone 테두리의 구분

## 원 해결과 후속 보정

편람 148쪽 처리 흐름 표의 Native 잔여 102픽셀은 그림이 아니라 중첩 표의
추가 괘선이다. 원본 section4의 2×11 표에서 화살표 칸의 윗변과 둘째 행 바깥
칸의 좌우 변은 명시적 NONE이다. 독립 Print에도 그 변이 없지만 현재 paint에는
원본의 표 기본 borderFill에서 보충한 검은 선이 있다.

기존 #6311·PR #6420, `93b0979b69`·`b81736b429`와 통합 기록을 추적했다.
`is_callout_partial_frame`은 선의 배치만 보고 일러두기 틀로 추정해, 칸이 차지한
NONE 슬롯까지 표 기본 테두리로 메운다. 편람의 처리 흐름 표도 그 조건에 걸린다.
조건을 더 붙여 특정 모양을 제외하지 않고 잘못된 보충의 근거부터 제거해야 한다.

후속 #6619와 `950300ea7b`는 #6311의 실제 원본 `156745900`을 다시 조사해,
빠진 회색 선의 실제 출처가 `cellzone` 38·39임을 확인했다. 그 공통 처리는 현재
`apply_cellzone_border_fill`에 이미 있다. 원본 표의 본문 셀 자체는 NONE이고
zone 38이 좌·우·아래에 `#BBBBBB 0.4mm`, zone 39가 왼쪽·위에 같은 선을 선언한다.
표 기본 borderFill 4의 검은 `0.12mm` 선과 구분된다. 원 이슈에서 측정한 최소 회색
186도 이 zone의 색과 대응한다. 현재 원본에서 해당 선언을 직접 확인했다.

## 잘못된 합성 검사와 독립 Print

`tests/cases/issue_6311_table_outer_border_fill.rs`는 원래 실물에 있던 zone을
빼고 표 기본 borderFill만으로 같은 프레임을 요구한다. 검사 함수가 생성하는
입력을 그대로 추출하고 원본 검사 소스를 바꾸지 않은 채 한컴 2020 Print로 출력했다.
이 합성 입력의 serializer 메타데이터는 11.x이며 해당 세대의 인쇄 경로를 사용했다.
독립 출력은 제목 칸의 네 변만 그리고, 검사가 요구하는 바깥 왼쪽·아래 선은 그리지 않는다.
현재 Native의 실제 비교는 **34.35374%·미대응 386픽셀**이다.

Print PDF SHA-256은 `2814cb331b49356b1884d3eb70db85719cdae7b44ed8ca1b548e8565924b1ea5`다.
실행 상태의 제품·버전·PrintMethod 0·인쇄 모드를 증적과 연결했다.
이는 합성 기대값의 잘못된 전제를 확인한 자료이며 현재 구현의 통과 증거가 아니다.
수정 출력의 Native/fresh WASM 90% 이상을 확인하기 전 기대값을 갱신하지 않는다.

## 공통 보정과 검증

`원본 칸 BorderFill → 칸 edge 점유 → cellzone의 명시적 덮어쓰기 →
실제 칸이 없는 표 외곽 슬롯의 기본값 → 최종 Line paint` 순서를 보존한다.
칸이 차지한 명시적 NONE에 선을 추측해 보충하는 분기를 제거한다.
이미 구현된 cellzone과 칸이 없는 슬롯의 기본값은 유지한다.
문서 ID·행/열 수·제목 모양·특정 좌표로 새로운 예외를 만들지 않는다.

두 편람의 148쪽에서 해당 윗변·좌우 변의 부재와 내용·소유·순서를 관계로 보호한다.
정식 원본의 현재 전쪽 Native/fresh WASM은 모두 90% 이상이며 이 신규 검사의
선행 범위를 충족한다. 같은 검사로 수정 전 실패와 수정 후 통과를 확인한다.
기존 #6619의 명시적 zone·병합 끝 주소·색 덮어쓰기 검사는 유지한다.
실물 #6311은 정상 대조군으로만 기존 경로와 출력을 확인하며 문서 보정 범위를 넓히지 않는다.

먼저 실제 영향 출력과 독립 Print의 같은 영역을 대조하고, 원본 전쪽과 기존 100%
페이지의 보존을 Native·표준 최적화 fresh WASM에서 확인한다.
잘못된 합성 기대값은 출력 보정과 양쪽 시각 선행 조건을 충족한 뒤 수정하고,
미검증 상태나 단순 assertion 완화로 완료를 대신하지 않는다.

합성 원본·PDF·비공개 정상 대조 자료·실행 결과는 ignored
`remaining-raw100-diagnostic/p148-callout-rule/`에만 보존한다.
정식 제출에 필요한 자료가 되면 정본 보존 위치와 출처를 따로 정리한다.
upstream 동기화·원격 GitHub 쓰기를 하지 않으며 전쪽 100%·필수 테스트 후 PR 준비까지만 한다.
