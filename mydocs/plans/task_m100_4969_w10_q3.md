## 1. 수정 이유

Q1 standalone shaper는 official Happiness Sans variable TTF의 axis를 검증하고 적용할 수 있다. Q2는 그 결과를
layout·paint owner에 연결했지만 variation vector가 비어 있는 경우만 활성화했다. 현행 Q2 transaction의 request와
cache key에는 axis가 없고, lowerer와 backend selector는 variation을 명시적으로 거부한다.

이를 한 번에 해제하면 같은 source별 mutable face가 이전 coordinate를 다음 요청에 누출할 수 있고, CanvasKit font
cache가 서로 다른 instance를 같은 Font로 재사용할 수 있다. 또한 HWP/HWPX에는 axis intent가 없으므로 글자 굵기나
장평을 `wght`·`opsz`로 추정하면 문서에 없는 의도를 만든다.

따라서 Q3는 effective instance identity, instance-local face/cache, replay capability, explicit request owner,
atomic product activation 순서로 진행한다.

## 2. source·axis 동결

공식 archive에서 byte 그대로 추적한
`ttfs/redistributable/happiness-sans/HappinessSansVF.ttf`만 Q3 exact source로 사용한다.

- SHA-256: `3bbd254dcc5780f7524f9d07af4aa981ba5e3e84cf32d7d4e04301b3943e8694`
- bytes: 1,503,064, face index 0, glyphs 3,889
- axes: `wght` 400/400/900, `opsz` 400/400/900
- named: Regular 400/400, Bold 900/400, Title 900/900

기존 WOFF2를 변환하거나 공식 TTF를 수정하지 않는다. Q3는 static instancing 결과를 font file로 생성·커밋하지
않는다. source bytes는 Q2 exact-source registry·resource accounting을 재사용한다.

## 3. canonical effective instance

canonical vector는 exact face의 `fvar` axis model을 기준으로 만든다.

1. tag가 4-byte ASCII인지, 중복이 없는지, 값이 finite인지, axis가 존재하고 범위 안인지 검증한다.
2. 요청 tag 순서와 무관하게 tag 순으로 정렬한다.
3. `-0.0`은 `0.0`으로 정규화한다.
4. `fvar` default와 같은 coordinate는 vector에서 제거한다.
5. partial vector의 생략 축은 default이므로 빈 vector·explicit defaults와 같은 effective instance가 된다.
6. source digest·byte length·face index·canonical non-default vector를 settings/cache identity에 넣는다.

Q3 공개 axis는 400~900 범위라 현행 6자리 JSON decimal로 f32 round-trip이 가능하지만, 판정 권위는 display 문자열이
아니라 canonical f32 bit vector다. future axis가 이 전제를 벗어나면 schema serialization을 별도 변경한다.

## 4. owner·cache 구조

```text
explicit slot instance request
  -> exact source handle + fvar model
  -> canonical non-default axis vector
  -> InstanceShapingKey
       registry generation + source handle + canonical vector
       -> instance-local rustybuzz Face
       -> immutable measurement Arc
       -> variable outline or proven backend typeface instance
  -> Q2 atomic publication
       line selection + bbox + next origin + replay payload
```

source bytes·prepared blob·face metadata는 unique source당 한 번 공유한다. mutable rustybuzz/ttf-parser/Skia face는
canonical instance 사이에 공유하지 않는다. cache entry와 typeface/outline 준비는 unique instance 수에 귀속하며
1/2/8 run이 같은 instance를 쓸 때 다시 증가하지 않아야 한다.

## 5. 단계별 절편

### Q3-A — canonical instance red 계약

1. 새 Rust 회귀 원본은 `tests/cases/`에만 추가한다.
2. 빈 vector·explicit 400/400·axis 순서 permutation이 같은 identity가 되는 계약을 red로 고정한다.
3. default→title→default, wght-only→opsz-only 순서에서 mutable face state 누출 0을 요구한다.
4. unknown·duplicate·NaN·Infinity·out-of-range·17-axis 요청의 기존 structured reason을 보존한다.
5. default Q2 old-Hangul layer/render JSON과 geometry가 그대로임을 control로 둔다.

**종료 게이트**: red 원인이 effective-default canonicalization, Q2 request/cache axis 부재와 source-only mutable face
reuse로 한정된다. 제품 caller·output 변화 0.

**결과**: [`Q3-A red 계약 결과`](../working/task_m100_4969_w10_q3_a.md)는 기존 control을 보존하면서
effective-default identity, explicit-default shaping 경계, mutable face의 전체·부분 축 누출과 Q2 request field
부재에서만 실패했다. 결과는 승인됐으며 checkpoint를 만들기 전까지 Q3-B 구현은 시작하지 않는다.

### Q3-B — instance-aware dormant measurement·cache

1. `HorizontalShapingRequest`와 cache key에 canonical variation vector를 연결한다.
2. face cache를 `(source handle, canonical effective instance)`로 분리하고 instance 변경 순서에 무관하게 같은 결과를
   내도록 한다.
3. Q1 shaper의 axis 검증·identity·`set_variations()`를 재사용하고 별도 variation engine을 만들지 않는다.
4. default, weight-interior, Bold, optical-interior, Title matrix를 pure Hangul·pure Latin non-ligature로 측정한다.
5. `1/2/8 instance × 1/2/8 run`에서 source bytes 공유, face parse·result cache hit/miss를 계측한다.

**종료 게이트**: native·Node WASM glyph·cluster·advance parity mismatch 0, cross-instance state leak 0, explicit default와
empty identity mismatch 0. 제품 consumer 0, Q2 output 변화 0.

**결과**: [`Q3-B dormant measurement·cache 결과`](../working/task_m100_4969_w10_q3_b.md)는 Q3-A red 네 건을
해소했다. 공개 5-instance Hangul·Latin matrix와 `1/2/8 instance × 1/2/8 run` 회계, native 66건과 Node WASM
9건에서 mismatch·state leak·cache collision 0을 확인했다. 결과는 승인됐고 제품 caller·publication은 계속
0이다. checkpoint commit과 Q3-C 시작은 각각 별도 승인 전 수행하지 않는다.

### Q3-C — replay payload·backend capability shadow

1. dormant measurement의 canonical vector를 `FontInstanceKey.variations`와 lowerer identity에 전달한다.
2. exact variable TTF에 같은 canonical vector를 적용해 runtime glyph outline을 만들고 shaping glyph·bbox와 대사한다.
3. CanvasKit 현행 JS API에서 exact instance typeface를 증명하지 못하면 GlyphRun selector를 열지 않고 qualified
   GlyphOutline 후보만 검증한다.
4. Native Skia는 exact blob typeface construction 뒤 `FontArguments`·`clone_with_arguments()` coordinate를 shadow로
   검증한다. 이 선행 proof가 실패하면 GlyphOutline/TextRun fallback을 유지한다.
5. SVG·Canvas2D는 published variable outline만 replay하며 backend reshaping을 금지한다.
6. CanvasKit/Native font cache key에 canonical vector가 포함되지 않은 상태에서 selector가 열리지 않음을 음성
   계약으로 유지한다.

**종료 게이트**: 각 backend가 `strict GlyphRun`, `qualified GlyphOutline`, `TextRun fallback` 중 증명된 하나로
결정되고 instance cache collision 0. static/modified font binary 생성 0, 제품 output 변화 0.

**결과**: [`Q3-C replay capability shadow 결과`](../working/task_m100_4969_w10_q3_c.md)는 canonical vector를
dormant GlyphRun identity와 producer-resolved outline proof에 연결했다. native·Node WASM에서 bbox mismatch 0,
Native Skia exact instance coordinate round-trip, CanvasKit cache 미개방을 확인했다. CanvasKit 계열·Native Skia·
SVG는 qualified GlyphOutline shadow, Canvas2D는 TextRun fallback이며 제품 publication과 selector 변화는 0이다.
결과는 승인됐고 checkpoint `0a248f3b8`로 고정했다. 최신 `upstream/devel@955abb5268c3`을 merge commit
`a8ff6a19d`로 통합한 뒤 같은 경계와 교차 영향·Native Skia·Studio·Docker/Node WASM을 재통과했다.

### Q3-D — explicit request owner·dormant product transaction

1. CQRS owner를 감사해 explicit opt-in command/API가 exact `(charShapeId, languageIndex)` slot에 canonical instance를
   결합하도록 한다. 이름과 공개 surface는 이 절편 결과 승인 전 확정하지 않는다.
2. HWP/HWPX parser, font name, bold, 장평에서 axis를 추정하는 caller가 0임을 계약 테스트로 고정한다.
3. request generation을 source registry generation과 함께 cache key에 넣고 instance 변경 시 파생 layout을
   일괄 무효화한다.
4. Q2 line owner·sidecar·resource reservation을 재사용하되 publication flag는 dormant로 유지한다.
5. axis request가 없거나 backend replay가 준비되지 않으면 Q2 default output으로 전체 rollback한다.

**종료 게이트**: explicit request만 deterministic instance transaction을 만들고 default·미지원 입력은 Q2와 동일.
제품 게시 0. 별도 activation matrix와 메인테이너 승인을 받는다.

### Q3-E — bounded atomic activation·최종 자격 판정

1. explicit request, horizontal LTR, one-line/one-run, homogeneous face/script, no synthetic style·display projection인
   공개 fixture만 활성화한다.
2. measurement·line selection·bbox·next origin·GlyphRun/Outline이 같은 instance measurement `Arc`를 소비한다.
3. default/400·interior·900 matrix와 negative·rollback matrix를 native·Docker WASM·CanvasKit·Native Skia·
   SVG·Canvas2D에서 검증한다.
4. source/instance 1/2/8 matrix의 face parse·outline/typeface cache·payload, layout wall time과 WASM size를 기록한다.
5. 결과를 `qualified`, `bounded-subset`, `blocked`로 판정하고 Q4 vertical 인계를 작성한다.

**종료 게이트**: 지원 backend parity mismatch 0, default Q2·비대상 회귀 0, cross-instance leak/cache collision 0,
fail-closed·resource 회계 누락 0.

## 6. 보호 불변식

1. axis 요청이 없으면 Q2 output과 identity를 유지한다.
2. 문서 버전·font name·bold·ratio로 axis를 추측하지 않는다.
3. source digest·face index·canonical instance가 identity/cache/trace에 함께 남는다.
4. effective default와 axis 순서 permutation은 같은 identity다.
5. 서로 다른 instance가 mutable face를 공유하지 않는다.
6. measurement와 replay가 같은 instance를 소비하고 partial publication을 허용하지 않는다.
7. backend independent shaping과 double GPOS를 허용하지 않는다.
8. instance proof가 없는 backend는 TextRun 또는 qualified outline으로 닫는다.
9. 기존 text/glyph/cluster/axis/cache/font resource 상한을 유지한다.
10. 공식 font bytes를 수정하거나 static instance font를 생성하지 않는다.
11. raw text·font bytes·host path·private identity를 trace에 넣지 않는다.
12. W8 correction·fallback registry·Q4 vertical을 같은 변경에 혼합하지 않는다.

## 7. 검증·제출 규칙

- 새 integration source는 `tests/cases/` 원본만 source PR에 포함한다.
- generated suite·manifest·Cargo marker는 review worktree와 CI 증적일 뿐 source commit에 포함하지 않는다.
- source `#[cfg(test)]`가 바뀌면 unit-tier check를 수행한다.
- activation 전후 Q2 K0/W9/D4/D5 보호 fixture, native/WASM, Studio selector·draw, Native Skia를 함께 검증한다.
- 모든 push 전 prepared exact candidate에서 `cargo fmt --all`과 `cargo fmt --all -- --check`를 통과한다.
- private corpus·Hyper-V·한컴 Oracle은 Q3 axis intent의 권위가 아니므로 사용하지 않는다.
