# #4467 피드백 — 업스트림과 다운스트림의 경계

- **Issue**: [#4467](https://github.com/edwardkim/rhwp/issues/4467)
- **일자**: 2026-08-10
- **작업지시자 피드백**: 공식 업스트림 배포 대상과 활발히 성장하는 다운스트림 제품의 범위를
  로드맵에서 구분하고, 새 기능을 rhwp에 기여할지 별도 제품으로 파생할지 판단할 기준을 제공해야 한다.

## 현재 생태계

rhwp 업스트림은 다음 공식 배포 대상을 유지한다.

- Chrome·Edge·Firefox 확장 프로그램
- VS Code 확장 프로그램
- npm 패키지

CLI와 MCP 서버는 다양한 자동화·백엔드 서비스가 공통 엔진을 사용할 수 있게 하는 연계 표면이다.

다운스트림에서는 데스크톱 앱, 사내 HWP·HWPX 뷰어, Google Docs 연계, macOS·iOS·Android 앱과
서비스별 백엔드 연계가 여러 형태로 파생되어 성장하고 있다.

## 반영 원칙

1. 업스트림은 공통 엔진, Web/WASM 기반, 공식 배포 대상과 재사용 가능한 CLI·MCP·공개 API 계약을
   책임진다.
2. 다운스트림은 특정 운영체제·조직·업무·서비스에 맞춘 제품 설계, 인증, 배포와 사용자 지원을
   책임진다.
3. 새 플랫폼 완제품은 다운스트림에서 시작하는 것을 기본으로 하고, 공식 편입은 유지 담당자·배포
   권한·보안 대응·CI·장기 지원 책임을 합의한 뒤 별도로 판단한다.
4. 범용 엔진 결함과 여러 제품이 재사용할 확장점은 작은 이슈와 PR로 분리해 업스트림에 제안한다.
5. 다운스트림 제품의 존재와 rhwp의 공식 배포·지원 범위를 혼동하지 않는다.

## 기존 판정과의 정합

[PR #4322](https://github.com/edwardkim/rhwp/pull/4322)에서는 Windows Tauri 셸과 사내 NSIS 배포
정책을 다운스트림 책임으로 판정했다. 공용 엔진 API나 호스트 확장점이 필요하면 해당 부분만 별도
이슈와 PR로 제안하도록 안내했다. 이번 로드맵 보정은 이 개별 판정을 생태계 전체의 일반 기준으로
정리한다.
