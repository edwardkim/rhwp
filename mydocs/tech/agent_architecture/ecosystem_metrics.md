# 생태계 지표 — 무엇을 세면 성장·정체를 말할 수 있는가 (R90)

로드맵 트랙 I [R90 생태계 지표 정의](../agent_roadmap/track_i_standards.md)의
1차 문서다. R90 의 착수 게이트는 **"측정 대상 합의(무엇을 성공으로 볼지)"** 인데,
합의는 문서가 선언할 수 있는 것이 아니다 — 그래서 이 문서는 **합의 선언이 아니라
제안 + 실측**이다: 지표 후보 3축의 정의·측정법·한계를 제안하고(§2), 그중 지금
측정 가능한 1축(리드타임)을 실제로 재서 기준선으로 수록한다(§3). 게이트의 소진
여부는 이 재료를 본 메인테이너의 채택 판단으로만 정해진다(§5).

R90 의 등급은 **[가설]** 이고, **이 문서는 그 등급을 올리지 않는다** —
[야간 자율 정비 사이클](../autonomous_maintenance/nightly_cycle.md) ·
[릴리스 노트 자동화](../autonomous_maintenance/release_notes_automation.md) ·
[엔드게임 판정 기준](../autonomous_maintenance/endgame_criteria.md)이 세운
"설계 문서가 있다고 근거가 생기지는 않는다" 관례 그대로다. 등급이 오르는 것은
[로드맵 README 운영 규칙 2](../agent_roadmap/README.md)대로 머지 링크와 함께,
DoD("지표 정의가 문서화되고, 최소 1개 지표가 실제로 측정된다")의 판정으로만이다.

근거 규약은 이 축([README](README.md) "근거 규율")을 따른다 — 모든 주장에
이슈·PR 번호 / 문서 경로(`파일:줄`) / 실측 출력 중 하나. 못 대면 "확인되지
않음"(§7). 숫자에는 측정일과 재현 명령을 함께 적는다(근거 규율 4).

---

## 0. 이 문서가 하는 것과 하지 않는 것

**하는 것** — ① 생태계 건강 지표 후보 3축(채택·호출·리드타임)의 정의·측정법·
한계를 한 곳에 고정한다(§2) ② 그중 리드타임을 실측해 90일 기준선을 남긴다(§3)
③ 이 수치가 답하는 것과 답하지 않는 것을 가른다(§4) ④ 합의 절차와 재평가
트리거를 적는다(§5·§6).

**하지 않는 것** — 측정 대상 합의의 선언(게이트는 문서로 우회되지 않는다),
R90 등급 상향, 대시보드·수집 자동화 구현 제안(그 부류는 트랙 J R94~R96 의
관할), 목표 수치 설정("중앙값 N 시간 이하" 같은 목표는 지표가 채택된 뒤에야
의미가 있다 — 지표 없는 목표가 아니라 목표 없는 지표가 올바른 순서다).

## 1. 왜 지표인가 — 현재 상태

R90 본문(track_i_standards.md:134-135)이 현재 상태를 이미 적었다: "무엇을
성공으로 볼지 합의가 없다 — 지표가 미정의라 성장·정체를 말할 기준이 없다."

이 로드맵은 목표 문장("새로 온 에이전트가 매뉴얼 없이 30분 안에 첫 유효
기여")과 그 판정 실험(R100)은 갖고 있지만, 그것은 **한 시점의 통과/실패**
판정이다. 생태계 건강은 시점이 아니라 **추세**의 문제다 — 채택이 늘고 있는가,
반응이 빨라지고 있는가를 물으려면 반복 측정 가능한 지표와 기준선이 먼저 있어야
한다. 기준선 없이 나중에 재면, 그 수치가 좋아진 것인지 나빠진 것인지 말할
비교 대상이 없다. 이 문서의 실측(§3)이 그 기준선 역할이다.

## 2. 지표 후보 3축 — 정의·측정법·한계

세 축의 상태가 서로 다르다는 것이 이 절의 핵심이다: 채택은 **구조적으로 측정
불가**(선행 단계 미착수), 호출은 **계약 제안 단계**(관측성 0), 리드타임은
**지금 측정 가능**(GitHub API 가 원천). 그래서 실측은 리드타임 1축에만 있다.

### 2.1 채택 — 외부 구현·의존 수

- **정의** — rhwp 의 공개 계약(planSchema R81 · irSchemaVersion R82 · MCP
  표면)에 의존하는 외부 구현·에이전트·프로젝트의 수.
- **측정법(제안)** — ① 패키지 저장소의 다운로드·역의존 수 ② GitHub dependents
  ③ MCP 레지스트리 등재 항목의 참조 수. 셋 다 배포 채널이 있어야 분모가 생긴다.
- **현재 측정 불가 사유** — 배포 채널이 0 이다.
  [R38 릴리스 바이너리 배포](../agent_roadmap/track_d_discovery.md)와 R39(MCP
  레지스트리 등재)가 둘 다 `[가설]`·미착수다(track_d_discovery.md:97-119).
  R86 이 같은 사실을 이미 적었다: "배포·등재 전이라 외부 사용자 자체가 아직
  없다"(track_i_standards.md:86-87). 없는 사용자의 수는 0 측정이 아니라
  **미정의**다 — 지금 이 축을 측정했다고 주장하는 것이 바로 이 문서가 피하려는
  가짜 진행이다.
- **프록시 실측 (2026-08-08, `gh api repos/edwardkim/rhwp`)** — star 3,649 ·
  fork 663. 단, 이것은 채택이 아니라 **관심**의 프록시다. fork 663 중 rhwp 를
  실제로 빌드·의존하는 외부 구현이 몇인지는 이 수로 알 수 없다(§7 ①).
- **한계** — R38·R39 이전의 어떤 숫자도 프록시다. 프록시를 채택 수로 보고하는
  순간 지표가 처음부터 왜곡된 기준선을 갖게 되므로, 이 축의 기준선 측정은
  배포 착지 이후로 미룬다(§6 트리거 1).

### 2.2 호출 — 도구 사용 통계 (R80 연계)

- **정의** — 도구명별 호출 수·오류 계열·소요 시간 집계.
  [R80 에이전트 관측성](../agent_roadmap/track_h_mcp_server.md)의 수집 축과
  동일하다 — 이 축의 원천은 R80 이고, 이 문서는 그 결과를 생태계 관점에서
  소비하는 자리다.
- **측정법(제안)** — R80 의 옵트인·로컬 통계를 그대로 쓴다. 수집 항목과 금지
  경계(문서 내용·파일 경로·인자 값 미수집)는 R80 계약 문서 — PR
  [#4198](https://github.com/edwardkim/rhwp/pull/4198)
  (`agent_architecture/observability_contract.md`, 2026-08-08 현재 **열린
  PR** — 머지 전이므로 경로가 아직 devel 에 없다) — 를 따르고, 이 문서는 그
  계약을 중복 서술하지 않는다.
- **현재 측정 불가 사유** — 관측성이 0 이다. R80 본문(track_h_mcp_server.md:
  148-149)의 "서버는 호출을 기록하지 않는다"가 현재 상태이고, #4198 §1 이
  `src/mcp_serve.rs` 전수 확인(계측 프리미티브 grep 0건)으로 이를 실측했다.
- **한계** — 둘이다. ① **옵트인 편향**: 통계를 켠 사용자만 잡히므로 절대량이
  아니라 구성비(어느 도구가 상대적으로 많이 불리나)로만 읽어야 한다.
  ② **로컬 한정 원칙과의 긴장**: R80 DoD 는 "데이터가 로컬 밖으로 나가지
  않는다"다. 생태계 지표로 집계하려면 사용자의 **능동 제출**(이슈에 요약을
  붙이는 식)이 한 단계 더 필요한데, 그 제출 경로는 #4198 도 이 문서도
  제안하지 않는다 — 계약 없이 수집 경로부터 여는 것은 #4198 §3 이 막은
  방향과 정확히 반대다.

### 2.3 리드타임 — 이슈 접수 → 종결

- **정의** — 이슈의 접수(`created_at`)부터 종결(`closed_at`)까지의 경과 시간.
- **R90 본문과의 차이(명시)** — R90 본문(track_i_standards.md:136-137)은
  "접수 → 머지"라 적었다. 이 문서는 **접수 → 종결**로 조작화했다. 이유:
  이슈↔PR 연결은 다대다(이슈 하나에 PR 여럿, PR 하나가 이슈 여럿 종결)라
  "그 이슈의 머지 시각"이 단일 값으로 정의되지 않는 반면, `closed_at` 은
  API 1차 필드라 전수 자동 측정이 성립한다. 본문 정의(접수→머지)의 자동
  측정 가능성은 확인되지 않음(§7 ④)으로 남긴다 — 정의를 바꾼 것이 아니라
  측정 가능한 근사를 먼저 재고 차이를 기록하는 것이다.
- **측정법** — GitHub search API 전수 조회. 재현 절차는 §3.3.
- **한계** — §4 에 모아 적는다(생존 편향·품질 무응답·모집단 성격).

## 3. 리드타임 실측 — 90일 기준선 (2026-08-08)

### 3.1 측정 창과 전수성

- **창** — 종결일 `2026-05-10..2026-08-08`(측정일 기준 최근 90일), 이슈만
  (`is:issue`, PR 제외), 종결 상태만(`is:closed`).
- **전수** — 1,366건. search API 는 쿼리당 1,000건까지만 돌려주므로 종결일로
  3개 부분 창(`..06-30` / `07-01..07-25` / `07-26..08-08`)에 나눠 받았다 —
  508 + 600 + 258 = 1,366 으로 단일 쿼리의 `total_count` 1,366 과 일치하고,
  이슈 번호 중복 0건을 확인했다.

### 3.2 분포

| 구간 | n | 중앙값 | p90 | 최대 |
| --- | --- | --- | --- | --- |
| 전체 | 1,366 | 18.3h (0.8일) | 154.8h (6.4일) | 1,404.1h (58.5일) |
| `completed` | 1,330 | 18.6h | 154.5h | 1,399.4h |
| `not_planned` | 36 | 2.1h | 161.7h | 1,404.1h |

- 24시간 이내 종결 **795/1,366 = 58.2%**, 7일 이내 종결 **1,248/1,366 = 91.4%**
  (`completed` 만으로도 57.7% · 91.4% — 종결 사유가 분포를 거의 바꾸지 않는다).
- 종결 월별 추이:

| 종결 월 | n | 중앙값 | p90 |
| --- | --- | --- | --- |
| 2026-05 (10일~) | 256 | 35.5h | 329.2h |
| 2026-06 | 252 | 12.4h | 192.5h |
| 2026-07 | 744 | 17.6h | 125.4h |
| 2026-08 (~8일) | 114 | 13.1h | 119.0h |

- **읽기** — p90 이 329 → 193 → 125 → 119h 로 넉 달 연속 내려갔다: 꼬리(오래
  걸리는 이슈)가 짧아지는 추세다. 중앙값은 12~36h 사이에서 진동한다. 7월의
  n=744 급증은 같은 기간의 기여 캠페인과 시기가 겹치지만 인과는 확인되지
  않음(§7 ②)이다.

### 3.3 재현 절차

별도 도구 파일 없이 아래 두 블록으로 재현된다. 부분 창 경계는 창당 1,000건
캡 아래에 있도록 고른 것이므로, 재측정 시점에는 각 창의 `total_count` 가
1,000 미만인지부터 확인하고 필요하면 더 잘게 쪼갠다.

```bash
for W in "2026-05-10..2026-06-30" "2026-07-01..2026-07-25" "2026-07-26..2026-08-08"; do
  gh api --paginate -X GET search/issues -f per_page=100 \
    -f q="repo:edwardkim/rhwp is:issue is:closed closed:$W" \
    --jq '.items[] | [.number,.created_at,.closed_at,.state_reason] | @tsv'
done > closed_issues.tsv
```

```bash
python - <<'EOF'
import csv, statistics
from datetime import datetime
p = lambda s: datetime.fromisoformat(s.replace("Z", "+00:00"))
rows = [r for r in csv.reader(open("closed_issues.tsv", encoding="utf-8"), delimiter="\t")]
hrs = sorted((p(c2) - p(c1)).total_seconds() / 3600 for _, c1, c2, _ in rows)
assert len(rows) == len({r[0] for r in rows}), "이슈 번호 중복 — 부분 창이 겹쳤다"
k = (len(hrs) - 1) * 0.9
p90 = hrs[int(k)] + (hrs[min(int(k) + 1, len(hrs) - 1)] - hrs[int(k)]) * (k - int(k))
print(f"n={len(hrs)} median={statistics.median(hrs):.1f}h p90={p90:.1f}h max={max(hrs):.1f}h")
EOF
```

2026-08-08 출력: `n=1366 median=18.3h p90=154.8h max=1404.1h`.

## 4. 이 수치가 답하는 것과 답하지 않는 것

**답하는 것** — ① 이슈에 대한 반응 속도의 분포(중앙값 하루 미만, 열에 아홉은
일주일 안에 종결) ② 그 꼬리의 추세(p90 넉 달 연속 하강) ③ 이후 재측정이 비교할
기준선.

**답하지 않는 것** — 넷을 명시한다.

1. **품질** — 빨리 닫힌 이슈가 잘 닫힌 이슈인지는 이 수치에 없다. 종결 후
   재개율(reopen)을 함께 재야 속도-품질 교환을 볼 수 있는데, 이번 측정은
   reopen 이력을 조회하지 않았다(§7 ③).
2. **생존 편향** — 종결일 필터라서 **아직 열려 있는 이슈는 어떤 창에도 잡히지
   않는다**(2026-08-08 열린 이슈 135건, `is:issue is:open` 실측). 오래 끄는
   문제일수록 분포에서 빠지므로 이 리드타임은 낙관 쪽으로 기운 값이다 — 열린
   이슈의 체류 시간(age) 분포를 보조 지표로 함께 봐야 균형이 맞고, 그것은
   재측정 시점의 추가 측정 항목으로 남긴다.
3. **모집단의 성격** — 현재 이슈의 다수는 외부 사용자 신고가 아니라 기여
   캠페인의 자기 이슈(착수 절차상 이슈 등록 → PR)다. 즉 이 수치는 지금
   시점에서는 "외부 신고에 대한 응답 속도"가 아니라 **"기여 루프의 회전
   속도"** 에 가깝다. 외부 사용자가 생기면(R38·R39 이후) 같은 정의의 수치가
   다른 것을 재게 된다 — 그때 라벨·작성자 구분 측정이 필요해진다.
4. **채택·호출** — 이 실측은 3축 중 1축이다. 나머지 두 축이 측정 불가인 이유는
   §2.1·§2.2 에 적었고, 리드타임이 좋다고 생태계가 건강하다고 말할 수 없다 —
   사용자 0 인 저장소도 리드타임은 좋을 수 있다.

## 5. 합의 절차 — 게이트를 어떻게 소진하는가

R90 의 착수 게이트("측정 대상 합의")는 이 문서의 머지로 소진되지 않는다.
문서 머지는 "정의가 문서화됐다"까지이고, **합의는 메인테이너가 측정 대상을
채택하는 행위**다. 이 문서가 제안하는 최소 합의 단위는 하나다:

> **리드타임(§2.3 의 정의, §3.3 의 측정법)을 R90 의 1호 지표로 채택할지.**

채택·호출 축은 지금 합의해도 측정이 성립하지 않으므로(선행 R38·R39, R80)
합의 대상에서 **제외를 제안**한다 — 측정 불가 항목의 합의는 빈 약속이 된다.
판단 결과가 어느 쪽이든 이 문서의 §2 정의는 남고, 등급·완료 표기는
[로드맵 README 운영 규칙](../agent_roadmap/README.md) 그대로 머지 링크와
함께만 움직인다.

## 6. 재평가 트리거

다음 중 하나가 발생하면 이 문서를 다시 본다.

1. **R38·R39 착지** — 채택 축(§2.1)의 측정법을 실물 배포 채널 기준으로 다시
   쓰고, 그 시점을 채택 축 기준선의 t=0 으로 잡는다.
2. **PR #4198 의 머지 또는 폐기** — §2.2 의 계약 인용을 devel 경로
   (`observability_contract.md`)로 바꾸거나, 폐기 시 호출 축의 측정법을
   재설계한다.
3. **이슈 흐름의 성격 변화** — 월별 n 이 현 수준(1~7백)에서 자릿수로 변하면
   (캠페인 종료·외부 유입 개시 등) §3 기준선을 재측정하고 §4-3 의 해석을
   갱신한다.
4. **측정 수단의 변화** — search API 의 캡·필드 의미가 바뀌면 §3.3 재현
   절차를 갱신한다.

## 7. 교차 확인과 확인되지 않음

**교차 확인 (2026-08-08 실측)** — `grep -n "지표\|리드타임"` 기준으로
[결정 대장](decision_log.md)·[공백 목록](open_gaps.md)·[불변식](invariants.md)에
생태계 지표 관련 항목은 **0건** — 이 문서와 충돌하는 기존 결정은 발견하지
못했다. 로드맵 쪽 원천은 R90(track_i_standards.md:131-140)이 유일했다.

**확인되지 않음** — ① fork 663 중 실동작 외부 구현의 수(§2.1 — dependents
조회를 하지 않았다). ② 2026-07 종결 급증(n=744)과 기여 캠페인의 인과(§3.2 —
시기 일치만 확인). ③ 종결 후 재개(reopen)율 — 이번 측정은 최종 상태만
조회했다(§4-1). ④ "접수 → 머지" 원정의의 자동 측정 가능성 — 이슈↔PR 연결의
다대다 해소 규칙이 서야 하고, 이 문서는 그 규칙을 제안하지 않는다(§2.3).
