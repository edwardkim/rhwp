# 결정 대장 — 무엇을, 왜, 그리고 지금도 유효한가

> 이 표면의 결정 대부분은 **PR 본문에만** 남아 있다. PR 은 머지되면 목록 아래로 내려가고,
> 반년 뒤에는 결론만 코드에 남고 논증은 사라진다. 그때 누군가 "왜 이렇게 했지?"라고 묻고,
> 근거를 모르는 채로 뒤집는다. **뒤집는 것 자체는 문제가 아니다. 근거를 모른 채 뒤집는
> 것이 문제다.**
>
> 그래서 결론이 아니라 **논증과 대안**을 남긴다.

관련 문서 — 규칙 자체는 [`invariants.md`](invariants.md), 층 구조는
[`layer_model.md`](layer_model.md), 로드맵 지도는 [`roadmap_atlas.md`](roadmap_atlas.md),
미해결 공백은 [`open_gaps.md`](open_gaps.md), 축 지도는 [`README.md`](README.md).
보안 축의 여섯 결정은 [`agent_security/detection_policy.md`](../agent_security/detection_policy.md)
가 원본이다. 상위 이슈 [#3880](https://github.com/edwardkim/rhwp/issues/3880).

## 0. 읽는 법

### 0-1. 항목 형식

| 칸 | 뜻 |
| --- | --- |
| **결정** | 무엇을 하기로/하지 않기로 했는가 |
| **시점** | PR·이슈 번호. 없으면 "확인되지 않음" |
| **그때의 근거** | 결정 당시 무엇을 알고 있었는가 |
| **대안** | 무엇을 안 택했는가. 여기가 비면 결정이 아니라 반사다 |
| **지금도 유효한가** | 아래 어휘로 판정 |

### 0-2. 유효성 어휘

| 판정 | 뜻 |
| --- | --- |
| **유효** | 전제가 그대로다 |
| **유효 (조건부)** | 전제는 그대로인데 감시할 조건이 붙어 있다 |
| **전제 변화** | 근거가 됐던 사실이 바뀌었다. **재검토 대상** |
| **이미 뒤집힘** | 후속 결정이 대체했다. 기록만 남긴다 |
| **미판정** | 결정하기로 해 놓고 결론이 안 났다 |

### 0-3. 근거 규약

이슈·PR 번호 / 코드 경로 / 실측 출력 중 하나를 붙인다. 못 대면 **"확인되지 않음"**.
실측은 `rhwp v0.8.2`(`<저장소>/target/release/rhwp.exe`) 2026-08-03 기준이다.

## 2. L3·L4 — 세션과 계획 실행기

### D-01 · `hwp_doc_verify` 를 신설하지 않는다

- **결정** — 세션 전용 검증 도구를 만들지 않는다
- **시점** — [#3826](https://github.com/edwardkim/rhwp/pull/3826) (판정 대상: [#3719](https://github.com/edwardkim/rhwp/issues/3719) §3-3)

**그때의 근거.** `src/mcp_serve.rs:521-528`(도구 선언)·`1387-1416`(`session_save()`)을 읽고
확인한 사실 — `hwp_doc_save{verify:true}` 는 저장 직전 만든 바이트를 **재파싱해 저장 전
세션 IR 과 대조**하는 왕복 검증이다. 여기서 두 시나리오를 갈랐다.

- **"저장 없이 검증만"** — 대조 대상이 항상 **세션 IR 자기 자신**이 되어 의미 있는 판정이
  성립하지 않는다. 자기와 자기를 비교하면 언제나 같다
- **"편집 단계마다 검증"** — L4 계획 실행기의 `assertions.verify`(1회 검증)와 **설계가
  동형**이다

**대안.** ① 신설한다 ② `hwp_doc_save{verify, dryRun}` 로 확장한다 ③ 안 만든다.
③을 택했다. ②는 "저장 없이 검증만"의 무의미함을 그대로 물려받는다.

**근거의 정직한 한계.** "별도 도구가 실제로 필요했던 요청 사례를 이슈·PR 스레드에서 찾지
못했다" — 없다고 단정하지 않고 **"확인되지 않음"** 으로 적었다. 수요가 나타나면 이 결정은
근거를 잃는다.

**지금도 유효한가 — 유효.** `capabilities --mcp` 실측 39개 도구에 `hwp_doc_verify` 는 없고,
그 부재로 인한 결함 보고도 확인되지 않았다.

### D-02 · `hwp_doc_transaction` 은 L4 가 상위 호환이다

- **결정** — 세션 트랜잭션 도구를 만들지 않고 종결한다
- **시점** — [#3826](https://github.com/edwardkim/rhwp/pull/3826)

**그때의 근거.** `src/main.rs:13210-13304`(`cmd_run_plan`)·`13341-13500`대(`run_plan_engine`)를
읽고 확인 — 이미 **"정적 선검증(실행 0) → 인메모리 원자 적용 → 사후 단언 후 단 1회 저장"**
을 구현하고 있다. 중간 실패 = 디스크 무변경이 **자연 트랜잭션**이다.

- 세션 상태를 넘나드는 트랜잭션 시나리오 — 계획서로 처음부터 표현하면 회피된다
- 다중 문서 원자성 — 계획 스키마 v2(다중 input)로 흡수될 항목이지 세션 계층 별도 구현
  사유가 아니다

**대안.** ① 세션에 `begin/commit/rollback` 을 넣는다 ② L4 로 대체한다.
①은 [`invariants.md` INV-14](invariants.md#inv-14--상위-층은-새-편집조판-로직을-만들지-않는다)
("새 로직 금지")를 정면으로 어긴다 — 같은 원자성을 두 곳에 구현하면 판정자와 실행자가 갈린다.

**지금도 유효한가 — 유효.** 실측으로 L4 의 원자성이 확인된다.

```
$ rhwp run <2단계 계획, 2단계가 없는 필드> --json
exit=2  출력 파일 미생성
{"invalid":[{"action":"fill_fields","reason":"필드 '없는필드이름' 이(가) 없거나 …","step":0}], …}
```

`tests/run_plan_contract.rs:143` `mid_plan_invalid_step_leaves_disk_unchanged` 가 고정한다.

### D-03 · `hwp_form_autopilot` 은 아직 판정하지 않았다

- **결정** — (미정) 도메인 매크로로 만들 것인가, 계획서 템플릿으로 배포할 것인가
- **시점** — [#3719](https://github.com/edwardkim/rhwp/issues/3719) §6 "판정 대기 2건" 중 남은 하나

**그때의 근거.** `hwp_form_autopilot`(조사 → 채움 → 체크 → 검증)은 계획 실행기의 `steps` +
`assertions` 로 **이미 표현 가능**하다. 그렇다면 새 도구가 아니라 **계획서 템플릿을 문서로
배포**하면 된다. 이 질문이 L6 백로그를 절반으로 줄일 수 있다.

**대안.** ① 매크로 도구 신설 ② 계획서 템플릿 문서 ③ 둘 다.

**지금도 유효한가 — 미판정.** 짝이었던 `hwp_doc_transaction`(D-02)은
[#3826](https://github.com/edwardkim/rhwp/pull/3826) 이 닫았지만 이쪽은 결론이 없다.
`capabilities --mcp` 39개에 `hwp_form_autopilot` 은 없다 — 사실상 ②로 가고 있으나
**결정으로 기록되지 않았다.** [`open_gaps.md` G-20](open_gaps.md).

### D-04 · 계획 스키마에 `dryRun` 을 일부러 넣지 않았다

- **결정** — `export-plan-schema` 가 내는 JSON Schema 에서 `dryRun` 필드를 **뺀다**
- **시점** — [#3808](https://github.com/edwardkim/rhwp/pull/3808)

**그때의 근거.** 그 시점에 `run --dry-run`([#3759]/[#3761])은 **아직 devel 에 없는 별개
PR** 이었다. 그래서 그 브랜치의 실행기는 `dryRun` 필드를 읽지 않았다.

> **스키마가 광고하면 에이전트가 `dryRun: true` 를 넣고 파일이 써진다.**
> 검사인 줄 알았는데 문서가 편집되는 것이 이 축에서 가장 나쁜 실패다.

**대안.** ① 넣는다(미래를 미리 선언) ② 뺀다 ③ 넣되 `readOnly`/주석으로 미지원을 표시.
②를 택했다. ①·③은
[`invariants.md` INV-13](invariants.md#inv-13--자기서술은-실물과-같다)("자기서술은 실물과
같다")을 어긴다 — 스키마는 **지금 이 바이너리가 하는 일**을 말해야 한다.

**지금도 유효한가 — 전제 변화. 재검토 대상.**

전제였던 "`--dry-run` 이 devel 에 없다"가 **사라졌다.** [#3761](https://github.com/edwardkim/rhwp/pull/3761)
은 CLOSED(머지)이고, 이 바이너리에서 **계획서에 실린 `dryRun` 이 실제로 존중된다.**

```
$ cat plan.json
{"planVersion":"1.0","dryRun":true,"input":"samples/field-01.hwp","output":"<임시>/dr.hwp",
 "steps":[{"action":"fill_fields","data":{"회사명":"검증사"}}]}

$ rhwp run plan.json --json
exit=0   출력 파일 생성=NO
{"dryRun":true,"invalid":[],"preview":[{"action":"fill_fields","step":0,"targets":[…]}], …}
```

`capabilities.commands[run].flags` 도 `["--json","--plan-json","--dry-run"]` 이다.

**따라서**: #3808 이 리베이스될 때 `dryRun` 을 스키마에 **추가해야 한다**(#3808 본문도
"머지 시 필드 추가 = minor"로 예고했다). 같은 이유로 dry-run `preview[]` 항목에

### D-06 · 조건은 입력 문서 기준으로 실행 전 1회만 판정한다

### D-08 · `csv-to-table` 은 셀 서식을 보존한다

- **결정** — CSV 를 표에 되돌릴 때 셀의 기존 서식을 유지한다. `edit set-cell`([#3391])과 **의도적으로 다르다**
- **시점** — [#3791](https://github.com/edwardkim/rhwp/pull/3791)

**그때의 근거.** 두 명령의 용도가 다르다.

  검게 지우면 **눈에 보이는 회귀**다
- `set-cell`/`fill-fields` — 서식이 없는 양식 채우기. 서식을 안 건드리는 것이 자연스럽다

②를 택했다. ①은 어느 쪽으로 통일하든 한쪽 용도를 망친다.

**지금도 유효한가 — 유효.** 다만 **일관성 비용**이 있다: 같은 "셀에 값을 쓴다"가 두 명령에서
다르게 동작한다. 이 비대칭은 PR 본문의 "리뷰 논점 1"로 명시됐고 매뉴얼에도 남았다.
비대칭을 문서화하지 않으면 그건 결정이 아니라 버그다.

**이 결정을 뒤집어야 할 신호**: 사용자가 `csv-to-table` 로 서식까지 초기화하려는 요청이
반복되면. 그때는 `--reset-style` 같은 옵트인이 답이지, 기본값 변경이 아니다.

- **시점** — [#3872](https://github.com/edwardkim/rhwp/pull/3872) (뒤집은 대상: [#3795](https://github.com/edwardkim/rhwp/pull/3795) 의 초기 구현)

**그때의 근거.** 선검사가 모든 워크트리에서 같은 오탐을 반복 보고했다 —
`export-capabilities-schema --json/--bare` 를 "CLI 가 거부한다"고. **실제로는 정상 동작한다.**

원인: 판정을 `stdout + stderr` 합본에서 `"알 수 없는 옵션"` 문자열로 했는데, 이 명령의
출력이 **종료 코드 사전**을 담고 있었다.

```json
"description": "사용법 오류 (인자 없음, 알 수 없는 옵션/명령)"
```

> **스키마를 출력하는 명령이 자기 스키마 안의 오류 설명에 걸려 스스로를 미구현으로
> 신고한다.** 문자열 판정이 구조 판정을 대신할 때 나오는 전형적인 오탐이다.

**대안.** ① 이 명령을 허용목록에 넣는다 ② 판정 방식을 고친다.
②. ①은 증상만 덮고 같은 부류가 또 나온다 —
[`invariants.md` INV-17](invariants.md#inv-17--오탐은-기능-실패다) 를 검사기 자신에게 적용.

**약화시키지 않았다는 증거.** red 시험 — 없는 플래그(`info --존재하지않는플래그`)를 일부러
선언하니 **여전히 잡는다**. 오탐 2건 → 0건, 플래그 **103개 전부 통과**.

**실측 재확인.** `rhwp export-capabilities-schema --bare` → exit 0, stdout 12,296B.

**지금도 유효한가 — 유효 (이 결정이 #3795 의 일부를 뒤집었다).**

### D-36 · 퍼징을 CI 에 바로 넣지 않고 코퍼스 재생 계약 스위트를 먼저 제안한다

- **결정** — `cargo-fuzz` 를 CI 에 넣는 대신, **stable `cargo test` 로 도는 코퍼스 재생 계약 스위트**를 먼저 만든다
- **시점** — [#3877](https://github.com/edwardkim/rhwp/pull/3877)

**그때의 근거 — 조사 결과가 결정을 바꿨다.**

퍼징 타깃 6개(`parse_hwp`·`parse_hwp3`·`parse_hwpx`·`parse_hml`·`parse_wmf`·
`parse_ooxml_chart`)와 시드 코퍼스 12개/269KB 가 **이미 있다.** 그런데:

```
0                          ← 2026-08-03 재현
$ ls fuzz/regressions
No such file or directory  ← fuzz/README.md:94 가 규정하는데 부재
```

`git log -- fuzz/` 커밋 3개가 전부 인프라 도입이고 **크래시 유입 0건**이다. 반대로
**퍼저가 잡을 수 있었던 손수정 결함은 커밋 로그에서 12건**이다. 퍼징이 실제로 잡은 것은
[#3311] 하나인데, 그것도 우리 `fuzz/` 가 생기기 **전에** 외부 사용자가 4분 런으로 찾은 것이다.

그리고 **퍼저는 봉투 결함을 원리상 못 본다** — 하네스가 반환값을 버린다. 에이전트 표면에서는
죽지 않는 것만으로 부족하다. 잘못된 봉투를 내면 에이전트가 잘못된 판단을 한다.

**대안.** ① nightly 를 CI 에 추가하고 `cargo fuzz` 를 돌린다 ② 코퍼스 재생 계약 스위트
③ 아무것도 안 한다.
②를 먼저. ①은 nightly 의존이 생기고 이 PC 에서는 **MSVC `dbghelp.lib` 손상으로 링크
자체가 안 된다**(`CVT1107`/`LNK1123`, 최소 크레이트로 재현). ②는 stable 에서 돌아 CI
즉시 편입이 가능하다.

**이 문서가 코드 결함을 찾았다.** [#3273] 처리 문서의 "퍼징 실행 시 자동 재현될 것으로
기대" 항목을 추적해 **미수정 패닉 2곳**을 찾아 별도 PR([#3875])로 고쳤다 —
WMF POLYLINE/POLYGON 음수 `NumberOfPoints` 의 `capacity overflow`(red→green 실증).

**지금도 유효한가 — 유효 (미착수).** 스위트는 아직 없다.
[`open_gaps.md` G-09·G-10](open_gaps.md).
