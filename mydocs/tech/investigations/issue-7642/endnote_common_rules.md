# 시험지 미주의 공통 간격·소유 규칙 조사

Issue: #7642

## 조사 범위와 관측 자료

사용자 요청에 따라 개별 시험지의 위치 보정에 앞서 공통 규칙을 조사했다.
제품 소스 `121485fb3`, 기준 devel `375aff294`에서 원본 모델과 기존 독립 한컴 Print를
읽었다. 이 조사를 위해 렌더링 코드를 바꾸거나 기준 PDF를 새로 만들지 않았다.

기존 검증 목록의 시험지 원본 50개 중 미주가 있는 입력은 30개다. 나머지 20개는 이
미주 모델의 양성 사례로 세지 않는다. 30개 모두 미주 참조가 46개이며, 같은 계열의
HWP/HWPX·간격 변형본은 번호 순서·미주 문단 텍스트·수식 스크립트·표 내부 텍스트가 같다.
이 의미 내용의 해시는 줄 좌표·스타일 ID·파일 바이트가 같다는 주장이 아니다.

| 내용 계열 | 대응 입력 수 | 미주 수 | 미주 직접 문단 수 | 대표 원본 |
| --- | ---: | ---: | ---: | --- |
| 2022년 9월 및 같은 내용의 2024 변형 | 8 | 46 | 714 | `samples/3-09월_교육_통합_2022.hwp` |
| 2023년 9월 | 2 | 46 | 505 | `samples/3-09월_교육_통합_2023.hwp` |
| 2022년 10월 | 2 | 46 | 561 | `samples/3-10월_교육_통합_2022.hwp` |
| 2022년 11월 및 같은 내용의 2024 변형 | 18 | 46 | 562 | `samples/3-11월_실전_통합_2022.hwp` |

원본·기준 PDF 경로와 SHA-256은 기존 검증 catalog 및 아래 ignored 증적에 있다.
30개 독립 PDF 모두 실제 미주 제목 46개가 원본 참조 스트림과 일치했다. 본문 문제 제목도
같은 `문N）` 표기를 사용하므로 92개 문자열을 모두 미주로 세지 않았다. 이 단일 구역·문서 끝
배치 비교군에서 본문 참조 스트림과 뒤의 실제 미주 스트림을 각각 확인했다.

## 독립 Print로 확인한 규칙

### 1. 미주는 표시 번호가 아닌 원본 참조의 소유와 순서를 따른다

번호는 `1..22, 23..30, 23..30, 23..30`이다. 표시 번호만으로 정렬·중복 제거하거나
같은 번호를 같은 미주로 취급할 수 없다. `(구역, 본문 문단, 컨트롤, 미주 내부 문단)`의
원본 소유와 참조 순서를 유지해야 한다. 질문·해설의 제목 문자열도 소유 키가 아니다.

### 2. 첫 미주 앞에서는 구분선 위·아래 여백을 함께 소비한다

본문이 같고 첫 미주의 쪽·단이 같은 변형을 비교하면 첫 미주 제목의 이동량은
`구분선 위 여백 변화 + 구분선 아래 여백 변화`와 일치한다.
30개 입력의 최대 잔차는 96dpi에서 0.06668 CSS px다. 선이 없는 20/20/20 변형도
여백을 0으로 취급할 근거가 없다. 선의 가시성과 여백의 흐름 점유는 별개다.

`FootnoteShape::separator_above_margin_hu` / `separator_below_margin_hu`가 원본 슬롯을
해석하고 `NoteSeparatorGeometry::advance`가 위·아래 여백의 합을 공급한다.
이 조사에서 선 굵기를 흐름에 더해야 한다는 새 근거는 얻지 않았다.

### 3. 같은 단의 완성 미주 경계는 실제 미주 사이 간격을 한 번 소비한다

같은 내용에서 인접한 두 미주 제목이 양쪽 PDF 모두 같은 쪽·단에 남는 경계를 비교했다.
제목 사이 거리의 변화는 원본 `미주 사이` 값의 변화와 일치한다. 변경 없는 대조군을
포함한 관측은 667개 경계이며, **실제 미주 사이 값이 달라지는 비교는 15개 PDF 쌍의
292개 경계**다. 후자의 최대 잔차는 0.22665 CSS px다. 평균 점수로 판정한 결과가 아니다.

예를 들어 11월 7mm → 0 변형의 같은 단 경계는 약 26.40~26.56 CSS px 줄어들며,
원본 1984 HWPUNIT의 96dpi 환산값은 26.45333 CSS px다. 20mm·8mm 변형도 같은
원본 값의 차이로 설명된다. **7mm를 모든 문서의 별도 기본 상수로 가정할 필요는 없다.**
이미 저장 줄이나 실제 흐름 끝에 같은 간격이 포함됐는지 확인한 후 한 번만 소비해야 한다.
이 관측만으로 저장 좌표에서 언제나 간격 전체를 더하거나 언제나 7mm를 빼라는 결론은
내리지 않는다. 기존 예약량·소유 경계를 확인하지 않은 일괄 교체는 이중 가산을 만들 수 있다.

### 4. 의미 내용이 같아도 저장 줄의 되감김은 다를 수 있다

11월 0/0/0 HWP와 HWPX는 의미 내용이 같지만 미주 내부에 vpos 되감김이 있는 문단 수가
각각 4개와 5개다. 따라서 모든 되감김을 내용 삭제·중복·새 미주 시작으로 해석할 수 없다.
단 전환의 저장 원점과 같은 미주 내부 2차원 배치를 구분해야 한다.
`row_projection::project_equation_rows`에도 저장 HWPX 단 경계와 실제 수식 줄 프레임을
구분하는 경로가 있다. 정상 저장 원본과 재조판의 계약을 따로 검증해야 한다.

### 5. 저장 vpos는 미주별 로컬 원점이다

30개 입력의 미주 1,380개 모두 첫 저장 줄의 vpos가 0이다. 서로 다른 미주의
`다음 첫 vpos - 앞 마지막 vpos`는 물리 간격이 아니다. 먼저 미주 소유별 로컬 줄을
실제 단의 흐름 원점에 배치한 뒤 점유 끝을 비교해야 한다.

11월 0/7/20mm 세 원본에서는 46개 중 21개 미주의 **내부 모든 저장 줄 메트릭이
세 파일에서 그대로 같은데도** 독립 Print의 미주 사이 거리는 UI 간격만큼 변한다.
따라서 미주 내부 줄 좌표만 읽어 미주 사이 간격까지 포함됐다고 일반화할 수 없다.
준비 단계가 더한 offset·trailing과 실제 소비된 예약량을 추적해야 한다.

## 공통 결과의 실제 소비 경로와 재검토 지점

| 단계 | 현재 코드 | 확인할 계약 |
| --- | --- | --- |
| 원본 속성 해석 | `src/model/footnote.rs` | 위·아래·미주 사이 원본 HWPUNIT의 의미 보존 |
| 구분선 점유 | `src/renderer/note_separator.rs` | 가시성과 분리한 공통 위·아래 여백 |
| 미주 준비 | `typeset/notes/endnotes/prepare.rs` | 앞 tail에 이미 포함된 간격과 새 예약량 |
| fit·이월 | `typeset/notes/endnotes/paragraph/reflow_fit.rs` 등 | 앞 미주의 마지막 소유 유닛과 실제 점유 끝을 같은 조건으로 소비 |
| 실제 배치 | `src/renderer/layout.rs`, `height_cursor.rs` | helper 뒤의 원점 덮어쓰기·제한·추가 간격까지 확인 |
| 공통 경계 helper | `src/renderer/endnote_spacing.rs` | 완성 미주 경계, 실제 줄·내용 점유, 간격의 한 번 소비 |

`origin_after_gap`, `occupied_end`, `starts_note_after_complete_tail`은 이미 존재한다.
이를 새로 이름만 바꾸는 대신 fit과 실제 배치의 모든 적용 분기를 대조해야 한다.
`profile.rs`의 1984HU 기준 초과분, `metrics.rs`의 80/40/100px 등의 임계값이 실제 저장 예약량과
독립적인 줄·개체 점유로 설명되는지 조사한다. 값이 크다는 이유만으로 원본 줄을 버리거나
clamp해 겹침만 숨기지 않는다. 현행 값의 역할을 확인하지 않고 일괄 삭제하지도 않는다.

## 아직 입증하지 않은 범위와 다음 실행

- 위 간격 변화 검증은 같은 단의 완성 미주 경계와 문서 끝 첫 미주에 한정된다.
  새 단·새 쪽에서 시작하는 미주, 앞 미주의 이어받기 꼬리, 표 분할·부동 그림의 점유는 별도다.
- 미주 전체 높이를 단순 `max(vpos + 높이) - min(vpos)`로 계산하면 충분하다는 근거는 없다.
  빈 줄, 음수 줄간격, 같은 줄의 여러 개체, 잘린 조각의 물리 높이를 포함한 실제 공통 결과가 필요하다.
- 내용이 같은 변형본에서 동일한 원본 미주의 시작·끝 컷, 예약량, 실제 원점을 추적한다.
  `원래 높이만 fit하는 예산 → 분할 → 다음 단의 이어받기 → 마지막 유닛 → 후속 미주` 경계를 우선한다.
- HWP/HWPX 쌍과 0/7/8/20mm 변형을 한 묶음의 대조군으로 실행하며, 공통 규칙으로 설명한
  뒤에만 제품을 수정한다. 새 회귀는 전쪽 Native/fresh WASM 90%·직접 판독 후 추가한다.
- 이 조사는 전체 시험지 시각 검증 완료, 최신 devel 대비 무회귀 또는 PR 제출 가능 판정이 아니다.

## 실제 fit·paint 연결의 추가 관측

1629는 제품을 바꾸지 않고 기본 B 경로의 진단 로그만 활성화해 11월 0/7/8/20mm
네 입력을 실제 Native Print로 출력했다. CLI가 초기 조판 뒤 compat를 설정해 다시 조판하는
경우가 있어 최종 세대의 query만 현재 paint와 연결했다. 이전 세대의 좌표를 섞지 않았다.

| 미주 사이 값 | 최종 미주 시작 query의 고유 소유 수 | 선택 10쪽의 실제 미주 제목 수 | Native 제목 y와 Print 최대 차이 |
| --- | ---: | ---: | ---: |
| 7mm | 46 | 10 | 0.07367 CSS px |
| 0mm | 46 | 11 | 0.08632 CSS px |
| 20mm | 43 | 8 | 0.07369 CSS px |
| 8mm | 45 | 9 | 0.14633 CSS px |

관측한 query는 `max(현재 flow 원점, 앞 점유 끝 + 간격)`과 최대 0.001 CSS px 차이다.
이는 로그가 소수 셋째 자리로 출력되는 정밀도 안의 차이다. 같은 원본 소유의 실제 제목을
단 원점으로 환산해 query와 연결한 차이는 최대 0.053 CSS px다. render tree debug JSON은
상자 좌표를 소수 첫째 자리로 출력한다. 이 결과로 모든 소비 분기를 검증했다고 쓰지 않는다.

20mm의 원본 미주 순서 9/24/39번과 8mm의 46번은 이 query를 통과하지 않았다.
번호 23을 표시하는 원본 39번째 미주도 별도 소유로 추적했다. 실제 호출은
`typeset/notes/endnotes/paragraph.rs`의 제목 꼬리 overflow 판정 뒤 단/쪽 전환이며,
다음 항목은 해당 원본 미주의 내부 문단 0번으로 넘어간다. helper가 같다는 추정으로
이 분기를 검증 완료 처리하지 않았다.

이 네 경계의 독립 Print는 모두 새 쪽 왼쪽 단의 맨 위에서 제목을 시작한다. 20mm 변형의
11/15/20쪽은 현재 전범위 Native의 실제 render tree에서도 해당 소유의 제목 y와 단의
상단이 모두 90.7 CSS px이고 Print는 90.65370 CSS px다. **이 새 쪽 시작에서는 같은 단의
미주 사이 20mm를 다시 앞에 예약하지 않는다.** 8mm 변형의 21쪽 Print도 같은 상단이지만
후속 전범위 Native 대조에서도 원본 소유 `(0,426,0)`의 제목은 가상 문단 976번,
21쪽 왼쪽 단 상단 90.7 CSS px다. Print와의 차이는 0.04630 CSS px이며 8mm를
새 쪽 시작에 다시 예약하지 않는다.

따라서 같은 단의 완성 미주 경계와 새 단·쪽으로 넘긴 미주의 시작을 별도 조건으로 확인해야
한다. 이어받는 미주 조각의 점유·마지막 유닛·다음 내용까지 이 결과로 대신하지 않는다.
추가 증거는 `stage1629-endnote-flow-traces/fit-paint-head-audit.json`,
`stage1629-new-column-actual-head-audit.json`, 각 변형의 실제 실행 명령·최종 pageCount·
`flow-debug.log`에 있다. 새 미주 조판 구현이나 기대값 변경은 아직 하지 않았다.

### 파싱 전 원본 레코드 확인

`stage1631-raw-note-coordinate-audit.py`로 parser를 거치지 않고 HWP 17개의 OLE
`BodyText/Section*` 레코드와 HWPX 13개의 section XML을 직접 읽었다. 원본 30개·미주
1,380개의 첫 저장 vpos가 모두 0이고 미주 내부 모든 줄 위치도 앞선 parser IR과 같았다.
이 비교군의 로컬 원점·되감김 관측이 parser 정규화 때문에 만들어진 값은 아니다.
`stage1631-raw-note-coordinate-audit.json`에 입력 SHA-256·형식별 건수·사다리 비교를 보존했다.


## 전쪽 Native의 미주 제목 소유·흐름 전수 대조

1636은 앞선 원시 HWP/HWPX에서 본문 직접 문단 수를 따로 읽어 미주 내부 문단의
가상 인덱스와 원본 소유를 연결했다. 30개·미주 제목 1,380개 모두 한 번 표시되고,
원본 참조 순서·독립 Print의 쪽·단과 일치했다. 이는 제목 소유에 대한 실행 증거이며
미주 내부의 모든 수식·글자·줄이 정확하다는 의미는 아니다.

직접 제목 y 대조의 최대 차이는 4.39370 CSS px다. 9월 2022 및 같은 내용의 변형본에서
같은 원본 미주에 반복된다. 1638의 16/20/21쪽 Native 실루엣은 모두 90% 이상이지만,
