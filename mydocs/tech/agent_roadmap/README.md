# 에이전트-네이티브 로드맵 R1~R100 — 상세 문서 지도

이슈 **#3907** 이 조망(스냅샷)이고, **이 문서 세트가 단계별 상세의 canonical** 이다.
진행 갱신은 "이슈 코멘트 + 이 세트의 해당 트랙 문서 PR" 을 짝으로 한다 — 둘 중
하나만 고치면 조망과 상세가 갈라진다.

목표 문장 하나로 요약하면: **"새로 온 에이전트가 매뉴얼 없이 30분 안에 첫 유효
기여를 만들고, 도구의 일상 정비를 에이전트가 맡는 문서 엔진"** — 그 판정 실험이
R100 이다.

## 운영 규칙 (이 지도의 본체)

1. **착수는 단계 번호가 아니라 근거가 결정한다.** `[가설]` 단계는 각 문서에 적힌
   **착수 게이트**(필요한 실측·판단)를 통과하기 전에 구현하지 않는다.
2. **완료 표기는 머지 링크와 함께만** 한다 (#3608 규칙 승계).
3. **열린 PR 캡 10 내외 준수** — 이 지도는 큐를 늘리는 면허가 아니다.
4. 단계 번호는 **의존성 순서**지 일정이 아니다. 트랙 간 병행은 정상이다.
5. 상세의 상위 원천(이슈·구현 PR·기존 설계 문서)이 이 세트와 다르면 **그쪽이
   이긴다** — 이 세트는 조망을 상세화한 것이지 원천을 대체하지 않는다.

## 증거 등급

| 태그 | 뜻 | 착수 조건 |
|---|---|---|
| `[완료]` | 머지된 실적 — 링크 필수 | (없음 — 회귀 가드만 유지) |
| `[실측]` | 측정·재현이 존재 | 설계 확정 후 바로 |
| `[문서]` | 설계 문서가 존재 | 판단 지점 답 후 |
| `[이슈]` | 업스트림에서 추적 중 | 이슈의 다음 행동 |
| `[가설]` | 근거 확보가 선행 조건 | **착수 게이트 통과 전 구현 금지** |

집계 (2026-08-04, 단계 제목 태그 기준 전수): **완료 28 · 실측 7 · 문서 7 ·
이슈 7 · 가설 51 = 100.** 조망 이슈 #3907 의 개략 수치(완료 35 / 추적 15 /
가설 50)와 다른 이유는, 이 세트를 쓰며 각 단계를 저장소 실물과 대조해 등급을
더 엄격히 매겼기 때문이다 — 예: 파이썬 예제는 실재 9편이라 R69 를 `[완료]` 가
아니라 `[실측]` 로, R61(바인딩 표류)·R76(문서 지능 서버)은 머지 실적이 아니라
설계 문서라 `[문서]` 로 내렸다. **이 세트가 canonical 이므로 이 숫자가 맞다.**
가설이 절반인 것이 정상이다 — 다 채워져 있으면 지도가 아니라 소설이다.

## 단계 서술 형식 (전 트랙 공통)

각 단계는 여섯 항목으로 적는다. 항목이 비면 비었다고 적는다 — 빈 칸을 문장으로
채우지 않는다.

- **한 줄** — 무엇이 달라지는가.
- **지금** — 현재 상태와 증거(실측·머지·이슈 링크).
- **설계** — 어떻게 만드는가(완료 단계는 "무엇이 보장되는가"로 대체).
- **착수 게이트** — 시작 전에 확보해야 하는 근거·판단(가설 단계의 핵심).
- **DoD** — 관측 가능한 완료 판정(테스트·수치·가드).
- **의존** — 선행 단계.

## 층 모델과의 관계

#3880 의 4층(L1 표면 / L2 신뢰 / L3 도달 / L4 표준)이 세로축이고, 이 로드맵의
트랙이 가로축이다: A→L1, B·C→L2, D→L3, I→L4, E·F·G·H 는 층을 관통하는 능력
기둥, J 는 전 층이 맞물려야 성립하는 지붕이다. 층 모델 자체의 canonical 은
#3880(및 그 문서 축)이다.

## 이 세트가 하지 않는 것

- 일정 약속 — 어디에도 날짜가 없다. 순서는 의존성이다.
- 원천 서술의 복제 — 완료 단계의 구현 상세는 해당 PR·이슈가 원천이다.
- 은닉·압축 통신, 잠금 데몬, 에이전트 간 전송 프로토콜 — 트랙 C 문서의
  "비목표" 절이 이유를 적는다.
