# 10년 선행 축 — 감사 표준: 규제가 도착하는 날의 참조 구현

- 좌표: 조망 [#3907](https://github.com/edwardkim/rhwp/issues/3907) →
  9년 정산([#4452](https://github.com/edwardkim/rhwp/issues/4452)) → **이 문서
  (사다리의 마지막 단)**
- 이슈: [#4453](https://github.com/edwardkim/rhwp/issues/4453)
- 등급: **[지평]** — 코드 0줄.
- 착수 조건: 9년 축 머지 **또는** 규제 신호 실측(에이전트 노동 감사를 요구하는
  규제·조달 요건의 등장) — 두 트리거 중 먼저 오는 것.

## 1. 질문 — 소프트웨어가 걸어간 길을 AI 가 걷는다면

소프트웨어 공급망의 경로는 기록돼 있다: 대형 사고 → 업계 자율 표준(SBOM) →
정부 조달 요건 → 사실상의 의무화. AI 구성요소 표기(AIBOM)와 투명성 규제가
같은 궤도의 초입에 있다. 이 경로가 "에이전트가 수행한 노동"까지 연장된다면 —
"이 문서/제출물/성과물은 어떤 에이전트가 어떤 과정으로 만들었고, 그것을
증명할 수 있는가" — 그날 요구되는 것은 새 이론이 아니라 **감사 보고의 표준
형식과 그것을 채울 수 있는 참조 구현**이다.

1~9년 축이 완주되면 rhwp 는 그 참조 구현의 실체를 갖는다: 영수증(사실)·
감사(재현율)·계보(역사)·서명(귀속)·앵커(시점)·게이트(판정)·번들(교환)·
공개(비밀 양립)·원장(정산). 10년 축은 이것을 **감사인이 읽는 언어**로 묶는다.

한 줄 정의: **감사 표준 축은 "검증 가능한 에이전트 노동"의 보고 형식·리콜
절차·적합성 등급을 문서 표준으로 고정하고, rhwp 를 그 자가진단 도구로 만든다.**

## 2. 설계

### 2.1 감사 보고 표준 — 기계 스키마 + 인간 서식의 쌍

`audit-report.schema.json` (기계) 와 보고 서식(인간)이 같은 내용을 두 표현으로:

```json
{
  "schemaVersion": "1.0",
  "kind": "agentLaborAuditReport",
  "scope": { "root": "감사 대상 폴더/번들", "period": ["…", "…"], "capsules": 412 },
  "reproduction": { "attempted": 412, "reproduced": 409, "rate": 0.9927,
                    "failures": [ { "capsule": "…", "reason": "…" } ] },
  "lineage": { "graphs": 37, "valid": 36, "broken": [ { "head": "…", "brokenAt": "…" } ] },
  "attribution": { "signed": 400, "unsigned": 12, "revokedKeyUses": 0 },
  "anchoring": { "anchored": 412, "checkpointsVerified": 4 },
  "gate": { "policy": "…해시…", "passed": 405, "denied": 7 },
  "toolVersions": { "rhwp": ["0.8.2"], "mixed": false },
  "auditor": { "keyId": "…", "reportSignature": "sig.json 참조" }
}
```

- 모든 수치는 **재계산 가능**해야 한다 — 보고서의 각 절은 그것을 산출한 명령
  (audit/lineage/gate/anchor verify)의 봉투에서 기계적으로 합산되고, 보고서
  자체가 4년 축으로 서명된다. "감사 보고서를 감사할 수 있다"가 표준의 요건이다.
- `rhwp audit-report <대상> --policy … -o report.json` 이 스키마 준수 보고를
  생성한다 — 수기 작성 보고서의 스키마 검증도 같은 명령이 한다.

### 2.2 오염 리콜 절차 — recall-scope

감사의 실전 수요는 사후 리콜이다: "부모 P 가 오염(잘못된 원본·침해 데이터·
훼손)으로 판명됐다. 무엇을 회수해야 하나."

```text
rhwp recall-scope --contaminated <캡슐|해시> --among <폴더|번들|원장> --json
  → { "contaminated": "…", "affected": [ { "capsule": "…", "path": ["P","…","X"] } ],
      "unaffected": 371, "claims": [ "정산 원장에서 영향 청구 2건" ] }
```

- 계보 그래프에서 오염 노드의 **후손 폐쇄집합**을 계산한다 — 합류(DAG) 확장이
  머지돼 있으면 material 경로 포함 여부를 role 별로 보고한다.
- 9년 원장이 있으면 영향 캡슐의 정산 청구까지 짚는다 — 리콜의 회계 연결.
- 표준 문서에는 리콜 보고 서식(무엇이·왜·어디까지·조치)을 함께 정의한다.

### 2.3 적합성 등급 — L1~L5

조직이 "우리는 어디까지 하는가"를 자가진단하는 사다리:

| 등급 | 요건 (누적) | 대응 축 |
|---|---|---|
| L1 | 산출물마다 영수증 발급 | 1년 |
| L2 | 주기적 전수 감사(재현율 보고) + 계보 기록 | 2·3년 |
| L3 | 서명 귀속 + 앵커 로그 운영 | 4·5년 |
| L4 | 정책 게이트 상시 배치 + 교환은 번들로만 | 6·7년 |
| L5 | 선택적 공개 운영 + 정산 원장 | 8·9년 |

`rhwp conformance <대상> --level L3 --json` — 등급 요건을 정책(6년 축 형식)으로
표현해 자가진단을 게이트 재사용으로 구현한다(새 판정기 발명 없음).

### 2.4 용어 사전

표준의 절반은 낱말이다. 영수증(receipt)·캡슐(workCapsule)·계보(lineage)·
앵커(anchor)·게이트(gate)·번들(bundle)·개봉(opening)·원장(ledger) — 각 용어의
정의·불변식·해당 봉투 필드를 한 표로 고정한 사전을 표준 문서에 포함한다.
(이 저장소의 지식지도 사전이 원형이다 — 내부 문서의 외부 표준화.)

## 3. 채택 전략 — 정직하게

표준은 선언이 아니라 **채택**이다. 단독 선언의 한계를 인정하는 것에서 시작한다:

1. **참조 구현 우선**: 문서보다 "돌아가는 자가진단"이 설득한다 — conformance
   명령이 표준 문서보다 먼저 쓸모를 증명해야 한다.
2. **기존 흐름에 접붙임**: SBOM/AIBOM 생태계의 형식(SPDX·CycloneDX 계열)에
   에이전트 노동 필드를 **확장 제안**하는 경로가 독자 표준보다 채택 확률이
   높다 — 이 판단은 착수 시점의 생태계 실측으로 재검증한다.
3. **국내 공공 조달 접점**: HWP 가 강한 곳(공공)이 에이전트 노동 감사 요구의
   초기 지점일 가능성 — rhwp 의 도메인 이점이 표준 채택의 지렛대가 되는
   시나리오. 전망이지 실측이 아님을 명시한다.

## 4. 단계와 DoD

| 단계 | 내용 | DoD |
|---|---|---|
| Y10-M1 | 보고 스키마+audit-report 생성 | 1~6년 축 봉투 합산과 보고 수치의 기계 대사(불일치 0) + 보고 서명 왕복 |
| Y10-M2 | recall-scope | 오염 픽스처(체인·DAG 각 1)에서 후손 폐쇄집합 정확 + 미영향 분리 |
| Y10-M3 | conformance L1~L5 | 등급별 통과/미달 픽스처 + 게이트 재사용 구현(신규 판정기 0) |
| Y10-M4 | 표준 문서 초안 공개 | 용어 사전+서식+리콜 절차 통합본 — 외부 의견 수렴 개시 |

## 5. 정직 조항

- 이 축의 트리거(규제 도착)는 통제 밖이다. 착수 조건에 "규제 신호 실측"을
  넣은 이유이며, 신호 없이 앞당겨 구현하는 것은 이 로드맵의 "착수는 근거가
  결정" 규약 위반이다.
- 채택 전략 3항은 전부 가설이다 — 각각 실측(생태계 조사·조달 요건 조사) 없이
  사실로 승격하지 않는다.
- 사다리는 여기서 끝나지만 표준은 시작점이다 — L6 이후(연합 공공 로그·ZK
  재현)는 이 문서가 아니라 그날의 생태계가 정한다.
