# 트랙 I — 표준·생태계 (R81~R90)

**질문**: rhwp 의 계약이 표준이 되는가 — L4.

L4 는 rhwp 의 계약이 내부 규약을 넘어 외부 구현·에이전트가 의존하는 대상이 되는
층이다. 표준은 선언으로 되지 않는다 — 공개된 계약(R81·R82), 그 계약을 외부가
재사용할 표면(R83·R85), 실제로 쓴 사례(R86)가 쌓인 뒤에야 표준화 제안(R88)이
빈말을 면한다. R81·R82 가 머지된 공개 계약이고, 나머지는 그 위에 생태계를 얹는
순서다 — R88 이 이 트랙에서 가장 먼 단계인 것이 정직한 모양이다.

## R81 planSchema 공개 계약 `[완료]`

- **한 줄** — `run` 의 계획(plan) 스키마를 공개 계약으로 고정하고 진화 규약을
  못박는다.
- **지금** — #3808. JSON Schema draft 2020-12 로 공개하고, 진화 규약을
  minor(필드 추가 — 하위호환)/major(의미 변경·삭제 — 파괴적)로 명문화했다.
- **설계(보장)** — planSchema 가 공개 스키마로 존재하고, 소비자가 버전으로
  호환을 기계 판정한다. 필드 추가는 minor, 의미 변경·삭제는 major 라는 규약이
  스키마 진화의 경계를 고정한다.
- **DoD** — 달성: planSchema 가 공개 계약으로 존재하고 minor/major 진화 규약이
  문서화된다.
- **의존** — 트랙 A(봉투 계약), 트랙 D R32(매니페스트에 planSchema 접합).

## R82 irSchemaVersion 규약 `[완료]`

- **한 줄** — IR(중간표현) 봉투에 버전을 달아 소비자가 호환을 기계로 판정한다.
- **지금** — #3691. IR 버저닝을 도입해 `irSchemaVersion` 이 봉투에 실린다.
- **설계(보장)** — IR 봉투가 자기 스키마 버전을 실어, 소비자가 파서·바인딩 판올림
  없이도 버전만으로 호환 여부를 가른다.
- **DoD** — 달성: IR 봉투에 `irSchemaVersion` 이 실리고, 소비자가 버전으로 호환을
  판정할 수 있다.
- **의존** — 트랙 A(봉투 계약).

## R83 스키마 레지스트리 단일 출처 `[가설]`

- **한 줄** — plan·ir·capabilities 의 모든 `*SchemaVersion` 을 한 레지스트리에서
  대사한다.
- **지금** — 셋(plan·ir·capabilities)이 **각자 상수**로 흩어져 있다. 한 곳에서
  대사하는 레지스트리가 없어, 버전 정책을 바꾸면 세 자리를 따로 고쳐야 한다.
- **설계** — 모든 `*SchemaVersion` 을 단일 레지스트리에서 선언·파생시키고, 흩어진
  상수를 금지하는 드리프트 가드를 붙인다. 버전 정책(트랙 G R67)과 한 몸으로
  설계한다 — 정책이 규칙이면 레지스트리는 그 규칙의 단일 적용점이다.
- **착수 게이트** — 트랙 G R67(버전 정책)과 함께 — 지금 셋이 각자 상수라, 한 곳에서
  관리하는 레지스트리를 설계한다.
- **DoD** — plan·ir·capabilities 스키마 버전이 단일 레지스트리에서 파생되고,
  흩어진 상수를 금지하는 가드가 CI 에서 돈다.
- **의존** — 트랙 G R67, R81, R82.

## R84 HWP/OWPML 정합 관찰 노트 공개 `[실측]`

- **한 줄** — HWP 와 OWPML(HWPX) 간 정합·비대칭을 관찰 노트로 공개한다.
- **지금** — [`mydocs/tech/owpml_conformance_observations.md`](../owpml_conformance_observations.md)
  로 착지(PR #4293, 리뷰 대기). 파서 기여 코드 주석에서 16건을 추출해 file:line·
  수정 PR/이슈로 근거를 남겼다. `mydocs/tech/README.md` 진입점 표에도 등재.
- **설계(달성)** — **관찰 기반 서술**로 적었다 — 스펙 단정이 아니라 한컴 동작 의존을
  각 항목에 명시하고, 문서 서두에 "관찰 기록이지 권위 스펙이 아니다" 경고를 둔다.
  `hwp_spec_errata.md`와 겹치는 항목(§31·§33·§34)은 원본을 밝히고 발췌로만
  재수록해 중복 저작을 피했다.
- **착수 게이트** — (없음 — 충족 확인 후 착수. 관찰 축적이 실제로 16건 존재함을
  코드 grep 으로 먼저 검증했다.)
- **DoD** — 관찰 노트 공개(달성, PR #4293 머지 대기) · 각 항목 "관찰" 표지(달성) ·
  한컴 동작 의존 주의(달성). `[완료]` 승급은 머지 후.
- **의존** — 파서 기여의 비대칭 사례 축적(로드맵 밖 원천) — 충족.

## R85 적합성 스위트 외부 공개 `[가설]`

- **한 줄** — 서드파티 HWP 구현이 자기 정합성을 검증하도록 적합성 스위트를 외부에
  공개한다.
- **지금** — 적합성 검사는 본체 내부용이라 외부 구현이 재사용할 표면이 없다.
  트랙 G R68(바인딩 적합성)이 본체 계약을 재사용 가능하게 만드는 것이 선행이다.
- **설계** — R68 이 바인딩용으로 재사용 가능하게 만든 본체 계약을, 외부 HWP 구현이
  자기 검증에 쓸 수 있는 스위트로 확장·공개한다.
- **착수 게이트** — 트랙 G R68(바인딩 적합성)이 본체 계약을 재사용 가능하게 만든
  뒤 그것을 외부에.
- **DoD** — 외부 구현이 스위트를 돌려 자기 정합성을 판정할 수 있고, 통과 기준이
  문서화된다.
- **의존** — 트랙 G R68.

## R86 외부 에이전트 온보딩 사례집 `[가설]`

- **한 줄** — 외부 에이전트가 rhwp 를 처음 쓴 실사용 리포트를 사례집으로 모은다.
- **지금** — 외부 사용자 리포트가 없다 — 배포·등재 전이라 외부 사용자 자체가 아직
  없다. 사례는 사용자가 생긴 뒤에야 생긴다.
- **설계** — 실사용 리포트(온보딩 성공·실패·마찰점)를 수집해 사례집으로 엮고,
  마찰점을 이슈로 환류한다.
- **착수 게이트** — 트랙 D R38·R39(배포·등재)로 외부 사용자 존재.
- **DoD** — 외부 온보딩 사례가 N건 정리되고, 각 사례의 마찰점이 이슈로 환류된다.
- **의존** — 트랙 D R38·R39.

## R87 문서 계약 국·영 이중화 `[가설]`

- **한 줄** — 계약 문서(스키마·capabilities·레시피)를 한글·영어 이중으로 유지한다.
- **지금** — 전 문서 한글은 **의도**다 — 대상 사용자가 한국어권이다. 영어권 유입의
  실측 근거가 없어, 지금 이중화는 도달 없는 유지비만 늘린다.
- **설계** — 도달 근거가 서면, 계약 문서를 영어로 이중화하고 두 판본의 정합을
  드리프트 가드로 검사한다.
- **착수 게이트** — 도달 근거(영어권 사용자 유입 실측) 선행. 지금 전 문서 한글은
  의도다.
- **DoD** — 계약 문서가 국·영 이중으로 유지되고, 두 판본 정합을 검사하는 가드가
  CI 에서 돈다.
- **의존** — 트랙 D R38·R39(외부 도달), R86(유입 근거의 원천).

## R88 표준화 제안 초안 `[가설]`

- **한 줄** — 검증된 rhwp 계약을 외부 표준화 제안 초안으로 정리한다 — 가장 먼
  단계.
- **지금** — #3608 M30. 커뮤니티 합의도, 외부 구현도, 사례집도 아직 없다 — 이 셋이
  없는 표준화 제안은 자칭에 불과하다.
- **설계** — 사례집(R86)과 외부 구현(R85)이 쌓여 계약이 실전에서 검증된 뒤, 그
  계약을 표준화 제안 초안으로 옮기고 커뮤니티 리뷰 경로를 연다.
- **착수 게이트** — 커뮤니티 합의(사례집 R86·외부 구현 R85 선행). 가장 먼 단계.
- **DoD** — 표준화 제안 초안이 존재하고, 커뮤니티 리뷰 경로가 열린다.
- **의존** — R85, R86.

## R89 AGENTS.md 진화판 `[가설]`

- **한 줄** — AGENTS.md 를 협업(트랙 C) 규약까지 담은 진화판으로 갱신한다.
- **지금** — 현재 AGENTS.md 는 단일 에이전트 관점이다. 협업 canonical(트랙 C R30)이
  머지되기 전에는 담을 규약 자체가 확정되지 않았다.
- **설계** — 협업 규약(잠금·assignee·무충돌 등)을 AGENTS.md 진화판에 편입하고,
  트랙 C canonical 과 단일 출처로 연결한다.
- **착수 게이트** — 트랙 C R30(협업 canonical) 머지.
- **DoD** — AGENTS.md 가 협업 규약을 담고, 트랙 C canonical 과 단일 출처로 이어져
  둘이 갈라지지 않는다.
- **의존** — 트랙 C R30.

## R90 생태계 지표 정의 `[가설]`

- **한 줄** — 채택·호출·이슈 리드타임 등 생태계 건강 지표를 정의한다.
- **지금** — 무엇을 성공으로 볼지 합의가 없다 — 지표가 미정의라 성장·정체를 말할
  기준이 없다.
- **설계** — 채택(외부 구현·에이전트 수), 호출(도구 사용량 — R80 옵트인 통계),
  이슈 리드타임(접수 → 머지)을 지표 후보로 놓고, 측정 대상 합의를 먼저 만든다.
- **착수 게이트** — 측정 대상 합의(무엇을 성공으로 볼지).
- **DoD** — 지표 정의가 문서화되고, 최소 1개 지표가 실제로 측정된다.
- **의존** — R80(호출 지표), 트랙 D(채택 측정의 원천).
