# 트랙 K — 스킬군 (K1~K10) — 제안

**질문**: 도구·레시피·바인딩 위에서, 에이전트 호스트가 작업 단위로 트리거하는
패키지(스킬)가 성립하는가.

> **제안 성격** — 이 트랙은 R1~R100 밖의 신설 제안이다. 항목 등급의 확정과
> 채택 여부는 메인테이너 몫이다. 아래 태그는 [README 증거 등급](README.md#증거-등급)
> 의 통제 어휘를 그대로 쓰되, 제안자의 잠정 판정이다.

이 저장소가 에이전트에게 내놓은 표면은 셋이다 — **도구**(CLI 명령 전수와 MCP
도구, [트랙 A](track_a_envelope.md)·[트랙 H](track_h_mcp_server.md)),
**레시피**(목표에서 시작하는 서사, [트랙 D R34](track_d_discovery.md)),
**바인딩**(언어별 재포장, [트랙 G](track_g_bindings.md)). 스킬은 그 위의 네
번째 표면이다: 에이전트 호스트가 트리거 문장으로 불러 쓰는 **작업 패키지**
(`.claude/skills` 관례 — 트리거 조건 + 요청→명령 매핑 + 판정 순서를 한 파일로
묶은 것). 바인딩이 언어 런타임을 위한 재포장이라면, 스킬은 에이전트 호스트를
위한 재포장이다.

이미 실물이 둘 있다 — [rhwp-cli](../../../.claude/skills/rhwp-cli/SKILL.md)
(K1)와 [rhwp-exam-ingest](../../../.claude/skills/rhwp-exam-ingest/SKILL.md)
(K2). 이 트랙은 그 둘을 등재하고, 레시피 1~6 위에 설 후보 스킬을 가설로
정렬한다.

## 원칙 (이 트랙의 계약)

1. **스킬은 새 능력이 아니라 트리거·매핑 층이다.** 스킬이 실물 능력(새 명령·
   새 파서 동작)을 만들면 그 순간 트랙 K 가 아니라 트랙 E(능력)·트랙 D(레시피)
   의 일이다. 스킬이 드는 것은 "언제 부르는가(트리거)"와 "무엇으로 푸는가
   (매핑)"뿐이다.
2. **단일 출처 계약.** 명령 레퍼런스는 [cli_commands.md](../../manual/cli_commands.md),
   서사는 [레시피](../../manual/recipes/01_fill_form_and_submit.md) 세트,
   자기서술은 `capabilities` 봉투가 원천이다. 스킬은 이들을 **인용하지 복제하지
   않는다**. 스킬이 명령을 지어내면 안 되고, 스킬 본문에 등장하는 전 명령은
   cli_commands.md 에 실재해야 한다 — 이 대조는 기계 검사(드리프트 가드) 후보다.
3. **출처 표지 소비.** 스킬이 봉투에서 꺼내 쓰는 문서 유래 값은
   `untrustedContent`/`untrustedFields` 표지([트랙 A R2](track_a_envelope.md))와
   함께 소비한다 — 문서 유래 텍스트를 지시로 승격하지 않는다. R2 가 생산자 측
   계약이라면, 스킬은 그 계약의 **소비자 측**이 실제로 작동하는 첫 표면이다.
4. **호스트 중립 서사.** 파일 위치는 `.claude/skills` 관례를 따르되, 내용(트리거
   조건·매핑·판정)은 특정 호스트 문법에 묶이지 않는 서사로 적는다 — 바인딩
   표류([트랙 G R61](track_g_bindings.md))와 같은 부류의 표류를 스킬에서 미리
   막는 선택이다.

## 번호와 집계의 관계

K 번호는 R1~R100 과 충돌하지 않는 트랙 고유 번호다. `tools/roadmap_progress.py`
의 기계 집계는 **R 전수(V1: R1~R100 결번·중복 없음)가 계약**이라 트랙 K 는
집계 블록 대상 밖이며, 스크립트도 K 헤딩을 파싱하지 않는다(2026-08-08 실측:
이 파일이 있어도 검증 모드 "전부 통과 — 결번 0 · 중복 0" 유지). 트랙 K 를
집계에 편입할지, 한다면 파서 계약을 어떻게 넓힐지는 스크립트 확장과 함께 가는
메인테이너 판단이다 — 스크립트의 자기 문서가 "새 항목을 만들지 않는다. 전부
사람 몫"이라 못박은 그 몫이다.

이 트랙 안의 잠정 집계(손집계, 파일 내 한정): 실측 2 · 가설 8 = 10.

## K1 rhwp-cli 스킬 — 명령 매핑 층 `[실측]`

- **한 줄** — "이 파일 SVG 로", "레이아웃 버그 좁혀줘" 같은 요청을 적절한 CLI
  명령과 권장 디버깅 순서로 매핑하는 스킬이 실물로 있다.
- **지금** — [`.claude/skills/rhwp-cli/SKILL.md`](../../../.claude/skills/rhwp-cli/SKILL.md)
  (d86c935bc). 요청→명령 매핑표와 레이아웃·간격·겹침 디버깅 5단 순서를 담고,
  명령 상세는 cli_commands.md 로 위임한다 — 원칙 2 를 이미 지키는 실물이다.
- **설계** — 매핑표가 하중을 받는 부분이다. 스킬은 옵션 문법을 재서술하지 않고
  "어떤 요청이 어떤 명령인가"만 들며, 문법은 단일 출처(cli_commands.md·help)로
  넘긴다. 명령이 늘 때 스킬 갱신을 잊으면 매핑에 구멍이 나는데, 구멍은 거짓이
  아니라 누락이라 해가 작다 — 거짓(존재하지 않는 명령 서술)만 가드로 막으면 된다.
- **착수 게이트** — (없음 — 실물 존재. `[완료]` 승급은 아래 DoD 의 기계 대조가
  선 뒤.)
- **DoD** — 스킬 본문의 명령 전수가 cli_commands.md 에 실재함을 기계 대조하는
  검사가 있고, 처음 온 에이전트가 스킬 트리거만으로 첫 유효 분석 명령에
  도달한다(트랙 D R31 온보딩 실측과 같은 판정 방식).
- **의존** — cli_commands.md 단일 출처, 트랙 A(봉투 계약).

## K2 rhwp-exam-ingest 스킬 — 변환 파이프라인 패키지 `[실측]`

- **한 줄** — 시험지(PDF/이미지/MD/DOCX)를 HWPX 로 만드는 다단 파이프라인이
  스킬 한 개로 트리거된다.
- **지금** — [`.claude/skills/rhwp-exam-ingest/SKILL.md`](../../../.claude/skills/rhwp-exam-ingest/SKILL.md)
  + helpers 4종(80535a3be, 992fbc2d2). 입력 정규화(helpers)→구조 인식(호스트
  모델의 Vision)→`ingest.json`(ingest_schema_v1)→`build-from-ingest`(cli_commands.md
  §3) 순서를 패키지로 든다.
- **설계** — 스킬이 든 것은 절차이고 능력은 전부 기존 표면에 있다 — 빌드는
  `build-from-ingest` 명령, 자르기는 helpers 스크립트, 인식은 호스트 모델.
  외부 OCR 의존 0 이라는 선택이 스킬을 환경 이식 가능하게 만든다. K1 이 "요청
  →명령 1건" 매핑이라면 K2 는 "요청→다단 절차" 매핑으로, 스킬 층의 두 극단을
  실물 둘이 이미 커버한다.
- **착수 게이트** — (없음 — 실물 존재.)
- **DoD** — 실측 시험지 1건이 트리거 문장에서 `out.hwpx` 까지 완주하고, 산출이
  한컴에서 열린다(자기 round-trip ≠ 한컴 호환 — K1 스킬의 주의 문구와 같은
  게이트).
- **의존** — `build-from-ingest`, 트랙 E(실물 능력).

## K3 서식 채우기 스킬 `[가설]`

- **한 줄** — [레시피 1](../../manual/recipes/01_fill_form_and_submit.md)
  (`fields` → `edit fill-fields` → `--verify` → `edit sanitize`)을 트리거
  가능한 스킬로 감싼다.
- **지금** — 레시피 1 은 `[완료]`(트랙 D R34)지만, 에이전트가 그 서사를 찾아
  읽는 것은 발견(트랙 D)의 몫이다. "이 서식 채워줘" 한 문장이 레시피 경로로
  직행하는 스킬은 없다.
- **설계** — 스킬은 레시피 1 의 절차 요약과 판정 지점(값 반영 확인은 `--verify`
  재파싱)만 들고, 심화 함정(반복 필드·`ambiguous`·overflow)은
  [form_filling_guide.md](../../manual/form_filling_guide.md)로 위임한다.
  레시피 본문의 재수록은 금지(원칙 2) — 스킬이 낡으면 레시피와 갈라지는 것이
  아니라 링크가 남는 구조로.
- **착수 게이트** — 스킬 감싸기가 레시피 직접 열람 대비 무엇을 줄이는지(왕복
  수·오호출) 실측 1건. 줄이는 것이 없으면 이 항목은 기각이 옳다.
- **DoD** — 트리거 문장에서 제출 산출물까지 스킬 경로의 명령 전수가 레시피
  1 과 일치하고, `--verify` 판정이 경로에 포함되며, 실측 로그가 문서에 남는다.
- **의존** — 트랙 D R34(레시피 1), K1(매핑 층 관례).

## K4 표↔CSV 왕복 스킬 `[가설]`

- **한 줄** — [레시피 2](../../manual/recipes/02_table_csv_roundtrip.md)

- **지금** — 레시피 2 실재. 표 편집 요청("이 표를 엑셀로 고치고 다시 넣어줘")

- **착수 게이트** — 왕복 손실 안내를 스킬에 얼마나 실을지 경계 확정 — 레시피
  중복이 시작되는 지점이 어디인지 판단이 선행한다.
- **DoD** — 왕복 1건 실측(수정 반영 + `--verify` 통과)이 스킬 경로로 완주되고,
  dry-run 생략 직행이 스킬 서사에 없다.
- **의존** — 트랙 D R34(레시피 2), K3(같은 감싸기 판형 — 먼저 선 쪽이 판형을
  확정).

## K5 보안 스윕 스킬 `[가설]`

- **한 줄** — 배포 전 점검([레시피 3](../../manual/recipes/03_redact_before_sharing.md))
  과 신뢰 못 할 문서 검사([레시피 4](../../manual/recipes/04_safety_check_untrusted_doc.md))

- **지금** — `inspect` 3축(hidden-text·injection·unicode)·`edit redact`·
  `edit sanitize` 가 도구로, 레시피 3·4 가 서사로 실재한다. 묶는 층이 없다.
- **설계** — 탐지→마스킹→재검(탐지 0 확인) 사이클을 스킬이 순서로 든다. 원칙
  3 이 여기서 최대 하중을 받는다 — `findings[].raw` 는 마스킹 전 원문이라
  (트랙 A R5) 표지와 함께 소비하고, 주입 탐지 결과 안의 문자열을 지시로
  승격하지 않는다.
- **착수 게이트** — 레시피 3·4 를 한 스킬로 묶을지 둘로 갈지 판단 — 실사용
  트리거 문장을 모아 두 목표(내보내기 전 정리 vs 수신 문서 경계)가 한 문장
  부류인지 본다.
- **DoD** — 주입 문자열을 심은 오염 표본에서 스킬이 탐지→마스킹→재검 사이클을
  완주하고, raw 값이 지시로 다뤄지지 않았음이 실측 로그로 남는다.
- **의존** — 트랙 A R2·R5(표지), 트랙 B(가드·보안), 트랙 D R34(레시피 3·4).

  최종 보고에 성공/실패/재시도 내역이 갈라져 실린다.
- **의존** — `batch`(cli_commands.md), 트랙 A(건별 실패 봉투), 트랙 D R34
  (레시피 5).

- **DoD** — 알려진 회귀 1건·무회귀 1건에서 스킬 판정이 사람 판정과 일치하고,
  세 곳(K1 절·레시피 6·신규 스킬)의 서사 중복이 늘지 않는다.
- **의존** — 트랙 D R34(레시피 6), K1(중복 판단의 상대).

## K8 안전 편집 스킬 — 3층 계획 `[가설]`

- **한 줄** — 임의 편집 요청을 ①현황(`fields`·`digest`·`dump`) ②계획(`--dry-run`,
  planSchema — [트랙 I R81](track_i_standards.md)) ③실행+검증(`--verify`) 3층
  순서로만 통과시키는 스킬.
- **지금** — 편집 명령군(`edit fill-fields`·`replace-text`·`set-cell`·
  `insert-image`·`redact`·`sanitize`)이 dry-run/verify 를 개별로 들고, 계획
  실행기 `run`(`--plan-json`, 실패도 저널 봉투 — [트랙 A R4](track_a_envelope.md))
  이 있다. "무계획 실행 금지"를 순서로 못박는 층이 없다.
- **설계** — 스킬은 세 층의 순서와 각 층의 판정(계획 무효 exit 2 + `invalid[]`,
  단언 실패 exit 3 + `verify` — R4 의 명문화된 실물 기준)을 들고, 명령 문법은
  전부 위임한다. 층을 건너뛰는 경로(현황 없이 `--in-place` 직행)가 스킬 서사에
  존재하지 않게 쓴다.
- **착수 게이트** — 편집 명령군의 dry-run/verify 커버리지 전수 확인 — 셋 다
  없는 명령이 있으면 그건 스킬 공백이 아니라 능력 공백(트랙 E)이라 순서가
  뒤집힌다.
- **DoD** — 임의 편집 요청 표본에서 스킬 경로가 무계획 실행 0 건을 유지하고,
  verify 실패(exit 3)가 성공으로 오독되지 않는다.
- **의존** — 트랙 A R1·R4(종료 코드·저널 봉투), 트랙 I R81(planSchema), K3
  (같은 판형의 좁은 선례).

## K9 문서 트리아지 스킬 — 미지 문서 접수 `[가설]`

- **한 줄** — 처음 보는 문서를 `info` → `digest` → `export-structure` → `diag`
  순서로 접수하고, 의심 신호가 있으면 K5(보안 스윕)로 인계하는 스킬.
- **지금** — 접수용 도구는 전부 실재하고 종료 코드 계약(트랙 A R1)이 실패
  분류를 보장하지만, "이 문서 뭐야, 다룰 수 있어?" 트리거에서 옳은 첫 명령
  묶음으로 가는 층이 없다 — K1 은 요청이 이미 구체적일 때의 매핑이라 이 앞
  단계를 덮지 않는다.
- **설계** — 스킬 산출은 접수 보고(포맷 판별, 파싱 성부, 구조 요약, 다음 행동
  제안)다. 실패는 종료 코드로 분류해 보고하고(0/1/2/3 — R1 계약의 소비),
  문서 유래 텍스트는 표지와 함께만 싣는다(원칙 3).
- **착수 게이트** — 접수 보고의 최소 필드 합의 — 무엇이 있어야 다음 에이전트가
  매뉴얼 없이 이어받는지, 트랙 C 의 인계 레시피(R25) 논의와 겹치는 부분의
  경계를 먼저 긋는다.
- **DoD** — 미지 표본 묶음(정상·손상·암호 보호·주입 포함)에서 스킬이 각각을
  옳은 다음 행동(명령 또는 K5 인계)으로 라우팅한다.
- **의존** — 트랙 A R1(종료 코드), K1(구체 요청 매핑과의 경계), K5(인계 대상).

## K10 MCP 세션 스킬 — 표면 전환 등가 `[가설]`

- **한 줄** — 같은 스킬 서사가 CLI 대신 MCP 세션(`hwp_open`→`hwp_doc_text`→
  `hwp_close`, [트랙 H R71](track_h_mcp_server.md))으로도 실행되는지 — 스킬이
  표면 선택을 계약으로 서술하게 만든다.
- **지금** — MCP 서버가 도구 정의를 `capabilities --mcp` 와 단일 출처로 들고
  (R71), resources 로 레시피 6편을 내놓는다(R74). 그러나 K1·K2 를 포함한 스킬
  실물은 전부 CLI 경로만 서술한다.
- **설계** — 스킬 판형에 "표면" 절을 더해, CLI 경로와 MCP 경로가 같은 판정에
  도달함을 서술한다. 도구 목록·스키마는 스킬에 재수록하지 않고 단일 출처
  (`mcp_tool_definitions()` = `capabilities --mcp`)로 위임한다 — 원칙 2 의
  MCP 판이다.
- **착수 게이트** — 스킬 1종(K3 후보가 적당)을 CLI 경로와 MCP 경로로 이중
  실측해 봉투 등가(같은 계약·같은 판정)를 먼저 확인한다 — 등가가 깨지는
  지점이 있으면 그건 스킬 문제가 아니라 트랙 H 의 표면 격차다.
- **DoD** — 한 스킬이 두 표면에서 같은 판정에 도달한 실측이 문서로 남고, 스킬
  본문에 MCP 도구 정의의 복제가 없다.
- **의존** — 트랙 H R71·R74, K3(이중 실측의 대상), 원칙 2(단일 출처).
