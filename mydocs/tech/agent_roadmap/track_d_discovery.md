# 트랙 D — 발견·온보딩 (R31~R40)

**질문**: 처음 온 에이전트가 매뉴얼 없이 길을 찾는가.

처음 온 에이전트는 명령 이름조차 모른다. 이 트랙의 원점 #3828(에이전트 유입
축)이 세운 공리는 하나다 — **저장소가 스스로를 설명하고 스스로를 가르친다.**
이름을 몰라도 키워드로 명령을 찾고(R31), 한 번의 왕복으로 자기서술 전 축을
받아오고(R32), 명령이 스스로를 서술하고(R33), 목표에서 시작하는 레시피가 손을
잡아준다(R34). R31~R37 이 매뉴얼 없는 길을 실제로 깐 실적이고, R38~R40 은
저장소 밖(설치·등재·대응 표면)에 막혀 있는 도달 표면이다.

## R31 capabilities --search `[완료]`

- **한 줄** — 명령 이름을 몰라도 키워드로 명령을 찾는다.
- **지금** — #3828 다리 B1 → #3836. 매칭은 `capabilities` 본문에 대한 **결정론적
  부분문자열 검색**이다 — LLM 도, 유사도 점수도 없다.
- **설계(보장)** — 같은 질의는 같은 결과를 내고, 판정에 모델이 끼지 않는다.
  순위·유사도 점수가 없으므로 "왜 이게 나왔나"가 질의 문자열만으로 설명된다 —
  발견 가능성을 확률이 아니라 규약으로 만든 것이 요지다.
- **DoD** — 달성: 키워드로 최상위 명령을 찾는다. `edit`·`inspect` 하위 명령까지의
  도달은 트랙 A R7(하위 명령 자기서술 등재) 머지 전까지 절반이다(트랙 A R7 이
  이 절반을 정량 근거로 기록한다).
- **의존** — 트랙 A(capabilities 자기서술 위에서 검색이 돈다).

## R32 export-agent-manifest 왕복 1회 + planSchema 접합 `[완료]`

- **한 줄** — 한 번의 호출로 에이전트가 필요한 자기서술 전 축을 받는다.
- **지금** — #3828 다리 B2 → #3843, planSchema 접합은 #3808.
  `capabilities`+`irSchema`+`provenanceMap`+`planSchema` 네 축을 **1회로 조립**한다.
- **설계(보장)** — 없는 축은 `null` 이 아니라 `missingAxes:["..."]` 로 이름을
  밝힌다. 침묵의 빈칸은 "축이 비었다"와 "이 빌드가 그 축을 안 실었다"를 뭉개지만,
  이름을 밝히면 소비자가 둘을 가른다(트랙 A·B 의 "키가 없으면 깨끗함이 아니라
  검사하지 않음"과 같은 공리).
- **DoD** — 달성: 왕복 1회로 네 축과 누락 축 명세를 함께 받는다.
- **의존** — R31(capabilities), 트랙 A R2(provenanceMap), planSchema(#3808).

## R33 rhwp explain 결정론적 자기서술 `[완료]`

- **한 줄** — 명령이 자기가 무엇을 하는지 문서로 스스로 서술한다.
- **지금** — #3828 다리 B4 → #3832. 문서·선언에서 기계적으로 조립한 **결정론적
  문장**이다 — LLM 을 쓰지 않는다.
- **설계(보장)** — 서술이 모델 생성이 아니므로 빌드마다 같고, "서술 ↔ 실물"의
  드리프트가 가드 대상이 된다(생성 문장이면 드리프트를 정의할 수 없다).
- **DoD** — 달성: `explain` 이 명령별 결정론적 자기서술을 낸다.
- **의존** — 없음(#3828 의 병렬 다리).

## R34 레시피 1~6 + 3(마스킹) `[완료]`

- **한 줄** — 목표에서 시작하는 서사로 에이전트가 첫 작업을 완주한다.
- **지금** — #3828 다리 B3 → #3835(레시피 1·2·4·5·6). 레시피 3(배포 전 개인정보
  마스킹, `redact`×`sanitize`)은 PR #3898.
- **설계(보장)** — 각 레시피는 명령 목록이 아니라 목표에서 시작하는 서사이고,
  인용된 출력은 **전 단계 실측 출력뿐**이다(가상 출력 금지). 레시피가 실물과
  어긋나면 실측 갱신 시 바로 드러난다.
- **DoD** — 달성: 레시피 1~6 이 목표까지의 서사를 실측 출력으로 완주한다.
- **의존** — R31(발견), 각 레시피가 엮는 실측 표면(트랙 E 편집 명령).

## R35 프로필 등재 누락 14건 + 재발 가드 `[완료]`

- **한 줄** — 어느 프로필에도 없어 존재조차 감춰졌던 도구 14건을 등재했다.
- **지금** — #3838. `insert_image` 하나인 줄 알았는데 `hwp_digest`·`hwp_run_plan`·
  `hwp_redact`·`hwp_inspect_*` 등이 **어느 프로필에도 없었다** — 프로필로 필터된
  에이전트는 그 도구의 존재조차 모른다(발견 가능성의 정확한 반대 상태).
- **설계(보장)** — 가드 `every_stateless_tool_belongs_to_some_specific_profile`
  추가. 무상태 도구가 프로필 한 곳에도 안 실리면 CI 가 잡는다 — R35 는 14건의
  일회 회수이고, 이 가드가 재발을 구조로 막는다.
- **DoD** — 달성: 14건 등재 + 누락 재발 시 가드 1개로 검출.
- **의존** — 트랙 A(프로필·capabilities 선언).

## R36 에이전트 가이드 4편 ×7.8 확충 `[이슈]`

- **한 줄** — 봉투 필드 148개를 전수로 설명하는 가이드로 넓힌다.
- **지금** — PR #3889. 577줄 → 4,487줄(×7.8), 봉투 필드 148개 전수.
- **설계** — 4편(가이드)이 봉투 필드를 예시 몇 개로 훑던 것을 148개 필드 전수
  설명으로 바꾼다. 필드 목록의 단일 원천은 R32 매니페스트이므로, 확충의 완결
  기준은 "매니페스트가 내는 필드 = 가이드가 설명하는 필드"다.
- **착수 게이트** — 없음(PR 존재). 다음 행동은 머지 유도·리뷰 대응.
- **DoD** — PR #3889 머지. 가이드 4편이 봉투 필드 148개를 전수 설명한다.
- **의존** — R32(필드 원천).

## R37 README 30초 온보딩 `[완료]`

- **한 줄** — README 만 읽고 30초 안에 첫 명령을 돌린다.

  경로다 — 온보딩의 첫 30초를 문서 깊이 탐색 없이 통과시킨다.
- **DoD** — 달성: README 단독으로 첫 명령까지 도달한다.
- **의존** — 없음.

## R38 릴리스 바이너리 배포 `[가설]`

- **한 줄** — `winget`·`scoop`·`brew` 로 설치 1줄이면 된다.
- **지금** — 미착수. **설치 1줄이 채택의 최대 병목**이다(#2659 Stage 4) — 자기서술도
  레시피도, 바이너리를 못 깔면 열리지 않는다.
- **설계** — 세 채널에 서명된 릴리스 바이너리를 등록한다. 채널마다 매니페스트
  형식·심사 절차가 다르므로(winget-pkgs PR, scoop bucket, homebrew formula) 채널별
  요건 조사가 착수의 일부다.
- **착수 게이트** — ① 릴리스 서명·버전 정책(트랙 G R67) 선행. ② 배포 채널별 심사
  요건 조사.
- **DoD** — 세 채널 중 최소 하나에서 설치 관리자 한 줄로 실행 바이너리가 깔린다.
- **의존** — 트랙 G R67(릴리스 서명·버전 정책).

## R39 MCP 레지스트리·에이전트 도구 목록 등재 `[가설]`

- **한 줄** — 에이전트가 도구를 찾는 곳(MCP 레지스트리)에 rhwp 가 뜬다.
- **지금** — 미착수. 등재는 "설치 가능"이 전제라야 의미가 있다 — 못 깔리는 도구를
  목록에 올리면 발견이 곧 막다른 길이 된다.
- **설계** — MCP 레지스트리·에이전트 도구 목록에 rhwp 를 등재하고, 등재 항목의
  설치 안내를 R38 경로로 잇는다.
- **착수 게이트** — ① R38(설치 가능해야 등재가 의미). ② `mcp-serve` 안정(트랙 H).
- **DoD** — 레지스트리에서 rhwp 를 찾아 설치 안내가 R38 경로로 이어진다.
- **의존** — R38, 트랙 H(mcp-serve).

## R40 레시피 07~10(인계·협업·대량·보안 점검) `[실측]`

- **한 줄** — 인계·협업·대량·보안 점검까지 레시피가 덮는다.
- **지금** — 09(대량)·10(보안 점검) 착지 — `mydocs/manual/recipes/09_bulk_extract_convert.md`
  (이슈 #4110, PR #4182 머지), `mydocs/manual/recipes/10_security_sweep_before_share.md`
  (이슈 #4111, PR #4183 머지). 07(인계)·08(협업)은 여전히 미착수 — 대응 표면
  (트랙 C R25·R29)이 아직
  `[문서]` 단계라 착수 게이트가 열리지 않았다. 레시피 09 본문이 번호가 07·08 을
  건너뛰는 이유를 직접 밝힌다: "다중 에이전트 협업 계약(#3905, 로드맵 트랙 C)의
  설계 승인이 선행이라 예약만 되어 있다. 빈 번호는 의도된 결번이다."
- **설계** — 네 레시피 모두 대응 표면의 실측 출력만 인용한다(R34 원칙 승계).
  07 인계·08 협업은 트랙 C, 09 대량은 batch, 10 보안 점검은 트랙 B 에 각각 기댄다.
- **착수 게이트** — (09·10은 없음 — 실물 존재.) 07·08 은 트랙 C R22·R23(CAS/지문
  체인)이 `[문서]`에서 실제 코드로 착지해야 R25 게이트가 열린다 — `src/`에
  `inputSha256`/`preconditionFailed`/`outputSha256` 구현이 아직 없음을 확인했다
  (2026-08-09 재확인).
- **DoD** — 09·10: 전 단계 실측 출력으로 목표까지 완주하는 서사를 담고 인용 출력이
  실물과 일치함 — 달성. 07·08: 미달성(레시피 파일 없음).
- **의존** — R34(레시피 형식), 트랙 C R25·R29, R45(batch), 트랙 B.
