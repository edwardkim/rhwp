# 트랙 H — MCP·서버 (R71~R80)

**질문**: 문서 엔진이 에이전트용 서버로서 성립하는가.

MCP 는 이 저장소가 CLI 를 넘어 에이전트가 호출하는 서비스가 되는 지점이다.
지금까지의 설계 내기는 하나다 — **의존성 0**(serde_json 만, rmcp 미도입)로
프로토콜을 손수 들고, 도구 정의를 capabilities 자기서술과 단일 출처로 묶는다.
R71~R73 이 그 서버 코어와 탈취 방어를 머지한 실적이고, R74~R80 은 표면
확장(resources·세션 풀·원격)과 그 내기 자체의 재평가(R75)다. 원격(R78)이
가장 뒤인 것은 우연이 아니다 — 신뢰 못 할 입력 표면이 거기서 최대가 된다.

## R71 mcp-serve 1단계 `[완료]`

- **한 줄** — 문서 엔진이 stdio 위에서 MCP 서버로 응답한다(initialize/ping/
  tools/list/tools/call).
- **지금** — #3140 → #3571. stdio JSON-RPC 로 네 메서드를 처리하고, **의존성 0**
  (serde_json 만, rmcp 미도입)로 프로토콜을 직접 구현했다. 도구 정의는
  `mcp_tool_definitions()` 한 곳에서 나와 `capabilities --mcp` 와 **단일 출처**다.
  무상태 13종은 `current_exe` 서브프로세스로 격리하고, 세션 3종(`hwp_open`·
  `hwp_doc_text`·`hwp_close`)만 인프로세스 핸들로 상태를 든다.
- **설계(보장)** — `mcp_tool_definitions()` 가 tools/list 와 `capabilities --mcp`
  의 공통 원천이라, 도구 목록이 두 표면에서 갈라지지 않는다. 무상태 도구는
  서브프로세스 격리로 서버 상태를 오염시키지 못하고, 상태는 세션 3종에만 모인다.
- **DoD** — 달성: initialize/ping/tools/list/tools/call 네 메서드가 stdio 로
  응답하고, 도구 정의가 capabilities 와 단일 출처로 고정된다.
- **의존** — 트랙 A(무상태 도구가 `current_exe` 서브프로세스라 CLI 봉투 계약을
  그대로 상속), capabilities 자기서술(도구 정의 단일 출처).

## R72 did-you-mean·nextCall 내성 `[완료]`

- **한 줄** — 오타 도구명과 닫힌 핸들 호출에 서버가 교정 힌트를 돌려준다.
- **지금** — did-you-mean #3694 → #3698(레벤슈타인 거리 자체 구현으로 **의존성 0**,
  오제안 0 임계 — 임계 밖이면 후보를 내지 않는다), nextCall #3699 → #3701
  (`tool_error_with_next` — 닫힌 핸들 오류 8사이트가 `hwp_open` 을 다음 호출로
  지목).
- **설계(보장)** — did-you-mean 은 레벤슈타인 거리로만 후보를 뽑고 임계 밖이면
  침묵하므로 근거 없는 오제안이 0 이다. nextCall 은 닫힌 핸들 오류 전 8사이트에서
  `hwp_open` 을 다음 행동으로 못박아, 에이전트가 무엇을 먼저 호출해야 하는지를
  오류 봉투 자체가 말한다.
- **DoD** — 달성: 오타 도구명에 근접 후보(또는 임계 밖이면 무제안)를 내고, 닫힌
  핸들 호출에 `hwp_open` 지목이 실린다.
- **의존** — R71.

## R73 stdin 도구 선검증 `[완료]`

- **한 줄** — paths 없는 무상태 호출이 서버의 JSON-RPC stdin 을 자식에게 뺏기는
  탈취를 서버가 선검증으로 막는다.
- **지금** — #3700. paths 인자 없이 무상태 자식을 띄우면 자식이 **서버 프로토콜
  stdin 을 상속**해 뒤따르는 JSON-RPC 프레임을 파일 경로로 소비하는 탈취가
  가능했다. 서버가 호출 전 paths 존재를 선검증해 자식을 아예 띄우지 않는다(트랙 B
  R14 의 보안 계약에도 같은 경로가 등재됨).
- **설계(보장)** — 무상태 도구는 `current_exe` 서브프로세스라(R71) paths 가 없으면
  자식이 부모 stdin(=서버의 JSON-RPC 스트림)을 상속한다. 서버는 호출을 자식에게
  넘기기 전에 paths 를 선검증하고, 없으면 `tool_error` 로 즉시 거부한다 — 자식
  기동 자체가 일어나지 않는다.
- **DoD** — 달성: paths 누락 무상태 호출이 자식 기동 전에 거부되고, 서버 stdin 이
  자식에게 상속되지 않는다.
- **의존** — R71.

## R74 MCP resources 표면 `[완료]`

- **한 줄** — 스키마·레시피를 MCP resources 프로토콜로 노출한다.
- **지금** — #3627의 잔여는 [#4116](https://github.com/edwardkim/rhwp/pull/4116)에서
  착지했다. resources/list·resources/read가 capabilities 매니페스트·문서 3편에
  스키마 3종과 레시피 6편을 더해 응답한다. 스키마는 export-*-schema와 같은 생성기,
  레시피는 원본 `include_str!`에서 파생한다.
- **DoD** — 달성: 광고한 모든 URI를 list→read 왕복하는 계약 test가 MIME·본문·JSON
  파싱을 대조하고, 미지 URI의 `-32002`·`data.uri`도 고정한다.
- **의존** — R71.

## R75 rmcp 전환 재평가 `[완료]`

- **한 줄** — 의존성 0 원칙과 rmcp(공식 크레이트) 도입의 교환비를 명문화하고
  판단한다.
- **지금** — [`mydocs/tech/agent_architecture/decision_log.md`](../agent_architecture/decision_log.md)
  D-41("rmcp 를 도입하지 않고 MCP 프로토콜 손수 구현을 유지한다")로 착지했다
  (원 PR #4206, 통합 PR #4253 로 devel 머지 — 머지 커밋 `1ede9c7ac`). D-41 상태는
  "유효(조건부)" — 도입 대신 유지를 택한 근거(의존성 0·드리프트 가드·프로토콜
  표면 통제)가 결정 기록에 있다. "devel 머지가 곧 비준"이 PR 본문 자체의 규약이라
  별도 메인테이너 승인 코멘트 없이도 이 판단은 유효하다.
- **설계(보장)** — rmcp 가 주는 것(프로토콜 준수·스펙 추적·유지보수 위임)과
  잃는 것(의존성 0, 프로토콜 표면의 완전한 통제, 드리프트 가드가 감시할 자기
  코드)을 표로 대사했고, 그 표 위에서 유지 쪽으로 결정했다.
- **DoD** — 달성: 교환비 문서(D-41)가 존재하고, 유지 결정과 그 근거가 기록된다.
- **의존** — R71.

## R76 문서 지능 서버 `[문서]`

- **한 줄** — 문서를 연 세션 위에서 질의에 반복 응답하는 지능형 서버.
- **지금** — #3878 설계 문서 존재. 핵심 판정은 하나다 — **증분 재파싱은 HWP 에서
  성립하지 않는다**(레코드 구조상 부분 편집 → 부분 재파싱 경로가 없다). 세션
  3종(R71)은 이미 문서를 열어두지만, 그 위의 지능(재파싱 없이 응답하는 캐시)은
  미구현이다.
- **설계** — 증분 불가가 확정 전제다. 따라서 "편집 후 부분 갱신"이 아니라 "무엇을
  캐시하면 재파싱 없이 응답 가능한가"로 방향을 튼다 — 파싱 산출(IR·텍스트·구조)을
  세션 핸들에 얹고, 편집 시 캐시 무효화 규약을 정한다.
- **착수 게이트** — 증분 불가 전제 위에서 무엇을 캐시할지 재설계(설계 문서의 다음
  단계).
- **DoD** — 세션 핸들이 캐시된 질의(텍스트·구조·검색)에 재파싱 없이 응답하고,
  편집 시 캐시 무효화 규약이 정의·테스트된다.
- **의존** — R71.

## R77 세션 풀·TTL·감사 로그 `[가설]`

- **한 줄** — 다중 클라이언트가 세션을 안전히 공유·격리하도록 풀·수명(TTL)·감사
  로그를 얹는다.
- **지금** — 세션 3종(R71)은 단일 클라이언트·무기한 핸들이다. 풀링도, 유휴 만료도,
  누가 무엇을 언제 열었는지의 감사도 없다.
- **설계** — 세션 풀(핸들 재사용·상한), TTL(유휴 핸들 만료), 감사 로그(문서 열람
  이력)를 얹고, 동시 클라이언트가 서로의 핸들을 볼 수 없게 격리한다.
- **착수 게이트** — 트랙 C R28(세션 동시성) + 다중 클라이언트 수요 근거.
- **DoD** — 풀 상한·TTL 만료·감사 로그가 동작하고, 동시 클라이언트가 서로의
  핸들에 접근하지 못한다.
- **의존** — R71, 트랙 C R28.

## R78 원격 실행 블루프린트 `[가설]`

- **한 줄** — MCP 서버를 로컬 stdio 밖(원격)에서 안전하게 실행하는 설계를 세운다.
- **지금** — #3608 M27. 현재 서버는 stdio 로컬 전용이라 원격 표면이 없다. 원격은
  **신뢰 못 할 입력 표면이 최대**가 되는 자리라, 보안 축이 서지 않은 채로 열면
  안 된다.
- **설계** — 원격 실행 블루프린트(전송·인증·격리)를 문서로 세운다. 전제는
  트랙 B 의 보안 계약이 원격 입력 경로까지 덮는 것이다.
- **착수 게이트** — 트랙 B 보안 축(R14·R15) 선행 필수 — 원격은 신뢰 못 할 입력
  표면이 최대다.
- **DoD** — 원격 전송·인증·격리 블루프린트가 문서화되고, R14·R15 가드가 원격 입력
  표면을 덮는 범위가 명시된다.
- **의존** — 트랙 B R14·R15, R71.

## R79 레시피의 MCP 리소스 서빙 `[완료]`

- **한 줄** — 레시피를 MCP resources 로 서빙해 에이전트가 프로토콜로 직접 읽는다.
- **지금** — [#4116](https://github.com/edwardkim/rhwp/pull/4116)이 R74와 함께
  레시피 6편을 `rhwp://recipes/01~06` URI로 서빙했다. 설치본에도 본문이 남도록
  런타임 파일 읽기 대신 컴파일 시점 `include_str!`을 사용한다.
- **DoD** — 달성: resources/list가 레시피를 열거하고 resources/read가 각 본문을
  `text/markdown`으로 반환하며, R74의 list→read 계약 test가 함께 검증한다.
- **의존** — R74, 트랙 D(레시피 원천).

## R80 에이전트 관측성(호출 통계 옵트인) `[가설]`

- **한 줄** — 도구 호출 통계를 옵트인·로컬로 수집해 서버에 관측성을 준다.
- **지금** — 서버는 호출을 기록하지 않는다 — 관측성 0 이다. 무엇이 얼마나 불리는지,
  어디서 오류가 나는지를 볼 수 없다.
- **설계** — 수집은 **옵트인·로컬·문서 내용 미수집**을 원칙으로 한다. 무엇을
  수집(도구명·빈도·오류율)하고 무엇을 안 하는지(문서 내용·파일 경로·개인정보)를
  계약으로 고정하고, 그 계약을 테스트로 지킨다.
- **착수 게이트** — 무엇을 수집하고 무엇을 안 하는지 계약 문서 선행.
- **DoD** — 옵트인 플래그가 있고, 수집 항목이 계약대로이며(문서 내용 미수집을
  테스트로 고정), 데이터가 로컬 밖으로 나가지 않는다.
- **의존** — R71.
