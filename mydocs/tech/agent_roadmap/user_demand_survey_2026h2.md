# 사용자·생태계 수요 실조사 2026H2 — 도달·배포 축 게이트 근거 (#4327)

> 이 조사는 당시의 수요와 제안을 보존하는 historical 근거다. 여기서 제안한 Python·Node
> 패키지와 신규 설치 채널은 공식 채널로 채택되지 않았고 v0.8.4에서 철회됐다(#4655).

**질문 두 개**: ① R1~R100 중 도달·배포 축 `[가설]` 단계(R38·R39·R63·R86·R87)의
착수 게이트가 요구하는 수요·도달 근거가 실재하는가. ② 트랙 문서의 "지금" 서술이
2026-08-09 실물과 일치하는가.

[trend_survey_2026h2.md](trend_survey_2026h2.md) 가 **도구 설계 동향**(만드는 쪽의
모범)을 조사했다면, 이 문서는 **사용자·생태계 수요**(쓰는 쪽의 현실)를 조사한다.
둘은 같은 5관문 선별 기준을 쓴다 — 출처 실재 / 3판정(이미 있음·부분·공백) /
논지 직접 기여 / 착수 게이트 서술 가능 / 캡. 이 문서의 신규 제안은 **2건**에서
멈춘다(기준 3·4를 지나는 후보가 그만큼이었다).

이 문서는 **제안+사실 정정**이다. 등급 변경은 짝으로 가는 트랙 문서 정정(같은
PR)이 수행하고, 신규 제안의 채택·번호 부여는 전부 메인테이너 몫이다.

   하는게 더 큰 목표거든요"

## 2. 발견 채널 감사 — 에이전트는 오늘 rhwp 에 도달하는가

에이전트(또는 에이전트를 만드는 개발자)가 실제로 던질 질의 5종으로 웹 검색 상위
노출을 감사했다(2026-08-09).

| 질의 | 상위 노출(1~5위) | rhwp |
|---|---|---|
| `convert hwp to text CLI` | 온라인 변환 서비스류, 개인 변환 스크립트 | **부재** |
| `hwp to markdown` | 변환 스크립트·신흥 경량 파서·변환 전용 MCP | **부재** |
| `parse hwp file python` | PyPI 의 기존/신흥 파서들 | **부재** (파이썬 진입 질의를 통째로 놓침) |
| `hwp mcp server` | 서드파티 HWP MCP 들 | **간접 1건** — 3위 서드파티 README 의 "built on rhwp" 문구뿐 |
| `read hwp file LLM RAG` | "LLM/RAG용" 을 표방한 신흥 경량 파서가 1위 | **부재** |

- MCP 레지스트리 4곳(glama·smithery·pulsemcp·mcpservers.org)에 rhwp **1st-party
  등재 0**. HWP 항목은 부분 기능 서버들뿐이다 — COM 의존(Windows+한컴 설치
  필수)이거나 HWPX 전용이거나 변환 전용.
- 실사용 선택의 결정타가 "프레임워크 공식 통합"이었다는 후기 실물: 한국 공문서
  RAG 구축기([velog, 2026-02-19](https://velog.io/@pjg9606/%ED%95%9C%EA%B5%AD-%EA%B3%B5%EB%AC%B8%EC%84%9C-RAG%EC%9D%98-%EC%B2%AB-%EB%B2%88%EC%A7%B8-%EB%B2%BD-HWP-%ED%8C%8C%EC%8B%B1-%ED%95%B4%EA%B2%B0%EB%B2%95))
  가 유료 파싱 API 를 고른 이유로 LangChain 공식 통합을 들었고, rhwp 는 언급조차
  되지 않았다. 표준 RAG ETL(unstructured)의 지원 포맷 목록에 HWP 자체가 없다
  ([저장소](https://github.com/Unstructured-IO/unstructured)).
- 기존 파이썬 추출 경로의 알려진 한계가 이 파이의 크기를 말해준다: 표 안 텍스트
  유실([mete0r/pyhwp#169](https://github.com/mete0r/pyhwp/issues/169), 2020 보고,
  원문 재검증), 미리보기 스트림 절단(가장 널리 유통되는 3줄 추출법이 문서 앞부분만
  꺼낸다 — [해설](https://wikidocs.net/170811)).

**함의**: 능력(§4의 CLI·MCP·바인딩)이 아니라 **도달**이 지는 자리다. 같은
카테고리에서 이긴 도구들(문서→Markdown/JSON 변환기·문서 파서)의 공통 공식은
원라인 설치(pip/npx) + Markdown·구조화 JSON 이중 계약 + 프레임워크 공식 로더 +
자체 MCP + 검색에 걸리는 영문 기술 문서다 — 원리 목록으로만 옮긴다(실명 비교는
이 문서의 몫이 아니다).

R86 의 종전 서술("배포·등재 전이라 외부 사용자 자체가 아직 없다")과 달리, 외부
소비자는 이미 실재한다.

k-skill 문서의 원문(기준 버전 v0.7.3, 2026-04-19):

> "편집 서브커맨드는 없다. v0.7.3 기준 업스트림 rhwp CLI 에는 edit / insert-text /
> save 같은 in-place 편집 명령이 없다" … "편집은 k-skill-rhwp CLI (rhwp-edit 스킬) 로"

오늘의 상류에는 `edit`(R41 세션 편집 계열)·`mcp-serve`(R71)·`capabilities` 자기서술
전 축이 있다. 즉 **최대 외부 소비자가 4개월 낡은 표면 스냅샷에 고정된 채 편집
축을 자체 CLI 로 갈라 나갔다**. treesoop 도 같은 모양이다(0.7.7 시점 한계를 현재
한계로 명기). 이것은 개별 소비자의 태만이 아니라 **상류가 소비자에게 버전 추종
경로를 제공하지 않은 구조**의 결과다 — 스키마 버전은 축마다 따로 구르고(R83 의
"각자 상수" 실측), 무엇이 언제 늘었는지 기계가 대조할 대사 채널이 없다. R67(버전
정책)×R83(스키마 레지스트리)의 착수 게이트("함께 설계할 것")가 요구하던 실수요
근거가 바로 이것이다.

| 다운로드 (v0.8.2, gh API 재검증) | linux 819 · windows 346 · macOS 137+15 · SHA256SUMS 219 |

| npm 배포 | `@rhwp/core`·`@rhwp/editor`·VSCode 확장은 `npm-publish.yml`로 배포 중(웹 축). 조사 당시 미배포였던 `@rhwp/node`는 #4655에서 공식 바인딩과 함께 철회 |

정리하면 웹 축은 배포가 완비됐고(npm 2종 + 스토어 2곳 + 온라인 데모), **에이전트
축은 바이너리가 존재하는데 도달 경로(채널 등재·README 1줄·PyPI/npm 휠)가 없다.**
R38 의 "지금 — 미착수"는 존재 층위에서 낡았고, 공백은 도달 층위로 이동했다 —
같은 PR 의 트랙 문서 정정이 R38 을 `[가설]`→`[실측]` 으로 올리고 지금·게이트를
재서술한다. 채널별 심사 요건 조사(게이트 ②)는 본 조사 범위 밖이라 **미충족으로
정직하게 남긴다** — R38 착수의 1차 산출물이다.

## 7. 신규 제안 (캡 2)

### U1 프레임워크 공식 로더 — LangChain·LlamaIndex

- **3판정**: 공백 — R1~R100 어느 단계도 "프레임워크 생태계에 공식 로더를
  기여한다"를 다루지 않는다(R63 은 배포까지, R39 는 MCP 등재까지).
- **근거**: 실사용 선택의 결정타가 프레임워크 공식 통합이었다는 후기 실물(§2),
  표준 ETL 의 HWP 공백(§2), 유료 파싱 API 진영이 같은 자리를 상용으로 공략
  중(§2) — 이긴 도구들의 공통 공식에서 rhwp 에 없는 마지막 조각.
- **착수 게이트**: ① R63 선행(pip 설치 가능이 로더의 전제). ② 대상 프레임워크
  기여 규약 조사(langchain-community · LlamaIndex 로더 기여 요건).
- **DoD**: 대상 프레임워크 최소 1곳에 HWP 로더가 머지되고, 로더 문서가 rhwp
  설치 경로(R63)로 이어진다.
- **트랙 편입 제안**: G(바인딩) 또는 I(생태계) — 메인테이너 판단.

### U2 외부 소비자 대사 채널 — R67×R83 DoD 확장 제안

- **3판정**: 부분 — R67(버전 정책)·R83(스키마 레지스트리)은 내부 정합 축으로
  설계돼 있다. 외부 소비자(§3)가 그 정책·레지스트리를 **구독·대조**하는 표면은
  공백이다.
- **근거**: 스테일 고정 실물 2건(§3). 소비자가 추종할 채널이 없으면 정책을 세워도
  같은 갈라짐이 재발한다.
- **제안**: R67×R83 착지 시 DoD 에 "외부 소비자 관점" 한 줄을 추가한다 — 버전
  정책 문서가 소비자용 추종 안내(무엇이 언제 늘었고, 어느 버전과 호환인가)를
  포함하고, 레지스트리 값이 `capabilities` 봉투로 노출되어 소비자가 기계로 대조할
  수 있을 것.
- **착수 게이트**: R67×R83 본체와 동시 설계(별도 선행 없음 — 이 조사가 그 근거).
