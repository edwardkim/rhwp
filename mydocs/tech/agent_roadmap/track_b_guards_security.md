# 트랙 B — 가드·보안 (R11~R20)

**질문**: 구멍을 사람이 아니라 가드가 먼저 찾는가. 그리고 문서가 에이전트를
조종하는 경로(보안 축의 정의, `agent_security/threat_model.md`)가 닫혀 있는가.

이 트랙의 공리는 하나다 — **선언을 믿지 않는다.** 출처 스윕이 지도를 참고하지
않고 문서 자체에서 오라클을 만드는 것(`provenance_contract.rs` 머리말), autofix
봇이 모델의 판단이 아니라 red→green 종료 코드로 PR 여부를 정하는 것, preflight 가
허용목록을 베끼지 않고 계약 테스트에서 직접 읽는 것 — 전부 같은 공리의 표현이다.

## R11 preflight 드리프트 가드 일괄 `[완료]`

  라 하나씩만 드러나서 같은 실수에 릴리스 빌드를 3번(18분) 태운 사고가 원점이다.
- **설계(보장)** — 허용목록(`NON_ARGV_PROPERTIES`·`HELP_HIDDEN`·인라인 제외)을
  **계약 테스트에서 직접 읽는다** — 베끼면 어긋나고, 어긋나면 실제 가드와 다른
  말을 한다. 사용: `py tools/agent_preflight.py --repo . --bin <릴리스 바이너리>`.
- **DoD** — 달성. 확장은 R12.
- **의존** — 없음.

## R12 실패 경로 전수 + 미선언 명령 감지 `[실측]`

- **한 줄** — preflight 의 실패 경로 검사를 하드코딩 3경로에서 전 명령(60경로)로
  넓히고, "아무것도 선언하지 않으면 검사를 피하는" 회피로를 막는다.
- **지금** — 산출물 착지: #3887 은 개별 close 됐고 내용은 누적 통합 #3912 로
  devel 머지(`tools/agent_preflight.py` 에 실패 경로 전수·미선언 명령 감지 검사
  실재). DoD 의 "CI 에서 잡힌다"만 잔여 — preflight 는 아직 CI 에 배선되지 않았다
  (2026-08-06 워크플로 전수 grep 실측 0건). 원점 실측 둘: ① 실패 경로 검사가 61개 명령 중
  2~3개만 보고 있었다. ② 플래그 검사가 선언된 것만 봐서 **선언 회피가 가드
  회피의 가장 쉬운 길**이었다(#3884 의 dump·diag·bench 가 정확히 그 사각에서
  자랐다). 부속 수정 #3872 — 스키마 출력 명령이 자기 출력에 걸리던 검사 오탐.
- **설계** — 실패 경로는 "없는 파일" 호출을 전 명령에 기계 생성으로 돌리고
  {exit≠0, stdout 0 B(run 예외 명문)}를 대조. 미선언 감지는 디스패치 목록 ↔
  capabilities 선언의 차집합 보고.
- **착수 게이트** — 없음. 잔여는 CI 배선 하나(경고 전용 큐 검사와 분리해 정적
  검사만 태울지가 설계 질문).
- **DoD** — CI 에서 미선언 신규 명령이 preflight 1개 검사로 잡힌다.
- **의존** — R11. R8 판정이 나면 "부류 밖" 명령의 검사 기준을 그 판정에 맞춘다.

## R15 취약점 제보 채널 개방 + 대기 1건 제출 `[이슈]`

- **한 줄** — GitHub Security Advisory 비공개 제보를 켜고, 준비된 취약점 1건을
  제출한다.
- **지금** — #3803. `SECURITY.md` 는 Advisory 제보를 안내하는데 **그 기능이 실제
  로는 꺼져 있음**을 실측(403 "private vulnerability reporting not enabled")으로
  확인했다. 대기 중인 1건: `export-svg --embed-fonts=full` 의 문서 글꼴 이름 경로
  탈출 — 악성 문서가 지정한 폰트 이름으로 `.ttf/.otf/.ttc` 를 읽어 SVG 로 반출.
  재현·패치 준비 완료, 공개 이슈·PR 로 세부를 올리면 0-day 를 광고하는 셈이라
  채널이 열리는 즉시 비공개로 제출한다.
- **설계** — 코드 쪽은 이미 섰다(재현 케이스 + 패치). 남은 것은 채널 자체:
  메인테이너가 저장소 설정에서 private vulnerability reporting 을 켜는 것. 폰트
  이름 경로는 채널이 열려 패치가 머지되면 악성 코퍼스(R13)에 회귀 케이스로 편입.
- **착수 게이트** — 채널 개방(저장소 설정에서 private vulnerability reporting
  활성화). 이것 없이는 정상 제출 경로 자체가 없다.
- **DoD** — 대기 1건이 비공개 채널로 접수되고 `export-svg` 폰트 경로 탈출 패치가
  머지된다.
- **의존** — R14(보안 축의 뼈대). 채널 개방은 코드가 아니라 저장소 설정이다.

## R16 findings[].raw 민감도 신호("로그 금지") 설계 `[가설]`

- **한 줄** — `findings[].raw` 처럼 마스킹 전 원문을 담은 값에 "이 값을 로그·저널·
  재전송에 남기지 마라"는 취급 경고를 봉투로 싣는다.
- **지금** — #3885 의 열린 판단(같은 이슈의 확정분 5건은 트랙 A R5 가 닫았다). R5
  로 redact 의 `findings[].raw` 는 이제 마스킹 전 개인정보 원문에 출처 표지
  (`untrustedContent`)를 달고 나온다. 그러나 표지는 "이 값은 문서에서 왔다(신뢰
  마라)"는 **출처** 경고이고, 여기서 더 중요한 것은 "이 값은 로그에 남기지 마라"는
  **취급** 경고다 — 두 축이 다르다.
- **설계** — 미정(선행 근거 필요). R14 의 `textSecurity` 가 세운 "키가 없으면
  깨끗함이 아니라 검사하지 않음" 해석 규약과 같은 계열의 자기서술 신호가 되겠지만,
  이름·위치·소비자 반응이 전부 미검증이다.
- **착수 게이트** — 둘. ① 이 신호를 봉투 어디에 어떤 이름으로 실을지 메인테이너
  판단(출처 표지와 한 필드로 합칠지, 별도 축으로 둘지). ② 소비자(에이전트)가 실제
  로 그 신호를 읽고 행동(로깅 억제)을 바꾼다는 근거 — 신호만 달고 아무도 안 읽으면
  봉투만 무거워진다.
- **DoD** — 민감도 신호가 계약에 명문화되고, 최소 1개 소비 경로(레시피 또는 MCP
  클라이언트)가 그 신호를 보고 로깅을 억제하는 것을 실증.
- **의존** — 트랙 A R5(`findings[].raw` 표지가 이미 실린 자리 위에 얹는다),
  R14(자기서술 신호 규약).

## R17 퍼징 CI 상시화 `[문서]`

- **한 줄** — 이미 있는 퍼징 하네스를 CI 에서 상시 돌려, 파서 크래시를 사람이
  손으로 돌리기 전에 잡는다.
- **지금** — #3877. 퍼징 인프라(하네스) 자체는 저장소에 있으나 CI 파이프라인에서
  돌지 않는다 — 누군가 로컬에서 수동으로 돌려야만 신규 크래시가 드러난다.
- **설계** — CI 에 퍼징 잡을 더하되, 상시 퍼징은 시간·사람 자원을 지속 소모하므로
  예산과 트리아지 절차가 배선보다 먼저 정해져야 한다. 발견 크래시는 R13 악성
  코퍼스에 회귀 케이스로 흘려보낸다.
- **착수 게이트** — 두 합의. ① CI 시간 예산(퍼징에 얼마를 줄지 — 무한정 돌릴 수
  없다). ② 크래시 트리아지 담당(사람) — 크래시가 나면 누가 분류·처리하는지 없이
  켜면 무시되는 red 만 쌓인다.
- **DoD** — 퍼징 잡이 CI 에서 주기적으로 돌고, 발견 크래시가 트리아지 큐를 거쳐
  악성 코퍼스에 편입되는 경로가 실증된다.
- **의존** — R13(크래시의 회귀 착지점). 인프라는 선행 완료.

## R18 회귀 코퍼스 100건 체계화 `[가설]`

- **한 줄** — 흩어진 회귀 샘플을 100건 규모의 체계적 코퍼스로 정리해, 탐지·파싱
  회귀 판정의 바닥을 넓힌다.
- **지금** — #3608 M23 로 추적. 현재는 samples/ 에 실물 사례가 있고 R13 이 그중
  은닉 2건을 회귀로 고정했으나, 100건 규모의 분류·기대값 체계는 없다.
- **설계** — 미정(선행 근거 필요). 무엇을 어떤 기준으로 모으고 각 사례의 기대
  판정을 무엇으로 고정하는지가 정해지지 않았다. 퍼징(R17) 크래시와 제보(R15)
  사례가 자연 유입원이다.
- **착수 게이트** — 두 선행. ① 수집 기준(크래시·은닉·주입·포맷 변종의 경계). ②
  라이선스: 한컴 문서를 저장소에 배포 가능한 범위 — 라이선스 불명 문서를 코퍼스에
  넣으면 배포 자체가 문제가 된다.
- **DoD** — 100건이 분류·기대값과 함께 코퍼스에 등재되고 CI 회귀에 편입, 라이선스
  근거가 각 사례에 기록된다.
- **의존** — R13(회귀 스위트 골격), R15·R17(사례 유입원).

## R19 autofix 봇 상시 가동 판단 `[실측]`

- **한 줄** — 포크에서 실버그를 자동 탐색해 업스트림 PR 을 여는 autofix 봇을,
  업스트림에 상시 가동할지 판단한다.
- **지금** — 포크(kevin9327/rhwp)에 GitHub Actions cron 으로 이미 구축·가동 중
  (실측). 핵심은 오탐 차단 설계다: PR 개설 여부를 LLM 의 판단이 아니라 bash 종료
  코드가 결정한다 — 수정분을 stash 한 상태에서 신규 테스트가 반드시 실패(red)해야
  하고, stash 상태에서도 통과(green)해 버리면 그 "수정"은 실버그를 못 짚은 오탐이라
  자동 폐기한다. 볼륨은 `MAX_OPEN_PRS` 가드가 자동 집행해 열린 PR 캡(지도 규칙
  3)을 넘지 않는다.
- **설계** — 판단 대상은 코드가 아니라 운영이다: 포크의 cron 을 업스트림 기여
  흐름으로 정식 편입할지, 편입한다면 주기를 얼마로 둘지. 성급히 주기를 짧게 하면
  큐가 봇 PR 로 넘친다.
- **착수 게이트** — 업스트림에 반영된 첫 PR 몇 건의 품질을 사람이 확인한 뒤 cron
  주기를 조정한다. 품질 미확인 상태로 주기부터 올리면 오탐 차단 설계를 신뢰할
  근거가 없다.
- **DoD** — 봇 유래 PR 의 초기 표본이 사람 리뷰에서 실버그 수정으로 확인되고, cron
  주기가 열린 PR 캡을 넘기지 않는 값으로 고정된다.
- **의존** — R11(봇이 제출 전 선검사로 preflight 재사용). 열린 PR 캡(지도 규칙
  3)을 자동 집행 대상으로 삼는다.

## R20 명령별 "가드 커버리지" 자기서술 노출 `[가설]`

- **한 줄** — 각 명령이 어떤 가드의 검사를 받는지를 `capabilities` 에 데이터로
  노출해, "이 명령은 검증됐다"를 소비자가 읽게 한다.
- **지금** — 미착수. 지금 가드 커버리지는 테스트 코드와 preflight 안에 흩어져
  사람만 읽고, 봉투를 받는 에이전트는 어느 명령이 어느 가드를 통과했는지 모른다.
- **설계** — 신뢰를 산문이 아니라 데이터로 만드는 축이다. 트랙 A R10 의 L1 완결
  메타 가드가 "각 `json:true` 명령이 4종 등재처에 다 올라왔는지"를 이미 계산하므로,
  그 산출을 명령별 `guardCoverage:[...]` 로 capabilities 에 노출만 하면 된다 — 새
  계산이 아니라 기존 계산의 표면화다.
- **착수 게이트** — R10 선행(트랙 A). 메타 가드가 커버리지 목록을 산출하는 것이
  전제이고, 그것 없이 커버리지를 따로 다시 계산하면 두 진실이 갈린다.
- **DoD** — `capabilities` 가 명령별 가드 커버리지를 싣고, 그 값이 R10 메타 가드의
  산출과 단일 출처로 묶여 드리프트 가드가 불일치를 잡는다.
- **의존** — 트랙 A R10(메타 가드가 커버리지를 계산).
