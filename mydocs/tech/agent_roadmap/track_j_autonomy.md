# 트랙 J — 자율 유지보수 (R91~R100)

**질문**: 에이전트가 도구의 일상 정비를 스스로 맡는가 — 엔드게임.

J 는 로드맵의 지붕이다 — 앞선 아홉 트랙이 전부 맞물려야만 선다. autofix 봇은
가드(트랙 B)가 초록이어야 안전하고, 드리프트 자동 기안은 L1 무결(트랙 A)이
드리프트를 감지해야 재료가 생기며, 자율 PR 은 발견(트랙 D)과 동시성 잠금(트랙 C)이
있어야 충돌 없이 돈다. R91~R93 은 실제 포크 봇과 실사고에서 나온 **실측**이고,
R94~R99 는 그 위에 얹는 자동화 가설, R100 은 최종 판정 실험이다 — 통과하면 이
로드맵의 목표 문장이 사실이 된다.

## R91 autofix 봇 상시화 `[실측]`

- **한 줄** — 포크에서 봇이 상시로 실버그를 찾아 업스트림 PR 을 낸다.
- **지금** — 포크(kevin9327/rhwp)의 GitHub Actions cron 으로 구축했다. PR 개설
  여부를 **모델이 아니라 red→green bash 종료 코드가 판정**한다 — 실패 재현이
  초록으로 바뀌어야만 PR 이 열린다. `MAX_OPEN_PRS` 가드가 열린 PR 캡(10 내외)을
  자동 집행한다. 트랙 B R19 와 같은 기구를, 여기서는 J 관점(자율 정비)으로 본다.
- **설계** — 봇의 판단 지점을 모델에서 종료 코드로 옮긴 것이 핵심이다 — red 프로브가
  green 이 되는 diff 만 PR 이 되므로 오탐이 구조로 차단된다. 캡은 사람의 감시가
  아니라 `MAX_OPEN_PRS` 로 집행되어, 봇이 큐를 늘리는 면허가 되지 않는다.
- **착수 게이트** — 첫 업스트림 PR 품질 확인.
- **DoD** — 봇이 낸 업스트림 PR 이 오탐 0 으로 머지되고, 열린 PR 캡이 사람 개입
  없이 준수된다.
- **의존** — 트랙 B R19(같은 red→green 봇 기구).

## R92 PR 접합 "선등재" 패턴 규약화 `[실측]`

- **한 줄** — 아직 devel 에 없는 명령을 미리 등재해, 머지 순서와 무관하게 무수정
  통과시키는 패턴을 규약으로 못박는다.
- **지금** — #3903 ↔ #3808 로 실증했다. 면제 호출표를 `SWEEP_EXEMPT` 기준으로만
  순회하므로 **목록에 아직 없는 명령을 미리 넣어도 초과 항목이 무해**하다(순회
  대상이 아니므로). 이 성질을 이용해, 두 병렬 브랜치가 서로가 추가할 명령을 미리
  등재해 두면 머지 순서와 무관하게 무수정으로 통과한다 — 병렬 작업 무충돌 규약이다.
- **설계** — 스윕이 `SWEEP_EXEMPT` 를 기준 집합으로만 순회한다는 사실이 하중을
  받는다 — 기준에 없는 초과 항목은 검사되지 않으므로 미리 등재해도 red 를 만들지
  않는다. 병렬 브랜치는 이 무해성을 이용해 상대의 등재를 선반영, 머지 순서에
  독립인 무수정 통과를 얻는다.
- **착수 게이트** — 이 패턴을 문서화(`agent_surface_playbook` 에 절 추가)할지 판단.
- **DoD** — 선등재 패턴이 playbook 에 한 절로 문서화되고, 실증 사례(#3903 ↔ #3808)가
  링크된다.
- **의존** — 트랙 A R6(면제 스윕·전수 대조 기구), R91(병렬 자율 작업).

## R93 이슈 assignee = 작업 잠금 규약 `[실측]`

- **한 줄** — 이슈 assignee 지정을 세션 간 작업 잠금으로 규약화한다.
- **지금** — 중복 PR 실사고(#3902/#3903 — 같은 이슈를 두 세션이 **4분 차**로 착수)
  에서 도출했다. canonical 절차 ③ "이슈 assignee 지정"이 곧 세션 간 잠금이다 —
  선점된 이슈는 다른 세션이 착수하지 않는다는 규약이 이 사고를 막았을 것이다.
- **설계** — canonical 절차의 assignee 지정 단계를 잠금으로 승격한다 — 착수 시
  assignee 를 선점하고, 선점 여부를 착수 전 확인한다. 잠금 매체는 새 데몬이 아니라
  이미 있는 GitHub assignee 필드다(트랙 C 의 비목표 — 잠금 데몬 금지 — 와 일치).
- **착수 게이트** — (없음 — 아래로 충족.) 워크플로 문서에 "착수 시 assignee
  선점" 명문화.
- **DoD** — `agent_surface_playbook.md` §2 는 이미 이 규약을 담았다(#4105→#4140).
  다만 **일반** Issue Workflow(`docs_and_git_workflow.md`, 트랙 A 추가 작업뿐
  아니라 전 작업 유형이 쓰는 canonical 절차) 는 그때까지 절차 ③을 "이슈 assignee
  지정"이라고만 적어, 이게 곧 세션 간 잠금이라는 명문화·재확인 명령·외부 기여자
  대체 경로가 없었다 — 이번에 `docs_and_git_workflow.md` §Issue Workflow ③에
  직접 보강했다(PR 링크는 머지 후 갱신). `[완료]` 승급은 그 PR 머지 후.
- **의존** — 트랙 C(협업 canonical 절차).

## R94 이 지도의 진행률 기계 산출 `[실측]`

- **한 줄** — 등급 태그를 파싱해 로드맵 진행률을 기계가 산출한다.
- **지금** — 실측 둘: ① 파서 원형이 #3907 본문 100행 전부를 파싱(결번 0·중복 0,
  [설계 문서](../autonomous_maintenance/progress_machine_readable.md) §2).
  ② 트랙 문서 전수 파서 `tools/roadmap_progress.py`(#4107)가 첫 실행에서 README
  손집계와 정확히 일치(28·7·7·7·51=100)를 재현, README 집계를 기계 생성 블록으로
  대체. 이슈 본문 검증(V3~V5 증거 토큰)은 P1(완료 정의 합의) 대기.
- **설계** — 등급 태그(`[완료]`/`[실측]`/`[문서]`/`[이슈]`/`[가설]`)를 전 트랙
  문서에서 파싱해 대시보드로 집계한다. 태그 형식이 안정이어야 파싱이 성립하는데,
  **이 문서 세트가 그 형식의 원천**이므로 형식 안정이 선행 조건이다.
- **착수 게이트** — 태그 형식이 안정(이 문서 세트가 그 형식의 원천).
- **DoD** — 파서가 전 트랙 문서의 태그를 집계해 README 손집계와 일치하고, 손집계를
  대체한다.
- **의존** — 이 문서 세트(트랙 A~J)의 태그 형식 안정.

## R95 드리프트 자동 감지 → 이슈 자동 기안 `[가설]`

- **한 줄** — 드리프트를 감지하면 이슈 초안을 자동 기안한다(사람 승인 게이트 유지).
- **지금** — 트랙 A R10(L1 완결 메타 가드)이 드리프트를 감지하는 방향이지만,
  감지 → 이슈 초안 자동화는 없다 — 감지 결과가 CI 로그에만 남고 이슈로 이어지지
  않는다.
- **설계** — R10 이 감지한 드리프트를 이슈 초안으로 자동 기안한다. **사람 승인
  게이트 필수** — 봇은 초안까지만, 개설·확정은 사람이 한다(Hyper-Waterfall 의
  통제권은 사람에 남긴다).
- **착수 게이트** — 트랙 A R10(L1 완결 메타 가드)이 드리프트를 이미 감지하므로,
  그 산출을 이슈 초안으로 잇는다 — R10 선행.
- **DoD** — 드리프트 발생 시 이슈 초안이 자동 생성되고, 사람 승인 없이는 개설되지
  않는다.
- **의존** — 트랙 A R10.

## R96 야간 자율 정비 사이클 `[가설]`

- **한 줄** — 야간에 봇이 자율로 정비 사이클(가드 그린 유지·캡 준수)을 돈다.
- **지금** — R91 봇은 실버그 탐색이 중심이다. 정비 사이클(가드 상태 점검·캡 준수·
  드리프트 환류)의 야간 자율화는 미구현이다.
- **설계** — 가드 그린 유지와 캡 준수를 야간 사이클로 묶는다. R91(봇 안정)과
  R95(자동 기안)가 부품이다 — 봇이 정비를 돌리고, 처리 못 할 것은 이슈 초안으로
  환류한다.
- **착수 게이트** — R91 봇 안정 + R95 자동 기안.
- **DoD** — 야간 사이클이 가드 상태를 점검하고, 캡을 넘지 않으며, 이상을 이슈
  초안(R95)으로 환류한다.
- **의존** — R91, R95.

## R97 릴리스 노트 자동 작성 `[가설]`

- **한 줄** — 저널·diff 를 근거로 릴리스 노트를 자동 작성한다.
- **지금** — 릴리스 노트는 수작업이다. 릴리스 경계(무엇이 한 릴리스인지)조차 버전
  정책이 확정되지 않아 자동화의 기준선이 없다.
- **설계** — 저널·diff 를 근거로 릴리스 노트 초안을 만든다. 릴리스 경계는 버전
  정책(트랙 G R67)과 스키마 레지스트리(트랙 I R83)가 정의해야, 무엇을 한 릴리스로
  묶을지가 기계로 정해진다.
- **착수 게이트** — 트랙 G R67·트랙 I R83(버전 정책·레지스트리)로 릴리스 경계 정의.
- **DoD** — 릴리스 노트가 저널·diff 에서 자동 생성되고, 그 경계가 버전 정책과
  일치한다.
- **의존** — 트랙 G R67, 트랙 I R83.

## R98 자기 치유 문서 `[가설]`

- **한 줄** — 깨진 링크·메타 불일치를 봇이 자동 PR 로 고친다.
- **지금** — `check_markdown_links.py`·`check_document_metadata.py` 가 **검사만**
  한다 — 결함을 잡아 보고하되, 수정은 사람이 한다.
- **설계** — 검사 스크립트가 잡은 것 중 안전 범위(깨진 상대 링크·메타 필드 누락
  등)를 봇이 자동 수정 PR 로 낸다. 안전 범위 밖은 봇이 손대지 않고 이슈로만
  환류한다 — 무엇이 안전 범위인지의 판단이 착수의 핵심이다.
- **착수 게이트** — 자동 수정의 안전 범위(무엇을 봇이 고쳐도 되는지) 판단.
- **DoD** — 안전 범위 내 문서 결함이 봇 PR 로 자동 교정되고, 범위 밖은 이슈로만
  환류된다.
- **의존** — R91(봇 기구), 안전 범위 판단.

## R99 "에이전트 유지보수 모드" 선언 `[가설]`

- **한 줄** — "사람은 판단·방향, 에이전트는 실행 상시"를 공식 모드로 선언한다.
- **지금** — Hyper-Waterfall 방법론(사람이 통제·AI 가 실행)의 극한이다. 선언할
  실물(봇·자동 기안·야간 사이클·자기 치유)이 다수 머지돼야, 선언이 빈말을 면한다.
- **설계** — 사람은 판단·방향, 에이전트는 실행을 상시로 맡는다. R91·R95·R96·R98
  중 다수가 실물로 존재해야 선언이 근거를 갖는다 — 선언은 실물의 요약이지 약속이
  아니다.
- **착수 게이트** — R91·R95·R96·R98 중 다수 머지(선언할 실물 존재).
- **DoD** — 유지보수 모드가 문서로 선언되고, 선언의 각 항목이 머지된 실물(봇·기안·
  사이클·치유)로 뒷받침된다.
- **의존** — R91, R95, R96, R98.

## R100 최종 판정 실험 `[가설]`

- **한 줄** — 신규 에이전트가 매뉴얼 없이 30분 내 첫 유효 PR 을 낸다 — 통과하면
  로드맵의 목표 문장이 사실이 된다.
- **지금** — 로드맵의 목표 문장("새로 온 에이전트가 매뉴얼 없이 30분 안에 첫 유효
  기여")을 판정하는 실험이다. 미실시다 — 트랙 D(발견) 전부가 선행이고, 실험
  프로토콜 자체가 아직 없다.
- **설계** — 신규 에이전트 세션이 매뉴얼 참조 없이 capabilities → manifest →
  explain → 레시피만으로 머지된 PR 을 산출하게 하고, 그 트랜스크립트를 증거로
  남긴다. "어떤 에이전트로, 무엇을 유효 PR 로 판정할지"의 프로토콜 설계가 실험의
  일부다.
- **착수 게이트** — 트랙 D(발견) 전부 + 이 실험의 프로토콜 설계(어떤 에이전트로,
  무엇을 "유효 PR"로 판정할지).
- **DoD** — 실제 신규 에이전트 세션이 매뉴얼 참조 없이 capabilities → manifest →
  explain → 레시피만으로 머지된 PR 1건을 산출하고, 그 트랜스크립트가 증거로
  남는다.
- **의존** — 트랙 D 전부, 그리고 이 트랙의 자율 정비 실물(R91·R95·R96·R98·R99).
