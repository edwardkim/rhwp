# R100 공개 실험 프로토콜 — "30분 첫 유효 산출"을 지금 연다 (#4355)

R100(트랙 J 엔드게임)의 판정 문장은 하나다: **"새로 온 에이전트가 매뉴얼 없이
30분 안에 첫 유효 산출을 만든다."** 종전 계획은 하위 트랙 완성 뒤의 최종
실험이었지만, 이 프로토콜은 그 실험을 **탑다운으로 지금 공개**한다 — 완성을
기다리면 측정이 없고, 측정이 없으면 어느 트랙이 진짜 병목인지 끝까지 추정으로
남는다. 실험 자체가 로드맵의 계기판이 된다.

참가 접수·결과 수집처는 [#4355](https://github.com/edwardkim/rhwp/issues/4355)
(상시 개방 이슈)다. 이 문서는 절차의 canonical 이다.

## 1. 실험 조건 (이게 핵심 — 어기면 측정이 오염된다)

- **시작 상태는 하나로 고정한다.** 새 빈 작업 디렉터리, 네트워크 접근, `git`,
  저장소 URL만 있는 상태에서 시작한다. 저장소 checkout, `rhwp` 실행 파일, build
  산출물, 언어별 package, warm cache는 미리 두지 않는다. 참가자에게 release
  binary를 따로 주는 경로는 이 실험에 섞지 않으며, 필요하면 별도 cohort와 별도
  프로토콜로 측정한다.
- **참가자 전달 패키지를 고정한다.** 진행자는 참가 준비를 확인한 뒤 저장소 URL,
  T1~T5 중 하나의 자연어 목표, 입력 파일, 산출물 제출 위치만 한 번에 전달한다.
  이 문서·아래 판정표·명령 이름·flag·예상 JSON key·검증 명령·정답 예시는 주지
  않는다. 참가자가 시작 뒤 저장소와 실행 파일에서 스스로 발견한 README,
  `llms.txt`, `--help`, `capabilities`는 허용된다. 진행자의 추가 힌트나 외부 해법
  링크를 받으면 그 회차는 "안내됨"으로 분리하고 1차 무안내 집계에서 제외한다.
- **측정 시작점과 종료점을 고정한다.** `t0`는 참가 준비 확인 뒤 진행자가 위
  전달 패키지를 보낸 시각이다. 그 전에는 명령·GUI·네트워크 탐색을 시작하지
  않는다. clone, 의존성 취득, build/install, 탐색과 추론을 모두 시간에 포함한다.
  `t1`은 참가자가 산출물과 판정 증거를 제출하고 진행자가 §2 기준으로 유효함을
  확인한 시각이다. 첫 제출이 무효면 시계는 계속 돌며, 30분에 유효 산출이 없으면
  미완주로 끝낸다.
- **사람+에이전트 페어 참가 허용** — 사람은 고정 전달 패키지를 중계하고 산출물을
  제출하는 역할만 맡는다. rhwp 지식, 명령, 탐색 방향을 주입하면 그 회차는
  "안내됨"으로 표기해 별도 집계한다.

## 2. 진행자용 과제·판정표 (참가자에게 전달 금지)

참가자에게는 `과제` 열의 목표만 자연어로 전달한다. `유효 산출 판정` 열은 진행자가
`t1`을 판정하기 위한 비공개 기준이며, 명령 이름이나 기대 봉투를 힌트로 주지 않는다.
전부 저장소 실물로 검증 가능하다.

| # | 과제 | 유효 산출 판정 | 난이도 |
|---|---|---|---|
| T1 | 임의 HWP 1개의 쪽수·형식·표 개수를 기계 출력으로 보고 | `info --json` 봉투 값과 일치 | ★ |
| T2 | 문서에서 특정 문자열이 "몇 쪽 어디"인지 찾기 | `search --json` 결과와 일치 | ★ |
| T3 | 서식 문서의 누름틀을 채워 저장하고 스스로 검증 | 저장본 `--verify` 통과 봉투 제시 | ★★ |
| T4 | 문서 1개를 Markdown 으로 변환해 표가 살아 있음을 보이기 | 변환물의 표 행·열이 원본 `export-tables` 와 일치 | ★★ |
| T5 | MCP 호스트에 rhwp 를 붙여 세션으로 열고 3회 이상 왕복 | 호스트 로그의 `initialize`→도구 호출 기록 | ★★★ |

과제는 "기여"가 아니라 **사용**부터 잰다 — R100 원문의 "첫 유효 기여" 이전
단계인 "첫 유효 산출"을 1차 관문으로 낮춘 것이며, 사용 5종이 30분 안에 되는
날 "기여 30분" 실험(코드/문서 PR 1건)을 2차로 연다. 낮춘 사실 자체를 숨기지
않는다.

## 3. 결과 보고 양식 (#4355 코멘트)

```
에이전트/모델: (예: Claude Code / GPT-x / 사람+페어)
시작 상태: 빈 작업 디렉터리 + git + 저장소 URL (고정)
호스트/이미지: (OS·버전, preinstalled 도구, cache가 비어 있음을 기록)
과제: T#
소요: mm:ss (고정 전달 패키지 전송 t0→진행자 유효 판정 t1)
완주: 예/아니오
막힌 지점: (정확히 어느 단계에서 무엇이 없거나 틀렸나 — 없으면 "없음")
산출물: (봉투/로그/링크)
안내 여부: 무안내 | 안내됨 (추가 힌트·외부 해법을 사용했다면 내용을 기록)
```

## 4. 환류 규약

- **막힌 지점 1건 = 이슈 1건** — 해당 트랙(A 봉투 / B 가드 / D 발견 / H MCP)
  으로 분리하고, 이 문서 §5 대장에 행을 남긴다.
- 완주 사례는 온보딩 사례집(`onboarding_cases_2026h2.md` 계열)에 등재한다.
- 회차 N 이 쌓이면 중앙값 소요·완주율을 §5 에 집계한다 — R100 게이트("30분")
  판정은 이 실측으로만 한다(선언 금지).

## 6. 하지 않는 것

- 참가 에이전트 선별·홍보 문구로의 왜곡 — 실패 회차도 그대로 대장에 남는다
  (실패가 로드맵의 연료다).
- 이 문서를 참가자에게 배포 — §1 조건 위반.
- 서로 다른 시작 상태(사전 clone, release binary 지급, warm cache)를 같은 대장에
  섞기 — 별도 cohort와 프로토콜로 분리한다.
- "30분 달성" 선언 — 판정은 §5 집계만 한다.
