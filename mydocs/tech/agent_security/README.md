# 에이전트 보안 문서 지도

`mydocs/tech/agent_security/`는 rhwp가 **에이전트 도구로서 노출하는 보안 표면**을 다룬다.
파서 견고성(패닉·메모리 안전)이 아니라, **문서 내용이 에이전트의 행동에 영향을 미치는 경로**가
이 축의 주제다.

## 왜 이 축이 생겼는가

rhwp는 문서 엔진에서 **에이전트 도구**로 성격이 바뀌었다([#3630](https://github.com/edwardkim/rhwp/issues/3630),
[#3719](https://github.com/edwardkim/rhwp/issues/3719)). 그 순간 위협 모델도 바뀌었는데 문서가
따라가지 않았다.

- **문서 엔진일 때** — 최악은 파싱 크래시다. 패닉을 막으면 된다.
- **에이전트 도구일 때** — 최악은 **문서가 에이전트를 조종하는 것**이다.

```
공격자가 만든 .hwp  →  rhwp export-text --json  →  에이전트 컨텍스트
                                                       ↓
                                    문서에 심긴 문장을 도구의 지시로 오인
```

에이전트는 **도구가 준 것을 신뢰**한다. 그게 도구 표면의 기본 계약이기 때문이다. 그런데 rhwp가
주는 텍스트의 출처는 **공격자가 만들 수 있는 파일**이다. 이 간극이 이 축이 다루는 공백이다.

## 이 축이 고정하는 계약

다섯 가지가 이 축 전체를 관통한다. 개별 문서의 결론은 모두 여기서 파생된다.

**① rhwp는 탐지하고 보고한다. 판단은 소비자가 한다.**
문서 텍스트를 조용히 고치지 않는다. 몰래 바꾸면 사용자는 원문을 봤다고 믿는데 아니다 —
그것대로 거짓말이다. 지우는 것은 사용자가 **명시적으로 부르는 별도 명령**의 일이고, 이 축의
탐지 명령은 그 일을 하지 않는다.

> [!NOTE]
> **현재 `rhwp edit`의 하위 명령은 `fill-fields`·`replace-text`·`set-cell` 3종뿐이다**
> (2026-08-02 실측). 개인정보 마스킹 명령(`edit redact`)은 [#3719](https://github.com/edwardkim/rhwp/issues/3719)
> §6-11로 **설계된 것이고 아직 없다.** 이 축의 문서는 "지우기는 별도 명령의 책임"이라는
> **역할 분리**를 말하는 것이지, 그 명령이 이미 있다는 뜻이 아니다.
> 현재 동작은 항상 `rhwp edit`와 `rhwp capabilities`로 확인한다.

**② 봉투는 출처를 밝힌다.**
어떤 필드가 문서에서 왔는지를 **기계가 읽을 수 있게** 표시한다. 에이전트가 "이건 데이터지
지시가 아니다"를 판별할 방법이 있어야 한다.

**③ 도구가 만든 값과 문서에서 온 값을 섞지 않는다.**
`nextCall`·`didYouMean`·산출 경로·`docId`는 문서 내용에서 파생되지 않는다.

**④ 오탐은 기능 실패다.**
정상 한국 공문서에서 헛울리면 아무도 안 쓴다. **안 쓰이는 방어는 방어가 아니다.**
근거는 [탐지·오탐 정책](detection_policy.md)에 있다.

**⑤ rhwp에 모델을 넣지 않는다.**
결정론적 규칙만 쓴다. LLM으로 LLM 공격을 막지 않는다.

## 보장하지 않는 것

과장은 보안 문서의 가장 흔한 실패다. 못 하는 것을 먼저 적는다.

- **완전 탐지를 보장하지 않는다.** 인젝션은 자연어이고 규칙은 유한하다.
- **소비 에이전트의 안전을 보장하지 않는다.** 봉투를 무시하면 rhwp가 할 수 있는 것이 없다.
- **암호·서명 검증이 아니다.** 문서의 진위 확인은 이 축의 범위 밖이다.
- **샌드박싱이 아니다.** rhwp는 호출자 권한으로 동작한다.

각 항목의 상세한 경계는 [위협 모델](threat_model.md)에 있다.

## 구현과의 관계

**이 문서 축이 계약이고, 코드가 그 구현이다.** 충돌하면 문서를 고치고 코드를 맞춘다
([`CLAUDE.md`](../../../CLAUDE.md)의 canonical 규칙과 같다).

- 계약과 근거: 이 축 (로드맵 [#3793](https://github.com/edwardkim/rhwp/issues/3793))
- 구현: [#3787](https://github.com/edwardkim/rhwp/issues/3787) S1~S10

구현이 진행 중인 항목은 각 문서에서 **"설계된 것"으로 명시**한다. 아직 없는 필드를 있는 것처럼
쓰면 그 문서는 즉시 거짓말이 되므로, 현재 동작은 항상 `rhwp capabilities --json`과
`--help`로 재확인한다.
