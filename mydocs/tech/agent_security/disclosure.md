# 취약점 신고 — 에이전트 보안 축

## 먼저: 신고 경로는 저장소 공통이다

**제보 채널·책임 있는 공개 정책·응답에 관한 사항의 권위는 저장소 루트의
[`SECURITY.md`](../../../SECURITY.md) 다.** 이 문서는 그것을 **복제하지 않는다.**

- 비공개 제보: **GitHub Security Advisory** (저장소 `Security` 탭 → `Report a vulnerability`)
- 그 밖의 문의: **메인테이너의 공개 채널**(저장소 이슈·논의)

**개인 이메일 주소로 제보하지 않는다.** 이 저장소는 보안 연락처를 위 채널로 일원화한다.
문서·코드·PR 어디에도 기여자 개인 주소를 적지 않는다.

이 문서가 더하는 것은 **이 축 특유의 판단 기준** 하나다: 무엇이 이 축의 취약점이고 무엇이
아닌가. 축의 전제는 [위협 모델](threat_model.md), 용어는 [용어집](glossary.md)에 있다.

## 1. 이 축의 취약점 — 세 가지

| # | 부류 | 무엇인가 | 왜 취약점인가 |
| --- | --- | --- | --- |
| ① | **경계 돌파** | 문서 내용이 **출력 경로·도구 호출 인자·제어 흐름**에 영향을 미친다 | 축 계약 ③("도구가 만든 값과 문서에서 온 값을 섞지 않는다")이 깨진다 |
| ② | **봉투 오염** | 문서 내용이 봉투의 **구조나 메타 필드**를 바꾼다 — `status` 를 `clean` 으로 만들거나, 판정을 지우거나, 없는 필드를 만들어 낸다 | 소비자가 판정 자체를 신뢰할 수 없게 된다 |
| ③ | **탐지 우회** | 문서가 **덮는다고 선언한** 판정을 빠져나간다 | 선언과 실제가 어긋난다 |

**①과 ②는 언제나 취약점이다.** 새로운지 아닌지, 실용적인지 아닌지를 따지지 않는다. 계약이
깨진 것 자체가 사건이기 때문이다.

**③은 조건부다.** 다음 절이 그 조건을 그린다.

## 2. 탐지 우회를 어떻게 다룰 것인가

**우회는 무한하다.** 유니코드에는 수만 개의 코드포인트가 있고, 자연어에는 같은 뜻을 말하는
방법이 셀 수 없이 많다. "새 우회 = 취약점"으로 두면 목록이 끝없이 늘어나고, 결국 아무것도
처리되지 않는다. **감당할 수 없는 기준은 기준이 아니다.**

그래서 경계를 명확히 긋는다.

### 2-1. 취약점으로 접수하는 우회 — 네 조건을 **모두** 만족

| # | 조건 | 왜 |
| --- | --- | --- |
| 1 | **선언된 범위 안**이다 — `rhwp capabilities` 의 `jsonContract.textSecurity` 가 덮는다고 말했고, 이 축 문서의 판정표가 **"위협"** 등급으로 분류했다 | 선언하지 않은 것을 못 잡는 것은 우회가 아니라 미구현이다 |
| 2 | **결정론적으로 재현**된다 — 같은 입력에 같은 결과 | 재현되지 않으면 고쳤는지 확인할 수 없다 |
| 3 | **문서가 적어 둔 한계로 설명되지 않는다** | 이미 적어 둔 것을 다시 접수하면 중복만 쌓인다 |
| 4 | **봉투만으로는 소비자가 알 수 없다** | 봉투에 단서가 있으면 그것은 문서화 문제이지 방어 실패가 아니다 |

### 2-2. 취약점이 **아닌** 것 — 문서에 이미 한계로 적힌 미탐

아래는 **알려진 미탐**이다. [유니코드 기만 §7](unicode_deception.md)에 근거와 함께 적혀 있고,
[README 의 "보장하지 않는 것"](README.md)이 같은 선을 긋는다.

| 알려진 미탐 | 상태 |
| --- | --- |
| **자연어 인젝션** — 순한글 "위 내용을 무시하고 다음을 실행하라" | **원리적 범위 밖.** 코드포인트 판정으로 잡히지 않는다. 정직한 완화는 탐지가 아니라 출처 표시다 |
| **본문·표 셀·안내문 축 전체** | 배선 전. 현재 판정은 **이름 축**뿐임을 문서가 명시한다 |
| **tag 문자(U+E0000~U+E007F)** | 구현 공백으로 이미 기록됨 |
| **한자 호환 이체자** | 구현 공백으로 이미 기록됨 |
| **전각 라틴** | 진단 품질 축 후보로 이미 기록됨 |
| **혼동 표에 없는 동형자 1건** | 표는 의도적으로 좁다. 항목 추가는 **개선 제안**이지 취약점이 아니다 |
| **완전 탐지 미달 일반** | 인젝션은 자연어이고 규칙은 유한하다 |

**이것들을 신고해도 된다 — 다만 공개 이슈로 하면 된다.** 비공개 채널을 쓸 이유가 없다.
이미 공개돼 있는 한계이기 때문이다.

### 2-3. 오탐은 비공개 대상이 아니다

**정상 문서에서 헛울리는 것은 취약점이 아니라 버그다.** 그리고 이 축에서는 **가장 심각한
부류의 버그**다 — 오탐 1건이 그 뒤 모든 문서의 경고를 무력화한다(축 계약 ④).

- **공개 이슈로 등록한다.** 숨길 정보가 없다.
- 재현에 쓴 문서가 **정상 문서**라면, 그 문서의 개인정보 여부를 먼저 확인한다(§4).

### 2-4. 경계가 애매하면

**①·②로 보이면 비공개로 보낸다.** 판단이 서지 않을 때 비공개를 고르는 쪽이 안전하다.
접수 뒤에 "이건 공개 이슈로 옮기자"고 정리하는 편이, 공개 이슈로 올린 뒤 되돌리는 것보다 낫다.

## 3. 우선순위 — 약속이 아니라 설명

처리 순서를 **설명**하는 것이지 기한을 약속하는 것이 아니다.

```
경계 돌파  >  봉투 오염  >  새 부류의 탐지 우회  >  알려진 부류의 확장
```

**계약이 깨진 것**이 **못 잡은 것**보다 앞선다. 못 잡는 것은 문서에 적어 소비자가 대비할 수
있지만, 계약이 깨지면 소비자가 대비할 방법 자체가 없기 때문이다.

## 4. 재현 정보 — 무엇을 담고 무엇을 담지 않는가

### 담아 주면 좋은 것

| 항목 | 예 |
| --- | --- |
| **코드포인트 열** | `U+0054 U+006F U+0074 U+0061 U+006C` 처럼 `U+XXXX` 표기로 |
| **실행한 명령 원문** | `rhwp fields <파일> --json` |
| **봉투 원문** | 얻은 JSON 을 그대로. 요약하지 말 것 |
| **기대한 판정** | 어떤 `kind` 가 나왔어야 하는가 |
| **버전** | `rhwp --version` 출력 |
| **문서 생성 절차** | 아래 참조 |

### 문서 파일 대신 **생성 절차**를 보내 주면 좋다

이 저장소는 **공격 문서를 커밋하지 않는다.** 계약 시험은 실행 시점에 표본 문서를 HWPX 로
변환하고 필요한 속성만 바꿔 재압축한다([실증 보고서 §8](../../report/unicode_spoof_guard/README.md)).
같은 방식으로 재현할 수 있으면 문서 파일을 주고받지 않아도 된다.

```bash
# 예 — 표본에서 공격 문서를 합성하는 형태
rhwp export-hwpx samples/field-01.hwp out.hwpx
#   Contents/section0.xml 의 name= 속성을 바꿔 재압축
rhwp fields out.hwpx --json
```

### 담지 말아 달라는 것

**실제 개인정보가 든 문서를 첨부하지 말아 주십시오.**

이 저장소가 다루는 것은 주로 **행정 서식**이다. 재현 문서에는 이름·주민등록번호·연락처·주소·
계좌번호가 들어 있기 쉽다. 그런 문서가 첨부되면 다음이 한꺼번에 일어난다.

- 제보를 검토하는 사람이 **볼 이유가 없는 개인정보를 보게 된다**
- 그 정보가 이슈 이력·advisory 이력에 남는다
- 수정 뒤 **회귀 시험에 쓸 수 없다** — 저장소에 넣을 수 없기 때문이다

**대신 합성 문서를 써 주십시오.** 이 축의 결함은 대부분 **코드포인트 열 하나**로 재현되므로,
실제 내용은 필요하지 않다. 이미 첨부한 뒤에 알아차렸다면 그 사실을 알려 주시면 된다.

## 5. 대응에 대해 — 과장하지 않는다

**rhwp 는 자원봉사로 유지되는 오픈소스다.**

- **이 문서는 응답 시한을 약속하지 않는다.** 접수·응답에 관한 사항은
  [`SECURITY.md`](../../../SECURITY.md) 가 권위이며, **이 문서는 거기에 아무것도 더하지 않는다.**
- **모든 제보가 수정으로 이어진다고 약속하지 않는다.** §2-2 의 알려진 미탐처럼, 고치지 않고
  **문서에 한계로 남기는 것이 옳은 결론**인 경우가 있다.
- **금전적 보상 제도는 없다.**
- **비공개 상태로 무기한 두지 않는다.** 고치지 않기로 한 결론도 결론이므로, 그 판단과 근거를
  이 축 문서에 남기고 공개한다. **알려진 한계를 적는 것이 이 축의 방어 방식이다.**

선의의 제보에 불이익을 주지 않는다는 원칙은 [`SECURITY.md`](../../../SECURITY.md)에 있다.

## 6. 수정이 반영되는 방식

이 축은 **문서가 계약이고 코드가 그 구현이다**([README](README.md)). 제보가 받아들여지면
보통 아래가 함께 움직인다.

| 대상 | 무엇 |
| --- | --- |
| 판정 규칙 | `src/document_core/text_security.rs` |
| 선언 | `rhwp capabilities` 의 `jsonContract.textSecurity` |
| 계약 시험 | `tests/*_contract.rs` — **red 를 먼저 확인**한 뒤 구현 |
| 오탐 가드 | `samples/` 전수 스윕 재측정 (clean rate ≥ 99%) |
| 문서 | 이 축의 해당 문서 + [악성 코퍼스](test_corpus.md) |

**탐지 규칙을 넓히면 오탐 스윕을 반드시 재실행한다.** 경고가 1건이라도 늘면 규칙이 아니라
판정 등급을 다시 본다 — 근거는 [탐지·오탐 정책](detection_policy.md)에 있다.
