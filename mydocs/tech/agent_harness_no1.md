# 검증 하네스 1등 선언 — 형용사가 아니라 축 개수로

- 이슈: [#4537](https://github.com/edwardkim/rhwp/issues/4537) · 주도 계측:
  [#4535](https://github.com/edwardkim/rhwp/issues/4535)

## 1. 주장의 정확한 형태 (정직 조항 먼저)

우리가 주장하는 1등은 **인지도·채택의 1등이 아니다** — 그것은 도달 캠페인이
앞으로 만들 몫이고, 지금 주장하면 거짓이다. 주장은 이것이다:

> **"검증 가능한 에이전트 노동"의 완비도에서, 아래 10축을 한 도구에 전부
> 갖춘 공개 문서 하네스는 확인된 바 없다.**

외부 비교는 원리로만 말한다(개별 프로젝트 명명 비교는 하지 않는다 — 이
저장소의 산출물 규약). 반례가 나타나면 이 문서가 수정되는 것이 규약이다:
반증 가능해야 주장이다.

## 2. 완비도 10축 — 전부 이 저장소에서 실측 가능

| # | 축 | 실체 | 판정 명령/가드 |
|---|---|---|---|
| 1 | 결정론 실행 | 같은 계획 = 같은 바이트 (교차: run↔replay) | replay 계약 테스트 |
| 2 | 작업 영수증 | 입력·계획·산출 3해시, attest/verify | `replay` |
| 3 | 자기완결 캡슐 | 계획+영수증 교환 파일 | `replay --capsule` |
| 4 | 해시 체인 계보 | 부모 파일 해시 + 산출=입력 불변식 | `lineage` |
| 5 | 서명 귀속 | Ed25519 분리 서명·키 등록부·폐기 | `verify-signature` |
| 6 | 전수 감사 | 폴더 재현율 회계 | `audit` |
| 7 | **루프 단일 명령** | 실행+영수증+캡슐+자동 체인+서명 한 방, 통합 판정 | `harness wrap/status` (이 PR) |
| 8 | 운동장 | 실문서 과제 12종·라이브 오라클 채점 | gym (PR #4465) |
| 9 | 살아있는 교본 | 실봉투 자동 생성 대전 + 멱등·커버리지 가드 | codex (PR #4534) |
| 10 | 표류·부패 가드 | 스킬↔CLI·문서↔바이너리·버전 단일 출처 | skills/codex/registry 가드 |

축 7이 이 PR 의 기여다: 축 1~6이 있어도 **에이전트가 매 작업마다 도는
루프**가 명령 5개 조합이면 하네스가 아니라 부품함이다. `harness wrap` 은
그 조합을 한 호출로 접고(직전 캡슐 자동 부모 연결 — 체인이 스스로 자란다),
`harness-status` 는 작업장 전체를 한 봉투로 판정한다 — 쓰기가 없어
쓰기 명령(harness)과 표면을 나눈 읽기 전용 명령이다.

## 3. 30초 사용 (하네스의 전부)

```bash
rhwp harness init 작업장 --key-id org.example/agent-7#2026
rhwp harness wrap --plan @계획1.json --dir 작업장 --sign-key 작업장/harness.key.json
rhwp harness wrap --plan @계획2.json --dir 작업장 --sign-key 작업장/harness.key.json
rhwp harness-status 작업장 --keyring 작업장/keyring.json --deep --json
# → { capsules: 2, chainValid: true, signed: {valid:2}, reproduced: {ok:2}, verdict: "ok" }
```

매 작업 = wrap 한 줄. 체인·서명·재현이 전부 자동이고, 판정은 언제나 exit 3
데이터다.

## 4. 주도 계측과의 결합

이 완비도가 누구의 작업량 위에 서 있는지는 감정이 아니라
`tools/agent_dominance_metrics.py` 가 산출한다 — 2026-08-11 스냅샷: devel
병합 기준 에이전트 축 추가 줄 77%(53,420/69,039)·커밋 58%(145/251), 경로군
7종 전부 과반. 완비도(무엇이 있는가)와 주도(누가 만들었는가)를 분리 계측하는
것 자체가 이 하네스의 방법론이다.

## 5. 남은 정직한 격차 (1등 주장이 덮지 않는 것)

- **채택**: 다운로드·스타·외부 사용 실적은 아직 없다 — 도달 캠페인의 미완
  과제이며, 이 문서는 그것을 숨기지 않는다.
- **범용성**: 이 하네스는 문서 작업 도메인 위에 서 있다. 범용 오케스트레이션
  프레임워크와의 비교는 범주 오류다 — 우리의 축은 "노동의 검증 가능성"이다.
- **표준화**: 캡슐·체인 형식은 아직 이 저장소의 규약이다. 감사 표준(10년
  축)과 연합(7년 축)이 그 다음 단이다.
