# 폰트 차이 RMSE 보정 측정 방법론

작성일: 2026-05-15
관련: [#885](https://github.com/edwardkim/rhwp/issues/885), [#696](https://github.com/edwardkim/rhwp/issues/696)

## 1. 배경

rhwp 의 시각 정합성을 한컴 변환 PDF 와 픽셀 RMSE 로 측정할 때, **글리프 모양 차이가 RMSE 의 대부분을 차지**하여 레이아웃 본질 결함이 가려진다.

Task #885 측정 결과 (samples/table-in-tbox.hwp p1):

| 측정 | RMSE |
|------|------|
| 전체 픽셀 RMSE | 26.8% |
| 메트릭 별칭 보정으로 줄어든 RMSE | 0.07 %p |
| 메트릭 보정 후 SVG 변화량 (Before vs After) | 3.9% |

→ 픽셀 RMSE 26.8% 중 메트릭으로 보정 가능한 비율은 1% 미만, 나머지는 **글리프 모양 + 색 차이** 영역.

## 2. 분리 측정 절차

본질적 레이아웃 결함을 측정하려면 RMSE 를 다음 세 성분으로 분리한다.

### 2.1 성분

| 성분 | 정의 | 측정 방법 |
|------|------|---------|
| **L (Layout)** | 텍스트 / 객체 의 위치 · 크기 차이 | 텍스트 bbox 일치도 (IoU 또는 중심점 거리) |
| **G (Glyph)** | 글리프 모양 차이 | 같은 글자 · 같은 위치 · 같은 폰트 라이선스 일치 시 0, 폴백 시 가산 |
| **C (Color)** | 색·음영·배경 차이 | 비-텍스트 영역 RMSE |

### 2.2 측정 절차

1. **텍스트 마스크 추출**: rhwp 가 출력한 SVG 의 `<text>` bbox 와 PDF 텍스트 추출 (pdftotext + bbox) 을 매칭하여 글자 영역 마스크 생성.
2. **G 성분 제거**: 텍스트 마스크 영역을 **단일 색으로 채워** 글리프 모양 정보를 지운다. 동일한 마스크를 PDF/SVG 양쪽에 적용.
3. **L 성분 측정**: 마스크 위치/크기 정합도 (IoU) 로 측정. RMSE 가 아닌 IoU 권장.
4. **C 성분 측정**: 텍스트 마스크 외 영역만 RMSE 계산.
5. **G 성분 추정**: 전체 RMSE − (L + C) 로 잔차 추정.

### 2.3 권장 보조 지표

- **MaskedRMSE**: 텍스트 마스크 외 영역만의 RMSE — 표 / 도형 / 배경 색 정합만 측정
- **TextBoxIoU**: 텍스트 bbox 위치 / 크기 정합 — 레이아웃 본질 결함 측정
- **GlyphFreeRMSE**: 양쪽 텍스트를 동일 색 사각형으로 가린 RMSE — L + C 합산

## 3. 본 절차로 측정 시 기대 효과

Task #885 의 측정을 본 절차로 다시 하면:

- MaskedRMSE (텍스트 외): ~5~8% 수준으로 떨어질 것 (배경/표 색 일치 비율 높음)
- TextBoxIoU: 0.9 이상 기대 (레이아웃은 거의 정확)
- GlyphFreeRMSE: ~5~10% 수준

→ "픽셀 RMSE 26.8%" 보다 본질적 결함을 정밀히 추적 가능.

## 4. 구현 권장 (별도 이슈)

- `tools/visual_diff.py` (또는 Rust 보조 바이너리) — SVG bbox + PDF 좌표 매칭 + 분리 측정
- CI 회귀 게이트: MaskedRMSE, TextBoxIoU 기반 (단순 RMSE 대신)

## 5. 사용 시 주의

- **G 성분이 큰 경우** 의 해석: 별칭 폴백 메트릭이 부정확하거나 (옵션 1), 실제 폰트 임베딩이 없거나 (옵션 2) 둘 중 하나. 양쪽 모두 시각 정합에 영향을 주지만, 레이아웃 본질 결함과는 무관할 수 있다.
- **L 성분이 큰 경우**: 줄바꿈, 표 행 높이, 단 폭 등 본질적 레이아웃 결함 가능성이 크다. 우선 조사 대상.
- **C 성분이 큰 경우**: 표 음영, 배경색, 도형 채움 등 색 정합 문제. 별도 분석.
