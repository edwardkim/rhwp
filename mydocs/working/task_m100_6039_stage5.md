# Task M100 #6039 Stage 5 — 상황 선 배율 조작 보정

## 목적

사용자가 제공한 Windows 한글 2024 상태 표시줄 실측을 기준으로 #6039의 확대/축소 조작을 보정했다.
별도 100% 버튼과 분리된 설정 아이콘·배율 표시를 정리하고, 숫자 키패드가 없는 키보드에서도 같은
단축키 계약을 제공하는 것이 목표다.

## 확정 계약

- 상황 선 순서는 `폭 맞춤`, `쪽 맞춤`, `축소`, `배율 가로바`, `확대`, `통합 배율 버튼`이다.
- 통합 배율 버튼은 확대/축소 설정 아이콘과 현재 배율을 하나의 hover·focus·click 영역으로 묶는다.
- 통합 버튼은 68px 고정 폭과 tabular 숫자를 사용해 9%·100%·500% 사이에서도 왼쪽 조작이 움직이지
  않는다.
- 가로바 범위는 10~500%이며, 100%를 정확히 중앙 위치에 두는 구간별 로그 매핑을 사용한다.
- 중앙 근처의 포인터 입력은 100%에 즉시 스냅한다. 문서 렌더를 늦출 수 있는 spring·bounce·지연
  애니메이션은 추가하지 않는다.
- 확대·축소는 macOS에서 `Command +/-`, Windows·Linux에서 `Ctrl +/-`로 실행한다. 호버 안내는 현재
  플랫폼에 맞춰 표시하며, 숫자 키패드 전용 입력에 의존하지 않는다.
- 기존 `Ctrl`/`Command+0`의 100% 복원은 유지한다.

## Test-first 증거

구현 전 focused test에서 다음 실패를 확인했다.

- `src/view/zoom-status-controls.ts` 모듈 미존재
- 10~500% 범위와 중앙 100% 매핑·스냅 계약 미존재
- 상황 선에 별도 `sb-zoom-100`, 설정 버튼, 배율 버튼이 남아 있어 통합 순서 계약 실패
- 문서 최소 배율이 5%여서 한컴의 10% 하한 계약 실패
- 확대·축소 명령과 메뉴의 기존 숫자 키패드 중심 단축키 표기 실패

구현 뒤 배율 매핑의 기준점·왕복, 스냅 경계, 플랫폼별 툴팁, 상태 표시줄 DOM 순서와 명령 매핑을
테스트로 고정했다. 일반 문서 영역의 단축키는 명령 레지스트리를 한 번만 통과하도록 기존 중복
document keydown 경로를 제거했다.

## 브라우저 검증

`http://127.0.0.1:7700/`의 로컬 서버를 macOS 브라우저에서 확인했다.

- 상태 표시줄 호버 안내: `축소 (⌘−)`, `확대 (⌘+)`
- 통합 배율 버튼의 안내: `화면 확대/축소 설정`; 클릭 시 기존 설정 대화상자 열림
- 가로바 원시 위치 510 입력: 중앙 위치 500, `aria-valuetext=100%`, 현재 배율 100%로 스냅
- 가로바 원시 위치 470 입력: 스냅 범위 밖 87% 유지
- `Command+=`: 87% → 97%, 한 번만 실행
- `Command+-`: 97% → 87%
- `Command+0`: 100%, 중앙 위치 500으로 복원
- 100%에서는 중앙 눈금이 thumb 아래 숨고, 다른 배율에서는 중앙 기준선이 노출됨

검증 뒤 배율은 100%로 복원하고 테스트 탭을 닫았다.

## 판단

100% 스냅은 사용자의 드래그 입력을 보정하는 기능이므로 즉시 반영이 가장 예측 가능하다. 별도 모션은
줌 렌더링과 배치 재계산을 추가로 지연시킬 수 있어 적용하지 않았다. `쪽 윤곽`은 배율 조작이 아니라
편집 영역의 용지 경계 렌더 의미를 바꾸는 기능이므로 계속 #6039 비범위로 둔다.
