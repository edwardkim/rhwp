## 판정

Q3-C는 **qualified**다. Q3-B의 canonical variation vector가 dormant `FontInstanceKey.variations`와 exact
variable TTF outline producer까지 같은 identity로 도달한다. default와 Title instance는 outline geometry를
공유하지 않았고, shaping glyph와 outline glyph의 bbox 대사 mismatch는 0이었다.

다만 이 결과는 제품 activation이 아니다. 새 outline과 proof는 crate-private lowering report에만 존재하며
`lower_horizontal_shaping_page_sidecars()`는 계속 기존 GlyphRun만 게시한다. 제품 variation caller도 0이다.
따라서 Q2 layout·render JSON·backend selector 기본 출력은 변하지 않았다.

## replay payload와 fail-closed 경계

1. exact replay certificate와 같은 font bytes·face index를 `ttf_parser::Face`로 다시 열고 Q3-B canonical
   non-default vector를 적용한다.
2. shaping이 결정한 glyph id·cluster·position을 그대로 사용해 glyph별 outline을 만든다. quadratic contour는
   동등한 cubic contour로 변환하고 font의 y-up 좌표는 run-local y-down 좌표로 바꾼다. backend reshaping은 없다.
3. 각 glyph는 `outline_glyph()`와 `glyph_bounding_box()`를 같은 variable face에서 대사한다. 하나라도 다르거나
   outline이 없으면 전체 candidate를 structured reject로 닫는다.
4. outline command는 run당 262,144개로 제한한다. 누적 overflow·비유한 bbox·빈 geometry는 자원 등록 전에
   거절하므로 부분 font resource publication이 남지 않는다.
5. canonical vector는 GlyphRun identity와 outline proof 양쪽에 기록한다. default(empty)와 Title
   (`opsz=900, wght=900`)은 settings identity와 outline bbox가 모두 분리됐다.

새 reject reason은 `variableOutlineUnavailable`, `variableOutlineLimitExceeded`,
`variableOutlineBboxMismatch` 세 가지이며 raw text·font bytes·host path를 포함하지 않는다.

역시 실제 제품 selector를 여는 구현이 아니라 exact-instance construction 가능성만 검증한다.
