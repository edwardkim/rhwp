## 카탈로그 입력의 생성 출처와 캐시 확인

Stage 117의 259종 입력은 HWPX의 수식 크기·기준선·LineSeg를 지운 뒤 RHWP로 HWP를
만들고 한컴 2020에서 저장·Print 출력한 합성 대조군이다. 최초 HWPX만 캐시를 지워도
RHWP 변환이 HWP에 새 합성 LineSeg를 발행한다. 원본 파일을 직접 파싱한 결과에서도
해당 줄의 tag `0x80060000`과 85% 기준선이 관측됐다. 이 진단의 고정 라이브러리는
source `e80207d5f`이며 그 값을 현재 구현 결과로 보고하지 않는다.

예를 들어 문단 185의 3행 EQALIGN은 저장 수식 높이 4800HU·기준선 27%인데 줄의
기준선은 4080HU(85%)다. 문단 186의 4행 EQALIGN도 수식 높이 6450HU·기준선 20%,
줄 기준선 5483HU다. 실제 배치에서는 각각 줄 상단보다 37.12px·55.91px 아래에
수식이 놓인다. 이 px 관측값은 진단 수치이며 회귀 기대값이나 대상 선택 범위가 아니다.
독립 Print에서는 해당 수식이 자기 줄 안에 배치된다. 원점 소비는 저장/합성 줄 기준선 →
`inline_baseline_px`의 수식 기준선 → `eq_y = line_y + line_baseline - eq_baseline`다.
단순 glyph 모양·점수만으로 이 기준선 차이를 면제하지 않는다.

## 원인 분리 사본과 독립 재생성

1. 원본을 보존하고 진단 사본의 수식 전용 줄 높이·기준선만 해당 수식의 저장 메트릭으로
   교체했다. Stage 123 Native와 기존 독립 Print 18쪽을 다시 대조했다. 90% 이상은
   1쪽에서 7쪽으로 늘고 13쪽은 15.51742%에서 89.31738%로 개선됐다. 11쪽은 여전히
   90% 미만이다. 사본의 통과 쪽도 원본 통과로 승격하지 않는다.
2. RHWP 변환 **뒤**에 모든 LineSeg 및 259개 수식의 width/height/baseline을 제거한
   별도 입력을 한컴 MCP 2020에서 다시 저장·Print 출력했다. 저장 job
   `8b2a96f0-9764-45fb-ac3b-65d5c465cac7`, Print job
   `e5352115-2338-4b9d-a7f4-48d37edc0e96`, 실제 11.0.0.9136,
   PrintMethod 0·1-up, PDF 18쪽이다. script·baseUnit·face·본문은 유지했다.
3. 새 HWP와 PDF는 원 입력과 다른 바이트다. 최초 원시 진단에서 조회한 문단 180–195의
   LineSeg는 비어 있다. 이후 259개 수식 전부를 원시 파싱해 수식 크기 캐시는 모두
   발행됐고, 120개 호스트에는 LineSeg가 있으며 139개 호스트에는 없음을 확인했다.
   일부 문단 관측을 문서 전체의 줄 캐시 부재로 확대하지 않는다. 현재 Native는 6쪽,
   독립 Print는 18쪽으로 쪽수가 다르다. TSV 점수를
   만들 수 없으며 측정 불가/쪽수 불일치다. `target hwp`의 성공만으로 한컴이 모든 저장
   줄 캐시를 다시 발행했다고 가정하지 않는다.

원본·사본·재생성 입력/출력과 해시는 ignored `stage124-*`에 각각 보존했다.

## 다음 보정의 계약

수식 전용 줄도 실제 줄 소속 개체의 어센트·하강부와 내용 순서를 보존해야 한다.
기존 scalar 재조판의 `apply_inline_control_line_height`는 커진 개체 높이의 85%를
새 기준선으로 사용하고, frame 재조판은 수식 기준선도 전달한다. 합성 줄을 생성/소비하는
실제 두 경로와 저장 줄 없는 HWP5의 흐름 측정·배치를 대조한 뒤 공통 메트릭으로 보정한다.
원본의 정확한 저장 줄은 유지하며 부적합한 합성 캐시의 무조건 수용이나 문서별 예외를
추가하지 않는다. 원인 미상의 goldens·baseline 갱신은 하지 않는다.

현재 90% 미달 및 측정 불가인 카탈로그에 정식 회귀를 추가하지 않는다. 검증 가능한 독립
