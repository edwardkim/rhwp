# Task M100 #4969 W10-Q2-D5-R0 — resource matrix·counter red 계약 결과

## 판정

Q2-D5-R0은 **qualified-red**다. 기존 page-local resource dedup과 D4 replay 회귀는 유지됐고, 새 계약은
수정 수행계획이 지목한 두 결손에서만 실패했다.

1. 같은 exact source의 font blob·face는 page에서 한 개지만, explicit BLAKE3 digest와 face parse·arena intern
   시도는 run 수에 비례한다.
2. CanvasKit은 이미 받은 inline blob을 한 개만 보존하지만 page마다 같은 456,688B payload가 입력된다. payload를
   생략하고 resource key로 받는 resolver 경계는 아직 소비되지 않는다.

따라서 R1은 unique-source prepared identity만 구현하고, R2의 by-key 전달을 앞당겨 섞지 않는다. R1 결과 승인
전까지 transport와 NO_LS boundary를 변경하지 않는다. 기계 판독 결과는
[`w10_q2_d5_r0_red_contract.json`](../tech/investigations/issue-4969/w10_q2_d5_r0_red_contract.json)에 고정한다.

## Rust 1/2/8 run 계약

`HorizontalShapingGlyphLoweringReport`에 successful attempt만 기록하는 internal-only
`HorizontalShapingPortableSourceWork`를 추가했다. 이 값은 직렬화되지 않고 selector·layer output·fallback을 바꾸지
않는다. arena 내부 fingerprint까지 중복 계산하지 않고 common-shaping lowerer가 직접 소유한 다음 세 작업만 센다.

- explicit BLAKE3 digest pass
- exact face parse attempt
- `ResourceArena` font intern attempt

공개 `SourceHanSerifK-OldHangul-subset.otf`를 같은 page arena에서 1/2/8회 lower한 결과다.

| run | explicit BLAKE3 | face parse | arena intern 시도 | blob | face |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 2 | 1 | 1 | 1 | 1 |
| 2 | 4 | 2 | 2 | 1 | 1 |
| 8 | 16 | 8 | 8 | 1 | 1 |

원하는 구조적 값은 세 작업 모두 `1/1/1`이다. 신규 red는 실제 `2/4/16`, `1/2/8`, `1/2/8`을 한 번에 출력하며
실패했다. 반면 blob·face는 전 구간 `1/1`이라 기존 page-local dedup이 정상임을 동시에 증명했다.

## Studio 1/2/8 page 계약

같은 공개 font payload를 1/2/8 page에서 `CanvasKitGlyphRunFontCache.registerResources()`에 전달했다.

| page | consumer에 제시된 inline bytes | retained blob | retained bytes |
| ---: | ---: | ---: | ---: |
| 1 | 456,688 | 1 | 456,688 |
| 2 | 913,376 | 1 | 456,688 |
| 8 | 3,653,504 | 1 | 456,688 |

이는 CanvasKit 내부 verified cache는 이미 한 blob만 보존하지만 그 전에 page JSON/consumer 경계를 지난 inline
payload는 page 수에 비례함을 보여준다.

동일 cache에 font bytes가 생략된 resource metadata와 resolver를 전달하는 red 계약도 추가했다. 목표는 모든
page count에서 `fetch=1`, `verified blob=1`, transferred bytes `456,688`이다. 현행 메서드는 resolver 인자를
소비하지 않으므로 실제 값은 모든 page count에서 `fetch=0`, `verified blob=0`, transferred bytes `0`으로
실패했다. 이는 잘못된 bytes를 승인한 것이 아니라 by-key capability 자체가 아직 없어서 fail-closed한 결과다.

## R1 입력

R1은 exact source handle과 registry generation을 key로 bounded prepared identity를 둔다. 최초 unique source에서만
digest·face metadata를 준비하고, 같은 page의 다음 run은 그 identity와 face key를 재사용해야 한다. source bytes는
기존 certificate `Arc<[u8]>`를 공유하고 stale generation·digest/length/face mismatch는 resource mutation 전에
거부한다.

R1의 종료 목표는 Rust matrix `[(1,1,1), (1,1,1), (1,1,1)]`, blob·face `1/1`, D4 회귀 0이다. R2의
WASM/Studio API, JSON omission option과 page transport는 R1에서 변경하지 않는다.
