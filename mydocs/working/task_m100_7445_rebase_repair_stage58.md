# #7445 리베이스 보정 58단계: 표 뒤 호스트 줄과 여백의 흐름 복구

## 재검사와 선행 근거

57단계 이후 runtime이 같은 `9ed44276cd654478494f45128bbd6bc910dd06a6`에서 이전 실패
23건을 다시 실행했다. 처음에는 과거 suite 이름으로 14건만 선택됐고 모두 실패했다.
현재 `--prepare` 결과의 모듈 배정을 읽어 빠진 9건만 추가 실행했으며 이들도 모두 실패했다.
합계 23건의 재현이며 전체 회귀를 다시 실행한 결과는 아니다. 과거 suite 번호를 현재 배정으로
간주하지 않는다. 각 명령·로그·현재 배정은 ignored `stage58-regression-recheck/`에 있다.

#5585의 선행 해결은 #7840의 `4cb8c1e1c2`다. 겹친 줄 상자의 정상 전진을 저장 프레임
되감김으로 오인하지 않게 했다. 후속 `e78481fef0`은 같은 커밋된 원본과 독립 7쪽 Print를
사용해 내용 소유·하단선·후속 표 관계를 보호했다. 해당 하단 좌표는 출력 수식에서 가져온 값이
아니므로 현재 실패를 기대값 교체로 처리하지 않는다.

같은 원본·PDF·글꼴 공급·96DPI에서 고정 base `605ccfd9`의 Native 전7쪽 최저는
98.42432%다. 현재 후보의 Native/fresh WASM은 각각 84.62310/84.62378%이며 3쪽만 미달한다.
양쪽 7/7쪽이고 중첩 표 자체의 위치·크기는 base와 같다. 표 뒤 문단 38부터 약7.5px 아래로
이동했고 wrapper 하단도 독립 좌표에서 벗어난다. 변경 전 review와 overlay를 직접 확인했다.
새 HWP 보정 대상을 찾은 것이 아니라 리베이스로 반영된 기존 #7840 검사의 실패를 추적한 것이다.

## 원인과 공통 소비 경로

원본 호스트 문단 37의 줄은 높이1400HU·줄간격-280HU이며 다음 문단 원점 차이는1120HU다.
`block_table_trailing_whitespace_line_hu`가 줄간격을 `max(0)`으로 올려1400HU를 반환했다.
이 값은 마지막 중첩 행의 `terminal_band`와 일반/부분 배치에서 같은 뒤 호스트 줄로 소비된다.
음수 줄간격도 양수 전진을 만들면 유효한 원본 간격이며 버릴 근거가 없다. 합산 overflow 또는
비양수 전진은 반환하지 않는다.

부분 배치의 `nested_y → table_h_rendered/visible_table_h → para_y`도 추적했다.
반환된 표 높이는 바깥여백을 포함하는데, 뒤 호스트 줄을 더하면서 아래 바깥여백을 다시 더했다.
후보는 같은 호스트 줄의 실제 전진만 추가한다. 표 원점·쪽수 기대값·원본·PDF·허용치는 바꾸지
않는다. 문서 ID나 페이지 번호로 적용 범위를 제한하지 않는다.

## 집중 검사와 Native 결과

fmt 뒤 suite를 다시 준비하고 기존 #5585·#4138 분할/자식 소유·#5966 검사를 현재 모듈 배정으로
실행했다. 14건 중13 PASS·1 FAIL, 7.898초다. 기존 #5585의 세 검사와 #4138의115/197쪽·
본문/그림 소유 검사는 통과했다. #5966의143/142쪽 불일치만 이 묶음에서 계속 실패한다.
이 결과를 전체 회귀나 남은 실패의 복구로 확대하지 않는다.

새 Native 빌드는126초에 종료 코드0으로 완료했다. 동일 원본 전7쪽은7/7쪽·미달0·
최저98.11680%다. 3쪽은84.62310→98.68155%로 복원됐고 다른6쪽 PNG SHA는 변경 전과
같다. 전7쪽의 TextRun 원문·순서도 동일하다. 3쪽 review와 overlay를 직접 열어 표 뒤 본문과
wrapper 하단의 복원을 확인했다. 글꼴 획 차이까지 해결했다는 주장은 아니다.

같은 소스의 Mac locked web/no-opt fresh WASM 빌드는228.729초·종료 코드0으로 완료했다.
원본7쪽의 새 WASM도7/7쪽·미달0·최저98.22942%이며 3쪽은84.62378→98.68225%다.
WASM 3쪽 review와 overlay를 직접 판독했고 Native와 같은 본문·하단 복원을 확인했다.
root pkg·Studio public·frozen package의 JS/WASM 해시가 각각 같다. 실제 Studio 초기화
응답은 아직 재검증하지 않았다. manifest·unit tiers 검사도 통과했으며 58단계는 검사 함수나
기대값을 바꾸지 않았다.

전후 TSV와 대표 PNG는 [host-flow 자산](../pr/assets/issue7445/completed-20261009/rebase-605ccfd9-20261022/host-flow/README.md)에 보존한다.
다른 완료 문서 영향 검증, 남은 실패·필수 게이트는 계속 진행한다. 아직 PR 준비 완료가 아니다.
로그·진단 원본은 ignored `stage58-wrapper-frame/`, `stage58-host-flow-fix/`,
`stage58-franchise-diagnostic/`에 보존한다. `git ls-remote`로 확인한 upstream/devel도 같은
`605ccfd9`여서 중복 리베이스는 하지 않았다.
