# Issue #7642 단계 800: 저장 TAC 축과 떠 있는 표 뒤 호스트 줄의 공통 소비

## 직전 후보의 확인 결과

- 후보 `099ae279f`의 단계 794에서 이미지 채우기 6쪽 Native 일치율은 **98.80080%**였다. 앞 후보의 잘못된 원점 인증을 수정한 뒤 사례 2·3의 표와 후속 본문 위치를 독립 Print PDF와 review PNG로 직접 대조했다. 전체 문서 통과나 새 px 회귀의 선행 조건으로 대신하지 않는다.
- 단계 796에서 관련 9개 입력·187쪽 Native TSV를 산출했다. 앵커 원본·저장본, 도형 원본·저장본, 임대차 서식, 상자 번호 서식, 보도자료 7개 입력은 전쪽 90% 이상이었다. 이미지 채우기는 1쪽 86.33166%, HWPML은 3·36·37·38·45·57·68쪽이 미달이며 최저 48.94168%였다. 이 후보의 fresh WASM은 단계 795의 새로운 package로 별도 검증한다.
- 원래 요청된 55개 문서·853쪽은 후보의 Native 전쪽 산출을 단계 801에서 진행 중이다. fresh WASM과 실제 `a5e88ad68` 기준 producer·비교도 별도로 준비했다. 미완료 대기열을 완료 결과로 세지 않는다.

## 독립 근거와 실제 소비 경로

### 본문 내용 하단과 저장 TAC 축

HWPML 36쪽의 표 223은 첫 제목 뒤 원본 축을 따라 배치됐다. 다음 제목 226의 원본 줄과 실제 paint 위치도 같은 축이지만, 조판은 표 뒤 `vpos_page_base`를 지워 `stored_content_bottom`이 순차 누적 높이로 돌아갔다. 단계 783에서 표 227의 저장 원점은 324.08px, 조판이 직전 내용 끝에서 연결한 원점은 312.02667px였다. 같은 표의 잘못된 위치를 판정할 때 사용한 관측값이며 조건으로 고정하지 않는다.

`accepted_tac_column_frame`는 초기 수용 문단의 실제 저장 앞 간격 또는 초기 표의 확정 pen과 원본 축을 대조한다. 이어서 현재 단의 원본 줄 유효성·순서를 확인하고, 모든 표가 같은 축에 발행한 `InlineBoxPlacement`의 원점·점유 끝을 대조한다. 부분 조각·독립 도형·재조판 줄·다른 축은 이 복원 경로로 인증하지 않는다. 이 결과를 본문 내용 하단 측정과 뒤 TAC의 진입 계산에 전달한다. 표의 선언 높이만으로 흐름 축을 복원하지 않는다.

### 떠 있는 표 뒤의 빈 호스트 줄

이미지 채우기 1쪽에서 빈 줄 14의 저장 끝은 51718HU다. 표 15의 본체 3397HU와 세로 오프셋 433HU를 더하면 호스트 줄 원점 55548HU가 된다. 호스트 줄 높이 1000HU와 뒤 간격 980HU를 더하면 뒤 TAC 16의 원점 57528HU와 정확히 닫힌다. 독립 Print PDF는 큰 파란 띠 뒤에 이 호스트 줄 공간을 두지만, 직전 후보는 다음 표를 띠에 겹쳐 배치했다. 파란 띠의 채움 모양 차이도 별도로 남아 있다.

기존 `stored_table_before_host_frame`의 앞·표·호스트·뒤 원본 줄 계약을 재사용한다. 뒤 항목이 원본 줄 전체를 소유한 TAC 표인 경우에도 그 줄 원점을 확인한다. 단 앞 장식 때문에 전역 축 조회가 불가능해도, 실제 직전 완전한 본문 항목과 저장된 상대 간격이 닫는 로컬 프레임은 수용할 수 있다. 물리 표 하단, 뒤 호스트 줄 원점, 뒤 줄 전진 끝을 구분해 발행하고 예산은 뒤 호스트 줄까지 확인한다. `ParagraphFloatPlacement::paragraph_end`도 인증된 뒤 줄 끝을 소비해 빈 호스트 줄의 실제 공간을 빠뜨리지 않는다.

## 검증 상태

이 단계의 변경은 두 원인 계층을 한 배치로 적용한 새 후보다. 구현 후 개선·회귀 통과를 아직 판정하지 않았다. 공유 target의 실제 devel producer 빌드가 끝난 뒤 새 후보를 순차 빌드한다. 미달 쪽과 직접 반례, 대조군의 전체 쪽수·Native/fresh WASM TSV·확대 판독 및 기준 대비 하락을 다시 확인한다. 전체 회귀·필수 lint와 PR 직전 기준 헤드 재확인을 완료한 다음 사용자 지시의 코드 PR → CI → 옵션 2의 별도 review·오늘할일 PR → 머지·후속 처리로 진행한다.
