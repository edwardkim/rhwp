# 원본 첫 조각의 원점과 실제 수용 행 높이의 공유

## 수정 전 관측과 독립 근거

PR #8530의 `samples/issue8529/rowbreak_exact_fit.hwpx`와 기존 독립 한컴 Print
`pdf/issue8529_rowbreak_exact_fit-2020.pdf`를 대조했다. 원 PR은 정확히 맞는 컷의 부동소수
잡음을 보정해 `[2, 3]` 유닛을 첫 쪽에 수용하며, 3쪽의 내용 경계도 보호한다. 이 계약은 유지한다.
원 PR이 별도로 기록한 중첩 표 넘침·첫 행 높이 차이도 현재 직접 판독에서 확인했다.

제품 `40778b67d6`의 전3쪽 최저 raw는 Native 90.68%, fresh WASM 90.59%다.
2·3쪽은 두 경로 모두 100.00%다. 1쪽 점수가 90% 이상이라는 이유로 가시적인 배치 결함을
완료 처리하지 않는다. 1쪽에는 절대 px 좌표 회귀를 추가하지 않는다.

원본 선언 첫 프레임은 68,454 HU, 96 DPI에서 912.72px다. 실제 스캔은 앞7행에 845.12px를
수용하고 남은 행 내용 61.60px와 안여백 6px를 받는다. 그런데 별도 저장 행 계획으로 환산한
원점은 823.6266667px여서 끝 행을 89.0933333px로 다시 늘렸다. 결과 첫 표 높이 934.2133333px는
선언 프레임보다 21.4933333px 크고, 마지막 행의 가운데 정렬 글자는 PDF보다 약 11px 낮다.

## 생산·소비 연결과 보정 범위

`prepare_block_table_continuation`의 `cut_row_h` 및 `painted_row_heights` →
최종 `whole_row_fit_h` → 행 스캔의 수용 높이 →
`source_first_cell_frame_height`가 소비하는 첫 조각 원점 → 끝 행 override →
`ordinary_rowbreak_fragment_heights`의 실제 표·셀 프레임이다.

초기 분석에서는 공통 저장 원점 캐시를 검토했다. 준비 초기에 `mt.row_heights`로 채우고,
중간 `resolve_row_heights_trusting_declared`가 별도 paint 계획을 같은 키에 게시하지만,
그 뒤 확정한 `whole_row_fit_h`는 캐시에 전달하지 않는 구조였다. 최종 수용 행 계획을
같은 캐시에 게시해 첫 프레임의 잔여 계산도 같은 원점을 소비하게 보강했다. 이 구조상 위험과
현재 남은 출력 오차의 실제 발생 지점은 구분하며, 후속 실행의 값으로 인과를 확인한다.
문서 ID·관측 오차·페이지 번호에 따른 좌표 보정이나 clamp를 추가하지 않는다.

선행 규칙은 PR #8228(`3e02fe2749`)과 저장 프레임 인증의 `1c807b984e`,
`a5911b4fbe`, `fcd434d63b`를 확인했다. 저장 줄 재시작·안여백·소유 인증을 완화하지 않는다.
편집 후 재조판·그림 셀·rowspan 대조군도 같은 최종 높이를 보존하는지 확인한다.

## 검증 계획과 남은 차이

- 수정 전 실제 스캔·render tree 진단은 ignored output의 `pr8530-row-drift.log`,
  `pr8530-frame-diagnostic.log`에 있다. 원본 선언과 독립 PDF는 저장소 경로를 재사용한다.
- 원 PR의 3쪽 내용·유닛 소유 관계 검사는 유지한다. 보정 후 전쪽 Native/fresh WASM과
  1쪽 직접 판독으로 첫 조각·마지막 행 정렬·뒤 내용 보존을 재검증한다.
- 중첩 TAC 표의 오른쪽 넘침은 별도 원인 확인이 필요하다. `treat_as_char`만으로 열 폭을
  줄이거나 출력 내용을 숨기지 않는다. 현재 높이 수정으로 그 차이까지 해결됐다고 주장하지 않는다.
- 기존 전체 회귀는 다른 검토 worktree에서 진행 중이며 그 소스는 수정하지 않는다.
  이 보정의 결과는 이후 빌드·검증으로 별도 기록한다. 현재 수정 후 통과를 선언하지 않는다.

## 첫 집중 실행과 추가 원인

제품 `874fac36f2`에서 준비 단계의 최종 행 계획 게시만 추가한 뒤 측정했으나,
Native 전3쪽은 90.68% / 100.00% / 100.00%로 거의 같았고 실제 끝 행도 여전히
89.0933333px였다. 당시에는 게시 뒤의 재귀 `resolve_row_heights_trusting_declared`가 같은
원점 캐시를 다시 덮어쓸 가능성도 검토했다. 한 번 게시한 사실만으로 실제 소비까지
같아졌다고 판단하지 않고, 추가 보정과 실제 원점 진단을 진행했다.

자동 높이 해소는 빈 원점 캐시를 채우는 `seed_stored_frame_rows`를 사용하고,
스캔의 최종 계획과 decoration fragment의 명시적 `remember_stored_frame_rows`는
계속 게시·교체할 수 있도록 구분한다. 자동 측정은 자체 paint 높이를 반환하되
다른 단계가 소유한 앞 행 원점은 덮어쓰지 않는다. source·font·레이아웃 세대가 바뀔 때의
기존 `clear_layout_caches` 초기화는 유지한다.

중첩 표의 오른쪽 차이도 독립 PDF content stream으로 확인했다. 부모 셀의 clip 경계는
PDF x=199.213~533.473pt이며, 중첩 표의 선은 그 오른쪽을 넘어 원래 폭으로 그리지만
부모 clip에서 잘린다. 열 너비 자체를 줄인 출력이 아니다. 일반 whole-table 경로는
이미 모든 소유 셀을 clip하지만 partial-table 경로는 쪽 컷에 걸친 셀만 clip하고 있었다.
부분 표의 온전한 행에도 같은 셀 경계를 적용하고 `page_fragment` 표시는 실제 쪽 컷 여부로
유지한다. 저장 줄이 인증한 중첩 노출과 본문 우단 제한은 기존 공통 clip 확장 경로를 따른다.

이 추가 보정의 Native/fresh WASM, 새 base·이전 PR TSV, 내용 누락·겹침·이어받기
대조군은 아직 재검증 전이다. 독립 근거가 있는 clip을 재사용한 것이며, 관측 오차만큼
좌표를 줄이거나 중첩 표 내용을 삭제하는 보정은 추가하지 않는다.

## 새 base의 실제 재검증

제품 `2071603998`에서 Native 전3쪽은 90.95% / 100.00% / 100.00%다. 중첩 표 우측의
부모 clip은 개선됐으나 첫 조각의 끝 행은 여전히 89.0933333px로 남았다. 따라서 앞의
캐시 게시·초기 채움 보정만으로 높이 원인이 해결됐다고 판단하지 않는다. 독립 PDF와
review·overlay에서도 마지막 행의 약 21.5px 과대 상자와 가운데 정렬 차이를 확인했다.

실제 저장 프레임 조회가 소비한 앞 행 원점과 캐시 유무를 기존 `RHWP_DIAG_SCAN` 경로에서
함께 출력해, 준비 단계와 컷·배치의 호출 경계를 구분한다. 컷 `[2, 3]`과 뒤쪽 내용 보호를
검사하는 기존 회귀는 새 base에서도 통과했다. 이 통과가 미세 배치 결함을 검출했다는 뜻은 아니다.

제품 `75d992bcac`의 실제 진단에서 저장 셀 프레임 조회 61회가 모두 캐시의 앞 행 원점
845.12px를 사용했다. 행 스캔도 남은 67.60px에서 안여백 6px를 빼고 같은 `[2, 3]` 컷과
내용 61.60px를 수용한다. 앞서 가정한 ‘현재 조회가 여전히 raw 원점 823.6267px를 사용한다’는
설명으로 남은 오차를 설명할 수 없다. 원점 캐시와 실제 스캔은 올바르게 연결됐으며,
그 이후 조각 확정·물리 띠·원장에 전달되는 재정의 값을 단계별로 추적한다. 원시 근거는
ignored output의 `logs/frame-trace-75d992bcac.log`에 있다.

## 남은 오차의 실제 덮어쓰기

제품 `a00a818113`의 단계 진단은 스캔·저장 행 확정·첫 프레임 확정이 모두
표 912.72px, 끝 행 67.60px라는 같은 결과를 유지함을 보였다. 그 뒤 물리 빈 띠 처리만
표 934.213333px, 끝 행 89.093333px로 바꾼다. 앞 행 원점은 전 단계에서 845.12px로 같다.
실제 원인은 raw 원점을 다시 쓰는 것이 아니라, 이미 닫힌 원본 첫 프레임에 일반 쪽 하단의
빈 띠를 다시 배정하는 소비 경로다. 원시 근거는 `logs/fragment-trace-a00a818113.log`다.

원본 줄 재시작을 인증하는 기존 `saved_multirow_opening_frame_height` 결과와, 실제 스캔·
조각 확정이 같은 프레임을 닫았다는 결과를 함께 사용한다. 이 경우 빈 띠의 물리 예산도
그 원본 프레임을 소비한다. 인증되지 않은 후보 높이·실제 내용이 다른 컷·이어받기 조각은
이 조건으로 제한하지 않는다. 관측 오차나 문서 ID를 상수로 넣지 않고, 좌표나 글자를 숨기지 않는다.
이 보정의 최종 Native/fresh WASM·이어받기·정상 대조군 결과는 아직 재검증 전이다.

## 실제 수용 프레임 보정의 Native 확인

제품 `4e182b94c469d1364a6ec381f2193e1de596a5a5`를 고정해 전3쪽을 다시 출력했다.
Native raw 표시값은 **99.94% / 100.00% / 100.00%**이며, 1쪽의 기존 90.95%에서
개선됐다. 같은 PNG의 overlay에서 계산한 원시 수치는 99.93715%다.
독립 PDF와 review·overlay를 직접 대조해 첫 프레임의 종료선, 마지막 행 높이와 가운데
정렬, 중첩 표 우측 clip이 대응하는 것을 확인했다. 뒤2쪽의 기존 100.00%도 유지됐다.

진단에서도 스캔 → 저장 행 → 첫 프레임 → 물리 띠 전 단계가 표 912.72px,
끝 행 67.60px를 유지했다. 따라서 수용 프레임 뒤의 빈 띠 재배정이 실제 과대 높이의
발생 지점이라는 가설을 수정 전후 실행으로 확인했다. 기존의 컷·내용 순서 집중 검사도
이 제품에서 통과했으나, 아직 새 높이 결함을 검출하는 회귀의 대체 증거는 아니다.

ignored output의 `accepted-frame-4e182b94c4-native/pr8530-accepted-frame/`에
전쪽 `silhouette.tsv`와 1쪽 `review/review_001.png`·`overlay/overlay_001.png`가 있다.
실행 로그는 `logs/accepted-frame-4e182b94c4-native.log`, 단계 진단은
`logs/accepted-frame-4e182b94c4-render-tree.log`다. 실행 파일 SHA-256은
`a37053f147e3ff44e1613e16061093c1768298b183ba879bb6d8232181a3c42c`다.

이는 리베이스 전 고정 제품의 원인 확인 결과다. 새 base `782ab3e2d0` 반영 뒤의
최종 Native/fresh WASM 출력으로 표기하지 않는다. fresh WASM 전쪽·확대 판독과
정상 대조군을 완료한 뒤 새 프레임 관계 회귀를 추가하고 개별 리뷰를 최종 갱신한다.

## 새 base 제품의 양쪽 전쪽·새 회귀 확인

코드 `dd0ac546e3389f1703e67cb86f1c5bdf615ff0c9`의 Native/fresh WASM 전3쪽을
새로 출력했다. Native는 99.94% / 100.00% / 100.00%, fresh WASM은
99.96% / 100.00% / 100.00%다. 1·2쪽의 실제 review·overlay를 다시 생성해
첫 프레임과 마지막 행·중첩 셀 경계·다음 조각의 시작을 독립 PDF와 직접 확인했다.
새 Native의 세 PNG는 앞선 고정 제품 `4e182b94c4`의 세 PNG와도 바이트가 같다.

원본 XML의 선언 68,454 HU를 독립 기대 크기로 사용하는 별도 검사
`issue_8529_accepted_opening_frame::accepted_source_frame_is_not_extended_into_the_page_bottom_band`를
추가했다. 표의 크기뿐 아니라 실제 끝 행을 포함한 셀의 포함, 첫 조각·다음 조각의
내용 소유·보존·중복 여부를 확인한다. 첫 쪽의 양쪽 raw 98% 이상·직접 판독을 완료해
±2 CSSpx 조건을 충족한다. 설치 글꼴을 요구하거나 글꼴이 없으면 건너뛰지 않는다.

원본 XML과 수정 전·후 실제 렌더 트리를 같은 검사 조건에 대조했다.
원본 912.72px에 대해 수정 전 상자는 934.5px로 조건을 위반하고, 수정 후는 913.0px로
통과했다. 이 별도 진단과 새 Rust 검사 실행은 구분한다. 새 Rust 검사는 최소 글꼴 5개를
노출한 Native Skia 기능 환경에서 1건 통과했다(exit 0, 나머지 304건은 집중 필터 제외).
기존 컷 회귀의 assertion은 유지하고 측정 주석만 현재 근거로 갱신했다.

현재 정식 전쪽 TSV·1·2쪽 review/overlay와 해시는
`mydocs/pr/pr_8530_review.md`에 연결했다. 원시 실행은 ignored output의
`logs/accepted-frame-regression-minfont.log`,
`logs/accepted-frame-independent-before-after.json`에 있다.
최종 전체 Rust·Skia·lint·새 base 비교와 다른 원 PR의 보존 검증은 아직 완료 전이다.
