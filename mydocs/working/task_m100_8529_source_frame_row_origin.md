# 원본 첫 조각의 원점과 실제 수용 행 높이의 공유

## 수정 전 관측과 독립 근거

PR #8530의 `samples/issue8529/rowbreak_exact_fit.hwpx`와 기존 독립 한컴 Print
`pdf/issue8529_rowbreak_exact_fit-2020.pdf`를 대조했다. 원 PR은 정확히 맞는 컷의 부동소수
잡음을 보정해 `[2, 3]` 유닛을 첫 쪽에 수용하며, 3쪽의 내용 경계도 보호한다. 이 계약은 유지한다.
원 PR이 별도로 기록한 중첩 표 넘침·첫 행 높이 차이도 현재 직접 판독에서 확인했다.

제품 `40778b67d6`의 전3쪽 최저 raw는 Native 90.68%, fresh WASM 90.59%다.
2·3쪽은 두 경로 모두 100.00%다. 1쪽 점수가 90% 이상이라는 이유로 가시적인 배치 결함을
완료 처리하지 않는다. 1쪽에는 절대 px 좌표 회귀를 추가하지 않는다.

원본 선언 첫 프레임은 68,454 HU, 96 DPI에서 912.72px다. 실제 스캔은 앞7행에 845.12px를
수용하고 남은 행 내용 61.60px와 안여백 6px를 받는다. 그런데 별도 저장 행 계획으로 환산한
원점은 823.6266667px여서 끝 행을 89.0933333px로 다시 늘렸다. 결과 첫 표 높이 934.2133333px는
선언 프레임보다 21.4933333px 크고, 마지막 행의 가운데 정렬 글자는 PDF보다 약 11px 낮다.

## 생산·소비 연결과 보정 범위

`prepare_block_table_continuation`의 `cut_row_h` 및 `painted_row_heights` →
최종 `whole_row_fit_h` → 행 스캔의 수용 높이 →
`source_first_cell_frame_height`가 소비하는 첫 조각 원점 → 끝 행 override →
`ordinary_rowbreak_fragment_heights`의 실제 표·셀 프레임이다.

공통 저장 원점 캐시는 준비 초기에 `mt.row_heights`로 채워지지만, 중간
`resolve_row_heights_trusting_declared`가 이를 별도 paint 계획으로 덮어쓴다.
그 뒤 확정한 `whole_row_fit_h`는 실제 스캔이 사용하면서도 원점 캐시에 전달하지 않았다.
최종 수용 행 계획을 같은 캐시에 게시해, 첫 프레임의 잔여 계산도 같은 앞 행 원점을 소비하게 한다.
문서 ID·관측 오차·페이지 번호에 따른 좌표 보정이나 clamp를 추가하지 않는다.

선행 규칙은 PR #8228(`3e02fe2749`)과 저장 프레임 인증의 `1c807b984e`,
`a5911b4fbe`, `fcd434d63b`를 확인했다. 저장 줄 재시작·안여백·소유 인증을 완화하지 않는다.
편집 후 재조판·그림 셀·rowspan 대조군도 같은 최종 높이를 보존하는지 확인한다.

## 검증 계획과 남은 차이

- 수정 전 실제 스캔·render tree 진단은 ignored output의 `pr8530-row-drift.log`,
  `pr8530-frame-diagnostic.log`에 있다. 원본 선언과 독립 PDF는 저장소 경로를 재사용한다.
- 원 PR의 3쪽 내용·유닛 소유 관계 검사는 유지한다. 보정 후 전쪽 Native/fresh WASM과
  1쪽 직접 판독으로 첫 조각·마지막 행 정렬·뒤 내용 보존을 재검증한다.
- 중첩 TAC 표의 오른쪽 넘침은 별도 원인 확인이 필요하다. `treat_as_char`만으로 열 폭을
  줄이거나 출력 내용을 숨기지 않는다. 현재 높이 수정으로 그 차이까지 해결됐다고 주장하지 않는다.
- 기존 전체 회귀는 다른 검토 worktree에서 진행 중이며 그 소스는 수정하지 않는다.
  이 보정의 결과는 이후 빌드·검증으로 별도 기록한다. 현재 수정 후 통과를 선언하지 않는다.
