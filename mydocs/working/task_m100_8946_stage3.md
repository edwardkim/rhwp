# #8946 실제 공급 글리프의 문장부호 소유 보정

2026-11-11 단계 2의 제품 `c6c3723958`와 검증 기록 `71303334bd`를 기준으로 한다.
범위는 실제 공급한 원본 프로그램의 선택·공통 측정·paint 소유다. 전체 출력 환경이나
HFT 자연 메트릭 정책을 바꾸지 않는다. 현재 수용 판정은 `re_review_required`다.

## 수정 전 근거와 반례

원본 HWPX 문단 12662/charPr 29는 한글 강낭콩, 영문 세나루를 선언한다.
강낭콩 CFF에는 `/`·`?`가 없고 세나루 영문 CFF에는 있다. 독립 한컴 Print의
350쪽 Type3 T8은 영문 본문과 두 문장부호를 함께 소유한다. 현재 trace는 두 문자를
한글 슬롯 0/강낭콩에 남겨 보충 브라우저 폭을 사용한다. 300dpi Native 확대에서는
잘못된 물음표 윤곽을 확인했다. 단계 2의 raw 99%대가 이 결함을 면제하지 않는다.

선행 #8397 통합 `99a176b7cb`는 공급된 한글 프로그램의 결측과 원 영문 프로그램의
실제 글리프를 확인한 경우 HWP3의 측정·run을 같은 슬롯으로 해소했다.
후속 `b00d9f0f4f`와 `09ada34bf1`의 유지보수자 보정은 영문 family가 비어 있지
않다는 이유만으로 모든 구두점을 영문 슬롯으로 보내던 잘못된 일반화를 제거했다.
해당 제한을 유지한다. 현재 HWPX의 HFT→CFF 실제 공급은 같은 결측/소유 사실이
있어도 HWP3 형식 가드에서 제외된다.

후보는 원본 두 슬롯이 HFT이고 실제 공급 목록이 CFF 프로그램인 경우에도 같은
결측/소유 계약을 적용한다. 상속 프로그램이 글리프를 가지거나 영문 프로그램이
없거나 결측이면 원래 슬롯을 유지한다. TTF 선언·미확인 공급·한자 뒤 괄호·공백
계약을 바꾸지 않는다. HWP3의 기존 공급 규칙도 그대로 둔다.

## 생산과 소비

`NativeOtfMetrics`의 실제 프로그램 형식·cmap →
`composer/punctuation_slots.rs::slot` → `metric_slot`을 소비하는 줄 측정과
`try_resolve_run_slots`의 실제 run 분할 → 해소된 `lang_index`의 TextStyle을
paint가 소비한다. backend별 문장부호 치환이나 최종 좌표 보정을 추가하지 않는다.

먼저 350쪽의 원본 슬롯·전진·윤곽과 기존 HWP3·한자 구두점 반례를 확인하고,
개선되면 최종 Native/fresh WASM 전쪽·기본 모드 보존·편람 gate를 재실행한다.
미달 표지와 새 회귀 추가의 선행 조건은 그대로 유지한다.

## 집중 보정 결과

미대응 픽셀 0이다. [Native TSV](../pr/assets/issue8946/stage3-20261111/native-probe.tsv),
[WASM TSV](../pr/assets/issue8946/stage3-20261111/wasm-probe.tsv),

보존했다. Native 350쪽은 보정 전 99.86%였지만 물음표 프로그램이 달랐다.
보정 후 실제 호스트 trace의 두 문자는 슬롯 1/#세나루/nativeOtf이며 독립 Print와
같은 소유를 확인했다. 원 영문 프로그램을 공급 목록에서 뺀 실제 대조의 350쪽 PNG는
보정 전후 바이트가 동일하다. 없는 글리프나 이름만 있는 후보로 전환하지 않았다.

실제 편집·삭제 후 763쪽과 원문 순서·전체 내용 SHA를 보존했고 Canvas2D/CanvasKit
기존 E2E도 통과했다. 기존 최소 글꼴 집중 회귀와 후보의 전체 시각 검증은 진행 중이다.
이 결과로 표지의 독립 그림 공급 문제나 전쪽 수용 조건을 완료 처리하지 않는다.
