## 원본 10종의 양쪽 583쪽 완료

실제 최적화 producer `68b4f6bdfda465aaafd0634c587cd6a17252fed6`의 fresh WASM에서
583/583쪽을 완료했다. 모든 쪽의 공식 raw는 98% 이상이며 같은 조건의 frozen base 대비
표시값 하락은 0쪽이다. 먼저 완료한 Native 583쪽과 함께 두 경로의 원본 전쪽을 확인했다.
WASM 원본별 최저는 복학원서 98.99%, 폴로 99.94%, 배포 문서 99.80%, 수출입 99.18%,

전쪽 TSV·각 부분의 manifest·producer와 비교 영수증을

바꾸어 쓰지 않으며, 최신 devel의 문서 변경·검사 이관과 생산 코드의 동일성은 stage8의
`source38-rebase-production-equivalence.json`으로 연결한다. 전체 보호, 유입 편집·저장·
재열기와 Studio 여정, 전체 Rust gate가 끝났다는 뜻은 아니다.

## #9293의 미달 0쪽 기록과 현재 판정의 차이

사용자가 지정한 `b4faa9e6d6633ce0fed56cd0540eea5ea01c3645`의 보호 기록을 직접 읽고
46조건의 원본 TSV SHA·페이지 연속성을 다시 확인했다. 당시 정본
`7f558bd4a1c8b901001492a977476efe1b1df3165dd3fef220f43ca1f87f55e3`에 대한
4,046쪽 미달은 실제로 0쪽이다. 이 기록을 현재 서버의 재현 미완료와 혼동하지 않는다.

현재 devel의 정본은 `b2ea68f97a242d111522132b6c733f15a65b29b56e227943fd9c15f9c8d35597`이다.
2026-11-22 00:29:44 KST의 `3be32a741cffdf100c6870a28fb606b33bce1851`에서 검증된
75개 표시값을 상향했다. 같은 #9293 TSV를 이 후속 정본에 대조하면 74행이 하한보다 낮다.
이것은 #9293이 당시의 기준에서 실패했다는 뜻이 아니라 두 기록의 기준 시점이 다르다는
뜻이다. 예를 들어 화학 Native 31쪽은 99.99% → 100.00%, 61쪽은 99.98% → 100.00%,
74쪽은 99.85% → 99.88%로 하한이 올랐다. 현재 작업은 새 정본을 그대로 사용한다.

페이지별 근거는 `source41-pr9293-baseline-comparison.json`에 보존했다. 당시와 현재의
기준·현재 환경 재현·코드 회귀 판정을 구분하고, 평균이나 98% 통과로 특별 하락을 면제하지 않는다.

## 글꼴 공급 보완과 브라우저 재개

화학·사양서의 실제 공급 순서는 semanticist21 최종 `font-supply/programs.tsv`에 보존되어
있었다. 기존 정규화 catalog 해시만으로 개별 파일이 없다고 판단하지 않고 이 목록도
대조한다. Windows에서 정확한 SHA가 일치하는 파일을 추가로 확인하여 H2GTRE·H2HDRM,
함초롬바탕 Bold·함초롬돋움 두 굵기, Arial Black·Wingdings 7개를 private 경로에 복사했다.
기존 복사한 함초롬바탕 regular도 이 최종 공급 목록의 SHA와 일치한다. 파일 권한은 0600이며
시스템 설치와 글꼴 바이트의 Git 반영은 하지 않았다. 공급 순서와 누락을 확인해 보호 검증을
계속하며, 명시한 독립 기호 family의 누락도 해소한다.

보호 WASM의 첫 Chrome 시작이 기본 30초를 넘긴 실패는 별도로 보존했다. 같은 namespace의
Chrome 155가 5,937ms에 시작함을 확인하고 동일 producer·명령으로 검증을 다시 시작했다.
제품 코드·시각 기준·임계값을 바꾸거나 실패한 측정값을 성공으로 재표기하지 않았다.
