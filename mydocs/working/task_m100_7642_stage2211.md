## 현재 검증과 남은 차이

동결한 뒤 기본 pkg와 Studio public의 JS/WASM 해시 일치를 확인했다. 두 생성 타입
파일의 순서 변경도 이 source의 실제 산출물로 보존한다. 해당 source의 Native/fresh

다른 원인을 한 분수 높이 보정으로 숨기지 않는다.

## 독립 Print와 보정

48개 기호 대조군은 로컬 XML 입력을 한컴 2024에서 저장한 HWP와 그 저장본의
독립 Print PDF다. 생성본과 정상 저장본을 구분한다. 두 face·네 크기의 ∴/∵ 다음
피연산자 원점은 1em 전진을 보이고, 명시적 ~에서만 반 em이 추가된다. 원본
시험지에서도 ∴만 다른 face의 작은 전진폭을 쓰며 뒤 분수들이 함께 왼쪽에 있다.
설치 두 face의 cmap/hmtx에도 ∴·∵의 1024/1024 전진이 있다.

`hancom_glyphs::measure`가 실제 기호 face·전진을 공통 GlyphRun으로 전달하게
연결했다. HancomEQN은 같은 논리 1em 격자를 사용한다. 이항/관계 기호의 자동
간격 목록을 바꾸지 않았다. 원본 수식·저장 폭·분수 높이·기준선을 조정하지 않는다.
이 변경의 새 Native/fresh WASM 검증과 전쪽 수용·회귀 추가는 아직 실행 전이다.

MCP Save job `9f6c1752-d800-4779-b075-9517002cec6a`, Print job
`159528f2-cca1-47be-9aee-0163e1c48515`, 한컴 13.0.0.3901,
`pdf_print_method=0`, `frame_print_to_pdf_ex_one_up`를 확인했다. 생성 원본·저장본
HWP·6쪽 PDF를 `pdf/issue7642-logical-symbol-diagnostic-20261017/`에 보존한다.
대조군의 분수 예제는 원본 시험지의 중괄호와 생성 방식이 다르므로, 이 단계의
1em 근거는 분수 없는 기호 대조에서 취한다. 대조군의 존재를 원본 전체 일치나
직접 시각 수용으로 간주하지 않는다.

실행·측정 증거는 ignored `output/pr-review/issue7642/failed-inputs-20261008/
stage15-current-validation/`의 stage2200 비교, stage2205 review/overlay,
stage2206 raw 위치 분석, stage2207 표시 원점 추적, stage2209 MCP receipt,
stage2210 독립 PDF 글리프 원점에 있다. 기존 Rust 실패와 다른 devel 하락은 남는다.

## 원래 대조군의 실패와 독립 대조의 한계

중괄호 없는 원래 `THEREFORE~q over p=39 over 108=13 over 36` 대조군은
Native 최저 80.98039→82.72387%에 그쳤다. 독립 Print는 ∴를 중첩 분수의
분자에 포함하지만 현재 parser는 밖에 둔다. 이 원본·실패 증거를 보존했다.
새 대조군 통과를 이 원본의 해결로 바꿔 보고하지 않는다. 일반 OVER의 소비
범위를 바꾸면 기존 저장 수식·정상 대조군에 미치는 영향과 독립 근거가 더 필요하다.

분수를 각각 중괄호로 묶은 `logical-symbol-isolated-fractions`를 별도 이름으로
생성·한컴 정상 저장·Print했다. 앞선 입력과 서로 다르며 정상 분수와 논리 기호
전진을 분리해 관측한다. Save job `7386ae0b-d0cd-4eea-b635-550fa6aab19d`,
Print job `ca3865ba-0fbb-4b46-9e9c-16d4183b931e`다. 6쪽 Native 최저는
84.02251→95.50959%, 6쪽 자체는 98.17010%다. 새 review/overlay를 함께 열었다.
쪽별 결과는 stage2224, 이미지와 원본 연결은 stage2225에 보존한다.
이 대조군도 fresh WASM 결과·확대 판독을 더 확인해야 한다.

확대 대조에서 직접 Unicode ∴ 입력은 명령형과 달리 Text 토큰 경로에 들어가
다른 표시 폭이 남는 것도 확인했다. `tokenizer.rs`의 비 ASCII Text 수집은 산술·
관계 기호만 구별한다. 다음 보정은 명령·직접 기호·인용 문자열·인접 문자의 경계를
같이 분석한 뒤 처리하며 이 실패를 점수 통과로 면제하지 않는다. 빌드 중인
15cb source를 다른 source로 바꾸거나 이 결과를 새 코드의 검증으로 재사용하지 않는다.
