# #7642 저장 줄 끝과 후속 물리 원점의 공통 정규화

Issue: #7642.

## 확인한 상태

직전 code head는 `0f58f2c445eb5386d74cbe3b03b2986bf6a9fadf`다. 해당 head의
Native 집중 검증 16개 중 13개가 수치 조건을 충족했다. 온새미로 원본
HWP/HWPX와 NO_LS 진단본은 계속 미달이다. 원본 두 형식은 독립 Print와
46쪽으로 일치하지만 6·15·36쪽이 90% 미만이다. HWPX 최저 raw는 43.36002%다.
국어 HWP/HWPX는 각각 전쪽 최저 92.39354%이며 14쪽은 99.79538%다.
이는 Native의 수치 결과이며 fresh WASM·직접 판독 완료를 뜻하지 않는다.

## 원인과 독립 근거

`stage2720-rejoined-tail-flow-trace/trace.log`에서 질문 p19는 한컴과 같이 한 줄이지만
뒤 p20이 기존 두 줄의 저장 원점으로 이동했다. 실제 흐름 `total=35.5`와 달리
p20 진입 `cur_h=59.5`가 남는다. 독립 Print의 같은 질문·후속 본문 위치와
함께 확인했다. 원본 저장 두 줄의 전진과 마커를 포함한 새 한 줄 전진의 차이는
소스 단위로 -1800 HWPUNIT이다. 이 값을 화면 좌표 상수로 구현하지 않는다.

## 구현과 실제 소비 경로

- `composer::project_stored_word_tail`: 같은 본문 frame·스타일·번호로 재조판한
  줄과 공백 메트릭을 한 번에 반환한다. 개행·실제 물리 프레임 경계·외부 배제
  소유와 구현 생성 줄은 기존 거절 조건을 유지한다.
- `render_normalization::stored_word_tail`: 원본 물리 단 폭과 같은 저장 띠에
  한해 줄을 교체하고, 전진 차이를 같은 물리 프레임의 뒤 문단 원점에 전달한다.
  명시적 쪽/단 전환·단 정의 변경·원본 VPOS 되감김·쪽/단 시작에서 전진 차이를
  종료한다. 단 폭이 서로 다르면 현재 문단의 소유 단을 추측하지 않는다.
- `DocumentCore::compute_render_normalized`: 파생 문단과 composed를 함께 발행한다.
  pagination의 section paragraphs/composed 선택과 paint의
  `section_render_paragraphs`/`section_render_composed`가 이 공통 결과를 소비한다.
  원본 `document`와 저장용 캐시는 수정하지 않는다.
- 원점이 이동한 파생 문단의 이전 VPOS snapshot을 제거한다. 문자 축·공백 메트릭은
  보존한다. 새 줄 벡터는 기존 `replace_line_segs_with_space_metrics`의 생산 경계를
  사용한다. 원본의 snapshot과 문자 축은 그대로다.
- 일반 본문을 paint에서만 재결합하는 임시 경로를 제거한다. 기존 셀·그림 공백
  메트릭의 지역 재조판 계약은 유지한다.
