# #7642 짧은 완결 줄과 정확한 물리 경계의 원본 단위 대조

Issue: #7642. 관측 소스는 `7bccb3d635e2e9d1c6b891719df0927232770e33`다.
`stage3360`의 빈 문단4개는 전쪽100%지만 최소 경계 `minimum-28500`의 뒤4쪽이
미달이다. 다른 문서의 개선으로 상쇄하지 않으며 이 회귀를 현재 구현에서 보정한다.

## 독립 Print 실험

`stage3372`의 실제 유닛·스캔 진단에서 두 입력 모두 완결 줄은13.333333px다.
`split-blank0`은 남은 물리15.6px에 그 줄을 싣는 것이 독립 Print와 일치한다.
반면 `minimum-28500`은 잔여13.333333px에 같은 높이의 줄을 실어 뒤 소유를 바꾼다.
25px 고아 기준을 되살리면 앞의 올바른15.6px 반례가 다시 실패한다.

원본의 한컴2020 Print는 `ROW 4`를6쪽에 둔다. `stage3373`에서 내용·행 최소·글꼴을
그대로 두고 실제 용지 높이에 대응하는 `pagePr.width`만 +1/+40/+170HU로 바꿔 각각
독립 Print를 산출했다. 세 출력 모두8쪽이며 `ROW 4`가5쪽에 표시된다. 특히 +1HU만으로
경계가 달라져 고정25px나 픽셀 여백을 요구한다는 가정을 배제한다. 첫 준비 중 ZipInfo
객체 재사용 오류는 MCP 호출 전에 발생했고, 원본은 그대로 보존했다. 복사한 메타데이터와
전체 ZIP 무결성 검사로 파생 입력을 다시 만들었으며 그 실패와 수정 출처도 기록했다.

실제 engine2020·PrintMethod0·one-up·input_preprocess=none, 입력/PDF SHA와
job ID는 `stage3373-minimum-headroom-print/receipt.json`에 있다.

## 수정 계약

작은 완결 줄의 내용은 원본 HWPUNIT으로 비교해 남는 공간이 있는 경우만 수용한다.
정확히 같은 경계를 부동소수점 누적이나0.5px 기하 허용으로 여유가 있는 줄로 바꾸지 않는다.
큰 줄의 기존 최소 유지 정책과 정렬된 내용 끝 검사는 유지한다. DPI에 무관한 원본 단위의
엄격한 경계이며 문서·예상 쪽수·픽셀 목표값별 예외를 추가하지 않는다.

## 검증 범위

현재6쪽의 공통 단 원점 보정과 함께49개 기존 회귀,63개 대조군 및 새3개 단위 경계를
한 후보에서 재검증한다. 새 정식 회귀·fixture/golden은 전쪽 Native/fresh WASM90%와
직접 판독 뒤 추가한다. 전체 원본·실패 입력, 최종 전체 Rust/lint/Studio와 PR·CI·후속 처리도
계속 남아 있으며 현재 단계의 일부 통과를 전체 완료로 표시하지 않는다.
