# Issue #7642: 원형 채우기 교차 검증과 독립 Print 회귀

## 검증한 생산 코드

생산 코드는 `aaa63849ea3f1664686e896ed309cfca457240eb`이다. 고정 devel은
`2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`이며 이번 fetch에서도 바뀌지 않았다.
따라서 리베이스하지 않았다. PR 생성 직전에는 다시 fetch하고, 변경됐다면 리베이스 후
새 기준으로 재검증한다. 이 기록은 PR 준비 완료나 최종 전범위 통과 판정이 아니다.

`stage1403-current-native.json`과 `stage1406-fresh-wasm-build.json`은 각각 실제
빌드 당시 working tree와 생산 파일 hash를 보존한다. 위 커밋의 생산 파일과 전부 같다는
추가 확인도 기록했다. 원래 빌드 당시 부모 SHA를 새 SHA로 덮어쓰지 않았다.
두 빌드는 고정 `target/pr-review`와 Cargo 빌드 잡 8을 순차 사용했고 exit 0이다.
fresh WASM은 최적화 완료 후 package를 따로 보존했고 Studio/public의 JS/WASM hash도 같다.

## 확대 판독과 한계

원형 통제군의 이동 중심, 곡률과 색상 띠, 셀 테두리와 원문 표식을 직접 대조했다.
6쪽은 양쪽 100%이며 같은 핵심 동작의 완료 페이지이므로 독립 Print의 중심·반경을
±2 CSS px로 보호한다. 중심이 0/100%인 쪽도 포함해 긴 축 절반이나 축별 정규화로
되돌아갈 때 검출한다. 원래 셀의 내용·소유·포함·비겹침도 별도 관계 검사로 유지한다.

원본 19쪽은 `stage1413-hwp3-gradient-detail-review.png`의 같은 영역에서 수정 전 Native,
수정 후 Native, fresh WASM, 독립 Print를 2배로 열어 보았다. 영역 확대는 판독용이며
그림에 적힌 점수는 전쪽 점수다. 원형 채우기 띠의 큰 차이는 해소됐다. 그러나 Print보다
가는 글자 농도·일부 자형 잔여 차이를 인정하며 전체 fidelity 또는 픽셀 완전 일치라고 쓰지 않는다.
이 페이지를 완료 페이지로 승격해 새 절대 좌표 회귀를 추가하지 않았다.

## 새 이름의 정식 회귀와 독립 기대값

`tests/cases/verified_radial_print_geometry.rs`에 두 검사를 새 이름으로 추가했다.
기존 시험지 검사 함수를 바꾸거나 같은 이름으로 대체하지 않았다.

1. `verified_radial_print_keeps_physical_circle_at_center_and_edge_origins`:
   독립 Print 타원 path의 실제 bbox에서 변환한 96dpi 중심·반경과 ±2px로 비교한다.
   실제 SVG의 사용자 좌표계, 초점/중심, 셀 면의 자원 참조, 원문 표식 보존을 검사한다.
2. `verified_radial_print_preserves_each_cells_fill_and_owned_text_once`:
   전체 6쪽에서 셀과 채우기 소유, 원문·채우기의 셀 내부 포함, 앞뒤 런 비겹침,
   `RADIAL 1`부터 `RADIAL 6`의 공백까지 포함한 원문 순서·누락·중복을 검사한다.

정식 fixture와 PDF는 `tests/fixtures/gradient/`에 함께 포함했다. 독립 Print를 새로
생성하거나 재저장하지 않고, 검증한 r3 입력/PDF의 동일 바이트를 복사해 hash를 확인했다.
6쪽 Native/fresh WASM 전쪽 100%를 먼저 확인한 뒤 테스트와 fixture를 추가했다.
기준 PDF의 타원 측정 원장은 `stage1402-radial-print-measurements.json`이며 입력/PDF
크기·SHA·생성 절차는 fixture README에 있다.

수정 전 `a36f3a3dc8ed39ce71dd172a1c33166e7ecdc141`의 보존 Native library에서
같은 최종 테스트 소스를 링크해 실행했다. 기하 검사는 첫 쪽 반경 actual 120px,
독립 Print expected 169.74867px로 **FAIL**, 내용 관계 검사는 **PASS**다.
수정 후 library에서는 **2/2 PASS**다. 빌드 실패를 결함 검출로 세지 않았다.
명령·테스트 소스 hash·실제 exit는 `stage1414-verification-r2.json`과 로그에 있다.

최초 새 테스트의 SVG 표식 비교는 공백을 글리프로 내보낸다고 잘못 가정했다.
SVG는 공백 대신 다음 text 원점을 전진시킬 수 있으므로 해당 소비 표현만 가시 문자로
비교하고, 렌더 트리 검사는 원문 공백을 포함한 전체 문자열을 그대로 검사한다.
이 정정 뒤 같은 최종 소스로 수정 전/후 실행을 다시 수행했다. 첫 로그도 보존했다.
정식 manifest를 준비해 공용 target·빌드 잡 8·테스트 스레드 12의 nextest도 별도로 실행한다.
아래 실행 결과를 확인하기 전에는 해당 Cargo 게이트 완료로 기록하지 않는다.

## 남은 범위

이전 생산 코드 `ee09c2d7c3a31aebc60a4c7c5b756352d82d1780`의 Native 전범위 큐는
71개 항목 모두 종료했고 69개가 수치 선행 조건을 통과했다. 당시 HWP3 19쪽과 배포 문서
3쪽이 미달이었다. HWP3의 이번 보정 증적과 그 이전 전범위 실행을 하나의 최종 head
검증으로 합쳐 보고하지 않는다. 최종 생산 코드 전체 TSV·devel 대비 0.01%p 하락 대조,
남은 회귀·lint·필수 게이트는 계속 수행해야 한다.

배포 문서의 표 x 위치는 아직 미해결이다. 새 9쪽 Print 통제군에서 공간이 남는 일반
자동 줄바꿈과 공백 자체가 줄 끝을 넘는 경우가 다름을 관측했다. 원문 ViewText 문단 47에는
저장 LineSeg가 없고, 전체 합성 HWPX 대조군은 DocumentCore에서 합성 LineSeg를 얻는다.
동일 규칙을 다른 측정/배치 경로가 소비하는지 추적 중이며 고정 8px 보정이나 마지막
공백을 무조건 이월하는 분기는 추가하지 않았다. 원장은 `stage1408-*`, `stage1409-*`,
`stage1410-*`, `stage1412-*`다. PDF shape 래스터가 실제 파란 띠를 잃는 별도 문제도
단계 1396의 미해결로 유지하며 기준이나 허용치를 바꿔 통과시키지 않았다.
