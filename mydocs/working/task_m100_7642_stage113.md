# Stage 113 — 캡션 저장 띠 누락과 수식 골든 반례의 원인 분리

Issue: #7642. 전체 55개 원본·853쪽, 회귀 292개와 #1139 전체 관계형 전환은 계속한다.
수식 HML의 기존 이관 범위는 복원하지 않는다. 신규 PR·전체 회귀 완료 판정은 아직 보류다.

## HWP3 캡션 정보의 독립 근거

원본 `samples/hwp3-sample.hwp`의 직접 Print job은
`75be4a50-4c64-4771-ba12-7435711ab68f`다. 분석용 정상 HWPX 저장 job은
`b427ebf1-5a3f-4dc6-b8bd-9b6f4354709e`이며 PDF 기준을 대신하지 않는다.
둘 모두 한컴 2020 engine이다. Print는 11.0.0.9136·PrintMethod 0·1-up 계약을
확인했다. 원본 16쪽과 RHWP 재저장본 16쪽의 Print는 서로 다른 기준이다.

문서 구조 3.0의 그림 정보 표 43에서 offset 46/48/50은 캡션 가로·세로·길이이고,
52/54는 박스·캡션·여백을 포함한 전체 크기다. 원본의 그림 4개에서 저장 캡션
세로는 1,852 HU, 내용 길이는 1,000 HU다. 전체 높이는 그림 높이 + 1,852 +
위·아래 여백 852씩이며, 한컴 정상 HWPX의 gap은 그 차인 852 HU다.
RHWP는 48/50을 읽지 않고 gap 0을 저장했다. 마지막 문단 줄간격을 더하면
독립 한컴 저장값과 달라지므로 그림 캡션에 표 캡션의 산식을 복제하지 않는다.

`parser::hwp3::picture_caption::stored_gap`이 이 저장 차이를 공통 Caption.spacing으로
옮긴다. 위·아래 캡션에 적용하며 아직 확인하지 않은 옆 캡션의 가로 띠를 세로
필드로 추정하지 않는다. 글꼴 바이트·윤곽·문서 ID·px 보정값을 추가하지 않았다.
새 fixture나 회귀 테스트는 추가하지 않았다. 이 변경의 빌드·시각 재검증은 다음 묶음이다.

생산·소비는 `그림 정보 48/50 → Caption.spacing →
composer::caption_height_px와 layout_body_picture의 caption_spacing →
캡션 원점 및 box_height → 후속 흐름`이다. typeset의 pushdown, 저장 그림 프레임,
layout_shape_item의 호스트 줄 처리도 소비 경로다. 후속 본문의 한 줄 전진과 측정의
캡션 예약 누락은 아직 원인 대조 중이며 간격 매핑 하나로 모두 해결했다고 주장하지 않는다.

정상 한컴 HWPX 자체를 같은 원본 Print와 Native로 대조한 결과도 최저 63.36314%,
8쪽 85.92816%다. 이 대조는 parser 속성 누락과 실제 배치 경로의 차이를 구분하는
분석용이며 원본의 시각 통과가 아니다. 수정 전 compare/review의 쪽 제목을 바로잡았고
래스터·같은 쪽·점수는 유지했다.

## 기존 수식 골든의 변경 분류와 독립 반례

이전 전체 nextest의 수식 골든 차이 242건 가운데 237건은 AST가 그대로이며,
5건은 위아래첨자 결합, LADDER/SLADDER 스타일, 빈 EQALIGN 행의 구조 변화다.
이 분류는 이전 실행 증거이며 현재 전체 회귀 재실행 결과가 아니다.
골든이나 허용치는 일괄 갱신하지 않는다.

5종 독립 입력의 정상 저장 job은 `42121815-4b16-40a0-a336-8caf66ca7598`,
Print job은 `97257b09-7747-4ca3-9e7e-22dffb6d604a`다. 크기·기준선·저장 줄을
지운 합성 입력을 한컴에서 정상 저장하고 Print로 재생성했다.
Native 전체 한 쪽은 73.00233%로 미달이다. 같은 좌표의 직접 확대에서는
위아래첨자 분수·빈 행 뒤 EQALIGN은 각각 100%, LADDER는 53.86667%,
SLADDER는 52.95699%다. 셀 원점과 괘선의 가로 간격이 다르다.

`stage113-golden-ast-review/golden-ast-native-print-detail-review.png`와
`detail-metrics.json`에 같은 배율의 판독과 영역 점수를 보존했다. 영역 선택은
진단용이며 정식 회귀의 고정 px 선택자로 사용하지 않는다. 공백 유무·글자/숫자·
가변 셀 폭을 9/15/22pt의 24개 수식으로 독립 저장·Print 대조하고 일반 규칙을
확인한 뒤 보정한다. 이 반례는 아직 시각 완료나 정식 회귀 증거가 아니다.

추가 분석의 정상 저장 job은 `be7427a0-465a-441b-9333-71cf9c2aed50`, Print job은
`941017ba-79a1-45a7-8499-092ce70ae6a2`다. 공백 유무의 폭은 24개 모두 같다.
15pt에서 한 자리 글자·숫자의 두 열은 2,850 HU, 긴 bbb 피제수는 4,200 HU다.
각 열의 실제 최대 전진폭을 별도로 정하고 제수 열에 반 em, 각 열 뒤에 0.2em을
예약하면 이 값과 일치한다. 이전 구현은 모든 열을 전체 최대 셀 폭으로 만들었다.
숫자 제수와 두 자리 피제수의 이전 대조군은 우연히 열 폭이 같아 이 오류를 검출하지 못했다.

`layout_ladder`에서 열별 폭·시작점과 첫 열의 제수 예약을 함께 생산하고 셀 배치와
공유 괘선이 소비하도록 바꾼다. 한 자리·긴 피제수·같은 열 폭의 기존 48개 대조군을
같은 빌드 묶음에서 재검증한다. 새 렌더링 통과와 회귀 추가는 아직 선언하지 않는다.

모든 TSV·JSON·로그·진단 래스터는 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`에 있다.
현재 전체 검증 controller는 소스 `a4454ac384f12bffe95eaec8356cefe2a63dda4c`의
고정 Native·WASM을 사용한다. 이후 캡션 변경의 결과와 섞어 보고하지 않는다.

## 보정 소스의 Native 실행 결과

소스 `86e4697b96d5bfacb0784839b742c7ac5663c51d`의 fmt·unit tier 정책·Native 빌드는
모두 종료 코드 0이다. fresh WASM은 같은 소스에서 빌드 중이다. 새 AST 반례 한 쪽,
공백·열별 폭 대조 24개 두 쪽, 원본 비-TAC LADDER 한 쪽은 Native 각각 100%다.
기존 숫자 대조 48개 세 쪽은 최저 99.72145%다. 같은 위치의 2배 확대에서
제수의 왼쪽 공간과 ㄴ자 괘선·피제수·결과 행의 간격이 독립 Print와 맞는 것을
확인했다. `stage114-ladder-before-after-review/ladder-before-after-print-review.png`에
변경 전·후·Print를 연결한다. 이 결과는 WASM 검증이나 전체 골든 갱신을 대신하지 않는다.

HWP3 원본은 캡션 간격 보정 후 3쪽 81.24545%, 8쪽 49.88585%로 여전히 미달이다.
특히 8쪽 점수 하락을 다른 쪽 개선으로 상쇄하지 않는다. 새 원본 결과는
`stage113-caption-ladder-focused/receipt.json`에 있다. 캡션이 붙은 그림의 저장
프레임을 일괄 줄 위치에 더한 첫 진단본은 17쪽이 되어 독립 기준 16쪽과 다르다.
한컴 저장본은 문단 41·78에는 그림 프레임을 반영한 호스트 위치를 저장하지만
문단 97은 기존 위치 21,440 HU를 유지한다. 이 비적용 반례 없이 일괄 가산하는
수정을 생산 코드로 채택하지 않는다. 두 적용 사례만 조정한 별도 진단본은
`stage114-hwp3-stored-two-frame-native`에서 대조 중이다. 문단 번호를 생산 분기로
사용하지 않으며, 일반 적용 조건은 원본 저장 정보에서 계속 추적한다.
