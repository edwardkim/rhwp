## 우선 보정과 추가 독립 근거

- 빈 PILE의 실제 경로는 composed line이 없고 `append_missing_single_equation_row`의 `flow_height > 0` guard가 호스트 생성까지 막는다. 표시 개체의 0 점유와 문단의 유효한 빈 글줄을 분리하고 원본 charPr·문단 스타일의 공통 프레임을 만든다. 생성 결과 → 측정/저장 → 실제 배치 소비를 함께 확인한다. 실제 저장 줄, 가시 본문 혼재와 정상 빈 템플릿은 보존한다.
- EQALIGN의 단어/분수 Print는 행별 원점인데 근호/괄호/첨자 Print는 & 열을 공유한다. 공식 [수식 형식 1.3](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_%EC%88%98%EC%8B%9D_revision1.3.pdf) 10쪽의 칸 소속 설명과 원본 토큰/그룹 경계를 대조한다. 타입·숫자 조건으로 대상을 좁혀 맞추지 않는다. 명시적 LHS 그룹, 항 전후 혼재, 괄호 안 분수, & 위치/간격의 독립 Print를 묶어서 산출해 칸 소유와 전진을 정한다.
- 같은 공식 문서 10쪽의 LSUB/LSUP은 **중위 명령**이다. 현재 prefix 해석과 다른 계약이다. 유효한 중위/괄호/연쇄 입력과 카탈로그의 prefix 입력을 한컴 정상 저장·Print로 대조해 항 소속·복구 문법을 확인한다. 카탈로그를 맞추려고 뒤 항을 버리지 않는다. SUP/SUB은 편집 창 표기와 스크립트 문법도 구분한다.
- 원 카탈로그 17쪽의 남은 차이는 직접 review와 원문으로 분리한다. 공개 호환 확장과 문서 생성 문법은 유지하고, 실제 Print 근거 없이 명령을 일괄 제거하거나 golden을 갱신하지 않는다.

## 추가 Print 근거와 미해결 사항

32쪽 대조군은 `pdf/issue7642-equation-ownership-diagnostic/`에 보존한다. 정상 저장 job `a892ec0a-ffbd-4c47-81f0-8be60c6e2545`, Print job `348a6d88-a1cf-470f-9529-17e68a82b464`다.
새 Print에서는 단어·분수·근호의 두 행 모두 & 칸을 공유한다. 이전 구조 대조군의 같은 단어 스크립트는 두 행 원점이 다르다. 기존 HWP 바이트의 재출력 두 번(job `5ecb1f82-eb3b-4ba4-be93-3612e5f471b5`, `80bf9810-14b4-47b6-9006-24326f601a3a`)은 기존 출력을 재현했다. EQEDIT는 byte-identical, common control은 instance ID 외 동일, DocInfo도 동일이며 문단 저장 줄의 세로 위치는 다르다. 문법 그룹/항 종류만으로 원인을 설명할 수 없으므로 정렬 분기 보정과 최종 판정은 보류한다. 추가 5쪽 순서 대조군도 동일한 & 열 정렬을 출력했다.

유효한 중위 왼쪽 첨자는 실제 표시되며, 잘못된 prefix LSUB/LSUP·SUB/SUP은 새 Print에서 빈 표시와 예약 영역을 남긴다. 오류 복구를 뒤 항 삭제로 바꾸지 않았고 카탈로그의 이 범위는 미해결이다. 새 관계형 회귀나 golden 기대값 갱신은 아직 수행하지 않았다.

Native 전체 재출력·확대 판독, fresh WASM, 55개 문서, 전체 회귀·lint와 PR/후속 처리는 미완료다. TSV·중간 JSON·로그·nextrun은 ignored output에만 둔다.
