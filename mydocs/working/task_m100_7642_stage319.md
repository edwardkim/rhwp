# Stage 319 — 변환 계보와 컨테이너 정책의 새 메타데이터 검사

Issue: #7642

기존 `hwp3_to_hwp5_variant_lineage_sync`는 계보 shim과 provenance의 동기뿐 아니라
`hwp3_layout == is_hwp3_variant`도 요구했다. 실제 저장 컨테이너가 HWP5인 변환본에서
계보는 true이고 HWP3 좌표 정책은 false인 것이 현재 명시된 계약이다.
`Document::layout_profile`의 컨테이너·계보 분리 설명과 FileHeader의 실제 major version으로
기대를 정하며 구현 출력의 화면 좌표를 새 기준으로 복사하지 않는다.

이전 검사를 제거하고 `tests/cases/issue_7642_converted_container_provenance.rs`에
새 이름으로 계보 보존, 파서가 읽은 HWP5 FileHeader, HWP5 저장 정책과 HWP3/HWPX
정책의 비적용을 검사한다. parser·renderer 생산 로직은 변경하지 않는다.

이 검사는 파일 메타데이터·정책의 계약이며 실물 배치·쪽수·fixture/golden을 추가하지 않는다.
시각 보정 완료나 실제 HWP3 변환 출력의 품질 통과를 주장하지 않는다.
렌더링 실패 원본과 별도 이슈 이관 대상의 활성 검증 경로는 이 검사로 대체하지 않는다.

정식 suite 실행·fmt/lint·base 고정 manifest 검사는 검토 worktree에서 실행한 후 기록한다.


## 사전 실행

Source315의 실제 Native release-test library를 연결한 새 이름의 메타데이터 검사는
컴파일 종료 코드 0, 1/1 통과했다. `CFB /FileHeader` 원문 서명과 버전 DWORD를
별도로 읽어 HWP5임을 확인하고 parser·계보·조판 정책의 관계를 검사했다.
사전 실행은 `target/pr-review/release-test/rhwp-stage319-container-contract`를 썼으며,
명령·소스 해시·결과는 ignored `stage319-container-contract.json`과 로그에 보존했다.
정식 integration suite·base 고정 정책·lint 검사는 별도로 필요하다.
