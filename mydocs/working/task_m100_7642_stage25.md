# 이슈 #7642 — TAC 도형 뒤 저장 줄간격의 보존

이전 단계 커밋: `e4df11cd963d44eaa5931438c9b17a2d2bc61064`.

## 독립 근거와 원인

`samples/3-11월_실전_통합_2022.hwp`의 마지막 쪽은 Native 88.61759%다.
동일 원본의 한컴 2020 Print PDF는 앞 단계에서 해시를 고정한
`mydocs/pr/assets/pr_7600_control_print_20261006/input-09-3-11월_실전_통합_2022-2020.pdf`다.
마지막 미주의 TAC 묶음 도형 줄은 높이 24309HU, 뒤 간격 452HU이고 다음
빈 문단의 저장 시작은 24761HU다. 따라서 도형 뒤 줄간격은 원본 저장 위치와
독립 Print 양쪽에서 확인된다. 도형 프레임 높이와 줄 높이가 같다는 사실은
간격을 버릴 근거가 아니다.

현재 formatter와 실제 배치의 진단에서 같은 문단의 다음 시작은 각각
330.1px / 324.1px다. 이후 `이므로` 문단도 같은 간격만큼 당겨진다.
이 좌표는 관측값이며 구현이나 회귀 기대값의 고정 px로 사용하지 않는다.

## 생산·측정·배치 경로와 보정 계획

1. 원본 LineSeg 높이·줄간격과 다음 문단의 시작 위치 →
   `format_paragraph_for_flow` → `compute_endnote_metrics`의 점유/진행값을 추적한다.
2. 실제 `layout_paragraph`의 TAC 도형 줄은 글자 높이로 접힌다. 이후
   `layout_column_item`의 도형 높이 복원 분기가 원본 줄간격을 재소비해야 한다.
   기존의 `shape_max_h < seg_lh` 조건이 그 간격을 버리는 원인이다.
3. 원본 저장 줄과 다음 문단의 위치 차이가 `line_height + line_spacing`을
   입증하는 조건을 유지하고, 프레임 높이 비교를 간격의 유효성 근거로 쓰지 않는다.
   저장 위치가 이를 입증하지 않는 줄·비저장 경로에는 간격을 추가하지 않는다.
4. Nov 17–21쪽과 Sep 7/8쪽, TAC 도형의 기존 대조군을 먼저 실행하고 영향 쪽
   review·확대를 직접 표시한다. 쪽수와 원본의 내용 보존도 확인한다.
   모든 실패는 이번 브랜치에서 보정한다. 검사 삭제·기대값 완화로 처리하지 않는다.

Native/fresh WASM 전쪽, 90개 실패의 최종 회귀, PR·CI·merge는 미완료다.
진단 명령·소스/바이너리/입력 해시와 로그·TSV는 ignored output에만 보존한다.
