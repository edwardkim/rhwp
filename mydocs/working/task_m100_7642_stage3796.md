# #7642 원본 HFT 공급 전쪽 대조와 법령 표의 원점 진단

Issue: #7642

## 원본 공급 조건의 독립성과 실행 출처

후보 실행 파일·fresh WASM의 실제 source는 `21bfc5b559b4c5b49edda70ffcee530228e8c059`,
base 실행 파일·WASM은 `6ed1682c3267ea786734eb2e75252916a861d1fd`다.
현재 후보 `11f0f74704a521bd1a348334ace06438a67e8c23`와 최신 devel
`224a326063a5aeab5a1ca8dcaa92918f55843ffc`에 대한 코드 동일성은
[리베이스 기록](task_m100_7642_stage3785.md)과 ignored 단계 3782 감사로 연결한다.
리베이스 SHA에서 새로 빌드했다고 표시하지 않는다.

독립 전체 한글 표본의 Print로 복원해 보관한 정규체 한양신명조 CFF를 공급했다.
대상 PDF에서 렌더용 글꼴을 추출하지 않았다. 공급 글꼴 SHA-256은
`d107d865d91ec72cede123e05bee1c2419b8bf869bf80af7475622ee7cdff035`다.
대상 10쪽의 Type3 두 subset에서 비교한 윤곽·전진폭 227개와 104개는 모두 같다.
다른 subset의 26개는 일치하지 않았으며 해당 face까지 같다고 주장하지 않는다.
글꼴과 독립 표본 PDF는 저장소 밖 로컬 경로에 보존한다.

base·후보와 Native·WASM 모두 같은 고정 글꼴 경로를 공급하고 3문서 30쪽을 각각
새로 캡처했다. WASM manifest에는 한양신명조로 적재한 실제 bytes의 SHA가 기록돼 있다.
Native에는 같은 글꼴 경로와 명령이 기록돼 있으며, 별도 실제 선택 trace까지 수집했다고
주장하지 않는다. 기존 시스템 대체 글꼴 결과는 다른 공급 조건으로 보존한다.

| 입력 | base Native 최저 | 후보 Native 최저 | base WASM 최저 | 후보 WASM 최저 |
| --- | ---: | ---: | ---: | ---: |
| `samples/issue1880_takeplace_host_before.hwpx` | 48.22946% | 93.37061% | 48.17509% | 93.35370% |
| `target-no-split.hwpx` 진단 대조군 | 55.21455% | 93.37061% | 55.24783% | 93.35370% |
| `all-two-row-no-split.hwpx` 진단 대조군 | 55.21455% | 93.37061% | 55.24783% | 93.35370% |

모든 후보 쪽의 raw는 90% 이상이고 독립 PDF와 10쪽씩 일치했다. 같은 조건의 base 대비
0.1%p 이상 하락은 양쪽 모두 없다. 이 결과를 글꼴 미달 예외나 기존 fallback 조건의 통과로
바꾸지 않는다. 6·8쪽의 review와 standalone overlay를 직접 열었다. 8쪽 하단 제목과
후속 표의 세로 차이, 왼쪽 셀 일부 줄 나눔 차이는 남아 있어 시각 완료 판정은 보류한다.
5쪽 100%도 다른 쪽의 결함이나 전체 문서 직접 판독을 대체하지 않는다.

## 법령의 글꼴 가설과 원점 추적

`78494-virtual-convergence-industry-decree.hwpx`는 확장자와 달리 실제 HWP5다.
독립 PDF 9쪽 휴먼고딕의 CID 매핑을 따라 설치된 `HMKMG.TTF`와 읽기 전용으로 대조했다.
47개 글리프의 분해 윤곽과 전진폭이 모두 같다. 이 범위에서 글꼴 버전 차이로 분류하지 않는다.
PDF는 굵은 글자에 fill+stroke를 쓰며 대상 PDF의 글꼴 bytes를 공급하거나 설치하지 않았다.

같은 쪽의 표 전체는 후보에서 약 1.8px 위에 있다. 원본은 문단 기준 오프셋과 위 바깥여백
141 HWPUNIT를 저장한다. 74쪽의 최상위 표와 PDF 수평선을 대조한 진단은 84개 대응 후보를
찾았고, 9·32·50·66쪽의 같은 표 구조 네 곳에서 약 1.7~1.8px 차이를 관측했다.
다른 표는 이미 맞거나 다른 방향의 잔차가 있으므로 모든 표에 여백을 더하지 않는다.
자동 선 대응은 독립 기대 좌표의 확정이나 시각 통과가 아니다.

`layout.rs`가 바로 앞 host 글 조각에서 문단 상단과 내용 바닥을 전달하고,
`compute_table_y_position`이 문단 오프셋·위 바깥여백을 해석한 뒤 push floor와
본문 제한을 적용한다. 현재 위여백 분기는 저장 앵커를 재선택했을 때만 열린다.
선택한 앵커의 좌표계와 여백 소유를 먼저 확인하고, 원본 바깥여백만 바꾼 독립 Print 대조군으로
기대값을 확인한다. 글꼴·합성 획을 점수에 맞춰 바꾸거나 문서 번호/1624 같은 수치를 분기 조건으로
추가하지 않는다. 적용·비적용 경로와 측정·예약의 소비까지 확인한 뒤 공통 규칙을 보정한다.
