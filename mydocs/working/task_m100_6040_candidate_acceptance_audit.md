## 사용자 측면 변화와 제한

- 빠른 확대·축소 재입력에서는 시작하지 않은 구 배율 작업을 폐기하고 최신 요청을 우선한다.
- 줌만 바뀌었다는 이유로 모든 페이지 surface를 일괄 해제하지 않는다. 기존 화면을 유지하며
  필요한 페이지를 갱신한다. **처음 보는 모든 쪽의 저화질 placeholder를 만드는 구현은 아니다.**
- 스크롤 후 클릭하지 않아도 정착한 읽기 페이지가 원래 요청 화질로 복원되도록 한다.
  raw 요청은 기존 per-canvas 안전 clamp를 거치므로 모든 고배율에서 effective DPR 2를 보장하지 않는다.
- 입력 정착은 120ms quiet heuristic이다. 물리적인 핀치 종료 이벤트를 완전히 대체하지 못한다.
- 이미 시작한 동기 WASM/native raster를 중간에 선점하지 못한다. rAF 경계를 둔다고 실제
  compositor 표시 완료나 GPU 업로드 감소까지 보장되는 것은 아니다.

화질 보호는 비용이 없는 변경이 아니다. 이전 settled-visible 64M 제한에 따른 하향을 제거해
읽는 페이지의 품질을 지키므로, 고배율에서 메모리·래스터 비용이 증가할 수 있다. 이번 후보를
“모든 정책을 그대로 둔 순수 CPU 최적화”로 설명하지 않는다. peak 메모리와 재입력 응답성을
완료 조건에 남긴다.
