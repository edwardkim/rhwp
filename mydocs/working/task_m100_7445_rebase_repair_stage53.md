# Stage 53: 작은 중첩 표의 저장 프레임과 부모 컷 소유 복구

Issue: #7445. parent `247988f3e981b9c4d9d56c24a1dc9f98457ec82b`, base `f7abae4a8e70c062c378db06ad64d2d2eacb88cd`다. 기존 개인정보 문서의 65→66쪽만 보정했고 HWP/HWPX 대상, 원본, PDF, 검사 기대값·문턱과 지침은 바꾸지 않았다.

원 해결 계보 #5846 → #5904 → #5912(b9eb551), #7642(363ef22d2c7), 기존 부모 종료 증명과 현재 #7752 정규화 경로를 대조했다. 부모의 앞 온전한 행 9864 HU + 자식 첫 프레임 1794 HU + 부모 위/아래 안 여백 223 HU씩 = 부모 선언 12104 HU가 닫히고, 자식 네 줄의 끝과 부모 다음 줄 원점 6262 HU도 닫힌다. 원본 내용·원점을 ID/쪽수 상수로 보정하지 않고 이 기존 증명을 canonical 프레임 원장에 연결했다.

실제 소비 추적에서 자식 5개 원본 줄은 정상 투영됐으나 부모의 저장 경계 조회가 부모 글줄 범위가 없는 재귀 유닛을 기각했다. 조회를 자식의 정확한 RowCut과 인증된 프레임에 대응시키고, 별도 단일 유닛 이월 가드도 같은 판정을 소비하게 했다. 일반 용량 컷·증명 없는 reset·편집된 저장 정보는 종전 경로를 유지한다. 부모 선언이 상하 안 여백까지 닫은 경우에는 그 소유 사실을 같은 원장에 싣고 기존 padding trim 소비자가 읽는다. 측정과 부분 paint가 같은 물리 높이/원점을 소비하며 열린 일반 중첩 프레임의 기존 trim은 유지한다.

P43 snapshot 등록은 P42와 전 66 PNG가 같아 수용하지 않았다. P44·P46 추적 코드는 제거했다. P45는 저장 경계 조회만 복구해 기존 검사 FAIL이었다. P46에서 같은 컷에 `stored_page=true`, `defer_single=true`임을 확인했고 P47에서 두 판정을 연결해 기존 #5846 검사 FAIL→PASS 및 집중 123/123 PASS를 얻었다. P47 직접 판독에서 부모 아래 안 여백 223 HU가 빠져 65쪽 행이 26.8933px(PDF 29.8879px)이던 잔여를 P48에서 원본 소유로 복구했다.
