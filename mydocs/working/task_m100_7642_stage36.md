# 이슈 #7642 — 미주 경계 간격의 예약과 소비 일치

시작 커밋은 `b55369c0d`다. 이번 회귀 실패는 현재 브랜치에서 보정한다.

## 독립 근거와 원인 경로

원본 `samples/3-11월_실전_통합_2022.hwpx`의 2024 Print 13쪽에서
(iii) n=9 그림 설명은 왼쪽 단 하단, 그림은 오른쪽 단 시작에 배치된다.
현재 출력은 설명까지 오른쪽으로 이월한다. 앞 미주 그림의 뒤 간격을
`prepare_endnote_emit → apply_endnote_tail_spacing`에서 현재 단에 예약하지만,
다음 제목의 `compute_endnote_metrics`가 직전 저장 bottom에서 다음 bottom까지
같은 간격을 다시 누적한다. 실제 렌더는 예약된 tail 간격을 한 번만 소비한다.

변경 전 기록은 ignored `stage15-current-validation/nov2022-before-p13-fit.log`와
`nov2022-p15-unmodified-vpos-debug.log`에 있다. pi593의 tail 예약 후 누계는
224.08이고 pi594는 자체 줄 전진 18.0267 대신 38.4533을 더한다. 중복분
20.4267은 이미 예약한 간격 증가분과 같다. 이는 진단값이며 구현 상수가 아니다.
실제 마지막 그림 점유 뒤 설명 줄은 들어가는데 누계의 초과 예약 때문에 이동한다.

## 보정 계약

- tail 간격을 소유한 현재 단에 실제 더한 증가분을 준비 결과에 전달한다.
- 새 미주의 첫 문단이 같은 단에 남고 저장 vpos 전진에 그 경계 간격이 포함된
  경우에만 이미 예약한 부분을 소비에서 제외한다.
- 문단 자체 줄 전진과 trailing 간격은 보존한다. 단 이동 후에는 앞 단의 예약을
  새 단에서 차감하지 않는다. 내부 되감김의 별도 줄 합산 경로도 그대로 보존한다.
- 저장 bottom 자체를 변경하거나 bleed·픽셀 허용치를 추가하지 않는다.
  원문 파일·Document/IR·기존 회귀 기대값·baseline은 변경하지 않는다.

생산 `state/commands.rs`의 실제 예약 → `prepare.rs`의 미주별 전달 →
`paragraph.rs`의 첫 문단·단 소유 확인 → `metrics.rs`의 fit/advance를 연결한다.
최종 render는 기존 tail 간격을 사용하며 따로 간격을 줄이지 않는다.

## 검증

Native build·Clippy 후 같은 2024 Print로 13·14·15·17쪽의 실제 출력과
HWP/2020 정상 대조를 확인한다. zero-gap HWPX는 예약이 없는 반례다.
개선되면 전쪽 Native와 fresh WASM을 실행하고 미세 수식·간격을 확대 판독한다.
90% 선행 조건을 만족하기 전에는 관계형 회귀로 기대값을 변경하지 않는다.

## 첫 시안의 재검토

저장 vpos의 원시 전진량에서 예약분을 먼저 제외한 첫 시안은 Native build·Clippy를
통과했지만 pi594의 전진량이 38.4533에서 40.0으로 바뀌어 중복 예약을 해소하지 못했다.
기존 과대 vpos 보정의 조건을 차감으로 먼저 바꾼 것이 원인이다.
이 시안의 바이너리는 `rhwp-endnote-prepaid-gap`이고 SHA-256은
`bc0e6418f7813a7239d92e066958acb00b6f7cc9c27062cf8bede3a5c5a5d409`이다.
진단은 `nov2022-prepaid-gap-p13-fit.log`에 보존한다. 진행 중이던 시각 검증은
해당 시안을 채택하지 않아 중단했으며, 부분 PNG를 통과 증거로 사용하지 않는다.

원시 저장값에 대한 기존 재검토를 먼저 수행하고 그 최종 전진량에서 예약분을 제외한다.
제외량은 실제 예약분·저장 경계 간격·문단 자체 전진을 뺀 잔여의 최솟값이다.
따라서 자체 줄과 trailing 간격이 사라지지 않는다. 수정 시안은 별도 frozen
`rhwp-endnote-credited-gap`으로 빌드하고 같은 영향 페이지를 다시 비교한다.

수정 시안의 진단에서 pi594는 자체 줄 전진 18.0267로 복원됐고 pi610 설명도
앞 단에 들어갔다. 동시에 pi593이 마지막 실제 넘침 검사에서 새 단으로 이동한 뒤
이동 전 전진량 197.6267을 재사용해 자체 trailing 6.0267이 누계에서 빠지는 경로를
확인했다. renderer는 224.08의 그림+경계 간격을 소비하지만 누계는 218.0533이다.
이 값들도 구현 상수가 아닌 원본 줄 메트릭의 관측값이다. 실제 render보다 작은 누계를
유지한 채 90% 통과로 완료하지 않는다.

처음에는 후단의 단 이동 뒤 재계산 누락으로 추정했지만, 실제 FLOW_BREAK 호출 위치는
`page_offcanvas_with_para` 분기였다. 후단 재계산 시안은 이 경로를 고치지 못하므로 제거했다.
이동 직후 `prev=None`으로 다시 계산하는 기존 호출은 이미 실행된다. 진짜 원인은
이전 단에서 산출한 local 되감김 상태를 `compact_local_rewind`에서 여전히 사용해
자체 줄 높이의 trailing 간격을 제거하는 것이었다. 실제 이전 문단이 같은 단에 있는
`prev.is_some()`인 경우에만 문단 간 compact 되감김을 적용한다. 내부 줄 되감김은
독립적인 상태이므로 유지한다. 재계산 시안 바이너리·패치는 ignored output에 남긴다.

## 현재 보정의 검증

현재 frozen Native는 `rhwp-endnote-owned-span`이고 SHA-256은
`e89ec2b139a33921b0617b0d57c4cd43b0d683c2ca5217f8f63eb13ab7926a1f`이다.
Native build exit 0(6분 1초), Native Clippy exit 0(49.50초)이며 포맷 검사도 통과했다.
소스와 실제 실행 명령은 ignored `endnote-owned-span-native-provenance.json`에 고정한다.

| 원본·기준 | 페이지 | 현재 2px 실루엣 일치율 |
| --- | --- | --- |
| 2022 HWPX·2024 Print | 13 / 14 / 15 / 17 | 98.03330 / 96.85306 / 95.75481 / 97.23218% |
| 2022 HWP·2020 Print 정상 대조 | 13–15·17 | 최저 95.73324%, 선택 4쪽 모두 통과 |

두 원본은 기준과 같은 전체 21쪽이며 표는 선택 쪽의 결과다.
최신 13쪽 review PNG와 같은 좌표·배율의 수식 확대 이미지를 직접 열고 표시했다.
설명 `(iii) n=9`는 왼쪽 단 끝, 해당 그림은 오른쪽 단 시작에 있다.
원본 source 문단 178의 미주 문단 7·8 소유와 순서를 `dump-pages`로 확인했다.
`nov2022-owned-span-p13-fit.log`에서 pi593은 자체 203.6533, 경계 예약 후
224.08을 소비하며 renderer도 224.08이다. pi594는 자체 18.0267만 소비한다.
좌표 허용치를 넓히거나 잘못된 배치를 baseline으로 고정하지 않았다.

확대 판독에서는 수식 중괄호, 첨자와 기호 주변 간격의 차이가 남았다.
점수와 별개로 이 영역은 아직 시각 완료가 아니다. 실제 PNG와 crop 원본 해시는
`endnote-owned-span-p13-equations-zoom.json`에 보존한다.
간격이 없는 대조의 재검증도 완료했다. 14쪽 93.10374%, 15쪽 75.79976%로
Stage35 및 이번 간격 보정 전과 동일하다. 15쪽 미달은 현재 브랜치의 후속 보정
대상이며 검사·원본을 제거하거나 별도 이슈로 이관하지 않는다.
최신 21쪽 전수 Native는 진행 중이고, 최신 fresh WASM·전체
회귀·전체 lint는 미완료다. 관련 회귀 기대값·baseline을 아직 변경하지 않았다.
현재 부분 개선을 PR 준비 완료나 통합 승인으로 보고하지 않는다.
