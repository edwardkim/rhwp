- 리베이스 전 head는 `85f5af6f4613ad72f79379e7172fd73a693a169d`다. 백업 `backup/7642-before-rebase-20261015-85f5af6f`에 보존하고 `--rebase-merges --reapply-cherry-picks --empty=keep`으로 이력을 유지했다.

## 충돌 통합의 의미

1. 문단 테두리: 새 devel의 `border_ignore_margin` 의미를 기존 공통 `paragraph_border_box`에서 소비한다. 옛 중복 배경 상자 계산을 다시 추가하지 않는다.
2. 인라인 개체: 새 devel의 원본 UTF-16 제어 위치를 보존하면서 종단 개체와 개행 뒤 줄 소유를 유지한다. 일반 흐름과 편집 프레임은 이 브랜치의 공통 `equation::flow_metrics_hwp` 기준선을 함께 소비한다. 새 devel의 선언 높이·백분율 기준선과 이 브랜치의 실측 수식 상자 계약은 같은 값이라고 가정하지 않으며 실제 출력과 편집 저장 대조가 필요하다.
3. 구역 끝 목록: 새 devel의 `SectionTail` 원본 보존을 유지하고, 표시 의미의 투영에는 이 브랜치의 `parse_extended_master_pages`를 사용해 임의 바탕쪽의 지정 쪽 번호도 보존한다.
4. TTC 공급: 새 devel의 `write_font_face`로 원본 SFNT 테이블을 복사하고 공용 해시 캐시에 원자적으로 공개한다. `TTFont.save`로 되돌리지 않으며 `nameRecordErrors`도 캐시와 manifest에 보존한다. 도구 모듈 SHA가 바뀌므로 이전 재컴파일 face 캐시는 재사용하지 않는다.

## 실제 검증과 구 기준 증거

- 리베이스 전 소스 85f5의 단계 779는 포맷·세 Clippy·workspace 빌드·집중 검사·Native Skia·정책 검사 19단계를 모두 통과했다. 새 소스의 결과로 대신하지 않는다.
- 같은 소스의 보도자료 Native 직접 PNG 전체 17쪽은 최저 **97.02736%**, 1쪽은 **98.95977%**다. 입력과 독립 Print PDF를 백업 Git 객체에서 꺼내 SHA를 확인했고, 변경되지 않는 review worktree의 도구와 frozen binary로 산출했다. 단계 786은 리베이스 전 진단이며 새 head의 최종 증거가 아니다.
- 리베이스 후 `venv/bin/python -m unittest discover -s scripts/tests -p test_visual_sweep_png.py`는 **20/20 통과**했다. 캐시 재사용과 손상 복원뿐 아니라 원본 SFNT·CFF·날짜·유효한 family 이름·UTF-8 보존 검사도 함께 실행했다.
- 구 기준 대기 중이던 Native/fresh WASM 실행과 구 기준 전체 비교 controller는 새 devel 전진을 이유로 종료했다. 실행 중인 Cargo는 중단하지 않았고 19단계의 최종 결과를 확인했다. 구 전체 비교의 당시 자식 작업도 중단하지 않았다. 별도 출력이 없다는 이유로 재시작하지 않았다.

## 남은 검증

새 기준에서 병합된 Rust 코드·인라인 수식 편집 저장·구역 끝 목록·집중 회귀·전체 회귀·Native/fresh WASM을 검증한다. 55개 원본 853쪽과 관련 대조군의 시각 범위는 유지하며 새 devel 대비 0.01%p 하락도 다시 산출해야 한다. 구 기준 4개 하락 쪽을 새 기준의 판정으로 옮기지 않는다. 이미지 채우기와 HWPML의 미달 보정도 남아 있다. 현재 PR 준비·CI·merge 완료를 선언하지 않는다.

## 사용자가 지정한 최종 제출 순서

- PR 생성 직전에 `upstream/devel`의 실제 SHA를 다시 확인한다. 고정한 검증 base가 바뀌었으면 변경을 보존해 리베이스하고, 새 base/head의 필요한 전체 검증을 완료한 후 제출한다. 같은 SHA이면 반복 리베이스하지 않는다.
- 모든 테스트·시각 검증이 완료된 코드 후보로 PR을 생성하고 정확한 code head의 CI를 모니터링한다.
- CI 성공 뒤에는 사용자가 지정한 **옵션 2: 별도의 새 PR**로 해당 코드 PR의 review와 오늘할일 기록을 처리한다. 기본 self PR의 같은 브랜치 trailing 방식 대신 이번 사용자 지시를 따른다. 번호와 실제 CI 증거가 나오기 전에 번호 기반 review·오늘할일을 만들지 않는다.
- 기록 PR의 최신 head CI·실제 병합 가능 상태까지 확인하고, 승인된 머지와 후속 처리를 완료한다. 코드 PR·기록 PR의 head와 CI, merge 결과를 구분하며 후속 기록 PR을 재귀적으로 만들지 않는다.
