# #7642 Stage 143 — 높이 0 미주 경계의 줄간격 소비

Issue: #7642

## 구현 전 근거와 반례

시작 head는 `bad8e50ac`, 생산 검증 source는 `68d8bf777f`다. 전체 Sweep에서 11월
`구분선위0미주사이0구분선아래0` HWP/HWPX의 10쪽이 각각 85.44196%다. 나머지
20쪽은 90% 이상이며 원본과 독립 한컴 2024 Print는 모두 21쪽이다.

원본의 마지막 본문 문단 450은 빈 문단이지만 저장 줄 높이 900 HU와 줄간격 452 HU를
가진다. Print의 첫 해설 제목과 Native의 차이는 이 마지막 줄간격에 해당한다. 빈 줄 자체의
점유 높이를 없애는 수정은 하지 않는다. Print에서 높이 0 경계에도 보이는 구분선이 Native에는
없다. 입력이나 독립 PDF를 바꾸지 않고 같은 원본으로 확인한다.

현재 `prepare_endnote_emit`는 구분선 위·아래 여백 합이 양수일 때만 경계 항목을 방출한다.
`build_single_column`은 그 항목에서 직전 본문의 마지막 줄간격을 제외하고 구분선을 그린다.
따라서 여백 합이 0이면 경계 의미와 선 paint까지 사라진다. 선 굵기는 흐름 높이의 대용이 아니다.

수정 경로는 `note_separator`의 완료된 본문 꼬리 조회 → `prepare_endnote_emit`의 흐름 예약과
미주 저장 원점 투영 → `build_single_column`의 같은 경계 소비 → `layout_endnote_separator_item`의
선 paint다. 높이 0 경계에서 측정·배치가 같은 원본 HU를 소비하고 빈 줄의 높이는 보존한다.
양수 위·아래 여백의 기존 동작은 대조군으로 유지한다. 마지막 줄을 아직 소비하지 않은 조각,
앞 단의 꼬리, 표·도형 항목 뒤에서 이전 글줄을 거슬러 회수하는 경우는 반례다.

## 검증 범위

- HWP/HWPX 원본 10쪽과 앞뒤 경계, 전체 21쪽 및 fresh WASM을 다시 대조한다.
- 양수 여백 11월 구분선없음/20/20, 0/7/2 문서를 대조한다.
- 모든 관련 쪽의 90% 이상과 확대 판독 전에 새 렌더링 회귀·골든을 추가하지 않는다.
- 통과 뒤 새 이름으로 빈 문단의 점유, 제목 순서·소유와 구분선 관계를 검사한다.
- 최종 전체 회귀·lint와 292개 의미 복원은 계속 별도 필수다. 지금 단계는 미달 출력 보정이다.

로그·TSV·중간 JSON·nextrun은 ignored output에만 보존한다.

## 실제 Native 검증 결과

보정 Native 빌드는 exit 0이며 빌드 전후 생산 source 해시가 일치한다. 바이너리 SHA-256은
`e02987f4376305b4ba86f5e3f78981cf809cf6e0b05e85963cd6f03de2b4e953`다. `fmt`,
`fmt-check`, Native/WASM lib Clippy, workspace build, workspace/all-target Clippy,
고정 base 대비 manifest 정책의 7단계 모두 exit 0이다.

원본 HWP의 9/10/11/21쪽을 재측정해 각각 99.75479/98.67338/98.34877/97.86274%를
확인했다. 원본과 독립 Print의 총 쪽수는 여전히 21쪽이다. 미달 10쪽은
85.44196%에서 98.67338%로 개선됐으며 이 쪽은 이진화 원값과 관용값이 같다.
양수 여백 대조군 `all-16`의 10/21/22쪽도 90% 이상이며 최저값 97.81114%다.
HWPX `all-19`의 선택 네 쪽도 모두 90% 이상이며 최저값은 97.86274%다.
양수 여백 대조군 `all-22`의 10/20/21쪽도 모두 90% 이상이며 최저값은 97.66512%다.
네 원본의 선택 총14쪽 측정을 실제 종료·판정했고 전체 쪽수도 각각 Print와 같다.

대표 전쪽 review와 동일 물리 영역의 보정 전/후/Print 확대를 실제로 열었다.
빈 문단 450의 상단·내용 높이는 `333.1/12.0`으로 보존되고 첫 미주 제목의 상단은
`351.1 → 345.1`이다. 이 수치는 출력 진단이며 회귀 기대값으로 고정하지 않는다.
마지막 줄간격 452 HU만 경계에서 제외하고 구분선도 표시한다. 첫 수식의 지수·괄호와
글꼴 잉크 차이는 추가 판독이 필요하며 확대 수식 판독 완료·완전 일치로 판정하지 않는다.
대표 증거는 [`issue7642-zero-note-boundary-20261012`](../pr/assets/issue7642-zero-note-boundary-20261012/README.md)에 보존한다.

전체 회귀 controller는 이 Native 대조군과 lint 종료를 실제 확인한 뒤 같은 source에서
`cargo nextest run --cargo-profile release-test --target-dir target/pr-review --tests
--test-threads 12 --no-fail-fast`를 실행하도록 준비했다. 대기 상태를 실행 완료로 보고하지 않는다.
그 결과·전체 Native/fresh WASM·남은 실제 실패 원본 보정이 모두 끝나야 PR을 생성한다.

## 실행 상태와 중단 관측

보정 source는 `f4bd0a760e930cc0bc9a257fb0a9b2f1c92a0513`에 커밋했다. 커밋한 생산 파일
전부가 Native 빌드 출처 원장의 해시와 일치한다. 전체 nextest는 선행 gate를 확인하고 실제
실행을 시작했다. `stage143-full-regression.json`의 Cargo PID 554631은 관측 시 살아 있으며
로그에 컴파일 진행이 있다. 최종 exit·summary 전에는 통과로 판정하지 않는다.

이전 source `68d8bf777f`의 전체 Sweep controller PID 437302는 `/proc`에서 사라졌고
그 출력 경로를 쓰는 visual worker 인자도 남아 있지 않다. 원장의 `running`만으로 실행 중이라고
보고하지 않는다. 종료 전 원장을 보존한 뒤 `interrupted_process_absent`로 기록했다.
확보한 측정은 Native 33문서/327쪽과 fresh WASM 28문서/222쪽이다. Native의 두 미달은
앞서 보정한 `all-18/all-19`의 10쪽이다. 종료 원인은 아직 확인하지 못했고 전체 완료가 아니다.
현재 보정 source의 전체 확인·fresh WASM 재빌드·미세 판독은 계속 필수다.
