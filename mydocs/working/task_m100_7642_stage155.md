# #7642 Stage 155 — 본문과 별도 흐름의 소유 및 TAC 저장 간격

Issue: #7642

## 근거와 수정 묶음

Stage 154 Native는 64쪽 중 6쪽(24, 35, 43, 45, 48, 49)이 미달이다.
43쪽 첫 세 본문은 원본 vpos와 일치하지만 Footer 컨트롤을 가진 문단 691에서
원본 앞 간격 568HU가 사라지고 후속 본문까지 차이가 누적된다. Header/Footer는
별도 프레임의 소유자이며 그 상자가 본문 글줄의 높이를 소비하지 않는다.
Footnote/Endnote의 본문 슬롯·예약과 구별해 부모의 텍스트 줄 앵커를 보존한다.
공통 본문 marker 분류를 저장 앵커와 순수 텍스트 재조판 전진에 함께 사용한다.

35·45·48·49쪽의 단일 TAC 표 줄은 `line_height = 표 높이 + 위아래 바깥여백`이다.
예를 들어 35쪽의 문단 603은 15792 = 15512 + 140 + 140HU다. 표의 높이는
재구성 사다리가 이미 소비하지만 그 다음 원본 줄까지의 빈 간격은 별도 소유다.
유효한 비편집 단일 줄과 캡션 없는 표의 실제 선언 상자가 정확히 닫힐 때만
`원본 점유 끝 → 재구성 점유 끝 → 다음 원본 줄까지의 간격`을 잇는다.
표 높이를 다시 더하거나 큰 표를 텍스트 줄 높이로 축소하지 않는다.
편집된 셀·표, 여러 소유 줄, 캡션과 상자가 일치하지 않는 경우는 추측하지 않는다.

경로는 `reflow_zero_height_paragraphs`의 source 간격 생산 → 저장 line_segs와
typeset 줄 높이/전진 → 본문 배치의 같은 vpos/개체 소유다. Footer 내부 문단의
line_segs를 본문 줄로 합치지 않는다. 표 뒤 텍스트뿐 아니라 표의 외곽과 다음 쪽을
새 Native 64쪽/대조군 9쪽에서 함께 검증한다.

## 남은 범위

5쪽의 점선 모양은 아직 Print와 다르다. PDF의 선을 단순 `dash` 연산자로
추측하지 않고 실제 작은 사각형 path의 길이·간격·두께를 분석해 독립 근거를 확보한다.
이번 저장 흐름 보정의 통과를 점선 보정 완료로 대신하지 않는다.
최종 fresh WASM/전체 55문서·853쪽, 전체 회귀와 lint는 계속 필요하다.
전쪽 90%·확대 판독 전에는 새 배치 회귀/기대값 변경·PR 생성을 보류한다.

## 실행 결과 (2026-10-12)

Native 빌드 종료 코드 0, 341.22초, source 해시 일치다. 대조군 9쪽은 모두 통과
(최저 98.50071%)했다. 전체 64/64쪽에서 이전 미달 6쪽은 모두 90% 이상으로
복원됐으나 37쪽이 새로 45.74496%가 되어 전체 검증은 실패다.
36쪽의 큰 TAC 표 609 뒤 제목 610이 현재 쪽 꼬리에 들어가 37쪽의 표가 위로 당겨졌다.
원본 표의 전진 끝은 71136HU이며 다음 쪽 원점 852HU와 제목 높이 1600HU를
함께 담으면 73588HU다. 본문 72848HU보다 크지만 기존 reset은 다음 높이만 더해
72736HU로 읽었다. 표 시작 vpos가 위쪽이라는 이유로 실제 점유 하단을 무시하는
후속 페이지 배정 경로도 함께 확인한다. 이 차이는 현재 보정에서 생긴 회귀이므로
이관·검사 제거로 처리하지 않는다.

점선 진단 입력의 Hancom 2024 Print도 확보했다. job은
`8f8cfe97-df63-4328-940c-687c8d8d005d`, 실제 버전은 13.0.0.3901,
PrintMethod=0, `frame_print_to_pdf_ex_one_up`, 전체 1쪽이다.
이 입력은 복제·편집한 합성 진단이며 원본 64쪽의 통과 증거를 대신하지 않는다.
`DASH`의 28/56/112/224HU 선은 Print에서 선분/두께 약 1.5, 반복 시작/두께 약
3.75의 같은 비율을 보인다. `DOT`는 긴 파선이며 기존 borderFill/tab mapping과
shape parser/serializer mapping의 불일치를 확인했다. Native 진단의 미달과 직접
판독은 별도로 남기며 새 배치 회귀·기대값 갱신·PR은 계속 보류한다.
