# Task M100 #4969 W10-Q2-C — dormant paragraph·line transaction

## 판정

Q2-C0~C2는 **qualified**다. 직접 저장된 옛한글 Jamo를 기능 탐지하는 좁은 horizontal LTR lane에서
paragraph segmentation, cluster-aware width owner, final-line reshape와 bounded convergence를 구현했다.
composer·layout·render tree·paint는 이 결과를 아직 소비하지 않으며 모든 line trace의
`productPublished`는 `false`다.

기계 판독 결과는
[`w10_q2_c_dormant_transaction.json`](../tech/investigations/issue-4969/w10_q2_c_dormant_transaction.json)이다.

Q2-C 단독 제품 활성은 여전히 기각한다. line selection과 emitted run이 같은 `Arc`를 소비하게 만드는 Q2-D
sidecar가 준비될 때 line boundary publication도 함께 열어야 한다.

## Q2-C0 — feature-detected activation

버전·한컴 build number를 묻지 않고 paragraph의 현재 상태만 판정한다. 최초 eligible lane은 다음 조건을 모두
만족한다.

- 직접 옛한글 Jamo가 있고 같은 target segment는 현대 Hangul 음절까지만 포함한다.
- horizontal-tb, LTR, bidi level 0이 상위 owner에서 확인됐다.
- model text와 shaping text가 1:1로 같고 exact source slot·size·장평·kerning 설정이 segment 안에서 같다.
- bold·italic·super·sub, 비영 자간, condense, inline control, tab, rotation, char overlap이 없다.
- fallback positions·style·hard-boundary 배열 길이와 scale이 유효하고 text·segment 상한 안이다.

hard boundary나 shaping identity split이 옛한글 cluster를 가르면 `hard-boundary-crossed` 또는
`style-boundary-crossed`로 문단 전체를 닫는다. 일반 Latin, bidi authority 미확정, display projection,
synthetic style와 spacing semantics는 typed reason을 남기고 기존 owner를 유지한다.

## Q2-C1 — cluster 단일 폭 owner

target segment는 Q2-B `HorizontalShapingContext`의 cluster 결과를, non-target scalar는 입력으로 동결한 W9/K0
fallback position을 사용해 paragraph width atom을 만든다. atom은 paragraph scalar 범위를 빈틈과 중첩 없이
한 번만 소유한다.

10px·장평 80% Source Han 공개 fixture `ᄒᆞᆫ글`의 결과는 다음과 같다.

| 범위 | 결과 |
| --- | ---: |
| K0 fallback paragraph | 16.000px |
| common-shaped paragraph `0..4` | 15.456px |
| 옛한글 cluster `0..3` | 7.728px |
| cluster 내부 `1..3` | 거부 (`None`) |
| 현대 음절 `3..4` | 7.728px |

혼합 fixture `Aᄒᆞᆫ글B`에서는 바깥 `A`·`B`의 fallback 폭을 각각 5px로 보존하고 target `1..5`만
15.456px로 교체해 전체 25.456px가 됐다. shaped target에 W9 pair adjustment를 다시 더하지 않는다.

## Q2-C2 — dormant line transaction

line transaction은 paragraph measurement와 같은 source generation·settings를 사용하고 다음 순서로 동작한다.

1. 입력 candidate를 정렬·범위·개수 검증한 뒤 cluster 내부 scalar boundary를 제거한다.
2. paragraph atom의 `range_width`로 initial line range를 고른다.
3. 채택 가능 final range를 독립적으로 다시 shape해 boundary context의 width와 `Arc`를 보존한다.
4. line range가 바뀌면 최대 2회 안에서 다시 결정한다.
5. source·glyph·cluster·후보·폭·attempt·수렴 조건이 실패하면 pristine fallback positions에서 문단 전체를
   W9 K1 또는 Existing K0 owner로 다시 계산한다.

후보 `[0, 1, 2, 3, 4]`, line width 10px인 옛한글 fixture에서 내부 후보 `1`, `2`는 채택되지 않았고 final line은
`0..3` 7.728px와 `3..4` 7.728px로 결정됐다. 이 결과는 final target run의 `Arc`와 함께 transaction 안에만
보존됐으며 제품에는 게시되지 않았다.

## rollback과 상한 증거

- exact source가 없으면 거절 attempt도 잃지 않고 `exact-source-unavailable`로 rollback한다.
- 앞 target segment가 성공한 뒤 뒤 segment가 source 부재로 실패해도 paragraph measurement는 `None`이고,
  앞 성공을 부분 게시하지 않는다.
- candidate 4,097개, shaping attempt 4,096개, final-line retry 2회를 상한으로 둔다.
- 역순·중복 candidate, 비유한·0 이하·과대 available width, attempt ID 공간 고갈은 typed rollback이다.
- `u32::MAX` attempt ID는 한 번만 기록되고 다음 ID가 필요하면 `attempt-limit-exceeded`로 닫힌다.
- rollback line에는 target run이 없고 요청에서 지정한 W9 K1 또는 Existing K0 owner가 그대로 기록된다.
- trace에는 raw text·font bytes·host path·private corpus identity를 넣지 않는다.

Node WASM 검증은 root dev dependency의 wasm32 제약을 우회하기 위해 root Cargo를 바꾸지 않는 최소 harness에서 같은
integration source를 실행했고 검증 후 harness를 삭제했다. runtime은 제품 layout 성능이 아니라 공개 fixture 테스트
참고값이다. 제품 경로가 dormant module을 호출하지 않으므로 Q2-C의 페이지 성능 영향은 현재 0이며, activation 이후의
layout 비용과 WASM size는 Q2-F에서 W9 기준선과 같은 조건으로 측정한다.
