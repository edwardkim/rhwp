# Stage 344 — 보존한 단 첫 여백과 후속 TAC 표의 내용 하단 연결

## 독립 근거와 원인

`samples/hwp3-sample16-hwp5.hwp`의 한컴 2024 Print 기준은 기존
`input-17-hwp3-sample16-hwp5-2024.pdf`다. 같은 입력의 물리 26쪽에서
제목과 본문 글자는 이전 정상 출력과 같은 위치지만 표와 자손만 위로 이동했다.
현재 원본 속성은 첫 문단 앞 간격 1704HU(실제 852HU), 첫 저장 원점 852HU다.
다음 문단의 저장 원점 4904HU, 줄 높이 1600HU와 뒤 줄간격 960HU는
표 호스트의 원점 7464HU를 연결한다. 문서 계보를 다시 HWP3 배치로 바꾸지 않는다.

실제 `RHWP_DIAG_FLOW`와 `RHWP_DIAG_FLOW_ORIGIN` 실행에서 다음을 확인했다.

- 일반 문단과 paint의 표 진입 커서는 같은 단 원점 0을 사용한다.
- 표 진입 paint 커서는 99.52인 반면, pagination의 이전 내용 하단은 75.36이었다.
- 저장 TAC 계획이 잘못된 하단에 상대 간격을 이어 붙여 88.16을 확정한다.
  paint는 확정 inline placement를 소비하므로 올바른 진입 커서가 있어도 표 원점이 덮어써진다.
- `paragraph/content.rs`가 첫 vpos와 단 원점의 동일성 및 앞 간격 0을 요구하여,
  이미 보존한 `StoredColumnTopSpacing` 프레임을 거부하고 트림한 순차 높이로 폴백했다.

## 수정과 적용 경로

단 첫 간격의 인증 프레임 → `stored_content_bottom`의 같은 원점 투영 →
실제 수용한 이전 내용 하단 → 저장 TAC의 상대 간격 연결 → inline placement →
표 paint 경로를 연결한다. 기존 프레임의 원점·간격이 원본 첫 vpos를 정확히 닫을 때만
사용한다. partial 첫 줄, 편집/재조판, dirty 저장 축과 인증되지 않은 첫 간격은
기존 거부 조건을 유지한다. 고정 px 또는 문서 ID 조건은 추가하지 않는다.

예외 분기를 추가하기 전에, 같은 정상 저장본의 독립 Print를 각각 재출력해 출처를 재확인한다.
