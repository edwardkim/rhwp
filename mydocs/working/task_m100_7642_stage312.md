# Stage 312 — 동일한 저장 TAC 줄의 후행 간격 계약

Issue: #7642

## 수정 전 근거와 원인 계층

사회 시험지 HWP/HWPX는 유효 글자 속성, 본문·셀 저장 줄, 46개 최상위 표의
측정 높이와 행 높이가 같았다. 각 입력의 독립 한컴 Print도 해당 본문의 위치가 같다.
그러나 Source269 Native는 HWP 91.19685%, HWPX 80.79%였으며 첫 쪽이 미달이다.

`tac_next_line_full_spacing`은 `현재 줄 원점 + 줄 높이 + 줄 뒤 간격 + 현재 문단 뒤 간격 +
다음 문단 앞 간격 == 다음 저장 줄 원점`이라는 독립 저장 사다리를 확인한다.
`stored_host`가 HWP5만 허용해 원본 HWPX는 동일한 사다리를 거절했다.
그 결과 `physical_tac::prepare`가 공통 확정 배치를 수용하지 않고 legacy 흐름을 사용했다.
표 앞뒤 문단 간격을 더한 뒤 별도의 높이 회수와 좌표축 갱신이 적용되어 위치가 갈렸다.

## 공통 결과의 실제 소비

- 생산: `composer/composition.inc.rs::tac_next_line_full_spacing`의 저장 사다리 계약.
- 측정·fit 소비: `typeset/controls/physical_tac.rs::prepare`가 실제 측정 표 높이·소유 줄과
  비교하고 `origin/end` 한 쌍으로 fit 예산을 검사한다.
- 배치 소비: `typeset.rs`의 `physical_tac::prepare` 성공 분기가 같은 origin/end를
  `commit_stored_tac_control`과 `record_inline_flow_bottom`에 전달하고 반환한다.
- paint 소비: `layout.rs`의 저장 TAC 후행 간격 선택도 같은 helper를 사용한다.
- 비적용: 편집 세션, dirty 줄 파티션, 구현 합성 태그, 뒤 문단 저장 원점 불일치에는
  기존 저장 원본 계약을 적용하지 않는다. 재조판 줄의 기존 계약은 별도 분기로 유지한다.

HWP5/HWPX 컨테이너 구분으로 동일한 저장 사다리를 거절하지 않도록 수정한다.
문서 이름·좌표를 사용하지 않으며 clamp, 예상 쪽수 변경, golden 완화는 추가하지 않는다.
같은 원본의 수정 전후 Native/fresh WASM과 HWP 정상 대조군을 실행한 뒤 판정한다.
전체 페이지 90% 이상과 직접 판독 전에 새 렌더링 회귀를 추가하지 않는다.
