## Studio 눈금자 timeout의 실행 방법 차이

앞서 재사용한 base 영수증을 실제 명령까지 다시 확인했다. base는 원래 눈금자 검사에
문서 열기의 실제 「대체 글꼴로 보기」 버튼 선택을 추가한 작업용 여정을 실행했다.
후보는 그 선택을 빠뜨린 등록 검사 원문을 실행하여 대화상자에서 기다리다가 timeout이 났다.
같은 잘못된 명령의 재실행도 실패했으며 두 실패 기록을 보존했다.

후보에서도 base와 동일한 작업용 여정을 실행했다. 원본 문서와 눈금자 assertion은 바꾸지
않았고, 두 문서에서 실제 글꼴 선택 버튼을 눌렀다. 세로 795px → 가로 1,123px의 눈금자
전환과 기존 세 검사가 모두 통과했다. 이 재실행은 timeout 값을 늘리거나 대화상자를
우회한 결과가 아니다. 기존 14개 base·후보 결과와 회복 영수증을 함께 보존한다.

이후 CTRL_DATA의 실제 HWP 편집·저장·재열기를 4개 원본에서 각 2회 실행했다.
별도 olefile·DEFLATE 레코드 판독기로 소유 경로와 payload SHA를 8회 모두 대조했다.
각 입력의 물리 packet 수 60·2·2·2와 소유·내용이 보존되었고 공개 본문도 유지되었다.
공개 기여자 gate 4개 문서의 양쪽 TSV·manifest·PNG도 정식 증거로 보존했다.

## 보호 글꼴 조사의 현재 한계

SPJGT를 포함한 자동 원본 선택의 화학 Native 전쪽 103쪽은 base·후보 최저 99.93%로
동일하지만 60·70·72쪽은 기존 100.00% 하한에 미달한다. 세 쪽의 높은 점수로 완료 처리하지
않는다. 같은 공급의 WASM도 전쪽 대조에서 추가 기호 차이가 있어 자동 선택을 정본 공급의
완전한 복원으로 채택하지 않는다. 실패한 Chrome 시작과 재실행도 별도 보존한다.

수정 없는 실제 Native 공급 추적에서 60쪽 U+279C 화살표는 Apple SD Gothic Neo·함초롬돋움,
72쪽 U+2022는 맑은 고딕으로 대체되는 것을 확인했다. SPJGT에 해당 Unicode 매핑이 없어
원본 기호 공급이 끝나지 않은 상태다. 시행령 따옴표는 Palatino가 아니라 한양신명조/HY신명조
경로이며, Windows 원본 Palatino 4종 공급만으로는 해당 미달이 해소되지 않았다.

과거 보호 공급 목록과 SHA가 일치하는 Windows Palatino를 승인 범위에서 추가 복사했고
시스템 설치와 Git 바이트 반영은 하지 않았다. 새 설치 OTF를 그대로 쓰는 비교도 별도로
실행했으며 기존 미달을 해소했다고 판정하지 않는다.

독립적인 한양중고딕·한양신명조 전체 한글 11,172자와 표준 기호·일반 문장부호의 표본을
별도로 만들었다. 각 11,187자를 Windows 한컴 2020의 Print 경로로 출력해 기호 매핑을
검증한다. 대상 문서·기준 PDF의 글리프나 좌표를 글꼴 생성에 사용하지 않고, 기존 보호 TSV·
PDF·판정 기준도 바꾸지 않는다. 이 조사는 진행 중이므로 보호 검증 준비 완료를 주장하지 않는다.
