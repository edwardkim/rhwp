# #7642 단계 2689: PostScript 식별자로 동일 글꼴 프로그램 조회

Issue: #7642.

## 원인과 변경

`HCRDotum-Bold`는 공식 `HANDotumB.ttf`의 name ID 6이며 family는
`HCR Dotum`이다. PDF subset의 고유 윤곽 57개와 전진폭 57개가 이 설치본과
일치했다. Regular 설치본의 윤곽 일치는 0개다. 프로그램 SHA-256은
`5b0b9fa5f3ba2f7b2e3576c6c2e2f2a7a92f68c98f8270e10791ceb363ce1e51`이다.

Native의 요청 family 판정은 이 식별자를 제외해 일반 대체 글꼴을 선택했다.
실제 family는 기존 CSS style 선택을 유지하고, family가 아닌 요청은
Typeface의 정확한 PostScript 이름이 같은 face만 수용한다. OS가 돌려주는
다른 폴백 프로그램은 거절한다. 필요한 시스템 face 색인은 renderer가 공유하는
시스템 목록 안에서 한 번 만들며, supplied catalog에도 별도 face 식별자로 보존한다.
FULL_NAME을 family로 등록하거나 문서별 정적 치환을 추가하지 않았다.

생산 경로는 `Typeface::post_script_name → font_lookup/font_catalog →
text_typeface_candidates → paint 및 같은 공개 font trace observer`다.
측정·원본 모델의 font 이름이나 좌표는 수정하지 않는다. source별 우선순위는
각 요청 안에서 custom → system → bundled 순서로 유지한다.

| 항목 | 결과 |

| name ID·공식 프로그램·PDF 윤곽 대조 | Bold 57/57, Regular 0/57 |

| 확대 판독 | 제목 굵기 개선, 날짜 굵기와 본문·그림 차이는 미해결 |
| 새 코드의 rustfmt 및 incremental diff check | 통과 |
| 새 코드의 Native 컴파일·정식 회귀·시각 검증 | 대기: af71 Native/WASM 작업 종료 후 같은 공용 target 사용 |

진단 환경은 최종 후보의 환경 또는 통과 증거로 승격하지 않는다. 결과는 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`의
`stage2685-pdf-postscript-family-diagnostic/`과 `stage2686-pdf-title-font-identity/`에 있다.
기존 full-face 비별칭 검사는 유지하고, 독립 name ID 6을 사용하는 작은 합성 계약을
새 이름 `explicit_postscript_identity_selects_its_supplied_program`으로 추가했다.
이는 실제 한컴 조판·픽셀의 일치 증거가 아니다.
