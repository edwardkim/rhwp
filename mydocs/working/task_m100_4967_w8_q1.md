## 2. current native/WASM trace

기존 CLI의 기본 1,024자 상한은 유지하고, core의 기존 보안 상한 `1..=4096` 안에서만
`--max-characters`를 지정할 수 있게 했다. 공개 fixture 전건은 1,556자다.

| 항목 | 결과 |
| --- | ---: |
| characters seen / emitted / omitted | 1,556 / 1,556 / 0 |
| metric entry `null` / match kind `none` | 1,556 / 1,556 |
| heuristic fullwidth / halfwidth / narrow | 390 / 1,114 / 52 |
| native/WASM canonical trace | byte exact |
| canonical trace SHA-256 | `54a79a950aa138b6873632ac37f0db45ded37d4b40ac102a2816744830a659a3` |

즉 현재 `KoPubWorld바탕체 Light`의 layout은 exact `hmtx`가 아니라 전건 heuristic advance다. 이는
`layout-metric` 가설을 조사할 충분한 current 기준선이지만, 아직 제품 교정 결론은 아니다.

## 3. actual fixed-frame geometry

기존 읽기 전용 text-layout query에서 공개 fixture의 실제 render line bbox를 집계했다. 표 셀 content width는
28,980 HWPUNIT(386.4 px), 글상자는 29,434 HWPUNIT(392.5 px)다. 아래 slack은 actual content width에서
현재 최대 line bbox를 뺀 값이며 음수는 frame crossing이다.

| context | lane | ratio / spacing | lines | max line px | min slack px | crossing |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| table-cell | stored | 100 / 0 | 1 | 481.0 | -94.6 | yes |
| table-cell | fresh | 90 / -5 | 2 | 387.0 | -0.6 | yes |
| table-cell | stored | 80 / -10 | 1 | 386.0 | 0.4 | no |
| text-box | fresh | 100 / 0 | 2 | 353.0 | 39.5 | no |
| text-box | stored | 90 / -5 | 1 | 393.0 | -0.5 | yes |
| text-box | fresh | 80 / -10 | 2 | 259.0 | 133.5 | no |

stored/fresh가 단순히 최신/과거의 단조 관계가 아니며, 같은 문구도 context와 lane에 따라 줄 수와 crossing이
달라진다. Q2는 이 current geometry에 exact `hmtx` 누적 advance를 대입해 최초 경계 변화와 개선·악화를
판정해야 한다.
