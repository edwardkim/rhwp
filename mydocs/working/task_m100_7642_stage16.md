# 이슈 #7642 — CASES 칸 맞춤 보정

이전 단계: [현재 브랜치 전수 검증](task_m100_7642_stage15.md).

## 독립 근거와 원인

- 원본 `samples/exam_math_8.hwp`와 같은 MCP 2020 Print PDF를 사용한다. 고정한
  `upstream/devel` (`74f9b71b15a2db18b17c37ceab6cf2b3c20c03c3`)은 67.24866%, 현재
  source (`e45d2461c`와 동일)는 83.49525%다. 이미 미달한 원본이지만 개선이 필요하며
  점수만으로 이관하거나 완료로 처리하지 않는다.
- 한컴 공개 수식 사양의 `&`는 세로 칸 맞춤(탭 효과)이다. 원본의 CASES 두 행은 `&&`로
  식과 조건을 나누며 독립 Print에서 두 조건의 왼쪽 괄호 원점이 같은 180.36pt다.
  이 좌표는 진단 관측값이며 구현이나 회귀 검사의 고정 좌표로 사용하지 않는다.
- 현재 `EqParser::parse_cases`는 `&`를 `SpaceKind::Tab`으로 보존하지만
  `EqLayout::layout_cases → layout_node → layout_row → layout_space`가 각 행에
  독립적인 1em 공백을 더한다. 앞 식 폭이 달라지면 같은 칸의 원점도 달라진다.
- 공통 결과 경로는 CASES의 행별 열 분리 → 열 폭/공통 원점 → 기준선 정렬된 행 상자 →
  중괄호 상자 → SVG/Canvas/Skia다. 저장 프레임 및 실제 본문 배치가 이 intrinsic 결과를
  소비하는 경로도 같은 원본에서 확인한다. 조건만 별도로 이동하거나 출력별 보정하지 않는다.

## 보정과 검증 순서

1. 크기 11pt/22pt와 `&` 수 0/1/2/3의 진단 입력을 MCP 2020에서 정상화·Print 출력한다.
   한컴이 만든 메트릭과 실제 열 원점을 대조한다. 진단 입력은 원본 기준 PDF를 대체하지 않는다.
2. 칸 맞춤을 사용하는 CASES만 공통 열 위치를 소비하도록 보정한다. 칸 맞춤이 없는 행과
   중첩 EQALIGN/행렬은 각자의 의미를 유지하며, 문서명이나 절대 px 조건을 추가하지 않는다.
3. 원본과 정상 대조군의 Native/fresh WASM을 다시 산출하고 수식 조건, 괄호, 분수, 첨자,
   앞뒤 본문 간격을 확대 판독한다. 90% 이상과 직접 판독을 모두 충족한 뒤 관련 검사를
   소유·순서·정렬·포함 관계로 변경하거나 추가한다.
4. 변경 영향의 검증을 완료한 source로 요청된 52개 문서 검증과 전체 회귀 실패 보정을 계속한다.

TSV·진단 입력·중간 JSON·실행 로그·nextrun은 ignored `output/pr-review/issue7642/`에 둔다.
공식 제출에 사용하는 원본/기준 PDF와 대표 이미지는 최종 검증 후 보존 경로에 포함한다.

## 이번 브랜치의 실패 처리 범위

최신 사용자 지시에 따라 이번 전수 회귀의 90개 실패는 고정 upstream/devel의 기존 미달 여부와
관계없이 모두 현재 브랜치에서 보정한다. 일반 이관 지침으로 검사를 제거하거나 새 이슈로
옮겨 이번 실패를 해소하지 않는다. base 대조는 원인 구분에 사용하며, 원본 출력 개선과
90% 이상 및 확대 판독을 확인한 뒤 필요한 관계형 검사 변경·재실행을 진행한다.

## 독립 칸 맞춤 진단 결과와 구현

MCP 2020 Print job `41e23654-131c-4973-bc92-71b8b8db1bef`, 정상화 HWP job
`fe5ab2c0-a664-4ace-bd96-f2f30775d6c9`는 한컴 11.0.0.9136이다. 중괄호로 아래첨자를
명시한 `a_{n}-3` / 분수와 `a_{n}`의 두 행을 11pt/22pt에서 대조했다. 같은 경계의
뒤 `b`/`c` 원점은 일치한다. 첫 `&`를 추가한 전체 폭 증가가 각각 220/440 HWPUNIT
(0.2em), 두 번째·세 번째 `&`는 각각 770/1540 HWPUNIT(0.7em)이다. 따라서 경계 간격
0.2em과 빈 열 0.5em을 분리해 소비한다. 상대 크기를 사용하며 문서 좌표를 고정하지 않는다.

`layout/cases_columns.rs`에서 CASES 직접 행의 Tab 경계로 셀을 분리하고 공통 최대 열 폭과
원점을 만든다. 각 행의 셀은 같은 기준선에 정렬된다. 중첩 EQALIGN의 내부 경계와 Tab이
없는 CASES는 각자 기존 배치를 유지한다. `matrix_geometry::layout_cases`의 중괄호와
행 높이 배치가 이 결과를 그대로 받아 SVG/Canvas/Skia에 같은 상자를 전달한다.
진단 파일·원점 관측·정상화 구조는 ignored `stage15-current-validation/cases-tab-braced-probe/`에 있다.
새 회귀 테스트는 아직 추가하지 않았다. 먼저 실제 원본과 반례의 Native/fresh WASM 및 확대
판독을 확인한다. 이번 코드는 source SHA와 함께 다시 빌드해 이전 캡처와 구별한다.

## 첫 보정의 실제 결과

Native 빌드 exit0, 7분12초, binary SHA-256
`64c4d1d1be4a545cdbbf98ea57319857547b8a21fdd933032fa25a7178213d9d`.
`exam_math_8.hwp`는 83.49525% → **86.26875%**로 개선됐다. 아직 90% 미만이므로
완료·회귀 추가/변경·PR 제출로 판정하지 않는다. 같은 source의 정상 대조는
`eq-002.hwp` / `hwpx/eq-002.hwpx` 각각 94.81146%, `exam-kor-1p.hwp` 98.89162%로 유지된다.
포맷 검사와 `git diff --check`는 exit0이다. 새 review와 확대 이미지를 직접 사용자에게 표시했다.

남은 차이의 경로도 확인했다. `layout_subscript`는 자식의 상단을 본체 기준선의 0.4배로
이동하여 작은 글자의 기준선이 본체보다 0.064em만 내려간다. 독립 Print의 아래첨자 위치와
다르다. CASES의 두 행 기준선 평균을 왼쪽 식의 기준선으로 사용하는 경로와, 한글 포함만으로
유효한 저장 프레임을 intrinsic 값으로 대체하는 `flow_metrics_hwp` 경로도 대조 중이다.
임의 좌표 보정 대신 한컴 정상화의 논리 줄 높이·기준선·행 점유와 공개 사양의 정렬 관계를
확인해 후속 보정한다. 글자 크기별 아래첨자와 분수 위치를 바꾼 CASES의 MCP 진단을 확보했다.

fresh WASM은 같은 source에서 release 컴파일이 성공하고 최적화가 진행 중이다. 최종 exit와
Studio 동기화 SHA는 아직 판정하지 않았다. 모든 회귀 실패를 이번 브랜치에서 보정하는
사용자 지시와 전체 52개 재검증 범위를 유지한다.
