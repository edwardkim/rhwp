# #7642 흑백 ROP 검사를 독립 비트 연산으로 보정

## 원래 검사의 잘못된 가정

기존 세 검사는 SVG에 `rop_pat` 정의가 없으면 흑백 마스크 처리가 맞는 것으로
판정했다. 이 방식은 마스크 전체를 삭제하고 바탕까지 단색으로 덮어도 통과한다.
현재 변환은 실제 패턴을 마스크로 남기므로 이 문자열 검사가 실패했다.

독립 근거는 [MS-WMF의 TernaryRasterOperation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wmf/1605dd68-a635-4639-ab81-99ff3e3fc5a3)이다.
PATINVERT는 XOR, DPa는 AND다. 같은 바깥 영역에서의 결과는
`((D XOR P) AND M) XOR P`이며 흰 마스크는 원래 바탕을, 검은 마스크는 브러시 색을 남긴다.
중간 연산 영역이 바깥 영역과 다르면 각 연산이 실제로 적용되는 영역에서 계산한다.

## 실제 변경

세 검사를 새 이름으로 바꾸고 변환 SVG를 원래 장치 해상도로 렌더한다.
합성 WMF에 직접 기록한 영역·DIB의 bottom-up 비트·팔레트를 독립 기대값으로 사용한다.
임의의 유색 바탕을 깔아 바탕을 지우거나 마스크를 평탄화한 출력도 검출한다.
팔레트 반전, 한 단위씩 다른 중간 영역, 바깥 영역 밖의 검정도 확인한다.

| 새 검사 이름 | 보호하는 의미 |
| --- | --- |
| `issue_6865_complete_mask_selects_brush_or_original_destination` | 브러시 또는 원래 바탕의 비트별 선택 |
| `issue_6865_halftone_padding_keeps_each_operation_region` | 서로 다른 연산 영역 보존 |
| `issue_6865_reversed_palette_reverses_brush_and_destination_selection` | 팔레트 반전 보존 |

기존 정상·불완전 연산 대조군은 유지했다. 실제 변환·paint 코드, golden, 허용치는
바꾸지 않았다. 실물 HWP 화면의 절대 px 위치를 고정하는 검사가 아니다.
이 합성 비트 계약을 실문서의 독립 Print 대조 완료 증거로 사용하지 않는다.

## 실행

같은 `9ca7535f258bd7e02d5d1ede1f83a79b3dcf4e31` Native 라이브러리에서
원래 파일은 12 PASS / 3 FAIL, 변경 파일은 15 PASS / 0 FAIL이다.
독립 비트 기대값은 채널별 최대 1의 반올림 오차만 허용한다.

첫 진단은 4배 확대 영상의 소수 위치를 표본으로 삼아 보간이 섞였으므로 실패했다.
원래 장치와 동일한 1:1 표본으로 바로잡았고 기대 색이나 허용치를 완화하지 않았다.
두 실패·성공 실행은 각각 `stage3477-mask-contract`와
`stage3480-mask-unit-raster-contract`에 그대로 보존한다.

실행 명령, 동결한 원문과 라이브러리 해시는 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`
아래 각 `receipt.json`, `before-run.log`, `after-run.log`에 있다.
임시 컴파일 파일의 include_bytes 경로만 같은 정식 fixture의 절대 경로로 치환했다.
자동 수집 suite를 포함한 최종 전체 Rust 검증과 실문서 Native/fresh WASM gate는
계속 남아 있다. 이것은 검사 보정 결과이며 엔진 수정의 전후 결함 검출 주장은 아니다.
