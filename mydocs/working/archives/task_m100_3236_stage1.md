# Task #3236 Stage 1 보고 — 근인 규명

## 결론

**셀 안 문단이 쪽 하단을 넘어서도 다음 쪽으로 넘어가지 않고 계속 아래로 그려진다.**
쪽 밖에 그려진 줄은 clip 되어 보이지 않으므로 사용자에게는 "내용이 사라진" 것으로
보인다. 표 분할(`split_table_rows`) 경로 자체에 **진입하지 않는다.**

### 결정 증거 — `LAYOUT_OVERFLOW_CELL` 진단 23건

렌더 실행 시 코어가 이미 경고를 내고 있었다(`layout/paragraph_layout.rs:3279`).

```
LAYOUT_OVERFLOW_CELL: section=0 pi=6 line=0 y=1139.0 page_bottom=1122.5 overflow=16.5px
LAYOUT_OVERFLOW_CELL: section=0 pi=7 line=1 y=1180.1 page_bottom=1122.5 overflow=57.6px
...
```

- 총 **23줄**이 쪽 하단(1122.5px)을 넘어 그려진다.
- 최대 초과 **468.3px** — 쪽 높이의 40%가 넘는다.
- 진단 주석이 밝히듯 "줄 윗변이 이미 쪽 밖이면 그 줄은 **어느 부분도 그려지지 않는다**".
  즉 이 23줄은 확정 소실이다.

## 계측 과정 — 분할 경로 미진입 확인

`pagination/engine.rs` 에 임시 `eprintln!` 을 5지점에 넣어 어디까지 도달하는지 확인했다
(계측 후 전량 원복, 작업 트리 clean).

| 계측 지점 | 도달 |
|---|---|
| `paginate_table_control` 의 fit 판정 (`current_height + eff_h <= avail`) | ❌ |
| `is_tac_table` 분기 | ❌ |
| `split_table_rows` 진입 | ❌ |
| `find_break_row` 호출 | ❌ |
| 인트라-로우 분할 게이트 (`is_row_splittable`) | ❌ |

**표가 페이지네이션의 표 분할 경로에 아예 오르지 않는다.** 따라서 계획서에 적었던
유력 가설("`layout_partial_table_item` 이 행 범위 기반이라 1행 표는 분할 대상이 못 된다")은
**기각**된다 — 그 코드에 도달조차 하지 않는다.

## 기각한 가설과 남은 후보

| 가설 | 판정 |
|---|---|
| 행 범위 기반이라 1행 1열은 분할 불가 | **기각** — `split_table_rows` 미진입 |
| `is_row_splittable` 게이트가 막음 | **기각** — 같은 이유 |
| Canvas/CanvasKit 백엔드 결함 | **기각**(착수 전) — SVG 도 동일 소실, render tree 단계에서 이미 없음 |
| **TAC(글자처럼 취급) 인라인 표가 페이지네이션에서 skip** | **유력** — `engine.rs:1739` 부근 `is_tac_table_inline_in_para` 가 참이면 `continue` 로 제외된다. 이 문서 표는 `treat_as_char` 이고 문단 안에 인라인 배치된 형태다 |
| 셀 내부 문단 레이아웃이 쪽 경계를 모름 | **유력** — 진단이 셀 컨텍스트(`cell_ctx.is_some()`)에서 나온다. 셀 안 문단 흐름이 쪽 하단에서 끊기지 않는다 |

두 유력 후보는 배타적이지 않다. TAC 인라인이라 페이지네이션에서 빠지고, 그 결과 셀 내부
문단이 쪽 경계를 무시한 채 계속 흐르는 **한 사슬**일 가능성이 높다.

## Stage 2 착수 전 확인 필요 — 범위 판정

계획서 §5 에 적은 대로, 수정 범위가 갈리는 지점에 도달했다.

- **(가) TAC 인라인 skip 조건 정정** — `is_tac_table_inline_in_para` 가 "쪽을 넘는 큰 표"를
  인라인으로 오판하지 않게 한다. 페이지네이션에 올려 기존 분할 경로를 타게 하는 방향.
  범위가 작고 기존 인프라를 재사용한다. 다만 TAC 표 배치 규칙(#3396 계열)과 상호작용
  위험이 있다.
- **(나) 셀 내부 문단의 쪽 경계 처리 추가** — 셀 안 문단 흐름이 쪽 하단에서 끊기고 다음
  쪽으로 이어지게 한다. 구조 추가라 범위가 크고 회귀 위험도 크다.

Stage 2 에서 (가)를 먼저 시도해 정답지에 도달하는지 보고, 부족하면 (나)를 검토하는
순서를 제안한다. **작업지시자 판단을 받고 진행한다.**

## 부수 발견 — 진단이 이미 울고 있었다

`LAYOUT_OVERFLOW_CELL` 은 이 결함을 정확히 가리키는 경고인데, stderr 로만 나가고 아무도
보지 않았다. 리포터(#3236)도, 내부에서도 7일간 몰랐다. 이 진단을 CI 나 서베이 게이트에서
집계하면 같은 계열을 선제 검출할 수 있다 — [#3668](https://github.com/edwardkim/rhwp/issues/3668)
로 등록(본 이슈의 sub-issue).

# 추적 2차 — 경로 완전 규명 (2026-08-01)

Stage 1 의 두 유력 후보((가) TAC 인라인 skip, (나) 셀 쪽 경계 미처리)는 **모두 기각**됐다.
문제 표는 `treat_as_char=false` 라 (가)의 대상이 아니었고, 진짜 조판 경로는
`pagination/engine.rs` 가 아니라 **`renderer/typeset.rs`** 였다 — Stage 1 의 계측 5지점이
전부 미도달이었던 이유는 그 코드가 죽은 경로였기 때문이다.

## 확정된 인과 사슬

1. 실제 조판은 `typeset.rs::typeset_section_with_variant` 가 수행한다.
2. 문제 표(pi=17)는 통짜 배치 조건 5개 중 **`single_row_object_height_advance`** 로
   `PageItem::Table`(비분할)이 된다. fit 자체는 명확히 실패한다
   (`cur_h 607.7 + 측정 910.8 = 1518.5 > avail 933.5`).
3. 이 특례는 [#1891](https://github.com/edwardkim/rhwp/issues/1891)
   (`193cd714d`, 2026-07-05, "HWP5-origin HWPX 쪽수 보정")에서 도입된
   `single_row_object_declared_fits_current` 다. 요건: 비-TAC · **1×1 단일 셀** ·
   RowBreak · host 문단 가시 텍스트 없음 · **측정 > 선언 + 64px** · 측정 ≤ 쪽 전체 ·
   **선언이 현재 쪽 잔여에 fit**. 이 문서: 선언 322.6px 가 잔여 325.8px 에 3.2px 차로
   fit → 특례 발동 → 통짜 배치 → 셀 내용 588px 이 쪽 밖 clip.
4. **작업지시자의 회귀 기억이 정확했다** — 셀 내부 분할(인트라-로우, start_cut/end_cut)
   인프라는 존재하고 정상 동작한다. 7/5 의 특례가 이 형상에서 그 경로를 우회시킨 것이다.
   리포터의 0.7.19 는 7/5 이후 버전이라 시점도 정합한다.

## 인과 확정 실험 (특례 임시 차단)

`single_row_object_height_fits_current` 를 강제 false 로 두고 재렌더:

| 지표 | 특례 켬 (현행) | 특례 끔 (실험) | 한컴 정답지 |
|---|---|---|---|
| pi=17 배치 | `Table` 통짜 (p1) | **`PartialTable` p1+p2** | 분할 |
| `LAYOUT_OVERFLOW_CELL` | 23건 | **0건** | — |
| 쪽별 분포 | 84% / 16% | **46% / 54%** | 45% / 55% |
| p2 시작 텍스트 | (다른 내용) | **"경과되지 않은 외국인투자기업인 경우, 또는…"** | 동일 — **글자 단위 일치** |

분할점까지 한컴과 정확히 일치한다. 인과 사슬 확정.

### 측정법 정정

계획서의 "63% 소실(6,651자 vs 2,450자)"의 **자릿수는 측정법 차이였다** — SVG `<text>`
노드 추출은 pdftotext 와 집계 방식이 달라 총량 비교가 성립하지 않는다(특례 끈 실험에서도
SVG 총량은 2,450 으로 동일 — clip 된 텍스트도 SVG 에는 방출되고 시각적으로만 잘린다).
**올바른 지표는 쪽별 분포와 p2 시작 텍스트**이고, 이 기준으로 결함·수정 효과 모두 확정됐다.
Stage 3 검증 기준을 이에 맞게 갱신한다(총량 일치 → 분포·경계 텍스트 일치).

## 임계값 실측 — #1891 fixture 와의 분리

특례의 하한이 이미 64px(`HWPX_ROWBREAK_SPLIT_ROW_OVERFLOW_TOLERANCE_PX`)라
"노이즈 상한" 접근은 특례를 통째로 죽인다. 그래서 #1891 fixture 4건(규제영향분석서
76076/80168/80250/86712)에서 특례 발동 값을 실측했다:

**4건 전부 특례가 한 번도 발동하지 않는다.** 발동하는 것은 #3236 문서뿐이다
(`declared=322.6 measured=910.8 excess=588.2 ratio=2.82`). 즉 #1891 의 쪽수 fixture 는
다른 가드(midpage/declared_whole_fits 계열)로 보호되고 있고, 이 특례의 실제 보호 대상은
로컬 테스트에 없다 — 10k 서베이 계열 문서일 가능성만 남는다.

## Stage 2 수정 설계 후보

- **옵션 A (권고): 비율 상한 추가** — `측정 ≤ 선언 × 1.5` 를 특례 요건에 추가.
  폰트 대체 노이즈는 10~20% 수준(인접 가드들의 근거)이라 **2.8배는 노이즈일 수 없다.**
  중간 초과(64px~50%) 구간의 특례는 보존되어 #1891 의도 유지. #3236(182% 초과)은
  탈락 → 분할 경로 → 실험으로 정답지 일치 확인됨.
- **옵션 B: 특례 제거** — 로컬 fixture 가 특례를 쓰지 않으므로 제거해도 로컬 테스트는
  통과할 것. 다만 10k 계열의 미지 보호 대상이 회귀할 위험이 있어 서베이 없이는 권고하지
  않는다.

두 옵션 모두 Stage 3 에서 issue_1891 쪽수 테스트 · 92셋 · release-test 전체 · 정답지
PDF 이미지 스왑으로 검증한다.
