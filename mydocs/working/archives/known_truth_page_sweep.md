# 아는 한글 쪽수 전부로 재는 스윕 (#6375 후속)

## 무엇을

`tools/oracle_page_count/sweep.py` — 저장소가 **알고 있는 한글 쪽수 전부**에 대해 rhwp 를
재고, 두 실행의 차이를 개선·회귀로 낸다. 픽스처도 게이트도 건드리지 않는다(읽기 전용).

```bash
python tools/oracle_page_count/sweep.py --rhwp target/release-test/rhwp.exe --out before.tsv
# ... 코드 수정 · 재빌드 ...
python tools/oracle_page_count/sweep.py --rhwp target/release-test/rhwp.exe --base before.tsv
```

## 왜 — 원장만 보면 오도된다

쪽수 원장(#6337)은 `pdf/` 에 정답지가 있는 문서만 덮는다. 그런데 저장소가 아는 한글
쪽수는 그것만이 아니다. `tests/` 안에 이렇게 박혀 있는 문서가 따로 있다.

```rust
assert_eq!(core.page_count(), 60, "한글 2020 정본은 60쪽이다");
```

이 차이는 **실제로 나를 오도했다.** `recalculate_section_vpos` 의 vpos=0 리셋 규칙을
넓혀 보고 원장으로 재니 개선 2 · 회귀 0 이라 안전해 보였다. 그런데 전체 통합 테스트를
돌리자 `samples/issue6031/3249937_asset_management_rules.hwpx` 가 **60 → 61 쪽**으로
깨졌다. 그 문서는 `pdf/` 에 정답지가 없어 원장이 못 보는 자리였다(#6375).

전체 통합 테스트는 90 분이 넘는다. 조판을 건드릴 때마다 돌릴 수 없다.

## 실측 — 그 회귀를 실제로 잡는다

devel 기준을 뜬 뒤 같은 규칙 확장(`first > 0` → `first >= 0`)을 넣고 재면:

```
아는 한글 쪽수 580문서 (pdf 555 · test 25) / 일치 563 (97.1%) / 불일치 17 / 건너뜀 1

기준 대비: 개선 1 / 회귀 1
  [개선][pdf] samples/issue2470/36341511_masked.hwpx: 9 -> 8 (한글 [8])
  [회귀][test] samples/issue6031/3249937_asset_management_rules.hwpx: 60 -> 61 (한글 [60])
```

**원장만으로는 회귀 0 이었다.** `[test]` 출처가 그 자리를 덮는다.

## 진실의 출처

| 출처 | 무엇 | 문서 수 |
| --- | --- | ---: |
| `pdf` | `pdf/` 의 한글 출력 PDF 쪽 수 (원장 픽스처) | 555 |
| `test` | `tests/` 의 `assert_eq!(…page_count…, N, "…한글…")` | 25 |
| | **합계** | **580** |

`test` 출처는 **파일에 `samples/…` 경로 문자열이 하나뿐일 때만** 귀속한다. 여럿이면 어느
문서의 값인지 확정할 수 없어 버린다. 이 규칙으로 34 개 문서가 확정되고 그중 25 개가
원장 밖이다(값이 갈리는 문서는 0 개).

## 왜 픽스처에 합치지 않았나

`test` 출처 값을 원장 TSV 에 굳히면 **시험과 픽스처가 서로 다른 진실을 갖게 된다.**
누가 시험의 상수를 고치면(예: `issue_2470` 핀 주석이 예고한 9 → 8 갱신) 픽스처는 그대로
남아, 개선이 게이트 실패로 나타난다. 그래서 이 스윕은 시험을 **그때그때 읽는다** —
사본을 만들지 않는다.

## 판정 규약

- 기준 실행에서 한글 값과 맞던 문서가 어긋나면 **회귀**, 종료 코드 1
- 어긋나던 문서가 맞으면 **개선**
- 모아 찍기(`printMethodImpliesNup`) 문서는 장 수가 애초에 달라 건너뛴다

## 검증 실측

| | 결과 |
| --- | --- |
| devel 에서 기준 뜨기 | 580문서 / 일치 563 (97.1%) / 불일치 17 |
| 같은 코드로 재실행 (`--base`) | 개선 0 · 회귀 0, 종료 코드 0 |
| 규칙 확장 후 (`first >= 0`) | 개선 1 · 회귀 1 (위 실측), 종료 코드 1 |
| 기준 파일을 조작해 회귀 유도 | `sungeo.hwp 94 -> 86` 검출, 종료 코드 1 |

마지막 줄은 도구가 회귀를 **놓치지 않는지**를 따로 확인한 것이다 — 통과만 봐서는
검출력을 알 수 없다.

## 한계

- `test` 귀속 규칙이 보수적이라 파일 하나에 샘플이 여럿이면 버린다. 지금 43 개 파일 중
  9 개가 그렇게 빠진다.
- 쪽 **수**만 본다. 같은 쪽수라도 배치가 다를 수 있다 — 그 축은 `layout-anomaly` 와
  `visual_roundtrip_baseline` 이 본다.
- 이 도구는 게이트가 아니다. CI 에 걸지 않았고, 조판 변경을 낼 때 사람이 돌리는 계측기다.
