## 1. 결론

R4C-1의 owned paragraph positions를 token total과 긴 단어 최초 후보가 그대로 읽고, 실제 줄 경계는 같은
layout transaction에서 앞줄 substring을 다시 R4B 측정하는 `KerningParagraphBreakSession`을 추가했다.
boundary 재측정은 경계 밖 glyph와의 pair adjustment를 제거하며, 최초 segmentation이 소비한 segment 실행
예산을 그대로 이어받는다.

긴 단어 경계는 먼저 paragraph positions에서 후보를 찾은 뒤 boundary-safe substring 폭으로 최대 4,096
문자 범위의 단조 binary search를 수행한다. 어느 후보든 최초+fallback+boundary 합계 256회 예산을 넘기면
세션 전체가 `SegmentExecutionLimitExceeded`로 닫히고, 호출자는 R4C-3에서 해당 문단을 기존 K0 측정으로
재실행해야 한다.

이번 절편은 이 소비 계약을 제품 `BreakToken` 한 경로에만 먼저 연결하지 않았다. `HeightMeasurer`,
`TypesetEngine`, page-tree `LayoutEngine`, 편집 reflow가 동시에 같은 결과를 받지 못한 상태의 부분 연결은
승인된 수정 계획의 보호 불변식을 위반한다. 네 경로의 원자적 배선은 R4C-3 승인 경계다.

## 2. 공통 소비 계약

### 2.1 token total과 최초 후보

`KerningParagraphBreakSession::range_width(start, end)`는 R4C-1 paragraph measurement의 `N+1` positions를
직접 읽는다. token 폭을 별도로 합산하거나 긴 단어용 문자 폭 vector를 다시 만들지 않는다.

`find_fitting_end`의 최초 후보도 같은 range API로 binary search한다. 따라서 token total과 char-level 최초
후보는 동일한 장평·자간·pair 결과를 소비한다.

### 2.2 실제 line boundary 재측정

`boundary_width(start, end)`는 실제 줄에 남을 substring을 다음 경계로 다시 나눈다.

- exact slot의 char-shape/language 변경
- kerning request·effective font size·장평 변경
- 탭·강제 줄바꿈
- inline-control hard boundary

각 substring은 같은 `KerningLayoutSession`의 cached exact face로 다시 R4B 측정된다. GSUB nominal identity
실패는 R4C-1과 똑같이 공백 기준 fallback만 허용한다. 경계 밖 glyph는 입력 substring에 없으므로 crossing
pair adjustment도 결과에 남지 않는다.

`boundary_pair_adjustment`는 기존 base line pen에 더할 pair delta만 제공한다. 탭·공백 압축처럼 line breaker가
동적으로 소유하는 폭을 kerning 계층이 다시 계산하지 않기 위한 R4C-3 배선 경계다.

### 2.3 bounded 후보 재탐색

최초 후보의 boundary-safe 폭이 fit 결과를 바꾸면 `[start, end]` 안에서 상향 midpoint binary search를 한다.
폭 결과는 `(start, end)`별로 transaction 내부 cache에 저장해 같은 후보를 다시 shape하지 않는다.

한 글자도 fit하지 않는 긴 단어는 기존 line-break 의미처럼 첫 글자 하나를 강제로 진행시키고
`overflow_forced=true`를 기록한다. 범위·가용 폭이 잘못되거나 최종 폭이 non-finite/음수이면 구조화해
fail-closed한다.

## 3. 실행 예산과 rollback 신호

`KerningParagraphBreakSession`은 paragraph의 `attempted_segment_count`에서 시작한다.

- R4C-1 최초/fallback 측정과 R4C-2 boundary 재측정 합계: 최대 256회
- 문자 범위: 최대 4,096 code point
- boundary cache hit: 실행 예산을 다시 소비하지 않음
- 257번째 측정 필요: width 반환 없음, `SegmentExecutionLimitExceeded`
- 실패 뒤 후속 token/boundary 요청: 계속 `None`, 부분 결과 재사용 금지

R4C-3 consumer는 이 실패 신호를 받으면 해당 문단의 K1 token 결과나 일부 line boundary를 게시하지 않고
기존 K0 tokenization/fill을 처음부터 다시 실행해야 한다.
