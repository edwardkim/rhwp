## 1. 결론

기존 문자 경계값과 exact-font pair candidate를 owned `KerningRunMeasurement` 하나로 합쳤다. K0, exact source
부재, unsupported/malformed source, 입력·상한 검증 실패에서는 별도 adjusted positions를 만들지 않고 기존
`base_positions`를 그대로 반환한다. 실제 pair 적용이 검증된 경우에만 adjusted positions와 backend replay용
px delta를 소유한다.

이 절편은 아직 paragraph/token/line-break 소비자에 연결하지 않았다. 따라서 R4B 자체는 문서 줄바꿈, layer
tree, SVG를 바꾸지 않는다. R4C에서 line 후보와 문자 경계 소비자를 같은 measurement에 연결하기 전에 수치
계약과 실패-폐쇄 경계를 먼저 고정한 것이다.

## 2. 구현 계약

### 2.1 owned 결과와 disposition

`KerningRunMeasurement`는 다음을 한 번 계산해 소유한다.

- 기존 `N+1` base character positions
- pair가 실제 적용됐을 때만 존재하는 adjusted positions
- 문자별 x advance delta
- backend가 재환산 없이 소비할 x/y advance·offset px delta
- 최종 total width
- payload 없는 exact source handle
- source session·capability·candidate trace
- bounded code-point/segment 회계와 구조화된 disposition/fallback

`positions()`는 adjusted positions가 없으면 base slice를 그대로 돌려준다. K0와 fail-closed 경로에서 큰
positions 벡터를 한 번 더 복제하지 않으며, font bytes·경로·원문은 trace에 넣지 않는다.

### 2.2 적용 순서

공통 진입점은 기존 `compute_char_positions`가 계산한 base positions를 입력으로 받는다. 이 base에는 이미 다음이
들어 있다.

1. single-glyph base advance
2. 위/아래첨자 script scale
3. 장평 ratio
4. glyph-relative 자간과 extra spacing

그 뒤에만 pair delta를 다음 식으로 px로 환산한다.

`pair design units × effective font size × width ratio ÷ unitsPerEm`

자간 값은 pair 계층의 입력이 아니므로 pair delta에 자간이 다시 곱해질 수 없다. ratio 100/90/80과 기존
자간 0/-1/-2 조합에서 공개 font의 `-120 DU`가 각각 `-2.40/-2.16/-1.92 px`로 적용됨을 고정했다.

### 2.3 실패-폐쇄와 상한

- K0: source 조회·parse·shape·base validation을 모두 건너뛰고 기존 positions 반환
- source handle 부재: provider 조회 없이 기존 positions 반환
- 4,096 code point 초과: source 조회 전에 중단하고 기존 positions 반환
- base position 수/finite 검증 실패: 기존 positions 반환
- session/capability/candidate 실패: 구조화된 trace를 남기고 기존 positions 반환
- UPEM·style scale·candidate 합계·glyph index·finite·monotonic 검증 실패: delta commit 취소

Pair 적용 시에만 최대 4,096자 advance 벡터와 candidate 상한 안의 px replay delta를 추가 할당한다.
