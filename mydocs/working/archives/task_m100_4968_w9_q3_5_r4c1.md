## 1. 결론

문단의 Unicode scalar를 exact font slot·kerning request·effective font size·장평이 같은 homogeneous run으로
분할하고, 탭·강제 줄바꿈·inline control 경계에서 pair 적용을 차단하는 bounded builder를 추가했다. 각 run은
R4C-0의 동일 `KerningLayoutSession`에서 R4B 측정을 받고, 최종 결과는 문단의 owned position map 하나로만
commit된다.

전체 run이 GSUB 때문에 nominal glyph 또는 cluster identity 검증에 실패한 경우에만 공백 경계의 비공백
sub-run을 각각 다시 feature-detect한다. 실패한 단어는 기존 positions를 유지하고, 독립적으로 검증된 다른
단어는 pair adjustment를 적용할 수 있다. source 추정이나 gate 완화는 하지 않는다.

최초 homogeneous run과 공백 fallback sub-run은 같은 256회 실행 예산을 소비한다. 257번째 측정이 필요하면
앞서 계산한 K0/K1 segment를 전부 버리고 문단 전체를 기존 positions로 되돌린다.

## 2. 경계와 입력 계약

### 2.1 scalar style

`KerningParagraphScalarStyle`은 scalar마다 다음만 고정한다.

- `ExactFontSlot(char_shape_id, language_index)`
- kerning request
- script scale까지 반영된 effective font size
- 장평 ratio

기존 single-glyph advance·자간·탭·추가 간격은 문단 base positions가 이미 소유한다. pair delta 환산과 exact
source 선택에 필요하지 않은 `TextStyle` 필드를 kerning 계층으로 복제하지 않아 두 측정 원본이 생기는 것을
막았다. 같은 slot이라도 request·effective size·ratio가 다르면 별도 run이다.

### 2.2 hard boundary

- 탭과 `LF`/`CR` 강제 줄바꿈은 문자 자체를 보고 segment에서 제외한다.
- 텍스트에 scalar로 들어 있지 않은 inline control은 `N+1` `hard_boundaries`의 해당 문자 경계를 `true`로
  전달한다.
- slot의 char-shape 또는 language index가 달라지면 자동으로 run을 닫는다.
- hard boundary를 건너 pair를 계산하지 않으며, 제어문이 차지한 기존 base 폭은 그대로 남는다.

이 입력 형태는 이후 R4C-3에서 `Paragraph.char_offsets`, active `CharShapeRef`, language detection,
`FlowInlineControl.char_position`을 투영할 수 있지만 R4C-1 자체는 제품 문단에 아직 연결하지 않는다.

## 3. GSUB 공백 fallback

최초 homogeneous run의 R4B candidate가 다음 이유로 fail-closed된 경우에만 fallback한다.

1. `NominalGlyphIdentityChanged`
2. `NominalClusterChanged`

run 안에 공백이 있을 때 비공백 word 범위를 각각 한 번 다시 측정한다. 공백은 base positions의 gap으로 남고,
word 간 pair는 생기지 않는다. 재측정한 word가 다시 identity 검증에 실패하면 그 word만 zero delta로 닫는다.
다른 실패 이유, 공백 없는 실패 run, source 부재는 재시도하지 않는다.

공개 Noto fixture의 `ffi AV` 검증에서는 전체 run과 `ffi`가 ligature 때문에 fail-closed됐지만 `AV`는 별도
segment에서 pair adjustment를 얻었다. 실행 회계는 최초 1회 + fallback 2회 = 3회이고 최종 segment는
`ffi`, `AV` 두 개다.

## 4. 보안·원자성

- 문단 code point: 최대 4,096; 초과는 source/shape 실행 전 중단
- 최초+fallback segment 실행: 최대 256회
- scalar style: code point와 정확히 1:1
- hard boundary: `N+1` position과 정확히 1:1
- base positions: `N+1`, finite, monotonic
- 실행 예산 소진: partial segment를 결과에 남기지 않고 전체 rollback
- trace: 시도 횟수와 공백 fallback run 수만 추가하며 원문·font bytes·경로를 보존하지 않음

상한 검사는 큰 vector를 새로 만들거나 source registry를 조회하기 전에 수행한다. 문단 text 순회와 fallback은
4,096 scalar·256회 실행 경계 안에서만 동작한다.
