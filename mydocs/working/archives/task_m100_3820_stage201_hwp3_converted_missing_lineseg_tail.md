# Stage 201 - HWP3 변환본의 누락된 줄 경계 복원

## 목적

Issue #3820 작업 중 발견된 `issue_1105` 회귀를 해소한다. HWP3에서 변환된 HWP5 문서는
일부 본문 문단의 저장 `LineSeg`를 보유하지 않지만, 한컴 출력은 페이지 말미에서 마지막
줄을 다음 페이지로 넘긴다.

## 원인

HWP3에서 변환된 HWP5에는 두 저장 형태가 있다.

- 2018·2024 변환본은 문단 안 `LineSeg.vertical_pos` 되감김을 보존한다.
- 2010·2022 변환본은 같은 문단의 `LineSeg` 전체를 생략한다.

기존 코드가 HWP3 변환 HWP5를 저장 reset 출처에서 제외해 첫 형태의 내부 쪽 경계를
무시했다. 누락 문단에 일반적인 75% 페이지 말미 규칙을 그대로 적용하면, 같은 5줄
정상 RDBMS 문단까지 과분할되어 64쪽이 65쪽으로 늘어난다.

## 변경

HWP3 변환 HWP5를 저장 `vpos` reset 해석 출처에 포함해, 보존된 내부 되감김은 직접
분할한다. 이 출처의 `vpos=0`은 변환기 local cursor 초기화로도 쓰이므로, 내부 reset은
세 줄 이상인 음수 cursor만 인정한다. 두 줄 음수 cursor는 변환기의 local cursor 보정에도
사용되어 실제 페이지 조각으로 승격하면 과분할된다. `LineSeg`가 완전히 없는 변환본은
고정 픽셀 여유값 대신 현재 formatter 줄 수로 `1 - 1/줄수`의 최소 페이지 채움 비율을
계산하고, 두 조각을 가능한 한 균등하게 나눈다. 따라서 5줄 문단은 4/5 이상이 채워졌을
때만 3+2 조각을 추론한다.

- 문단 번호, 파일명, 특정 문구, 고정 픽셀 여유값에 의존하지 않는다.
- 원본 HWP3와 HWP3 계보 HWPX는 HWP5 변환 전용 누락 추론에서 제외된다.
- 표, 그림, 각주처럼 물리 공간을 차지하는 control은 기존 인라인 메타데이터 조건에서 계속 제외된다.
- HWP3 변환본의 저장 reset 또는 `LineSeg` 누락을 현재 formatter의 실제 줄 수로만 복원한다.

## 검증 대상

- `issue_1105`: sample16 원본 HWP3 및 2010/2018/2022/2024 변환 HWP5의 64쪽과 23쪽 문단 내 분할.
- #3820 집중 회귀군 및 전체 integration 회귀군.
