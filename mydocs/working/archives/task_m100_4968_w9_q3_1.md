## 1. 결론

Q3의 첫 절편은 문서의 kerning 요청을 손실 없이 `TextStyle`에 전달하되, 아직 pair adjustment를 적용하지
않는다. `kerning=false`는 layer-tree JSON에 필드를 쓰지 않아 Q1/Q2 이전 schema와 position을 그대로
보존한다. `kerning=true`만 `"kerning":true`로 관측할 수 있다.

공개 Q2 fixture의 body 18개 run에서 K0는 9개 모두 필드가 없고 K1은 9개 모두 true였다. 같은
ratio·spacing·LineSeg lane의 K0/K1 9쌍은 positions가 전부 같았고, Q2에 동결한 9개 position hash도
전항 일치했다. 따라서 이번 절편은 의도 전달만 고정했으며 조판 변화는 만들지 않았다.

## 2. 구현 경계

| 경계 | 변경 | 이번 절편에서 하지 않은 일 |
| --- | --- | --- |
| `ResolvedCharStyle` → `TextStyle` | `kerning` 전달 | pair delta 계산 |
| `TextStyle` 기본값 | `false` | 기존 문서의 암묵적 opt-in |
| serde JSON | true만 직렬화 | K0 schema 변경 |
| layer-tree 수동 JSON writer | true만 `kerning` 출력 | backend별 reshaping |
| integration regression | K0 생략, K1 true, positions 동일 고정 | generated suite·manifest 제출 |

초기 구현 점검에서 내부 `TextStyle` 전달만 추가한 상태로는 K1 필드가 layer-tree에 나타나지 않았다. 원인은
파서나 style resolver가 아니라 `src/paint/json.rs`의 수동 `write_text_style`이 새 필드를 알지 못한 것이었다.
writer도 true-only로 보완한 뒤 공개 CLI 경로에서 의도 전달이 확인됐다. 이 경로를 빠뜨렸다면 Rust의
`Serialize` 파생 검증만 통과하고 실제 공개 layer-tree 계약은 여전히 kerning을 잃었을 것이다.

## 3. 보호 불변식 판정

1. **K0 byte/schema 보호**: false는 serde와 수동 writer 양쪽에서 생략한다.
2. **K0 geometry 보호**: Q2에 고정한 9개 position SHA-256이 모두 동일하다.
3. **K1 조기 적용 금지**: K1 positions도 아직 K0와 같다. pair provider와 capability 판정 전에는 움직이지
   않는다.
4. **원인 분리**: font selection·fallback·metric DB·LineSeg 정책은 수정하지 않았다.
5. **테스트 제출 규칙**: 새 회귀는 `tests/cases/` 원본 하나만 추가했다. source-side `#[cfg(test)]`, generated
   suite·manifest, Cargo target marker는 추가하지 않았다.
