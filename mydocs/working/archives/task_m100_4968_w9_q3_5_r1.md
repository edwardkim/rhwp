## 1. 결론

W9-Q3-5 prototype의 full Noto static registry와 제품 measurement 연결을 전부 제거하고, font selection과
layout-session provider 사이의 payload-free exact source handle 계약만 도입했다.

handle은 SHA-256, byte length, face index만 보존한다. font bytes·파일 경로·family 이름을 `TextStyle`이나
직렬화 결과에 싣지 않는다. provider가 반환한 source는 신뢰하지 않고 32 MiB 상한, face index, byte length,
SHA-256을 다시 대사한 뒤에만 후속 capability/shaping 경계로 전달할 수 있다.

Docker 최종 WASM은 Q3-4와 동일한 8,978,378 bytes와 동일 SHA-256으로 복귀했다. 따라서 R1 계약은 core에
font payload를 내장하지 않으며 현재 제품 호출 경로·layout·직렬화·bundle을 변경하지 않는다.

## 2. 계약

### 2.1 `ExactFontSourceHandle`

- `font_source_sha256`
- `font_bytes`
- `face_index`

handle에는 source bytes, path, font family, 문서 식별자를 넣지 않는다. source identity 자체가 selection과
provider resolution 사이의 key다.

### 2.2 `ExactFontSourceProvider`

document embedded font, native font selection, WASM host font registry가 같은 trait 경계를 구현할 수 있다.
provider는 handle에 대응한다고 주장하는 borrowed bytes와 face index만 반환한다. 현재 R1은 실제 host를
연결하지 않으며 계약만 고정한다.

### 2.3 재대사 이유

provider가 잘못된 source를 반환하는 경우를 다음처럼 분리한다.

- `source-unavailable`
- `font-byte-limit-exceeded`
- `face-index-mismatch`
- `byte-length-mismatch`
- `sha256-mismatch`

family 이름이나 fallback 후보로 다른 source를 찾는 분기는 없다.

## 3. prototype 제거 판정

중단된 prototype은 `Noto Sans KR` 이름을 tracked 2.52 MiB TTF와 정적으로 연결했고 WASM을 33.95% 키웠다.
R1에서는 다음을 제거했다.

- core `include_bytes!(NotoSansKR-Regular.ttf)`
- global Noto pair engine
- family 이름 기반 static registry
- `TextStyle` measurement의 prototype adjustment 적용
- composer token의 prototype pair measurement

Q3-4 capability·run gate·candidate 구현은 그대로 유지했다.
