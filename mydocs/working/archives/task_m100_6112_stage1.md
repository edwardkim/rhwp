- **이슈**: [#6112](https://github.com/edwardkim/rhwp/issues/6112)
- **선행 이슈**: [#5738](https://github.com/edwardkim/rhwp/issues/5738)
- **일자**: 2026-08-26 KST
- **문서 성격**: 작업 뒤 실행 로그와 최종 diff를 대사한 감사 증거

## 입력과 사용자 기대

사용자가 제공한 한글 2024 펼침·접힘 화면과 rhwp-studio 화면을 비교했다. 기대 동작은 큰 아이콘 도구
상자를 상시 버튼이나 `Ctrl+F1`로 접고 펴는 것이며, 서식 도구 상자의 별도 재배치는 요청 범위가 아니었다.

## 변경 기점 조사

- 초기 Studio부터 아이콘 도구 상자는 존재했다.
- `2307a5c99`에서 아이콘 도구 상자의 줄바꿈이 도입됐다.
- `625f7667f`에서 그룹형 서식 영역 높이가 28px에서 68px로 커졌다.
- 즉 특정 시점에 저장 기본값이 펼침으로 바뀐 것이 아니라, 도구 상자 자체 높이가 커져 기존 기본
  노출 정책의 비용이 커진 문제였다.

## 재사용 가능한 기존 자산

#5738이 이미 다음 경로를 제공하고 있었다.

- `view:toolbox-basic`, `view:toolbox-format` 커맨드
- `userSettings.view.toolbarBasic/toolbarFormat` 저장·복원
- `applyToolboxVisibility`의 루트 data 속성과 메뉴 상태 동기화
- `theme-init.js`의 번들 전 첫 페인트 처리
- `style.css`의 data 속성 기반 숨김 규칙
- 표시 상태 저장·복원 단위 테스트와 브라우저 E2E 골격

따라서 새 상태 모델이나 이미지 자산 없이 단일 커맨드의 추가 진입점만 연결하는 방향으로 범위를
확정했다.

## 실패 계약

구현 전에 다음 계약 테스트를 추가하고 실패를 확인했다.

1. `Ctrl/Command+F1` 매핑 부재
2. 신규 기본값이 기본 도구 상자 보임인 상태
3. 우측 직접 버튼과 버튼 접근성 상태 동기화 부재
4. `MenuBar`가 드롭다운 항목만 dispatcher에 연결하는 상태
5. 첫 페인트 초기화가 기본 보임을 전제하는 상태

focused 실행은 24개 중 19개 통과, 위 계약에 해당하는 5개 실패로 시작했다.

## 단계 판정

기존 커맨드·설정·FOUC 경로 재사용으로 목표를 달성할 수 있으며, 서식 도구 상자 레이아웃 변경은
분리하는 것이 적절하다고 판정했다.

## 절차 이탈

이 조사와 실패 테스트는 당시 이슈·계획·단계 보고서 없이 진행됐고, 별도 Stage 1 커밋으로 보존되지
않았다. 정상 Hyper-Waterfall 단계였다고 간주하지 않으며 사후 재구성 사실을 유지한다.
