# task_m100_4086_stage1 — 함초롬 폴백 체인의 죽은 표기와 뒤집힌 주석

이슈 #4086 이 제기한 두 갈래를 한글 2022 동봉 폰트 8종의 cmap·name table 실측으로 확정하고,
그 결과대로 `src/renderer/mod.rs` 의 폴백 체인을 정정한 보고서다.

## 1. 무엇이 문제였나

`generic_fallback()` 의 serif/sans 체인은 마지막 단계에 함초롬 family 를
**확장B → 확장 → 일반** 순으로 끼운다. 근거로 달린 주석은 이렇게 적혀 있었다.

> 함초롬바탕 **확장B** 가 한컴 PUA 글리프를 보유하므로 chain 의 generic 직전에 우선순위로
> 매칭시킨다.

이슈는 두 가지를 지적했다.

1. `'HCR Batang Ext-B'` (하이픈)는 어떤 폰트와도 매칭되지 않는다 — 실제 패밀리명은 하이픈 없는
   `HCR Batang ExtB` 다.
2. 한컴 PUA 원문자(U+F02B1~F02C4)는 확장·확장B 에 **없다**. 주석의 전제가 틀렸다.

## 2. 실측 — 폰트가 말하게 한다

`ttfs/hwp/` 에 놓인 한글 2022 동봉 8종을 stdlib TTF 파서로 직접 읽었다(fontTools 부재 환경).
name table 은 nid1/lid0x409·0x412, 커버리지는 cmap format 4·12 를 구간 합집합으로 셌다 —
폰트는 같은 내용을 두 서브테이블에 싣는 일이 흔해 단순 합산하면 2 배로 부푼다.

### 2.1 패밀리명 (파트 1)

| 파일 | nid1/lid0x409 | nid1/lid0x412 |
| --- | --- | --- |
| `HANBatangExtB.ttf` | **`HCR Batang ExtB`** | 함초롬바탕 확장B |
| `HANBatangExt.ttf` | `HCR Batang Ext` | 함초롬바탕 확장 |
| `HANDotumExt.ttf` | `HCR Dotum Ext` | 함초롬돋움 확장 |

하이픈 없음이 확정이다. 비-B 표기(`HCR Batang Ext`)는 원래 옳았다. 이슈가 "확인 필요" 로 남긴
`HCR Dotum Ext-B` 계열은 **파일 자체가 없다** — 돋움은 확장까지만 있고 확장B 가 없어, 소스에도
없던 것이 정합이다.

### 2.2 담당 대역 (파트 2)

| 패밀리 | 고유 부호점 | 담당 | U+F02B1~F02C4 |
| --- | --- | --- | --- |
| HCR Batang / HCR Dotum (일반) | 59,330 | 한글 음절 11,172 · CJK 통합 20,940 · 확장A 6,582 · BMP PUA 5,382 · 평면15 PUA | **20 자 전부 보유** |
| HCR Batang ExtB (확장B) | 42,799 | **CJK 확장B(U+20000~) 42,711** + 평면15 소량 86 | 미보유 |
| HCR Batang Ext / HCR Dotum Ext (확장) | 3,535 | **평면 1 희귀 스크립트**(U+10000~, Linear B 등) | 미보유 |

주석의 전제는 사실과 **반대**였다. PUA 원문자의 소재는 일반이고, 확장·확장B 는 그 목적과 무관한
다른 대역을 맡는다. 지금까지 화면이 맞게 나온 것은 브라우저가 글리프 없는 폰트를 건너뛰어
결과적으로 일반에서 떨어졌기 때문이다 — 이슈 표현대로 **의도가 아니라 우연**이다.

### 2.3 순서를 바꿔도 되는가

세 family 의 커버리지 교집합을 직접 셌다.

```
일반 ∩ 확장   = 0 자
일반 ∩ 확장B  = 2 자   (U+0020, U+00A0 — 공백뿐)
확장 ∩ 확장B  = 0 자
```

담당이 겹치지 않으므로 나열 순서는 **무엇이 매칭되는지를 바꾸지 않는다**. 따라서 순서 정정은
동작 변경이 아니라 의도 표기의 정정이다.

## 3. 고친 것

| 대상 | 내용 |
| --- | --- |
| 체인 6곳 + 테스트 2곳 | `'HCR Batang Ext-B'` → `'HCR Batang ExtB'` |
| 체인 8곳 | 순서를 **일반 → 확장 → 확장B** 로 (목적과 일치) |
| `generic_fallback()` 주석 | 실측 수치로 다시 씀. 확장B 를 PUA 보유자로 적던 문장 제거 |
| `test_generic_fallback` | 하이픈 부활·순서 역전을 잡는 단언 추가 |

체인에서 함초롬을 빼지 않았다. 확장·확장B 는 CJK 확장B·희귀 스크립트라는 **다른 목적**으로
여전히 필요하다.

| 게이트 | 결과 |

| `cargo fmt --check` | 통과 |
| `cargo clippy --all-targets -- -D warnings` | 통과 |

### 4.1 시각 증적 — 기하 변화 0

렌더러 변경이므로 전후 SVG 를 실물로 비교했다. `samples/pua-test.hwp`(한컴 PUA 원문자 포함)를
변경 전 바이너리와 변경 후 바이너리로 각각 내보냈다.

```
크기        423,949 → 423,174 byte   (차 775 = 하이픈이 있던 775 곳 × 1 byte)
text 요소   777 → 777
path 요소   0 → 0
font-family 문자열을 지운 뒤 diff → 차이 없음
```

즉 바뀐 것은 폰트 문자열뿐이고 좌표·글리프 배치는 한 곳도 움직이지 않았다.

### 4.2 골든 SVG 7 건은 폰트 문자열만 바뀐다

`tests/golden_svg/` 스냅샷 7 건이 처음에 실패했다. 폰트 체인이 SVG 의 `font-family` 속성에 그대로
실리기 때문이다. 갱신 전에 **기하가 정말 그대로인지** 전수 확인했다 — `font-family` 속성을 지운
뒤 비교하니 7 건 모두 **diff 0 줄**이었다.

| 스냅샷 | font-family 제외 diff |
| --- | --- |
| `table-text/page-0` · `form-002/page-0` · `issue-147/aift-page3` · `issue-157/page-1` · `issue-267/ktx-toc-page` · `issue-617/exam-kor-page5` · `issue-677/bokhakwonseo-page1` | 0 줄 |

그래서 `UPDATE_GOLDEN=1` 로 갱신했다. 갱신 diff 에서 `font-family` 를 뺀 나머지 변경은 `</g>`
닫는 태그 16 쌍의 위치 이동뿐이고(+16/−16), 좌표·글자·경로는 한 곳도 바뀌지 않았다.

## 5. 남긴 것

- 이 기계(Linux)에는 함초롬 폰트가 **시스템 설치되어 있지 않다**(`fc-list` 0 건). `ttfs/` 의
  파일을 파서로 읽은 실측이므로 폰트 파일 자체의 사실은 확정이지만, "설치된 환경에서 브라우저가
  실제로 어느 폰트를 고르는가" 는 이 보고서의 범위 밖이다.
- 확장·확장B 가 맡는 CJK 확장B·희귀 스크립트 대역이 렌더에서 실제로 필요한 문서가 있는지는
  별도 축이다. 체인에서 빼지 않았으므로 현행 동작은 유지된다.
