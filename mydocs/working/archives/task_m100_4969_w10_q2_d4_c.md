# Task M100 #4969 W10-Q2-D4-C — cross-backend·성능 최종 자격 판정

## 판정

Q2-D4-C는 **qualified-bounded**다. D4-B의 최초 one-line/one-run strict lane은 유지한다. 실제 CanvasKit draw,
native/WASM, backend fallback, #5821과 W9 보호 회귀, 전체 Rust·Studio 회귀가 모두 통과했다. 다만 portable font를
각 layer resource에 운반하는 비용은 작지 않다. 따라서 **현재 lane은 닫지 않지만, font resource 재사용·중복 제거를
입증하기 전에는 lane을 넓히지 않는다.** D4는 여기서 완료하며 D5는 별도 승인 전 시작하지 않는다.

기계 판독 결과는
[`w10_q2_d4_c_final_qualification.json`](../../tech/investigations/issue-4969/w10_q2_d4_c_final_qualification.json)에
고정했다.

## 실제 CanvasKit 오라클

저장소의 `SourceHanSerifK-OldHangul-subset.otf`와 D4-A의 고정 glyph·cluster vector를 사용했다. Node의
CanvasKit software surface에서 실제 pixel을 읽었으며 host 설치 폰트나 private corpus는 사용하지 않았다.

| 항목 | 결과 |
| --- | ---: |
| glyph IDs | 614, 1230, 1497, 2085 |
| page advance | 61.824px |
| 현재 계약 | `fontSize=40×√0.8`, `scaleX=√0.8` |
| 현재 ink bbox | 58×34px, `(16,22)~(73,55)` |
| #5821 이전 비교 계약 | `fontSize=40`, `scaleX=0.8` |
| 이전 계약 ink bbox | 58×38px, `(16,18)~(73,55)` |
| local→page 위치·advance 오차 | 0px, 허용치 1e-9px |

두 계약은 page advance와 ink 폭을 유지하지만, 이전 계약은 glyph 높이가 4px 더 크다. 현재 계약이 압축 장평의 세로
`√ratio` 축소를 실제 draw에서도 보존한다. strict flag가 꺼지거나 affine에 `NaN`이 들어가면 selector는 GlyphRun을
선택하지 않고 TextRun으로 닫혔다. cluster glyph range `[0,1]`, `[1,4]`도 바뀌지 않았다.

CanvasKitBrowser는 Node와 같은 selector·font cache·draw consumer를 사용한다. Canvas2D·legacy SVG는 TextRun,
native Skia는 blob typeface 생성 증명이 생길 때까지 TextRun을 유지한다. native-skia feature의 15개 proof/fallback
검사가 이 경계를 확인했다.

## native/WASM과 integration 보호

D4-B에서 root dev-dependency 때문에 직접 실행하지 못했던 wasm32 integration은 root Cargo를 바꾸지 않는 최소
`wasm-bindgen-test` harness로 다시 실행해 2/2 통과했다. 표준 Docker WASM release build와 wasm32 lib clippy도
통과했다.

분리된 review worktree에서 integration source 991개, static test attr 4,463개를 32 suite + 16 exception = 48
target으로 준비했다. D0~D4와 #5821 focused 검사는 35개, W9 보호 subset은 6개가 통과했다. 이 과정에서 D1 source가
이전 owner split 뒤 `shaping_publication` 모듈을 직접 포함하지 않아 독립 integration source로는 낡아 있음을 발견해
include를 보완했다. 제품 결함이나 제품 코드 변경은 아니다. generated suite·manifest·Cargo target은 source
worktree나 제출 목록에 포함하지 않는다.

## 성능 영향

동일 fixture와 동일 release probe로 D4-A dormant checkpoint `520f14dcf`와 D4-B activation checkpoint
`4992ccbf3`를 비교했다. 20회 warmup 뒤 200회×9그룹의 중앙값과 cold core 25개의 중앙값을 사용했다.

| 항목 | D4-A dormant | D4-B active | 차이 |
| --- | ---: | ---: | ---: |
| warm layer build | 0.843µs | 703.600µs | +702.757µs, 834.64배 |
| cold layer build | 1.608ms | 2.314ms | +0.706ms, +43.91% |
| layer JSON | 6,849B | 619,562B | +612,713B, 90.46배 |
| portable font payload | 0B | 456,688B | +456,688B |

이 수치는 기능 오류가 아니라 exact portable replay의 비용을 드러낸다. warm 반복마다 새 `ResourceArena`에 같은
456,688바이트를 대사·등록하고 layer JSON에 직렬화하는 현재 구조에서는 상대 배수가 매우 커진다. 최초 strict lane은
정확성과 fail-closed 조건을 만족하므로 유지할 수 있지만, multi-run·multi-line·여러 문단으로 확장하면 payload 비용이
누적될 수 있다. 따라서 다음 확대 전 보호 조건은 page/document 수준 font blob 재사용, digest 계산 재사용, JSON 전달의
중복 제거가 실제 측정으로 입증되는 것이다.

## 남은 경계

D4는 제품의 최초 strict lane과 cross-backend 검증까지 끝났다. multi-line/run, mixed target,
center/right/justify/distribute, ratio 항등·확대, nonzero GPOS y positioning, RTL/vertical/variation, native Skia blob
typeface replay는 계속 fail-closed 또는 TextRun fallback이다. 이 목록은 D4 실패가 아니라 승인되지 않은 후속 범위다.

D5는 별도 승인 전 시작하지 않는다. lane 확대는 별도 성능 threshold를 임의로 만들기보다, 위 resource 재사용 증거와
다음 기능 오라클을 갖춘 수정 계획으로 다시 승인받는다. push·PR·GitHub comment도 기존 승인 경계를 유지한다.
