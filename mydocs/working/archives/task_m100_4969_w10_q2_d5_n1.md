# Task M100 #4969 W10-Q2-D5-N1 — NO_LS atomic activation 결과

## 판정

Q2-D5-N1은 **qualified**다. 모델 `LineSeg`가 없고 N0의 ordinary single-interval 기능 탐지를 통과한 문단만
R3의 exact-source 경로를 사용하도록 제품 caller를 연결했다. line selection, TextRun bbox, next origin과
page sidecar/common GlyphRun은 같은 `Arc<HorizontalShapingMeasurement>`를 공유한다. page-local sidecar와 unique
source 예산을 먼저 원자적으로 예약한 뒤에만 shaping 폭을 게시하며, 실패하면 기존 W9/K0 TextRun·geometry를
그대로 사용한다.

최초 지원 범위는 여전히 한 줄·한 run·한 target인 bounded lane이다. multi-interval, edit reflow, stored prefix,
split cell, inline control, center/right/justify/distribute, RTL·vertical 등은 이번 결과로 열지 않았다. 기계 판독
결과는
[`w10_q2_d5_n1_no_lineseg_activation.json`](../../tech/investigations/issue-4969/w10_q2_d5_n1_no_lineseg_activation.json)에
고정한다. 이 판정은 N2 최종 cross-backend·성능 판정을 자동으로 승인하지 않는다.

## 제품 owner와 원자 게시

NO_LS 문단은 초기 composition 시점에 저장 폭이 없어 Q2-C outcome을 만들 수 없다. N1은 물리 frame이 최종
단일 interval을 확정한 뒤 같은 `ComposedParagraph`에 horizontal shaping handoff를 다시 계산한다. 그 뒤 제품
TextRun을 만들기 직전에만 다음 transaction을 수행한다.

```text
final physical-frame interval
  -> Q2-C final target measurement Arc
  -> N0 feature detection + exact replay certificate
  -> page-local atomic reservation
       sidecar NodeId/range
       unique exact-source count and bytes
  -> one publication
       line width
       TextRun bbox width
       next origin delta
       common GlyphRun sidecar
```

게시된 네 소비자는 모두 pointer identity가 같고 세 geometry 값은 measurement의 `total_advance_px`와 같다. 같은
exact source를 쓰는 두 번째 run을 게시해도 예약은 source 1개·456,688 bytes로 유지된다. sidecar 충돌이나 자원
상한 위반은 sidecar와 예약을 모두 mutation하기 전에 닫힌다.

LayerBuilder는 게시된 sidecar에서 common GlyphRun 하나만 만들고 같은 TextRun의 nominal GlyphRun slot은 다시
사용하지 않는다. TextRun 하나는 backend가 strict GlyphRun을 선택하지 못할 때의 fallback으로 계속 남는다.

## red→green에서 확인한 원인

1. red 계약은 N1 publish API가 없는 compile failure에서 시작했다.
2. `Paragraph::new_empty()`가 기본 `LineSeg`를 가진다는 fixture 사실을 확인해, NO_LS 테스트는 이를 명시적으로
   비우도록 고쳤다.
3. 첫 제품 red는 common GlyphRun이 0개였다. NO_LS 초기 composition의 segment width가 0이라 Q2-C outcome이
   만들어지지 않는 것이 원인이었다. 임의 기본 폭을 주입하지 않고 최종 physical-frame partition 뒤 handoff를
   다시 계산하도록 owner 시점을 옮겼다.
4. 최초 green 뒤 geometry 게시 전에 paint와 같은 page source 예산을 예약하지 않는 공백을 발견했다. source
   count 256, 총 font bytes 64 MiB, 개별 portable blob 32 MiB 상한을 한 정의로 공유하고 sidecar attach와 source
   회계를 한 mutation 경계로 묶었다.

## positive·negative 제품 계약

공개 `SourceHanSerifK-OldHangul-subset.otf`와 `ᄒᆞᆫ말` fixture만 사용했다.

| 항목 | qualified NO_LS | reject surface |
| --- | ---: | ---: |
| TextRun fallback | 1 | 1 |
| common GlyphRun | 1 | 0 |
| nominal duplicate GlyphRun | 0 | 0 |
| portable font blob / face | 1 / 1 | 0 / 0 |
| TextRun bbox = GlyphRun bbox = page advance | true | 해당 없음 |
| legacy layer JSON과 exact 일치 | 해당 없음 | true |

negative 제품 대조는 center alignment와 edit-dirty NO_LS 문단에서 exact source를 등록한 결과를 source가 없는
legacy 기준선과 전체 layer JSON으로 비교했다. 두 경우 모두 byte-level JSON이 같고 resource mutation은 0이다.
기존 sidecar NodeId와 충돌시키는 owner 테스트도 원래 owner를 그대로 보존하고 N1 source 예약을 0으로 유지한다.
