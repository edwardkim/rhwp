## 1. 기존 자료 재사용 결과

W3의 10,000-entry checkpoint journal, W4 공개 ranking, W5 rank 7 ladder·readiness, W7 projection과 W7.5
v2 registry를 hash·semantic identity로 대사했다. corpus 원문을 다시 열거나 parse하지 않고 journal의 기존
decision만 한 번 streaming 조회했다.

rank 7 `KoPubWorld돋움체 Light`의 실제 cohort는 5문서이며 HWP 3, HWPX 2다. 문서별 target usage row와
final aggregate의 같은 face usage row는 모두 174개이고 target 문자 합계는 63,858자다.

| 항목 | 결과 |
| --- | ---: |
| 위험 문자 | 63,732 |
| face-miss / heuristic / char-miss | 63,732 / 0 / 0 |
| compressed 전체 / 위험 | 63,082 / 62,960 |
| compressed·fixed-context 위험 | 51,924 |
| stored / fresh 위험 | 63,732 / 0 |
| table-cell / body / header / footer | 52,149 / 11,504 / 175 / 30 |

W4의 category, format(HWP 3,159자·HWPX 60,699자), compressed fixed-context와 fresh lane 수치에 모두
정확히 일치했다. 위험 문자의 81.8%가 table-cell이고 target 전체의 98.8%가 ratio 축소 또는 음수 자간에
노출된다. 특히 ratio 95·spacing -9가 51,226자로 target의 80.2%다. 이후 판정은 평균 폭이나 page count가
아니라 이 실제 편집 습관과 actual table frame의 line crossing을 보호해야 한다.

style domain에는 bold 4,468자, italic 0자가 있다. Q2에서 regular exact metric만 비교하고 bold 요청을
누락하지 않도록 이 aggregate를 공개 baseline에 고정했다.

## 2. exact source와 W5 Oracle 경계

local-only exact TTF는 W5가 봉인한 SHA-256
`069494cce21a4222c88e537f256b6f46fee209375aba769f82431b2d382bc84f`와 일치했다.

| 항목 | 관찰 |
| --- | --- |
| SFNT family | `KoPubWorld돋움체 Light`, `KoPubWorldDotum Light`를 포함한 4개 family name |
| PostScript name | `KoPubWorldDotumLight` |
| unitsPerEm | 1,000 |
| glyph / cmap / hmtx | 31,556 / 25,974 / 31,537 |
| `OS/2.fsType` | 8, editable embedding |
| 공식 record | UCI `G905-13287211`, 기존 결정은 local analysis only |

W5 exact-only는 exact KoPubWorld 돋움 bytes를 PDF subset으로 사용했다. 그러나 fixture가 선언한
`KoPubWorld바탕체 Light`는 subst-only에서 실제 선택되지 않았고 subst-only·none-related가 같은
`HCRBatang-Bold` projection으로 귀결됐다. 따라서 document `substFont`를 제품 fallback relation으로
승격하지 않는다. W5 ladder와 source identity가 유효하므로 Hyper-V를 다시 실행하지 않았다.

## 3. 현행 registry·projection 경계

현행 v2 registry와 W7 projection에서 target active rule은 다음 supply 두 개뿐이다.

| projection | 현재 역할 |
| --- | --- |
| `canvas2d-webfont` | jsDelivr WOFF2 공급 계획 |
| `canvaskit-sfnt` | online jsDelivr OTF 공급 계획, offline unavailable |

Rust `layout-name`·`layout-metric` target rule은 0이다. 이는 Q1의 runtime miss 가설을 조사할 근거지만 아직
제품 결함이나 exact metric 적용 결론은 아니다. OTF·WOFF2의 이름과 URL도 exact TTF와 metric이 같음을
증명하지 않으므로 Q2 전에는 supply를 layout truth로 사용하지 않는다.

## 4. 공개·비공개 경계와 검증

`scripts/font_rank7_qualification.py`는 511 MiB W3 journal을 1회 streaming 처리하고 다음을 fail-closed로
검사한다.

- 입력 크기·journal line 크기·index 중복·document count

- exact TTF name·cmap·hmtx·unitsPerEm·OS/2.fsType

## 5. 다음 gate

Stage W8-R7-Q1은 W5 generator로 rank 7 HWPX fixture를 복원하고 봉인 hash와 byte-exact함을 먼저
검사한다. 그 fixture의 결정적 HWP 짝에서 다음 경계를 형식별·backend별로 전건 trace한다.

```text
raw document face
  -> parser normalization
  -> layout-name decision
  -> layout-metric lookup / heuristic
  -> paint request
```

HWP/HWPX와 native/Docker WASM parity가 성립하고 첫 divergence가 한 decision plane으로 좁혀져야 Q2로
진행한다. Q1은 별도 승인 뒤 시작하며 Q0 변경은 제품 font 동작을 바꾸지 않는다.
