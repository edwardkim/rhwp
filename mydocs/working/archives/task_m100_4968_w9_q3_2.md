## 1. 결론

Q3-2는 family 이름으로 font를 다시 추측하지 않는다. 상위 font selection이 확정한 bytes와 face index만
`ExactFontSource`로 받아 `gpos-kern`, `legacy-kern`, `unsupported`를 기능 탐지한다. GPOS는 `kern`
feature가 실제 pair positioning lookup을 참조할 때만 지원으로 판정한다. legacy는 Q2 계약과 같은 horizontal
format 0만 지원하며, 두 기능이 함께 있으면 GPOS를 선택한다.

source 없음, malformed SFNT, 32 MiB 초과, 지원 pair table 없음은 각각 다른 fallback reason으로 구조화했다.
상한 초과는 font parse와 SHA-256 계산 전에 거부한다. 유효하고 상한 안의 exact source만 SHA-256,
face index, byte 수, units-per-em을 남긴다.

이 절편은 capability를 판정할 뿐 measurement나 positions에 delta를 적용하지 않는다. 공개 Q2 fixture의 K0/K1
9쌍은 계속 같은 positions이며 Q2에 동결한 9개 position hash도 전항 일치한다.

## 2. capability 계약

| 입력 | capability | fallback reason |
| --- | --- | --- |
| GPOS `kern` + pair lookup | `gpos-kern` | 없음 |
| usable horizontal legacy format 0 | `legacy-kern` | 없음 |
| GPOS와 legacy 동시 존재 | `gpos-kern` | 없음 |
| 유효 face이나 지원 table 없음 | `unsupported` | `pair-table-unsupported` |
| exact source 없음 | `unsupported` | `font-source-unavailable` |
| 파싱 불가 또는 face index 불가 | `unsupported` | `malformed-sfnt` |
| 32 MiB 초과 | `unsupported` | `font-byte-limit-exceeded` |

`unsupported`와 문서의 `kerning=false`는 동일한 상태가 아니다. 전자는 요청이 있어도 exact face에서 적용할
수 없다는 capability 결과이고, 후자는 Q3-1에서 고정한 `not-requested` 입력이다. run disposition은 다음
절편에서 두 축을 결합한다.

## 3. 구현 경계

- `src/renderer/kerning.rs`

  - `KerningCapabilityDecision`: capability, fallback reason, source SHA-256, byte 수, face index,

  - `MAX_KERNING_FONT_BYTES`: 32 MiB
  - `inspect_exact_font_kerning`: bounded 기능 탐지
- `src/renderer/mod.rs`: 공통 renderer 내부 모듈 등록
- `tests/cases/issue_4968_kerning_capability_provider.rs`: 외부 integration 원본

새 source-side `#[cfg(test)]`는 만들지 않았다. integration 시험은 공개 Noto face, 기존의 작은 공개 test font,
메모리 안에서 합성한 legacy table만 사용한다. 별도 font binary, generated suite·manifest, Cargo target marker는
추가하지 않았다.

## 4. 보호 불변식 판정

1. **exact source만 사용**: family 이름이나 fallback 후보를 provider 안에서 검색하지 않는다.
2. **기능 탐지**: HWPX·한컴 버전이나 font 이름 분기가 없다.
3. **bounded input**: 32 MiB 초과는 parse·hash 전에 종료한다.
4. **우선순위**: GPOS `kern` pair lookup을 legacy보다 먼저 선택한다.
5. **fail-closed**: source 없음·손상·미지원·상한 초과에서 pair 적용값을 만들지 않는다.
6. **조판 무변경**: capability 결과는 아직 measurement와 position 소비자에 연결하지 않았다.
7. **backend 무관**: platform 조건부 코드와 새 dependency가 없으며 native/WASM이 같은 모듈을 컴파일한다.

```bash
cargo check --locked --lib
cargo test --locked --lib --no-run
cargo build --locked --release --bin rhwp --bin rhwp-q-kit
docker compose --env-file .env.docker run --rm wasm

node --test \
  scripts/tests/kerning_q1_baseline.test.mjs \
  scripts/tests/kerning_q2_fixture_baseline.test.mjs
python3 -m unittest -q scripts.tests.test_kerning_q2

cargo fmt --all
cargo fmt --all -- --check
```

현재 source checkout에서는 `--prepare`와 manifest `--check`를 실행하지 않았다. capability integration 원본은
저장소 밖 임시 Cargo manifest로 직접 컴파일·실행하고 임시 파일을 제거했다. Q2 baseline 생성기는 추적 파일이
아닌 `/tmp` 출력에 실행해 native/WASM parity를 확인한 뒤 그 출력도 제거했다.
