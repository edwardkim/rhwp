# Task M100 #4969 W10-Q2-D5-N0 — NO_LS dormant owner·rollback 결과

## 판정

Q2-D5-N0는 **qualified**다. 모델 `LineSeg`가 없는 ordinary single-interval 문단의 Q2-C final target을
line selection·TextRun bbox·next origin·page sidecar/GlyphRun 네 소비자가 동일한
`Arc<HorizontalShapingMeasurement>`로 소유하는 dormant transaction을 고정했다. transaction은 composition,
page sidecar, resource arena와 제품 geometry를 입력으로 받지 않는다. 따라서 exact source 인증까지 전건
성공하기 전에는 부분 게시를 표현할 수 없고, 실패 결과에는 pristine W9/K0 geometry만 남는다.

제품 caller는 0이며 serialization·render/layer JSON·화면 출력 변화도 0이다. 기계 판독 결과는
[`w10_q2_d5_n0_no_lineseg_owner.json`](../../tech/investigations/issue-4969/w10_q2_d5_n0_no_lineseg_owner.json)에
고정한다. 이 판정은 N1 activation을 자동으로 열지 않는다.

## owner 계보

N0는 새 layout 분기를 만들지 않고 기존 owner 사이에 다음 dormant 경계를 추가했다.

```text
ComposedParagraph가 보존한 Q2-C outcome Arc
  -> final line [0,4]의 target measurement Arc
  -> D2 emitted-run mapping
       line selection Arc
       bbox Arc
       next-origin Arc
  -> D4 exact-source certificate를 가진 sidecar decision Arc
       page sidecar/GlyphRun consumer Arc
  -> N0 transaction 완성
       제품 caller 0, product_published=false
```

성공 transaction은 원래 `Arc<HorizontalShapingLineOutcome>`도 그대로 보존한다. 따라서 final range와 네 geometry
소비자가 다른 composition transaction에서 섞일 수 없다. pointer identity가 하나라도 다르거나 line/bbox/next-origin
폭이 measurement total advance와 다르면 `OwnerIdentityMismatch`로 닫는다.

## boundary-changing shadow 오라클

공개 `SourceHanSerifK-OldHangul-subset.otf`와 `ᄒᆞᆫ글` fixture만 사용했다.

| 항목 | pristine W9/K0 | N0 staged | 제품 게시 |
| --- | ---: | ---: | --- |
| line width | 16.000px | 15.456px | 없음 |
| TextRun bbox width | 16.000px | 15.456px | 없음 |
| origin x | 23.500px | 23.500px | 없음 |
| next origin x | 39.500px | 38.956px | 없음 |

staged boundary delta는 `-0.544px`이지만 N0는 이를 layout에 적용하지 않는다. line selection, bbox, next origin,
sidecar/GlyphRun의 measurement는 모두 `Arc::ptr_eq=true`이고 Q2-C final target도 같은 allocation이다. 이 결과는
N1이 원자 게시할 수 있는 입력을 증명할 뿐 activation 증거는 아니다.

## 기능 탐지와 typed reject

HWP/HWPX 버전이나 한컴 build 번호는 보지 않는다. 현재 객체 상태만 판정한다.

| 상태 | 결과 |
| --- | --- |
| model LineSeg 1개 이상 | `ModelLineSegPresent` |
| frame interval 0개 또는 2개 이상 | `FrameIntervalCountUnsupported` |
| 일반 edit reflow | `EditReflowUnsupported` |
| stored prefix | `StoredPrefixUnsupported` |
| split cell | `SplitCellUnsupported` |
| inline control | `InlineControlUnsupported` |
| final target 0개 또는 2개 이상 | `TargetCountUnsupported` |
| Q2-C outcome이 qualified가 아님 | `OutcomeNotQualified` |
| emitted surface mapping 실패 | `EmittedRunRejected(<typed D2 reason>)` |
| stale/missing/mismatch source | `ReplaySourceRejected(<typed D4 reason>)` |
| Arc·range·geometry owner 불일치 | `OwnerIdentityMismatch` |

위 실패는 모두 원래 `HorizontalShapingLegacyGeometry`를 그대로 반환하며 `product_published=false`다. rejection
타입에는 page sidecar·resource handle이 없으므로 일부 target, font resource 또는 boundary만 남길 수 없다.

## red→green과 harness 계보 정정

red는 기존 등록 source integration인 `issue_4969_shaping_emitted_run_mapping`에 N0 계약을 먼저 추가해 새 API가
없다는 compile failure로 확인했다. 새 integration source나 generated suite를 만들지 않았다.

R1에서 `kerning.rs`의 exact resource resolver가 paint helper를 사용하게 된 뒤, glyph-lowering source만 좁은
`paint` wrapper를 갖고 D0/D1/Q2-B/Q2-C source harness 네 곳은 직접 컴파일할 수 없는 상태였음도 발견했다.
제품 API를 넓히지 않고 다섯 source integration 원본이 같은 public helper와 32 MiB 상수만 재노출하도록
정규화했다. 이는 제품 결함 수정이 아니라 R1 이후 누락된 test harness 인계 보정이다.

최초 green 실행은 owner·rollback 7건이 통과하고 next-origin의 `15.456000000000003`과 `15.456`을 exact 비교한
테스트 한 건만 실패했다. 기존 D2와 같은 `1e-12` 허용오차로 oracle을 고쳐 8/8 통과했다. 제품 계산이나 기대
geometry를 바꾸지 않았다.
