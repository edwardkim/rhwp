# #4898 ③ HWPX 평문 문단 여백 표기 보존

## 목표

HWPX → HWPX 저장(x2x)에서 한글이 원본보다 쪽수를 1쪽 더 세는 잔존군을 없앤다. s36 전수에서
x2x 쪽수 결함은 28경로였고 그중 25가 "+1쪽"이었다.

## 원인

한글은 문단 여백·줄간격에 `hp:switch` 가 있으면 `hp:case`(HwpUnitChar, 1× 스케일)를 우선 읽는다.
rhwp 직렬화기는 원본 표기와 무관하게 항상 switch 를 씌우고 `case = 저장값/2`, `default = 저장값`
으로 냈다. 원본이 평문(switch 없음)이던 문서는 저장값이 곧 한글이 읽던 값이므로, case 에 절반이
들어가는 순간 한글이 보는 여백·고정 줄간격이 반토막 나 조판이 밀리고 쪽수가 늘었다.

이식 실험으로 원인을 좁혔다(모두 한글 2022 실측).

| 변형 | 결과 |
|---|---|
| 산출에 원본 `header.xml` 이식 | 6/6 원본 쪽수 복귀 |
| 산출에 원본 `section0.xml` 이식 | 효과 없음 |
| header 안에서 `hh:paraProperties` 만 원본으로 | 3/3 복귀 (charPr·tabPr 은 무효) |
| `case` 분기 값을 `default` 값으로 되돌림 | 6/6 복귀 |

값 비교에서도 여백·고정 줄간격이 정확히 절반이었다(3000→1500, 5000→2500, 3560→1780).

## 기각한 대안 — 파서에서 ×2

평문 경로에 ×2 정규화를 넣는 안은 x2x 23건을 고치는 대신 **x2h 58건을 깨뜨렸다**(영향 문서 280건
전수 측정). HWP5 저장기는 현재 IR 스케일을 그대로 쓰므로 파서를 바꾸면 그쪽이 무너진다. 그래서
저장 표기를 보존하는 방향으로 갔다.

## 변경

- `ParaShape.hwpx_plain_para_margin` — HWPX 원본이 평문 표기였는지 보존(`break_latin_word` 선례).
- HWPX 파서: switch 밖 평문 여백을 읽으면 표시하고, switch 를 만나면 해제한다.
- HWPX 직렬화기: 그 표시가 있으면 switch 없이 평문 그대로 방출한다.
- HWP5 파서는 이 표기 구분이 없으므로 `false`(switch 형태 유지).

## 검증 실측 — 한글 2022 오라클

수정 바이너리로 코퍼스 HWPX 입력 3,418건을 양 축으로 재변환해 산출이 달라지는 문서를 전수 추출했다.

| 축 | 산출이 달라진 문서 |
|---|---|
| x2x | **290** |
| x2h | **0** (파서 무변경 — 설계대로) |

그 290건을 한글 2022 로 전수 측정한 결과:

| 구분 | 건수 |
|---|---|
| **고침** — 쪽수 결함이 원본 쪽수로 복귀 | **23** |
| **깨짐** | **0** |
| 둘 다 정상 | 267 |
| 텍스트 길이 / 컨트롤 집계 변화 | **0 / 0** |
