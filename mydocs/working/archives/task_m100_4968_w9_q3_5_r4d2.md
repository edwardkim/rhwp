## 1. 결론

R4D-1에서 최종 `TextRunNode`에 게시한 exact scalar positions를 SVG, Web Canvas2D, HTML, native
Skia, paint JSON, portable GlyphRun, CanvasKit policy, command-only CanvasRenderer가 공통 소비하도록
전환했다. backend는 font source를 다시 찾거나 kerning shaping을 다시 실행하지 않는다.

K1에서는 glyph·cluster, shade, decoration, control mark와 portable glyph advance가 layout owner의 같은
좌표를 읽는다. K0, malformed payload, replay 문자열 projection 불일치는 run 전체를 기존
`compute_char_positions` 경로로 되돌린다. R4D-1 커밋과 현재 후보를 같은 공개 HWPX로 교차 실행한 결과
K0 SVG와 render-tree JSON은 byte-for-byte 동일했다.

## 2. 공통 replay 계약

`validated_replay_positions`를 `Renderer` 공통 경계에 두어 `TextRunNode` accessor뿐 아니라
`Renderer::draw_text_positioned` 직접 호출도 같은 검사를 통과하게 했다.

- 최대 4,096 scalar / 4,097 positions
- 길이 `N+1`, 첫 값 `0.0`
- finite·non-negative·monotonic
- visible replay 문자열과 scalar 수 불일치 시 전체 K0 fallback

`replay_positions_or_compute`는 유효한 K1 slice를 borrow하고, 그렇지 않을 때만 기존 K0 positions를
계산한다. 따라서 visual consumer마다 서로 다른 유효성 판정이나 부분 적용 상태를 만들지 않는다.

## 3. 소비자별 처리

| 소비자 | R4D-2 처리 | K0·실패 처리 |
|---|---|---|
| SVG / SvgLayer | glyph cluster x, shade, decoration, 공백·탭 control mark가 공통 positions 소비 | 기존 scalar 계산 |
| Web Canvas2D | glyph/effect pass, shade, decoration, control mark가 공통 positions 소비 | 기존 scalar 계산 |
| HTML | K1 scalar별 absolute span을 producer 좌표에 배치 | 기존 단일 `text-run` span 유지 |
| native Skia | glyph cluster, shade, decoration, control mark가 공통 positions 소비 | 기존 scalar 계산 |
| paint JSON | text/display positions, cluster origin, tab leader, control mark, decoration 전환 | 기존 JSON 형식·계산 유지 |
| portable GlyphRun | glyph origin과 advance를 producer positions에서 투영 | identity 불일치 시 기존 TextRun fallback |
| CanvasKit policy | replay geometry 판정이 공통 positions 소비 | bounded-work payload 회계는 R4D-3에서 마감 |
| command CanvasRenderer | K1 `FillTextPositioned`로 좌표 보존 | 기존 `FillText` 형식과 command count 유지 |
| text-layout query | 공개 문자 좌표가 공통 positions 소비 | 기존 scalar 계산 |

PUA 확장이나 inline placeholder 제거로 replay scalar 수가 달라지면 positions를 억지로 맞추지 않고 K0로
닫는다. CharOverlap은 R4D-1 producer가 positions를 게시하지 않는 특수 run이므로 기존 전용 경로를 유지한다.

focused 정확성 결과만으로 비용 상한을 선언할 수 없다. 이 값들은 R4D-3의 bounded-work·Docker WASM
검증에서 별도 계측하고, 동일하게 참고 데이터와 보안 상한 판정을 구분한다.
