# Task #3308 Stage 1 보고 — 중첩 표 폭 스트레치 근인 + 배치 모델

## 근인 확정 — 전면 스트레치 정규화

`RenderNormalizationOverlay::collect_nested_tables`(`render_normalization.rs`)가
**비-TAC 중첩 표의 선언 폭 < 부모 셀 폭이면 셀 폭으로 비례 확장**한다.

| 측정 | 선언 | rhwp 렌더 |
|---|---|---|
| 직인 1×2 표 폭 | 32,635HU = 435.1px | **641.3px (부모 셀 폭)** — ×1.4738 |
| 직인 셀 x | — | 670.1 (= 원점 + 385.5×1.4738, 정확 재현) |

**한컴 권위 3중 확인**: ①작업지시자 편집기 크기 판독 115.13mm = **435.1px 정확 일치**
②한컴 HWP5 재저장본도 선언값 유지(width/h_off/v_off 불변) ③정답지 픽셀 좌표.

## 기원과 보호 대상 분리 — 임계값 실측

스트레치는 #2195(NO_LS 재계산 축, 76076=82/86712=65/sijang=307 쪽수 게이트)에서
도입, #2308 에서 오버레이 이관. **직접 의존 테스트 없음**(쪽수 게이트 간접 보호).

비율 분포 실측 — **완벽 분리**:

| 문서군 | 스트레치 비율 |
|---|---|
| 76076 (17건) · 86712 (12건) — 보호 대상 | **0.956 ~ 0.995** (근소 미달 = 셀 폭 맞춤) |
| 직인 표 | **0.679** |

가드: 비율 하한(예: ≥0.9)으로 근소-미달만 스트레치 — #3236(1.5×)과 동일한
"상한 없는 정규화에 경계 부여" 패턴.

## 비스트레치 시 배치 모델 — 미확정 1건

한컴 정답지에서 중첩 표 원점 ≈ 198.9px. 후보 대조:

| 모델 | 예측 | 오차 |
|---|---|---|
| **부모 셀 내 가운데 정렬** | 199.5 | **0.6px** ✓ |
| 셀 content 원점 + 선언 h_off(6226HU) | 183.2 | 15.7px ✗ |
| 본문 단 원점 + h_off | 179.4 | 19.5px ✗ |

선언은 `horzAlign="LEFT" horzRelTo="COLUMN" horzOffset="6226"`, 앵커 문단 정렬도
LEFT 인데 **실렌더는 가운데와 일치**한다 — 셀 안에서 COLUMN 기준이 무효화되며
한컴이 다른 규칙(가운데?)로 배치하는 것으로 보인다. **작업지시자 편집기 확인 요청**:
직인 중첩 표의 표 속성 → 위치 탭의 가로 기준·값 판독.

## Stage 2 설계(안)

1. 스트레치에 비율 하한 가드(≥0.9 부근, 실측 분리대 0.679↔0.956 사이).
2. 비스트레치 표의 셀 내 가로 배치를 확정 모델로 구현(편집기 판독 후).
3. red-check + 직인 x 좌표 계약(한컴 598.7 대비 ≤5px) + #2195 쪽수 게이트 무회귀.
