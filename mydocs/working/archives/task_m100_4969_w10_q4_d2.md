## 결론

Q4-D2는 `layout_vertical_cell_text`의 기존 즉시 mutation 경로 앞에 하나의 제한된 transaction 경계를
추가했다. HWP5 의미 계보, `text_direction=2`, one cell·paragraph·line·source run·column, pure CJK,
100% 장평·0 자간·무합성 스타일, host가 exact slot에 등록한 공개 Noto Sans KR bytes라는 조건을 모두
통과해야만 후보가 된다.

후보는 Q4-C/D1의 동일 geometry `Arc`에서 glyph bbox, run/line bbox, next inline/column origin을 읽는다.
line owner와 문자별 `TextRun` fallback, page-local vertical sidecar를 전부 메모리에서 준비한 뒤
`commit_bounded_vertical_hwp5_table_cell` 한 곳에서만 frame ID와 sidecar, cell children을 게시한다.
실패하면 이 commit을 호출하지 않거나 sidecar validation 전에 멈춰 기존 문자별 legacy 루프를 그대로 실행한다.

## 1. 구현 계약

1. `LayoutEngine`은 exact registry의 immutable clone으로 D2 vertical context를 만들며 parser나 font name은
   source를 등록하지 않는다.
2. 최초 target은 Noto Sans KR Regular 공개 파일의 SHA-256
   `6e06a7fe5d696ca719894a23f36bb2b1be8c816a5937cd4ad0f23ca67780dd74`와 정확히 일치해야 한다.
3. Q4-C line/bbox/next-origin owner는 pointer identity가 같은 `Arc` 하나다.
4. page sidecar는 node 중복, registry generation, source identity, entry/source/byte 상한을 mutation 전에 검사한다.
5. node ID는 읽기 전용 preview로 overflow를 먼저 검사하고, sidecar attach 성공 뒤에만 한 번 전진한다.
6. D2는 sidecar를 paint에 노출하지 않는다. fallback `TextRun`은 남고 vertical `GlyphRun` 생성은 D3 권위다.
