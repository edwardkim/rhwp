# Task M100 #4969 W10-Q2-D5-R3 — resource qualification 결과

## 판정

Q2-D5-R3는 **qualified**다. R1의 unique-source 준비와 R2의 opt-in font-by-key transport는 D4의 공개 오라클,
native/WASM, Studio selector와 실제 CanvasKit draw에서 같은 glyph geometry와 pixel을 냈다. `1/2/8 run`의
digest·face parse·arena intern은 각각 1회, `1/2/8 page`의 by-key fetch와 retained font는 각각 1회분으로
고정됐다. default inline 계약과 NO_LS boundary는 바뀌지 않았다.

기계 판독 결과는
[`w10_q2_d5_r3_resource_qualification.json`](../../tech/investigations/issue-4969/w10_q2_d5_r3_resource_qualification.json)에
고정한다. 이 판정은 다음 절편 N0을 자동으로 열지 않는다.

## 입력과 재사용 범위

- 공개 fixture `ttfs/opensource/SourceHanSerifK-OldHangul-subset.otf` 456,688B만 사용했다.
- D4-C의 실제 CanvasKit 오라클과 R1·R2의 승인된 `1/2/8` counter matrix를 재사용했다. 제품 checkpoint가
  바뀌지 않은 동일 항목을 전수 재계측하지 않았다.
- private corpus, host 설치 font, Hyper-V, 한컴 Oracle은 사용하지 않았다.
- 진단 중 in-memory fixture를 HWP5로 내보냈다가 다시 읽은 경로는 exact font registry가 직렬화 대상이 아니어서
  resource key를 보존하지 않았다. 이는 fixture 변환 문제이며 제품 증거에서 제외했다. 최종 native 계측은 D4와
  같은 in-memory public `DocumentCore` fixture에서 수행했다.

## 구조적 회계

| 축 | 1 | 2 | 8 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 같은 page의 run 수 | digest 1 / face parse 1 / arena intern 1 | 1 / 1 / 1 | 1 / 1 / 1 | unique source 귀속 |
| page 수 | fetch 1 / 456,688B | fetch 1 / 456,688B | fetch 1 / 456,688B | page 수 비례 제거 |
| default inline raw 합계 | 456,688B | 913,376B | 3,653,504B | 기존 계약 유지 |
| opt-in inline font payload | 0B | 0B | 0B | metadata만 page에 유지 |

실제 CanvasKit cache는 generation 7에서 blob 1, typeface 1, font 1, bytes 456,688을 보존했다. generation 8의
missing resolver를 받은 뒤에는 네 값이 모두 0이 됐고, 이후 과거 generation 7 응답은 cache를 다시 채우지 못했다.

## inline·by-key cross-backend parity

native가 만든 두 JSON은 `root`와 `fontResources`가 exact-equal이며 `resources.fontBlobs` payload만 다르다.
일반 크기의 공개 진단 run에서 두 경로는 다음 값을 공유했다.

- glyph IDs: `614, 864, 1479, 1674`
- x positions: `0, 11.520222, 23.040444, 23.040444`
- x advances: `11.520222, 11.520222, 0, 0`
- cluster glyph ranges: `[0,1]`, `[1,4]`
- 실제 CanvasKit ink: `20×12px`, `(14,70)~(33,81)`
- inline/by-key software surface pixels: byte-identical

이 소형 진단 run은 transport parity를 보기 위한 것이다. D4-C의 크기 40 공개 오라클은 별도로 glyph IDs
`614, 1230, 1497, 2085`, page advance `61.824px`, current ink `58×34px`를 유지했다. 두 fixture의 glyph ID를
서로 바꿔 읽지 않는다.

생성 WASM의 `getSourceFontBytes`도 canonical resource key에서 exact 456,688B를 반환했고 선언 길이를 1B 바꾼
key는 거부했다. cache miss·wrong·oversized·stale·partial batch에서는 R2 fail-closed matrix대로 verified mutation
0과 TextRun fallback을 유지한다.

## 성능과 크기

release native probe는 20회 warmup 뒤 warm·직렬화·query를 200회×9그룹의 중앙값, cold를 25회 중앙값으로
측정했다. wall time은 환경 의존 참고값이며 합격선으로 사용하지 않는다. 구조적 counter가 판정 권위다.

| 항목 | inline 또는 D4 기준 | by-key/R3 | 변화 |
| --- | ---: | ---: | ---: |
| warm layer build | D4 703.600µs | 609.270µs | -13.41% |
| cold layer build | D4 2.314ms | 2.230ms | -3.65% |
| layer JSON | 619,562B | 10,640B | -608,922B, -98.28% |
| serialization | 473.585µs | 247.468µs | -47.75% |
| warm cached query | 17.194µs | 0.124µs | -99.28% |
| cold query | 3.118ms | 2.481ms | -20.44% |

R3 inline JSON이 D4 active 기준과 동일한 619,562B인 점은 default inline 출력이 크기 수준에서도 유지됐음을
보인다. by-key cache가 보존하는 font bytes 456,688B는 unique source 한 벌이며 page 증가에 따라 늘지 않는다.

R3 재검증에서 renderer 계약 정규식이 구형 `registerResources(fontResources, resources)` 2인자 호출만 허용해
처음 실패했다. 실제 제품 순서는 `currentFontResources` 지정 → key resolver와 document generation을 포함한 4인자
동기 검증 → text variant 선택으로 안전했다. 제품 코드는 바꾸지 않고 계약 정규식이 이 강화된 순서를 직접
검증하도록 최소 정정했으며 재실행은 통과했다.

task worktree 정책상 generated integration target이 없는 source-only
`issue_4969_shaping_atomic_activation`과 `issue_5821_condensed_ratio_glyph_height`는 여기서 Cargo target을 만들지
않았다. 연속 명령은 등록된 13건을 통과한 뒤 두 번째 missing target에서 exit 101을 반환했으나 이는 제품 test
실패가 아니다. D4 review worktree의 기존 통과 증거를 재사용하며 generated suite·manifest·Cargo marker는
변경하지 않는다.

checkpoint 직전 `cargo fmt --all`도 같은 32개 generated suite source 부재로 진입 전에 종료됐다. R3에는 Rust
source 변경이 없고 명령 전후 변경 목록도 동일했다. task worktree에서 `--prepare`하지 않는 정책을 지키며,
push/PR 후보는 별도 review worktree에서 suite를 준비한 뒤 `cargo fmt --all`과 `cargo fmt --all -- --check`를
반드시 다시 통과시킨다.

## 보호 불변식

1. full-font digest·face 준비는 run 수가 아니라 unique exact source 수에 귀속한다.
2. opt-in by-key는 bytes만 생략하며 root·glyph geometry·font identity metadata를 바꾸지 않는다.
3. default inline JSON과 기존 API 동작은 그대로다.
4. resource key·digest·length·상한·generation 검증 전에는 consumer cache를 변경하지 않는다.
5. generation 변경과 partial batch 실패는 blob·typeface·font를 부분 게시하지 않는다.
6. missing resource에서 strict GlyphRun을 선택하지 않고 TextRun fallback을 남긴다.
7. R3는 line selection·bbox·next origin·sidecar owner를 바꾸지 않는다.
