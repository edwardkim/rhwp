## 결론

Q4-A는 Noto Sans KR TTF와 Source Han Serif K OTF의 top-to-bottom 결과를 glyph id, UTF-8
cluster, x/y advance, x/y offset의 exact vector로 고정했다. native와 Node WASM이 같은
font bytes·rustybuzz 0.20.1·ttf-parser 0.25.1에서 같은 결과를 냈다.

이 결과는 vertical table의 존재만 확인하던 Q1 capability test와 다르다. 이제 특정
source·direction·writing mode·script·language·feature 요청의 exact vertical output이 바뀌면
테스트가 즉시 실패한다. 다만 아직 문서 의도·column progression·bbox·hit-test와 연결하지
않았으므로 product vertical shaping을 지원한다고 판정하지 않는다.

## exact oracle

### Noto Sans KR

- `한글`, `Hang/ko`, TTB·vertical-rl: glyph 11232/1156, cluster 0/3, 두 glyph 모두
  `(xAdvance=0, yAdvance=-1000, xOffset=-460, yOffset=-880)`.
- `AB`, `Latn/en`: glyph 34/35, y advance -1000, x offset -304/-328, y offset -880.
- vertical-lr는 vertical-rl과 glyph·position이 같지만 settings identity는 다르다. RL/LR column
  progression은 shaper가 아니라 Q4-C layout owner의 책임으로 남겨 둔다.

### `vert`·`vrt2` fixture

Noto Sans KR이 실제로 coverage하는 U+2014·U+2026만 선택했다. 처음 선택한
전각 괄호·낫표는 이 파일의 cmap에 없어 glyph 0이었으므로 oracle 후보에서 제외했다.

- default와 explicit `vert=1,vrt2=1`은 이 fixture에서 glyph 197/11826으로 같다.
- explicit `vert=0,vrt2=0`은 glyph 197/206이다.
- 따라서 U+2026의 default vertical substitution은 고정되지만, 이 한 fixture를 모든 script·font·
  punctuation의 전역 feature 정책으로 일반화하지 않는다.

### Source Han Serif K Old Hangul

`ᄒᆞᆫ글`(U+1112 U+119E U+11AB U+AE00), `Hang/ko`, TTB·vertical-rl은 glyph
614/1230/1497/2085를 사용한다. 앞의 두 glyph은 y advance -1000·offset (-483,-880),
뒤의 두 mark glyph은 y advance 0·offset (483,120)이다. `VORG`를 가진 exact CFF OTF의
결과를 그대로 고정했으며, 각 offset을 VORG 단일 table의 효과로 과장해 해석하지 않는다.

초기 probe에서 U+119E 아래아 대신 U+11A1을 입력한 오류를 diff 감사로 발견했다.
해당 결과는 채택하지 않고 Q1의 기존 공개 문구와 같은 U+119E로 재계측해 glyph 614를
최종 oracle로 고정했다.
