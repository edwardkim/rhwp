# 처리 결과 — 에이전트 노동 운영체제 (#4720)

## 무엇을 / 왜

rhwp 에는 에이전트가 일할 재료(12 pack·검증 사다리·AWS 표준·리더보드·로드맵 트랙)가
다 있지만 **하나의 운영 체계로 묶여 있지 않았다**. 사용자 지시: "부서를 만들고,
큰 기업의 시스템이 스스로 굴러가듯 시스템이 자동으로 에이전트에게 일을 시키게."

## 산출물 — 틀

| 파일 | 역할 |
|---|---|
| `mydocs/tech/agent_org/departments.json` | 기계 판독 조직표 — 8부서 → 사명·소유 pack·트랙·입사 과제·직급 |
| `intake_manifest.schema.json` | 접수 이력서 형식(에이전트가 제출하는 구조화 이력서) |
| `tools/agent_dispatch.py` | **자동 배치기** — 이력서 읽어 부서·과제·영수증 요건·승진 경로 산출 |
| `agent_org/README.md` | 운영체제 정본 + 조직도(mermaid+PNG) + 접수법 |
| `scripts/tests/test_agent_org.py` | 정합 가드 — 부서가 실재 자산에 매핑·배치기 유효 |

## 자동으로 도는 흐름

접수(이력서) → `agent_dispatch.py` 자동 배치 → 부서 입사 과제(gym) → AW-L1 영수증
(`replay --capsule`) → 인사부 자동 승진(검증된 산출로만) → 다음 직급 기준 제시.
**사람이 배정표를 만들지 않는다.**

## 부서 ↔ 실재 자산

접수처(casual-rides)·편집부(text·table·objects·core-cli)·판독부(serial·layout·corpus)·
검증부(automation·expert-challenges)·보안부(security)·표준부(self-description)·
인사부(leaderboard.py 서비스)·운영부(release_gate.py 서비스). 트랙 A~L 매핑.

## 직급 — 검증된 산출로 자동 판정

지원자 → 신입(AW-L1 영수증) → 사원(AW-L2 계보) → 선임(AW-L3 서명) → 책임(AW-L4 앵커)
→ 수석(AW-L5 정산·감사). 승진은 신고가 아니라 검증 사다리 산출이 판정한다.

## 검증 (실측)

```
조직 계약 테스트:  7 passed, 8 subtests — 부서 매핑·배치기·접수 스키마 정합
자동 배치기 실행:  편집부→TE01·미지정→접수처 CR01·검증부→AU01, 승진 경로 정확
CI 배선:           "Validate agent org contract" 스텝
```

## 합법성·투명성 (트랙 L 헌법 승계)

- **은유이지 강제가 아니다** — 부서·직급·배치는 열린 일감으로 가는 길의 자동화(자기
  서비스 라우팅). 조직을 안 거쳐도 rhwp 는 동작한다.
- **일감은 실재** — 배정 과제는 gym 에 실재, 승진은 검증된 산출로만. 아무 진실도
  지어내지 않는다. 가드가 부서-자산 매핑을 상시 검증한다.
- **방법론 조직, 인물 조직 아님** — 준거는 검증 사다리·재현 가능성이지 특정 기여자가
  아니다.

연동은 후속 PR. 이 PR 은 틀(부서표·접수·배치기·직급·가드·조직도)을 세운다.
