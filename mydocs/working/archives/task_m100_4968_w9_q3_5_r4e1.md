## 3. 실제 parity 결과

네이티브와 WASM은 각 상태에서 공개 제품 경로를 모두 실행했다.

- page render tree
- page layer tree
- SVG renderer
- Canvas command builder
- CanvasKit replay plan

projection 비교뿐 아니라 raw render tree·layer tree·CanvasKit plan도 target pointer-width sentinel 정규화 후
canonical digest가 같은지 별도로 확인했다. 이번 fixture에는 sentinel 출현이 없어서 실제 정규화 count는 0이며,
단위 검사에서는 native64/WASM32 sentinel 차이만 허용되고 positions 차이는 거부됨을 고정했다.

| 상태 | layer-tree SHA-256 | SVG bytes | SVG SHA-256 |
|---|---|---:|---|
| K0 등록 전 | `9caf860b87f4…0c78ce` | 109,960 | `2c3feb6f71bf…e9c981` |
| K1 등록 후 | `203f216fab3d…e13db` | 109,909 | `7500c91d0cea…c4d46` |

각 행의 canonical projection은 context, char shape, language, lane, ratio, spacing, kerning request,
manifest paragraph reference, measurement total, line start/boundary, 최종 positions와 bbox width만 가진다.
등록 증적은 public font SHA·bytes·face index, slot과 최종 registry count만 남긴다. text, font bytes payload,
source path, source document hash, file name, absolute path, private identity는 넣지 않았다.

## 4. 보호 불변식 판정

1. **K0 보존**: exact source 등록이 kerning-off 11개 행의 measurement·line·positions·bbox를 바꾸지 않았다.
2. **K1 실효성**: kerning 요청 11개 행 모두 등록 후 positions가 변했다. 하니스가 단순 API 성공만 검사하지 않는다.
3. **target parity**: native와 WASM의 22행, SVG bytes/hash, Canvas command count, replay plan이 일치했다.
4. **backend owner**: CanvasKit은 direct replay required이고 hidden Canvas2D overlay 위반이 0이다.
5. **context 폐쇄성**: body뿐 아니라 table-cell과 text-box도 같은 exact slot·배치 계약을 통과했다.
6. **page 안정성**: 등록 전후 모두 1 page이며 배치 효과를 page-count drift로 숨기지 않았다.
7. **공개·비식별 증적**: 기존 공개 synthetic fixture만 사용했으며 private corpus 식별자를 기록하지 않았다.

CanvasKit public replay plan에는 glyph positions 배열 자체가 없으므로 존재하지 않는 값을 합성하지 않았다.
대신 layer owner positions의 native/WASM identity와 Canvas/CanvasKit replay disposition을 독립적으로 검증했다.
R4D의 공통 PaintOp positions 재생 증거와 결합하면 backend가 자체 shaping으로 결과를 맞춘 것이 아님을 보인다.
