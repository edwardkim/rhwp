## 1. 확정 증거 재사용

W3 final aggregate와 10,000-entry checkpoint journal을 hash·checkpoint identity로 대사했다. corpus 원본을
열거나 parse하지 않고 journal을 한 번 streaming해 kerning flag가 true인 문서만 선택했다.

| 항목 | 결과 |
| --- | ---: |
| kerning 문서 | 157: HWP 115 + HWPX 42 |
| kerning 문자 | 175,466: HWP 160,041 + HWPX 15,425 |
| 문서별 usage row | 2,318 |
| final aggregate dimension row | 1,723 |
| stored LineSeg | 173,469자, distinct 154문서 |
| fresh lane | 1,997자, distinct 4문서 |
| corpus source file open | 0 |

stored와 fresh를 모두 포함한 문서가 하나 있으므로 lane별 distinct 문서 수 154+4를 전체 문서 수로 합산하지
않는다. stored/fresh 결과도 이후 영향 판정에서 별도로 유지한다.

문맥은 table-cell 86,610자, body 83,367자, footnote 2,036자, text-box 1,778자, caption 1,436자 순이다.
가장 큰 장평·자간 조합은 100/0 114,403자, 95/-5 10,618자, 100/-10 8,000자다. 이는 kerning을 일반적인
본문 영문 장식으로만 다룰 수 없고 HWP 사용자의 압축 조판과 fixed context를 함께 판정해야 함을 보여준다.

## 2. journal과 final aggregate 대사

projector는 journal의 document-level row에 상위 record의 format을 명시적으로 결합한 뒤 count를 다시
집계한다. 그 결과 2,318개 문서별 row가 final aggregate의 1,723개 dimension row와 다음 전항에서 일치했다.

- dimension key 전건 일치
- distinct `documentCount` 일치
- `paragraphCount`, `runCount`, `charCount` 합계 일치
- checkpoint entry 10,000, complete 9,909 일치
- aggregate SHA-256
  `378671053ae94c02cda4caf8b8a4a1ac7866c3711fdf72c14aa527f8d9bc2888`
- checkpoint chain
  `94d9bbe3cce4218728ff29def8ab24abb51ffc434ec395d8be663fdab6b03649`

최초 실행에서는 format이 journal record 상위, final row 내부에 있다는 schema 차이를 projector가 반영하지
못해 fail-closed 중단됐다. 출력은 생성되지 않았고, format을 journal dimension에 명시적으로 결합한 뒤 계약
테스트와 실제 실행을 다시 통과했다. 오류 메시지도 row 전체 대신 count와 digest만 남기도록 정정했다.
