# Task M100 #4969 W10-Q2-D5-N2 — 최종 cross-backend·성능 판정

## 판정

Q2-D5-N2 결과는 **qualified-bounded**다. ordinary single-interval NO_LS 문단의 원자 activation은 native,
Node WASM, 실제 CanvasKit draw에서 같은 common GlyphRun을 게시했고 Canvas2D·legacy SVG·Native Skia의 미지원
경로는 TextRun fallback을 유지했다. 전체 integration 8,562건과 native-skia 전체 library, Studio 전체 검증에서
회귀는 없었다.

지원 범위는 넓히지 않는다. multi-interval, 일반 edit reflow, stored prefix, split cell, inline control,
center/right/justify/distribute, RTL·vertical·variation과 Native Skia portable blob replay는 계속 제외한다. 기계 판독
결과는
[`w10_q2_d5_n2_final_qualification.json`](../../tech/investigations/issue-4969/w10_q2_d5_n2_final_qualification.json)에
고정한다. N2는 D5를 닫지만 Q2 전체의 최종 support classification은 수정 수행계획에 따라 별도 다음 승인
단계에서 확정한다.

## 재사용한 증거와 새로 측정한 범위

- R3의 `1/2/8 run × 1/2/8 page` 구조 counter는 resource 구현이 바뀌지 않았으므로 재사용했다. digest·face
  preparation과 by-key fetch가 unique source 1개에 귀속한다는 전건을 다시 계측하지 않았다.
- D4-C의 실제 CanvasKit 기준선인 page advance `61.824px`, current ink `58×34px`, 이전 잘못된 계약
  `58×38px`를 재사용하고 N2 Studio E2E에서 다시 확인했다.
- N1이 새로 연 NO_LS 제품 positive·negative, 최종 Docker WASM, CanvasKit selector/draw, fallback backend,
  native-skia와 전체 integration은 최종 소스에서 새로 실행했다.
- private corpus, host 설치 font, Hyper-V와 한컴 Oracle은 사용하지 않았다. 공개 456,688B Source Han subset만
  사용했다.

## backend 판정

| backend | strict common GlyphRun | fallback | 결과 |
| --- | --- | --- | --- |
| Native/Node WASM layer producer | 조건 충족 시 1 | TextRun 1 유지 | parity |
| CanvasKit | exact font resource 검증 뒤 선택·draw | 검증 실패 시 TextRun | `58×34`, pass |
| Canvas2D·legacy SVG | 선택하지 않음 | TextRun | pass |
| Native Skia | portable blob replay는 미지원 | TextRun | 15 focused + full lib pass |

CanvasKit cache는 blob 1, typeface 1, font 2, retained bytes 456,688을 보고했다. unsupported selector와
strict eligibility가 거부된 입력은 GlyphRun을 선택하지 않았다. 따라서 backend가 capability를 갖지 못한 경우에도
빈 출력이나 부분 glyph가 아니라 기존 TextRun으로 닫힌다.

## NO_LS 성능과 resource 회계

release probe는 20회 warmup 뒤 200회×9그룹의 그룹 평균 중앙값과 cold 25회 중앙값을 측정했다. wall time은
환경 의존 참고값이며 합격선이 아니다. 구조적 counter와 원자 rollback이 판정 권위다.

| 항목 | N1 active NO_LS | exact source 없는 legacy NO_LS | 차이 |
| --- | ---: | ---: | ---: |
| warm layer build | 612.521µs | 0.939µs | +611.582µs |
| cold layer build | 2,296.597µs | 18.033µs | +2,278.564µs |
| inline serialization | 495.470µs | 30.534µs | +464.936µs |
| by-key serialization | 257.070µs | 해당 없음 | inline 대비 -238.400µs |
| inline JSON | 619,562B | 6,849B | +612,713B |
| by-key JSON | 10,640B | 해당 없음 | active inline 대비 -608,922B |

legacy 대조는 shaping과 portable font를 전혀 쓰지 않는 fail-closed 경로이므로 “N1만의 증분”이 아니라 기능 전체
비용의 참고 상한이다. N1 boundary activation 자체를 분리하는 더 가까운 기준은 R3 stored-LineSeg active
609.270µs다. N1 warm은 +3.251µs(+0.53%)이고, D4 703.600µs 기준보다는 91.079µs(-12.94%)다. cold는 D4
2,314.000µs보다 17.403µs(-0.75%) 낮다. 이 역사 비교도 동일 하드웨어의 참고값이며 구조 gate를 대신하지 않는다.

N1 active 한 page의 구조 결과는 TextRun 1, common GlyphRun 1, nominal duplicate 0, font blob 1, face 1이다.
legacy 대조는 TextRun 1, common GlyphRun·font resource 0이다. R3의 1/2/8 matrix대로 같은 source의 digest·face
preparation은 1회, by-key 전달은 문서 generation당 1회로 유지된다.

## N2에서 발견해 닫은 계보 누락

N2 전건 검증은 N1 runtime 회귀가 아니라 이전 R1·R2 변경이 드물게 빌드되는 소비자까지 전달되지 않은 세 곳을
찾았다.

1. W9 integration source는 `kerning` module을 독립 override하는데 registry가 `crate::paint`를 역참조해 compile
   경계가 깨졌다. resource key parsing·digest 검증은 제품 caller인 `layout`에 두고 registry는 byte length와
   caller predicate로 source를 찾도록 의존 방향을 바로잡았다.
2. #3315 image-by-key 회귀 fixture의 `LayerJsonOptions` literal에 R2의 `omit_font_bytes`가 누락됐다. 기존 의미를
   보존하는 `false`를 명시했고 7건이 통과했다.
3. image audit 예제 3개가 R2의 네 번째 WASM 인수를 전달하지 않았다. 기존 inline-font 동작인 `Some(false)`를
   명시했고 all-target Clippy가 통과했다.

target 수를 늘리거나 module override를 제거해 우회하지 않았다. 원래 48-target 예산을 유지했고, 각 정정은 기존
소비자의 의미를 그대로 명시한다.

## 보호 불변식

1. line selection·TextRun bbox·next origin·common GlyphRun은 같은 measurement `Arc`에서 원자 게시한다.
2. 어떤 준비나 backend capability가 실패해도 네 값을 부분 게시하지 않고 pristine W9/K0 TextRun으로 닫는다.
3. full-font 준비·page resource·by-key fetch는 run/page 수가 아니라 unique exact source와 document generation에
   귀속한다.
4. TextRun fallback은 strict GlyphRun과 함께 남고 nominal GlyphRun은 중복 게시하지 않는다.
5. default inline 계약은 유지하며 by-key는 payload만 생략한다.
6. raw text·font bytes·host path·private corpus identity를 trace에 기록하지 않는다.
