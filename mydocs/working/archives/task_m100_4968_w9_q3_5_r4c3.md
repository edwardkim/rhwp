## 1. 결론

R4C-2의 owned paragraph position과 boundary-safe pair adjustment를 실제 fresh line-breaking에
연결했다. 한 pagination/edit transaction은 exact source generation과 문단 측정 cache를 하나만 소유하고,
`HeightMeasurer`, `TypesetEngine`, page-tree `LayoutEngine`, 편집 reflow가 같은
`ResolvedStyleSet`의 context를 읽는다.

`BreakToken::Text`는 기존 scalar pen과 paragraph-position token total을 분리해 보존한다. 동적 tab/space,
공백 압축, 자간 fit의 기존 소유권은 scalar pen에 남기고, token fit과 긴 단어의 각 문자 후보마다 현재 줄
substring의 boundary-safe pair delta만 더한다. 따라서 경계를 가로지른 pair는 다음 줄로 유출되지 않는다.

boundary 재측정의 256회 예산이나 범위 검증이 실패하면 이미 carve한 frame을 되돌리고 문단 전체를 K0로
처음부터 다시 실행한다. specialized edit reflow도 같은 실패를 감지해 suffix 일부만 K1로 게시하지 않고
동일 입력의 K0 fill로 재실행한다.

## 2. 공통 소유권

### 2.1 exact source payload 한 번 소유

`ExactFontSourceRegistry`의 face bytes를 `Arc<[u8]>`로 바꾸고 registry clone은 slot/handle table과 byte owner만
공유하게 했다. 폰트 bytes를 pagination engine 수만큼 복제하지 않는다. Debug 출력은 payload 대신 slot 수,
face 수, 총 byte 수, generation만 기록한다.

`DocumentCore::paginate_pass`가 현재 `LayoutEngine` registry를 immutable
`KerningMeasurementContext` snapshot으로 만들고 `ResolvedStyleSet`에 싣는다. `ResolvedStyleSet`은 기존 세 엔진과
편집 명령이 이미 함께 전달받는 객체이므로 별도의 전역 상태나 thread-local 없이 네 경로가 같은 generation을
읽는다.

batch mode에서 pagination이 지연되어도 등록 직후 edit reflow가 낡은 snapshot을 읽지 않도록 native exact
source 등록과 embedded source rebuild 시점에도 context를 즉시 갱신한다.

### 2.2 owned paragraph measurement cache

context는 다음 전체 입력을 cache key로 사용한다.

- 문단 text
- 기존 scalar `N+1` base position의 bit pattern
- scalar별 exact slot, kerning request, effective size, 장평 bit pattern
- inline control hard boundary

hash만 같다고 재사용하지 않고 key 전체가 같아야 한다. cache와 원문은 transaction 메모리에만 있고 trace나
직렬화에는 들어가지 않는다. 기존 R4C의 4,096 scalar 상한도 그대로 적용된다.

## 3. line-breaking 배선

### 3.1 K0와 K1 token 값의 분리

`BreakToken::Text`는 다음 두 값을 함께 가진다.

- `base_width`, `base_char_widths`: 기존 K0 scalar pen과 fallback
- `width`, `char_widths`: 같은 owned paragraph positions의 token/character range

K0에서는 둘이 동일하다. exact source나 kerning request가 없으면 context 준비 자체를 하지 않고 기존 scalar
경로로 바로 간다.

### 3.2 실제 fit과 긴 단어

line pen은 기존 tab 위치, 공백 폭, condense, trailing letter-spacing 규칙을 유지한다. 후보를 fit할 때만 현재
`line_start..candidate_end` substring의 `boundary_pair_adjustment`를 더한다. 긴 Latin token도 글자 하나씩 같은
boundary-safe substring을 질의한다. 이전 break 뒤 폭 재계산은 K0 base pen으로 수행하고 다음 fit에서 새 줄
경계의 pair delta를 다시 묻는다.

### 3.3 원자적 rollback

frame path는 최초 frame checkpoint를 보존한다. boundary session이 실패하면 부분 row를 모두 버리고
kerning을 끈 동일 문단 frame을 재실행한다. cell split, prefix-preserving cell edit, inline-control specialized
reflow는 공통 fill에 같은 session을 넘기고 실패 시 전체 suffix를 K0로 다시 채운 뒤에만 `LineSeg`를 게시한다.

## 4. 제품 회귀 검증

기존 `tests/cases/issue_4968_kerning_capability_provider.rs`만 확장했다. 새 integration source, generated suite,
manifest, Cargo target은 제출하지 않는다.

### 4.1 편집 reflow

공개 `RHWPExactKerningSmoke.ttf`와 `AV` 반복 문단을 사용했다. 제한된 본문 폭 사다리에서 exact source가 없는
K0와 등록된 K1의 저장 `LineSeg.text_start`가 실제로 달라지는 임계값을 찾고, 같은 exact generation을 다시
실행했을 때 경계가 완전히 같음을 확인했다.

### 4.2 fresh pagination과 page tree

저장 `LineSeg`가 없는 같은 공개 문단을 pagination/page-tree 경로로 보냈다. K0와 K1의 `TextRun` 길이 사다리가
달라졌고 같은 K1 입력의 반복 page-tree가 동일했다. 이 검증은 registration 후 pagination, typeset fit,
page-tree fresh recomposition이 같은 context를 소비하는 공개 제품 경로를 지난다.

첫 fixture는 고정 9,000 HWPUNIT 폭에서 K0/K1이 모두 8자씩 접혀 차이를 노출하지 못했다. 특정 폰트 advance를
하드코딩하지 않고 7,000..13,000 HWPUNIT의 bounded 100-unit 사다리로 바꿨다. fresh 검증의 첫 버전은 첫
페이지만 집계해 K0 `13×6`, K1 `11×7`의 서로 다른 pagination을 텍스트 소실로 오인했다. 모든 page-tree를
조회하고 최종 판정을 경계 차이와 반복 결정성으로 고쳤다.
