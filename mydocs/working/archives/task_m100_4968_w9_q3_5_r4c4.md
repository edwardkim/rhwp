## 1. 결론

R4C-4에서 fresh 본문뿐 아니라 표 셀과 글상자도 같은 exact kerning measurement를 소비하는지 공개 제품
경로로 다시 검증했다. 이 검증이 R4C-3의 실제 누락을 잡았다. 표 셀은 K0/K1 줄 경계가 달랐지만, 저장
`LineSeg`가 없는 가로 글상자는 `compose_paragraph`의 45자 fallback을 그대로 사용해 exact source를 등록해도
K0/K1 경계가 같았다.

가로 글상자의 NO_LS 문단만 본문·표 셀과 같은 fresh frame reflow로 보냈다. 유효한 stored `LineSeg`가 있는
글상자는 기존 feature-detection 경로를 그대로 유지한다. 공개 small exact face의 bounded width ladder에서
표 셀·글상자 모두 K0/K1 경계 차이와 K1 반복 결정성을 확인했다.

한컴 PDF 오라클과 실제 샘플을 교차검증한 결과, 대상 글상자 내부 그림의 가로 위치·크기는 사실상 같고 앞 문단
기준 상대 간격도 유지됐다. 다만 이 샘플의 글상자 텍스트는 공백 5자뿐이고 보이는 내용은 inline image 2개라서,
오라클은 **실문서 글상자 배치 비회귀**를 검증하지만 새 문자 kerning 줄 경계를 직접 판정하지는 않는다. 그
경계는 공개 synthetic integration test가 담당한다.

### 1.1 용어와 표기 정의

이 보고서의 `K0`와 `K1`은 rhwp #4968 조사·구현에서 사용한 **로컬 시험 표기**이며 OpenType, HWPX 또는
한컴의 공식 용어가 아니다. `K` 뒤의 문자는 알파벳 `O`가 아니라 숫자 `0` 또는 `1`이다.

- **K0 (K-zero, 커닝 비활성 기준)**: HWPX `useKerning=false`에 대응하며, exact font source 조회·SFNT
  parse·shaping·pair adjustment를 수행하지 않고 기존 rhwp scalar positions를 그대로 사용하는 호환성 기준
  경로다. K1 실행 조건이나 상한 검증이 실패해 fail-closed할 때도 문단 전체가 이 경로로 되돌아간다.
- **K1 (K-one, 커닝 활성 후보)**: HWPX `useKerning=true` 요청과 정확한 font source가 모두 존재하고,
  OpenType capability 기능 탐지와 구조·수치 검증을 통과했을 때만 glyph pair adjustment를 적용하는 경로다.
  단순히 flag가 켜졌다는 이유만으로 K1 결과를 강제하지 않으며, 안전 조건을 충족하지 못하면 K0가 된다.
- **exact font source**: family 이름으로 다시 검색한 대체 폰트가 아니라 `(char_shape_id, language_index)` slot에
  확정 등록된 font bytes와 face index다. 이 보고서의 K1은 이 source가 확인된 경우에만 성립한다.
- **K0 native/WASM identity**: 통제된 K0 입력 9건에 대해 native와 WASM의 정규화 layer tree가 같고 SVG가
  byte-for-byte 같다는 판정이다. 모든 플랫폼 실행 파일이나 WASM binary 자체가 동일하다는 뜻은 아니다.
- **canonical SHA-256**: 위 정규화 결과 envelope을 canonical JSON으로 직렬화해 계산한 결과 식별자다.
  `pkg/rhwp_bg.wasm` 파일의 SHA-256과는 서로 다른 값이며 서로 대체할 수 없다.

## 2. R4C-3 누락과 정정

### 2.1 실패가 먼저 증명한 것

기존 `tests/cases/issue_4968_kerning_capability_provider.rs`에 새 source를 만들지 않고 다음 공개 경로 검사를
추가했다.

1. blank document에 kerning request가 켜진 `AV` 반복 문단을 만든다.
2. 같은 문단을 1×1 표 셀과 가로 글상자에 각각 넣는다.
3. 7,000..13,000 HWPUNIT의 100-unit width ladder에서 K0와 exact-source K1 줄 경계를 비교한다.
4. 차이가 드러난 첫 폭에서 K1을 다시 실행해 결정성을 확인한다.

초기 실행에서 표 셀은 통과하고 글상자만 실패했다. 따라서 “네 소비 경로가 모두 연결됐다”는 R4C-3 판정을
R4C-4에서 그대로 재사용하지 않고 실제 container별 공개 출력으로 재검증한 것이 유효했다.

### 2.2 원인

`LayoutEngine::layout_shape_control`의 가로 글상자 경로는 `Paragraph.line_segs.is_empty()`여도
`compose_paragraph` 결과를 직접 사용했다. 이 fallback은 본문 폭이나 `KerningMeasurementContext`를 소비하지
않는 45자 고정 줄이므로 exact registry 등록이 글상자 줄 경계까지 도달하지 않았다.

### 2.3 정정 경계

- stored `LineSeg`가 있으면 기존 composed paragraph를 그대로 사용한다.
- NO_LS 가로 글상자만 실제 inner width와 paragraph margin으로 `ParagraphBox`를 만든다.
- `recompose_stored_lines_in_frame(..., StoredRowMissPolicy::Reflow)`를 사용해 본문·표와 같은 fresh
  measurement context를 소비한다.
- inner width가 0이거나 재조판이 실패하면 기존 composed 결과로 fail-closed한다.
- 세로 글상자와 backend glyph replay는 이번 절편에서 바꾸지 않는다.

최초 R4C-4 HEAD의 WASM 순증분 432 bytes 판정은 4.4의 동일 기준선 비교로 보존한다. 이 절의 수치는 이후
upstream 변경까지 포함한 최종 제출 후보의 현재 산출물이며, 두 수치를 섞어 R4C-4 단독 영향도로 해석하지 않는다.

### 7.4 재판정

최신 devel의 layout·table layout 변경과 신규 회귀 4건을 합친 뒤에도 R4C 보호 불변식과 제품 경로는 모두
통과했다. 따라서 병합으로 R4C-4 수정 방향을 바꿀 근거는 발견되지 않았다. merge commit과 이 보고서 갱신은
로컬에만 있으며 remote push·PR·comment는 수행하지 않았다.
