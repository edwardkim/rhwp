# #7642 독립 글꼴 대조와 재조판 행의 물리 최소 보정

Issue: #7642. 계획은
[재조판 행과 걸침 칸의 물리 최소](../plans/task_m100_7642_reflow_rowspan_physical_minimum_20261017.md)다.

## 실제 확인한 증거

같은 독립 PDF의 휴먼명조를 Linux HMKMM.TTF와 대조했다. 관측한153개
문자의 윤곽·전진 폭은 모두 같았다. HY신명조는 시스템 조회에서 실제 face가
아닌 Noto Sans로 대체됐다. Windows win10-ted의 공식 설치 경로
C:\Windows\Fonts\H2MJSM.TTF를 읽기 전용으로 복사해 로컬 ignored output에
보존했다. 5,410,040바이트이며 SHA-256은
f78f538885b29f956cf84286e430898462d11430604625857ad587c0ea73925b다.
PDF에서 관측한30개 문자의 윤곽·전진 폭이 이 설치본과 모두 같았다.
글꼴 파일은 Git에 포함하지 않았으며 시스템 글꼴 설정도 변경하지 않았다.

같은 공급 경로를 적용해 고정 기준9415b920c8과 후보57d4adf2a0의 법령74쪽
Native를 각각 다시 산출했다. 후보25쪽99.99597%,26쪽99.99818%,27쪽100%,
63쪽99.98422%였다. 이전 글꼴 공급의 TSV와 혼합해 기준 하락을 판정하지
않는다. 기준 fresh WASM도 같은 공급 경로로74쪽 산출을 완료했다.
이 공급은 글꼴 예외가 아니며 미달·쪽수·직접 판독 의무를 바꾸지 않는다.

## 43쪽 하락 원인과 수정

Native43쪽은 기준98.39429%에서 후보90.93299%로 낮아졌다. review·독립
overlay를 실제로 열어 사용자에게 함께 표시했다. 아래쪽 병합 라벨과
주요내용이 약14.3px 위로 이동했고 표 하단도 짧았다. 행·글줄·실행 로그를
대조했으며 점수90% 통과로 면제하지 않았다.

12행 원본 최소는7410 HU(98.8px), 본문 두 줄은 정상적으로 모두 소진됐다.
scan은66.8px의 BAND_CUT을 수용했지만 override=None이었다. paint는44.1px로
다시 계산했고, 기존 높이를 그대로 예약한 실제 상자를 소비하지 못했다.
fold 로그에는 접기가 없었다. 다른 열에서 먼저 시작한 rowspan이 있다는
이유로 reflow_row_physical_minimum이 일반 칸의 최소를 배제하는 가정을
제거했다. 일반 칸의 독립 선언·내용 점유를 대조하는 기존 산식을 유지한다.
scan·PageItem·paint·이어받기는 같은 수용 상자와 잔여를 사용한다.

## 검증 상태와 미완료

수정 Rust의 rustfmt·git diff --check는 통과했다. 이번 최소 높이 수정의
Native/fresh WASM·시각 결과는 아직 없다. 현재298211faf7의 Native 빌드는
완료됐고 WASM 및 전쪽 Native 검증이 진행 중이다. 진행 중인 producer와
공용 target을 변경하거나 중단하지 않았다. 이번 수정은 그 다음 빌드에서
검증한다. 전쪽90%·쪽수·직접 판독·기준 대비 하락, 새 이름의 관계 회귀와
조건 충족 쪽의 px 회귀, 전체 Rust/lint/UI, PR·CI·옵션2 후속 처리는 미완료다.
