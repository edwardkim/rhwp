# #7642 Stage 69 — 분할 예산의 중복 차감과 TAC 뒤 재조판 흐름

Issue: #7642

## 범위와 독립 관측

55개·853쪽과 관련 회귀 전체의 목표를 유지한다. Stage 68 source cf08c7316의
Native 빌드·fmt·Native Clippy가 exit 0이며, 같은 source의 6쪽은
79.64273 → 96.88635%로 개선됐다. 다른 쪽을 이 점수로 대신하지 않는다.

한컴 Print 23쪽은 원본 460의 첫 세 줄을 같은 쪽에 두고 24쪽에서 나머지
세 줄을 표시한다. 현재 Native는 두 줄을 23쪽에, 네 줄을 24쪽에 둔다.
앞 두 줄의 텍스트는 Print와 같으므로 이 쪽 경계 차이를 글꼴의 줄바꿈
문제라고 판정하지 않는다. 잔여 예산의 생산·소비 경로를 추적했다.

## 분할 예산의 공통 계약

두 place_split_paragraph 호출 경로는 base_available_height에서 안전 여백을
이미 뺀다. 줄 스캔의 avail_for_lines에서 같은 값을 한 번 더 차감하고 있었다.
새 이름 base_available_after_safety로 그 계약을 명시하고 추가 차감을 제거한다.
HWPX FootnoteArea의 직접 available_height 경로만 같은 여백을 한 번 차감한다.
줄 스캔은 기존 content_h로 실제 줄 점유를 검사하며 후행 간격을 내용 높이로
대신하지 않는다. 조각 끝·높이·다음 시작의 기존 단일 분할 결과를 유지한다.
허용치나 기존 safety 값을 완화하지 않는다.

## TAC 뒤 NO_LS 본문

22쪽 표 441의 원점·높이·위아래 괘선은 Print와 맞지만 뒤 본문 기준선은
약 5.6px 위다. 원본 줄간격 840HU의 절반과 일치한다. 원본 442에는 저장
줄이 없어 후속 vpos에서 누락 간격을 복원할 수 없다. 실제 표/Print 경계와
본문의 기준선을 stage68-page22-tac-heading-geometry.json 및
stage68-page22-print-positions.json에 연결했다. 이 관측값을 고정 보정값으로
사용하지 않는다.

권위 있는 마지막 TAC 줄 → 뒤의 일반 NO_LS 본문인지 판정 → 저장 TAC 계획의
끝과 legacy 높이 reconcile → layout의 같은 확정 끝/후행 간격으로 연결한다.
tac_successor_uses_reflow_spacing을 그 공통 판정으로 사용한다. 마지막 줄이
아니거나 뒤에 저장 원점이 있으면 기존 사다리 연결 판정을 유지한다.
편집·dirty·합성 소유 줄·뒤 개체 owner는 이 저장 원본 계약과 구분한다.
문단에 여러 표가 있다는 이유만으로 같은 줄로 묶지 않는다.
