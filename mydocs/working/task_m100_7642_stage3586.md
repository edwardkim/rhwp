# #7642 원래 굵은 표시 face와 fallback 보완 굵기의 구분

Issue: #7642

## 독립 근거와 관측

PrEP 원본 `samples/issue2006/1790387_prep_final_report.hwpx` 3쪽은 devel보다 Native raw가 0.02964%p 낮았다. source `69ecddfe22`와 실제 devel `6ed1682c32`의 진단 SVG 문자 노드 501개를 대조한 결과, 바뀐 문자 속성은 font-family 사다리뿐이며 좌표·크기·문자열은 같았다. SVG를 Visual Sweep 대신 사용한 것이 아니라 paint 선택의 차이를 좁히는 진단이다.

`8408ca43e2`의 실제 Native Skia 관찰자는 제목의 요청 `HY헤드라인M`을 시스템 `HYHeadLine M`으로 선택했다. 원본 charPr 2에는 bold 속성이 없다. 이 호스트 fontconfig는 같은 프로그램에 regular 요청 시 weight 80, bold 요청 시 weight 200과 `embolden=True`를 보고한다. `TextStyle::is_visually_bold`의 기존 계약은 원 face가 없을 때 fallback의 굵기를 보완하는 목적이다. 그러나 실제 원 face가 설치된 경우에도 그 보완 weight로 같은 프로그램을 다시 굵게 만들고 있었다. `Font::set_embolden(false)`만으로 fontconfig의 가상 weight가 없어지지 않는 근거와 동일 프로그램 재개방 코드는 이미 존재한다.

## 공통 규칙과 반례

원본 `CharShape.bold`가 false이고 요청 자체가 원래 굵은 표시 face일 때, **실제 선택한 프로그램의 SFNT family 레코드**가 원 요청을 소유하는지 확인한다. 대체명 목록에는 HCR Dotum 같은 fallback도 섞여 있으므로 사다리에 있다는 이유로 같은 원 face라고 판정하지 않는다. 같은 프로그램이면 fallback 보완용 합성 굵기만 제거한다. 원본 bold=true, 일반 face, 원 face가 없는 fallback, 실제 bold 프로그램·가변 축·기울임은 기존 계약을 유지한다. 판정은 프로그램 ID와 원 요청별로 캐시한다. 특정 문서·좌표·원 face 이름의 추가 예외는 만들지 않는다.

`text_typeface_candidates → 실제 선택 Typeface → fonts::for_text/finish → 원 프로그램의 Font → 같은 글자 위치의 raster` 경로 중 마지막 폰트 생성에서 적용한다. 측정 전진폭·줄 구성·좌표·WASM/Canvas 출력은 변경하지 않는 Native paint 보정이다. 현재 source에서의 실제 devel 관찰자를 추가 실행해 선택 차이도 확인한다.
