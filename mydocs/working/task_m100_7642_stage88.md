# Stage 88 — 수학 변수 스타일의 공통 전진·표시 계약

## 범위와 독립 근거

Stage 87의 기본 대문자·명시 공백은 독립 대조군에서 개선됐으나 혼합 스타일
확대 영역은 18pt 77.74977%다. 높은 페이지 점수로 완료 판정하지 않는다.
변경 전 source는 `0274190fb`이며 Stage 87의 결과 기록은 `334c3ef64`다.
현재 구현 후보 source는 `b4d47e2554f3de6d2c5f024e7b29fecc0e2f53e9`다.

한컴 2024 Print의 굵은 변수는 일반 이탤릭과 같은 CID를 사용한다.
`Tr=2`로 fill과 stroke를 함께 그리며 획은 0.02em이다. 장평과 글자 전진도
별도 계약을 사용한다. 정체의 기준선은 같은 줄의 이탤릭과 다르다.
`q/Q` 상태를 복원해 읽은 원점·획·장평이 독립 근거이며, 개별 화면 좌표를
회귀 기대값으로 고정하지 않는다.

## 분석·구현·검증 순서

1. 6/9/12/18pt 전체 A~Z·a~z의 정체와 굵은 입력을 각각 한컴 2024에서
   정상 저장한 뒤 Print method 0으로 출력한다. 캐시를 비운 생성 입력과
   정상 저장본을 구분하고 입력·PDF SHA, job, 제품/빌드와 출력 경로를 기록한다.
2. 모든 글자의 전진과 기준선, 굵은 표시의 장평·획을 대조한다. 네 글자만의
   관측에서 모든 알파벳의 규칙을 추정해 구현하지 않는다. 기존 미주 원본과
   NOT·정체/이탤릭·다른 face·그리스 대조군의 적용/비적용을 연결한다.
3. 독립 계약에 맞는 공통 측정·표시 결과를 마련한다. 공개 글꼴 윤곽과 허용된
   메트릭만 사용하며 사설 바이트·윤곽은 포함하지 않는다. 글자 크기·인쇄 단위와
   저장 원문 속성에서 해소하고 문서 ID·절대 화면 px로 보정하지 않는다.
4. 같은 결과를 SVG·Canvas·Skia·paint JSON·실제 CanvasKit이 소비하도록
   실제 호출 경로를 확인한다. 논리 전진과 표시 기하를 별개 경로에서 추정하지 않는다.
5. 후보 한 번의 Native/fresh WASM 빌드 후 대조군·실물 영향 쪽·전체 원본 TSV를
   산출하고 직접 확대 판독한다. 전체 90%와 미세 판독을 충족한 원본의 관련
   회귀를 관계형으로 전환하며 전체 #1139 77개 함수와 기존 91파일 범위를 유지한다.

## 현재 상태

전체 알파벳의 정체·굵은 대조군을 각각 정상 저장하고 Print 출력했다.
공통 변수 표시 후보를 구현했으며 Native의 300dpi 수식 소유 영역 60개는
모두 90% 이상이다. 원본 시험지의 단 이동 결함은 현재 후보에서도 남는다.
fresh WASM은 빌드 중이며 전체 원본 검증·관계형 전환은 미완료다.
이번 단계에서 정식 회귀·기대값을 바꾸지 않았다.

## 공식 저장·Print 대조군 확보

생성했다. 각 크기의 혼합 스타일 대조군도 유지했다. 생성 HWPX의 수식 선언
크기·기준선 캐시를 비웠고 **한컴 정상 저장 HWP**를 비교 입력으로 사용한다.
각 Print PDF는 전체 한 쪽이며, 2024 `13.0.0.3901`, method 0과
`frame_print_to_pdf_ex_one_up`을 실제 status에서 확인했다.

**99.49783%**로 통과했다. 이 결과는 혼합 스타일 미달의 면제 근거가 아니다.

## 공통 후보 적용과 비적용 경로

정체 진단은 85.53311% → 95.74685%, 굵은 진단은 56.33776% →
98.23631%다. 진단 SVG를 실제 렌더러의 검증으로 대신하지 않는다.
정체의 18pt 알파벳 영역 네 줄은 92.72611/94.79448/93.68677/96.95718%다.
혼합 스타일 줄에는 보정 전 굵은 글자가 남아 85.44844%이며, 두 보정을
같은 후보에서 실제 재산출한다.

추가로 14 크기 × 일반/정체/굵은 이탤릭/굵은 정체 56개 수식을 정상 저장하고
Print 출력했다. 저장 job `99b11e28-77d8-4290-9698-ab20b9b607bb`, Print job
`ba86c360-281b-4c0f-ba34-5b3c8b876926`, 실제 전체 두 쪽이다.
같은 glyph의 굵은 전진 증가는 5/6/7 인쇄 단위이며 75HU 격자 증가와
인쇄 원점 반올림에 대응한다. 장평은 8/14/20pt에서 이웃 크기와 다르므로
`font_size/(font_size+2)` 같은 단순 근사로 대체하지 않는다.
`grid/metrics-summary.json`과 원본 스트림에 각 크기의 근거를 보존했다.

`source_font_text`는 기존 정체/이탤릭 전진을 사용하고 검증된 굵은 전진에
75HU 한 단위를 더한다. `source_variable_style`은 확인한 14 크기의 장평과
0.02em 획을 선택한다. `variable_outline`은 공개 정체 A~Z/a~z와 이탤릭
소문자의 윤곽을 원 face의 em 프레임에 배치한다. 정체의 다른 기준선도 같은
인쇄 격자와 em에서 해소한다. 공유 `FontGlyphPaint`의 획·장평을 SVG,
Canvas, Skia와 paint JSON이 소비하고 CanvasKit도 동일한 fill+stroke를
그린다. Skia/CanvasKit의 공용 최소 획 굵기를 이 인쇄 획에 적용하지 않는다.

검증되지 않은 다른 face·SansSerif/Monospace/Calligraphy/Fraktur/Blackboard의
측정과 표시를 보존한다. 표시 계약을 적용하지 않는 경로도 종전의 소스 전진을
사용해야 함을 코드 검토에서 확인하고 후보를 교정했다. 확인되지 않은 굵은
크기는 종전 경로로 남겨 원문 전체 검증에서 평가하며 완성된 일반 계약이라고
보고하지 않는다. 일반 그리스/CJK와 숫자·기호의 별도 경로는 원래 역할을 유지한다.

새 공개 subset은 13,488 byte이며 family/full/PostScript/CFF 이름을 변경했다.
원본 저작권·라이선스·timestamp와 manifest를 보존하고 사용하지 않는 이전
대문자 전용 subset을 변수 subset으로 교체했다. 사설 바이트·윤곽은 포함하지 않는다.

최초 후보의 fmt·Native Clippy·WASM Clippy·Skia check 및 Studio TypeScript는
통과했다. 비적용 경로의 측정 보존 교정 뒤 Rust 검사는 재실행하며, 실제
Native/fresh WASM와 전체 원본·관계형 회귀 전환은 여전히 미완료다.


코드 검토에서 발견한 비적용 경로 문제는 표시 계약의 선택과 측정의 선택을
분리해 교정했다. SansSerif 등은 기존 정체 전진을 보존하며, 검증되지 않은
새 윤곽을 선택하지 않는다. 동일한 Source 결과의 `outline_contract`만 표시
적용 여부를 정한다. 실제 바깥 앵커·clamp에 별도 보정을 추가하지 않았다.

## 원본 시험지의 단 이동 차이 — 보정 계속

변경 전 전체 Native 검증에서 `미주사이20/구분선아래2` 및
`미주사이7/구분선아래20`의 HWP/HWPX 네 입력이 추가로 미달했다.
현재 후보의 실제 Skia 96dpi 13쪽은 각각 HWP에서 **66.80147%**, **45.98645%**다.
현재 일반 Native Sweep의 `미주사이20/구분선아래2.hwp`도 13/16/17쪽에서
65.98698/53.79032/48.83636%이며 다른 선택 쪽 처리가 진행 중이다.
오래된 source 결과를 현재 후보의 결과로 대신하지 않았다.

두 HWP의 13쪽을 독립 Print와 직접 열었다. 한컴은 문20 제목을 앞 단의
하단에 남기고 본문을 다음 단에서 시작한다. 현재 `미주사이20` 후보는
제목까지 다음 단으로 넘겨 이후 내용을 한 줄 아래에 놓는다.
`미주사이7` 후보는 앞 단의 풀이 한 줄을 다음 쪽으로 넘긴 차이가 이어진다.
쪽수 일치나 변수 대조군 통과로 이 구조 차이를 면제하지 않는다.

`미주사이20`의 미주19 표는 HWPX 원문에서 셀 행 선언 합 3546HU와 개체 선언
3771HU가 다르다. `height_measurer`에는 내용이 자라지 않은 행 선언을 보존하는
경로가 있으나 `typeset/table.rs::fit_measured_for_host`가 개체 높이로 재조정한다.
현재 흐름 표의 행은 16.76 단위씩 세 행으로 관측되며, 후속 문단의 저장 vpos
선택과 미주 간격까지 실제 호출 경로에서 확인한다. 이것이 독립 Print의 행
경계·후속 원점 차이를 설명하는지 추가 입증하기 전에는 원인 해결로 판정하지 않는다.
임의 허용치·제목 위치 clamp나 테스트 완화로 통과시키지 않는다.

현재 원본 비교 PNG와 입력/PDF·명령·source SHA는
`stage88-original-skia/{receipt.json,all-20-p013-current-review.png,all-24-p013-current-review.png}`에
보존했다. 표 측정 결과 → 표 format의 재조정 → 실제 layout의 저장 vpos 선택 →
새 미주 제목의 `NewHeadFit` 수용 결과를 같은 사례에서 추적하며 보정을 계속한다.
