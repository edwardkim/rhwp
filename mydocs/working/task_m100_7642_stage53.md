# 이슈 #7642 Stage 53 — 미주 분할 줄의 점유와 후행 간격

Issue: #7642

## 독립 출력과 최초 차이

9월 미주 사이 20 HWP의 독립 한컴 2024 Print는 문7 풀이의 합 기호 줄을
9쪽 오른쪽 단 하단에 두고, 다음 등호·분수 줄을 10쪽 왼쪽 단에서 이어간다.
이후 다른 풀이·문8·문9도 10쪽 왼쪽 단에 있다. source
`1af0ae1790578ad04a0530cbb1d398e58255ded2`의 Native는 합 기호 줄을
10쪽 왼쪽 단에 두고 나머지 풀이를 오른쪽 단으로 옮긴다. 10쪽은 32.34038%다.

원본 본문 문단 55, 미주 7 내부 문단 6은 두 저장 줄을 가진다. 줄 0의
vertical_pos는 0, line_height는 2438, line_spacing은 452 HWPUNIT이다.
줄 1은 vertical_pos 2890, line_height 2070, line_spacing 452다.
양쪽 줄의 수식과 순서를 변경하지 않는다. 원본 JSON과 Print 9/10쪽의
추출 본문은 ignored stage53 진단 자료에 보존했다.

## 생산·소비 경로와 원인

현재 단 + 첫 줄의 공통 배치는 점유 끝 995.76, 흐름 끝 1001.7867을
반환한다. 가용 끝은 1001.56이다. 점유는 들어가며 흐름에는 후행 줄간격이
포함된다. prefix fit은 이 점유를 받아 분할 컷 1을 유지하지만,
`reflowed_endnote_single_line_overflows`의 다줄 분기는 흐름 끝도 비교해
단을 먼저 넘긴다. `emit_endnote_split`은 기존 컷의 앞부분을 새 단에
내보내고 또 단을 넘긴다. 로그는 paragraph.rs와 emit.rs의 연속 두 번
단 이동을 확인한다. 빈 왼쪽 단을 남기는 최초 원인이다.

소비 경로는 `저장 두 줄 → PartialParagraph 첫 줄의 실제 점유 → prefix fit →
사전 overflow 판정 → emit의 앞 조각 → 단 전환 → 뒤 조각`이다.
점유 결과에 후행 간격을 다시 더하거나 허용치를 늘리지 않는다. 첫 줄
수용 여부는 내용/줄 상자 점유로 판정하고, 뒤 내용의 원점에는 기존 흐름
전진을 유지한다. 실제 첫 줄 점유가 넘치는 경계의 단 이월은 유지한다.
측정 불가는 시각 통과나 fit 증거로 간주하지 않는다.

## 검증과 회귀 계약

13/14/19쪽 그림·표 대조군과 미주 사이 20의 9/10쪽을 새 코드로 함께
검증한다. 10쪽의 빈 단 제거뿐 아니라 앞 조각의 원래 단 소속과 뒤 줄·
후속 미주 순서, 누락/중복, 최종 쪽수도 확인한다. 수정 후 전체 Native와
fresh WASM TSV 및 확대 판독이 필요하다.

현재 페이지 문맥 수정의 Native 빌드와 fmt·Native Clippy가 모두 exit 0으로
종료한 뒤 소스를 변경했다. 다줄 첫 줄의 사전 overflow 판정도 단일 줄 및
prefix fit과 같은 점유 끝을 소비하도록 연결했다. 흐름 전진과 emit의 컷·
항목 순서는 유지했다. 이 변경의 새 빌드와 시각 검증은 아직 실행 전이다. 원본 문서가
전체 90% 이상일 때 관련 회귀를 문단/줄 소유·순서·보존 관계로 수정한다.
고정 진단 px를 회귀 기대값으로 옮기지 않는다. Stage52의 non-TAC 표
행 분할과 전체 입력 범위도 계속 남아 있다.


## 첫 보정의 실행과 남은 쪽 경계

source `99a7b47c4bef4f67887f1cb7262fc865f4ef9f01`의 Native 빌드는
364.72초, exit 0이었다. frozen binary SHA-256은
`3093859a819667effae6d38319f709460bb2246ae3b2986dc31e8243a44106c8`다.
포맷 검사 16.92초·Native Clippy 50.69초 모두 exit 0이다.
이후 문서만 추가한 `1e3a98a7d`와 Rust·Cargo·글꼴 소스 차이가 없음을 확인했다.

미주 사이 20 HWP의 9쪽은 97.95588%, 10쪽은 96.67299%다.
전체 쪽수도 Native 24 / Print 24로 같다. 새 10쪽 review를 열었으며
문7의 등호·분수 줄과 다른 풀이·문8·문9가 Print와 같은 왼쪽 단에서
이어지는 것을 확인했다. 이전의 빈 단은 제거됐다.

다만 문12의 CH 수식 줄(가상 문단 572)이 Native 10쪽 단 하단에 나타나고
Print는 이 줄을 다음 쪽에 둔다. 숫자 통과로 이 내용 소속 차이를 면제하지 않는다.
원본 본문 문단 99의 미주 12 내부 문단 5이며, 저장 위치는 3139,
줄 높이 1080, 줄간격 452 HWPUNIT이다. 바로 앞 C 문단은 저장 위치
1637, 줄 높이 1050, 줄간격 452다. 원본 JSON 및 Print 10쪽 bbox를
ignored stage53 자료로 보존했다.

Print의 문12 제목·AH 수식·C 설명 원점은 Native와 대응한다. 실행 로그에서
C 문단의 흐름 끝 뒤 CH 문단 시작만 후행 줄간격만큼 되돌아간다.
이는 뒤 문단의 실제 원점 선택 문제이며 더 큰 허용치나 회귀 기대값 변경으로
처리하지 않는다. HeightCursor의 저장 위치 보정 진단을 별도로 시작했다.

세 문서(구분선 아래/위 20 HWP/HWPX 및 미주 사이 20 HWP)의 전체
70쪽 Native TSV를 같은 frozen binary로 추가 산출 중이다. 선택 16쪽의
대조군 배치 검증도 진행 중이다. 이 결과는 전체 55개 원본의 최신
Native/fresh WASM 전쪽 통과나 관계형 회귀 전환 완료를 뜻하지 않는다.
