# Issue #7642 단계 134 — 셀 끝 줄간격의 측정·분할 회계 정합

## 근거와 범위

- 시작 소스: `4ed009b6027dba8ac9373c7006a74a073811a669`.
- 원본 `samples/KTX.hwp`와 독립 한컴 2020 Print PDF를 대조했다. 새 MCP 작업
  `eb21c9da-660c-415e-800c-6f2578402ab7`의 27쪽 PDF이며, 기존 기준 PDF와 같은 차이가 재현됐다.
- 2쪽 표의 마지막 셀은 27개 문단이며 마지막 공백 문단에도 저장된 줄 높이가 있다.
  원본의 마지막 줄 위치 63180 HU, 높이 1400 HU와 양쪽 여백 282 HU를 합하면
  64862 HU이다. 앞 네 행 5556 HU를 더한 70418 HU는 원본 표 높이와 Print 외곽에 일치한다.
- 기존 측정은 뒤에 줄이 없는데도 마지막 줄간격 1120 HU를 추가했다. 반면 중앙 정렬의
  콘텐츠 높이는 이를 제외했다. 행 높이가 커지고 중앙 정렬 본문이 추가 공간의 절반만큼 밀렸다.
- 입력의 마지막 줄간격만 0으로 바꾼 **진단용 IR**에서는 같은 2쪽 실루엣이
  49.86757%에서 99.72705%로 개선됐다. 원본 입력의 수정 후 통과로 판정하지 않는다.

## 소비 경로와 수정

| 소비 단계 | 코드 위치와 계약 |
|---|---|
| 일반 셀·병합 셀 요구 높이 | `height_measurer.rs`의 두 줄 합산 경로: 마지막 줄 높이는 유지하고 뒤의 줄간격 제외 |
| 행 성장과 분할 예산 | 측정한 행 높이, `table_layout.rs`의 `cell_units_uncached` 세 경로: 같은 마지막 줄간격 규칙 |
| 실제 정렬과 paint | `calc_cell_paragraphs_content_parts` / `calc_para_lines_height`, MeasuredCell의 줄 높이는 이미 마지막 줄간격 제외 |

TAC 여부나 문단 수는 다음 줄의 존재를 뜻하지 않는다. KTX 이름이나 특정 수치를 조건으로
사용하지 않는다. 뒤 문단이 있는 줄, 중첩 표 호스트의 별도 전진량과 공백 줄 자체의 점유는 보존한다.
마지막 줄간격을 더한 뒤 선언 높이로 되돌리던 무효 보정도 제거한다. 그 보정은 RowBreak에서
추가한 줄간격을 비-RowBreak에서만 회수하도록 되어 실제로 회수하지 못했다.

## 검증 계획과 판정

1. fmt와 Native Clippy로 두 측정 경로 및 세 분할 경로를 함께 확인한다.
2. 실제 원본 KTX와 AIFT, 셀 마지막 줄·분할 대조군을 새 빌드로 검증한다.
3. Native/fresh WASM의 관련 전체 페이지 90% 이상 및 확대 판독 후 새 이름 관계형 검사를 추가한다.
4. 현재 실행 중인 전체 55문서 검증은 시작 SHA의 결과로 보존한다. 이 수정의 증거로 재사용하지 않는다.

현재 판정: 구현 보정 진행, 실제 원본의 수정 후 Native/fresh WASM 검증 미완료.
