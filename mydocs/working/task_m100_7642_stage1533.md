## 새 회귀 네 건과 교체한 기존 가정

`tests/cases/verified_hwp3_original_print_boundaries.rs`에 새 이름으로 등록했다.

1. 원문 `1. 추진목적`의 공백, 세 확장 제어, 문자 원점 배열과 공통 IR 8유닛 축을 검사한다.
   원문과 최종 제목을 연결하고 독립 Print의 본문 시작 x=109.919993을 확인한다.
2. 세 제목을 원문 소유로 찾아 전쪽에서 3쪽에 한 번씩 있는지, 내용·순서와 기준선을 검사한다.
   독립 기준선은 159.199992/359.039998/771.199951 CSS px다.
3. 두 제목 사이의 원문 Rectangle과 최종 Rectangle을 소유 키로 연결한다.
   점선·그라데이션, 같은 도형 자식의 글상자 원문·포함, 제목 앞뒤 비겹침을 확인한다.
   독립 Print의 검정 점선은 채워진 벡터 경로이며 외곽은
   `(102.983999, 174.689372, 612.151988, 130.895996)` CSS px다.
4. 목차 제목부터 본문 제목 앞까지의 원문 탭·끝 번호로 26개 항목을 찾는다.
   독립 Print의 페이지 번호 순서, 각 문단의 원문·줄 소유와 상대 오른쪽 정렬을 검사한다.
   화면의 `x > 600` 영역으로 번호를 식별하지 않는다. 기존 정렬 공차 1.5는 넓히지 않았다.

3쪽은 양쪽 최솟값 99.92693%인 해당 동작의 완료 페이지라서 좌표를 보호한다.
더 높은 19쪽은 수정 제목·점선 상자를 검증할 수 없다. 관계 검사를 유지하며,
이후 3쪽은 양쪽 모두 98% 이상을 유지해야 한다. 좌표 검사만 통과하고 시각 점수가
98% 미만이면 회귀로 판정한다. 문서 전체가 98%라는 뜻은 아니다.

`tests/issue_1008_gradient.rs`의 단순 장식 제거 검사와 잘못된 실선 기대,
`tests/issue_1116.rs`의 다른 저장 모드 제목 좌표와 고정 영역에 의존한 HWP3 목차 검사를
제거했다. 위 새 이름의 네 검사로 기존의 정확한 내용·정렬 계약을 보호한다.
더 이상 쓰지 않는 SVG 위치 helper도 제거했다. HWP5 별도 원본의 기존 검사,
그라데이션 색·글꼴 선언처럼 정확한 다른 기대값은 변경하지 않았다.

## 수정 전 실행과 정식 검증

ignored `stage1531-hwp3-print-contract/receipt.json`은 동일 검사 본문을
수정 전 `librhwp-stage1487.rlib`와 수정 후 `librhwp-stage1520.rlib`에 연결했다.

검사를 제품 결함의 수정 전 FAIL로 부풀리지 않았다.

최종 등록·rustfmt 뒤 manifest를 prepare하고 파생 target과 실제 모듈이 일치하는지
확인했다. 새 네 검사와 남은 기존 두 모듈을 한 nextest 명령으로 묶었다.
공용 `target/pr-review`, 빌드 잡 8개·테스트 스레드 12개·native-skia를 사용한다.

**13/13 PASS**, run ID `b2c1ae14-cf44-4918-9483-c35971693861`를 확인했다.
네 새 검사와 유지한 기존 검사 아홉 건을 함께 실행했다. 진단 검사 본문과
정식 파일의 본문이 같은 것도 해시로 확인했다. rustfmt·`git diff --check`가 통과했다.
이 결과는 전체 회귀 10,450건의 재실행이 아니다.
