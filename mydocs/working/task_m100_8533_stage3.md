# #8533 Visual Sweep의 실제 PostScript 프로그램 공급

## 원인과 보정

Native 공개 공급 영수증은 실제 프로그램의 PostScript 이름인 `HCRBatang`과
`NotoSansKR-Regular`를 사용할 수 있다. WASM Sweep의 FontTools 목록은 name ID 1·4·16만
수집하여 같은 파일이 준비되어 있어도 ID 6 조회에는 공급하지 못했다. 최소 글꼴 집중 출력에서
220쪽 글머리표와 쪽번호가 네모로 출력되는 실제 결함을 확인했다.

실제 name ID 6 별칭을 기존 family 목록 뒤에 추가한다. 기존 family 조회 우선순위와 원본
프로그램 바이트는 보존한다. 캐시 schema를 3으로 올려 이전 별칭 누락 캐시를 재사용하지 않는다.
환경에 전달하는 family는 여러 굵기를 합친 typographic 이름보다 같은 프로그램의 legacy
family(ID 1)를 사용한다. 임의 별칭이나 글리프를 생성하는 변경은 아니다.

## 확인한 결과와 아직 남은 범위

- 실제 작은 SFNT의 cold/warm 캐시·PostScript 조회·바이트 보존 관계 검사는 보정 전 실패,
  보정 후 통과했다. 현재 관련 Python 36건과 Node 16건이 통과한다.
- Native 공개 프로그램 9개와 저장소 공개 번들만 공급하고 사용자·추가 시스템 글꼴 파일
  접근을 차단한 WASM 집중 비교에서 272쪽은 100%, 220쪽은 94.37243%다.
  이전의 네모 글리프는 해소했으나 이 수치만으로 전쪽 완료를 선언하지 않는다.
- 220쪽은 동일 문서의 portable 전진 6.666667px를 Canvas 측정 세션이 12.930099px로
  대체한다. 글리프 누락 복구와 별개인 간격 차이다. 이 추가 명시 환경 진단을 Native의
  383쪽 결과나 일반 WASM 자동 선택의 결과로 섞지 않는다.
- 순수 base는 새 `documentGlyphFallbacks` 환경 형식을 지원하지 않는다. 실패 로그를
  보존하며, 다른 환경으로 바꾸어 동일 조건의 base 비교라고 주장하지 않는다.
- Rust 소스와 Native·WASM 번들은 변경하지 않았다. 그러나 목록·family 선택은 WASM
  자동 선택에도 영향을 줄 수 있으므로 이전 자동 분기의 동일성 증명만으로 수용하지 않는다.
  같은 현재 검증 호스트에서 base/후보의 대상 36문서와 편람을 다시 비교한다. 아래처럼 36문서는 완료했고 편람은 진행 중이다.

최종 제출 TSV·raw PNG·review·overlay는 이 재검증 결과로 갱신한다. 미완료 범위가 있으므로
이 기록은 PR 준비 완료 보고가 아니다. 로그·진단 스크립트·부분 산출물은 ignored output에 보존한다.

주장하지 않는다. 고정 px 검사의 기관명 5쪽은 Native 98.91953%, 현재 WASM 99.37969%로
선행 조건을 충족하며, 실제 새 review·overlay로 잔여 글리프 차이와 상자 배치를 함께 확인했다.
이 증거로 편람이나 Native 공개 프로그램 명시 WASM의 전쪽 완료를 대신하지 않는다.
