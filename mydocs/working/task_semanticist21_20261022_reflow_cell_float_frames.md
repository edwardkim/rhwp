# 재조판 셀의 부동 표 원점과 실제 점유

## 범위와 선행 증거

현재 45개 PR 통합 범위를 유지한다. 행정업무편람 개선과 사양 설명본·정오표 변경은
다른 PR의 작업이므로 제외한다. TABLE 값 2/CELL/RowBreak의 셀 내부 글줄 나눔
정정은 검토에 참고한다. 현재 반례의 표 속성은 NONE이다.

전 단계 1853~1866은 동일한 원본의 개별 속성만 바꾸고 실제 한컴 2020 Print와
Native121을 대조했다. 복제 ID·셀의 구역/단 정의는 Print 표 경계를 바꾸지 않았다.
안쪽 표가 글자처럼 취급이면 raw 99.09172%지만, 원래의 부동 표는 47.35546%다.
99% 쪽도 안쪽 오른쪽 괘선 차이가 있어 시각 완료로 보지 않았다.

선행 문단에 실제 텍스트를 넣은 대조에서 flowWithText=0/1의 Print 경계가 달라졌다.
이 값은 Task #1282 Stage 10/11의 실측대로 쪽 영역 안으로 제한(bit 13)이다.
이름을 글과 함께 이동으로 직역해 새 정책을 정하지 않는다.

## 원인 추적과 현재 가설

기존 reflow_block_table_host_occupied_height는 NO_LS 빈 자리차지 표 호스트의
줄과 개체를 합산하지 않고 합집합으로 센다. 다만 제한이 켜진 host만 대상이며,
HeightMeasurer의 여러 셀 경로는 셀 전체 all_no_ls도 요구한다. 현재 반례는
저장된 선행 글줄 뒤에 NO_LS host가 있어 일반 합산 경로로 빠진다.

현재 sequential_nested_cell_layout도 NO_LS가 하나라도 있으면 일반 계획을
반환하지 않는다. 측정은 unabsorbed_nested_tables_height/상세 줄 원장을 거치고,
배치는 reflow_nested_table_origin 뒤 별도 앵커·높이 선택을 거친다. 공통 helper를
호출한다는 이름만으로 소유가 일치한다고 판정하지 않는다.

새 규칙은 실제 저장 줄의 사다리를 전면 폐기하지 않고 재조판을 소유하는 host에서
필요한 줄/개체 원점과 물리 점유를 같은 결과로 발행해야 한다. 빈 글줄, 보이는 글자,
부동 개체의 flow 전진은 구분한다. 제한 off/true, 선행 텍스트 유무와 자식 높이를
각각 독립 Print로 대조한 뒤 수식과 적용 조건을 정한다. 특정 원본 ID·고정 px·
문서별 좌표 보정 또는 출력 숨김으로 해결하지 않는다.

`float_placement/reflow_block_cell.rs`가 저장된 선행 글줄과 NO_LS 빈 표 호스트의

## 새 쪽 경계 반례: 자식 소유와 부모 흐름은 아직 분리 미완료

1893 입력은 표준 A4의 본문 예산을 여백으로 줄이고, 독립 주소가 있는 자식 3행과
부모/자식 `pageBreak=CELL`을 사용한다. 제한 false/true의 독립 Print는 각각
job `b240828a-61d4-4a07-8265-56000449168b`,
`2a9510fd-71ed-47d4-8771-e03469328959`이며 모두 한컴 2020의 Print 2쪽이다.
입력 변경·해시는 1883 → 1890 → 1893의 각 입력 영수증에 연결한다.

중간 진단의 오류도 보존한다. 사용자 지정 용지의 1883 입력은 Print가 A4로 나와
그대로 같은 용지 대조 근거로 쓰지 않았다. 1890 입력은 셀의 구역/단 정의 복사본을
제거하며 빈 `<hp:ctrl/>` 3개를 남겼고, 한컴이 여는 중 오류로 종료했다. 빈 wrapper를
제거한 별도 1893 입력은 정상 Print됐다. 실패 입력·job을 덮어쓰거나 같은 파일로
성공한 것으로 바꾸어 기록하지 않는다.

| 제한 | 독립 Print | 보정 전 Native121 | 현재 Native124 | 판정 |
| --- | --- | --- | --- | --- |
| false | 2쪽, 다음 쪽에 자식 마지막 행 | 2쪽, raw 최저 34.32542% | 1쪽, 전쪽 측정 불가 | 현재 변경의 자식 소유 회귀. 먼저 보정한다. |
| true | 2쪽 | 2쪽, raw 최저 72.49731% | 2쪽, raw 최저 72.49731% | 기존 출력 차이가 남았다. 통과 아님. |

1897의 review·overlay에서 true의 첫 조각을 직접 판독했다. 1898은 독립 PDF의
표 경계·본문·쪽별 직접 래스터를 보존한다. false의 Print 첫 쪽에서는 부모 외곽은
짧게 닫히지만 자식 두 행이 그 밖으로 이어진다. 둘째 쪽에는 부모 외곽 없이 자식
마지막 행만 이어진다. true는 부모 외곽도 이어진다. 따라서 false의 부모 높이를
자식 높이로 늘리거나, 부모 흐름이 끝났다는 이유로 자식 원본 소유를 버리면 안 된다.

후속 공통 결과는 부모 흐름 점유와 자식 원본/물리 구간을 따로 발행해야 한다.
`MeasuredCell`·전체 fit·`CellUnit`/RowCut 예약·부분 배치가 같은 소유 구간을 소비하게
연결한다. 겹친 선행 글줄과 자식의 구간은 합산 대신 실제 원점의 합집합으로 예산을
정하고, 부모 외곽의 종료와 자식 다음 쪽 소유를 함께 보호한다. 새 반례를 피하려고
문서 ID·고정 좌표·단일 쪽수에 맞춘 조건을 추가하지 않는다.

위 쪽 경계 반례·괘선 차이·fresh WASM 등 필수 항목이 남아 있어 PR 생성·승인·통합은
보류한다. 이 상태를 완료나 별도 이슈 이관으로 대신하지 않고 현재 브랜치에서 계속 보정한다.

1903 리베이스는 base `605ccfd92f2f12f18e14182548d729f9929fda00` 위에서 완료했다.
기존 189개 커밋의 range-diff는 모두 `=`이며, 현재 커밋은
`00a637480332c896aa89de2c15f4d39a1bdb6398`이다. 아래 결과는 그 뒤의 작업 트리를
고정해 빌드한 Native125에 해당한다. 최종 커밋이나 fresh WASM 검증 결과가 아니다.

1905~1913에서는 부모·자식의 NONE/TABLE/CELL과 영역 제한 false/true의 18개
조합을 실제 한컴 2020 Print로 출력했다. 전부 2쪽이지만 자식 행과 후속 본문의
소속은 다르다. 예를 들어 제한 false의 CELL 자식은 부모 정책과 관계없이 2행/1행으로
이어지고, NONE 자식은 첫 쪽에 3행이 나온다. 제한 true·부모 TABLE은 자식 표가
둘째 쪽으로 이동하고 후속 본문이 첫 쪽에 남는다. 한 조합의 관측을 모든 부모 정책의
흐름 규칙으로 일반화하지 않는다. 입력·PDF 해시, MCP job과 쪽별 내용은
`reflow-policy-print-matrix-1913.json`에 보존했다.

이 결과에 따라 앞 절의 원장 재작성 제안을 수정했다. 자식 원본의 예약·컷은 기존
`MeasuredCell`/`CellUnit` 경로가 유지하고, 공통 재조판 계획에서 완료 셀의 별도
테두리 행 높이 `row_frame_heights`를 발행한다. 전체 배치는 외곽 높이와 후속 흐름
전진량을 구분한다. 부분 배치의 원본 소비를 부모의 짧은 외곽 높이로 덮어쓰지 않는다.
완료 재조판 셀의 경계는 조상 표의 사후 clip 확장이 다시 늘리지 않게 했다.

## 전체 검사에서 재확인한 80168의 93쪽 회귀

1924 전체 실행 중 `regulatory_analysis_completed_pages`의 93쪽 검사가 실패했다.
표 784 뒤의 제목 기준선은 실제 202.933333px, 독립 Print는 229.120000px다.
이 검사는 기존 완료 페이지의 ±2px 근거와 내용 보존을 함께 검사하므로 기대값을
갱신하지 않는다. 1931~1934에서 같은 원본과 기존 독립 Print의 93쪽을 대조했다.

| 실행 파일 | 93쪽 Native raw(%) | 표 784의 쪽 소유 |
| --- | ---: | --- |
| 이전 base `2e087a5b4b`, Native1504 | 99.99223 | 이전 base의 진단 대조. 최종 최신 base 대조를 대신하지 않는다. |
| 보정 전 Native121 | 41.61277 | 기존 작업 head에도 차이가 있었다. |
| Native124 | 99.99223 | 93쪽에서 전체 표로 시작한다. |
| Native125 | 41.61277 | 앞쪽에서 유닛을 소비한 `startCut=[1]`의 이어받기로 바뀌었다. |

입력 SHA와 PDF SHA는 정식 검사에 기록된 원문과 같다. 결과·새 review/overlay는
`regulatory-page93-native-comparison-1931/`, 이전 base의 독립 대조는
`regulatory-page93-older-base-1932/`에 있다. 1934의 `dump-pages -p 92 --json`은
전체 표가 이어받기로 바뀐 사실을 보여준다. 따라서 이를 단순한 그리기 원점 차이로
처리하거나 후속 제목의 좌표만 조정하지 않는다. 측정 원장과 원본 컷의 경계에서
원인을 보정하고 앞뒤 쪽·후속 본문을 재검증한다.

1936의 CLI 모델 덤프와 1937의 직접 CFB/해제 레코드 읽기에서 부모·자식 TABLE의
원시 속성은 모두 `0x00000006`, 하위 두 비트는 2다. 부모의 셀은 저장 줄이 없는
빈 문단 하나와 3행×4열 자식을 소유한다. 사용자 전달 정정대로 CELL은 셀 내부
글줄도 나눌 수 있지만, 이 사실만으로 현재의 첫 유닛 소비가 올바르다고 판정할 수 없다.
독립 Print와 앞뒤 내용 소유를 함께 만족하도록 공통 예약·배치를 보정해야 한다.

1927 정책 조합 대조는 18건을 모두 마쳤고 4건만 90% 이상이다. 현재는 완료 상태가
아니며, 원본 쪽 경계와 위 완료 페이지의 후퇴를 함께 보정한다. 새 렌더링 회귀를
추가하거나 기존 기준값을 바꾸지 않았다. 전체 Rust 실행의 최종 결과는 아직 대기 중이다.

## 전체 실행의 진단 종료와 성능 원인

1924는 2026-10-23 02:05:42에 진단 중단으로 종료했다. exit 100이며 총 1774.84초,
nextest 실행 1149.729초다. 최종 summary는 11,554건 중 9,402건 실행, 9,357 PASS,
45 FAIL, 45 skip이다. FAIL에는 중단 신호를 받은 실행 중 6건이 포함되므로 실제
단언 실패 39건과 SIGINT 6건을 구분한다. 2,152건은 인터럽트로 실행하지 못했다.
전체 통과·최종 검증 완료의 근거로 사용하지 않는다.

출력 공백이나 SLOW 알림만으로 중단한 것이 아니다. 별도 Native125 진단을 gdb의
자식으로 실행한 두 스택 표본에서 `native_stored_table_has_intra_paragraph_frames`
아래의 `cell_units` 재조판과 `source_rows_before_hu`가 반복 실행됐다. 1940의 직접
원본 읽기에서 시장구조조사의 큰 표는 2,195행·2,196행, 각각 8열이다.
현재 코드는 재시작 가능성 확인 전에 셀마다 선행 행을 순회하고, 각 선행 행에서
전체 셀을 다시 검색한다. 실제 재시작이 없는 셀도 이 비용을 낸다.

소스는 중단 종료를 확인할 때까지 Native125 고정본을 유지했다. 후속 보정은
원본 문단 내부의 재시작 필요조건을 먼저 확인해 결과를 바꾸지 않는 계산 순서를
적용하고, 큰 표의 실행 시간과 기존 원본 컷 계약을 다시 확인한다. 80168의 93쪽과
부분 배치의 미달 보정도 계속한다. 전체 Rust·lint·fresh WASM 필수 검증은 보정한
후보에서 다시 완료한다. gdb 진단 프로세스와 이전 nextest 자식은 모두 종료했다.
