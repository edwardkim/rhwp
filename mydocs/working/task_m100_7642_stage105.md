Issue: #7642. 원본 55개·853쪽과 회귀 292개·#1139 전체 관계형 전환 목표를 유지한다.

리베이스 직후 head는 `479e34b85`이며 upstream 대비 behind 0이다. 이전 브랜치는

## Print 확대가 바꾼 해석

독립 Print의 `vec {OP}^2`는 화살표가 OP와 위첨자를 함께 덮는다. 기존의 외부
첨자 해석은 틀렸으므로 완성된 인자의 후행 첨자를 먼저 소비한 뒤 장식을 감싸는
경로를 확인한다. `vec {x^2}`의 내부 첨자와 명시적으로 장식 자체를 다시 묶은
`{vec {OP}}^2`를 구별하고, 부모 첨자 슬롯의 `attach_scripts=false`는 유지한다.

Stage 103의 크기별 1230/1538/2228/3023HU 프레임은 위 입력의 독립 측정값이다.
이를 외부 위첨자 프레임으로 분류한 것도 철회하며 장식 안의 단일 위첨자 경로에
귀속한다. 독립 자료 없이 추가한 외부 장식의 uppercase gap/shift/프레임 분기는
제거한다. 일반 대문자 본체의 기존 0.15em 여유·독립 글줄 shift는 유지한다.

## 묶음 검증

실제 AST → 인자 위첨자의 글자 원점·전진 → 장식의 전체 본체 폭·상단 → 공통
논리 프레임 → 저장 줄의 점유/paint 원점 → SVG/Skia/Canvas2D/CanvasKit 소비를
추적한다. 먼저 현재 parser 소유 진단과 순차 lint/typecheck·Native 진단 16개·실제
원본 20쪽의 새 확대를 확인한다. 전쪽 점수와 확대 미달을 별도로 기록한다.
Native/fresh WASM 전쪽 TSV와 확대를 충족한 뒤 관계형 회귀를 변경한다.
진단·TSV·nextrun은 ignored output에 보존한다. 전체 회귀와 PR/CI/후속은 미완료다.

## 현재 소스의 선행 확인

source `db43ff92e`의 fmt·Native Clippy·WASM Clippy·Skia check는 모두 exit 0이다. 리베이스 충돌로 통합한 Studio constructor/font bytes/math fallback의 TypeScript 검사도 exit 0이다. 현재 parser를 직접 포함한 소유 진단은 장식 안의 OP와 2, 내부 첨자, 별도 그룹으로 장식 자체에 붙인 첨자, 부모 위·아래 슬롯과 thin 공백의 구별을 확인했다. 같은 소스의 Native build와 실제 비교는 실행 중이며 시각 개선 완료로 판정하지 않는다.

source `3d89e1f4`의 이전 전체 WASM controller는 handle exit 143과 PID 소멸로 종료를 확인했다. 완료된 15개 문서·318쪽은 모두 90% 이상(최저 91.31424%)이며 이전 source의 증거만 보존했다. 종료 원인은 확인하지 못했다. controller queue를 interrupted로 기록했고 해당 작업의 살아 있는 자식은 없었다. 이전 결과를 현재 head의 전쪽 검증으로 사용하거나 이전 source 작업을 다시 시작하지 않는다.

## 현재 소스의 실행 확인

Native release-test 빌드는 exit 0, 462.94초이며 frozen binary SHA-256은 `0ab9186aa44bbe7c871572ac68a6e93f325d3d922d3ddd141d883513c320cd55`다. 16개 직접 Skia 진단은 모두 90% 이상이다. 벡터 본체 문서는 한 쪽으로 Print와 대응하며 최저 99.67851%다.

9/11/16/22pt 첨자 영역은 73.33/63.06/66.67/66.91%에서 각각 **100%**로 개선됐다. 새 `vector-sup-selected-detail-review.png`에서 OP와 2 전체를 덮는 화살표 범위·기준선·숫자 원점을 직접 확인했다. 이는 2px 관용 실루엣 값이며 실제 픽셀의 완전 동일은 아니다. 공개 화살촉의 끝 윤곽/음영과 작은 안티앨리어싱 차이는 남아 있다.

실제 2022년 9월 원본 20쪽은 전쪽 92.34222%, 선택 벡터는 91.81818%다. 같은 입력/PDF SHA와 소유 기반 선택으로 새로 렌더했고 새 compact PNG를 사용자에게 표시했다. 이 대조의 괄호·글리프/기준선에는 작은 차이가 남아 있으며 전쪽 TSV와 backend 공통 소비의 판독이 필요하다. 다른 페이지·다른 backend의 완료로 확대하지 않는다.

전체 Native SVG TSV controller와 같은 source의 fresh WASM 빌드를 시작했다. Native 첫 입력 `21_언어_기출_편집가능본.hwp`의 15쪽은 모두 90% 이상, 최저 95.17139%이며 exit 0이다. controller는 같은 source/바이너리/입력/PDF/TSV SHA가 대응한 문서별 완료 결과만 재개할 수 있다. 로그/TSV/중간 자료는 ignored output에 보존한다.

리베이스 후 91개 원본 경로의 함수명 보존을 정적으로 재확인했다. 원 파일에서 빠진 이름은 기존 감사와 동일한 HML 12개(승인된 제외), #1139 이동 9개, #1308 이름 변경 2개다. 관계형 전환 또는 실행 통과 증거로 사용하지 않는다. integration manifest는 persist=false로 28개 suite를 파생 조회했으며 source/파생 tracked 파일을 변경하지 않았다. 최신 base `21ed64071`의 unit-tier 검사도 exit 0이다.
