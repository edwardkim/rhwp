# 단계 1017 HWP3 수식 상자의 공통 배치·기본 크기·기준선 보존

Issue: #7642.

## 원인과 독립 근거

단계1014의 HWP3 sample16 6쪽에서 한컴 Print의 두 입찰가격 수식이 RHWP에는 통째로 보이지 않았다. 입력 파싱 dump에는 스크립트와 개체 크기가 있지만 `font_size=0`, 빈 글꼴명, `tac=false`다. parser는 같은 84바이트 공통 상자를 표로 읽어 놓고 수식 변환 때 공통 속성을 버려, 크기만 기본 Equation에 복사했다. 저장 어댑터의 #4367 정규화는 HWP5 변환 때만 실행돼 직접 열기의 0 크기 글꼴을 해결하지 못했다.

독립 HWP3 사양 10.6절 표40/41은 기준 위치·그림 피함·정렬·여백과 박스 크기를 같은 구조에 저장하고, offset76의 수식 기준선은 1800dpi 길이다. 공통 IR의 Equation 기준선은 높이의 백분율이다. 길이를 그대로 백분율로 복사하지 않는다. 기본 수식 크기 1200HU와 `HYhwpEQ`는 기존 #4367의 한컴 저장본 바이트 대조 계약이며, 이번 원본 HWP3의 독립 Print에도 수식의 `평점`이 12pt로 표시된다. 본문은 별도 약13pt여서 본문 글자 크기를 수식에 대입할 근거가 아니다. 실제 원본/한컴 HWP5 dump 및 Print 문자 관측은 ignored 단계1017에 보존한다.

## 생산과 소비 경로

HWP3 공통 상자·셀의 수식 스크립트 → parser의 Equation IR → composer/typeset의 inline 참여·프레임·baseline → 공통 수식 layout/paint → Native·WASM이다. 이미 해석한 공통 상자를 그대로 넘기고, 기준선은 원본 길이/상자 높이의 비율로 변환한다. 원본 폭·높이·offset·스크립트·여백을 유지하며 한컴 HWP5 변환본의 다른 폭으로 덮어쓰지 않는다. 유효 범위 밖의 기준선은 좌표 clamp로 숨기지 않고 저장 기준선을 사용하지 않는 0으로 둔다. 표·글상자·버튼 분기는 기존 경로를 유지한다.

## 검증 계획과 한계

사양에 맞게 구성한 작은 HWP3 상자의 파싱 계약에서 원본 글자/문단 기준, 정렬·여백·크기·스크립트·기준선의 단위 변환을 검사한다. 이것은 합성 parser 계약이며 실물의 시각 완료를 의미하지 않는다. 실제 HWP3 sample16은 전체 64쪽 Native/fresh WASM을 다시 비교하고 6쪽 수식 및 35쪽 그림·본문 차이를 직접 읽는다. 같은 배치 검증 묶음에서 단계1016의 넓은 부동 표도 확인한다. 전쪽 90% 미달이면 새 실물 배치 회귀나 기존 기대값 변경은 보류한다.

## 실제 실행 결과와 남은 차이

단계1018의 수정 전 `c11717fe0`에서 합성 HWP3 수식의 source flow 검사는 실제 tac=false/기대true로 실패했다. 수정 후 `c0bc7d9e9`에서 기준선 75%·12pt·원본 크기/스크립트/글자/문단 기준 검사가 통과했다. 기존 표·글상자 대조군, #4367 HWP5 저장 계약을 포함한 관련 53건이 모두 통과했다. 새 실물 렌더링 회귀를 추가한 것은 아니다.

단계1022의 실제 6쪽 Native/독립 Print review에서 누락됐던 수식 2개가 표시됐고 보조값은 76.03357→79.53825%로 개선됐다. 수식의 폭·본문 글자 간격·일부 줄 위치는 남아 있으므로 완료가 아니다. 단계1020의 HWP3 전체 64쪽은 쪽수가 같고 최저 79.35244%이며 16쪽이 미달이다. 이 상태에서 실물 배치 baseline이나 golden을 갱신하지 않았다. 새 개발 WASM의 전쪽 대조는 단계1021에서 계속한다.

현재의 직접 확대 판독은 독립 Print와 실제 Native를 비교한 것이며, 진단용 공개 layout의 글꼴 속성 조회는 등록 글꼴을 공급한 시각 검증과 구분한다. 후속 조사에서 이 PDF의 본문 글꼴은 Type3이고 수식 한글 글꼴은 별도 Haansoft Batang TrueType임을 확인했다. 글꼴 종류만으로 폰트 예외를 선언하지 않으며 실제 글자 모양·간격·프레임 차이를 계속 대조한다.
