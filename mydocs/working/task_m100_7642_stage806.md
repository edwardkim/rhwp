# Issue #7642 단계 806: Native 도형 그라데이션 채우기

## 확인한 결함

이미지 채우기 원본의 표 15는 `border_fill_id=32`이며, 실제 문서 모델의 0 기반 border fill 31은 Gradient다. 한컴 Print PDF의 파란 띠는 오른쪽으로 밝아진다. 단계 799의 Native 직접 판독은 이 띠를 단색으로 표시했다. Native Skia의 PageBackground·Rectangle·Ellipse·Path 분기는 모두 `gradient.colors.first()`만 소비하고 있었다. 조판 간격 결함과 별개의 backend paint 결함이다.

## 구현과 범위

`skia/gradient_fill.rs`가 원본 색상·정규화 스톱·opacity와 기존 공통 물리 축을 Native shader에 전달한다. 선형은 SVG·Canvas가 이미 소비하는 `linear_gradient_axis`, 원형은 `gradient_geometry::radial_circle`을 사용한다. 페이지 배경과 세 도형 분기가 같은 결과를 소비한다. 색상 위치를 문서에 맞춰 덮어쓰거나 프린트 픽셀을 조건으로 삼지 않는다. 미지원 원뿔·사각 또는 무효 스톱의 기존 폴백을 이번 선형·원형 검증 범위에 포함하지 않는다.

기존 Native 합성 도형 단위 검사의 두 끝 색상 관계도 보완한다. 이는 알려진 파랑·빨강 스톱의 도형 채우기 계약이며, 실물 HWP의 절대 위치 회귀나 한컴 일치 증거로 사용하지 않는다. 첫 색을 전체 상자에 칠한 변경 전 구현에서는 오른쪽 빨강과 두 끝 색상 순서의 기대 관계가 실패해야 한다.

빌드 전 설치된 Skia 0.153.3의 실제 API 선언을 대조했다. `Colors`는 `Color4f` 배열을 받으므로 기존 ColorRef 변환 뒤 이 형식으로 전달한다. 공통 선형 축의 0도는 세로 축이고 90도는 왼쪽에서 오른쪽 축이다. 합성 검사의 선언도 확인하려는 가로 두 끝 관계에 맞춰 90도로 정했다.

## 검증 상태

이 변경의 컴파일·합성 검사·실물 시각 결과는 아직 미검증이다. 이미 실행 중인 단계 804는 이전 후보 `e66ce9c54`의 저장 축·호스트 줄 보정만 검증하므로, 이 Native shader의 통과 증거로 사용하지 않는다. 이를 포함한 새 후보에서 영향 페이지와 전쪽 Native/fresh WASM, 직접 판독·실제 devel 비교 및 필요한 전체 회귀·lint를 이어간다. 기존 후보 `099ae279f`의 fresh WASM 관련 9개 입력 산출은 단계 798에서 끝났으며 7개 입력만 전쪽 90% 이상이었다. 이미지 1쪽과 HWPML 7개 미달 쪽은 계속 보정한다.
