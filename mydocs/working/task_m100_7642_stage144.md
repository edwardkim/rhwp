# #7642 Stage 144 — 생략된 탭 폭의 측정·배치 대조

Issue: #7642

## 현재 검증과 변경 경계

시작 head는 `29843d1ea`, 생산 source는 `f4bd0a760`이다. Stage 143의 전체 nextest가
실제 실행 중이며 이 실행이 끝나기 전에는 생산 Rust source를 변경하지 않는다. 같은 source의
Native 선택 14쪽과 lint 7단계는 통과했지만 전체 Native/fresh WASM 및 미세 판독은 미완료다.
현재 목표는 남은 테스트·검증을 끝내고 PR, CI 확인, merge와 후속 처리를 수행하는 것이다.

## 독립 근거와 발견한 불일치

원본 `samples/issue1892_hwp3_tab_roundtrip.hwp`는 독립 한컴 2020 Print와의
Native/fresh WASM 일치율이 82.43006%다. 원본을 한컴이 정상 HWPX로 저장한
`pdf/issue7642-hwp3-realign-controls-20261012/issue1892_hwp3_tab_roundtrip-hancom-2020.hwpx`에서
문단 7/8/9의 탭 폭은 모두 4000 HU다. 이 저장본은 원본 속성 해석의 독립 진단이며 기준 PDF를
대신하거나 원본 시각 통과로 보고하지 않는다.

같은 원본을 RHWP가 저장한 진단 HWPX는 같은 문단의 폭이 모두 0이다. `TAB_EXT_PLACEHOLDER`는
저장 폭이 생략된 항목이며 다음 탭 확장의 순번을 보존한다. 저장된 원본 폭을 잘못 읽었다고
단정하지 않고 실제 기본 탭 정지의 소비 차이를 확인했다.

- 생산: HWP3 parser가 폭·채움이 없는 탭에 자리표를 보존하고 composer가 순서대로 전달한다.
- 글자 배치: `layout/text_measurement.rs::compute_char_positions_walk`는 자리표를 제외하고
  `find_next_tab_stop`의 기본 정지로 내려간다. 해당 탭의 순번도 한 번 소비한다.
- 전체 폭: 같은 파일의 `EmbeddedTextMeasurer::estimate_text_width_exact`는 자리표도 저장 폭으로
  읽어 0을 더한다. `estimate_line_run_widths`가 이를 사용해 오른쪽 정렬 원점을 계산한다.
- 최종 소비: `layout/paragraph_layout.rs`의 실제 run 배치·SVG가 그 정렬 원점과 글자 전진을 쓴다.

문단 7/8/9는 오른쪽 정렬이고 글자 네 개 뒤에 탭과 글자 두 개가 있다. 원본 기본 정지는
8000 HU이며 앞 네 글자의 점유는 4000 HU다. 한컴 저장 폭 4000 HU는 그 다음 정지까지의
전진으로 설명된다. 특정 문서 ID나 4000 HU를 구현 상수로 쓰지 않는다. 원형 글리프 크기 차이는
이 탭 결함과 별개로 남아 있으며 해결 완료로 판정하지 않는다.

## 수정과 검증 순서

전체 회귀 종료 후 자리표에 대해 전체 폭 측정도 같은 기본 정지와 순번 계약을 사용하도록 수정한다.
폭이 실제 저장된 탭, 채움만 저장된 탭, 자리표 뒤의 둘째·셋째 탭, run 경계에서 나뉜 탭과
오른쪽 정렬을 반례로 대조한다. 실제 저장 탭의 기존 의미를 일괄 재해석하지 않는다.

원본과 독립 Print를 Native/fresh WASM으로 재산출하고 모든 관련 쪽이 90% 이상인지 먼저
확인한다. 위치·원형 글리프를 확대 판독한 뒤 새 이름의 관계형 회귀를 추가한다. API·직렬화의
순번 보존 검사만으로 실제 출력 개선을 입증하지 않는다. 기대값·골든을 통과 목적으로 완화하지 않는다.

진단 파일과 명령·입력 해시는 ignored output의 `stage144-inline-tab-source-diagnostic.json`에
연결했다. 로그·진단 HWPX·TSV·중간 JSON·nextrun은 Git에 커밋하지 않는다.

## 전체 회귀 중의 실패 원인 대조

같은 생산 source의 전체 실행에서 새 검사 44개는 모두 실제 PASS다. 전체 실행은 마지막
장시간 검사 종료를 기다리고 있으므로 44개 통과를 전체 통과로 보고하지 않는다.
현재 실패의 함수·소스 위치·출력과 입력 후보는 `stage144-failure-diagnostics.json`에
수집했다. 파일 전체에서 찾은 입력 후보와 실패 함수가 실제 쓰는 입력은 별도로 확인한다.

`#6706`의 제목과 `#6172`의 네모 런 검사는 텍스트 런 하나의 문자열 완전 일치를 가정한다.
새 Native RenderTree에서 해당 내용은 글꼴 슬롯별 여러 런으로 나뉘어 남아 있다. 이 관측은
내용 누락과 검사 선택 오류를 구분하는 근거이며, 실제 배치의 정확성까지 입증하지 않는다.
`#6597` 합성 입력의 `CharShape::default()`는 `base_size=0`이다. 줄 폭 목록이 비었다는
실패를 공백 비율 결함으로 판정하지 않고 유효한 글자 크기와 입력 계약부터 확인한다.
`#7362`에서는 표 조각이 본문 하단을 실제로 넘겼다. 이 포함 관계 검사는 그대로 유지하고
분할·예약·최종 배치의 소비 경로를 추적해 구현에서 해결한다.

원본과 독립 Print의 Native 선택 쪽을 새로 출력하고 review/overlay를 직접 열었다.

| 입력 | 쪽 | TSV 관용 일치율 | 이진화 원값 | 직접 판독 |
| --- | ---: | ---: | ---: | --- |
| `issue6172/2599643_port_call_form.hwp` | 1 | 95.19569% | 95.19569% | 표 흐름은 대응하지만 신청 번호 상자의 크기·글리프 차이가 남음 |

두 행의 원본 전체 쪽수는 각각 1/64쪽이고 Print와 같다. sample16의 선택 1쪽을
전체 64쪽 통과로 보고하지 않는다. Native 점수 통과를 fresh WASM·확대 판독 완료로
대신하지 않는다. PNG 재사용으로 산출한 TSV 명령은 실제 exit 0이다. 최초 PNG 실행의
detached 부모는 exit를 수집하지 못했으므로 산출 manifest의 `complete`와 exit 관측 부재를
원장에 각각 기록했다. 이전 실행을 완료했다고 가정하거나 같은 작업을 중복 시작하지 않았다.

새 대표 PNG는 [실패 원본의 Native 대조](../pr/assets/issue7642-failed-regression-diagnostics-20261012/README.md)에
보존한다. 두 입력의 실제 출력 차이를 보정하기 전에는 정상 회귀의 기대값·골든을 갱신하지 않는다.

## 전체 회귀 종료와 탭 폭의 1차 보정

Stage 143 전체 실행은 exit 100으로 종료했다. 실제 summary는 `10255 tests run:
10207 passed (12 slow), 48 failed, 45 skipped`이며 테스트 실행 시간은 707.458초다.
빌드·선행 gate 대기 시간을 테스트 실행 시간으로 보고하지 않는다. 생산 source 해시는 실행
전후 일치했다. 새 검사 44개의 실제 PASS와 48개의 실패 함수·원본 후보를 각각 ignored
`stage144-current-new-tests-audit.json`, `stage144-full-regression-result.json`에 보존했다.

종료 및 Cargo/Rust 프로세스 부재를 확인한 뒤 전체 폭 측정에도 자리표 필터를 적용했다.
실제 저장 폭·점끌기·뒤 탭 순번을 유지하면서 누락 폭만 기본 정지에서 계산한다. Native 빌드는
exit 0이며 생산 source 해시가 빌드 전후 일치한다. 바이너리 SHA-256은
`be990687ed7ca512c393d8d1e53f0ecad957193e6bf00e4d1d6f732ce4127192`다.

| 원본 | 전체 쪽 | Native 최저값 | 실제 종료 |
| --- | ---: | ---: | --- |
| `issue1892_hwp3_tab_roundtrip.hwp` | 1 | 93.91816% | 원본 출력 및 PNG 재사용 TSV 모두 exit 0 |
| `hwp3-table-cell-order.hwp` | 1 | 98.85144% | exit 0 |
| `hwp3-table-grid-gap.hwp` | 3 | 98.39623% | exit 0 |

같은 원본·독립 Print에서 총 5쪽을 확인했고 이 쪽들의 색상 경계 보정 픽셀은 0이다.
탭 원본의 이전 고정 source `68d8bf777f` 결과 82.43006%에 비해 개선됐다.
새 전쪽 review를 직접 열었다. 경찰서장·교도소장·구치소장 시작은 독립 Print에 가까워졌지만
`귀하`의 시작과 하단 `(인)`, 원형 글리프 차이는 남아 있다. 점수 통과와 이 차이의 해소를
구분한다. 측정의 자연 줄 원점과 오른쪽 정렬 뒤의 배치 원점에서 기본 정지를 재계산하는
경로를 다음 보정 대상으로 추적한다. helper 호출의 일치만으로 공통 결과가 완성됐다고
판정하지 않는다.

원본/PDF 해시·명령·실제 exit·전체 쪽 TSV는 `stage144-tab-preflight/receipt.json`에 있다.
이 Native 보정만으로 fresh WASM·최종 전체 회귀·시각 검증 완료 또는 PR 준비 완료를
주장하지 않는다. 새 렌더링 회귀·골든은 아직 추가하거나 변경하지 않았다.
새 [탭 원본의 Native review](../pr/assets/issue7642-placeholder-tab-20261012/README.md)를 보존한다.
