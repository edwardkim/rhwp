# 정렬 기준 충돌의 원본 레코드 대조와 전체 Rust 환경 보완

Issue: #7642

## 독립 원문 레코드

정렬 진단의 `all_x`, `bare_matrix`, `bare_pile`, `two_bare` HWP에서
첫 `EQALIGN{a &= 1 # longword &= 2}`의 EQEDIT와 CTRL_HEADER 원문 바이트를
CFB/레코드 단위로 대조했다. 스크립트만 아니라 속성·글자 크기·기준선·
미지 필드·버전/글꼴 문자열과 공통 개체 속성까지 각각 byte 동일하다.
EQEDIT SHA-256은
`02b84adda2fe2ef8edc680e105ce4fc00abf1e682f23bd502f608586206e599e`,
CTRL_HEADER는
`d01e8a7fbb9599a0a12d6ee04c61048f1be4ca683526eca6ff684b38eadd53e7`다.

그러나 기존 독립 Print에서 전자/후자의 행별 열 원점은 서로 달랐다.
이 차이를 수식의 새로운 attribute나 미지 비트로 설명할 근거는 없다.
문서 ID·후속 빈 MATRIX의 존재를 renderer 조건으로 추가하지 않는다.
정렬 원인의 현재 범위는 여전히 미검증이며 카탈로그/구조의 미달은 유지한다.
이 비교는 한컴의 정상 정렬 규칙을 아직 확정하지 않는다.
원문·메타데이터·레코드 해시는 ignored `stage279-*`에 보존했다.

## 전체 Rust 검증과 원본 자료 연결

Stage275 전체 nextest는 실제 10,260개 검사 실행 단계로 진입했다.
미완료 실행 중 실패에는 저장소의 skill·template 등 sparse 경로 부족이 포함됐다.
실제 회귀와 경로 부족을 구분하며 최종 실패 수는 terminal summary로 확정한다.
같은 테스트를 PASS시키려고 assertion이나 baseline을 변경하지 않았다.

review worktree의 모든 추적 자료 경로를 canonical main의 실물 경로와 대조했다.
Rust source는 이미 완전하며 수정하지 않았다. 없는 추적 자료 26,436개는 동일
원본을 참조하도록 연결했고 아직 제공되지 않은 추적 입력은 0개다.
기존 자료를 덮어쓰거나 삭제하지 않았다. 원본 해시는 검증 기록에 연결한다.
`template`도 보완했다. 이미 실패한 환경 항목은 현재 실행 종료 뒤 다시 검사한다.
새 Source269 코드는 9월 HWP/HWPX·10월 원본 전체 Native를 통과했지만
fresh WASM·확대·새 정식 관계 회귀·전체 Rust/lint·PR 단계는 아직 미완료다.
