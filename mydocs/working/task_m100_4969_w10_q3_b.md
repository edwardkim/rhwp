## 판정

Q3-B는 **qualified**다. Q3-A가 고정한 네 red 원인을 standalone shaper와 Q2 transaction의 한 canonical
instance 경계에서 해소했다. explicit default와 빈 요청은 같은 effective instance가 되고, 서로 다른 instance는
mutable rustybuzz face와 result cache identity를 공유하지 않는다. 이 연결은 dormant measurement까지만 도달하며
layout publication, replay payload, backend selector와 공개 API를 열지 않았다.

제품 caller는 계속 빈 variation vector만 전달한다. 따라서 Q2 기본 조판·render JSON·page sidecar의 기존 출력은
변하지 않는다. Q3-C 전에는 variable instance가 제품 paint/backend로 전달되지 않는다.

## canonical instance와 owner 정정

1. exact face의 `fvar` model로 요청 축을 검증하고, `-0.0`을 정규화한 뒤 default와 같은 coordinate를 canonical
   vector에서 제거한다.
2. 빈 요청, explicit `wght=400, opsz=400`, partial default와 축 순서 permutation은 같은 settings identity를
   사용한다.
3. shaping 전에 face의 **모든** `fvar` 축을 default로 복원한 뒤 canonical non-default 좌표만 적용한다. Title 뒤
   default, `wght`-only 뒤 `opsz`-only 순서에서도 앞선 좌표가 누출되지 않는다.
4. transaction은 exact source의 digest 검증과 immutable `ttf_parser::Face` 준비를 source마다 한 번 수행한다.
5. mutable rustybuzz face key는 `(exact source handle, canonical variation vector)`이고, result cache key에도 같은
   canonical vector가 포함된다.

unknown axis, NaN, out-of-range와 17-axis 요청은 실제 transaction 경로에서도 각각 `variationAxisUnsupported`,
`variationValueNonFinite`, `variationValueOutOfRange`, `variationAxisLimitExceeded`로 닫혔다. rejected 요청은 instance
face나 result cache entry를 만들지 않았다.

공식 `HappinessSansVF.ttf`의 다섯 effective instance를 pure Hangul `가변`과 Latin non-ligature

| instance | wght | opsz | Hangul px | Latin px |

두 문자열 모두 instance 사이 glyph id는 유지됐고 settings identity는 5개로 분리됐다. 이 결과는 variation이 모든
문자열에서 반드시 폭 차이를 만든다는 주장이 아니다. 같은 exact glyph identity에서도 axis 조합에 따라 advance가
달라질 수 있으므로 cache와 replay가 effective instance를 소유해야 한다는 공개 fixture 증거다.

## 1/2/8 ownership·성능 참고치

`1/2/8 instance × 1/2/8 repeated run` 전 조합에서 다음 회계가 성립했다.

```text
prepared exact source = 1
parsed mutable faces = unique effective instances
result cache misses = unique effective instances
result cache hits = instances × (runs - 1)
result cache entries = unique effective instances
```

초기 구현은 cache hit 전에도 1.5 MB source의 SHA-256 검증과 SFNT parse를 반복해 matrix 단일 테스트가 약
1.455초 걸렸다. source preparation을 transaction-local 1회 owner로 분리한 뒤 같은 테스트는 약 0.230초로 줄어
약 84.2% 감소했다. 이는 warm test harness의 구조 비교 참고치이며 페이지 조판 성능이나 릴리스 SLA로 해석하지
않는다. 최종 9-test shadow target은 nextest 내부 시간 0.239초였다.
