# #7642 일반 괄호의 한컴 glyph 연결과 큰 상수 배열 보정

## 변경 근거와 범위

[계획](../plans/task_m100_7642_literal_delimiter_20261017.md)에 따라 일반 `(`/`)`을
기존 한컴 glyph 선택의 Operator 경로에 연결했다. 같은 경로가 실제 PUA·전진·기준선과
표시 face를 보존하므로 폭만 한컴에서 가져오고 다른 글꼴을 그리던 차이를 제거한다.
표시 source glyph는 독립 Print의 U+E044/U+E045, 전진은 설치 프로그램의 398/1024다.
사설 글꼴 파일·윤곽을 추가하지 않는다. 명시적인 확장 괄호와 공개 수학 face는 기존
각 경로를 사용한다. HancomEQN의 미지원 PUA 메트릭은 기존 fail-closed 반환을 유지한다.

같은 batch에서 HancomEQN의 큰 전진폭 배열을 `const`에서 `static`으로 옮겼다.
수치·조회 함수는 그대로며 경고 허용을 넣지 않았다. stage2089 native Clippy의
실제 `large_const_arrays` 실패를 보정한다. 이전 source의 prepare·fmt는 exit 0,
native Clippy는 exit 101이며, 나머지 lint는 그 실패 뒤 실행하지 않았다.
전체 lint 성공으로 쓰지 않는다.

## 검증 상태

현재 단계는 source 보정이며 새 Native/fresh WASM 재출력 전이다. 이전 producer의
전쪽 TSV를 이번 변경의 결과로 재사용하지 않는다. 같은 원본·PDF와 변경 영역의
실제 glyph·앞뒤 내용·devel 대비 하락을 다시 확인해야 한다. 새 관계 회귀와 px 핀,
기존 golden·기대값·허용치는 이번 단계에서 바꾸지 않았다. PR 준비 완료가 아니다.
실행 중인 이전 source의 전쪽 검증은 해당 source 증거로 계속 보존한다.

ignored stage2089-current-lint의 실제 명령·exit·로그와 stage2088의 독립 Print
관측을 근거로 사용했다. 후속 빌드와 시각 결과는 새 source SHA로 별도 기록한다.
