사용하지 않았다. 로컬 family `RHWP Hancom Legacy Equation`을 사용자 글꼴로
등록하고 `fc-match`의 실제 파일을 확인했다. 사설 글꼴은 Git에 포함하지 않는다.

반복 가능한 생성·복원은 `scripts/prepare_legacy_equation_font.py`로 제공한다.

최초 Native182 안은 별도 표시 출처 봉인을 두었으나 최종안에서는 제거했다.
표시 세대는 `version_info`·`font_name`의 의미이며 런타임 캐시 출처가 아니다.
봉인을 두면 JSON 왕복이나 같은 글꼴 이름의 대소문자 변경 후 표시가 달라질 수 있다.

## COL 문법의 독립 대조와 수정 계획

2910의 50개 Print 대조군은 총 6쪽이며 같은 Windows 2020 Print 계약을 충족한다.
추출 시 수식 윗부분이 문단 label보다 위에 있으므로 label 사이를 단순 절단한 최초
진단은 폐기했다. 원본 PDF를 보존하고 label과 글리프의 실제 y 범위를 확인해
2911을 다시 산출했다. COL은 행렬 안에서만 유효한 명령이 아니며, 단독 `col {a#bb}`도
정상이다. LCOL/RCOL은 좌·우 정렬을 바꾸고 MATRIX의 선두 열은 뒤 COL들과 열
구성을 이룬다. 열 사이 &/#나 일반 항은 오류다. 따옴표의 coll은 문자로 남는다.

따라서 문맥 밖 COL을 숨기는 계획은 사용하지 않는다. 누락된 COL/LCOL/RCOL의
명령 경계와 필수 중괄호 인자를 보정한다. 잘못된 열 명령은 현대에서는 앞 항을
보존하며 입력을 중단하고 구형에서는 전체 수식을 무효화한다. 이는 저장 너비나
문서 ID의 예외가 아니다. 기존 `a7e73168f4`의 MATRIX 선두 PILE과
`eea6977663`의 구조 인자 오류 계약도 함께 보존한다. 표시 유효성과 저장 상자의
흐름 점유는 분리하며 빈 AST 때문에 원래 저장 상자를 지우지 않는다.

`document_script::parse(Equation)`이 표시 세대를 공통 파서에 전달하고 흐름 측정·
문단/표/분할 표/떠 있는 수식의 실제 배치가 이를 소비하도록 연결한다. 속성이 없는
신규 UI 미리보기와 OLE Contents 스크립트는 기존 현대 문서 계약을 유지한다.
정상 COL·인자 오류·따옴표·MATRIX 열 소유·기존 PILE을 한꺼번에 보정한 뒤
동일 동결 생산물에서 독립 대조군과 원본 영향 페이지를 함께 확인한다.

## COL 공통 파서 보정의 실제 결과

Native184는 동일 target·빌드 잡 8에서 249.87초에 성공했다. 파일 속성이 있는
수식의 파싱을 `document_script::parse`로 통합했다. 신규 UI/속성 없는 OLE의
현대 계약은 유지했다. 독립 Print의 COL/LCOL/RCOL·필수 인자·선두 열 목록 오류를
반영했으며, 기존 MATRIX 선두 PILE 분기는 유지했다.

2913의 실제 공개 문서 로드·RenderTree 진단은 Print와 같은 50개 수식을 같은
순서로 생성했다. ASCII 문자·숫자·더하기의 내용과 순서를 대조한 2918은 49개가

이 대조를 모두 통과했다고 쓰지 않는다.

2914의 원본 HWP/HWPX는 각각 115쪽 모두 raw 90% 이상, 최저 97.23352%다.
Native183 대비 76쪽만 각각 0.24517%p 개선했고 나머지 114쪽씩은 점수가 같다
(2921). 2916에서 첫 잘못된 수식의 실제 LayoutKind는 Empty이며 저장 bbox의
원점·4.48×16px 점유는 이전과 같았다. 출력을 문서 ID나 너비로 숨긴 결과가 아니다.
76쪽의 최신 공식 review·standalone overlay를 함께 직접 판독했다(2920).
중복 표시는 제거됐으나 P=460·C_L 등의 폭·첨자·간격 차이는 남아 있다.

HWP3 대조군 64쪽은 Native183과 페이지별 raw가 모두 같고 최저 96.96972%를
유지했다(2915). 기존 수식·편집·OLE·문서 경계의 정식 회귀 38개가 모두 통과했다
(2917). 새로운 렌더링 회귀나 기대값·허용치 변경은 추가하지 않았다.

구형 평문 반례는 여전히 82.15278%이며 현대 대조군은 97.54158%다. 새 문법
대조군의 전 6쪽 최저는 46.87256%, 앞선 유효성 대조군 전 2쪽 최저는 72.62905%다.
둘 다 저장 상자를 크게 지정한 합성 입력에서 구형 글리프의 표시 원점·예약 프레임
차이를 드러낸다. 문법 내용의 개선과 시각 완료를 구분하고, 이 입력들을 정식
렌더링 회귀의 완료 fixture로 추가하지 않는다. 아직 fresh WASM과 전체 필수
검증도 남아 있으므로 PR 준비 완료가 아니다.

공식 수식 revision 1.3 PDF의 MATRIX 설명은 COL/LCOL/RCOL의 열 정렬 문법을
제공한다. 필수 인자 오류의 표시 세대 차이는 사양에서 추정하지 않고 2910의 독립
Print로 확인했다. 기존 2869 원문/ASCII 공백 제거의 글리프 원점을 직접 다시
추출한 2919도 보존했다. 고정 너비에서 마지막 원점은 같지만 중간 괄호·그룹
원점이 달라, 하나의 무근거 가로 배율이나 ASCII 공백 일괄 표시로 보정하지 않는다.

## WASM050과 독립 좌표 진단

`89629de404`의 standard release WASM050은 빌드·최적화·패키지 동일성 검증을
926.21초에 완료했다. 원본 HWP/HWPX 각각 115쪽, 합계 230쪽의 fresh Canvas
전쪽 raw는 최저 97.25234%이며 모두 90% 이상이다(2925·2927). Native184의
같은 원본 최저는 97.23352%다. 이 증거는 해당 소스 snapshot의 결과이며 이후
보정을 포함한 최종 PR head의 검증으로 바꾸어 표시하지 않는다.

2924에서는 글자·그룹·너비·높이·크기·COLOR/닫힘을 분리한 100개 독립 대조군을
한컴 2020 Print로 출력했다. 빈 버전은 정상 COLOR 인자도 표시하지 않지만
Version 60은 표시한다. 구형은 COL의 닫는 중괄호가 없어도 전체 표시가 사라지며,
현대는 이미 읽은 내용을 유지한다. 백슬래시로 보호한 coll은 두 세대에서 표시된다.
따라서 legacy tokenizer의 명령 사전을 분리해 COLOR를 COL보다 긴 현대 명령으로
보호하는 조건을 세대에 맞추고, 구형 COL의 닫힘을 파싱 전에 확인한다. 버전 없는
공개 호환 파서·신규 미리보기의 현대 계약과 따옴표·백슬래시의 문자 소유는 유지한다.

2930의 독립 영문·숫자 62자×1/2/3회 반복은 186개 모두 정확한 문자 수로
인쇄됐다. 2932는 원점 간격과 저장 너비에서 root 여백 대비 논리 전진의 비율을
계산했다. 2회/3회 비율 차이의 최댓값은 0.00965 이하다. 여백의 절대 em 값이나
글리프 d1 전진과의 동일성은 이 측정만으로 단정하지 않는다.

2934는 제품을 바꾸지 않고 실제 공개 Native paint에 이 비율의 가로 원점 가설을
적용한 진단이다. 무변경 경로 9쪽은 공식 Native184 내보내기와 RGBA가 전부
같았다(2937). 같은 독립 Print의 전쪽 raw는 기존 35.92655%에서 진단 최저
39.84305%이며 완료 기준에 미달한다(2935·2936). 가로 위치는 가까워졌지만
2938의 공식 합성 함수 review·overlay를 함께 직접 판독하니 첫 문단 뒤 세로
위치와 페이지 끝 문단 소속도 달랐다. 첫 쪽 Native는 C21까지, Print는 C20까지다.
따라서 글자 메트릭의 추정값만 제품에 넣지 않고 첫 문단의 흐름 점유도 추적한다.
기존 186개 입력·실패 근거를 보존하며 다른 대조군 통과로 원본을 대체하지 않는다.
이 자료는 정식 회귀나 시각 완료 증거로 승격하지 않는다.

## Native185 문법 완료와 첫 문단의 흐름 원인

COLOR 사전과 닫히지 않은 COL 보정을 함께 동결 Native185로 검증했다. 빌드는
성공했고 기존 정식 수식·편집·OLE 회귀 38개가 모두 통과했다(2941). 기존 50개
문법 대조의 문자 내용·순서가 전부 Print와 같아졌고(2945), 추가 COLOR·빈 열·
닫힘 누락·백슬래시 문자 전환 16개도 전부 같았다(2946). 이것은 문법의 검증이며
앞서 남긴 구형 배치 미달이나 fresh WASM 최종 head 검증을 면제하지 않는다.

2940의 실제 모델 덤프에서 첫 문단의 컨트롤은 SectionDef·ColumnDef·Equation,
그 다음은 Equation뿐이다. 첫 세 문단의 줄 높이와 기준선은 각각 2,200/1,760 HU로
같지만 첫 문단 line_spacing은 720 HU, 뒤 문단은 1,320 HU다. 첫 문단의 다음
VPOS가 2,920 HU인 것도 이 합계와 같다. 독립 Print의 첫 label 간격은 약
46.83px이며 3,520 HU의 약 46.93px와 대응하고, 2,920 HU의 약 38.93px와 다르다.
따라서 가로 글리프 진단의 점수만 보고 x 변환 가설을 완료하거나 폐기하지 않는다.

생산 경로는 `reflow_paragraph* → publish_regenerated_rows → refresh_rows →
frame_metrics_for_line → replace_line_segs`다. 공통 publisher는 컨트롤 전체가
TAC Equation일 때만 진입하므로 구역·단 메타데이터를 함께 가진 첫 문단이
제외된다. 원래 조합 단계의 글자 기준 leading 720이 남는 반면 뒤 문단은 실제
`affect_line_spacing` 수식 상자를 소비한 leading 1,320으로 발행된다. 실제 줄
소속·텍스트/개체 합집합은 이미 refresh_rows가 계산한다. 후속 보정에서는 이
공통 결과를 구조 메타데이터가 함께 있는 같은 수식 줄에도 소비시킨다. 그림·표·
다른 흐름 개체를 수식으로 간주하거나 첫 문단에 고정 px를 더하는 방식은 쓰지 않는다.

첫 문단 보정 전에 기존 `0f27a861f9`(혼재 줄의 공통 메트릭 발행)와 `ce086e386a`
(줄간격 참여와 반복 재조판 보존)의 실제 diff를 다시 대조했다. 공통 계산 자체를
복제하지 않고 publisher의 자격 조건만 바로잡는다. TAC 수식이 하나 이상 있고
그 밖의 컨트롤은 SectionDef·ColumnDef·Bookmark인 문단을 허용한다. 이들은
선언·위치 표지이며 글줄의 별도 점유 개체가 아니다. 그림·표·양식·떠 있는 수식과
다른 컨트롤은 기존대로 이 경로에 합치지 않는다. 수식 없는 구조 문단도 제외한다.
실제 높이·기준선·leading과 줄 소속은 기존 refresh_rows 결과를 그대로 소비한다.
수정 후 같은 186개 입력의 원본 모델·쪽 소속과 Native paint 진단을 재확인한다.

## 첫 문단 공통 발행 보정의 결과

Native186은 238.98초에 성공했다. 실제 모델의 첫 세 문단은 줄 높이 2,200 HU,
line_spacing 1,320 HU로 같아졌고 VPOS는 0→3,520→7,040 HU다(2948).
기존 정식 회귀 38개가 모두 통과했다(2949). 현대 수식 3개를 넣은 별도의 정상
대조군은 같은 독립 Print 대비 Native185 49.17444%에서 Native186 100%로
개선됐다(2956). 새 review·standalone overlay를 함께 직접 판독했고 첫 문단 뒤
간격과 세 문단의 실제 표시를 확인했다(2957). 임의 좌표 이동 없이 공통 줄
메트릭의 발행을 재사용한 결과다.

원본 HWP/HWPX 전 230쪽의 Native186 최저는 97.23352%로 모두 90% 이상이며,
Native184와 모든 페이지의 raw가 같다(2958·2960). 이 검증은 Native186의
실제 제품 출력이다. 별도의 구형 영문·숫자 186개 입력의 실제 제품 출력 최저는
35.92655%에서 70.42352%로 개선됐으나 여전히 미달이다(2951).

같은 입력에서 글리프 원점 가설을 공용 Native paint에 적용한 진단은 전 9쪽 최저
99.98690%이며 나머지 8쪽은 100%다(2953). 이 변환은 아직 제품 코드에 없다.
제품의 구형 수식이 99.98690%가 됐다고 쓰지 않는다. 독립 100개 대조군 중
실제 LayoutKind가 선형 문자이고 명시적 그룹이 없는 44개를 교차 대조했다.
너비·높이·글자 크기·대소문자 혼재와 ASCII 공백이 다른 입력에서 x 원점 최대
오차는 0.82987px다(2959). 이는 다른 파일의 좌표 계약 대조이며 전체 시각
통과나 회귀 추가 선행 조건을 대신하지 않는다. OVER 등 구조 명령은 원문이
ASCII여도 문자 행으로 취급하지 않았다. 그룹 경계를 지운 채 같은 변환을
복합 수식에 적용할 근거도 없으므로 명시적 그룹·기호·첨자의 프레임 소유를
공통 결과로 보존하는 보정을 계속한다. 최신 제품의 fresh WASM과 전체 필수
검증·정식 회귀 추가는 아직 완료하지 않았고 PR도 생성하지 않았다.

## 구형 공통 좌표 평면의 구현 계획

2962의 명시적 그룹·기호·첨자·분수 112개와 2964의 빈 그룹·크기 보호·글자처럼
취급·줄 범위 22개를 각각 한 번의 독립 한컴 2020 Print로 출력했다. 이전 독립
62자 반복과 별도 44개 교차 대조를 함께 사용한다. 대상 PDF의 수식을 잘라
구현 정답으로 쓰거나 문서 좌표를 상수로 넣지 않는다.

구형 parser는 명시적 중괄호의 Group 소유를 AST에 남긴다. 기존 자연 배치의
분류는 그룹 본체를 소비해 기존 기호·기준선 계약을 유지하며, 좌표 평면에서는
명시적 Group과 일반 Row를 구분한다. 현대·공개 호환 파서의 AST는 바꾸지 않는다.
선형 문자 평면부터 기존 입증된 원점 계약을 실제 공통 EqLayout 결과로 연결하고,
같은 단계에서 그룹·복합 구조의 소유와 독립 Print 차이를 계속 보정한다. 선형
문자 통과를 원본 76쪽 복합 수식의 완료로 대신하지 않는다.

표시 글리프의 자연 크기·기울임과 논리 전진을 분리한다. 독립 문자 반복에서
얻은 root 여백 대비 전진으로 논리 프레임을 만들고, 절대 너비를 가진 선언
프레임에 글리프 원점을 배치한다. 글리프를 가로 확대하지 않는다. 일반 Row와

font_size·baseline·y는 그대로 유지했다. 명시적 빈 그룹도 뒤 문자 전진을 예약한다.
생산 경로는 `EqParser의 Group/Row → Plan의 경계·전진 → LayoutBox.width와
HancomGlyphs.positions → Native/Canvas`다. 한 backend만의 좌표 보정은 추가하지 않았다.

첨자 128개는 3023/3024에서 실제 공통 tokenizer·parser 소스를 각각 컴파일해 대조했다.
표시 세대만 진단용 metadata 객체로 주입했고, 실제 파일 metadata 판정·렌더링은
정식 제품에서 별도로 확인한다. 구형 위첨자는 뒤 아래첨자를 인자 내부로 소유한다.
일반 `a_b^c`의 병렬 슬롯과 명시적 기저 `{a}_b^c`의 중첩도 구분한다. 첨자 인자의
중괄호와 새 기저 그룹을 혼동해 `a^{b}_c^d`의 d를 한 단계 더 줄이지 않는다.
새 재귀 경로에도 깊이 상한을 적용했다. 구형 64개는 모두 Print의 문자별 크기 단계와
맞고, 현대 64개의 AST는 보정 전과 같다. 이는 파서 소유 진단이며 전쪽 시각 통과나
새 정식 회귀의 선행 증거를 대신하지 않는다.

그룹·첨자 보정을 함께 고정한 다음 Native190으로 실제 파일 경로, 기존 계약과 전체
원본을 재검증한다. 글꼴 명령의 논리 여백·구조 연산자·복합 수식 가로 배치가 아직
끝난 것은 아니다. 3022의 진단 고득점을 원본 P=460 수식의 완료로 바꾸어 보고하지 않는다.

### Native190의 실제 검증 결과

Native190은 공용 target·빌드 잡 8에서 241초에 성공했다. 실제 원본 파일 경로로
확인한 기존 계약 47개가 모두 통과했고, HWP/HWPX 각 115쪽의 Native 최저는
97.23352%다. 230쪽의 raw는 이전 Native189와 모두 같다(3037 보존 비교).
현대 실제 대조군 세 개도 100/99.68240/99.56633%로 유지됐다.

256개 그룹 입력의 정식 Native 출력 22쪽은 최저 99.98077%다. 22쪽 전체의
디코딩한 RGB 픽셀이 3021 진단과 동일함을 3036에서 확인했다. 새 2쪽 review와
standalone overlay를 함께 열어 문자 순서·기준선·그룹 뒤 공백을 직접 확인했다.
이후 fresh WASM 선행 조건을 채우기 전에는 이 입력을 새 정식 fixture/회귀로
등록하지 않는다. 진단용 문단 높이에서 나온 프레임 경고도 정상 자료로 감추지 않는다.

3035는 실제 파일 metadata를 읽은 Native189/190의 128개 표시 트리를 대조했다.
구형 64개는 모두 독립 Print의 문자별 첨자 크기 단계와 맞고, 이 중 30개가
수정 전과 달라졌다. 현대 64개의 전체 LayoutBox는 동일하다. 다만 첨자 대조군의
전쪽 Native 최저는 81.90601%이며, 글꼴 전환 대조군도 77.28604%다. 인자 소속의
보정이 가로 배치·전체 시각 통과를 대신하지 않는다. 새 회귀·기대값을 등록하지 않았다.
추가한 재귀 경로는 128/512/1024회 부착 인자 진단도 정상 종료했다(3034).
이것은 새 결함을 검출하는 정식 회귀의 수정 전 FAIL 증거로 표시하지 않는다.

### 다음 가로 구조 분석의 독립 근거

3031의 두 독립 Print는 한컴 2020 11.0.0.9136·Print method 0·전처리 없음이다.
짝이 맞는 괄호 240개, 20쪽의 job은 `872de839-7e08-4855-a134-4daf12c2075b`,
완전한 연산자 피연산자 232개, 20쪽은 `b3b04ddb-1dfb-43e4-8f99-65cb579678d7`다.
3032는 472개 label·글리프·행렬을 대응시켰다. 짝이 맞지 않는 괄호 반복과 단독
구분자를 일반 문자 전진의 근거로 쓰지 않는다. 기존 2989의 괄호 반복 피팅은
완전한 괄호식의 메트릭으로 채택하지 않는다.

3037의 너비 쌍 대조에서 완전한 괄호식은 앞·뒤 전진과 글리프 원점을 따로
소유한다. `(xx)`와 `(xx)^2`, `(xx_x)`의 내부 여백도 같다고 가정할 수 없다.
`left (xx right)`와 일반 `(xx)`의 관측도 연결했다. 이를 현재 파서의 노드 이름만으로
구분하지 않고 실제 괄호 소유·내부 구조와 대조해 다음 공통 평면에 반영한다.
현재 기록은 무차원 전진의 분석 자료이며, 픽셀 보정 상수나 정식 기대값이 아니다.
원본 P=460 수식의 괄호·연산자·첨자 가로 배치, 새 source의 fresh WASM과
원래 전체 범위의 필수 검증은 계속 남아 있다. PR 생성 대기 지시도 유지한다.
