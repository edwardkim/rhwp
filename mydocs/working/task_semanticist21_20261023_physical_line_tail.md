# 표 조각의 내용 수용과 글줄 뒤 간격

Issue: #4138, #1949. 시작 head `b455d57065`, 기준 base
`d9fd85ed5bc3c4d9ce6b2981422e48bf9bb90867`.

## 선행 분석

이전 수식 단계의 새 API 저장본과 이전 저장본은 한컴 Print 전쪽 196쪽이
같은 배율에서 RGB까지 같다. Native148은 아직 197쪽이다. 원본 HU 여백과
기존 100HU inset으로 계산한 내용 예산에서 마지막 글줄 상자와 뒤 간격을
나누면 초기 23개 컷 중 21개를 설명한다. 나머지 두 곳은 실제 빈 글줄의
뒤 간격이 유닛에서 0으로 발행되어 생기는 차이다.

기존 내용/빈 종료 띠 분리 `cd8b307a24`는 교육과정 일반 격자의 내용 수용과
걸침 종료 띠를 동시에 보호하려 했다. 이후 #8101 보정 `247791e111`은
noAdjust 여부에 따라 종료 inset을 0/100HU로 공통 생산한다. 원 수정은
`1cf3b879b61a9f8fd00a6b1aa0aac85a2c588033`, 통합 PR은 #8148이다.
현재 실제 입력·서식 차이를 유지하면서 이 두 계약과 글줄 뒤 간격을 함께 검토한다.
번호 #8101은 PR이 아니라 이슈이며, 실제 원문·통합 경로는 ignored
`issue8101-frame-provenance-2339.json`, `commit247791-frame-pulls-2339.json`에 있다.

수정 전 Native148에서 `rowbreak_short_row_whole_carry`,
`issue_7518_reflow_row_physical_frame`, `issue_7470_rowbreak_source_frame_ownership`
전체 52건은 51 PASS / 1 FAIL이다. 실패는
`rows_inside_a_crossing_rowspan_still_split_after_one_line`이다. 기존 실패와
후보가 새로 만드는 실패를 구분하며 기대값은 변경하지 않는다.

## 후보 구현과 반증 범위

- 조판이 생산한 일반 글줄의 뒤 간격은 수용할 마지막 줄 상자의 바깥 전진이다.
  유효한 빈 글줄도 실제 상자와 뒤 간격을 구분한다. 겹침 spacer·접힌 줄·개체 띠를
  일반 글줄 간격으로 추정하지 않는다.
- 물리 밴드의 컷은 같은 마지막 상자를 소비한다. 문단 끝 여부나 재생성 여부만으로
  뒤 간격 전체가 들어가야 글자를 받는 별도 예산을 만들지 않는다.
- 현재 조각의 바깥 프레임은 같은 소유자가 측정·컷·paint에 전달한다. 멀리 있는
  그림 때문에 행 전체가 순수 텍스트가 아니라는 이유로 현재 조각의 바깥 위 여백을
  예산에서 생략하지 않는다. 중첩 viewport의 독립 예산은 유지한다.
- noAdjust·기존 저장 본문 프레임의 차이는 같은 공통 경계에서 유지한다.
  단독 셀/일반 격자의 행·열 개수만으로 내용 하단을 달리하는 가정은 위 세 수정과
  함께 실행으로 검토한다. 모든 격자에 무조건 맞는다고 미리 판정하지 않는다.

한 번의 Native 후보 빌드 뒤 위 52건과 #8101 3건, 기존 35문서/66쪽 대조군,
현대 수식, 원본 115쪽의 영향 경계, 새 API 저장본의 첫 24쪽 경계를 확인한다.
새로 후퇴하는 경우 기대값을 고치지 않고 공통 원점·상자·간격 소비 경로를 재분석한다.
196쪽 전체 Native/fresh WASM와 직접 판독을 완료하기 전에는 정식 새 회귀나
197쪽 기대값 변경·PR 제출을 진행하지 않는다.

## Native149의 반증과 다음 보정

빌드는 239.57초, 종료 코드 0이다. 35문서/66쪽 대조군은 모두 raw 100%·쪽수
일치다. 원본 영향 경계 6쪽, #7840 전체 9쪽, 현대 수식 7쪽도 기존 점수·쪽수를
유지했다. 두 API 저장본의 bytes는 이전 `bfb7a5e5...`와 같아 같은 Print를 사용했다.
걸침 셀의 기존 실패는 통과했지만, 물리 계약 전체 55건은 52 PASS / 3 FAIL이다.
새 실패는 자식 표의 첫 조각에 UNIT 018을 한 개 더 수용한 세 검사다. 한컴 Print는
그 조각에 UNIT 000..017을 두므로 기대값은 유지한다. 바깥 페이지 컷의 뒤 간격
분리를 자식 viewport의 전진 원장에도 적용한 것이 적용 범위의 오류다.

#4138은 26~28쪽이 raw 100%로 개선됐지만 15쪽이 59.08734%로 후퇴했다. 새 로그의
14쪽 끝 컷은 542로, 한컴이 수용한 빈 문단 유닛 542를 다음 쪽으로 넘겼다.
그 빈 문단의 실제 LineSeg는 높이 1200HU·간격 720HU이고, 다음 저장 원점과의
차이가 1920HU다. 기존 `stored_empty_successor_advance`는 이 전체 전진을
정확히 발행하지만 줄 상자/뒤 간격 정보는 잃어 유닛의 following을 0으로 만든다.
따라서 유닛 생산부의 보이는 글자 조건만 제거해도 해결되지 않는다.

다음 보정은 원본 빈 문단의 전체 전진과 뒤 간격을 같은 producer에서 함께 발행한다.
다음 저장 원점 차이가 원본 줄 높이+줄간격+양쪽 문단 간격과 정수 HU로 일치할
때만 뒤 간격을 분리한다. 동시 원점·별도 띠의 전체 전진은 그대로 유지한다.
기존 측정·paint는 이 공통 결과의 전체 전진을 계속 소비하며, 컷은 같은 결과의
뒤 간격을 사용한다. helper 이후 Square/float spacer 필터도 두 값을 함께 걸러
전체 전진은 무효인데 뒤 간격만 남는 경로를 만들지 않는다.
자식 표의 수용량은 부모 원장에 넘길 기존 전진 계약을 유지하고, 바깥 조각에서만
마지막 줄의 뒤 간격을 다음 쪽에 넘긴다. 조건은 기존 프레임 소유 정보이며 문서
번호·좌표·행/열 수 조합을 새로 추가하지 않는다.

## Native150의 실제 결과

분리한 모듈의 `VertRelTo`·`VertAlign` import를 빠뜨린 첫 빌드는 종료 코드 101이었다.
이를 보정한 두 번째 빌드는 237.37초, 종료 코드 0이다. 실패 로그를 숨기거나
첫 빌드를 성공 결과로 바꾸지 않았다. 생산 소스·library는
`char-overlap-native-build-150-result.json`에 고정했다.

- 두 셀 분할 API의 현재 저장본은 모두 이전과 같은 `bfb7a5e5...`이고, 새 CLI의
  출력은 모두 196쪽으로 독립 Print 196쪽과 일치한다.
- 관련 정식 계약은 55 PASS / 0 FAIL이다(`reviewed-contract-tests-2347-result.json`).
  원래 실패했던 걸침 셀과 Native149에서 새로 실패했던 중첩 소유 3건이 모두 통과했다.
  검사·기대값은 수정하지 않았다.
- 35문서/66쪽 대조군은 전체 raw 100%·쪽수 일치다
  (`native150-matrix-2350-summary.json`). 원본 영향 경계 6쪽·#7840 전체 9쪽·
  현대 수식 7쪽은 점수와 쪽수를 유지했다. 이는 최종 전체 검증의 대체 증거가 아니다.
- #4138의 15~20쪽은 모두 raw 100%다. 1~21쪽은 모두 90% 이상이다.
  그러나 22쪽 89.84928%, 24쪽 70.89935%, 25쪽 83.14856%, 26~28쪽과 196쪽도
  미달이어서 gate는 계속 `re_review_required`다. 쪽수 일치로 이를 면제하지 않는다.
- `issue4138-native150-critical-review-2351`의 22·24쪽 review와 standalone overlay를
  함께 직접 판독했다. 22쪽 본문 배치는 맞지만 중첩 표의 오른쪽 괘선이 부모 셀 밖으로
  표시된다. 24쪽은 그림이 문단 원점을 잃고 위쪽 본문을 덮는다. 본문 3.4.6.3 이후의
  줄들은 같은 위치라 그림 원점과 전체 페이지 흐름을 구분해 확인할 수 있다.
- 새 컷 추적을 원본 문단/줄로 대조했다(`native150-cut-comparison-2354.json`).
  첫 24쪽 경계는 한컴 재저장 프레임과 같고, 첫 내용 컷 차이는 25쪽 끝이다.
  Native는 다음을 문단 337에서 시작하지만 한컴은 문단 336부터 시작한다.
  그림의 물리 점유와 실제 원점을 다음 원인으로 추적한다.
- `cargo fmt --all -- --check`는 종료 코드 0이며 로그는
  `logs/physical-line-tail-final-fmt-2355.log`에 보존했다.

소비 경로는 새 `float_placement/empty_successor.rs`의 공통 기하 → `cell_units`의
전체 전진/뒤 간격 → 바깥 물리 컷과 자식 viewport의 서로 다른 수용 계약이다.
whole/partial 셀 paint도 같은 producer의 전체 전진을 소비한다. Square/float
spacer 필터 뒤에는 동일한 기하를 사용한다. `rowbreak_fragment_bounds`가 생산한
동일한 원점·하단을 root 행 수용과 paint가 사용하며, noAdjust와 인증 본문 프레임은
이 공통 결과에 포함된다. 새 렌더링 회귀·197쪽 기대값 변경·PR 생성은 하지 않았다.
