## 공통 보정과 독립 근거

[계획](../plans/task_m100_7642_canvas_source_sampling_20261017.md)에 따라
SFNT의 실제 PostScript 이름과 family 이름을 연결하고, 그림 축소의
실제 장치 크기가 선형 필터의 두 source 표본 범위를 넘을 때만 넓은
필터를 요청한다. 문서·쪽·좌표·점수 기준은 분기 조건에 넣지 않았다.

`stage2827`의 계측 진단은 #7970 image-count 전쪽에서 base 대비
0.01%p 이상 하락을 없앴다. 무조건 low로 바꾸는 대안은 가는 선의
대조군에 불리해 채택하지 않았다. 원 글꼴의 윤곽선·advance 대조는
HCRBatang 147개, HCRDotum 33개, Windows Batang 410개 모두
일치했다. Windows 글꼴은 비공개 로컬 검증 경로에서만 사용한다.
진단 JavaScript는 제품 수정의 통과 증거가 아니며 새 빌드로 재검증한다.

## 전체 Rust 검사의 관측값과 검사 보정

앞 source `145ea00478110948ae7add2142692527dd05c9e7`의 전체 nextest는
10,924개 중 10,901개 통과, 23개 실패, 45개 생략으로 종료했다.
ignored `output/pr-review/issue7642/failed-inputs-20261008/`
`stage15-current-validation/stage2789-full-rust-regression/nextest.log`와
`stage2836-full-rust-failure-intake/failures.json`에 실행 결과를 보존했다.

이번 묶음에서 두 실패의 검사 계약을 보정했다. HWP3 char_count 검사는
사람이 읽는 종료 문구 대신 기존 CLI의 구조화된 JSON 판정을 읽으며,
문단·셀의 char_count 차이 건수가 0인지 검사한다. 나머지 IR 차이를
없는 것으로 처리하지 않고 exit code·필드 형식도 확인한다.

passthrough 무효화 guard에는 문서 IR을 바꾸지 않는 메타파일 host font
API 두 개를 세션 상태로 분류했다. 별도 public API 검사는 등록·중복
등록·해제·재등록 전후 문서 IR과 저장 bytes 보존을 확인한다. 실물
배치의 golden이나 좌표 검사가 아니며, 기존 실패를 숨기도록 허용 수를
늘리지 않았다. 긴 기존 guard의 분류 상수만 공통 include로 옮겨 두
파일을 각각 1,000줄 이하로 유지했다. 자동 suite 수집 경로를 사용한다.
