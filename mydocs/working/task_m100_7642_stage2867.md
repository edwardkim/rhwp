## 기준 갱신과 이력 보존

최신 fetch에서 `upstream/devel`이 `515bd72dcde0eecdeece333666b675354b7fa91d`에서
`7d01ef610f378157b79d36ef23e8ed4a3c8ab051`로 전진했다.
리베이스 전 작업은 `b7712ccb3a1dec34840f8fce0867380d6a314392`에 커밋했고
로컬 `backup/7642-pre-rebase-7d01ef61`에 보존했다. 리베이스 후 head는
`35f5f90acabcb51b89ae306c52e8b84665fea922`이며 새 base 포함을 확인했다.
기존 로컬 커밋 903개를 유지했고 작업 트리는 깨끗했다.

처음에는 동시 상태 조회가 인덱스 잠금과 겹쳐 재개했다. 잠금·다른 Git
프로세스가 없고 작업 트리가 깨끗함을 확인했으며 reset이나 코드 폐기는
하지 않았다. 이후 Git 변경 명령은 진행 중인 rebase와 겹치지 않았다.

## 충돌 해소의 의미

CanvasKit import는 새 `magnificationFiltering`과 기존 수식 replay를
함께 보존했다. Native 이미지 소비는 최종 source 창과 장치 변환에서
확대 선언의 nearest/linear를 선택하고, 전체 원본의 축소 mipmap을 유지한다.
crop strict 경계와 binary·빠른 미리보기의 명시적 nearest는 다시 보간하지
않는다. 이 결합의 출력 동등성은 아직 실행 전이다.

Cargo는 기본 `wasm-api`와 opt-out 경계를 유지하며, 공통 WMF에 필요한
nonoptional resvg를 유지했다. nonoptional 의존성을 `dep:resvg`로 다시
지정하지 않았다. TOML 파싱·해당 feature 관계를 확인했고, 양쪽에서 추가한
DomMatrix/ReadOnly 중복 feature 이름 두 개만 정리했다.

생성 JS·타입 선언 충돌은 최신 upstream #7995의 검증된 세 파일을 임시로
보존했다. 최종 후보의 fresh WASM에서 JS·타입·WASM을 함께 동기화하기 전
Studio 통과나 PR 준비 완료로 처리하지 않는다. 각 충돌의 양쪽 파일과
실행 로그는 ignored stage2867에 보존했다.
