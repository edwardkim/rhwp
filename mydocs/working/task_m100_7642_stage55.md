## 생산과 실제 소비 경로

앞 두 입력은 `query_rewind_tail`의 그림 되감김 전 제목 묶음 또는
수식 꼬리 묶음이 `paragraph.rs`의 단 전환으로 이어진다. 실제 줄이
들어가는지 검사하기 전에 가용 높이 비율·고정 하단 여유·다음 내용 종류로
이월한다. 다음 그림이 다른 단에 있다는 사실은 앞 제목의 keep 계약이 아니다.

셋째 입력은 저장 누계에서 생산한 split 후보가 `emit_endnote_split`의
PartialParagraph 두 조각으로 소비된다. 현재 전체 점유 재확인은 내부
vpos 되감김이 있을 때만 적용돼, 연속된 일반 두 줄의 실제 수용을 놓친다.

## 함께 수정할 범위

묶음은 명시적인 keep_with_next 속성과 실제 다음 줄/개체의 점유로 판단한다.
속성이 없는 제목·수식은 자신의 물리 점유가 들어가면 남긴다. 하단 비율·
고정 여유로 임의 묶음을 만드는 두 판정은 제거한다. TAC 그림 한 줄처럼
다음 요소가 분할 불가인 경계는 같은 실제 배치 문맥으로 대조한다.

자동 분할 후보는 전체 문단의 실제 점유를 먼저 재확인한다. 명시적 단·쪽
경계, keep 및 별도 float 계획을 일반 FullParagraph 측정으로 대신하지
않는다. 전체가 들어가지 않으면 원래 컷과 부분 문단의 실제 점유 검사를
계속 사용한다. 문서 번호·미주 번호·진단 좌표를 분기에 추가하지 않는다.

## 검증 범위와 미검증 경계

세 실패 페이지와 앞뒤 페이지, Stage52의 표 분할, Stage54의 CH 이월,
2022/2023 대조군을 한 번의 Native 빌드로 대조한다. 관련 전쪽 Native 및
fresh WASM TSV와 수식·간격 확대 판독이 끝난 뒤 관계형 회귀를 변경한다.
새 테스트·baseline 변경으로 이 차이를 통과시키지 않는다. 명시적 keep
그룹과 다줄 successor의 경계는 실제 지원 범위와 실행 결과를 별도로 기록한다.

## 구현과 적용 경계

그림 되감김 직전 제목과 수식 꼬리 줄에 적용하던 두 묶음 휴리스틱을
호출부·결과 carrier·재사용 판정에서 제거했다. 명시적 keep_with_next가
있는 문단과 한 줄 successor는 같은 원본 소유·projection·실제 항목 순서로
scratch 배치해 점유를 확인한다. 속성이 없으면 뒤의 내용 종류·되감김과
무관하게 묶음 이월을 만들지 않는다. 다줄 successor와 scratch에서 지원하지
않는 별도 float·표는 이번 한 줄 묶음 조회의 통과 근거로 사용하지 않는다.
이 경계는 별도 실행 증거를 확보하기 전 미검증이다.

실제 전체 점유로 분할을 취소하던 기존 내부 되감김 경로를 유지하면서,
자동 컷이 있는 일반 글줄에도 같은 조회를 연결했다. 새 경로는 명시적
묶음·쪽 경계와 별도 Table/Picture/Shape 계획을 제외한다. 원래의 내부
되감김 개체 처리를 일반 글줄 조회로 바꾸지 않았다.

포맷을 적용했고 새 구현을 커밋해 Native 빌드·집중 시각 검증을 시작한다.
새 source의 빌드·시각 통과는 아직 미검증이며 회귀 기대값은 변경하지 않았다.
