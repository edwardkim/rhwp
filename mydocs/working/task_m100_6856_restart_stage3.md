## 결론

**정상 내부 문단이 있는 경우의 구분은 유지되지만, 불완전 입력에서는 원본 영역의 존재와
파싱 성공 여부를 현재 IR만으로 구별하지 못하는 경로가 있다.** 조판부호 함수에 조건을
더하는 것이 아니라, 해당 파서 경계에서 다룰 문제다.

이번 절편에서는 파서 제품 코드를 바꾸지 않았다. 소유권 보호 시험 3개를 추가했고 모두 통과했다.
별도로 14개의 진단 입력을 실행했다. 아래 진단 입력은 메모리상의 HWP 레코드 또는 HWPX XML
조각이며 **정상 한컴 문서나 시각 판정용 샘플이 아니다.** 원본 A4/편람 파일도 변경하지 않았다.

## 1. 정상 구조의 소유권 보호

`tests/cases/issue_6856_parser_ownership.rs`:

1. HWP 캡션만 있는 사각형은 일반 사각형으로 남는다. 캡션과 빈 내부 문단 영역이 같이 있으면
   캡션과 내부 영역을 각각 보존한다.
2. HWP 그룹 안 일반 사각형과 빈 글상자가 서로의 내부 문단을 가져오지 않는다.
   자식 순서를 바꾼 경우도 확인했다.
3. HWPX 외부 글상자의 `outer` 문단과 중첩 글상자의 `inner` 문단이 각자 소유자에 남는다.
   뒤따르는 별도 사각형은 내부 영역 없는 사각형으로 남는다.

집중 실행 3/3 통과. 기존 최종 라이브러리에 `rustc --test`로 연결했으며, PR 전체 integration
게이트를 대체하지 않는다. 모든 표 셀·도형 종류·손상 깊이를 검사했다는 뜻도 아니다.

시험 작성 중 형제 사각형을 `<hp:rect/>`로 표현했을 때 해당 컨트롤이 남지 않아 첫 실행이
실패했다. 이번 소유권 시험은 내부 영역이 없는 `<hp:rect></hp:rect>`로 한정해 재실행했다.
이는 제품 수정으로 해결한 것이 아니다. 자기닫힘 도형의 생략 문제는 관찰로 남기며,
한컴의 정상 사각형 샘플이라는 근거 없이 이번 분류 문제의 원인으로 확장하지 않는다.

## 2. 불완전·빈 구조 진단 결과

| 입력 | 현재 실제 결과 | 의미 |
| --- | --- | --- |
| HWP 영역 없음 | 일반 사각형 | 기대와 일치 |
| HWP 빈 문단 1개 | 글상자, 문단 1개 | 기대와 일치 |

| HWP 캡션만 존재 | 일반 사각형 + 캡션 | 캡션을 내부 영역으로 가져오지 않음 |
| HWP 문단 1개 선언 후 문단 레코드 제거 | 오류 없이 일반 사각형 | 불완전 구조와 영역 없음이 합쳐짐 |
| HWP LIST_HEADER 본문과 후속 문단 모두 제거 | 오류 없이 일반 사각형 | 불완전 구조를 별도로 나타내지 않음 |
| HWP LIST_HEADER 본문만 제거, 문단 유지 | 오류 없이 글상자 | 속성 읽기 실패를 기본값으로 대체 |
| HWPX 영역 없음 | 일반 사각형 | 기대와 일치 |
| HWPX `<drawText/>` | 글상자, 문단 0개 | 선언 보존; 정상 한컴 생성 여부는 별도 |

| HWPX 캡션만 존재 | 일반 사각형 + 캡션 | 기대와 일치 |

HWP 선언 0문단의 **정상 포맷 허용 여부는 미확정**이다. 원본 편람의 기존 계측
`output/6856/sample-audit/raw-ownership.json`에는 내부 영역 소유 개체 179개, 선언 0문단 0개로
기록되어 있다. 이번에는 기존 자료를 재사용했으며 전수 재계측하지 않았다.
불완전 입력 진단 결과를 편람에서 발견한 실문서 결함으로 보고하지 않는다.

## 3. 원인과 이력

- HWP `parse_gso_control`: LIST_HEADER가 있어도 `!text_paragraphs.is_empty()`일 때만
  `Some(TextBox)`를 만든다. 속성 읽기 실패도 `unwrap_or(0)`으로 기본값화한다.
  이 때문에 '영역 없음', '선언 후 문단 누락', '0문단'의 결과가 같아진다.
- HWPX `parse_draw_text`: `p`가 자기닫힘이면 문단을 추가하지 않고, EOF는 정상 종료로 빠져나온다.
  바깥 `parse_shape_object`는 그 결과로 `Some(TextBox)`를 저장한다.
- 두 파서 파일은 baseline `b5eee9c50`과 현재 HEAD 사이에 변경이 없다.
  따라서 **이번 조판부호 변경으로 발생한 회귀는 아니다.**
- HWP 빈 문단 조건과 HWPX EOF 기본 처리의 blame은 저장소 초기 커밋 `f0f7f1a4b4`에 닿는다.
  프로젝트 최초 설계 시점까지 증명하는 것은 아니다.
- HWPX 자기닫힘 `p` 방어는 `1b8c39b6c32`(2026-08-21, #5844 통합 커밋)의 #5797 관련 변경이다.
  목적은 문단 파서가 뒤 문단·형제 도형을 삼키는 것을 막는 것이다. 방어를 제거하면 안 된다.
  빈 문단을 보존하지 않는 현재 경로는 확인했지만, 이전 코드가 올바르게 보존했다는 뜻은 아니다.

## 5. 다음 절편 권고 — 오류 계약을 먼저 명확히 한다

1. HWPX `<p/>`를 뒤 형제 소비 없이 빈 문단과 속성을 보존하도록 최소 보완한다.
   글자 유무 판정은 추가하지 않는다. 기존 #5797 보호 조건은 유지한다.
2. HWPX `drawText` 잘림과 HWP LIST_HEADER/선언 문단 불일치는 정상 사각형·빈 글상자 판정과
   구분하는 오류 전달 방법을 먼저 정한다. HWP의 컨트롤 파서는 현재 Result를 반환하지 않으므로,
   문서 전체 열기 실패로 바꿀지 같은 정책을 구현자가 임의로 선택하지 않는다.
3. HWP 선언 0문단은 정상 포맷 근거를 확인한 뒤 보존/진단 정책을 정한다.
   단순히 `Some(TextBox)`로 바꾸어 손상 입력까지 정상 글상자로 만들지 않는다.

기존 계획의 '기존 오류/진단 정책 유지'만으로는 위 손실을 해결할 수 없다. **위 경계의 오류
전달 계약을 구체화하는 수정계획 승인 후 제품 보완**하는 것을 권고한다. 전체 파서 엄격화,
다른 도형의 자기닫힘 처리, 전수 코퍼스 조사는 이번 절편에 끼워 넣지 않는다.
메인테이너가 후속 수정계획 작성을 승인했다. 단계 전환 전에 본 보고서와 새 보호 시험을
로컬 커밋으로 보존한다. 원격 push·PR·WASM 교체는 수행하지 않았다.

### 수정계획 작성 전 추가 확인

`src/parser/mod.rs`의 HWP 일반/lenient 경로는 섹션 파싱 오류를 경고 후 빈 섹션으로 대체한다.
따라서 하위 파서가 오류를 반환하게 바꾸는 것만으로는 내용 손실 방지가 되지 않는다.
이번 승인으로 이 정책을 변경한 것은 아니며, 후속 계획은 오류가 문서 열기 호출자까지 전달되는
경로와 호환성 영향을 명시해야 한다. 소유권 보호 시험은 다시 실행하여 3/3 통과했다.
