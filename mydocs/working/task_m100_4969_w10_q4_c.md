## 결론

Q4-C는 Q4-A exact shaping output과 Q4-B typed vertical intent를 하나의 dormant transaction으로
결합했다. 이 transaction은 glyph id·source UTF-8 cluster range·vertical origin·glyph bbox·run bbox·
다음 inline origin·다음 column origin을 한 번에 결정한다. line selection, bbox, next origin accessor는
동일한 `Arc` geometry를 공유하므로 서로 다른 계측을 섞을 수 없다.

새 source는 `src/renderer/shaping_vertical.rs`지만 아직 `renderer::mod`에 등록하지 않았다. 기존 layout,
paint, page sidecar, horizontal lowerer는 이 코드를 호출하지 않는다. Q4-D 전까지 제품 출력은 바뀌지
않고, `VerticalPositioningAuthorityPending` 거부도 그대로 유지된다.

## 1. 좌표 계약

1. font design unit은 `font_size_px / units_per_em`으로 px에 투영한다.
2. font의 y-up 좌표는 `screenY = originY - fontY`로 y-down 화면 좌표에 옮긴다.
3. rustybuzz의 음수 vertical advance는 `nextInlineY = originY - ΣyAdvance × scale`로 아래쪽 진행이 된다.
4. Latin sideways는 shaped glyph origin을 중심으로 시계 방향 90도 회전하고, upright는 회전하지 않는다.
5. `vertical-rl`은 column pitch를 x에서 빼고 `vertical-lr`은 더한다.
6. cluster는 source UTF-8 byte range다. old Hangul의 여러 glyph가 같은 `9..12` cluster를 공유해도
   개별 문자로 거짓 분해하지 않는다.

## 2. exact geometry

공통 입력은 font size 10px, origin `(100, 200)`, column pitch 12px이다.

### Source Han old Hangul

`ᄒᆞᆫ글`의 glyph 614/1230/1497/2085와 cluster `0..9`, `9..12` 3건을 유지했다.
run bbox는 `(95.42, 200.41, 9.20, 19.23)`, inline advance는 20px, next inline origin은
`(100, 220)`, RL next column origin은 `(88, 200)`이다. 네 glyph의 origin과 bbox는 기계 판독
oracle에 각각 고정했다.

### Latin orientation

Noto Sans KR `AB`는 sideways와 upright가 같은 shaping glyph 34/35와 같은 next inline origin을
사용한다. 차이는 geometry transform뿐이다.

| intent | transform | run bbox |
| --- | --- | --- |
| `VERTICAL`/sideways | clockwise 90° | `(96.72, 208.84, 7.57, 16.08)` |
| `VERTICALALL`/upright | none | `(97.00, 201.47, 6.00, 17.33)` |

즉 Latin 눕힘/세움 때문에 shaping을 다시 수행하거나 glyph identity를 바꾸지 않는다.

### punctuation·column progression

`—…`는 Q4-A와 같은 glyph 197/11826, run bbox `(95.99, 205.68, 8.01, 13.31)`을 사용한다.
RL next column은 `(88, 200)`, LR은 `(112, 200)`으로 분리된다. OpenType substitution 결과와
column progression을 같은 의미로 합치지 않았다.

## 3. atomic rejection

다음 입력은 모두 transaction을 만들지 않고 전달받은 legacy bbox·next origins를 그대로 반환한다.

- CJK+Latin mixed run: `MixedRunUnsupported`
- vhea/vmtx 없는 Happiness Sans: `ShapingRejected(VerticalMetricsUnavailable)`
- horizontal intent: `HorizontalIntentUnsupported`
- typed intent와 shaping writing mode 불일치: `DirectionIntentMismatch`
- NaN column pitch: `ColumnPitchInvalid`
- variable outline bbox: `VariationGeometryUnsupported`

Q4-C가 variable glyph bbox를 추정하지 않는 이유는 shaping variation과 ttf-parser outline instance가
동일하다는 증명이 아직 없기 때문이다. mixed run도 homogeneous run 경계가 증명되기 전에는 부분 적용하지
않는다. 모든 rejection의 `product_published`는 false다.
