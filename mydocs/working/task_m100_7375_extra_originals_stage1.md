# 기존 미달 원본의 공통 원점·줄 소속 보정

Issue: #7375, 추가 검증 입력 #1994·#4138. 2026-11-06 21:06 KST 기준 진행 기록이다.
사용자는 두 원본의 추가 보정과 이 브랜치에서 다루는 모든 문서의 전쪽 98% 이상을 지시했다.
기존 base와 같은 미달도 완료로 취급하지 않는다. PR 준비는 보류 상태다.

## 원 해결과 현재 원인

- #1994의 원 해결 PR #2034(`e5f9e00864`)는 용지 기준 글뒤 표를 절대 Y에 배치하고
  본문 흐름을 밀지 않도록 했다. #5587의 메인터너 통합 PR #5680에 반영된
  `851b472944`는 부모보다 넓은 중첩표의 잘림을 유지한다. 두 계약을 보존한다.
- `issue1994_behindtext_table_20200830.hwp` 3쪽의 원본 표 두 개는 왼쪽 바깥여백
  852HU를 가지고 있다. 세로 배치와 달리 용지 기준 가로 배치는 이를 누락했다.
  공통 글앞·글뒤 원점 조회를 용지·쪽 기준에도 적용하고, 측정의 수평 범위와 실제
  표 배치에서 같은 여백을 한 번 소비한다. 표 폭·절대 Y·중첩표 clip은 바꾸지 않는다.
- 분할 저장 원본 `saved-split-1x2.hwp` 90쪽의 `140℃`는 독립 한컴 Print에서
  `14 | 0℃`로 나뉜다. 한글 글자 단위 조판의 숫자를 영문 낱말과 같은 이월 단위로
  취급한 것이 원인이다. 비라틴 줄머리 금칙 앞 숫자는 글자 토큰으로 나누고 마지막
  숫자·금칙 문자는 기존 흡수 규칙으로 함께 소유하게 했다. 공통 토큰화·줄 채움이
  편집 및 분할 캐시 복원·실제 배치에 연결된다. 유효한 저장 줄을 일괄 폐기하지 않는다.
- 숫자·단위 대조군의 독립 한컴 2024 Print는 job
  `9a03f95d-d7b1-4af6-bbd9-8d7f74c25a0f`, 제품 `13.0.0.3901`, 실제 Print 방식 0,
  1쪽이다. `140%`·`ABC℃`는 낱말째 이월되고 `140도`는 숫자 뒤에서 나뉘는 반례도 확인했다.

## 22시 재검증·리베이스 후 중요 좌표 보호

`77ee2cd1ce545bba080ff1cc8f599d232a3d659d`에 구현과 당시 증거를 커밋한 뒤
base `45684640be5eddcf5972b063260250345b34d928`로 리베이스했다. 충돌은 없었으며
후보 `fa0436f4951db3bcafa2403c05e202cb425355fe`의 49개 패치는 range-diff에서 모두 같았다.
따라서 별도 충돌 해소 보고서는 없다. 리베이스·fetch·range-diff 로그와 상태는
ignored `output/.../post-rebase-ece9/rebase-20261106-210859/`에 보존했다.

새로 들어온 #8694/#8658의 그림 쌓기·분할·정렬·선언 높이·겹침 허용·가로 비충돌·남은 공간
8조건10쪽은 새 base/후보 Native/fresh WASM 전쪽 각각100%다. #7728도 양쪽 전18쪽
최저98.83905% / 98.83565%를 유지했다. 전후 Native의 추가 두 원본·#7728 총219쪽은
리베이스 전과 PNG가 바이트 단위로 모두 같았다. 이것은 전체163조건의 완료를 뜻하지 않는다.

초기 공용 target의 base→후보 빌드에서 Cargo가 base 산출물을 후보에도 재사용한 문제를 발견했다.
동일 해시의 잘못된 후보 쌍은 INVALID로 격리하고, 소스 바이트를 바꾸지 않은 mtime 갱신으로
후보를 실제 다시 컴파일했다. 유효 후보 Native SHA는 `ab03ac2a2328ef57c78135edd62f25430cbcb5f7480b726cabb88cd12857a9a2`,
WASM SHA는 `d54389b3bded90c84cc0e22060200cfbb033804d8573bad9fd3ecb5c80b32f70`이다.
잘못된 후보 결과는 통과 증거에 포함하지 않았다. 공유 target이나 사용자 산출물을 삭제하지 않았다.

#1994는 원본이 요청한 face와 독립 Print가 실제 사용한 face를 구별했다. 기준 PDF의 본문
486개 glyph 쌍 중471개가 검증용 Haansoft Batang과 같은 윤곽이며15개 기호 차이를 남겼다.
독립 한컴2020 재인쇄도 같은 대체를 재현했다. 그 동일한 비교 환경에서 후보 전4쪽의
Native/fresh WASM 최저98.22544% / 98.14207%, 3쪽98.22544% / 98.19505%다.
기본 출력 정책은 변경하지 않았다. 기본 환경의91.80504% / 92.02788%와 이 결과를 혼동하지 않는다.
[정식 글꼴 환경·전쪽 증거](../pr/assets/issue1994/reference-fonts-20261106/README.md)에
비교 설정과 남은 차이를 연결했다. 글꼴 프로그램·윤곽 배열은 커밋하지 않는다.

[전쪽 TSV·90쪽 review/overlay](../pr/assets/issue4138/numeric-closing-20261106/README.md)를 보존했다.
두 문서의 완료 페이지를 직접 판독한 뒤 독립 PDF 좌표를 ±2px로 지키는 고정형2개를 추가했다.
