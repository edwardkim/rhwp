# #7642 저장 본문 조각의 현재 흐름 증거와 과거 재조판 이력 분리

`stage3431/3437`에서 같은 원본 `samples/hwp3-sample4-hwp5.hwp`의 실제 새 base
`6ed1682c32`와 후보 런타임 `7d685cc178`을 대조했다. 최초 가시 쪽 소유 차이는
문단 338의 둘째 줄이다. 독립 Print·base에서는 12쪽, 후보에서는 11쪽 본문 밖이다.

원본 첫 줄 vpos 64,080HU, 높이 1,000HU이고 둘째 줄은 vpos 0으로 재시작한다.
실제 측정 원점도 정확히 854.4px(64,080/75)이며 첫 줄 점유 끝은 본문 안이다.
배치는 같은 원점에서 두 줄을 모두 그려 둘째 줄이 본문을 10.9px 넘는다.
`stored_body_reset_fragment_matches_current_flow`가 현재 문단·원점·끝점 증거를
읽기 전에 앞선 항목에서 남은 page-wide dirty 이력만으로 거부해 강제 분할이 빠진다.

현재 조각 소유를 과거 페이지 이력의 대용으로 판정하지 않는다. 현재 문단의 편집 여부,
동일 실제 원점, 비합성·연속 저장 prefix, 본문 안의 마지막 점유 끝, 다음 줄의 0 reset을
모두 확인하는 기존 계약은 유지한다. 그 계약보다 앞선 blanket dirty 거부를 제거한다.
HWP3의 음수 local cursor나 첫 줄 불일치, 편집된 문단, 본문 밖 prefix는 이 계약을
충족하지 않는다. 수치 문턱·문서별 분기·내용 숨김·좌표 clamp를 추가하지 않는다.

전체 페이지 TSV·Print 직접 판독 및 수정 전/후 실행은 아직 대기 중이다. 이를 현재
원본의 시각 통과나 새 회귀 적격성으로 보고하지 않는다. 저장 TAC 경계·중첩 표 호스트
보정과 묶어 빌드하고 원래 영향 범위와 실제 새 base 무회귀를 재검증한다.

진단 스크립트는 첫 rustc 실행에서 기존 enum 이름을 `Rect`로 잘못 적어 실패했다.
`Rectangle`으로 바로잡아 재실행하며 실패 로그는 보존한다. 이 컴파일 오류는 엔진
결함 재현이나 회귀 실행 증거로 사용하지 않는다.

## 표 예산 실패의 구체화
