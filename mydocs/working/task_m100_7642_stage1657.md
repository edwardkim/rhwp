# #7642 수학 영숫자 대체 글꼴의 공통 전진폭

Issue: #7642

## 구현 전 근거와 범위

PrEP 31쪽의 본문 U+1D441 `𝑁`은 KoPub 돋움체 Light의 cmap에 없다. Paint의 선언 체인에
있는 함초롬바탕 확장에는 있고 hmtx 전진은 691/1000em이다. 독립 Print도 이 글꼴을
사용한다. 현재 배치는 KoPub에 메트릭 DB 항목이 없다는 이유로 실제 cmap 결측을
확인하지 못해 0.5em 추정으로 돌아간다. 그 뒤 인라인 수식 두 개가 3.45/4.27 CSS px
왼쪽에 놓인다. 글꼴이 없는 상황과 메트릭 DB가 불완전한 상황을 구분해야 한다.

원본 KoPub 2계열·3굵기의 수학 영숫자 전체 블록 U+1D400..U+1D7FF cmap을 읽어
일관된 결측 여부를 확인한다. 기존 선언 대체 체인의 HCR Batang Ext도 전체 블록의
cmap/hmtx를 추출한다. 문서명·문자 하나·PDF 좌표를 조건으로 추가하지 않는다.
사설 글꼴 bytes·윤곽을 추가하지 않고 프로그램 SHA와 수치 메트릭만 기록한다.

## 생산·소비 경로

- `font_metrics_data.rs::FontMetric::get_width`: 기존 표를 우선하며 실제 프로그램에서
  확인한 누락 블록만 보충한다. 기존 metric alias·치환 우선순위는 바꾸지 않는다.
- `text_measurement.rs::char_width_decision_with_hft_tracking`: 원 face의 확인된 cmap
  결측과 DB 조회 실패를 구분하고 선언한 paint 체인 안의 확인된 대체 전진을 소비한다.
- 공통 문자 폭 결과는 composer의 줄 구성, 실제 paragraph 배치의 문자 원점에 전달된다.
  뒤 인라인 수식의 원점을 별도로 이동하거나 줄 폭으로 역산하지 않는다.
- 원 face가 glyph를 갖는 경우, 확인하지 않은 face·weight·italic, 다른 Unicode 블록과
  기존 HFT 폭 계약을 반례로 유지한다. 설치되지 않은 글꼴을 새로 공급했다고 쓰지 않는다.

## 검증과 보존

현재 de4546436의 Native/fresh WASM producer가 실행 중인 동안 src를 바꾸지 않는다.
추출 도구·독립 프로그램 증거를 먼저 준비한다. 소스를 바꾸면 기존 전쪽 결과를 새 head의
결과로 승격하지 않는다. 한컴 Print의 glyph 원점·문자 폭과 전후 실제 출력을 대조하고,
관련 전쪽 Native/fresh WASM 90% 및 직접 판독 후 새 이름의 회귀를 추가한다.
단위는 원본 em/HWPUNIT 관계를 기본으로 하고, 양쪽 98% 이상 완료 페이지에만
독립 Print의 ±2 CSS px를 보완한다. 기존 관계 검사도 유지한다.

입력은 `samples/issue2006/1790387_prep_final_report.hwpx`, 기준은
`pdf/issue2006/1790387_prep_final_report-hwpx-2024.pdf`다. 원본·독립 PDF의 SHA와
Print 출처는 기존 1621 기록을 재사용한다. 측정 도구와 numeric 근거는
`scripts/extract_verified_math_alphabet_metrics.py` 및 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`에 보존한다.


## 실제 paint와 미수집 DB 구간의 구분

수정 전 `de4546436`의 보존 Native 라이브러리에 읽기 전용 진단을 연결했다.
같은 네 글꼴 경로로 실행한 Native trace에서 31쪽 U+1D441의 실제 paint face는
`HCR Batang Ext`, 측정 출처는 `heuristicHalfwidth`, 기본 전진은 550 HWPUNIT였다.
이름만 비교한 fontconfig 후보가 아니라 `nativeGlyphCoverageObserved` 결과다.
`stage1657-actual-native-math-fallback.json`과
`stage1659-native-font-and-space-traces-r2/receipt.json`에 원 레코드와 실행 명령을 보존한다.
첫 진단은 maxCharacters 16384가 API 상한 4096을 넘어서 실패했다. 제한값을 바로잡은
재실행만 유효한 관측으로 사용했다.

현재 구현은 확인된 원 프로그램의 결측을 메트릭 DB의 유무와 별도로 조회하고, 실제
paint가 구성하는 전체 선언 체인의 확인된 프로그램 폭을 소비한다. 기존 메트릭 hit는
그대로 우선한다. 생성 체인의 임시 문자열은 측정 결과에 빌려주지 않고 선택한 프로그램의
정적 DB 이름으로 같은 폭과 진단 메트릭을 조회한다. 최초 Native 빌드의 E0515는 이
임시 문자열의 수명 오류였으며, 수정 뒤 새 로그 `stage1660r2-current-native-build.jsonl`로
빌드한다. 이 컴파일 실패를 렌더링 결함의 수정 전 FAIL 증거로 사용하지 않는다.

SFNT에서 재추출하고 rustfmt를 적용한 파일은 제품 수치 표와 바이트가 같다.
`stage1657-reproducibility-check.json`에 추출 명령과 SHA-256을 기록했다.
프로그램 바이트·윤곽선이나 새 글꼴 공급 규칙은 추가하지 않았다.

## 공백 줄임의 독립 대조군 분석

기존 한컴 Print 대조군 13개의 PDF 조각을 같은 물리 baseline으로 묶어 원문 어절
경계를 비교했다. PDF 추출기의 span 분할을 실제 줄 수 증가로 해석하지 않았다.
Native 생산 소스는 `de4546436`, 입력·PDF 해시와 줄 경계는
`stage1658-condense-physical-line-comparison.json`에 기록했다.

| 글꼴 | 공백 줄임 | Native / Print 물리 줄 수 | 줄별 내용 일치 |
| --- | --- | --- | --- |
| KoPub 돋움 Light | 0, 15 | 각각 5 / 5 | 미일치 |
| KoPub 돋움 Light | 30 | 5 / 4 | 미일치 |
| KoPub 돋움 Light | 45, 75 | 각각 4 / 4 | 일치 |
| 맑은 고딕 | 0, 15, 30, 75 | 각각 5 / 5 | 일치 |
| 굴림 | 0 | 5 / 5 | 미일치 |
| 굴림 | 15, 30, 75 | 각각 5 / 5 | 일치 |

이 자료는 원본 PrEP 67쪽을 분리·재저장한 진단본이며 원본 전쪽 자격으로 쓰지 않는다.
원본 67쪽은 현재 이미 네 줄이고, 미세 어절 분할 차이가 남아 있다. 저장 줄과 새 줄의
공백 정책·압축 기준 소비 경로를 계속 대조한다. 이 단계에서는 공백 상수나 condense
판정 조건을 바꾸지 않았으며, 수학 영숫자 보정의 효과와 구분한다.

## Native 실행으로 확인한 공통 측정 보정

첫 보정의 r2 빌드는 통과했지만 실제 trace의 기본 전진이 550 HWPUNIT로 유지됐다.
`font_metric_trusted`는 TrueType 선언 자체가 아니라 사전 확인한 폭 표의 신뢰 여부이므로
KoPub의 별도 표 경로에서는 false였다. 이 플래그를 전역으로 완화하지 않았다.
확인한 원 face의 cmap 결측은 별도로 사용하되, `source_font_is_hft`가 false이고
측정 face와 표시 face가 같은 경우에만 새 경로를 허용한다. HFT와 다른 측정 프로그램의
폭 계약은 기존 조건을 유지한다.

r3 Native 빌드는 종료 코드 0, 소스 해시 불변으로 완료됐다. 이어 같은 보존 라이브러리에
연결한 실제 Native trace에서 U+1D441은 `declaredGlyphFallbackMetric`,
`HCR Batang Ext`, 기본 전진 **760 HWPUNIT**, 배치 전진 **708 HWPUNIT**로 바뀌었다.
수정 전 기본 전진 550 / 배치 전진 508과 구분한다. 이 진단은 원점의 증거이고
전쪽 시각 gate 통과를 대신하지 않는다.
`stage1660r3-current-native.json`과
`stage1663r3-native-font-and-space-traces/receipt.json`에 명령·라이브러리 해시·종료 코드를 보존했다.

대체 face보다 앞에 오는 설치·번들 프로그램 25개를 전체 수학 영숫자 블록에 대해
확인했으며 해당 glyph는 모두 없었다. `stage1657-preceding-paint-cmap-audit.json`에
실제 프로그램·font index·SHA·cmap 결과를 기록했다. 설치되지 않은 이름의 존재나
임의 OS 대체를 확인한 것으로 보고하지 않는다.

새 head의 Native/fresh WASM 전쪽 재검증·확대 판독과 전체 Rust·lint는 아직 완료되지
않았다. 이 단계에서는 새 렌더링 회귀나 fixture/golden을 추가하지 않았다.
