# 단계 1281 메타파일 회귀의 독립 Print와 cosmetic pen 단위 분석

Issue: #7642. 검증 engine source는 `d00653d6d95480c5fb63ad8c7692876be15c95f8`, 고정 devel은 `463c48cc228170b576c832591b76826116e86a49`다. 단계 1258의 저장 줄 보정·정식 관계형 검사 완료 뒤 남은 WMF/EMF 실패를 진행한다. 전체 검증·PR gate는 미완료다.

## 원본과 독립 출력의 구분

`pdf/issue7642-metafile-primitive-diagnostic/README.md`의 기존 한컴 2024 Print를 재사용했다. 이 자료는 처음부터 정상 golden으로 승인하지 않은 합성 진단이다. 수동 작성한 HWPX, 한컴 정상 저장 HWP, 그림의 원문 bytes와 헤더 보정 여부를 구분한다. 다른 입력의 통과를 기존 실패 입력의 일치로 보고하지 않는다.

- primitive: 14쪽, 저장·Print job과 파일 SHA는 위 README에 있다.
- header-v2: 12쪽, 88/108바이트 헤더·명시 stock object 선택의 대조군이다.
- 원문 HWPX의 현재 전쪽 결과는 `stage1278-metafile-{native,wasm}/`다.
- 한컴 정상 저장 HWP를 같은 PDF와 대조한 결과는 `stage1279-metafile-{native,wasm}/`다.
- 모든 결과는 ignored output에 두며 TSV·로그·중간 JSON을 Git에 넣지 않는다.

원문 HWPX는 양쪽 primitive 전쪽 최저 0%, header-v2 Native 20.60009% / WASM 28.11502%로 미달이다. 정상 저장 HWP도 미달이며 원문 HWPX와 결과가 다르다. 이 자료로 golden 기대값을 갱신하지 않는다. 헤더가 잘못된 원래 test seed와 정상 프레이밍으로 보정한 seed의 동일성을 주장하지 않는다.

## 실제 직접 판독과 선 폭의 관측

정상 저장 HWP header-v2의 4쪽을 Native로 다시 출력했다. `stage1280-emf-header-native-focus/emf-header-p4/review/review_004.png`에서 제목·사각형의 위치와 크기는 가까우나, RHWP 외곽선이 훨씬 굵고 Print의 외곽선은 매우 얇음을 확인했다. Native는 40.71093%로 미달이다. 이 차이를 좌표·크기 문제로 단정하거나 사각형을 숨기지 않는다.

독립 PDF 4쪽의 해당 도형은 벡터 path가 아니라 RGB image+soft mask다. 실제 자원 xref 18/17을 읽어 알파와 검은 잉크를 구분했다.

| 항목 | 독립 PDF의 관측값 |
|---|---|
| raster 크기 | 1515×1500 |
| 배치 transform | 179.903×179.803 point |
| 유효 해상도 | 약 606.33×600.66 dpi |
| 세로 중앙의 검은 선 | x=159와 x=1434, 각각 **1 raster pixel** |
| alpha | 0/255, 가운데의 채움과 외곽 잉크를 구분 |

측정 원문은 `stage1281-emf-cosmetic-pen-print-measurement.json`, 재생용 진단 PNG는 같은 prefix의 `print-rgba.png`다. 투명/불투명 경계만으로 선 폭을 재지 않고 RGB의 실제 검은 잉크까지 확인했다.

현재 `src/emf/converter/player.rs::stroke_spec`는 기본 pen을 폭 1로, 명시 pen도 `width.max(1)`로 만든다. 이 값이 선·사각형·타원·path에 들어간 뒤 root frame 변환과 DC page/world 변환을 소비한다. cosmetic 장치 선을 logical 기하 선처럼 확대하는 경로가 있어 독립 관측과 대조할 필요가 있다. 한 사례의 약 600dpi만으로 모든 한컴 버전·출력 경로의 규칙을 확정하지 않는다.

## 다음 구현 전에 확인할 계약

1. 기본/stock pen, LOGPEN 폭 0/양수, cosmetic/geometric EXTLOGPEN을 원문 레코드에서 구분한다.
2. root frame → page/world 변환 → stroke 소비까지 추적해 장치 선과 기하 선의 단위를 분리한다. Bounds를 다시 Frame 대신 쓰거나 문서별 scale을 추가하지 않는다.
3. 같은 도형·확대 배율에서 명시 굵은 선, 비등방 변환, 기본/stock pen의 반례를 독립 Print와 대조한다. 임의의 한 페이지 수치로 모든 선을 가늘게 만들지 않는다.
4. 그림의 SVG 변환·캐시·Native/fresh WASM 최종 소비를 함께 확인한다. Print와 화면 profile의 장치 단위 차이가 있다면 캐시 키와 소비 지점도 일치시킨다.
5. 기존 88바이트 기본 상태의 도형이 Print에 없는 관측은 따로 유지한다. 이를 정상 도형을 숨길 근거로 사용하지 않는다.
6. 원본 입력과 정상 저장 대조군의 전쪽 Native/fresh WASM 90% 이상·직접 판독을 확인한 범위에서만 기존 회귀 기대값을 재검토하고 새 이름의 관계 검사로 정리한다. 현재 golden 갱신은 보류한다.

현재는 원인 분석과 독립 측정까지 완료했고 추가 production 변경은 하지 않았다. 수식 golden·단독 수식 추출·탭/공백 줄·글꼴 슬롯 메트릭의 나머지 실패와 HWP3 sample16 19쪽 미달도 계속 남아 있다. 마지막 전체 회귀 25 FAIL 이후의 확인 범위는 단계 1258에 기록한 off-canvas 16 PASS와 새 관계 검사 2 PASS이며, 전체 suite 성공으로 확대 해석하지 않는다.

## 버전 반례와 구현한 단위 전달 경로

추가 한컴 2020 Print 작업 `dfcb80ce-8719-4e3d-b972-7ccf3b810fb3`은 engine 2020, build `11.0.0.9136`, `pdf_print_method=0`, `hancom2020_pdf_driver_one_up`으로 성공했다. 입력은 같은 정상 저장 HWP이며 추가 출력은 `metafile-emf-header-v2-2020.pdf`다. 2024 입력의 주 기준을 교체하지 않고 출력 장치 차이를 확인하는 대조군으로 보존한다.

동일한 4쪽 사각형을 2020은 폭 1.893 point의 벡터로, 2024는 약 600dpi 이미지의 1픽셀 선으로 출력한다. `stage1282-header2020-paint-inventory.json`과 앞 측정을 대조했다. 모든 버전에 600dpi 규칙을 일률 적용할 가정을 폐기했다.

Microsoft의 [CreatePen](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createpen), [ExtCreatePen](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-extcreatepen), [cosmetic pen](https://learn.microsoft.com/en-us/windows/win32/gdi/cosmetic-pens) 사양도 함께 확인했다. CREATEPEN의 양수 논리 폭, 폭 0의 장치 선, EXTLOGPEN의 cosmetic/geometric 종류와 stock pen을 구분해야 한다.

구현은 원시 `LogPen`의 폭과 함께 `PenWidthKind`를 보존한다. 참조 장치 재생은 root frame을 유지하고 page/world 변환에서 장치 선의 굵기가 달라지지 않게 한다. 명시적인 출력 장치를 받은 경로는 root까지 반영한 경로 점에 출력 픽셀 폭을 적용한다. 도형을 clamp하거나 선을 숨기지 않는다. 기존 clip의 바깥 좌표계를 유지하며 별도 역변환 그룹 안에서 선을 방출한다.

실제 소비 연결은 `parser 폭 종류 → Player::stroke_spec → push_stroked의 기하 변환 → LayerBuilder의 출력 장치 → Native paint 또는 WASM paint JSON`이다. 2024 compat는 Print에서 관측한 600dpi, 화면에서는 기본 화면 DPI의 장치 픽셀을 레이아웃 단위로 전달한다. 2020 호환 경로는 참조 장치를 유지한다. 일반 EMF 그림은 배치·자르기·채움 크기를 받아 변환하고 OLE의 preview/CONTENTS EMF는 원문과 재생 사각형을 RawSvg에 보존해 같은 레이어 단계에서 재생한다.

배치와 장치에 맞춘 이미지 바이트는 원본 bin 키로 조회할 수 없으므로 `OutputDevice` payload로 구분해 실제 바이트를 전달한다. Native와 WASM이 서로 다른 그림을 조회하거나 서로 다른 배치의 payload를 같은 원본 키로 섞지 않게 한다. 기존 문서 세대·profile 캐시는 그대로 사용하고 새 payload는 실제 바이트 내용으로 구분한다.

새 helper 파일은 1000줄 미만이다. 기존 큰 builder·render tree에는 연결 코드와 직렬화하지 않는 EMF 원문 필드만 추가했다. source-side 기존 테스트의 LogPen 생성자는 새 단위 필드만 보완했으며 기대값을 갱신하지 않았다. 현재 구현은 빌드·현재 head Native/fresh WASM과 명시 굵기·비등방 변환 대조를 아직 통과하지 않았으므로 완료 판정이 아니다.
