# #7642 작은 병합 그룹의 저장 보호와 실제 재조판 흐름 구분

Issue: #7642. 수정 전 검증 SHA는 `9bcf5c500f279728865ea1e01958f595f02aab37`다.

## 수정 전 관측과 독립 기대값

`stage3344`의 기존 36건은 모두 PASS다. `stage3347`은 이 SHA에서 Native 전쪽
대조를 진행한다. 이를 전체 검증 완료로 보고하지 않는다. 별도로 보존한 빈 문단
4개 대조군 중 작은 분할 입력 2개가 아직 미달이어서 현재 범위에 포함해 보정한다.

`stage3354`는 현재 바이너리의 실제 스캔 경로를 기록했다. `split-blank0`은
2행 병합 그룹의 높이 123.1px가 현재 쪽 잔여 60px를 넘지만 새 쪽에는 들어간다.
보호 블록 조회는 모든 내용이 끝난 컷을 내고도, 저장 줄 정보가 없는 입력을 작은
제목 그룹으로 묶어 다음 쪽으로 보낸다. 현재 1쪽에는 첫 행만 남는다.
독립 한컴 2020 Print는 같은 입력의 첫 쪽에 병합 시작·일반농업·다음 행의 글자를
싣고 빈 물리 잔여만 2쪽으로 이어받는다. 빈 문단 3개를 추가한 대조군은 실제로
점유하는 줄 때문에 다음 행 글자가 2쪽에 있다. 빈 문자열을 점유 없음으로 보지 않는다.

원본·독립 Print는 `stage3096-trailing-blank-paragraph-print`, 현재 전쪽 재측정은
`stage3356`에 있다. 과거 결과와 구분하고 입력/PDF/바이너리 SHA를 receipt에 남긴다.

## 공통 계약과 소비 경로

`RowBlockQuery::candidate`의 보호 그룹 분류 → `scan_block_table_split_rows`의
블록/일반 행 선택 → 기존 행·유닛·물리 최소 원장 → fragment 컷과 이어받기 → 실제 배치다.
RowBreak이며 그룹 전체가 실제 plain 재조판 줄을 쓰는 경우에는 저장 제목 그룹의
작은 행 수 휴리스틱을 적용하지 않는다. 같은 공통 줄·최소 계획으로 일반 행을 스캔한다.
실제 저장 줄·중첩 개체·CellBreak의 통째 단위는 기존 경로에 남긴다.

짧은 한 줄의 수용도 고정 25px 밴드가 아니라 실제 소비한 내용 높이와 정렬된 내용 끝이
남은 예산에 들어가는지 확인한다. 한 줄이 들어가지 않는 미세 조각은 여전히 이월하며,
내용이 끝난 뒤의 큰 빈 최소는 별도 물리 원장이 보존한다. 문서 ID·행 번호·픽셀 목표값으로
분기하지 않는다. 기존 경계 9개와 겹친 병합·큰 최소·긴 내용 대조군을 함께 재검증한다.

컴파일·export 시작 전에 종료했다. 실행 중인 Cargo·Native 캡처는 중단하지 않았다.
