# 단계 966 그림 자원 중복과 Chrome 편집 테이블 진단

원본 sample16의 구성도는 동일한 PNG 데이터가 반복되어 SVG가 4,389,512바이트가 되고 Native의 기존 4MiB 안전 한도에서 거부된다. 한도를 높이지 않고, 같은 PNG/표시 크기/종횡비를 갖는 leaf image를 defs의 동일 image로 공유한다. x/y·transform·clip·순서·id와 viewBox 계산은 기존 경로를 유지한다. W3C SVG2 5.5의 image 참조 use는 자체 viewport가 없으므로 크기는 참조 image에 둔다. 비대상 속성·다른 크기·다른 종횡비는 합치지 않는다.

독립 rsvg 시제품은 1,630,472바이트로 감소했다. 624×456에서 alpha는 동일하며 RGB만 9픽셀에서 최대1 차이다. 정확한 바이트 일치로 보고하지 않는다. 실제 Native 재렌더와 독립 Print 전쪽 검증이 필요하다.

startup-contest WASM은 글꼴 부재가 아니라 설치된 나눔고딕의 zero-length TSI3를 OTS가 거부했다. 원본은 보존하며, 빈 VTT 편집 테이블만 공급본에서 제외하고 cmap/glyf/hmtx 등 실제 렌더 테이블을 바이트 단위 대조한다. 원본 이름·face·SHA와 공급본 수정 내역을 기록한다. 다른 손상을 일반적으로 제거하거나 대체 글꼴로 숨기지 않는다.

## 공급본 선행 확인

원본 나눔고딕의 OTS 실패는 `TSI3: zero-length table`로 확인했다. 빈 TSI3만 제외한 공급본은 같은 Chrome에서 적재됐다. 실제 렌더 테이블을 원본 그대로 보존하고 비어 있지 않은 TSI5를 유지하는 검사와 캐시 재사용 검사를 포함해 Python 22건이 통과했다. 이 결과는 문서 전쪽 Visual Sweep의 대체가 아니다.

루트의 `cargo fmt --all`은 오래된 파생 suite가 이미 삭제된 test 경로를 참조해 종료1이었다. 제품 compile 실패나 fmt 통과로 보고하지 않는다. review worktree에서 최신 원본으로 `--prepare`한 뒤 fmt·lint를 다시 실행한다. 생성 suite를 source commit에 포함하지 않는다.

W3C SVG2의 [use 배치 계약](https://www.w3.org/TR/SVG2/struct.html#UseElement)에 따라 표시 크기는 참조 image에 유지한다. 나눔고딕 OTS 진단과 원본/공급본 테이블 비교는 ignored 단계967·Python 검사에 남긴다. 새 실제 문서 회귀 추가는 전쪽 Native/fresh WASM 90% 선행 조건 이후에만 진행한다.

## 원래 클립 좌표계의 반례

SVG `<image x=20 clip-path=...>`의 x는 그림 내용만 이동하지만 `<use x=20 clip-path=...>`의 x는 참조 좌표계를 이동한다. 독립 rsvg 실행에서 원본의 색칠 범위는20..30, 처음 공유 방식은20..40으로 클립 밖에 남았다. clip/transform/id는 바깥 g에 유지하고 x/y만 내부 use에 두자 원본과 RGBA가 완전히 같았다(ignored 단계978/979). 자원 공유의 첫 두 구조 검사만으로는 이 결함을 입증하지 못하므로, 실제 WMF 재생 → resvg 출력의 유색 픽셀이 원래 장치 clip 안에 남고 내용도 사라지지 않는 정식 반례를 추가한다. 수치는 합성 WMF의 선언 좌표로서 실물 화면 px 핀이 아니다.

처음 내부 source 모듈을 복사한 검사는 별도 integration target 예산49>48을 만들었다. 공개 WMFConverter 재생 경로를 사용하는 정식 cases 원본으로 바꿔 파생 suite에 수집되도록 교정했다. 루트 포맷 결과를 보존한 review worktree에서 checkout 시 임시 fmt 변경이 남아 오류가 났으나, 원본 commit과 byte 일치를 확인하고 그 임시 변경만 정리해 재개했다. 어느 실패도 검사 통과로 기록하지 않는다. 단계974의 첫 Native 빌드는 완료됐지만 클립 보정 전 producer이므로 최종 증거로 쓰지 않는다. 단계977은 이 producer를 쓰기 전에, 결과0건 상태에서 중단하고 보정 후 재산출한다.

## 다른 회귀 입력의 직접 판독

수용 TAC 보정 `207c74af1`에서 #6132의 기존3개 검사는 기대값 변경 없이 통과했다(단계968). 글꼴 공급 보정 뒤 fresh dev WASM도10쪽·전쪽 최저98.90219%다(단계970). 최종 release 검증은 남아 있다.

단계972는 새 출력이 아니라207c74af1의 Native/fresh dev WASM PNG로 만든 새 review임을 명시한다. #5756 전3쪽 최저 Native96.33295/WASM96.27461%, 3쪽은97.77511/98.01479%다. 해당 쪽 Native가98% 미만이므로 px 검사 신규 허용 대상이 아니다.

#6800의 전1쪽94.46648/94.57827%에도 불구하고 실제 Print의 검은 원7개가 빠져 있다. 원본과 render tree에는U+26AB가 유지된다. 한컴 Print는 SegoeUIEmoji를 사용하지만, Linux 대체 체인의 HBATANG.TTF는 cmap의uni26AB가 비어 있는0contour glyph여서 다음 fallback으로 넘어가지 않는다. HANBatang.ttf(HCR Batang)에는 실제 윤곽이 있다. 글머리표 API가 아닌 실제 본문 문자다. 이 결함을 점수 통과나 무해한 런 분리로 면제하지 않고 출력 보정과 재검증 후 기존 탭 검사를 변경한다. PDF·원본·글꼴은 수정하지 않았다. 실제 layer tree/글꼴 프로그램/Print font 정보의 진단은 ignored 단계975/976에 보존한다.

## 실제 호출 경로의 클립 재현과 원 기호 보정

초기 WMF 합성 검사는 IntersectClipRect가 실제 SVG clip까지 내보낸다고 잘못 가정해 단계974에서2건 중1건이 실패했다. 실제 구현에서 이 레코드는 DC의 clipping_region만 기록하며, 출력 clip 발행은 CreateRegion → SelectClipRegion이다. 입력을 유효한 Region/Scan 선언으로 고쳐 후자의 실제 경로를 실행했다. 보정 전 `0ca06258d`에 새 검사만 얹은 단계982는3건 중1건 통과/2건 실패였고, 유색 픽셀이 원래 clip 우단 밖에 남는 원인으로 실패했다. 컴파일·환경 실패가 아니다. 별도 소유 ID 검사도 새 그룹 계약을 만족하지 않아 실패했다. 수정 후 결과는 다음 실행에서 확인한다.

U+26AB의 실제 PDF는 SegoeUIEmoji 2048em, 원 glyph bbox (256,-431)..(2556,1869)다. 한양 HFT처럼 실제 프로그램이 검증되지 않은 face의 기존 공통 원 기호 helper에서 이 fallback 윤곽을 em 기준 중심(1406,719)/반지름1150으로 그린다. 문서 ID·화면 px·특정 글자 크기를 분기하지 않는다. 원래 글자 전진과 내용 소유를 유지하며, 검증된 TrueType face와 다른 문자·글꼴에는 적용하지 않는다. Native/Canvas/SVG가 이미 소비하는 공통 helper 결과를 사용한다. SVG의 투명 접근성 text도 실제 기호를 보존하도록 수정했다. 폰트 파일을 변경하거나 PDF의 제한된 font subset을 배포하지 않는다. 이 구현의 실제 문서 개선은 새 Native/fresh WASM과 확대 판독 전까지 미검증이다. 단계980에 원본·PDF SHA와 glyph 프로그램 관측값을 기록했다.
