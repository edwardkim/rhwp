# 단계 1206 머리말·꼬리말 정의를 가진 단일 TAC 저장 줄

Issue: #7642. 기준 `463c48cc228170b576c832591b76826116e86a49`, 보정 전 코드 `f28e94205`.

## 독립 근거와 원인

주거 계약서 원본의 문단 33은 저장 TAC 표와 Footer 정의를 함께 가진다. 저장 줄은 `vertical_pos=35986`, `line_height=text_height=10402`, `line_spacing=300`이다. 표 선언 높이 10122와 위·아래 바깥여백 140+140이 줄 높이 10402를 정확히 닫는다. 독립 Print와 devel의 안내 표 상단은 약 519.5px, 현재 출력은 515.0px다. 앞뒤 본문 원점은 같고 안내 표 전체만 위로 올라간다. 단순 글꼴 굵기 차이가 아니다.

기존 단일 저장 개체 줄 계획은 컨트롤 배열을 `[Table]`로 제한한다. 이 원본의 `[Table, Footer]`는 거절해, 원본으로 인증할 수 있는 동일 줄을 일반 배치로 보낸다. 반면 구역 `collect_header_footer_controls`는 전체 문단을 별도로 순회하며 Footer 정의를 소비한다. Footer는 본문 표와 같은 공간을 점유하는 두 번째 개체가 아니다.

## 같은 결과의 소비 경로

`저장 줄/제어 슬롯과 선언 높이 → stored_tac::prepare의 단일 저장 줄 → 앞 실제 내용 끝과 저장 상대 간격에 따른 origin → 같은 origin/occupied_end의 fit → StoredTacPlan::placement → commit_stored_tac_control의 실제 표 원점/흐름`을 사용한다. 좌표를 뒤에서 clamp하거나 고정 픽셀을 더하지 않는다.

단일 표와 Header/Footer 정의만 있는 컨트롤 배열에서 **실제 표 인덱스**를 보존한다. 해당 제어 슬롯이 저장 줄 0에 소속되는지 확인한다. 표 두 개, 그림·수식·다른 흐름 컨트롤, 수정된 줄, 쪽 예산을 넘는 표, 각주·미주 표의 기존 별도 경로는 유지한다. 앞글줄과 저장 원점의 인증, 실측 높이·바깥여백·쪽 예산 검증도 유지한다. 머리말·꼬리말의 별도 수집은 같은 구역 finalize 경로에서 확인했다.

## 검증 계획과 현재 한계

보정 전은 같은 원본·Print의 단계 1194/1202 비교 이미지와 공개 render tree로 확인했다. 새 Native와 fresh WASM에서 안내 표 원점, 표 안의 4줄·빈 행 밴드, 앞뒤 본문·꼬리말 보존을 직접 대조하고 전체 3쪽의 TSV/쪽수를 확인한다. 동일 머리말·꼬리말 정의가 없는 TAC 및 기존 공백 6쪽은 대조군으로 확인한다. 실제 실행 뒤 결과를 연결하며, 현재 보정 후 출력은 미검증이다. 정식 새 이름의 관계형 검사는 같은 입력의 양쪽 전쪽 90%와 직접 판독을 확보한 뒤 추가한다.

원본 입력·독립 PDF·이전 생산자의 SHA와 진단 값은 ignored 단계 1202/1203에 보존했다. 원본 수정이나 기준 PDF 교체는 없다.
