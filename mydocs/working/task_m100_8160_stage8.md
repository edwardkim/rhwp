## 전체 검사에서 발견한 기존 수식 SVG 선택 가정 정정

정식 테스트 head `72c144f49`의 전체 nextest는 11,574건 중 11,573 PASS·1 FAIL,
기존 제외 45였다. 실패는 #8191의
`inline_equations_keep_source_size_baseline_and_single_line_ownership` 하나이며,
`평점`·`예정가격의`가 단일 SVG text라는 선택 가정에서 발생했다.
이를 전체 검사 통과로 기록하지 않는다.

원 해결 #7642의 `fd42be4af17e452e7b5587b36b15b43620a3cf9a`와 #8191 통합
`60972534680a0c5e51e54ec189b92e252e81a867`, 기존 단계13의 독립 Print 관측을
대조했다. 현재 공통 옛 수식 경로는 원 프로그램의 글자별 전진을 반영해 같은 단어를 여러
SVG text로 발행한다. 단일 노드 묶음은 원본·Print 계약이 아니다. 원본 수식 IR·글줄 소유·
크기·기준선은 기존 assertion을 통과했고, 독립 원점과 실제 첫 글리프의 차이는 ±2px 이내다.

같은 HWP3 원본 전 64쪽은 Native 최저 98.87272%·WASM 최저 98.78369%이며,
6쪽은 각각 99.97285%·99.97688%다. 같은 독립 한컴 2020 PDF 6쪽을 다시 읽어
기존 세 원점 값을 확인했고, 실제 Native·표준 WASM 확대 수식의 분자/분모·괄호·본문을
직접 대조했다. 기존 원점 기대값과 ±2px 공차는 변경하지 않는다.

기존 함수에서 원문과 일치하는 연속 글리프를 선택하고 같은 기준선·가로 전진 순서를
확인하도록 고쳤다. 한글 전체 내용·순서·누락·중복 검사를 추가했고 기존 수식 소유·IR·크기·
줄 포함과 좌표 assertion을 유지했다. 같은 현재 기본 제품 라이브러리를 연결한 수정 후
집중 실행은 기존 3/3 PASS다. 먼저 시도한 동결 Native rlib 연결은 공유 의존 아티팩트가
교체되어 컴파일에 실패했으므로 실행 검출 근거에 포함하지 않는다.

제품·UI·기대 좌표를 바꾸지 않았다. 수정한 정식 테스트 head에서 전체 nextest와
Native Skia·lint를 다시 완료한 뒤 기존 PR에 제출한다. CI 이후 후속 처리는 새 승인을 받는다.
