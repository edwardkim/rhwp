# Issue #7642 단계 767: 직접 PNG 글꼴 컬렉션의 재생성 비용 보정

## 확인한 비용과 처리

- fresh WASM의 첫 문서에서 Linux Noto TTC의 여러 face를 `FontTools.save`로 개별 program으로 저장하는 작업이 반복됐다. 기존 전쪽 TSV가 지연된 원인은 컴파일 이후의 이 저장 작업이었다.
- 공용 `output/pr-review/font-catalog-cache/`에서 원본 SHA-256, 생산 코드와 FontTools 버전으로 program을 구분한다. 같은 원본의 완전한 face 목록과 실제 program SHA를 확인할 때만 재사용한다. 원본 변경, face 누락·중복, program 손상·누락은 다시 생산한다.
- 파생 program은 원본 head의 시각 값을 유지해 저장 시각에 따른 바이트 변화를 없앤다. 임시 파일을 완성한 뒤 원자적으로 게시하며, glyph·cmap·크기·색상·실루엣 계산은 변경하지 않는다. 문서별 catalogue에는 실제 재사용한 program 경로와 SHA를 남긴다.
- 이전 생산 코드 `339882b50aa93fcda44afb43e9952d0633d35ed55f9315c1aa84844dc127a860`가 이미 저장한 TTC face도 확인했다. 원본의 모든 face, 이름·굵기·glyph ID 순서·cmap/UVS와 실제 program 바이트를 대조한 12개 컬렉션 70개 face를 hardlink로 연결했다. 중복 저장하지 않았으며 완성되지 않은 컬렉션은 재사용하지 않는다. 상세 원장은 ignored output의 단계 768에 있다.

## 검증

- `venv/bin/python -m unittest scripts.tests.test_visual_sweep_png -v`: 15건 통과.
- 실제 컬렉션의 완전 재사용, 부분 metadata 복구, 파생 program 손상 복구, 원본 파일 변경에 따른 새 catalogue와 선택 TTC face의 논리 family 보존을 검사했다.
- 이번 변경은 시각 검증의 font program 준비 비용을 줄인다. Native/fresh WASM 90% gate, 완료 페이지의 양쪽 98% 및 직접 확대 판독, 고정 devel 대비 0.01%p 하락 확인은 그대로 수행한다. px 회귀 등록과 PR 준비를 완료한 상태로 보고하지 않는다.
