# Stage 108 — 점 연산자 표시와 전체 실패 원인의 묶음 보정

Issue: #7642. 55개 원본·853쪽 및 복원한 회귀 292개, #1139 전체 관계형 전환 범위를 유지한다.

## 구현 전 근거

- Stage 107 실제 Studio 확대에서 `BULLET`/`CDOT`의 크기가 한컴 Print와 다르다.
  Canvas2D roman-context 전쪽은 90% 미만이고, CanvasKit은 전쪽 90%를 넘지만
  직접 판독의 차이가 남는다. 높은 점수를 시각 통과로 보고하지 않는다.
- 설치 HYhwpEQ의 UPM 1024 cmap/hmtx/bbox와 독립 Print의 Unicode·font·원점을
  읽기 전용으로 대조했다. U+2219의 잉크 상자는 (386,174,638,427), U+22C5는
  (424,218,598,381)이다. 사설 윤곽이나 글꼴 바이트는 코드에 복제하지 않는다.
- 생산 위치는 `layout/source_font_symbol.rs::layout`의 논리 폭·기준선이고,
  SVG/Canvas2D/Skia/CanvasKit이 `FontGlyph`의 공통 outline을 소비한다.
  대체 글꼴의 원을 선택하던 두 기호를 독립 em 잉크 상자에 맞는 수학 타원으로
  전달한다. 기준선 원점은 기존 수학 연산자와 같은 출력 DPI의 원점 격자를 쓴다.
  문서 ID·페이지 좌표·고정 px로 적용 조건을 만들지 않는다.
- ±/∓·prime 등 다른 기호는 이 원 보정의 대상이 아니다. 일반 `FontGlyph` 선언
  글꼴 소비 계약도 유지한다. 점의 너비와 이항 자동 여백은 기존 논리 계약을 유지한다.

## 검증 계획과 남은 범위

현재 실행 중인 전체 nextest의 최종 실패 목록과 원본/Print의 조판 세대를 확인한다.
동시에 실행 중인 Native/fresh WASM 전쪽 대조는 고정된 db43ff92e 소스 증거이며,
새 코드의 최종 증거로 승격하지 않는다. 다음 묶음 코드 보정 후 fresh 빌드와 영향
반례의 전체 TSV·확대 판독, 관련 회귀 및 전체 필수 게이트를 실행한다.
시각 선행 조건을 충족하기 전에 기대값·golden 갱신이나 신규 실물 회귀를 추가하지 않는다.

## 현재 실패의 독립 대조

- `issue_1261_2024_sep_page10_question12_tail_stays_inside_column`은
  `samples/3-09월_교육_통합_2024-미주사이20.hwp`의 고정 px 기대값에서 실패했다.
  고정 db43ff92e 바이너리로 같은 입력을 `--compat 2022`/`2024`로 모두
  재출력했다(각 종료 코드 0). 문10/11/12 제목 위치는 두 설정에서 같았다.
- 독립 `input-07-3-09월_교육_통합_2024-미주사이20-2024.pdf`의 10쪽 텍스트
  상자도 현재 출력과 일치한다. 기존 검사의 402.8/618.5/995.6px는 이 Print의
  제목 위치와 다르다. 설정 차이를 회귀 해결 근거로 사용하지 않는다.
  `stage108-regression-compat-diagnostic/receipt.json`과 `print-title-bboxes.json`에
  원본·PDF·바이너리 hash 및 실제 출력 상자를 보존했다. 아직 이 테스트를
  갱신하지 않았고, 해당 원본 전쪽 TSV·확대 판독 뒤 소유/순서/단 포함으로 바꾼다.
- 전체 회귀의 중간 실패 목록은 `stage108-full-regression-failure-snapshot.json`에
  보존했다. 최종 결과가 아니며 원인을 확정하거나 실패를 제외한 목록이 아니다.
- `a_n+1`/`a_{n}+1` 및 짧은/긴 본체의 위첨자 경계를 9/11/16/22pt
  16개 식으로 독립 한컴 저장·Print 산출 중이다. 임의 LineSeg/폭/기준선은
  기준값으로 채택하지 않고 한컴에서 재생성한다. 정식 fixture 추가나 golden
  갱신 전에 실제 구문 범위와 수식 점유를 판독한다.
- 점 연산자 공통 outline 구현은 수정 중이다. Rust 빌드·fresh WASM·새 출력은
  아직 실행하지 않았다. 공유 Cargo는 전체 nextest가 종료된 뒤 순차로 사용한다.

## 커밋 시점의 검증 경계

점 표시 모듈의 Rustfmt 구문/포맷 확인과 `git diff --check`는 통과했다. 이 커밋은
원인 보정 진행분을 고정하며 빌드·회귀·시각 통과를 선언하지 않는다. 전체 nextest의
실행 checkout은 detached `33c0082f4`이므로 새 구현과 섞이지 않는다.
기존 실행이 끝나면 전체 실패를 분석한 묶음 보정에 이 구현을 포함해 검증한다.
