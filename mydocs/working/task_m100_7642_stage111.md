## 전체 실패 117개의 입력 근거

실제 실행한 review checkout의 소스를 읽고 문자열·중첩 주석을 제외한 중괄호 경계로
함수 본문을 추출했다. 중첩 helper 때문에 본문이 잘리던 이전 추출을 보완했다.
117개 중 99개는 직접 함수 정의를 찾았고, 100개에서 입력 경로 근거를 수집했다.
같은 파일의 helper 호출·상수는 정적 후보이며 분기 실행이나 정확한 원본 확정으로
세지 않는다. 매크로 생성 함수·외부 helper·합성 입력은 별도로 확인한다.
실패 본문에서 원장 증가 기록 18개를 직접 추출했다. 허용치·기준 원장은 갱신하지 않았다.
근거는 `stage111-failure-input-evidence.json`에 보존한다.

새 Native로 `samples/hwp3-sample.hwp`의 실패도 재현했다. HWPX 왕복의 전체 쪽수는
16쪽으로 같지만 6쪽의 본문 한 줄이 7쪽으로 이동하고 구조가 달라져 `render-diff`는
종료 코드 3이다. 원본의 6쪽 본문 하단 초과도 남는다. 기존 한컴 기준 PDF의 본문
소속은 왕복본 쪽과 대응하므로 원본 출력 경로의 분할 판단을 추적한다.
6·7쪽 SVG 대조는 embedded 글꼴이 없는 텍스트를 전송 helper가 거절했다.
이 실행은 시각 통과가 아니며 올바른 글꼴 공급 후 다시 산출해야 한다.

### HWP3 기준 대조 재실행

Windows 검증 호스트의 설치된 `H2MJSM.TTF`·`batang.ttc`를 ignored 비공개 경로로
복사했다. 내부 face 이름이 입력의 `HY신명조`·`바탕`과 대응함을 확인했고 해당
실행에만 `RHWP_FONT_PATH`로 공급했다. 글꼴 파일·embedded 글꼴 SVG는 Git이나
공개 PR asset에 넣지 않는다. 파일 출처·해시는 진단 폴더의 JSON에 보존한다.
같은 바이너리의 6·7쪽 compare·overlay·review 생성은 완료됐지만 7쪽은
89.34555%여서 gate가 `re_review_required`, 종료 코드 1이다. 글꼴 공급을 고쳐도
본문 소속과 캡션 간격 문제가 남으므로 글꼴 예외로 통과시키지 않는다.

`dump-pages`에서 동일한 문단 76의 저장 줄 13개와 9번 줄 되감김을 확인했다.
원본의 조각은 `0..10`, 왕복본은 `0..9`를 소비한다. 독립 PDF에서는 해당 꼬리
본문이 7쪽에 있다. 같은 문단의 그림은 두 입력 모두 위치 502·non-TAC로 보존됐다.
문단 전체의 컨트롤 종류만으로 저장 줄 경계를 배제하는 조건과, 실제 컨트롤의
줄·조각 소속을 추적한다. 아직 원인 보정을 구현하거나 검사 기대값을 바꾸지 않았다.
