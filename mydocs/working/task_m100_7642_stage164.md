# #7642 Stage 164 — 각주 표식이 있는 저장 본문의 좌표 재시작

## 독립 근거와 실패 경로

Stage 163의 생산 소스는 `89285d012dba022d50989816267830be0101bd2d`이며,
Native 검증 기록과 대표 PrEP PNG는 `a7b1c64e5`에 보존했다. 정확한 전체 Rust
회귀가 종료할 때까지 생산 소스는 수정하지 않는다.

대상은 `pdf/issue6812-multiple-square-pictures-print/multiple-square-pictures.hwpx`와
같은 저장본을 한컴 2020의 Print로 출력한 `multiple-square-pictures-2020.pdf`다.
입력 생성·독립 Print 작업 ID와 해시는 해당 폴더 README에 있다. 원본 HWP는
별도 대조군이며 진단 저장본의 통과로 원본 검증을 대신하지 않는다.

진단 저장본 2쪽 Native 일치율은 63.43505%다. pi8의 뒤 두 줄을 수용한 측정
흐름은 64px인데 pi9 진입에서 50.6667px로 되감긴다. pi9의 문단 앞 간격
1000 HU를 빼지만 배치 커서는 같은 되감김을 적용하지 않는다. 이 차이가 pi11의
그림 표 원점과 뒤 본문에 전달된다. 이 수치는 진단 관측이며 기대값이나 보정
상수로 사용하지 않는다.

저장 pi8의 줄 좌표는 64157, 66557, 68957 HU이고, pi9는 1000, 3400, 5800 HU로
새 축을 시작한다. pi8에는 개체가 없고 pi9에는 각주 표식 하나가 있다. pi10의
각주 표식 둘과 pi11의 그림 표는 각각 별도 소유를 유지한다. 앞 분석의
"pi8과 pi9 모두 각주가 있다"는 추정은 실제 HWPX XML 대조 결과와 달라 정정한다.

## 생산과 소비

- `height_cursor_saved_boundary.rs::restart_below_origin`은 권위 있는 저장 축의
  재시작을 판별하지만 `controls.is_empty()`로 각주 표식도 개체 배치로 취급한다.
- `HeightCursor::vpos_adjust`는 재시작이 승인되면 이미 소비한 흐름과 현재 문단
  앞 간격에서 `seed_stored_flow_origin`을 호출하고 순차 커서를 보존한다.
- `typeset/section/vpos.rs::vpos_snap_current_height`는 결과와 새 page/lazy 원점을
  다음 수용에 전달한다. `layout.rs`의 실제 inter-item 경로도 같은 HeightCursor를
  소비하며, 앞 항목의 배치 경로에 따라 보정을 건너뛰는 경우가 있다.
- pi11의 `physical_tac` 배치는 확정된 측정 원점을 사용한다. 잘못된 선행 커서에
  표 높이·그림 좌표 보정을 더해 문제를 숨기지 않는다.

각주·미주 표식은 글줄 안의 번호를 소유한다. 각주 내용의 공간은 별도 각주
예약에서 계상하며 표식 자체가 본문 개체 프레임을 추가하지 않는다. 정상 저장
줄의 높이·간격을 사용할 때도 각주 표식만 있다는 이유로 축 재시작을 거부하면
측정과 배치의 소비가 갈라진다. 미주의 의도된 되감김은 호출자의
`allow_vpos_rewind` 계약으로 구분한다.

## 구현과 검증 계획

1. 정상 저장 줄·비편집 입력이라는 기존 인증은 유지하고, 각주·미주 표식만 가진
   본문을 축 재시작 판별에 포함한다. 표·그림·수식 등 본문 개체가 있거나 저장
   분할이 dirty·합성인 입력은 이 근거로 수용하지 않는다.
2. 진단 입력 전체 11쪽, 원본 HWP 전체 11쪽, PrEP의 각주·표 분할 경계와 저장
   축 재시작 대조군을 같은 독립 Print로 다시 비교한다. fresh WASM도 새로 빌드해
   실제 출력과 전체 쪽수를 확인한다.
3. 기존 #6812 정확한 관계 검사는 유지하고 실행한다. 신규 회귀와 잘못된 절대
   위치 검사의 대체는 관련 모든 페이지의 Native/fresh WASM 90% 이상과 확대
   판독을 확인한 뒤 별도 이름으로 작성한다. 현재의 미달 진단은 새 golden이 아니다.
4. 전체 Rust 실패를 실제 원본·독립 Print·실패 원인에 연결해 같은 원인별로
   보정한다. 기존 실패를 근거 없이 기대값 갱신으로 통과시키지 않는다.

Stage 163 전체 Rust의 최종 결과와 이 단계의 수정 전후 실행 결과는 확인한 뒤
추가한다. 현재 계획만으로 시각 통과·회귀 통과·PR 준비를 판정하지 않는다.

## 보정 시작

Stage 163 전체 Rust가 exit 100으로 종료됐으며 10,197 PASS / 58 FAIL /
45 skipped, 소스 해시 유지 true를 확인했다. 실행 중인 Cargo/Rust 검증이
없는 것을 확인한 뒤 생산 소스를 수정했다.

`restart_below_origin`의 컨트롤 인증을 각주·미주 표식만 있는 본문까지
확장했다. dirty 여부·줄 좌표·합성 태그·줄 순서 검사와 호출자의 편집·미주
되감김 가드는 유지한다. 표·그림·수식은 여전히 이 경로의 축 인증에서 제외한다.
수치 보정이나 출력 숨김은 추가하지 않았다. 아직 새 Native/fresh WASM 결과는
없으며 신규 회귀나 기존 기대값은 변경하지 않았다.

## 새 Native 결과와 미완료 범위

Native 빌드는 exit 0, 286.237초, 소스 해시 유지 true이며 생산 소스는
`9787757e42fd7111872baf22ab440b1a7ff8462d`다. binary SHA-256은
`1c378170e2e9e9537ad17cc957447042e7569629ba1c21497d695df6bcd3dd6a`다.
새 실행에서 pi9 진입의 소비 높이 64px가 유지되고 pi10과 후속 본문도 새 축을
이어받는다. Native의 문제 2쪽은 63.43505% → 97.37226%로 개선됐으며,
진단 HWPX와 원본 HWP는 각각 전체 11쪽 최저 95.76069%, 미달 0쪽이다.
새 비교는 [대표 PNG](../pr/assets/issue7642-saved-note-axis-20261012/README.md)에 보존했다.

PrEP도 같은 소스의 Native 전체 140쪽을 다시 산출했다. 최저 91.75234%,
미달 0쪽, 전체 쪽수 140/140, 소스 해시 유지 true, 699.344초다. 앞 단계의
PNG를 재사용하지 않고 각 묶음을 새로 출력했으며 같은 canonical 산식과
정확한 1~140 합집합으로 전체 TSV를 확인했다. fresh WASM은 빌드 중이다.

#7593 원본 Native는 91.61325%, 최소 입력은 99.17678%다. 그러나 원본 보기 ㄴ의
2580 HU 저장 예약 프레임이 `normalized_simple_math_metrics`에서 18px 논리
프레임으로 줄어드는 경로를 확인했다. 실제 새 render tree는 이 수식의 높이를
18px로, 독립 Print는 큰 프레임 안의 수식과 더 낮은 뒤 본문을 표시한다.
90% 통과만으로 이 미세 배치 차이를 면제하지 않는다. 기존 두 검사에서
SVG `<text>`가 없어 실패하는 현상도 있으므로 표시 형식의 변화와 실제 배치
결함을 구분해 보정한 후 새 이름의 관계형 검사로 작성한다. 현재 기대값은 변경하지 않았다.

원래 55개 원본 중 이전에 미달했던 6개 입력은 새 소스의 영향 쪽을 먼저
재검증하고 있다. 9월 2022 HWP의 10~11쪽은 여전히 미달이며 최저 35.35162%다.
부분 쪽 진단을 전체 55문서 재검증으로 보고하지 않는다. 나머지 시각 결함과
전체 Rust 58건, Native/fresh WASM 선행 조건은 계속 해결해야 한다.

## fresh WASM과 관계형 회귀의 실제 입증

fresh WASM 빌드는 exit 0, 857.163초, 소스 해시 유지 true다. 루트 `pkg/`와
Studio public의 JS·WASM 해시가 일치한다. WASM SHA-256은
`37e0b5847ad6a738d09f85f2cfc0aa459a4c75aec18bdb543f1e45ed366e1f2c`이며,
JS는 `2d0d0469c582a49331d023d475ae53a17cb9f601a78a78e09d18e5b6a9047cc1`로
기존 tracked 파일과 동일하다. JS를 변경한 것처럼 보고하거나 빈 커밋을 만들지 않는다.

실제 fresh WASM의 진단 HWPX와 원본 HWP는 각각 전체 11쪽 최저 95.76066%,
미달 0쪽이다. PrEP 67~70쪽은 최저 98.83194%, midpage 대조군 두 쪽은 100%다.
#7593 원본/최소는 각각 91.61325% / 99.17678%지만 앞 절의 큰 예약 프레임
차이는 여전히 보정 대상이다. 동일 소스의 #6812, #7362, #7390 기존 검사
41건은 변경 없이 41 PASS, exit 0, 소스 해시 유지 true다. 전체 Rust 통과는 아니다.

`tests/cases/issue_7642_saved_note_axis.rs`에 새 이름의 실제 출력 검사를 추가했다.
표 제목으로 원본의 표·컨트롤 소유를 찾고, 앞 본문 글줄의 끝에서 마지막 저장
줄간격과 앞 문단 아래/뒤 표 문단 위 간격을 소비한 뒤 표가 놓이는지 검사한다.
본문·표 소속, 표의 누락·중복과 독립 Print의 전체 11쪽도 확인한다. 원본의 앞
문단 아래 간격은 0이므로 그 간격만 있다고 가정한 초안은 폐기하고 실제 두
문단 사이 간격을 사용했다. 고정 위치·고정 영역·절대 px 기대값은 없다.

동일한 테스트 소스 SHA-256
`f103db3141bab44aa7a6cb46eaed9c1949de3604834b3a67a4820f8b81efc7d2`를
수정 전 `89285d012dba022d50989816267830be0101bd2d`의 격리 체크아웃에서도
실행했다. 그 체크아웃의 원래 생산 소스와 동일 새 검사만 가져오는 진단 harness,
명시적 Cargo manifest, 공용 `target/pr-review`를 사용했다.

| 실행 | 실제 결과 |
| --- | --- |
| 수정 전 생산 소스 + 동일 새 검사 | 0 PASS / 1 FAIL, exit 100; 두 문단 사이 간격을 잃는 관계 assertion에서 실패 |
| 수정 후 생산 소스 + 동일 새 검사 | 1 PASS, exit 0 |

초기 체크아웃 누락으로 현재 저장소를 사용한 비교와 sparse dependency 누락의
빌드 실패는 결함 재현에서 제외했다. 실제 수정 전 검사는 독립된 manifest를
확인하고 필요한 원래 소스를 복구한 뒤 실행했으며, 소스와 테스트 해시가 유지됐다.
명령·실패 문구·해시는 ignored `stage164-new-relation-before-after.json` 및
`stage164-before-note-axis-relation/`에 보존한다.

Native 미달 6개 원본의 영향 쪽 진단은 완료됐으며 모두 여전히 미달이다.
9월 HWP 2022는 최저 35.35162%, 나머지 9월 세 입력은 35.26860%, 11월 두
입력은 35.22554%다. 이 진단을 전체 페이지 검증으로 승격하지 않는다.
PrEP 전체 140쪽 fresh WASM은 현재 실행 중이며 소스 변경 없이 결과를 기다린다.

## PrEP 전체 fresh WASM 완료

같은 생산 소스의 실제 fresh WASM 전체 140쪽도 완료됐다. 최저 91.75234%,
미달 0쪽, 전체 쪽수 140/140, 소스 해시 유지 true, exit 0, 781.118초다.
각 묶음의 WASM manifest 쪽수 140과 실제 출력 페이지 합집합 1~140을 확인했다.
Native 결과를 WASM 출력으로 대체하지 않았으며, 매 묶음 종료 뒤 해시를 기록한
중간 raw/patched SVG만 정리하고 전체 PNG·TSV·로그·manifest를 보존했다.
PrEP은 Native/fresh WASM의 전체 페이지 선행 조건을 충족한다. 전체 PR의 미달
원본과 Rust 실패, #7593의 미세 배치 차이는 별도이며 완료로 보고하지 않는다.

실행·증적은 ignored `stage164-prep-whole-native/receipt.json`과
`stage164-prep-whole-wasm/receipt.json` 및 각 `whole/silhouette.tsv`에 있다.
수정 전 검사용 임시 체크아웃은 프로세스 종료와 소유를 확인하고 제거했다.
공용 `target/pr-review`는 보존했다. 이 단계 이후 생산 소스가 바뀌면 해당
영향의 검증과 제출용 증적을 다시 확인한다.
