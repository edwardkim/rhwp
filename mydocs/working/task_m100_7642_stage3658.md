# #7642 분할하지 않는 TAC 호스트와 KoPub의 이중 격자 절삭

Issue: #7642

## 원본과 반례를 함께 판정

`bedb253f79`의 Native CLI 빌드 종료 코드 0과 `stage3649-certified-anchor-head-native`의
전쪽 TSV를 확인했다. 원본 `samples/issue1880_takeplace_host_before.hwpx`는 독립 Print와
같은 10쪽이며 전쪽 최저 93.75308%, 1쪽 99.96111%, 5쪽 99.99890%다. 앞선 시도의
3·4·5쪽 회귀는 복원됐다. 새 1·5쪽 review와 standalone overlay를 함께 직접 판독했다.
표 외곽, 위쪽 본문, 아래쪽 가운데 정렬 내용과 두 중첩 표의 위치가 겹친다. PNG의 5쪽
표시는 소수 둘째 자리에서 100.00%로 반올림됐지만 TSV 원값은 99.99890%다.

그러나 다음 저장 TAC 자식 표의 분할만 끈 두 대조군은 5쪽 66.70831%가 남았다. 한컴
Print에서 이 두 대조군은 원본과 같은 페이지를 출력했다. 원본의 높은 점수로 이 반례를
통과 처리하지 않고, fresh WASM과 새 렌더링 회귀 추가를 보류한다.

## 분할 방식과 호스트 줄 소유의 구분

`stage3656-no-split-unit-analysis`에서 같은 다음 문단 9의 원본 줄을 대조했다. 줄 상단은
0, 높이는 5021 HU이며 TAC 자식 표 4739 HU와 위·아래 바깥여백 141 HU씩의 합과 같다.
다음 문단의 저장 상단은 5621 HU로 그 줄 높이와 줄간격 600 HU의 합이다.

- 분할 허용 자식 표: 첫 유닛은 `nested_row=Some(0)`이고 자식 행들을 각각 소유한다.
- 분할 금지 자식 표: 한 유닛이 원본 한 줄을 통째로 소유한다. `nested_row=None`이지만
  `hard_break_before=true`, `page_frame_reset_before=true`이며 실제 전진은 5621 HU다.

기존 인증은 자식 행으로 펼친 경우만 인정해 두 번째 경우의 현재 쪽 물리 띠를 버렸다.
분할 여부를 원본 호스트 줄의 존재 여부로 사용한 가정을 제거했다. 이미 검증한
`stored_inline_owner_frame`을 공유하며, 단일 유닛도 실제 높이가 저장 줄 높이+줄간격과
정수 원본 오차 2 HU 안에서 닫힐 때만 그 줄의 내용 높이를 사용한다. 중간 줄·혼합 조각·
빈 spacer·다음 유닛이 같은 문단을 이어받는 경우는 이 단일 줄 인증에서 제외한다.

같은 결과를 `stored_inline_restart_row_end_frame → scan의 물리 예약/내용 컷 →
PageItem의 프레임 소유 → 행 괘선과 가운데 정렬`로 소비한다. 자식 표를 이전 쪽에
가져오거나 다음 쪽의 내용 컷을 바꾸지 않는다. 문서 ID와 고정 화면 좌표를 쓰지 않는다.

## KoPub 전진폭의 독립 대조

PrEP의 devel 대비 하락을 분석하며 배치와 paint 차이를 분리했다. 3쪽의 요약 배치 트리는
base와 같지만 15·26쪽은 그림 위치와 양쪽 정렬 전진이 함께 다르다. PDFium 글자 원점과
PDF image object 상자를 직접 읽었으며, 점수만으로 그림 정렬을 되돌리지 않았다.

같은 원본의 charPr 1과 글꼴 목록을 보존한 진단 HWPX를 만들고, 본문을 왼쪽 정렬의
짧은 16개 크기·장평·자간 조합으로 교체했다. 저장 LineSeg는 넣지 않았으며, 원본 파일은
수정하지 않았다. `stage3652-kopub-tracking-controls`의 생성 과정과 입력 SHA,
`stage3653-kopub-tracking-print`의 MCP job·PDF SHA를 보존했다. 실제 한컴은
13.0.0.3901, engine 2024, Print method 0, `frame_print_to_pdf_ex_one_up`, 1쪽이다.

| 크기·장평·자간 | Print의 평균 글자 전진, 96 DPI px | 기존 계산 | 차이 원인 |
| --- | ---: | ---: | --- |
| 11pt·98%·0% | 12.523677 | 12.480000 | 원본 em을 먼저 HU로 잘라 장치 단위를 한 번 더 잃음 |
| 11pt·98%·+5% | 13.172017 | 13.120000 | 같은 이중 절삭 |
| 11pt·98%·+10% | 13.811068 | 13.706667 | 이중 절삭 뒤 자간 반올림 경계까지 달라짐 |
| 11pt·100%·0% | 12.793576 | 12.800000 | 장평 없는 정상 대조 |

관측은 같은 줄의 20개 연속 한글 원점을 사용했다. 실제 PDF 글꼴은
`INPILL+KoPubDotumLight`이고, PDF `/W`의 한글 폭은 872/1000em이다. 수치는 독립
PDF의 인쇄 격자 반올림을 포함하며 Python의 공식 대조만으로 엔진 통과를 선언하지 않는다.
전체 16개 조합과 좌표는 `stage3654-kopub-tracking-observation`에 있다.

KoPub 폭 조회는 원래 em 비율을 함께 반환하도록 바꿨다. 기존 진단용 HU 기본 폭은
유지하고, 실제 `hancom_device_advance_px`는 다른 내장 메트릭과 같이 절삭 전 em을
소비한다. 글꼴 계수·기준 PDF·DPI·허용치를 바꾸지 않았다. 측정과 글자 배치가 같은
`CharWidthDecision`을 사용하므로 Native와 WASM에 동일하게 적용된다.

## 검증 계획과 미완료 범위

두 구현의 실행 검증 전이다. 먼저 Native CLI로 원본·분할 반례·#7336과 KoPub 독립
대조군을 함께 비교하고, 방향이 맞으면 같은 source의 집중 회귀·fresh WASM·PrEP 등
영향 문서의 전체 페이지 TSV를 확인한다. 전쪽 90%와 직접 판독 뒤 새 이름의 관계 회귀와
양쪽 98% 이상 페이지의 중요 좌표 회귀를 추가한다. 기대값과 golden을 먼저 갱신하지 않는다.

현재 남은 별도 미달·devel 대비 하락·전체 Rust와 최종 시각 검증은 유지한다. 이 기록의
원본 Native 통과와 산술 대조는 PR 준비 완료 또는 fresh WASM 통과를 뜻하지 않는다.
