# #7642 normal 공간 보정의 Native 전쪽 확인

Issue: #7642

## 검토 경로와 source

기본 경로는 collaborator self PR이다. 로컬 검증·시각/fixture 증적·대형 변경의
재작업 검토를 적용한다. PR review·오늘할일은 사용자가 선택한 옵션 2 후속 PR에서
처리한다. 아직 원 코드 PR은 생성하지 않았다.

upstream/devel `b7a5388034ee66f58a7e1d5363974e83b6374f57` 위에 840개
기존 커밋을 리베이스했다. Cargo 충돌은 upstream의 PDF 기본 활성화·tiny-skia와
현재의 공통 resvg 의존성을 모두 보존했다. 기존 tracked diff와 untracked 경로를
그대로 복원했다. `cargo metadata --locked --no-deps`는 통과했다.

실제 검증한 코드 source는 `cc4255a58d8112c07013e89eda1b1a065c824fea`다.
Native CLI는 stage2256에서 release-test/native-skia, jobs 8, 공용
`target/pr-review`로 295.095초에 빌드했다. source 목록에는 vendor도 포함했고
파일 해시 불변과 실제 compiler artifact를 고정했다. stage2250의 이전 빌드
세션은 exit 143으로 중단됐으므로 통과 근거가 아니다. 전체 테스트·lint 완료를
뜻하지 않는다.

## 이미지의 직접 판독과 제외 증거

stage2265에는 간격/분수 확대 review·standalone overlay가 있다. stage2267은
원래 PNG 크기를 그대로 사용한 두 face의 18pt 전체 쪽 증거다. 벡터 p6은
94.84729%, p12는 99.96636%이며 전쪽 TSV와 동일하다. M의 가로 간격 개선과
나머지 벡터·식의 기준선/윤곽 차이를 구분한다. p6은 98% 미만이므로 그 쪽의
절대 px 회귀를 추가하지 않는다.

stage2266은 실제 PNG보다 큰 고정 crop 범위가 검은 바깥 픽셀을 만든 잘못된
진단 이미지다. 수용 근거에서 제외하고 crop 없는 stage2267로 바로잡았다.
원래 stage2257의 입력 PNG·TSV는 수정하지 않았다. 원래 TSV 94.84729%를
그 오류 이미지의 89.72738%로 덮어쓰지 않는다.

원래 11월 시험지 `all-18` p9의 새 Native raw는 99.87570%다. 반면 `all-04`
p9 98.65522%, `all-12` p7 97.66292%의 기존 WMF 경계 차이는 남는다. 최신
b7a5388034의 동조건 기준 빌드를 새로 준비하므로 과거 FE 기준으로 최종 무회귀를
선언하지 않는다. 0.01%p 하락 gate는 유지한다.

## 남은 검증과 다음 단계

stage2258의 동일 source fresh WASM 빌드를 실제 시작했다. jobs 8,
codegen-units 16으로 공용 target을 순차 사용한다. 완료 뒤 최신 devel의
Native/WASM도 순차 빌드하며 stage2262가 원본 97개를 양쪽 source/backend에서
산출한다. stage2264는 동일 입력/PDF·계산 방법/조건을 확인하고 Decimal 0.01%p
하락을 비교한다. 전체 큐·baseline 미완료를 수용으로 계산하지 않는다.

새 정식 회귀는 관련 전쪽 Native/fresh WASM 90% 및 확대 판독 뒤 새 이름으로
추가한다. 중요한 완료 쪽은 두 경로의 100→99→98% 순으로 독립 ±2px와 관계를
함께 보호한다. 현재는 fresh WASM이 미완료이므로 회귀를 추가하거나 기존
기대값/golden을 갱신하지 않았다. 전체 Rust에 남은 실패, Native Skia·lint·실제
Studio 소비 경로 검증과 최종 PR·CI·merge 후속 처리는 아직 미완료다.

기존 법령 입력의 p48은 내용 대응을 확인했고, 다음 두 관찰을 stage2261에
분리했다. Native는 빈 문단 460을 쪽 앞에 소유해 본문을 약 16px 내린다.
독립 PDF는 굵은 heading의 동일 글리프를 fill/stroke 두 번 그린다(48개 span쌍).
이는 단순 글꼴 명칭 차이만으로 설명할 수 없으며, 빈 문단 소유와 합성 굵기의
실제 호출 경로를 더 확인해야 한다. 아직 해당 입력의 출력 보정을 완료하지 않았다.
