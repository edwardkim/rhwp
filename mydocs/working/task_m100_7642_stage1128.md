# 단계 1128 자동 줄바꿈 구분 공백의 배분 소유 보정

Issue: #7642. 기준 devel은 `463c48cc228170b576c832591b76826116e86a49`다.

## 독립 근거와 실패

단계1093의 합성 HWPX를 같은 내용 그대로 한컴 engine2020의 Print로 출력한 6쪽 대조군을 사용한다. PDF 경로·SHA는 단계1117에 기록했다. 앞 공백 0·1·3개와 자간 0·음수의 각 쪽에서 Left/Justify의 첫 글자 원점은 같고, Justify의 가시 끝 글자는 본문 끝을 채운다. 원본은 수동 합성 입력이며 정상 한컴 저장본으로 분류하지 않는다.

단계1126의 공개 문자 경계 후보는 현재 구현에서 실제 실패했다. 원본 용지·여백 HU로 계산한 본문 너비266.6667에 비해 첫 줄 가시 전진은260.5다. 마지막 소비 구분자까지 배분 공백 수에 포함해 가시 글자 앞의 배분이 줄어드는 경로와 일치한다. 임의 목표 좌표나 문서 ID 분기를 추가하지 않는다.

## 생산·소비 경로와 보정

`compute_line_extra_spacing`의 내부 공백 수·가시 폭 → `extra_word_sp` → `emit_line_runs`의 말미 공백 회수 → `emitted_run_layout_positions`의 게시 positions → bbox·다음 런 원점으로 추적한다. 자동 줄바꿈에서 소비한 구분 공백도 원문 문자 소유와 자연 전진은 보존하지만 내부 낱말 사이 배분에는 참여하지 않는다. 마지막 음수 자간의 가시 끝 보정도 저장 줄과 같은 경로를 사용한다. 문자간 배분·탭·마지막 개체 이전 공백의 별도 계약은 유지한다.

방출 시에는 선두 또는 말미 공백의 배분 회수가 필요하면 exact kerning 적용 여부와 무관하게 같은 positions를 게시한다. exact pair가 없는 fallback에서도 회수 결과를 버리지 않는다. 이 묶음은 Frame의 PUA 폭을 전역 재해석하지 않으며 단계1117의 공개 경계 수정은 유지한다.

## 검증 순서와 한계

새 devel의 배경 처리 회귀와 기존 집중 검사·진단 후보를 함께 실행하고 11문서245쪽 및 독립 Print6쪽의 Native TSV·영향 review를 산출한다. 그 뒤 fresh WASM과 새 base 대조를 진행한다. 새 공식 fixture·회귀 추가와 기존 합성 검사 기대값 변경은 관련 Native/fresh WASM 시각 선행 조건을 충족한 뒤 수행한다. 현재 후보는 ignored 실행 증적과 review worktree에만 있으며 정식 회귀 추가로 보고하지 않는다. 남은 HWP3 19쪽·HWPX25쪽과 tracked4쪽 하락은 별도로 해소해야 한다.

초기 묶음에서 fmt와 새 base 기준 unit-tier는 통과했지만 컴파일이 E0061로 실패했다. 리베이스에서 분리된 머리말·꼬리말의 배경 수집 호출에 새 인수 두 개를 전달하지 않은 통합 누락이다. 본문·셀·머리말/꼬리말의 전체 호출을 다시 확인하고, 실제 bin_data와 진입 시점의 배경 삽입 위치를 전달하도록 보정했다. 이 결과는 렌더링 결함의 수정 전 FAIL로 세지 않으며 같은 승인 범위의 검증을 다시 실행한다.

## 실제 검증 결과와 남은 차이

구현 source `fa56a97f683fb7ca690ae6a155bf1902bcfc9406`에서 집중 검사 78건이 통과했다. 새 기준 SHA를 전달한 source unit-tier 검사도 통과했다. Native CLI는 명시적인 `native-skia` 빌드의 종료 코드 0과 실행파일 해시로 고정했다. 테스트만 다시 실행한 뒤 실행파일 mtime이 바뀌지 않은 것을 실패로 보았던 초기 검증기 판단은 실제 컴파일 실패와 구분했다.

집중 시각 검증의 실제 범위는 새 배경 처리 대조군을 포함한 16문서 257쪽이다. 전쪽 Native와 fresh optimized WASM을 모두 산출했고, 15문서는 양쪽 최저값이 90% 이상이다. 원본 HWP3는 19쪽이 Native 88.60821%, WASM 88.93917%로 미달한다. HWPX 변환본의 64쪽은 Native 최저 92.04012%, WASM 최저 92.04361%다. 추적 변경 문서는 최저 92.39495%와 92.55982%이며, 지적된 4쪽의 Native 값은 97.19361%다. 점수 통과를 시각 완료로 판정하지 않는다.

독립 Print 6쪽은 Native 최저 97.19000%, WASM 최저 97.46868%다. Native의 1·2·4·6쪽 review를 직접 확인해 앞 공백과 Left/Justify 줄 구성을 대조했다. 이 PDF의 원본은 같은 3회 반복 입력이며, 집중 검사 후보의 8회 반복 입력과는 다르다. 따라서 6쪽의 통과를 8회 반복 입력의 공식 fixture 증거로 옮기지 않는다. 새 정식 회귀는 같은 6쪽 원본과 독립 PDF를 사용해야 하며 fresh WASM의 확대 판독도 남았다.

합성 후보의 첫 기대값 중 명목 글자 전진 끝을 본문 끝에 0.11 이내로 고정한 검사는 독립 PDF의 명목 bbox와 실제 잉크 경계를 구분하지 못했다. 해당 후보 실패를 실제 넘침의 증거로 세지 않는다. 대신 Left와 Justify에서 소비한 말미 구분 공백의 자연 전진이 같고 내부 공백만 배분되는 관계를 검사했다. 이 관계 후보는 현재 source에서 통과하고, 실제 새 `devel`에 링크한 별도 공개 API 진단에서는 의도한 자연 전진 assertion으로 실패했다. 다른 fixture 누락으로 생긴 앞선 컴파일 실패와 구분한다. 아직 정식 회귀 추가 완료가 아니다.

확대 판독에서 HWPX 25쪽의 `정/보시스템`과 추적 변경 4쪽의 `반/영하는` 줄 소속이 독립 Print와 다른 것을 확인했다. PUA를 표준 네모로 바꾼 파생 입력은 25쪽의 줄 소속을 맞추지만 24쪽을 4줄에서 5줄로 바꾸므로 전역 폭 치환을 다시 적용하지 않는다. 파생 입력은 계측용이며 원본의 일치 증거가 아니다. 독립 Print의 자연 공백 전진은 음수 자간을 반영하므로, 공백에서 자간을 전부 제외하는 가설도 채택하지 않았다.

새 기준 Native에서 HWP3 19쪽은 72.38875%, 추적 변경 4쪽은 94.68857%다. HWP5 변환본은 기준 출력 65쪽과 PDF 64쪽이 달라 TSV를 산출하지 못했다. 이 실패를 임의 대응 페이지의 수치 비교나 통과로 바꾸지 않는다. 현재 head의 전체 55문서 검증과 새 기준 Native/fresh WASM의 전쪽 비교는 진행 중이며, 전체 Rust 회귀·lint·최종 PR 게이트는 미완료다.
