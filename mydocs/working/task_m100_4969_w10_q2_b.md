# Task M100 #4969 W10-Q2-B — horizontal shadow measurement

## 판정

Q2-B는 **qualified**다. W9 `ExactFontSourceRegistry`의 immutable generation·slot·handle·bytes를 그대로 빌리는
`HorizontalShapingContext`와 transaction을 추가했다. rustybuzz face는 transaction에서 exact source별 한 번만
준비하고, px로 변환한 결과는 bounded context cache가 `Arc`로 공유한다.

기계 판독 결과는
[`w10_q2_b_horizontal_shadow.json`](../tech/investigations/issue-4969/w10_q2_b_horizontal_shadow.json)이다.

이 모듈은 `renderer/mod.rs`에 선언됐지만 composer·layout·render tree·paint 어느 곳에서도 호출하지 않는다.
따라서 이번 절편의 제품 출력 변화는 0이며, Q2-C 승인 전에는 line break나 bbox에 영향을 주지 않는다.

## owner와 cache 경계

- context는 W9 exact-source registry를 소유하고 transaction은 그 generation을 불변으로 빌린다.
- cache key는 registry generation, exact source handle, 원문 전체, font size·장평 bit identity,
  script·language, ordered feature를 모두 비교한다. hash만 같다고 결과를 재사용하지 않는다.
- 같은 요청의 cache hit도 호출자가 준 새 `attemptId`를 가진다. attempt 회계와 `Arc` payload 재사용을 섞지 않는다.
- transaction 내부 rustybuzz face cache는 같은 source의 서로 다른 두 run에서도 parse count 1을 유지했다.
- entry 4,096개 외에도 raw text 1 MiB, glyph 262,144개, cluster 262,144개의 context 총량 상한을 둔다.
  mutex poison·상한 초과·유효하지 않은 scale은 partial result 없이 typed reason으로 닫는다.
- 원문은 메모리 cache key에만 있고 trace·JSON에는 없다. font bytes와 host path도 diagnostics에 복제하지 않는다.

validator의 zero-copy SFNT table view는 cache miss별 요청 capability를 다시 대사한다. 반면 실제 shaping face는
source별 한 번만 준비한다. 이 구분은 source identity 검증을 cache에 맡겨 생략하지 않으면서 반복 shaping parse를
막기 위한 것이다.

## font-unit에서 px·cluster로의 변환

horizontal LTR 결과는 다음 한 번의 변환만 거친다.

```text
x scale = effective font size px × width ratio ÷ unitsPerEm
y scale = effective font size px ÷ unitsPerEm
glyph x = 누적 pen x + xOffset × x scale
glyph advance x = xAdvance × x scale
```

glyph의 UTF-8 cluster offset을 문자 경계와 대사하고, 연속한 같은 cluster를 glyph range와 Unicode scalar range에
함께 연결한다. `range_width(start, end)`는 양 끝이 cluster 경계일 때만 폭을 반환한다. ligature나 옛한글
cluster 내부 범위에는 가짜 문자 advance를 만들지 않고 `None`으로 닫는다.

## 공개 fixture shadow delta

모든 px 값은 effective font size 10px, 장평 80% 조건이다.

| lane | baseline | common shaping | delta·의미 |
| --- | ---: | ---: | --- |
| K0 → W9 K1, Noto `AV` | kern off 9.464px | kern on 9.320px | -0.144px, glyph·cluster 수 유지 |
| Latin liga, Noto `office` | liga off 20.504px, 6 glyph | liga on 20.488px, 4 glyph | -0.016px, scalar `1..4`가 한 cluster |
| old Hangul, Source Han | nominal cmap advance를 전 scalar에 만들 수 없음 | 15.456px, 4 glyph·2 cluster | 폭 비교보다 `0..3` Jamo cluster 내부 절단 금지가 핵심 |

옛한글 fixture는 nominal cmap lookup만으로 모든 scalar advance를 만들 수 없었다. 이는 기존 문자별 nominal replay에
임의 폭을 보충해서는 안 되고, Q2의 complex-required subset을 cluster 결과로 다뤄야 한다는 추가 근거다.

- 동일 Noto source에서 두 cache miss와 한 hit: parsed face 1, miss 2, hit 1
- Q2-A focused source: 12 pass, 0 fail
- `cargo check --locked --lib`: pass
- `cargo clippy --locked --lib -- -D warnings`: pass
- `cargo clippy --locked --target wasm32-unknown-unknown --lib -- -D warnings`: pass
- `git diff --check`: pass
- composer·layout·render tree·paint consumer: 0

wall time과 RSS는 source 등록 SHA 대사와 다섯 focused test를 합친 기초 참고값이다. 제품 layout 경로가 아직 이
context를 호출하지 않으므로 페이지 wall time 영향으로 해석하지 않는다. 실제 layout overhead·WASM size는 Q2-F에서
W9 기준선과 같은 절차로 측정한다.

저장소 root의 `cargo test --target wasm32-unknown-unknown --lib --no-run`은 기존 dev dependency
`wait-timeout`의 wasm32 미지원으로 중단됐다. 변경 코드 자체는 WASM lib clippy를 통과했고, generated suite나 root
Cargo를 변경하지 않은 별도 최소 harness가 동일 integration source 5건을 Node WASM에서 실행했다. harness는 검증
후 삭제했다.

cluster 경계·hard boundary·rollback 단위를 포함한 activation matrix를 먼저 제시해 별도 승인을 받아야 한다.
