# #7642 기준 PDF의 글자 stroke를 분리한 진단

## 원본과 실제 관측

10월 원본 7쪽의 본문은 HWPX와 실제 layer JSON 모두 bold=true다.
source `197f88e079`의 frozen WASM으로 조회한 layer에도 같은 속성이 보존된다.
glyph 하위화는 bold 경로를 거부하고 기존 합성 painter로 되돌아가는 조건을 확인했다.
속성 누락이라고 단정하거나 굵기를 키우는 source 변경은 하지 않았다.

같은 Print PDF의 Font F4는 실제 subset 프로그램을 포함하며 OS/2·cmap·name 없이
head/hhea/maxp/hmtx/fpgm/prep/cvt/loca/glyf를 갖는다. FontDescriptor의 Flags는 32,
StemV는 0이다. 이 관측만으로 PDF가 손상됐거나 다른 글꼴을 쓴다고 판단하지 않는다.
원본 FontFile을 포함한 진단 복사본은 ignored output에만 두며 font 파일을 공개하지 않는다.

본문 일부의 동일한 96DPI 영역에서 ink mass는 Native 228.54, Cairo 462.88,
Splash 292.13, MuPDF 246.76, PDFium 475.53이었다. 좌표·텍스트·원본 PDF는
같다. 이 값은 문서의 raw 실루엣 점수나 PR gate가 아닌 glyph raster 분리 관측이다.
다른 renderer의 높은 일치율을 골라 제출하지 않는다.

## 좌표 동치와 독립 사각형 대조

PDF의 `.120 cm / 75 Tf / 1.500 w`와 좌표를 환산한 `9 Tf / .180 w`를
같은 source glyph로 대조했다. Cairo·Splash·MuPDF는 fill/stroke 각각 같은 PNG를
만들었다. 따라서 이 관측으로 CTM을 누락한 오류라고 주장하지 않는다.
PDFium의 stroke에는 작은 raster 차이가 있었으며 별도로 보존했다.
Cairo의 antialias gray를 명시해도 기본 결과와 같았고, best/none은 다른 결과였다.
이 옵션 변경도 해결 근거가 아니다.

이어 사각 윤곽 한 개만 직접 작성한 TTF와 같은 PDF 사각 경로를 대조했다.
한컴 글꼴 바이트·윤곽을 사용하지 않은 수학적 진단이다. 96DPI에서 순수 기하의
fill 면적은 60.48, 0.18pt stroke를 더한 면적은 64.2816이다.

| renderer | 글리프 stroke+fill | 사각 경로 stroke+fill | 글리프 fill | 경로 fill |
|---|---:|---:|---:|---:|
|Cairo|78.49|80.00|60.48|60.47|
|Splash|66.48|72.00|60.51|56.00|
|MuPDF|64.80|65.80|60.57|60.28|
|PDFium|77.46|77.46|61.82|72.00|

얇은 stroke의 표시 방식이 달라지는 관측이다. 이를 곧바로 글꼴 차이나 엔진 배치
결함으로 환원하지 않는다. [Adobe PDF Reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.5_v6.pdf)는
요청 선폭과 장치의 실제 선폭 차이 및 stroke adjustment의 영향을 구분한다.
순수 면적만으로 renderer의 규격 위반을 판정하지 않는다.

공개된 [Poppler Cairo source의 해당 revision](https://skia.googlesource.com/third_party/poppler/+/c7f3f602f8aa648feed2aee8f17c540c19dc1cca/poppler/CairoOutputDev.cc)은
stroke_adjust를 기본 true로 두고, 비인쇄 경로에서 가는 선을 최소 장치 한 칸으로
늘리는 코드를 갖는다. 현재 실행한 24.02.0 binary와 같은 revision이라는 증거는
아직 없으므로 설치본의 원인 확정으로 쓰지 않는다. 실제 Print 물리 선폭·표시의
선 강조·고정 reference 정책을 구분해 확인할 다음 조사 근거다.

## 판정과 남은 일

기존 Cairo의 균일색 보존 계약과 이 stroke 진단을 함께 검토한다. 이 단계에서는
canonical PDF renderer, DPI, 입력/PDF, raw 식·90%·98%·0.01%p를 바꾸지 않았다.
진단 PDF를 한컴 정답으로 제출하거나 기대값을 갱신하지 않았다. reference의
stroke 차이를 분리하기 전에는 이 영역을 새 px 회귀나 시각 완료 근거로 쓰지 않는다.

ignored stage2111~2114·2116~2118에 layer JSON, 원본 content 관측, 원본 변경 없음,
실제 renderer 명령·PNG와 독립 사각 glyph의 생성식을 보존한다. 같은 엔진 source의
전쪽 Native/fresh WASM과 lint는 계속 실행 중이며 해당 결과와 진단의 의미를 구분한다.
