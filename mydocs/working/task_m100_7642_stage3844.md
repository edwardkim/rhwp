## 원인과 수정

[앞 단계의 원인 추적](task_m100_7642_stage3823.md)을 실제 출력으로 검증했다.
여러 줄의 높이를 매번 실수로 환산해 누적하면서, 정확히 들어가는 내용도 셀 높이를
넘었다고 판정해 좌우 안여백을 1px로 축소했다. 수정은 원본 HWPUNIT의 정수 합을
한 번만 환산한다. 문서 이름·특정 높이·줄 수로 분기하거나 비교 허용치를 늘리지 않았다.

구현 커밋은 `ca0c4f4e3a57434853f96849f748ad1b190fddda`이며, rustfmt까지 적용한
실제 Native/fresh WASM producer는 `f59acc84f3de6ab9c4d93e0e0622bcc9e4b2bbff`다.
측정·배치의 소비 경로와 실제 넘침 시의 기존 동작은 앞 단계에 기록했다.

기존 수동 PDF의 결과를 새 기준의 결과로 재사용하지 않았다.

## 직접 판독과 글꼴 확인

Native/fresh WASM의 전체 review·standalone overlay와 같은 문단 확대본을 각각 열었다.
줄바꿈·들여쓰기 결함은 해소됐지만, Native의 작은 크기 글자 농도는 PDF와 차이가 남는다.
이를 점수 통과만으로 없어진 차이라고 보고하지 않는다.

실제 Native renderer snapshot의 글꼴 추적에서 표 문단의 396개 문자 모두
`맑은 고딕 → Malgun Gothic`, 공급 `system`으로 확인했다. ExtraLight fallback 가정은
성립하지 않는다. 별도 읽기 전용 비교에서는 설치된 malgun.ttf와 PDF의 비교한 완성형 한글
윤곽이 같았고, 전체 149개 글자의 전진폭도 같았다. 전체 윤곽 일치는 133/149개이며 일부
문장부호·숫자·호환 자모는 달랐다. 288dpi의 독립 재출력에서는 농도 차이가 작아졌으나,
그 진단으로 96dpi 판정이나 농도 차이의 원인 입증을 대신하지 않는다. 대상 PDF에서 추출한
글꼴을 렌더 입력으로 사용하지 않았고, 임의의 굵게 표시나 감마 보정을 추가하지 않았다.

이번 새 검사는 해소한 안여백·줄바꿈·문단 소유 관계를 보호한다. 글자 농도를 정상 baseline으로
고정하지 않으며, 남은 농도 차이의 완료 판정과 이 페이지의 절대 px 좌표 핀은 보류한다.

## 새 회귀 검사와 수정 전 검출

[새 검사](../../tests/cases/issue_7642_cell_padding_unit_relations.rs)는 기존 검사 함수를
교체하지 않고 새 이름으로 추가했다. 전체 74쪽의 Native/fresh WASM 시각 선행 조건을
확인한 다음 추가했다. 원본 속성으로 안여백을 읽으며, 독립 Print의 11개 줄 끝·네 문단
소유·원문 내용 보존·줄 순서·비겹침·셀 안쪽 포함을 검사한다. JSON bbox의 0.1px 직렬화
반올림 오차는 두 상자의 상대 관계 비교에서만 허용하며 절대 위치를 고정하지 않는다.

같은 Rust 검사 실행 파일을 보존한 수정 전/후 CLI에 각각 실행했다.

1,599개 source·6,955개 정적 test attribute·28개 suite와 20개 예외, 48/48 target을 확인했다.
CI에 별도 개별 호출을 추가하거나 기존 검사·기대값을 삭제·완화하지 않았다.
