# Task M100 #4969 W10-Q2-D5-R2 — opt-in font-by-key transport 결과

## 판정

Q2-D5-R2는 **qualified**다. 기본 layer JSON과 기존 API 호출은 font bytes inline 계약을 그대로 유지한다.
Studio 내부의 capability-detected opt-in 경로만 page JSON에서 font payload를 빼고 exact resource key로 한 번
조회한다. `1/2/8 page`에서 fetch는 모두 1회였고 missing·wrong·oversized·stale 응답은 verified cache를 채우지
못하며 TextRun fallback이 선택됐다. NO_LS boundary와 D4 selector 자격은 변경하지 않았다.

기계 판독 결과는
[`w10_q2_d5_r2_font_by_key_transport.json`](../tech/investigations/issue-4969/w10_q2_d5_r2_font_by_key_transport.json)에
고정한다.

## 생산자 계약

`LayerJsonOptions.omit_font_bytes`의 기본값은 `false`다. 따라서 `PageLayerTree::to_json()`과 명시적 default
options의 결과는 byte-identical이다. opt-in일 때만 `resources.fontBlobs`를 빈 배열로 내보내며 다음 정보는
그대로 보존한다.

- `resources.fontBlobKeys`
- `fontResources.blobs[].dataRef.id`
- BLAKE3 digest와 byte length가 포함된 canonical `font:blake3:<length>:<digest>` key
- blob portability와 face identity/face index

그림 byte omission과 font byte omission은 document JSON cache에서 각각 독립된 bit를 쓴다. 기존 `u8` cache
fingerprint를 `u16`으로 넓혀 inline·image-by-key·font-by-key 변형이 같은 cache entry를 잘못 공유하지 않게 했다.

## exact resolver와 소비자 cache

WASM `getSourceFontBytes(key)`는 현재 `ExactFontSourceRegistry`가 실제 보존하는 owner만 검색한다. key가
canonical 형식이고 선언 길이가 32 MiB 이내이며 registry bytes의 길이와 BLAKE3가 모두 일치할 때만 복사본을
반환한다. host font 이름·경로·family 재탐색은 하지 않는다.

Studio는 WASM에 resolver capability가 있을 때만 네 번째 omission option을 켠다. 첫 cache miss에서 받은 bytes를
resource key·digest·length·32 MiB 개별 상한·64 MiB document 상한으로 재검증한 뒤 한 번에 commit한다. 같은
document generation과 key에서는 다시 fetch하지 않는다. generation이 증가하면 blob·typeface·font cache를 함께
비우며 더 낮은 과거 generation은 cache를 다시 채울 수 없다.

by-key batch는 staging을 거쳐 전건 검증 뒤 commit한다. 두 resource 중 뒤 resource가 실패한 fixture에서도 앞
resource가 부분 등록되지 않았다.

## 보호 불변식

1. default inline JSON과 기존 2·3인자 WASM 호출은 바뀌지 않는다.
2. opt-in은 payload만 생략하고 exact identity metadata를 남긴다.
3. resolver는 현재 registry owner 외의 bytes를 family 이름으로 추측하지 않는다.
4. consumer는 key·digest·length·상한을 검증하기 전에 cache를 변경하지 않는다.
5. by-key batch 하나가 실패하면 새 verified entry는 전부 0이다.
6. document generation이 바뀌면 이전 verified blob·typeface·font를 재사용하지 않는다.
7. fetch·검증·typeface 실패에서 TextRun fallback이 남는다.
8. R2는 NO_LS line selection·bbox·next origin·sidecar owner를 열지 않는다.

## 다음 절편

Q2-D5-R3는 새 구현을 추가하지 않고 resource qualification을 수행한다. native/WASM·inline/by-key·cache miss의
glyph geometry와 CanvasKit bbox parity, `1/2/8 run × 1/2/8 page` counter, warm/cold layer build·JSON 크기·retained
bytes·generation invalidation을 한 보고서에서 확정한다. R3가 qualified가 아니면 N0/N1은 시작하지 않는다.
