# Stage 123 — 큰 둥근 괄호의 공통 조립 윤곽

Issue: #7642. Stage 121의 Native 행렬·근호 60종 3쪽은 최저 91.04621%다.
점수와 별개로 22pt의 분수 PMATRIX를 확대하면 한컴의 직선 가운데 부분을 RHWP가
하나의 긴 Bézier 곡선으로 표시한다. Stage 121 fresh WASM의 고정 산출·대조를 완료한
뒤 이 모양을 보정한다. 기존 검사 이름을 수정하지 않고 필요한 새 관계형 검사를 추가한다.

## 독립 근거와 적용 경계

- 공개 `LatinModernMath-Regular.woff2`의 MATH 수직 괄호 variant 최댓값은 2991/1000em이다.
  그보다 큰 둥근 괄호는 cap·extender·tail의 assembly 정보를 사용한다.
  [OpenType MATH 계약](https://learn.microsoft.com/en-us/typography/opentype/spec/math)에 따라
  extender 수와 connector 겹침을 산출한다. 임의의 문서 번호나 절대 px 높이로 분기하지 않는다.
- 독립 한컴 Print의 해당 큰 괄호는 HYhwpEQ의 E07C cap·E07E tail로 표시된다.
  공개 디자인을 원 face의 bbox 메트릭에 대응한다. UPM 1024, cap 위끝 623,
  tail 아래끝 5, cap/tail 높이 826, 왼쪽 bbox 38..443, 오른쪽 -41..365다.
  사설 글꼴의 바이트·곡선은 source나 Git에 복제하지 않는다.
- 논리 줄 프레임과 잉크 프레임을 구분한다. 괄호의 전체 예약 높이에서 일반 글줄의
  여백만 제외하고 위·아래로 같은 여백을 둔다. 본체의 쪽·행·열·슬롯 폭은 변경하지 않는다.
  지원되는 원 face의 일반 줄 메트릭이 없으면 기존 경로를 유지한다.
- 작은 괄호·일반 glyph 구분자·다른 face·대괄호·수직선에는 새 조립 경로가 적용되지 않는다.

## 생산과 소비 및 검증

`delimiter_outline` → 공개 MATH 조립 helper → `LayoutKind::Paren`의 left/right outline →
SVG·Canvas의 기존 outline 소비 경로다. 두 backend가 서로 다른 괄호 곡선을 추측하지 않는다.
한컴 60종·추가 근호 45종·HWP3 16쪽의 Native/fresh WASM TSV와 큰 괄호 확대 비교를
다시 산출한다. 새 관계형 회귀는 관련 모든 쪽의 90% 이상 및 직접 판독 뒤에만 등록한다.

ignored `stage123-round-assembly-diagnostic/`는 변경 전 고정 SVG에서 공개 부품의 가설을
대조한 결과다. 3쪽 100.00000/98.24227/91.49265%로 나타났지만 생산 코드 검증이 아니다.
원래 글자 크기가 SVG stroke 수치에서 반올림되어 있으므로 정확한 source 빌드의 대조를
대신할 수 없다. 공개 글꼴의 굵기 차이도 확대 확인하며 최종 판정은 실제 새 출력으로 한다.

수식 카탈로그 전체 259종의 Stage 121 Native 18쪽은 쪽수는 같지만 17쪽이 90% 미만이며
최저 15.51742%다. 이 결과는 전체 카탈로그의 시각 완료나 golden 갱신 근거가 아니다.
해당 출력 분석과 최종 원본 55개·853쪽 검증 및 전체 Rust 회귀는 계속 남아 있다.

## 구현 반영과 다음 실행

Stage 121 Native/fresh WASM 21쪽의 완료 및 같은 code source 해시를 확인한 뒤
`round_stretch.rs`·공개 `round_stretch_data.rs`를 추가하고 `delimiter_outline`에 연결했다.
출력 backend의 기존 outline 소비 경로를 재사용한다. GUST 저작권·라이선스·공개 원본
SHA-256과 파생 부품을 `THIRD_PARTY_LICENSES.md`에 기록했다. 사설 윤곽은 포함하지 않았다.
fmt와 포맷 완료 후 파생 suite 준비·고정 base manifest 검사는 종료 코드 0이다.
현재 커밋의 실제 Native/fresh WASM 재빌드·TSV·확대 판독은 다음 순차 검증에서 확인한다.

이전 Stage 113 전수 실행은 `running` 기록이 남았으나 실제 controller는 종료됐다.
관측한 종료 코드는 143, 로그의 마지막 오류는 디스크 부족이다. 중간 TSV 13건을 별도
복구 원장에 기록했으며 현재 코드의 완료 증거로 세지 않는다. 종료된 실행의 재생성 가능한
SVG 6.957GiB를 정리했고 입력·PDF·PNG·TSV·로그와 공유 Cargo 캐시는 보존했다.
ignored `stage113-terminal-recovery.json`·`stage113-terminal-svg-cleanup-receipt.json`에
근거를 남겼다. 최종 전수 실행은 raster가 이미 기록한 중간 SVG 해시를 재사용해 정리하며
동일한 대용량 파일을 다시 전부 읽는 비용을 줄인다.
