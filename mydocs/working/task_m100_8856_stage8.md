# #8856 그림의 부드러운 가장자리 공통 도색

앞 단계의 반경 전달을 `17800f1496`으로 커밋한 뒤 시작한다. 원 모델·저장·조판의
반경 전달과 실제 마스크 도색은 별개다. 원 해결 #8656의 크기·crop 계약은 유지한다.

단색, 확대, 자르기, 추가 반경, 투명 PNG를 독립 한컴 2020/2024 Print로 대조했다.
확대 전 bitmap 크기에 따라 반경을 늘리지 않으며, 자른 뒤 새 경계에도 효과가 있다.
모서리는 가로·세로 감쇠의 곱과 일치하고 단순 최소 거리 감쇠와는 다르다.
투명 구멍의 경계도 안쪽으로 흐려지며, 균일 alpha 128의 중앙은 128을 유지한다.
따라서 RGB 자체를 흐리거나 원 alpha를 두 번 곱하지 않는다.

Windows GDI+의 독립 Gaussian 표본은 유한 커널 sigma=radius/2와 최대 1단계 차이다.
이를 한컴이 같은 API를 호출한다는 증거로 해석하지 않는다. 효과 표본의 반경 정수화에는
추가 확인할 경계값 차이가 있으므로 대조군 점수를 제품 완료로 표시하지 않는다.

공개 메모리 PNG로 LayerBuilder의 실제 PaintOp 이미지에 경계·구멍·기존 투명도와
crop의 소유가 반영되는지 먼저 실패를 실행한다. 원 RenderTree·원본 BinData를 바꾸지 않고
공통 이미지 준비 경로에서 처리하여 Native와 WASM이 같은 효과 결과를 소비하게 한다.
반경 없음/0은 재인코딩하지 않는다. 표본 준비·자르기·최종 인쇄 재표본의 차이는 실제 원본
Native/fresh WASM 및 같은 쪽 review/overlay로 재검증한다.

## 실제 공통 도색과 집중 검증

공통 LayerBuilder에서 원본 crop을 해소한 alpha를 침식·유한 Gaussian으로 준비한다.
효과 격자는 장치 확대와 분리하며, 색 자원은 원본 가시 창보다 축소하지 않는다.
사진 RGB를 흐리지 않고 전역 opacity와 밝기·대비는 기존 소비 경로에 남긴다.
원 모델·RenderTree·BinData는 보존하고 paint 복제본의 crop만 한 번 해소한다.
준비된 바이트에는 SourceWindow 자원을 사용하여 같은 BinData의 무효과/다른 반경과
지연 조회·캐시가 섞이지 않게 한다. 반경 없음/0은 재인코딩하지 않는다.

새 경계·crop 검사 2건은 실제 0 PASS / 2 FAIL로 누락을 재현했다. 보정 후 사진 해상도와
한 픽셀 RGB 보존 반례까지 추가한 최종 소스는 3 PASS다. 기존 모델·저장·전달 4건과
#8593 크기·자르기 2건도 최소 글꼴 Native에서 다시 통과해 집중 검증은 총 9 PASS다.
중간 컴파일 중 변경된 소스의 실행은 최종 영수증에서 제외하고, 마지막 고정 소스의
after-final 실행과 실제 해시만 사용한다.

각 경로 6쪽을 같은 독립 PDF·96dpi·기존 raw 2px 판정으로 실제 산출했다.
interview 1쪽 사진 외곽의 감쇠를 review/overlay에서 직접 확인했고, 다음 본문·2쪽을
보존한다. 앞 단계의 최소 환경 기록은 1쪽 Native 97.19457%, WASM 97.32378%다.
제목의 원본 글꼴 부재에 따른 글리프·간격 차이는 이 사진 보정의 완료에 포함하지 않는다.

Mac locked wrapper의 로컬 no-opt WASM을 완료했다. 루트 pkg·Studio public·실제 새
Chrome의 초기 JS/WASM GET 응답 해시가 일치하고, 그 응답으로 캡처한 1쪽 PNG는
현재 전쪽 WASM의 같은 쪽과 바이트가 같다. Docker 최적화 통과로 주장하지 않는다.
처음 HTTP 진단은 쪽 묶음의 옵션 경로를 상위 폴더로 잘못 지정해 브라우저 시작 전에
실패했으며, 실제 성공한 수정 실행만 영수증에 사용한다.

작업 격자의 반경 정수화는 추가 반경에서 차이가 남으며, 한컴의 내부 API나 정확한 마스크
전표본 일치를 주장하지 않는다. 투명 구멍 모서리의 독립 비교에서는 단순 축별 곱도
완전히 일치하지 않았고, 원형 침식으로 바꾼 진단은 사각 침식보다 오히려 달랐다.
그 차이를 문서별 상수로 맞추지 않는다. 제품의 실제 집중 페이지와 원본 크기·crop·alpha
보존을 각각 검증한 결과로 범위를 판단한다.

원본·PDF·전쪽 TSV·같은 쪽 raw/review/overlay·소스/바이너리/HTTP 영수증은
[단계별 증적](../pr/assets/issue8856/stage8-soft-edge-paint/README.md)에 보존했다.
이 단계만으로 #8856 전체나 제출 게이트 완료를 선언하지 않는다. 남은 글리프·간격·도형의
실제 원인 보정과 최종 전체 검증을 계속한다.

## 추가 투명 PNG의 실제 소비 대조

원 alpha 128과 내부 투명 구멍의 반경 0/1000 HU를 두 Print 엔진·두 backend에서
추가로 실제 출력해 총 16조건을 확인했다. Native/WASM 점수는 각 조건에서 같았다.
2020은 반경 0 두 조건 모두 100%, 반경 1000은 alpha 128 99.88653%,
구멍 99.98980%다. 2024는 반경 0 두 조건 모두 100%, 반경 1000은 각각
97.98599%와 99.07187%였다.

확대 판독에서 2024의 균일 반투명 중앙 색이 달랐다. 효과 없는 반경 0에서도
같은 좌표의 Native RGB(159,191,223)와 PDF RGB(206,222,238)가 달라,
이번 효과가 만든 새 중앙 색 회귀로 취급하지 않는다. raw 100%는 실루엣 일치일 뿐
RGB 동일성의 증거가 아니다. 이 기존 색·마스크의 장치 전달 차이는 같은 브랜치에서
계속 원인을 확인·보정하며, 이 단계의 사진 효과 복구로 완료를 대신하지 않는다.
[추가 16조건의 실제 증거](../pr/assets/issue8856/stage8-soft-edge-paint/alpha-visual-validation.json)에
전쪽 TSV·동일 쪽 raw/review/overlay·색 표본을 구분해 보존한다.
