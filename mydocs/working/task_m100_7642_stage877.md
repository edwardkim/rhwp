# 단계 877 저장 줄 좌표축·캡션 간격·등록 글꼴 공급의 공통 보정

Issue: #7642. 기준 a5e88ad682c805e1d845502ddc9521b94ea8eccd.

## 독립 근거와 실제 소비 경로

- 단계 874의 a1dea81dd Native는 37쪽 99.94404%로 첫 조각의 행 소유를 맞췄다. 38쪽 첫 행도 Print와 같아졌지만, 캡션과 그 뒤 내용은 8px 더 내려가 64.95407%가 됐다. 이는 새 후보에서 확인한 회귀이며 점수 기준을 완화하지 않는다.
- 첫 줄의 8082HU는 인라인 형제 표·캡션·바깥 여백의 합이다. 부동 표는 같은 줄에 앵커됐지만 이 줄 높이를 소유하지 않는다. 원본 닫힌 종료 프레임은 남은 행 8232HU + 캡션 1802HU + 여백 276HU = 다음 문단 vpos 10310HU다. 현재 종료 커서는 145.493333px로, 이 프레임의 137.466667px에 호스트 후행 간격 600HU가 중복된 값이다.
- `float_placement::block_table_caption_host_spacing_px`는 같은 원본 줄을 실제 소유하는 인라인 형제 상자를 인증하면 부동 캡션에 그 줄 간격을 재사용하지 않는다. `table/block/prepare.rs`의 캡션 예산과 `layout/table_partial.rs`의 실제 캡션 원점이 같은 조회를 소비한다. 이름·행 번호·관측 px를 조건으로 쓰지 않는다.
- 57쪽 저장 TAC fit의 measured/declared/caption 잔차는 0이고 수용 자체는 성공했다. `controls::try_place_stored_tac_paragraph`의 `StoredTacPlan`이 원본 축을 발행했지만 `section/post_flow.rs`가 다시 초기화했다. 실제 inline placement의 `stored_column_origin_hu`를 해당 후처리에도 전달하여 fit과 paint의 축을 유지한다. layout.rs는 이미 같은 필드를 소비한다.
- 공식 한컴 글꼴의 등록 디렉터리 `/usr/local/share/fonts/hancom-office-2020`은 설치 원본의 심볼릭 링크다. `Path.rglob`는 내부 디렉터리 링크를 따라가지 않아 WASM 비교의 catalogue가 설치 face를 누락했다. 수집은 링크를 따라가며 물리 디렉터리 식별자로 순환을 방지한다. 같은 font program의 해시·face index를 보존한다.
- #5821 아래 문장의 Print font는 H2hdrM이며 원본도 HY헤드라인M이다. 설치 H2HDRM.TTF의 영문 family `HYHeadLine M`을 기존 공통 별칭에 추가해 Native도 원 face를 찾는다. 글꼴 파일을 복제해 커밋하거나 시스템 글꼴 설정을 바꾸지 않는다.

## 실행 결과와 다음 검증

새 공급 회귀 `test_registered_symlink_directory_supplies_fonts_without_following_cycles`는 수정 전 0 face / 예상 2 face로 실패했다. 수정 후 실제 두 원본 face와 경로를 보존했고 Python 계약 검사 21건이 모두 통과했다. 이것은 파일 공급 계약이며 렌더링 시각 통과로 승격하지 않는다.

Native 하나를 새로 빌드하고 원본 HWPML의 3·37·38·57·68쪽 및 #5821 전체 1쪽을 함께 대조한다. fresh WASM은 그 코드와 수정한 catalogue로 다시 출력한다. 실제 지표와 확대 판독을 완료하기 전에는 회귀 기대값 변경·PR 생성·완료 판정을 보류한다. 실패 로그·TSV·진단 JSON은 ignored output에 둔다.
