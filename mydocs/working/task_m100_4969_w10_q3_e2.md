## 판정

Q3-E2는 **qualified-public-dormant**다. `HwpDocument.setExactFontInstance(optionsJson)`와
`clearExactFontInstance(optionsJson)`를 wasm-bindgen public surface에 추가했으며, 두 adapter는 Q3-E1 strict native
command를 그대로 호출한다. validation·canonicalization·mutation 로직의 WASM 사본은 만들지 않았다.

생성 TypeScript 선언과 실제 Node/WASM 왕복에서 native와 같은 status·canonical axis·generation·error schema를
확인했다. 공개 요청 owner는 열렸지만 composer activation과 outline publication은 추가하지 않았으므로 default 제품
출력은 그대로이고 Q3-E3·E4 red 두 건이 남아 있다.

## 공개 계약

```ts
doc.registerExactFontSource(charShapeId, languageIndex, fontBytes, faceIndex);
doc.setExactFontInstance(JSON.stringify({
  charShapeId,
  languageIndex,
  mode: 'boundedHorizontalLtrV1',
  axes: [{ tag: 'wght', value: 650 }],
}));
doc.clearExactFontInstance(JSON.stringify({
  charShapeId,
  languageIndex,
  mode: 'boundedHorizontalLtrV1',
}));
```

- strict JSON DTO와 16 KiB·16 axis·language 0..6 상한은 native authority와 동일하다.
- font bytes는 JSON으로 받지 않고 기존 `registerExactFontSource`가 소유한다.
- 반환은 상태·slot·canonical axis·source/request generation·request count만 포함한다.
- public TypeScript 설계 선언, consumer guide, Unreleased CHANGELOG를 함께 현행화했다.

## 실제 Node/WASM 왕복

Docker 산출물을 Node에서 직접 초기화하고 Happiness Sans VF를 slot `(0, 0)`에 등록했다.

| 동작 | status | request generation |
| --- | --- | ---: |
| 최초 set (`wght=650`, `opsz=default`) | `registered` | 1 |
| unknown `fontBytes` field | 예외, snapshot 불변 | 1 |
| 같은 canonical request 재설정 | `already-registered` | 1 |
| clear | `cleared` | 2 |
| 다시 clear | `already-cleared` | 2 |

최초 응답 axis는 default `opsz=400`을 제거한 `[{'tag':'wght','value':650}]`로 canonicalized됐다. malformed 요청은
`unknown field 'fontBytes'`로 거절됐고 다음 멱등 set의 generation이 1이므로 mutation이 없었음을 확인했다.
