# Issue #7642 단계 658: HWP5-origin HWPX의 조판 프로필 보존

- stage653은 source `8d8a2c415ab2057c47a464b554cc55535147dc29`에서 공개 CLI 재저장 IR 차이 0건과 쪽수 64 → 67을 재현했다. 두 출처 마커도 실제 ZIP에서 확인했다.
- stage657에서 기존 release-test 라이브러리에 연결한 독립 진단 harness로 원본 컨테이너 검사 PASS, 공개 `DocumentCore::export_hwpx_native()` 후 프로필 동일 검사 FAIL을 확인했다. 의도한 실패는 `hwp3_layout`: 재열람 true / 원본 false다. 이는 정식 Cargo 검증을 대신하지 않는다.
- 첫 진단은 하위 serializer를 직접 호출해 CLI가 보존하는 출처 마커 경로를 건너뛰었다. 그때의 계보 누락 실패를 원인 증거로 사용하지 않고 공개 저장 API로 수정·재실행했다.
- HWP5-origin HWPX 마커가 있는 경우 실제 HWP5와 같은 문단 단위를 유지하도록 `Document::layout_profile()`의 HWP3 전용 정책에서 제외했다. 원 HWP3와 HWP3-origin 단독 HWPX의 계약은 유지한다. 문서 ID·좌표·쪽수 예외는 추가하지 않았다.
- 생산 위치는 model 프로필이며 소비 위치는 본문 높이, 저장 줄 및 문단 간격 복원 분기다. 같은 IR의 저장 전후에 프로필을 공유하도록 원인을 보정했다. 쪽수 확인을 제거하거나 기대값을 완화하지 않았다.
- 수정 후 정식 집중 검사·lint·CLI 재저장·Native/fresh WASM·독립 PDF 및 확대 판독은 아직 진행 전이다. 최신 source의 통과나 전체 완료로 보고하지 않는다.
