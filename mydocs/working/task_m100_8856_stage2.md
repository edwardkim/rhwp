# #8856 잔여 렌더링 보정 — 표 원형 점선

## 선행 원인과 독립 근거

원 PR #8604는 idol 원본의 표 외곽선·각주 순서를 보호했다. 통합 #8857 이후 잔여 이슈는
축소 그림의 외곽선이 실선처럼 보인다고 기록했지만, 실제 원본 HWPX의 borderFill 7은
`CIRCLE`·0.2mm이고 기존 독립 PDF에도 원형 점의 벡터가 있다. 실선으로 바꾸지 않는다.

현재 `stroke_pattern::border_circle`은 #8368 문단 테두리의 16개 선언 굵기에서 얻은
600dpi 물리 지름·간격이다. 표 셀의 `create_edge_border_line_nodes`도 그 값을 소비하면서
표의 원형 점을 지나치게 크고 성기게 그린다. 변경할 값은 표용 원형 패턴이며,
선언 index → 표 경계의 공통 Path → Native/Canvas paint로 전달한다. 셀 상자·글자·줄 배치는
바꾸지 않고 문단·글자 테두리의 기존 패턴은 유지한다.

한컴 2020(11.0.0.9136)·2024(13.0.0.3901)의 같은 16개 표 선언 굵기 Print를 대조했다.
0.2mm에서 표의 지름·간격은 600dpi 기준 6·10칸이고 문단은 8·18칸이다.
각 선언의 실제 값은 독립 PDF 벡터로 확인했으며 원본 idol의 0.2mm도 같은 규칙이다.
합성 파일은 벡터 측정만을 위한 진단 자료이며 쪽 배치의 정답지로 쓰지 않는다.
처음 만든 진단 파일은 비연속 borderFill ID를 한컴이 해석하지 못해 테두리가 없었다.
해당 출력은 패턴 근거로 제외하고 연속 ID인 v2만 사용한다.

## 적용 경계와 반례

표 경계만 명시적인 표 패턴을 선택하게 한다. 표와 문단의 선언 굵기가 같아도 한컴의 실제
물리 패턴이 다르므로 둘을 하나의 패턴으로 통일하지 않는다. `NONE`·실선·기타 반복선과
각주 구분선은 바꾸지 않는다. 제품·정본 Visual Sweep·원본 기준 PDF의 판정 문턱도 유지한다.

## 검증 상태

stage1의 idol 최소 글꼴 전2쪽 Native/fresh WASM은 각각 최저 99.50595%/99.50727%다.
표 패턴 검사에서 보정 전 0 PASS / 1 FAIL을 확인했다. 지름·간격만 보정한 중간 실행은
Native/fresh WASM 전 219쪽씩 완료했지만, 직접 확대 판독에서 도색 농도가 달랐으므로
최종 수용 자료로 쓰지 않는다. 독립 PDF의 각 원은 채움+600dpi 한 칸 외곽선으로
두 번 그려진다. 외곽을 채움 원에 합치면 raster의 장치 최소 획 규칙과 덧그리기 농도를
잃는다. 표에만 이 도색을 보존하고 문단의 기존 채움 패턴은 유지한다.

도색까지 포함한 추가 검사는 다시 0 PASS / 1 FAIL에서 1 PASS / 0 FAIL로 바뀌었다.
현재 최종 도색 소스의 fresh WASM 전쪽 비교는 진행 중이다. 문단 원형 점선의 기존 검사도
실제 1 PASS / 0 FAIL로 확인했다. 최종 수치·그림·producer는 완료 뒤 아래에 보완한다.
임시 진단 파일·Print 응답·로그는 `output/issue8856/` 아래에만 둔다.

이 단계는 표 셀의 원형 경계만 보정한다. 다른 7문서군과 clip5587의 과거 엄격 하락은
해결 완료가 아니다. 설치 글꼴 대조군은 최소 글꼴 전쪽 결과와 분리한다. 과거 Mac 글꼴
프로그램 1,210개는 현재도 모두 같은 hash지만 과거 명시적 글꼴 환경 JSON은 삭제되어
당시 조건 전체의 재현을 아직 입증하지 못했다. 이전 사용자 지정 Haansoft Batang 선택을
추적하며, 그 환경을 임의의 점수 보정 수단으로 대신하지 않는다.

## 최종 도색 소스의 전쪽 검증

Native/fresh WASM 각 9문서군·219쪽을 실제 완료했다. 고정 base와 비교한 새 raw 하락은
양쪽 모두 0쪽이고 90% 미만·쪽수 누락도 0이다. 이 결과는 다른 잔여 결함의 해결이나
전체 제출 준비 완료를 뜻하지 않는다. 별도로 빌드한 같은 base WASM 219쪽도 포함했다.
request의 base WASM 96.13416% → stage1 99.20457% 개선을 같은 글꼴 조건에서 보완 입증했다.

최종 표 원형 도색 회귀와 기존 문단 원형·물결선 대조군은 각각 실제 1 PASS / 0 FAIL이다.
각 원의 채움 경로·외곽선·두 번 도색과 중심 간격을 최종 Path에서 보호한다. 초기 0건 실행은
파생 suite를 준비하기 전 파일 크기 변경으로 배정이 달라진 실행이므로 증거에서 제외했다.
최종 명령 전 `--prepare`로 실제 수집 경로를 다시 맞췄다.

루트 pkg·Studio public·실제 새 브라우저 초기 GET 응답의 JS/WASM hash도 일치한다.
Native·WASM·독립 PDF의 같은 원형 경계를 확대 판독했다. 한컴 PDF와 두 raster backend의
얇은 획 AA와 작은 원점 차이는 구별해 기록하며, 원본의 CIRCLE을 SOLID로 바꾸지 않았다.
이 도색 보정이 글자·표 내용의 줄이나 쪽 소속을 변경하지 않는 것도 전쪽 출력으로 확인했다.
