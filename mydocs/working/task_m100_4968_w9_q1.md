## 3. kerning-off native·Docker WASM 기준선

| 정규화 tree SHA-256 | `f33bb97d308834512bc4903097a1eee5761d59de71ccdad397506cc50c816f0c` |
| SVG | 400,536 bytes, byte-exact 일치 |
| SVG SHA-256 | `c693b6f1710caeb0ab61a22e2ebdbefe38390161c163ea3b5ca5b5ecbf6d1431` |
| Docker WASM blob | 8,977,497 bytes |
| 제품 mutation | 0 |

### 3.1 raw layer-tree가 byte-exact하지 않은 이유

raw layer-tree는 native와 WASM의 hash가 다르다. 차이는 synthetic paragraph source key의 sentinel 한
종류뿐이다.

```text
native: section:0/para:18446744073709551615/char:N
WASM:   section:0/para:4294967295/char:N
```

이는 각각 64-bit와 32-bit target의 `usize::MAX` 표현이다. native와 WASM에서 각각 20회 나타났으며 좌표·
style·resource에는 다른 차이가 없었다. 기준선 도구는 양쪽 raw hash를 그대로 남기고 정확히 이 pattern만
`para:MAX`로 바꾼 뒤 전체 tree를 canonical 비교한다. 일반 paragraph ID는 정규화하지 않는다. 따라서 이
기존 차이가 새 layout 회귀를 가리는 통로가 되지 않는다.

## 4. capability와 disposition 계약

세 상태를 섞지 않는다.

| 축 | 허용값 | 의미 |
| --- | --- | --- |
| request | `disabled`, `enabled` | 문서의 kerning 의도 |
| capability | `gpos-kern`, `legacy-kern`, `unsupported` | 실제 선택 face source에서 기능 탐지한 결과 |
| disposition | `not-requested`, `applied`, `no-pair-adjustment`, `fail-closed` | 해당 run에 내린 결정 |

capability 우선순위는 GPOS `kern`, legacy `kern`, unsupported 순이다. enabled라도 대상 pair의 adjustment가
0이면 `no-pair-adjustment`이며, source 부재·malformed·상한 초과·glyph/cluster 불안정은 기존 advance를
유지하는 `fail-closed`다. `unsupported`와 `disabled`는 같은 상태가 아니다.

최소 trace는 request, capability, disposition, `fontSourceSha256`, face index, 본 pair 수, 조정 pair 수,
총 advance 조정값과 fallback reason을 가진다. backend는 이 결정을 다시 계산하지 않고 공통 positions만
재생한다.

## 5. 자원 상한

새 임의 수치 대신 현재 portable text 경로의 상한과 맞췄다.

| 자원 | 상한 | 초과 동작 |
| --- | ---: | --- |
| font source | 32 MiB | `fail-closed`, 현행 advance 유지 |
| run code point | 4,096 | 동일 |
| run glyph | 4,096 | 동일 |
| 인접 pair | 4,095 | 동일 |
| run trace record | 4,096 | 동일 |

pair 수는 bounded run의 인접 pair 최대치다. 이 계약은 문자 수 상한을 제거하지 않으며 비정상 입력이 shaping
시간·메모리·trace를 무제한 소비하지 못하게 한다.

## 6. shaping engine 선택

현재 `rustybuzz 0.20.1`은 native에서 `usvg`를 통해 간접 포함되지만 WASM target의 rhwp 제품 dependency
tree에는 없다. 따라서 “이미 lockfile에 있다”는 이유로 비용을 0으로 간주하지 않았다.

| 후보 | 장점 | 위험·판정 |
| --- | --- | --- |
| 제한된 pair parser | 초기 surface가 작아 보임 | GPOS class pair·extension lookup·script/language routing·legacy kern 형식 누락 위험으로 제외 |
| `rustybuzz` | GPOS와 legacy kern, OpenType feature routing을 검증된 공통 Rust 경로로 처리 | Q2 fixture와 Q3 WASM size/perf를 통과해야 하는 qualified candidate |

Q3에서 단순히 전체 shaping 결과를 기존 layout에 덮어쓰지 않는다. kerning off/on 비교에서 glyph identity와
cluster가 같을 때만 pair advance delta를 소비하고, 달라지면 W10 GSUB/complex shaping 영역으로 넘기며
fail-closed한다. 이는 W9가 pair positioning이라는 범위를 넘지 않게 하는 경계다.

## 7. backend 책임

```text
document request
  -> selected exact font source에서 capability 탐지
  -> bounded common pair decision
  -> measurement와 position이 동일 delta 소비
  -> SVG / Canvas2D / CanvasKit / native Skia는 결정된 positions 재생
```

backend reshaping은 금지한다. CanvasKit이 positions를 받으면 `drawGlyphs`로 재생하는 현재 구조를 유지하고,
positions가 없을 때의 `drawText` fallback을 kerning 결정 경로로 사용하지 않는다.

## 9. Q2 진입 조건과 남은 위험

Q2는 이 보고서 승인 뒤 시작한다. 다음을 공개 fixture에서 증명해야 한다.

1. GPOS-only, legacy-only, 둘 다 있음, table 없음, malformed/oversized의 feature detection 경계
2. 알려진 pair와 비대상 pair의 on/off 차이
3. 장평·자간과 pair delta의 적용 순서
4. glyph identity·cluster가 바뀌면 적용하지 않는 fail-closed 경계
5. body/table-cell/text-box와 stored/fresh lane 분리

Q1 결과는 kerning을 이미 지원한다는 뜻이 아니다. 현재 off 출력을 고정하고, 안전하게 지원 여부를 설명할
언어와 자원 경계를 만든 것이다. 메인테이너가 이 결과를 승인하기 전에는 Q2 fixture 생성이나 제품 구현에
진입하지 않는다.
