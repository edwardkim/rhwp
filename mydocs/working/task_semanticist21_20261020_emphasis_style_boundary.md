# 강조점의 실제 서식 경계와 보충 메트릭 우선순위

## 구현 전에 확인한 독립 근거

현재 제품은 `5d736f74ca`이며 Native047/fresh WASM021의 제품 바이트와 같다.
기존 `emphasis-boundary-241-split`의 전쪽 raw는 각각 94.27793%/94.41489%다.
직접 review·overlay를 판독하면 PDF의 빨간 강조점이 RHWP에서 빠진다. 점수 통과를
완료로 보지 않는다. 원본의 `a`와 결합 악센트는 실제 글자 색이 서로 다른 구간이다.

MCP 2020, 한컴 11.0.0.9136, PrintMethod=0·1-up으로 두 반례를 별도로 출력했다.

| 반례 | 실제 한컴 출력 | 판정 근거 |
| --- | --- | --- |
| ID는 다르지만 모든 글자 속성이 같은 두 구간 | 강조점 1개 | 같은 ID만 사용한 대조군과 전쪽 RGB 픽셀이 동일 |
| 실제 색이 다른 원본 두 구간 | 검정·빨강 강조점 각 1개 | 96DPI의 독립 PDF 점 영역은 각각 x=121..125 / 135..139, y=123..127 |

ID만 달라도 무조건 나누는 수정은 하지 않는다. 원문의 글자 모양을 실제 해소한 결과가
같은지는 비교하되, 언어별 표시 런이 나뉜 것만으로 원본 자소를 새로 만들지 않는다.
입력·PDF·실행 job과 픽셀 대조는 ignored output의 `emphasis-style-boundary-397`,
`mcp-emphasis-style-boundary-397`, `emphasis-style-boundary-pixel-audit-399.json`에 있다.
이 두 새 반례는 현재 양쪽 모두 100%다. 원본의 강조점 누락은 아직 보정 전이다.

## 생산과 소비

`SourceGraphemes`가 원문 scalar·객체 경계와 실제 스타일 경계에서 강조점 소속을 만든다.
일반 문단과 인라인 표 경로가 이 결과를 소비하며, 공통 강조점 geometry가 SVG·Native·
Canvas2D·Paint JSON/CanvasKit과 clip에 전달된다. 가상 경계는 원문 주소나 표시 위치를
전진시키지 않는다. 글자·글꼴·폭·캐럿·저장 정보는 변경하지 않는다.

## 전체 Rust에서 발견한 별도 보충 측정 회귀

`#7084`의 타임라인에서 원 해결 PR은 `#7119`임을 확인했다. `#7090`은 관련 이슈이며
PR이 아니다. 후속 `#7805`의 장치 격자와 원 해결의 실제 backend 측정·세대·서식·
문단 자소 소속 계약을 함께 확인한다. 원 PR과 실제 통합은 실행 전 읽고 대조한다.

현재 선언 체인의 다른 face 메트릭을 찾는 새 경로가, 유효한 실제 backend 보충 전진보다
먼저 선택된다. 단일 자소의 유효한 보충 측정을 지키고, 여러 scalar 자소를 부분적으로
다른 face로 재는 가정도 재검토한다. 원 face의 정상 DB hit와 HWP 명시 폭 규칙은 유지한다.
기존 보충 측정 실패를 새 수치로 덮지 않는다.

## 실행 순서와 미완료 범위

공유 target을 사용하는 전체 Rust 390의 최종 종료를 확인한 뒤 제품 파일을 수정한다.
관련 원인과 반례를 묶어서 보정하고 한 Native 빌드에서 함께 확인한다. 수정 전후의 실제
공개 출력·관계 검사와 같은 원본의 Native/fresh WASM 전쪽 TSV·확대 판독을 완료한 뒤
새 이름의 정식 회귀와 제출용 증거를 추가한다. `text-source-metrics-assets-393`은 현재
ignored output에 준비한 자료이며 아직 완료 판정이나 커밋된 제출 자료가 아니다.

편집 가능한 #7694 차트, #8055 원본의 전쪽 미달과 전체 Rust의 다른 실패도 작업 범위에
남아 있다. 이 단계의 개선으로 통합 PR 준비 완료를 선언하지 않는다.
