# Task #3674 Stage 1 보고 — 발산 지점 좌표화 (진단, 코드 무변경)

## 핵심 결론 — 편차 +3 은 "3곳"이 아니라 **양방향 편차의 합성**이다

쪽별 텍스트 전역 정렬(밴드 제한 DP, shingle 유사도)으로 386↔383 전 구간을 매핑했다.

| 방향 | 쪽수 | 위치 |
|---|---|---|
| rhwp 가 더 쓴 쪽 (R-gap) | **11** | p161 / p283·288·294·299·301·305·307·310·314 / p378 |
| 한컴이 더 쓴 쪽 (P-gap) | **8** | pdf p321·325·334·336·348·357·360·366 |
| **순편차** | **+3** | = 11 − 8 ✓ (386 vs 383 정합) |

단순 앵커·쪽번호 라벨 방식은 이 문서에서 실패했다(반복 머리말·세로 갈피·쪽번호 혼입,
목차 점선). 최종 채택한 방법: 공백·숫자 제거 정규화 → 본문 shingle 유사도 행렬 →
밴드 ±12 전역 DP — 국소 잡음(반복 서식 쪽)에 면역이고 삽입 위치가 경로에서 그대로
읽힌다.

## 결함 축 분류 (시각 증거 확보)

### 축 A — 다쪽 표 누적 높이 (p161, +1)

**rhwp p161(라벨 153)은 공동이용 표의 꼬리 2행만 얹힌 ~85% 빈 쪽이다.** 한컴은 같은
표를 라벨 152 안에서 끝냈고, 라벨 153 은 "라. 작성방법 해설" 전면 쪽이다(양쪽 모두
"라." 는 새 쪽 시작 — 강제 쪽나눔 추정). 즉 여러 쪽에 걸친 공동이용 표의 누적 높이가
rhwp 에서 2행분 더 커서 넘친 것이다.

- 증거: `scratchpad/vis/rhwp_p161.png` vs `pdf161-161.png`

### 축 B — 질의·답변 블록 세로 팽창 (제5장 전반, +9)

**같은 물리 쪽에 한컴은 질문 3개(Q3·4·5), rhwp 는 2개(Q1·2).** 질문 머리띠(번호+아이콘)
높이, 블록 간 간격, 답변 불릿 줄간격이 모두 rhwp 쪽이 크다. 질문 ~30쪽 구간에서
쪽당 밀도 차이가 누적되어 +9.

- 증거: `scratchpad/vis/rhwp_p284.png`(라벨 276, Q1~2) vs `pdf283-283.png`(라벨 275, Q3~5)

### 축 C — 부록 신구조문 대비표 (후반, **−8**)

역방향. 규정/시행규칙 2열 대비표 구간에서 **한컴이 더 많은 쪽을 쓴다** — rhwp 가 여기서
8쪽을 "회복"해 순편차가 +3 에 그친 것이다. 시각 표본(rhwp p330 vs pdf p321)에서 행
짝맞춤(row-pairing) 동작이 다르게 보인다: rhwp 좌측 상단이 비는 행 정렬 흔적, 한컴은
같은 쪽에 제9조+제10조를 수용. 반복 법조문 탓에 DP 매칭 신뢰도가 낮은 구간이라
**행 단위 정밀 대조는 Stage 2 과제**다.

- 증거: `scratchpad/vis/rhwp_p330.png` vs `pdf321-321.png`

### 축 D — HWPX(387) vs 저장 HWP(386): p144 ⇒블록 (+1)

꼬리 앵커 스캔으로 특정: **hwpx p145 가 전용 쪽** — p144 의 "⇒ 기안문에 작성한 붙임
문서를 첨부…(붙임파일 직인 안내)" 블록이 HWPX 파스에서만 다음 쪽으로 밀린다. 저장
경로가 만든 조판 입력 차이(#1315 계열, LINE_SEG 합성·선언 높이)와 정합.

**부수 발견**: p30 부근에서 **머리말 배정도 다르다** — HWPX 는 "2025 행정업무운영
편람"(책 제목), 저장 HWP 는 "제2장. …"(장 제목). 쪽수와 무관하지만 저장 경로가 구역
머리말을 바꾸는 별도 축이다.
