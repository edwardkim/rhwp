# 수식 앞 순수 텍스트 줄의 공통 점유 메트릭 보정

- Issue: #7642
- 변경 전 head: `6bb959e64`
- 대상: 11월 ‘구분선 없음’ HWP/HWPX의 21~22쪽 컷과 전체 55개 원본의 Native/fresh WASM 대조. 기존 전체 목표를 유지한다.

## 독립 근거와 원인

같은 원본의 한컴 2024 Print는 21쪽 오른쪽 끝에 ‘설정하면’을 두고, 22쪽 왼쪽을 좌표 수식으로 시작한다. 코드 `4ed009b6027d`의 전22쪽 Native/fresh WASM에서는 두 형식 모두 22쪽이 46.41339%다. 최신 생산 코드 `592a7a889`의 진단 SVG에도 같은 고립된 텍스트 줄이 22쪽 맨 위에 남는다. 과거 점수를 최신 head의 최종 검증으로 보고하지 않는다.

HWPX 원문의 해당 미주 문단은 실제 저장본이다. 세 줄 중 중간 텍스트 줄의 `vertsize=2205`, `textheight=900`, `baseline=765`, `spacing=452`, 원점 17936이다. 다음 줄 원점 19288은 **900+452**만큼 전진하며, 다음 줄의 실제 TAC 수식 선언 높이가 2205다. 따라서 큰 상자는 다음 줄 수식이 소유하고, 앞 텍스트 줄은 높이 900을 점유한다. ‘설정하면’은 누름틀이나 편집 전용 표식이 아니다.

`composer/equation_line_metrics.rs::refresh_rows`에는 실제 후속 개체 소유·저장 전진·글자 메트릭으로 앞줄의 중복 큰 상자를 제거하는 규칙이 이미 있다. 그러나 텍스트 메트릭을 합치기 전에 `new_logical_height <= 0`으로 반환해 **수식이 없는 앞 텍스트 줄이 이 규칙에 도달하지 못한다**. 대상 문단의 순수 텍스트 줄은 이 경로에 해당한다. 수식의 실제 새 메트릭이 유효하지 않은 경우는 계속 보류하고, 수식이 없는 줄은 글자 메트릭과 기존 독립 소유 조건으로 판단한다.

## 생산·소비 경로와 반례

`refresh_rows`의 공통 ComposedLine → `stored_row_projection::project_equation_rows`의 파생 저장 메트릭·후속 원점 → 미주 row_projection과 format의 줄 예약·컷 → 실제 paragraph_layout의 줄 상자·기준선·전진을 대조한다. 다음 줄 실제 개체 높이와 저장 전진이 맞지 않거나, 원본 줄 분할이 dirty/합성이거나, 다른 표·그림이 현재 줄을 소유하면 기존 소유 조건이 보정을 거절한다. 수식 자체의 유효하지 않은 메트릭도 기존 보류 계약을 유지한다.

특정 문서·좌표·17.4px 보정 상수를 추가하지 않는다. 앞 텍스트·다음 수식의 소유와 실제 저장 메트릭에서 결과를 발행한다. 먼저 두 원본의 전22쪽·영향 컷을 비교하고, 같은 줄 수식·그림 및 정상 대조군을 포함한 전체 55개 Native/fresh WASM을 확인한다. 다른 미달이 발견되면 같은 배치의 원인 분석에 포함한다.

## 검증과 회귀 추가 순서

현재 Cargo 작업이 실제 종료된 뒤 공통 생산 조건을 보정한다. Native와 fresh WASM은 같은 공유 target에서 순차 빌드하고 source/산출물 해시를 고정한다. 독립 Print와 전체 페이지 TSV 및 21~22쪽 review를 대조하며, 페이지·문단 소유·본문 끝 누락·수식·그림·간격도 직접 판독한다. 모든 관련 페이지가 90% 이상인 뒤, 이 컷의 내용 순서·소유·누락/중복을 새 이름의 정식 관계형 회귀에 포함한다. 전체 회귀·lint·정책·Studio와 PR/CI/후속 절차는 실제 종료 결과로 판정한다.

원본 출력·실행 로그·TSV·중간 JSON과 nextrun은 ignored output에 보존한다. 측정 전에는 출력 개선 또는 완료로 판정하지 않는다.

## 실제 검증 결과

- 생산 source는 `015764c13c99ad3694b35ee57411728f83cb6579`다. Native 빌드와 fresh WASM wrapper 빌드 모두 exit0으로 종료했다. Native 고정 바이너리 SHA-256은 `01e3bdf17081fa93b70b7940a6c663c68cf60692703fbb5391ee72a9627da0f5`이며, WASM의 루트 `pkg/`·고정 검증 package·Studio public 산출물 해시 일치도 확인했다. 실제 Studio 브라우저 동작은 아직 별도 미검증이다.
- 두 원본의 Native 21~22쪽 사전 대조는 전체 쪽수 22/22가 일치했다. HWP 21쪽 **98.95831%**, 22쪽 **97.81114%**이며, HWPX는 각각 **98.95802%**, **97.81223%**다. 이는 선택한 컷의 결과이며 전체 22쪽 또는 fresh WASM의 완료 증거로 대신하지 않는다. 22쪽 원값은 각각 90.06277%/90.06394%이며, 정본의 유색 이진화 경계 처리로 7,271픽셀이 대조되었다. 문서별 임계값이나 비교 영역은 바꾸지 않았다.
- 실제 render tree에서 ‘설정하면’은 앞 텍스트와 함께 21쪽 오른쪽 단에 남고, 같은 원본 문단의 좌표 수식·‘이므로’는 22쪽 왼쪽 단에 이어진다. 22쪽 마지막 본문 줄도 보존된다. Native review 21~22쪽을 직접 열어 컷·수식·그래프·뒤 본문을 판독했다. 녹색 그래프는 양쪽에 존재하며 PDF에 없는 그림으로 분류하지 않는다. 미세 raster 톤 차이는 남아 있어 자동 점수를 시각적 동일성으로 표현하지 않는다.
- 전체 55개·853쪽의 Native/fresh WASM 재검증과 전체 nextest는 같은 source로 실행 중이다. 실제 최종 receipt·exit code 확인 전에는 전체 완료로 판정하지 않는다. 기존 `4ed009b6027d`의 전쪽 결과는 두 입력의 22쪽만 미달이고 다른 53개는 양쪽 90% 이상이지만, 이를 새 source의 전쪽 증거로 재사용하지 않는다.
- 이관 후 남겨 둔 `table_text_page_0` 실패 입력은 `samples/hwpx/table-text.hwpx`, 독립 Print는 `pdf/hwpx/table-text-hwpx-2020.pdf`다. 새 source의 전체 1쪽 Native/fresh WASM 모두 **99.98998%**, 쪽수 1/1이다. 표 전체·제목·수치 정렬을 같은 배율의 실제 PNG로 판독했다. 기존 검사는 음수 자간의 마지막 후행 전진까지 포함한 런 상자를 표시 폭으로 사용한다. 마지막 한글 뒤 전진과 실제 표시 끝을 구분하는 새 이름의 관계형 검사 초안만 ignored output에 마련했으며, 정식 검사 교체와 실행은 아직 하지 않았다. 기준값·tolerance를 완화하지 않는다.
- 최신 #7445 본문을 재조회해 stage137에 확인한 목록과 동일함을 확인했다. 추가 이관 함수·helper 선언 50개 중 활성 source의 잔여는 0개다. 최신 19개 제거와 유지 검사 53개 통과, 필수 7단계 lint·정책 통과는 stage137의 실제 source와 결과이며 이번 생산 수정의 전체 회귀 통과로 사용하지 않는다.

원시 증적은 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/stage138-*`와 `stage139-issue7445-latest-audit.json`에 보존한다. 직접 판독 PNG는 새 source의 원본 캡처이며, 기존 부정 관계 기호 그림을 반복 사용하지 않았다.
