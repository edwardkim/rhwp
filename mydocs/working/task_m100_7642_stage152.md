# #7642 Stage 152 — 저장 호스트 글줄과 합성 문단의 프레임 연결

Issue: #7642

## 정밀 분석으로 함께 수정할 원인

Stage 151 전체 64쪽에서 미달 15쪽, 최저 27.23722%를 확인했다.
부분 개선을 정상 baseline으로 고정하지 않고 같은 입력·독립 2024 Print와 대조했다.

1. 문단 70은 책갈피·새 번호·쪽 번호 위치가 함께 있는 텍스트 줄이다.
   Field/Bookmark만 인정한 분류가 852HU를 잃었다. 문단 628~630도 부동 타원과
   본문이 각자 표시되며, 도형이 있다는 이유로 본문 줄 앞의 간격을 끊으면 안 된다.
   공통 `empty_host_controls_are_flow_neutral` 분류로 저장 본문 줄의 소유를 유지한다.
2. 문단 426, 437~439는 원본 XML에 저장 줄이 없어 합성해야 한다.
   합성 줄의 높이·줄간격만 더하고 문단 앞뒤 간격을 빠뜨린 사다리를 고친다.
   가까운 앞 저장 프레임의 끝과 그 사이 합성 텍스트의 전진을 연결해 다음 저장 원점의
   되돌아감이 본문 예산 경계인지 판단한다. 개체나 편집 줄의 전진을 추측하지 않는다.
3. 표지 문단 0의 Paper/Square 그림은 첫 빈 저장 글줄을 없애지 않는다.
   원본 첫 줄은 0+2000+1200=3200HU로 다음 독립 줄을 정확히 닫는다.
   측정은 page base 0을 쓰지만 배치는 Shape 처리 뒤 이를 지워 lazy base 2000HU를
   역산했다. 본문 전체가 2000HU 위로 당겨졌다. 동일한 저장 줄 소유 계약을
   base 초기화와 Shape 처리 뒤 유지 분기에서 함께 소비하도록 한다.

## 근거·소비 경로·반례

한컴 2024 Print의 21쪽에서 문단 426이 첫 제목이고, 22쪽은 문단 440의 제목으로 시작한다.
입력 XML과 Native `dump`·render tree·HeightCursor 실행 로그를 같은 문단 소속으로 연결했다.
표지의 본문 원점 차이는 실제 fit base 0 / paint base 2000HU에서 확인했다.
Source의 저장 위치가 같은데 배치가 달랐으므로 이미지 좌표 보정을 넣지 않는다.

`공통 컨트롤 분류 → 원본 줄 앵커 → 합성 텍스트 전진 → 다음 저장 프레임 경계 →
fit/paint의 저장 원점`을 잇는다. 독립 저장 줄의 정확한 닫힘이 없는 가이드,
자리차지 개체·Square 표·캡션·중첩 흐름, 설명할 수 없는 합성 개체의 전진은
기존 배치 경로를 유지한다. 가시성으로 줄의 공간 점유를 대체하지 않는다.

Native 한 번의 새 빌드로 비적용 대조군 4문서 9쪽과 sample16 전체 64쪽을 재검증한다.
sample16은 기준 Print 버전과 맞는 compat 2024로 TSV를 산출한다.
표지와 3·5·21~24·39·40쪽의 내용·간격·소속을 직접 판독한다.
90% 이상이어도 남은 도형 그라데이션·그림의 미세 차이를 완료 판정에서 따로 확인한다.
새 회귀 검사와 PR은 전체 Native/fresh WASM 선행 조건을 충족한 뒤 진행한다.

## 실행 결과 (2026-10-12)

Native 빌드는 종료 코드 0이며 source 해시는 실행 전후 동일하다. 비적용 대조군
4문서 9쪽은 모두 90% 이상, 최저 98.50071%다. compat 2024로 전체 64쪽을 산출했고
최저 27.23722%, 미달 10쪽(21, 22, 23, 24, 35, 39, 43, 45, 48, 49)으로 실패했다.
표지 1쪽 99.28576%, 3쪽 99.76694%, 52쪽 99.20798%, 53쪽 99.97057%,
57쪽 99.94261%로 원점과 간격이 복원됐다. 전쪽 통과나 최종 완료로 판정하지 않는다.

원본과 같은 원점으로 문단 70=4904HU, 72=18576HU, 73=19892HU,
427=3496HU, 440=852HU를 확인했다. 그러나 실제 문단 426은 20쪽, 문단 440은
21쪽에 남았다. `stage152-flow.log`의 실행에서 문단 426의 현재 높이 947.1px,
앞 간격 15.1px, 줄 높이 17.3px인데 fit 높이는 17.3px였다.
합성 lineseg의 span을 기존 저장 span처럼 수용하여 문단 앞 간격을 fit에서 잘랐다.
이 값을 소비하는 `paragraph/format.rs → whole_fit → 실제 배치`까지 수정해야 한다.

39쪽 문단 628~630의 타원은 부동 개체가 아니라 TAC 개체다. 실제 크기 804×740HU가
1300HU 텍스트 줄 안에 들어 있으나 앞 간격 568HU의 소유를 끊고 있었다.
작은 TAC 개체와 텍스트가 같은 줄을 소유하는 독립 메트릭 조건을 추가로 확인한다.

새로 직접 판독했다. Print의 원형 채우기는 10개 원형 벡터이며 채우기 누락이 아니다.
