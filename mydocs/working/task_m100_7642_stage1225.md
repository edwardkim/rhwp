# 단계 1225 글앞·글뒤 개체가 있는 첫 글줄의 쪽 원점

Issue: #7642. 비교 기준 `463c48cc228170b576c832591b76826116e86a49`, 보정 전 runtime `393b159cf3a216939419cc6332152451ad00a938`.

## 실행으로 구분한 원인

주거 계약서 2쪽 안내 표 보정은 Native 98.99721% / fresh WASM 99.05070%이고, 전체 3쪽의 양쪽 TSV·쪽수와 새 review PNG를 확보했다. 관계형 검사 초안은 같은 원본·같은 검사에서 이전 runtime FAIL / 새 runtime PASS다. 정식 suite 추가는 확대 판독의 남은 차이를 보정한 뒤 수행한다. 점선 주기는 Print와 달라 아직 페이지 완료나 px 고정 자격을 선언하지 않는다.

3쪽의 별도 하락을 공개 render tree와 독립 Print에서 대조했다. 첫 본문 `별지)`는 같은 위치지만 첫·둘째·셋째 안내 글상자와 제목 표는 약 2.67px 올라간다. 단순 글꼴 굵기 차이나 앞 문단의 뒤 간격 누락으로 판정하지 않는다.

실행 trace에서 쪽 첫 문단 37의 저장 vpos는 200HU, 앞·뒤 간격은 각각 200HU의 물리 간격이다. 뒤 문단 38·39는 개체가 없고 저장 줄을 소유한다. 37·38의 실제 전진은 각각 22.9px이며 원본 간격을 보존한다. 그러나 39 진입에서 **45.9 → 43.2px 역스냅**이 발생하고, 40의 개체 앵커가 56.0 대신 53.3px가 된다. 두 흐름의 쪽 기준이 갈린 원인은 `vpos_page_base=200`이다.

첫 문단 37에는 글앞 도형이 있다. `stored_first_margin_is_page_relative`가 글앞/글뒤와 위·아래 자리차지를 모두 `para_has_overlay_shape`로 거절해, 앞 간격 200HU를 쪽 원점으로 빼고 있었다. 원본 사다리는 `1920 = 200 + 1100 + 220 + 200 + 200`으로 닫힌다. 첫 vpos는 물리 앞 간격이며 독립 Print도 0축을 확인한다.

## 생산·측정·실제 배치 경로

`원본 첫 vpos와 앞·뒤 간격/다음 저장 줄 → stored_first_margin_is_page_relative → typeset::section::vpos의 초기 base → HeightCursor 역스냅과 확정 float 앵커 → layout::build_single_column의 같은 원점 helper → 실제 글줄/도형/제목 표 배치`를 대조했다. helper 이후의 별도 첫 줄 원점 선택과 float 앵커도 확인한다. 잘못된 좌표에 2.67px를 더하거나 문서 ID로 분기하지 않는다.

글앞/글뒤 도형은 보이지만 본문 줄 전진을 소유하지 않는다. 같은 저장 사다리 증거로 앞 간격을 인증한다. 문단 기준 위·아래 배치 도형·그림은 별도 본문 밴드를 소유할 수 있어 기존 제외를 유지한다. 글자처럼 취급하는 첫 도형의 기존 제외, 합성 줄·수정된 문단·다음 사다리 불일치의 기존 거절도 유지한다. 판단 범위를 줄이기 위한 문서별 조건은 추가하지 않는다.

## 검증과 남은 범위

새 Native/fresh WASM의 전체 3쪽, 첫 본문·모든 안내 글상자/제목·하단 로고를 같은 배율로 직접 대조한다. 첫 문단에 도형이 없는 6쪽 공백 대조군과 현재 전쪽 corpus도 확인한다. 실제 위·아래 배치/글자처럼 취급 도형의 반례를 기존 정식 검사와 연결한다. 수정 전후 테스트와 전체 영향 페이지 90%를 확보하기 전 새 관계형/px 검사를 정식 추가하지 않는다.

별도로 2쪽 표의 점선 주기는 같은 위치의 직접 pixel row에서도 Native/WASM 약 4px, Print 약 1.6px로 다르다. 픽셀 값은 진단이며 고정 기대값이 아니다. 선언 선 굵기·borderFill 종류와 독립 Print의 반복 비율을 대조해 일반 규칙으로 보정한다. 도형 점선의 기존 600dpi 계약을 표에 근거 없이 복사하지 않는다.

위 실행 trace·source/PNG SHA·전체 TSV·점선 직접 판독은 ignored 단계 1217·1218·1220·1221·1223에 보존했다. 현재 수정 후 출력은 미검증이며 기존 393b159의 전쪽 큐를 새 코드 결과로 보고하지 않는다. PR/CI/merge는 진행 전이다.
