# Issue #7642 단계 708: 저장 글줄 원점과 본문 위 개체의 흐름 구분

## 독립 관측과 수정 범위

- #1880 원본 12쪽 Native는 88.91037%다. 같은 Print의 하단 문구와 저장 LineSeg 66321 HWPUNIT을 대조했다. typeset page base 0과 paint -1000의 차이가 문단 앞 간격의 중복 소비와 일치한다.
- ParagraphFloatPlacement.stored_successor_line_origin은 앞 간격을 이미 포함한 첫 글줄 원점이다. 이를 문단 원점으로 전달한 HeightCursor가 앞 간격을 다시 더해 기준축을 바꿨다. 뒤 shared-spacing 처리는 현재 줄만 복원해 다음 줄의 축 차이가 남았다.
- FlowOrigin::Paragraph와 FlowOrigin::Line으로 두 생산 결과를 구분한다. 미주 점유 끝의 문단 원점은 기존 앞 간격을 소비하고, 닫힌 개체 프레임의 글줄 원점은 앞 간격을 중복 가산하지 않는다.
- samples/issue7235/156086935_none_image_fill.hwp는 1쪽 49.56657%, 6쪽 미달이다. 첫쪽 안내 상자와 뒤 본문이 함께 내려가는 차이를 직접 확인했다.
- 선행 문단의 TopAndBottom 그림은 음수 세로 오프셋과 높이를 합쳐도 호스트 위쪽에서 끝난다. 출력은 그 위치를 보존했지만 표 호스트 측정은 높이 6000 HWPUNIT을 흐름에 더했다. 조판과 paint 커서 차이도 같은 6000 HWPUNIT이다.
- 바깥여백 포함 하단이 호스트 원점 이전에 있으면 순차 본문 띠를 예약하지 않는다. 실제 그림과 좌표는 보존한다. 양수 오프셋과 원점을 걸치는 개체의 기존 별도 처리까지 이번 보정의 완전한 계약으로 주장하지 않는다.

## 소비 경로와 검증 계획

- 닫힌 표 프레임의 successor line → FlowOrigin::Line → HeightCursor 저장 기준축 → shared spacing → 뒤 문단과, 미주 점유 끝 → FlowOrigin::Paragraph → 앞 간격 → 실제 줄을 대조한다.
- 원본 개체 오프셋/높이/바깥여백 → shape_flow 예약 여부 → TypesetState 다음 커서 → 실제 shape 배치를 대조한다. 두 원인 분석 뒤 한 번의 빌드와 Native/fresh WASM 재검증으로 확인한다.
- 원본·독립 Print의 전쪽 90% 이상과 확대 판독 전에는 새 렌더링 회귀를 추가하거나 기존 기대값을 갱신하지 않는다. 현 단계의 검사·시각 결과는 아직 미검증이다.
- 이전 source d4b756bb4d의 HWP3 묶음 원본 Native는 95.50501%, RHWP HWP5 저장본 Native는 98.42686%다. 둘 다 전체 2쪽이며 같은 독립 Print 기준이다. IR/쪽수 보존도 확인했다. 이를 새 source의 통과로 보고하지 않는다.
- 로그·TSV·JSON·진단 patch는 ignored output stage708~712에 보존하고 커밋하지 않는다.
