# #7642 부분 표의 마지막 행과 호스트 종료 간격 보정

Issue: #7642. 계획은

## 수정 전 실행 증거

57d4adf2a0 Native와 같은 원본·독립 한컴 Print·PDFium 전쪽 TSV에서 법령의
25쪽 99.77190%, 27쪽 99.92885%, 63쪽 99.91236%를 확인했다. 26쪽도
90% 이상이다. 63쪽 review와 standalone overlay를 열어 사용자에게 함께
표시했다. 참고 상자의 꼬리말 겹침은 해소됐지만 글자 굵기 차이는 남았다.
18·19쪽은 각각 67.91019%·66.82272%로 통과하지 않았다.

원본 193문단의 내부 표는 TAC이며 저장 줄이 없다. 원본을 바꾸지 않고
진단용 RHWP HWPX 내보내기의 속성과 기존 dump·CellUnit 로그를 대조했다.
이 내보내기는 독립 기준이나 공식 한컴 저장본으로 사용하지 않았다.
GDB로 동일 Native 바이너리를 실행해 helper의 실제 호출·반환을 확인했다.
측정·CellUnit은 5.2px를 반환하지만 부분 배치는 이 TAC 호스트에서 helper를
호출하지 않았다. 원인은 일반 셀의 synthetic 줄 판정이 아니라 부분 표의
자식 종료 판정이다. 이전 단계의 원인 가설을 이 실행 증거로 정정한다.

## 보정과 미검증 범위

행 컷은 자식의 마지막 행 소유로 terminal을 정하고 부모 end_unit의
usize::MAX 여부를 대용하지 않는다. recursive 컷은 존재 자체가 아니라
terminal·끝 행을 확인한다. 명시적 자식 컷을 가진 경우 행 본체 높이와
바깥여백 포함 높이의 차이로 이어받기를 재판정하지 않는다. 가용 높이로
계산한 fallback의 높이 판정은 유지했다.

종료한 NO_LS TAC scalar 행 컷에는 다음 문단이 같은 조각에 있을 때
공통 helper의 줄 뒤 간격과 원본 문단 뒤 간격을 적용한다. recursive/mixed
flow_height가 이미 담은 간격에는 중복 적용하지 않는다. 현재 수정의
Native/fresh WASM 빌드·시각 검증은 아직 미실행이다. 새 rendering 회귀와
기존 golden·baseline·쪽수 기대값은 변경하지 않았다.

검증 로그와 GDB 입력/결과는 ignored output의 stage2497~2503에 보존했다.
코드의 rustfmt·git diff --check는 통과했다. 최종 제출·PR·CI·통합은
전쪽 시각 gate, 새 이름 회귀, 전체 Rust/lint/UI 검증 후에 진행한다.
