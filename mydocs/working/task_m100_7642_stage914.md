# 단계 914 장평 회귀의 독립 기대값 교정

Issue: #7642. Native/fresh WASM 전체 1쪽의 99.98879%/100.00000%와 직접 판독은 단계 910 및 ignored 단계 909에 있다. 기준 Print의 원시 Tf와 세로 CTM은 선언 크기를 유지하고 Tz는 가로 축만 바꾼다.

기존 #5821은 추출 span의 기하평균 size를 실제 세로 크기로 오인해 sqrt 장평 축소를 정답으로 고정했다. 새 이름 `issue_5821_condensed_title_preserves_source_height_and_horizontal_ratio`로 바꾸고, 실제 사용 원본 글자 모양의 크기·상대 크기·장평을 실제 SVG 글리프와 대조한다. 화면의 고정 font-size 문자열·절대 좌표·영역을 고르지 않는다. header에서 사용하지 않은 큰 글자 모양은 제외한다. 가로/세로 변환과 제목의 실제 표시를 함께 확인한다.

새 검사는 같은 입력의 고정 base a5e88ad6와 현재 renderer 후보에서 순차 실행한다. 수정 전후 실제 실행을 확인하기 전에는 결함 검출을 완료로 적지 않는다. 이 원본의 시각 통과를 HWPML 122쪽 전체나 55문서 전체의 완료로 쓰지 않는다. 미완료 범위와 최종 동일 release 검증은 유지한다.

## 수정 전후 실제 실행 결과

동일 입력·새 검사로 base `a5e88ad682c805e1d845502ddc9521b94ea8eccd`에서 실행한 결과, 원본 세로 크기 33.33333 대신 sqrt 장평을 적용한 31.62278이 검출되어 FAIL했다. 현재 `6ab79ebdd`의 같은 검사는 PASS했다. 실행 로그는 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/stage918-before.log` 및 `stage919-after-fresh-package.log`에 보존한다.

base worktree에서 현재 worktree로 돌아온 첫 실행은 공유 산출물의 이전 동작을 재사용했다. 공유 target을 삭제하지 않고 현재 Cargo.toml·renderer 모듈의 내용 SHA를 보존한 채 mtime을 갱신해 package를 다시 컴파일한 뒤, 현재 코드의 통과를 확인했다. 후속 base/head 실행은 저장소 SHA 확인뿐 아니라 실제 SVG의 원본 세로 크기·장평도 확인한다. 이 재컴파일 문제를 출력 보정이나 별도 결함 검출로 계산하지 않는다.

55문서·853쪽의 현재 Native 재산출을 시작했다. HWPML 3쪽 미달, 최종 release Native/fresh WASM 전체 대조, 최신 base 대비 하락 검사와 전체 회귀·lint는 아직 남아 있다. PR 생성·CI·merge 완료로 판정하지 않는다.
