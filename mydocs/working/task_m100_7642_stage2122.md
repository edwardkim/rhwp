## 새 검사 범위와 독립 기대값

`tests/cases/verified_hancom2024_reserved_palette.rs`를 새 이름으로 추가한다.
실물 배치 좌표나 기존 golden은 바꾸지 않는다. 실제 DocumentCore → 공통 layer
→ image payload → inline JSON / 바이트 생략 뒤 조회 경로를 대조한다.
그림의 문단 소속·내용 순서·개수·원본 해상도·알파를 함께 보호한다.

독립 Print의 회색 표본 128→131, 240→246에 JPEG 양자화 한 단계만 허용한다.
구현의 전달식을 기대값으로 복사하지 않는다. 위치를 고르지 않고 원본의 해당
회색인 모든 픽셀을 검사한다. 팔레트 유지 대상과 Screen·2020 호환 출력은 원본
색 전체를 보존해야 한다. Print → Screen → Print와 호환 모드 전환 후 같은
payload를 확인해 캐시 오염과 전달식 중복 적용을 검출한다.

같은 검사 SHA-256 `21beae4a5941ff34a18bb6c6ab7c166d2aba0956e3ae00ee8f426b90ca7d4d40`를
예약색 수정 직전 `8b1053b18e`와 새 검사 commit `d48ef6cffb`에 제공했다.
stage2123의 수정 전은 정상 빌드 뒤 두 검사 모두 원본 128이 그대로 출력되는
독립 Print 계조 불일치로 실패했다(exit 100). 빌드·환경 실패가 아니다.

공용 target의 작업 트리 전환 직후 수정 후 첫 실행도 이전 라이브러리 결과를
사용해 실패했다. 이 기록은 보존하고 성공 증거에서 제외했다. stage2129는
현재 review 작업 트리의 `src/lib.rs`와 `print_tone.rs` **내용을 바꾸지 않고**
mtime만 갱신해 crate를 다시 빌드했다. 캐시는 삭제하지 않았다. 4분 25초의
실제 재빌드 뒤 같은 두 검사가 모두 PASS(exit 0), source 해시 불변을 확인했다.
새 소유·색·조회·캐시 검사의 기대값이나 허용치는 이 과정에서 바꾸지 않았다.
전체 명령과 로그는 stage2123·2129, 결합 판정은 stage2134-palette-final-proof에 있다.

이후 공용 target에서 다른 source 작업 트리로 전환할 때는 내용 SHA 보존과
crate 재빌드 여부를 함께 확인한다. Git SHA와 테스트 실행만으로 이전 라이브러리의
재사용 여부를 추정하지 않는다. 이 보정은 현재 검사 실행의 증거이며 과거의
모든 producer가 잘못됐다고 판정하거나 이전 시각 결과를 새로 빌드한 것으로 바꾸지 않는다.
