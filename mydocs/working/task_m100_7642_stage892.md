# 단계 892 서로 다른 저장 줄의 아래 캡션 포함 TAC 수용

Issue: #7642. 기준 a5e88ad682c805e1d845502ddc9521b94ea8eccd.

## 독립 근거와 경로

3b8f24ead의 HWPML 37·38·57쪽은 Native 99.94404·99.92523·99.91661%, fresh WASM 진단 99.93970·99.92989·99.91975%다. 대표 출력에서 행 소속, 캡션과 뒤 문단 배치를 직접 확인했다. WASM 진단은 dev profile이며 최종 동일 release 비교와 전체 필수 회귀를 대체하지 않는다.

68쪽 문단 3.103은 내용 없는 캐리어의 두 TAC 표를 서로 다른 저장 줄이 소유한다. 첫 줄 10082HU는 선언 표 8000HU + 원본 아래 캡션 1802HU + 여백 280HU와 같다. 두 번째 줄 21302HU도 같은 방식으로 닫힌다. 기존 `composer::stored_tac_lines`는 캡션을 빼고 선언 높이와 여백만 비교해 두 줄 모두를 거절했다. 그 결과 보정된 저장 TAC 계획으로 수용하지 못하고 일반 흐름에서 다음 표의 저장 위치를 잃었다.

저장 줄 계획은 원본 아래 캡션의 실제 줄이 있는 경우만 캡션 점유를 포함해 줄 상자를 인증한다. 편집·합성·무효 줄·위/옆 캡션은 새 인증의 근거로 쓰지 않는다. 숫자와 문서 ID를 분기에 넣지 않는다. 이 결과를 소비하는 controls의 fit, InlineBoxPlacement와 layout의 표 원점이 같은 줄 소속·occupied_end·advance_end를 사용한다. 원본 선언 높이와 독립 Print로 수용 여부를 확인한 뒤, 범위 전체 90% 조건을 만족하기 전에는 새 실물 회귀를 추가하지 않는다.

## 공급과 남은 검증

#5821 Print의 H2hdrM을 원본 SFNT로 대조했다. Linux 설치 Version 6.00의 일부 글리프는 Print와 다르고, Windows Version 1.00은 대조한 7개 글리프의 좌표·contour·flag·advance가 모두 같았다. 원 face는 ignored 진단 경로에만 보존하며 명시 공급의 Native/fresh WASM 확대 판독을 계속한다. 3쪽 목차와 전체 회귀·55문서 전쪽 검증은 아직 완료되지 않았다.

글꼴 캐시 정리에서 현재 key를 이전 버전으로 잘못 분류한 건은 원본으로 재산출해 복구했다. 1544 face의 program SHA가 이전 catalogue와 모두 같음을 확인했다. 종료한 이전 버전 cache만 다시 구분해 제거했고 공유 target·입력·TSV·PNG·로그는 보존했다. 누락 캐시로 실패한 진단을 시각 실패나 완료 결과로 세지 않는다.
