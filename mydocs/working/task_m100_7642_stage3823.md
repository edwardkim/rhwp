# #7642 새 MCP 기준 채택과 셀 안여백의 높이 누적 오차 보정

Issue: #7642

## 현재 기준과 이전 검증

작업지시자가 새 MCP 출력을 기준으로 지정했다. 원본
`samples/issue6776/78494-virtual-convergence-industry-decree.hwpx`의 실제 형식은 HWP5다.
그대로 올린 첫 요청은 실패했고, 바이트·SHA가 같은 `.hwp` 사본으로 Print 출력했다.
이것은 HWPX 변환이나 원문 수정이 아니다. 저장 제품 메타데이터는 한컴 2018
`10.90.0.983`이고, 현재 계약에 따라 engine 2020을 명시했다.

실제 한컴은 `11.0.0.9136`, PrintMethod 0, `hancom2020_pdf_driver_one_up`, 74쪽이다.
새 기준 PDF와 입력 SHA·job·바이트 수는
[기준 PDF 기록](../../pdf/issue7642-legal-table-origin/README.md)에 보존한다.
기존 수동 PDF는 과거 자료로 유지한다. 두 PDF의 글자/그리기 결과가 모든 쪽에서 같다는
초기 가정은 거부됐으며, 2~74쪽에서 차이가 있다. 9쪽 꼬리말 위치 차이를 직접 확인했다.
원본 기준을 자동 교체한 것이 아니라 명시적인 사용자 지정에 따른 새 기준이다.

이전 코드 `090e4763641ab65f1f2682688c8781baf3631485`의 Native 빌드는 4분 45초에
완료됐고, 앵커·표 관련 기존 focused 회귀 14개는 모두 통과했다. 해당 코드의 Native
14문서 301쪽은 모두 raw 90% 이상과 쪽수 일치를 확인했다. 세 issue1880 입력에는
독립 원본 HFT 글꼴을 공급했고 다른 입력의 기존 글꼴 공급은 유지했다.
새 기준 법령은 후보 최저 29쪽 90.89886%이고, devel producer의 최저는
48쪽 18.67544%다. devel의 실패를 후보 실패로 보고하지 않는다.
같은 조건의 Native 비교에서 남은 0.1%p 이상 하락은 PrEP 15쪽 한 곳
97.83052→97.20649%다. 다른 전체 원래 범위의 검증을 대신하는 결과는 아니다.

위여백 대조군 0·141·283·566 HWPUNIT의 영향 4쪽씩 총 16쪽은 해당 코드에서
모두 100%였다. 283/566 대조군의 수정 전 56~65% 미달과, 여백 0 대조군의
수정 전후 100% 유지도 보존했다. 별도 대조군의 부분 검증이며 원본 전쪽 판정을 대신하지 않는다.

## 29쪽의 독립 기대값과 실제 원인

90.89886%의 review와 standalone overlay를 직접 열었고, 작업지시자가 상단 표의
줄바꿈·간격 결함을 지적했다. 원본 표 pi=256의 1행 2열은 좌우 안여백 510 HWPUNIT를
가진다. PDF 본문은 이 여백 안에서 시작하지만 후보는 1px까지 축소해 한 줄에 더 많은
글자를 배치한다. 평균 점수와 90% 통과로 이 차이를 면제하지 않는다.

기존 `RHWP_DIAG_SHRINK` 실행 추적은 실제 셀에 다음 값을 기록했다.

| 값 | 관측 |
| --- | ---: |
| 안쪽 물리 높이 | 294.666666666666629px |
| 줄마다 환산·실수 누적한 내용 높이 | 294.666666666666799px |
| 기존 한 단계 연산 오차 비교 한계 | 294.666666666666686px |

원본 글자 크기 1300 HWPUNIT와 줄간격 780 HWPUNIT, 문단별 3·3·3·2줄의 합에서
마지막 줄간격을 제외한 높이는 정수 22100 HWPUNIT다. 한 번 환산하면
294.666666666666686px로 같은 셀 안에 들어간다. 실제 넘침이 아닌 실수 누적 오차를
근거로 안여백을 510 HWPUNIT에서 1px로 깎고 있었던 것이다.

## 공통 보정과 소비 경로

`composer::shrunk_cell_horizontal_padding`은 줄 높이·줄간격을 i64 HWPUNIT로 더하고,
마지막 줄간격을 같은 단위로 뺀 뒤 한 번만 환산한다. 서로 다른 문단/줄 높이·음수 줄간격을
그대로 더하며, 줄 끝의 비음수 간격을 한 번 제외하는 계약도 유지한다.
기존 `next_up` 비교나 원래 넘침 조건·실제 공간 부족의 축소 규칙은 완화하지 않는다.
문서·글자 크기·줄 수·고정 좌표를 분기 조건으로 추가하지 않았다.

`compose/recompose의 정수 줄 메트릭 → 공통 높이 합 → 셀 물리 안높이 비교 → 유효 안여백 →
본문 너비와 줄 재구성 → 실제 TextLine/TextRun 배치`를 따라 보정한다. 같은 함수를 호출하는
일반 셀·중첩 셀·부분 조각의 기존 수용 조건은 그대로다. 부분 조각의 전체 높이 추정이나
셀 높이 확대·paint 이동으로 대신하지 않는다. 측정이 쓰는 원본 안여백을 실제 배치에서도
보존하도록 잘못된 넘침 판정을 제거한다.

## 검증과 남은 범위

이 보정 후 실행 검증은 아직 미완료다. 기존 090e 후보의 14개 PASS와 301쪽 결과를
새 코드의 통과로 쓰지 않는다. 이전 후보의 진행 중 WASM은 새 문단 보정으로 대체했다.
해당 작업의 독립 세션/프로세스 그룹만 SIGTERM으로 종료하고 부재와 종료 코드 143을
확인했다. 부분 pkg는 완료된 fresh WASM으로 사용하지 않는다. 공유 target은 보존했다.

새 후보에서 원본 74쪽·29쪽 직접 판독·같은 근본 원인의 다른 셀과 정상 대조군,
실제 높이 넘침의 기존 회귀를 묶어서 확인한 뒤 fresh WASM을 검증한다.
새 렌더링 회귀·px 핀과 기존 기대값 변경은 시각 선행 조건 충족 뒤 진행한다.
원래 시험지·수식 전체, 남은 PrEP 하락, 전체 Rust·lint·Studio·유입 PR 검증과 PR/CI/merge·
옵션 2 기록 PR·후속 처리는 계속 남아 있다.

ignored 검증 루트의 단계 3800~3819에는 새 기준 생성·앞 후보 결과·이미지가,
3820~3822에는 진단 SVG·실제 안여백 추적·원본 단위 합산 관측이 있다.
진단 SVG는 최종 Native/WASM raster 증적을 대신하지 않는다.
