Issue: #7642

## 현재 소스의 검증과 남은 보류

`912ebd5a1b72f115a51836cb7f192555a474a0b1`의 Native 14문서 301쪽은 전쪽 raw 90% 이상이며
독립 Print PDF와 쪽수가 같다. fresh WASM은 `stage3748`에서 빌드·Studio 동기화를 마쳤고,
`stage3753-producer-axis-head-wasm`의 같은 14문서도 전쪽 90% 이상이다. PrEP 전체 140쪽의
최저값은 Native 91.13318%, WASM 90.56609%다. 이 결과는 뒤에 수정한 범례 코드의 검증이 아니다.
추가 축 반례 4문서 78쪽은 별도 범위이며, aift는 base부터 큰 미달이 있어 통과로 합산하지 않는다.

`stage3747`의 관련 회귀 22개 중 20개가 통과하고 기존 #5961 축 단위 검사 2개가 실패했다.
이 기대값이나 입력을 바꾸거나 제거하지 않았다. `stage3762` Native Decimal 비교는 같은
`upstream/devel` SHA `6ed1682c3267ea786734eb2e75252916a861d1fd`와 비교했으며,
주 검증 301쪽 중 17쪽의 0.01%p 이상 하락이 남았다. 추가 aift 반례의 18쪽 하락과 구분한다.
전체 Rust·원래 시험지 전체 범위·최종 PR gate는 완료되지 않았다.

## 독립 근거와 진단

원본은 `samples/issue2006/1790387_prep_final_report.hwpx`, 기준은
`pdf/issue2006/1790387_prep_final_report-hwpx-2024.pdf`다. 입력과 기준을 바꾸지 않았다.
원본 Chart/chart1.xml·chart2.xml은 하단 범례, 11pt 기본 글자 크기와 서로 다른 길이의 이름을
선언한다. PDF의 짧은 이름 사이 기호 간격은 긴 이름 뒤의 간격보다 작다. 원본 HWPX와
한컴 HWP 재저장본의 Print는 모두 차트를 래스터 이미지로 포함한다. 이 사실만으로
낡은 미리보기의 값·라벨을 정본으로 승격하지 않는다.

기존 `render_legend`는 항목별 실제 이름과 무관하게 최대 100px의 동일 폭을 배정했다.
`stage3763/3764`는 실제 Native의 RawSvg만 바꾼 진단이며 수정하지 않은 keep 출력의 RGB가
정식 CLI와 같음을 확인했다. 기존 글자 폭 계산과 기호·간격 18px로 항목별 점유 폭을 구해
합계의 중심과 각 항목의 전진에 함께 쓰면 전쪽 점수는 다음과 같이 바뀐다.

| 독립 Print 대조 | 기존 Native | 내용 폭 범례 진단 |
| --- | ---: | ---: |
| PrEP 26쪽 | 93.73791% | 94.40664% |
| PrEP 27쪽 | 91.13318% | 91.56644% |

글꼴만 맑은 고딕으로 바꾼 진단은 93.40466% / 91.09358%로 개선 근거가 없었다.
계열 테두리를 복원한 별도 진단도 양쪽을 함께 개선하지 못했다. 두 실험을 이번 후보 코드에
포함하지 않는다. 최초 테두리 실험 `stage3758`은 중복 SVG 속성으로 자리표시를 그렸으며,
렌더 종료 코드 0을 시각 성공으로 보지 않고 무효로 기록한다. 속성 중복을 바로잡은 `stage3760`
출력만 실제 테두리 진단으로 쓴다. 원인 미확정 차트 글꼴·색·테두리는 남은 차이로 보존한다.

## 수정 범위와 소비 경로

`legend_items`의 원래 순서·색·기호 → `label_text_width`의 기존 글자 크기별 폭 →
항목별 기호·간격 포함 폭 → 동일 배열의 합계로 전체 시작점 결정 → 같은 폭으로 실제 전진한다.
문서 ID·라벨 문자열·고정 좌표로 분기하지 않는다. 기호와 텍스트 사이 기존 간격과 세로 배치,
우측 범례, 계열 순서·값·차트 축·본문 조판은 바꾸지 않는다. 이번 주장은 하단 **한 줄** 범례의
내용 폭 배치이며 범례 자동 줄바꿈 지원을 새로 완료했다는 주장이 아니다.

## 검증 계획

공유 `target/pr-review`, 빌드 잡 8개에서 새 Native CLI와 fresh WASM을 순차로 준비한다.
PrEP 전 140쪽과 현재 301쪽의 TSV를 다시 산출하고 같은 devel 기준과 Decimal 비교한다.
변경 영역의 review·standalone overlay를 직접 판독하고, 일반 차트 대조군과 기존 차트 검사를
확인한다. 새 렌더링 회귀는 새 코드의 양쪽 전쪽 90% 이상 선행 조건 뒤에 다른 이름으로 작성한다.
정식 검사에서는 라벨 길이에 따른 상대 간격·기호/라벨 순서·내용 보존을 확인한다. 26/27쪽은
98% 미만이므로 절대 px 좌표를 고정하지 않는다. 진단 점수나 이전 소스 결과로 최종 통과를 선언하지 않는다.
