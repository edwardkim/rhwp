## 새 검사와 독립 기대

기존 시험지 검사를 수정하지 않고 새 이름
`issue_7642_stored_cell_row_preservation`으로 검사한다. 원본 저장 줄의
문자 시작 0/3과 셀 소속, 줄의 원문 순서·누락·중복, 셀 내부 포함과 줄
비겹침, 뒤 표의 순서를 확인한다. 해당 핵심 쪽은 양쪽 raw가 99%대이므로
독립 PDF의 셀 경계 선분 교점만 ±2px로 보호한다. 다른 쪽의 좌표 핀이나
문서 전체 98% 판정으로 확대하지 않는다.

stage2886의 실제 출력 관계 진단에서 수정 전 `9a1e7806`은 `true` 한 줄로
FAIL, 수정 후 `0a6ada2b`는 `tru`/`e`로 PASS다. 정식 Rust 검사는 새로
추가했으며 아직 컴파일·실행 전이다. 새 base의 공유 target 빌드가 끝난 뒤
같은 검사 실행 파일에서 이전·현재 불변 CLI를 각각 지정해 실패/통과를
재확인한다. 이 문서는 미실행 검사를 통과로 보고하지 않는다.

두 전쪽 TSV 원문과 Native/WASM 대표 review·overlay 네 PNG를
`mydocs/pr/assets/issue_7642/stored-cell-rows/`에 복사했다. 입력과 독립
PDF는 이미 추적 중인 파일을 재사용하며 중복 원본을 추가하지 않는다.

## 다른 검증과 남은 문제

- 현재 source의 composer 검사는 91개 모두 통과했고 fresh WASM 빌드도
  종료 코드 0이다. JS·WASM·두 DTS의 후보 worktree 동기화를 확인했다.
  기본 작업공간 Studio의 최종 산출물 반영 검증은 아직 남아 있다.
- Native에서 유입 #7980의 원본 PDF 22개·재저장 42개, #7969의 13개
  대조군이 각각 측정 가능했고 전부 90% 이상이다. 새 base와의 페이지별
  하락 비교, fresh WASM과 기능 계약 검증·확대 판독은 진행 중이다.
- 새 전체 검증 스크립트의 출력 경로 오기로 과거 stage2782 Native 폴더에
  충돌한 시도가 있었다. 해당 큐만 종료하고 혼합 기록을 무효로 표시했다.
  고유한 stage2870-full 경로로 재시작했다. 혼합 증거는 수용 근거로 쓰지
  않으며 실행 로그와 오류 원인을 ignored stage2870-destination-error에 보존했다.
- 수식 golden 카탈로그 259개 script를 그대로 담은 합성 입력을 준비했다.
  직접 HWPX 열기는 한컴 worker의 opening 단계에서 실패했다. HWP로 만든
  별도 입력을 한컴 2024에서 저장·Print한 66쪽을 확보했고 저장 script는
  259개 모두 원문과 같다. 이는 원 HWPX와 저장본이 동등하다는 판정이 아니다.
  Native 49·65·66쪽이 90% 미만이므로 golden은 갱신하지 않았다.
- 49쪽의 EQALIGN 가로 배치가 기존 독립 정렬 대조군과 상충한다. 기존
  2020 대조군을 한컴 2024로 저장·Print해도 2020의 정렬 원점이 보존됐다.
  제품 세대 차이라고 추정해 분기를 추가하거나 공유 열 계약을 제거하지
  않았다. 입력 생성·저장 정보와 실제 소비 경로를 더 확인한다. 미수용
  HWP/PDF는 해시를 유지해 ignored temporary-inputs 아래로 옮겼다.
- 원 전체 Rust 23개 실패 중 이전 source에서 2개만 재확인됐고, 나머지
  21개는 이 head에서 해결·재검증된 상태가 아니다. 전체 Rust·lint,
  102개/1,704쪽 및 유입 PR의 새 base 비교와 최종 제출 증적은 남아 있다.
