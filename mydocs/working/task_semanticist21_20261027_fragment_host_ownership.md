## 생산·측정·배치의 실제 대조

4468의 기존 opt-in 진단에서 Native257과270의 두 소유 칸의 CellUnit 62개 기록은
바이트로 같다. 원본 내용과 유닛 분할이 바뀐 것이 아니다. 그러나 4467의 실제 paginator는
3쪽 끝 컷을 [1,10]에서 [1,9]로 바꾸고, 4쪽에 수용한 자식 3행을2행으로 줄인다.

새 visible NO_LS 경로가 기존 `reflow_cut_content_height`를 수용하면서, 선택한 마지막
문단 바로 다음의 표 호스트가 유닛을 하나도 소유하지 않아도 그 빈 글줄을 미리 예약한다.
그 호스트의 실제 첫 NestedTable 유닛에도 같은 글줄이 포함되어 다음 조각과 중복 예약된다.
소비하지 않은 다음 문단의 줄을 현재 컷에 포함시키는 가정을 제거한다. 선택한 source unit의
소유 높이·실제 자식 컷·처음/끝 여백은 기존 공통 원장을 계속 소비하게 한다.

작은 경계와 독립 원본의 Native 전쪽·대표 PNG를 먼저 확인하고, #7833 8원본·최소 IR3조건·
정상13조건·#8188 전쪽을 함께 보존한다. 최종 fresh·기존 회귀·전체 Rust/lint·Studio·새 base
비교는 실제 종료 증거가 필요하며 이 계획으로 완료 처리하지 않는다. Cargo는 공용
`target/pr-review`·8 jobs, 테스트12 threads를 순차 사용한다.
