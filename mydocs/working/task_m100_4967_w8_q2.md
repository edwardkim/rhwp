## 1. source identity와 배포 경계

W5 exact TTF는 외부 font root의 기존 bytes를 사용했고 봉인 SHA-256과 일치했다. 현행 v2 registry가
가리키는 `font-kopubworld@1.0.3` OTF·WOFF2와 package metadata·license는 같은 외부 font root 아래에
고정했다. font bytes는 Git 산출물에 포함하지 않는다.

| source | SHA-256 | technology | UPEM | cmap | requested name exact |
| --- | --- | --- | ---: | ---: | --- |
| W5 exact TTF | `e3ee21a…3fb18` | TrueType `glyf` | 1,000 | 25,971 | yes |
| CanvasKit CDN OTF | `895fdc6d…4c0a` | OpenType CFF | 1,000 | 26,089 | no, `_Pro` family |
| Canvas2D CDN WOFF2 | `679e263a…ed9` | WOFF2/CFF | 1,000 | 26,089 | no, `_Pro` family |

비교 결과는 다음과 같다.

- TTF ↔ OTF/WOFF2: 공통 25,970 codepoint의 advance mismatch 0, fixture 53개도 0
- OTF ↔ WOFF2: cmap 26,089개 advance mismatch 0, fixture outline digest 53/53 일치
- TTF ↔ OTF/WOFF2: fixture outline digest는 2/53만 일치하고 name·technology·bytes도 다름

따라서 세 source를 동일 font identity나 paint identity로 부르지 않는다. Q2가 증명한 것은 공유 cmap의
`hmtx` 호환뿐이다.

registry가 사용하는 package는 KOPUS 정본 자체가 아니라 third-party wrapper다. pinned package의
[jsDelivr 파일 목록](https://cdn.jsdelivr.net/npm/font-kopubworld@1.0.3/)과
[repository license](https://github.com/adrinerDP/font-kopubworld/blob/master/LICENSE.md)를 대사했다.
현재 한국출판인회의 배포 페이지는 TTF·OTF를 별도 source로 제공하며 서버·프로그램 embedding에는 별도
승인이 필요하다고 안내한다. 따라서 이번 qualification은 기존 supply의 재배포 적법성이나 공식 byte
lineage를 새로 승인하지 않는다.
[한국출판인회의 KoPub World 안내](https://www.heritagelab-chacl.org/9e8dfdd2-0faf-4224-a88e-6bd841c3ce06)

## 2. current transform replay

Q1 trace의 current base advance를 그대로 넣어 엔진의 순서를 독립 재생했다.

```text
base advance
→ ratio
→ glyph-width-proportional letter spacing
→ extra character/word spacing from justification
→ negative-spacing clamp
```

1,556건의 replay mismatch는 0이다. 그 뒤 base만 exact TTF `hmtx`로 바꾸고 나머지 transform 값과 순서를
그대로 유지했다. 즉 장평·자간뿐 아니라 current line에서 생성된 justification 보정도 누락하지 않았다.

| 항목 | current | exact candidate | delta |
| --- | ---: | ---: | ---: |
| 전체 advance (HWPUNIT) | 847,977 | 845,252 | -2,725 |
| record 분포 | — | narrower 778 / wider 778 | equal 0 |

정확한 metric이 모든 문자를 좁힌다는 단조 가설은 거짓이다. 18개 장평·자간·kerning 축 가운데 총폭이
증가하는 축도 있으므로 전체 평균 -2,725만으로 제품 변경을 정당화하지 않는다.

## 3. actual fixed-frame metric capacity

Q1의 actual table-cell 28,980 HWPUNIT, text-box 29,434 HWPUNIT와 동일 frame을 사용했다. 아래 boundary는
current 관찰 line partition을 보존한 metric-capacity projection이며, Q3의 실제 reflow 판정을 대신하지 않는다.

| context | lane | ratio / spacing | current → candidate total HU | first crossing | disposition |
| --- | --- | ---: | ---: | --- | --- |
| table-cell | stored | 100 / 0 | 36,100 → 35,572 | 43 → 44 | delayed |
| table-cell | fresh | 90 / -5 | 32,524 → 32,000 | 49 → 50 | delayed |
| table-cell | stored | 80 / -10 | 28,889 → 28,527 | none → none | unchanged |
| text-box | fresh | 100 / 0 | 36,100 → 35,572 | 44 → 45 | delayed |
| text-box | stored | 90 / -5 | 29,452 → 28,928 | 57 → none | removed |
| text-box | fresh | 80 / -10 | 26,352 → 25,934 | none → none | unchanged |

앞당김 또는 새 crossing은 0이다. 이 결과는 exact base가 fixed geometry에서 현재보다 나쁘지 않다는 Q3
진입 근거다. stored LineSeg를 그대로 신뢰하거나 실제 6문서의 개선을 증명한 결과는 아니다.
