# [#4659] 위조 불가능한 리더보드 — 처리 결과 (stage 1)

> 이슈: [#4659](https://github.com/edwardkim/rhwp/issues/4659) · 브랜치: `task_m100_4653` (운동장 확장 스택에 합류)

## 1. 한 문장

운동장의 점수판을 markdown 표가 아니라 **검증 사다리(서명·앵커·정산 원장) 위에**
세웠다. 모든 순위는 제3자가 오프라인에서 재검증할 수 있고, 점수 위조·소급 조작·
이중 등재가 사람의 양심이 아니라 해시로 막힌다.

## 2. 왜 이 설계인가 — 자기 순환

AI 벤치마크 리더보드의 세계적 병폐는 점수의 신뢰다: 수치는 자기 신고이고, 소급
수정이 가능하고, 같은 결과의 재탕을 막을 방법이 없다. 그런데 이 저장소에는 그
문제의 해답 전체가 이미 있다 — 검증 사다리 1~10년 축. 그래서 **사다리를 시험하는
운동장의 점수 자체를 그 사다리로 봉인한다.** 새 암호학은 0줄, 전부 기존 rhwp
명령(keygen·settle·anchor)의 조합이다.

## 3. 등재 사슬

```
score.py → scorecard.json + admission.json   (채점기가 점수·입장 판정 발급)
  → keygen                                    (에이전트 신원 — 공개키만 keyring 에 커밋)
  → settle propose --sign-key                 (명세서·스코어카드·입장봉투 3해시 고정 + 서명)
  → settle record --ledger                    (append-only 원장 — 재등재 불가)
  → anchor add(claim) + anchor add(원장 스냅샷) + checkpoint   (투명성 로그 + 머클 에폭)
```

`admission.json` 은 채점기(`gym/score.py`)가 새로 발급하는 입장 판정 봉투다.
판정 기준은 "채점이 유효하게 완주했는가"(pack 1개 이상)이지 만점 여부가 아니다 —
리더보드는 낮은 점수도 순위이지 입장 거부 사유가 아니다.

## 4. 3공격 실측 (수리 포함 정직 기록)

| 공격 | 방식 | 결과 |
|---|---|---|
| 점수 위조 | 커밋된 스코어카드 점수를 99999 로 부풀림 | `verify` **exit 3** — `pin.scorecard` 실패 |
| 소급 조작 | 원장 첫 줄의 capsuleSha256 바꿔치기 | `verify` **exit 3** — 스냅샷 봉인 불일치 + `ledger.crossPin` |
| 이중 등재 | 같은 스코어카드로 attest 재시도 | 원장 **거부** `duplicate: true, existingSeq: 0` |

첫 구현에서 **공격 2·3이 뚫렸다** — 정직하게 기록한다.

- **이중 등재가 통과한 줄 알았다** → 사실은 `SystemExit` 메시지가 stderr 라
  캡처에 안 잡혔을 뿐, 원장은 처음부터 `duplicate: true` 로 거부하고 있었다.
- **소급 조작이 실제로 뚫렸다** — 원장 항목이 1개일 때는 "다음 줄이 폭로"
  하는 체인 방어가 성립하지 않는다(꼬리 줄은 후속 줄이 봉인하기 전까지 미봉인,
  5년 축의 알려진 한계). 두 방어선을 추가해 막았다:
  1. **원장 스냅샷 봉인** — attest 마다 원장 파일 바이트 해시를 앵커에 함께
     등재하고, verify 는 "앵커 마지막 항목 == 현재 원장 바이트 해시" 를 요구한다.
  2. **교차 대조** — 원장 항목의 capsuleSha256 이 claim 파일의 capsuleSha256 과
     일치하는지 본다. 원장만 바꿔도 claim 이 남아 폭로된다.

수리 후 3공격 전부 차단, 기준·복원 모두 `verify` exit 0(무결 복귀).

## 6. 정직 조항

- 봉인 범위는 "이 스코어카드가 이 시점 이 신원으로 등재되어 이후 변조되지
  않았다" 까지다. 채점 자체의 재현은 이 사슬 밖이며, 스코어카드의 runner
  신원(version·commit·capabilities digest)과 커밋된 제출물로 수행한다.
- 비밀키는 `gym/leaderboard/keys/` 로 커밋 금지(.gitignore). 공개키만 keyring 에.
- `chain_walk`·`merkle_root` 는 `anchor_log` 의 파이썬 거울이다 — rhwp 에
  settlementLedger 를 단독 검증하는 CLI 가 없어(원장은 settle verify 의 opt-in
  축) 바이너리 불요 경로를 위해 같은 알고리즘을 둔다. 두 구현이 갈라지면
  가드가 잡도록 계약 테스트로 고정했다.
