## 98%여도 완료로 판정하지 않은 이유

공식 Visual Sweep 일반 모드에서 1·35쪽의 새 review와 standalone overlay를 산출해
직접 열었다. 35쪽 그림 안의 `Windows 서버군`·`Unix 서버군`과 작은 장비 문구에서

이 페이지를 완료 페이지로 선언하거나 새 px 좌표 회귀를 등록하지 않았다.

원인은 원래 격자의 마스크 합성 뒤 큰 그림을 작은 PNG로 옮기면서 bilinear 표본만
선택한 것이다. 축소율이 크면 얇은 획의 면적을 보존하지 못한다.
마스크를 축소 전에 합성하는 순서는 유지하되, 합성된 premultiplied RGBA를
Lanczos3 저역 통과로 축소한다. 기존 4배 mask/fragment 경로가 사용하던 같은 축소·색 보존
처리를 공통 helper로 옮긴다. 좌표·요청 PNG 크기·색상 임계값·2px 반경은 바꾸지 않는다.
Lanczos overshoot의 색 채널 제한은 기존 premultiplied 불변식 `R/G/B <= A` 그대로다.

진행 중이던 stage1985 fresh WASM과 대기 stage1987은 이 실제 품질 결함 때문에 중단했다.
컴파일 출력 공백이나 시간 경과 때문에 중단한 것이 아니다. 해당 작업 전용 프로세스 그룹과
대기 controller만 확인해 종료했으며, 이전 고정 producer의 전쪽 queue·공유 캐시는 보존했다.
중단된 WASM을 성공한 package로 재사용하지 않는다.
