# #7642 Stage 150 — 책갈피 문단의 원본 간격 보존

Issue: #7642

## 발견한 실제 회귀

Stage 149의 sample16 전체 Native 64쪽은 최저 27.23722%, 미달 18쪽이다.
Stage 147의 미달 17쪽에 5쪽이 추가됐다. 5쪽은 98.87642%에서 55.21134%로 내려갔다.
동일 입력·독립 한컴 2024 Print PDF로 비교했으며 현재 수정에서 생긴 회귀로 기록한다.
평균·전체 쪽수·다른 쪽의 통과로 면제하거나 새로운 이슈로 이관하지 않는다.

원점 수용의 f64 경계는 안정화됐으나 수용할 저장 원점 자체가 로드 중 축소돼 있었다.
`reflow_zero_height_paragraphs`가 일부 합성 줄을 보충한 뒤 전체 저장 사다리를 재작성한다.
이때 `text_only_controls`는 Field만 인정하며, Bookmark가 있으면 `source_anchor_end`를
끊는다. 책갈피는 문단 위치 표지이며 표·그림처럼 줄 높이나 바깥 상자를 소비하지 않는다.
이 분류 때문에 원본 첫 줄 앞의 물리 간격이 없어졌다.

| 원본 문단 | 원본 첫 vpos | 로드 후 첫 vpos | 원본 앞 문단 끝과의 간격 |
| --- | ---: | ---: | ---: |
| 124 — 책갈피가 있는 “1. 일반사항” | 17400HU | 16548HU | 852HU |
| 125 — 뒤따르는 “(1) 개요” | 20528HU | 19108HU | 568HU |
| 141 — “(4) 사업자 선정방식” | 73116HU | 71128HU | 568HU |

원본 XML과 같은 source의 CLI `dump`를 직접 대조했다. 계산값이나 이미지 좌표에서
기대값을 역산하지 않았다. 세부 행과 명령 출력은 ignored output의
`stage149-sample16-bookmark-gap-source-diagnostic.json` 및 `stage149-sample16-dump-pi*.log`에 있다.
원점 비교의 기존 기각이 우연히 일부 잃은 간격을 paint에서 되살리고 있었으므로, 그 결과를
정상 캐시 계약으로 고정하지 않는다.

## 다음 구현과 소비 경로

`원본 저장 프레임 → 합성 줄 보충의 source_anchor_end → 재작성 first vpos →
HeightCursor → fit/페이지 배정 → 실제 줄 원점`을 같은 근거로 잇는다.

Field와 Bookmark만 있는 문단은 텍스트 줄의 앵커·끝점·줄 내부 저장 간격을 보존한다.
둘 중 하나와 표·그림이 섞인 문단은 이 분류에 넣지 않는다. 기존 Page/Section·저장 0
프레임 경계를 보존하고, 새 콘텐츠가 자랐으면 원본 앵커로 성장분을 되감지 않는다.
본문 프레임과 reset 판정에서도 같은 분류를 사용해 간격 보존이 한 분기에만 적용되지 않게 한다.
문서 ID·제목 문자열·고정 px 오프셋 조건을 넣지 않는다.

## 검증과 남은 범위

Stage 149의 fresh WASM 빌드와 선행 9쪽은 완료됐고, Native와 같은 전쪽 90% 이상이다.
Native/fresh WASM 최저는 98.50071%이며 source 해시는 실행 전후 동일했다.
전체 55문서 Native/fresh WASM은 고정된 Stage 149 바이너리·패키지로 대조를 계속한다.
이 결과는 변경 전 source의 진단이며 새 코드의 검증을 대신하지 않는다. 5쪽·6쪽 새 review PNG에서
원본 간격과 내용 소속을 확인했다. 새로운 분류로 고친 뒤 sample16 전체 64쪽을 재출력하며,
원본/HWP5/HWPX·수정 비적용 대조군을 함께 비교한다. 전쪽 90%와 확대 판독 전에는
관계형 회귀의 추가·기대값 변경·PR 생성을 보류한다.

## 실행 결과 (2026-10-12)

Native 빌드는 종료 코드 0이며, 실행 전후 source 해시가 일치했다.

탭·표 셀 순서·영월 서식·표 격자 대조군 4문서 9쪽은 모두 90% 이상이다.
최저 98.50071%다. 전체 sample16 HWPX 64쪽은 최저 27.23722%, 미달 17쪽으로
아직 통과하지 못했다. 5쪽은 55.21134%에서 84.40029%로 개선됐고 6쪽은 통과했다.
반면 40쪽은 50.97425%로 새 미달이 확인되어 현재 보정 범위에 포함한다.

원본/로드 후 첫 원점 비교에서 문단 124=17400HU, 125=20528HU가 복원됐다.
문단 131은 글자처럼 배치된 사각형이며 저장 줄 높이와 도형 높이가 같은 7056HU다.
이 줄 끝은 37096+7056+780=44932HU이고 다음 문단 132의 원본 첫 원점은
45500HU다. 물리 도형이라는 이유로 앵커를 끊어 이 사이의 568HU가 아직 소실됐다.

40쪽의 “3. 사업현황”은 원본 문단 632의 첫 원점이 852HU이나 로드 후 69116HU다.
직전 그림 문단 631의 저장 첫 원점은 31196HU, 저장 줄 높이 포함 끝은 72240HU다.
기존 쪽 리셋은 직전 마지막 줄의 시작만 확인하여 큰 개체가 끝까지 점유한 경우를 놓친다.
개체 뒤 원본 간격과 저장 쪽 리셋의 소유를 별도로 수정·재검증해야 한다.

검증 영수증은 ignored output의 `stage150-native-realign-build.json`,
`stage150-realign-preflight/receipt.json`, `stage150-sample16-whole-native/receipt.json`에 있다.
같은 최신 출력으로 `stage150-sample16-selected-review/review/review_005.png`,
`review_006.png`, `review_040.png`를 산출했다. 5쪽과 40쪽을 직접 판독했으며,
5쪽 도형 뒤의 세로 간격과 40쪽 제목의 쪽 소속 차이가 남아 있다.
이 결과를 최종 시각 통과로 판정하지 않으며 새 회귀 검사·PR 생성은 계속 보류한다.
