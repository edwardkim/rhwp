# #7642 재조판 줄의 실제 예산 초과와 저장 줄 관용의 구분

Issue: #7642. 수정 전 생산 소스는 `9b285a996e1456304360edd4e9e65fce9193e833`이다.

## 독립 출력으로 확인한 원인

#7518의 두 `nested-mixed-cell.hwp`에서 마지막 행 오른쪽 문단9가 RHWP에서는
7쪽과 8쪽에 한 줄씩 나뉜다. 원본 그대로의 한컴 Print는 두 줄 모두 8쪽에 둔다.
문단의 widowOrphan·keepLines·keepWithNext는 모두 꺼져 있다. 이 관측을 문단
분할 금지 규칙으로 일반화하지 않는다.

stage2967에서 별도 진단 HWPX 세 건을 한컴2020 11.0.0.9136의 Print method0,
`hancom2020_pdf_driver_one_up`으로 출력했다. 기존 HWP와 PDF는 변경하지 않았다.
읽기 전용 내보내기 대조군은 같은 0+2줄 분할이다. 문단9만 늘리면 0+3줄,
앞 문단을 한 줄 줄여 공간을 늘리면 1+2줄이다. 따라서 한컴도 해당 문단의
줄 내부 분할을 허용하며, 잔여 예산과 줄 점유로 경계가 달라진다.

stage2966의 실제 scanner는 마지막 행에 169.293333px의 내용 예산을 주지만,
169.333333px인 11개 유닛을 수용한다. 차이 0.04px는 96dpi에서 원문 3HU다.
처음에는 기본 용량 비교의 0.1px 관용을 원인으로 추정했으나 아래의 실제
분기 추적으로 그 추정을 정정했다. 실제 수용 지점의 초과는 f64 합산 끝자리
오차가 아닌 원문 단위 초과다.

## 생산 결과와 소비 경로

`cell_units`의 재조판 줄 높이 → `advance_row_cut_inner` 및
`advance_row_block_cut`의 용량 선택 → `RowCutResult.end_cut`과 같은 컷의
내용 높이 → scan의 수용·이월 → partial paint의 문단/줄 범위로 이어진다.
scanner 뒤에서 글자를 숨기거나 좌표를 이동시키지 않고 첫 컷의 수용을 고친다.
row-offset block 경로는 이미 물리 상자와 예산을 직접 비교하므로 새 관용을
추가하지 않는다. 기존 저장 줄과 중첩 표/그림의 별도 점유 규칙도 구별한다.

새로 조판한 일반 텍스트 줄은 실제 예산을 지켜야 한다. 이 줄에는 합산 횟수와
값의 크기로 계산한 f64 연산 오차만 허용한다. 저장 LINE_SEG를 재사용하는
줄의 기존 독립 출력에서 확인된 복원 관용을 이 변경으로 없애지 않는다.
문서 ID·행 번호·고정 좌표·특정 여유 높이로 분기하지 않는다.

## 검증 상태와 다음 판정

구현 뒤 두 원본과 세 진단 대조군의 전체 Native/fresh WASM·독립 Print를
다시 대조한다. 1+2줄 정상 분할, 문단9의 8쪽 소유, 문단10·11과 빈 끝 줄,
쪽수 및 앞 중첩 표의 누락·중복을 확인한다. #5566, 중첩 host 간격, #7969와
새 devel의 기능 보존 검증도 유지한다. 기존 #7518 기대값은 바꾸지 않는다.
새 정식 회귀 추가는 전쪽 90% 이상과 확대 판독을 확인한 뒤 수행한다.
현재 기록은 원인 근거와 검증 계획이며 구현의 통과를 선언하지 않는다.

## 수정 후보의 실제 재검증과 가설 제한

후보 `33e608e2e6`의 Native 재검증(stage2973)은 원래 표 배치 5문서를 유지했지만,
#7518 두 원본과 세 진단 대조군은 개선되지 않았다. 두 원본의 최저값은 그대로
56.14546%이며, 마지막 행 컷도 `[2, 11]`로 같다. 따라서 위의 3HU 초과 해석만으로
실제 수용 원인을 입증한 것은 아니다. 공통으로 출력한 내용 예산과 칸별 실제
예산·유닛 속성의 차이를 더 추적해야 한다. 이 후보를 #7518 수정 완료로 세지 않는다.

`RHWP_DIAG_REFLOW_CAPACITY`는 단위 높이 안쪽의 경계에서 실제 적용된 칸별
예산·저장 줄 유무·제어 수·유닛 종류·관용치를 기록한다. 기본 실행의 컷·높이를
바꾸지 않으며 WASM에서는 진단 분기를 컴파일하지 않는다. 실행 로그는 ignored
output에만 보존한다. Native/fresh WASM 및 기존 검사의 기대값을 완화하지 않는다.

## 실제 수용 분기와 후속 보정

stage2997은 실제 경계 유닛이 `no_ls=true`, 제어0개, 일반 텍스트 줄임을
확인했다. 기본 비교에 들어온 높이는 171.733333px이므로 이 분기는 원래도
예산을 초과한다. 이후 `native_saved_reset_cut_trailing_trim`의 재조판 줄
간격 2.4px 제외 결과가 169.333333px인데, 그 결과를 재수용하는 별도 비교의
0.5px 관용이 남은 0.04px 초과를 허용했다. 첫 비교만 고친 후보는 이 소비
분기를 놓쳤다.

줄간격을 제외한 뒤에도 같은 재조판 용량 정책을 적용한다. 저장 줄 경로는
해당 지점의 기존 관용을 유지하고, 재조판한 일반 텍스트 줄은 두 비교 모두
합산 오차만 허용한다. 요구 높이·종료 컷·실제 배치의 공통 원장은 유지한다.
변경 후 두 원본·세 반례와 기존 정상 대조군을 다시 검증하며, 아직 통과
결과가 없는 범위는 완료로 보고하지 않는다.

## 보정 소스 f91ff1d189의 실제 검증
