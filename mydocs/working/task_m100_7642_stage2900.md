# #7642 원문 소유와 글꼴 측정 결정 검사의 전제 교정

Issue: #7642

## 근거와 변경 범위

생산 소스 `0a6ada2bd29baec40b9f8c768b574bb552e568e5`의 기존 출력과 원문을
읽고, 전체 회귀에서 실패한 세 검사의 전제를 함께 교정했다. 생산 코드는
바꾸지 않았다. 공용 target의 선행 검증이 끝난 뒤 같은 변경 묶음을 실행한다.
이 기록 작성 시점에는 새 Rust 검사 결과를 아직 확인하지 않았다.

| 대상 | 독립 근거 | 검사 변경 |
| --- | --- | --- |

#4961 변경은 배치 정답 좌표나 출력 해시를 갱신한 것이 아니다. 기존의 원문
주소에서 어느 측정 경로가 선택됐는지 검사한다. fresh WASM의 실제 trace도
같은 결정을 확인했지만 이것을 Native Rust 테스트 통과로 대신하지 않는다.

## 시각 선행 근거와 직접 판독

같은 생산 소스의 `stage2869-pdfium-head-{native,wasm}/receipt.json`과 전쪽
`silhouette.tsv`를 재사용한다. PDFium,96dpi,Print 프로필과 입력/PDF 해시는
원 실행 기록 그대로다. 이 테스트 변경 후 새로 렌더했다고 기록하지 않는다.

| 원본 | 전체 쪽수 | Native 최저 raw | fresh WASM 최저 raw |
| --- | ---: | ---: | ---: |
| `samples/hwp3-sample16.hwp` | 64/64 | 96.89198% | 96.98804% |
| `samples/issue6776/78494-virtual-convergence-industry-decree.hwpx` | 74/74 | 91.07651% | 90.63917% |

`stage2899-qualified-heading-punctuation-panels/`에서 원 캡처의 같은 페이지를

않는다. 새 절대 px 위치 핀을 추가하지 않았다.

## 실행 상태와 남은 범위

`rustfmt`와 `git diff --check`는 통과했다. 세 검사의 Rust 실행은 선행
`stage2893-stored-cell-regression` 종료 뒤 같은 `target/pr-review`에서 수행한다.
공용 target의 Cargo 작업을 겹치지 않고 빌드 잡8개를 사용한다.

새 devel `7d01ef610f378157b79d36ef23e8ed4a3c8ab051`의 Native/fresh WASM
빌드는 모두 종료 코드0이다. 전체102문서의 후보/base 전쪽 비교, 수식 atlas의
정렬 차이, 나머지 회귀 실패 및 최종 lint·Studio 검증은 아직 남아 있다.
이 단계는 PR 준비 완료가 아니다.

## 묶음 실행 결과

`a0b84ac0df`를 별도 검토 worktree에서 실행한 stage2901은 종료 코드0이다.
파생 suite 자동 수집 후 공용 target·빌드 잡8개·`native-skia`로 세 suite를
한 번에 컴파일했다. HWP3 왕복2개, 글꼴 trace9개, 영문 슬롯1개가 **12/12**
통과했다. 각 로그는 ignored stage2901 아래 모듈 이름별로 보존한다.
정식 전체 회귀나 다른 실패의 통과로 확대하지 않는다.

KoPub 근거도 재확인했다. 시스템의 실제
`/usr/local/share/fonts/hwp-convert-mcp-safe/KoPubWorld Dotum Light.ttf`
SHA-256은 `069494cce21a4222c88e537f256b6f46fee209375aba769f82431b2d382bc84f`다.
원본 프로그램의 `two` 글리프는 UPM1000에서 전진563이며, 이 문자의
글자 크기를 반영한 전용 표 조회와 같은 계열이다. 글꼴 파일을 저장소에
추가하거나 현재 trace의 숫자를 배치 정답 좌표로 고정하지 않았다.

저장 셀의 별도 정식 검사도 stage2893에서 완료했다. 같은 Rust 검사와
수정 전9a1e7806/수정 후337ae04f의 CLI를 각각 연결했고, 전자는 의도한
`true` 한 줄의 경계 위반에서 FAIL, 후자는 `tru`/`e`와 독립 Print 경계에서
PASS다. 이 결과를 이번 세 전제 교정의 검출 증거와 혼합하지 않는다.

## 새 devel의 Native 대조군 비교

stage2904는 base7d01ef61과 생산 소스0a6ada2b의 #7980 대조군64개,
페이지 테두리12개, #7969 대조군13개, #7970 대조군15개를 비교했다.
입력/PDF 해시·글꼴·DPI·compat·계산 모듈·PDFium 정책·전체 쪽수와 쪽 번호를
맞춘104문서453쪽이다. Decimal 비교 결과103문서에는0.01%p 이상 하락이 없다.
`operators` p1은95.70920%→95.58632%, **0.12288%p 하락**이므로 재검토다.
90% 이상이라는 이유로 이 차이를 면제하지 않는다. fresh WASM과 실제 API·
브라우저 기능 계약은 이 Native 비교로 대신하지 않는다.

나머지 기존 실패의 현재 결과를 얻기 위해 stage2905에서 원래23건 중 이번에
확인한3건을 제외한20건을 묶어 재검증한다. 여기에는 이전 소스에서만 통과를
확인했던2건도 포함된다. 이 기록 작성 시점에는 컴파일 중이다.
