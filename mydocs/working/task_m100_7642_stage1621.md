# #7642 정상 한컴 수식 저장본의 관계·완료 페이지 회귀

Issue: #7642

## 선행 근거와 범위

1607단계의 제품 보정 커밋은 `121485fb3`이다. 정상 한컴 저장 128개 수식·16쪽과 원본
PrEP 140쪽을 같은 독립 Print PDF로 대조한다. Native 전쪽은 1618에서 완료했으며,
fresh WASM 1619/1620 전쪽 검증과 확대 판독을 마친 뒤에만 fixture·새 회귀를 활성화한다.

새 검사 이름은 `verified_hancom_structure_frames`로 정한다. 과거 시험지 회귀 함수나
골든의 기대값을 갱신하는 작업이 아니다. 검사 범위는 다음과 같다.

- 정상 저장본의 전체 128개 수식 스크립트, 원본 문단·컨트롤 소유, 16쪽의 쪽별 8개 보존.
- 유효한 저장 줄의 상대 전진과 저장 줄이 없는 문단의 실제 앞 줄 점유 뒤 간격.
- HancomEQN 네 크기의 분수 뒤 아래첨자 소속·좌우 순서·분모 기준선 아래 하강 관계.
- 완료 조건을 충족한 원본 33쪽의 합·상한·분자·분모·장식 본체 glyph 원점 ±2 CSS px.
  독립 PDF의 실제 원점에서 정하며 관계 검사도 유지한다. 31쪽은 미세 위치 차이가 남아 제외한다.

같은 두 진단 assertion은 수정 전 1608에서 각각 간격 0과 잘못된 첨자 위치로 실패하고,
현재 1617에서 통과했다. 정식 검사로 활성화한 뒤 Cargo suite에서 다시 확인한다.
독립 Print·fixture와 대표 PNG를 함께 보존하며 TSV·로그·JSON은 ignored output에 둔다.

## 남은 검증

fresh WASM 전쪽·확대 대조와 실제 CanvasKit 수식 replay가 진행 전이다. 정상 fixture의
선행 조건이 입증되지 않으면 새 회귀 추가를 보류한다. 기존 전범위 문서 재산출, 최신 devel과의
비교, 전체 Rust와 알려진 다른 차이는 별도 남아 있으며 이 단계로 PR 완료를 선언하지 않는다.


## 현재 검증 결과

1617 Native·1619 fresh WASM은 제품 소스 1,612개 해시가 같고 `121485fb3` 커밋의
제품 소스와도 전부 일치한다. fresh release 빌드의 실제 exit 0·최적화 종료를 확인했고
`pkg`와 Studio public JS/WASM의 바이트도 같다. 공개 JS wrapper 변경을 함께 반영한다.

| 범위 | Native | fresh WASM | 전체 쪽수 |
| --- | ---: | ---: | --- |
| 정상 저장 진단 최저 | 98.89677% | 99.24726% | 16/16 |
| 원본 PrEP 최저 | 91.54965% | 92.43307% | 140/140 |
| 진단 완료 9쪽 | 100% | 100% | 원본 128개 수식 보존 |
| 원본 완료 33쪽 | 99.46565% | 99.47442% | 해당 쪽 수식 5개 보존 |

1618/1620 전쪽 TSV, `stage1621-regression-visual-prerequisite.json` 및
`stage1621-product-source-commit-binding.json`이 같은 ignored 증적 루트에 있다.
진단 1/5/6/9/14쪽과 원본 26/27/31/33/56/70쪽을 출력하고 핵심 구조·미세 간격을
확대 대조했다. 원본 31쪽의 알려진 인라인 위치는 미해결로 유지한다.

[정상 한컴 HWP·Print 및 생성 설명](../../tests/fixtures/equation-font-metrics/HANCOM_STRUCTURE_DIAGNOSTIC.md)을
함께 추가했다. 새 이름의 정식 회귀는
[`verified_hancom_structure_frames.rs`](../../tests/cases/verified_hancom_structure_frames.rs)다.
9쪽과 33쪽의 독립 원점 ±2 CSS px는 관계 검사를 함께 유지하며 보호한다.
같은 핵심 동작을 검출하는 완료 쪽 중 저장 줄 없는 흐름은 양쪽 100%인 9쪽,
원본의 합·분수·장식은 해당 동작이 있는 99%대 33쪽을 선정했다.

| 새 검사 | 수정 전 1608 관측 | 현재 1617 / 정식 Cargo |
| --- | --- | --- |
| 전체 인라인 소유·간격 | 40→41 문단의 앞 줄 뒤 간격 0으로 실패 | 통과 |
| 분수 뒤 아래첨자 | 첨자가 분모 위에 붙어 실패 | 통과 |
| 완료 9쪽 원점 | 둘째 줄 기준선 121.60 / Print 130.09782로 실패 | 통과 |
| 원본 33쪽 구조 원점 | 첫 분모 tau의 x 157.01333 / Print 154.40으로 실패 | 통과 |

`stage1627-before-tests.log`는 **같은 정식 검사 소스**를 수정 전 라이브러리에 연결해
네 검사 모두 해당 결함으로 실패한 실행이다. 빌드 오류를 결함 검출로 세지 않았다.
1626은 잡 8개·테스트 스레드 12개·공용 target의 실제 14개 case 경로에서
**84/84 통과**, 2,392개 필터 제외를 확인했다. 전체 Rust 통과를 뜻하지 않는다.

1624는 실제 CanvasKit software renderer에서 원본 33쪽 수식 5개와 공통 분수선 3개를
직접 replay했다. 설치 HancomEQN을 실제 공급했고 unsupported op·미등록 글꼴 fallback은
0개, runtime readiness는 통과했다. 수식만 추린 진단이므로 전체 CanvasKit 본문·Studio
문서 여정의 증거를 대신하지 않는다. 하네스의 진단 메서드명을 실제 API로 교정한 뒤
이 결과를 얻었고, 시작한 Vite·Chrome 임시 프로필도 종료·정리했다.

## 사용자 요청에 따른 미주 공통 규칙 우선 조사

[시험지 미주 공통 규칙 조사](../../mydocs/tech/investigations/issue-7642/endnote_common_rules.md)에서
50개 원본, 미주가 있는 30개 입력과 독립 Print를 대조했다. 변경 없는 대조군을 포함한
667개 경계 중 실제 간격 값이 달라지는 관측은 292개다. 미주별 로컬 좌표·표시 번호와
원본 소유의 차이, 위·아래 여백과 미주 사이 간격의 역할을 구분했다.
[한컴 0/7/20mm Print 대조군 그림](assets/issue7642/hancom_structure_20261016/nov-print-spacing-references.png)은
참조 PDF 사이의 속성 변화만 보여 주며 현재 RHWP의 일치 판정이 아니다.
문서별 예외를 더하기 전에 같은 규칙이 fit·예약·실제 배치에서 소비되는지 계속 추적한다.

## 완료 범위와 남은 범위

이 단계의 Native/fresh WASM 선행 조건·새 회귀 4개·focused 84개는 완료했다.
전체 기존 문서의 현재 head 재산출, 최신 devel의 실제 전쪽 비교, 전체 Rust와 알려진
다른 차이는 남아 있다. PR 생성·승인·통합 완료 판정이 아니며 기존 검증 범위를 줄이지 않는다.
