# #8533 제출 범위 확정과 클릭·Esc 이슈 분리

2026-11-04 사용자 지시에 따라 편람 3·4쪽 클릭·Esc 문제는
[#8578](https://github.com/edwardkim/rhwp/issues/8578)에서 별도로 해결한다.
실제 재현의 잘못된 셀 주소, Esc 후 다음 쪽 이동, 한컴의 기대 동작, 원인과 완료 조건을
이슈에 등록했고 게시 본문을 다시 읽어 일치함을 확인했다.

이 브랜치에서 먼저 적용했던 묶음 우선 선택은 본문 편집 완료를 입증하지 못했다.
`input-handler-mouse.ts`의 해당 변경을 철회하여 현재 devel base와 같게 복원한다.
묶음/글상자 선택용으로 추가했던 검사도 제외하고, 남은 Screen/Print 메트릭 전환 검사는
`issue-8533-print-metric-context.test.ts`와 전용 runner로 이름과 범위를 정리한다.
이전 단계의 개체 선택 성공을 클릭·Esc 편집 문제의 해결로 주장하지 않는다.

현재 제출 범위는 Print의 portable 메트릭 격리, 원본 TTF 프로그램 공급,
정적 fallback의 인쇄 윤곽과 문맥 문자 경계, JPEG 장치 프레임의 공통 복호화,
정확한 #8389 쪽별 하한 비교다. 경고를 숨기거나 원본/PDF/문턱을 바꾸지 않는다.

사용자가 지정한 ubuntu-ted 커밋 `eae46acddbccf3316733e3e6d313d2cbc53984a0`도 확인했다.
현재 Mac 코드에도 PostScript 전용 face에서 `names[0]`를 먼저 조회하는 결함이 있었다.
새 검사 두 건은 보정 전 `IndexError`로 실패했고, 패치를 반영한
`a0f490fa95`에서 관련 Python 38건이 통과했다. 원격의 다른 dirty 변경은 읽기만 했으며
수정하지 않았다. 원격에서 광고되지 않는 SHA fetch 대신 동일 커밋의 format-patch를
읽어 적용했고 원 author와 변경 내용을 보존했다.

최신 WASM `b366ca…`의 최소 글꼴/일반 환경은 각각 383쪽을 완료하여 #8389의
표시 정밀도 하한 대비 하락 0건이다. Native 383쪽도 같은 하한을 유지한다.
원시 최저값은 Native 99.96465%, 최소 글꼴 WASM 99.96403%, 일반 WASM 99.96401%다.
두 자리 표시값과 원시값이 정확히 100%인 쪽 수를 혼동하지 않는다.
전체 회귀와 나머지 필수 게이트 완료 여부는 최종 검증 정본에서 확정한다.
