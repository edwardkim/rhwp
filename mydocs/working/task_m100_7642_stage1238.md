# 단계 1238 표 테두리 반복 구간의 공통 물리 단위

Issue: #7642. 보정 전 code head는 `4bfbb8302c9bf2eb418472c2ed5fc9a36b54dac5`, 비교 devel은 `463c48cc228170b576c832591b76826116e86a49`다.

## 독립 근거와 범위

주거 계약서 2쪽 안내 표의 점선이 Native/Canvas에서는 약 4px 주기, 독립 Print에서는 약 1.6px 주기였다. 이 수치는 진단 관측이며 화면 좌표 기대값으로 고정하지 않는다. parser의 HWPX DASH/DOT와 BorderLineType 대응은 이미 맞으므로 바꾸지 않는다.

기존 HWPX의 표를 복제한 합성 입력에서 표준 굵기 16개와 실선·긴 점·짧은 점·일점쇄선·이점쇄선을 조합했다. 두꺼운 반복도 수용하도록 A3·720pt 셀·명시적 쪽 나눔을 선언했다. 저장 LineSeg는 넣지 않았다. 이 입력은 **선 패턴의 독립 매개변수 진단**이며 원본 문서의 조판 완료나 회귀 fixture 자격을 대신하지 않는다.

같은 입력 SHA `681899303a964004f66d8324727a8f868995422868694123296615051e1dc680`을 MCP의 PDF **Print** 경로로 두 번 출력했다.

| engine | 실제 한컴 | job | Print mode | 쪽 수 |
| --- | --- | --- | --- | --- |
| 2020 | 11.0.0.9136 | c89e8437-d343-438f-86d3-749551a06324 | hancom2020_pdf_driver_one_up, method 0 | 20 |
| 2024 | 13.0.0.3901 | a825328f-4d59-44d3-9c2f-a8d972467790 | frame_print_to_pdf_ex_one_up, method 0 | 20 |

셀 본문과 앞 제목의 원문 순서로 80/80 사례를 연결했다. PDF 벡터의 각 선분 길이·다음 시작까지의 거리에서 인쇄 변환 행렬을 제거하면 두 engine의 전체 16×6 구간 값이 **1/600 inch 단위로 일치**한다. PDF의 소수 3자리 좌표 반올림과 페이지별 물리 축척은 구분했다. 중간 폭의 소수 반올림을 추정한 근사식은 채택하지 않는다. 유한한 표준 BorderFill 굵기 index에 대응하는 독립 인쇄 단위 표를 사용한다. 도형의 fill+outline pen 계약과 혼합하지 않는다.

입력과 두 기준 PDF는 `pdf/issue7642-border-pattern-matrix-20261015/`에 함께 보존한다. 전체 metadata·SHA·원문 소유 연결·각 구간 원래 소수값과 명령은 ignored output의 `stage1233-border-pattern-probe/`, `stage1234-border-pattern-print-measurements.json`, `stage1235-border-pattern-print-measurements.json`에 있다. 원래 주거 계약서 Print 기준은 교체하지 않는다.

## 실제 소비 경로

`BorderLineType + 선언 굵기 index → stroke_pattern::border::border_dash → 확정한 물리 반복 구간 → 표/대각선 LineStyle → Native Skia / Canvas2D / SVG / paint JSON / CanvasKit`으로 연결한다. 이중·삼중선의 별도 배치와 이번 측정에 없는 LongDash/Circle은 기존 계약을 유지한다. 확정한 구간에 backend가 선 굵기를 다시 곱하지 않는다.

JSON은 확정한 구간을 숫자 배열로 내보내며 CanvasKit이 같은 값을 소비한다. 기존 문자열 스타일은 유지한다. 원본 줄·문단·셀 소유와 표 위치·선 굵기는 변경하지 않는다. 문서 ID 분기, 글꼴 교체, 점수 계산·마스크·허용치 변경은 없다.

## 검증 계획과 현재 미완료 범위

한 번의 Native 빌드 뒤 주거 계약서 전쪽·표가 있는 영향 페이지와 대조군을 재출력한다. 같은 source의 fresh WASM·직접 확대 판독·기준 devel 비교도 수행한다. 새 관계형/좌표 회귀는 해당 원본의 전쪽 90%와 확대 판독, 좌표 검사는 해당 쪽 양쪽 98% 조건을 확보한 뒤 정식 추가한다.

이전 4bfbb8 WASM 빌드는 exit 0, source hash 유지, 루트 pkg/Studio JS·WASM hash 일치로 완료했다. 같은 source의 주거 계약서 전쪽 출력도 종료됐으며 판독을 이어간다. source 393b159의 전쪽 corpus 큐는 새 보정 결과로 보고하지 않는다.

시험지 일부 쪽의 devel 대비 하락도 별도로 검토 중이다. 한컴돋움의 PDF/로컬 프로그램은 72개 글자 중 61개 윤곽이 같으나 fpgm/prep/cvt 프로그램은 다르다. regular SFNT 재로딩과 시스템 normal face의 독립 Skia 진단은 같은 결과였으므로, 설정 손실이라고 추정해 코드를 변경하지 않았다. 글꼴 문제 또는 합성 굵기 문제의 최종 판정은 아직 하지 않는다. 전체 회귀·lint·PR·CI·merge는 미완료다.

## 최초 사전 검사

파생 integration suite를 `--prepare`로 갱신한 뒤 `cargo fmt --all` 및 `cargo fmt --all -- --check`가 exit 0으로 완료됐다. Studio 작업 디렉터리의 로컬 TypeScript compiler `./node_modules/.bin/tsc --noEmit`도 exit 0이다. 처음 루트에서 실행한 fmt는 오래된 파생 참조 때문에 실패했고, 루트 `npx tsc`는 프로젝트 compiler를 찾지 못했다. 이 실패를 통과로 보고하지 않으며 올바른 준비·작업 디렉터리로 재실행한 결과를 구분한다. 파생 inventory는 커밋하지 않는다. Native/fresh WASM 실행 검증과 전체 lint는 아직 전이다.
