# #7642 Stage 182 — 정렬·빈 칸·조합·긴 나눗셈의 공통 결과 보정

Issue: #7642

## 독립 관측과 범위

현재 코드/base는 `b2568a0b1c91533724e4d09ee10cebfc8aeea4bc` / `552f5228d2dbfd6046c838f14241704f1bcb8a05`다. 직전 수식 엔진 tree 내용은 rebase 전후 동일하다. 원 카탈로그의 5·6·13·14·16·17·18쪽 미달을 다음 원인별로 분석한다.

- 카탈로그 14쪽 EQALIGN의 등호 원점은 Print에서 첫 여덟 행과 마지막 두 행이 다르다. 현재 최대 왼쪽 폭으로 모든 행을 이동하는 경로를, 폭이 다른 독립 행 대조군과 비교한다. 모든 구조를 일괄 왼쪽 정렬한다고 가정하지 않는다.
- 빈 행렬 칸은 parser에 남아 있으나 layout의 Empty 폭은 0이다. 한컴 저장 프레임은 빈 칸/빈 템플릿에 논리 슬롯을 예약한다. 일반 비어 있는 수식과 명시적 빈 행/칸을 구분하고 괄호 유무·후행 구분자·가변 행 길이를 검증한다.
- `n CHOOSE k`는 Print에서 n/k 모두 조합의 본체다. 현재 CHOOSE는 앞 항을 소비하지 않아 n을 밖에 두며 LONGDIV는 실제 긴 나눗셈 대신 ÷와 = 문자열을 만든다. 같은 원문에서 피연산자의 소속·보존과 선·괄호의 실제 출력까지 확인한다. 공개 호환 파서 계약과 문서 파서의 수정 경로를 구분한다.
- `COLOR red x`는 Print에서 red 문자열을 표시하지 않는다. 이름/숫자 RGB/그룹/불완전 입력을 정상 저장·Print로 비교한 뒤 소비 문법을 정한다.
- 인자 없는 MATRIX/PILE/EQALIGN 등은 Empty AST이고 저장 크기가 1×1, 음수 baseline인 정상 저장 진단이 있다. 표시 없는 수식의 크기와 호스트의 유효한 빈 줄 점유를 구분한다. 캐시 값을 clamp하거나 내용을 숨기지 않고, 실제 semantic Empty와 명시적 빈 템플릿의 점유 계약을 확인한다.

## 소비 경로와 검증

`문서 토큰 → 피연산자/행·칸 소유 AST → EqLayout 공통 자식 원점·논리 슬롯·윤곽 → flow_metrics/줄 composition → 측정·pagination → 최종 EquationNode → SVG/Canvas`를 추적한다. LONGDIV 윤곽은 측정 단계에서 일반 선·괄호와 같은 결과로 발행하며 backend가 별도로 배치를 추측하지 않게 한다.

독립 Print의 폭 차이/빈 칸/인자 누락과 CHOOSE·LONGDIV·COLOR를 함께 대조군으로 산출한 뒤 필요한 변경을 묶어 수행한다. parser/source 사전 검사는 공용 target/pr-review를 사용한다. 한 번의 Native 빌드 뒤 진단 전체와 원 카탈로그 전체를 비교하고 같은 source의 fresh WASM을 산출한다. 원 카탈로그 미달을 대조군 점수로 대신하지 않는다. 새 관계형 회귀는 전체 관련 Native/fresh WASM 90%·확대 판독 뒤 새로운 이름으로 추가하며 기존 golden·허용치를 먼저 바꾸지 않는다. 전체 55개 문서·전체 회귀·lint·PR/CI/후속 목표는 계속 미완료다.

## 적용 내용과 현재 검증

- 독립 한컴 2020 Print 30쪽은 `pdf/issue7642-structural-command-diagnostic/`에 원본 HWPX·정상 저장 HWP·PDF와 함께 보존한다. 버전 11.0.0.9136, PrintMethod=0이며 자세한 해시는 해당 README에 있다.
- 글자·분수·역순 EQALIGN 대조로 행별 왼쪽 원점 계약을 확인했다. 한컴 face 경로는 각 행의 폭으로 오른쪽을 전진시키며 일반 호환 layout의 전역 정렬은 유지한다.
- 명시적 빈 행렬 칸과 빈 템플릿은 반 em 슬롯을 예약한다. MATRIX/EQALIGN의 누락 인자는 정상 저장 프레임에 맞는 빈 템플릿 AST로 남긴다. PILE 누락 인자의 표시 없는 AST·범위 밖 기준선 캐시는 개체 높이로 강제 보정하지 않고 기존 호스트 빈 줄을 유지한다.
- 중위 CHOOSE는 앞·뒤 항을 모두 소유한다. LONGDIV는 세 항을 소유하는 AST와 공통 행/괘선 layout을 만든다. 일반 곡선의 상세 모양은 실제 확대 대조 전까지 미검증이다.
- COLOR 이름/미지원 인자는 소비하되 표시하지 않는다. 숫자 RGB는 색 범위 layout으로 전달하며 SVG·Canvas·paint JSON·CanvasKit 및 글자 프레임 분석이 같은 본체를 소비한다. 본체 크기를 색과 무관하게 보존한다.
- 첫 `cargo check --locked --lib --target-dir /home/tsjang/rhwp/target/pr-review`는 통과했다. 색 범위 추가 뒤 전체 tests 사전 컴파일에서 paint JSON·CanvasKit 정책의 누락 match가 검출되어 보완했다. 해당 실패는 실제 문서 시각 회귀 판정과 구분한다. 기존 golden의 직렬화 arm만 보완하며 기대값/허용치를 갱신하지 않았다.

Native/fresh WASM 시각 검증, 새 관계 회귀와 전체 회귀/lint는 미완료다. 이 단계의 구현 결과만으로 통과를 선언하지 않는다.

전체 `cargo check --locked --profile release-test --tests --target-dir /home/tsjang/rhwp/target/pr-review` 재실행과 Studio `npx tsc --noEmit`는 각각 exit 0이다. 이 확인 뒤 색 포장의 정체/이탤릭 프레임 전달과 LONGDIV의 독립 저장 기준선(행렬 올림과 구별)을 추가 대조해 반영했다. 다음 Native 빌드와 시각 확인에서 이 최종 소스를 검증한다. 전체 테스트 실행·lint 통과를 의미하지 않는다.
