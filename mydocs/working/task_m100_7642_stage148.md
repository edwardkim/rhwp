# #7642 Stage 148 — 재정렬 셀의 저장 높이·줄 수 수용과 기본 괘선

Issue: #7642

## 독립 근거와 구현

source `fe5ad4db922e03f38665a6c1fb7ba34627e13596`의 영월 원본은 Native/fresh WASM
전체 4쪽이 90% 이상이었으나, 3쪽 마지막 셀의 “누계”가 셀 하단을 넘어 잘렸다.
원본은 한 줄 캐시, 한컴 2020 정상 저장본은 같은 CENTER 셀의 두 줄을 기록했다.
독립 Print에서도 두 줄이 같은 셀 안에 있다. 정상 저장본으로 원본 통과를 대신하지 않는다.

- `recompose_horizontal_cell_lines_for_width`가 만든 실제 두 줄 높이를
  `trust_stored_cell_flow`가 작은 저장 extent로 덮어쓰고 있었다. 재정렬 요청에서는
  저장 셀 흐름과 inline/그림 프레임을 수용하지 않아 실제 높이가 세로 정렬에 사용된다.
- `shrunk_cell_horizontal_padding`에도 같은 `StoredGeometryPolicy`를 전달했다.
  재정렬로 무효해진 저장 한 줄을 여백 축소의 증거로 사용하지 않는다.
- 한컴 정상 저장본의 기본 얇은 실선·점선 두께는 0.12mm이며, Print 실선은 0.36pt다.
  HWP3의 기본 얇은 선 종류 매핑을 이에 맞췄다. 원본 서식·여백·줄 정보는 보존하고,
  문서 ID나 화면 좌표 조건을 추가하지 않았다. 재정렬 요청 없는 저장 경로는 유지한다.

공용 `target/pr-review`에서 release-test Native 빌드가 exit 0으로 완료됐다.
입력 source 해시가 빌드·검증 전후 동일했다. `cargo fmt --all -- --check`와
`git diff --check`도 통과했다. 실행 명령과 원본/PDF 해시는 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/` 아래
`stage148-native-realign-build.json`과 `stage148-realign-preflight/receipt.json`에 있다.

이 진단은 정식 회귀 테스트 추가를 대신하지 않는다.

## 공간 정리와 남은 범위

종료된 Stage 141/147 WASM 검증의 중간 SVG 498개만 정리해 약 14.2GiB를 확보했다.
입력·Print PDF·PNG·TSV·로그·JSON과 최신 Native SVG는 보존했다.
명시적인 삭제 경로·크기·종료 상태는 `stage148-svg-cleanup.json`에 있다.

Stage 147 sample16 전체 64쪽은 Native/fresh WASM 모두 최저 27.23722%, 미달 17쪽이다.
양쪽 64쪽 PNG의 SHA-256과 페이지별 지표가 모두 동일함을 추가 확인했다. 독립 Print와의
차이는 여전히 미충족이다. 6쪽 제목 등 페이지 배정과 실제 배치가 갈리는 원점을 추적한다.
부동소수점 합산 순서로 forward 비교가 바뀌는 분석 결과는 실행 중 내부 값 전체 계측과
구분해 보존했다. 전체 55문서·853쪽, 실패 회귀 보정, 최신 전체 nextest와 PR 절차는 남아 있다.
