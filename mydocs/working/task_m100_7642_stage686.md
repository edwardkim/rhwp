# Issue #7642 단계 686: 열린 SPEAR 윤곽과 source-unit 정책 보정

- source01c의 stage679는 fmt·Native/WASM/workspace Clippy·workspace build·HWP3 parser 6건·출처/암호/OLE/#7092 집중 검사를 통과했다. #1880/#1892 왕복 검사는 여전히 각각 실패했다.
- 최종 source-unit 정책은 새 `cfg(test)` import를 금지해 exit 1이었다. 기존 검사에서 작은 mapper의 helper를 직접 참조하도록 바꿔 새 support 선언을 제거했다. 보정 후 base SHA를 지정한 단독 정책 검사는 통과했다(4101 tests, cfg support 28). 최종 lint 묶음에서 다시 확인하며 전체 통과로 보고하지 않는다.
- 이에 따라 stage680/681/682와 글꼴 추적 후보 진단은 실제 렌더링/빌드 전에 선행 검사 실패로 종료됐다. 실패 receipt를 보존하고 새 source로 재실행한다. 기존 최저 일치율을 이번 보정의 결과로 사용하지 않는다.
- 독립 한컴 HWPX 저장본의 `SPEAR`와 Print의 선형 화살촉을 대조했다. 공통 선 속성 2는 parser에서 구분했지만 LineStyle은 채운 Arrow로 근사했고 공통 arrow helper는 윤곽을 닫았다.
- `OpenArrow`를 별도 스타일로 보존해 두 사선의 끝점과 방향을 유지한다. 바닥 선과 면 채움을 추가하지 않는다. 기존 채운 Arrow의 크기·윤곽은 유지한다.
- SVG·WebCanvas·Skia 및 CanvasKit replay는 기존 공통 arrow producer의 열린 path/filled=false를 소비한다. JSON 스타일 이름과 replay decoder도 같은 새 스타일을 지원한다. 획 두께·선 끝점·원본 크기 코드는 바꾸지 않았다.
- 수정 후 Native/fresh WASM 및 확대 판독, 해당 입력 전쪽 90%와 전체 회귀는 아직 미검증이다. 새 렌더링 회귀 또는 baseline은 추가/갱신하지 않았다.
