# #7642 Stage 145 — 탭 정렬 원점과 글꼴 해석 분리

Issue: #7642

## 구현 전 근거

시작 head는 `373d35be56dba0a1cef0082a88ce0104271ba15f`다. 원본
`issue1892_hwp3_tab_roundtrip.hwp`의 Native 1쪽은 93.91816%지만 확대 위치·원형 글리프
차이가 남았다. Native/fresh WASM 완료나 새 회귀 추가의 근거로 사용하지 않는다.

오른쪽 정렬 문단 7/8/9의 자연 폭은 저장 폭이 없는 탭을 원본 기본 정지에서 해소해
측정한다. `estimate_line_run_widths`의 `est_x`가 그 자연 원점이다. 이후 `x_start`는
오른쪽 정렬 이동을 더하지만 `emit_line_runs`는 `line_x_offset = x - col_area.x`에서
기본 정지를 다시 찾는다. 줄 전체 이동을 탭 간격의 변경으로 소비하는 두 번째 계산이다.
독립 Print의 `귀하` 시작은 653.406이며 현재 출력은 646.7이다. 이 값은 같은 물리
단위로 바꾼 진단 관측이며 절대 px 회귀 기대값으로 사용하지 않는다.

하단 `(인)`의 문단 24는 가운데 정렬이다. 앞 공백의 전진·글꼴 해석·
탭의 저장값을 별도로 대조한다. 문서 ID·문단 번호·픽셀 이동으로 출력을 맞추지 않는다.

## 독립 저장본과 원본의 구분

한컴이 원본을 정상 저장한 HWPX의 진단 Native 일치율은 99.38233%다. `귀하`와
`(인)` 위치는 더 대응하지만 원형 글리프 차이는 여전히 남았다. 원본 HWP의 시각 일치율로
대체하지 않는다. 한컴 저장본의 HFT와 RHWP 진단 저장본의 TTF 표기를 확인했지만,
유형만으로 글리프의 실제 모양까지 해결된다고 판정하지 않는다.

원본 RHWP 진단 저장본과 글꼴 유형만 바꾼 별도 입력을 같은 Native·Print로 대조한다.
원본 파일은 유지하고 변형값·생성 절차·입력 해시를 ignored output에 기록한다.
한컴의 정상 저장 과정에서 바뀐 여러 속성을 한 번에 원본 해석의 정답으로 역수입하지 않는다.

글꼴 유형만 TTF에서 HFT로 바꾼 진단 입력은 원본 RHWP 저장본과 같은 RenderTree
위치·폭을 냈다. 글꼴 유형을 탭 위치 차이의 원인으로 판정하지 않는다. 이 진단은 원본
입력이나 공식 대조군을 변경하지 않았으며 ignored output에만 남겼다.

## 외부 생성 문서의 재정렬 요청

[한컴 HWP3 공식 사양](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D3.0_HWPML_revision1.2.pdf)의
3.2절 표 3, 문서 정보 offset 28의 bit 0은 외부 생성 문서의 재정렬 요청이다.
원본 탭 문서와 영월 서식, 셀 순서 대조군은 이 비트가 켜져 있고 격자 간격 대조군은
꺼져 있다. 표 39의 인라인 탭 값은 전진폭이며 절대 정지 위치로 재해석하지 않는다.
한컴 정상 저장에서 달라진 폭은 재정렬된 결과로 구분한다.

파서가 읽고 버리던 요청을 별도 CFB/HWPX 출처 마커로 보존하고
`Document::layout_profile`의 재정렬 속성으로 전달한다. 원시 탭 폭·순번·점끌기를 유지하되
자연 줄 측정과 실제 배치에서 이 요청이 있는 저장 폭 캐시를 수용하지 않는다.
기본/왼쪽 탭의 최종 원점은 자연 줄 원점에 정렬 이동을 더하고, 오른쪽/가운데 탭의
단 기준 앵커는 유지한다. HWPX에서 HWP로 저장할 때도 마커를 전달한다.

같은 속성은 `legacy_hwp3_stored_geometry`의 수용 여부에 전달되어 셀·문단의 공통 줄
구성 계산에 영향을 준다. 플래그가 없는 원본에는 기존 저장 기하 계약을 유지한다.
플래그가 있는 원본의 실제 출력과 없는 대조군을 먼저 비교하며, 이 속성만으로 모든 저장
LineSeg를 무효화하거나 재정렬 완료를 선언하지 않는다.

## 보정 계약과 반례

탭을 해소한 자연 줄 배치와 그 뒤의 정렬 이동을 구분하고, 최종 폭·글자 경계·paint가
그 같은 결과 또는 원점을 소비하도록 연결한다. 기본/왼쪽 정지, 명시적 오른쪽·가운데 정지,
저장 전진폭, 폭 없는 자리표, run 경계·앞뒤 탭 순번을 대조한다. 오른쪽·가운데 정지는
단의 끝에 맞추는 계약이 있으므로 줄 정렬 이동을 기계적으로 빼지 않는다.

같은 원본·독립 Print의 Native/fresh WASM 90% 이상과 확대 판독 뒤 새 이름의 관계형
회귀를 추가한다. 현재 실패한 원본 48건의 분석·보정도 같은 branch에서 계속한다.
이번 진단의 통과를 최종 전체 회귀·전체 페이지 TSV·PR 준비 완료로 보고하지 않는다.

## 보정 후 Native 결과

빌드 exit 0, source 1,505개 파일의 빌드 전후 해시 일치를 확인했다. 새 helper도 해시
수집에 포함했다. fmt/check, diff check, Native Clippy `-D warnings`는 실제 exit 0이다.
fresh WASM 및 나머지 lint·최신 전체 회귀는 아직 실행하지 않았다.

전 9쪽을 비교했고 쪽수는 모두 Print와 같다. 탭 원본은 이전 93.91816%에서 개선됐고
새 review/overlay를 직접 열었다. 자연 줄과 정렬 뒤 탭 원점을 분리해 `귀하` 및 `(인)`
위치가 한컴 정상 저장 진단과 대응하게 됐다. 원형 글리프는 여전히 Print보다 크게 보이며
이를 점수 통과로 면제하지 않는다. [새 Native 증거](../pr/assets/issue7642-realign-tab-20261012/README.md)를
보존했다.

HWP3 원본 → RHWP HWPX → HWP 저장과 각 저장본의 RenderTree 재읽기는 모두 exit 0이다.
HWPX의 마커 바이트 `1`과 HWP의 해당 CFB 스트림 이름을 확인했고, 위 탭 문단들의
내용·상자 위치·폭을 원장에 연결했다. 이 진단은 파일 전체 무손실·독립 Print 재출력이나
정식 회귀 검사와 구분한다. `stage145-storage-consumer-diagnostic.json`과
`stage145-tab-roundtrip-geometry.json`에 명령·실제 결과를 남겼다.

영월 원본은 재정렬 요청 보존만으로 해결되지 않았다. 새 2쪽 PNG에서 제2호 서식 표제가
원본 출력의 이전 쪽에 있고, 제3호 표제가 2쪽 하단에 남는 것을 확인했다. 표 시작과 선 두께,
일부 셀 줄바꿈 차이도 남았다. 한컴이 정상 저장한 별도 HWPX의 전4쪽 진단 최저값은
99.29419%이며 실제 exit 0이다. 이를 원본 HWP의 통과로 바꾸어 보고하지 않는다.
양쪽 용지·표 선언 크기는 대응하지만 문단의 저장 vpos·셀 여백·테두리 속성의 소비 차이가
남는다. `stage145-yeongwol-paragraph-boundary-comparison.json`과
`stage145-yeongwol-table-geometry-comparison.json`에서 확인하며 다음 보정 범위로 이어 간다.

명시적 오른쪽/가운데 탭과 기본 탭이 섞인 줄의 적용 경계, 변경 영역의 fresh WASM,
영월 및 나머지 기존 48개 실패의 보정·전체 검증은 미완료다. 새 렌더링 회귀·golden을
추가하거나 변경하지 않았다. PR 생성·승인·merge를 보류한 채 현재 목표를 계속 진행한다.
