## v1 미수용과 기존 각주 영역 소비

진입 조건만 복구한 v1은 Native 51쪽으로 독립 50쪽과 불일치해 미수용했다.
요청한 PDF 대응 50쪽 TSV는 진단일 뿐 Native 51쪽 전체 수용 근거가 아니다.
기존 검사는 실제 51 대 50으로 실패했고 기대값을 바꾸지 않았다.
진단 driver의 capture lock 상위 경로를 한 단계 잘못 적은 오류는 기존 Native 빌드·검사를
보존한 채 캡처만 올바른 공용 lock으로 이어 실행해 정정했다. Cargo 중복 실행은 없었다.

같은 통합 커밋에서 진입 조건과 함께 삭제한 `BodyFootnoteMeasure::stored_current_area_height`
소비도 확인했다. 본문의 빈 줄과 큐 각주 배출에는 같은 측정이 남아 있지만 표 큐의 진입은
현재 쪽의 실제 저장 각주 상자 대신 추정 높이와 안전 여백을 다시 예약했다.
v2는 이미 이 쪽이 소유한 저장 각주만 공통 paint 상자로 조회·예약하고, 그 상자에 안전 여백을
다시 더하지 않는다. 유효 저장 줄이 없어 조회가 거절되면 기존 추정·안전 여백을 유지한다.
다음 표 각주의 소유와 현재 각주 영역의 공간을 구분하며 새 픽셀 예외를 추가하지 않았다.

## v2의 남은 물리 행 결손과 v3 공통 결과

v2는 50쪽을 복구하고 49쪽은 raw 90%를 넘었지만, 38쪽은 51.85214%였다.
기존 검사의 Center 관계도 실패했다. 원본의 병합 칸 높이 6906HU는 일반 행 3개의
각 2302HU와 정확히 닫힌다. 이어받기에서 앞 행을 소비한 뒤에도 남은 일반 행 2개는
각각 2302HU의 독립 공간을 소유한다. v2는 그 공간을 내용 높이 17.093333px로 줄여
원본 30.693333px 대신 사용했고, 병합 꼬리도 Top 정렬했다.

v3의 `stored_complete_block_row_minimum`은 유효 저장 줄·완전한 일반 칸·독립 선언 높이·
병합 선언 높이를 닫는 원본 행 사슬을 함께 확인한다. 내용 컷이 끝나지 않았거나 그 일반 칸이
이미 소비됐으면 적용하지 않는다. 이 결과를 `row_block_cut_physical_height`에서 스캔과
실제 행 배치가 함께 소비한다. `table_partial`은 같은 결과로 실제 양수 높이의 행 공간을
확인한 뒤, 완결된 병합 꼬리의 Center/Bottom 정렬 공간을 인정한다. 소비한 0 높이 행이나
선 접기로 바뀐 상자를 정렬 공간으로 재인증하지 않는다. 문서·쪽 ID와 고정 이동값은 없다.
