# Issue #7642 단계 810: 확대 판독에서 확인한 그림 글머리표

## 직전 후보 검증

단계 807에서 `cd8af1ee3`의 Native shader 후보를 빌드하고 합성 도형의 색상 스톱 검사 1건을 통과했다. 이미지 채우기 1쪽 Native는 **99.35804%**, 6쪽은 **98.80080%**였다. HWPML 36쪽은 99.93492%, 45쪽은 99.95017%였으며 3·37·38·57·68쪽은 여전히 미달이다. 선택 쪽 진단을 전쪽 완료로 대신하지 않는다. 새 shader의 검출력은 단계 809에서 이전 구현 `e66ce9c54`에 두 끝 색상 검사만 적용해 별도로 확인한다.

## 직접 판독과 독립 근거

HWPML 36쪽의 높은 점수에도 글머리표가 달랐다. 원본 5번째 Bullet 레코드의 문자 값은 `●`이지만 그림 ID는 1이고, 원본 `BinData/BIN0001.png`를 직접 꺼내 확인한 내용은 60×60 파란 책 그림이다. Native는 이를 검은 원 문자로 그렸다. Print PDF도 파란 책 그림을 포함한다. 추출한 그림과 진단은 ignored output에만 두며 수용 원본은 기존 커밋 HWP와 독립 Print PDF다.

[한컴 HWP 5.0 공식 사양](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)의 글머리표 정의도 문자와 그림 참조를 구분한다. 원본 레코드·BinData·독립 출력과 모델 값의 대응을 확인했으며 이번 수정에서 문서 ID나 그림의 관측 픽셀 위치를 사용하지 않는다.

## 생산과 배치의 공유

문단 머리의 그림 ID가 있으면 기존 비 ASCII 마커와 같은 1em 칸·원본 본문 거리를 유지한다. 실제 표시만 원본 BinData의 ImageNode로 발행해 Native·WASM·SVG의 공통 이미지 경로가 소비한다. 문단·셀 소속을 보존하고 존재하지 않는 그림 컨트롤 번호를 생성하지 않는다. 문자 마커와 그림 자료를 얻지 못한 경우의 기존 폴백은 유지한다. 그림 마커의 크기는 같은 마커 글자 모양의 em으로 산출하며 고정 px 크기로 정하지 않는다.

## 남은 검증

그림 글머리표 변경은 아직 컴파일·시각 검증 전이다. 알려진 미달 쪽과 같은 원본 전체 페이지를 새 후보에서 확인하고, 작은 마커 모양·색상 차이도 점수와 별도로 판독한다. 90% 선행 조건을 충족하지 않은 원본에 새 실물 회귀나 golden을 추가하지 않는다. 전체 회귀·lint·기준 대비 하락 비교와 PR 직전 헤드 확인 이후 코드 PR·CI를 진행하고, 옵션 2의 별도 review·오늘할일 PR과 머지 후속 처리로 이어간다.
