# 열린 이슈 재검증 3단계: 글상자 안 표의 인라인 그림

이 문서는 제한된 코드 보정과 focused 계약 검증 단계의 완료 보고다. #6699 전체 해결,
시각 동치 또는 PR 제출 준비 완료를 뜻하지 않는다.

## 범위와 출발점

- Issue: #6699. 직전 단계 #6714 수정은 `ed60ee1a7`에 고정했다.
- `samples/table-in-tbox.hwp`와 기존 `pdf/table-in-tbox-hwp-2020.pdf`를 사용한다.
  원본은 한컴 2018 저장 메타데이터이므로 현행 지침의 2020 bucket이다. 초기 비교에 사용한
  `table-in-tbox-2022.pdf`와 글리프·그림 좌표는 같지만 PDF hash는 다르다.
- 작성자의 정정 코멘트를 모두 읽었다. 표 전체 이동, 그림만 가운데 정렬, 단순 폭 두 배 가설을
  확정된 원인으로 취급하지 않는다. 실제 줄 시작점과 TAC 전진을 각각 확인한다.
- 현재 큰 로고 x는 215.6px, 기준은 약 259.5px이며 같은 줄 글자의 방향도 함께 검사한다.

## 조사와 수정 계획

1. 글상자 안 문단의 원본 정렬, 여백, 문자 오프셋, 줄 구간, 그림 속성을 공개 IR API로 읽는다.
2. `layout_embedded_table`은 문단 레이아웃에 `bin_data_content=None`을 넘기고 뒤의 수동 루프에서
   `pic_x=inner_x`로 그림을 생성한다. 인라인 배치가 계산한 줄 위치를 사용할 수 없는지 확인한다.
3. 텍스트·그림을 같은 줄에서 한 번 배치하고 등록 키도 같은 셀 경로를 쓰게 한다.
   raw 속성과 셀 폭은 근거 없이 변경하지 않는다.
4. 실물 문서 두 쪽에서 대상 5개 그림과 텍스트를 검사하고, 외부 글상자 아이콘 및 기존
   #5727·중첩 셀 hit-test/crop 계약을 대조한다. 합성 계약으로 중복 그림과 인라인 순서를 고정한다.
5. 새 시각 sweep과 현행 기준 비교를 완료한 뒤 수용 판단한다. 전체 검증은 최종 후보에서 수행한다.

## 확인한 결함과 보정

- 내장 표가 `bin_data_content=None`을 넘겨 문단의 인라인 그림 배치를 우회했다.
  뒤의 수동 루프는 그림을 셀 왼쪽에 놓았다. 바이너리 자료를 문단 배치에 전달하고 기존 등록 키로
  후속 중복 생성을 막는다. 셀 전체 경로와 crop/effect 정보는 유지한다.
- 글상자의 TAC 표 분기는 표 앞 문자를 전진하지 않고 표를 독립 정렬했다. 기존 문자 커서를
  사용하고 표 왼쪽 바깥 여백을 적용한다. 표 뒤 커서도 표 폭과 좌우 바깥 여백만큼 전진한다.
- 배선을 연결한 첫 후보는 좌표 테스트 13개를 통과했지만, 2쪽 로고 3개가 분홍 배경 뒤에 가려졌다.
  그림의 원본 `BehindText`가 인라인 배치에서도 별도 배경 plane으로 적용된 것이 원인이다.
  원본 모델은 바꾸지 않고 TAC 그림의 render node만 flow로 분류한다.
- 표 폭을 인라인 정렬 계산에 넣자 그림 사이 공백 분배 규칙까지 새로 활성화됐다. 왼쪽 정렬
  변형에서 x=347.104px로 밀리는 실패를 확인했다. TAC 표 앞 공백은 이 분배에서 제외한다.
- 첫 후보는 정렬 폭에서 표 바깥 여백을 빼고 실제 배치에서는 더해, 가운데 정렬 표와 글자를
  약 1.9px 함께 이동시켰다. 그림만 보면 큰 로고가 기준 1px 안에 들어오지만 표 테두리가
  틀어지므로 수용 근거가 아니다. 좌우 바깥 여백을 정렬 폭과 커서 전진에 모두 포함한다.
- 기준 PDF의 큰 로고 뒤 글줄 bbox 시작에는 원본 공백이 포함돼 있다. 첫 한글 글리프는
  x=334.59px이며 공백을 뺀 x=318.7px를 한글 시작점으로 해석하지 않는다. 원래 rhwp 한글
  시작 x=333.33px와 공백 간격 15.97px를 유지하고, 남은 메트릭 차이를 표 이동으로 가리지 않는다.
