# 자리차지 개체와 같은 호스트의 TAC 줄 순서 보정

## 독립 근거와 현재 결함

#6133의 원 해결 PR #6169와 #2813의 원 해결 PR #3270을 대조했다. 실제 원본과
축약 입력을 구분한다. Native098의 #6133 실제 원본은 독립 한컴 2020 Print와
4/4쪽, 최저 raw 98.52373%다. 공개 축약 입력은 2/2쪽이지만 raw 0%다.
한컴은 제목을 1쪽, 대체 그림을 2쪽에 놓고 후보는 두 개체의 쪽을 반대로 소유한다.

축약 입력은 한 저장 줄에 그림과 TAC 제목 표를 가진다. 저장 줄 높이는 2831HU,
그림의 문단 기준 세로 오프셋은 3518HU다. 그림은 제목 줄을 침범하지 않지만,
그림 높이를 먼저 흐름에 반영하면 TAC 표가 다음 쪽으로 밀린다. 옛 회귀의
83.1px는 실제 원본 4쪽 좌표이며 축약 입력의 본문 원점과 다르므로 그대로 갱신하지 않는다.

## 생산 결과와 소비 경로

## 공통 규칙과 구현 범위

빈 호스트의 문단 기준 TopAndBottom 개체는 종류에 관계없이 같은 세로 오프셋과

## Native103: 셀 내부 쪽 경계의 최종 수용 보정

### 규칙과 소비 경로

미편집 HWP5 RowBreak 셀의 같은 원본 문단에서 양수 vpos 뒤 0으로 돌아가는
경계는 같은 셀 유닛의 `hard_break_before`·`page_frame_reset_before`가 함께
증언할 때 물리 쪽 나눔으로 소비한다. 서로 다른 문단의 지역 원점 0,
합성 줄, dirty 문단·셀, 재조판 표, TAC와 직접 HWPX는 새 판정의 대상이 아니다.
기존 두 줄 저장 프레임 판정은 유지하고 일반 문단 내부 경계를 함께 조회한다.

## Native110 보정 전: 첫 물리 상자의 최종 소비

`logs/issue8060-native109-row-tail-diag-1648.log`에서 19쪽 부모 첫 조각의
잔여는 일반 fallback의 `DIAG_5714`가 만든 값으로 확인했다.

넘긴다. 이 첫 띠에는 독립 저장 상자의 빈 공간이 있으므로 논리 내용의
소비량으로 빼면 안 된다. 다음 조각의 실제 내용은 61.73333px다.

`stored_nested_parent_opening_frame`이 실제 자식 컷·원본 첫 표 상자·
이미 수용한 완전 행으로 부모의 첫 높이와 마지막 행 높이를 함께 발행한다.
첫 조각 예약, emit의 정확한 수용 확인, 최종 paint의 원본 프레임 소유가
같은 결과를 사용한다. 최종 paint는 이 상자를 `fold_last_row`로 다시
줄이지 않으며, 셀 정렬 소유는 바꾸지 않는다. emit도 같은 상자를 수용한
경우 일반 원본 행 최소 차감 fallback을 적용하지 않는다.
다중 프레임의 독립 최소 원장과 다른 컷·편집 경로는 기존 조건을 유지한다.

## 혼합 자식의 첫 원본 프레임: 구현 전 계약

실제 7쪽의 부모 컷 `(0, 16)`은 앞의 가시 글줄과 자식의 첫 컷 `(0, 7)`을
소유한다. 자식의 마지막 저장 줄 끝 10,600 + 안 여백 282 = 선언 높이

이 원본 닫힘을 인증한 경우에만 부모의 첫 물리 상자에서 원래 세로 정렬을
보존한다. 임의 예산 컷·로컬 원점·편집/재조판·자식의 완전 종료를 같은
계약으로 승격하지 않는다. 부모 앞 행과 이 행의 선언 높이도 첫 개체 상자를
닫아야 하며 다른 저장 분할 방식의 기존 소유는 유지한다.

`ParagraphFloatPlacement::from_stored_host`가 발행하는 상대 배치 상자를
선택 내용의 점유 높이와 실제 자식 원점에서 함께 사용한다. 호스트 마지막
저장 줄의 위에서 자식 offset·바깥 여백·실제 첫 상자를 계산한다. 줄 뒤
간격을 자식 상자 앞에 별도로 재합산하지 않는다. 저장 셀의 물리 높이와
컷·유닛 소비 순서는 바꾸지 않으며, 흐름 전진과 선택한 내용의 점유 끝을
