# Stage 103 — 장식 바깥 위첨자와 실제 줄·쪽 점유

Issue: #7642. 이전 구현 source는 `e362940b413bfdbc17ab4f5d1812efc7cc99dcee`다.
55원본/853쪽과 292개 원본 회귀·#1139 전체 관계형 전환 목표를 유지한다.
HML 수식 제외와 현재 branch의 실패를 제거하지 않고 보정하는 사용자 지시를 유지한다.

## 독립 근거와 원인 추적

같은 원본 장식 본체 32개 Print에서 바깥 위첨자만 90% 미만이고 Native 2쪽/
Print 1쪽 차이가 있다. 이 차이는 수정 전에도 있었지만 현재 branch에서 보정한다.
31개 첫 Native 쪽의 실제 구문/소유와 글자 크기에 따른 여유로 진단했으며,
두 번째 쪽의 22pt 입력을 첫 PDF 쪽과 대응한 정상 점수로 보고하지 않았다.

`vec {OP}^2`의 독립 폭은 9/11/16/22pt에서 1800/2220/3330/4530HU다.
각각 장식 base 폭 + 독립 숫자 전진 + 0.15em 대문자 뒤 여유와 대응한다.
현재 `ends_with_uppercase_letter`는 장식 안의 끝 글자를 소비하지 않으며,
`superscript_shift`의 font-line 계약도 장식 base를 받지 않아 공개 MATH 기본
shift로 돌아간다. 기대값을 현재 구현에서 역산하지 않고 독립 Print의 base/sup
문자 원점, 저장 프레임, 실제 paint 원점과 대조한다.

쪽수는 저장 LineSeg의 줄 높이/간격·점유와 실제 paragraph/page 예산을 추적한다.
원본 정상 저장의 정보부터 대조하고 Synthetic 입력이라는 이유로 정상 판정을
면제하지 않는다. 큰 예약 높이에 자식을 숨기거나 좌표 clamp로 통과시키지 않는다.
공통 화살촉의 connector 굵기도 같은 확대에서 확인한다. 공개 부품의 가는 stem과
공통 shaft가 직접 판독에서 끊겨 보이면 출력 기하를 보정한다.

## 구현한 원인 보정 — 검증 전

- 윗줄·벡터·양방향 화살표는 본체 끝 대문자를 보존하므로 위첨자의 0.15em 여백 판단이 장식 본체를 재귀적으로 읽도록 했다. 명시 공백·닫는 구분자는 기존 판정을 유지한다.
- 벡터 바깥 위첨자의 일반 글줄 본체는 독립 프레임의 기준선 거리를 소비한다. 9/11/16/22pt Print의 본체·첨자 원점 차이는 각각 3.9571/4.7965/7.7943/10.0726pt다. 공개 MATH 기본 shift로 되돌아가던 조건을 보정했다.
- 정상 저장의 벡터 위첨자 높이·기준선은 1230HU/90%, 1538HU/89%, 2228HU/90%, 3023HU/90%다. 이를 크기별 독립 글꼴 프레임으로 보존하고 중첩 본체·prime·별도 첨자 크기는 같은 계약으로 접지 않는다. 다른 장식의 높이 표를 대신 쓰지 않는다.
- 소비 경로: `script_geometry::layout_superscript`의 자식 기준선·원점 → `logical_font_frame`의 벡터 위첨자 프레임 → `matrix_row_box`의 같은 기준선 상대 위치 → `layout_for_paint`의 저장 프레임 원점 → 각 backend. 측정과 paint의 공통 결과를 유지하며 출력 전체를 clamp하지 않는다.
- 위 결과는 코드 검토와 독립 메트릭 대조다. 새 source의 빌드·직접 Print 비교 전에는 시각 개선 완료로 판정하지 않는다. 렌더링 회귀 기대값·baseline은 변경하지 않았다.

쪽수 진단: 독립 저장의 마지막 줄은 vertpos 84430HU + 높이 3023HU = 87453HU이며 본문 가용 높이 87592HU 안에 들어간다. 마지막 spacing 660HU까지 다음 내용처럼 예약하면 88113HU로 넘어간다. 실제 pagination 소비 경로가 이 간격을 예약하는지 추가로 확인한다.

## 마지막 쪽 이월의 실제 실행 확인

보정 전 frozen source `e362940b413bfdbc17ab4f5d1812efc7cc99dcee`에서 `RHWP_DIAG_6031=1`로 같은 원본을 직접 실행했다. 로그는 `pi=32 cur=1125.7 fit_h=40.3 avail=1163.9 single=false`다. 실제 fit 높이는 3023HU에 대응하며 spacing 660HU를 포함하지 않는다. 앞 절의 후행 간격 예약 가설은 이 입력의 원인이 아니므로 철회한다.

`prepare_fit_budget → fit::layout_drift_safety_px`가 본문 1167.9px에서 4px를 차감한다. `whole_fit::inspect`는 단일 저장 줄의 물리 하단과 현재 흐름을 별도로 확인하지만, 활성 대상은 텍스트·TAC 그림/도형이고 TAC 수식은 누락되어 있다. 수식은 그림의 하단 spill 허용을 받으면 안 된다. 저장 경계와 실제 측정 줄 점유가 대응하는 수식 줄에 대해 물리 본문 하단을 확인하는 방향으로 보정하며, 저장 줄 없음·개체 크기 증가·다줄·강제 쪽 경계·본문 밖 하단은 제외한다. 전역 안전값을 줄이거나 특정 문서/쪽을 예외로 두지 않는다.

실행 명령·exit 0·2쪽 PNG·로그는 ignored `stage103-page-fit-before/receipt.json`과 `render.log`에 보존했다. 위첨자 묶음 source `d17d14084`의 순차 lint/build/진단을 먼저 완료해 같은 source 증적을 보존한 뒤 이 경계 보정의 전후를 대조한다.

## 실제 AST 경로 확인과 선행 가정 수정

Native source `d17d14084fd60ed54c6af6f7f89d85a8001317c8`의 비교에서 벡터 본체 문서 점수가 보정 전과 동일했다. 동일 라이브러리로 AST를 직접 조회하니 `vec { OP }^2`가 `Row[Decoration(Vec, OP), Superscript(Empty, 2)]`로 파싱되어 있었다. 앞 절의 배치 보정은 `{vec {OP}}^2`처럼 장식을 다시 묶은 표현식에는 도달하지만, 실제 실패 입력의 명령 뒤 첨자 경로에는 도달하지 않는다. 이 선행 가정을 수정한다.

`parse_command_fallback`의 장식 분기는 `finish_command_atom`을 거치지 않는다. 일반 명령은 이 공통 경로로 뒤 첨자를 연결하며 `attach_scripts=false`인 부모 첨자 슬롯에서는 결합을 유보한다. 장식도 같은 경로를 소비하도록 다음 묶음에서 보정한다. `vec {x^2}`의 내부 첨자와 `vec {x}^2`의 외부 첨자를 구분해 실제 AST와 Print를 대조한다. source `d17d14084`의 위치 보정만으로 실제 실패 입력이 개선됐다고 판정하지 않는다.

AST 실행 exit 0과 원문 결과는 ignored `stage103-decoration-ast-before.txt`에 남겼다. 이 확인은 파서/배치 경로의 증거이며 렌더링 회귀의 시각 선행 조건을 대신하지 않는다.
