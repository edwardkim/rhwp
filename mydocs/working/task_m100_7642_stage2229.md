# #7642 명시적 공간의 항 소유와 직접 논리 기호

## 독립 Print가 구분한 경계

`explicit-space-terms` 48식은 두 face·9/18pt를 사용한 로컬 XML 대조군이다.
한컴 2024의 정상 저장 HWP와 그 저장본의 6쪽 Print PDF를 함께 보존한다.
Save job은 `8c84a89e-2564-4f64-94c3-147a97750211`, Print job은
`7dc7db39-5e15-46ff-bff2-3ba4ffad1e26`이며 한컴 13.0.0.3901,
PrintMethod=0, `frame_print_to_pdf_ex_one_up`를 실제 응답에서 확인했다.
원본과 정상 저장본을 구분하며 파일이 존재하는 것을 시각 통과로 세지 않는다.

독립 PDF에서 `THEREFORE~q over p`는 ∴와 q의 기준선이 같다. `THEREFORE ~ q`,
`THEREFORE ~q`, `THEREFORE~ q`에서는 ∴가 분수 밖에 있다. 붙은 얇은 공백도
∴를 분수 밖에 둔다. `a~b over c`와 `a ~ b over c` 역시 같은 구분을 보인다.
선행 ~와 명시적으로 묶은 {q}/{p}는 각자 원래 경계를 보존한다. 정상 저장 속성과
PDF의 실제 글리프 원점은 stage2228에 기록했다. 전체 앞 항을 무조건 분자에
흡수하는 수정이나 분수 높이·배율·px 보정은 이 반례에 맞지 않는다.

## 소비 경로의 보정

기존 `has_term_continuation`은 일반 공백으로 분리되지 않은 ~도 무조건 항의
끝으로 처리했다. 붙은 normal ~만 현재 항의 Row 안에 보존하도록 바꿨다.
일반 공백·얇은 공간·행/칸 구분·명시적 그룹은 기존 경계를 유지하고 선행 공간도
현재의 단독 요소 경로를 유지한다. 문서 항 수집 경로에서만 적용되므로 공개
LaTeX 호환 파서의 항 결합 규칙은 바꾸지 않는다. Row의 소유를 OVER가 그대로
분자로 소비하게 하며 레이아웃이나 painter에서 별도 위치 보정을 추가하지 않았다.

직접 ∴·∵는 비 ASCII Text 수집에서 분리하고 명령형과 같은 MathSymbol로
전달한다. 이항/관계 연산자 목록에 넣지 않아 자동 여백을 추가하지 않는다.
기존 인용 문자열 경로는 기호 분류보다 먼저 실행되며 인접 문자·원본 위치와
명시적 공백을 보존한다. 이 변경을 문서별 예외나 저장 상자 크기로 제한하지 않았다.

## 검증 상태와 다음 단계

수정한 네 Rust 파일은 rustfmt와 diff 공백 검사를 마쳤다. 이 source의 실제
빌드·정식 회귀·Native/fresh WASM은 아직 실행 전이다. 원래 두 기호 대조군과
새 항 경계 대조군을 같은 원본/PDF로 다시 비교하며, 미달 입력을 다른 대조군의
통과로 바꿔 보고하지 않는다. 새 정식 회귀는 양쪽 전체 쪽 90%와 확대 판독 뒤
새 이름으로 추가한다. 기존 golden·px 핀을 먼저 갱신하지 않는다.

이전 source 15cb5e6f60의 fresh WASM 빌드와 전쪽 queue는 해당 source로 동결해
계속 검증한다. 렌더 runner는 실제 빌드에서 source 해시가 유지됐다는 receipt와
고정 binary/package 해시를 확인한다. 다음 보정 중인 main의 파일을 그 producer와
동일하다고 요구하거나 최신 source를 검증한 결과로 재표기하지 않는다.

이전 source의 대기 lint 프로세스는 exec session 50662에서 exit 143으로 종료됐고
실제 Cargo 자식·검사 로그는 없었다. 종료 원인을 추정하지 않았으며 통과로 세지
않는다. 별도 중단 기록을 보존하고 새 source에서 필수 lint를 수행한다. 전체 Rust의
기존 실패와 다른 페이지의 devel 하락도 아직 해소되지 않았다.
