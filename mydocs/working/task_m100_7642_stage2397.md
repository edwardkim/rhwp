# #7642 한양신명조 HFT의 고유 폭과 굵기 전진 보정 후보

Issue: #7642. 독립 Print 분석과 구현 후보이며 시각 검증 완료를 뜻하지 않는다.

## 독립 근거

한양신명조 HFT와 HY신명조 TTF를 12/20/28pt, 정체·굵게, 자간0/-5/+10으로
비교했다. 원본 속성을 가진 HWPX를 한컴에서 HWP로 정상 저장하고 그 HWP를
Print했다. 첫 20개 조합의 정상 저장 job은 `ab3423ce-a6d8-4b95-8f59-92c737b9c32e`,
Print job은 `d532cfab-4aba-400a-a355-3f53ec678840`이다. 같은2020 engine의
한 쪽씩 Print 경로를 확인했다.

숫자는 HFT 정체 약0.50em, 굵게 약0.55em으로 전진한다. TTF 대조군에는 같은
굵기 증가가 없다. 양수·음수 자간은 이 추가 전진과 함께 소비된다. 추가 표본은
ASCII95자와 한글 정체·굵게를 포함한26개 조합이다. 두 Type3 프로그램의
intrinsic ASCII95개 폭은 모두 같으며 숫자는500/1000em, 마침표는244/1000em이다.
한글 표본의 intrinsic 폭은1000/1000em이고 굵게의 실제 전진은 약1.05em이다.

MCP job·입력/PDF 해시·속성별 전진·Type3 폭 표는 ignored stage2386~2394의
receipt에 보존한다. PDF span의 글자 크기만으로 프로그램을 추정하지 않고 실제
Type3 /Widths와 위치를 함께 확인했다. 대조군은 아직 시각 선행 조건을 통과한
정식 회귀 fixture로 등록하지 않았다.

## 구현과 실제 소비 경로

원본 글꼴의 HFT 선언 → 해소된 슬롯의 검증된 HFT metric face → 같은 문자
측정 walk의 고유 폭·굵기 전진·장평·자간·장치 격자 → 실제 char positions →
각 backend의 glyph-fit 소비가 적용 경로다. TTF 선언 슬롯에는 이 표를 선택하지 않는다.

한양신명조 HFT의 고유 ASCII 표를 기존 신명 HFT 두 프로그램 뒤에 추가했다.
기존 항목의 순서는 유지한다. 추가 굵기 전진도 원래 자간·장평과 함께 같은
장치 격자를 소비하도록 바꿨다. glyph-fit walk는 그 전진을 빼고 고유 폭을
유지하므로 표시 glyph를 가로로 늘리는 보정이 아니다.

가운데·오른쪽 정렬의 마지막 가시 글자 뒤에는 다음 글자가 없다. 해당 HFT
끝 간격도 같은 측정 walk의 원래 자간과 굵기 전진을 제외한 끝에서 산출한다.
문서 ID·표지 문자열·특정 쪽·절대 px 보정은 추가하지 않았다. 앞서 확인한
HWP3 제어 문자 축·자연 페이지 소유 보정은 유지한다.

## 검증 상태

표시용 TTF 선택, 새 source의 전체 쪽수·Native/fresh WASM TSV·확대 판독,
이전 신명 HFT 두 프로그램과 시험지 대조군의 재검증은 아직 남았다.
rustfmt와 변경 차이 공백 검사는 통과했다. source/test의 전체 gate가
미실행이므로 이 후보에 대한 PR 생성·승인·새 렌더링 회귀 추가는 보류한다.
