# #8856 잔여 렌더링 보정 — 이전 인쇄 세대의 연속 글자 그림자

## 선행 분석과 독립 근거

원 #8611·#8617과 통합 #8857의 interview 제목 차이를 원본·실제 공통 paint와 대조했다.
흰 돌출 그림자는 글맵시 개체가 아니라 보통 글자의 `shadow_type=2`다. 원본의 글자 모양
14는 41pt·장평90%·색 `#EA5E00`·흰 그림자·signed 간격(10,10)%를 가진다.
HWP5 개정1.3 표33·35의 연속 그림자 계약이며 2024 문서에만 허용되는 속성이 아니다.
독립 기존 2020 Print는 제목 `10`의 흰 중간 원점을 여러 개 보존한다.

원 이슈 #8153을 해결한 실제 통합 PR #8389(`c417310cab`)의 공통 연속 그림자 계획은 실제 공급 SFNT의 OS/2·VDMX와 signed 원본
백분율로 장치 거리를 해소한다. 공통 생산·소비 자체는 재사용하되 `LayerBuilder`의
글꼴 등록과 그림자 준비가 모두 2024 Print flag에 묶여 있어 이전 인쇄 세대에서는
단일 끝점 그림자로 떨어진다. 별도 dot leader의 2024 규칙은 확장하지 않는다.

같은 작은 입력을 한컴 2020(11.0.0.9136)·2024(13.0.0.3901)에서 각각 Print했다.
Times New Roman의 9/41/100pt와 NONE/DROP/CONTINUOUS 9조건을 대조했다.
두 엔진 모두 NONE 0회, DROP 1회, CONTINUOUS 11/43/102회 그림자 span을 보존한다.
진단 입력이 보존한 원본의 부수 내용 쪽은 이 벡터 대조에서 제외한다. 해당 합성 자료는
일반 문서의 쪽 배치 정답지로 사용하지 않는다.

## 변경할 생산·소비와 반례

원본 종류·간격 → 실제 supplied/embedded SFNT → 공통 연속 그림자 계획 →
Native·Canvas·SVG의 반복 도색을 추적한다. 같은 장치 계약이 확인된 Print 세대에서만
그림자 계획을 준비하며 Screen, NONE, DROP, 본문 전진·쪽 소속·저장 원본을 보존한다.
backend가 별도 간격을 추정하거나 단일 끝점으로 덮어쓰지 않게 실제 소비도 확인한다.
엄격 glyph replay에도 같은 계획이 전달되면 이를 실제 재생하는지 별도로 확인한다.

## 검증 상태

진단 원본·두 Print PDF·벡터 좌표는 `output/issue8856/oracle-control/`과 `start/`에 있다.
새 검사는 저장소의 MIT 합성 TTF를 내장하므로 설치 글꼴이 없는 환경에서도 실행한다.
이전 2020/현재 2024 Print의 계획 일치·본문 소유·저장 보존과 Screen·NONE·DROP 반례를
관계형으로 검사한다. 아래에 보정 전 실제 FAIL·보정 후 PASS와 최종 Native/fresh WASM 전쪽 결과를 구분한다. 1단계·2단계 결과를 새 source 결과로 재인용하지 않는다.

보정 전 실제 실행은 세대·반례 검사 2 PASS / 1 FAIL, 엄격 Native 재생 검사
19 PASS / 1 FAIL이었다. 첫 추가 검사 빌드의 Box/TextRun 타입 오류를 수정한 뒤의
실제 실행만 FAIL 증거로 사용한다. 1차 보정 뒤 두 그룹은 각각 3 PASS·20 PASS였으나,
기존 전송 검사 3건에서 새 builder가 재조회할 글꼴이 없을 때 확정 계획을 지우는
회귀를 검출했다. 기존 검사는 유지하고 확정 계획과 원본 종류의 우선권을 보존하도록
구현을 추가 보정했다. 이후 실제 공급·페이지별 요청 경로까지 아래와 같이 보정·재검증했다.

엄격 Native 효과 재생의 원 해결 PR은 [#6881](https://github.com/edwardkim/rhwp/pull/6881),
현재 이력의 적용 commit은 `77e51006fb6bfb2c8485813602e223296d0435a9`다.
당시 단일 그림자·외곽선·양각/음각의 순서와 atomic fallback을 보존했다. 이후 #8389가
공통 연속 계획을 도입했으나 이 소비자의 단일 끝점 재생은 남았다. 새 보정은 같은
계획의 표본을 이 소비자에도 연결하며 기존 실패 guard·예산·선택 판정을 완화하지 않는다.


## 실제 공급 경로의 추가 확인

계획·전송·엄격 재생과 기존 양식·점선 대조군은 최소 글꼴 환경에서 실제 29 PASS였다.
그러나 실제 Native 출력에는 개선이 없어, 소비자의 선행 공급 경로를 다시 추적했다.
문서 단위 `get_text_shadow_font_requests_native`, Native PNG 준비, 공통 렌더링의
글꼴 전달에도 별도의 2024 제한이 남아 있었다. 실제 프로그램을 내장하지 않은 합성
문서로 API와 Native exporter를 검사해 4 PASS / 2 FAIL을 재현했다. 공급 구현을
보정한 뒤 새 6건과 기존 26건은 32 PASS / 0 FAIL이었다. 이전 세대의 실제 탭 점 리더는
여전히 요청하지 않도록 반례를 유지했다.

이 공급 보정의 실제 interview Native 1쪽은 최소 글꼴 환경에서 97.02270% → 97.19457%,
원본 글꼴 설치 대조군에서 97.52428% → 97.92044%였다. 2쪽은 모두 99.99221%를 유지했다.
원본 글꼴 대조군의 확대 판독에서 끊긴 끝점 그림자가 연속 흰 그림자로 연결됐다.
최소 환경과 원본 설치 환경의 자형 차이, 배경 이미지의 가장자리 차이는 별개 잔여다.
이 집중 4쪽 결과를 전체 219쪽 또는 fresh WASM 검증으로 표시하지 않는다.

WASM 내보내기는 문서 단위 API보다 페이지별 `get_page_paint_font_requests_native`를
우선한다. 해당 요청 생산의 2024 제한도 별도로 발견해 실제 실패 검사를 준비했다.
이 경로를 보정·재검증한 뒤 최종 Native/fresh WASM 전쪽과 함께 수용 여부를 판정한다.


## 최종 그림자 소스 검증

페이지별 요청 검사도 실제 6 PASS / 1 FAIL로 누락을 재현했다. 이후 양쪽 인쇄 세대의
두 쪽에 A/B를 분리해 실제 쪽 소유까지 보완했고, 최종 집중 검사는 최소 글꼴 환경에서
35 PASS / 0 FAIL이었다. 현재 7개 새 검사는 설치 글꼴 없이 MIT 합성 프로그램으로
계획·문서 요청·페이지별 요청·실제 Native 공급·NONE/DROP·Screen·저장 보존을 검사한다.
기존 엄격 glyph 재생 20건, 전송·SVG 3건, 세션 2건과 앞 단계 대조군 3건도 유지했다.

최종 source의 Native/fresh WASM은 각각 9문서군·219쪽을 모두 산출했다. 두 경로 모두
90% 미만·누락·새 base 대비 raw 하락은 0쪽이다. 직전 단계 대비 바뀐 두 쪽은 다음과 같다.

| 대상 | Native 전 → 후 | fresh WASM 전 → 후 |
| --- | ---: | ---: |
| interview 1쪽 | 97.02270 → 97.19457% | 97.15145 → 97.32378% |
| KTX 1쪽 | 99.38897 → 99.66127% | 99.42441 → 99.69700% |

나머지 217쪽은 경로별 직전 점수를 유지했다. 제목의 흰 연속 그림자와 KTX의 회색 그림자
개선은 같은 쪽 raw·review·overlay에서 직접 확인했다. 최소 환경의 원본 글꼴 부재에 따른
자형 차이와 배경 가장자리, 다른 #8856 문서의 잔여는 이 보정의 완료 범위에 포함하지 않는다.
원본 글꼴 설치 확대 그림은 별도 진단 source·환경을 표시해 보존하며 최종 최소 전쪽과 섞지 않는다.

Mac locked wrapper의 `--no-opt` 로컬 대체 WASM 빌드를 실제 완료했다. 루트 pkg와 Studio
public의 JS/WASM, 새 Chrome 초기 GET 응답의 해시가 모두 일치하며 관측한 request PNG도
같은 조건의 최종 WASM 전쪽 PNG와 바이트가 같다. Docker 최적화 통과로 주장하지 않는다.
전체 nextest·최종 제출 게이트와 남은 문서 보정은 아직 완료되지 않았다.
