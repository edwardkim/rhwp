Issue: #7642. 수정 전 소스는 `47f7e9a79f294b8d669a2a1bbc592a4447ebee95`다.

## 독립 근거와 실제 거절 경로

원본 #7028의 관측된 Print 글꼴에서 5쪽 68행의 첫 줄은 내용 13.333333px,
패딩 포함 약 17.066667px이고 잔여 32.12px에 들어간다. `advance_row_cut`도
`end_cut=[1]`을 반환한다. 이후 `row_step`은 저장 줄 계약이 없다는 이유로
고정 `MIN_TOP_KEEP_PX` 검사를 적용해 해당 행을 전부 이월한다. 실제
stage3045 로그의 CUT_TRY `[1]` 뒤 fragment가 `rows=56..68, cut=[]`로 바뀐다.

독립 한컴 Print 5쪽에는 “도시교통”이 y=1018.632426px에 남고 6쪽에는
“설계”와 이웃 병합 칸의 “교통, 지질및지반)”이 이어진다. Native는 두 줄을
모두 6쪽에 두고 이웃 병합 내용은 5쪽에서 모두 소비했다. 폰트 교체나 컷의
최종 좌표 이동으로 해결하지 않는다.

## 변경 계약과 소비 경로

실제로 재조판한 일반 텍스트의 완전한 줄 유닛은 문단 유지 지시에 따라
분할한다. 기존 저장 줄 인증 경로는 유지하고, 같은 실제 유닛·문단 경계·
widow_orphan/keep_lines/keep_with_next 검사에 재조판 출처를 추가한다.
편집 세션·세로쓰기·개체·미소비 셀·비가시 빈 유닛은 이번 완화 대상이 아니다.
기존 문단 유지 지시와 실제 표시 높이·패딩·병합 칸·페이지 예산 검사는 유지한다.

생산한 `res.end_cut` → 실제 일반 셀의 줄 유닛/문단 유지 계약 → row_step의
고아 조각 판정 → 기존 split_total의 페이지 예산 검증 → 같은 컷의 emit/paint를
따라간다. 문서 번호·행 번호·별도 px 하한을 추가하지 않는다.

동일 원본의 3·6쪽과 앞뒤 경계, 6쪽 전체 TSV를 먼저 확인한다. 기존 2쪽
97.44351%와 1·4·5쪽을 후퇴시키지 않아야 한다. 작은 whole/split 병합 대조군,
#7518의 0+2와 1+2줄, 기존 보정 53쪽 및 #7969 대조군도 함께 확인한다.

새 정식 회귀나 px 기대값을 추가하지 않는다. 아직 이 단계의 통과 증거는 없다.
