# Issue #7642 단계 844: 인증 값의 발행 범위와 실제 그룹 검사

## 직전 검증

`41150f732`의 Native 빌드와 fmt는 통과했다. 파생 suite 005에는 그룹 검사가 없어 0건 실행으로 실패했다. 실제 suite 008에서 단계 843의 4건을 실행했고 탭 2건 통과, 새 그룹 검사 2건 실패였다. 검사 오류를 수정한 뒤 다시 실행해야 한다.

내용 차이는 HWP3 개체 슬롯 `U+FFFC` 두 개가 HWP 저장 뒤 실제 표 컨트롤로 유지되는 표현 차이였다. 같은 위치의 공백과 다른 37개 내용 항목은 같았다. 개체 슬롯 문자만 표시 내용 비교에서 제외하고 표의 실제 쪽·문단·컨트롤·셀 소속과 순서·행·열을 별도로 검사한다. 표시 문자와 공백은 계속 보존한다. 입력 SHA-256은 원본과 worktree, 단계 819에서 모두 같았다.

원본 IR에 비영 오프셋이 반드시 있다고 요구한 조건은 입증되지 않았다. 빈 묶음, 실제 오프셋·행렬 관계, Absolute 크기와 왕복 보존을 검사하며 비영 값의 필수 존재는 제거한다. 실제 출력 결함을 baseline 갱신으로 숨기는 변경이 아니다.

## 원점 전달 보완

단계 830에서 HWPML 표 3.42의 측정 수용 true와 원점 162.933333px를 확인했다. 일반 `stored_tac_lines` 계획에는 기존 page base가 있는데 보조 `single_saved_line` 경로만 source_origin을 발행해 전달 필드가 비어 있었다. 일반 원본 계획의 실제 pen이 기존 저장 원점과 1HU 이내로 같으면 그 page base를 전달한다. 흐름 때문에 이동한 계획이나 page base가 없는 계획에는 값을 만들지 않는다.

공동 앵커의 호스트 사영도 현재 계획이 수용한 page base를 먼저 사용한다. 현재 축이 없을 때만 초기 단 기록을 대조한다. 실제 문단 시작·원본 앞 간격의 일치 조건과 첫 조각의 선언 높이·행 끝 인증을 유지하며 관측 행 번호나 px로 컷을 고정하지 않는다.

## 공간과 헤드 확인

종료된 output ELF와 폰트 전송 사본 약 8.75GiB를 제거했다. 이후 공간이 다시 소진되어 단계 문서 저장이 실패했고 일부 matrix controller도 종료됐다. 이를 검증 완료로 처리하지 않는다. 입력·PDF·TSV·로그·대표 PNG와 공유 target은 보존했다.

종료된 `stage187`·`stage192`·`stage534` worktree는 변경 없음, 기본 branch 아님, 같은 작업의 소유, 실행 중인 프로세스 없음, 자체 target·output 없음과 기존 branch ref의 HEAD 보존을 확인한 뒤 제거했다. 약 5.3GiB를 추가 확보했다. 다른 dirty worktree와 현재 review·base worktree는 보존했다. ext4 예약 비율은 변경하지 않았다.

GitHub의 devel ref를 직접 조회한 SHA는 `a5e88ad682c805e1d845502ddc9521b94ea8eccd`로 고정한 local upstream/devel과 같았다. 현재 rebase는 필요 없다. PR 직전 다시 확인한다.
