# #7642 임시 저장 원점의 본문 꼬리 회귀 보호

Issue: #7642

## 원인과 선행 증거

`c8d5dccb20`에서 확정 쪽 축과 첫 항목의 임시 원점을 구분해, 내용이 들어가는 줄이 불필요하게 다음 쪽으로 이월되는 것을 보정했다. 원본 HWP/HWPX의 46쪽 Native/fresh WASM 검증과 41쪽 직접 판독은 [증적](../pr/assets/issue7642/confirmed-body-frame-origin/README.md)에 연결했다. 두 backend 모두 41쪽 raw99.5% 이상이며 전쪽 최저90% 이상이다.

## 새 검사

`issue_7642_confirmed_body_frame_origin::provisional_source_origin_keeps_fitting_tail_on_its_print_page`를 새 이름으로 추가한다. 원본 구절로 문단을 식별하고 모든 쪽에서 네 줄의 쪽 소유·내용 보존·순서·본문 포함을 검사한다. 중요 꼬리의 기준선과 가로 시작은 독립 PDF에서 측정한 ±2px 계약이다.

현재 runtime `c8d5dccb20`의 native-skia 라이브러리에 새 검사 파일을 직접 링크해 실행한 결과 **1 PASS / 0 FAIL**이다. 로그는 ignored `stage3509-confirmed-origin-regression/test.log`에 보존했다. 처음 작성한 검사에서 모델 Rect와 렌더 BoundingBox 타입을 혼동한 컴파일 오류는 수정했으며, 해당 오류는 엔진 실패로 세지 않는다. 수정 전 CLI는 47쪽이며 꼬리 줄의 쪽 소유가 다르다는 기존 관측이 있으나, 새 검사 자체의 수정 전 FAIL은 아직 실행하지 않았으므로 결함 검출 완료로 보고하지 않는다. 실행 후 이 기록을 갱신한다.

## 다른 실패 입력

sample4의 원본 HWP3는 저장 `TAG_FIRST_LINE_OF_PAGE`로 문단218의 마지막 줄을 다음 쪽에 두지만, HWP5 변환본은 그 신호가 없어 허용치21.3px를 본문 점유에도 사용한다. 허용치0 진단에서 변환본7·8쪽이 원본 배치와 일치했고, 무변경 복제본은 원본 렌더 트리와 같았다. SO-SUEOP의 HWP/HWPX 미주 흐름은 별도 대조했다. 이 진단은 아직 공통 예산 구현 수정이나 전쪽 개선 완료를 뜻하지 않는다.
