# Issue #7642: Visual Sweep 기준 PDF의 채우기 보존

## 독립 근거와 수정 범위

부모는 `c239bf118`이다. RHWP의 실제 배치 보정은 앞 단계의 변경으로 커밋했고
같은 소스 Native 재빌드가 진행 중이다. 이 단계는 기준 PDF→PNG 변환 정책을 고친다.
변경 직전 실행 중인 Visual Sweep이 없고 다음 Native 대조가 빌드를 기다리고 있음을
확인했다. 한 큐 안에 서로 다른 스크립트 정책이 섞이지 않게 한다.

원본은 `samples/task1768/distribution_doc.hwpx`, 독립 한컴 Print는
`pdf/issue7642-failed-regression-print-20261015/distribution_doc-2020.pdf`다.
기준 PDF SHA-256은 `0299869bf040b01e07a19dde600852e44aec406257916b781eabdfbce6ed5aba`다.
`stage1393-pdf-raster-diagnostic/receipt.json`은 같은 PDF를 shape/solid/none과
독립 MuPDF로 읽은 원래 진단을 보존한다. shape/solid는 실제 파랑 그라데이션을
흰색으로 만들지만 none과 MuPDF는 파랑 채우기를 보존한다.

`stage1483-distribution-raster-diagnostic.json`에서 같은 보정 Native 3쪽과 비교하면
shape 90.67474%, none 100.00000%다. 배치·DPI·232 임계값·2px 관용 거리·색상 허용치는
같다. 점수를 올리는 특정 문서 예외를 추가하거나 올바른 RHWP 출력을 숨기는 수정이 아니다.
원본 PDF·RHWP PNG를 변경하지 않고 **전체 문서에서 같은 기본 raster 정책**을 적용한다.

[Poppler의 pdftoppm 문서](https://skia.googlesource.com/third_party/poppler/+/master/utils/pdftoppm.1)는
none이 기본값이며 shape/solid는 얇은 선을 픽셀 경계로 조정한다고 설명한다.
원래의 비례 coverage 취지와 실제 채우기 손실을 구분한다. 기본 none으로 명시 고정하고
선택 쪽·전쪽 명령과 manifest가 같은 정책 상수를 사용하게 한다.

## 검증과 적용 경계

기존 페이지 선택·전쪽 명령 계약 테스트를 새 일관된 정책으로 검증한다. 같은 Print PDF의
실제 PNG에서 파랑 채우기가 유지되는지 직접 판독하고 명령·SHA를 보존한다.
기존 PNG·TSV를 덮어쓰지 않고 새 output에 산출한다. 이전 shape 수치와 none 수치를
같은 baseline으로 섞어 비교하지 않는다. 이후 최종 전쪽 비교는 Native/fresh WASM,
고정 upstream/devel과 후보 head 모두 none으로 다시 측정한다.

앞 단계의 공백 35쪽 및 실패한 기존 명시적 개행 입력도 같은 정책으로 새로 산출한다.
아직 fresh WASM·최종 71행 검증·devel 대비 무회귀가 끝나지 않았으므로 PR 준비 완료나
승인으로 보고하지 않는다. PDF의 채우기를 보존하는 것과 실제 배치 회귀 판정은 별도다.

## 도구 검증 결과

`PDF_THIN_LINE_MODE = "none"`을 전체·선택 쪽 명령과 provenance에 함께 사용한다.
문서별 raster 선택 옵션은 추가하지 않았다. 기존 테스트의 기대 모드도 이 계약으로 바꿨다.
`venv/bin/python -m unittest scripts.tests.test_visual_sweep`는 **83/83 PASS**다.
로그는 ignored stage15-current-validation의 `stage1485-visual-sweep-unit.log`에 있다.

실제 수정한 `pdf_raster_commands`로 동일 Print PDF 3쪽을 다시 출력한
`stage1485-raster-runtime/receipt.json`에 명령·도구 SHA·PDF SHA·PNG SHA를 기록했다.
파랑 계열 픽셀은 이전 shape PNG **0개**, 새 none PNG **15,723개**다.
같은 보정 Native PNG와의 2px 일치율은 **100.00000%**다. 출력 PDF 파일·입력·
RHWP PNG는 바꾸지 않았고, 기존 shape 증적은 보존했다.

이 runtime 검사는 실제 Print PDF의 채우기 손실을 검출한 도구 진단이다.
전체 브랜치의 시각 무회귀나 개별 렌더링 회귀 추가의 선행 조건을 대신하지 않는다.
이후 `stage1488` Native 대조부터 새 none 정책과 실제 script SHA를 기록한다.
기존 shape 기반 devel 비교 수치는 최종 승인 근거로 재사용하지 않는다.
