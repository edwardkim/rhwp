# #7642 저장 줄이 없는 인라인 문단과 한컴 수식의 공통 프레임

Issue: #7642

## 구현 전 근거

한컴 2024가 저장한 128개 수식 진단 HWP에는 앞 40개 문단의 LineSeg만 있다.
뒤 문단의 수식 크기·기준선은 정상이고 독립 Print도 16쪽을 정상 출력하지만,
현재 두 backend는 6쪽부터 줄 간격을 잃는다. 문단 모양은 160%다.
공통 프레임 내부는 인라인 수식·그림·폭 중립 마커를 지원하는데 외부 재구성
게이트가 이 문단을 거절해 400HU·간격 0의 임시 줄에 남긴다.

측정은 `typeset/paragraph/format.rs::recompose_for_flow`, 실제 배치는
`layout/paragraph_layout.rs`가 같은 `recompose_stored_lines_in_frame_with_known_square_band`
결과를 소비한다. 저장 줄이 없는 유효한 인라인 호스트를 이 공통 결과에 연결한다.
표·부동 개체·별도 소유자가 있는 컨트롤의 수용 조건은 해당 계약으로 대조한다.

두 수식 face의 대응 64개 높이·기준선과 세로 글꼴 메트릭은 같다. 전진폭·실제 glyph는
서로 다르다. 이를 구분해 HancomEQN의 일반 글줄·첨자·장식·분수 프레임을 연결한다.
원본 33쪽의 분수 여백·장식 뒤 연산자 간격과 합 기호는 새 Print 자료로 대조한다.
저장 폭에 맞추기 위해 잘못 계산한 전체 수식을 압축하는 것을 해법으로 삼지 않는다.

## 구현과 검증 범위

- LineSeg가 없는 TAC 수식·그림과 폭 중립 마커의 공통 프레임 수용 및 실제 간격 보존.
- HancomEQN 대문자 그리스 기호의 실제 cmap·GDI 전진, 일반 글줄·장식·분수의 공통 프레임.
- 분수의 본체 기준선·점유, 합의 잉크와 상하한, 장식 뒤 자동 간격의 중복 여부.
- 16쪽 정상 한컴 저장 진단과 원본 PrEP 전쪽 Native/fresh WASM 및 확대 판독.
- 저장 줄이 있는 경로, 기존 HY·일반 Math와 별도 소유 컨트롤을 대조군으로 확인.

진단 입력·Save/Print 이력은 1598, raw 모델·캐시 경계는 1605/1606,
확장 GDI는 1603의 ignored 증적에 보존돼 있다. 새 회귀·fixture는 두 경로의 관련 전쪽
90% 이상과 직접 판독 후 추가한다.

## 중간 관측과 다음 보정의 근거

작업 트리의 Native producer 1613으로 16쪽 진단과 원본 140쪽을 전쪽 재출력했다.
진단 최저값은 22.45847%에서 98.89677%로 개선됐고 원본 최저값은 91.54965%다.
원본 31쪽은 98.07380%에서 98.76804%, 33쪽은 98.50405%에서 99.46554%로 개선됐다.
나머지 원본 138쪽의 점수는 이전 후보와 같다. 이는 최신 devel과의 비교 완료를 뜻하지 않는다.

확대 판독에서 분수 전체 뒤 아래첨자가 분모 위에 붙는 결함을 확인했다. 단순 글자 아래첨자와
분수 아래첨자의 점유 계약은 다르다. 공통 분수 첨자 프레임을 실제 배치에서도 소비하고,
HancomEQN의 최종 기준선을 저장본과 같은 정수 백분율로 맞춘다. 일반 Math와 기존 HY의
분기는 유지하며, 분수 본체·첨자의 상대 기준선을 독립 Print에서 대조한다.

또한 HancomEQN 쉼표의 GDI 전진에는 수학 문장부호의 오른쪽 간격이 없다. 네 크기의
Print에서 쉼표부터 다음 글자까지의 거리와 GDI 전진의 차이를 대조한 뒤 0.07em을 별도
예약한다. 쉼표 glyph 원점과 다른 face의 전진은 보존한다.

CanvasKit JSON에는 저장 폭 비율이 있지만 실제 `renderEquation`은 이 필드를 소비하지
않는다. CanvasKit·Native·Canvas2D·SVG 모두 현재 자연 폭으로 그리는 호출 경로를 확인했다.
따라서 가로 압축이 실제 발생한다고 단정한 앞선 우려를 교정한다. 실제 CanvasKit 캡처는
아직 미검증이며 Native 점수로 전체 backend 완료를 선언하지 않는다.
수정 뒤 Native·fresh WASM 전쪽과 확대 판독을 재수행한다. 전체 회귀와 새 회귀 추가는
해당 선행 조건 충족 후 진행한다. 현재 단계는 진행 중이다.


## Native 재검증과 결함 검출

1617 Native 빌드는 공용 `target/pr-review`, 잡 8개로 exit 0을 확인했다. 1618 전쪽
재검증은 진단 16쪽 최저 98.89677%, 원본 PrEP 140쪽 최저 91.54965%이며 전체 쪽수와
측정 범위가 일치한다. 마지막 첨자·문장부호 보정 뒤 진단 2/4/6/8쪽이 개선됐고,
원본 31/33쪽은 각각 98.76787/99.46565%다. 이전 후보 대비 0.01%p 이상 하락은 없다.
이는 새 devel 자체와의 비교를 대신하지 않는다.

1621의 ignored 진단 초안은 같은 두 검사로 수정 전 1608 라이브러리에서 2건 실패,
현재 1617에서 2건 통과를 확인했다. 실패 원인은 각각 40번 이후 문단의 줄 간격 0과
분수 첨자가 분모 위에 놓인 배치다. 저장 줄의 상대 전진과 재조판의 실제 점유 뒤
양수 간격을 구분한다. 글자 크기만으로 실제 표시 줄 상자의 높이를 재계산한 첫 초안은
하강부를 놓쳤으므로 그 가정을 제거했다. 실패 로그도 ignored 증적에 보존한다.

독립 Print와 원본 31/33쪽의 수식 glyph 원점 89개를 대조했다. 33쪽 42개는 최대
0.54746 CSS px 차이다. 31쪽의 본문 중 인라인 수식 두 개는 최대 4.26665 CSS px
왼쪽으로 이동해 있다. 해당 부분을 완료 페이지나 px 추가 대상으로 판정하지 않는다.
합·분수·장식의 구조 개선이 모든 본문 인라인 위치의 완료를 뜻하지 않는다.

현재 fresh WASM 빌드와 기존 전체 검증 문서의 Native 재산출을 진행 중이다.
새 회귀·fixture 활성화는 두 경로의 전쪽 선행 검증과 직접 판독 후 수행한다.
전체 Rust, 최신 devel과의 전쪽 대조 및 알려진 미세 차이가 남아 있어 PR 준비 완료가 아니다.
