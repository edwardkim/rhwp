사용자 지정 기준은 #8389의 편람 HWPX 전 383쪽 TSV다. 130쪽 표시값 99.96%,
다른 382쪽 100.00%를 하한으로 삼는다. 새 작업 base는

## 인쇄와 화면의 소비 계약

#8389의 인쇄 캡처와 Native는 portable 메트릭을 사용했다. 후속 Sweep은 Studio의
Canvas 측정 세션을 준비한 뒤 화면 폭을 활성화한 채 Print PNG를 만들었다.
이는 SVG 인쇄가 쪽수 조회 전에 portable로 전환하는 계약과 달랐다. 기존 화면의
보충 측정은 없애지 않고 Canvas Print의 호출자도 전환·복원을 수행한다.
Rust Print 진입점은 화면 폭이 남아 있으면 명시적으로 거부한다.

동일 #7084 입력의 실제 검사에서 인쇄 진입 거부 assertion은 보정 전
10 PASS / 1 FAIL, 보정 후 11 PASS였다. 화면 메트릭의 실제 위치 변화,
화면 레이어 생성 성공, portable 전환 뒤 Print 성공과 원문 보존도 함께 검사한다.
Studio 실제 bridge 함수는 Screen → Print → Screen과 paint 실패 후 상태 복원을 검사한다.

기존 WASM(`f49fc9cbe5cfea6b344593bf57642c274eff5c2f7268007e228340407e5974dd`)
에 Sweep의 portable 인쇄 전환만 적용한 선행 진단은 다음과 같다. 새 Rust/WASM 빌드의
완료 증거가 아니며, 같은 독립 PDF·96 DPI·2px 원값을 사용했다.

| 쪽 | 기존 화면 폭 활성 Print | portable Print |
| ---: | ---: | ---: |
| 130 | 99.96401% | 99.96401% |
| 198 | 99.68453% | 99.68423% |
| 220 | 99.91442% | 100.00000% |
| 272 | 100.00000% | 100.00000% |

198쪽은 여전히 #8389 하한 미달이다. 이 결과를 전체 완료로 표시하지 않는다.
공개 프로그램 공급 조건과 최종 fresh WASM 전쪽 대조를 계속한다.

## 묶음 개체의 주소 소유

사용자 화면의 편람 3쪽에서 `sec=0 ppi=4 ci=0 cei=0 cpi=0` 오류를 재현했다.
원본 HWPX section0의 문단 4는 두 글상자를 가진 container다. 자식 렌더 노드가
외곽 Group의 컨트롤 번호를 물려받는데, 마우스 처리가 이를 독립 글상자의 셀 0으로
편집하려 하여 존재하지 않는 모델 주소를 조회했다.

실제 개체 hit가 Group이면 텍스트 hit보다 먼저 묶음 선택을 확정한다. 원문·조판·
그림과 글상자의 내용을 바꾸지 않으며 일반 글상자와 연결선의 기존 선택은 유지한다.
실제 제품 mouse 함수를 호출한 새 검사는 보정 전 묶음 선택 assertion에서 실패했고,
보정 후 관련 13건이 통과했다. 개체의 원본 주소·페이지와 잘못된 셀 조회 부재를 확인했다.
실제 Studio 화면 재검증과 새 소스 전체 검증은 아직 남아 있다.
