## 완료한 Native 전쪽 측정과 남은 gate

같은 생산 소스의 보존 CLI와 Poppler none을 사용한
`stage1493-current-native-scope/receipt.json`은 원래 목록 **71행·1110쪽**을 완료했다.
모든 쪽이 90% 이상이고 최저는 **90.71006%**다. 누락·쪽수 불일치는 없다.
중복 입력이 있는 원래 목록의 행을 임의로 합치지 않았다.

같은 none 정책의 고정 devel과 비교한
`stage1503-current-native-none-base-drops.json`은 67행·938쪽을 비교했고,
**59쪽이 0.01%p 이상 하락**했다. 최대는 국어 HWP/HWPX 14쪽의 1.78206%p다.
나머지 네 행은 devel 자체의 전체 쪽수가 기준 Print와 달라 비교 불가로 남겼다.
후보의 전쪽 90% 통과로 이 gate를 면제하지 않는다.
fresh WASM의 원래 목록 전체 검증은 별도 진행 중이다.

## 배포 문서의 잘못된 줄 수 전제 교체

원본 `samples/task1768/distribution_doc.hwpx`와 독립 Print 3쪽을 재사용한다.
전 3쪽 Native 최저 98.17563%, fresh WASM 최저 98.04595%이고,
해당 3쪽은 양쪽 100%다. 입력/PDF 해시와 확대 판독은
[직전 등록 기록](task_m100_7642_stage1507.md)에 있다. 생산 코드는 바뀌지 않았다.

실제 원문의 호스트 문단에는 단위 표시 앞의 공백과 표 앞 구분 공백이 있다.
첫 TextLine은 단위 표시, 다음 TextLine은 글자처럼 취급 표의 점유 영역을
표현한다. 둘째 줄의 가시 글자가 없다는 이유로 표의 줄 상자까지 없다고
간주하면 측정·배치의 소유 계약을 잃는다. 현재 원본과 독립 Print의 예산 표
외곽 및 후속 주석은 일치한다. 실패를 근거로 정상 표의 줄 상자를 숨기지 않는다.

기존 `trailing_whitespace_does_not_get_its_own_line`을 제거하고,
다른 PR에서 과거 시험지 검사 파일을 정리해도 남는
`tests/cases/verified_inline_print_rows.rs`에 새 이름
`verified_distribution_whitespace_rows_belong_to_the_budget_table`을 추가한다.
원문으로 호스트를 찾고 문자·공백·원점 배열, 단위 표시 한 번, 표 한 번,
가시 글자 없는 줄의 개체 포함, 앞뒤 줄 순서와 비겹침을 검사한다.
독립적인 빈 줄을 허용하거나 모든 빈 줄을 단순히 필터링하지 않는다.
새 검사에는 고정 px나 전체 TextLine 수 핀을 사용하지 않는다.

이 검사는 과거 코드의 제품 결함 재현을 새로 주장하는 것이 아니다.
정확한 독립 Print와 기존의 새 예산 표 경계 검사를 유지하면서,
가시 줄과 개체 점유 줄을 혼동한 기존 기대를 바로잡는다.
정식 집중 검사는 **5/5 PASS**, run ID
`2dfeeffc-f6a9-4e86-864c-769dc96bbef4`다. 기존 새 검사 네 건과 추가한 소유
검사를 함께 실행했다. 첫 시도는 generated suite를 준비하지 않아 파생 manifest의
배정과 실제 suite가 달랐고, 0건 실행·종료 코드 4였다. 이 시도는 검사 통과나
제품 결함 재현으로 세지 않았다. `rust-test-suite-manifest.mjs --prepare` 후
같은 필터로 실제 다섯 검사를 실행했다. 로그는 `stage1517-inline-semantic-regression-r2.log`다.
이후 rustfmt가 배정 가중치의 소스 바이트 수를 바꿔 남은 기존 검사 실행도
0건·종료 코드 4가 됐다. 다시 prepare하고 파생 target과 실제 generated 모듈을
대조한 뒤 두 suite를 한 명령으로 실행했다. 소스·포맷을 변경한 뒤에는 실행 직전
prepare와 실제 모듈 확인을 적용한다. 테스트 인프라 코드는 바꾸지 않았다.

최종 집중 결과는 **8/8 PASS**, run ID
`256b6751-c0a6-44b0-938b-3fd7a37ef0e9`다.
새 파일의 다섯 검사와 기존 파일의 남은 세 검사를 함께 실행했다.
`stage1517-distribution-combined-regression.log`에 명령과 종료 요약을 보존했다.
빌드 잡 8개·테스트 스레드 12개·공용 target을 사용했다.
제거한 검사에서만 쓰던 helper와 상수도 함께 제거했다.
두 파일의 rustfmt와 `git diff --check`도 통과했다.
전체 회귀의 15실패 결과를 집중 검사 결과로 덮어쓰지 않는다.

## devel 하락 페이지의 실제 Native 글꼴 관측

전체 회귀 종료 뒤 보존 라이브러리에 읽기 전용 진단을 연결했다.
Native renderer를 실제 시각 검증과 같은 네 글꼴 경로로 준비해
`SkiaLayerRenderer::get_font_decision_trace`를 호출했다.
`stage1516-native-font-snapshot/affected-character.json`에서 국어 14쪽의
원문 `신명 태고딕`·문단 30 첫 글자 `학`은 실제 Native inventory에서
시스템 `HYGothic-Medium`으로 해소됨을 관측했다. 원본 HFT 프로그램과
이 대체 프로그램이 같다고 주장하지 않는다. trace는 원본 프로그램 바이트의
동일성을 증명하지 않는다. 올바른 원본 글자 높이 계약을 과거 값으로 되돌려
점수 하락을 숨기지 않고 이 차이의 원인을 계속 확인한다.
