## 저장 공간과 검증 실행

`/dev/sda`의 250GiB → 300GiB 증설 뒤 `/dev/sda3`, LVM PV·LV와 ext4를
온라인 확장했다. `growpart`, `pvresize`, `lvextend -r`는 모두 종료 코드 0이었다.
루트 파일시스템은 `df -h` 기준 294G이며, 이 기록 시점에 40G가 남아 있다.
공유 `target/pr-review`는 보존했다. Cargo 컴파일 jobs는 6, nextest test threads는 12다.

이전 기록의 “원본 55개” 표현을 정정한다. 요청 원본은 **52개·783쪽**이며,
추가 대조군 3개·70쪽까지 포함한 실제 전체 범위는 **55개 문서·853쪽**이다.
검증 범위를 줄인 것이 아니다.

고정 Source269 `6c172496124874247fe4ebb3c7b26961a0c0658e`의 Native 전체 산출은
55개 문서 모두 쪽수 일치·전체 페이지 포함을 확인했다. 요청 원본의 미달은
`exam_social-p1.hwpx`(81.26332%)와 `exam_social.hwpx`(80.79%)의 첫 쪽이다.
추가 대조군 `hwp3-sample16-hwp5.hwp`는 64쪽 중 13쪽이 미달이며 최저 44.77541%다.
Native 전체 통과가 아니다. 원본 전체 fresh WASM은 아직 실행 중이다.

수식 진단 9종·183쪽은 Native/fresh WASM 모두 산출을 완료했다. 두 backend의
카탈로그 13·14·17·18쪽(최저 46.99045%), 구조 진단 1·3·4쪽(최저 78.07245%)이
미달이다. 나머지 7종의 전체 페이지 점수는 90% 이상이지만 확대 판독을 별도로 적용한다.

## 각주 독립 저장·Print 자료

`pdf/issue7642-footnote-reserve-style-diagnostic/`에 최소 입력 HWPX, 한컴 정상 저장 HWP,
해당 저장본의 독립 Print PDF를 3세트 보존한다. 원본은 `samples/hwpx/footnote-01.hwpx`에서
문서·글꼴·구역 속성을 유지하고 본문 및 각주 내용을 최소화한 진단 입력이다.
각주 글자 크기를 400·600 HWPUNIT(4·6pt)로 명시하고 오래된 LineSeg는 제거한 뒤
한컴이 정상 저장한 실제 줄 정보를 읽었다. 원본 시험지나 과거 기준 PDF를 대체하지 않는다.

한컴 2020 MCP 저장 → 저장본 Print → 결과 다운로드 순서로 실행했다.
모든 PDF는 engine build `11.0.0.9136`, `pdf_print_method=0`,
`pdf_output_mode=hancom2020_pdf_driver_one_up`의 1쪽이다. 비공개 접근 정보는 기록하지 않는다.

| 자료 | 변경한 조건 | 확인한 독립 출력 |
| --- | --- | --- |
| `footnote-reserve-style-*` | 본문 10pt, 각주 4·6pt | 본문 참조 번호는 약 7.56pt, 각주 본문 번호는 각주 크기를 유지 |
| `footnote-reserve-note-number-superscript-*` | 각주 자동 번호의 `supscript`만 켬 | 본문 참조 번호는 그대로이며, 각주 영역 번호만 작아지고 올라감 |
| `footnote-reference-font-sizes-*` | 본문 9·11·16·22pt, 각주는 4·6pt 유지 | 본문 참조 번호는 약 6.72·8.28·11.99·16.55pt로 본문 크기에 비례 |

첫 세트는 Source269 Native/fresh WASM 전체 1쪽이 모두 94.46602%다. 그러나 확대 판독에서
RHWP 본문 참조 번호가 Print보다 작고 높아 **미충족**으로 남긴다. 점수 통과로 면제하지 않는다.
독립 저장 줄 높이와 실제 글자 크기가 일치하는 각주 예약 높이 진단은 1/1 통과했다.
이 진단을 정식 회귀 추가나 전체 렌더링 완료로 보고하지 않는다.

## 사회 HWPX 원인 추적

HWP/HWPX의 실제 글자 모양 필드·본문 및 셀의 저장 LineSeg를 비교했다.
글자 모양 85개는 원본 raw bytes와 attr 원문을 제외한 유효 필드가 모두 같고,
본문 95개 및 셀 문단 459개의 저장 텍스트·줄 메트릭도 같았다. 단순 attr 비트 차이를
스타일 유실로 오인하지 않는다. 실제 출력 480개 run 중 323개는 주로 y 위치가 다르다.
저장 메트릭 이후의 표 점유·흐름 및 HWPX 소비 경로를 추적해야 한다. 원점 clamp나
문서별 좌표 예외는 추가하지 않았다.
