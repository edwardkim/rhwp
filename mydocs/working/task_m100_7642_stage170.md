# #7642 Stage 170 — 큰 본체 뒤 위첨자의 기준선

## 독립 관측

9월 2022 HWPX 전체 23쪽은 Stage 168 Native/fresh WASM 모두 최저
91.85820%지만, 11쪽 확대 판독에서 루트를 분모로 가진 분수의 닫는 괄호 뒤
제곱 첨자가 독립 한컴 Print보다 낮다. 이 결함은 점수 통과로 면제하지 않는다.
원본 미주 13의 수식 `= sqrt {1- LEFT ( {2} over {sqrt {5}} RIGHT ) ^{2}}`와
10쪽의 분자 1 대조군을 함께 확인한다. 원본이나 기준 PDF는 바꾸지 않는다.

## 원인과 소비 경로

`layout/script_geometry.rs::script_superscript_shift`는 원본 글꼴 프레임이
적용되지 않으면 일반 MATH shift와 위첨자 하단 여유만 소비한다. 실제 원본
배치 진단에서 fs 12의 괄호 본체 높이는 29.262, 기준선은 17.724인데 위첨자
기준선은 13.368이다. 분모에 루트가 있어 `fraction_sup_frame::ordinary_fraction`
계약에 해당하지 않으며 일반 글줄 프레임도 아니다. 이 숫자는 관측값이며
구현 분기나 회귀 기대값으로 고정하지 않는다.

OpenType MATH는 상자·늘어난 본체의 위첨자 기준선을 본체의 잉크 상단과
연결하도록 명시한다. [정본](https://learn.microsoft.com/en-us/typography/opentype/spec/math)의
`superscriptBaselineDropMax`와 Extended Shape 설명을 독립 근거로 사용하되,
표시 글꼴 상수를 HYhwpEQ 논리 프레임과 바로 혼용하지 않는다. 실제 한컴
저장·Print에서 적용 경계와 관측값을 먼저 확인한다.

공통 생산자는 `EqLayout::layout_superscript/layout_subsup`의 LayoutBox이며,
상위 Row/Sqrt가 이를 소비해 높이와 기준선을 정한다. 이후
`equation/mod.rs::flow_metrics_hwp/layout_for_paint`의 저장 프레임 선택을
대조한다. SVG와 Canvas의 Superscript/Paren 분기는 같은 자식 원점을 소비한다.
괄호의 filled outline과 일반 stretch path를 구별하며, 논리 상자 상단을 실제
잉크 상단으로 단정하지 않는다. backend에서만 첨자를 옮기는 처리는 하지 않는다.

## 반례와 검증

600/900/1500HU에서 일반 글자, 짧은 괄호, 보통 분수 괄호, 루트 분모의
분자 1·2, 루트 안의 같은 식, 아래·위첨자 병존을 독립 한컴 2024에서
재저장하고 Print로 출력한다. 원본 2022 HWPX/Print도 유지한다. 진단 입력은
정식 fixture나 회귀 테스트가 아니며 생성 방식과 SHA를 ignored output에 남긴다.

현재 Stage 169 HWP 전체 WASM 검증이 실행 중이므로 생산 소스는 유지한다.
독립 관측 이후 필요한 공통 배치 계약을 보정하고, 관련 전체 Native/fresh WASM
TSV와 확대 자료를 다시 확인한다. 90%·직접 판독을 만족한 뒤 새 이름의 관계형
회귀를 추가하며 실제 수정 전 FAIL / 수정 후 PASS를 확인한다. 일반 글자와
이미 확인된 보통 분수 프레임을 무조건 변경하지 않는다.

전체 55개 문서·853쪽, 추가 입력, 전체 회귀·lint와 PR/CI/후속 처리는 미완료다.

## 재생성 관측과 보정

MCP 2024 저장 job `11206672-527d-4a51-bc46-3f94358c39e0`, Print job
`ba1b58bc-fc98-4980-8a4a-a4282904f9f4`를 완료했다. 실제 한컴은
13.0.0.3901, Print method 0, `frame_print_to_pdf_ex_one_up`이다. 산출은
`pdf/issue7642-extended-base-script-diagnostic/`에 있으며 진단 입력이다.
저장 HWP SHA는 `b56f792854da2126022f19a9b82b1054621568647024295c05e112e55c3e82fc`,
독립 PDF SHA는 `bf86189aec6cf835f5546ef556c2bc5900c9708e8193f244dc5b133e1a6c7e18`이다.
21개 식은 전체 한 쪽으로 출력됐다. 보정 전 Native 전체 점수는 96.21091%지만
루트 분모의 첨자가 낮으며 아래첨자 병존도 직접 판독을 계속한다.

한컴 저장값에서 보통 분수 첨자의 높이는 1465/2217/3720HU이고 루트 분모는
1555/2352/3945HU다. 차이 90/135/225HU는 해당 글자 줄 위에 근호가 추가한
상단 밴드와 같다. 분수 안에서는 분모의 추가 밴드가 아래쪽 점유가 되고,
본체의 기준선 위 거리와 위첨자를 일반 글자 위치로 되돌릴 이유가 없다.
따라서 앞의 일반 MATH fallback만 수정하는 가설 대신 누락된 한컴 분수
프레임의 공통 소비를 보정한다.

`fraction_sup_frame::line_extension/source_fraction_frame`이 일반 글줄과
같은 크기의 무지수 근호 글줄을 구분해 추가 점유를 계산한다.
`fraction_geometry::source_position`과 `logical_font_frame::frame_with_style`이
같은 분수 프레임을 소비하고, 첨자 프레임은 같은 분자·분모 확장을 소비한다.
괄호 슬롯도 공통 논리 프레임을 받아 기존 한컴 폭을 사용한다. 다줄·근 지수·
복합 근호 본체·크기 변경은 이 단일 글줄 계약으로 접지 않는다.

현재 구현은 새 빌드와 Native/fresh WASM·원본 전체 재검증 전이다. 확대 판독과
아래첨자 병존의 잔여 결함을 판정한 뒤 새 관계형 회귀를 추가한다.

새 Native 빌드는 exit 0, source hash 유지 true, 296.85초다. immutable binary
