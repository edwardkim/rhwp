# #7642 Stage 169 — 수식·미주를 포함한 저장 글줄의 표 진입 간격

## 독립 관측과 원인 경로

9월 2022 HWP 원본 전체 23쪽의 Stage 167 Native 결과는 4쪽만 78.47295%다.
이전 source 164의 같은 입력/독립 Print와 PNG 바이트가 같으며, 현재 미주 컷
수정으로 생긴 회귀라고 판정하지 않는다. 사용자의 현재 브랜치 보정 지시에 따른다.

독립 한컴 2020 Print PDF의 4쪽 오른쪽 단 첫 확률분포 표 위 괘선은
81.51099pt다. 원본 문단 242의 저장 줄은 원점 0, 높이 900HU, 후행 간격
452HU이고, 다음 TAC 표 문단 243의 원점은 1352HU다. 표의 저장 높이 3279HU와
실제 Native 표 높이는 일치하지만 위쪽 원점은 102.7px다. 동일 좌표계의 PDF
원점은 약 108.68px이며, 표 이후 문28·29의 시작도 같은 후행 간격만큼 위에 있다.
px 관측은 진단이며 구현 분기나 회귀 기대값으로 사용하지 않는다.

문단 242에는 선두 미주와 글줄 안의 `rm X` 수식이 있다. 수식은 TAC이며
원본 높이 900HU로 글줄 높이 안에 포함된다. 진단은 표 진입 당시 물리 흐름
12.0px를 기록한다. 다단의 저장 문단은 후행 간격을 fit에서 제외하고 뒤 원점이
복원해야 하지만, `stored_tac::prepare`의 앞 글줄 검증은 controls가 하나라도
있으면 거부한다. 이 때문에 유효한 저장 연결 0+900+452=1352를 사용할 수 없고
일반 TAC 흐름으로 돌아가 뒤 간격 전체가 사라진다.

## 보정 계약과 반례

앞 문단의 제어가 존재하는지와 독립된 몸체를 배치하는지는 다르다. 선두 미주
표시와 TAC 수식을 포함해도 유효한 저장 글줄의 높이·내용 끝이 실제 소비한
물리 끝과 일치하면 그 글줄의 후행 간격을 표 진입 밴드로 사용할 수 있다.
일반 폭 중립 marker는 기존 composer 분류를 재사용한다. 별도 float, 표·그림·
도형·폼 등 독립 배치가 있는 앞 문단은 기존 일반 경로로 유지한다.

편집/합성 줄은 수용하지 않는다. 저장 태그·문자 분할, 이전 줄 끝+후행 간격+
문단 간격=다음 줄 원점, 실제 물리 끝과 저장 내용 끝의 일치, 가용 높이를
모두 확인한다. 이 기존 조건을 완화하거나 문서 ID·미주 번호·px 임계값으로
선택하지 않는다. helper의 원점과 점유 끝을 fit와 paint가 함께 소비하고 후속
문단을 그 원점에서 진행시킨다.

## 검증 순서와 현재 상태

Stage 168의 Native/fresh WASM 빌드·원본 검증이 실행 중이므로 이 문서는 다음
보정 계획이다. 생산 소스는 검증 중에 바꾸지 않는다. 종료 뒤 보정하며 같은
9월 HWP 전체 23쪽과 독립 Print의 Native/fresh WASM TSV·대표 PNG를 확인한다.
HWPX 짝, 미주 경계, 앞 제어 없는 정상 글줄과 독립 float 대조군을 유지한다.
관련 전체 페이지가 90% 이상이고 확대 판독이 끝난 뒤 새 이름의 관계형 회귀를
추가하며, 내용 소속·표와 앞뒤 문단의 순서·보존·겹침을 검사한다. 수정 전 FAIL /
수정 후 PASS를 실제 호출 경로에서 확인한다.

전체 55개/853쪽, 추가 64쪽·실패 원본과 전체 Rust/lint, 최신 devel 동기화,
PR·CI·후속 처리는 미완료다. 이 단계의 계획을 검증 통과로 보고하지 않는다.

## 구현

선행 Native/fresh WASM168의 HWPX 23쪽 전체 게이트가 끝난 뒤 보정했다.
앞 문단의 제어가 TAC 수식, 각주/미주 표시 또는 기존 폭 중립 marker일 때
유효한 저장 연결을 검증한다. float·표·그림·도형·폼 등 독립 몸체를 배치하는
제어는 계속 이 단축 수용 경로에서 제외한다. 저장 유효성, 원래 사다리 등식,
실제 소비한 물리 끝과 저장 내용 끝의 일치, 가용 높이와 공통 원점/끝의 소비를
보존했다. 조판 코드 한 곳의 계약 검사만 바꾸며 px 보정이나 특정 문서 선택은 없다.

새 빌드·HWP 전체 Native/fresh WASM, 대조군과 정식 새 관계형 회귀는 아직
실행하지 않았다. 이후 단계에서 실제 수정 전후와 독립 Print로 판정한다.

## Native 재검증

새 Native 빌드는 exit 0, source hash 유지 true다. HWP 원본 전체 23쪽을
같은 독립 Print로 재산출했다. 쪽수 23/23, 최저 91.84074%, 미달 0쪽,
source hash 유지 true, exit 0, 330.097초다. 4쪽은 78.47295%→97.74341%다.
새 대표 review는 `mydocs/pr/assets/issue7642-inline-table-entry-20261012/`에 있다.
fresh WASM도 전체 23/23쪽, 최저 91.84074%, 미달 0쪽,
source hash 유지 true, exit 0으로 완료됐다. 새 WASM 4쪽 review는
같은 assets 경로의 `wasm169-p004-review.png`이고 점수는 97.74341%다.
11쪽 큰 괄호의 첨자 위치는 별도 보정 대상으로
남기며 이 Native 결과로 최종 완료·새 회귀·PR 승인을 대신하지 않는다.
