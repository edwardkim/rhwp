# 이슈 #7642 Stage 48 — 미주 소유에 따른 실제 경계 원점

Issue: #7642

## 독립 근거와 실패 경로

시작 source는 `0a3c80d3f3beabf3105f31c6b2271bf34624b46d`다. 2022 HWPX의
잘못된 제목 이월은 18/19쪽 97.51434%·97.72020%로 개선했지만 2023 HWP/HWPX
19쪽은 각각 79.50462%·79.49588%다. Native fit은 앞 내용의 실제 끝과 섹션
미주 간격으로 원점을 계산하지만 뒤 HeightCursor가 같은 값을 덮어쓴다.

`stage47-all04-vpos.log`의 실제 호출은 앞 줄 점유 457.7733, 간격 1984 HU에서
고정 18px를 더해 502.2267을 반환한다. 한컴 Print의 제목은 앞 줄 점유와 해당
간격을 한 번 소비하는 위치다. 다줄이라는 이유로 임의 완충을 추가할 근거가 없다.

## 공통 원점 계약과 반례

- 같은 단에 앞 미주의 마지막 줄이 있고 현재 항목이 다른 미주의 첫 줄을 소유하는지
  기존 `starts_note_after_complete_tail`로 확인한다. 제목 문자열·문서 ID를 근거로 쓰지 않는다.
- 실제 paint의 내용 끝·빈 줄을 포함한 흐름 줄 상자 끝과 섹션 gap을 공통 원점으로
  만든다. 현재 커서가 gap을 이미 소비했으면 다시 더하지 않는다.
- HeightCursor는 이 소유 원점과 다음 저장 사다리의 기준을 함께 소비한다. 저장 vpos
  점프·18/40px 완충으로 실제 예약을 덮어쓰지 않는다. 원점이 없는 첫 미주·같은 미주
  내부·이월된 tail을 완성하지 않은 조각은 기존 경로를 유지한다.
- 실제 한 줄이 단에 들어가지 않는 경우는 이 원점 유지의 적용 대상이 아니다. 새
  clamp나 출력을 숨기는 분기를 추가하지 않고 pagination의 실제 fit을 확인한다.

2024년 9월 20/20 HWP/HWPX의 8쪽 그림은 독립 PDF x=173.1867/y=229.0293에
있고 현재 Native x=173.1/y=105.3이다. 원본 Picture는 본문 429/control 21,
Para 상대 Square, 원본 offset 1093 HU다. 저장 줄의 앞 6개는 전폭이고 뒤 4개는
좁은 차선이다. 가로 배치는 맞으므로 이 차이를 글꼴 문제로 분류하지 않는다.
원본 control 위치와 저장 줄/전폭 구성 producer를 먼저 추적하고, 좁은 줄과
겹친다는 이유만으로 새 소유 예외를 만들지 않는다.

## 검증 범위

관련 미주 원점 수정과 그림 앵커 진단을 한 묶음으로 빌드한다. 2023 HWP/HWPX 19쪽,
2022 HWPX 18/19쪽과 2024 9월 20/20의 영향 페이지, 11월의 기존 다섯 쪽수 대조군을
확인한다. 정상 한컴 저장 수식의 큰 크기 수직 차이는 별도 실제 glyph/프레임 분석을
계속한다. 기존 source의 전체 Native 측정은 중단하지 않고 변경 전 근거로 보존한다.
회귀 기대값은 아직 변경하지 않는다. 최신 Native/fresh WASM 전체 페이지·수식 확대
판독의 선행 조건을 충족한 뒤 관계형 검사를 변경한다.

## 수식 확대 재측정과 독립 수직 계약

Stage 47 frozen source의 원본 11월 9/8/7 HWPX 10쪽은 97.48253%, 같은 미주 7의
수식 소유 줄 483~486 영역은 96.77507%다. 변경 전 확대 86.02059%에서 개선됐다.
새 이미지를 직접 열어 합 다음 분수·근호·뺄셈·뒤 숫자의 전진을 확인했다. 전체
문서 또는 fresh WASM의 완료 판정으로 확대하지 않는다. 증적은 ignored
`source-math-spacing-note7-detail/provenance.json`과 새 `review/review_001.png`다.

성분 Print job `8823bfb7-1665-4a38-bcb4-3fc66ab3577c`도 한컴 2024
`13.0.0.3901`, `pdf_print_method=0`, `frame_print_to_pdf_ex_one_up`으로 완료했다.
PDF SHA-256은 `e3dc926c19a2bfc2427749a06b6537467bf05619af1871e9629827ea76f370ab`다.
32개 성분 한 쪽의 Native 보조값은 97.93179%다. 이 평균적인 쪽 점수로 개별
큰 합 기호의 수직 위치를 면제하지 않고 복합 수식의 2쪽 미달 원인을 분석한다.

단순 `1 over 2`를 네 글자 크기로 독립 Print한 결과에서 본문 기준선과 분수선
중심의 간격은 명목 em당 0.32826으로 일치한다. 실제 PDF 글자 변환 배율을
분리하면 약 0.3285em의 원문 수학 축이며, 현재 대체 표시 글꼴의 TeX 0.25em
축과 다르다. 분수선·큰 연산자·연산자 glyph가 어느 축을 소비하는지 함께 추적한다.

현재 임의로 전체 수식을 위로 옮기거나 프레임에 압축하지 않는다. 실제 논리 축과
표시 글꼴의 glyph 축을 분리해 공통 layout 결과로 전달할 범위를 먼저 확인한다.

`stage48-independent-sum-axis.json`, `stage48-saved-probe-page2-text-object-matrices.json`에
독립 글자 객체 원점·변환·bounds와 관측값을 보존했다. 이 분석 자체를 구현 완료로
판정하지 않는다.

## 구현과 Native 검증 결과

완성 미주 경계의 실제 원점을 렌더러가 HeightCursor에 전달하도록 했다.
커서는 해당 원점을 반환하면서 뒤 저장 사다리 기준도 같은 위치로 연결한다.
제목 문자열·고정 18/40px 분기는 이 경계의 실제 원점을 덮어쓰지 않는다.
일반 본문 커서는 경계 원점을 제공하지 않는다. 첫 미주, 같은 미주 내부와
완성 tail을 소유하지 않은 조각도 종전 경로를 사용한다.

초기 컴파일은 일반 본문 커서의 새 필드 초기화 한 곳 누락으로 E0063, exit 101이었다.
해당 초기화를 보완한 뒤 Native release-test 빌드는 476.64초, exit 0이다.
source 1453개 파일의 빌드 전후 해시를 대조했으며 frozen binary SHA-256은
`c6161fba905543b89d6da4775cc587b5e10e433e178bffcbe0d40b20514b0414`다.
fmt check 22.41초·Native Clippy 106.05초, 둘 다 exit 0이다.

2023 HWP 19쪽의 새 review를 직접 열어 문29 제목·본문·그림의 간격 개선을 확인했다.
아래 변형 수식의 미세 간격은 별도 확대 판독을 계속한다. 위 선택 쪽의 통과는
55문서 전쪽·fresh WASM·정식 관계형 회귀의 완료를 뜻하지 않는다. 20/20 HWP/HWPX
영향 페이지 비교도 아직 실행 중이다. canonical summary와 실제 exit code는 ignored
`owned-note-origin-focused-native/queue.json`에 보존한다.

그림 앵커의 실제 입력은 `instance_id=2095277206`, control 21, raw UTF-16 시작 347,
유효한 저장 줄 10개, dirty=false다. `stored_picture_anchor_delta`의 입력 로그는 있으나
저장 앵커 또는 전폭 앵커를 반환하는 로그는 없다. 전폭 composer의 admission은
같은 문단에 중첩 Endnote가 있어 이 경로를 거부한다. 그 뒤 0 원점 폴백이 그림을
앞으로 배치한다. 근거는 ignored `stage48-picture-anchor-debug.log`, 원본 모델은
`stage47-all10-source429.json`이다. 이 거부 조건을 실제 근거 없이 전역 완화하거나
좁은 줄 위치만으로 소유를 추정하지 않고 해당 앵커 계산 경로를 후속 보정한다.
