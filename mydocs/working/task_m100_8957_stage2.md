Native Skia 공식 3종, 최적화 fresh WASM을 통과했다. 표지 4종은 각 전체 1쪽에서 양쪽 raw

독립 PDF·직접 판독·전쪽 TSV·실행 요약은 [최종 근거](../pr/assets/issue8957/final-validation/README.md),

드라이버 차이는 공통 조판에 반영하지 않았다. 아래 절은 구현·검증 순서별 기록이다.

## 구현 전 근거와 경계

- #741 → #753(`a90ecd09b476c7909ca52c628b6ba86b0a454967`)는 연결 경로 보존과 **화면**의 대체 표시 계약이다.
- #2225의 원래 인쇄 계약은 그림 미지정의 화면 표시/인쇄 생략이다.
- #8858 → #8865(`eb02dc39e782c717d87f23f42de114c36272b556`) → 통합 `ad2649ded2` / #8923
  (`e118de8abadd2dffb2798036b9ffd381b96ed7d5`)은 외부 경로 없는 ImageNode까지 같은 처리를 적용했다.
  독립 2쪽 입력·전쪽 TSV와 기존 회귀가 있으며 현재 base에도 그 계약이 있다.
- 이번 표지는 HWPX manifest에 `isEmbeded=0`인 oracle.gif/rdb02.gif/s1.jpg의 옛 Windows 경로가 있다.
  한컴 2024 자체 Print와 사용자 Microsoft Print는 해당 그림 자리를 비우지만 rhwp는 대체 상자를 인쇄한다.
- 인쇄 설정 반례: 같은 표지의 첫 그림만 저장소의 oracle.gif로 내장한 대조본에서 한컴 2024는
  정상 그림 하나를 출력하고 미해결 연결 그림 둘만 비웠다. 입력 section·줄·그림 크기·여백은 그대로다.
  따라서 전체 그림 인쇄 비활성화로 설명되지 않는다. job `8663c286-3140-4b3a-a11a-9396b0b3d36a`,
  한컴 `13.0.0.3901`, Print method 0, `frame_print_to_pdf_ex_one_up`, input preprocess none, 1쪽이다.

원인 계층은 공통 paint의 인쇄/편집 표시 정책이다. `ImageNode`의 데이터·외부 경로 상태 →
`LayerBuilder::build_node`의 profile 분기 → 공통 PaintOp/backend가 소비한다. 레거시 SVG도 같은
판정 함수를 소비한다. 측정·실제 배치는 기존 RenderTree bbox와 저장 줄을 그대로 쓰며 이 변경은
최종 인쇄 paint에서 편집용 표시만 제외한다. 그림의 흐름 점유, 문단 소속과 4.26pt 보정을 바꾸지 않는다.

새 계약은 기존 그림 미지정 또는 **그림 개체·외부 경로 있음·공급 데이터 없음/빈 데이터**다.
실제 바이트가 공급된 연결 그림, 정상 내장 그림, 채우기 이미지는 제외 대상이 아니다.
외부 데이터의 디코딩 실패를 이 관찰만으로 확대 판정하지 않는다.

## 검증 진행

최신 base/후보의 Native·fresh WASM, 보통/굵게/정상 그림 혼재 대조, 기존 4.26pt·Print 프레임·
합성 굵기 보호, 리베이스 반영 기능과 필수 제출 게이트를 실행한다. 미실행을 통과로 기록하지 않는다.

### 기존 배치와 정상 그림의 소비 경계

`layout/picture_footnote.rs`의 ImageNode와 캡션은 같은 부모의 별도 자식이며,
`tac_picture_item.inc.rs`의 실제 그림과 명시 테두리도 별도 노드다. 이번 판정은 ImageNode의
편집용 대체 표시만 제외한다. 캡션·명시 테두리·RenderTree의 bbox·저장 줄 정보는 바꾸지 않는다.
기존 #1142/#1143의 연결 그림 검색·주입·캐시 무효화 계약과 #741 화면 표시 계약은 유지 대상이다.

### 최신 기준의 실제 재검증

- 기준 바이너리는 `80b1c354c29b7a02fb2b3c14a274da7f5b653ada`에서 별도 검증 사본으로 빌드했다.
  Native SHA-256 `3768906b9ee18d14692c1f4af34e32921417b80c5e0f7ccd15340472730bd27d`.
  최적화 WASM은 locked wrapper와 wasm-opt를 완료했다. 임시 로그·중간 산출물은 T7의 `output/`에만 둔다.
- 최신 기준의 14자 SVG 원점은 v0.9.0 대비 모두 x −4.26pt이며 기준선과 크기는 같다.
  첫 글자는 `(211.62, 708.82)pt`, 마지막 글자 x는 `475.58pt`, 크기는 `18pt`다.
  이는 SVG의 기존 정렬 보존 기준이며 수정본 Native/WASM의 전진폭 검증을 대신하지 않는다.
- #8858의 2쪽 원본은 최신 기준 Native 98.54/99.15%다.
- 기존 HWP sample10의 보호 페이지 509/757쪽은 최신 기준 Native/WASM 각각 99.90/99.55%다.
  763쪽 중 이 두 쪽의 보호 비교이며 전쪽 검증으로 표현하지 않는다.
- #8896/#8945의 8개 표 끝·행 나눔 대조 원본은 전체 14쪽에서 최신 기준 Native/WASM 모두
  100.00%다. 새 후보에서도 같은 조건으로 실행해 비교한다.
- 리베이스로 들어온 #8958의 39개 기능은 기존 검토의 44개 입력 조건·주장 88쪽과 전체 쪽수를
  같은 조건으로 비교한다. 표 배치·캡션·그림 밴드·HFT 원 프로그램·공급 글꼴 환경·Canvas paint 순서가
  공통 소비 경로다. 추가되는 딸기 family와 미해결 연결 그림 조건 외의 원래 동작을 바꾸지 않았다는
  코드 대조와 실제 base/head 출력 대조를 함께 사용한다. CI 운영·문서 변경은 렌더러 소비 경로 밖이며
  해당 workflow나 정책 구현은 이번 후보에서 수정하지 않았다.

WASM 대조의 초기 공개 글꼴 공급만으로는 Native가 선택한 웹폰트 환경이 전달되지 않았다.
기존 검토의 글꼴 해시를 추적하고 Native에서 확정한 프로그램·환경과 필요한 OS Times New Roman
4종을 WASM에도 명시 공급했다. #8788의 3쪽은 초기 77.73%에서 동일 공급 후 99.75%로 회복됐다.
초기 실행은 보존하고 최종 비교로 사용하지 않는다. 실제 문서 출력의 허용치·기준 PDF를 바꾸지 않았다.

현재 항목들은 기준 측정이다. 후보 및 전체 필수 게이트가 끝나기 전에는 PR 준비 완료로 판정하지 않는다.


### 후보의 표지 전쪽·직접 판독 완료

Native Skia와 최적화 fresh WASM에서 굵게·보통·전진폭 대조·정상 그림 혼재 네 입력이
각 전체 1쪽 raw 100.00%다. 양쪽에서 제목·14자 본문·여섯 행의 간격과 기준선,
정상 그림·미해결 연결 그림 자리를 같은 배율로 직접 판독했다.
정식 근거는 `mydocs/pr/assets/issue8957/linked-print/`다.
Native Skia 바이너리 SHA-256은 `f72ce1276b55f34f4a26a9e4e1cfdd4738ab89ecdf4b943fce4e519f691fa4e5`다.
초기 옵션 누락 Native CLI의 PNG 시도는 실행 실패이며 통과 증거로 사용하지 않는다.

새 관계형·그림 수 회귀를 시각 선행 조건 확인 후 등록했다. 기존 보안 검사의 basename 안내는
화면 계약으로 명시하고 인쇄에서 안내·작성자 경로가 노출되지 않는지도 확인한다.
기존 테스트의 XML 예산·비이미지 거부·정상 연결 그림 공급 계약은 바꾸지 않았다.
같은 원본을 참조하는 #1142/#1143과 변환·글꼴 선언 검사에는 제거할 절대 px 핀이 없었다.
#8730의 Square 저장 줄 검사는 원본 cs/sw 관계형 계약을 유지한다.
최종 커밋의 전체 필수 검증은 이어서 실행한다.


### 전체 회귀의 기존 합성 입력 점검

#1197 → #1252의 원 해결과 메인터너 보정 `3bd66137f74a9fa9ff4239cf5c3947d495da10a1`,
그 보정의 검토 문서·독립 시각 판정, 후속 stableIndex 변경 `3879f85b`를 추적했다.
현재 z-order 회귀는 실제 그림 대신 `data=None` + `external_path=Z11_IMAGE`의 안내문을 그림
표지로 사용했다. #8957의 유효한 인쇄 계약에서는 이 안내가 없어지므로 그 입력 전제를 고쳤다.
직접 생성한 1px PNG를 공급하고 실제 `<image>` 한 개를 식별한다. 기존 바탕쪽 → 낮은 표 → 그림 →
높은 표 → 전면 도형의 모든 순서 assertion은 유지한다. 정렬 구현이나 기대 순서를 바꾸지 않았다.
시각 선행 조건은 정상 그림/미해결 연결 그림을 분리한 #8957 두 원본의 전쪽 양쪽 100%와 직접 판독이며,
이를 #1197 실물 원본 전체의 새 측정값으로 표현하지 않는다.

초기 전체 회귀의 다른 실패는 sparse 검증 사본의 동적 파일명·JSON 원장 참조 입력 누락이었다.
해당 커밋의 Git blob·파일 모드를 그대로 복원한다. 테스트 허용치·baseline을 바꾸지 않고 새 head에서
전체 회귀를 다시 실행한다. 초기 실패 로그는 비공개 output에 보존한다.
