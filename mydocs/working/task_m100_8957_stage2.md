## 구현 전 근거와 경계

- #741 → #753(`a90ecd09b476c7909ca52c628b6ba86b0a454967`)는 연결 경로 보존과 **화면**의 대체 표시 계약이다.
- #2225의 원래 인쇄 계약은 그림 미지정의 화면 표시/인쇄 생략이다.
- #8858 → #8865(`eb02dc39e782c717d87f23f42de114c36272b556`) → 통합 `ad2649ded2` / #8923
  (`e118de8abadd2dffb2798036b9ffd381b96ed7d5`)은 외부 경로 없는 ImageNode까지 같은 처리를 적용했다.
  독립 2쪽 입력·전쪽 TSV와 기존 회귀가 있으며 현재 base에도 그 계약이 있다.
- 이번 표지는 HWPX manifest에 `isEmbeded=0`인 oracle.gif/rdb02.gif/s1.jpg의 옛 Windows 경로가 있다.
  한컴 2024 자체 Print와 사용자 Microsoft Print는 해당 그림 자리를 비우지만 rhwp는 대체 상자를 인쇄한다.
- 인쇄 설정 반례: 같은 표지의 첫 그림만 저장소의 oracle.gif로 내장한 대조본에서 한컴 2024는
  정상 그림 하나를 출력하고 미해결 연결 그림 둘만 비웠다. 입력 section·줄·그림 크기·여백은 그대로다.
  따라서 전체 그림 인쇄 비활성화로 설명되지 않는다. job `8663c286-3140-4b3a-a11a-9396b0b3d36a`,
  한컴 `13.0.0.3901`, Print method 0, `frame_print_to_pdf_ex_one_up`, input preprocess none, 1쪽이다.

원인 계층은 공통 paint의 인쇄/편집 표시 정책이다. `ImageNode`의 데이터·외부 경로 상태 →
`LayerBuilder::build_node`의 profile 분기 → 공통 PaintOp/backend가 소비한다. 레거시 SVG도 같은
판정 함수를 소비한다. 측정·실제 배치는 기존 RenderTree bbox와 저장 줄을 그대로 쓰며 이 변경은
최종 인쇄 paint에서 편집용 표시만 제외한다. 그림의 흐름 점유, 문단 소속과 4.26pt 보정을 바꾸지 않는다.

새 계약은 기존 그림 미지정 또는 **그림 개체·외부 경로 있음·공급 데이터 없음/빈 데이터**다.
실제 바이트가 공급된 연결 그림, 정상 내장 그림, 채우기 이미지는 제외 대상이 아니다.
외부 데이터의 디코딩 실패를 이 관찰만으로 확대 판정하지 않는다.
