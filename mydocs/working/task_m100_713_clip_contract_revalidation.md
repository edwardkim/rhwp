# 이슈 #713 — 셀 viewport와 실제 행 분할 계약 재검토

## 기존 해결과 현재 실패

- 원 해결 [PR #715](https://github.com/edwardkim/rhwp/pull/715)의 목적은 페이지 끝에
  대상 행의 작은 조각만 남기는 현상을 방지하는 것이다. 원격 PR은 closed이고 GitHub의
  `merged`는 false다. 저장소의 수용 커밋 `d4efc29aa1`과 원 보정 `3bb8719162`를 구분한다.
- 최초 검사 `e2fb974b50`는 `clip=false`를 행 전체 이동의 대용 지표로 사용했다.
  [당시 분석](archives/task_m100_713_stage2.md)은 `RowBreak`라는 내부 이름을 근거로
  셀 내부 분할을 금지한 초기 가설을 이미 폐기했다.
- 현재 [정오표 §35](../tech/hwp_spec_errata.md#35-table-쪽-경계-속성-값-2--나누지-않음-중복-기재)는
  원시 값 2를 HWPX `CELL`과 대응시킨다. 내부 이름으로 행 경계 전용 정책을 추정하지 않는다.
- `upstream/devel` 기준은 `7fdd5441ff1e77c083818e920a48089f294de35e`, 검증 head는
  `895205d5a7c9a545997e4d4248dcceac6c9314f9`다. 제품 코드는 `4b149b6cdf`와 같다.

전체 최소 글꼴 회귀에서 `issue_713_rowbreak_table_no_intra_row_split`가 실패했다.
실제 관측은 전체 35쪽, 대상 row 8의 셀 5개가 모두 같은 0-based 31쪽에 있으며
`clip=true`다. 한 페이지 소속 검사는 통과했고 clip 플래그 검사만 실패했다.
clip은 viewport 제한에도 쓰이므로 이 플래그만으로 실제 행 분할을 판정할 수 없다.

## 독립 기준과 보정 전 확인

원본은 `samples/2022년 국립국어원 업무계획.hwp`, 기존 독립 Print는
`pdf/2022년 국립국어원 업무계획-hwp-2020.pdf`다. PDF metadata의 실제 작성 제품은
한컴 2022이며 전 35쪽이다. 새 PDF를 출력하거나 기존 기준을 교체하지 않는다.

먼저 같은 원본·Print의 전쪽 Native/fresh WASM, 대상 표의 앞 조각·다음 조각과
row 7/8/9의 내용 소속·누락·중복을 확인한다. 두 경로 전쪽 90%와 확대 판독을 마치기 전에는
기대값을 바꾸거나 새 회귀를 등록하지 않는다. 실제 회귀이면 구현을 고친다.

잘못된 대용 지표로 확인되면 원래 목적을 유지하는 새 이름의 관계형 검사로 보호한다.
대상 원본 셀 전체의 존재·고유한 열 소속·한 페이지 소속·내용 보존을 확인하고,
paint viewport 제한과 실제 내용 분할을 구분한다. 고정 px 임계값을 다시 도입하지 않는다.

원시 실패 로그는 `output/pr-review/planet6897-20261103/logs/rebase-895205d5a7-full-nextest-minfont.log`,
Native 비교는 `logs/rebase-4b149b6cdf-issue713-native.log`다. 현재 검증 진행 중이며
이 문서의 원인 분석을 시각 검증 완료나 회귀 보정 완료로 표시하지 않는다.

## 실제 검증 결과

기본 전체 회귀는 12,558건 중 12,557 PASS, 이 검사 1 FAIL, 45 skipped로 종료됐다.
실제 nextest 종료 코드는 100이며 `logs/rebase-895205d5a7-full-nextest-minfont.exit`에 있다.
Native Skia를 명시한 최소 글꼴 집중 검사는 최신 base와 현재 후보 양쪽에서 통과했다.
기본 전체 실행과 Native 집중 실행의 빌드 구성을 혼동하지 않는다. 같은 기본 전체 빌드 구성을
유지하고 검사 선택만 제한한 실행을 추가해 차이를 확인한다.

| 물리 쪽 | 현재 Native raw | 최신 base 7fdd5441ff Native raw |
| ---: | ---: | ---: |
| 31 | 78.32835% | 78.27216% |
| 32 | 99.94705% | 99.94707% |
| 33 | 40.25603% | 40.25603% |

두 제품 모두 전 35쪽이며 독립 Print와 쪽수가 같다. 최저 40.25603%로 문서의 시각 선행 조건은
최신 base에서도 충족하지 못한다. 33쪽 PNG SHA-256은 두 제품 모두
`c4f43616d53ebdf4c498fd4906cb8abab06d691792d5f19b33508416687eca6e`다.
이전 base `1924d371d6`도 같은 33쪽 PNG였지만 이 과거 실행을 최신 base 실행으로 대신하지 않았다.

32쪽 review/overlay에서 대상 행의 다섯 열과 한국어교육 지원·교원 자격·연수 내용이 한 번씩
같은 페이지에 표시됨을 확인했다. 33쪽은 내용 누락 대신 제목 상자와 뒤 본문의 세로 위치가 다르다.
이는 32쪽의 행 조각 검사가 원래 보호하려던 증상과 구분한다. 문서 전체 통과로 표시하지 않는다.

`TableCellNode.clip`은 셀 viewport 제한에도 사용한다. 실제 쪽 조각 여부는 별도
`page_fragment`와 시작·끝 컷이 소유한다. 따라서 `clip=true`만으로 행 내부 분할을 판정한
기존 assertion은 적절하지 않다. 현재 코드를 무조건 통과시키기 위해 이 값을 바꾸지 않는다.
원본 셀의 존재·열 소속·내용 보존·중복 및 실제 조각 소속이 원래 목적에 해당한다.

원격 이슈 검색의 같은 문서 관련 23건은 모두 closed였고 이슈 #7445 본문에도 이 원본은 없었다.
원래 행 조각 문제와 별개의 제목·본문 원점 미달을 원래 이슈가 해결했다고 확대하지 않는다.
새 회귀 등록이나 기존 기대값 변경은 시각 선행 조건과 별도 이슈 절차를 확인한 뒤 처리한다.
현재 테스트 파일과 제품 구현은 변경하지 않았다.

최신 base Native 제품 SHA-256은
`a02afdf7440e8cb987fc8d2bd074023278422a91067ffd0bc2e5b8f1601d1bd1`다.
base 집중 검사와 전쪽 비교는 각각 `logs/base-7fdd5441ff-issue713-native-test.log`,
`logs/base-7fdd5441ff-issue713-native-visual.log`이며, 현재 Native 집중 검사는
`logs/current-895205d5a7-issue713-native-test.log`다.

## 기본 전체 빌드 구성에서의 단독 재현

전체 실행과 같은 `cargo nextest ... --tests`·feature·최소 글꼴·보안 입력 환경을 유지하고
`-E 'test(/(^|::)issue_713::/)'`로 실행 대상만 제한했다. 같은 셀 5개가 0-based 31쪽에
모였고 clip 5개를 이유로 다시 실패했다. 1건 FAIL, 12,602건 필터 제외, 종료 코드 100이다.
이는 Native feature를 추가한 집중 실행의 통과로 덮어 쓰지 않는다.

Native 집중 실행의 동일 실행 파일을 추가 컴파일 없이 진단 실행해 같은 35쪽·같은 셀 5개·같은
페이지 소속에서 clip 0개임도 확인했다. 실행 파일 SHA-256은
`22edaea7ef8a6e699bd74f656d3a41af8dec6ac2f32d624cfcead41a79351cc5`다.
이 반복 진단은 별도의 새 회귀나 추가 커버리지로 집계하지 않는다.

판정은 **원래 행 조각의 회귀를 검출하는 조건으로 clip=false를 고정한 부분이 부적절함**이다.
셀 viewport 제한과 실제 내용 분할은 구분해야 한다. 행의 한 페이지 소속은 유효한 보호 목적이며,
셀 수·열 소속·전체 내용·누락·중복을 함께 확인해야 한다. 원래 결함이 현재 다시 나타났다는
근거 없이 구현을 되돌리지 않는다. 기본 구성과 Native 구성에서 같은 플래그를 기대해서도 안 된다.

원시 재현 로그는 `logs/current-895205d5a7-issue713-stock-graph.log`, Native 진단은
`logs/current-895205d5a7-issue713-native-stdout.log`다. 문서의 base 미달과 부적절한 검사 조건은
별도로 기록하며 기존 검사·기대값은 이 검증 단계에서 수정하지 않았다.

## 정본 절차에 따른 이관과 보존

검증 뒤 같은 원본·미해결 범위의 열린 이슈를 다시 검색해 0건임을 확인하고
[이슈 #8598](https://github.com/edwardkim/rhwp/issues/8598)을 등록했다. 담당자는
`jangster77`이며, source·원본·PDF 해시·base/head 전쪽 Native TSV 원문과 복원 조건을
본문에 기록했다. 원래 이슈 #713을 재발로 다시 열거나 #7445에 자동 편입하지 않았다.

정본은 Native만으로 base 미달이 확인된 경우도 이관을 허용한다. fresh WASM까지 측정한 것으로
표시하지 않았다. 원래 2022 PDF도 별도로 확인했으며 31·32·33쪽의 픽셀이 이번 기준 PDF와 같다.
새 Print를 만들거나 유리한 기준으로 바꾸지 않았다.

[보존 자산](../pr/assets/issue_8598/README.md)에 모듈 전체 `.rs.txt`, 복원 원장,
전쪽 base/후보 Native TSV와 31·32·33쪽 review/overlay를 보존했다. 검사 source blob과
사본의 바이트·SHA-256 일치를 확인했다. 사본 추가만으로 자동 수집 목록이 바뀌지 않았고,
활성 제거 후 모듈 집합의 차이는 `tests/issue_713.rs` 한 개뿐이다. 검사 함수 감소도 1개다.

공유 원본 HWP·두 PDF는 정상 메타데이터·추출·보안·parser/serializer·편집 계약에서 사용하므로
기존 경로·바이트를 유지한다. 그 계약들과 다른 문서의 검사를 함께 제거하지 않는다.
이관된 출력 결함은 이 통합 PR의 해결·Closes 범위에 포함하지 않는다. 올바른 전쪽 출력과 확대
판독을 완료한 뒤 새 이름의 관계형 회귀로 복원한다. 파생 suite는 검토 worktree에서 재생성한다.
