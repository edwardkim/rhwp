# 저장 글줄의 쪽 컷과 말미 전진 소유 보정

## 앞 단계와 관측

[회귀 계약 보정](task_semanticist21_20261023_regression_contracts.md)은 커밋
`0f56459349`에 고정했다. 이 단계는 #4138 현재 API 저장본의 실제 196쪽 Print와
내용 컷 차이를 해결한다. 기존 197쪽 기대값을 쪽수 일치만으로 바꾸지 않는다.

실패 입력 SHA-256은 `9ae8200417a39b912b36044a7371e9e3946afe21bc884beec868076f15c63ab8`이며,
현재 Print PDF SHA-256은 `4a68e97d690d7f4a3d15f11e1364f957ba5448684aa5210586fb33b951add781`이다.
실제 2024 Print 계약과 빈 스크립트 저장 스트림의 증명은 앞 단계 보고서에 있다.

같은 고정 Native142에서 편집 전 원본의 첫 두 쪽은 raw 99.98006%·100%다
(`issue1949-original-native142-diagnostic-2248`). 115쪽 전체의 완료 증거로 해석하지 않는다.
편집 저장본은 compat 2022·2024 모두 196쪽 중 195쪽 미달이며 최저 17.92141%다.
2쪽은 Native가 앞 쪽에서 한 줄을 더 소비해 나머지 문단도 위로 올라갔다.

작업 중 증거는 ignored `output/pr-review/semanticist21-20261019/`에 보존했다.
`issue4138-line-alignment-2249.json`, `issue4138-unit-prefix-2251.json` 및
`logs/issue4138-unit-trace-2250.log`를 대조했다. 셀 좌표가 같은 중첩 표의 trace와
최상위 7,519개 유닛 stream을 구분했다. 첫 컷 0..38은 전진 높이 971.2px이고
활성 내용 예산은 962.093px다. 저장 말미 줄간격 9.6px를 빼서 961.6px로 수용하지만
한컴 Print의 다음 쪽 첫 줄은 이 컷이 앞 쪽에서 추가로 소비한 줄이다.

## 원인 경로와 독립 근거

`CellUnit.height/following_line_advance` 생산 → `row_physical_band::cut_trailing_advances`
→ `native_saved_reset_cut_trailing_trim` → `stored_plain_cut_closing_advance`의 차감 →
수용된 `RowCut.end_cut`과 부분 표 paint의 같은 source 유닛 소비를 추적했다.
연속된 저장 줄이라는 사실만으로 다음 물리 쪽에 말미 줄간격을 넘길 수 있다는 가정은
이 Print 출력과 맞지 않는다. 이 원본의 저장 슬롯은 synthetic이 아니고 같은 문단 안에서
진행하며 실제 페이지 프레임 재시작의 증언은 없다. 잉크 끝과 줄 슬롯 수용량을 구분해야 한다.

해당 helper는 `429dee416e64e26ae6b66e0e7f395caf35e0735b`, PR #7877에서 들어왔다.
원 PR 본문을 `pr7877-cut-provenance-2252.json`에 읽어 보존했다. 원 PR은 병합 칸의
이어받기 정렬·빈 문단·후속 본문 소유와 #7704 성능 개선을 함께 다뤘다. 검증된 19문서·835쪽과
`tests/fixtures/pr7704_manual_reflow/MANIFEST.json`을 후퇴 검증 범위에 포함한다.
수동 저장 줄 대조군은 그 생성 방식과 Print 결과로 한정하고 일반 수용 규칙의 근거로
승격하지 않는다. 원 기여 성능 개선을 새로 체리픽하거나 제거하지 않는다.

## 구현·검증 계획

1. 일반 저장 글줄의 연속성만으로 수행하던 말미 전진 차감을 제거한다. 이미 분리된 저장
   프레임·재시작의 독립 소유 계약과 원래 병합 칸의 행 프레임 계약은 보존한다.
2. 병합 프레임의 helper는 해당 역할의 작은 모듈에서 명시적으로 구현한다. 문서 ID·부모/자식
   우연한 수치·instanceId 이력으로 현재 입력만 제외하거나 고정 px를 더하지 않는다.
3. Native143에서 실패 원본의 첫 컷·2쪽과 편집 전 원본을 먼저 대조한다. 올바른 방향이면
   편집 저장본 전 196쪽 및 원본 전 115쪽, 기존 35개 표/이월 대조군과 #7877의 실제 영향을
   대조한다. 쪽수만으로 판정하지 않는다.
4. Native의 실패 원인·수용 컷이 맞는지 확인한 뒤 필수 fresh WASM과 영향 회귀를 실행한다.
   전쪽 90% 이상·확대 판독 전에는 #4138의 기존 검사·기대값을 바꾸거나 새 렌더링 회귀를
   추가하지 않는다. 정확한 기존 소유·소스 보존 검사는 유지한다.

현재는 원인 관측과 범위를 고정한 단계다. 이 계획은 구현·시각 검증 완료나 PR 제출 판정이 아니다.

## Native143와 독립 저장 메타데이터의 실제 관측

일반 셀에 대해 연속된 저장 줄만으로 말미 전진을 빼던 경로를 제거했다. 기존 병합 행 프레임의
함수는 같은 계산을 `stored_span_content.rs`의 `stored_spanning_cut_closing_advance`로
명시했다. 수용량·실제 상자의 공통 차감 경로가 이를 소비하며 문서 ID·고정 px를 추가하지 않았다.

Native143은 공유 target·잡 8개·249.29초·종료 코드 0이다
(`char-overlap-native-build-143-result.json`). 변경 중 소스의 SHA를 빌드 전후 대조했다.
편집 저장본 첫 두 쪽은 raw 100%·99.98032%로 개선됐다. 편집 전 원본은 115쪽을 유지하며
첫 두 쪽도 99.98006%·100%다. `issue4138-native143-opening-2254-*-result.json`에 있다.
2쪽의 review·standalone overlay를 직접 확인하고 함께 표시했다
(`issue4138-native143-opening-review-2262`). 본문·제목의 한 줄 이탈은 해소됐으나 전체
출력은 **197쪽으로 Print 196쪽과 다르다**. gate는 `re_review_required`이며 새 완료 판정은 없다.
197쪽에는 실제 본문 여섯 줄이 있어 빈 쪽을 지워 해결할 수 없다.

기준은 원래 196쪽 Print PDF로 유지한다. 같은 원본을 MCP 2024에서 HWP → HWP로 저장해
보조 글줄 메타데이터를 관측했다. HWPX나 별도 PDF로 기준을 바꾸지 않았다. 보조 저장본은
input SHA `9ae8200417a39b912b36044a7371e9e3946afe21bc884beec868076f15c63ab8`,
output SHA `a410e0dd53357f813a080264b5fdfa653d66708222d8de00e04c30100c0e344b`이며,
job `232a1806-9e7f-4197-9b38-768ea3eecdfd`의 완료·다운로드는
`mcp-issue4138-hancom-save-2256/complete.json`에 보존했다. 이 파일은 진단용 `output/`에 둔다.

한컴 저장 전후 셀의 2,507개 문단 텍스트·7,483개 저장 글줄 수는 같고 실제 페이지 재시작
195개가 기록됐다. 첫 재시작은 문단 9의 여섯 번째 줄이며 개선한 첫 컷과 맞는다.
높이·text height가 달라진 글줄은 10개, 기준선은 9개, 줄간격은 4개, text start는 두 문단의
5개 경계에서 달랐다. 같은 한컴 저장본도 현재 Native143에서는 197쪽이므로 저장본의 통과로
원본 검증을 대신하지 않았다. `issue4138-saved-metrics-2258-*-saved.json`,
`issue4138-saved-line-metric-differences-2260.json`, `issue4138-saved-frames-2261.json`을
보존했다. 다음 분석은 수식/개체 줄의 실제 메트릭·컷과 중첩 표 지점의 원점·예약을 연결한다.
텍스트 추출에서 빠진 수식 문자를 실제 그림 누락으로 단정하지 않는다.

#7877은 manifest의 18개와 최종 #5543 대조군 1개를 합해 19개·835쪽이다. 입력/PDF의
SHA와 마지막 대조군이 실제 merge `22317614b03722e95349a1d3d71c86923363c6f5`에 포함된
bytes임을 `pr7877-preservation-input-audit-2253.json`에서 확인했다. 이것은 입력 인증이며
새 후보의 835쪽 통과 증거가 아니다. 현재 큰 차이를 먼저 보정한 후 필요한 전체 검증을 진행한다.

이 단계는 진행 중인 후보 보정이다. #4138 기대값 변경·신규 렌더링 회귀 추가·PR 제출은 계속
보류하며, 현재 개선된 두 쪽으로 나머지 페이지나 rebased 기능의 검증을 대체하지 않는다.

## 단계 커밋 점검

Native143에서 확인한 첫 컷 보정을 진행 중인 일반 커밋으로 보존한다. 전체 쪽수 미달과
후속 검증 항목은 위와 같이 남아 있으며 PR 준비 완료를 뜻하지 않는다.
`logs/stored-line-slot-fmt-2266.log`의 `cargo fmt --all -- --check`는 종료 코드 0이고
`git diff --check`도 통과했다. Native143 빌드 이후에는 호출 지점의 기존 영문 주석만
새 동작에 맞는 한국어로 정정했다. 실행 코드는 바꾸지 않았다. 다음 단계는 수식/중첩 표의
실제 메트릭과 페이지 경계를 분석한다.
