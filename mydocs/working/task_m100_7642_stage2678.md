# #7642 문자 분할만으로 저장 줄을 수용한 회귀의 보정

Issue: #7642.

[계획](../plans/task_m100_7642_square_plan_saved_origin_20261017.md)의
독립 Print와 실제 Native 관측을 근거로 한다.

## 발견한 회귀

0e7f112db0 Native의 국어 14쪽은 raw 99.79769%로 개선됐지만 17쪽은
raw·경계 보정 진단 44.87939%, 엄격 내용 픽셀 10.31%로 하락했다.
17쪽 review·standalone overlay에서 본문과 자료 상자가 위로 당겨진 것을
직접 확인하고 두 PNG를 함께 표시했다. 완료로 처리하지 않았다.

같은 문자 분할은 같은 물리 줄·높이를 입증하지 않는다. 특히 개체 높이를
포함한 저장 한 줄과 재구성한 실제 본문 줄을 구분해야 한다.
14쪽만 개선됐다는 이유로 이 회귀를 허용하지 않았다.

## 변경과 소비 지점

`plan_square_table_host`의 문자 분할만 비교하는 단축을 철회했다.
`controls::square_host_frame::stored_host_origin`은 다음을 읽는다.

- 현재 단의 실제 첫 소유자와 그 원본의 vpos=0
- 호스트까지의 비합성·비편집·단조 저장 축과 source snapshot의 동일성
- 이미 수용한 plan의 원본 문자 분할·줄 높이·간격 보존
- 일반 선행 문단의 실제 구성 줄 수·높이·간격과 저장 값의 대응

단 전체의 저장 세로 축이 유지됐으면 `paragraph_flow`가 **fit 전에** 같은
원점을 `align_flow_to`로 선택하고 공통 plan을 사용한다. 이전 plan이 줄을
합치거나 높이를 바꿨으면 옛 원점을 복원하지 않는다. 단 이월 뒤에는 새
프레임의 cursor를 사용하며 paint에서 좌표를 따로 덮어쓰지 않는다.
누적 cursor를 clamp하거나 내용·빈 문단을 숨기는 처리를 추가하지 않았다.

## 검증

수정 파일 rustfmt·diff 검사를 통과했다. 이번 코드의 컴파일과 실제 출력은
아직 미검증이다. 전체 수용·분할의 prefix 소유 보정과 함께 새 후보로 검증한다.
실행 중인 기준 devel 빌드는 유지하며 이전 후보의 미시작 WASM을 반복 빌드하지 않는다.
전체 범위·90% 기준·devel 대비 하락 재검토·직접 확대 판독은 유지한다.
