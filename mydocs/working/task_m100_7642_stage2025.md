# #7642 시험지 공통 그림의 색 수·형식·제품 세대 분리

Issue: #7642

## 독립 Print 실험

시험지의 구·원뿔 그림에서 원본 bitmap과 Native 디코드 RGB가 같은데 한컴 Print의
회색은 더 밝았다. 원본 11월 문서를 다시 Print한 JPEG도 기존 PDF와 바이트까지 같았다.
전역 밝기 조절, 문서 ID·그림 크기·그룹 여부·BMP DPI를 조건으로 삼지 않는다.

이어서 같은 24비트 RGB 형식·640×160 크기의 그림에 색을 256·257·512·4096·65536개
넣어 한컴 2024에서 Print했다. 256개까지의 회색 240은 유지되고, 257개부터 밝아졌다.
JPEG 경계 오차를 분리하기 위해 각 회색을 32×32 평탄한 면으로 다시 배치했다.
256색 원본의 픽셀 하나만 비회색으로 바꾼 257색 대조군도 같은 변화가 발생한다.

| 입력과 Print | 회색 228의 PDF 값 | 회색 240의 PDF 값 |
|---|---:|---:|
| 256색 RGB BMP, 2024 |228|241|
| 257색 RGB BMP, 2024 |236|248|
| 같은 RGB PNG, 2024 |236|248|
| 같은 픽셀의 불투명 RGBA PNG, 2024 |236|248|
| 256색 팔레트 PNG, 2024 |228|241|
| 같은 그림의 JPEG, 2024 |228|241|
| 257색 RGB BMP, 2020 |228|241|

2024에서는 BMP·RGB PNG·불투명 RGBA PNG가 PDF의 같은 JPEG 자원으로 합쳐졌다.
JPEG 입력과 256색 팔레트 PNG는 그 자원과 다르다. 2020 Print에서는 257색에서도
밝아지는 변화가 없었다. 따라서 모든 이미지나 모든 한컴 세대에 공통으로 색을 바꾸는
가정은 반례에 위배된다. JPEG 재압축 오차와 decoder의 세대별 RGB 변환도 구분한다.

색 성분 `c + (c >> 5)`를 255에서 포화시키는 가설은 원본 사진을 같은 Q35로
재압축했을 때 PDF와의 평균 성분 오차를 약 4.3에서 0.485로 줄인다.
평탄한 257색 대조군은 평균 0.109다. 그러나 원본 사진의 정확한 픽셀 일치는 약
88.43%이므로 이를 한컴 내부 구현과 바이트 단위로 같다고 주장하지 않는다.
5비트로 먼저 양자화하는 가설보다 결과가 가깝다는 진단이며, 제품에는 적용하지 않았다.

## 입력 변형을 이용한 원인 진단

stage2023은 11월 HWPX 원본의 bitmap 중 불투명·256색 초과인 BMP/PNG 픽셀만
위 가설대로 바꾼 임시 복사본을 만들었다. JPEG·문단·줄·표·그림 좌표는 그대로다.
제품은 기존 고정 `05b84fa932`의 Native CLI이고, 대조 PDF는 수정하지 않은 원본의
독립 Print다. 원본 입력 SHA와 변형본 SHA, 변경한 ZIP entry와 전후 바이트 해시를
receipt에 별도로 기록했다.

21쪽 raw는 원본 HWPX의 약 83%에서 변형본 96.09167%로 높아졌다.
이는 공통 bitmap 색 변환이 미달의 주요 원인이라는 가설을 지지한다.
**입력을 바꾼 진단이므로 원본 출력 보정·제품의 90% 통과·회귀 등록 증거가 아니다.**
실제 구현과 원본 재출력이 없으므로 PR gate를 통과한 것으로 쓰지 않는다.

## 구현 전에 연결할 소비 경로

같은 조건이 Native와 fresh WASM에 실제로 도달하는지 확인해야 한다.
LayoutCompatibilityProfile의 `hangul2024_layout()`과 실제 원본 bitmap 형식·색 수를
소비할 위치를 먼저 정한다. 같은 원본의 2020 출력, 256색 이하, JPEG, 불투명 PNG,
투명 이미지 및 기존 그림 효과의 적용 순서를 구분한다. 미실행한 조합은 미검증이다.

그림을 만드는 `paragraph_layout`, `shape_layout`, 셀·각주·배경 경로와 최종 ImageNode를
확인한다. 출력에서는 `image_resolver::resolve_image_payload`만 바꾸면 끝나지 않는다.
`paint::source_image_key`는 `SourceImageVariant`로 원본 신원을 발급하고,
`emitted_source_image_bytes`와 paint JSON의 `omit_image_bytes` 소비자가 그 키로 다시
바이트를 얻는다. 새 변환을 `src` 키와 섞으면 fresh WASM의 재조회에서 원본 색이
돌아올 수 있다. Native Skia·SVG·Canvas의 같은 원본 바이트·효과 적용 순서를 대조한다.
이 문서는 구현 완료나 실제 호출 경로 검증 완료를 주장하지 않는다.

## Print 실행 출처

진단 HWPX는 RHWP scaffold·그림 삽입 명령으로 작성했으며 한컴 2024 저장본이라고
주장하지 않는다. 2024 PDF는 제품 세대 비교를 명시한 진단 출력이고, 같은 입력의
2020 PDF를 별도로 보존한다. 새 회귀의 시각 자격은 실제 구현 뒤 canonical 기준 PDF
계약과 전쪽 Native/fresh WASM·직접 판독을 충족한 자료로 다시 판단한다.

## devel 비교와 검증의 구분

고정 `552514f423` Native/fresh WASM 빌드는 stage2014에서 각각 성공했다.
이후 upstream이 `fe5725dc38`로 전진해 리베이스하므로 최신 devel의 최종 근거로 쓰지 않는다.
stage2019의 Native controller는 실제 manifest `native-export.json` 대신 존재하지 않는
`native-export-complete.json`을 찾았다. 실루엣 수치와 child exit는 보존됐지만 그 receipt의
쪽수 확인은 별도 감사로 실제 manifest에서 보완해야 한다. 이 도구 오류와 제품 미달을 구분한다.
원본 sample16과 정상 저장 HWPX의 각 64쪽을 같은 지표로 부분 대조한 결과에는
0.01%p 이상 하락이 없었다. 이 두 문서만의 부분 결과이며 전 범위 통과가 아니다.

이번 단계에서 제품 코드·기존 회귀 기대값·golden·허용치는 바꾸지 않았다.
정식 회귀 추가와 전체 승인·PR 준비는 계속 보류다.
