## 1. 조사 경위

비공개 샘플 HWPX 를 SVG 로 내보내 한컴 2022 PDF 와 비교하던 중, ☞ 로 시작하는 5개 항목 블록이 SVG 에 없는 것으로 보여 "표 누락"으로 진단했다(v1 계획서). 1단계에서 렌더 경로를 단계별로 추적하며 이를 검증했다.

## 2. v1 전제 오류 확인

렌더러 추적 결과 모순이 드러났다:

- `dump` — 파서 IR 에 표·셀 5개 문단 모두 정상 존재.
- `dump-pages` — 표가 6→7쪽 `PartialTable` 로 정상 분할 배치, 세로 공간도 예약.
- SVG 산출물 — 표 외곽 테두리(rect/line)는 6·7쪽 모두 정상 렌더링.

테두리는 그려지는데 텍스트만 없다는 점이 이상하여 SVG `<text>` 요소를 직접 확인한 결과, **셀 텍스트는 `fill="#5d5d5d"`(회색)로 정상 렌더링**되고 있었다. 조사에 쓴 텍스트 추출 스크립트가 `fill="#000000"` 만 필터링하여 회색 셀 텍스트를 통째로 누락한 것이 "표 누락" 오진의 원인이었다.

→ **v1 의 "렌더링 누락" 전제는 폐기.** 표는 정상 렌더링된다.

## 4. 근본 원인

`src/renderer/layout/table_layout.rs` `compute_cell_line_ranges` 의 일반 문단 줄 루프가 분할 경계 양쪽에서 비대칭 기준을 쓴다.

- 분할 끝 페이지(`content_limit`): 줄 포함 판정 `line_break_pos = cum + h` — 줄간격 제외.
- 분할 시작 페이지(`content_offset`): 줄 스킵 판정 `line_end_pos = cum + line_h` — 줄간격 포함.

분할 경계가 한 줄의 줄간격 구간 `[cum+h, cum+h+ls]` 안에 떨어지면, 끝 페이지는 `break_pos ≤ 경계`로 포함, 시작 페이지는 `end_pos > 경계`로도 포함 → 그 줄이 두 페이지에 모두 렌더링된다.

수치(cp[1]): `cum=23.5px, h=14.7px, ls=8.8px`, 분할 경계 41px.
- 끝 페이지: `cum+h = 38.1 ≤ 41` → 포함.
- 시작 페이지: `cum+line_h = 46.9 > 41` → 스킵 안 됨 → 포함.

Task #656 이 끝 페이지 측을 `cum+h` 모델로 정정하면서 시작 페이지(offset 스킵) 측을 함께 갱신하지 않은 누락으로 판단된다.

## 5. 페이지 수 차이 재검증

올바른 추출로 SVG 180쪽 ↔ PDF 179쪽을 재정렬한 결과, 약 16개 분기점에서 ±1쪽씩 어긋나며 대부분 상쇄되어 순 +1쪽. 표 셀/줄 높이 정밀도의 누적 드리프트로, 본 버그와 별개 사안(별도 타스크).
