## 독립 출력과 원인 추적

입력은 `samples/issue6776/78494-virtual-convergence-industry-decree.hwpx`
(실제 형식 HWP5), 독립 기준은 `pdf/78494-virtual-convergence-industry-decree-2020.pdf`다.
PDF의 HY중고딕 프로그램과 설치된 공식 글꼴15개 글리프의 윤곽·전진 일치는
stage2415에서 확인했다. 명시적 TrueType 환경의 기존 producer056d370f89를
진단했고, 같은 내용의 현재8aaa2ee705 SVG·flow 추적도 실행했다. 진단 SVG는
시각 sweep 대체 자료가 아니며 PNG 전쪽 TSV를 수용 근거로 사용한다.

46쪽의 문단424~440은 독립 PDF와 모든 줄의 텍스트가 같고 근사 기준선 차이도
0.12px 이내다. 문단442의3행 TAC 표에서만 제목과 뒤 내용이약34px 내려간다.
해당 문단은 공백 두 개와 표를 저장하며 원본 LineSeg는 없다. 본체613.85px,
좌우 바깥여백3.76px, 공백20px가 본문642.53px에 함께 들어가는데 기존 경로는
공백 줄의170% 줄간격34px를 먼저 소비한다. 표의 x도 약4.5px 어긋난다.
독립 PDF는 공백과 표가 같은 물리 줄에 놓인다.

기존 standalone RowBreak 예외가 실제 줄 계획을 건너뛰게 한다. 폭90%의
인라인 분류에만 의존하는 fallback에서는 넓은 표 앞의 공백이 별도 줄이 된다.
그 결과 현재 높이980.5px 뒤의 빈 문단443이47쪽으로 넘어가20px를 소비하고,
다음 빈 문단460도48쪽으로 넘어가16px를 소비한다. 빈 줄 감추기 속성은
원본에서 false이므로 빈 줄 삭제나0높이 흡수 후보는 적용하지 않았다.

## 공통 결과의 실제 소비 경로

| 경로 | 변경 뒤 처리 |
| --- | --- |
| 저장 줄 없는 단독 RowBreak 표, 전체 계획 수용 | inline_flow::plan의 문자/표/여백 줄 상자 → plan.end로 예산 확인 → commit_inline_flow → 최종 renderer의 같은 계획 |
| 같은 표의 전체 계획이 현재 단에 미수용 | 상태 변경 전에 기존 행 분할 소유자로 반환 |
| 유효한 저장 줄 | 기존 저장 줄 소유 유지 |
| 이미 구성한 합성 개체 줄 | 기존 소유 유지 |
| 캡션·셀 각주·중첩 표·탭 등 미지원 | 기존 owner 유지 |

실제 줄 계획이 공백·명시적 개행·너비 부족·개체 순서를 결정한다. 단독 표가
현재 단에 다 들어가지 않는다는 이유로 전체를 다음 쪽으로 강제 이월하지 않는다.
지원 판정은1000줄 이하 모듈로 분리했다. 기존 파일은982줄에서 줄었고 새 파일은
100줄 미만이다.
