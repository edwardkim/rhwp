## 관측된 미달과 실제 호출 경로

Source194 Native의 `exam_kor.hwp`는 20쪽 중 13·17쪽이 미달이며 최저 82.33453%다.
`samples/hwpx/exam_kor.hwpx`는 9·12·13·16·17·18쪽이 미달이며 최저 53.64154%다.
이 HWPX는 이전 Source186에서 최저 91.61595%였으므로 현재 변경의 회귀를 조사한다.
`exam_math_8.hwp`는 1쪽 89.60729%로 cases 수식의 미세 배치 차이가 남아 있다.

국어 HWP의 17쪽 `s2:p22`는 문항 37 제목이고 `s2:p23:ci0`는 보기 표다.
원본 제목 줄은 vpos 47721HU, 표 줄은 50541HU다. 원본과 독립 Print는 유지한다.
Source194 진단에서 `HeightCursor::vpos_adjust`는 제목 다음 원점을 885.5px로
복원했지만, 실제 표는 839.7px에서 그려져 제목 위로 겹쳤다. 이 수치는 진단값이며
회귀 테스트의 절대 좌표 기대값으로 사용하지 않는다.

소비 경로는 `paragraph.rs`의 내용 하단 기록 → `state/stored_tac.rs`의 직전 소유
조회 → `controls/stored_tac.rs::prepare`의 진입 원점 →
`state.rs::commit_stored_tac_control`의 inline metadata → `layout.rs`의
`flow_placement` 원점 선택이다. 그 전에 렌더러의 `HeightCursor`가 별도로 복원한
원점을 metadata가 덮어쓰는 지점까지 확인했다. 현재 진단 확장은 기존
`RHWP_DIAG_FLOW`에서 단·시작 높이·저장 축·dirty 상태·첫 항목과 저장 표의
진입 판단을 함께 기록한다. 일반 실행의 배치 동작은 바꾸지 않는다.
