## 다음 구현의 소비 경로와 반례

`script_geometry::script_subscript_geometry`의 현재 분수 경로는 일반 fallback에
들어간다. 독립 아래첨자 프레임이 본체의 어느 하강 점유를 소비하는지 추적해
Subscript와 SubSup에 같은 결과를 전달한다. 부모 프레임·줄 높이·저장 예약과
`layout_for_paint`의 기준선 선택, SVG/Canvas의 실제 자식 원점까지 확인한다.
첨자를 아래로 옮긴 뒤 부모 높이가 그대로인 처리는 하지 않는다.

근호 확장은 근 지수의 실제 상자 포함과 중첩 본체의 점유를 확인한다. 지수가
상자 밖으로 나오는 복합 입력이나 다줄 본체를 일반 글줄로 접지 않는다.
새 분기는 독립 근거로 적용·비적용 경계를 설명하며 문서 ID나 px로 선택하지 않는다.

Stage 170의 원본 Native와 fresh WASM 검증은 종료됐으며 생산 소스 해시의
불변을 확인했다. 이 단계의 구현·전후 실행·전체 TSV·정식 새 관계형 회귀는 아직
미완료다. 검증 종료 후 알려진 결함을 함께 보정하고 관련 전체 페이지와
확대 판독을 확인한다. 전체 작업의 PR/CI/후속 처리도 미완료다.

## Stage 171 구현과 검증 순서

분수 아래첨자의 논리 높이는 `분수 높이 + 분자/분모의 근호 점유 + 일반
아래첨자의 줄 대비 하강 확장`으로 계산한다. 배치 원점도 같은 높이와
첨자의 논리 하강부를 소비한다. `logical_font_frame`의 Subscript/SubSup
분기는 일반 줄 메트릭으로 덮어쓰지 않고 이 분수 프레임을 선택한다.
`script_geometry`의 실제 자식 원점, `matrix_row_box`의 부모 논리 프레임,
최종 SVG/Canvas의 자식 위치는 이 결과에서 이어진다. 자연 glyph와 논리
줄의 하강부 차이는 출력 대조로 확인하며 임의 clamp로 숨기지 않는다.

근호의 본체는 같은 글자 줄로 검증된 경우에만 크기별 상단 밴드를 소비한다.
정상화된 단일 자식 Row는 독립 줄 메트릭과 자식 기준선 연결을 확인한다.
근호 자식 Row는 자식 높이·기준선·원점을 보존해야 한다. 다줄, 분수 본체,
다른 크기, 상자 밖의 근 지수는 이 글줄 분기로 접지 않는다. 근호가 만든
높이는 다음 근호·분수의 측정과 배치에 전달한다.

15개 크기의 기본 프로그램(v5)은 저장 job
`6b67e676-9151-4399-9ad8-7ebfaac27d2b`, Print job
`1cf245d5-bc96-4e2b-b9ac-b694bf66e308`이다. HWP SHA는
`c7be851e91ce0a8c4c86c116dd3cb6498ceaa0b5c823328ee1424ca30dfd3a39`,
PDF SHA는 `febba50f75fc20d573f80ebd0040b2948d55cae8d50ee7f47316f6e784efb34c`다.

무지수·근 지수·두 겹 근호·근호 분수 60개(v6)는 저장 job
`0c10bac1-84fd-4b3a-be74-d3aa93aefae3`, Print job
`2822125c-cbc1-46fe-a4f1-473bc8ba7cdd`다. HWP SHA는
`81654c6545a0dd0fee8a7ef35370d2bec4faf8fc78291a67e2662c09fca55e0d`,

## fresh WASM 종료와 새 관계형 검사의 결함 검출

fresh WASM 빌드는 exit 0, 소스 해시 유지 true, Studio JS/WASM 동기화 일치
true다. 진단 v1~v7 전체 17쪽은 Native와 동일한 쪽수·최저값으로 모두
90% 이상이다. 실제 두 경로의 PNG 17개를 해시로 대조해 모두 동일함을
확인했고 새 WASM review를 직접 열었다. 원본 HWP/HWPX도 fresh WASM
전체 23/23쪽, 최저 91.83899%/91.85645%, 미달 0쪽으로 종료됐다.

기존 검사 이름을 바꾸지 않고 `tests/cases/issue_7642_fraction_script_ownership.rs`를
새로 추가했다. 첫 검사는 원본 문단·컨트롤의 단일 소유, 분모 5와 아래첨자 i의
보존, 분모 기준선보다 아래에 있는 첨자와 최종 SVG 잉크를 확인한다. 수학
이탤릭 i의 Unicode 표면도 같은 문자로 확인한다. 둘째 검사는 15개 BaseUnit의
무지수·근 지수 대조군에서 지수 3과 제곱 2의 내용 보존, 소유와 제곱 기준선의
동일성을 확인한다. 화면의 고정 px 위치로 선택하지 않고 실제 소유 상자와
글자 크기의 비율, 한 HWPUNIT 저장 정밀도로 검사한다.

같은 강화된 검사 원문을 수정 전 `9d340e28fc23736ee52a93efa43186f183a79653`의
실제 라이브러리에 링크해 실행했다. 두 검사 모두 의도한 기준선 결함으로
FAIL했다. 아래첨자는 분모 기준선보다 위에 있었고, 600HU 근 지수 대조군의
제곱 기준선 비율은 무지수 0.5743833 / 근 지수 1.2953333으로 갈라졌다.
이 관측값을 기대값으로 고정하지 않는다. 처음 두 번의 sparse checkout
빌드 실패(vendor, 저장 template 누락)는 환경 실패이며 결함 재현에 세지 않는다.
현재 구현의 초안 두 검사는 PASS했으며, 지수 내용 보존까지 강화한 같은
원문의 정식 nextest 실행 결과는 종료 뒤 기록한다.

수정 전 분리 worktree도 공용 `/home/tsjang/rhwp/target/pr-review`를 사용했다.
실행 중인 Cargo 작업을 확인해 순차로 빌드했으며 메인 생산 소스와 immutable
시각 검증 산출물을 바꾸지 않았다. 해당 worktree는 입증 종료 후 정리한다.
