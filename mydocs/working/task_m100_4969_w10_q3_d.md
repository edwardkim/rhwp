## 판정

Q3-D는 **qualified-dormant**다. exact `(charShapeId, languageIndex)` slot에만 결합되는 내부 CQRS command owner와
immutable request snapshot을 만들고, source generation과 request generation을 함께 소유하는 명시 요청 전용
transaction을 연결했다. 요청은 exact source의 실제 `fvar` model로 완전히 검증·canonicalize된 뒤에만 snapshot을
바꾼다.

그러나 native/WASM 공개 adapter와 composer activation은 열지 않았다. 현행 제품 composer는 계속
`variations: &[]`인 기본 transaction만 사용한다. 따라서 이번 결과는 제품에서 variable instance가 보이거나
게시된다는 뜻이 아니며 Q3-E activation matrix를 자동 승인하지 않는다.

## 원인 계보와 owner 배치

Q3-C까지는 low-level test request가 canonical variation vector를 measurement·outline shadow에 직접 전달할 수
있었지만, 실제 문서 CQRS 계층에는 요청을 소유할 곳이 없었다. 기존 공개 `registerExactFontSource`는 exact bytes와
slot을 결합할 뿐 axis intent를 받지 않는다. 이 상태에서 composer가 font name·bold·장평을 보고 axis를 만들면
문서에 없는 의도를 발명하게 된다.

Q3-D는 다음 경계를 추가했다.

```text
internal explicit slot command
  -> exact source handle 재검증
  -> 실제 fvar axis·범위·중복·finite·16-axis 상한 검증
  -> canonical non-default vector
  -> request snapshot generation 증가
  -> source snapshot + request snapshot을 같은 shaping context에 복제
  -> explicit-instance transaction만 vector 주입
  -> measurement cache key에 slot + request generation 보존
```

- `LayoutEngine`이 exact source registry와 instance request registry를 함께 소유한다.
- `DocumentCore`의 내부 command는 성공한 변경에만 context·composition·측정·page tree를 일괄 무효화한다.
- 동일 effective instance의 tag 순서 변경은 `AlreadyRegistered`이며 generation을 올리지 않는다.
- exact source를 비울 때 request registry도 함께 비워 stale slot intent가 새 source에 붙지 않게 한다.
- measurement에는 `(slot, request generation)` provenance가 남는다. direct Q2 measurement에는 이 값이 없다.

공개 native/WASM 메서드는 추가하지 않았다. `HWP/HWPX parser`, font name, bold, 장평/자간에서 이 내부 command를
호출하는 경로도 0이다.

## fail-closed·cache 계약

- unknown axis, NaN, range 밖 값, axis 상한 초과는 snapshot mutation 전에 structured error로 거절한다.
- 등록되지 않은 exact slot은 `sourceUnavailable`이며 orphan request를 만들지 않는다.
- explicit transaction의 slot과 measurement slot이 다르면 `explicitInstanceSlotMismatch`로 닫는다.
- caller가 explicit transaction에 별도 variation vector를 덮어쓰려 하면
  `explicitInstanceOverrideNotAllowed`로 cache mutation 전에 닫는다.
- explicit 400/400은 Q2 empty instance와 settings identity·advance가 같지만 request provenance가 다르므로 같은
  cached `Arc`를 재사용하지 않는다.
- request가 없으면 기존 Q2 transaction을 그대로 사용하며 product publication과 backend selector는 변하지 않는다.
