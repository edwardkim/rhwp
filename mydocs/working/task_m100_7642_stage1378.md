# Issue #7642: HWP3 원본 영문 프로그램의 실제 소비 경로 재검토

## 독립 근거와 변경 전 관측

- 부모 source는 `ee09c2d7c`다. upstream은 fetch 뒤에도 `2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`이며 현재 branch가 포함하므로 리베이스하지 않았다.
- 원본 `samples/hwp3-sample16.hwp`와 독립 `pdf/issue7642-hwp3-original-print/hwp3-sample16-2020.pdf`의 19쪽은 Native 88.22090%다. `stage1370-native-sample16-p19/sample16-p19/review/review_019.png`를 직접 열어 ORACLE/GIS/File D/B를 포함한 영문 줄의 폭·간격 차이를 확인했다.
- 독립 PDF의 T3는 xref31이며 `/Widths`의 원본 HCI Poppy 값은 `font_metric_hci_poppy.rs`에 보존되어 있다. PDF 본문의 같은 줄에서 ORACLE D/B, GIS D/B, XML D/B, File D/B 모두 T3로 출력됐다.
- `stage1373-before-sample16-p19/font-trace.json`의 원본 문단 405는 글꼴 선언 HCI Poppy, 영문 슬롯 1, **altType 0**이다. 실제 폭 요청은 Palatino Linotype이다. 기존 HCI Poppy altType 2 합성 계약의 통과가 이 실제 경로의 원본 폭 소비를 입증하지 않는다.
- HWP3 parser는 이름을 정규화한 글꼴만 원본 HFT 종류로 표시하고, 이름이 유지되는 HCI Poppy는 미지정으로 남긴다. style resolver의 기존 계약은 HFT 원본과 TTF 대체를 구분하므로 미지정 원본은 표시용 Palatino를 계속 측정한다.

## 보정 방향과 반례

HWP3에서 확인된 원본 HFT 프로그램 종류는 parser에서 공통 Font 메타데이터로 보존한다. 렌더러에 HWP3 전용 분기를 추가하거나 HWP5/HWPX의 미지정 또는 TTF 선언을 강제로 바꾸지 않는다. 확인한 HCI Poppy에만 원본 프로그램 종류의 근거를 연결한다. 확인하지 않은 이름은 기존 상태를 유지한다.

생산·소비 경로는 HWP3 이름 선언 → Font의 원본 프로그램 종류 → 기존 스타일의 HFT 메트릭 face 선택 → 문자별 확인한 폭/em 선택 → 줄 채움·최종 문자 위치·paint다. 같은 helper 이름만 보지 않고 실제 문단 405의 trace가 HCI Poppy 원본 폭을 소비하는지 확인한다. 미측정 문자와 bold/italic, 실제 Palatino TTF 선언의 기존 동작도 보호한다.

Native 선행 64쪽 및 문제의 19쪽을 먼저 대조한 뒤 같은 소스의 fresh WASM 전쪽·직접 판독을 수행한다. 90% 미달 상태에서 실물 golden이나 px 기대값을 등록하지 않는다. 적격 문서가 된 뒤 새 이름의 소속·내용 관계 검사와 양쪽 98% 이상 중요 페이지의 독립 ±2px 검사를 검토한다.

## 함께 분석 중인 하락

고정 devel의 같은 원본·PDF와 비교한 Native 938쪽 중 이전 생산 source 810654da의 67쪽에서 0.01%p 이상 하락을 확인했다. 이는 이전 source 진단이며 ee09c2d7c 최종 판정이 아니다. 언어 10쪽은 이번 단계 전의 단 경계 보정으로 개선됐고, 사회 1쪽의 표·후속 본문 원점, 언어 8쪽의 저장 어절 경계, 국어 14쪽의 위치·구두점은 별도로 원인을 추적한다. 정확한 독립 PDF가 영문 구두점을 별도 T3로 출력하는 사례가 있으므로 구두점 슬롯을 일괄 되돌리지 않는다. 증적은 ignored `stage1371-native-before-batch-base-drops.json`, `stage1372-native-detail-diagnosis/`, `stage1376-*-social-p1/`에 보존한다.
