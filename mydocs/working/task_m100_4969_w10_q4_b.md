## 결론

Q4-B는 HWP5 `0/1/2`와 HWPX `HORIZONTAL`/`VERTICAL`/`VERTICALALL`을 같은 숫자로
뭉개지 않는 typed contract를 실행 가능한 테스트로 고정했다. 두 계열 모두 가로, 세로 영문 눕힘,
세로 영문 세움으로 대응하며, 현재 공개 fixture가 보여 주는 열 진행은 `vertical-rl`이다. 알 수 없는
HWP5 값 `3..7`, 알 수 없는 HWPX 문자열, 서로 다른 source family를 잘못 넘긴 호출은
`unsupported-raw`로 닫았다. 이 계약은 아직 제품 parser·IR·layout caller가 소비하지 않는다.

가장 중요한 판정은 `VERTICALALL`의 의미다. OWPML 스키마는 이를 **“세로 영문 세움”**으로
명시한다. `samples/hwpx/tbox-v-flow-01.hwpx`의 글상자는 `VERTICALALL`이고, 한컴이 만든 짝
HWP5 파일의 같은 글상자는 실제 `LIST_HEADER` 코드 `2`다. 따라서 초기 #1028 분석에 남았던
“1 또는 2” 가설은 `2`로 종결된다. Hyper-V 재실행은 필요하지 않다.

## 1. 표면별 mapping

| source surface | raw | writing mode | Latin orientation | 판정 |
| --- | --- | --- | --- | --- |
| HWP5 표 셀·글상자 | `0` | horizontal-tb | 해당 없음 | supported |
| HWP5 표 셀·글상자 | `1` | vertical-rl | sideways, 영문 눕힘 | supported |
| HWP5 표 셀·글상자 | `2` | vertical-rl | upright, 영문 세움 | supported |
| HWPX 표 셀·글상자·구역·바탕쪽 | `HORIZONTAL` | horizontal-tb | 해당 없음 | supported |
| 같은 HWPX 표면 | `VERTICAL` | vertical-rl | sideways, 영문 눕힘 | supported |
| 같은 HWPX 표면 | `VERTICALALL` | vertical-rl | upright, 영문 세움 | supported |
| HWP5 `3..7`, 미지 HWPX token, source family 오용 | 미지 | 없음 | 없음 | `unsupported-raw` |

`vertical-rl`은 글자가 위에서 아래로 흐르고 다음 열이 오른쪽에서 왼쪽으로 진행한다는 뜻이다.
`sideways`는 세로 줄 안의 Latin 문자를 눕혀 배치하고, `upright`는 Latin 문자도 세워 배치한다.
이는 OpenType `vert`/`vrt2` feature와 동일어가 아니다. source intent를 shaping·layout 요청으로
바꾸는 중간 계약이다.

## 3. 현재 제품 gap

typed contract가 드러낸 결손은 다음과 같다.

1. HWPX 표 셀 parser는 `VERTICAL`만 1로 읽고 `VERTICALALL`은 0으로 합친다.
2. HWP5 표 셀 코드 2를 HWPX로 직렬화하면 현재 `HORIZONTAL`이 되어 cross-format 의미가 손실된다.
3. HWPX 글상자는 `vertical_all` 불리언으로 문자열 왕복은 보존하지만 layout에는 코드 1을 넘겨
   `VERTICAL`과 `VERTICALALL`을 같은 영문 눕힘으로 처리한다.
4. 구역·바탕쪽 parser/serializer도 0/1 이진 필드라 `VERTICALALL`을 보존하지 못한다.
5. 여러 기존 parser가 미지 token을 0으로 바꾼다. Q4 계약상 이는 horizontal이 아니라
   `unsupported-raw`여야 한다.

Q4-B는 이 gap을 한꺼번에 고치지 않는다. parser·IR·serializer의 확장은 표면마다 영향과 왕복 형식이
다르고, 즉시 조판에 연결하면 보호 불변식 6을 다시 위반한다. Q4-C는 먼저 이 typed contract를
소비하는 dormant vertical layout transaction만 만든다. 제품 표면 activation은 Q4-D까지 0이다.
