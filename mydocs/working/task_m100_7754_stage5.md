## 실행 순서와 판정

1. 순차 Cargo로 현재 후보의 최적화 Native·fresh WASM을 만들고 SHA·명령·입력
   코드 신원을 고정한다. 먼저 안내문 첫 쪽·5쪽, 24쪽 전체와 실제 어울림 경계를
   대조해 방향을 확인한다. 원문·문자 주소 보존과 가시 원 glyph의 선택을 함께 확인한다.
2. 새 base의 생산물도 같은 프로필·DPI·compat·명시 글꼴 환경으로 준비한다.
   10개 평문 원본 583쪽과 실제 암호 원본 24쪽을 Native/fresh WASM으로 전쪽 비교한다.
   사용자 요구에 따라 대상의 최저 98% 이상을 지키고 가능한 쪽을 100%로 개선한다.
3. 직접 확대 판독 후 핵심 동작의 완료 페이지를 양쪽 최솟값 100% → 99%대 → 98%대
   순서로 골라 회귀를 등록한다. 관계 검사와 내용·소유·순서·누락·중복 보호를 유지한다.
   실제 좌표를 고정할 때만 양쪽 98%와 독립 좌표 근거를 확인해 ±2px를 적용한다.
   비공개 또는 시스템 글꼴 설치를 회귀 테스트의 가정으로 사용하지 않는다.
4. 정식 편람 383쪽과 정본 보호 TSV 전쪽, 새 base의 기능, 브라우저와 기여자 공통
   검증을 완료한다. Native와 WASM 수치·직접 판독·실제 편집 검증을 서로 대신하지 않는다.
5. 최종 테스트 수집·정책·fmt, 최소 글꼴 회귀 환경, 공식 Native lib·placeholder·PDF,
   필수 Clippy·workspace build·전체 nextest의 실제 종료를 확인한다.
   기본 전체 Rust 명령은 `cargo nextest run --cargo-profile release-test
   --target-dir target/pr-review --tests --test-threads 12 --no-fail-fast`다.
   공유 target을 동시에 사용하거나 진행 중인 검사를 임의로 종료하지 않는다.

합성 분할 글꼴 계약은 소스 36에서 3 PASS/0 FAIL이다. Native 전용 paint가 기본
suite의 수집만으로 실행되지 않는 점을 확인해 세 검사를 기존 CI 호출 대상인

Print SVG를 검사한다. 첫 쪽 여백은 올바른 대조 문단과 비교하고, 같은 핵심 동작의
