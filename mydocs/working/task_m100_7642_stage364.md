## 직접 판독과 검사 의미

수식 문서는 같은 배율의 Native/Print 확대에서 escaped 명령의 정체 범위,
명시적 `it` 뒤 이탤릭 복귀, 표시되는 여는 중괄호와 앞뒤 문자,
단일·이중 화살표와 세로 기호를 확인했다. 두 원본의 Native와 실제 fresh WASM
페이지 픽셀도 동일했다. 전체 페이지 점수와 이 확대 판독은 별도로 확인했다.

64쪽 문서의 7·26쪽 최신 Native/fresh WASM review를 직접 표시했다.
제목·앞 본문·표의 원점과 괘선, 합계 행, 표 뒤 문단이 Print의 같은 위치에서
이어진다. 7쪽은 99.79126%, 26쪽은 99.81163%다.
단순 내용 존재만으로 이 배치를 판정하지 않는다.

새 이름의 정식 검사 원본은 `tests/cases/`에 두 파일로 추가한다.

- `issue_7642_native_command_literal_relations.rs`: 독립 Print의 정체/이탤릭·기호·괄호,
  명령과 문자 범위, 원본 수식의 소유·내용 순서·누락·중복을 검사한다.
- `issue_7642_stored_column_margin_owner_relations.rs`: 본문 소유, 제목→본문→표→뒤 본문의
  순서·비겹침과 원본 저장 줄 간격/줄 높이·표 높이의 비율을 검사한다.
  원본 단위의 계약을 대조하며 절대 px 위치나 SVG 해시를 고정하지 않는다.

동일한 검사 초안 5건은 수정 전 코드에서 컴파일에 성공한 뒤 의도한 원인으로
모두 실패했고 보정 코드에서는 모두 통과했다. 문자 검사는 실제 출력의 이탤릭 잔류와
화살표 대신 남은 명령어를, 표 검사는 같은 저장 원점을 소비하지 않은 간격 비율을
검출했다. 빌드 실패를 수정 전 FAIL 증거로 세지 않았다.
정식 파생 suite 020·028에 추가한 뒤 같은 테스트 원본으로 focused nextest를
실행해 5개 모두 PASS를 확인했다. 필터 범위 밖 416개는 이 실행에서 제외했다.
형식만 바꾸어 정식 경로로 옮긴 원본도 수정 전 코드에서 다시 컴파일·실행해
5개 모두 같은 원인으로 FAIL임을 확인했다.

```bash
CARGO_BUILD_JOBS=8 cargo nextest run --locked --cargo-profile release-test \
  --target-dir /home/tsjang/rhwp/target/pr-review \
  --test regression_suite_020 --test regression_suite_028 \
  -E 'test(issue_7642_native_command_literal_relations::) | test(issue_7642_stored_column_margin_owner_relations::)' \
  --test-threads 12 --no-fail-fast
```
