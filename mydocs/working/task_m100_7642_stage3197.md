## 공통 원인과 실제 소비 경로

1. 독립 최소는 칸별 선언과 그 칸의 전체 유닛 점유를 비교한다. 옆 칸의 긴 내용은
   짧은 칸이 가진 최소를 지우지 않는다. `stage3194`의 실제 export-png 추적에서 원본 40행의
   긴 칸에는 10유닛이 있으며, 앞쪽 9유닛의 152.7px는 전체 점유가 아니다. 앞 단계의
   152.7px를 전체 내용으로 해석한 부분을 정정한다. 짧은 칸의 독립 최소는 여전히 유효하다.
2. `reflow_row_physical_minimum → scan의 실제 수용 상자 → end_row_height_override →
   paint의 접기 제외`를 같은 소유로 연결한다. 실제 빈 공간을 더하지 않은 내용 컷에는
   override를 새로 부여하지 않는다. paint도 해당 상자가 독립 최소 안에 있을 때만 보호한다.
   이는 #7518에서 내용 높이보다 작은 이웃 선언이 마지막 줄간격까지 고정하지 않게 한다.
3. 완료 일반 칸의 큰 잔여는 다른 열의 병합 칸과 별도 원장이다. 병합 칸이 계속된다는 이유로
   일반 칸의 480px 최소 잔여를 버리던 분기를 제거한다. 반대로 모두 소비된 내용 뒤 한 줄 이하의
   빈 최소만 남으면 다음 쪽에 새 빈 조각을 만들지 않는다. 실제 남은 글줄은 이 흡수 대상이 아니다.
   이 판정이 원시 선언 fallback에서 뒤집히지 않게 하고, 물리 잔여가 없으면 완료 행의 커서를 전진시킨다.
4. 1×1 상자를 paint에서 쪽 하단까지 늘리는 경로는 위 정렬만으로 NoLS 일반 글줄에 적용하지 않는다.
   독립 최소 또는 저장 줄 출처의 기존 상자 계약을 유지한다. `stage3195`에서 위·가운데 정렬 모두
   scan은 98.667px를 수용했지만 위 정렬 paint만 108.667px로 덮어썼다. 새 분기는 이 덮어쓰기를 제거한다.
5. 병합이 닿는 일반 행에도 실제 독립 최소가 있고 평범한 줄 유닛이면 같은 밴드 컷 적격성을 쓴다.
   저장 프레임·원자 셀 정책과 독립 그림/중첩 개체를 재분류하지 않는다.

## 독립 Print 경계 대조

`stage3193`·`stage3196`은 같은 6행·2열 NoLS 원본에서 각 셀의 최소와 표 전체 선언만 바꾸었다.
입력·PDF 해시, job ID와 `engine=2020`, 실제 한컴 11.0.0.9136,
`pdf_print_method=0`, `hancom2020_pdf_driver_one_up`을 각 receipt에 보존한다. 사양을 흉내 낸
저장 LineSeg를 새로 넣지 않았다. 원본과 이미 확보한 PDF는 보존했다.

- 308·320px 최소는 다음 쪽의 다음 행이 본문 위에서 시작한다. 320px의 사용 후 13.333px 빈 꼬리는 이어지지 않는다.
- 320px+1HU도 같은 출력이다. 328·332px에서는 다음 행이 각각 21.333·25.333px 뒤에서 시작한다.
- 340·360·380·400px는 남은 최소가 다음 쪽으로 이어진다. 480px는 전쪽 10쪽의 실제 Print와 대조했다.
- 따라서 최소를 전부 버리거나 모든 양수 꼬리를 보존하지 않는다. 원본 마지막 줄 유닛 높이와
  1HU 반올림을 쓰며 문서 ID·특정 쪽·320px 같은 실물 좌표를 조건에 넣지 않는다.

현재 기록은 구현 근거와 이전 후보 결과다. 새 후보의 Native/fresh WASM, 29건·전체 회귀,
lint·Studio 및 제출 증적은 실제 실행 뒤 SHA와 연결하며 PR 준비 완료로 표시하지 않는다.
