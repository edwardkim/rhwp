# 중첩 표의 물리 높이와 후속 단의 하단 고정 틀

Issue: #7642

## 독립 출력과 실제 관측

Source230의 사회 단쪽 원본은 83.45146%, 전체 원본은 1쪽 83.08082%,
4쪽 77.48895%다. 원본과 독립 한컴 Print PDF는 변경하지 않았다.
ignored `stage235-social-actual-flow.json`에 실제 render-tree 명령과
새 비교 이미지를 연결했다. 덤프의 첫 실행은 `--paragraph` 오기로 실패했고,
지원되는 `--para`로 재실행한 결과를 `*-source-correct.log`에 구분했다.

사회 0구역 문단 15의 원본 외곽 표는 27774HU다. 공개 측정 조회는 내부
6행의 합 343.88px를 반환한다. 측정기가 투명 래퍼를 풀어 내부 행을 소유하는
계약이며 외곽 표 높이가 아니다. 일반 `table::format`은
`unwrapped_table_whole_height`로 바깥 패딩·자식 여백·물리 최소 높이를 복원한다.
그러나 저장 TAC 수용의 `measured_fits`는 내부 합을 외곽 선언 높이와 직접 비교해
인증을 거절했다. 실제 trace에는 직전 글줄의 원점 연결이 확인되는데도 일반
흐름으로 돌아간 두 번의 조회가 남아 있다.

사회 1구역 문단 61은 4쪽 오른쪽 단의 문항과 쪽 하단 확인 사항 표를 함께
소유한다. 표는 비인라인, TopAndBottom, Page/Bottom이다. 기존
`is_page_bottom_fixed_float` 계약에 해당하지만 block 진입이 첫 단만 허용해
오른쪽 단에서는 문서순 높이로 더했다. 그림 문단 62 진입 커서는 120.3px이고
뒤 표의 실제 직전 내용 하단은 316.23px인데 순차 커서는 416.39px였다.
이 차이가 보기와 다음 문항을 아래로 이동시킨다. 수치는 관측값이며 고정
회귀 기대값이나 문서별 보정에 사용하지 않는다.

## 같은 결과를 소비하는 보정

저장 TAC 수용도 일반 표 포맷과 같은 물리 래퍼 높이를 소비한다. 내부 행을
외곽 선언 높이에 비례 확대하지 않는다. 래퍼가 아니면 기존 높이를 쓰며
실제 성장·줄 연결 단절·편집·각주·캡션의 기존 수용 조건은 유지한다.

하단 고정 틀의 기존 호스트 줄 발행·현재 단 배타 영역·저장 축 보정 경로를
모든 단에 적용한다. 인라인, 문단 상대, 위 정렬 표는 이 분기에 해당하지 않는다.
표를 숨기거나 뒤 문단 좌표를 clamp하지 않는다. 실제 paint의 Page/Bottom
원점과 다음 본문의 흐름을 함께 비교한다.

## 검증 계획

종료된 검증 작업 공간에서 Source230 이후 이 두 소비 경로만 수정한다.
공용 `target/pr-review`에서 한 번 빌드한 뒤 과학·사회와 국어·영어·10월·11월
전체 대조군을 함께 실행한다. 현재 보정 후 결과·fresh WASM·확대 판독·새 이름
관계 회귀·최종 전체 Rust/lint는 미검증이다. 공개 측정 probe는 실제 CLI의
전체 render pipeline을 대체하지 않으며 정식 회귀로 추가하지 않는다.

## 빌드와 소스 커밋의 확인

공용 target의 실제 컴파일은 exit 0, 339.96초이며 소스 해시 불변을
확인했다. 바이너리 SHA-256은 `1983e6a5c9461b9fdd17cbd20ced2b43540e4beff2f380808e8821377ea42d42`다.
커밋 완료 응답 전에 빌드를 시작해 최초 HEAD 메타데이터는 이전 문서 커밋을
가리켰다. 실제 빌드 소스 1526개 해시를 완료된 커밋
`178658a2dacc7a368d000272afe9d814dbbcbce9`의 Git 파일 바이트와 전부 대조했다.
기존 `head_before_build`는 원래 관측값으로 보존하고 검증 큐의 소스 SHA는
해시가 일치한 커밋을 별도로 사용한다. 재빌드·소스 변경으로 이 불일치를 숨기지 않았다.
ignored `stage235-build-source-commit-reconciliation.json`에 대조를 기록했다.
