# #8055 원본의 나누지 않는 자리차지 표

## 독립 근거와 원 해결 추적

원 #2101의 선언-fit은 #2108의 `a12b42ab643b6a166f57d286b02b9abd26b69476`로 반영됐다.
원 #2109·#2133은 #2135의 `bb87b367a546b7f9b3482aa772effbc0abfd3d71`에서 충돌 보정과 함께
반영됐다. 선언 높이가 들어갈 때 과분할을 막는 계약이며, 제한하지 않는 None 개체도 본문보다
크면 반드시 행을 잘라야 한다는 근거는 아니다. 기존 선언-fit의 정상 출력은 유지한다.

원 #8055의 입력 `generated-fixtures-012/pr8055-split-successor.hwpx`는 None·flowWithText=false다.
독립2020 Print는1쪽에 표 전체를 배치하고 종이 바깥 부분을 표시하지 않으며2쪽에는 뒤 문단만
놓는다. Native052는51/9행으로 나눈다.2쪽이라는 개수만 같을 뿐 같은 출력이 아니다.
공개 API로 새로 만든506 대조의 flowfalse HWP/HWPX도 같은 Print 동작이다.
공개 restrictInPage로 만든522 대조는 실제 저장 비트를 확인했고, flowtrue에서는 두 형식 모두
표를 다음 쪽으로 통째 이동시키고 뒤 본문을 앞쪽에 남긴다. 이 제한 모드는 별도로 검증한다.

`unsplit-public-print-geometry-529.json`, `unsplit-public-wire-flow-525.json`,
`split-policy-geometry-audit-499.json`이 근거다. 기존 입력을 CELL/TABLE 진단으로 교체하지 않는다.

## 구현 범위와 값의 실제 소비

- 표의 나눔 정책이 None이고 문단 기준 자리차지 float의 쪽 제한이 꺼져 있으면, 행 컷을 새로
  만들지 않는다. 셀 각주의 별도 물리 예약이 있는 경로는 기존 경로를 유지하며 이 보정의
  일반 상자만으로 각주 소유를 대신하지 않는다.
- `FormattedTable.total_height`와 기존 확정 프레임을 먼저 사용한다. 확정 원점이 없는 빈
  Top 앵커의 통째 상자는 같은 host-before·offset·표/캡션/뒤 여백에서 한 번 만든다.
- `block::entry`의 whole-fit 결정 → `record_paragraph_float_placement` →
  `place_table_with_text` → `ColumnContent` → layout의 확정 원점/끝 소비를 연결한다.
  이미 인증된 저장 원점·계산 호스트 결과는 이 fallback으로 덮어쓰지 않는다.
- 새 clip·좌표 clamp·행 숨김을 넣지 않는다. 전체 개체를 한 번 배치하고 기존 종이 영역의
  출력 clip이 적용되며, 뒤 문단은 실제 상자/배제와 자기 앞 간격으로 다음 쪽을 결정한다.
  RowBreak/CellBreak와 제한을 켠 None을 이 분기로 통과시키지 않는다.

## RowBreak 대조의 입력 전제

옛 #8055 축약 입력에는 수동 저장 LineSeg가 있다. 이 입력만 맞추려고 저장 줄 수용 조건을
넓히지 않는다. 현재 public API로 pageBreak1/2·flowfalse/true·앞 본문 없음/있음을 조합한
20개 HWP/HWPX를 만들고 실제 저장 정책·flow 값이 일치함을560에서 확인했다.561의
20개 독립 Print가 모두 성공했다. 나눔 정책만 바꾼 옛482 입력은 실패 증거로 보존한다.

원 #7095→#7141은1×1의 쪽 조각 상자·100HU와 끝 조각의 다른 계약을 명시한다. #7685는
모든 RowBreak 조각에 바깥 여백을 무조건 더하는 규칙이 실제 문서에서 후퇴함을 기록했다.
형상별 임의 조건을 더하기 전에 실제 소유·HU 정밀도·조각 예약과 배치를 대조한다.

현재 public API의 source 줄 부재/구현 태그 경로에서 CellBreak는50/10행, RowBreak는51/9행으로
나뉘는 것을 Native052의 실제 render tree로 확인했다. 두 경로의 첫 조각 위쪽은 이미 같으므로
수동 저장 앵커를 더 허용할 이유가 없다. 계산 빈 호스트의 RowBreak 물리 프레임 술어를
fit/누적 예약과 부분 배치가 함께 사용해 위·아래 여백을 한 번씩 소비하도록 한다.
실제 저장 줄은 이 술어에 들어오지 않으므로 #7095의 저장1×1 쪽 상자나 #7685의 원본
행 높이 경계를 임의로 넓히지 않는다. source의 나눔 정책과 현재 계산 호스트 소유로만 결정한다.
`public-split-before-geometry-562.json`에 수정 전 실제 호출 출력이 있다.

## 원 PR의 간격 주장과 현재 원본의 차이

#8055 원 head `b5053178fc789e68bf232a3b776edc2e855ed55b`의 본문과 실제 테스트를

소비하지 않는 것이다. 원문은 한컴 기준을 확보하지 못했다고 명시한다. 이 계약을
