# #7642 저장 TAC 새 쪽 앞 조각의 빈 물리 공간 보존

Issue: #7642

## 독립 근거와 원인 경로

원본 `samples/issue1880_takeplace_host_before.hwpx`의10쪽 중 기존 후보 `664b952c88` Native는1쪽55.25867%,5쪽66.70831%가 미달이다. 이 단계는5쪽 경계를 보정하며1쪽의 호스트 원점 차이를 해결했다고 보고하지 않는다. Print는 기존 `stage3418-failed-originals-print/issue1880_takeplace_host_before-2020.pdf`를 유지한다. 같은 원본의 `6b946be400` 진단도 같은10쪽·내용 컷이다.

5쪽은 바깥 문단6의 행6 가운데 정렬 셀에서 유닛16 앞에 끝난다. 유닛15는 저장 vpos29874HU의 마지막 일반 글줄이고, 다음 유닛16은 문단9의 첫 TAC 자식 행이다. 생산 결과는 `hard_break_before=true`, `page_frame_reset_before=true`, `nested_row=Some(0)`다. 문단9의 원본 줄 상단은0, 높이5021HU이며 자식 표4739HU+위·아래 바깥여백141HU씩의 합과 정확히 같다. 다음 일반 문단의 vpos5621HU도5021HU+줄간격600HU와 일치한다. 실제 저장 쪽 재시작이며 수동으로 만든 pageBreak 속성은 아니다.

스캔은 다음 원본 쪽의 내용을 가져오지 않게 컷 `[2,16]`을 지켰지만, 현재 조각의 내용901.840px만 예약하고 가용973px의 남은 물리 띠를 표 밖으로 버렸다. 현재 행6은415.4px이고 그 안의 내용이 바로 위에서 시작한다. 독립 PDF는 같은 내용을 가진 행을 본문 끝까지 유지하고 가운데 정렬한다. 원본5쪽의 큰 괘선과 스캔·유닛·원본 XML은 `stage3605-original-host-source-analysis`에 보존한다.

## 적용 규칙과 반례

이미 유효성을 확인한 `stored_inline_owner_frame`과 `stored_inline_row_frame_content_height`를 사용한다. 새로 시작한 보통 행의 끝 컷이 다음 저장 쪽 원점0의 첫 TAC 행 바로 앞이고, 남은 모든 셀이 같은 재시작을 인증하거나 내용을 모두 소비했을 때만 현재 조각의 빈 물리 띠를 수용한다. 걸친 셀·중간 자식 행·가용보다 큰 현재 내용·원래 행 최소 높이를 넘는 확대·편집/재조판·무효 객체/줄 높이는 인증하지 않는다. 새 쪽의 TAC·후속 글은 이전 조각의 내용 컷에 추가하지 않는다.

`원본 호스트 줄과 자식 높이 → 같은 cell_units의 컷/소유 → 스캔의 가용 물리 높이 및 consumed/end_row_height_override/source_frame_band → PageItem의 저장 프레임 소유 → 같은 행 상자의 정렬/괘선`을 연결한다. 생산된 source_frame_band는 이미 예약한 빈 공간이다. 배치에서 후행 줄간격으로 다시 접지 않도록 그 소유를 PageItem에 전달한다. 기존에 양수 source_frame_band를 만든 저장 프레임도 같은 계약으로 보존한다. 화면 좌표나 문서 ID를 분기 조건으로 사용하지 않는다.
