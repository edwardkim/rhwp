## 입력과 독립 근거

저장소의 `samples/rowbreak-problem-pages.hwp`는 실제 저장 문서이며, 대응하는
`pdf/rowbreak-problem-pages-hwp-2024.pdf`의 18쪽을 기준으로 삼는다. 수동으로 LineSeg나
쪽수를 수정한 합성 입력으로 저장 정보 수용 조건을 완화하지 않는다. 사용한 로컬 글꼴과
글꼴을 포함하는 SVG는 공개 산출물에 포함하지 않는다.

## 마지막 행의 내용 컷과 물리 밴드 — 추가 보정 중

11쪽 직접 대조에서는 4.2/4.3의 내용 소유를 복원한 뒤에도 아래 테두리와 병합 셀 정렬 차이가 남았다.
원본 개체의 첫 프레임 16,840HU와 앞 행 합 14,535HU는 마지막 행의 물리 공간 2,305HU를 남긴다.
선택한 첫 내용 유닛의 줄 높이·안 여백만 예약하면 이 빈 공간을 잃는다.
`native_saved_two_line_row_frame`의 원본 줄·셀 높이 닫힘 증거를 컷 간격과
`saved_multirow_opening_frame_height`가 함께 사용하고, `fragment::emit`에서 예산 안의 실제
프레임 높이와 마지막 행 높이를 확정한 뒤 `layout_partial_table`이 같은 값을 소비하게 하는 후보다.
내용 컷은 그대로 두며 물리 빈 밴드를 뒤 유닛에서 차감하지 않는다. 아직 재출력·검증 전이다.

## 중첩 부동 표의 바깥 여백 소유 — 추가 보정 중

7쪽의 중첩 표 본체 상단·하단은 PDF와 맞았지만, 뒤 문단이 약 두 바깥 여백 합만큼 내려가 셀 경계에 걸렸다.
원본 HU에서 호스트 마지막 줄 5,280 + offset 1,124 + 위 여백 283 + 본체 13,331 + 아래 여백 283
= 뒤 문단 원점 20,301이다. `calc_nested_table_height`는 바깥 여백을 포함하는데
`ParagraphFloatPlacement::from_stored_host`가 이를 본체 높이로 받아 위·아래 여백을 다시 계상했다.
`nested_table_body_height`를 분리하고, 저장 float의 공통 배치 계획에는 본체만 전달한다.
일반 총 점유 높이 함수는 본체+바깥 여백을 유지한다. 같은 배치 계획을 컷의 요구 높이와 실제
표 원점·뒤 문단 흐름이 소비한다. 조건을 더 붙여 특정 표만 좁히거나 잘못된 좌표를 clamp하지 않는다.

## 검증 단계 체크포인트

최소 공통 메트릭 기초는 적용 승인 후 유지한다. 새 필드를 초기화해야 하는 기존 composer 테스트의
12개 생성자도 수정했다. 신규 테스트·기대값·baseline을 추가하거나 완화한 변경은 아니다.
11쪽 물리 밴드 보정 후 Native/fresh WASM의 18쪽은 모두 90% 이상이었지만, 7쪽의 여백
중복 계상 차이를 직접 판독으로 검출하여 추가 보정했다. 따라서 그 18쪽 결과는 최종 증거가 아니며
새 소스에서 7·8쪽과 전체 Native/fresh WASM을 다시 출력한다. 최종 회귀·lint·제출은 아직 미완료다.
