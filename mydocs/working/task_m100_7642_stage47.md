# 이슈 #7642 Stage 47 — 합·근호·복합 분수의 실제 수학 간격

Issue: #7642

## 기준과 실패 증거

시작 source는 `940c1802fc3484212b319d236a9f9c487c62a668`, 정책 base는
`79abd9e49675f4286eaed38197f7e837afb744e7`이다. 전체 55문서·853쪽 Native TSV는
이 source의 고정 바이너리로 문서 세 개씩 실행 중이며 fresh WASM·회귀는 미완료다.
알려진 다섯 쪽수 실패를 해결했지만 9/8/7 HWPX 10쪽 미주 7 수식 영역은
같은 독립 Print와의 2px 내용 실루엣 보조값이 86.02059%다. 페이지 96.43106%로
이를 면제하지 않으며 회귀 기대값을 바꾸지 않는다.

## 독립 메트릭과 원인 후보

원본의 첫 합·분수 수식은 BaseUnit 900 HU, 선언 폭 8391 HU다. 현재 Native의
내용 프레임 폭은 111.9지만 마지막 숫자 원점이 프레임 안에서 이미 113.07이다.
전체 수식을 선언 프레임에 가로 압축하면 실제 간격 문제를 숨기므로 사용하지 않는다.

Print의 PDFium 글자 객체는 원시 font size와 변환 matrix를 함께 소비한다.
이 PDF의 scale 0.12에서 75/51/135는 실제 9/6.12/16.2pt다. 따라서 첨자 0.68배는
정상이며 이 비율을 폭 차이의 원인으로 바꾸지 않는다. 실제 합 기호와 아래 첨자의
원점도 Native와 거의 일치한다. 첫 분수 괘선은 Print x=421.92이고, Native의
합 첨자 점유 끝에서 그 위치까지의 간격은 약 0.10em이다.

`BIG_OP_TRAIL_PAD=0.45`의 설명은 기존 `scale_x`가 자연 폭과 여백을 압축한다는
가정에 의존한다. 현재 `svg.rs`는 자연 가로 폭을 보존하므로 그 가정이 남은
예약 값을 정당화하지 못한다. 분수·근호의 내부 여백과 연산자 양쪽 간격도 같이
추적해 하나의 사유로 모두 축소하지 않는다.

ignored `stage47-native-equation-frame-and-glyphs.json`에는 원본 소유와 같은
SVG group의 실제 글자 원점, `stage47-print-equation-glyph-positions.json`에는
독립 PDF 객체의 글꼴·변환·원점이 있다. 공개 Latin Modern Math 글리프 메타데이터와
설치된 한컴 글꼴의 메타데이터도 분리해 읽었다. 한컴 글꼴 바이트·윤곽은 새 증적이나
Git에 포함하지 않는다.

## 묶음 분석·수정·검증 계획

1. 같은 합·복합 분수와 합 없는 분수·근호·단순 숫자 분수를 여러 BaseUnit으로
   정상 한컴 저장·Print 출력해 실제 논리 전진과 간격을 확인한다. MCP canonical
   `start → status → download`, 명시적 2024 engine을 사용하며 원본 PDF를 대체하지 않는다.
2. 큰 연산자의 첨자 점유 끝 → 다음 피연산자 원점, 분수의 자식 점유 → 괘선 여백,
   근호의 몸체 원점 → 다음 연산자 간격을 연결한다. 저장 폭·문서 ID·고정 px 좌표로
   분기를 만들지 않는다. 실제 글꼴·수학 구조의 공통 결과를 측정과 SVG/Canvas에 전달한다.
3. 근거가 모인 관련 수정을 묶어서 빌드한다. 원본 미주 7의 같은 영역·앞뒤 문단,
   정상 단순 분수·합·근호와 요청 corpus의 영향 페이지를 비교한다. 실패 영역의
   90% 이상과 직접 판독을 확인한 뒤 fresh WASM·전체 TSV를 실행한다.
4. 관련 입력의 모든 페이지·출력 경로가 90% 이상이고 확대 판독도 충족하면 #1139
   전체와 관련 회귀를 소유·순서·보존·포함·겹침 관계로 변경한다. 원래 55문서 검증과
   전체 회귀·필수 lint·PR/CI·trailing·머지·후속 처리는 계속 남아 있다.

TSV·JSON·실행 로그·nextrun은 ignored output에 보존하고 Git에 커밋하지 않는다.

## 정상 저장·Print의 독립 계약 확인

한컴 2024 `13.0.0.3901`의 정상 저장 job
`803233e1-9a70-48a7-b826-f2b55e4934cc`, Print job
`666cf7d5-e108-46f1-a0df-5c5c975d79a8`을 완료했다. Print의
`pdf_print_method=0`, `pdf_output_mode=frame_print_to_pdf_ex_one_up`을 확인했다.
독립 PDF SHA-256은 `75bd13336bc9283122f0617d080e1fcbe1c48b12d6df2067af6fe36c9c844d5c`다.
성분 저장 job `16237bca-fbee-42aa-a581-2aee38336e09`도 정상 완료했다.
진단 입력은 RHWP가 작성한 프레임을 정답으로 쓰지 않고 한컴이 다시 계산한 저장 폭과
그 저장본의 Print로 대조한다. 이 자료는 기존 corpus PDF를 대체하지 않는다.

네 글자 크기 모두에서 `sum x`의 폭은 `sum` 단독 폭과 `x` 단독 폭의 합과
정확히 같다. `sum {1 over 2}`도 같은 성질을 만족한다. 따라서 합 뒤 추가
0.45em은 없어야 한다. 앞서 괘선의 잉크 시작에서 약 0.10em으로 추정한 값은
분수 괘선 자체의 안쪽 여백을 포함한 관측이므로 합의 전진 간격으로 쓰지 않는다.

`sqrt{a_k}+sqrt{a_{k+1}}`의 폭에서 두 근호 성분의 폭을 빼면 다음과 같다.
분수 `({sqrt{kd}-sqrt{(k+1)d}}) over {-d}`도 분수 여백과 두 근호 성분을
분리해 같은 방식으로 확인했다. 근호가 이미 예약한 끝 여백 위에 왼쪽 연산자
여백을 다시 더하는 것이 초과 원인이다. 분수 자체의 1/4em 여백은 정상이다.

| BaseUnit HU | `+` 경계 HU | `−` 경계 HU | 독립 계약 |
| --- | --- | --- | --- |
| 600 | 534 | 534 | 해당 glyph 전진 + 오른쪽 0.14em |
| 900 | 801 | 801 | 동일 |
| 1200 | 1068 | 1068 | 동일 |
| 1800 | 1677 | 1602 | 서로 다른 glyph 전진 + 오른쪽 0.14em |

`−`는 설치·Print 메트릭의 전진 774/1024를 사용한다. 현재 fallback은 정규화된
이 값을 소비하지 않아 근호 경계의 여백도 중복한다. 합의 실제 첨자 상자와
근호의 몸체·기호 크기는 바꾸지 않고 위 전진 계약만 공통 Row에 반영한다.
상세 원본 값은 ignored `stage47-independent-operator-gap-contract.json`,
`stage47-spacing-probe-saved-widths.json`, `stage47-saved-component-widths.json`에 있다.

## 전체 TSV에서 추가로 확인한 미주 경계

2022 HWPX의 19쪽은 67.09313%, 2023 HWP의 19쪽은 79.55750%로 미충족이다.
같은 source의 전쪽 캡처에서 새 review를 합성해 직접 판독했다. 2022 HWPX는
문28 제목이 Print의 18쪽 끝에 있어야 하지만 Native는 19쪽 첫머리에 둔다.
Print 제목 상단 1065.54와 앞 줄 점유·설정 gap의 관계가 맞고, 원본 제목
스타일의 `keepWithNext=0`, `keepLines=0`, `pageBreakBefore=0`도 확인했다.
실제 호출 로그는 `paragraph.rs:1268`의 제목·다음 본문 묶음 추정에서 단을
넘긴다고 입증한다. 선행 실제 제목 fit을 이 호출 전에 소비하고, 명시적 묶음이
없는 제목을 다음 본문과 임의로 한 그룹으로 만들지 않는다.

2023 HWP는 같은 19쪽 안에서 문29 제목 이후의 간격·원점 차이가 남는다.
이 문서를 2022 HWPX와 같은 앞쪽/뒤쪽 제목 소유 결함으로 단정하지 않는다.
별도 실제 호출·앞 문단 예약을 추적하며 이번 수정의 자동 통과 대상으로 보고하지 않는다.
두 새 review는 ignored `stage47-current-whole-failed-reviews/` 아래에 있다.

## 묶음 구현과 Native 1차 검증

합 뒤 추가 전진을 제거하고 근호가 이미 예약한 연산자 앞 여백을 중복하지 않도록 했다.
뺄셈 기호도 독립 전진 메트릭을 공통 Row에 전달한다. 새 미주 제목의 실제 fit 조회를
제목·본문 묶음 추정에 따른 단 이동보다 먼저 소비하며, 명시적 keep-with-next가 있는
제목에는 이 선행 유지 계약을 적용하지 않는다. 앞 내용을 실제로 emit한 경로는 조회를
다시 수행해 변경 전의 흐름 상태를 재사용하지 않는다.

Native release-test 빌드는 617.23초, exit 0이다. source 1453개 파일의 해시를
빌드 전후 대조했다. frozen binary SHA-256은
`6d65b285dcd898d1351defa894177657ead308bbfa2873d6b72d32355ff862dc`다.
`cargo fmt --all -- --check`와 Native Clippy `-- -D warnings`는 각각
33.04초·135.19초, exit 0이다. 나머지 필수 lint와 전체 회귀를 통과했다고 주장하지 않는다.

실제 canonical Visual Sweep summary와 overlay metrics JSON에서 위 값을 읽었다.
외부 묶음 driver의 요약 수집은 summary의 `overlay_metrics`를 페이지 배열로 잘못 읽어
예외가 발생했다. 이는 렌더 실패와 구분하고, 완료된 canonical 실행 원문에서 결과를
별도로 수집했다. 다음 실행의 driver는 `overlay_metrics_json.pages`를 읽도록 수정했다.
이 오류 때문에 같은 렌더를 재실행하거나 테스트 통과로 대체하지 않는다.

진단 중 2023 HWP의 실제 `VPOS_NOTE_GAP`/`VPOS_CORR`에서 앞 줄 점유 끝
457.7733, 문서 gap 1984 HU와 별개로 고정 18px가 추가된 502.2267 원점을 확인했다.
이 원인은 `height_cursor.rs`의 다줄 tail 완충 분기다. 별도 단계에서 실제 줄 점유와
미주 소유를 소비하도록 수정한다. 2024 9월 20/20 HWP/HWPX의 여러 쪽 배치 차이도
전쪽 TSV에서 확인했으며 미검증·미충족 범위로 남긴다.

종료된 `native-all-requested`, `native-all-requested-stage25`의 재생성 가능한 SVG만
정확한 경로로 제거해 24.60GiB를 확보했다. 입력·독립 PDF·PNG·TSV·로그·JSON·실행 중
검증과 공유 Cargo target은 보존했다. 정리 원장은 ignored `stage47-old-svg-cleanup.json`이다.
새 원본 전체 Native 측정은 계속 실행 중이다. fresh WASM·관계형 회귀 변경·최종 전체
검증·PR 생성은 아직 완료하지 않았으며 페이지 통과로 수식 확대 미달을 면제하지 않는다.
