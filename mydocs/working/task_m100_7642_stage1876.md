# #7642 국어 14쪽의 세로선과 홀수형 상자 재검토

Issue: #7642

## 범위와 기준

사용자가 지적한 `samples/exam_kor.hwp` 14쪽의 오른쪽 세로선과 바탕쪽의 홀수형 상자를
우선 확인했다. 기준은 원본과 대응하는 독립 한컴 Print
`pdf/issue7642-exam-print/exam-03-exam_kor-hwp-print-2020.pdf`다.
이전 확대 판독에도 외곽과 글자 차이가 남았다. 페이지 점수로 이 차이를 완료 처리하지 않는다.

`upstream/devel`의 `0953598d8e08af5e9149b3e4cdbbbf2f5f2bae64` 위로 리베이스했고,
검증한 제품 head는 `e05ed324898cf60efafb309102f1d1ea666a95cb`다.
기존 29개 문서·220쪽의 양쪽 90% 이상 결과는 리베이스 전 제품의 증거다.
이 기록은 새 head에서 다시 확인한 범위만 보고한다.

## 새 head 검증 결과

1876단계 Native와 1877단계 fresh WASM은 같은 제품 source hash를 사용했고,
빌드 전후 변경이 없었다. 공유 `target/pr-review`에서 빌드 잡 8개로 순차 빌드했다.
root `pkg`와 Studio public JS/WASM의 hash도 일치한다. 생성된 Studio JS를 함께 보존한다.

| 원본 | 독립 Print 쪽수 | Native 최저 | fresh WASM 최저 | 누락·쪽수 차이 |
| --- | ---: | ---: | ---: | --- |
| `samples/exam_kor.hwp` | 20 | 92.19571% | 92.23388% | 없음 |
| `samples/hwpx/exam_kor.hwpx` | 20 | 92.19571% | 92.23388% | 없음 |

문단 외곽·인라인 개체·캡션·수식 대조군의 기존 36개 검사는 1884단계에서
**36 PASS / 0 FAIL**이다. 전체 Rust 검증이나 전체 문서 gate를 마쳤다는 뜻은 아니다.
전쪽 TSV, 실행 로그, JSON과 진단 source는 ignored `output/pr-review/issue7642/`에만 둔다.

## 사용자 지적 영역의 미해결 상태

14쪽의 Native **99.74686%**, fresh WASM **99.72217%**는 페이지별 수치다.
같은 좌표를 3배로 확대하면 세로선과 홀수형 상자가 여전히 다르다. 완료 판정을 보류한다.

- 세로선은 Native x=1005.3333, 독립 Print x=1004.1813 CSS px로 약 1.15px 차이다.
  양쪽 선언 선폭은 0.48 CSS px다. 실제 96dpi PNG의 220·675·1150행에서 Native의
  1004열은 233~234, 1005열은 198~199의 회색이고, PDF의 1004열은 검정(0)이다.
  위치와 얇은 선의 래스터 농도를 따로 확인한다. 이 수치를 화면 보정 상수로 쓰지 않는다.
- 홀수형은 원본 한양견고딕 HFT(Type3)와 선택된 HYgtrE TTF의 윤곽이 다르다.
  예를 들어 ‘홀’의 Print 제어점 범위는 em 기준 x=0.061..0.938, y=-0.087..0.790이고,
  설치 TTF의 실제 윤곽 범위는 x=0.03125..0.96875, y=-0.09863..0.83594다.
  자간 이동만으로 이 차이를 해결했다고 하지 않는다.
- 같은 원본을 MCP 2020에서 다시 Print했다. 실제 제품은 11.0.0.9136이며,
  `pdf_print_method=0`, `pdf_output_mode=hancom2020_pdf_driver_one_up`, 전체 20쪽이다.
  새 PDF SHA-256은 `ed495ce993b0f9f278c71ce95a0c31e58da3e930f72fc45f59733b5453564a5b`다.
  기존 기준과 14쪽의 벡터·글자 원점 및 PyMuPDF 원시 렌더 바이트 SHA가 같다.
  기존 기준 PDF를 유지한다.

## 독립 용지·선 종류 대조군

수동 작성 HWPX를 열고 한컴 `PageSetup`으로 A3(84188×119052 HU), A4(59528×84188 HU),
Letter(61200×79200 HU)를 각각 설정했다. Windows PowerShell과 COM 11.0.0.9136의 실제
읽기값 및 저장 HWP의 `page_def`가 모두 이 값과 일치한다. 원격 작업 전 Hwp 프로세스가
없었고, 자기 COM을 종료한 뒤 프로세스 0개와 자기 임시 경로 삭제를 확인했다.

초기 수동 HWPX의 용지 정보는 한컴이 모두 A4로 열었다. 초기 저장본을 용지별 독립 증거로
사용하지 않고 실패 관측을 output에 보존했다. 보정된 진단 입력은 다음과 같다.

| 용지 | 정상 저장 HWP | 독립 Print PDF | Native / fresh WASM |
| --- | --- | --- | ---: |
| A3 | [HWP](../../pdf/issue7642-paper-shape-controls-authored-20261016/a3-authored.hwp) | [PDF](../../pdf/issue7642-paper-shape-controls-authored-20261016/a3-authored-2020.pdf) | 97.79443% / 97.79443% |
| A4 | [HWP](../../pdf/issue7642-paper-shape-controls-authored-20261016/a4-authored.hwp) | [PDF](../../pdf/issue7642-paper-shape-controls-authored-20261016/a4-authored-2020.pdf) | 97.84755% / 97.84755% |
| Letter | [HWP](../../pdf/issue7642-paper-shape-controls-authored-20261016/letter-authored.hwp) | [PDF](../../pdf/issue7642-paper-shape-controls-authored-20261016/letter-authored-2020.pdf) | 98.42874% / 98.42874% |

실제 Print는 모두 engine 2020, 11.0.0.9136, method 0,
`hancom2020_pdf_driver_one_up`, 전체 1쪽이다. 각 입력에는 다음 9개 도형이 있다.

1. 실선: 36 / 60 / 425 HU.
2. 같은 굵기 이중선, 가는/굵은 이중선, 굵은/가는 이중선, 삼중선: 각각 425 HU.
3. 굵은/가는 이중선: 1600 HU.
4. 둥근 굵은/가는 이중선: 425 HU.

PAPER 기준 좌표·원본 선 속성·정상 저장값을 대조했다. 전쪽 Native/fresh WASM TSV도
산출했다. A3의 실제 review/overlay에서는 복합선이 단선으로 합쳐진 결함이 직접 보인다.
따라서 이 자료를 정식 fixture/golden/회귀에 등록하지 않는다. 원본 시험지의 검증을
대신하지 않는 진단 자료로 보존한다.

## 다음 구현과 보류 범위

사용자가 이중선 누락을 추가로 지적했다. `drawing_to_shape_style`에서
`LineRenderType`을 버리고 dash만 소비해 일반 사각형의 복합 선 종류가 소실된다.
선 종류와 폭에 따른 닫힌 띠의 기하를 공통 layout에서 만들고 Native/Canvas/SVG가
같은 결과를 소비하도록 보정한다. 직선·표 테두리의 기존 비율을 근거 없이 복사하지 않는다.
정상 저장 도형에서 폭을 바꾼 추가 대조군의 선과 빈 간격을 먼저 측정한다.

현재 단계는 독립 근거와 재현을 보존한 진행 커밋이다. 세로선·HFT 윤곽·복합선,
고정 devel 대비 하락, 남은 Rust 실패와 전체 PR gate는 미완료다.
PR 생성·승인·통합은 보류한다. 다음 실행 인계도 ignored output에만 둔다.
