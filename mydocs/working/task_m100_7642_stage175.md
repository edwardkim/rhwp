# #7642 Stage 175 — 그림 목적 점의 표준 압축 표현

Issue: #7642

## 근거·호출 경로·반례

동일 #6469 원본·독립 Print를 유지한다. Stage 174의 압축 PNG/JPEG 객체는
수용됐지만, 해당 그림을 배치하는 `DrawImagePoints`의 C=1을 거절해 전체
EMF+가 legacy WMF로 돌아갔다. 그림 bytes와 목적 점은 서로 다른 표현 계약이다.

[MS-EMFPLUS DrawImagePoints](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emfplus/9bad3867-71b0-46fb-9b90-f7d8fb37ff76)는 P=0/C=1에서
40바이트 데이터·세 개의 [signed 16bit Point](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emfplus/a0558721-f6df-4325-b455-a0e6edf63cf4),
P=0/C=0에서 52바이트 데이터·세 개의 float PointF를 정의한다.
원문 bitmap 네 개는 전자, nested metafile 세 개는 후자다. P=1 상대 점은
별도 표현이며 이번에 추측해 읽지 않는다. 예약 비트로 그림 ID를 바꾸지 않는다.

표현을 읽은 뒤 같은 f64 목적 삼각형 → source-to-destination 행렬 →
world transform·SrcRect·TileFlipXY·clip → 공통 Image SVG·paint를 소비한다.
고정 px 이동·문서별 예외·바깥 그림 크기로 원본 크기 대체를 하지 않는다.
사전 재생에서는 원문의 image3/4/5를 모두 실행해 다른 거절 지점을 확인한다.
그 결과는 최종 시각 판정을 대신하지 않는다. Native/fresh WASM 전체 15쪽과
아이콘·그림 경계의 확대 판독 후 새 이름의 정식 관계형 검사를 추가한다.

## 전체 메타파일 경로의 사전 재생

수정한 실제 EMF+ 모듈에 거절 지점 기록만 추가한 독립 진단을 컴파일했다.
원문의 image3/4/5 세 EMF 모두 전체 재생 수용(exit 0)을 확인했다.
float 목적 점의 정상 대조군 두 개와 signed 정수 목적 점·압축 그림 혼합을 함께
실행했다. 이 결과는 렌더링·Print 일치 판정이 아니며 Native 페이지 대조가 이어진다.
진단 실행 파일은 공용 `target/pr-review/release-test/stage175-emfplus-preflight`이고
코드 출처·명령·로그는 ignored `stage175-emfplus-preflight.json`에 보존한다.
