# #8856 그림 효과 반경의 조판·그리기 전달

기호의 엄격 하락을 복원한 `193f03a6bd`를 커밋한 뒤 이 단계를 시작한다.
효과의 원 해결 #8656과 후속 읽기·저장 보정은
`task_m100_8856_stage5.md`의 원시 레코드·독립 한컴 HWPX·8개 Print 대조군을 따른다.
기준 PDF나 효과 반경을 바꾸어 출력 차이를 숨기지 않는다.

현재 PictureEffects에는 HU 반경이 있지만 ImageNode에는 그 필드가 없다.
따라서 HWP/HWPX 왕복 저장은 통과해도 조판 트리와 공통 PaintOp가 반경을 잃는다.
원본 Picture를 조판하는 일반·셀·inline·각주 경로를 함께 확인하고, 이미지 노드에
선택적인 HU 반경을 전달한다. 그림 채움 등 원래 효과가 없는 경로에는 None을 유지하며
JSON도 None을 생략해 기존 무효과 출력 계약을 보존한다.

설치 글꼴 없는 관계 검사로 원본의 반경 목록과 모든 페이지의 ImageNode 및 Print PaintOp
반경 목록을 비교한다. 파싱·저장과 실제 소비 경계를 분리한 검사이며 반경을 전달했다는
사실만으로 사진 마스크 도색을 완료했다고 표현하지 않는다. 부드러운 가장자리의 계산·자르기
순서·기존 alpha·변환 및 backend 소비는 독립 대조군과 별도로 검증한다.

마스크의 정수 표본 분석에서는 16×16 Bayer 문턱과 255 불투명 특례를 구분한다.
단일 열의 넓은 alpha 구간만으로 Gaussian 공식이라고 단정하지 않는다. 단조 제약으로
관측 구간을 좁힌 중간 분석은 output에만 두며 제품 공식·최종 시각 통과로 사용하지 않는다.

## 실행 결과

원본 반경의 모델·저장 검사 3건은 PASS였지만 조판·그리기 전달의 새 검사는
`interview.hwp`의 기대 `[1000]` 대비 실제 `[]`로 FAIL했다. 반경을 6개 그림 생성 경로와
공통 ImageNode에 전달한 뒤 4 PASS가 됐다. 무효과 그림의 JSON 필드 생략, 기존 #8593
크기·자르기 2건과 앞 단계 기호 검사 1건도 최소 글꼴 Native에서 통과해 총 7 PASS다.

같은 30000×20000 HU 출력 틀에서 원래 크기·확대 행렬을 2×2 또는 2×1로 바꾼 대조군과
각 축 양끝을 10% 잘라낸 대조군을 두 엔진으로 Print했다. 2020 11.0.0.9136과
2024 13.0.0.3901의 실제 6건이 모두 1쪽이다. 확대 두 조건의 마스크는 각 엔진에서
기존 동일 반경 대조군과 전표본 일치한다. 자른 대조군의 표본 차이는 2020 156개,
2024 2개이며 새 경계의 감쇠는 유지된다. 원 bitmap의 효과를 먼저 적용하고 자르는 방식과
구분해야 하며, 이 결과만으로 내부 blur 공식을 확정하지 않는다.

원본·PDF·해시·직접 비교와 실제 검사 기록은
`mydocs/pr/assets/issue8856/stage7-soft-edge-transport/`에 보존한다.
