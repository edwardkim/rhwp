# Stage 412 — 네모 숫자와 일반 네모의 전진 계약 분리

Issue: #7642
수정 전 source: `fe55746368436da939c4e405690f24e773a9f89b`
검증 base: `22317614b03722e95349a1d3d71c86923363c6f5`

## 독립 근거와 원인

원본은 `samples/issue6172/2599643_port_call_form.hwp`, 기준은
`pdf/issue7642-failed-inputs-followup-20261011/2599643_port_call_form-2020.pdf`다.
입력 SHA-256은 `94b705e86e3894c14d38ffa8469e662426e2ddc3b86aa2013f99a4999afd2f1e`,
PDF SHA-256은 `3e23db3c4d9da6a5163a16b59ab7e803b5e15e1ff1a24993cd167a1f28dc5b1a`다.
기존 독립 Print 생성 기록을 재사용한다.

PDF의 Haansoft Batang 네모 숫자 hmtx와 설치 프로그램의 같은 PUA를 대조하면
전진은 1024/1024em이다. 반면 PDF Batang의 일반 `□`는 911/1024em이다.
기존 Batang 메트릭 DB는 U+25A1을 수집하지 않아 전각 추정으로 떨어진다.
기존 네모 숫자도 일반 `□`로 바꿔 측정하므로 서로 다른 두 계약이 섞여 있다.
일반 네모의 초과 전진이 셀 가운데 정렬의 줄 시작점까지 바꾼다.

## 변경과 실제 소비 경로

기존 검증 메트릭 보충 경로에서 Batang Regular의 결측 U+25A1만 실제 hmtx로
보충한다. 이미 수집한 폭, 다른 face·굵기·이탤릭의 폭은 유지한다.
네모 숫자는 기존 합성 전진 계약의 1em으로 측정하며 일반 네모로 치환하지 않는다.
문서 ID·화면 좌표·셀 번호 조건을 코드에 넣지 않는다.

`FontMetric::get_width → char_width_decision → 공통 글자 위치/문단 정렬 →
SVG·Canvas·Skia의 layout_positions 소비`를 대조한다.
원본 HWP와 글자모양의 font size/ratio는 수정하지 않는다.

## 별도로 남는 그리기 결함

기존 사각형 0.72em·숫자 0.5em 합성도 독립 PDF보다 작다.
실제 Haansoft Batang PUA 글리프 경계는 PDF와 같지만 합성이 이를 대체한다.
같은 원점에서 실제 글리프로만 바꾼 ignored 진단은
`stage408-boxed-font-source-diagnostic/before-font-source-print-detail.png`다.
이 진단은 제품 수정 결과가 아니다. 본 단계의 전진 보정으로 그리기 결함이나
전체 문서·회귀 검증 완료를 선언하지 않는다.

## 검증 계획

공용 `target/pr-review`, 빌드잡 8개·테스트 스레드 12개를 사용한다.
현재 대상의 Native/fresh WASM 재출력과 독립 Print 확대 대조에서 네모 숫자·
일반 네모·하이픈의 순서, 줄 가운데 정렬, 전진 간격을 확인한다.
Batang 일반 네모를 사용하는 정상 대조군과 네모 숫자만 있는 반례도 대조한다.
실제 그리기 결함까지 보정한 뒤 전쪽 90%·직접 판독을 충족하고 새 이름의
관계 검사를 추가한다. 기존 #6172 검사·기대값은 아직 변경하지 않는다.
