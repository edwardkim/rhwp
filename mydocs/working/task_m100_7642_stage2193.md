Sweep 스크립트·Cairo·96DPI에서 다시 출력한다. stage2187의 Native 부분 비교는

판정과 같은 이진화·2px 이웃 마스크를 바꾸지 않고 불일치 위치만 조사했다.
수식 bbox의 위쪽 변화는 SVG의 내부 baseline에서 상쇄되고 있었다. 오히려
추가된 불일치의 큰 부분은 분홍색 `기하` 글상자의 바깥 이중선이었다.
source Path는 87.982부터 칠하지만 Body clip은 90.702부터여서 바깥 띠가 잘린다.
독립 PDF에는 두 띠가 모두 있다. 단일 굵은 선이던 base는 이 문제를 가렸다.

stage2192는 원본·PDF를 바꾸지 않고 진단 SVG의 clip에 실제 경로 범위를
반영했다. 같은 rsvg 진단 출력의 raw는 97.00614→98.14367%다. 이 값은
Native/fresh WASM 완료나 새 head의 검증으로 재표기하지 않는다.

## 원인 계층의 보정

`filled_path_bounds`는 실제 PathCommand와 painter의 중심·회전·대칭 순서에서
채움 경계를 계산한다. 3차 곡선은 도함수의 내부 극값을 사용하고 호는 기존
공통 arc→cubic 계약으로 계산한다. 배치 bbox와 합쳐 기존 `expand_clip`에만
전달하며 원본 bbox·변환 원점·쪽 배치·선의 비율을 바꾸지 않는다.
기존 셀 clip과 실제로 clip하는 글상자의 자손도 상위 clip을 확대하지 않게 한다.
기존 flow/float 분류와 용지 하단 상한은 그대로 소비한다.

생산 경로는 `compound_rectangle::append_border`의 실제 채움 Path, 소비 경로는
`layout.rs::expand_clip`→Body.clip_rect→공통 LayerBuilder→각 painter다.
같은 배치 bbox를 실제 ink 범위인 것처럼 재사용한 가정을 제거했다.
아직 새 source의 Native/fresh WASM·반례·정식 회귀를 실행하기 전이다.

## WMF 반올림 가정의 반박

stage2182·2183의 가로·세로 8개 Print에서 18005 HU의 768:512 원본은
2250×1500인데 현재 연속 배율 계산은 2251×1500이다. 반대 방향도 같다.
그러나 같은 축 배율의 stage2185·2186에서는 18003×12002 배치가
1499×999, 18006×12004가 1501×1000, 나머지는 1501×1001이었다.
단순히 한 축을 round하고 나머지를 원본 비율로 고정하는 가정도 이 반례를
설명하지 못한다. 추정 ceil/floor나 문서별 1px 보정을 제품에 추가하지 않았다.
이 진단과 실제로 잘리는 본문 테두리의 원인을 구분했다.

## 완료된 이전 source와 새 검증의 구분

stage2169의 source 6b363c39ed fresh WASM은 실제 빌드·package 동결·Studio
동기화까지 끝났다. stage2190은 그 package와 현재 Studio 글꼴 세션을 연결해
실제 PNG 직접 전달·동일 세대 재사용·오래된 문서 소유자 거부를 다시 확인했다.

새 빌드·정상 문서 전쪽 Native/fresh WASM·확대 판독·devel 비교를 수행한다.
새 회귀는 전쪽 90%와 직접 판독 뒤에 새 이름으로 추가한다. 기존 golden·핀을

독립 반올림 반례의 원본/PDF 네 쌍도 기존 공식 진단 디렉터리

`metafile-fractional-aspect-explicit-pen`, `metafile-rounded-axis-controls`,

실제 `-2024.pdf`다. 작은 파일이며 비공개 글꼴은 포함하지 않는다.
이 파일들의 존재를 Native/fresh WASM 시각 수용으로 세지 않는다.

기존 이관 범위도 GitHub 원문으로 확인했다. 파일명에 `7418`이 든 ASCII

남은 정상 검사를 추가 삭제하지 않았다. 원문·현재 댓글은 로컬 증적에 보존했다.
