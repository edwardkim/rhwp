## 사용자가 지정한 SPJGT의 실제 시험

사용자가 존재하지 않는 `RHWPIndependentHFTSourceSymbols` 대신 `SPJGT.otf`를 시험하도록
지시했다. 파일은 private 복사본으로 공급했고 원본 TTF → 검증 TTC → CFF 순서를 유지했다.
시스템 설치나 상용 글꼴 바이트의 Git 반영, 윤곽·CMap·폭 수정은 하지 않았다.

기존 명시 환경의 없는 기호 family를 SPJGT의 PS명 또는 family명으로 일괄 바꾼 시험은
Native 61·74·91쪽 99.98%·99.86%·100.00%, WASM 100.00%·99.88%·99.96%다.
WASM 91쪽이 하락하고 확대 화면에서도 원의 크기가 달라 이 대체는 채택하지 않는다.
74쪽의 틸데 높이 차이도 남아 점수 상승을 틸데 해결로 기록하지 않는다.

같은 SPJGT와 확보된 원본 글꼴을 공급하고 없는 family를 가리키던 명시 환경을 제외해
실제 원본 선택 경로를 실행한 별도 시험에서는 다음을 확인했다.

| 쪽 | Native raw | fresh WASM raw |
| --- | --- | --- |
| 61 | 100.00% | 100.00% |
| 74 | 100.00% | 99.99% |
| 91 | 100.00% | 99.98% |

세 쪽의 개선은 전체 보호 통과를 뜻하지 않는다. 같은 공급 조건으로 base·후보의 103쪽 전부를
양쪽에서 재측정 중이며 페이지별 최댓값을 조합하지 않는다. 원본 선택의 실제 공급 기록과
독립 PDF 확대 판독도 함께 확인한다. 기존 보호 하한은 변경하지 않는다.

Windows에서 SHA가 일치하는 원본 H2GTRE·H2HDRM TTF를 공급한 시행령 4·24·45·63쪽은
base·후보가 같지만 기존 보호 하한의 미달이 해소되지 않았다. 이 결과도 실패 진단으로 보존한다.
화학·사양서의 기존 공급 목록 순서 복원 진단과 별개이며 전체 보호 완료로 합치지 않는다.

## 남은 검증과 자원 관리

전체 정본 보호 검증은 계속 진행 중이다. Studio 여정 중 눈금자 문서 전환은 브라우저
`Runtime.callFunctionOn` timeout으로 종료되어 같은 명령으로 재실행 중이다. 나머지 여정의
성공으로 이 실패를 상쇄하지 않는다. 승인된 검증을 마친 뒤 제출 준비 여부를 판정한다.

사용을 마친 과거 원본 출력 PNG 9,072개만 실제 프로세스 참조와 재사용 경로를 확인해
정리했다. 입력·PDF·TSV·manifest·로그·base 출력·최종 출력은 보존했고 실사용 공간
685,195,264바이트를 확보했다. 삭제 목록과 SHA를 같은 증거 폴더에 기록했다.
