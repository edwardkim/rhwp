# #7642 본문 점유와 레거시 미주 예산의 분리

Issue: #7642

## 규칙과 독립 근거

본문 줄·표의 적합성 판단은 실제 본문 영역과 각주 예약을 사용한다. 레거시 변환 출처의 페이지네이션 허용치가 있다는 이유로 일반 본문의 글줄까지 물리 영역 밖에 수용하지 않는다. 미주의 기존 단 흐름 허용치는 별도 계약으로 유지한다. 문서 식별자·고정 좌표·본문 시작 비율 분기를 추가하지 않는다.

sample4 HWP5 변환본의 문단218은 마지막 줄의 물리 하단893.333px가 본문876.853px를 넘지만, 추가 예산21.333px 안에 들어 전체 문단으로 수용됐다. 독립 한컴 Print는 그 줄을8쪽에 둔다. HWP3 원본은 명시적인 저장 쪽 표식으로 같은 위치를 나눈다. 허용치0 진단에서도 변환본7·8쪽의 내용 소유와 위치가 원본과 일치했다. 무변경 복제본의 해당 렌더 트리는 원본과 바이트 단위로 같았다.

진단은 ignored `stage3505-legacy-flow-budget`와 `stage3506-sample4-source-flow-traces`에 보존했다. SO-SUEOP의 원본 HWP/HWPX와 허용치0 복제본도 대조했다. HWP의 미주128·129는 현재 이미45쪽이며, HWPX와 독립 PDF는44쪽이다. 따라서 오래된 주석의44쪽 복구 주장을 현 후보의 통과 증거로 재인용하지 않는다. 이번 수정은 미주 허용치를 보존하며 이 미해결 차이를 숨기지 않는다.

## 생산과 소비

`PageLayoutInfo::physical_body_height`는 본문 높이에서 실제 각주 영역을 뺀다. `TypesetState::base_available_height`는 일반 본문에 이 결과를, 미주에 기존 허용치 포함 결과를 전달한다. `available_height`의 각주·존 예약, 전체 문단 fit, 줄 스캔·분할, 표 예약이 이 공통 값에서 계산된다. 다단 경계 감지와 단 시작 예산 조회도 같은 state 결과를 쓴다. paint의 본문 원점·용지 크기는 바꾸지 않는다.

저장 경계와 개체별 기존 넘침 계약을 없애거나 출력 좌표를 clamp하지 않는다. 이번 변경의 영향 범위는 추가 허용치가 있는 입력의 본문 흐름이며, 미주 흐름·허용치0 입력은 대조군이다.
