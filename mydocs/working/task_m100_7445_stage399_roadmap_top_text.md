# 단계 399: 로드맵 44쪽 상단 글자 시작점

## 사전 분석

- 사용자가 상단 행의 여백 차이를 지적했다. 최신 실제 PNG와 독립 한컴 Print PDF의 벡터 좌표를 함께 확인했다.
- 첫 행 상단은 Native 136.0px, PDF 136.0107px이다. 글자 기준선은 Native 150.3867px, PDF 150.2358px이다. 표 상단을 임의로 이동할 근거는 없다.
- 첫 기호 `∘`는 U+2218이다. PDF의 `/T8` ToUnicode `<08> <2218>`와 같은 코드의 `/Widths` 1000, FontMatrix 0.001은 자연 전진폭 1em을 명시한다. 기존 한양신명조 메트릭은 U+2219만 보완하며 U+2218은 반각 폭으로 떨어진다.
- Native 기호 원점 219.8933px 뒤 ‘양’이 233.1300px에 시작하지만 PDF는 기호 219.7209px, ‘양’ 239.5502px이다. 기호의 폭 오류가 뒤 글자를 왼쪽으로 당긴다. 일반 공백이나 셀 패딩을 바꾸지 않는다.
- 원본 face에 대한 독립 PDF의 글리프 전진폭을 기존 메트릭 조회에 보완한다. 공통 글자 측정 → composed run 전진 → 실제 SVG/Skia/WASM 글자 원점이 이를 소비한다. 문서 ID, 페이지 번호, 임의 좌표 보정은 추가하지 않는다.
- 기호 뒤 굵은 글자와 숫자의 누적 간격 차이는 별도로 대조한다. 2px 보조값 100%만으로 미세 간격까지 완료로 판단하지 않는다.

## 검증 계획

기존 메트릭·관련 문서 소속·넘침 회귀를 재실행한다. 새 Native와 fresh WASM의 실제 44쪽 review PNG에서 첫 행을 확대 확인하고, 전체 302쪽 TSV로 누락·쪽수·미달 여부를 다시 확인한다. 새 회귀 테스트와 허용치 변경은 추가하지 않는다.

## 구현과 첫 검증

- 한양신명조의 U+2218 자연 전진폭을 기존 U+2219와 같이 1em으로 보완했다. 원문 기호와 공백·장평·자간·셀 상단 좌표는 보존한다.
- `cargo fmt --all -- --check`와 `git diff --check`를 통과했다. 기존 메트릭·문서 소속·본문 넘침 nextest는 새 코드로 컴파일 중이며 완료 결과는 아직 없다.
- 하단 보정 코드의 추가 기존 검사 12 PASS / 0 FAIL과 Native/WASM32 Clippy PASS는 이전 코드 후보의 결과다. 이번 글리프 폭 변경의 회귀 통과 증거로 대신하지 않는다.
- 이전 fresh WASM 시각 검증의 실행 중 캡처를 보존한다. 대기 중이던 다음 WASM 빌드만 새 코드 후보 검증으로 대체하고, 실행 중 Cargo를 중단하지 않았다.
