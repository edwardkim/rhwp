# #7642 Stage 142 — HWP3 외부 문서 재조판과 회귀 의미 복원

Issue: #7642

## 구현 전 독립 근거와 반례

생산 source는 `68d8bf777f4a5c5ef54c85f4ee5c0613eb6534d1`, 정책 base는
`bfa28a77a2714482f647ee6a7b9aa7f7876d8404`다. Stage 141의 Native/fresh WASM 빌드는
종료했고 같은 source의 30개 관계형 검사도 모두 통과했다. 전체 55문서/853쪽의 완료와
원래 91파일/292검사의 의미 복원은 아직 미완료다.

영월 원본의 DocInfo offset 28 값은 1이다. 한컴의
[HWP 3.x 공식 사양](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D3.0_HWPML_revision1.2.pdf)
표3은 외부 변환 문서 플래그와 재조판을 설명한다. 3.x 저장 쪽·단 정보 역시 힌트이며
페이지 정리로 재구성해야 한다. 현재 `Hwp3DocInfo::reserved1`은 읽지만 수용 조건에 연결하지 않는다.
이는 원인 후보이며 아직 구현으로 입증하지 않았다.

같은 원본의 독립 2020 Print와 한컴 HWPX 저장본은 조건9·안전사고 안내를 각각 두 줄로
표시하고, 새 서식 제목을 다음 쪽에 둔다. 현재 원본 직파싱은 압축 한 줄과 앞쪽 잔류 제목을
그린다. Native/fresh WASM 전4쪽 최저값은 모두 30.66268%다. 입력·기준 교체나 기존
고정 px 기대값 갱신으로 차이를 숨기지 않는다.

사양의 셀 선 종류 1은 실선이다. 원본 첫 셀의 네 면은 실제로 모두 1이다.
Stage 141의 `fill_type=None`은 배경 채움 부재이며 테두리 부재로 해석한 기록을 교정했다.
선 종류를 임의로 바꾸는 구현을 하지 않고, 0.1mm/0.12mm 사상과 버전별 여백 차이는
독립 저장본 및 실제 Print를 연결해 검토한다.

대조군은 외부 플래그가 있는 `hwp3-table-cell-order.hwp`,
`issue1892_hwp3_tab_roundtrip.hwp`, 없는 `hwp3-table-grid-gap.hwp`다.
각각 engine 2020의 Print와 HWPX 저장본을 start/status/download로 공급한다.
서버 작업의 성공·로컬 바이트 확인 전에는 기준 확보로 판정하지 않는다.
기존 유효한 저장 줄의 원점·분할 및 paint-only 재구축 계약이 반례다.

## 생산·소비 경로와 수정 순서

- 생산: `parser/hwp3/records.rs`의 DocInfo → `parser/hwp3/mod.rs`의 저장 줄·표 변환.
- 수용: `model/document.rs::layout_profile` → `composer/stored_cell_reflow.inc.rs`의
  실제 구성 → `composer/line_breaking.rs::resolve_stored_line_segs_in_frame`.
- 측정: `height_measurer.rs::measure_paragraph`와 `typeset/paragraph/format.rs::recompose_for_flow`.
- 배치: `layout/paragraph_layout.rs::layout_partial_paragraph`와 `typeset/section/vpos.rs`의 후속 원점.
- 외부 문서 플래그의 의미·원본 단위를 보존하고, 재조판 경로의 구성 결과를 측정/배치가 함께
  소비하는지 확인한다. 이후 별도 snap·clamp·일찍 반환하는 경로와 마지막 줄 허용도 대조한다.
  저장 기하를 무조건 해제하거나 특정 문서 ID·수치로 출력을 맞추지 않는다.
- 먼저 같은 원본과 Print의 실제 출력을 90% 이상으로 보정한다. 전체 쪽과 제목·표·후속
  본문·빈 쪽을 직접 확인한 뒤 새 이름의 소유·순서·보존·포함 관계 검사를 추가한다.
  구현 전 FAIL/후 PASS는 해당 결함의 실제 실행으로 입증한다.

## 내용/API 계약 복원 초안

원래 빌더 검사 14개는 실제 문서의 화면 위치를 검사하지 않고 ingest JSON의 텍스트 순서,
문제 번호 정책·공유 지문 중복·보기 문단 소유·헤더/꼬리말 및 HWPX 직렬화 계약을 확인했다.
새 이름의 `tests/cases/issue_7642_ingest_content_contracts.rs`에 구조/API 계약 14개를 추가했다. 직렬화 성공만 확인하던 항목은
독립 parser로 재읽은 내용·순서·누락/중복 검사로 보강하고, 보기의 고정 style ID는 같은
보기 소유와 본문의 다른 style 관계로 바꾼다. 파생 harness를 준비했고 `regression_suite_014`의 `test(issue7642_ingest_)` 필터로
14개를 실제 실행해 모두 PASS, exit 0을 확인했다. 실행 0.055초이며 관련 없는 192개는
필터로 제외했다. Stage 141의 기존 새 이름 관계 검사도 30 PASS, exit 0(실행 105.106초)다.
44개 통과를 원래 292개 의미의 전부 복원으로 판정하지 않는다.
렌더러·좌표·골든을 사용하지 않는 구조/API 계약이며 실물 시각 90%의 대용이 아니다.

로그·TSV·중간 JSON·nextrun은 ignored output에만 남긴다. 시험지 관련 HML 이관은 유지한다.
