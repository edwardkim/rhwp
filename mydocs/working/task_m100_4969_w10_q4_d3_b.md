## 결론

Q4-D3-B는 승인된 D2 target line의 두 문자별 fallback leaf에 portable vertical `GlyphRun` 대안을 하나씩
게시했다. 각 leaf는 자신의 `TextSourceId`와 `text-N` equivalence group만 소유하며 기존 `TextRun`은 첫 op로
남는다. 한 line의 glyph ops와 portable font delta는 원본을 바꾸기 전에 전부 준비·검증되고, 마지막 commit만
resource arena와 line subtree를 변경한다.

target 결과는 `2 TextRun + 2 vertical GlyphRun`, equivalence group 2, portable font blob payload/record와 face
record 각 1, nominal duplicate 0이다. 제품 publication은 시작됐지만 모든 backend selector는 아직 두 group
모두 `TextRun`을 선택하므로 화면 출력은 바뀌지 않는다.

## red-first와 원자성

기존 D3-A 제품 구조 계약을 D3-B 계약으로 전환한 첫 실행은 첫 fallback leaf에 두 번째 op가 없어서 실패했다.
구현 뒤 같은 계약은 통과했다.

거부 경로는 완성된 D2 render tree의 두 번째 leaf 문자열 `글`을 같은 UTF-8/UTF-16 길이의 `가`로 바꿔
sidecar source identity를 의도적으로 깨뜨렸다. 결과는 vertical `GlyphRun` 0, font blob payload/record 0,
face record 0이다. 첫 leaf만 게시되거나 font resource만 남는 부분 mutation은 없었다.

## 구현 경계

1. `prepare_vertical_shaping_line_shadow`가 line/source/leaf/glyph/cluster를 먼저 대사한다.
2. exact certificate bytes를 기존 BLAKE3 resource key와 blob/face metadata로 준비하고 기존 key 충돌과 page
   budget을 검사한다.
3. clone한 line subtree의 각 leaf에 `verticalGlyphRun`을 붙인 뒤 `validate_text_variant_scope`를 통과시킨다.
4. 하나의 commit 함수가 portable font delta와 완성된 line을 등록한다.
5. `LayerBuilder`는 vertical → horizontal → nominal 순서로 lowerer를 호출하고 앞의 두 claim 집합을 합쳐
   nominal 중복만 차단한다.

horizontal lowerer의 `VerticalPositioningAuthorityPending`, Rust/Studio selector, `text_v2`와 public schema는
수정하지 않았다.

D3-B 판정은 atomic publication 자체만 다룬다. 다음 항목은 승인된 계획대로 D3-C에서 수행한다.

- layer JSON source/variant/glyph/resource 값 대사
- #6029와 canonical sample 두 건 회귀
- native·격리 Node WASM·표준 Docker WASM 값 대사
