## 1. red-first와 원인

기존 Studio `replayStatus()`는 orientation과 writing mode가 수평이 아니면 모든 GlyphRun을 거부했다. 반대로
renderer의 variant 선택은 실제 surface Canvas가 `drawGlyphs`를 제공하는지 알지 못했다. 선택 뒤 draw가 실패하면
이미 제거된 TextRun fallback을 다시 그릴 수 없어 blank가 될 수 있었다.

기존 `issue-4969-shaping-replay.test.mjs`에 bounded vertical fixture를 먼저 추가한 red는
`canvasKitCanvasSupportsGlyphRunReplay` export 부재로 실패했다. 새 별도 E2E source는 만들지 않았다.

## 2. 구현

`glyph-run-fonts.ts`는 Rust selector와 같은 tuple을 모두 만족할 때만 세로 run을 허용한다. provenance,
variant id·kind·part, requires 세 항목, `vertical-rl`, `vertical-upright`, LTR/bidi 0,
`rustybuzz-q4-vertical-v1`, no-fallback, exact·portable·strict, 무변형·무variation·무synthetic style을
전부 검사한다. bounded provenance나 variant를 일부만 선언한 run은
`boundedVerticalGlyphRunTupleMismatch`로 fail-closed한다. 기존 수평 run 규칙은 그대로다.

renderer는 surface에서 얻은 실제 Canvas를 variant 선택에 전달하고, `drawGlyphs`가 현재 함수일 때만 font
검증·생성까지 통과한 GlyphRun을 선택한다. draw helper도 같은 기능을 다시 확인한다. 따라서 기능·blob 검증·face
생성 어느 경계에서든 실패하면 선택 단계에서 TextRun fallback이 남는다.
