# 이슈 #7642 — DYAD 글자와 저장 예약 프레임의 표시 원점

이전 단계: [구두점 공통 구성](task_m100_7642_stage19.md), source `1017fefff`.

## 독립 근거와 소비 경로

#7593 원본의 DYAD 세 수식은 BaseUnit1100/기준선85%다. 앞 두 저장 프레임은1125HU,
보기 ㄴ은2580HU다. 독립 MCP2020 Print에서 앞 두 AB는 본문 근처, ㄴ의 AB는 본문보다
위에 놓이며 글자 크기는 같다. source83 Native97.08779% 통과와 기존 관계 검사는 이
실제 기준선 차이를 입증하지 못했다. 확대 review/PNG와 실제 SVG를 다시 대조했다.

새 진단 입력의11pt/22pt, rm 바깥/안쪽·관계 기호 행의 정상화와 Print를 확보했다.
HWP job `904ba789-6a69-433c-a97b-8c29a84a6926`, Print job
`aeedae30-4c2f-4a87-8b77-31ad2060fdae`, engine2020/PrintMethod0다.
11pt의 DYAD 정상 프레임은1350HU/87%다. 원본의1125HU 또는2580HU를 이를 이유로
덮어쓰지 않는다. 정상화한 별도 진단을 원본의 개선 결과로 보고하지 않는다.

실제 호출 경로:

1. `flow_metrics_hwp → inline_baseline_px`는 저장 예약 프레임의 기준선을 소비한다.
2. `paragraph_layout`은 `줄 기준선 - 예약 프레임 기준선`으로 수식 bbox 원점을 정한다.
3. `layout_for_paint`가 예약 기준선과 자연 glyph 기준선의 차이를 다시 루트 y에 더한다.
4. SVG/Canvas/Skia는 그 루트 y까지 소비해 자연 glyph를 본문 기준선에 재정렬한다.

3번의 재정렬이 이미 적용한 원점의 의미를 지운다. 큰 프레임의 ㄴ은 원래 떠 있어야 하지만
본문 기준선으로 돌아온다. 기존 검사는 `bbox.y + layout_box.baseline`만 보고 루트 y의
실제 소비를 놓친다. 좌표와 값은 원인 추적용이며 고정 px 보정·검사에 사용하지 않는다.

## 보정과 반례

- 세로 압축이 없는 HYhwpEQ의 같은 크기 비CJK 글자 줄에 놓인 DYAD는 자연 glyph의 원점을 저장 프레임 안에서 유지한다.
  예약 프레임을 줄 기준선에 앵커한 뒤 glyph를 다시 그 기준선에 강제 정렬하지 않는다.
- 일반/큰 프레임의 동일 BaseUnit, rm 바깥/안쪽, 관계 기호를 포함한 행을 확인한다.
  압축·한글 대체 프로그램·분수·첨자·크기 변경·다줄처럼 글자 줄 계약이 아닌 DYAD에 같은 가정을 적용하지 않는다.
- 기존 저장 폭·높이·기준선·본문 흐름을 유지한다. 저장 프레임 크기를 작은 값으로 덮거나
  출력/내용을 숨겨 점수를 맞추지 않는다. 다른 수식 경로의 기존 계약은 근거 없이 바꾸지 않는다.
- #7593 원본/최소와 math8·eq002 HWP/HWPX·국어1p의 새 Native/fresh WASM Print 대조,
  전쪽 TSV·동일 배율 확대를 연결한다. 실제 glyph와 뒤 본문의 관계 및 장식 폭을 확인한 뒤
  필요한 회귀를 실제 paint 원점·소유·순서·내용 보존 관계로 교정한다.

전체 회귀 실패90개는 현재 브랜치에서 보정한다. 테스트 제거·새 이슈 이관·기대값/허용치
일괄 갱신으로 해소하지 않는다. 최종 제출 전 전체52개 원본과 전체 회귀 검증을 수행한다.
진단·로그·TSV·JSON·nextrun은 ignored output에 두며 아직 이 단계의 구현/최종 판정은 없다.

비압축 DYAD 글자 줄은 자연 루트 원점을 그대로 소비하는 분기를 구현했다. 기존 공통
세로 스케일로 압축 여부를 판단하며 프레임·기준선·흐름 값을 변경하지 않는다. 압축과
CJK는 독립 근거가 없는 다른 경로이므로 기존 계약을 보존한다. 새 Native와 확대 판독은
아직 실행 전이며 이 근거로 새 회귀 기대값을 추가하거나 변경하지 않았다.
