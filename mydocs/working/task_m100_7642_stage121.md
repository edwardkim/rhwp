Issue: #7642. Stage 120의 기존 시험지 검사 제거 뒤 source `577245fa9`에서 새 이름
관계형 20개를 nextest로 실행해 20 PASS, 종료 코드 0을 확인했다. Native·WASM·전체 target
Clippy와 workspace build도 각각 종료 코드 0이다. 전체 회귀·최종 시각 검증은 아직 아니다.

## 독립 출력과 원인

행렬·근호 60종의 한컴 정상 저장·Print 3쪽에서 Native와 fresh WASM 최저값은 모두
84.47499%다. 22pt 첨자 행렬의 저장 높이 5131HU에 대해 실제 배치는 5568.98HU다.
PDF의 같은 행에서 `x_i`와 `y^2` 본체 기준선은 서로 다른 위치에 있다. 행렬 셀의
논리 상자를 세로 가운데에 놓은 결과와 대응하며 글줄처럼 기준선을 하나로 합치는
현재 가정이 추가 높이를 만든다. 마지막 행도 원시 nominal em을 다시 합산하면 안 된다.

근호 대조군을 일반 괄호·숫자/변수/여러 항의 근 지수·분수/첨자/중첩 본체로 확장해
45종을 한컴에서 정상 저장하고 Print 출력했다. engine 2020, 한컴 11.0.0.9136,
PrintMethod 0·1-up, 2쪽이며 job은 저장 `c84704d9-99d8-4c55-b330-c464f468d0e2`,
Print `d80e5af2-8ab1-4eb3-bf57-59b48ab26262`다.

- 일반 `LEFT(3)`·`LEFT(x+1)`·`LEFT(n)`·`LEFT(x+y)`의 폭은 세 크기에서 이미 일치한다.
  숫자 뒤 일반 괄호의 전역 간격을 바꾼다는 초기 가설은 폐기한다.
- 근 지수의 논리 폭은 근호 기호의 절반 슬롯 오른쪽에 맞추고, 넘친 폭만 기호 앞에 예약한다.
  한 자리 숫자뿐 아니라 `n`, `13`, `n+1`의 독립 저장·Print가 이 관계를 확인했다.
- 둥근 닫는 괄호로 끝나는 지수·본체의 근호 경계 여백은 해당 글자 크기의 0.07em이다.
  일반 괄호의 내부 폭을 바꾸지 않는다. 세 크기의 `SQRT(x+1)`·`SQRT(x+y)`는 같은 추가 폭이다.
- 근호의 추가 세로 띠는 일반 논리 글줄의 0.15배다. 본체의 logical frame을 소비하며
  분수·첨자·중첩 근호를 raw nominal em으로 다시 재지정하지 않는다. 22pt의 작은
  HWPUNIT 차이와 공개 글리프의 모양 차이는 실제 출력·확대 판독에서 별도로 확인한다.

## HWP3 흐름

원본 `hwp3-sample.hwp`의 독립 Print 16쪽을 사용한다. 진단에서 빈 그림 host의
자체 줄과 TAC 표 뒤 간격을 함께 보존했을 때 전쪽 최저 91.24570%, 8쪽 92.95960%다.
진단용 여백 변경을 생산 코드에 복제하지 않는다. HWP3 parser가 이미 계산한 글자 크기·
문단 줄간격을 TAC 표 host에 보존하고, caption 있는 빈 그림 host의 자체 줄은 조판과
실제 배치가 같은 helper 결과로 추가한다. 원본 여백·잉크 위치와 물리 점유를 구분한다.

생산·소비 경로: parser `fallback_line_spacing` → TAC 표의 후처리 → 누적 vpos,
원본의 단일 빈 caption host(유효한 저장 줄, 미편집) → `typeset/section/controls.rs` 추가 예약 → `layout/shape_item.inc.rs`
그림 배치의 최종 흐름 끝. 저장 그림/단 밖 그림/비흐름 덮어쓰기 뒤 실제 소비를 확인한다.
HWP5/HWPX·caption 없는 그림·텍스트가 있는 host는 해당 새 경로에 포함하지 않는다.

## 검증 계획

분석한 변경을 묶어 적용한 뒤 Native/fresh WASM을 순차 빌드한다. 기존 60종, 추가 45종,
HWP3 원본 16쪽과 대조군을 먼저 직접 Visual Sweep·확대 판독한다. 미달 쪽이 남으면
출력을 보정한다. 이 단계에서 golden을 갱신하거나 미달 fixture에 새 회귀를 등록하지 않는다.
최종 55개 원본·853쪽 및 전체 Rust 회귀·Studio 검증은 계속 남아 있다. TSV·JSON·로그는
ignored output에 보존하고 source SHA와 대표 그림을 결과에 연결한다.

## Native 실행 결과와 확대 판독

source `155f3e9fe379ab925c464e404a00d4cd2a233b9f`의 고정 Native 빌드에서 실제 21쪽을
다시 출력했다. 행렬·근호 60종 3쪽의 최저 91.04621%, 추가 근호 45종 2쪽의 최저
99.98836%, 원본 HWP3 16쪽의 최저 91.24570%다. 모든 항목은 원문·Print PDF 전체
쪽수가 같고 종료 코드 0이다. HWP3 8쪽은 92.95960%다. TSV·명령·입력/PDF·바이너리
SHA-256은 ignored `stage121-logical-frames-focused/receipt.json`에 보존했다.

같은 source의 대표 그림을 새로 산출하여 직접 열었다. 행렬 3쪽의 큰 PMATRIX 괄호는
점수를 통과해도 가운데 직선이 긴 곡선으로 바뀌어 있어 확대 판독 완료로 판정하지 않는다.
Stage 123에서 공개 MATH 조립 정보로 보정한다. fresh WASM은 동일 코드의 빌드·대조를
진행 중이며, 이 Native 결과를 WASM 통과나 최종 원본 전수 검증으로 대신하지 않는다.

순차 빌드 중 source는 변경하지 않았다. 준비 뒤 `cargo fmt`로 source 가중치가 달라진
파생 suite 불일치를 발견하여 포맷 완료 후 `--prepare`를 다시 실행했다. 고정 base
`21ed64071f81f35f37618717693bd30f727392c9`의 manifest `--check`와 fmt check는
종료 코드 0이다. 최초 실패 로그도 보존했으며 파생 파일은 커밋하지 않았다.
