stage2106 Native/fresh WASM은 모두 `aae3ea1b26006f2b7dc4b0ead2f8a65640fff9aa`의
고정 producer로 91개 항목을 끝냈다. Native는 수치 선행 조건 80개·미달 9개·
쪽수 불일치 2개, WASM은 각각 81개·8개·2개다. queue 종료는 전체 수용 판정이 아니다.

이 결과는 새 WMF surface source의 통과 근거로 재표기하지 않는다.

## 실제 WASM 글꼴 공급

이전 queue의 terminal 상태를 확인한 뒤 guarded sweep script를 바꿨다.
`export-wasm-png-for-sweep.mjs`는 Canvas font setter에서 관측한 본문 family뿐 아니라
새 `getMetafileFontRequests`의 실제 이미지 내부 family도 수집한다.
같은 font catalog·source bytes를 기존 FontFace와 새 `registerMetafileFont`에 공급한다.
등록 family는 WMF가 요청한 범위로 제한하며 기존 HFT·본문 측정 API 의미는 바꾸지 않는다.
선택 TTC face는 기존 catalog factory에서 동일 standalone 프로그램으로 공급한다.

두 script의 `node --check`는 exit 0이다. 아직 새 fresh WASM의 실제 실행 결과는 아니다.
새 Native와 fresh WASM을 같은 committed source에서 공용 target·빌드 잡 8개로 순차
빌드한다. source/worktree의 내용과 실제 CLI/WASM artifact를 고정하고 정상 WMF
18·35쪽 및 관련 전쪽의 새 PNG·TSV를 산출한다. 필요 glyph를 공급하지 못하거나
기준보다 미달이면 완료·새 회귀·PR 생성으로 진행하지 않는다.

변경 전/후 직접 판독은 같은 원본과 독립 Print PDF·페이지·DPI를 유지한다.
공식 Cairo 정책과 90%/98%/devel 하락 기준은 이 단계에서 변경하지 않았다.

## 호스트 비동기 경계와 사전 검사

Studio의 메타파일 font 준비에는 문서·renderer 세대뿐 아니라 캡처한 local font
세대도 대조한다. host provider가 아닌 Local Font Access의 준비 중 교체도 오래된
face를 등록하지 않도록 한다. 본문 canvas metric 세대 계약은 바꾸지 않는다.
stage2152 Studio `tsc --noEmit`는 exit 0이다.

stage2153의 기존 실제 브라우저 검사 3개도 모두 통과했다. 실제 Canvas advance와
glyph, 원본 advance의 이름/공백/한국어 alias, Chrome 시작 실패 뒤 output 전용
profile 정리를 확인하는 기존 계약이다. 새 WMF PNG의 시각 통과를 대신하지 않는다.
stage2149~2151의 Native → 기존 mask 계약 → fresh WASM은 `84fa650793`의
고정 Rust source를 사용한다. 이 이후 Studio의 local font 세대 guard 변경은
그 Rust source/SDK 빌드에 포함된 변경이라고 재표기하지 않는다.
