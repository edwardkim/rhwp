# #7642 문단 끝 표 슬롯의 원본 위치 축 보정

Issue: #7642. 이전 구현 head는 `76ea0edd367f79f281a26708fd162b3e1cb59c23`이다.

## 직전 실행 결과와 원인

stage2917 Native 빌드는 종료 코드 0이다. stage2918에서 원본
`samples/hwp_table_test-m.hwp`의 3쪽은 최저 98.09909%였으나, 기존 #5566
회귀가 생성한 정확한 두 HWPX의 각 3쪽은 미달했다. 최저 17.56084%로
이전과 같으므로 저장 줄 계획의 개선을 입증하지 못했다. 기대값이나 시각
기준을 갱신하지 않는다.

정확한 입력의 문단 0.3은 가시 문자열 `앵커 제목 줄` 7글자와 뒤따르는
8유닛 표 컨트롤을 가진다. char_count는 종단 포함 16, 마지막 저장 줄의
text_start는 7이다. 표의 가시 문자열 위치는 7이지만 그 위치에는
char_offsets 항목이 없다. 기존 source helper가 `get(7)?`에서 거절하여
새 프레임 투영이 실행되지 않았다.

## 수정과 생산·소비 경로

`Paragraph::control_utf16_positions`는 가시 글자 앞 갭과 문자열 끝 컨트롤의
원본 PARA_TEXT 시작 위치를 계산하는 공통 모델 계약이다. 표 슬롯의 소유를
이 반환값으로 판별한다. 저장 줄의 text_start와 같은 좌표계이며, 임의의
기본 오프셋을 넣거나 원본의 저장 줄 유효성 조건을 완화하지 않는다.

이후 경로는 stage2916과 같다: source 소유 판별 → 같은 LayoutFrame의
배제·저장 줄 투영 → FormattedParagraph → 표 원점과 후속 흐름 소비.
표 앞 접두 글자와 컨트롤의 가시 인덱스는 문자열 검사에만 사용한다.

## 검증 계획과 미검증 범위

Native 재빌드 뒤 동일한 두 HWPX·독립 Print PDF와 원본 3쪽을 먼저 대조한다.
#7969 저장 줄 대조군도 다시 확인한다. fresh WASM과 전체 검증은 이 좁은
경계의 실제 개선을 확인한 뒤 진행한다. 이 문서는 구현 근거이며 통과 판정이
아니다. 90% 미달 입력의 새 회귀 테스트나 golden은 추가하지 않았다.
