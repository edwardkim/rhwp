# #7642 원 face와 문자 fallback의 같은 계열·획 보존

Issue: #7642

## 독립 출력과 실제 선택

검증 기준 devel은 `6ed1682c3267ea786734eb2e75252916a861d1fd`, 비교 후보는 `8408ca43e2`다. 동일 API·입력·font path로 실제 Native Skia의 글꼴을 관찰했다. PrEP 3쪽은 source glyph 636개의 paint가 bundled Noto Sans KR에서 system Malgun Gothic으로 바뀌었으며 layoutMetric은 같았다. 원본 Print는 Dotum을 내장한다. 이 호스트의 exact Dotum은 없고 DotumChe는 별도 face이므로 그것을 원본 face로 대신하지 않는다. 앞의 HY헤드라인M 합성 굵기 보정이 이 본문 face 전환의 원인까지 해결한다고 확대하지 않는다.

#7336 HWPX 6쪽은 source U+FF65 `･` 두 글자의 후보가 Noto Sans CJK KR에서 Noto Sans KR ExtraLight로 바뀌었다. 독립 Print PDF의 실제 문자 인덱스 282·430에서 PDFium `FPDFText_GetFontInfo`를 호출한 결과 두 글자 모두 `HCRDotum`이었다. PDF 안의 프로그램을 추출하거나 공급하지 않았다. 설치된 HCR Dotum의 메타데이터와 원문 이름을 사용한다.

같은 쪽의 마지막 `3`, `년`에 대한 Print의 loose box 시작은 각각 666.839px, 674.834px다. 후보의 시작은 약667.1px, 675.0px로 base의 667.8px, 675.7px보다 가깝다. 점수를 올리려고 올바른 끝 자간 배치를 되돌리지 않는다. 이 위치 관측은 새로운 px 회귀 고정값이 아니다.

## 공통 규칙과 적용 경계

Native·Canvas가 공유하는 generic fallback을 작은 모듈로 분리했다. 일반 고딕은 요청 face·설치 별칭과 플랫폼 face를 유지하고, 그 face에 문자가 없으면 같은 계열의 설치된 HCR Dotum을 범용 Noto보다 먼저 찾는다. 명조·고정폭의 기존 계약은 유지한다. KoPub Light는 앞의 전용 가벼운 face를 유지한다. 일반 HCR Batang·확장 글꼴은 기존 후반 대역 공급을 유지한다.

원본 돋움·굴림은 실제 원 face와 설치 별칭이 있으면 먼저 사용한다. 없을 때의 대체 획은 기존 Task #1224의 돋움 밀도 측정에 근거한 Noto Sans KR ExtraLight를 우선하며, bold는 기존 helper로 ExtraLight를 제외해 Noto Sans KR의 해당 굵기를 찾는다. 현대 맑은 고딕·Apple face를 돋움과 동일 프로그램으로 간주하지 않는다. DotumChe·GulimChe 같은 고정폭 face까지 이 규칙으로 확장하지 않는다. 특정 문서 ID·페이지·좌표·문자 하나를 판별하는 분기를 추가하지 않는다.

`TextStyle의 요청 face → render/canvas_font_family_chain 및 Native text_family_candidates → 같은 generic_fallback_for_weight → 실제 문자 coverage 선택 → 기존 glyph 위치의 paint`에서 적용한다. 메트릭·줄 구성·개체 원점·높이·정렬 계산을 바꾸지 않는다. 실제 Bold·원 face가 있는 일반 문자·명조·고정폭은 대조군으로 확인한다.
