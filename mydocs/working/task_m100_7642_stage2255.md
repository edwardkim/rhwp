# #7642 명시적 normal 공간의 face 분기 보정

Issue: #7642

## 구현과 근거

`layout_space`의 normal 분기에서 HancomEQN도 실제 한컴 반 em 공간을 소비한다.
HYhwpEQ, 두 face의 기존 Thin 규칙, 일반 글꼴/LaTeX는 유지한다. 기존 독립
Print의 두 face·네 크기·96식에 포함된 `rm AD~M`, `rm AC~M` 등과 직접 대조했다.
한컴 18pt AD의 A→D는 약 20px로 맞지만 M만 약 4px 앞섰고, 기존 출력은
24×0.33=7.92px 공백을 사용한다. Print는 약 12px를 사용한다. 새 상수·문서
분기·좌표 보정은 추가하지 않았다.

## 실제 검증 상태

리베이스는 upstream/devel `b7a5388034` 위에 완료했고 이전 head
`3906300cfe8248574f9c0caade1cf2777e3a57c3`의 Native 빌드는 stage2250에서
진행 중이다. 그 빌드는 이 보정을 포함하지 않는다. 보정 전 7e2907f7a3의
독립 벡터 12쪽 최저 raw는 93.34686%이나 확대 판독에서 위 결함을 확인했다.
관련 원본과 Print는 기존 커밋 파일을 재사용한다. stage2253의 review와 standalone
overlay, stage2254의 실제 glyph 원점을 ignored output에 남겼다.

현재 보정의 formatter·실제 Native/fresh WASM·전체 회귀는 아직 완료하지 않았다.
수치 통과를 시각 수용이나 회귀 추가 근거로 대신하지 않는다. 최신 devel 비교,
전체 Rust의 남은 실패와 PR 준비도 미완료다.
