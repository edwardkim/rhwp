# Issue #7642 단계 520: HWP3 원본 보정과 폐기한 가정의 기록

## 검증한 현재 수식 동작

- 확정 수식 source `0e62c1b289`의 9개 대조군·전12쪽은 Native/fresh WASM 모두 최저 93.09138%, 쪽수·범위 일치다. 실제 webfont PNG 12개도 SHA-256이 모두 같다(stage501–504/509).
- 같은 2022년 11월 원본·독립 한컴 Print로 source0e를 전21쪽 재검증했다. Native 최저 95.56319%, 18쪽 97.67544%, 쪽수 일치다(stage513). 이전 a973의 18쪽 84.80412%와 구분한다. 새 review에서 그래프의 큰 세로 이동이 해소된 것을 직접 확인했다. fresh WASM 전21쪽은 stage519에서 진행한다.
- 원본 미분 줄의 저장 높이는 1125HU/78%였고, 같은 구문을 캐시 없이 한컴에서 재생성한 진단은 900HU/86%였다. 새로운 크기가 작다는 사실만으로 원본 예약 공간을 줄이거나 보존하는 일반 조건을 정할 수 없다. 같은 실제 문서의 Print 결과로 검증한다.
- 줄의 새 내용이 저장 영역에 들어가면 무조건 예약을 보존하는 프로토타입은 11월 전21쪽에서 최저 39.81296%로 악화됐다. 이 가정과 추가 간격 가정을 폐기하고 검증된 source0e 수식 동작을 유지한다. 관련 patch·실패 측정·원본은 ignored stage507/512/517에 보존한다. 이를 현재 브랜치의 완료 결과로 보고하지 않는다.

## HWP3 보정의 근거와 소비 경로

- 원본 `samples/hwp3-sample16.hwp`의 독립 Print는 `pdf/issue7642-hwp3-original-print/hwp3-sample16-2020.pdf`다. 기준을 바꾸지 않았다. 한컴에서 단순 저장한 진단본은 속성 해석 확인용이며 기준 입력을 대체하지 않는다.
- 새 쪽의 첫 문단 앞 간격은 실제 저장본에서 852HU로 남는다. 파서가 쪽 시작을 이유로 생략하던 앞 간격을 누적하고, `stored_first_margin_is_page_relative`가 닫힌 저장 사다리를 인증할 때 측정과 배치 모두 쪽 원점 0을 소비한다. 개별 문서·좌표 조건을 추가하지 않는다.
- 인라인 도형만 있는 문단도 호스트 글자 크기·문단 줄간격에서 나온 여유를 갖는다. 파서의 0 강제를 제거해 독립 저장본의 780HU 전진과 연결한다. 개체 높이에 줄간격을 곱하지 않는다.
- 원시 도형 스타일 2는 같은 한컴 저장본에서 Dot(3)이고 Print도 점선이다. 기존의 모든 변형을 실선으로 바꾸는 처리를 제거한다. 둥근·반원 모서리 옵션도 공통 사각형 속성으로 전달한다. 원본과 한컴 저장본의 채움 색상·그라데이션 속성은 같아 변경하지 않는다.
- stage507/510 Native 부분 대조에서 3쪽 90.86551%, 64쪽 97.97455%로 개선됐다. 이 프로토타입에는 위에서 폐기한 줄 보존도 포함되므로 확정 head 전체 증거로 승격하지 않는다. 새 확정 코드의 전64쪽 Native/fresh WASM 및 확대 판독은 재실행한다.
