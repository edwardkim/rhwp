# Issue #7642 단계 638: 빈 OLE 호스트의 점유 끝 단일 소비

- source0083의 전체 검사에서 OLE Enter/Backspace/Re-enter HWP·HWPX4건이 새로 실패했다. 저장 줄 피치의2배로 다음 문단이 내려갔다. 정확한 저장 피치 기대값을 유지하고 출력 원인을 추적했다.
- 기존 실행 파일에 `RHWP_DEBUG_TAC_CURSOR`를 적용한 stage637 추적에서 FullPara pi0가132.3→153.6, Shape pi0가153.6→174.9로 각각 같은21.3 줄 피치를 소비했다. 다음 빈 문단의 원점은174.9였다. 첫 진단의 잘못된 env 이름은 출력 추적 증거로 사용하지 않았다.
- `layout.rs`는 빈 후속 저장 줄의 점유도 예약하도록 보정했고, `shape_item.inc.rs`의 OLE는 여전히 현재 흐름 커서에 원래 호스트 피치를 더했다. 저장 delta가 문제인 것으로 가정해 태그·허용치를 덧붙이지 않는다.
- OLE가 기존 `para_start_y`의 원래 호스트 원점+저장 피치를 점유 끝으로 소비하도록 했다. FullParagraph가 이미 전진한 경우 같은 끝을 다시 예약하지 않으며, FullParagraph가 없는 경우에는 현재 원점 fallback으로 같은 피치를 예약한다. 기존 흐름 커서의 단조 전진과 실제 OLE 크기·표시·wrap 영역은 유지한다.
- 호스트 원점 생산 → FullParagraph 줄 점유 → Shape의 같은 점유 끝 소비 → 다음 문단/커서 소유를 연결했다. 개체 위치를 clamp하거나 보이지 않게 처리하지 않고 테스트의 기대값도 변경하지 않았다. Picture를 별도 OLE 규칙으로 바꾸지 않아 HWP3 첫 페이지 보정과 구분된다.
- 새 source의 집중4건·미편집 OLE·실제 편집 저장본 Print/Native/fresh WASM·HWP3/서식 대조군은 아직 미검증이다. 현재 실행 중인 stage634는 이 변경 전 source의 검사이며 새 보정의 최종 통과로 보고하지 않는다.
