# #7642 입력 보존 점검과 독립 Dotum 프로그램 대조

Issue: #7642.

## 검증 대상과 결과의 구분

요청 시험지의 보정, 전체 회귀에서 추가한 대조 문서, 리베이스로 들어온
#7969·#7970 기능 보존을 구분한다. 온새미로는 최초 시험지 목록 밖의
전체 회귀 실패 입력이다. 기준 `515bd72dcde0eecdeece333666b675354b7fa91d`도
독립 Print 46쪽과 달리 47쪽이었다. 기존 결함을 현재 변경의 새 회귀로 보고하지 않는다.
기준 대비 실제 하락과 필수 증거 부족은 각각 계속 추적한다.

직전 검증 source는 `0f58f2c445eb5386d74cbe3b03b2986bf6a9fadf`다.
이 source의 #7969 13개 입력은 Native/fresh WASM 모두 수치 조건을 충족했고,
동일 조건 base 대비 0.01%p 이상 하락한 쪽은 없었다. Native 최저 99.88926%,
WASM 최저 99.29125%다. 새 `b86d75469824f30ab796abfca58fb6dfccf3a18b`의
최종 검증을 대신하지 않는다.

## 입력과 실제 커밋 내용

102개 문서의 입력·PDF 204개 참조를 모두 읽고 SHA-256을 대조했다.
누락·실행 파일 해시 불일치는 없었고, 이미 커밋된 파일은 Git blob/LFS 내용과
일치했다. 15개 참조는 아직 ignored 임시 경로에 있다. 이 파일은 전쪽 양쪽
시각 검증·직접 판독 후 수용 여부와 안정 경로를 확정한다. 모든 입력이 이미
커밋됐거나 PR 준비가 끝났다는 의미가 아니다.

## 위첨자 문서의 원인 분리

원본은 `samples/issue5756/156732409_superscript_advance.hwp`, 독립 기준은
`pdf/issue7642-failed-regression-print-20261015/156732409_superscript_advance-2020.pdf`다.
3쪽의 base/head RenderTree 차이 114개는 가로 원점 63개·폭 51개다.
세로 좌표·본문 텍스트·구조 차이는 없었다. 픽셀 점수만으로 이 가로 차이를
완료나 회귀 기대값으로 고정하지 않는다.

실제 Native 글꼴 관측에서 원본의 `돋움`이 대부분 `Malgun Gothic`으로 대체됐다.
독립 PDF의 `Dotum`과 다른 프로그램이었다. Windows의
`C:\Windows\Fonts\gulim.ttc`에서 Dotum face만 로컬 검증용으로 분리하고,
PDF의 해당 subset 438개 글리프를 원본 프로그램과 대조했다.
윤곽선·em 정규화 전진폭은 438/438개 일치했다.

| 항목 | SHA-256 |
| --- | --- |
| 원본 gulim.ttc, 13,531,200바이트 | `4b9ac63e8920ed1bae29c068025ed30493464c18ee18617887daa18e59189226` |
| 분리한 Dotum-Regular.ttf | `1a5a9b70b08f936eb2b6242b29db88653e37325fd82206a7369a03ba01ace5c1` |

시스템 글꼴 설정은 변경하지 않았고 글꼴 바이너리는 Git에 포함하지 않았다.
PDF에서 글꼴을 꺼내 공급한 것이 아니라 별도 Windows 프로그램의 일치를 확인했다.

## 같은 글꼴 조건의 base/head 대조

두 source 모두 같은 Dotum face와 기존 글꼴 경로, Print profile, compat 2022,
96 DPI, 고정 PDFium·raw 실루엣 계산 모듈을 사용했다.

| 경로·쪽 | base raw | 직전 head raw | 차이(%p) |
| --- | ---: | ---: | ---: |
| Native 1 | 99.83927% | 99.80558% | -0.03369 |
| Native 2 | 98.72899% | 98.92764% | +0.19865 |
| Native 3 | 98.47933% | 98.71609% | +0.23676 |
| WASM 1 | 99.86438% | 99.86256% | -0.00182 |
| WASM 2 | 98.72827% | 98.93006% | +0.20179 |
| WASM 3 | 98.53403% | 98.77775% | +0.24372 |

2·3쪽의 하락은 해소됐지만 Native 1쪽은 계속 재검토 대상이다. 해당 쪽의
잔여 차이는 휴먼명조 본문·한양신명조 모서리 괄호·HCI Poppy 인용 부호 등에
분산된다. 기존 값으로 기준을 갱신하거나 다른 쪽 개선으로 상쇄하지 않는다.
새 source의 집중·전체 검증에는 이 글꼴 조건을 적용하고, 비교기도 같은 조건의
base 행을 선택하도록 구성했다. 다른 문서의 글꼴 공급은 변경하지 않았다.

## 실행 상태와 남은 검증

직전 source의 Native 공급 글꼴 식별 회귀 6개는 모두 통과했다. 이름 ID 6의
독립 PostScript 프로그램 선택과 family/full-face 구분도 포함한다.
컴파일 36분 24초, 검사 36.370초였다. I/O 대기 중에도 원 프로세스를 유지했고,
종료된 검사를 재시작하지 않았다. 이전 head 대조 작업만 nice/ionice 우선순위를
낮췄으며 Cargo/Rust·새 source·base 검증은 변경하지 않았다.

시스템 PostScript 색인은 누락 family의 fallback 조회에서도 비용이 발생할 수 있다.
[OpenType 이름 표 사양](https://learn.microsoft.com/en-us/typography/opentype/spec/name#name-ids)에
따른 식별자 문자 조건과 원본 요청/생성 fallback의 구분을 검토 중이다.
단순 이름 모양 추측으로 실제 프로그램을 제외하는 보정은 추가하지 않았다.

새 정규화 source의 Native/fresh WASM, 전체 Rust·lint, 미커밋 입력의 수용,
전쪽 TSV와 확대 판독, PR·CI·merge·별도 기록 PR·후속 처리는 미완료다.
실물 회귀·baseline은 이 단계에서 추가하거나 완화하지 않았다.
