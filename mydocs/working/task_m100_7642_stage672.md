# Issue #7642 단계 672: HWP3 선 끝점과 묶음 선의 화살표 보존

## 독립 근거와 실패 범위

- 원본 `samples/issue1892_hwp3_drawing_group_roundtrip.hwp`의 기존 Print 기준은 Native 1쪽 86.78774%, 2쪽 100%다. 1쪽의 치수선과 화살표가 누락됐다.
- 한컴 2020으로 저장한 HWPX 대조군은 원본을 수정하지 않고 job `96d7e0a8-2700-4e95-b050-dfd461e8ac61`에서 만들었다. Print PDF의 대체 기준으로 사용하지 않는다. 대조군의 가시 치수선은 시작/끝 `SPEAR`, 선 없음 구분선은 `NONE`을 기록한다.
- 원본 바이트의 독립 스캔에서 화살표 값 2와 0, 선 폭 11, 축 크기 1과 실제 긴 축 크기, 세부정보의 vertical flip 비트 2를 확인했다. 스캔을 완전한 파서 검증으로 보고하지 않는다.
- [한컴 공식 HWP3 사양](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D3.0_HWPML_revision1.2.pdf)의 표 68/69/74에서 개체 크기, 두 끝의 화살표 필드, 축별 반전 정보를 확인했다.

## 생산·소비 경로와 보정

- 기존 HWP3 mapper는 `LineShape::default()`를 만들고 세부정보를 버려 두 끝점이 모두 0이었다. 기본 속성의 두 화살표 필드도 공통 선 속성에 옮기지 않았다.
- 선의 개체 크기를 HWPUNIT으로 변환해 두 끝점을 복원하고 세부정보의 각 축 반전을 적용했다. 획 두께를 포함하는 `bounds`를 선 끝점으로 오해하지 않는다. 원본의 무색 sentinel과 선 없음 속성은 유지한다.
- 기본 속성의 시작/끝 화살표를 공통 선 속성에 보존한다. None/Spear는 독립 한컴 저장본과 대조했고, 다른 모양의 실물 대조는 아직 미검증이다.
- 아핀 묶음 자식 경로는 끝점을 변환한 뒤 일반 shape path를 만들어 화살표를 잃었다. 가시 직선은 일반 직선과 같은 `drawing_to_line_style` 및 `LineNode`로 만든다. 원본이 선 없음인 path는 기존 비가시 상태를 보존한다.
- `원본 선 크기·반전·화살표 → 공통 LineShape/선 속성 → 묶음의 아핀 끝점 → LineNode의 획·화살표 → SVG/paint` 경로를 연결했다. 소유 section/paragraph/control 주소도 같은 노드에 보존한다. 문서 ID·고정 px·좌표 clamp로 맞추지 않았다.
- mapper를 작은 별도 파일로 분리해 HWP3 parser는 1000줄 이하로 줄였다. 기존 source-side 검사 이름은 유지했다. 묶음 직선의 새 helper도 별도 작은 파일에 두었다.

## 검증 상태

현재 source의 정식 집중 검사·Native/fresh WASM·전쪽 90% 및 직접 확대 판독은 아직 미검증이다. 90% 미만 입력의 새 렌더링 회귀를 추가하거나 기대값을 갱신하지 않았다. source1840의 전체 nextest는 별도 worktree에서 계속 실행 중이며 이번 보정의 통과 증거로 보고하지 않는다.
