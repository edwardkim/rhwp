# #7642 Stage 167 — 유효한 저장 미주 단 소속의 보존

## 독립 근거와 원인

9월 2022 원본 HWP/HWPX와 각각의 독립 한컴 Print는 문7 마지막 수식 줄을
다음 쪽 첫 단에 둔다. HWP에는 이 줄의 저장 원점 0이 보존돼 있지만 공통
미주 fit 재생이 전체 문단의 자연 높이가 앞 단에 들어간다는 이유로 컷을 제거한다.
현재 단 첫 문단의 저장 원점이 직전 문단의 끝보다 앞이므로 기존
`endnote_column_starts_at_stored_break` 계약으로 저장 단 시작임을 확인했다.
문단 사이 되감김에는 이 계약을 소비하고, 내부 컷 취소에는 소비하지 않는다.

HWPX 파서는 같은 원본의 마지막 0을 앞줄 전진으로 바꾼다. 이 경계 손실은
별도 원인이므로 공통 fit 보정만으로 HWPX까지 해결했다고 선언하지 않는다.
21개 HWPX 원본을 읽기 전용 조사해 12개의 마지막 0 패턴을 찾았지만, 모든
패턴을 실제 결함으로 확정하지 않았다. 원본/짝/Print와 편집 후 재조판을 구분한다.

## 공통 계약과 소비 경로

- 편집하지 않은 유효한 저장 분할이며 현재 단이 저장 단 시작과 같은 경우,
  내부 되감김은 다음 단의 내용 소속이다. 앞 단에 물리 공간이 있다는 이유로
  뒤 줄을 앞 단에 넣지 않는다. 단 원점이 이미 달라졌거나 편집한 재조판에는
  이 계약을 적용하지 않는다. 높은 위치/문서 ID/단 개수 임계값으로 구별하지 않는다.
- 미주 대상의 실제 저장 사다리·문자 분할 유효성·줄 태그·이미 소비한 컷을
  확인하는 공통 Query를 작은 기존 measure include에 둔다.
- 실제 표시 fit의 `Fits/SplitAt/NextColumn`과 전체 문단 수용·컷 취소 helper가
  이 같은 Query를 소비한다. 반환 컷의 앞쪽 실제 점유를 재생해 확인한다.
- 이미 앞 조각을 소비하고 뒤 조각을 새 단에 둔 경우 동일 컷을 다시 적용하지 않는다.
  물리 공간 수용과 내용 소속을 함께 확인하며 clamp/출력 숨김을 추가하지 않는다.

## 검증 범위

같은 Native 빌드에서 9월 HWP 원본 전체 23쪽과 HWPX 짝을 우선 대조하고,
이전 고득점 2023 입력과 PrEP/일반 각주·표 대조군을 확인한다. 새 native/fresh
WASM 전쪽 TSV와 달라진 페이지/확대 PNG로 판단한다. 관련 모든 페이지가
90% 이상이 되기 전 새 회귀 기대값을 고정하지 않는다. HWPX 미달이 남으면
원본 경계 보존의 별도 원인을 해결한다. 전체 55개/853쪽, 실패 원본, 전체
Rust/lint·최신 devel 동기화·PR/CI/후속 처리는 그대로 남는다.

## 결과

`stored_endnote_column_cut`을 실제 원본 문단/단 상태로 조회하는 공통 Query로
구현했다. 유효한 저장 단 시작과 편집/합성 여부, 기존 컷 소비를 확인한다.
`measure_endnote_render_ink_fit`는 이 컷 이하의 앞 조각을 실제로 재생하고,
`reflowed_endnote_whole_paragraph_fits`도 같은 소속 계약을 확인한다. 두 코드
파일은 각각 1000줄 이하이며 큰 조정자 파일에 별도 추정 조건을 더하지 않았다.
새 출력·빌드와 반례 검증은 아직 완료되지 않았다.


## 중간 실행 결과

Native 새 빌드는 exit 0, 소스 해시 일치다. fresh WASM도 exit 0, 소스 해시와
Studio JS/WASM 동기화 일치를 확인했다. W 빌드 성공은 입력의 시각 통과가 아니다.

9월 HWP 첫 12쪽의 Native TSV에서 10쪽 98.88989%, 11쪽 98.77369%로 개선됐다.
4쪽 78.47295%가 남는다. 수정 전 Native의 같은 입력/Print/compat 2022와 대조해
4쪽 PNG SHA가 정확히 같음을 확인했다. 현재 수정의 회귀로 숨기거나 upstream
base의 미달로 추정하지 않고 현재 브랜치의 별도 보정 대상으로 유지한다.
새 대표 PNG는 `mydocs/pr/assets/issue7642-owned-endnote-cut-20261012/`에 보존했다.

검증 도구의 페이지마다 전체 문서를 다시 여는 비용을 확인해 이후 Native 묶음은
실제 CLI의 전체 SVG/tree 내보내기를 각각 한 번 실행한다. 전체 글꼴 바이트를
같은 로컬 파일 URL로 공급해 transient SVG 공간을 제한하며, 원문 SVG 복원 SHA와
실제 font 파일 SHA를 확인한다. 작은 대조군의 raw SVG와 PNG SHA가 기존 경로와
정확히 같고 점수도 98.50470%다. 점수 산식·canonical script·래스터 backend와
Native/WASM 코드에 변경이 없다. 현재 실행 중이던 worker는 계속 진행했다.
관련 영수증과 새 helper는 ignored output에 보존하며 Git에 추가하지 않는다.


HWP 원본 전체 Native 23쪽 검증이 끝났다. 실제 출력/기준 PDF 쪽수 23,
소스 해시 일치이며 90% 미만은 4쪽 하나다. 나머지 22쪽은 90% 이상이다.
`complete_failed`를 제출 보류로 유지한다. HWPX 짝 전체 검증이 새 Native 일괄
내보내기 경로에서 실행 중이며 새 WASM 입력 TSV는 아직 산출하지 않았다.
