# 단계 1185 줄 나눔의 표시 문자 폭과 실제 끝 자간 공유

Issue: #7642. 수정 전 구현은 `fa56a97f683fb7ca690ae6a155bf1902bcfc9406`, 현재 테스트 포함 head는 `91b95fce8`이다. 비교 기준은 `463c48cc228170b576c832591b76826116e86a49`다.

## 독립 근거와 적용 경로

같은 `samples/hwp3-sample16-hwp5.hwpx`와 독립 한컴 Print 64쪽의 24·25쪽을 유지한다. 24쪽 계약 문단의 첫 줄은 `응용프로그램,`까지, 25쪽은 `정보시스템` 앞에서 끝난다. 원본에는 저장 LineSeg가 없으며 DocumentCore가 원래 문자·글자 모양을 사용해 Frame으로 재조판한다. 파생 Unicode 네모 입력은 원본의 대체 증거가 아니다.

`tokenize_paragraph_with_regenerated_space_metric → measure_token_char_widths → BreakToken의 합/글자별 전진 → FitWidthHwp::trimmed → fill_interval → Frame의 줄·LineSeg → compose_paragraph → compute_line_extra_spacing → emitted_run_layout_positions → paint/공개 charX`를 대조했다. 원문/UTF-16 오프셋과 언어 슬롯을 유지한 표시 문자 폭, 실제 글리프에 적용된 자간을 같은 측정 함수에서 소비해야 한다.

## 현재 구현의 계측

현재 라이브러리에 링크한 공개 RenderTree·EmbeddedTextMeasurer 진단은 같은 96dpi에서 다음 값을 냈다. 미반올림 결과와 HU 변환을 구분한다. 실제 실행은 ignored 단계 1184에 보존했다.

| 항목 | 24쪽 문단 461 | 25쪽 문단 474 |
| --- | ---: | ---: |
| Frame 가용 폭 | 46024HU | 46024HU |
| 첫 줄 원문 PUA 측정 전진 | 610.91413px | 604.93333px |
| 같은 스타일의 표시 문자 측정 전진 | 618.54080px | 612.56000px |
| 말미 공백 | 7.28000px | 없음 |
| 마지막 가시 문자 | 쉼표 | `정` |
| 실제 글리프 자간 | 약 −0.68693px | 약 −2.77333px |

PUA 한 글자는 7.62667px, 표시 네모 한 글자는 15.25333px로 다르다. 24쪽에서 표시 폭을 사용한 가시 전진은 약 45844HU이며 실제 쉼표 끝 자간을 제외한 fit 폭은 약 45896HU로 가용 폭 안이다. 기존 글꼴 크기 기준 자간을 빼면 약 46052HU가 되어 잘못 줄을 넘긴다. 25쪽의 표시 폭은 약 45942HU이며 마지막 한글의 끝 자간을 제외하면 약 46150HU라 다음 줄이어야 한다. 두 수정이 함께 필요하며 PUA 전역 치환 하나로 맞추지 않는다.

## 보정과 반례

- 원문 scalar 수가 같은 검증된 PUA 표시 투영만 토큰 측정에 사용한다. 원문·문자 오프셋·글자 모양·언어 슬롯은 바꾸지 않는다. 숨긴 filler·여러 글자 확장·겹침은 기존 경계를 유지한다.
- 끝 자간은 같은 스타일의 글리프 측정에서 자간 유무의 차이로 구한다. ASCII 구두점의 별도 영문 슬롯 자간도 같은 과정에서 해소한다. 음수 자간의 부호와 실제 압축 제한을 보존한다.
- 줄 채움과 정렬의 끝 자간이 같은 helper를 사용하게 한다. 1:1 PUA가 앞에 있다는 이유로 뒤 쉼표의 자간 전체를 무시하던 정렬 guard도 대응 계약으로 검토한다. 다문자 표시와 삽입 컨트롤은 일반 scalar 소유로 추정하지 않는다.
- 공백의 자연 전진·내부 배분, 음수 자간, 작성된 개행, 개체·겹침, 다문자 PUA와 정상 저장 줄을 대조한다. 같은 독립 Print 6쪽의 새 공백 회귀를 유지하고 실제 24·25쪽과 주변 19·35쪽을 먼저 재출력한다. 관련 Native/fresh WASM이 통과하기 전에 새 실물 배치 핀이나 baseline을 추가하지 않는다.

## 비교에서 발견한 다른 남은 범위

현재 source의 원래 55문서 853쪽 Native TSV는 모두 90% 이상이다. 대조군을 합쳐 base/head를 같은 조건으로 직접 비교할 수 있는 938쪽 중 61쪽은 0.01%p 이상 하락했다. 기준 쪽수가 다른 4개 입력은 임의 대응시켜 비교하지 않았다. `stage1177-native-page-delta-audit.json`과 `stage1178-native-decline-review-provenance.json`에 십진수 비교와 같은 배율의 base/head/Print를 연결한다. 이 상태는 PR 완료가 아니다.

특히 사회 시험지 제목의 현재 문자 원점은 Print의 `사` 280.0px, `회` 약 330.4023px와 대응한다. 과거 base의 약 293.8px/48px 전진으로 되돌리는 것은 실제 위치를 악화시킨다. 점수 하락만 보고 HFT 굵기 전진을 삭제하지 않는다. 실제 표시 글꼴·굵기와 glyph-fit, 주거 문서의 공백 배치, HWP3 19쪽 미달 및 추적 변경 4쪽의 줄 소속은 별도 원인 분석이 남아 있다.

배포 문서의 3쪽 표 머리글은 한컴 2020 Print에는 흰색, 기존 2024 PDF에는 그라데이션이 있어 버전별 기준 차이를 확인했다. 이를 근거 없이 새 gradient 결함으로 분류하거나 높은 점수의 기준으로 바꾸지 않는다. `.hwpx` 확장자이지만 실제 입력은 HWP5 CFB임도 확인했다.

이 문서 작성 시점의 새 보정은 아직 미검증이다. 기존 source의 새 정식 공백 검사 3건은 같은 현재 라이브러리에 링크해 모두 PASS했으며, base의 의도한 2건 FAIL과 구분했다. Cargo의 새 정식 suite/기존 Split 집중 검사는 실행 중이고 최종 종료 결과를 기다린다. 전체 회귀·lint·fresh WASM·새 source 전쪽 비교·PR/CI와 옵션 2 문서 PR·merge 후속 처리는 미완료다.

단계 1170의 이전 source 집중 nextest는 이후 실제 종료 코드 0, 7건 PASS로 완료됐다. 새 공백 검사 3건과 기존 Split 검사 4건이며 전체 회귀 결과는 아니다. 이 단계 보정의 수정 후 검증은 아직 남아 있다.

## 첫 후보 실행에서 확인한 소비 누락

source `4e0ad2759`의 Native 빌드와 새 공백 검사 3건은 통과했지만, 실제 문단 474의 첫 줄에는 여전히 `정`이 남았다. 토큰의 묶음 측정만 공통 표시 폭으로 바꾼 상태였고 개별 기호·한글 글자 모드·금칙 결합·영문 글자 모드·준비된 문단 투영에는 직접 문자 측정이 남아 있었다. helper 수정만으로 실제 소비 경로 전체가 바뀌었다고 판정하지 않는다.

이 직접 분기를 `reflow_scalar_width`로 모두 연결한다. 합산 폭·개별 전진·준비된 투영이 원문 슬롯을 유지하면서 같은 1:1 표시 글리프를 재도록 보정한 뒤 실제 문단 461·474를 다시 확인한다. 전쪽 TSV를 아직 수정 후 완료로 보고하지 않는다.
