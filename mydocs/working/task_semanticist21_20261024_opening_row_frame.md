# 완결 행에서 닫히는 첫 저장 물리 프레임

## 근거와 원인

기준 소스는 `215057b5b9`, 마지막 Native는 179다. 원본 HWP/HWPX는 각각 115쪽이며
같은 원본의 독립 한컴 2024/2020 Print와 전쪽 최저 raw 90% 이상이다. 102쪽의
8행×2열 자식 표는 첫 행을 모두 소비하고 103쪽에서 둘째 행부터 이어진다. 102쪽
아래 선은 점수 통과와 별개로 직접 판독에서 차이가 남는다.

원본 `cell2/p2276`의 개체 높이는 2456HU, 첫 행 보조 칸 높이는 2797HU다.
첫 행 저장 줄 1000HU와 활성 위·아래 여백 1134HU는 개체 프레임 안에 들어간다.
독립 Print의 첫 괘선 높이는 약 32.60px이고 선언 개체 높이 환산은 32.75px다.
현재 Native의 첫 행은 37.29px다. 전체 표 높이와 첫 물리 조각의 높이를 구분해야 한다.
같은 원본의 해당 조건 표는 하나이며, 파일 번호나 이 좌표로 분기하지 않는다(2847).

#7140의 원 PR #7184, 실제 통합 #7197, 구현 `ec5825f8c4`, merge `6cd3c0692a`와
메인터너 보정 `f2e21164c0`를 다시 확인했다(2849). 원 계약은 행 유닛·컷 예약·실제
배치가 같은 프레임을 소비하는 것이다. 기존 실제 끝 컷·종결 예약 및 예산 재선택은 유지한다.
`issue3637` 26/27쪽과 뒤 문단의 누락·중복을 대조군으로 둔다.

## 보정 범위

원본 일반 저장 그리드에서 첫 개체 프레임이 마지막 선택 행의 빈 띠 안에서 닫히는
경우의 행 벡터와 종료 행을 source 단위로 한 번 계산한다. 전체 열 구획과 선택한 모든
행의 실제 저장 줄·여백을 인증한다. 내용보다 작거나 되감긴 줄·합성 줄·병합 행·편집된
표·자리차지 표는 이 규칙으로 줄이지 않는다. 원본 정수 단위로 확인하고 px 임계값이나
문서별 수치로 프레임 소유를 추정하지 않는다.

`공통 저장 행 벡터 → HeightMeasurer와 resolve_row_heights → cell_units → 컷 예약 →
row_cut_content_height와 table_partial`가 같은 결과를 소비하게 한다. 셀 유닛 생산 후
원래 칸 높이로 다시 max 하는 경로와 부분 배치에서의 재계산도 함께 확인한다. 이어받기는
둘째 행부터 시작하며 첫 행의 빈 띠를 별도 내용으로 다음 쪽에서 다시 소비하지 않는다.

## 검증 계획

기존 Native179와 후보의 원본·복원 live/재열기 전쪽, 101~104쪽 review·overlay를
대조한다. 첫 조각의 내용 포함·다음 쪽의 행 순서·누락·중복과 뒤 표를 확인한다.
기존 #7140/#5880/#6095/#7114/#7418/#7902 및 프레임 계약 묶음을 재실행한다.
같은 줄의 편집 성능 계약도 유지한다. 기존 기대값을 완화하지 않는다.
후보의 Native/fresh WASM 시각 선행 조건과 직접 판독을 마친 뒤 새 이름의 회귀를 추가한다.


## Native180 구현·검증

공통 결과는 `float_placement::stored_plain_opening_row_frame`이다. 원본 열 구획과
선택 행의 저장 줄·위/아래 여백을 정수 HU로 인증하고, 행 벡터와 첫 조각 종료 행을
함께 반환한다. 정확한 기존 행 경계, 내용 하한을 넘는 축소, 합성/재조판 줄과 병합 행은
추가 축소하지 않는다. 보조 칸 높이를 바꾸거나 원본 모델에 좌표를 기록하지 않는다.

소비 경로는 다음과 같다.

| 생산/소비 | 실제 경로 | 후속 덮어쓰기 확인 |
| --- | --- | --- |
| 공통 행 벡터 | 새 source helper | 내용+활성 여백 이하로 줄이지 않음 |
| 측정 | `HeightMeasurer`의 저장 행 선택 | 같은 벡터로 전체 높이 구성 |
| 행 유닛 | `resolve_row_heights_with_common_fit → cell_units` | 원본 첫 조각 종료 행도 같은 결과 사용 |
| 컷 요구·예약 | `row_cut_height`의 완결 행 분기 | 보조 칸 높이의 max로 다시 늘리지 않음 |
| 실제 조각 | `table_partial`의 저장 행/컷 높이 | 동일 벡터를 소비한 실제 노드 높이 확인 |

`output/pr-review/semanticist21-20261019/`에 보존한다.

## 남은 직접 판독과 다음 보정

현재 최저는 76쪽 96.14693%, 그다음은 53쪽 97.95182%다. 2860으로 두 쪽의 새
review·overlay를 만들고 76쪽 두 이미지를 함께 열었다. 본문 순서·줄바꿈과 별개로
수식 크기·간격이 기준 Print와 다르다. 점수 통과만으로 완료 처리하지 않는다.

2861에서 76쪽의 실제 수식 노드와 원본 수식 속성을 확보했다. `p1685`에는 두 수식
컨트롤이 있고 서로 다른 script·보조 폭을 갖는다. 원본 탭·두 개체의 UTF-16 소유도
함께 확인해야 하므로 중복처럼 보인다는 이유만으로 한 개체를 제거하지 않는다.
`p1688` 등은 `font_size=900`, `font_name=HYhwpEQ`이며 그 글꼴의 시스템 등록본이
실제로 존재한다. 글꼴 미설치로 추정하거나 수치 보정으로 맞추지 않고 원 해결·배치 경로를
분석해 보정한다. 증거는 ignored 2861 JSON에 보존했다.

이번 단계는 첫 표 프레임의 Native 보정과 기존 경계 재검증이다. 수식 보정·fresh WASM·
새 이름의 정식 회귀 및 나머지 필수 검증을 마치기 전에는 PR 준비 완료로 판정하지 않는다.
새 회귀나 기준값 완화는 추가하지 않았다.


후속 읽기(2864): 같은 원본 Print 76쪽의 수식 폰트 span은 약 8.99265pt이며 원본
9pt와 대응한다. PDF는 Type3 subset이다. `layout_for_paint → stored_vertical_scale →
paint`의 자연 글리프/선언 상자 소비와 원본 두 수식의 소유를 더 추적해야 한다.
