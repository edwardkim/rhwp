# 이슈 #7642 — 연속 미주 문단의 실제 점유에 따른 분할

시작 커밋: `e2e48e8aa`. 이번 회귀 실패는 현재 브랜치에서 모두 보정한다.

## 원본·독립 기준과 원인

`samples/3-11월_실전_통합_2022.hwpx`의 2024 Print는 미주 풀이를 다음 단으로
이어 배치한다. Stage32의 같은 원문은 누계 원점과 실제 원점이 정합해도 내용 높이
70.5를 잔여 55.6에 수용한다. 저장 span의 bleed 허용값으로 fit을 판정한 뒤
실제 내용 끝을 대조하지 않은 것이 현재 남은 원인 후보다. 수치는 진단 관측이며
실물의 절대 px 기대값이나 문서 식별 조건으로 사용하지 않는다.

## 생산·소비와 수정 범위

`현재 단의 확정 items + 전체 후보 → measure_endnote_column_with_item →
실제 build_single_column 점유 끝 → 분할 후보의 같은 PartialParagraph 측정 → emit`
경로를 연결한다. 저장 span에 들어간다는 이유로 실제 본문 밖 내용을 수용하지 않는다.
현재 범위는 저장 내부 되감김이 없는 연속 다줄 문단이다. 내부 저장 컷, 명시 단 나눔,
keep 계약과 그림·표·도형이 있는 후보는 별도 계약을 유지하며 임의 컷으로 대신하지 않는다.
현재 단의 표 측정 문맥은 동일하게 전달한다. 뒤 줄 간격의 흐름 예약과 보이는 내용의
점유는 구별하고 단 마지막 내용의 fit을 trailing 간격 합만으로 판단하지 않는다.

Native 15·17쪽의 실제 컷과 전체 쪽수, 원본 HWP/2020 대조군부터 확인한다.
미충족이면 원인을 계속 보정한다. 영향 전쪽 Native/fresh WASM의 90% 이상과
확대 판독 전에는 기존 회귀 기대값·baseline을 변경하지 않는다.
