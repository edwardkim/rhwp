# Stage 325 — Native 명령 우선순위의 독립 Print 대조

Issue: #7642

`native-keyword-precedence`의 수식 30개를 한컴 일반 저장·Print로 출력했다.
저장 전후 script의 순서와 바이트가 같고 전체 PDF는 1쪽이다. 실제 한컴 빌드·
Print 경로·job·HWP/HWPX/PDF SHA는 해당 진단 폴더의 README에 보존했다.

다음 관계는 독립 Print의 실제 글자와 배치로 확인했다.

- `a OVERSET{x}{y} b`와 `a OVER SET{x}{y} b`는 같은 분수 구조다.
- `a UNDERSET{x}{y} b`와 `a UNDERLINE SET{x}{y} b`는 같은 밑줄 구조다.
- `UNDERfoo`와 `UNDERLINEfoo`도 같은 밑줄 구조다.
- `OVERRUN`·`OVERlap`·`OVERfoo`는 긴 글자라고 앞의 OVER를 무시하지 않는다.
- 따옴표 단어는 원문 글자를 유지한다. 백슬래시 overset/underset도 이 Print에서는
  문자로 남아 공개 LaTeX 파서의 구조 해석과 다르다.

현재 문서 tokenizer는 공개 호환 tokenizer의 전체 키워드·길이 가드를 먼저 쓰므로
이 Native 명령 우선순위를 놓친다. 특정 파일이나 수치를 선택하는 분기로 처리하지 않고
문서 생성 문법에서 키워드와 피연산자의 경계를 구분해야 한다.
긴 Native 명령·유사 이름·명시적 백슬래시 대조를 추가한 뒤 한 번에 보정한다.

ignored `stage325-keyword-print-trace.json`과 `stage325-keyword-analysis.json`에
원문·PDF glyph/좌표·확인한 동치 관계를 보존했다. 부분 PUA 문자 해독과 실제 glyph
판독을 구분하며 문자 추출만으로 모양의 일치를 판정하지 않는다.
현재 production 수정과 새 렌더링 회귀 추가는 아직 수행하지 않았다.
