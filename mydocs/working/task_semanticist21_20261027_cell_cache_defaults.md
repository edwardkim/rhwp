  설명할 수 없는 세로 원점이 함께 어긋난 경우를 공통 소유 판정으로 다룬다.

## 생산·소비와 구현 순서

1. `compute_render_normalized`의 공통 렌더 사본에서 셀·부모 호스트의 무효 캐시를 함께
   폐기한다. 원본 IR·저장 바이트는 보존한다. 실제 측정·조판·paint는 같은 사본을 소비하고
   유효한 저장 프레임은 유지한다. 2 HU는 정수 저장 경계 오차이며 px 좌표 핀은 아니다.
2. 글자모양 표가 아예 없는 HWPX의 암묵적0번 스타일을 조회 문맥에서 제공한다.
   명시된 글꼴은 우선하고 없는 슬롯만 독립 Print에서 확인한 기본값을 사용한다.
   기본형 IR의12px 계약을 전역으로 바꾸거나 저장본에 글꼴·캐시를 써넣지 않는다.
3. Percent 음수 줄간격은 글자 높이에 대한 전진 감소량이다. TAC의 양수 간격 분배 규칙과
   구분해 공통 생산 결과를 측정·실제 배치까지 소비한다. 근거 없는 clamp로 대신하지 않는다.
4. 한 Native 빌드로 원 입력8조건·최소 IR3조건·직전 정상13조건·#8188 전쪽을 확인한다.
   큰 출력 차이를 먼저 보정한 뒤 표준 최적화 fresh WASM, 직접 review/overlay, 새 이름의
   회귀와 최종 전체 검증으로 진행한다. 기준 PDF·허용치·글꼴 공급을 바꿔 점수를 숨기지 않는다.

중간 분석은 ignored `output/pr-review/semanticist21-20261019/`의4401~4430에 있다.
실제 수정·실행과 종료 결과는 수행 뒤 추가한다. Cargo는 공용 target/pr-review·8 jobs,
테스트는12 threads를 순차 사용한다. 미해결 필수 범위가 남으면 PR을 생성하지 않는다.

## 실제 선행 InlineFlow 경로와 부호 있는 전진

4440은 컴파일 exit0, 4441의 원본 #7833 8조건 모두 raw100이다. 기존 정상 13조건도
모두 통과했다. 최소 IR 3조건은 여전히 미달이다. `dump-pages`의 실제 format은 이제
표 물리 높이53.333px·간격−13.333px·전진40px를 발행한다(4446).

실제 배치는 format 이후의 통째 표 경로보다 앞의 `try_place_reflowed_table_rows`에서
종료했다. 앞서 통째 표 경로라고 추정한 것은 실제 호출 추적 결과가 아니므로 정정한다.
이 경로의 `InlineFlowPlan`은 표가 있으면 음수 gap을0으로 clamp하고 최종 end도
물리 하단의 최댓값으로 바꿨다. 이미 `occupied_end()`로 쪽 수용의 물리 높이를 따로
보존하므로 Percent의 부호 있는 줄 전진은 `next_row_top`을 소비하도록 수정한다.
Fixed 등 다른 줄간격의 기존 계약은 유지한다. 표 선언 높이·행 높이·fit 점유를 줄이거나
본문 좌표를 직접 보정하지 않는다. 4447 빌드와 4448/4449로 원본·대조군을 재검증한다.

4447은 컴파일 exit0이다. 최초 결과에서 #8039 두 원본이 모두 raw100으로 개선됐다.
같은 부호 있는 `InlineFlowPlan.end`를 사용하는 일반 혼합 본문 경로의 세 fit 조회도
추적했다. 전진40px가 물리 점유53.333px를 대신해 쪽 수용을 통과하지 않도록
기존 end와 `occupied_end()`의 큰 값을 수용 예산에 사용한다. 다음 본문은 부호 있는
end를 그대로 사용하며 fit 때문에 흐름을 다시 물리 하단으로 되감지 않는다.
4452 Native 빌드에서 모든 영향 조건을 재검증한 뒤 표준 fresh080을 빌드한다.

빌드 중 여유 공간이 줄어 사용 중이 아닌 output의 옛 진단 rlib·CLI 27개, 약2.35GiB를
정리했다(4577). 실제 프로세스 인자·열린 파일 참조와 소유를 확인했고 현재/기준 제품·
RED/이전 정상 제품·WASM package·증적·공유 Cargo target은 보존했다. 앞선 유휴 경로의
SVG 확인은 삭제 대상0개였으며 이를 확보 공간으로 집계하지 않는다(4576).
