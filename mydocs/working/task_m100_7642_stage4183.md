# Issue #7642 단계 4183: CI 수식 검사의 시스템 글꼴 의존성 보정

Issue: #7642 / PR: #8064

## 원인과 변경 범위

- 제출 head `f33f7d9b3924bf4169d45a3805bf9a6a5c7d01d7`의 CI run `39181669838`에서 Archive B/D의 아래첨자·dyad 최종 SVG 윤곽 검사가 실패했다. 나머지 필수 workflow와 Archive C는 성공했다. 실패 로그는 ignored `stage4183-ci-failure-analysis/{archive-b,archive-d}.log`다.
- 기존 검사는 `usvg::Options.fontdb.load_system_fonts()`에 의존했다. 한컴 글꼴이 설치된 로컬에서는 통과했지만, 해당 face가 없는 CI에서는 SVG text의 실제 문자가 윤곽으로 변환되지 않았다. 빈 fontconfig로 격리한 로컬의 정확한 검사 4건 중 3건에서 같은 누락을 재현했다. 잘못 선택한 과거 suite의0건 실행은 증거에서 제외했다.
- dyad는 저장소의 공개 `LatinModernMath-VariableOutline-subset.otf`만 명시해 AB와 장식의 최종 윤곽·동일 폭·뒤 본문 비겹침을 검사한다. 시스템 글꼴은 적재하지 않는다. 원본 문자의 정체·순서·소유와 실제 SVG 좌표 변환을 유지했다.
- 아래첨자는 한컴 PUA를 다른 글리프로 바꾸지 않는다. 원본 소유·단일 방출·분모/첨자 보존과 레이아웃 기준선 관계에 더해, 최종 SVG 원문의 문자·조상 변환 후 페이지 기준선을 검사한다. 사설 face가 없는 환경의 대체 윤곽을 실제 한컴 잉크라고 부르지 않는다. 검사 이름도 `...emits_below_the_denominator`로 바꿨다. 실제 글리프 모양은 아래 독립 Print 시각 대조로 별도 확인한다.
- 제품 소스·문서 바이트·Print PDF·기대 좌표·golden·허용치를 바꾸지 않았다. 이 검사 보정을 조판 엔진의 추가 개선이라고 보고하지 않는다.

## 독립 출력과 집중 검증

- 현재 제품 소스와 같은 D7 Native/fresh WASM producer로 새로 출력한원본 3종의 전체 6쪽은 양쪽 raw 90% 이상·독립 PDF 쪽수 일치다. Native 최저 99.77969%, fresh WASM 최저 99.88334%, 미달·누락 0이다.
- [원문 TSV·입력/Print SHA·대표 review/overlay](../pr/assets/issue7642/cifonts/README.md)를 보존했다. 아래첨자·분모·제곱·근 지수와 AB/장식·뒤 본문을 직접 판독했다. 안티앨리어싱·글리프 굵기 잔차가 있으며 raw 100%를 동일 이미지로 해석하지 않는다.
- 수정 후 집중 nextest 4 PASS, 시스템 글꼴을 제외한 정확한 4개 검사도 4 PASS다. 원래 조판 결함의 수정 전 FAIL/수정 후 PASS는 stage171·165의 독립 기대값과 연결하며, 글꼴 공급 실패를 원래 조판 결함 재현으로 섞지 않는다.
- 변경된 검사 크기로 자동 suite 구성이 달라져 최초 정책 확인이 drift로 중단됐다. 정본 `--prepare`로 파생 harness를 재생성한 뒤 정책을 다시 확인했다. 파생 파일을 직접 수정하거나 커밋하지 않았다.

## 전체 재검증

- 전체 nextest **11,014 PASS / 0 FAIL / 45 SKIP**로 종료했다. fmt, diff, 고정 base suite/unit 정책과 workspace all-target Clippy `-D warnings`도 모두 exit 0이다.
