## 독립 관측과 원인 계층

동일 원본 `samples/3-11월_실전_통합_2022.hwp`와 독립 MCP2020 Print
(job `cc8b4953-2dbd-4bfd-b46a-4a3db2d8fc30`, PrintMethod 0, 21쪽)를 대조했다.
source `603a41837`의 Native 17–21쪽은 각각 95.47163 / 82.66459 / 40.94945 /
65.91557 / 86.60499%이며 누락은 없다. 이는 영향 페이지 진단이며 전쪽 통과가 아니다.

18쪽 끝의 2줄 미주 문단은 남은 예산보다 높지만 같은 단에 통째로 방출된다. 독립 Print는
19쪽에서 이 문단을 시작한다. 이후 19쪽 왼쪽 문항들이 그 문단 높이만큼 앞당겨지며,
오른쪽도 앞 단의 3줄 문단을 잘못 수용한 것과 대응하는 이동이 보인다. 최신 19쪽 review를
직접 열고 사용자에게 표시했다. 진단 좌표와 높이는 출력 차이의 원인 추적용이다.

현재 실제 점유 확인은 `reflowed_endnote_single_line_overflows`에서 저장/구성 각 1줄에만
적용된다. 여러 줄에는 작은 저장 vpos 누계와 하단 bleed 예외가 남아 실제 예산 초과를
수용한다. 문단의 keepLines/keepWithNext/widowOrphan은 모두 false임을 파서 속성으로
확인했다. RHWP의 export-hwpx는 속성 진단에만 썼고 한컴 저장본이나 기준 Print로 쓰지 않았다.

## 공통 결과와 보정 계획

1. `simulate_endnote_column_with_item`이 호출하는 실제 `build_single_column`의 흐름 끝과
   줄/내용 점유 끝을 같은 결과로 노출한다. 기존 소비자의 선택 의미는 보존한다.
2. 다줄 문단은 현재 단에 첫 물리 줄도 들어가지 않으면 다음 단에서 시작한다. 첫 줄의
   줄간격까지 포함한 흐름 예약과 실제 점유를 모두 확인한다. 그릴 글자의 유무와 물리 공간을
   혼동하거나 잘못된 배치를 clamp하지 않는다.
3. 기존 저장 내부 단 컷과 유효한 부분 문단의 소유는 별도 계약이다. 비적용/미검증 경로를
   명시하며, 임의 문서 ID·문항 번호·고정 px 높이로 예외를 만들지 않는다.
4. 새 Native의 영향 페이지를 먼저 대조하고, 개선 방향과 내용 순서·누락·중복·쪽수 및
   정상 대조군을 확인한다. 같은 원본의 전쪽 Native/fresh WASM 90%와 확대 판독 전에는
   관련 회귀·baseline·golden을 변경하지 않는다.

현재 전체 회귀 실패는 이 브랜치에서 보정한다. 새 이슈 이관이나 검사 삭제로 해소하지 않으며,
52개 원본과 전체 회귀·lint·fresh WASM의 최종 검증은 별도 필수 게이트로 남아 있다.
로그·TSV·중간 JSON·nextrun은 ignored output에 보존한다. 아직 구현·새 시각 결과는 없다.

## 구현 중간 상태

실제 단 배치의 흐름 끝과 점유 끝을 공통 `EndnoteColumnGeometry`로 노출했다. 기존 소비자는
전체/부분 문단·미래 tail·occupied-only의 기존 선택을 유지하며, 새 첫 줄 판정은 그 동일 결과의
흐름 예약과 실제 점유를 모두 소비한다. 새로 계산한 독립 좌표나 고정 bleed 값을 사용하지 않는다.

저장/구성 줄 수가 대응하고 저장 내부 vpos 리셋이 없는 연속 다줄 문단은 첫 물리 줄을
`PartialParagraph(0..1)`로 실제 측정한다. 그 줄의 흐름 또는 점유가 현재 예산을 넘으면 다음
단에서 시작한다. 저장 내부 컷, 명시적 단 경계, 줄 수가 다른 경로는 기존 계약을 유지하고
이번 첫 줄 판단의 적용 증거로 일반화하지 않는다. 기존 1줄 점유 경로는 유지한다.

아직 새 Native와 독립 Print의 영향 페이지 대조를 실행하지 않았다. 기존 미달 문서의 검사·
기대값·baseline은 변경하지 않았으며 이 구현을 시각 개선 완료로 판정하지 않는다.

## 실행 Print PDF의 커밋 보존 확인

전체 요청 52개에서 실행한 독립 Print PDF의 SHA-256을 모든 추적 PDF의 실제 Git blob과
대조했다. **52개 모두 동일 바이트가 기존 HEAD `8aeda78b0`에 이미 커밋되어 있었다.**
같은 파일명으로 추정한 기존 PDF는 바이트가 달랐지만, 전체 해시 조회로 실제 대응 파일을
확인했다. 새 PDF 사본은 만들지 않았다. `requested-print-commit-audit.json`에 실행 경로,
공식 보존 경로·Git blob·PDF SHA-256을 연결하고 후속 명령의 기준 경로를 그 보존 경로로
고정했다. 이 확인은 PDF가 커밋되어 있다는 증거이며 해당 문서의 시각 통과를 의미하지 않는다.
