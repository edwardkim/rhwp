# 절댓값 구분자의 실제 논리 전진폭

Issue: #7642

## 독립 저장·Print의 분해

Stage241의 24개 수식에서 `LEFT | a _n RIGHT |`의 정상 저장 폭은
900/1100/1600/2200HU에서 각각 1725/2025/3150/4350HU다.
같은 크기의 둥근 괄호 입력에서 정상 괄호 슬롯을 제외한 `a _n` 본체는
각각 825/975/1350/2100HU다. 따라서 절댓값 각 구분자의 슬롯은
450/525/900/1125HU다. PDF 글리프 원점에서도 왼쪽 막대와 `a`의
전진을 확인했다. 입력·정상 저장·Print·CMap·원점 기록은 ignored
`stage241-small-delimiter-diagnostic`에 보존했다.

일반 글꼴의 0.333em 괄호 폭과 양쪽 PAREN_PAD를 절댓값에 사용하는
기존 경로는 이 독립 슬롯보다 작다. 작은 괄호의 정상 전진폭을 바로잡으면
중첩 절댓값의 부족한 전진이 더 분명해졌다. 두 오차가 서로 상쇄되던
전체 폭만으로 정상 배치를 판정하지 않는다.

## 후보와 검증

확인한 논리 글자 크기의 글꼴 슬롯만 발행한다. 절댓값의 원점과 전체 폭은
같은 슬롯을 소비하고 generic pad를 중복 가산하지 않는다. 미측정 크기의
메트릭을 보간하거나 실물 문서 위치를 고정하지 않는다. 숫자는 독립 글꼴
메트릭이며 회귀 검사의 px 기대값이 아니다.

Source252의 저장 컷 보정과 작은 괄호 채움 윤곽을 같은 후보에 누적했다.
math8과 정상화 24개 입력의 원점·폭·형태를 한 빌드로 비교하고 9월·10월
및 나머지 전체 원본도 재검증한다. Native/fresh WASM 전쪽 gate와 직접
판독은 아직 미완료이며 새 관계 회귀 추가를 통과로 앞당기지 않는다.
