# 작업 2464-2511 단계 3 - E2E runner 완료성 보정

## 문제

- `save-as-format.test.mjs`가 두 `runTest()`를 기다리지 않고 동시에 시작해 공용 reporter 상태를 덮어쓴다.
- `text-flow.test.mjs`가 top-level `runTest()` Promise를 기다리지 않아 긴 입력 단계의 완료와 HTML report 생성을 보장하지 못한다.

## 계획

1. 저장 포맷 E2E의 두 시나리오를 top-level `await`로 순차 실행한다.
2. 텍스트 플로우 E2E도 top-level `await`로 전체 비동기 흐름을 유지한다.
3. manifest 정합, HML 열기, 저장 포맷, undo, text-flow E2E를 다시 실행한다.

## 경계

- `e2e/helpers.mjs`의 공용 reporter 설계는 이 단계에서 변경하지 않는다.
- 문서 파서·serializer·renderer·확장 runtime 코드는 변경하지 않는다.

## 결과

- 두 스크립트에서 top-level `await runTest(...)`를 사용해 모듈이 E2E 완료, HTML report 생성, browser 정리를
  명시적으로 기다리게 했다. 저장 포맷 시나리오는 순차 실행되어 공용 reporter 경합이 사라졌다.
- `save-as-format.test.mjs --mode=headless`는 HWP→HWPX와 HWPX→HWP 모두 blob 매직, MIME, 재열기 assertion을 통과했다.
- `text-flow.test.mjs --mode=headless`는 2페이지 생성과 Backspace 문단 병합까지 통과했다.
- `hml-open.check.mjs --mode=headless`, `undo-contracts.test.mjs --mode=headless`, E2E manifest 검사는 이전 단계에서 통과했고,
  이번 변경은 다른 E2E의 helper/runtime 의미를 바꾸지 않는다.
- 첫 text-flow 출력 중단은 실행 셀의 짧은 시간 제한 때문이었고, PTY 장기 실행으로 실제 exit code `0`과 report 생성을 확인했다.
