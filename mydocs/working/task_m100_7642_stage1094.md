# 단계 1094 양쪽 정렬의 마지막 가시 글자 점유

Issue: #7642. 수정 전 생산 source는 `c8530907401c87a1018d994d4ad033e8fe38444e`, 기준 devel은 `a5e88ad682c805e1d845502ddc9521b94ea8eccd`다.

## 독립 관측과 원인

HWP3 sample16 19쪽의 여러 양쪽 정렬 줄은 마지막 본문 글자의 원점이 Print보다 약2px 오른쪽이다. 첫 줄의 마지막 `의`는 Native708.45333 / Print706.23885이며, Print의 명목 글자 상자 끝은723.51884다. 다른 정상 마지막 줄의 오차는 대체로0.1px 이내다. 양쪽 정렬 줄의 원본 자간은 음수이므로 마지막 글자의 advance에 남아 있는 자간을 포함해 줄을 채우면 명목 글자 폭이 우단을 넘는다. 수치를 빼서 맞추지 않고 원본 자간과 마지막 가시 글자의 점유를 구별한다.

현재 `compute_line_extra_spacing`은 Split의 낱말 배분에만 마지막 음수 자간의 점유를 되돌린다. Justify는 같은 규칙을 적용하지 않는다. 이미 Center/Right가 소비하는 `terminal_tracking_for_alignment`는 마지막 원본 grapheme의 자간, 저장 스타일, 끝 개체 소유를 확인한다. 이 결과를 생산 위치에서 넘겨 Justify의 가시 글자 끝을 기준으로 배분한다. 기존 Split·합성 soft-wrap의 보존 구분 공백 계약은 유지한다. 낱말 배분이 없는 문자 분배나 kerning 경로까지 검증됐다고 확장해 보고하지 않는다.

생산·소비 연결은 `line_tac_offsets_for_width → terminal_tracking_for_alignment → compute_line_extra_spacing의 effective_used → extra_word_sp → emit_line_runs의 layout_positions/bbox → Native·WASM paint`다. 마지막 개체 뒤의 본문 간격을 끝 자간으로 빼지 않도록 기존 helper의 개체 경계를 소비한다. 구현 이후 별도 원점을 이동하거나 clamp하지 않는다.

## 검증 계획

선두 공백과 음수 자간을 각각 구별하는6쪽 합성 HWPX를 공개 serializer 출력으로 구성했다. Left/Justify, 선두0/1/3칸, 자간0/−12%의 대응 문단이며 한컴2020 engine Print를 요청했다. MCP job `a2492590-4fec-4e6d-9cd9-45fdda8e328c`는 현재 대기 중이다. 합성 저장 정보를 정상 한컴 저장본으로 분류하거나 결과를 실행 전에 통과로 기록하지 않는다.

수정 전후의 공개 문자 경계와 원본19쪽·HWPX25쪽 및11문서245쪽을 함께 대조한다. 기존 집중65건과 마지막 글자 점유의 공개 API 후보를 묶어 실행한다. 실제 원본의 전쪽 Native/fresh WASM90% 및 확대 판독 조건을 충족하기 전에는 새 실물 baseline이나 정식 회귀를 추가하지 않는다.
