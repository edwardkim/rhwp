# Task M100 #4969 W10-Q2-D3 — GlyphRun lowering shadow

## 판정

Q2-D3는 **qualified**다. `LayerNode.source_node_id`로 D2 page sidecar를 찾고, Q2-B의 exact embedded
font identity와 glyph geometry·cluster를 기존 `LayerGlyphRunPaint`로 손실 없이 내리는 별도 shadow
entrypoint를 만들었다. 제품 LayerBuilder caller는 여전히 0이므로 render·layer·JSON·화면 출력 변화도 0이다.

기계 판독 결과는
[`w10_q2_d3_glyph_run_lowering.json`](../tech/investigations/issue-4969/w10_q2_d3_glyph_run_lowering.json)이다.

## lookup·font identity

1. lowerer는 `LayerNode.source_node_id`가 없거나 같은 `NodeId`의 sidecar가 없으면 즉시 닫는다.
2. sidecar가 applied measurement를 소유하고 TextRun 전체 scalar·UTF-8·UTF-16 길이가 D2 range와 같을
   때만 계속한다.
3. `char_shape_id`·언어 slot에 더해 embedded bytes SHA-256, byte length, face index를 Q2 source handle과
   모두 대사한다. 같은 identity가 둘 이상이면 임의 선택하지 않는다.
4. face parse와 units-per-em을 다시 확인하고, shaping identity가 LTR·horizontal-tb·`Hang`·`ko`, 단일
   `kern` feature, variation 없음인지 확인한다.
5. 공개 fixture font는 456,688 bytes, face index 0,
   SHA-256 `2f86ef9a52acb6d1dad9d915843239123b635d97edd88fd0573a88ffcb4e16f1`이다.

## 손실 없는 glyph·cluster 변환

Q2-B raw design unit로부터 px 좌표를 다시 계산해 measurement가 변조되지 않았음을 먼저 확인한다. 장평 80%,
font size 10px의 Source Han 옛한글 fixture는 native와 Node WASM에서 다음 고정 오라클과 일치한다.

| glyph index | glyph ID | x (px) | y (px) | advance x (px) | advance y (px) | cluster UTF-8 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 614 | 0.000 | 0.000 | 7.728 | 0.000 | 0 |
| 1 | 1230 | 7.728 | 0.000 | 7.728 | 0.000 | 9 |
| 2 | 1497 | 15.456 | 0.000 | 0.000 | 0.000 | 9 |
| 3 | 2085 | 15.456 | 0.000 | 0.000 | 0.000 | 9 |

cluster는 다음처럼 보존된다.

- 첫 cluster: scalar `0..3`, UTF-8 `0..9`, UTF-16 `0..3`, glyph `0..1`, many-to-one이므로
  `Ligature`/unsplittable 표시
- 둘째 cluster: scalar `3..4`, UTF-8 `9..12`, UTF-16 `3..4`, glyph `1..4`, one-to-many이므로
  ligature로 오표기하지 않음

초기 fixture 검토에서 scalar `0..3`을 glyph `0..3`으로 잘못 읽은 기대값은 native 결과로 발견해 바로잡았다.
이는 구현 결함이 아니라 서로 다른 좌표계의 테스트 기대값 오류였으며, 이번에는 위 고정 오라클로 두 좌표계를
각각 잠갔다.

## fallback·중복 방지·fail-closed

- shadow lowerer는 기존 `PaintOp::TextRun`을 삭제하거나 바꾸지 않는다.
- 성공 report의 `claims_glyph_run_slot=true`는 D4가 같은 TextRun의 nominal glyph lowerer를 건너뛰게 할
  단일 소유권 신호다. D3에서는 report 밖으로 게시하지 않는다.
- rejected report에는 source `NodeId`와 stable typed reason만 남긴다. raw text·font bytes·host path와 public
  annotation은 기록하지 않는다.
- vertical/RTL·display projection·layout positions·rotation·CharOverlap·field marker·border·텍스트 효과·자간·
  tab·synthetic style은 계속 닫는다.
- glyph·cluster는 각 4,096개, 개별 portable font는 32 MiB, page-local common shaping font payload 합계는
  64 MiB로 제한한다.
- 모든 identity·geometry·cluster·resource budget 검증을 통과한 뒤에만 font resource를 등록하므로 reject가
  resource arena를 부분 변경하지 않는다.

## D4 activation 전 계약 충돌

D3는 Q2-B의 측정 계약을 그대로 표현하기 위해 glyph position·advance에 가로 장평 `r`을 반영하고 각 glyph에
`GlyphTransform(xx=r, yy=1)`을 보존했다. 이 payload는 의도적으로 현재 strict selector에서 선택되지 않는다.

- strict GlyphRun 선택기는 `glyph_transforms`가 있으면 `glyphTransformAuthorityPending`으로 거부한다.
- `PaintTextStyle::is_fill_only_glyph_replay()`도 `ratio != 1`을 거부한다.
- D3 diagnostics도 기하 품질은 `Exact`로 보존하되 `strict_visual_eligible=false`와
  `q2CommonShapingReplayAuthorityPending`으로 명시적으로 닫는다.
- 반면 #5821 이후 TextRun renderer는 압축 장평에서 glyph 크기 `fs×√r`, 추가 가로 scale `√r`을 사용해 총 폭
  `×r`과 세로 glyph 크기 `×√r`을 함께 재현한다.
- Q2-B measurement의 y scale은 아직 `fs / unitsPerEm`이므로 D3의 `xx=r, yy=1`을 그대로 제품 replay하면
  폭은 맞아도 #5821의 세로 조판 계약을 위반한다.

따라서 기존 D4 계획대로 단순 wiring해서는 안 된다. D4 전에 “측정 좌표가 최종 glyph outline 좌표까지 소유할지,
아니면 #5821 draw parameters가 최종 replay transform을 소유할지”를 하나로 정하고, 같은-boundary 공개 fixture의
오라클을 native·WASM에서 다시 잠그는 수정 계획과 메인테이너 승인이 필요하다. 이는 D3 실패가 아니라 activation
전 발견한 보호 불변식이다.
