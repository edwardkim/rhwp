# task_m100_4698_stage1 — 쪽 경계에 걸친 병합 셀의 조각 소유

이슈 #4698 이 보고한 "표 셀 글자 4자 누락"의 근본 원인을 한컴 정답지(`pdf/kps-ai-2022.pdf`)와
저장 `LINE_SEG` 실측으로 확정하고, 그 원인대로 `src/renderer/layout/table_layout.rs` 의 셀 조각
배분을 정정한 보고서다.

## 1. 보고된 현상

`samples/kps-ai.hwp` 66 번째 쪽(0-based 65)의 표 셀 문구 `3. 민간 소프트웨어 시장침해 가능성`
에서 **`시장침해` 4 자가 SVG 에 전혀 나오지 않는다**. `<text>` 요소 자체가 없다. 0.8.2 까지는
나오고 0.8.3 에서 처음 사라졌다.

앞선 조사(이슈 코멘트)는 원인 커밋을 `6d36bafa`(#3593·#3595 통합 수정)로 bisect 확정하고,
저장 `vpos` 가 `[0, 1920, 3840, 0, 1920]` 로 **되감기는** 것까지 밝혔으나, "양수 뒤의 0 = 조각
경계" 판별자가 #3595 의 42065 셀과 같은 모양이라 반증되며 멈춰 있었다.

## 2. 정답지 — 한컴은 이 셀을 쪽 경계에서 나눈다

```
$ pdftotext -f 65 -l 65 -layout pdf/kps-ai-2022.pdf -   # 쪽번호 - 62 -
3. 민간         주요기능과 동일·유사한 소프트웨어를 민간에서 판매를 위해 제공하는지 여부
소프트웨어                       □ 있음     □ 없음

$ pdftotext -f 66 -l 66 -layout pdf/kps-ai-2022.pdf -   # 쪽번호 - 63 -
 시장침해
  가능성        o
```

라벨은 **두 쪽에 걸쳐 나뉜다** — 앞 쪽이 `3. 민간 / 소프트웨어`, 뒤 쪽이 `시장침해 / 가능성`.
0.8.2 도 정답이 아니었다. 0.8.2 는 되감긴 앵커로 뒤 두 줄을 앞 조각의 y(954.3/979.9)에 그려
앞 두 줄과 **겹쳐** 놓았을 뿐이다. 글자는 보였지만 그림은 틀렸다.

## 3. 근본 원인 — 기하만 나누고 내용은 나누지 않았다

셀[39](r=18, rs=6, 전체 높이 256.8px)의 조각별 계측:

| | 우리 렌더 (수정 전) | 한컴 |
| --- | --- | --- |
| p65 조각 (h=83.3px) | 문단 **5 개 전부** 배치 → 하단 1033.8 초과분 clip | `3. 민간 / 소프트웨어` |
| p66 조각 (h=173.5px) | **텍스트 0 건 (빈 셀)** | `시장침해 / 가능성` |

두 갈래가 겹쳐 4 자가 어느 쪽에도 남지 않았다.

1. **앞 조각** — `layout_partial_table` 이 조각 높이만 잘라 주고 셀 문단은 전부 넘긴다.
   `시장침해`(1031.1~1047.1)가 조각 하단을 걸쳐 Cell clip 에 먹힌다.
2. **뒤 조각** — `table_layout.rs` 의 **[Task #1073]** 분기가
   "rowspan 셀이 분할 시작 행보다 먼저 시작하면 라벨은 앞 쪽에 이미 렌더됨" 이라는 가정으로
   `composed_paras.clear()` 를 건다. 그 가정은 라벨이 앞 조각에 **다 들어갔을 때만** 참이다.

`6d36bafa` 는 원인이 아니라 **은폐를 걷어낸 커밋**이다. 그 전에는 되감기 앵커가 초과 문단을
조각 안으로 되돌려 놓아(겹친 채) 소실이 드러나지 않았다.

## 4. 판별자 — 저장 `vpos` 재시작이 곧 조각 경계다

앞선 조사가 반증했다고 본 신호가 사실은 정답이었다. 반증의 전제는 "저장 패턴만으로 가른다"
였는데, 필요한 두 번째 축은 **이 셀이 실제로 조각으로 나뉘는가**다.

| 조건 | kps-ai 셀[39] | 42065 셀[20]·셀[7] |
| --- | --- | --- |
| 저장 vpos 재시작 | 있음 | 있음 |
| `row_filter` 분할 + `rowspan > 1` 병합 셀이 경계에 걸침 | **예** | 아니오 (1×1 scalar 경로) |

`LINE_SEG.tag` 의 `페이지의 첫 줄`(bit 0) 은 이 문서에서 전 줄이 `0x00060000` 으로 저장돼
있어 신호가 되지 못한다(실측). 쓸 수 있는 신호는 vpos 재시작 + 조각 문맥이다.

## 5. 수정

`layout_partial_table` 의 셀 루프에서, 조각에 걸친 병합 라벨 셀에 한해 저장 조각 그대로 문단을
배분하고 그 조각만 담은 셀을 아래로 넘긴다.

- `stored_cell_fragment_groups()` — 둘째 이후 문단의 첫 `LINE_SEG.vpos == 0` 을 조각 경계로 보고
  문단을 묶는다.
- `stored_fragment_extent_hu()` — 조각의 저장 높이(`vpos + line_height` 최댓값).
- 적용 조건: `row_filter` 분할 · `rowspan > 1` · 셀이 실제로 필터 경계에 걸침 · 조각 2 개 이상 ·
  **모든 조각의 extent > 0**(마지막 조건이 "전부 vpos=0" 센티널 셀 #3593 을 배제한다).
- 이 조각이 받을 범위는 앞 쪽들이 이미 소비한 셀 높이(`cell_y - raw_cell_y`)만큼 조각을 건너뛴
  뒤, 조각 높이(`cell_h`)에 들어가는 만큼 고른다.
- 조각을 골라 넘긴 셀은 [#1073] 공란화 대상에서 제외한다 — 비우면 그 문단이 어느 쪽에도 없다.

부수 효과로 판별자 문제 자체가 사라진다. 조각으로 자른 슬라이스 안에는 vpos 재시작이 없으므로
`local_vpos_restart_seen` 게이트가 발화하지 않고 저장 앵커가 자연히 유효해진다.
