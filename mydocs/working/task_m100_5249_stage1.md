- 이슈: [#5249](https://github.com/edwardkim/rhwp/issues/5249) (원인 조사 원천 [#2768](https://github.com/edwardkim/rhwp/issues/2768))

## 1. 조사 설계

#2768 은 482구역에서 **바탕쪽이 없는데 47인 구역 259개**를 제시하고 판단을 요청했다.
그러므로 이 조사의 물음은 하나다 — **바탕쪽이 아니면 무엇이 38과 47을 가르는가.**

이슈의 조사 축(SectionDef flags·바탕쪽·머리말/꼬리말·쪽 번호·다단·호환 설정·tail 비영
필드)을 한 표에 같이 실어 상관을 한 번에 본다. 표본은 `samples/**/*.hwp` 전수다.

**출처 분리를 먼저 했다.** 코퍼스에는 rhwp 자신이 변환해 만든 산출물이 섞여 있고
(`RhwpHwpxOrigin` 스트림이 표식), 그것은 한컴 계약의 증거가 아니라 **현재 동작의 기록**이다.
이 분리를 하지 않으면 결론이 자기 출력으로 오염된다.

## 2. 실측 (한컴 저작 517구역 / rhwp 산출 3구역)

### 2.1 저장 버전이 tail 을 정한다

```
한컴 저작: 저장 버전대 × secd 크기
  < 5.0.4.0  secd  36 byte : 4
  < 5.0.4.0  secd  38 byte : 188
  >= 5.0.4.0 secd  47 byte : 325
```

버전별로 풀면 **한 버전이 정확히 한 크기**를 갖는다. 예외가 없다.

| 저장 버전 | 구역 | secd |
|---|---:|---|
| 5.0.1.7 | 4 | 36 |
| 5.0.2.4 · 5.0.2.5 | 5 | 38 |
| 5.0.3.0 ~ 5.0.3.4 | 183 | 38 |
| 5.0.4.0 · 5.0.5.0 | 45 | 47 |
| 5.1.0.0 ~ 5.1.1.0 | 280 | 47 |

### 2.2 바탕쪽 게이트는 양방향으로 어긋난다

```
  바탕쪽 0 인데 47 byte : 284
  바탕쪽 있는데 38 byte : 10
```

어댑터 게이트(`master_pages.is_empty()`)라면 앞쪽 284구역에 38을, 뒤쪽 10구역에 47을
냈을 자리다. #2768 의 "바탕쪽 없는 47 259건"은 **버전 축의 그림자**였다.

### 2.3 반례 3건이 각각 설명된다 (이슈 구현 원칙)

| 파일 | 저장 버전 | 바탕쪽 | secd | 규칙으로 설명되는가 |
|---|---|---:|---:|---|
| `samples/math-001.hwp` | 5.1.0.1 | 0 | 47 | ✅ ≥5.0.4.0 이므로 47. 바탕쪽 0 은 무관 |
| `samples/aift.hwp` | 5.1.1.0 | 0·1·50 | 47 | ✅ 세 구역 모두 ≥5.0.4.0 |
| `samples/table-001.hwp` | 5.0.3.0 | 0 | 38 | ✅ <5.0.4.0 이므로 38 |

### 2.4 v5.1.0.0 이 갈리는 것처럼 보이던 이유

버전만 보면 5.1.0.0 에서 38 이 3구역 나온다. 그 3구역은 전부 **rhwp 산출물**이다 —
`issue2439_zero_offset_coanchored_float_exclusion.hwp`,
`issue4514/sample1-repro.hwp`, `issue5447/묶은세로막대형-행추가-HWPX에서변환.hwp` 셋 다
`RhwpHwpxOrigin` 스트림을 갖는다. 즉 **결함의 증거이지 반례가 아니다.**

같은 5.1.0.0 의 한컴 저작본(`samples/hwpx/hancom-hwp/[2027] 온새미로 1 본교재.hwp`,
5구역)은 전부 47 이다.

### 2.5 tail 내용 (부수 관측)

47 byte tail 325구역 중 **311구역이 전부 0**이다. 비영은 14구역뿐이고 확장 영역 offset 0
또는 offset 4 의 u16 이 1·2·4 를 갖는다. 이 값은 **바탕쪽 수의 함수가 아니다** —
`exam_math`(바탕쪽 1)는 1, `exam_science`(바탕쪽 1)는 4, `exam_social`(바탕쪽 1)은 0 이다.

## 3. 결론 — 두 기존 계약의 처리

| 계약 | 판정 | 근거 |
|---|---|---|
| 어댑터의 바탕쪽 게이트 | **폐기** | 양방향 반증 284 + 10 |
| 직렬화기 #1058 의 "정답지 = 38" | **범위 축소 후 유지** | 5.0.4.0 **미만**에서만 참. 그 아래에서는 188/188 정확 |
| (새로 확정) 버전 게이트 | **채택** | 한컴 저작 517/517, 예외 0 |

`#1058` 주석의 정답지는 5.0.3.x 파일이었을 것이다 — 그 시절 계약으로는 옳았고, 파일 형식이
5.0.4.0 에서 확장 영역을 8 → 17 byte 로 늘리면서 어긋난 것이다.

## 4. 적용 범위와 미해결

- 적용은 **HWPX→HWP 합성 경로에만** 한다(이슈 목표 4). HWP5 원본에서 파싱한
  `raw_ctrl_extra` 는 손대지 않는다(목표 5).
- 버전 경계의 관측 범위는 **(5.0.3.4, 5.0.4.0]** 이다. 그 사이 버전은 코퍼스에 없다.
  미관측 구간은 보수적으로 구 계약(10 byte)으로 떨어진다.
- **미해결**: 확장 영역의 비영 u16(14/325). 결정 요인을 못 찾았으므로 종전 정답지에서
  유도된 규칙(`master_pages.len() >= 3` → offset 0 에 1)을 **넓히지도 좁히지도 않고**
  그대로 뒀다. 넓히면 311구역의 0 을 깨고, 지우면 exam 계열 정답지와 멀어진다.
- 36 byte(5.0.1.7, 8 byte tail)는 관측만 하고 합성 대상으로 삼지 않았다 — HWPX 출처는
  그 버전으로 저장되지 않는다.
