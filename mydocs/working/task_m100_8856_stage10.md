# #8856 HFT 글머리표의 원본 전진 보존

stage9의 실제 Print 평면 보정과 검증을 `019f43cac0`로 커밋한 뒤 시작한다.
원 PR #8642는 각주 앞 조각/표 높이의 후속 보정이다. 원 head는 `7d40345bc0`이며 #8857에서 실제 통합한 뒤 닫혔다. report-628 잔여 중
110쪽 표의 글머리표 뒤 본문이 앞당겨지는 원인은 각주 높이나 그림 효과와 별개다.

같은 원본 Section3/문단587/표0/셀2·3의 U+2022는 기호 슬롯의 한양신명조 HFT다.
실제 font decision trace는 원본 프로그램 표 `한양신명조 (HFT)`의 문자 결측 뒤
`heuristicHalfwidth`로 내려간다. source glyph의 미수집과 원본 글자의 반각 계약은 다르다.
기존 `HanyangSinMyeongJo` 보충표에는 같은 문자의 전각 계약이 있으나, 원본 HFT 프로그램을
별도 표로 선택하면 그 값이 연결되지 않는다. 단순히 표시 대체 글꼴의 자연 폭을 쓰지 않는다.

독립 한컴 Print110쪽의 실제 내용 연산은 bullet 원점893, 후속 본문975이며 0.12배·96/72
변환 뒤 전진13.12px다. 같은 줄 원본1100HU·장평90%의 장치 전진과 일치한다.
현재 공통 레이아웃은6.56px로 줄인다. PDF의 paint 자원은 Gulim descriptor·U+2022의
0.375em 폭을 갖지만 후속 본문 원점을 그 자연 폭으로 정하지 않는다. PDF의 `/HCI Poppy`
이름에는 escape되지 않은 공백도 있어 그 이름만으로 실제 프로그램을 주장하지 않는다.
원본 PDF는 변경하지 않고 정본 PDFium 비교를 유지한다.

원본 HFT 측정 표의 확인된 U+2022 전진만 복원한다. 생산 지점은 원본 프로그램의 부분 폭 표,
소비 지점은 공통 char_width_decision → 확정 run/cluster → PaintOp/각 backend다.
문서·쪽 분기나 paint에서 별도의 문자 이동을 추가하지 않는다. TTF 원본 기호의 자연 폭·
표의 padding/행 높이·각주·다른 글자의 전진은 유지한다.
같은 원본 HFT 기호 표에 제곱근을 연결한 선행 보정 `5f5a3488c1`도 같은 생산·소비 경로다.

새 관계 검사는 실제 원본22개 bullet의 원본 글자 크기 대비 전진과 좌우 셀 소속을 확인한다.
기존 #8315의 TTF 기호 슬롯 검사와 원본 프로그램 소유 검사도 반례로 검증한다.
수정 전 관계 검사1 FAIL → 수정 후1 PASS를 실제 확인했다.
같은 최소 글꼴·독립 PDF 조건으로 Native/fresh WASM 전195쪽을 완료했다.
110쪽은93.35921%/93.37018%에서99.79423%/99.79424%로 개선됐고, 각194쪽의 PNG는
stage4 같은 조건의 이력과 바이트가 같다. 문서 최저는 기존1쪽94.83952%/94.84611%다.
기존 정상 대조23건도 통과했다. 원본 글꼴 공급의 별도110쪽 대조는99.98846%/99.98845%다.
두 조건을 섞거나 원래 최소 글꼴 전쪽 조건을 교체하지 않는다.
완료110쪽의 핵심 원점을 독립±2CSSpx로 보호하는 고정형도 실제 통과해 최종 새2 PASS다.
첫 좌표 검사 시도의 비공개 API 컴파일 오류는 제외했고 공개 API로 바로잡았다.
Native/WASM Clippy·fmt·suite manifest·unit tier 및 실제 초기 JS/WASM 응답도 확인했다.
다른 글리프 잔여와 최종 제출 전체 게이트는 아직 완료하지 않았다.
