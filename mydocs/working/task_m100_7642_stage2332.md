## 계보와 실제 데이터의 분리 진단

XML·그림은 유지하고 private HWP3 marker만 제거한 별도 대조군도 Print했다.
job ec45587b-e16e-43d1-8782-6d3b9ef93c01은 같은 method0/64쪽이다.
그러나 Native는65쪽으로 갈라져 marker를 지우는 것만으로 해결되지 않는다.
원래 marker1 산출물과 제거 대조군은 각각 실패 상태로 보존했다.

원본 문단610은 자연 쪽 경계에서 승격한 Page이고 저장 줄은 vpos852다.
왕복본의 같은 문단은 XML pageBreak0이며 Page 소속이 없다. 저장 줄의
9개 값은 같다. serializer는 합성 자연 쪽나눔을 실제 pageBreak로 쓰지 않는
기존 계약을 지킨다(다른 긴 문서의 빈 쪽 증가를 방지). 반면 native HWP3
계보만 유지하고 원래 자연 쪽 소유를 전달하지 못하는지는 추가 진단 중이다.

stage2333에서는 원본의 Page 소유62개 중 XML에서 생략된 항목만 되살린
별도 counter를 만들었다. 이를 정식 serializer 수정이나 독립 Print 통과로
보고하지 않는다. 원인이 맞는지 확인하고, 맞더라도 합성 나눔을 무조건 실제
pageBreak로 저장하는 회귀를 다시 만들지 않는 일반 계약으로 해결해야 한다.
원본과 대조군의 SHA·변경 항목·진단 출력을 ignored output에 보존한다.

## 경계 분리 대조의 실제 결과

stage2334 counter의 Native 실행이 끝났다. 전체64쪽을 유지하며37쪽은
45.47572→99.98906%로 바뀌었다. 따라서 이 쪽의 제목/표 소유 차이는 자연
쪽 시작 정보의 소실과 인과관계가 있음을 확인했다. 그러나 전체 최저는
63.06601%이고1·3·5·18·19·20·39쪽7개는 여전히90% 미만이다.
자연 경계만으로 모든 차이를 설명하지 않으며 나머지 원인을 묶어 분석한다.

이것은 진단 목적으로 XML pageBreak를 바꾼 counter와 원래 Print의 비교다.
같은 원본의 독립 Print 검증이나 새 정상 fixture의 근거로 사용하지 않는다.
실제 serializer·parser·renderer 코드는 아직 바꾸지 않았다. 이 수치만으로
합성 나눔의 일괄 저장을 구현하지 않으며, 정상 문서에서 빈 쪽이 생기는
반례와 실제 소비 경로를 함께 확인한 뒤 보정 방식을 판단한다.
