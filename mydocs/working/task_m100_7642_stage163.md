# #7642 Stage 163 — TAC pen 원점과 각주 예약의 공통 결과

Issue: #7642

## 구현 전 근거와 수정 범위

Stage 162 원본 그림 문서 4쪽은 Native 97.54161 → 82.97181%로 회귀했다.
`layout.rs`의 TAC metadata 소비는 `placement.y`를 바깥 여백 전 pen으로
받아 위 여백을 한 번 더한다. 새 helper가 테두리 원점을 전달해 pi45 표가
768.9에서 772.1로 밀렸다. 그 helper의 y를 실제 pen으로 바꿔 기존 소비
계약과 일치시키며 정확한 미래 그림·표 위치 관계 검사를 유지한다.

PrEP 68쪽은 본문 원점 767.56px와 paint 상대 원점 767.5px가 일치한다.
각주 실제 영역은 65.2px지만 typeset 예약은 59.1667px다. 각주 paint의
구분선/글줄은 Print와 거의 일치한다: 구분선 Native 966.4 / Print 965.98,
첫 각주 글줄 Native 974.7 / Print 975.2. 본문의 추가 줄이 실제 영역의
상단에 걸친다. producer는 `register_body_footnote`가 저장 줄 높이만 합산한
`estimate_footnote_note_height`를 쓰는 분기이고, paint는 스타일을 포함해
`footnote_paragraphs_content_height`의 공통 줄 구성·간격을 소비한다.

실제 배치의 각주 내용 높이 조회를 본문 예약에서도 소비하도록 연결한다.
블록 표의 기존 별도 소유 판정과 저장 각주 조각 경계는 유지한다. 독립 PDF의
각주 글자 위치를 바꾸거나 상수 여백을 늘려 다음 쪽으로 보내지 않는다.
본문 예약 → 같은 각주 내용 메트릭 → 기존 구분선/각주 사이 간격 → 본문 예산
→ 실제 FootnoteArea 및 다음 쪽의 문단·표 소유를 대조한다.

## 검증 계획

Native의 다중 그림·원본 그림 전체 11쪽씩과 PrEP 영향 67~70쪽, 독립 재저장
표를 우선 대조한다. 20개 기존 #6812 검사를 변경 없이 재실행한다. PrEP는
전체 140쪽 및 각주·표 분할 관계를 확인하고 fresh WASM을 새 source로 빌드한다.
90%와 확대 판독을 충족하기 전에는 기대값·golden 변경이나 새 회귀를 추가하지 않는다.
