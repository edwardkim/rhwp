# 단계 1030 HWP3의 줄별 들여쓰기 속성 정규화

Issue: #7642.

## 원인과 독립 근거

기준 `upstream/devel`은 fetch 후에도 `a5e88ad682c805e1d845502ddc9521b94ea8eccd`로 같고 현재 HEAD에 포함되어 있어 리베이스를 반복하지 않았다. 현재 생산 코드 `c0bc7d9e9`의 HWP3 sample16 40쪽에서 본문 후속 줄이 독립 Print보다 약 33.36px 왼쪽에서 시작한다. 같은 위치의 제목 문단은 약 0.08px 차이다. 글꼴 폭의 전역 보정으로 설명할 수 없는 문단별 차이다.

원본 `samples/hwp3-sample16.hwp`와 한컴 저장본 `samples/hwp3-sample16-hwp5.hwp`의 문단 633은 공통 IR의 여백·내어쓰기·줄 시작·폭이 같다. 다만 HWP3의 모든 줄은 tag=0x60000이고, 한컴 저장본은 첫 줄 0x60000, 후속 줄 0x160000이다. HWP3 사양의 문단 모양은 부호 있는 들여쓰기를 저장하며 HWP5의 줄별 tag는 저장하지 않는다. 파서가 합성한 tag에서 들여쓰기 의미를 누락했다. 독립 Print는 `pdf/issue7642-hwp3-original-print/hwp3-sample16-2020.pdf`이며 내용과 쪽수는 기존 기준을 유지한다. 실제 dump와 줄 원점 대조는 ignored 단계 1029에 있다.

## 생산과 소비 경로 및 수정 범위

HWP3 문단 모양의 부호 있는 들여쓰기 → 파서의 공통 ParaShape와 LineSeg → composer의 저장 줄 → `paragraph_line_indent_for_source`의 줄별 플래그 해석 → 실제 `layout_paragraph_in_frame`의 줄 원점·가용 폭이다. 소비자는 저장 tag의 부재를 들여쓰기 금지로 해석한다. 파서에서 첫 줄의 양수 들여쓰기와 후속 줄의 음수 내어쓰기를 공통 tag로 표현한다. 폭·원점·글꼴을 임의로 바꾸지 않으며 렌더러에 HWP3 분기를 추가하지 않는다.

합성 parser 계약으로 양수·음수·0과 여러 저장 줄/저장 줄 없는 재구성 줄을 확인한다. 원본 텍스트·줄 순서·기존 단일 줄 플래그를 보존한다. 수정 전 실패와 수정 후 통과를 실행하고 관련 HWP3·저장 들여쓰기 대조군을 함께 검사한다. 실물은 새 Native/fresh WASM 전체 64쪽 TSV와 40쪽 확대 판독으로 확인한다. 전체 90% 미달 상태에서는 실물 배치 회귀·golden의 추가나 기대값 변경을 하지 않는다. 진행 중인 55개 문서 검증은 고정한 기존 생산 산출물의 결과로 보존하고 새 코드 결과와 구분한다.

## 공간 정리

사용자가 승인한 target 정리 범위에서 실행 중인 Cargo/Rust 작업이 없음을 확인하고, 2026-10-15 10:00 KST 이전에 종료된 정확한 `target/pr-review/debug/incremental/rhwp-*` 13개만 제거했다. 약 10.47GiB를 확보했다. 공유 target 자체·deps·fingerprint·실행 산출물·입력·독립 PDF·현재 시각 증거는 보존했다. 목록과 시각·크기는 ignored `output/pr-review/issue7642/target-cleanup-20261015-second.json`에 있다. 파일 시스템 예약 설정은 바꾸지 않았다.

## 실제 검증 결과

수정 커밋은 `838834c6c58c411c3303b1d57fbeaf170b0c7a0b`이다. 단계 1031에서 수정 전 `c0bc7d9e9`에 새 합성 parser 계약만 적용해 실행한 결과, 음수 들여쓰기의 두 번째 줄에서 실제 false/기대 true로 실패했다. 단계 1032의 수정 후에는 양수·음수·0 및 저장 줄 유무 대조군이 통과했다. 기존 HWP5 저장 플래그, HWP3 표·수식·탭·줄 높이·제본 여백 대조군을 묶어 **25건 실행, 25건 통과**했다. 공유 target에서 빌드 잡 8개와 테스트 스레드 12개를 사용했고 fmt 검사도 통과했다. 이 결과는 전체 회귀 또는 lint 완료가 아니다.

단계 1034에서 같은 원본·독립 Print로 전체 64쪽 Native TSV를 재산출했다. 입력 SHA-256은 `559fd94860cf836d5800436d56055c23a73e59eedef3da273a5ba365e6ed9e16`, PDF는 `f1f2e6dd265d098ea468bae14b44e98a1609dd7eba293f91d73ba16704be73c5`다. 명령은 같은 단계의 ignored JSON에 원문으로 보존했다. 96dpi, Print 프로필, compat 2022, 시스템 글꼴 네 경로를 그대로 사용했다.

단계 1035는 **직전 생산 코드 c0bc7d9e9와 이번 수정의 비교**다. Decimal로 64쪽을 대조해 0.01%p 이상 하락한 쪽은 0개였다. 이를 upstream/devel 대비 최종 무회귀 판정으로 바꾸어 보고하지 않는다. 단계 1034·1036의 새 review 2·6·19·35·40쪽을 직접 열었다. 2쪽 하단의 별첨 기호·간격과 40쪽 일부 영문·제목 간격도 남아 있어, 98% 점수만으로 px 회귀 추가나 시각 완료를 선언하지 않는다. TSV의 exit 1은 미달 페이지에 따른 재검토 gate이며 측정 누락은 아니다.

Native 55개 문서 대기열은 기존 `c0bc7d9e9` 생산 바이너리를 고정해 계속한다. 단계 1037에서 입력 magic과 SHA를 확인한 결과 HWP5 34개·HWPX 21개이고 HWP3는 없다. 그 생산 코드 이후의 라이브러리 변경은 HWP3 parser 두 파일뿐이다. 기존 결과를 새 HEAD의 재출력이라고 이름만 바꾸지 않는다. 개발 WASM은 수식이 많은 두 문서에서 Puppeteer의 180초 실행 제한에 걸려 실패 증거를 보존하고 대기열을 중단했다. 마지막 실행 중 문서는 전체 TSV 산출을 마쳤으나 부모 중단 후 exit code를 관측하지 못했으므로 별도로 표시했다. 단계 1033의 새 release WASM을 빌드한 뒤 전체 대조와 최종 판정을 계속한다.
