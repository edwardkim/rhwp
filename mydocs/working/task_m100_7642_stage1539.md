# Issue #7642: 저장 줄의 공백 메트릭 변경과 PrEP 재조판

## 독립 근거와 수정 범위

부모는 `6b5c9738888911e7f0f0d0e5fea81ab8bc21d993`이고 고정 devel은
`2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`다. 원본 PrEP는
`samples/issue2006/1790387_prep_final_report.hwpx`이며 SHA-256은
`c68baed24096386f9041930d24d39409b61ac99463bf04dfd242440dfdeb739f`다.
원본의 한컴 2024 Print는 140쪽이고 67쪽 해당 문단은 네 줄이다.
원본 저장 캐시는 다섯 줄이며, 내용을 바꾸지 않은 한컴 HWP 저장본에도 같은 캐시가 남는다.
따라서 저장했다는 사실만으로 캐시를 최종 Print의 정답으로 삼지 않는다.

ignored 단계 1536의 진단 입력은 해당 문단의 LineSeg 배열만 제거했다.
원본과 진단 입력의 한컴 2024 Print 67·68쪽은 96dpi RGB와 추출 글자 기하가 같다.
실제 job·입력/PDF 해시는 `stage1536-prep-cache-diagnostic.json`, 비교는
`stage1536-prep-cache-print-comparison.json`에 있다. 진단본을 원본 검증으로 바꾸지 않는다.

## 생산 값과 소비 경로

`stored_cell_reflow.inc.rs`의 기존 그림 포함 양쪽 정렬 프레임은 재조판 시
`KoPubJustified` 공백 메트릭을 사용한다. 원본 저장 run의 기본 공백과 다르며,
단계 1535에서 같은 저장 줄의 자연 폭과 해당 공백 적용 폭이 서로 다름을 확인했다.
일반 본문 전체의 어절 꼬리 재검토를 막은 `f6d04ffba`는 이 메트릭 변경 경로도 막았다.
그 결과 67쪽의 마지막 `음` 한 글자가 다섯 번째 줄에 남고 다음 문단의 한 줄이
68쪽으로 넘어가 차트와 후속 표까지 밀렸다.

현재 프레임이 선택한 공백 전진이 저장 run과 실제로 다를 때에 한해서 기존 어절 꼬리
재검토를 허용한다. 그림의 존재나 새 글꼴명 조건만으로 캐시를 거절하지 않는다.
명시적 개행·다른 쪽/단·어울림·원문 편집·원본 HWP3의 기존 가드는 유지한다.
줄 수만 적어지는 같은 메트릭의 정상 본문은 그대로 보존한다.

공통 결과는 `stale 판정 → Frame resolver 채움 → Reflowed 줄/공백 기하 게시 →
측정과 실제 본문 배치`로 전달한다. 별도 paint 좌표 보정이나 줄 숨김은 추가하지 않는다.

## 검증 계획과 미완료 범위

원본 PrEP의 27·67~70쪽과 전 140쪽을 먼저 Native로 확인한다.
언어 기출 문단 177의 독립 Print 열 줄, 기존 셀 경로와 검증된 inline 원본들을
대조군으로 함께 확인한다. 같은 생산 소스의 fresh WASM·전쪽 TSV·직접 판독 전에는
PrEP 회귀 기대값을 바꾸거나 새 렌더링 회귀를 추가하지 않는다.
원래 71행 전수 결과와 devel 대비 하락은 별도이며 이 수정만으로 완료라고 하지 않는다.

## 병행한 전수 측정과 글꼴 진단

수정 전 생산 코드 `63a1c13b2`의 fresh WASM 전수 측정도 종료됐다.
`stage1500-current-wasm-scope/receipt.json`의 71행·1110쪽은 전체 쪽수가 일치하고
최저 91.14522%, 90% 미만·누락이 없다. Native 전수 최저는 90.71006%다.
이 자료를 이번 공백 보정의 새 head 측정으로 바꾸어 기록하지 않는다.

비교했으며 Native 59건·WASM 40건이 고정 devel보다 0.01%p 이상 낮다.
나머지 네 행은 base 쪽수 불일치로 비교 불가다. 전체 PR gate는 아직 보류다.

단계 1534·1537의 동일 배치 글꼴 실험에서 `HY견고딕`이나 별도 공급한
`HYSinMyeongJo-Medium`은 exam_kor 14쪽 하락을 해결하지 못했다.
후자는 Windows의 설치 파일을 ignored 진단 경로로만 읽어왔고 시스템 등록이나
Git 추가를 하지 않았다. 두 실험 모두 실제 PNG를 비교했으며 기본 PNG의 RGB가
기존 Native 전수 출력과 같은 것을 확인했다. 조회 결과만으로 글꼴 원인 해결을
주장하거나 원본 글자 높이를 이전의 장평 종속 값으로 되돌리지 않았다.
