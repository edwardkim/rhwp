## 실행 순서

1. 원본 파일·기준 PDF·관련 PR·정정 코멘트를 대조한다.
2. 현재 소스의 focused 계약과 대표 페이지를 재검증한다. 기존 PDF를 우선 재사용하고,
   실제 저장 버전과 변환 엔진의 출처를 구분한다.
3. 이미 해결된 건은 개별 근거 PR, 현재 SHA, 실행 결과를 코멘트한 뒤 닫는다.
4. 미해결 건은 원인별 다음 stage 문서를 작성하고, 수정·회귀 테스트를 이슈별 커밋으로 나눈다.
5. 변경 범위의 로컬 검증을 완료한 뒤 하나의 PR을 생성한다. PR 번호 확정 후 self-review와
   오늘할일을 같은 브랜치의 trailing commit에 넣는다.

## 증빙과 작업 경계

- 로그, 중간 SVG/PNG/JSON은 임시 작업 경로에서만 사용하고 커밋하지 않는다.
- 최종 코멘트에 실제 삽입할 대표 비교 PNG만 `mydocs/pr/assets/`에 보관한다.
- 현재 공유 `target/pr-review`를 재사용한다. 남은 디스크가 약 2.8GB이므로 Cargo 실행은
  순차 수행하고 공간을 계속 확인한다. 다른 작업의 산출물은 임의로 삭제하지 않는다.
- 종료되지 않은 이슈는 종료하지 않고, 증상·완료 조건의 미달 항목을 정확하게 기록한다.
