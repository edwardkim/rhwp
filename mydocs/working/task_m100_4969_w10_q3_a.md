# Task M100 #4969 W10-Q3-A — canonical variable instance red 계약 결과

- **결과 상태**: `qualified-red` 승인
- **승인일**: 2026-08-29 KST

## 판정

Q3-A는 **qualified-red**다. 제품 source를 바꾸지 않고 기존 Q1 request 계약과 Q2 shadow transaction 원본에
variable instance 계약을 추가했다. baseline 21건은 모두 통과했고, 신규 계약은 수정 수행계획이 지목한 네 계보
단절에서만 실패했다.

1. explicit `wght=400, opsz=400`과 빈 vector가 서로 다른 settings identity다.
2. 위 기본 좌표를 canonical vector에서 제거하더라도 현행 raw-request/canonical-vector empty 검사까지 함께
   고치지 않으면 explicit default shaping이 malformed로 닫힐 후속 위험이 있다.
3. 하나의 mutable rustybuzz face에서 Title 뒤 default, `wght`-only 뒤 `opsz`-only를 실행하면 생략 축에 이전
   coordinate가 남는다.
4. Q2 `HorizontalShapingRequest`에는 variation vector를 운반할 field가 없다.

따라서 Q3-B는 단순히 transaction field를 추가해서는 안 된다. `fvar` default 기반 canonicalization, canonical
identity와 raw request의 적용 경계, instance-local mutable face owner, variation-qualified cache key를 하나의
dormant measurement 절편으로 처리해야 한다. 기계 판독 결과는
[`w10_q3_a_red_contract.json`](../tech/investigations/issue-4969/w10_q3_a_red_contract.json)에 고정한다.

## standalone canonical·face red

`issue_4969_shaping_request_contract`에는 기존 source를 유지한 채 Q3-A test 네 건을 추가했다. 결과는 16건 중
기존 12건 통과, 신규 4건 실패다.

| red 계약 | 현재 관측 | 목표 |
| --- | --- | --- |
| empty = explicit/partial defaults | explicit default hash `a7b271…`, empty hash `adc926…` | canonical identity·vector 동일 |
| explicit defaults shaping | glyph는 같지만 identity가 다름 | disposition·identity·glyph 전부 empty와 동일 |
| Title → default | 첫 Latin advance `598`, fresh default `579` | 모든 glyph record가 fresh default와 동일 |
| `wght=650` → `opsz=650` | 첫 Latin advance `585`, fresh optical-only `579` | 생략 `wght`가 400으로 복원된 결과와 동일 |

현재 `rustybuzz::Face::set_variations()`는 전달된 축만 설정한다. `set_variations(&[])`는 앞선 900/900을 지우지
않았고, `opsz=650`만 설정해도 앞선 `wght=650`이 남았다. 이는 추정 위험이 아니라 실제 advance 차이로
재현됐다.

기존 malformed·unsupported·bounded 계약에는 Infinity와 3-byte malformed axis tag를 보강했다. duplicate,
NaN/Infinity, malformed, unknown, out-of-range, 17-axis는 모두 기존 structured reason으로 통과했다. 옛한글
glyph·cluster·advance oracle도 그대로 통과했다.

## Q2 request·cache compile red

Q2 shadow source에는 Happiness Sans exact source와 다음 행동 계약을 추가했다.

- 빈 vector와 explicit defaults는 같은 measurement `Arc`와 cache entry를 사용한다.
- Title은 별도 measurement·instance face를 사용하고 default와 advance가 달라야 한다.
- 결과 cache는 두 effective instance만 보존해야 한다.

현행 제품 source를 바꾸지 않았으므로 target은 다음 compile-time red에서 멈췄다.

```text
error[E0609]: no field `variations` on type `HorizontalShapingRequest<'_>`
  --> tests/cases/issue_4969_shaping_shadow_context.rs
```

이 실패는 public API를 미리 확정하지 않는다. crate-private Q2 transaction이 canonical instance를 받을 내부 seam이
없다는 사실만 고정한다. HWP/HWPX parser·font name·bold·장평에서 axis를 추론하는 caller는 추가하지 않았다.

## Q3-B 입력과 승인 경계

Q3-B는 다음 순서만 연다.

1. exact face `fvar` model에서 default coordinate를 제거한 canonical non-default vector를 만든다.
2. raw request가 non-empty인지가 아니라 canonical effective vector를 shaping 적용 권위로 삼는다.
3. `HorizontalShapingRequest`와 result cache key에 canonical instance를 연결한다.
4. mutable face를 `(source handle, canonical effective instance)`별로 격리한다.
5. native·Node WASM 공개 matrix와 1/2/8 instance/run counter를 dormant measurement에서 검증한다.

Q3-A 결과는 승인됐다. checkpoint commit과 Q3-B 시작, remote push·PR·GitHub comment는 각각 별도 승인 경계를
유지한다.
