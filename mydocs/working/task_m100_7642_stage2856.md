## HFT 식별에서 확인한 차이

언어 문서 15쪽의 public font trace는 원본 `신명 중명조` 1,720자를
표시용 `HY신명조`로 해소했다. HWP FACE_NAME 원 레코드도 HFT 종류와
원 이름을 확인했다. 표시 이름만으로 원 프로그램을 선택하면 서로 다른
HFT face를 합칠 수 있으므로 원본·표시 이름을 구분해야 한다.

기본 한양신명조 독립 전체 표본의 Print/CFF는 이 본문과 일치하지 않았다.
잘못된 프로그램을 원 글꼴로 공급하지 않았다. 별도로 HY신명조를 요청한
표본은 Type3 한글이 0개라 복원기가 거부했다. 이름을 바꿔 같은 원본으로
주장하거나 해당 거부를 시각 통과로 처리하지 않았다.

요청 face를 명시하도록 표본 도구를 일반화하고 기존 기본 face의 이름과
식별자는 유지했다. 생성·복원·provenance에 같은 요청 face를 기록한다.
관련 단위 검사는 12개 모두 통과했다. 전체 알파벳·행렬·원 좌표 보존과
일반 문서 PDF 거부 조건을 유지하며, 프로그램 동일성 자체는 별도로
확인한다. 이것은 렌더링 golden의 추가·완화가 아니다.

`신명 중명조` 독립 11,172자 표본을 실제 한컴 Print로 출력해 복원했다.
대상 15쪽의 Type3 세 subset에서 윤곽과 전진폭이 각각 255/255,
239/239, 128/128 일치했다. 대상 PDF에서 글꼴을 만들지 않고 별도
전체 표본으로 만든 프로그램을 읽기 전용으로 대조한 결과다.
확인하지 않은 견명조·다른 HFT까지 같은 프로그램이라고 확대하지 않는다.

MCP는 문서화된 client의 `start → status → download`, engine 2020,
PrintMethod 0, `hancom2020_pdf_driver_one_up`을 사용했다. 실제 제품은
11.0.0.9136이다. 해당 표본 job과 해시는 ignored stage2847~2854에
기록했고, 글꼴과 표본 PDF는 저장소 밖 `rhwp-local-reference`에만 둔다.
비밀 endpoint/token은 출력하거나 기록하지 않았다.

## 다음 구현의 경계와 미완료

원본 HFT face의 식별을 실제 paint 소비 지점까지 보존하는 공통 경로를
검토한다. 이름이 비슷하다는 이유로 HY신명조 전체를 새 프로그램에 연결하지
않고, 원본 언어 슬롯·명시적인 대체 환경·실제 공급 여부를 함께 확인한다.
일반 Studio의 기존 공급 환경과 원 HFT 공급 환경은 별도 검증한다.
원본과 기준 PDF·DPI·raw 계산은 유지하며 같은 공급으로 base/후보를
재검증한다. 원본 공급 보완만으로 하락·수식·미세 간격을 면제하지 않는다.

남은 Rust 실패, Native/fresh WASM 전쪽·유입 PR 기능 보존과 base 하락,
완료 쪽의 회귀·전체 lint·GitHub PR/CI·기록 PR·merge 후속은 계속 미완료다.
