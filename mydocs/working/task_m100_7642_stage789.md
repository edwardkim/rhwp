# Issue #7642 단계 789: 빈 단 밴드와 재시작 TAC 프레임의 공통 소비

## 독립 근거와 수정 전 관측

- HWPML 원본·사용자가 확인한 독립 Print PDF의 3쪽 목차를 대조했다. 첫 빈 문단은 원본 줄 높이 1000HU, 뒤 줄간격 600HU다. 제목 앞 단 전환은 조판에서 21.33333px와 별도 단 간격을 소비하고, paint도 초기 밴드를 solo가 아니라는 이유로 같은 8px를 남겼다. 제목 기준선은 Native 약 179.16px, 독립 PDF 약 170.05px였다. 이 값은 입력·출력 관측이며 구현의 고정 조건으로 쓰지 않는다.
- 이미지 채우기 6쪽의 첫 TAC 표는 원본 줄 높이 10377HU이며, 다음 문단의 저장 원점 11129HU는 전체 뒤 간격 752HU를 더한 값이다. 옛 호스트 vpos 67373HU를 그대로 재사용할 수 없는 새 쪽인데, 원점만 0으로 바꾼 이전 보정은 반쪽 뒤 간격을 계속 사용했다. 단계 785에서 흐름 143.37333px, 다음 스냅 153.4px, 뒤 표의 저장 원점 328.92px와 실제 진입 333.93333px 차이를 확인했다.
- 두 사례 모두 문서 ID나 관측 px 값을 조건에 추가하지 않는다. 입력의 저장 줄·개체 소유·실제 수용 항목이 같은 프레임을 닫는지 확인한다.

## 생산 결과와 소비 경로

1. `blank_band::stored_blank_tail_spacing`는 원본의 단일 빈 글줄과 흐름을 점유하지 않는 설정만 가진 수용 밴드의 후행 간격을 반환한다. 실제 글줄 높이와 문단 여백은 유지한다. 조판은 `flush_column`이 확정한 항목에서 이 값을 읽어 다음 단 예산의 내용 끝을 계산하고, paint는 같은 항목과 helper로 다음 단 원점을 계산한다. 표·그림·수식·합성/편집 줄·복수 문단 밴드는 해당 계약으로 바꾸지 않는다.
2. `restarted_tac::restarted_tac_line_advance`는 원본 한 줄의 전체 표 바깥 상자와 뒤 저장 줄의 로컬 원점이 맞닿는지 확인한다. composer의 뒤 간격 결정도 이 닫힌 결과를 소비하므로 최초 표 계획이 전량 뒤 간격을 발행한다. fit 예산은 실제 점유 끝으로 검사하고 후속 흐름은 완전한 전진 끝을 사용한다.
3. `accepted_column_origin`는 단 첫 표의 확정 `InlineBoxPlacement` 원점·전진 끝까지 같은 원본 프레임과 대조한다. 조판 후처리와 paint 초기화·후처리는 이 결과로 0축을 보존한다. 재시작 전의 옛 호스트를 다음 문단의 이전 글줄로 사용하지 않는다. 뒤에 본문이나 다른 개체가 이미 있는 경우의 원점을 추측하지 않는다.

## 검증 상태와 다음 게이트

현재 구현은 분석을 묶어 적용한 후보이며 새 출력의 개선·회귀 통과를 아직 주장하지 않는다. 리베이스 소스 1a1905의 검증은 별도 review worktree에서 종료까지 유지하고, 이 후보의 검증과 혼합하지 않는다. 공용 `target/pr-review`를 순차 재사용하고 빌드 잡 8개를 유지한다.

후보에서 실제 호출 경로의 전후 스냅·전체 쪽수·Native/fresh WASM 전체 TSV를 산출한다. HWPML·이미지 채우기의 알려진 미달 쪽과 보도자료·앵커·도형 등 대조군을 직접 확인하고, 새 devel A5 기준의 하락도 다시 검사한다. 아직 90% 미만인 범위에는 새 렌더링 회귀나 golden을 추가하지 않는다. 90% 이상과 확대 판독이 완료된 실제 범위에 새 이름의 내용·소유·순서·포함 관계 검사를 추가한다.
