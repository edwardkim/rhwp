## 구현과 수정 전후 검증

`visual_sweep_pdf.py`의 공통 명령을 같은 Python의 PDFium으로 통일했다.
글자·이미지·경로 antialias와 흰 RGB 배경을 사용한다. 실제 라이브러리·Python·
wrapper·helper 해시를 기록하고 누락·잘못된 DPI·범위 밖 쪽에서 실패한다.
PdfPage와 bitmap은 명시적으로 닫아 다쪽 출력의 자원을 해제한다.

새 Type3 획 검사 하나를 기존 Cairo None에 먼저 실행했다.96/144DPI의
두 subtest가 모두 실제 획 소실을 원인으로 실패했다. 새 공통 경로에서는
같은 검사가 통과했다. 기존 균일 이미지 RGB·인접 면 RGB 기대값은 완화하지
않았고 실제 독립 한컴 Print의 파랑 그라데이션 검사도 유지했다.

Python 전체 `test_visual_sweep*.py` 자동 수집172건이21.851초에 통과했다.
로그는 ignored stage2473-pdfium-and-sweep-contracts.log이며 수정 전
실패는 stage2473-type3-before.log다. 별도 새 테스트 호출을 CI에 추가하지
않았다. 기존 Python 검사 step에 필요한 pypdfium2==5.13.0만 설치하도록
추가했다. 로컬 PDFium은153.0.7999.0이다. 기존 CI 영향 분류·정책 Node
검사95건도 통과했고 trigger·권한·필수 check 이름·자동 수집 범위는 바꾸지 않았다.

## 중단한 옛 정책 큐와 보존

Cairo None의 Type3 소실을 확인했으므로 같은 잘못된 기준 래스터의 추가
산출을 중단했다. 자신의 시각 큐 dispatcher와 자식9개를 실제 프로세스 트리로
확인해 종료했다. stage2472에 PID·명령·사유를 기록하고 미완료 영수증은
superseded_raster_contract_failure로 구분했다. 이미 완료된 PNG·manifest·
TSV는 삭제하지 않았다.27문서 이전 후보 fresh WASM은 종료 전 이미
완료되어 완료 상태를 보존했다. Cargo·rustc·wasm-opt는 종료 대상에 없었다.

4311d9e58f의 Native 빌드는 별도 고정 worktree·공유 target에서 계속 실행했다.
이 Rust source의 Native→fresh WASM 빌드를 사용해 새 정책의102문서
전쪽 검증을 재개한다. 고정 devel9415b920c8도 같은 정책과 실제 글꼴 프로필로
재측정한다. 같은 source의 완료된 RHWP PNG는 원본·PDF·profile·compat·
DPI·producer 신원·manifest와 파일 해시를 확인한 범위만 재사용하며,
PDF PNG와 TSV·review·overlay는 새로 생성한다. 새 정책의 전체 결과가
나오기 전에는 과거 Cairo TSV나2465 진단을 최종 통과 근거로 쓰지 않는다.
