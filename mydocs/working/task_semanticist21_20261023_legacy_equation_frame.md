# 구형 저장 수식 프레임과 재조판 줄의 소유

Issue: #4138, #1949. 기준 코드 `95c050e00f`, base
`d9fd85ed5bc3c4d9ce6b2981422e48bf9bb90867`.

## 독립 근거와 남은 실패

현재 API 저장본 `9ae8200417a39b912b36044a7371e9e3946afe21bc884beec868076f15c63ab8`의
한컴 2024 Print는 196쪽이다. Native147은 197쪽이며, 첫 내용 컷 차이는 15쪽 끝이다.
원본과 API 저장본의 18개 수식은 HYhwpEQ·빈 version_info·유효한 선언 크기를 갖는다.
독립 한컴 재저장본에서도 이 선언 크기는 유지된다. 근호 Q/E는 높이 1300HU,
기준선 85%, 위첨자 단위는 높이 1340HU·기준선 86%다. 한컴의 재계산된 줄도 이를
소비하지만 현재 논리 프레임 정규화는 더 작은 높이를 발행한다.

대조군 v5/v6의 210개 한컴 2024 생성 수식은 `Equation Version 60`이다.
같은 글꼴이라는 이유로 구형 선언 상자와 새로 생성한 논리 프레임을 동일시하지 않는다.
근거는 ignored `equation-frame-origins-2324-*.json`,
`issue4138-saved-line-metric-differences-2260.json`에 있다.
일반 텍스트 혼재 줄의 발행 제한만 제거한 Native144는 이 문제를 해결하지 못했다.

## 수정 계획과 소비 경로

파서에서 실제 읽은 구형 선언 프레임에 런타임 서명을 부여한다. 서명은 내용·글꼴·버전·
크기·기준선·줄 범위·보호 속성을 포함하며, 편집으로 이 값이 바뀌면 재사용하지 않는다.
새 IR·현대 수식·크기가 없는 수식에는 구형 출처를 추정하지 않는다. 파일에는 서명을
저장하지 않으며, HWP/HWPX 파서는 같은 모델 계약을 사용한다.

`flow_metrics_hwp`의 공통 결과를 줄 구성·실제 인라인 기준선·paint가 소비한다.
기존 미계산 호스트의 세대 선택 계약과 구형 저장 개체의 출처는 별도로 유지한다.
재생성한 혼재 텍스트/수식 줄도 이미 있는 줄 소유와 기준선 합집합을 저장하도록 한다.
현대 수식의 논리 프레임 계산, 근호 내부의 상속 프레임 계산은 유지한다.

Native 빌드는 공용 `target/pr-review`, 8잡으로 한 번 수행한다. 새 API 저장본의
줄 메트릭과 출력 컷, 원본 115쪽의 영향 경계, 현대 수식 v5/v6 및 #7840 대조군을
비교한다. 196쪽 전체 Native/fresh WASM·확대 판독을 완료하기 전에는 기존 197쪽
기대값을 바꾸거나 새 렌더링 회귀를 등록하지 않는다. 그림의 캡션·저장 프레임 문제는
별도 남은 원인이며, 수식 수정의 쪽수만으로 해결됐다고 판정하지 않는다.

## 다음 물리 프레임 분석의 근거

새·이전 Print 196쪽을 모두 96dpi RGB로 대조해 전쪽 픽셀 동일함을 확인했다
(`issue4138-independent-print-equivalence-2336.json`). 따라서 수식 메트릭 저장 보정은
한컴의 실제 정답 배치를 바꾸지 않는다.

새 Native148의 전체 컷·유닛 추적은 `logs/issue4138-native148-owner-trace-2335.log`다.
본문 행은 멀리 떨어진 그림·중첩 표 때문에 `row_has_plain_line_units`가 false여서,
이미 계산된 물리 프레임 예산 대신 더 큰 기존 예산을 사용한다. 반대로 현재 용량
검사는 일반 저장 줄의 뒤 간격까지 들어가야 줄을 수용한다. 이 두 가정은 별도로 검토한다.

원본 본문 높이 75686HU에서 바깥 위·아래 283HU씩, 셀 안 위·아래 141HU씩과
기존 100HU inset을 제외한 후보 내용 예산은 74738HU다. 마지막 줄의 실제 상자를
비교하면 첫 23개 원본 컷 중 21개에서 원하는 줄은 들어가고 다음 줄은 거절된다.
14·19쪽은 마지막 빈 문단의 실제 줄간격이 유닛의 `following`에 발행되지 않아
이 단순 비교와 맞지 않는다. 빈 줄이 차지하는 줄 상자와 뒤 간격은 구분해야 한다.
이 계산은 진단일 뿐 엔진 수정의 검증 결과가 아니며, 새 픽셀 허용치를 도입하지 않았다.

`rowbreak_frame.rs`의 내용/빈 띠 경계 분리는 기존 보정 `cd8b307a24`에서 나왔다.
그 기록은 교육과정 일반 격자의 줄 수용과 걸침 종료 띠 3개 계약을 동시에 보호한다.
따라서 후보 74738HU에 맞는다는 이유로 모든 격자의 내용 하단을 빈 띠 하단으로
바꾸면 안 된다. 기존 적용·비적용 경로와 실제 조각 소유를 먼저 대조한다.
분할 재저장 topology에만 별도 strict cut을 적용한 기존 #4138 경로도
`row_step.rs`의 `native_split_continuation_row_tail`에서 추적해야 한다.
