# #7419 Stage 2 — 원본과 경계 회귀의 보완

제품 코드: `a08cf5cc6`. 원 PR #7433을 체리픽한 뒤의 메인터너 보정이다.
[Stage1](task_m100_7419_stage1.md)의 독립 Print·양쪽100%·직접 판독 이후에만 검사를 변경했다.

## 검사 계약

- 원본2개 함수명은 유지하고 SVG의500~700px 고정 영역 선택을 제거한다. 원본 셀 주소·행 소유,
  전체 표/셀 수, 각 셀의 자기 내용과 중첩 내용의 구분, 순서·누락·중복, 줄·표의 세로 포함을 검사한다.
- 선언4838HU는 원본과 독립 Print가 같은 높이인 대조군이다. 수치 경계로 다시 축소되지 않아야 한다.
- 같은 줄·명시적 개행·폭 부족은 실제 소유 줄과 앞뒤 비겹침을 검사한다. 마지막 개체 아래에 원본 셀
  하단 여백만 남는 관계도 검사해 같은 줄의 두 높이를 합산한 빈 예약 공간을 검출한다.
- 앞뒤 본문은 실제 표 앞/뒤의 가로 순서도 검사한다. 바깥여백은 원본HU로 정한 상·하 점유 계약을
  유지한다. 이는 구현이 산출한 기대값이나 화면 위치 핀을 재인용하는 검사가 아니다.
- 용지28000HU는 독립 Print의3쪽, 제목/첫 표/뒤 표의 쪽 소유와 본문 포함을 함께 검사한다.
- 해당 완료 페이지 전부 양쪽100%이므로 독립 Print의 표 제목 glyph 원점을96dpi에서±2px로
  별도 검사한다. 원본·PDF SHA와 전체 TSV, 같은 영역 Native/Print/WASM 판독은 Stage1에 있다.
  좌표 검사로 위 관계 검사를 대신하지 않는다. 이후에도 해당 쪽의 양쪽98% 이상이 필요하다.
- CLI 검사는 런타임 `CARGO_BIN_EXE_rhwp`를 먼저 소비한다. 따라서 같은 검사 실행 파일에 frozen
  devel/체리픽 CLI를 공급해 수정 전 결함을 검출할 수 있다. parser/model은 이번 보정에서 바꾸지 않았다.

## 검증 상태

첫 `focused-dev.log`는 포맷 전후 suite 가중치 이동으로 다른 묶음을 실행해0 tests였다. 통과 근거로
사용하지 않는다. 포맷 → suite 재생성 → 실제 case가 포함된 묶음 선택 순서로 재실행한다.
포맷 뒤 다시 생성한 `regression_suite_027`의10개 검사가 실제 실행돼10 PASS였다.
`focused-dev-final.log`: 컴파일16.98초, 실행1.66초. 최초0개 실행은 제외했다.

같은 검사 실행 파일(`regression_suite_027-3ddae35555662275`)의 런타임 CLI만 교체했다.

`regression-before-after.json`, `{base,cherry,candidate}-regression-proof.log`에 실제 argv 경로와
원인별 assertion을 보존했다. 예: 체리픽의4838HU 둘째 제목 y287.3067 vs Print292.9598,
같은 줄 뒤 빈 예약93.7px vs 원본 하단 여백1.8933px, 폭 부족의 두 번째 표가 앞 줄에 남는 결함이다.
오래된 코드의 컴파일 실패를 재현으로 세지 않았다. 작은 용지 검사가 체리픽에서도 통과하므로
현재 devel의 기존 pagination 하한을 중복 보정하지 않았다는 주장과도 일치한다.

기존2개는 실제 셀·내용 관계로 교체했고 새8개는 경계7종과 완료 페이지 좌표 검사다.
이전 일반 검사에 있던 앞뒤 표 비겹침 관계는 유지·확대했다. 새 좌표 핀은 독립 PDF 원점만 사용한다.
전체 회귀·lint·Native Skia는 다음 검증 단계에 기록한다.

원본·PDF는 보존하고 기존 회귀를 삭제하거나 실패를 숨기는 baseline 완화는 하지 않는다.
