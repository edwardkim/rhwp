# 이슈 #7642 — 저장 되감김 컷을 실제 단 예산에 맞게 재검토

시작 커밋: `e08eae718`. 이번 회귀 실패는 현재 브랜치에서 모두 보정한다.

## 독립 근거와 원인 후보

원본 `samples/3-11월_실전_통합_2022.hwpx`의 문26 풀이 다섯 줄은
vpos 1352, 4494, 3142, 6246, 8768이다. 한컴 2024에서 내용 변경 없이 Save한
정상 HWP는 둘째 줄을 0으로 저장한다. 같은 원본의 2024 Print도 둘째 줄부터
17쪽 첫 단으로 이월한다. 현재 RHWP는 원본의 셋째 줄 되감김을 컷으로 받아
앞 두 줄을 16쪽에 남긴다. 이후 그래프와 문항까지 한 줄씩 일찍 시작한다.
저장본은 진단 자료이며 원본/독립 Print를 대체하지 않는다.

`split_candidate → reflowed_endnote_prefix_split → 실제 PartialParagraph 점유 → emit`
중 기존 helper는 저장 컷보다 긴 prefix만 검사한다. 원래 컷 자체가 잔여 높이에
들어가지 않아도 더 짧게 수정할 수 없다. 호출도 수식 줄 재발급 여부로 제한돼
현재 단 앞부분의 간격 예약 변경을 포함하지 못한다.

## 수정 범위와 검증

저장 내부 컷을 처리하는 경로에서 실제 수용 가능한 prefix를 대조한다. 이미
소비한 내용 컷과 미소비 줄의 소유·순서는 그대로 유지한다. 수식 재발급 여부만으로
물리 예산 재검토를 생략하지 않는다. 명시 단 나눔, keep/widow 계약, 후보 안의
표·그림·도형은 기존 helper의 보호 조건을 유지한다. 원래 컷보다 길거나 짧아지는
방향 모두 같은 부분 문단 배치 결과로 결정한다. 원점 clamp나 내용 숨김은 하지 않는다.

Native 15·16·17쪽의 내용 소속과 컷, 원본 HWP/2020 대조를 확인한다. 더 짧은
컷·변경 없는 컷·첫 줄도 안 들어가는 경계의 후속 호출을 대조하고, 영향 전쪽의
Native/fresh WASM 90% 이상 및 확대 판독 전에 정식 검사 기대값을 바꾸지 않는다.

## 첫 실험의 회귀와 범위 보정

수식 줄 재발급 여부와 무관하게 모든 저장 컷을 가장 긴 prefix로 다시 고르는
첫 실험은 build/Native Clippy exit 0이었지만 15쪽을 95.75481%에서 40.21102%로
악화시켰다. 16쪽 57.33643%, 17쪽 44.09679%로 미충족이다.
HWP/2020 대조군도 15쪽 40.27512%, 16쪽 57.37652%로 악화됐다.
바이너리 `32b57d360dc900b3b0df99b9dcdcde126a5e3803e78ee03928d1c196a7b2a2d6`의
`endnote-budgeted-rewind-focused-native/`에 실패 증거를 보존했다. 이 실험은 승인하지
않으며 내가 추가한 세 Rust 파일의 변경만 Stage33 커밋 상태로 복원했다.

기존 컷의 확대 재조판 조건은 유지한다. 이미 정한 컷 안의 prefix를 같은 측정
helper로 검사해 실제로 수용 불가능한 컷만 더 짧게 검토한다. 기존 확대 검색과
제한된 축소 검색은 후보 범위만 다르고 소유·keep·개체 보호·부분 문단의 실제
점유 검사는 공유한다. 첫 실험의 결과를 수정한 코드의 통과 증거로 재사용하지 않는다.

## 제한된 축소 실험도 거부하고 생산 코드 복원

둘째 실험의 build와 Native Clippy도 exit 0이다. 바이너리 SHA-256은
`8f1c757881cb807483b5945d71538ef4289d24bd5436f8597d32de237a80b696`이다.
이 실험도 15쪽 40.21102%로 악화됐다. 새 검사 범위에서 문제 문단 첫 줄도
가용 높이를 넘는 것으로 측정됐다. 그러나 앞쪽의 다른 저장 컷을 줄인 결과
15쪽의 첫 내용 소속 자체가 바뀌었다. 기존 독립 Print와 일치하는 컷까지
바꾸는 일반화를 수용하지 않는다.

내가 추가한 두 Rust 파일의 변경만 Stage33 상태로 복원했다. 첫/둘째 실험의
바이너리·소스 해시·로그·캡처는 ignored output에 남기고 생산 코드로 커밋하지 않는다.
최종 생산 코드는 `e08eae718`의 15쪽 95.75481% 보정이다. 이후 실패 실험의 Clippy를
복원 코드의 새 검증으로 보고하지 않으며 Stage33 증거를 해당 코드에 연결한다.

다음 단계는 복원 코드와 2024 Print의 전쪽 대조다. 16·17쪽 컷을 바꾸기 전에
그 앞의 최초 배치 차이와 측정/실제 배치 문맥을 확인한다. 이 기록은 거부한
실험의 분석이며 분할 결함 해결·회귀 통과·PR 준비 완료 판정이 아니다.
