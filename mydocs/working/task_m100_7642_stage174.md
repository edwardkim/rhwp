# #7642 Stage 174 — EMF+ 압축 그림과 전체 그림 재생

Issue: #7642

## 독립 근거와 원인

원본 `samples/issue6469/wmf_fill_shapes.hwpx`와 독립 한컴 2020 Print
`pdf/issue6469/wmf_fill_shapes-2020.pdf`를 사용한다. Stage 173의 Native/fresh
WASM 전체 15쪽 최저 92.83091%이나 3쪽 로봇·작은 아이콘이 누락됐다.
점수만으로 완료 판정을 하지 않는다.

원문 WMFC의 3쪽 EMF+에는 중첩 metafile 세 개와 압축 JPEG/PNG 네 개가
있다. 압축 그림의 Width/Height/Stride/PixelFormat은 모두 0이다. 이는
[EmfPlusBitmap 사양](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emfplus/112a5e2c-6bb3-4daf-8ee3-0f3d3984410f)의 압축 그림 계약과 일치하며
해당 필드는 무시하고 [CompressedImage 내용](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emfplus/9c00912b-adfa-469e-8baa-82d9d3d8d6ae)에서 실제 형식·크기를 읽어야 한다.

호출 경로: `objects::parse`가 Bitmap ImageDataType 1을 거절 →
`player::render`가 EMF+ 전체 재생을 거절 → `svg::convert_wmf_to_svg`가
legacy WMF 폴백을 반환 → ImageNode/paint/SVG/Canvas가 그 결과를 소비한다.
실제 3쪽 SVG도 `elem` 노드가 있는 legacy WMF였다. 압축 그림의 수용이
아이콘을 복원하는지는 보정 후 독립 Print와 실제 출력으로 입증한다.

## 구현과 반례

- 표준 compressed BitmapDataType 1의 PNG/JPEG를 내용에서 판별하고 크기를 읽는다.
  이미지 전체를 제한된 decoder로 확인한 뒤 원래 encoded 바이트·색상·알파를 보존한다.
- 실제 pixel viewport를 공통 Image SVG로 만들어 기존 SrcRect·TileFlipXY·
  변환·clip 소비 경로에 연결한다. 문서 ID·페이지·고정 px 예외를 추가하지 않는다.
- 객체 문자열도 공통 bytes 예산에서 예약해 객체 등록만으로 메모리가 누적되지 않게 한다.
- 압축 헤더의 0 크기, PNG 알파와 JPEG, 재사용 객체 ID, 기존 중첩 metafile을 대조한다.
  깨진 encoded 데이터·과도한 크기·미지원 bitmap type은 전체 폴백 계약을 유지한다.
- 2쪽은 정상 중첩 metafile 대조군이며, 배경 격자는 alpha의 Print 표현인지 실제
  그림 누락인지 구분한다. 큰 아이콘 누락과 이를 같은 사유로 면제하지 않는다.

## Native 실행 결과와 추가 거절 조건

생산 SHA `b84dd87be`의 Native 빌드 exit 0, source hash 유지 true다.
전체 15/15쪽 최저 92.83091%이며 미달·누락이 없지만 실제 3쪽 review의
로봇·작은 아이콘 누락은 남았다. 압축 이미지 수용만으로 해결했다고 판정하지 않는다.
이 알려진 미완성 source의 fresh WASM 빌드는 시작하지 않았다.

원문의 bitmap DrawImagePoints 네 개는 C=1(`flags 0x400e/0x4012`)이며
데이터 길이 40바이트, 목적 점은 signed 16bit다. 기존 `player::image`는 이
비트를 상대 좌표와 함께 거절했다. 객체와 목적 점 표현을 함께 소비해야
EMF+ 전체 재생이 수용된다. Stage 175에서 이 조건을 보정하고 전체 경로를
사전 재생한 뒤 Native/fresh WASM을 검증한다. 사전 컴파일도 공용 target을 사용한다.
