# #8856 그림의 부드러운 가장자리 효과 복구

## 선행 해결과 독립 근거

앞 단계의 정책연구 서식 보정을 커밋한 뒤, `b5064fae1e`를 기반으로 충돌 없이 리베이스했다.
기존 보정 소스 22개는 전후 SHA-256이 동일하다. 새 base의 #8867 기능 보존 검사는
`output/issue8856/rebase-b5064fae-20261110/`에서 별도로 진행한다.

기존 #8593은 효과 꼬리를 이미지 원본 크기로 잘못 읽던 문제를 고쳤으며,
`issue_8593_picture_soft_edge_dim` 검사는 크기·자르기·투명도 보존만 보호한다.
그 검사 자체도 흐림 구현을 주장하지 않는다. 이번 단계는 그 계약을 유지하며 효과의
읽기·저장·공통 도색 소비 누락을 다룬다.

`interview.hwp`의 첫 그림 레코드 원시 꼬리는 효과 플래그 4와 반경 f32 1000 HU를 포함한다.
독립 한컴 2020 11.0.0.9136 변환 HWPX에도 `<hp:softEdge radius="1000"/>`가 있다.
공식 HWP5 사양 표 108·111은 효과 정보와 반경 float를 정의한다. 현재 공통 모델에는
그림자만 있고, HWPX 저장 결과는 `<effects/>`가 되어 효과를 잃는다.
원본 JPEG에는 흰 가장자리가 없지만 독립 Print에는 실제 그림 마스크가 있다.
따라서 임의 여백·사진 확대·대체 글꼴 변경으로 맞추지 않는다.

## 검증 계획과 현재 상태

반경 0·300·1000·2000 HU와 단색 그림을 조합한 독립 2020/2024 Print 대조군을 준비한다.
기하·자르기·원본 표본과 효과의 반경 소비를 구분하여 확인한 뒤 공통 경로를 보정한다.
먼저 원본 HWP의 반경이 모델·HWPX 저장에서 소실되는 실패를 실행하고, 반경 보존을
복구한 뒤 실제 Native/fresh WASM 출력과 전쪽 TSV로 도색을 확인한다.
모델·저장 검사 통과를 실제 효과 출력 완료로 보고하지 않는다.

임시 대조군·실행 로그는 `output/issue8856/soft-edge-oracle/`에 둔다.
원본 입력·기준 PDF·판정 기준은 유지하며, 기존 자르기·투명도 검사를 제거하지 않는다.

## 원 해결 이력 정정과 현재 보정

#8593은 이슈 번호이며 실제 원 PR은 #8656이다. 원 구현 `d8e6c8a445`,
메인터너 보강 `b68f673f23`와 `pr_8656_review.md`가 크기 해석·효과 도색을 구분한다.
새 모델/저장 관계 검사는 효과 없음 1 PASS·소스 반경 소실 1 FAIL로 실제 재현했다.
첫 진단의 Document 전체 Serialize 컴파일 실패와 suite 배정 변동으로 실행된 0 tests는
결함 재현/통과 증거에서 제외한다. 포맷 후 다시 prepare한 실제 실행을 사용한다.

공통 PictureEffects에 선택적 HU 반경을 두고, HWP5 단독 플래그 4의 13/21/22바이트 꼬리와
HWPX softEdge를 적재한다. 다른 가변 복합 효과 오프셋은 추정하지 않는다. HWP/HWPX 저장에
반경을 보존하고, 알려진 단독 효과의 편집·제거와 alpha를 갱신한다. 기본 불투명의 생략된
꼬리는 그대로 두며 누락된 원본 크기를 무편집 저장 때 임의로 추가하지 않는다.
효과 있는 그림은 편집 가능 PDF stroke sidecar의 동일 픽셀 증명에 포함하지 않는다.
새 필드가 없는 기존 그림의 JSON은 None 생략으로 유지한다.

최소 글꼴 환경의 Native Skia 새 검사 3 PASS와 기존 #8593 크기·crop·alpha 보존 2 PASS를
확인했다. HWP → HWPX → HWP 반경 보존, 0/2000 HU 편집·제거와 50/100% 투명도도 검사했다.
읽기/저장 완료를 효과 도색 완료나 새로운 전쪽 일치율로 보고하지 않는다.

## 독립 효과 대조군

그림의 물리 크기 30000×20000 HU, 위치 5000×5000 HU, 단색 RGB(64,128,192),
확대/회전 행렬 identity, 전체 crop을 사용했다. 4개 반경 0/300/1000/2000 HU를
한컴 2020 11.0.0.9136과 2024 13.0.0.3901에서 각각 Print method 0으로 출력했다.
최종 물리 대조군 8개는 실제 모두 1쪽이다. 초기 원본 프레임 대조군 8개는 2쪽이며
물리 대조군과 혼합하지 않는다. 입력·출력 해시/실제 서버 버전·작업 ID를 함께 보존한다.
이 자료는 효과 방식 판별의 독립 oracle이며 현재 제품의 전쪽 통과 증거가 아니다.

## 효과·투명도 편집의 자르기 기준 반례

`787ad43f5e` 뒤에 첫 그림의 실제 렌더 트리 자르기 기준까지 대조했다.
반경·alpha만 검사하면 저장이 원본 크기 기준을 바꿔 사진을 왜곡해도 놓칠 수 있다.
효과+50% 투명도 편집에서 기존 `None` 기준이 `(48000,33676)`으로 바뀌어
실제 2 PASS / 1 FAIL이었다. 이 값은 crop의 오른쪽/아래 끝점으로 원본 전체 크기가 아니다.
원본 JPEG·crop 끝점·실제 bitmap의 암묵 기준은 별개다.

확인한 단독 효과 꼬리에 alpha를 새로 붙일 때, 모델의 원본 크기가 미확인(0,0)이면
그 미확인 상태를 그대로 기록하도록 보정한다. crop 끝값이나 개체 틀로 추정하지 않는다.
다른 가변 효과·원본 크기를 명시한 기존 #1929 경로는 유지한다.
옛 #1930의 원 검토는 imgDim을 렌더 미소비 필드로 간주했지만 지금의 소비는 crop 기준에
사용하므로, 같은 필드 이름만으로 오래된 판단을 재사용하지 않는다.

자르기 기준 보강 후 최소 글꼴 Native Skia의 새 3건과 기존 11건을 다시 실행해
14 PASS / 0 FAIL을 확인했다. 후속 로그·소스 해시는 stage5 assets의
`crop-frame-followup.json`에 앞 단계와 구분하여 보존했다.
