## 결론

D3-C 사전 게이트에서 native와 격리 Node WASM은 같은 D3-B target에 대해 source 2개, fallback
`TextRun` 2개, leaf별 vertical `GlyphRun` 2개, portable font blob/face 1개를 확인했다. 각 glyph JSON은
자기 `TextSourceId`, `text-N` group, `verticalGlyphRun`, `vertical-rl`, `vertical-upright` 및 한 개의
glyph/position/advance/cluster를 보존한다.

Rust selector와 `text_v2`는 두 leaf 모두 strict variant를 열지 않고
`verticalGlyphOrientationAuthorityPending` 사유로 fallback을 선택했다. 따라서 제품 layer에는 portable
candidate가 존재하지만 backend가 잘못 선택한 경우는 0이다.

native에서 고정한 값과 동일한 assertion을 wasm32+Node에서도 통과시켜 JSON·resource 수치의 런타임 차이는
0으로 판정했다. 메인테이너가 사전 결과를 승인한 뒤 표준 Docker WASM 배포 빌드도 통과했고, 빌드 뒤 같은
native 영수증을 재실행해 수치 변화 0을 확인했다. 따라서 D3-C 최종 판정 후보는
`qualified-publication-parity`다.

## 2. 크기 영수증

| 항목 | bytes |
| --- | ---: |
| portable font payload | 2,519,996 |
| accepted layer JSON | 3,375,512 |
| rejected layer JSON | 9,078 |
| accepted-rejected JSON 증가량 | 3,366,434 |

이 값은 현재 synthetic target의 직렬화 기준선이다. JSON 증가량 대부분은 portable font의 base64 표현을
포함하므로 성능 개선·악화의 결론으로 사용하지 않는다. 이 target은 accepted line 한 개와 unique interned
source 한 개만 측정한다. 여러 line에서 실제 source preparation 호출이 캐시되는지까지 증명하지 않으며, 그
판정은 D5 계측 범위에 남긴다.

## 3. 교차 런타임

| runtime | 결과 |

| native Rust | publication 값·크기 assertion 통과, JSON 영수증 출력 |

| 표준 Docker WASM | 성공, wasm-pack 6분 43초 / 전체 명령 429.34초 |

최적화된 `pkg/rhwp_bg.wasm`은 9,874,453 bytes이며 SHA-256은
`4213af83ef6b38c2a8abd923ffe3545ffc920edb8c8526ba4a77e0ac008610f1`이다. 이 절대값은 현재 source의 배포
빌드 영수증이다. 동일 기준의 pristine D3-B 대조 빌드를 별도로 짝짓지 않았으므로 D3-C의 WASM 크기 delta나
성능 결론으로 사용하지 않는다.

격리 harness는 저장소 source를 복사하지 않고 현재 rhwp를 path dependency로 참조했다. 검증 뒤 harness와
418 MiB target은 휴지통으로 이동했으며 worktree에 산출물을 남기지 않았다.
