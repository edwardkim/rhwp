# 이슈 #7642 — 새 미주 경계의 예약 간격과 실제 배치 연결

## 근거와 범위

시작 생산 소스는 `f58b01c81`이다. 간격 0 경계의 Native 보정은 선택 쪽에서
통과했으나 기본 미주 간격의 원본 2022년 11월 HWPX 10쪽은 별도 결함이 남는다.
Native/fresh WASM 전21쪽의 최저90.64775%와 직접 판독을 구분한다.

원본 Print의 문1~문4 제목은 Native와 같은 흐름에 있고, 문5·문6의 기준선은
직전 경계에서 약20.4267px가 누락된다. Print text layer에서 문5의 본문은
Native와 같은 한 줄이다. 처음 그림만 보고 줄바꿈 차이로 설명한 내용을
정정하며, 실제 결함은 문4→문5의 미주 간격이다.

진단의 문단466은 실제 paint에서 18.0만 전진하는데 조판은 다음 미주 준비에
20.4267을 추가 예약한다. 다음 제목의 HeightCursor는 lazy 기준 역산이
음수여서 순차 원점을 유지한다. 뒤 gap 보존 분기는 vpos가 원점을 바꾸었거나
앞 문단이 이어받기 조각일 때만 실행되어 새 미주의 정상 간격을 놓친다.
수치는 독립 Print·실행 진단이며 고정 px 회귀 기대값이 아니다.

## 구현 및 반례

- 미주 원본 소유 정보로 다른 컨트롤의 첫 문단인지 판정한다. 제목의 특정
  글자·문항 번호를 새 미주 경계의 근거로 사용하지 않는다.
- 현재 단이 이전 미주의 마지막 줄을 완전히 소유한 경우에만 경계의 간격을
  소비한다. 내부 문단, 다음 단에서 이어받는 제목 조각, 미완성 앞 조각,
  원본 소유 정보가 없는 입력은 이 새 경로에 해당하지 않는다.
- 독립적으로 확인한 잘못된 가정인 'vpos가 바뀌어야만 예약 간격을 지킨다'를
  제거한다. 같은 실제 점유 끝과 이미 소비한 흐름 끝을 공통 간격 helper에
  전달한다. 간격이 이미 예약됐으면 같은 공간을 다시 더하지 않는다.
- 소비 경로는 prepare의 tail 간격 → render 문단 사본 → 실제 마지막 줄의
  점유 끝 → 새 미주 원점과 vpos 기준이다. scratch 단 측정과 실제 paint는
  같은 build_single_column을 실행하며 source 매핑도 확인한다.
- 수정 전후 10쪽과 정상 경계19·20쪽, 간격0 반례14·15쪽을 같은 Print로
  대조한다. 큰 위치·누락·중복 차이가 없음을 확인한 뒤 전쪽 Native/fresh
  WASM을 검증한다. 90% 및 확대 판독을 충족하기 전 회귀를 바꾸지 않는다.

새 Native 진단은 기존 공용 target의 release-test 프로필을 재사용한다.
release 최적화를 사용하되 LTO를 생략하고 codegen units를 16으로 두는 프로필이며 회귀
검증에서도 사용하는 프로필이다. 산출물 경로를 새로 만들거나 캐시를 지우지
않는다. 모든 source·binary 해시와 명령·결과는 ignored output에 기록한다.
전체52입력·기존110실패·관계형전환·PR/CI/merge는 여전히 미완료다.

모든 실행의 전체 쪽수는 Native/Print 21쪽이며 선택 쪽 누락은 없다.
새 10쪽 review를 직접 열어 문4→문5의 경계 간격과 문6의 시작 위치가

새 경계로 판정하지 않는다. 정식 관계형 회귀의 수정 전 FAIL/후 PASS는
아직 미검증이며 아래 교차 검증 후 계속한다.

summary가 없는 이 실행은 전체 회귀 통과 또는 최신 실패 수의 근거가 아니다.
