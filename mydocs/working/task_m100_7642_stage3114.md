# #7642 일반 칸이 없는 종료 행의 병합 원본 소유

Issue: #7642. 앞 단계 후보는 `7606228e9e`다. 원본 #7028의 관측된 Print 글꼴에서
Native 6쪽이 모두 90% 이상이다. 쪽별 원값은 99.68890 / 99.73053 / 96.97041 /
98.47569 / 98.23171 / 98.83256%이며 이 단계의 변경에는 아직 적용하지 않는다.

## 독립 출력과 적용 경계

`stage3047`의 같은 전체/분할 입력은 겹치는 세 병합 칸 A(0~3행), B(3~4행),
C(4~6행)로 구성된다. 전체 Print는 Native 100%지만 분할 Print의 2쪽은
58.63576%다. `63c14b3538`의 실제 스캔은 4행의 물리 띠 48px와 빈 일반 컷
`[]`를 수용하고도 4행에서 다시 시작한다. Native는 C의 글자를 두 번 그리고,
5행을 12px 뒤에서 시작한다. 독립 Print는 C의 글자를 앞쪽에만 그리고 5행을
다음 쪽 맨 위에서 시작한다. 남는 C의 물리 높이는 마지막 6행이 보존한다.

실제 경로는 block 컷이 아니다. `block=None`, `cut=[]`, 일반 칸이 없는 행의
rowspan band 경로다. 일반 칸이 있어야만 완료로 인정하는 가정 때문에 이미
소비한 행이 다시 열렸다. 빈 일반 컷이라는 이유만으로 완료로 판단하지 않는다.

## 공통 판정과 소비 경로

일반 칸이 없는 RowBreak 행에서 그 행에 끝나는 병합 칸을 모두 확인한다.
실제 재조판 일반 글줄이어야 하며, 같은 조각 원장의 종료 컷이 모든 유닛을
소비하고 그 내용 높이가 누적 수용 물리 공간 안에 들어가야 완료다. 저장 줄·
중첩 표·개체·부족한 원장은 이 경로로 완료 판정하지 않는다. 다른 병합 칸이
이어지는 경우 그 칸의 내용 커서와 물리 합은 기존 원장에 유지한다.

`accepted_straddle_fragment_units`의 원본별 컷·수용 합 → 종료 행의 완료 여부 →
기존 `has_intra_row_tail` → `straddle_page_bands_after_fragment`의 다음 행 소유 →
다음 조각의 같은 원본별 커서·종료 요구를 연결한다. 좌표 이동, 글자 숨김,
선언 높이 삭제나 허용치 변경을 하지 않는다. 미소비 글줄이 남는 종료 칸은
완료로 판정하지 않는 반례를 유지해야 한다.

같은 시작 행에서 재개할 때도 기존 원장의 `next_unit`은 이미 소비한 원본
커서다. `resumes_inside_own_start_row`를 공유하는 측정·종료 요구·paint가 이
커서를 함께 인식하게 한다. 현재 조각의 `fragment_cut.end`를 이전 소비로
취급하지 않는다. 앞 조각을 실제로 소비한 커서만 사용해 첫 표시를 숨기지 않는다.

## 검증 조건

분할 대조군의 C 글자 단일 소유와 5행 시작·6행 종료·뒤 문단을 독립 Print와
대조한다. 전체 대조군, 원본 #7028 6쪽, 작은 빈 문단·병합 대조군, 기존 53쪽과
#7969 13쪽을 확인한다. 앞 단계 실행이 종료된 뒤 같은 공용 target에서 후속
빌드를 수행하며, 현재 단계의 최종 실행·fresh WASM 증거는 아직 없다.
