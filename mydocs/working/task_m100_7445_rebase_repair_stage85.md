# Stage85: 저장 쪽 경계와 조각 그림의 양수 앞 공간 복구

Issue: #7445. 부모 HEAD는 `cec3710f1dc5c06f5364c6f5af74a10b4772fef4`, 고정 base는
`d9fd85ed5bc3c4d9ce6b2981422e48bf9bb90867`이다. 기존 50조건의 문서 범위만 사용했다.
이 단계는 집중 보정 증적이며 전체 검증 또는 PR 준비 완료가 아니다.

## 공통 소비 경로의 보정

1. 생물독소 원본의 `section6 paragraph19`는 저장 vpos가 50850→300 HU로 되감긴다.
   whole-fit 판정은 이미 저장 쪽 경계를 수용했지만, 뒤의 atomic-overflow 소비자는
   overflow 전용 bool만 받아 그 경계를 덮었다. `flow::place`가 수용한 일반 저장 경계와
   overflow 경계를 함께 넘겨 기존 비되감김 top-fit 스필은 보존한다.
2. 같은 원본 11쪽의 빈 호스트는 양의 높이 1300 HU인 정상 저장 줄을 소유하고, 표는
   그 아래 1340 HU에서 시작한다. `stored_independent_table_frame_host`의 마지막 fallback이
   글자 잉크만 요구해 바깥 위 여백 283 HU를 누락했다. 줄의 유효성·단일 표 소유·문단 기준
   top/inside·offset≥줄 높이는 유지하고 잉크 유무를 줄 상자 유무로 사용하지 않는다.
   기존 예약과 최종 표·캡션 배치가 같은 predicate를 소비한다.
3. 보도자료 9쪽의 셀 문단 158 그림은 양수 offset3898 HU를 보존한다. 공통
   `cell_wrap_vertical_offset_hu`와 개체 위치 계산은 이를 반영했지만, 조각 소유 분기가
   최종 y를 bare anchor로 다시 덮었다. 전체 셀과 partial-table 양쪽 소비자가 같은 공통
   offset을 더한다. 음수의 이전 쪽 변위 제거는 기존 공통 판정을 유지한다.
   독립 PDF top 680.05599 CSSpx, 보정 전 Native 629.0 CSSpx이며 원본 offset은 51.97333 CSSpx다.
4. 메타파일의 요청 bold와 실제 SFNT 일반체를 기존 PDF 합성 굵기 판정으로 대조했다.
   PDF의 usvg 0.45와 resvg의 usvg 0.47은 타입이 달라 첫 직접 연결은 컴파일 실패했다.
   두 소비자가 동일한 판정 소스를 각 버전 alias로 컴파일하게 정정했다. 알고리즘이나
   글꼴 DB를 복제·변환하지 않고, Native PDF의 public API·cfg도 유지했다.
   이는 아래 HWPX의 주원인을 해결하지 못했으며 완료로 수용하지 않는다.

문서 ID·쪽 번호·출력 backend별 좌표 보정이나 비교 문턱 변경은 없다.
생물독소는 동일 입력의 독립 한컴 2020 Print 재출력 205쪽 중 확인한 6쪽이 기존 PDF와 100%였다.
기준 PDF·입력은 교체하지 않았다. 보도자료의 .hwpx 확장자 입력은 실제 HWP5 CFB임도 확인했다.
