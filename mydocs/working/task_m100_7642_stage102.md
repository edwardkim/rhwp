# Stage 102 — Skia 실제 face와 공통 장식 기하의 일치

Issue: #7642. 이전 검증 source는 `1e6ca62e8e5c81894ec7e12e6c9000becca97542`다.
55원본/853쪽, 요청 회귀 292개와 #1139 전체 관계형 전환 목표를 유지한다.
HML 수식 제외와 현재 branch에서 기존 실패를 보정하는 사용자 지시를 유지한다.

## 원인과 구현 계획

독립 Skia 실행은 `HyhwpEQ` 설치 face가 `HYhwpEQ` 요청에도 실제 조회되지만,
rhwp의 대소문자 구분 사전 필터에서 제외되는 것을 입증했다. 이 필터를 실제 face
조회 계약과 일치시키고 누락 family를 임의의 fallback으로 인정하지 않는다.
대소문자만 다른 요청과 실제 없는 family를 함께 대조한다. 글꼴 환경은 기존 시스템
등록을 쓰며 새로운 RHWP_FONT_PATH나 사설 글꼴 바이트를 도입하지 않는다.

벡터·DYAD·BAR는 원본 기준선·본체 소유·논리 프레임과 실제 화살촉을 공통 결과로
발행해야 한다. 이전 단계에서 독립 Print 행렬/메타데이터와 공개 Latin Modern Math의
MATH 부품을 확보했다. 사설 윤곽·바이트를 코드에 복제하지 않고 공개 부품과 독립
ink 프레임을 대조한다. 측정·paint 원점과 Native SVG·Skia·WASM·CanvasKit의
소비를 함께 확인한다. unsupported 본체를 조건 없는 단순 font-line으로 접지 않는다.

글꼴·기하 보정을 묶고 동일 80수식 및 기존 13개 대조군, 실제 2022년 9월 원본
20쪽의 확대를 먼저 비교한다. 필수 lint/Native/fresh WASM을 같은 source로 실행하고
55원본/853쪽 Native/fresh WASM TSV를 확인한다. 전체 페이지 90% 이상과 확대 판독
뒤 원본 소유·순서·보존·포함·겹침 관계로 정식 회귀를 변경한다.
전체 회귀·workspace Clippy·Skia3·정책 검사와 새 PR/CI/merge 후속 처리는 남아 있다.
진단·TSV·nextrun은 ignored output에만 보존하며 Git에 포함하지 않는다.

## 글꼴 필터의 기존 단위 계약 보정

기존 `system_family_membership_uses_exact_family_name`은 실제 Skia와 달리 ASCII
대소문자가 다른 이름을 누락으로 판정하도록 고정했다. 직접 Skia 실행의 독립 근거에
따라 같은 family의 원문/소문자/대문자는 허용하고 다른 접미사·누락 이름은 제외하도록
기존 단위 검사를 수정한다. 이 검사는 설치 이름 집합의 조회 계약이며 실물 문서의
위치·모양을 고정하는 렌더링 회귀가 아니다. 292개 원본 회귀의 관계형 전환이나
시각 검증 통과로 보고하지 않는다. 실제 렌더링 재확인은 계속 필요하다.

## 장식 공통 결과의 구현

한컴 face의 BAR/VEC/DYAD에 공개 MATH head의 상대 채우기 윤곽을 공통 배치에서
발행한다. shaft와 화살촉 접합은 공개 MATH connector 길이로 정하며,
9/11/16/22pt 독립 Print의 잉크 bbox·600dpi 글꼴 크기 격자와 대조한다.
VEC의 위쪽 shaft와 DYAD/BAR의 낮은 shaft를 구분하고 본체 상대 원점을 쓴다.
빈 본체와 다른 face/장식은 기존 경로를 유지한다. 사설 곡선을 복제하지 않는다.

실제 소비 경로는 `layout_decoration → LayoutKind::Decoration.outline →
SVG/Skia/Canvas 및 Paint JSON outlineGeometry → CanvasKit 공용 outline 표시`다.
기존 본체·부정·BOX 표시를 보존하고 source의 공개 윤곽이 있으면 각 backend가
같은 결과를 사용한다. `THIRD_PARTY_LICENSES.md`에 공개 MATH 부품 파생을 추가했다.

단순 글자 본체의 VEC/DYAD/BAR는 같은 논리 예약 프레임을 공유한다.
FontStyle·가로 Row·Paren에서 정체 문맥을 전달하고 독립 정상 저장의 정체
9/11/16/22pt 줄/장식 프레임을 소비한다. 다른 크기의 기존 메트릭은 유지하며
분수·첨자·다줄의 장식 본체를 font-line으로 강제 수용하지 않는다. 이 공통
프레임을 괄호 측정도 소비하므로 자연 높이 1.25em만 보고 늘인 괄호를 선택하던
차이를 같이 확인한다. DYAD의 별도 paint 원점 조건은 기존 범위를 유지한다.

새 렌더링 회귀 기대값은 아직 변경하지 않았다. #7593 기존 검사에는 추가된
공통 기하 field를 무시하는 `..`만 추가해 컴파일 패턴을 완전하게 한다.
독립 진단·실제 원본 영향 쪽의 재검증 결과를 확인하기 전에는 완료 판정하지 않는다.

## 독립 반례에서 확인한 추가 보정

정체 문맥 48개 정상 저장 job `0f8c7130-4708-48f9-bab3-e6601ceaee5c`,
Print job `7e007923-481d-4f48-85b5-48d49fee2456`은 한컴
11.0.0.9136 / engine 2020 / method 0 / one-up으로 완료됐다. 숫자·기호·
그리스 문자도 외부 정체 문맥의 줄 프레임을 사용한다. 따라서 글자 내용만 보고
정체 프레임 적용을 제거하지 않는다. `rm vec x`와 `vec {rm x}`는 16pt에서
1902/1915HU, 22pt에서 2622/2635HU로 다르다. 내부 정체는 본체의 줄 프레임을
먼저 바꾸고 장식 예약 높이에 그 차이를 보존한다. 외부 정체 프레임으로 대신하지 않는다.

9pt 독립 `rm vec {OP}+vec {OA}`의 폭은 3606HU다.
`1365 + 675 + 126 + 1440`이며 장식 뒤 연산자의 앞 여백 126HU를 다시 더하면
독립 저장 폭과 다르다. 벡터 괄호식은 앞 여백 두 개를 제거한 9738HU가 정답이며,
기존 계산 9990HU는 252HU 과다했다. 공통 `reserves_operator_gap`에 장식 점유를
반영하고 뒤 여백·명시적 공백·실제 본체 여유는 보존한다.

11c942d23의 포맷·Native/WASM Clippy·Skia check와 Studio typecheck는 통과했지만,
위 독립 근거를 얻어 잘못된 구현의 Native 빌드 완료를 기다리지 않고 이 controller의
process tree 4개만 SIGTERM으로 종료했다. 이는 quiet log/관측 timeout 때문이 아니다.
공용 target과 이전 원본 WASM queue는 보존했다. 실제 unified exec 종료는 143이고,
최종 새 source의 lint/빌드/80개 및 정체 48개 대조를 다시 묶어 실행한다.
