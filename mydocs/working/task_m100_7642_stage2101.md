# #7642 한컴 Print 팔레트의 흑백 예약색 경계 보정

## 독립 반례와 수정

[기존 계획](../plans/task_m100_7642_bitmap_tone_20261017.md)의 단순 원본 색 수 가정을
추가 Print로 재검토했다. 원본 255/256색에 흑백을 포함하는지 각각 분리했다.
24비트 BMP와 같은 픽셀의 RGB PNG·indexed PNG·indexed BMP가 아래와 같이 일치했다.
JPEG의 경계나 전체 히스토그램 대신 source와 대응하는 평탄한 내부를 비교했다.

| 실제 사용한 원본 RGB | 빠진 예약색 | 2024 Print의 회색 128 / 240 |
|---|---|---|
|256색|없음|128 / 240|
|256색|흰색만|131 / 246|
|256색|검은색만|131 / 246|
|255색|흑백 모두|131 / 246|
|255색|검은색만|128 / 240|

흑백 두 색을 합친 집합이 256개를 넘을 때 full-color 전달로 바뀌는 공통 조건이다.
이를 renderer/image_resolver/print_tone.rs의 기존 변환 한 곳에서 반영한다.
HashSet을 흑백 두 예약색으로 시작하며, RGB 채널 전달식과 alpha·이미지 효과·세대·
Print 조건은 유지한다. inline JSON·바이트 생략 후 재조회·Native fallback은 이미
같은 resolver와 SourceImageVariant 신원을 소비한다. 문서 ID·좌표·크기에 따른
분기는 없으며 팔레트 포함 여부를 파일 형식 이름으로 추정하지 않는다.

이번 보정은 원본색 bitmap의 팔레트 경계다. WMF는 합성 뒤의 surface가 같은 조건을
소비하도록 연결해야 하며 아직 해결되지 않았다. 255색 WMF DIB의 장치 축소와 같은
추가 색 생성도 source 색 목록만 세어 처리하지 않는다.

## 검증 상태와 보존

현재는 source 수정이며 새 Native/fresh WASM 검증 전이다. 앞 단계의 수식 괄호·
Clippy 보정과 함께 빌드하고 같은 원본 전체 쪽을 재출력한다. 이번 palette 입력도
같은 버전 Print와 대조한다. 합성 진단의 성공으로 기존 원본의 일치나 새 회귀 등록
자격을 대신하지 않는다. 관련 모든 쪽의 양쪽 90%·직접 판독 후 새 이름의 관계
회귀를 추가하며 기존 golden·기대값·허용치는 아직 바꾸지 않았다.

ignored stage2091~2099에 실제 명령·Print 실행 receipt·입력/PDF 해시·원본 mode·
정확한 사용 RGB 수·대응 내부 표본을 보존한다. 인증값은 기록하지 않는다.
작은 실제 HWPX·Print PDF만 이 기록과 함께 커밋하며 TSV·로그·JSON은 제외한다.
이전 source의 전체 queue와 이번 source의 재검증을 혼동하지 않는다.
