## 제출을 막는 미완료 범위

1. 편람224/226쪽 raw 하락: 주된 잔여 불일치는 오른쪽 종이 끝이다. 원본196×266mm의
   논리740.787×1005.360px에 대해 한컴 Print MediaBox는555×754pt이고 PDF raster는
   740×1006px다. 현재 PNG는741×1006px다.224쪽의 실제 불일치480픽셀 중
   오른쪽1열 등에423픽셀이 집중된다. 정렬 개선으로 content union이 줄어 raw 비율이
   하락한 사실과, 실제 원점·종이 경계 차이를 구분한다.
2. 색조 합성 진단 입력의 공개: `pdf/issue7751/`3개 PDF의 정확한 HWPX 입력은
   ignored output에만 있다. 정식 수용 근거의 입력 커밋 계약을 아직 충족하지 않았다.
  3개 입력을 Native/fresh WASM으로 직접 비교하니90% 미만이다. 예를 들어 기본
   대조군 Native50.90903%이며, Native에만 편람의 바탕쪽이 보이고 그림 행 간격도
   다르다. 이 문서 전체를 정상 회귀 fixture로 등록하거나 진단이라는 이유로
  90% gate를 면제하지 않는다.

## 독립 근거 확보와 구현 경계

- 기존 편람 원본·383쪽 Print PDF는 그대로 재사용한다. 새로 전권 인쇄하지 않는다.
- 종이 경계의 진단에서 단순 전체 축소는224/226쪽을 악화했다.600dpi 선 endpoint만
  적용한 진단은 보류를 해소하지 못했다. 종이의 raster bounds만 바꾸는 진단은
  raw가 상승했지만, 이 결과만으로 제품의 종이 크기·비교 영역을 변경하지 않는다.
  실제 Print의 MediaBox·장치 종이 계약과 Native/Canvas/PDF 소비 경로를 먼저 확인한다.
  해당 정책이 확정되면 공통 Print 원점/종이 결과를 쓰고 screen 동작과 구분해 검증한다.
- 색조 입력은 편람 틀을 수동 편집한 합성 HWPX이며 본래 실물 저장본이 아니다.
  기존 원본·실패 TSV·PNG·기존 PDF를 보존한다. 한컴의 실제 열기/저장으로 재생성한
  동반 대조군을 만들고 생성 절차·입력 변경·독립 Print의 새 SHA를 공개한다.
  동반 대조군의 통과를 이전 원본 HWPX의 일치로 바꾸어 보고하지 않는다.
- 가능하면 불필요한 기존 자원을 제외한 작은 입력을 보존하되, 파일을 바꿨으면 새
  입력을 실제 한컴으로 저장/Print하고 SHA를 고정한다. PDF의 관측값만 보고 입력을
  바꾼 뒤 동일 입력으로 표시하지 않는다. 임의 LineSeg 수용 완화도 추가하지 않는다.

## 종이 경계와 별도로 확인한 본문 폭 근거

224쪽 pi250의 실제 paint op는 KoPub바탕체 Light16px/장평99%/자간−2%다.
현재 마지막 단어 시작은481.6937px, 독립 PDF는479.8400px로 누적 차이가 있다.
엔진의 `kopub_char_width`는 바탕 계열 전각을0.94em으로 근사했다.
동일 시스템의 Light/Medium/Bold cmap+hmtx는 대상 한글 모두936/1000이며,
같은 Print PDF의 KoPubBatangLight CID 폭도598글리프가936, Medium은263개가936이다.
`kopub-batang-independent-advance.json`에 글꼴/입력 SHA와 관측을 고정했다.
이는 임의 점수 보정 계수가 아니라 글꼴 자체와 독립 PDF의 같은 메트릭이다.

공통 측정은 `kopub_char_width`의 glyph 폭을 HWPUNIT으로 양자화해 composer의
글자 전진폭·줄 구성을 만든다. 저장 줄 영역/inline pen과 실제 paint cluster가 그
결과를 소비한다. 바탕의 근사값을 실제0.936em으로 정정하고, 돋움0.872·ASCII·
공백·개별 기호의 기존 경로는 유지한다. 이미 별도 조건에서 처리하는 기호를
전각 상수 변경의 근거로 섞지 않는다. 문서 ID나 특정 글자 조합 분기는 추가하지 않는다.

먼저 Native 영향8쪽을 독립 PDF와 비교해 누적 폭이 줄어드는지, 완료 경계와
글줄 소속이 보존되는지 확인한다. 이후383쪽 양쪽 TSV·기존 회귀·최종 lint를 다시
판정한다. 이 정정으로 종이 크기를 줄이거나 비교 영역을 crop하지 않는다.

## 한컴 저장 대조군의 실제 RGB 결함 보정

기존 수동 HWPX는 미달 증거와 함께 보존하고 한컴2024에서 실제 HWP로 저장한
동반 대조군3개를 새로 인쇄했다. 모든 대조군의 Native/fresh WASM 전쪽 raw는90%
이상이지만 RGB를 직접 읽으니 일반 회색조에 Canvas가 워터마크 투명도를 적용했다.
정식 수정 전 브라우저 검사는 행8 검정 패치 Print0에 대해 실제212로 실패했다.

원인 경로는 `image_resolver::is_watermark_image`의 OR 판정 → Canvas JPEG bake/
legacy opacity0.17이었다. 모델·ImageNode의 공통 판정은 두 색조 값이 모두 비영인
경우다. 공통 predicate를 사용하며 한쪽만 바꾼 일반 회색조·흑백을 제외한다.
진짜 워터마크(B/C 모두 비영)의 기존 분기는 유지한다.

흑백은 Native/Canvas의 필터 중첩 순서가 달랐다. 새 저장본의 B=0/10/50 독립
PDF 이미지11패치는 회색 바이트 → 밝기·대비 → 128초과 흰색 순서다. B50에서도
원본검정은 검정으로 남는다. 반올림해 흰색으로 만들지 않는다. 기존 공통
`adjusted_picture_bytes`가 일반 흑백의 색조와 이산화를 한 번 수행하게 하고 모든
backend가 이미 사용하는 이 producer를 소비한다. 두 색조가 모두 비영인 legacy
흑백 워터마크와 미지원 입력의 Direct PDF fail-closed 경계는 확대하지 않는다.

Windows의 실제 KoPub GDI 측정도 성공했다.600dpi의 −100/width91 글자는93단위,
−83/width75는76단위다. 이것만으로 기존1800dpi 공통 양자화나0.94를 교체하지
않는다. `.936` 후보는 앞서 전쪽 반례로 철회한 상태다.
