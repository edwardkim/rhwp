## 변경 전 근거

현재 생산 코드 `810654da2af51c727bf639c3c6ecec8595d3c5f2`는 테스트 head `27e97e96d89e2c5f1b3b2451f48994880234d53a`와 같다. 고정 upstream은 `2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`다. 전체 회귀의 17개 실패 원문은 ignored `stage1348-current-failure-inventory.json`에 있다. 세 HWP5 기대값 오류는 단계 1351에서 독립 Print와 전쪽 검증 뒤 새 검사로 대체했으며, 다른 실패는 해결했다고 보고하지 않는다.

### 저장 줄의 실제 단 경계

- `samples/21_언어_기출_편집가능본.hwp` / 독립 `pdf/issue7642-exam-print/exam-01-21_언어_기출_편집가능본-hwp-print-2020.pdf`의 10쪽은 Native base 99.24317% → 현재 89.40182%, 현재 fresh WASM 89.31357%다. 이 하락은 현재 구현을 보정해야 하는 회귀다.
- 원본 문단 211은 17개 저장 줄이며 16번째 줄의 `vertical_pos`가 89644에서 0으로 되감긴다. 마지막 2개 줄만 보면 다시 증가한다. 현재 출력은 16개 줄로 재구성해 후속 문단 212와 별도 글상자를 한 줄 위로 당긴다. base는 원래 17개 줄을 보존한다. 문단 식별과 줄 시작은 원본 내용·저장 정보에서 얻었다.
- `stored_word_tail::can_rejoin_stored_word_tail`은 마지막 두 줄만 검사해 문단 전체가 같은 물리 프레임이라는 가정을 한다. 같은 문단의 앞쪽 단/쪽 경계도 확인해야 한다. 단일 `LayoutFrame`의 캐시 수용 실패 역시 여러 물리 프레임의 저장 경계를 하나로 재작성할 근거가 아니다.
- 추적: 원본 LineSeg → `stored_cell_reflow.inc.rs`의 단어 꼬리/저장 줄 판정 → `line_breaking::resolve_stored_line_segs_in_frame` → frame 줄 분할 → `FormattedParagraph`와 실제 본문 배치. 꼬리 판정만 막고 뒤의 일반 cache-miss fill이 다시 평탄화하면 해결이 아니다. 두 소비 지점에서 같은 물리 프레임 소유 판정을 사용한다.
- 편집으로 저장 분할이 무효해진 경우, 저장 정보가 이미 stale인 경우와 한 프레임 안의 자동 어절 나눔은 별도 경로로 유지한다. 문서명·문단 번호·좌표값을 구현 분기로 사용하지 않는다.

### HCI Poppy 원본 전진폭의 우선순위

- 독립 HWP3 Print Type3의 원본 regular 전진폭은 `font_metric_hci_poppy.rs`에 em=1000으로 보존돼 있다. `O=785`, `/=605`다. 글꼴 표시용 대체는 Palatino이며 두 프로그램을 구분한다.
- 현재 전역 메트릭 색인의 첫 이름 우선 정책에서 upstream의 HCI Poppy 일반 overlay(em=2048, Palatino ASCII + 확인된 가운뎃점)가 뒤쪽 원본의 부분 측정 표를 가린다. 공개 `O/O` 계약에서 관측 비율은 0.40952로 독립 605/785와 다르다.
- 전역 표의 순서를 바꾸거나 다른 em의 폭을 u16으로 합치지 않는다. 확인된 source 프로그램의 해당 문자·정체에만 원본 표를 선택하고, 미측정 문자·bold/italic·별도로 확인한 가운뎃점은 기존 경로를 유지한다. `measure_char_width_embedded_decision_for_font`을 통해 줄 채움·최종 문자 전진·paint의 공통 측정 출처를 연결한다.

### 한컴 2024 Print의 cosmetic 선 coverage

- 실제 Windows GDI로 생성한 15개 입력과 독립 한컴 2024 Print에서 cosmetic 펜은 RGB bitmap과 별도의 명시적 binary mask를 함께 출력한다. geometric 펜은 정상 대조군이다. 원본 PDF와 입력은 `pdf/issue7642-gdi-device-pen-diagnostic-20261015/`에 보존했다.
- 현재 Native 15쪽 최저 92.66247%, fresh WASM은 9쪽 미달·최저 54.25202%다. SVG intrinsic 크기, 600dpi 중간 bitmap, 보간 변경만으로 해결되지 않았다. 그 진단을 제품 수정이나 정식 시각 증거로 사용하지 않는다.
- 원본 p7 선 영역에서 PDF의 최소 회색은 242·잉크 합은 5157이다. 원본의 별도 mask만 제거한 진단 사본은 각각 198·67386으로 크게 달라진다. 기준 PDF는 수정하지 않았다. 같은 SVG 경로에 별도 coverage mask를 적용한 브라우저 진단은 15쪽 모두 점수 100%이며 p7 최소 회색 249·잉크 합 3494다. 점수 100%가 농도 완전 일치를 뜻하지 않는다.
- 계획: 명시적인 2024 Print의 `OutputDevice` payload 경로에서만 별도 geometry coverage를 재생한다. 한컴 2020 벡터·일반 SVG·geometric 펜·원래 색과 opacity는 보존한다. 마스크 경계는 각 정규화 경로와 stroke에서 계산하며 페이지 좌표나 문서별 상수를 쓰지 않는다. 단순 진단의 root viewBox 범위를 제품 계약으로 복사하지 않는다.
- 추적: Print profile의 장치 픽셀 → EMF device path의 출력 좌표 정규화 → `paint::metafile`의 payload/RawSvg → Native/fresh WASM image 소비. 둘 모두 같은 payload를 읽는지 확인한다. 음수/이동·비등방 변환, stroke/fill과 clip의 의미도 검토한다.

## 검증 계획과 제한

세 원인의 수정 방향을 정리한 뒤 공용 `target/pr-review`·빌드 잡 8개로 묶어 빌드한다. 지금 실행 중인 고정 upstream fresh WASM 빌드와 Cargo를 겹치지 않는다. source SHA와 producer를 고정하고 해당 원본의 Native/fresh WASM 전쪽 TSV·쪽수·직접 확대 판독을 다시 수행한다. 언어 문서의 원래 10쪽뿐 아니라 전 15쪽과 두 단의 내용·줄 소속·후속 문단을 확인한다. GDI 대조군은 전 15쪽의 실제 색/농도·전체 도형을 확인하며 경계를 잘라 점수를 올리지 않는다. HWP3 sample16 전쪽과 기존 글꼴 대조군도 다시 확인한다.

원본이 전쪽 90% 이상이 되기 전에 새 실물 회귀나 golden을 등록하거나 실패 기대값을 바꾸지 않는다. 통과 후 새 이름의 소속·내용·분할 관계 검사를 만들고, 양쪽 98% 이상과 확대 판독이 끝난 중요 쪽에 독립 Print ±2px 검사를 추가한다. 기존 미달 문서를 평균이나 font 예외로 정상 golden으로 고정하지 않는다. 수정 전 실패·수정 후 통과와 정상 대조군을 연결한다.

실행 로그와 중간 JSON/TSV는 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`의 `stage1357-*` 이후 원장에 보존한다. 전체 원래 71문서/1110쪽, 다른 회귀 실패, lint·frontend·최종 CI/PR/옵션 2 후속 처리는 여전히 완료 전이다.
