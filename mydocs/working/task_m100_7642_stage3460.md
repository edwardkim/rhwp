# #7642 재조판으로 무효화된 첫 표 조각의 예산 허용 제거

## 독립 계약과 원인

`mark_table_text_reflowed_after_edit`의 기존 계약은 live 재조판이 저장 조각 프레임을
대체한다는 것이다. 쪽 나눔·저장 되쓰기·다른 source-frame 소비자는 그 overlay의
유효성 결과를 사용한다. `fragment/budget.rs`의 첫 조각 생산만 이 검사를 빠뜨렸다.

`stage3458`의 실제 작은 셀 편집은 문단 1136, 행 4에서 남은 내용 예산 2.02667px에
21.33333px짜리 첫 줄을 골랐다. 저장 첫 조각 허용치로 수용해 `consumed=386.94667`이
실제 행 예산 367.64px를 넘는다. 본문 위에 이미 예약된 앞 행과 각주 경계는 그대로다.
이는 정상적인 본문·셀 포함 검사를 느슨하게 만들 사유가 아니다.

`stage3459`는 원본 IR을 그대로 clone해 새 Core에 넣으면 첫 표 조각 315.70667px,
live 편집 Core는 379.18667px임을 확인했다. HWPX의 문서 profile은 session_edited=false,
IR의 cell/paragraph dirty flag도 false다. 이를 편집하지 않았다는 근거로 쓰지 않는다.
이 사례의 실제 reflow 소유는 기존 render-normalization 논리 표 키가 보존한다.

## 생산·소비와 수정

셀 편집 → `mark_table_text_reflowed_after_edit` → overlay pointer 등록 →
`saved_first_fragment_source_frame` 생산 → 최근접 행 끝·첫 조각 overflow 허용 →
`scan/runner/row_step.rs`의 줄 수용 → 조각 배치 순서다.

첫 source frame 생산에서 같은 overlay의 `table_text_reflowed`를 확인한다. 무효인
프레임은 다음 소비자에 전달하지 않는다. 현재 좌표가 맞는다는 사실을 과거 내용의
첫 프레임이 유효하다는 증거로 대신하지 않는다. 원본 단위, 줄 높이, 실제 각주·본문
예산과 source 유효 저장본 경로는 유지하며 새로운 수치·문서 예외를 추가하지 않는다.

## 검증 범위

마지막 행 접기의 셀 소유도 함께 보정한다. 기존 코드는 원본 rowspan의 마지막 행이
현재 마지막 행과 같을 때만 셀의 내용·안 여백을 접기 상한에 넣고 상자를 갱신했다.
현재 조각 밖으로 계속되는 병합 칸도 같은 마지막 물리 행을 소유하므로 같은 소유
판정으로 실제 여분을 계산하고 같은 행 띠만큼 상자를 갱신한다. 일반 칸·교차 병합 칸의
테두리가 서로 다른 끝을 갖지 않게 한다. 내용·여백의 기존 상한을 보존하고,
실제 수용 행과 셀 소유를 재사용하는 작은 모듈로 범위 계산을 공유한다.

`stage3458`의 축소 입력에서 원래 접기 4.64px는 일반 칸만 보고 정한 값이었다.
교차 병합 칸의 선택 글줄·여백도 같은 계산에 참여시킨다. 접기 전 행 높이와 이후
continuation 원장의 물리 소비가 같은지, 앞·뒤 조각의 누락·중복·클립을 함께 확인한다.
기존 큰 함수에는 이 소유 조건 호출과 source 유효성 guard만 추가하며 새 코드는
작은 모듈에 둔다.

아직 수정 후 실행 전이다. 두 보정을 묶음 검증한다.
기존 소스의 52건 중 2건 실패는 보존하고 source `e579f10ecd`의 결과를
수정 후 PASS로 쓰지 않는다. 새 Native/fresh WASM 전쪽 Print 검증·직접 판독 전에는
새 렌더링 회귀·fixture/golden을 추가하거나 기존 기대값을 바꾸지 않는다.

작은 편집 저장본 Print는 215쪽, 성장 편집 Print도 215쪽이지만 성장 live는 216쪽이다.
같은 내용이라도 live·clone·저장 재열기의 조판 상태가 달라 위 Print로 live 일치를
선언하지 않는다. `stage3446/3452/3458/3459`의 입력·Print·로그·PNG는 ignored output에
보존한다. 원래 전체 문서 범위와 CI/PR/후속 처리도 계속 남아 있다.
