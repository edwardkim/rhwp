# #7642 Stage 146 — 재정렬 요청의 캐시 수용과 높이 소비

Issue: #7642

## 구현 전 근거

기준 head는 `7101483c96e26ba7ae90c70431ade9de92c7ff1e`다. 원본
`samples/issue5699/20099369_yeongwol_forms.hwp`와 독립 한컴 2020 Print의 전4쪽
Native 최저값은 30.65792%다. 한컴의 정상 저장 HWPX를 같은 Print로 비교한 진단은
최저 99.29419%다. 원본과 기준은 보존하며 정상 저장본으로 원본 통과를 대신하지 않는다.

원본의 조건9·안전사고 안내는 각각 한 줄로 압축되고, 독립 Print와 정상 저장본은 각각
두 줄이다. 뒤쪽 서식 표제가 이전 쪽에 남는다. 현재 재정렬 요청은 탭과 legacy 원점
수용에는 전달되지만 일반 저장 줄의 캐시 판단에는 전달되지 않는다. `stored_rows_are_stale`
의 일반 과밀 허용치를 전역 변경하지 않고 실제 출처의 요청을 공통 수용 경로로 전달한다.

## 생산과 실제 소비 경로

- 생산: 원본 헤더 요청 → `Document::layout_profile` → 출처별 저장 기하 정책.
- 수용: `composer/stored_cell_reflow.inc.rs`의 body/cell/probe 공통 재구성 →
  `line_breaking.rs::resolve_stored_line_segs_in_frame`의 캐시 수용 또는 실제 Frame 채움.
- 측정: `HeightMeasurer` 및 `typeset/paragraph/format.rs::recompose_for_flow`.
- 배치: `layout/paragraph_layout.rs` 및 table/cell 소비 경로.
- 마지막 덮어쓰기: `format_paragraph_for_flow`의 `height_for_fit`은 원본 저장 vpos의
  한 줄 span과 새 두 줄 높이 중 작은 값을 선택할 수 있다. 새로 채운 줄에는 그 원본
  span을 적용하지 않고 새 줄 구성의 점유 높이를 소비한다.

정책은 HWP3 원점 보존과 외부 재정렬 요청을 별개 값으로 전달한다. 기존 bool 호출은
기존 원점 계약으로 변환하고 요청 없는 입력의 동작을 유지한다. raw LineSeg·본문·서식은
고치지 않으며 요청을 편집 상태나 synthetic LineSeg로 위장하지 않는다. 프레임이 소유하지
못하는 split/exclusion·별도 개체 경로는 기존 사양과 비해당 근거를 유지한다.

## 대조와 완료 조건

영월 원본 전4쪽과 같은 탭·셀 순서·격자 대조군 전5쪽을 먼저 Native에서 재출력한다.
조건9·안전 안내의 줄 소유/내용 보존, 서식 표제와 표의 쪽 소속, 셀 줄바꿈·표 바닥을
직접 판독한다. Native에서 남은 큰 차이를 고친 뒤 fresh WASM과 전체 범위를 검증한다.
Native/fresh WASM 90% 및 확대 판독 전에는 새 회귀나 기존 기대값·golden을 변경하지 않는다.
로그·TSV·JSON·nextrun은 ignored output에 남기고 검증 뒤 코드와 실제 결과를 함께 커밋한다.

## 1차 실행에서 확인한 다음 소비 지점

1차 Native 빌드는 exit 0이며 source 해시가 실행 전후 일치했다. 조건9·안전 안내는
각각 두 줄로 재구성됐고 1쪽 점수는 70.7331%에서 81.75240%로 개선됐다. 다른 세
쪽과 표제의 쪽 소속은 아직 미달이다. 탭·셀 순서·격자 대조군은 이전 점수를 유지했다.

원본 첫 표는 글자처럼 취급되는 표다. 표의 실제 상자는 정상 저장본과 대응하지만
복수 inline 표 경로의 `layout_inline_table_paragraph`에는 실제 줄 상자에 따른
흐름 계산이 필요하지만, 영월 단일 TAC 표는 이 경로를 사용하지 않는다. 그 때문에 표의 아래 바깥여백과 줄간격이 사라졌다. 독립
저장본은 표 선언높이와 위·아래 바깥여백을 합한 줄 상자 및 별도의 후행 줄간격을 기록한다.
이 관측값은 진단 근거이며 특정 px 보정값으로 사용하지 않는다. 실제 각 표의 배치 하단과
아래 여백을 모아 줄 상자 끝을 계산하고, 그 끝에 줄간격을 잇는다. 기존의 유효한 저장 줄
배치와 재정렬 요청이 있는 경로를 구분하며 측정·배치의 공유 geometry 반환값을 함께 바꾼다.

외부 생성·재정렬 요청에는 한글97의 마지막 줄 배치를 가정한 1600 HU 허용치를
추가하지 않는다. 파일의 용지 여백은 유지하고 저장 왕복의 origin 복원에서도 요청을
보존한다. 요청 없는 대조군의 기존 허용치는 유지한다. 2차 Native 출력으로 서식 표제의
쪽 소속과 앞뒤 내용을 다시 확인하며, 큰 차이가 남으면 완료로 판정하지 않는다.

## 2차 실행과 단일 TAC의 실제 소비 경로

2차 Native 전9쪽은 탭 99.38884%, 셀 순서 99.53058%, 격자 최저 98.39623%다.
영월 원본은 82.61235 / 100.00000 / 97.96134 / 100.00000%이며 전4쪽이다.
Native Clippy는 exit 0이다. 1쪽은 아직 미달이므로 완료·회귀 추가 조건을 충족하지 않는다.

실제 `RHWP_TABLE_DRIFT` 출력에서 첫 표는 182.9..580.5에 배치됐지만 표 host의
흐름은 200.2까지 되돌아갔다. `layout_table_control_block`의 HWP3 저장 사다리 보정이
재정렬 요청에도 적용됐기 때문이다. 다음 문단은 실제 표 하단으로 복구되지만 이미
버린 후행 줄간격과 아래 여백은 복구하지 않았다. 이 값은 진단이며 상수 보정에 쓰지 않는다.

3차 변경은 재정렬 요청에서 그 저장 사다리를 수용하지 않는다. 실제 표 하단과 기존
후행 줄간격·아래 바깥여백의 소비를 유지한다. `typeset/table/host_spacing.rs`에 같은 간격을 추가하는 3차 실험은 아래에서
중복 소비가 확인되어 철회했다. 기존 문단의 후행 간격 소비를 유지한다. 요청 없는 대조군의
저장 사다리와 간격 분배 계약은 유지한다. 모든 쪽과 직접 PNG 판독으로 결과를 재검증한다.

## 3차 실행의 쪽수 회귀와 중복 소비 제거

3차 Native 빌드와 Native Clippy는 exit 0이다. 실제 배치 로그에서 첫 표 host는
실제 하단 뒤로 전진하고 다음 문단 원점은 정상 저장본과 대응했다. 다만 전쪽 출력은
5쪽이며 독립 Print는 4쪽이어서 gate 미충족이다. 이 실행의 PNG/TSV는 생성하지 못했고
수집기도 TSV 부재로 exit 1이었다. 수집기 상태는 실제 종료 결과로 정정했다.

추가 추적에서 `typeset.rs::place_table_with_text`의 마지막 TAC 후행 처리는 이미
`fmt.total_height - fmt.height_for_fit`를 소비했다. 3차 `host_spacing`의 TAC 양의
줄간격 가산은 그 간격을 두 번 예약했다. 같은 원래 문단 간격을 표 높이에 다시 합산하는
변경을 제거했다. 최종 흐름은 실제 표와 바깥여백의 기존 예약 + 문단의 기존 후행 복원,
paint는 실제 표 하단 + 후행 간격이며, 요청된 원본의 잘못된 저장 사다리 덮어쓰기만 제외한다.
4차에서 쪽수·전체 TSV·대표 PNG를 다시 확인한다. 첫 정상 저장본의 속성을 구현 기대값으로
재인용하지 않고 원본 독립 Print로 최종 출력을 판독한다.

## 4차 Native 결과와 남은 범위

4차 Native 빌드 exit 0, Native Clippy exit 0이며 각각 source 해시가 실행 전후 일치했다.
전9쪽 Native TSV는 탭 99.38884%, 셀 순서 99.53058%, 격자 최저 98.39623%다.
영월 원본은 전4쪽 99.26310 / 100.00000 / 99.19799 / 100.00000%로 Print의 4쪽과
일치한다. 최초 1쪽의 저장 사다리 역행과 후행 간격 누락은 독립 Print 대조에서 개선됐다.

원본 첫 표 뒤 계약조건·서명 원점, 조건9·안전 안내의 두 줄, 2·3·4 서식의 쪽 소속을
직접 새 review/overlay에서 확인했다. 괘선 잉크 두께·일부 글자 모양 차이는 남는다.
대표 Native PNG는 `mydocs/pr/assets/issue7642-hwp3-row-flow-20261012/`에 보존한다.
바이너리 SHA-256은 `dc3da30218ab08821c8cb95a96dccb2da9d9b891f8b8eb012053a710760206bd`다. 원본 입력·기준 PDF·명령·TSV·실제 exit는
ignored `stage146d-realign-preflight/receipt.json`과 연결한다.

복수 inline 표 geometry의 재정렬 분기는 이 원본 단일 TAC 실행의 증거가 아니다.
해당 적용 경계는 아직 미검증이며 최종 범위 검증에서 별도로 확인한다. fresh WASM,
새 이름의 관계형 회귀, 실패 회귀 전체 보정, 전체 Native/WASM와 필수 lint 묶음은 남았다.
이번 단계의 Native 성공만으로 PR 준비 완료를 선언하지 않는다.

종료된 Stage141 전쪽 스윕의 재생성 가능한 SVG 중간 파일 63개, 7,155,232,642바이트를
정리해 디스크 여유를 약 13GB로 확보했다. 원본/PDF/TSV/log/PNG/render tree와 공유 target은
보존했고 삭제 경로·실제 결과는 ignored `stage146c-obsolete-svg-cleanup.json`에 남겼다.
