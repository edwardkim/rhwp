## 확대 판독으로 확인한 두 원인

1. #1880 12쪽 하단 문구는 원본 `바탕체`, 독립 PDF의 `BatangChe`인데 Native 출력이 고딕 형태였다. Skia는 원 face·설치 별칭 이후에 고정 Noto Sans 우선 목록을 사용했고, SVG/Canvas는 원 서체에 맞는 공통 generic 정책을 사용했다. Skia도 그 기존 정책의 서체 분류와 굵기를 소비하게 한다. 요청 이름과 명시한 대체 face 순서는 유지하며, 문서 ID나 좌표로 글꼴을 선택하지 않는다. 고딕·명조·굵은 글꼴 대조군과 실제 출력을 재확인한다.
2. 보도자료의 첫 표 호스트는 정상 구역 시작 문단이며 구역정의·단정의·쪽번호 위치·표를 가진다. 단계 737의 원본 줄 검사에서 모든 break 비트를 금지하고 쪽번호 설정을 배제해 단 첫 프레임을 수용하지 못했다. 빈 새 단을 소유한 호출 경로에서만 원본 구역 시작을 허용하고, 줄·표 높이·뒤 저장 줄의 닫힘 계약을 유지한다. 명시 쪽/단나누기, 편집·합성 줄, 실제 앞쪽 내용은 여전히 별도 계약이다. 쪽번호 위치는 본문 글줄을 점유하지 않는 설정이다.

## 중요 px 검사 준비와 후속 검증

- #1880 12쪽의 독립 Print에서 하단 문구 x=75.52px, 기준선 y=1012.48px 및 `Ⅱ급비밀용` 표 왼쪽 330.22267px, 상단 495.93733px, 하단 547.24133px를 읽었다. 모두 96dpi CSS 좌표다. 표는 PDF의 선분 좌표를 사용하며 현재 구현 좌표를 기대값으로 복사하지 않는다.
- 같은 페이지의 소속·원본 문자·표 구조·순서·본문 포함·비겹침을 함께 검사하는 새 이름의 초안을 ignored output에 준비했다. 99.86%여도 글꼴 형태 차이가 보였으므로 아직 정식 px 회귀를 등록하지 않는다. 이번 보정 이후 양쪽 98% 이상과 직접 판독 및 관련 전쪽 90% 이상을 확인한 후 ±2px 검사로 추가한다.
- Skia 글꼴 선택과 구역 시작 수용을 한 source 배치로 묶는다. 공용 target 빌드는 순차 실행하며 잡 8개를 유지한다. 정확한 새 source에서 lint·집중 회귀·Native/fresh WASM·고정 devel 기준 대조를 수행하고, 미달 쪽과 확대 판독의 남은 차이를 계속 보정한다.
- 오늘할일·PR review trailing 기록은 PR 채번 및 정확한 code head CI 성공 이후에 작성한다. 현재 전체 검증과 PR 준비는 완료되지 않았다.
