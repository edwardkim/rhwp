# #8856 정책연구 서식의 하단 줄 소유 보정

## 선행 해결과 독립 재현

원 PR #8662는 #8639의 변경 추적 설정·줄 끝 공백·TAC 높이를 처리했으며 통합 #8857의
`edbd510677`에 반영됐다. flags 0 서식의 원본 프로그램 재조판과 flags 8/56의 저장 줄 유지는
서로 다른 계약이다. 이 단계는 앞 단계 `33836ac0c0` 뒤에 시작하며 기존 구분을 유지한다.

원본 `samples/issue8639/policy_research_review_request-trackchange0.hwpx`와 기존 2024 Print
PDF를 그대로 사용한다. 한컴 2024 13.0.0.3901에서 동일 입력을 다시 Print해, 하단 첫 줄은
`포상금`까지이고 다음 줄은 `지급(`에서 시작함을 확인했다. 기존 PR 본문의 해당 줄 설명과
실제 PDF 텍스트가 달라 실제 PDF·재인쇄를 우선했다. PDF·원문·기준 점수는 바꾸지 않는다.

저장 경계만 51→40으로 바꾼 작은 대조군을 flags 0/8로 각각 Print했다. flags 0은 바꾼
저장 경계를 무시하고 같은 `포상금 / 지급(` 경계를 만든다. flags 8은 변경한 저장 경계를
보존한다. 두 입력 모두 내용·전체 쪽수는 유지했다. 이 실험으로 현재 저장 줄을 무조건
지우거나 모든 문서의 재조판을 강제하지 않는다.

## 현재 원인과 검증 범위

하단 문단의 뒤쪽 `․`를 ASCII 마침표로만 바꾼 진단은 앞줄 소유를 정상화했다. 이 진단은
서로 다른 입력이므로 개선 점수나 원본 수용 증거로 사용하지 않는다. 현재 원 프로그램
검증은 KoPub Light의 확인한 문자 범위만 허용하고, 이미 실제 측정 경로에서 확인된
결측 글리프 공급자의 폭도 무시해 문단 전체를 저장 줄로 돌린다.

원문 `KoPub돋움체 Light,한컴바탕`의 U+2024는 KoPub 프로그램의 확인된 cmap 결측이다.
독립 PDF는 그 기호만 Haansoft Batang으로 그린다. 공통 폭 생산이 실제로 선택한 공급자가
같은 선언 체인에 있고 확인한 글리프·폭 hit일 때만 재조판의 검증 범위에 포함하도록 검토한다.
폭 표 미수집·일반 OS 폴백·미확인 공급자를 근거로 원본 글꼴 전체를 인증하지 않는다.

새 관계형 검사는 최소 글꼴 환경에서 실제 0 PASS / 1 FAIL이었다. 내용 누락·중복은 없으나
`포상금`이 뒤쪽으로 밀렸다. 검사 파일은 `tests/cases/issue_8856_policy_field_line_ownership.rs`다.
이후 실제 보정·전쪽 검증은 아래에 구분했다. 최종 제출 게이트는 미완료다.
진단 입력·Print·로그는 `output/issue8856/policy-width-oracle/`에 둔다.


## 보정과 실제 검증

기존 공통 폭 결정의 `declaredGlyphFallbackMetric`·글리프 hit를 소비한다. 원 프로그램의
확인된 cmap 결측, 동일 선언 체인의 공급자, 기존 폭 결정의 실제 공급자가 모두 일치할 때만
부분 검증에 포함한다. 일반 OS 폴백이나 미수집 표는 인증하지 않는다. glyph 전진폭 표·원문·
PDF·판정 문턱을 바꾸지 않았다. flags 8 저장 줄과 미확인 U+0378의 보수적 경계도 보호했다.

최소 글꼴 환경의 관계·정상 대조군은 19 PASS / 0 FAIL이었다. 기존 #8639 2건,
#7765 5건, 표시 치환 후 원본 공급자 1건과 폭 coverage 8건을 포함한다. 최종 새 관계 검사의
3건도 다시 통과했다. 실제 Native 1쪽은 97.75797% → 99.99813%, fresh WASM은
97.78365% → 99.99259%로 개선됐다. 같은 쪽 review/overlay에서 포상금·지급의 위치와
두 하단 필드의 간격을 직접 확인했다.

양쪽이 98% 이상인 완료 쪽이므로 별도 고정형 검사
`tests/cases/issue_8856_policy_field_print_positions.rs`를 추가했다. 기존 관계 검사는 유지한다.
독립 PDF의 근/포/지 문자 원점을 96/72로 환산한 ±2px 기대값이다. 원래 composer 호출
지점에서 실제 0 PASS / 1 FAIL(포상금 x=212.34667px, PDF=670.35669px)을 확인했다.
추가한 미사용 검증 helper 정의는 둔 채 원 호출점만 복원해 원인 경계를 재현했다.
이후 후보를 복원해 source hash 일치와 실제 1 PASS / 0 FAIL을 확인했다. 이 임시 상태는
최종 후보에 남기지 않았다. 과거 잘못된 좌표나 후보 수치를 기대값으로 옮기지 않았다.

최종 source의 Native/fresh WASM을 각각 9문서군·219쪽 전쪽 산출했다. 직전 단계에서
바뀐 것은 양쪽 모두 정책 서식 1쪽뿐이며, 나머지 218쪽은 경로별 기존 raw 점수를 유지했다.
90% 미만·쪽수 누락·새 하락은 0쪽이다. 이 전쪽 결과는 다른 #8856 잔여의 해결을 뜻하지 않는다.
루트 pkg·Studio public·새 Chrome 초기 GET 응답의 JS/WASM hash가 모두 일치하고,
관측 request PNG는 같은 최종 WASM 산출물과 바이트가 같다. Mac `--no-opt` 로컬 대체
빌드이며 Docker 최적화 통과로 보고하지 않는다.

재인쇄의 665개 글자 원점은 기존 PDF와 전부 같았다. 두 flags 대조군도 원문 글자별
개수와 전체 1쪽을 보존했다. 진단 입력·Print는 `pdf/issue8856/policy-*`에 보존하며,
각 측정의 입력과 실제 Print method 0·13.0.0.3901은 영수증에 연결한다.
