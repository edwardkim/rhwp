# Stage 101 — 벡터 장식·bullet의 독립 프레임과 실제 표시 원점

Issue: #7642. 이전 구현 source는 `3d89e1f454f5c42a7b4bf9796287e35eab117a00`다.
전체 55원본/853쪽, 요청 회귀 292개와 #1139 전체 관계형 전환 목표를 유지한다.
HML 수식의 명시적 제외를 유지하고 기존 검사·원본을 제거하지 않는다.

## 원인 조사와 독립 기준

2022년 9월 HWP 전쪽은 90% 이상이나 20쪽 벡터·bullet 영역에서 기준선과 기호
크기 차이를 확인했다. 실제 EquationNode의 원문 구문·미주 소유로 선택했으며 특정
문서 좌표나 절대 px 영역을 정식 회귀 selector로 사용하지 않는다. 좁은 crop과
인접 행이 일부 섞인 확대 점수를 수식 단독의 최종 판정으로 섞지 않는다.

현재 장식 배치는 일반 `0.25em` 상단 여유를 쓰고 원래 glyph 원점에 더한다.
원본 저장 프레임과 본체 기준선의 실제 소비는 `layout_decoration → layout_row/Paren →
layout_for_paint → SVG/Skia/Canvas/Paint JSON`에서 추적한다. DYAD에는 paint 원점의
별도 조건이 있으므로 이름이 비슷하다는 이유로 VEC에 같은 조건을 적용하지 않는다.
bullet은 공개 face의 일반 glyph로 표시된다. 독립 Print의 논리 전진과 실제 ink 크기·
수학 축을 대조하며 private font의 곡선을 코드에 복사하지 않는다.

## 실행 계획

9/11/16/22pt에서 VEC/DYAD/BAR, 정체/이탤릭 본체, bullet/CDOT의 단독/이항,
장식 유무의 동일 괄호식을 함께 정상 저장·Print한다. 크기·baseline·LineSeg가 없는
입력을 한컴에서 재생성하고 원문·BaseUnit·실제 버전·method 0·one-up·입출력 해시를 확인한다.
MCP canonical client의 start/status/download를 쓰며 분석 HWPX는 로컬 export로 구분한다.

독립 PDF 문자 원점/기호 ink와 저장 frame을 대조해 공통 결과를 마련한다.
측정과 최종 paint가 같은 자식 기준선·장식 원점을 소비하게 하고 특정 구문·문서·숫자로
출력을 clamp하거나 숨기지 않는다. 일반 장식/지원하지 않는 본체의 대조군도 유지한다.
수정은 묶어서 적용하고 lint/빌드 후 동일 진단과 원본 영향 쪽을 함께 비교한다.
같은 source의 전체 Native/fresh WASM TSV와 확대를 충족한 뒤 관계형 회귀를 변경한다.
현재 source의 전체 queue는 비교 증거로 유지하고 코드 변경 뒤 새 증적과 구분한다.
전체 필수 검증·새 PR·CI·merge 후속 처리는 미완료다.

## 독립 산출과 이번 보정

48개 크기·스타일 진단의 정상 저장 job은 `e6a974e8-b515-406c-ad4a-c3344be878f5`,
Print job은 `9473f36a-ad3a-4311-a89f-1b0dae49c30e`다. 장식 본체 32개 대조군은
저장 `b599ad0e-cb8d-449d-92d5-bf289839d52d`, Print
`d69615b4-ca03-449f-8288-82d7196787e2`다. 두 Print 모두 engine 2020,
한컴 `11.0.0.9136`, method 0, `hancom2020_pdf_driver_one_up`을 확인했다.
원문·BaseUnit 80개는 로컬 분석 HWPX와 대응한다. HWPX는 MCP 산출물이 아니다.

Print의 BULLET은 `∙`(U+2219), CDOT은 `⋅`(U+22C5)다. 기존 `•`/`·` 매핑을
수학 기호로 수정한다. 설치 HYhwpEQ의 두 기호는 모두 UPM 1024에서 전진 1024이며,
9/11/16/22pt의 독립 Print 전진은 한컴 논리 em과 대응한다. BULLET의 이항 여백은
명목 크기의 좌우 0.14em이고 CDOT에는 자동 여백이 없다. 9pt `x bullet y`의
독립 저장 폭 2127HU는 `525 + 126 + 900 + 126 + 450`이며 CDOT은 1875HU다.
공통 `row_children`이 기호와 여백을 발행하고 각 backend는 같은 자식 상자를 소비한다.
글꼴은 설치 face를 사용하며 사설 글꼴 바이트·윤곽을 코드에 포함하지 않는다.

VEC/DYAD/BAR는 독립 저장에서 본체 폭에 논리 em의 0.1배를 더한다. OP/x,
복합 가로 줄, 내부/외부 첨자, 분수·한글 대조군의 네 크기를 함께 확인했다.
장식 본체의 좌우 0.05em을 공통 배치에 추가하고 backend의 기존 `body.x` 중심 소비와
연결했다. 높이·기준선·화살표 모양의 보정은 아직 완료되지 않았다. PDF 텍스트 추출의
shaft font-size는 가로 장평을 포함한 값이므로 세로 크기로 직접 사용하지 않는다.
실제 PDF content의 `Tf`·`Tz`·`Tm`을 대조해야 한다.

변경 전 source `3d89e1f45`의 48개 직접 Skia 진단은 최소 59.48712%로 미달이다.
이는 Native SVG/fresh WASM의 최종 통과 증거가 아니다. 새 구현의 빌드·시각 비교를
진행하며, 회귀 기대값은 아직 변경하지 않았다. 기존 source 전체 TSV는 Native
10문서/216쪽, fresh WASM 4문서/81쪽까지 산출한 시점의 모든 완료 쪽이 90% 이상이다.
최신 구현의 증거로 재사용하지 않는다.

ignored 증거 루트는
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`다.
`stage101-vector-bullet-frame-probe/`와 `stage101-vector-body-counterexamples/`에
입출력 해시·job 계약·저장 frame·Print 문자 원점을 보존했다.
전체 55원본/853쪽, 관계형 회귀 전환·전체 게이트·새 PR은 계속 미완료다.

## 빌드와 대조 결과

최종 구현 source `1e6ca62e8e5c81894ec7e12e6c9000becca97542`에서 포맷,
Native Clippy, WASM Clippy, native-skia lib check와 Native release-test 빌드가
모두 exit 0이다. 현재 단계는 원인 보정 진단이며 전체 workspace Clippy·회귀 검증 완료가 아니다.
80개 새 수식과 기존 13개 대조 문서를 직접 Skia로 묶어 확인했다. 기존 13개는
각 문서의 모든 진단 쪽이 90% 이상이다. 새 vector-bullet은 첫 쪽
83.75699% → 94.51725%, 둘째 쪽 59.48712% → 75.65677%이며,
vector-body는 71.66342% → 73.00463%다. 새 진단은 여전히 미달이다.

대표 새 확대는 ignored `stage101-after-skia/vector-bullet/`의
`dot-decoration-selected-detail-review.png`와 같은 이름 JSON에 보존했다.
9pt 이항 BULLET은 53.21101% → 91.86047%, 이항 CDOT은
54.65116% → 90.47619%이나 단독 기호·22pt·벡터는 미달이다.
전쪽 통과로 이 차이를 면제하지 않으며 정식 회귀 기대값은 변경하지 않았다.

Skia 실행 진단에서 시스템 family는 `HyhwpEQ`이고 실제 요청은 `HYhwpEQ`다.
Skia `FontMgr.match_family_style`은 양쪽 모두 `HyhwpEQ`를 반환하지만 rhwp의
사전 `HashSet.contains` 필터가 대소문자를 구분해 첫 요청을 제외한다.
따라서 Unicode 매핑·전진 보정 후에도 Skia에서 대체 글꼴의 점 크기를 쓰고 있었다.
`stage101-skia-font-family-diagnostic.json`에 실행 명령·실제 결과를 기록했다.
독립 Print 행렬의 shaft/head 16개는 현 화살촉의 0.1em 폭과 0.12em 높이가
너무 작음을 확인한다. 공개 Latin Modern Math 원본의 MATH 조립 head를 확보했으며
사설 윤곽 대신 공개 부품을 공통 표시 기하에 사용하는 후속 보정이 필요하다.

기존 Native 전체 controller는 unified exec handle 1778에서 exit 143으로 종료됐고
root/남은 입력 process의 소멸을 확인했다. 완료 기록 10문서와 종료 직전 실제
TSV/summary 2문서를 합해 12문서/258쪽을 보존했다. 마지막 두 입력의 process
exit code는 기록이 없어 추정하지 않았다. 완료된 실제 TSV 쪽은 모두 90% 이상이며,
controller 종료 사유는 미확정이다. 해당 자료는 변경 전 source의 증거다.
새 source의 전체 검증·확대 통과·전체 관계형 회귀·새 PR은 계속 미완료다.
