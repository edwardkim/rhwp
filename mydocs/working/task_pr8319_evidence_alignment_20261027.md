# PR #8319 후속 증적의 원본·주장 대응 정정

## 작업 범위와 원인

원 PR 45건의 본문·원 작성자 댓글·diff와 게시한 기존 통합 댓글을 다시 대조한다.
기존 대표 이미지에는 실제 보고 문서 대신 합성 경계 입력을 사용한 사례가 있다.
같은 코드 경로의 회귀 PASS와 원 PR이 지목한 실물 문서의 시각 검증 완료는 별개다.
원본 파일과 편집 상태가 다른 이미지는 원 문서의 대표 증거로 사용하지 않는다.

작업지시자는 증적이 없으면 증적만 재산출해 별도 PR로 처리하고, 개별 review 문서도
수정하도록 지시했다. 원 PR과 통합 PR에는 새 정정 댓글을 추가하지 않고 기존 댓글을
직접 수정한다. 엔진·테스트·baseline·Visual Sweep 정책 변경은 이번 범위가 아니다.

## 확인 기준

1. 원 PR 본문과 원 작성자 댓글에 기재된 실제 파일·페이지·실패 영역을 먼저 확정한다.
2. API 생성 입력이면 원 PR의 생성·편집 순서와 저장 형식 및 편집 전후 상태를 대조한다.
   비슷한 표나 다른 개체를 넣은 합성 대조군을 같은 입력으로 취급하지 않는다.
3. 실제 파일·입력 SHA·독립 Print PDF SHA·실행 source와 producer·backend·DPI·페이지를
   연결한 뒤 해당 경계의 review와 standalone overlay를 직접 판독한다.
4. 같은 입력의 기존 증적만 재사용한다. 원 작성자의 과거 before/after는 원 보고 자료로
   명시하며 현재 통합 source의 새 출력이나 독립 한컴 Print 증거로 승격하지 않는다.
5. 빠진 증적은 동일 원본·동일 조작 상태로 재산출한다. 전쪽 Native/fresh WASM TSV와
   대표 PNG를 제출하며 점수와 실제 결함의 확인을 구분한다.
6. 개별 review/review_impl, 통합 리뷰와 증적 색인 및 PR 본문의 잘못된 대응을 함께 고친다.
   정식 증적 PR 반영 후 기존 댓글의 이미지·수치·설명을 교체하고 API로 재조회한다.

## 원본·PDF 동반 보존과 기여자 제출 조건

작업지시자의 추가 요청에 따라 공식 배포 HWP/HWPX 16개와 PDF를 함께 연결하는 대응표를 추가했다. 현재 PDF 11개를 보존했으며 나머지 5개는 보완 중이다. 공식 배포 PDF를 Print 경로 확인 기준으로 임의 승격하지 않는다. 새 PDF의 전 페이지 90% 보정은 요청 범위가 아니다.

## 실제 원 PR 주장 확인과 미개선 항목의 현재 PR 보정

작업지시자는 새로 확보한 HWP/HWPX와 같은 입력의 PDF를 비교해 실제 원 PR이 주장한 개선을 확인하고, 미개선이면 현재 PR #8328에서 구현도 보정하도록 지시했다. 문서·증적 정정만으로 완료하지 않는다.

1. 저장 제품에 맞는 MCP 2020/2024 Print PDF를 확보하고 원본·SHA·주장 영역·대응 쪽을 고정한다.
2. 변경 전 Native/fresh WASM의 같은 영역을 캡처해 원 PR 주장과 대조한다. 전 페이지 90% 보정 면제는 실제 주장 영역의 검증을 생략하는 뜻이 아니다.
3. 미개선은 원 해결 PR·통합 보정·독립 Print·정상 대조군을 함께 분석하고 공통 로직에서 수정한다. 특히 #8036의 원문 13쪽 경계와 기존 1쪽 Print 대조군을 함께 보존한다.
4. 같은 원본·PDF로 영향 영역과 정상 대조군을 재검증한다. 회귀 추가·변경은 기존 시각 선행 조건을 따른다.
5. source/test가 바뀌면 이전 review-only CI를 재사용하지 않고 해당 로컬 게이트와 새 product head의 CI를 완료한다. 최종 범위로 PR 본문·개별 리뷰·이미지를 다시 작성한다.

빌드 전까지 변경 전 producer를 유지해 원문 대조 증거를 먼저 수집한다. Native/WASM 산출물·공용 target을 다른 검증과 동시에 바꾸지 않는다. 머지는 실제 주장 확인·필요 보정·새 head 검증 후에 진행한다.

원본 HWP/HWPX 16개와 대응 Print PDF 16개를 확보했다. #8049는 MCP worker 종료 후 동일 원본을 win10-ted에 복사하고 사용자 수동 Print PDF를 가져왔으며 82쪽·한컴 2020 11.0.0.9136·입력/PDF 해시를 확인했다. 나머지 신규 출력은 저장 제품에 맞는 MCP 2020/2024의 Print method 0·1-up 결과를 확인했다. 실제 주장 영역의 수정 전·후 검증과 구현 보정은 계속한다.

### 원문에서 재현한 공통 원인과 소비 경로

- #8027: 공식 고용동향 HWPX의 두 번째 OLE 프리뷰에서 EMF `0x5B` 두 레코드가 각각 닫힌 막대 29개를 보유하고, 앞선 `0x5E`가 8×8 DIB 브러시를 제공한다. 기존 파서는 두 레코드를 `Unknown`으로 버려 오른쪽 차트의 막대가 사라진다. 실제 경로는 OLE 프리뷰 → 공통 EMF parser → SVG player → RawSvg의 Native/WASM 재생이다. 복합 채움·브러시 선택·저장/복원 상태를 같은 결과로 유지하며 개별 backend에 문서 전용 보정을 두지 않는다. 원본 3쪽은 Native 93.47628%, WASM 93.87708%여도 막대 누락이 직접 보이므로 점수 통과를 주장 해결의 증거로 사용하지 않는다. 구현과 검증은 [MS-EMF 복합 다각형 명세](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emf/96ad447f-25d6-4272-8d18-51b395e669c6)와 독립 Print를 함께 따른다.
- #8036: 공식 서울시 HWPX의 145번 문단에서 완성된 인라인 표의 저장 끝이 본문 하단에 닿고, 다음 146번의 자리차지 표는 새 쪽 원점에서 시작한다. 그 표의 바깥 프레임 끝은 다음 저장 줄의 시작과 일치한다. 기존 저장 경계 판정은 HWPX의 이 객체 소유 사다리를 놓쳐 두 쪽의 표와 글을 한 쪽에 겹친다. 저장 프레임 결과 → `apply_stored_paragraph_boundary`의 실제 쪽 전환 → 표 항목의 후속 배치를 연결하며, 동일 Print가 한 쪽임을 증명한 기존 `zero.hwpx`·`continuing.hwpx` 대조군은 유지한다. 저장 좌표 0이나 긴 줄만으로 쪽을 강제로 넘기지 않는다.
- #8050의 처리절차 바깥 테두리는 새 한컴 Print와 Native 화면에서 일치했다. 같은 #8052 문서는 이번 MCP Print와 Native가 모두 빈 2쪽을 출력한다. 원 PR의 1쪽 주장과 서로 다른 관측이므로, 이 자료만으로 1쪽으로 강제하거나 원 주장 전체가 해결됐다고 표시하지 않는다.

### 후보의 선행 회귀와 fresh WASM 부분 확인

- 동일 검증 worktree의 수정 전 검사에서는 실제 차트 막대와 표 쪽 소유가 각각 실패하고 기존 1쪽 한컴 Print 대조군 2건은 통과했다. 후보에서는 두 원문 검사·기존 대조군 2건·EMF 채움 계약 3건이 모두 통과했다. 후보는 아직 커밋 전이며 추가 검증이 필요하다.
- fresh WASM 후보의 선택 페이지는 #8027 3쪽 96.67%, #8036 11쪽 99.51%, 12쪽 97.64%다. 직접 확인한 차트 막대 복원과 표 쪽 분리는 점수와 별개로 기록한다. 차트 채움·글자 굵기 차이와 Native 비교는 계속 검토한다. 이 선택 페이지 측정은 전쪽 TSV와 전체 회귀 결과가 아니다.
- `native-skia` 후보도 같은 PDF에서 #8027 3쪽 96.40290%, #8036 11~12쪽 최저 98.07662%다. #8027은 양쪽 6쪽, #8036은 양쪽 13쪽으로 쪽수가 일치한다. 차트의 패턴 채움과 일부 글자 모양 차이는 남아 있어 직접 확대 판독을 계속한다. 해당 Native·WASM 선택 쪽의 review와 overlay는 `output/pr-review/pr8319-comment-correction/source-claim-validation/candidate/`에 있다.
- #8027 막대의 확대 판독에서 채움은 복원됐으나 PDF보다 초록색 외곽선이 매우 흐리고 차트 프레임도 흐리다. 독립 PDF에는 해당 외곽선이 약 0.047pt인 벡터 경로로 들어 있다. EMF의 실제 선택 펜·변환과 Native/Canvas·PDF의 세선 래스터화 경로를 구분해 분석한다. 점수 통과만으로 이 차이를 완료로 처리하지 않는다.
- 실제 막대 외곽 펜은 `EMR_EXTCREATEPEN`의 기하 펜(style `0x00010200`, 논리 폭 2)이고, 출력 SVG에서 월드 변환 `0.0625`를 받아 약 0.125px 폭이 된다.
