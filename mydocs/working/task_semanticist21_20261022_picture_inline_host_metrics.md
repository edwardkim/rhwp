# 그림 인라인 전환에서 혼합 글줄의 높이 보존

## 범위와 독립 근거

행정업무편람의 추가 개선과 사양 정정 문서 변경은 제외한다. 사용자가 전달한 TABLE
정정은 참조하며 값 2/CELL/RowBreak를 행 경계 전용 정책으로 해석하지 않는다.
이번 단계는 #4961의 공개 API 생성 반례에서 확인한 그림 토글의 줄 캐시 생산 결함이다.

원 #1151의 한컴 시나리오 A~D와 원 #3781 앵커 비트 계약을 확인한다.
`hancom_picture_tac_toggle.md`가 입증한 그림 높이=줄 높이는 텍스트가 없는 개체
문단이다. 같은 규칙을 18pt 글자와 작은 그림 두 개가 함께 있는 문단의 첫 줄에
적용하면 1800HU 글자의 줄을 400HU로 덮는다. Native118의 1832 계측에서 두 번의
속성 토글 직후와 중첩 셀로 복사 직전 모두 400/400/340HU를 실제 관측했다.

같은 원본 HWP/HWPX의 한컴 2020 Print는 중첩 셀의 글자 전체를 표시하며 현재
Native는 잘린다. 바깥 표 높이도 다르다. 기존 반례의 잘못된 캐시를 renderer의
저장 줄 수용 조건 완화나 clip 확장으로 숨기지 않고 캐시 생산부터 고친다.

## 공통 수정과 소비 위치

그림 앵커의 Para 기준·0 offset·packed attr 동기화는 공통 전환 함수에서 유지한다.
빈 문단의 한컴 독립 계약은 유지하고, 텍스트 혼합 문단은 기존 reflow_line_segs에
실제 내용 상자와 현재 스타일을 전달한다. 원문 글자·제어 순서·주소는 보존하며
이미지 높이만으로 글줄 전체를 다시 정의하지 않는다.

본문은 실제 소속 단의 폭·문단 여백, 미주와 머리말/꼬리말은 해당 흐름의 내용 폭을
사용한다. 본문과 머리말의 동일 전환을 다른 측정식으로 구현하지 않는다. 본문 후속
문단의 원점은 재조판 전 흐름 끝과 새 줄 결과로 기존 vpos 갱신기가 소비한다.
중복 reflow를 피하고 측정·paint·저장 모두 같은 새 LineSeg를 읽게 한다.

## 실행 계획

1. 본문·가상 미주·머리말/꼬리말에서 공통 전환 결과를 소비한다. 셀 직접 속성 API는
   기존 소유 셀 동기화 경로이며 여기의 첫 줄 덮어쓰기 함수를 호출하지 않는다.
2. 기존 #1151 빈 문단·그림 소속·저장 원본 검사와 #4961 원문 소유 대조군을 실행한다.
3. 기존 재현 절차를 새 Native로 다시 수행해 입력을 보존한다. 원본 1818과 변경 전후를
   구별하고, 새 저장본도 실제 버전의 독립 한컴 Print로 출력한다.
4. 전쪽 Native/fresh TSV와 새 review·overlay에서 잘림·표 경계·원점·내용 보존을 확인한다.
   90% 미만이면 완료나 새로운 배치 회귀 추가로 진행하지 않는다.
5. 같은 공통 흐름의 기존 정상 대조군을 함께 검증한다. 최종 head의 전체 검증은 별도다.


## 실제 구현과 검사

`picture_inline_migration`의 공통 함수가 앵커 변경 후 혼합 텍스트를 같은
`reflow_line_segs`로 구성한다. 본문은 소속 단, 가상 미주와 머리말/꼬리말은 해당
내용 상자를 전달한다. `finish_body_inline_object_reflow`가 이미 계산한 새 줄을
후속 본문 원점에 반영하며 중복 reflow를 하지 않는다. 기존 shape 삽입 경로도
같은 후속 원점 처리 결과를 소비한다.

코드 재검토에서 HF의 구역 검증 이전 폭 조회가 panic할 수 있음을 발견했다.
현재 폭 조회는 Result로 오류를 전달한다. 실제 Native119 PASS → 진단 Native120
FAIL(panic) → Native121 PASS로 API의 기존 오류 계약 복원을 확인했다.
`picture-property-error-before-after-1851.json`에 실제 라이브러리·명령·로그를 남겼다.
새 정식 검사는 존재하지 않는 주소에서 오류 반환과 모델 보존만 확인하며 실물
배치나 시각 fixture·골든을 추가하지 않는다.

Native121은 시작 head `aae015b451`의 보정 작업 트리에서 237.97초, exit 0으로
빌드했다. 컴파일 잡 8개·공유 target·빌드 전후 소스 동결을 유지했다.
실제 검사 85건은 모두 PASS, 누락은 0건이다.

## 독립 Print와 실제 시각 결과

같은 공개 편집 절차를 Native120에서 다시 실행한 1837 HWP/HWPX를 원래 1818과
구분해 보존했다. 새 저장본은 각기 다른 job으로 실제 한컴 2020 11.0.0.9136의
PrintMethod 0·1-up PDF를 출력했다. 1841의 영수증에 입력/PDF 해시와 실제 Print
필드가 있다. 새 저장본에서는 400HU 캐시가 유효한 저장 줄로 방출되지 않는다.

현재 Native121에서 새 저장본을 같은 Print와 전쪽 비교한 1850은
HWP 42.45367%, HWPX 47.35546%, 모두 한 쪽으로 미달이다. 진단 Native120의
동일 결과와도 같다. 1845의 새 review·overlay를 직접 읽었으며 텍스트 잘림은
사라졌지만 중첩 표가 아래·오른쪽으로 밀리고 바깥 표 높이가 다름을 확인했다.
따라서 이 단계는 캐시 생산 결함의 보정이며 중첩 표 시각 완료가 아니다.

1846에서 기존 1818과 새 1837의 독립 Print TABLE 경로 좌표가 동일함을 확인했다.
현재 재현 절차는 바깥 표를 복제해 안쪽 표를 만들면서 같은 instance_id를 갖는다.
1853은 원본을 보존한 채 안쪽 표 ID만 변경한 대조군과 모든 표/그림 ID만 바꾼
대조군이다. ZIP member 원문 대조로 Contents/section0.xml만 바뀌었음을 확인했다.
이 대조군의 통과를 원본 통과로 쓰지 않고 ID 가정이 Print에 영향을 주는지 별도로
확인한다. 중첩 표의 pageBreak는 NONE(값 0)이며 이번 차이를 RowBreak(값 2)의
행 경계 정책으로 해석하지 않는다.

전쪽 Native/fresh 90%와 직접 판독, 남은 실패와 최종 전체 검증을 마치기 전에는
PR을 제출하지 않는다. fresh WASM은 이 단계에서 아직 새로 검증하지 않았다.


## 중첩 문맥의 독립 반례 분리

별도 2020 Print job과 Native121 전쪽 TSV로 원인 가정을 대조했다. 모든 대조군은
원본 1837과 다른 이름·해시로 보존했으며 원본의 완료 판정에 대입하지 않았다.

| 변경한 가정 | Native raw | 독립 Print에서 확인한 차이 |
| --- | ---: | --- |
| 안쪽 표 ID만 고유하게 변경 | 47.35546% | 표 경계 원본과 동일 |
| 표·그림 ID를 모두 고유하게 변경 | 47.35546% | 표 경계 원본과 동일 |
| 셀에 복사된 구역·단 정의만 제거 | 47.35546% | 표 경계 원본과 동일 |
| 안쪽 표의 treatAsChar만 1로 변경 | 99.09172% | 인라인 기준의 원점·높이로 변경 |
| 공개 API로 앞 문단에 앞줄 삽입, flowWithText=0 | 49.18468% | 안쪽 표는 바깥 셀 상단 기준의 경계 유지 |
| 같은 선행 텍스트, flowWithText=1 | 47.60186% | 안쪽 표가 인라인 대조군과 같은 경계로 변경 |

영수증·TSV는 각각 1853/1854/1855, 1857/1858/1859, 1862/1863/1864/1865에
있고 독립 PDF 경로 좌표는 1856·1860·1866에 보존했다. 새 1861 review·overlay도
직접 판독했다. 99.09172%인 인라인 대조군조차 안쪽 표의 오른쪽 괘선이 PDF보다
바깥으로 나간다. raw 실루엣 점수가 이 괘선 차이를 면제하지 않으며, 이 쪽도
시각 완료·px 회귀 추가 조건을 충족했다고 쓰지 않는다.

`flowWithText`는 이름의 직역인 글과 함께 이동이 아니라 쪽 영역 안으로 제한이다.
기존 Task #1282 Stage 10/11의 실제 한컴 HWP/HWPX 대응 주석과 bit 13 근거를
참조했다. 해당 사양 설명본·정오표는 다른 PR에서 진행 중이므로 수정하지 않았다.

원인 추적은 NO_LS 중첩 부동 표의 공통 원점·본문 점유를 향한다. 현재
`sequential_nested_cell_layout`은 저장 줄이 없는 문단이 있으면 일반 경로에서
None을 반환하고, 실제 배치는 `reflow_nested_table_origin` 및 별도 후속 원점
분기로 이어진다. 측정의 `unabsorbed_nested_tables_height` 계열과 실제 배치가
그 문맥에서 같은 개체·호스트 공간을 소비하는지 다음 단계에서 대조한다.
기존 저장 사다리·인라인 결과가 맞는 대조군은 보존하며, 가시 텍스트와 빈 줄의
점유 및 부동 개체의 본문 전진을 하나의 상태로 간주하지 않는다. 단순 원점 clamp나
표를 인라인으로 강제하는 방식으로 이 차이를 숨기지 않는다.
