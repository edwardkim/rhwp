## 1. 결론

R4D-2에서 모든 visual consumer가 공유하게 된 optional `layout_positions`를 기존 CanvasKit bounded-work
회계와 JSON bounded sidecar가 온전히 다루지 못하는 두 틈을 닫았다.

1. CanvasKit pre-lowering·layer scan은 이제 positions 원시 byte 수까지 비용에 포함한다. payload가
   손상되었더라도 먼저 byte 비용을 세므로, 유효성 실패를 이용해 예산 검사를 우회할 수 없다.
2. 장식·탭·control mark JSON은 전체 positions를 복제하지 않는다. 전체 배열이 유효하면 허용된 scalar
   prefix의 slice만 빌리고, 전체 배열이나 prefix 관계가 손상되면 해당 sidecar만 K0 계산으로 닫는다.

4,096 scalar / 4,097 positions 경계와 NaN·Infinity·역행·길이 불일치가 모두 fail-closed임을 확인했다.
전체 native·native-skia·wasm32·Docker WASM gate와 K0 native/WASM 교차 검증도 통과했다. R4D의 목표였던
"layout owner가 한 번 결정한 K1 positions를 모든 backend가 안전한 상한 안에서 그대로 재생"하는 경계가
완성되었다.

## 2. 원인 감사와 정정

### 2.1 CanvasKit payload 과소계상

`text_run_payload_bytes`는 `text`와 `display_text` byte만 더하고 `layout_positions: Vec<f64>`를 세지 않았다.
이 함수는 render-tree pre-lowering과 paint layer scan 양쪽의 비용 원천이므로, 큰 positions 배열이 text
예산보다 훨씬 큰 메모리·순회 비용을 만들 수 있었다.

정정은 `positions.len() * size_of::<f64>()`를 checked arithmetic으로 더한다. overflow는 정상 수치로
포화시키지 않고 `Exceeded`로 닫힌다. positions의 길이·finite·monotonic 검증과 별개로 raw byte를 먼저
계상하므로 malformed payload도 예산을 우회하지 못한다.

### 2.2 bounded JSON prefix의 K1 유실

기존 bounded sidecar는 잘린 문자열에 `replay_positions_for(prefix)`를 호출했다. 전체 K1 positions는 원래
문자열의 `N+1` 길이이므로 prefix와 길이가 맞지 않아 K0를 다시 계산했다. 전체 배열을 복제하지는 않았지만,
안전하게 빌릴 수 있는 K1 prefix를 잃었다.

`replay_positions_prefix_for(full, prefix)`를 추가해 다음 순서로 처리한다.

1. prefix가 실제 Unicode scalar prefix이며 4,096 scalar 이하인지 확인한다.
2. 전체 positions를 전체 replay 문자열에 대해 검증한다.
3. 유효하면 `positions[..=prefix_scalar_count]`만 `Cow::Borrowed`로 반환한다.
4. 어느 조건이라도 실패하면 prefix 문자열만 기존 K0 계산으로 생성한다.

paint JSON의 tab leader, control mark, decoration이 이 공통 경계를 사용한다. source offset이나 원문을
positions와 함께 복제하지 않는다.
