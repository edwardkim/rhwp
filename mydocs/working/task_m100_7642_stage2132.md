# #7642 Cairo 화면·인쇄 모드의 독립 분리

## 같은 설치 버전의 코드와 실제 호출

stage2128은 공식 Poppler `poppler-24.02.0` 태그의 `CairoOutputDev.cc`와
`utils/pdftocairo.cc`를 읽어 설치 버전 24.02.0과 맞췄다. PNG/JPEG/TIFF 출력은
`printing=false`이며 `setPrinting(printing)`으로 실제 device에 전달한다.
`CairoOutputDev::updateLineWidth`는 화면 모드의 얇은 획을 최소 1장치 픽셀로
늘리지만 인쇄 모드에서는 0이 아닌 선폭에 이 보정을 적용하지 않는다.

이는 한컴 PDF를 만드는 경로와 별개의 **PDF 래스터 표시 모드**다. 한컴 Print
원본은 수정하지 않았다. PDF에서 stroke 폭을 읽을 때 원시 user 단위를 실제 pt로
오인하는 문제도 [stage2119](task_m100_7642_stage2119.md)와 분리한다.

stage2130은 설치된 libpoppler-glib 24.02.0의 공식
`poppler_page_render`와 `poppler_page_render_for_printing`을 같은 Cairo image
surface·96DPI로 실행했다. 인쇄 API는 기본 ALL annotation flags다.
[공식 API 문서](https://poppler.freedesktop.org/api/glib/poppler-Poppler-Page.html)와
[같은 버전의 구현](https://gitlab.freedesktop.org/poppler/poppler/-/blob/poppler-24.02.0/poppler/CairoOutputDev.cc)을 근거로 한다.

| 독립 계약 | 화면 모드의 관측 | 인쇄 모드의 관측 |
|---|---:|---:|
|직접 작성한 사각 글리프, 채움만|60.47843|60.47843|
|동일 사각 경로, 채움만|60.47451|60.47451|
|0.18pt 획 포함 사각 글리프|78.48627|65.74118|
|동일 획 포함 사각 경로|80.00000|65.64314|
|축소 CTM / 정규화 CTM의 같은 실제 글자·획|각각 324.06275|각각 174.89412|

표 값은 96DPI의 적분 ink mass이며 판정 실루엣 점수가 아니다. 수학적 사각 면적은
채움 60.48, 획 포함 64.2816이다. 글리프와 도형에 공통으로 나타나는 화면 최소
선폭 보정을 분리했으며 잔여 raster 오차까지 완전히 제거했다고 주장하지 않는다.
손실 없는 DeviceRGB 0·64·128·192·231·232·233·255는 화면/인쇄 양쪽의
96·144DPI에서 모두 정확히 유지됐다. 3쪽 선택과 실제 페이지 치수도 확인했다.

## 실제 10월 7쪽의 진단과 남은 차이

같은 원본 2020 Print PDF의 알려진 bold 영역 `(62,130)–(164,145)`은 화면
ink mass 462.88627, 인쇄 249.94510이다. 페이지 전체 ink mass도 달라졌다.
이 차이는 글자모양 bold 속성을 더하거나 지워서 해결할 문제가 아니다.

stage2131에서 인쇄 API 기준의 새로운 review·standalone overlay를 실제 생성하고
직접 대조했다. 이 진단 기준에서도 base `fe5725dc38` raw 97.45993%, 현재 엔진
`aae3ea1b26` 96.43362%로 **현재 하락은 남는다**. 인쇄 모드 선택이 현재 PR의
무하락 증거나 구현 보정 완료를 대신하지 않는다. 그림의 선·본문/수식의 간격·
테두리 차이가 남아 있고 도형은 PNG payload 경로도 대조해야 한다.

## 검증 경계

현재 공식 `visual_sweep_pdf.py`와 기존 전쪽 측정의 Cairo 화면 정책은 바꾸지 않았다.
진행 중인 queue의 helper hash와 기준 cache를 혼합하지 않는다. stage2130·2131의
JSON·PNG·실제 library 호출·PDF/PNG SHA는 ignored output에만 있다.

공식 정책 변경을 결정하려면 인쇄 모드의 전체 쪽/선택 쪽 번호·page box·회전·알파·
annotation 계약과 플랫폼 의존성을 먼저 명시하고 독립 계약을 확인해야 한다.
그 뒤 같은 고정 base와 head의 전체 Native/fresh WASM을 동일 정책으로 다시
대조한다. 점수가 높아지는 문서에만 기준이나 DPI를 선택하는 방식은 사용하지 않는다.
