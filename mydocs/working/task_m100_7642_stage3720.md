# #7642 양쪽 정렬의 공백 압축 한계와 잔여 자간 공통화

Issue: #7642

## 독립 근거와 구현 계획

현재 source `e09b9df40a`에서 이어간다. `stage3707`의 52조건,
`stage3711`의 20조건, `stage3716`의 16조건을 한컴에서 저장하고 2024 Print로 출력했다.
원본 colPr을 유지한 생성본이며 사용자 원본 파일을 고치지 않았다. 각 입력·저장본·PDF의
SHA와 실제 Print 경로는 ignored output의 3708/3709, 3712/3713, 3717/3718 receipt에 있다.

`stage3710`, `stage3715`, `stage3719`는 원본 한글 순서·단어 경계를 확인한 PDF 원점 관측이다.
양쪽 정렬에서 공백은 원본 자간을 제외한 자연 전진의 약 20%까지 줄고, 나머지 초과 폭은
공백 외 글자 사이로 분배된다. useFontSpace=true에서도 같은 비율이며, 10/12pt 혼합 줄의
두 크기는 같은 절대 추가 자간과 같은 공백 감소를 사용한다. 한 줄의 가장 작은 공백이
그 한계를 정한다. 마지막 가시 글자 뒤의 추가 자간은 줄의 fit에 들어가지 않는다.
무자간 조건의 마지막 원점+자연 전진은 인쇄 오른쪽 경계와 약 0.11px 이내였다.

기존 구현은 첫 run의 자간 포함 공백 폭을 50%까지 줄이며, 나머지는 셀 안에서만 모든 글자에
분배한다. 이를 일반 Justify의 음수 slack에서 보정한다. Split·양수 slack·탭·억제 셀의
별도 계약은 바꾸지 않는다. 선두 공백·필드·TAC는 자연 폭을 유지하고 실제 run별 속성을 읽는다.

## 생산과 소비

`compute_line_extra_spacing` → 공통 LeadingSpacePlan의 표시 run과 독립 원본 속성 →
추가 word/char spacing → `emit_line_runs`의 같은 run 분할과 TextStyle → Native/WASM paint.
추가 자간은 공백에도 적용되므로 word spacing에서 그 몫을 상쇄해 관측된 공백 한계를 지킨다.
측정은 실제 emit와 같은 exact text width를 쓰고, 고정 개체 폭은 원래 줄 폭에서 보존한다.
끝 개체 소유가 있으면 마지막 글자의 뒤 자간도 실제 다음 내용으로 소비한다.

## 검증 범위

88조건의 Native 전쪽 TSV와 미세 간격을 먼저 확인한다. 동일한 원본·Print를 사용해
기존 11문서 293쪽과 집중 회귀를 배치 실행하고, 방향이 확인되면 fresh WASM도 실행한다.
새 실물 회귀의 선행 gate를 우회하지 않는다. 기존 기대값을 완화하지 않는다.
전쪽 90%, devel 대비 0.01%p 무하락, 확대 판독과 최종 head의 전체 검증은 여전히 필수다.
이 문서는 구현 전 계획이며 완료·PR 가능 판정이 아니다.
