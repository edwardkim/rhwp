# #7642 자동 쪽번호의 목표 조판 세대와 독립 Print 대조

Issue: #7642. 이 단계 전 HEAD는 `f29211f9f51b12c0ee7db4ddf55adfbd78821a2c`다.
표 분할 보정의 Native·29건 검증은 별도 소유 worktree에서 이 SHA로 실행 중이다.
이 문서의 쪽번호 변경을 해당 실행의 통과 증거에 포함하지 않는다.

## 독립 근거와 반례

원본 `36384689_결재문서본문_화재발생종합보고서(제2026-298호).hwpx`에는
명시적인 `쪽 번호` 스타일이 없다. 쪽번호 제어를 담은 run은 파란 한컴바탕이고,
바탕글은 검은 HY신명조 10pt다. 제어를 담은 run을 상속하는 것은 잘못된 가정이다.

ignored output의 `stage3327`과 `stage3329`에서 같은 원본 및 바탕글의 한 속성만
바꾼 두 대조군을 각각 한컴 2020·2024의 실제 Print로 출력했다. 원본·기존 PDF는
유지했으며 실행 receipt에 입력·출력 SHA, engine, 실제 빌드, PrintMethod=0,
one-up, input_preprocess=none이 있다. 기존 수동 2024 PDF의 HY신명조 쪽번호와
새 2024 Print의 원본 결과가 일치한다.

| 입력 | 2020 Print 쪽번호 | 2024 Print 쪽번호 |
| --- | --- | --- |
| 원본 | Haansoft Batang 약10pt 검정 | H2mjsM 약10pt 검정 |
| 바탕글만 15pt·빨강 | 원본과 같음 | H2mjsM 약15pt 빨강 |
| 바탕글 영문 face만 굴림 | 원본과 같음 | Gulim 약10pt 검정 |

따라서 바탕글 상속은 2024 목표 조판 세대에만 적용한다. 기존 명시 `쪽 번호` 스타일은
양 세대에서 우선하며, 스타일이 없는 2020 경로의 기본 10pt 바탕도 유지한다.
문서 이름·ID·저장 연도로 분기하지 않는다. 세대는 기존 세션 설정만 소비한다.

## 생산·소비 경로

`DocumentCore::effective_layout_profile`의 세션 세대 →
`resolve_render_styles/resolve_styles_with_environment`의 쪽번호 글자모양 선택 →
기존 언어별 face·크기·색·장평·자간 해소 → `LayoutEngine`의 쪽번호 측정과
최종 TextRun → Native/WASM paint가 같은 스타일을 소비한다.
세대 전환 때 스타일도 재해소해 2022→2024→2022 반복 전환에 이전 값이 남지 않게 한다.
기존 문서 IR·쪽번호 제어·원본 파일은 수정하지 않는다.

## 검증과 남은 범위

기존 `nested-host-spacing` 행은 기준 PDF가 2024인데 compat=2022였다.
이는 현재 canonical의 ‘기준 Print와 같은 조판 세대’ 계약에 맞지 않는다.
그 점수는 과거 출처로 보존하고, 새 base·후보 모두 compat=2024로 다시 출력한다.
2020 반례는 새 2020 Print와 compat=2022로 따로 비교한다. 기존 기준 PDF를
새 PDF로 갈아 끼워 하락을 숨기지 않는다.

새 head에서 29건, 표 분할 대조군, 두 세대의 세 입력과 명시 스타일 대조군을 검증한다.
전쪽 Native/fresh WASM 90% 이상 및 직접 판독 전에는 새 정식 회귀나 golden을 추가하지 않는다.
현재 결과는 구현 근거이며 검증 완료·PR 준비 완료가 아니다.
