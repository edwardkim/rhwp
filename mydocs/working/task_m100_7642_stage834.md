# Issue #7642 단계 834: 수용한 TAC 원점 전달과 그룹 회귀 계약

## 완료된 후보 검증과 미달

단계 819·820은 `35ccddcff4f9f40d1c0ca7712bae3c2dc7b8bcda`의 Native와 fresh WASM으로 대조 문서 9개·187쪽을 각각 산출했다. 8개 문서의 전체 페이지가 양쪽 모두 90% 이상이며 HWPML은 3·37·38·57·68쪽이 미달이다. 입력·Print PDF와 producer 해시는 각 receipt에 고정했다. TSV·로그는 ignored output에 보존한다.

단계 824는 `c5f97f420`의 Native 빌드와 합성 그라데이션 검사 1건을 통과했다. HWPML 37쪽은 98.68167%, 38쪽은 87.57342%다. 직접 판독에서 37쪽 하단에 Print보다 한 행이 더 있었으므로 98% 통과로 구조 차이를 면제하지 않는다. 나머지 선택 쪽의 미달은 3쪽 72.16740%, 57쪽 86.43364%, 68쪽 75.81327%다. 선택 쪽 확인을 전쪽 완료로 대신하지 않는다.

## TAC 저장 원점의 생산과 소비

`controls/stored_tac.rs`의 원본 단일 줄 수용은 원본 개체·캡션·바깥여백과 측정 높이를 대조하고 실제 앞 내용의 끝과 저장 간격으로 원점을 인증한다. `StoredTacPlan.source_origin`은 이미 이 결과를 갖고 있었으나 일반 표 뒤 앵커 초기화에서 fit·paint의 축이 다시 지워졌다. 57쪽 첫 표의 실제 plan은 측정 수용 true, 원점 162.933333px였다. 이후 문단에서는 page base가 없고 lazy base 632HU가 나타났으며, 다음 TAC의 원점에 약 8.43px 차이가 이어졌다.

새 `InlineBoxPlacement.stored_column_origin_hu`에 인증된 결과를 전달한다. 다른 일반·합성·물리 흐름 생성자는 None이며, 원본 줄 계획만 값을 발행한다. 상태의 `commit_deferred_table_anchor`와 layout의 표 뒤 처리에서 같은 값으로 page base를 보존하고 lazy base를 지운다. 뒤 본문은 자체 줄 소속과 실제 개체 원점을 유지한다. 문서 ID·임의 보정 상수·clamp를 추가하지 않는다. 관련 호출 경로의 새 시각 검증이 필요하다.

## 첫 부동 조각의 닫힌 저장 프레임

공동 앵커는 이미 배치한 같은 줄의 TAC 형제와 같은 물리 frame에서만 수용한다. 첫 부동 조각의 저장 호스트 원점은 단의 인증된 원점으로 사영하고, 실제 문단 시작과 원본 앞 간격의 합에 1HU 이내로 일치할 때만 발행한다. 컷 budget이 이 호스트와 원본 선언 높이의 닫힌 행 끝을 비교한다. 앞 TAC를 소비한 현재 흐름 높이가 호스트 원점을 대신하지 않는다. 앞 쪽을 소비한 이어받기, 다른 줄·다른 frame, 위·옆 캡션과 재조판은 이 계약을 적용하지 않는다. 행 번호나 관측 px를 기대값으로 고정하지 않는다.

## 그룹 도형 회귀 변경의 선행 증거와 검사

원본 `samples/issue1892_hwp3_drawing_group_roundtrip.hwp`와 공개 저장 경로의 재저장본을 같은 독립 Print와 전 2쪽 비교했다. Native 최저값은 각각 95.64711%, 98.59804%, fresh WASM은 각각 96.06542%, 98.50949%다. 단계 833에서 대표 쪽도 별도로 생성한다. 수정 후 최종 head의 재검증은 아직 필요하다.

기존 그룹 검사 2개의 이름과 계약을 바꾼다. 모든 노드의 1px 변위 대신 실제 쪽·문단·셀 내용 순서와 보존, 묶음·자식 종류 및 소유, 원본 용지에 대한 개체 프레임 비율을 검사한다. 프레임의 수용 정밀도는 원본 정수 단위 1HU다. 자식 행렬 identity 검사는 원본 상대 오프셋 누적·묶음 깊이·빈 자식과 Absolute 크기 기준 보존으로 교체한다. 탭 원본의 별도 검사 2개는 이번 그룹 원본의 검사로 바꾸지 않는다. 컴파일과 실제 실행 뒤 결과를 기록한다.

## 후속 검증과 PR 순서

위 변경을 묶어 빌드·그룹 회귀·공동 앵커 대조군·영향 쪽 시각 검증을 수행한다. HWPML 전체 페이지와 나머지 55개 원본, 실제 base 대비 하락 비교, 전체 회귀와 lint 및 정책 검사를 완료해야 한다. 아직 PR을 만들 수 있는 상태가 아니다. PR 직전 upstream/devel 변경 시 리베이스와 재검증을 수행하고, 코드 head CI 성공 후 옵션 2의 별도 review·오늘할일 PR, 머지와 후속 처리 순서로 진행한다.

단계 835의 `117245fd1` 빌드는 E0609로 중단됐다. fit 상태의 단 상대 앵커 이름을 HeightCursor에 사용한 구현 오류다. paint의 실제 원점은 절대 쪽 좌표 `col_anchor_y`이므로 이 필드로 수정한다. 소스 정수 원점은 공통 결과를 사용하고 물리 앵커는 각 소비자의 좌표계로 보존한다. 실패한 빌드에서 시각·회귀 검증 결과를 얻었다고 기록하지 않는다. 수정 후보에서 다시 실행한다.
