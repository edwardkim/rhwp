## 1. 무엇을 만들었나 — 한 문단

1~9년 축의 검증 재료를 감사인이 읽는 언어로 묶는 10년 축: ① `audit-report` —
재현(--deep)·계보·귀속(--keyring)·앵커(--anchor-log)·게이트(--policy) 수치를
**기존 축 검증의 기계 합산**으로 산출한 `agentLaborAuditReport` 를 생성하고
보고서 파일 자체를 4년 사이드카로 서명한다("감사 보고서를 감사할 수 있다"),
② `recall-scope` — 오염 노드(경로 또는 sha256)의 **후손 폐쇄집합**을 계보
걷기로 계산해 영향(경로 증명 포함)/미영향을 가르고 `--ledger` 로 정산 청구
좌표까지 짚는다(리콜의 회계 연결), ③ `conformance` — L1(영수증)~L5(원장)
누적 요건을 기존 판정기 재사용으로 자가진단한다(신규 판정기 발명 0, 미달
exit 3). M4 초안으로 표준 문서 `mydocs/tech/agent_labor_audit_standard.md`
(용어 사전 12항·보고 규정 R1~R3·리콜 절차·등급 표·정직 조항)를 동봉했다 —
외부 표준 제출은 범위 밖(채택 전략은 가설, 설계서 §5 승계).

## 2. 설계 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 공용 코어 | `src/audit_standard.rs` — collect(비재귀 `*.capsule.json`, audit 폴더 규약)·walk_ancestry(부모 해시+계보 불변식)·heads_and_roots(해시가 정체성) | 세 명령이 같은 그래프 원를 쓴다. 부모 참조 대조는 경로가 아니라 **파일 해시** — 표기가 달라도 같은 파일이면 같은 노드 |
| 판정 재료 일원화 | `y10_axis_materials()` — 서명/앵커/계보/재현 재료를 한 번 계산해 절과 게이트가 공유 | audit-report 의 gate 절이 별도 재검사를 돌면 "보고 수치의 기계 대사"가 깨질 수 있다 — 같은 재료, 같은 판정 |
| 재현 opt-in | `--deep` 없으면 reproduction 절 = `null` | 부재를 0이나 100%로 위장하지 않는다(표준 요건 R3 — 부재의 정직) |
| 리콜의 자기 포함 | 오염 노드 자신도 affected(회수 1호) | "후손만"은 오염물 자체의 회수를 빠뜨린다 |
| 파손 사슬의 조상 | walk 는 파손 지점에서 멈춘다 — 파손 너머는 리콜 범위에 안 들어간다 | 파손 이후의 "조상"은 검증 불가한 주장 — 주장으로 리콜을 확장하면 오검출이 된다(한계는 표준 문서에 명시) |
| 등급 재료 선검사 | L3+ 에 keyring/anchor-log, L4+ 에 policy, L5 에 ledger 없으면 **exit 2** | "재료 없이 통과"라는 우회로 봉쇄 — 판정(3)과 사용법(2)의 구분은 #2707 그대로 |
| L5 공개 항목 | `checks` 에 `ok: null` + "기계 판정 밖(수동 확인)" 명시 | 조직 절차를 기계가 판정하는 척하지 않는다 |

## 4. 부딪힌 함정 (정직 기록)

1. **유효 체인 픽스처의 열쇠** — 다음 링크 입력은 앞 링크의 `run` **실산출**
   이어야 계보 불변식이 성립한다(replay 는 임시 전용이라 출력이 안 남는다).
2. **원장 항목 스키마와 리콜의 궁합** — 원장이 capsuleSha256 를 직접 들고
   있어(9년 구현 세부) 리콜의 회계 연결이 claim 파일 재열람 없이 닫혔다.
3. **시각 증거 크롭 함정** — 렌더 줌을 바꾸면 관심 영역의 상대 위치가 변한다.
   합성 후 눈검증이 잡았다(스트립 4장이 전부 동일해 보이면 증거가 아니다).
4. **clippy 항등 map** — 판정 재료 도입 시 남긴 `map(|n| n)` 을 클리피가 잡음.
