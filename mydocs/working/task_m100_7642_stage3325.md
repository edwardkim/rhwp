# #7642 종료 병합 칸의 빈 최소와 남은 내용을 분리

Issue: #7642. 실제 검증 source는 `57e9192f7270b30eb533d69ee5229ec217dd1a81`이다.
현재 변경은 다음 후보이며 아래 결과를 그대로 통과 증거로 쓰지 않는다.

## 검증 결과

`stage3282`의 기존 29건은 모두 PASS다. 원본의 실제 Print 글꼴 조건 `stage3283`은
전쪽 6쪽 일치, 최저 98.83256%다. 기본 시스템 글꼴 진단은 최저 41.26641%로 미달이며
실제 Print 글꼴 조건의 점수와 혼합하지 않는다. 일반·병합·혼합 최소 6문서, 정렬 2문서와
최소 경계 9문서는 전쪽 100%, 명시적 개행/문단 경계 4문서는 최저 98.20348%다.
#7518 등 53쪽 및 #7969 13쪽은 모두 90% 이상을 유지했다.

그러나 긴 종료 병합 `stage3292`는 Print 2쪽과 달리 3쪽이다. 따라서
`stage3300`은 Native 선행 gate에서 종료했으며 fresh WASM을 시작하지 않았다.
원본 개선이나 29건 PASS로 이 쪽수 회귀를 면제하지 않는다.

## 원인과 계약

종료 병합 칸의 남은 글줄은 `fragment_cut/next_unit`과 기존
`straddle_continuation_demand → straddle_page_band_relief`가 이미 소유한다.
이 내용을 새 최소 잔여로 다시 전달하면, 원래 행 높이에서 실제 앞 조각을 빼는 기존
이어받기 경로를 건너뛰게 된다. 8줄 종료 칸은 앞의 3줄과 뒤의 5줄을 보존하지만,
뒤쪽 행 상자가 142.7px로 남아 Print와 같은 98.7px 상자로 줄어들지 않고 후속 본문이
3쪽으로 넘어간다. 내용 보존만으로 물리 상자의 정확성을 대신할 수 없다.

새 종료 최소 조회는 **그 칸의 유닛을 모두 소비한 경우의 빈 최소 차이만** 반환한다.
줄이 남으면 기존 유닛·이어받기 계약을 소비하며, 그 높이를 최소 상자의 대용으로 새로
만들지 않는다. 일반 칸의 작은 빈 꼬리를 흡수해도 다른 종료 칸의 큰 미소비 최소는
유지한다. source ID·행 번호·예상 페이지 수·픽셀 상수로 나누지 않는다.
함수 이름도 `reflow_ending_span_minimum_remainder`로 명확히 했다.

`stage3326`은 같은 8줄 입력에서 종료 칸의 선언 최소만 80px에서 240px로 바꾼
독립 Print 대조군이다. 내용이 남은 경로에서도 실제 큰 최소를 버리지 않는지 함께
확인한다. 원본·기존 PDF는 보존하고 입력/출력 SHA와 실제 2020 Print 실행 정보를
ignored output의 receipt에 남겼다. 이 자료는 새 정식 회귀의 90% 선행 조건을 아직
충족하지 않았으며 현재 단계에서 fixture/golden을 추가하지 않는다.

같은 29건과 원본·전체 대조군을 새 source에서 재실행한다. Native 선행 조건 뒤
fresh WASM, 전쪽 TSV와 확대 판독, 전체 Rust·lint·Studio를 계속한다.
