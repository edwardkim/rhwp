## 수식 SVG·파서 검사의 독립 근거

기본 K·명시 it K·정체 rm K·abc·pi·적분 위첨자 pi·중괄호 유무의 a_n+1을
9·11·16·22pt에서 비교하는 32개 수식을 만들었다. 기존 수식 컨트롤을 재사용하되
크기·기준선·저장 LineSeg를 지우고 한컴 자체 저장 뒤 Print로 독립 기준을 생성했다.
MCP 저장 job은 `fbc27b77-3abb-4ec9-ba13-939925581839`, Print job은
`46559f32-50d0-40b9-91ce-0499180e375f`다. 실제 2020 engine과 PrintMethod 0의
1-up PDF driver 계약은 `stage112-equation-typography-counterexamples/conversion-pipeline.json`에 있다.

Native/fresh WASM 전 1쪽은 각각 99.86757%다. 동일 잉크 영역의 2배 확대에서
K·it K의 이탤릭, rm K의 정체, abc의 순서, pi·적분 첨자, 아래첨자 인자의 범위를
직접 대조했다. Native/fresh WASM에서 이 의미가 보존된다. 래스터 경계 차이는 남는다.
`stage112-typography-review/typography-native-wasm-print-review.png`에 연결한다.

독립 출력은 중괄호 없는 `a_n+1`의 n+1 전체가 아래첨자이며, `a_{n}+1`의 +1은
본문임을 보여 준다. 기존 함수 이름은 실패 추적을 위해 유지하고 기대값은 이
소유·내용 순서로 바꿨다. SVG는 CSS italic 속성이나 연속된 문자열 한 태그를
필수로 삼지 않고 XML의 실제 텍스트 노드와 이탤릭 Unicode 수학 글리프를 검사한다.
이 검사 변경은 실행 전이며 통과를 선언하지 않는다. 수식 골든·원장 허용치는 갱신하지 않았다.
짧은 본체와 괄호 분수 위첨자 검사도 같은 독립 Print의 관계를 소비한다.
절대 0.01px 허용치와 본체 상단 제한을 지우고, 첨자/본체 기준선의 순서·가로 순서·
합성 기준선 일치·자식 점유 포함을 검사한다. 상대 오차는 무차원 값이다.
공개 MATH fallback의 세부 위첨자 shift는 별도 미검증 범위로 유지한다.

## HWP3 저장 경계의 생산·소비 연결

새 Native의 `RHWP_DIAG_SPLIT_BUDGET`에서 문단 76의 6쪽 예산은 원본 211.25333,
왕복본 189.92000으로 차이가 정확히 1,600 HWPUNIT이었다. 생산 지점은
`PageDef.pagination_bottom_tolerance`, 소비 지점은
`PageLayoutInfo::available_body_height → place_split_paragraph`다. 독립 PDF는
저장 줄 9번 이후를 7쪽에 두지만 원본은 추가 예산으로 10번까지 소비했다.
그림은 같은 문단의 UTF-16 위치 502이며 저장 경계의 text_start 499 뒤에 있고,
non-TAC·문단 기준·TopAndBottom이다. 속성은 고정 fresh WASM의 공개 질의로 확인했다.

문단의 모든 컨트롤을 인라인 metadata로 요구하던 경계 조회는 다음 조각의 그림까지
앞 조각의 쪽 경계 거부 사유로 삼았다. 이를 실제 source UTF-16 소속으로 바꾼다.
Field·Hyperlink의 기존 경로는 유지하고, 유효한 source 위치를 가진 다음 조각의
non-TAC 문단 기준 그림을 허용한다. 앞 조각의 그림·TAC·표·각주·알 수 없는 소유는
이 새 조건으로 허용하지 않는다. 추가 예산 자체를 지우거나 좌표를 clamp하지 않는다.

경계는 `internal_vpos_page_break_line → prepare_forced_page_boundary →
place_split_paragraph → PartialParagraph 조각 → 실제 배치`에서 함께 소비한다.
검증에서는 6·7쪽 본문 내용과 그림·캡션, 앞뒤 조각의 누락·중복과 전체 16쪽을 확인한다.
HWP3의 새 정식 회귀 추가는 해당 범위의 전쪽 Native/fresh WASM 90%와 확대 판독을
충족할 때까지 보류한다. 현재 구현 보정은 빌드·실행 전이며 보정 성공 판정이 아니다.

모든 중간 파일은 ignored
`output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/` 아래에 있다.
다음 묶음에서 소스 변경 검사·Native 빌드·회귀 실행·fresh WASM·시각 재검증을 수행한다.
