# #7642 Stage 65 — 재조판 뒤 빈 저장 줄의 원점과 문단 앞 간격

Issue: #7642

## 범위와 독립 근거

55개 원본·853쪽의 Native/fresh WASM 전체 비교, 확대 판독, #1139 전체를
포함한 관계형 회귀 변경과 전체 검증 목표를 유지한다. HML 이관은 유지한다.

`samples/hwp3-sample16-hwp5.hwp`의 41쪽을 원본과 독립 한컴 2024 Print
`mydocs/pr/assets/pr_7600_control_print_20261006/input-17-hwp3-sample16-hwp5-2024.pdf`로
대조했다. 앞 제목과 본문 기준선은 Print와 일치하지만, 빈 문단 655 뒤
657~669의 본문 기준선은 약 7.5733px 위로 어긋났다. 이는 진단 관측값이며
구현·회귀의 고정 보정값으로 사용하지 않는다.

655의 저장 vpos는 25768HU, 줄 높이 1300HU, 줄간격 652HU이고,
656의 vpos는 27720HU다. 655의 문단 앞 간격은 해석된 style의 568HU다.
재조판된 654 뒤에서 빈 줄의 원점을 연결하는 기존 분기는 앞 간격 적용 전
흐름 y로 저장 기준을 역산했다. 실제 빈 줄 상자는 이 뒤에 앞 간격을
소비하므로, 656부터 그만큼 되감기는 잘못된 기준이 만들어진다.

## 생산·측정·배치 경로와 변경

원본 ParaShape → ResolvedStyleSet의 spacing_before → HeightCursor의 빈
저장 줄 원점 → typeset의 다음 항목 높이와 layout의 다음 문단 원점으로
이어진다. 이 원점은 현재 문단의 앞 간격을 소비한 첫 줄 시작과 연결해야 한다.
현재 y 반환값은 간격 적용 전 계약을 유지하며 호출자가 앞 간격을 한 번 소비한다.
HWP3 흐름은 실제 paint가 사용하는 기존 간격 해석 함수를 동일하게 사용한다.
문서 ID·특정 수치나 겹침을 숨기는 clamp를 추가하지 않는다.

0 간격, 이미 저장 줄을 가진 앞 문단, 빈 줄이 아닌 문단, 개체가 있는 문단은
변경의 비적용 대조다. 기존 #7160 전체 3쪽 및 정상 미주 경계를 함께 대조한다.
정식 관계형 회귀 변경은 관련 전체 페이지의 Native/fresh WASM 90% 이상과
확대 판독 뒤 진행하며, 아직 이 단계에서 기대값이나 baseline을 바꾸지 않는다.
