## 구현 결과

### P1 — HWPX 빈 문단

`parse_paragraph_element`가 일반/자기닫힘 문단의 속성 파싱과 후처리를 공유한다.
`<p/>`에서는 하위 이벤트만 읽지 않는다. 글자의 유무나 배경·선 속성으로 분류하지 않는다.
id, 문단 모양·스타일 참조, 쪽/단 나눔과 빈 문단 자체를 보존하며 뒤 문단·형제 도형을 삼키지 않는다.
적용 지점은 drawText 내부 문단이다. 다른 위치의 자기닫힘 도형 처리를 확장하지 않았다.

### P2 — 확정적 손상을 정상 빈 구조로 바꾸지 않음

- HWP: 이미 읽은 레코드를 한 번 순회하며 사각형 SHAPE_COMPONENT의 **직접 소유** LIST_HEADER와
  문단 헤더만 확인한다. 그룹 자식·캡션·표 셀 문단을 다른 도형의 문단으로 세지 않는다.
  재귀 파싱이나 선언 문단 수에 따른 대량 할당을 추가하지 않았다.
- 표 65의 공통 헤더 최소 6바이트보다 짧은 LIST_HEADER, 양수 문단 선언보다 실제 직접 문단 헤더가
  적은 경우에 `BodyTextError::DrawingTextStructure`를 반환한다. 샘플에서 본 33바이트를 강제하지 않는다.
  문단 수는 표 65의 하위 16비트 필드를 확인한다. 이를 전체 헤더 변형 검증이라고 주장하지 않는다.
- 검증은 섹션 진입점에서 수행하므로 뒤의 관대한 중첩 문단 파서가 이 오류를 생략하기 전에 검출된다.
  HWP 일반/lenient 문서 열기는 이 오류만 호출자에게 반환한다. 다른 섹션 오류의 기존 복구는 유지한다.
- HWPX: drawText 안의 EOF 또는 실제 XML reader 오류를 `HwpxError::DrawingTextStructure`로 반환한다.
  본문뿐 아니라 바탕쪽을 연결하는 경로도 이 오류를 생략하지 않는다.
- `XmlError`라는 enum 하나에 기존 깊이 제한 오류도 들어 있다. 이를 모두 구조 손상으로 바꾸지 않도록
  XML reader가 실제로 내부 영역에서 오류를 기록했는지 `error_position()`으로 구분한다.
  오류 문자열 검색으로 분류하지 않는다. 중첩 깊이 제한의 기존 오류 종류 유지 시험도 통과했다.
- HWPX drawText는 다른 그리기 기하도 공유한다. 따라서 내부 영역의 확정적 XML 잘림에 대한 오류
  전달은 이 공유 경로에도 적용된다. Rectangle/TextBox 의미 판정이나 선 표시 정책을 바꾸지는 않는다.

**범위 한계:** 이번 검사는 모든 바이너리 손상을 판정하는 검증기가 아니다. 레코드 스트림 자체의
파싱 실패, 모든 확장 헤더 필드의 손상, 양수 문단 안의 모든 속성 오류까지 새 치명적 오류로 바꾸지
않았다. 개별 `parse_paragraph`를 직접 호출하는 저수준 API에 새 전역 검사를 붙인 것도 아니다.
검증 계약은 완전 문서/섹션 진입점과 위에서 명시한 소유 영역 오류에 한정한다.

## 0문단 선언 경계 — 조사 당시 보류와 한컴 판정

- HWP 공식 표 65는 문단 수 필드를 규정하지만, 0을 정상 글상자로 인정하는지 명확한 제한을 제시하지 않는다.
  기존 편람 raw 계측의 179개 내부 영역 중 0문단 선언은 0개다. 현재 자료로 정상 한컴 생성 사례를
  확보했다고 말할 수 없다.
- 로컬 OWPML 2024 스키마의 drawText는 subList, ParaListType은 최소 1개의 p를 요구한다.
  이 스키마를 HWP5나 이전 namespace의 모든 문서에 일괄 강제하지 않았다.
- 따라서 새 검증은 **완전한 0문단 선언을 자동으로 거부하거나 정상 글상자로 복구하지 않는다.**
  기존 동작(HWP에서 영역 소실, HWPX에서 선언 보존)의 차이가 남아 있다.
  모델의 `Some(TextBox)`가 글상자로 판정된다는 시험은 HWP 파서가 이 선언을 보존한다는 증명이 아니다.
- 이 경계는 승인된 계획의 근거 부족 시 별도 보고 조건에 해당한다. 이슈 완료 전에 메인테이너가
  구조 선언 보존을 rhwp의 관대한 읽기 계약으로 채택할지, 별도 유효성 근거를 요구할지 결정해야 한다.
