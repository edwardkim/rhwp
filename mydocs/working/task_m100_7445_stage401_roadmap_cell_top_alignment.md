# 단계 401: 로드맵 44쪽 큰 셀의 상단 간격

## 사전 분석

- 사용자의 추가 첨부는 아래 큰 셀 첫 문장 ‘정규직 고용보호 완화’의 상단 간격을 가리킨다. 첫 얇은 행의 기호 전진폭 보정으로 이 세로 간격은 해결되지 않았다.
- 현재 실제 default Native SVG의 첫 문장 기준선은 187.24px다. 독립 한컴 Print PDF의 같은 문장은 변환 행렬 y 배율 0.119869, Tm y=1230이므로 196.58516px다. Native가 9.34516px 위에서 시작한다. 다음 ‘경영상’ 기준선에서도 같은 방향의 차이를 확인했다.
- 원본에서 내보낸 진단 HWPX의 해당 셀(6행 2열)은 세로 가운데 정렬이고, 첫 문단 저장 vpos=0, 다음 문단 vpos=1980, 줄 높이 1100, 줄간격 880이다. 이 내보내기 파일은 독립 오라클로 사용하지 않으며 원본의 정렬·줄 소속을 확인하기 위한 진단 자료다.
- 현재 렌더 트리에서 해당 셀 상자는 y=172.9px, 높이=831.1px다. 표 상단선을 임의로 이동하는 문제로 처리하지 않는다. 큰 셀의 가운데 정렬에 사용하는 내용 높이와 실제 저장 문단 사다리 범위를 대조한다.
- `layout/table_layout.rs`의 내용 높이 생산(`calc_composed_paras_content_height`와 저장 extent) → `stored_flow_shape_is_trusted` → `total_content_height` 선택 → Center의 `(inner_height - total_content_height - align_lead)/2` → `text_y_start`가 확인할 소비 경로다. 현재 저장 흐름의 신뢰 판정은 중첩 또는 TAC 표를 먼저 요구한다. 원본 비인라인 셀의 저장 내용 범위가 제외되는지 확인하고 공통 규칙으로 보정한다.
- 완료 후보의 빌드·WASM 검증이 실행 중이므로 같은 소스 파일을 중간에 변경하지 않는다. 실제 수직 정렬 계산값을 확인한 뒤 수정·기존 회귀·전체 Native/fresh WASM TSV·review PNG로 검증한다. 새 테스트, 문서 ID 분기, 임의 좌표 이동은 추가하지 않는다.

## 상태

원인 계층은 셀 내용 높이와 수직 정렬 경로로 좁혔으며, 세로 간격 수정과 검증은 아직 완료되지 않았다.
