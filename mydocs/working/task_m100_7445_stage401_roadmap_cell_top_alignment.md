# 단계 401: 로드맵 44쪽 큰 셀의 상단 간격

## 사전 분석

- 사용자의 추가 첨부는 아래 큰 셀 첫 문장 ‘정규직 고용보호 완화’의 상단 간격을 가리킨다. 첫 얇은 행의 기호 전진폭 보정으로 이 세로 간격은 해결되지 않았다.
- 현재 실제 default Native SVG의 첫 문장 기준선은 187.24px다. 독립 한컴 Print PDF의 같은 문장은 변환 행렬 y 배율 0.119869, Tm y=1230이므로 196.58516px다. Native가 9.34516px 위에서 시작한다. 다음 ‘경영상’ 기준선에서도 같은 방향의 차이를 확인했다.
- 원본에서 내보낸 진단 HWPX의 해당 셀(6행 2열)은 세로 가운데 정렬이고, 첫 문단 저장 vpos=0, 다음 문단 vpos=1980, 줄 높이 1100, 줄간격 880이다. 이 내보내기 파일은 독립 오라클로 사용하지 않으며 원본의 정렬·줄 소속을 확인하기 위한 진단 자료다.
- 현재 렌더 트리에서 해당 셀 상자는 y=172.9px, 높이=831.1px다. 표 상단선을 임의로 이동하는 문제로 처리하지 않는다. 큰 셀의 가운데 정렬에 사용하는 내용 높이와 실제 저장 문단 사다리 범위를 대조한다.
- `layout/table_layout.rs`의 내용 높이 생산(`calc_composed_paras_content_height`와 저장 extent) → `stored_flow_shape_is_trusted` → `total_content_height` 선택 → Center의 `(inner_height - total_content_height - align_lead)/2` → `text_y_start`가 확인할 소비 경로다. 현재 저장 흐름의 신뢰 판정은 중첩 또는 TAC 표를 먼저 요구한다. 원본 비인라인 셀의 저장 내용 범위가 제외되는지 확인하고 공통 규칙으로 보정한다.
- 완료 후보의 빌드·WASM 검증이 실행 중이므로 같은 소스 파일을 중간에 변경하지 않는다. 실제 수직 정렬 계산값을 확인한 뒤 수정·기존 회귀·전체 Native/fresh WASM TSV·review PNG로 검증한다. 새 테스트, 문서 ID 분기, 임의 좌표 이동은 추가하지 않는다.

## 상태

원인 계층은 셀 내용 높이와 수직 정렬 경로로 좁혔으며, 세로 간격 수정과 검증은 아직 완료되지 않았다.

## 구현

- 원본 본문 표의 내용 범위가 셀 안높이에 들어가고 문단 사다리가 유효할 때 기존 저장 흐름의 높이·원점을 수직 정렬에도 사용하도록 확장했다. 측정과 실제 문단 배치는 같은 저장 결과를 소비한다.
- 편집·재조판·줄 수 변경·합성 줄·중첩 표·머리말/꼬리말 경로는 기존 판정을 유지한다. 비흐름 개체와 줄 앵커 유효성은 기존 공통 검사를 그대로 적용한다.
- 특정 문서·행·페이지 ID나 고정 이동량은 코드에 넣지 않았다. 아직 실제 PNG와 기존 회귀 실행 전이므로 구현을 완료 검증으로 보고하지 않는다.
- 이전 글리프 폭 코드의 Native 빌드, Native/WASM32 Clippy와 Mac no-opt fresh WASM 빌드는 완료됐다. 이번 내용 범위 변경의 새 빌드와 시각·회귀 증거로 대신하지 않는다.

## 첫 후보 철회와 실제 소비 경로 확인

- `a99c88bee` 후보의 실제 44쪽 SVG/PNG는 기준선 187.24px와 비교 수치가 이전과 동일했다. 일반 셀의 저장 흐름 확장은 이 분할 표에 효과가 없다. 해당 소스 변경은 철회한다.
- 완료된 fmt·default Native 빌드·실제 PNG는 그대로 보존한다. 효과 없는 후보를 철회하므로 진행 중이던 해당 후보의 focused nextest만 취소했으며, 취소 사유·PID·로그를 output에 기록했다. 이를 PASS로 세지 않는다.
- 실제 경로는 `layout/table_partial.rs::layout_partial_table_cells`다. 원본 셀의 일부 문단이 다음 쪽에 남았다는 사실 때문에 `cell_was_split`이 참이 되고, 조각 자신의 유한한 물리 프레임이 있어도 `effective_align`이 Top으로 바뀐다. 위 정렬만을 가정한 프로브 최적화는 가시 내용 높이 계산도 생략한다.
- 기존 `row_cut_starts_original_paragraph_frame`은 원본 문단 사이의 저장 쪽 경계를 측정에서 인증한다. 본문 물리 프레임이 소유하는 같은 끝 컷을 배치에서도 소비하여, 프로브와 높이·정렬 모두 현재 조각의 소유를 공유하도록 수정한다.

## 분할 표 소비 경로 보정

- `source_body_frame`과 동일한 원본 문단 끝 컷을 `frame_owns_alignment`에 반영했다. 선언 본문 프레임이 있고 기존 source certificate가 문단 사이의 원본 쪽 경계를 인증할 때, 현재 가시 문단 범위를 구성하여 원래 Center/Bottom 정렬을 계산한다.
- 위 정렬 전용 프로브 최적화도 같은 프레임 소유 판정을 소비하므로 가시 내용 높이를 0으로 생략하지 않는다. 새로운 컷·문단·높이·좌표는 만들지 않으며 앞뒤 조각의 소유는 보존한다.
- 병합 셀·블록 컷·원본 프레임이 없는 재조판·문단 내부 임의 컷은 이 변경에 포함되지 않는다. 숫자 이동량이나 문서 이름 분기는 없다. 새 Native PNG와 기존 회귀 실행이 필요하다.

## 실제 Native 판독 결과

- 분할 표 소비 경로 보정 `641602768`의 default Native 빌드가 163초대에 완료됐고 실제 44쪽 review 생성도 exit 0으로 완료됐다.
- 첫 글줄 기준선은 187.24px → 196.78667px로 바뀌었다. 독립 한컴 PDF 196.58516px와의 차이는 -9.34516px → +0.20151px다. 고정 이동량을 적용한 결과가 아니라 인증한 물리 조각에서 원래 Center 정렬을 계산한 결과다.
- 수정 전후 렌더 트리의 TextRun 텍스트와 문단 인덱스 순서가 모두 동일함을 확인했다. 실제 PNG와 확대 판독용 crop을 `roadmap-cell-top-p044-native-review.png`와 `roadmap-cell-top-p044-native-detail.png`로 보존했다.
- 해당 쪽의 2px 보조 일치율은 99.99955%, 엄격 내용 픽셀 일치율은 84.01278% → 86.82509%다. 확대 판독에서 큰 셀의 상단 간격이 맞아졌으며, 잔존 글자 모양·누적 간격과 전체 Native Skia/fresh WASM 검증은 별도 확인한다.
- 기존 focused nextest는 실행 중이다. 완료되지 않은 검사와 단일 쪽 보조값으로 PR 준비 완료를 주장하지 않는다.
