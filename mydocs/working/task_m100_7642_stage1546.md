# Issue #7642: 차트 원문의 시스템 색과 소유 프레임

## 독립 근거와 원인

단계 1539의 PrEP 본문 보정 뒤 전 140쪽 중 Native 27쪽이 89.91062%로 남았다.
고정 devel `2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`도 같은 Print·96dpi·none에서
89.89956%다. 이 수치만으로 기존 회귀를 제거하지 않고 현재 브랜치에서 보정한다.
원본 `Chart/chart2.xml`의 바깥 `c:spPr/a:ln`은 9525 EMU와
`a:sysClr val="windowText" lastClr="000000"`을 선언한다. 실제 Print는 검정 선이다.
기존 parser가 `srgbClr`·`schemeClr`만 처리해 시스템 색을 누락했고,
renderer는 명시 선이 없다고 판단해 기본 회색 프레임을 그렸다.

[Microsoft의 SystemColor 문서](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.systemcolor?view=openxml-3.0.1)의
`lastClr`은 생성 프로그램이 마지막으로 계산한 색이다. 이 서버 출력에서는 그 저장 값을
소비하는 방식을 택하며, 원본의 `000000`과 독립 Print의 검정 선이 일치함을 근거로 삼는다.
현재 호스트 UI 색으로 문서의 저장 값을 바꾸지 않는다.

## 생산과 소비

현재 `line_owner`가 인정한 chartSpace·plotArea 선의 `lastClr`을 RGB로 읽어
`LineSpec::Solid`에 원래 굵기와 함께 전달한다. `line_attr`가 같은 속성을 SVG로 쓰고
Native/fresh WASM의 RawSvg 재생 경로가 소비한다. 좌표·실루엣 문턱은 수정하지 않는다.
색을 계열 채우기나 제목·축 등 다른 소유로 승격하지 않는다. 잘못된 색 문자열이나
`lastClr` 부재는 독립적인 색을 추정할 근거가 없으므로 기존 미지정 상태를 유지한다.

기존 parser 테스트는 별도 자식 파일로 옮겨 수정 코드 파일을 1000줄 이하로 유지한다.
테스트의 입력과 기대값은 바꾸지 않는다. 새 렌더링 회귀는 원본 전쪽의
Native/fresh WASM 90%·직접 판독을 마친 뒤에만 추가한다.

## 남은 분석과 검증

27쪽의 막대·범례·세부 위치와 67쪽의 미세 줄 나눔을 같은 독립 Print로 확인한다.
차트 색은 `apply_preview_palette`가 OLE 미리보기의 막대에서 복원하는 경로도 있어서,
단순 테마 색만으로 현재 출력의 원인을 설명하지 않는다. 원본 fallback OLE의
legacy presentation은 현재 reader에서 수용되지 않았으며, 이를 새 파싱 성공으로
보고하지 않는다. 해당 실패는 ignored 단계 1544에 보존했다.

전쪽 미달·확대 판독의 남은 차이와 fresh WASM·전체 회귀가 해소되기 전까지 PR은 보류다.

## 실행 결과와 생산물 구분

초기 기본색 처리 후보의 Native 생산 기록은 `stage1548-current-native.json`이다.
그 후보로 실행한 `stage1549-chart-and-body-qualification/receipt.json`은 원본
140쪽의 쪽수 일치·누락 없음·전쪽 90% 이상을 확인했으며 최저는 **91.54965%**다.
27쪽은 89.91062%에서 91.54965%로 개선됐다. 원문이 지정한 검정 차트 외곽의
반영을 확인하는 자료이며, 범례·막대·67쪽 미세 분할까지 완료됐다는 뜻은 아니다.

그 뒤 시스템 색에도 기존 `lumMod/lumOff` 처리를 공유하도록 했다.
새 분기의 원래 색을 보관하고 닫는 태그에서 기존 명도 계산과 선 소유 전달을 사용한다.
이 최종 소스의 Native/fresh WASM 재산출은 별도 진행한다. 앞의 초기 Native 자료를
최종 소스의 fresh 출력으로 표시하지 않는다.

`stage1547-chart-parser-tests.log`와 `stage1550-chart-parser-tests.log`에서
기존 차트 모듈 **165/165 PASS**, 종료 코드 0이다. `rustfmt`·diff check도 통과했다.
`stage1550-chart-parser-test-move.json`은 기존 테스트 블록과 이동한 파일이
같은 rustfmt 결과임을 확인한다. 입력·기대값·검사 이름을 고치지 않았고 새 렌더링
회귀를 등록하지 않았다. parser와 자식 테스트 파일은 각각 963줄·634줄이다.
