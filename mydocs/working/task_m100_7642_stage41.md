# 이슈 #7642 — 간격 0 미주 경계의 마지막 줄 간격 소유

## 독립 근거와 실패

대상 원본은 `samples/3-11월_실전_통합_2024-구분선위20미주사이0구분선아래20.hwpx`다.
한컴 2024 Print는 `pdf/issue7642-equation-print/`의 같은 이름
`equation-26-…-hwpx-print-2024.pdf`다. 이전 생산 소스 f316의 15쪽은
75.79976%이며 현재 61bf의 줄 배치 진단에서도 같은 경계 간격이 남는다.

15쪽 왼쪽의 앞 미주 마지막 본문은 한컴 기준선 241.28, 다음 미주 제목은
253.28이다(96 DPI 좌표). 차이는 본문 한 줄의 900 HWPUNIT이다. 원본의
마지막 줄은 높이 900과 줄 간격 452를 저장하지만 미주 사이 설정은 0이다.
RHWP는 앞 문단의 흐름 끝 249.04를 새 제목 원점으로 사용해 452 HWPUNIT의
간격이 남는다. 실제 내용 점유 끝은 243.0133이다. 다음 본문의 원점에도
같은 차이가 이어진다. 이 수치는 진단 근거이며 고정 px 회귀 기대값이 아니다.

`HeightCursor`의 간격 0 제목 forward 분기는 저장 좌표의 큰 전진을 버리면서
마지막 줄 간격을 포함한 순차 흐름을 그대로 소비한다. 그 뒤의 간격 회수
분기는 forward 분기를 제외하므로 미달 경계를 고치지 못한다. 제목 문자열이나
문항 번호에 조건을 추가하는 대신 실제 미주 경계의 공간 소유를 보정한다.

## 구현 계획과 적용 경로

1. 새 미주 준비 시 앞 미주의 마지막 줄을 현재 단이 완전히 소유하는지 확인한다.
   마지막 줄을 아직 소비하지 않은 조각, 앞 단의 조각, 첫 미주는 적용하지 않는다.
2. 미주 사이가 0이면 앞 미주 끝의 양수 줄 간격을 경계 간격으로 재사용하지 않는다.
   원본 IR은 유지하고 렌더 문단 사본의 마지막 줄 간격과 조판의 예약 높이를
   함께 회수한다. 본문 줄 높이·빈 문단·내부 줄 간격·내용은 유지한다.
3. 같은 회수량으로 다음 미주의 저장 흐름 기준도 이동한다. 소비 경로는
   원본 마지막 줄 → 현재 단의 tail 소유 확인 → 렌더 사본/조판 높이 →
   다음 미주 vpos 기준 → fit의 scratch 배치와 실제 paint다. 양수 미주 간격과
   음수 압축 간격은 정상 대조로 보존한다.
4. 고정 source의 Native로 14·15쪽 및 이웃 경계를 먼저 Print 대조한다.
   간격 0의 다른 원본과 기본 미주 간격 문서를 대조한다. 내용·소속·겹침과
   직접 확대를 확인한 뒤 전쪽 Native/fresh WASM을 검증한다.
5. 모든 관련 페이지 90% 이상과 판독을 충족한 뒤 실제 미주 소유·내용 순서·
   포함·겹침으로 정식 회귀를 작성/변경한다. 현재 미달을 숫자 기대값 완화나
   회귀 제거로 해소하지 않는다. 전체 110개 실패와 #1139 전환도 계속한다.

진단 JSON·로그·TSV·nextrun은 ignored output에 보존한다. 실행 전후 source와
입력·Print의 SHA를 고정하고, 이전 부정 기호 단계의 전쪽 결과는 해당 source로
구분한다. 현재 단계의 구현·새 출력 검증은 아직 미완료다.
