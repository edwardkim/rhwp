# #7642 Stage 173 — 그리스 기호 표시와 고정폭 공백 검사 입력

Issue: #7642

## 고정폭 공백의 독립 계약과 검사 계획

기존 `issue_6597_figure_space_advance`는 `CharShape::default()`의 크기 0을
직렬화해 측정 줄이 비었다. 전역 기본값 0의 계약을 바꾸거나 원래 검사를
통과했다고 보고하지 않는다. 원본 30307의 글자 속성에서 휴먼명조 계열의
정상 fontRef를 가져오고 spacing=0, 1000/1500/2000/3000HU의 각 크기마다
`가가`/일반 공백/고정폭 공백의 세 문단을 독립 저장·Print했다.

진단 `pdf/issue7642-figure-space-diagnostic/figure-space-input.hwpx`와 한컴
2024 저장 HWP·Print PDF는 하나의 동일 입력 계보다. MCP는 명시적 engine
2024, Print method 0이다. Native/fresh WASM 모두 전체 1/1쪽, 최저 100%,
미달·누락 없음이며 직접 review에서 본문 순서·같은 크기의 공백 차이를 확인했다.
Print의 고정폭 전진/글자 크기는 0.253/0.248/0.245/0.248em이며, 일반
공백과의 비는 약 절반이다. 소유 문단·내용 보존과 이 독립 비율을 새 이름의
정식 검사로 추가한다. 소스/렌더 원점의 고정 px 선택은 사용하지 않는다.
기존 0pt 설정의 검사는 새 검사로 교체하되, 이를 엔진 결함의 수정 전 FAIL /
수정 후 PASS로 주장하지 않는다. 원본 30307 전체도 현재 생산 코드에서 재검증한다.

## 그리스 변형과 스타일의 독립 근거

v9: 600/1500/2400HU의 변형·직접 Unicode·스타일 114개, 전체 4쪽.
현재 Native 최저 89.86447%, 4쪽 미달이다. `phi`/`varphi`,
`epsilon`/`varepsilon`을 동일 Unicode로 접은 기호표와 `varrho`의 누락,
직접 Unicode의 대체 face를 확인한다. `varkappa`는 한컴도 문자로 읽으므로
임의 명령으로 추가하지 않는다.

v10: 20개 이름 × 기본/rm/it/bold × 1500/2400HU의 160개, 전체 5쪽.
현재 Native 최저 89.80821%, 5쪽 미달이다. 독립 Print의 각 이름은 네
스타일에서 같은 글꼴·기호 코드다. 그리스 기호는 라틴 변수 스타일로 다시
기울임·굵기를 적용하지 않는다. 특히 `phi`는 HYhwpEQ U+E0B1,
`varphi`는 U+E0C2, `epsilon`은 U+E0A1, `varepsilon`은 U+E10E로 구분된다.
`varrho`는 Haansoft Batang의 U+03F1을 사용한다. 직접 U+03D5/U+03F5/
U+03F1/U+03F0/U+03D1도 Print의 실제 대체 face를 대조한다.

생산·소비 추적: 명령 표의 원문 의미 → parser의 MathSymbol/Text 구분 →
한컴 face의 기호 표시·논리 전진 → LayoutBox 공통 결과 → SVG/Canvas/Native
paint. MathML 일반 표시 경로와 한컴 기호의 Print 계약을 구분한다.
소유 입력·식 문자열·페이지 좌표 예외 대신 기호와 face의 규칙으로 수정한다.
라틴 rm/it/bold, 혼합 철자와 미지원 명령은 반례로 보존한다.

출력을 먼저 보정하고 전체 Native/fresh WASM·확대 판독 뒤 새 이름의 관계형
회귀를 추가한다. 기준값/golden 완화·자동 갱신과 PR 완료 판정은 하지 않는다.

## 그리스 표시의 구현 근거와 소비 위치

`layout/source_greek_symbol.rs`가 기호별 공개 수학 glyph·원본 hmtx 전진과
직접 Unicode의 독립 대체 face를 하나의 LayoutBox로 만든다.
`layout_text`의 한컴 literal 경로와 `layout_math_symbol`의 한컴 명령 경로가
이를 소비한다. 일반 수학 face는 기존 경로로 남긴다. SVG/canvas는 공통
수학 알파벳 glyph를 다시 기울임·굵기로 바꾸지 않으며, 명시적 FontGlyph의
대체 face도 두 출력이 같은 상자를 소비한다.

원문 의미는 `symbols.rs`에서 varphi/varepsilon을 각각 별개 scalar로 보존하고
varrho를 추가한다. tokenizer의 기존 안전 그리스 접두사 조회도 같은 의미를
소비하므로 붙인 X를 누락하지 않는다. 한컴 글꼴의 바이트·윤곽을 추가하지
않고 설치 face의 hmtx 메트릭과 공개 LMM glyph 대응만 사용한다.

v11의 64개 혼합·직접 문자·라틴 대조도 독립 Print했다. 수정 전 전체 Native
최저 94.39969%이나 확대 결함을 점수로 면제하지 않는다. 구현 뒤 v8–v11 전체를
Native/fresh WASM에서 다시 대조하며, 기존 원본의 영향 범위도 이어 검증한다.
