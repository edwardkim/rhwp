### 코드에서 확인한 불일치와 원인 후보

1. `typeset.rs::try_typeset_empty_para_float_table`은 표 높이가 남은 공간에 들어가면
   `para_float_lanes`에 점유 영역을 예약한다. 들어가지 않으면 false를 반환한다.
2. 호출자는 false일 때 `typeset_block_table`로 전환한다. 이 경로가 통째로 배치한
   표의 점유 영역을 같은 lane 예약에 등록하는 처리가 없다. 후속 float의 보정도
   `PageItem::PartialTable`을 검사하며, 통째 표 `PageItem::Table`은 포함하지 않는다.
3. block 경로의 `saved_host_line_after_stack_fits`는 저장된 선언 높이와 host 원점으로
   통째 배치를 구제한다. 같은 host에서 사용자가 내용을 늘렸으나 아직 연속 조각이
   없는 이번 상태를 종전 보완 조건만으로 차단하지 못한다.
4. `layout/table_layout.rs`의 문단 기준 표 하단 제한은 `본문 하단 - 표 높이`로
   y를 클램프한다. 이는 실제로 표가 커질수록 위로 이동하며 하단 1084.7px가 고정되는
   관측과 일치한다.

반복본의 5회째에는 본문 시작 이후 예약 높이 약 95.0 + 936.9 = 1031.9px가
가용 높이 약 1046.9px 안에 들어가지만, 6회째에는 95.0 + 958.2 = 1053.2px로
넘는다. 원본은 시작점이 8px 높아 이 전환이 7회째다. 이 수치와 코드 분기가
**공간 부족 시 lane→block 전환, 저장 배치 구제, 후속 점유 정보 누락**이라는 원인
후보를 지지한다. 이번 브라우저 실행에서 내부 분기별 trace를 직접 수집하지는 않았으므로,
수정 전 회귀 테스트로 해당 경로를 고정하고 확인해야 한다.

### 후속 #7065의 수정 방향 — 아직 미구현, #3587 범위 제외

- 배치 경로와 무관하게 먼저 놓인 표의 실제 점유 공간을 후속 표가 공유해야 한다.
  통째 표와 분할 조각을 서로 다른 점유 규칙으로 취급하지 않는다.
- 사용자 편집으로 변경된 표 크기에는 변경 전 저장 frame이 현재 쪽에 들어간다는
  증명으로 사용되지 않도록 한다. 기존 #2813의 미편집 서식 보호는 별도로 유지한다.
- 공간 부족은 페이지네이션에서 해결한다. y를 위로 당겨 기존 표 위에 얹는 결과를
  수정 완료로 인정하지 않는다. 단순 하단 clamp 삭제만으로 처리하지 않는다.
- 원본/HWP/HWPX 및 한컴 복사본에 Enter 1~15회 각각의 순서·겹침 검사를 추가하고,
  줄 삭제·undo의 역방향 전환도 검사한다. 특정 Enter 횟수나 샘플명 분기는 금지한다.

## 메인테이너 결정 — 재편집 결함의 별도 처리

2026-09-12 메인테이너는 생성 HWP/HWPX가 한컴편집기에서 정상 편집되므로 이번 현상을
복사·붙여넣기 결함으로 취급하지 않고, 별도 이슈로 등록해 나중에 처리하도록 결정했다.

- 등록: [#7065 — 셀 Enter 편집 중 후속 표가 이전 쪽으로 되돌아와 겹치는 페이지네이션 오류](https://github.com/edwardkim/rhwp/issues/7065)
- 분류: `bug`, `layout`, `table`, `rhwp-studio`; milestone `v1.0.0`.
- 상태: 후속 처리 대기. 이슈만 등록했으며 새 브랜치·구현에 착수하지 않았다.
- #3587의 복사·저장 구현은 보존한다. 이번 결함을 이유로 파일 내용이나 복제 속성을
  임의 변경하지 않는다. 기존 Stage 7 코드의 삭제·되돌리기도 이번 지시에 포함하지 않는다.
- 재현 실패와 증적은 그대로 유지한다. 범위 분리는 해당 실패를 PASS로 바꾸거나
  B 종료 게이트·C 구현·Gym 시뮬레이션 등 #3587의 다른 잔여 절차를 면제하는 결정이 아니다.
