# #7642 중첩 표 종료 조각에서 호스트 전체 높이의 재소비 방지

## 원인과 실제 경로

`stage3431/3432/3433`은 후보 런타임 `7d685cc178`과 새 base `6ed1682c32`의
`samples/issue1880_takeplace_host_before.hwpx`를 같은 조건에서 실행했다.
전체 Print 대조는 양쪽 모두 미달이며, 원래 차이와 새 겹침을 구분한다.
후보에서만 `layout-anomaly`의 가시 글자 겹침 6건이 6쪽에 생긴다.

바깥 표 문단 6의 셀 (6,1)은 rowSpan=1이다. 시작 컷 17에서 중첩 문단 9의
자식 행 1..2를 이어받으며, 자식의 실제 bbox는 양쪽 모두 y94.7, h27.4px다.
같은 물리 행 상자와 같은 내용 컷인데 다음 문단 10의 원점은 base y130.2,
후보 y167.8이다. 이후 문단마다 37.6px가 누적 잔류해 셀 말미가 다음 행과 겹친다.

자식의 종료 여부를 올바로 확인한 뒤 `table_partial.rs`의
`stored_inline_table_successor_advance`가 저장된 **호스트 전체** 전진량으로
현재 조각의 `para_y`를 덮어쓴다. 앞 조각이 이미 첫 행을 소비했는데도 그 몫을
또 싣는 것이 원인이다. 컷 선택·자식 실제 배치 → 현재 조각 전진 끝 → 저장
successor 덮어쓰기 → 뒤 문단 배치의 실제 연결을 확인했다.

## 수정과 적용 경계

기존 `owns_paragraph_entry`는 실제 CellUnit 컷이 그 문단의 첫 유닛을 소유하는지
확인한다. 문단 앞 간격과 자식 시작점에 쓰는 동일 소유 결과를 저장 successor
전체 슬롯의 수용 조건에도 사용한다. 시작을 이전 조각이 소유하면 이미 구한
현재 자식 컷의 전진 끝을 유지한다. 종료 줄간격은 기존 종료 소유 조건으로 남긴다.
일반 온전한 문단의 저장 슬롯, 부분 중첩 표의 종료 의미, 내용 순서·컷을 바꾸지 않는다.

기존 큰 함수에는 소유 조건과 설명만 추가한다. 별도 계산 helper나 문서별 예외를
늘리지 않고 현재 공통 소유 결과를 재사용한다. 좌표 clamp·출력 숨김·baseline 갱신은 없다.

## 실행 계획과 미검증

아직 수정 후 실행 전이다. `stage3429`의 저장 경계 수정과 한 후보로 묶어 빌드한다.
대기 중이던 이전 후보 전용 빌드는 아직 Cargo를 시작하지 않았음을 확인한 뒤
대체한다. 기존 49건, 새 적격 경계 검사, 두 실패한 표 예산 검사, 해당 겹침 진단을
같이 확인한다. 이 원본 10쪽 Native/fresh WASM Print 비교와 6쪽 확대 판독을
이어가며 전체 90%를 충족하기 전에 새 렌더링 회귀·fixture를 추가하지 않는다.

현재 원본 10쪽 미달과 나머지 실패 보정, 최종 전체 Rust·전체 시각 검증·PR·CI·
옵션 2 문서 PR·후속 처리 범위는 유지한다. 일부 겹침 수정으로 전체 완료를 주장하지 않는다.
