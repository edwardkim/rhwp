# #7642 단계 2694: 줄 끝·마커·어울림 원점의 근거 분리

Issue: #7642.

## 실행으로 확인한 앞 후보

af71 Native 빌드가 exit 0, 673.23초로 완료됐다. #1440 원본 두 형식의
쪽수는 46쪽으로 독립 Print와 일치했다. p138은 앞 쪽 1줄·다음 쪽 3줄로
분할되고, p168의 빈 문단도 같은 쪽의 물리 여유에 보존됐다. 쪽수만으로
시각 완료를 선언하지 않는다. 원본 6·15·36쪽은 90% 미만이다.

국어 두 형식은 14쪽이 85.11866%로 미달이다. 첫 어울림 호스트 p33은
독립 원점 450.5px로 돌아왔지만 두 번째 p37은 643.8px로, 독립 원점
671.1px보다 위에 있다. 첫 plan의 재계산 간격과 저장 값의 차이가
후속 원점 검증을 거절한 실제 경로를 확인했다.

## 현재 변경

1. 앞 plan의 문자 소속·줄 높이를 확인하고 실제 행 점유가 다음 저장
   원점 안에 포함되는지 검사한다. 재계산 후행 간격의 단순 숫자 일치를
   원점 유효성의 대용으로 쓰지 않는다. 실제 겹침과 행 구성 변경은 거절한다.
2. 같은 토큰의 자동 줄 끝을 현재 frame으로 검증하는 기존 경로를 Reflow
   본문에도 연결한다. 영숫자·한글 꼬리와 금칙 닫는 기호를 확인한다.
3. paint와 같은 마커 스타일의 크기를 첫 물리 줄의 공통 최대 글자 크기에
   포함한다. 뒤 줄 또는 중간 조각에 번호 높이를 중복 계상하지 않는다.
4. PostScript 조회는 실제 설치 style set의 식별자 색인만 사용한다.
   없는 family를 OS에 직접 질의하지 않아 headless CoreText 다운로드 IPC
   회피 계약을 보존한다. 앞 cf2 커밋의 불필요한 직접 질의를 제거했다.

## 검증 상태

새 변경의 incremental diff check와 rustfmt는 통과했다. 현재 af71의
WASM 최적화와 앞 후보 검증이 실행 중이므로 공용 target 빌드를 병행하지 않는다.
새 코드의 컴파일·전체 회귀·Native/fresh WASM 및 base 무회귀는 미검증이다.
새 실물 회귀는 관련 전쪽 90%와 확대 판독이 선행한 뒤 추가한다.

진단 근거는 ignored output의 `stage2687-shared-boundary-1440-traces/`,
`stage2691-shared-boundary-1440-panels/`, `stage2693-1440-word-tail-probe/`에
보존했다. 진단 HWPX는 p19의 LineSeg만 제거한 RHWP 진단 입력이며 공식
한컴 생성 입력 또는 새 기준 PDF로 보고하지 않는다.

### 같은 마커 결과를 소비하는 경로 보완

`line_breaking/list_marker_metrics.rs`에서 실제 마커 크기와 본문 크기의
최댓값을 공통으로 정한다. 현재 frame의 fresh 첫 줄뿐 아니라 저장 행의
carve 메트릭과 scalar 재조판의 첫 LineSeg 생성도 같은 결과를 소비한다.
중간부터 재조판하는 행은 UTF-16 시작·실제 첫 행 여부로 제외한다.
이 연결 역시 컴파일·시각 검증 전이며 앞 후보의 실행 결과와 구분한다.
