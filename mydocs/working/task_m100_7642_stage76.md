# #7642 Stage 76 — 종단 TAC 단어와 줄 끝 공백의 공통 줄 소유

Issue: #7642

## 독립 근거와 반례

Stage 75에서 잘못된 복합 수식 프레임 수용은 제거했다. 수정한 source
9a56582e9의 정상 paired CASES 전체 1쪽은 98.16677%로 회복했으며,
Native 빌드·fmt·Native Clippy가 exit 0이다. 전체 55개 원본·853쪽과
292개 회귀의 범위는 유지하며 아직 완료로 판정하지 않는다.

한컴 2024 저장·Print한 공백 0/1/3/6개 대조의 원본 줄과 PDF를 분석했다.
공백 0개에는 `(단위 : ` 다음 줄에서 `천원)`을 소유하고 그 다음 줄에
표가 있다. 1/3/6개는 표와 앞 단어 사이에 작성된 공백이 있으므로
같은 무공백 단어 묶음이 아니다. 공백 3개는 첫 두 공백을 앞 줄이
소유하고 마지막 공백은 표와 같은 줄에 남는다. 6개는 앞 두 공백 뒤
별도 공백 줄과 표의 자기 줄이 있다.

Print의 실제 3쪽 문자열에는 앞 줄의 두 공백 원점이 본문 우단 전후에
있다. 공백은 전진 끝이 우단을 넘었다고 즉시 다음 줄로 옮기는 잉크
글자가 아니다. 기존 plan은 현재 pen과 공백의 끝을 같은 상태로
판정해 한 공백 일찍 줄을 끝낸다. 특정 공백 수나 px 좌표로 보정하지
않고 현재 줄의 전진량과 다음 구분 공백의 소유를 구분한다.

또한 한컴돋움 단위 표기의 공통 measurer는 89.29333px인데 plan은
문자를 하나씩 반올림해 89.66667px를 소비한다. 이는 진단 관측이며
기대 좌표 상수가 아니다. source offset·글자 모양·같은 측정 함수를
사용하고 마지막 글자마다 반올림하지 않는다. 실제 HWPUNIT/배제
영역의 기존 좌표 변환 계약은 유지한다.

## 생산과 소비 경로

`inline_flow::plan`의 공통 텍스트/표 atoms → 어절과 직접 붙은 TAC의
후보 폭·기준선 → row_geometry의 같은 줄 수용과 제외 영역 →
finish_row의 줄 소유·점유 끝 → commit_inline_flow의 fit·예약 높이 →
layout_inline_flow_plan의 실제 원점으로 이어진다. 저장 LineSeg를
소비하는 경로에는 새 재조판 규칙을 적용하지 않는다.

- 텍스트 scalar는 기존 unrounded measurer로 재고 paint의 같은 box에 보존한다.
- 공백 없이 붙은 TAC는 어절의 수용 후보에 포함한다. 앞 줄에 후보가
  안 들어가면 어절부터 다음 줄로 옮기고, 빈 줄에서도 둘을 함께
  수용할 수 없으면 개체 앞의 물리 경계에서 분리한다.
- 개체 앞 공백은 pen이 아직 줄 안이면 현재 줄에서 전진할 수 있다.
  이미 우단을 지난 뒤의 다음 구분 공백은 앞 줄에서 소비해 줄을
  끝낸다. 그 뒤의 작성된 공백은 다음 물리 줄과 개체가 함께 소유한다.

고정 offset·클램프·문서 ID·공백 개수 분기를 추가하지 않는다.
정상 paired CASES, 저장 공백 대조, 저장 줄 없는 대조, 실제 배포
원본, 기존 시험지·그림 경계를 같은 Native/fresh WASM source에서
확인한다. 전체 원본 TSV와 확대 판독 뒤에만 관련 회귀를 관계형으로
변경한다. 실패 입력을 제거하거나 baseline을 완화하지 않는다.

재실행 전이므로 완료로 판정하지 않는다. 기존 회귀 기대값과
fixture는 변경하지 않았다.
