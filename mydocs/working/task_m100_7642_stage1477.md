# Issue #7642: 개체 앞 작성 공백과 명시적 개행의 줄 소유

## 독립 근거와 원인

부모는 `bfb3f1f9e`다. 사회 호스트 보정과 새 회귀는 이전 단계에서 커밋했다.
이하 JSON·실행 파일은 ignored stage15-current-validation에 보존한다.
이전 소스의 WASM 대조군 큐는 보존한 Native·package를 사용하므로 그 결과를
이번 수정의 검증으로 재사용하지 않는다.

한컴 Print 2020의 r2 6쪽·r3 9쪽·r4 20쪽 진단은 문서 ID나 고정 좌표가 아닌
작성 공백의 경계 계약을 분리한다. `stage1450-inline-boundary-input.json`,
`stage1450-inline-boundary-print.json`, `stage1451-inline-boundary-print-measurements.json`,
`stage1459-inline-boundary-native-vs-print-origins.json`에 원본·PDF 해시와 독립 측정이 있다.
진단 파일은 아직 정식 회귀 fixture가 아니며 전쪽 Native/fresh WASM과 직접 판독 전에는
새 렌더링 회귀로 등록하지 않는다.

본문 뒤 개체 앞의 연속 작성 공백에서 첫 공백만 줄 우단을 넘어 전진할 수 있다.
그 뒤 공백이 넘치면 폭 없이 현재 줄에서 소비하고 줄을 닫으며 남은 공백은 개체와 함께
다음 줄의 폭을 차지한다. 현재 구현은 그룹의 첫 공백이 아니라 최초로 기하학적 폭을
넘긴 공백을 hanging 대상으로 삼는다. 따라서 81·82개 선행 공백, tracking -10·-20,
동일 스타일로 나눈 런에서 마지막 작성 공백을 잘못 흡수해 표를 약 8px 왼쪽에 놓는다.
tracking -5 이상·다른 선행 공백 수·공백만 있는 줄·후행 공백 4~5개는 반례다.

그룹은 가시 문자 인덱스의 인접 여부로 추정하지 않고 실제 atom 순서로 구분한다.
글자 축을 소비하지 않는 개체도 그룹을 끊으며, 부동 앵커·명시적 개행도 경계다.
글꼴 폭이나 문서별 상수를 조절하지 않는다.

`stage1461-inline-forced-break-print-metrics.json`에서 r3 자동 줄바꿈 4쪽과
명시적 개행 9쪽의 단위 표시는 같은 기준선 111.717906 CSSpx다. 뒤 공백만 있는 줄을
포함한 개체 기준선은 162.862020px다. 원문 개행은 본문 11pt와 다른 14pt 스타일이며
행이 비지 않았다는 이유로 이 개행의 줄 메트릭을 버리면 기준선·다음 줄 높이가 작아진다.
폭 0의 기존 개행 상자를 빈 줄뿐 아니라 작성된 모든 개행의 행 메트릭에 포함한다.
빈 줄·연속 개행의 실제 공간과 같은 크기 개행의 정상 경로도 확인한다.

## 실제 생산과 소비

`typeset/controls/paragraph_flow.rs::try_place_reflowed_table_rows`
→ `typeset/inline_flow/plan.rs::build_plan` → `inline_flow.rs::plan`이 공통 계획을 만든다.
`Atom::Break`와 공백 수용은 같은 `RowMetrics`·`finish_row`를 사용한다.
측정/fit는 계획의 end와 행 범위를, `layout/paragraph_layout.rs`의 실제 출력은 같은
boxes·rows 원점을 소비한다. 이번에는 다른 경로로 owner를 바꾸거나 원점을 clamp하지 않는다.

## 검증과 완료 조건

두 원인을 묶어서 수정한 뒤 고정 target/pr-review·잡 8개로 Native를 한 번 빌드한다.
r2/r3/r4 전체 쪽, 원래 배포 문서, 기존 인라인 개체·명시적 개행·그림과 사회 대조군을
검증한다. 큰 시각 차이를 먼저 직접 판독하고 동일 소스 fresh WASM을 빌드한다.
전쪽 90%와 쪽수·내용 보존·확대 판독 뒤에만 새 이름의 관계 회귀를 추가한다.
완료한 98% 이상 쪽의 중요한 경계에는 독립 Print ±2px도 관계 검사와 함께 둘 수 있다.

배포 문서의 PDF 래스터는 thinlinemode=shape가 실제 파랑 채우기를 흰색으로 만드는
별도 진단이 있다. 이 문제를 RHWP 채우기를 숨겨 해결하지 않는다. 기준 래스터 수정이
필요하면 모든 base/head와 Native/WASM에 같은 조건을 적용해 재측정한다.
## 첫 Native 검증

계획한 두 원인을 함께 보정했다. `separator_spaces.rs`가 실제 atom 순서에서 개체 앞
작성 공백 그룹의 첫 공백을 발행하고, 공통 계획이 이 소속을 수용 판정에 사용한다.
명시적 개행은 비어 있지 않은 줄에서도 기존 폭 0 상자를 행 메트릭에 포함한다.
`inline_flow.rs`는 982줄이며 문서별 수치나 글꼴 분기를 추가하지 않았다.

`stage1478-current-native.json`은 고정 target·잡 8개 빌드 exit 0과 생산 소스 해시 불변을
기록한다. `stage1479-inline-boundary-native/receipt.json`의 진단 결과는 다음과 같다.

명시적 개행 9쪽에서 단위 표시의 기준선과 표의 다음 물리 줄이 독립 Print와 일치하는지
새 review를 직접 열어 확인했다. 아직 fresh WASM 검증은 아니며 새 회귀를 등록하지 않았다.

배포 문서 3쪽의 남은 머리글 색상 차이는 PDF→PNG의 `shape` 설정이 실제 그라데이션을
지우는 문제다. `stage1483-distribution-raster-diagnostic.json`은 **같은 보정 Native PNG**와
**같은 원본 PDF**를 고정해 shape 90.67474%, 기본 none 100.00000%를 기록한다.
이 숫자는 기준 래스터 변경의 원인 진단이며 최종 gate로 대체하지 않는다.
none을 적용하려면 전 문서와 base/head 양쪽에 같은 정책으로 다시 측정해야 한다.
원본 PDF를 수정하거나 RHWP의 올바른 파랑 채우기를 숨기지 않는다.

## 기존 회귀와 최종 소비 경계에서 찾은 두 오류

`stage1480-host-fragment-focused-nextest.json`의 기존 관련 회귀는 **32 PASS / 1 FAIL**이다.
실패는 `issue_7482_shared_paragraph_table_rows::authored_break_moves_second_tac_even_when_both_fit`의
가운데 정렬 표 경계다. 개행 메트릭 상자를 넣은 뒤 `finish_row`의 역방향 후행 공백 조회가
빈 범위를 만나 중단했다. 따라서 표 앞에서 소비할 공백 너비가 가운데 정렬 폭에 남았다.
빈 메트릭 범위도 후행 공백 조회가 통과하게 하며 실제 너비는 0을 유지한다.
정확한 기존 관계 검사와 기대값을 바꾸지 않는다.

`stage1482-break-position-diagnostic.rs`는 개행과 앞 글자를 같은 스타일로 만든 합성 대조다.
이 대조는 한컴 출력 일치의 증거가 아니다. 기존 배치 후 소비자의 독립 불변식인
`layout_positions.len() == text.chars().count() + 1`이 실패했다. 91자 런에 93개 원점이
생겼다. `layout/paragraph_layout.rs`의 런 합치기가 폭 0·빈 개행을 가시 문자 한 개처럼
붙였기 때문이다. 빈 개행은 자체 원점 하나를 유지하며 앞 가시 런에는 합치지 않는다.
줄 메트릭과 커서용 빈 런을 제거하거나 줄 높이를 되돌리지 않는다.

기존 대형 배치 파일에는 이 실제 소비 지점의 최소 조건만 수정한다. 임의 파일 분할이나
전체 배치 재작성으로 범위를 늘리지 않는다. 두 오류를 함께 보정한 새 생산물에서 기존
33건·원점 배열 진단·전체 공백 진단·실패한 원본 `tac-explicit-break.hwpx`와 독립 Print를
다시 확인한다. 그 뒤 fresh WASM을 검증한다. PR 준비 완료로 판정하지 않는다.
