# #7642 Stage 178 — 피연산자의 공백 경계와 세로 묶음의 독립 대조

Issue: #7642

## 독립 근거와 확인할 계약

Stage 177의 카탈로그 3쪽은 93.06517%이지만 공백 없는 `a+b OVER c+d`가 잘못 묶인다. `a TIMES b OVER c TIMES d`의 Print에서는 앞뒤 TIMES가 분수 밖에 있다. 연산자 전체를 무조건 분수 인자로 묶지 않고, 공백을 달리한 네 조합·명시적 그룹·연쇄 OVER·ATOP의 독립 출력을 먼저 확인한다. mixed-case SQRT/ROOT와 정상 이름을 대조한다.

기존 독립 저장에서 일반 PILE 2·3·5행의 높이는 각각 3225·4950·8400 HU다. 현재 layout_pile은 일반 행 높이와 MATRIX_ROW_GAP 0.3em을 소비하고 기준선은 전체 높이의 절반이다. 한컴의 예약 기준선 비율·실제 표시 기준선·글리프 높이를 구분하며, 행 프레임을 같은 source 계약에서 계산한 뒤 실제 Native/WASM 소비 경로를 확인한다. 아직 이 차이를 보정 완료로 판정하지 않는다.

## 대조군 생성

기존 한컴 정상 저장 HWPX의 스타일·구역을 사용해 script 18개를 한 페이지에 하나씩 배치했다. 원래 수식 크기·baseline·LineSeg를 제거하고 MCP engine 2020의 정상 HWP 저장 뒤 같은 HWP를 Print했다. 실제 한컴 11.0.0.9136, PrintMethod 0, hancom2020_pdf_driver_one_up, 전체 18쪽을 확인했다. SAVE job `99959971-a032-474b-985f-6fe29732b213`, Print job `863d38f4-f275-49e7-a8ed-12e6c749747e`다. 입력·한컴 저장 HWP·Print PDF는 `pdf/issue7642-operand-frame-diagnostic/`에 보존한다. 수동 작성 script 대조군이며 최초 카탈로그의 일치나 검증된 회귀 fixture로 대신하지 않는다.

source 생성·MCP 결과의 비공개 항목을 제외한 receipt·실행 로그는 ignored output의 `stage178-operand-frame-print/`에 있다. 현재 source SHA의 Native 전체 대조를 실행한다. fresh WASM 빌드는 Stage 177 producer로 실행 중이므로 Rust 소스는 변경하지 않는다. 일반 문법·프레임 보정은 이 독립 대조 이후 묶어서 진행하며 90% 및 직접 판독 전에는 기존 golden을 바꾸거나 정식 렌더링 회귀를 추가하지 않는다.

## 현재 Native 및 실제 소비 경로의 추가 관측

18쪽은 누락 없이 측정됐지만 최저 8.23529%, 미달 16쪽이다. 2·5쪽만 100%다. 6쪽의 명시적 그룹 분수도 13.92097%로, 문법 차이 외에 본문+수식 줄의 높이·기준선 문제가 있다. 원본 6쪽 수식 높이는 3450 HU지만 LineSeg가 없고 현재 TextLine은 14.7, 수식 bbox는 46.0 CSS 단위다. `flow_metrics_hwp → compose_paragraph_in_context → refresh_equation_rows`는 실제 수식 높이를 받지만 `owned_equation_row`의 `text_height == 0` 조건으로 본문이 있는 캐시 누락 줄을 제외한다. 그 뒤 paragraph_layout의 raw_lh·baseline 및 인라인 EquationNode 원점이 이 작은 줄을 그대로 소비한다. 변환 과정에서 자료를 잃었다고 추정하거나 print를 잘못된 기준으로 제거하지 않는다.

Native TSV·source frame·같은 영역 review를 보존했다. 캐시 누락/재생성 줄의 본문·수식 ascent/descent 합집합과 정상 저장 줄의 별도 계약을 확인하고, 공백 피연산자 및 PILE 행 프레임 보정을 같은 구현 묶음에서 진행한다. 현재 source에는 이 추가 보정을 적용하지 않았다.

## 적용할 구현 묶음

이전 producer의 fresh WASM과 카탈로그 전체 대조가 종료된 뒤 Rust 소스를 변경했다. 캐시 없는/재생성된 혼재 줄에 같은 ascent/descent 합집합을 발행하며 정상 저장 줄의 계약은 유지한다. PILE은 matrix_row_box의 논리 프레임과 경계당 0.15em을 소비하고 가운데 수학 축과 기준선의 차이를 보존한다. 독립 Print에서 문자였던 혼합 대소문자 SQRT/ROOT는 문서 tokenizer에서 Text로 유지하며 공개 LaTeX 경로를 바꾸지 않는다. 공백 없는 복합 피연산자의 문법 보정은 한컴 공식 수식 사양의 항 구분 및 글꼴 전환 범위를 추가로 확인하고 있다. 해당 문법 차이를 이번 세 보정으로 해결했다고 보고하지 않는다. 세 원인의 보정을 함께 빌드하고 현재 대조군 전체 및 원 카탈로그 전체를 재산출한다.

사전 대소문자 검사에서는 실제 이전 document_script 소스를 사용해 혼합 근호 2건의 문자 분류가 수정 전 FAIL / 수정 후 PASS임을 확인했다. 정상 대문자·소문자·명시적 확장·기존 한컴 대조군 8건 및 공개 LaTeX parser도 통과했다. 실행 파일은 공용 target/pr-review/release-test이며 원문 receipt는 ignored output의 stage178-document-token-preflight.json이다. 이 결과로 혼재 줄·PILE의 시각 검증을 대신하지 않는다.

[한컴 공식 수식 사양 revision 1.3](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_%EC%88%98%EC%8B%9D_revision1.3.pdf)의 1.1.2.1·1.1.2.5에서 공백·탭·개행은 항을 구분하며 표시 공백을 만들지 않는다고 확인했다. 복합 피연산자 보정은 이 경계와 글꼴 전환 범위를 함께 보존해야 한다. 스타일의 범위를 바꾸는 임의의 중괄호 삽입으로 대신하지 않는다.
