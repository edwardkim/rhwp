# 단계 1045 수식 호스트의 줄 여유와 원본 HFT 영문 메트릭

Issue: #7642.

## 독립 근거와 묶어서 수정할 원인

이전 단계 `838834c6c`의 release WASM은 단계 1033에서 14분 24초 만에 정상 생성됐고 입력 소스 해시가 유지됐다. Native 25건 검사와 구분하며, 전체 시각 gate·전체 회귀·lint 완료를 뜻하지 않는다. 기존 생산 산출물의 55개 문서 검증은 그 source SHA로 보존한다.

HWP3 sample16 6쪽의 수식 호스트 문단 155·158은 본문 1300HU, 줄간격 130%, 수식 상자 높이 2808HU다. 파서는 상자 높이에 30%를 곱해 뒤 여유를 842HU로 만들었다. 한컴 저장본은 392HU이며 독립 Print에서도 다음 본문이 수식 하나마다 약 6px 덜 벌어진다. 원본 호스트 글자 크기의 30%인 390HU와 저장본의 차이는 2HU다. 고정 줄간격 분기는 유지하고, percent 줄간격의 TAC 수식 줄에서도 호스트 글꼴의 줄 여유를 소비한다. 그림·표의 기존 호스트 여유 계약과 같은 의미이며 수식 상자 자체 높이를 줄이지 않는다.

19쪽의 `ORACLE D/B, GIS D/B, XML D/B, File D/B` 줄은 각 `/` 뒤에서 오차가 누적된다. 원본은 HCI Poppy이고 대체 표시 face는 Palatino Linotype이다. 독립 Print의 Type3 T3(xref31), FontMatrix 0.001, Widths(xref1738), ToUnicode(xref1739)는 `/` 전진을 605/1000em으로 기록한다. 기존 대체 face의 약 0.32em과 다르다. 다른 영문 글자의 원점은 대부분 일치한다. HWPX 25쪽 `관련S/W` 뒤 약 4.1px 차이도 같은 부호·크기다. 출처는 `pdf/issue7642-hwp3-original-print/hwp3-sample16-2020.pdf`, SHA-256 `f1f2e6dd265d098ea468bae14b44e98a1609dd7eba293f91d73ba16704be73c5`다. 관측한 84개 문자 전진만 원본 HFT의 측정 자료로 등록한다. 글꼴 프로그램·윤곽선은 복제하지 않는다.

## 생산과 소비 경로

수식은 HWP3 저장 줄·호스트 CharShape → parser LineSeg.line_spacing → composer/typeset의 전진량 → 다음 본문 원점이다. 상자의 높이와 호스트 글꼴의 줄 여유를 분리한다. 원본 제어·스크립트·선언 높이는 보존한다.

영문은 원본 FontFace → 기존 legacy-latin 표시 치환 → 선언 face의 독립 메트릭 선택 → 공통 문자 측정·줄 나눔·charX → Native/WASM paint 원점이다. 표시 치환 규칙은 변경하지 않는다. 확인하지 않은 굵기·기울임에는 새 regular 표를 강제로 사용하지 않는다. 관측하지 못한 ASCII 문자는 원본 프로그램의 glyph 결측으로 선언하지 않고 기존 표시 face의 측정 경로를 보존한다. 공백의 별도 조판 계약도 그대로 둔다. 일반 Palatino 글꼴에 HFT 폭을 덮어쓰지 않는다.

## 대조군과 검증

합성 입력에서 수식 높이가 달라도 같은 호스트 글꼴·percent 줄 여유를 유지하는지 확인한다. 원본 HFT의 regular 슬래시와 실제 Palatino의 슬래시를 구별하고, 미측정 ASCII·확인하지 않은 bold/italic의 기존 경로를 확인한다. 수정 전 실패와 수정 후 통과를 실행한다. 실물 배치의 새 baseline·golden·절대 좌표 검사는 추가하지 않는다. 두 원인을 묶어 Native를 빌드하고 관련 검사를 실행한 뒤 HWP3/HWP5/HWPX 전쪽 TSV와 6·19·25·35쪽 확대 판독을 수행한다.

35쪽의 그림과 상자 위치는 별도로 추적했다. Native 그림 조각에 기존 PDF 합성 굵기 helper를 적용한 진단은 87.92359→87.96414%에 그쳐 주원인 해결로 채택하지 않았다. 이 수치는 전체 쪽 gate가 아니다. 같은 쪽의 표603은 독립 Print보다 약 7.4px 위이고 앞 문단 간격과 같은 크기다. 실제 route 진단에서 HWP3와 한컴 HWP5의 표 호스트 수용 경로가 갈린다. source U+FFFC·글자 유무·표 분류·저장 원점의 소비를 추적하며 확인 전에는 출력 보정이나 기대값 변경을 하지 않는다. 진단은 ignored 단계 1041~1044에 보존했다.

## 수정 전 실행

단계 1046은 정확한 기존 코드 `838834c6c`에 새 합성 검사만 적용했다. 초기의 비공개 helper 접근과 첫 제어를 수식으로 가정한 테스트 구성 오류는 수정했으며 그 실패를 엔진 결함 재현으로 세지 않는다. 공개 charX·실제 수식 제어를 사용한 정상 실행에서 원본 영문 전진 비율은 실제 0.40/기대 605÷785로 실패했고, 수식 뒤 여유는 실제 960HU/기대 600HU로 실패했다. 미측정 ASCII·미확인 bold/italic의 기존 표시 메트릭 대조군은 통과했다. source·로그·정정 실행은 ignored 단계 1046에 구분해 보존했다. 수정 후 결과는 아직 별도 실행이 필요하다.
