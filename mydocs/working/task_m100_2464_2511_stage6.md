# 작업 2464-2511 단계 6 - 확장 HML E2E 보정

## 문제

- 실제 Chrome unpacked extension E2E에서 정적 `.hml` 링크는 처리됐지만, `MutationObserver`로 추가된 노드가 `<a>` 자체인 경우 링크가 처리되지 않았다.
- `processLinks(node)`가 `node.querySelectorAll('a[href]')`만 순회해 root 노드 자신은 포함하지 않았기 때문이다.

## 수정

- Chrome, Firefox, Safari content script의 `processLinks`가 root가 `a[href]`이면 root 자체와 하위 링크를 모두 처리하도록 보정한다.
- HWP/HWPX/HML 모두에 공통으로 적용되며, 기존 정적 링크 처리와 중첩 컨테이너 처리에는 영향을 주지 않는다.

## 검증 결과

- Chrome production build를 통과했다.
- 실제 Chrome에 unpacked `rhwp-chrome/dist`를 로드해 정적 `.hml` 링크와 동적으로 추가한 단일 `.HML?download=1` 링크 모두 `data-rhwp-processed="true"`와 `rhwp로 열기` badge를 받는 것을 확인했다.
- trusted badge click이 extension viewer에 원본 URL을 전달하고, `samples/hml/formatting_table.hml`을 1쪽 canvas로 렌더링했다. 상태 바는 `formatting_table.hml — 1페이지`를 표시했다.
- `node --test` shared HML signature/URL resolver 및 Chrome/Firefox 확장 회귀 57개를 통과했다.
- Firefox production build와 Safari macOS `CODE_SIGNING_ALLOWED=NO` build를 통과했다. Safari의 CoreSimulator 버전 경고는 simulator 비활성화 경고이며 macOS app/extension build는 성공했다.
