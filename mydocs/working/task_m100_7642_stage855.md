# Issue #7642 단계 855: PDF 크기 추출값과 실제 장평 변환의 구분

## 독립 출력의 원시 연산

HWPML 3쪽의 `H2gtrE`는 `Tf=183`, CTM의 세로 계수 0.119869, `Tz=94.565216`이다. 실제 세로 글자 크기는 약 21.936027pt다. 추출 span의 21.337484pt는 가로 변환까지 포함한 기하평균 크기와 일치하며 세로 크기가 아니다. 원본 22pt·장평 95%를 세로도 약 2.5% 줄일 근거가 되지 않는다.

기존 #5821의 수용 원본 `samples/issue5821/condensed_ratio_title_box.hwpx`와 커밋된 독립 Print `pdf/issue5821/condensed_ratio_title_box-hwpx-2020.pdf`도 확인했다. 원시 `Tf=208`, CTM 세로 계수 0.119869, `Tz=90.206184`다. 실제 세로 크기는 약 24.932752pt로 원본 25pt에 대응한다. 추출 크기 약 23.686882pt는 변환 기하평균이다. 기존 검사 설명의 세로 √장평 축소 주장은 이 둘을 혼동했다.

[MuPDF 공식 geometry 구현](https://raw.githubusercontent.com/ArtifexSoftware/mupdf/master/source/fitz/geometry.c)의 matrix expansion도 행렬식 절댓값의 제곱근이다. 직접 읽은 PDF 연산과 이 계산값, 추출값을 구분했다. 진단 JSON은 ignored output 단계 854에 보존한다.

## 공통 구현 변경

`renderer/mod.rs::condensed_ratio_draw_params`는 원본 font_size를 유지하고 장평을 가로 축에 적용한다. SVG·Canvas·Native의 공통 그리기 입력이 이를 소비하며 advance와 char_positions의 장평 폭 계산은 유지한다. 문서 ID나 관측 px에 대한 보정·예외를 추가하지 않는다. 글자 세로를 임의로 줄여 기존 baseline이나 셀 높이의 차이를 숨기지 않는다.

HWPML 본문 Regular/Bold의 확인한 한글 13개는 PDF subset과 설치된 TTF의 좌표·contour·flag·advance가 같았다. 확인한 제목의 차·례는 HYgtrE와 윤곽이 달라 별도로 조사한다. 본문 미달 전체를 해결 불가능한 글꼴 차이로 분류하지 않는다. 단계 852에 비교값을 보존한다.

## 회귀와 재검증

기존 #5821 sqrt 크기 문자열 검사는 아직 바꾸지 않는다. 원본 전체 Native/fresh WASM을 Print와 대조하고 90% 이상·확대 판독을 확인한 뒤 독립 크기·장평 관계에 맞게 변경해야 한다. 이 변경은 전체 영향 문서와 현재 검증 corpus를 다시 확인한다. 높은 평균이나 기존 통과를 새 코드 증거로 재사용하지 않는다.

단계 850은 ade234c83의 Native 빌드 뒤 새 IR 수집기의 잘못된 타입 사용으로 integration 컴파일이 실패했다. drawing 문단은 `text_box.paragraphs`를 사용하고 Footnote·Endnote는 별도 타입으로 순회하도록 수정했다. fresh WASM은 해당 실패로 시작되지 않았다. 실패한 회차를 테스트·시각 통과로 기록하지 않는다. 수정 후보에서 실제 등록 suite의 그룹 검사 4건과 HWPML·이미지 채우기·#5821 선택 쪽을 함께 실행한다.
