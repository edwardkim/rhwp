# Issue #7642: 저장 쪽 경계와 재조판 누적 좌표의 분리

## 관측과 독립 근거

- 현재 code source `1b047be0e8b6ac09d976e466b7d18e151ded2a4b`, 기준 upstream `2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`.
- sample16 HWPX의 독립 한컴 2024 Print 18쪽에 대한 Native 일치율이 이전 source의 98.98914%에서 67.02444%로 하락했다. 17쪽의 가시 본문 위치는 동일하지만 빈 문단 391이 다음 쪽으로 넘어가 제목과 후속 표·그림을 약 25px 밀었다.
- `stage1300/1303`의 실제 문서 속성에서 문단 391의 현재 줄 vpos는 74008 HU, 보존된 원본 쪽 좌표는 69480 HU다. 원본의 줄 상자와 앞 문단은 17쪽에 들어간다. 빈 줄도 같은 쪽에 실제 13.3px 상자로 배치되던 이전 render tree와 독립 Print의 뒤 제목 위치를 함께 대조했다.
- `RHWP_FLOW_BREAK_DEBUG` 실행은 `typeset/section/heading.rs:108`의 제목 고립 방지 휴리스틱이 쪽을 전환했음을 확인했다. 원본 저장 쪽 경계라는 주장에 재조판 누적 vpos를 사용한 것이 원인이다. 빈 문단을 숨기거나 점유 높이를 0으로 만들지 않는다.

## 생산·소비와 보정

`Paragraph::source_line_seg_vertical_pos`의 원본 쪽 좌표 보존 → 제목/후속 블록 휴리스틱의 현재 문단 끝·쪽 시작 좌표 판정 → `advance_column_or_new_page` → 실제 페이지와 뒤 본문 배치 경로를 보정한다. 두 좌표 모두 유효한 같은 원본 스냅샷을 소비한다. 스냅샷과 현재 줄 수가 다르거나 내용/셀 배치가 dirty인 경우 그 스냅샷으로 제목 경계를 추측하지 않고 통상 흐름 fit에 맡긴다. 원본 스냅샷이 없고 유효한 저장 줄이면 기존 좌표 계약을 유지한다.

## 검증 계획

현재 source의 17·18쪽 직접 대조, 전쪽 Native/fresh WASM 64쪽 TSV, 다른 페이지의 내용·소유·쪽수 보존, 기존 제목 고립 대조군을 확인한다. 양쪽 전쪽 90%와 확대 판독 뒤 새 이름의 소유 관계 회귀를 추가한다. 완료 페이지의 좌표 검사는 변경된 지침에 따라 양쪽 점수 최솟값 100% → 99%대 → 98%대의 우선순위와 독립 ±2px 근거를 확인한다.

기존 검사 기대값은 아직 변경하지 않았다. 현재 source의 새 통과 증거와 full regression/lint/PR/CI/merge/옵션 2 후속 처리는 미완료다.
