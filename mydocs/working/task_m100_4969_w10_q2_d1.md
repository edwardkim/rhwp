# Task M100 #4969 W10-Q2-D1 — composition owner handoff

## 판정

Q2-D1은 **qualified**다. W9 kerning과 Q2-B shaping context를 동일한 exact-font registry
snapshot에서 만들고, Q2-C의 `DormantQualified` 결과만 `ComposedParagraph`가 internal `Arc`로
보존한다. 기존 `compose_paragraph()`·`compose_section()`은 sidecar가 `None`인 호환 경로로
유지되며 layout·paint 제품 소비자는 아직 0이다.

기계 판독 결과는
[`w10_q2_d1_composition_handoff.json`](../tech/investigations/issue-4969/w10_q2_d1_composition_handoff.json)이다.

## owner와 파생-state 순서

- `LayoutEngine::exact_font_measurement_context_snapshots()`는 registry를 한 번 clone한 뒤 그 한
  generation에서 `KerningMeasurementContext`와 `HorizontalShapingContext`를 함께 만든다.
- `ResolvedStyleSet`은 두 context의 transaction-shared `Arc`를 함께 소유한다. 한쪽만 없거나 registry
  generation이 다르면 composition handoff는 실행되지 않는다.
- `DocumentCore`의 전체 파생-state 순서를 `style resolve → exact source rebuild → paired context snapshot →
  style-aware composition → pagination`으로 고정했다. section·paragraph 증분 재구성도 같은 opt-in
  entrypoint를 사용한다.
- qualified Q2-C outcome의 `Arc`를 clone하지 않고 그대로 `ComposedParagraph`로 옮긴다. 따라서 final-line
  target measurement도 Q2-C가 만든 동일 `Arc`다.

## 호환·fail-closed 경계

- 기존 `compose_paragraph()` 호출 수는 기준 commit과 현재가 모두 155건이며 기존 callsite 교체는 0건이다.
- opt-in entrypoint는 먼저 legacy composition을 완성하고 internal sidecar만 추가한다. lines, run, line height,
  boundary, numbering, control 정보는 다시 쓰지 않는다.
- context 없음, 서로 다른 registry generation, text 상한 초과, scalar/range 불일치, 유효하지 않은 line width,
  Q2-C rollback/not-target은 모두 sidecar `None`으로 끝난다.
- 일반 문단은 최대 4,097 scalar만 읽는 무할당 candidate gate에서 종료한다. 옛한글 후보가 아니면 style
  projection·kerning paragraph measurement·shaping transaction을 만들지 않는다.
- 모델 텍스트와 composed run 텍스트가 다르거나, bidi/RTL, 자간, condense, tab, control, CharOverlap 등이
  있으면 Q2-C의 기존 feature detection이 거부한다.

## 출력·성능 경계

- `ComposedParagraph.horizontal_shaping`을 읽는 제품 callsite는 0이며 쓰기 callsite만 1개다.
- page sidecar attach, glyph-run lowering, layout position 교체, paint 소비는 D2 이후 절편의 일이다.
- public render-tree/layer-tree/JSON schema 변화는 0이고, 전체 기존 library test가 출력·조판 회귀 없이
  통과했다.
- exact source가 없는 문서는 두 context가 모두 `None`이므로 기존 fast path를 유지한다. exact source가
  있는 일반 문서의 추가 비용은 composition당 bounded candidate scan뿐이다.
