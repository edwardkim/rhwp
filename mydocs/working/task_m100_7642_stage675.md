# Issue #7642 단계 675: 문단 첫 저장 경계와 뒤 줄의 페이지 되감김 분리

- #1880 원본의 6쪽은 Native 18.81919%다. 한컴 Print와의 첫 baseline 차이는 원본 paraPr 2의 선행 간격 1000 HWPUNIT에 대응한다. 원본 문단 51은 첫 줄 68820, 다음 줄 3340/5680으로 저장 페이지를 걸친다.
- stage674의 기존 source73 실행 추적에서 이 문단은 전체 fitted 경로가 아니라 split 경로를 거쳤고, 다음 문단 52의 흐름 커서는 106.9였다. fit은 앞 간격을 포함한 반면 paint의 첫 문단 원점은 113.4로 그 간격을 보존하지 않았다.
- `place_split_paragraph`는 첫 줄 조각에서 `record_stored_column_top_spacing`을 호출한다. 실제 새 단·쪽의 첫 항목인지, current/start height가 원점인지, 편집/미주가 아닌지, 저장 줄 수가 같은지 먼저 확인한다.
- 기존 공통 resolver는 현재 문단의 모든 저장 줄이 단조 증가해야 첫 경계를 인정했다. 다음 줄에 물리 페이지 되감김이 있으면 앞 간격을 증언하는 첫 경계까지 무효가 됐다. 첫 줄의 간격 판정에 뒤 줄 전체의 단조성을 요구하지 않도록 분리했다.
- 현재 문단의 실제 저장·양수 높이·비음수 위치/간격·dirty/synthetic/개체 검사는 유지한다. 첫 위치가 선언 선행 간격을 닫거나, 이전 문단의 정상 저장 끝과 현재 문단 첫 위치가 앞뒤 선언 간격을 정확히 닫아야 한다. 이전 문단의 사다리 단조성도 유지한다.
- resolver가 만든 같은 `StoredColumnTopSpacing`은 typeset의 page/source origin에 기록되고 layout의 page base 및 PartialParagraph 앞 간격 override로 소비된다. 별도 측정값이나 임의 y 이동을 추가하지 않는다.
- 새 renderer helper는 별도 작은 파일에 두고 기존 public frame type은 re-export해 API를 유지했다. 기존 실패 검사의 기대값은 바꾸지 않았다. 수정 후 Native/fresh WASM·반례·확대 판독·전체 회귀는 아직 미검증이다.
- 실행 전 대기 중이던 stage673을 `superseded_before_execution`으로 기록하고 화살표·간격 보정을 한 검증 source로 묶는다. 실제 실행 중인 source1840 전체 nextest는 계속 유지한다.
