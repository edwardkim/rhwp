## 검증 상태

### 분리 후보의 의존성 점검

첫 전체 검증은 테스트 실행 전에 OLE 호출부의 미완료 API 참조로 컴파일에 실패했습니다.
제외한 OLE 모듈과 같은 기존 API를 호출하도록 해당 호출부도 되돌렸습니다.
다른 도형·캡션·좌표 보정은 유지하고 실제 테스트 실패로 집계하지 않습니다.


### Studio 기존 계약 검사

Studio 전체 단위 검사는 1827개 중 1824 PASS, 1 FAIL, 2 SKIP입니다.
실패는 새 글꼴 환경 setter가 mutation 분류 원장에 빠진 기존 드리프트 검사입니다.
`DocumentCore::set_font_environment`는 문서 글꼴·저장 줄·IR·편집 히스토리를 변경하지 않고
렌더 환경과 파생 상태를 갱신하므로 `EXCLUDED_NON_DOCUMENT`에 근거를 적어 분류했습니다.
기존 검사나 기대값은 완화하지 않고 재실행합니다.


### 분리 범위의 검사·주석 정합

제외한 양자 문서 EMF 확장의 레코드 이름 두 개가 golden 검사 분류에 남아 컴파일을 막았습니다.
해당 검사 파일도 기존 EMF 타입과 같은 분류로 복원했습니다. 기존 golden·fixture 바이트는 바꾸지 않았습니다.
후보에 새로 추가된 영문 설명 주석 일곱 줄을 한국어로 고쳤습니다.
두 번의 준비 단계 컴파일 실패는 실제 회귀 실패나 통과로 집계하지 않습니다.
Studio 빌드는 아직 fresh WASM의 타입 파일이 없어 실패했으므로 fresh 생성 후 다시 검증합니다.


### 시각 수용과 회귀 실행 환경의 일치

사업신청서 2쪽의 기존 관계 검사에 필요한 참조 글꼴 JSON도 포함합니다.
이 문서는 이전 단계에서 전쪽 Native/fresh 90% 이상을 확보한 완료 대조군이므로 최종 전쪽 대상에도 추가했습니다.
개인정보 관계 검사는 전쪽 시각 수용한 선언 환경 JSON을 실제 적용하도록 맞췄습니다.
90% 미달이 남은 기본 환경 corpus 제외는 유지하며, 다른 환경의 통과로 대신하지 않습니다.
검증하지 않은 본문 파생 HWPX 복사본은 제출 후보의 새 sample로 넣지 않습니다.
원래 브랜치와 원본 HWP·자료는 그대로 보존했습니다.

## 보정 348 사전 분석: WMF 패턴 정의와 보이는 paint의 역할

기존 WMF 세 함수의 실패는 합성 `PATINVERT → DPa → PATINVERT` 변환 SVG에
`rop_pat` 문자열이 있다는 assertion입니다. 실제 출력은 그 패턴을 `<defs>` 안의
휘도 mask로 사용하고, 보이는 원래 브러시색 도형이 그 mask를 참조합니다.
패턴 정의의 존재는 흑백 패턴이 직접 칠됐다는 뜻이 아닙니다. 현재 실패는
SVG 리소스 역할을 문자열 부재로 대신한 검사 가정입니다.

독립 근거는 [Microsoft MS-WMF TernaryRasterOperation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wmf/1605dd68-a635-4639-ab81-99ff3e3fc5a3)의
PATINVERT(XOR)와 DPa(AND)입니다. `(D XOR G) AND M XOR G`는 검정 mask에서 G,
흰 mask에서 D를 보존합니다. SVG에서는 흑백 패턴을 RGB 반전한 휘도 mask로
브러시색 paint를 선택하며, 패턴이 독립 paint로 나오면 잘못입니다.

이 변경은 해당 합성 레코드의 SVG XML 자원/연산 계약을 교정합니다. 생산 WMF
변환·그림 픽셀·HWP 입력·문서 위치·기존 실제 curve fixture 검사는 그대로이며,
월간 수출입 문서 전체의 피델리티가 승인됐다고 주장하지 않습니다. 실물 문서
위치 핀을 바꾸는 것이 아니라 패턴이 mask에만 속하고 실제 paint가 그 mask를
한 번 참조하는 관계를 검사합니다. 전체 HWP의 시각 수용은 별도 기존 보류와
구분하며, 이 합성 XML 계약은 HWP/PDF 배치 게이트 비해당입니다.
