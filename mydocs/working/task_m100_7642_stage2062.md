# #7642 축소 재검증의 미달과 문단 기준 그림 원점 보정

## 실제 재검증

`a6a095c25f3298463fa4680008eb3a4f7343cc2c`의 Native 빌드와 기존 마스크 회귀
2건은 exit 0이다. Native 빌드는 약 5분 18초 걸렸다. fresh WASM은 stage2055에서
별도로 빌드 중이다. 이전 `d6406d3541` WASM 결과를 새 코드의 결과로 쓰지 않는다.

10월 원본 HWP 전쪽은 여전히 미달이다. 1쪽은 88.52370% → 90.69311%,
6쪽은 88.11096% → 89.06661%, 8쪽은 91.77203% → 89.97725%다.
HWPX 전쪽도 Native 최저 89.08171%다. 수치 상승과 미달·하락을 모두 보존한다.
11월 두 원본의 새 Native 최저는 각각 96.29390%다. 새 WASM 전쪽 결과는 아직 없다.
새 source의 검증이 끝나기 전 PR을 생성하지 않는다.

stage2058의 6·8쪽 review와 standalone overlay를 직접 열어 함께 제시했다.
6쪽은 그림 음영의 내용 마스크 차이, 8쪽은 그림의 실제 세로 위치 차이를 확인했다.
사진 축소의 개선을 전체 시각 완료로 판정하지 않는다.

## 8쪽의 실제 호출 경로

원본 HWP의 pi384/ci1은 Para 기준 Square 그림이다. 그림 속성의 세로 offset은 0,
brightness/contrast/effect는 모두 0이다. 저장 첫 줄의 vertical_pos는 4236HU,
다음 소유 줄은 10629HU다. 독립 Print PDF의 그림 상단은 174.16898pt,
96DPI에서 약 232.225px다. 이 좌표는 조사 근거이며 새 px 회귀 핀이 아니다.

현재 Native의 텍스트 첫 줄은 147.2px지만 그림은 373.7px다.
기존 진단 플래그로 실행한 stage2060은 다음을 기록했다.

```text
[5715] pi=384 ci=1 base=288.5 from_map=true y_off=288.5
PICTURE_ANCHOR_SAVED ci=1 anchor=85.2400
```

공통 delta가 틀린 것이 아니라 그 뒤 실제 배치에서 덮어쓴 기준점이 문제다.
`typeset/state/transition.rs`의 frame은 문단 top을 받아 `picture_exclusion`에서
같은 `stored_picture_anchor_delta`를 사용한다. `layout/shape_item.inc.rs`는 선행
TAC Table/Shape만 있으면 현재 floating 그림의 호출 시점 흐름 끝으로 para_start_y를
갱신했다. 이 값에 올바른 delta를 더하면 373.7px가 된다.

현재 개체도 TAC일 때만 기존 TAC 줄 진행을 사용하도록 조건을 고쳤다.
떠 있는 후속 그림·도형은 문단 원점을 유지한다. 뒤에 수용한 저장 placement를
우선하는 분기는 유지했으며, 그 뒤 layout_body_picture가 원본 offset을 한 번 적용한다.
문서명·쪽·좌표 보정이나 clamp를 추가하지 않았다.

이 변경은 아직 컴파일·시각 재출력 전이다. 원본 전쪽의 양쪽 90%와 확대 판독,
선행 inline box 뒤 floating 그림, 다른 줄 TAC와 수용 frame,
편집 재조판 반례를 확인한 뒤 관계 회귀를 새 이름으로 추가한다.
기존 golden·기대값·허용치를 이번 단계에서 바꾸지 않았다.

## 6쪽의 구분된 진단

원본 PNG는 1201×657이며 넓은 면의 RGB가 232다. 독립 PDF의 같은 크기 자원을
MuPDF로 디코드해도 넓은 면은 232지만, canonical pdftoppm PNG에서는 주로 231이다.
현재 Native는 주로 232를 유지한다. raw 내용 마스크의 경계가 이 사이에 있어 영향을 준다.
사진을 임의로 어둡게 만들거나 마스크 임계값을 바꾸지 않는다. 동일 PDF를 다른 renderer로
읽는 stage2061은 원인 분리용이며 canonical 기준과 gate를 변경하지 않는다.
단순 폰트 예외로 처리하지 않는다.
