# #7642 다줄 수식 기준선과 행렬의 선두 PILE 구문

Issue: #7642

## 독립 대조와 원인

수식 원본 카탈로그는 계속 미달 상태로 보존한다. 원본 259개 EQEDIT의 바이트를 유지한 가족별 9개 진단 입력을 한컴 2024 MCP의 `target=pdf`, Print method 0으로 출력했다. `ace031f953` Native/fresh WASM에서 PMATRIX 8쪽과 EQALIGN 4쪽이 여전히 90% 미만이었다. 다른 7개 가족의 페이지 점수가 높아도 원본 혼합 카탈로그의 통과로 보고하지 않는다.

EQALIGN 10개 분수의 원본 저장 LineSeg는 높이 35850HU와 첫 기준선 2277HU를 갖는다. 실제 공유 layout도 높이 478px, 기준선 30.36px다. 그러나 EQEDIT의 정수 기준선 7%로 다시 만든 2509HU는 33.45333px여서 paint 루트에 3.09333px를 더한다. 6개 분수에서도 11% 반올림으로 1.09333px가 추가된다. 독립 Print의 분수선과 Native raster의 원점 차이를 직접 확인했다. 줄 간 피치는 거의 같으며, 긴 수식을 문서별 좌표로 당기는 처리는 하지 않는다.

PMATRIX의 `PILE{a # b}` 선두 구문은 Print에서 a·b만 행렬 본문으로 표시된다. 원본 속성과 한 식의 호스트를 유지하면서 스크립트만 바꾼 진단 17개를 추가 Print했다. MATRIX·PMATRIX·BMATRIX·DMATRIX, PILE·LPILE·RPILE 모두 같은 선두 구문을 소비했다. 반면 `{PILE{...}}` 포장, 두 번째 칸, `a+PILE{...}`, 선두 EQALIGN·CASES는 나머지 칸을 표시한다. 행렬 밖 `+ z`도 남는다. 이 차이는 출력에서 특정 문자를 숨길 이유가 아니라 파서의 본문 소유 범위를 고칠 근거다. 진단 파일은 원본과 별도이며, 첫 문단의 저장 쪽 나눔 때문에 생긴 앞 빈 쪽도 페이지 수에서 제외하지 않는다.

## 공통 규칙과 소비 경로

1. 기존 비보호·HYhwpEQ·글자 단위 정규화 경로에서, 전체 root가 독립 정렬 묶음이고 실제 구성 높이가 저장 높이와 HWPUNIT로 일치하면 첫 행의 정확한 구성 기준선을 발행한다. 폭·높이·줄 간격은 유지한다. 다른 높이의 예약 프레임, 보호 크기, 다른 글꼴, 실제 부모 수식 안의 EQALIGN에는 이 소유를 적용하지 않는다. `flow_metrics_hwp → composer의 줄 높이/기준선 → inline_baseline_px → layout_for_paint → SVG/Canvas/Native`가 같은 값을 소비한다. paint에 별도 문서 좌표 보정을 더하지 않는다.
2. 문서 전용 파서의 행렬 몸체가 바로 PILE 계열 명령으로 시작하면 그 PILE 하나가 본문을 소유한다. 바깥 행렬 닫힘까지 나머지 토큰을 소비하고, 그 뒤의 바깥 항은 보존한다. PILE의 정렬과 행을 AST에 유지한다. 괄호 포장·선행 항·다른 칸의 일반 파싱 및 공개 LaTeX 호환 경로는 유지한다. `dispatch → parse_matrix → parse_pile → Matrix/Pile AST → 같은 측정·paint layout` 경로를 사용한다.

## 현재 검증 상태

구현 후 검증 전이다. 기존 golden이나 허용치를 갱신하지 않았다. 선두 PILE의 비어 있는 본문 등 추가 적용 경계, 원본 혼합 카탈로그·가족별 전체 페이지·실물 수식 대조군을 새 Native/fresh WASM으로 확인한다. 의도한 원인의 수정 전 FAIL/수정 후 PASS를 확인하고 전쪽 90%·확대 판독을 충족한 뒤 정식 회귀를 새 이름으로 추가한다.

이전 커밋 `69ecddfe22`의 병합 셀 보정은 같은 focused 138/138 통과, Native 13/13쪽 90% 이상이며 영향 4쪽 raw가 99.41528%에서 99.89262%로 개선됐다. 그 source는 별도 고정 worktree에서 fresh WASM 검증 중이다. 이 결과를 이번 수식 수정의 통과로 사용하지 않는다.
