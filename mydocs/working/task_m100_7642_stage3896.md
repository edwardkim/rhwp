## 점수 통과 후 발견한 실제 차이

마지막 본문 `2 - 48`의 실제 잉크는 Native에서 y=925..935, 원본 Print에서
917..926이다(96dpi 진단 관측). 서명과 빈 문단을 지날수록 차이가 누적된다.
이 좌표를 보정 상수나 테스트 기대값으로 쓰지 않는다.

원본의 고정 줄간격 문단 4~7은 ParaShape에서 1200 HWPUNIT를 선언한다.
현재 파서는 각 줄에 `line_height=1200`, `text_height=1000`, `line_spacing=200`을
만든다. 구역 커서는 `line_height + line_spacing`으로 전진하므로 실제 누적은
1400이며, 이미 포함한 여유 200을 다시 더한다.

## 독립 한컴 저장본으로 확인

원본 HWP3의 Print PDF를 기준으로 유지하면서 같은 원본을 한컴 2020에서 HWP로
저장한 진단본의 줄 속성을 읽었다. MCP job `8a10c93a-25d5-43e7-bd1f-dfe5039e07f1`,
engine 2020, 실제 한컴 `11.0.0.9136`, target hwp다. 저장본 SHA-256은
`52b1a303a50035f2802dea933f18cb405bd610d4e309069ce07ff99b80c3ffdc`다.
이 저장본은 원본의 Print 기준을 대체하지 않는다.

한컴 저장본의 같은 다섯 줄은 `line_height=1000`, `text_height=1000`,
`line_spacing=200`이며 고정 전진은 1200이다. 문단 4의 첫 vpos 51288은 같고,
다음 줄은 52488이며 문단 5/6/7은 54188/55388/56588이다. 현재 원본 파싱의
52688, 54588/55988/57388과 달라, 중복 누적의 생산 위치를 독립적으로 확인했다.
Print의 본문 줄 기준선 차이도 1200 HWPUNIT의 물리 간격과 대응한다.

`stage3894-issue1950-tail-spacing/fixed-line-contract-before`는 고정 문단의
`line_height + line_spacing == ParaShape의 고정 간격` 계약을 검사한다.
동일 원본·현재 소스에서 **다섯 줄 모두 불일치, 의도한 exit 3**을 확인했다.
빌드·환경 오류를 FAIL 증거로 세지 않았다. 같은 진단 코드를 수정 후 다시 실행한다.

## 공통 규칙과 수정 범위

HWP3의 고정 전진은 글자 점유 높이와 그 뒤 여유로 한 번만 분해한다.
`line_height = text_height`, `line_spacing = fixed - text_height`를 공통 helper로
계산해 기본 fallback과 저장 줄의 두 생산 경로가 소비하게 한다. 부호 있는 간격은
보존하며 문서명·쪽수·특정 좌표를 조건으로 두지 않는다. 일반 percent 계산과
HWP5/HWPX의 실제 저장 줄은 바꾸지 않는다.

생산 경로는 `hwp3::paragraph::fixed_line_metrics` → fallback 및 LineInfo 변환 →
구역 vpos 누적이다. 소비는 composer의 저장 줄·height cursor의 전진·실제 layout의
저장 원점이며, 최종 paint 좌표를 clamp하거나 빈 문단을 숨겨 차이를 없애지 않는다.
원래 TAC 표의 별도 호스트 줄 여유 분기는 유지한다.

수정 후 원본의 Native/fresh WASM 전쪽 TSV·Print 직접 판독과 고정/퍼센트·공백 줄·
인라인 개체 대조군을 확인한다. 전쪽 하한과 판독을 충족한 뒤 정식 관계 회귀를 추가한다.
관련 전체 범위와 나머지 실패·lint·브라우저·리베이스 기능 보존 검증까지 끝내기 전에는
PR을 제출하지 않는다.
