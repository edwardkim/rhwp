# 이슈 #7642 — 부정 기호 장식의 공통 배치와 그리기

## 근거와 원인

생산 소스 `f316ad1e6`의 20쪽은 97.09636%지만 확대에서 `a not= 0`의 빗금이
위쪽 가로선으로 표시된다. 원본 한컴 2024 Print는 등호와 빗금을 같은 원점에
겹쳐 그린다. AST의 `StrikeThrough` 해석은 유지하고 표시와 줄 측정의 잘못된
위쪽 장식 가정을 제거한다. 소스의 대상은 원본 본문 404의 미주 문단 22이다.

4개 크기(600·900·1200·1800 HWPUNIT)의 부정 등호·부등호와 정상 대조를 수동
HWPX로 만들고 한컴 2024에서 HWP로 재저장한 뒤 Print 출력했다. 저장 줄·수식
크기·기준선을 비워 한컴이 재생성했으며 출력의 glyph·원점을 읽는다. 첫 진단의
`not {xy}`는 한컴에서 괄호를 부정하는 것으로 해석되어 같은 계약의 대조가 아니므로
정상 `<`로 바꾼 v2를 사용한다. 첫 입력과 결과는 실패 가정의 기록으로 보존한다.

v2 Print의 content stream은 본체와 빗금의 `Tf`가 같고 빗금에만 `Tz` 장평을
적용한다. text trace의 `size`는 이 변환을 포함하므로 실제 글자 크기로 해석하면
안 된다. 첫 양축 확대 후보는 이 근거와 달라 빌드를 중단하고 폐기했다. 세로
크기를 보존하는 장평 후보를 빌드·검증한다. 4개 크기의 실제 장평은 등호
152·147.368423·150·158.666656%, 부등호 211.999985·197.368423·210·200%다.
현재 공통 선분의 150/200%는 초기 표시 후보이며 독립 출력과의 정밀 일치로
판정한 값이 아니다. 확대 비교에서 남는 차이를 확인해 보정한다.

첫 Native 후보는 진단 전쪽 95.65→96.79711%, 원본 20쪽 97.09636→97.10355%다.
확대에서 18pt 부정 부등호는 앞뒤 간격이 달라 완료가 아니다. 원점 차이를
대조하면 부등호는 UPM 1024의 864 전진폭을 HWPUNIT 격자로 게시하고, 정상
연산자 앞뒤는 0.21em, 명시적 Thin은 BaseUnit/8을 사용한다. 6·9·12·18pt의
정상 `<`와 `not<`/`not>` 원점이 같은 규칙을 따른다. 기존 경로는 NOT 내부에서
대체 표시 글꼴의 전진폭에 0.3em 여백까지 더해 다음 피연산자를 밀었다.
`source_font_symbol::operator_metrics`에 `<`/`>`의 수학 전진폭을 연결해 보정한다.
이 변경은 정상 부등호에도 적용하므로 정상 대조를 함께 재검증한다.

정상 대조의 `neq`는 `not=`와 별개의 Unicode `≠`다. Print subset과 설치 face는
UPM 1024·전진폭 1024·잉크 bbox `(180,14,841,582)`가 같다. 대체 표시 글꼴의
긴 빗금을 그대로 쓰면 18pt 대조의 모양·간격이 다르다. 전진폭과 관계 기호
여백을 원 face의 계약으로 연결하고, 두 가로획·빗금의 수학 선분을 공통
`FontGlyph` 결과에 전달한다. 사설 글꼴의 윤곽·바이트를 추가하지 않는다.
이 표시도 초기 후보이며 새 Native/fresh WASM에서 별도로 판독한다.

두 번째 Native 후보는 전쪽 99.83337%, 20개 수식 영역의 최저 97.44898%다.
그림에서 부정 빗금의 획이 독립 Print보다 얇은 차이가 남았다. Tz는 끝점뿐
아니라 획도 가로로 늘리므로, 변환 전 선분 길이·변환 후 길이·행렬식으로
수직 두께를 함께 변환한다. 원 face의 빗금 수직 획은 약 0.044em이다.
장평 1.5·2에서 측정한 수직 두께는 0.06158·0.07621em이다. 이 값은 설치
글꼴의 수치 메트릭이며 사설 윤곽·바이트를 코드에 포함하지 않는다.

## 구현과 소비 경로

- 빗금은 위쪽 악센트가 아니라 본체 위의 표시다. `layout_decoration`에서 본체의
  논리 높이·기준선·원점을 보존한다. 유효한 저장 프레임은 재정의하지 않는다.
- 공통 빗금 기하를 수식 모듈에서 생산하고 SVG·Canvas·Skia가 같은 시작·끝·두께를
  소비한다. 대상 기호의 표시와 부정 표시를 모두 남기며 clipping·clamp로 숨기지 않는다.
- 기호의 형태에 맞는 글자 크기 비율을 사용하고 문서 ID·문항 번호·고정 px 좌표로
  분기하지 않는다. 논리 상자와 glyph의 실제 잉크를 구분하고 저장 프레임의 기준선
  선택 이후 최종 paint 원점까지 확인한다. 부정이 없는 장식·기호는 정상 대조다.
- 경로는 AST 장식 → 논리 상자 → `flow_metrics_hwp`/`inline_baseline_px` →
  `layout_for_paint`의 최종 원점 → 각 backend의 빗금이다. 원본의 선언 프레임과
  한컴의 실제 표시를 서로 다른 증거로 기록한다.

## 검증과 판정

고정 target에서 Native 빌드·Clippy·fmt를 순차 확인한다. v2 저장본·동일 Print와
원본 19·20쪽의 Native/fresh WASM을 새 코드로 대조하고 같은 영역을 확대한다.
일치율·기호·기준선·앞뒤 간격을 각각 판독한다. 변경 전 frozen source의 결과는
변경 전 증거로만 유지한다. 다른 크기·부등호·정상 기호의 미검증·차이를 숨기지 않는다.

검증 범위의 90% 이상과 확대 판독을 충족하기 전에는 새 fixture/회귀를 추가하거나
기대값·baseline을 바꾸지 않는다. 기존 실패는 현재 브랜치에서 원본을 보정하고
소유·순서·포함·겹침 관계로 필요한 검사를 변경한다. 로그·TSV·JSON·nextrun은
ignored output에만 기록한다. 원본·한컴 저장본·Print 및 대표 PNG는 증적으로 보존한다.

검토용 crop이며 고정 px 회귀 기대값이나 전쪽 TSV의 대체물이 아니다.
동일 영역의 변경 전·후·Print 확대 PNG를 직접 열어 빗금, 부등호 앞뒤
간격과 `neq` 모양을 확인했다. 이전의 가로선·피연산자 밀림과 과도하게 긴
`neq` 빗금은 보정됐다. 공개 표시 글리프와 원 face의 세부 획 차이는 남는다.
자동 실루엣 일치율 100%인 영역도 정확한 glyph 복제나 최종 승인으로 해석하지 않는다.

증적은 ignored `output/pr-review/issue7642/failed-inputs-20261008/stage15-current-validation/`
아래 `negation-stroke-native-review/`, `negation-equation-final-detail-metrics.json`,
`negation-equation-final-selected-detail-review.png`에 있다. 입력·Print의 저장/인쇄
job과 해시는 `negation-contract-mcp-save-v2.json`·`negation-contract-mcp-print-v2.json`에
있으며 한컴 2024 `13.0.0.3901`, Print method 0,

**fresh WASM 및 최신 소스의 영향 문서 전쪽 검증은 아직 미검증이다.**
이 단계에서 회귀 테스트·fixture·baseline은 변경하지 않았다. 전체 52개 입력,
기존 110개 실패와 #1139 파일의 관계형 전환도 완료가 아니다. 코드 보정을
일반 커밋으로 고정한 뒤 같은 소스로 fresh WASM과 전쪽 검증을 계속한다.
