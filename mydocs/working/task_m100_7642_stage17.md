# 이슈 #7642 — 아래첨자와 CASES의 논리 기준선

이전 단계: [CASES 칸 맞춤](task_m100_7642_stage16.md), source `1a3163763`.

## 원인과 독립 기대값

아래첨자의 상단을 본체 기준선의 일정 비율로 이동하는 기존 경로는 자식 글자의 기준선을
소비하지 않아, 11pt에서 본체·아래첨자 기준선 차이가 0.064em이다. 한컴 Print와 확대
판독에서 차이가 보인다. 본체와 자식의 논리 글줄 프레임·하단 점유를 사용해 해결한다.

- 15개 글자 크기에서 서로 다른 본체/첨자 `a_{n}` / `x_{m}`을 한컴으로 재생성했다.
  정상화 HWP job `57289556-fcb9-4edd-96df-f60e9d26ac53`, Print job
  `79d22649-066f-445a-a57b-30650faf5409`, 한컴 11.0.0.9136이다.
  두 식의 같은 크기 논리 높이와 기준선이 일치한다. 11pt는 1350 HWPUNIT /71%,
  22pt는 2626 HWPUNIT /71%다. 원점 실측은 보조 관측이며 고정 좌표로 구현하지 않는다.
- CASES의 단순 행/분수 행 순서를 바꾼 11pt/22pt 진단은 정상화 HWP job
  `4106cda1-ec98-4165-80f3-6a2c1799d2e7`, Print job
  `2ad83043-0511-47f3-b7d1-60494077a8c1`이다. 수학 축은 묶음 전체의 가운데이며
  왼쪽 글자의 기준선은 일반 글줄에서 수학 축까지의 거리를 더해 결정한다.
  두 행 글자 기준선 평균을 왼쪽 식의 기준선으로 사용하는 기존 가정을 제거한다.
- 일반 글줄 프레임은 기존 독립 한컴 메트릭을 재사용한다. 새로 진단한 22pt 글자 프레임은
  한컴 정상화 job `ee04e67a-b8cb-4297-9f26-716027f9eb7e`에서 확인한다.

## 적용과 검증

독립적으로 확인한 글자 크기에서 일반 글줄 본체와 일반 글줄 첨자의 논리 프레임을 사용한다.
키 큰 분수·중첩 첨자·다줄 본체는 그 계약의 증거가 없어 같은 프레임으로 접지 않는다.
본체의 측정 기준선, 자식의 실제 paint 원점, CASES 행 점유와 전체 높이를 함께 확인한다.

원본 `exam_math_8.hwp`의 이전 83.49525%, 첫 칸 맞춤 보정 86.26875%와 같은 Print PDF를
대조한다. Native/fresh WASM 90% 이상 및 확대 판독 전에 테스트 기대값이나 baseline을
바꾸지 않는다. 정상 eq-002 HWP/HWPX·국어 1쪽 대조와 CASES 경계의 출력도 재확인한다.
이번 전체 회귀의 90개 실패는 사용자의 지시에 따라 모두 현재 브랜치에서 보정한다.
진단·TSV·로그·JSON·nextrun은 ignored output에 보존한다.

## 첫 보정의 fresh WASM 및 후속 구현

`1a3163763`의 fresh WASM 빌드는 exit0, 15분10초다. root `pkg/`와 Studio `public/`의
JS·WASM SHA-256이 각각 일치한다. 이 source의 math8 WASM은 86.26875%로 Native와
동일하며 미달 gate의 exit1이다. 브라우저 실제 검증·최종 시각 통과로 기록하지 않는다.

후속 구현은 일반 글줄의 독립 논리 프레임 깊이를 첨자 크기에 비례해 적용하고, 첨자 프레임의
남은 깊이를 기준선 하강 거리로 소비한다. 자식 상단은 본체·자식 기준선 차이에서 결정하고
동일한 논리 높이를 측정과 실제 배치에 전달한다. 지원 크기는 독립적으로 확인한 표의 범위다.
일반 글줄이 아닌 본체/첨자는 같은 계약으로 접지 않는다. CASES는 전체 높이의 가운데에
일반 글줄의 축 거리를 더해 기준선을 정한다. 행 순서에 따른 기준선 평균은 사용하지 않는다.
포맷 검사와 `git diff --check`는 exit0이며 후속 Native 빌드가 실행 중이다.

전수 Native의 별도 미달도 확인했다. `3-10월_교육_통합_2022.hwpx`의 9쪽83.31998%,
10쪽45.28294%이고 양쪽18쪽·누락0이다. 이 값은 CASES 보정 전 frozen source이며 10쪽
review를 사용자에게 직접 표시했다. 요청 전체와 회귀 실패의 보정 범위에 그대로 포함한다.

후속 Native 빌드는 7분46초, exit0이다. binary SHA-256
`ae8f41bd965385a28df2e06affa222c56648c6f27365921827f734c48278b811`로 고정했다.
이 source의 math8·eq002 HWP/HWPX·국어1p 재비교를 시작했으며 아직 점수/최종 판정은 없다.

## 후속 Native 결과

math8은 **89.16346%**로 다시 개선됐으나 아직 90% 미만이다. eq002 HWP/HWPX는
94.81146%, 국어1p는 98.89162%로 유지됐다. 최신 확대 이미지를 사용자에게 표시했다.
이 source의 fresh WASM은 아직 산출하지 않았고 검사/baseline은 변경하지 않았다.

추가 대조에서 본문 `(가)`의 괄호가 한컴 Print의 영문 슬롯 글꼴(T2)과 다르게 한글 HFT
반각 슬롯으로 측정되는 경로를 확인했다. CharShape11의 한글은 `신명 중명조`, 영문은
`한양신명조`이며 원본 언어별 face와 같은 Print를 대조한다. 이 가설은 후속 별도 단계에서
생산→측정→배치/paint 슬롯 선택과 정상 대조를 검증하며 특정 문서 좌표로 보정하지 않는다.
