## 실제 미달과 독립 근거

현재 Native 전쪽 최소는 HWP3 sample16 19쪽88.65879%, fresh release WASM은 같은 쪽88.98556%다. 두 backend 모두 나머지63쪽은90% 이상이다. HWP5·HWPX·math_no·report·tracked-visibility 대조군도 전쪽90% 이상이다. 전체 승인·새 실물 baseline 추가 조건은 아직 충족하지 않았다.

원본 문단402와404의 앞 문자열 ` ◦ `는 같은 글자모양6을 쓴다. 402의 양쪽 정렬 첫 줄은 Native 기호 x=120.511, 첫 본문 글자146.942이고 독립 Print는117.92,144.32다. 뒤 본문도 대체로 같은 방향으로 밀린다. 같은 문단의 마지막 줄과 단일 줄인404는 원점 차이가 약0.1px 이내다. 원본2020 Print와 한컴 재저장본2024 Print의 해당 원점이 같은 것도 대조했다.

자연 반각 공백은 글자 간격의 절반을 소비한다. 글자모양6의 앞 공백 자연 전진은 약7.97px이고 독립 Print의 실제 전진은600dpi 격자에서7.92px이다. 현재 Native는 약10.51px로 배분 여분이 더해진다. 이는 고정 원점을 빼서 맞출 사유가 아니라, 자연 폭·배분 대상·문자 소유를 구별할 근거다. ignored 단계1080~1082에 글자별 원점과 원본 line info를 보존했다. raw space_correction52의 단위를 추측해 보정하지 않는다.

## 수정 전 최소 계약 실행

ignored 후보 `justified_line_space_ownership_contract.rs`는 같은 합성 원본의 Left와 Justify를 공개 HWPX 파싱·조판·text-layout으로 비교한다. 0/1/3개의 앞 공백, 색상 경계로 앞 공백 런을 분리한 경우, 10/20pt를 구성한다. 원본 내용·순서·수량을 모든 쪽에서 대조하고, 배분되는 내부 공백과 앞 공백 자연 전진을 구별한다. 실물 페이지의 절대 좌표를 고정하지 않는다. 정식 source PR 추가는 실물 미달 보정 뒤 판정한다.

초기 import 오류와 line_spacing 미설정으로 줄들이 겹친 합성 구성은 정정했으며 엔진 재현으로 세지 않는다. 유효한160% 줄간격을 준 source c8의 정상 실행은 앞 공백1개에서 Left6.7/Justify9.4로 실패했다. `stage1084-leading-before-final.log`의 실제1건 FAIL이다. 내부 공백 대조도 먼저 통과해 배분이 실제 활성화된 경우임을 확인했다. 공개 JSON 소수점 한 자리의 양자화 여유와 실물 배치 허용치를 혼동하지 않는다. 후보는 review worktree에만 있으며 본 작업 트리의 정식 회귀로 아직 추가하지 않았다.

## 생산·소비를 함께 고칠 범위

`compute_line_extra_spacing`의 현재 내부 공백 계수는 선두 공백도 포함한다. `emit_line_runs`와 각주·TAC 앞뒤 실제 조각의 폭·charX·paint는 같은 문자별 배분 결과를 소비해야 한다. 이미 처리하는 줄 말미 공백의 원본·synthetic soft-wrap 예외를 보존하며, 선두 공백을 분모에서 빼는 것만으로 끝내지 않는다.

- 줄의 유효 표시 텍스트와 실제 인라인 개체의 소유로 선두·말미 범위를 정한다. 런이 색상·글꼴 경계에서 나뉘어도 같은 줄의 범위다.
- 자연 폭을 버리거나 음수 좌표를 clamp하지 않는다. 양수·음수 배분 모두 자연 공백과 내부 공백을 구별한다.
- 전체 런과 각주/TAC 앞뒤 조각의 원본 범위를 교차해 같은 결과를 사용한다. 탭이 배분 비해당인 실제 분기와 shaping·kerning의 수용 조건을 확인한다.
- bbox만 줄이지 않고 최종 layout_positions, 다음 런/개체 원점, 공개 charX·hit-test와 Native/WASM replay를 함께 대조한다.
- 형식·문서명·문단 번호 조건을 추가하지 않는다. 커널 단위 검사나 진단 PNG만으로 완료하지 않는다.

이 경로 확인과 수정 전후 계약·원본19쪽 및 정상 대조군 전쪽 검증을 먼저 수행한다. 그 뒤 원래55문서853쪽의 전수 Native/fresh WASM과 전체 회귀·lint를 진행한다. 이전 source 전수 실행은 Native9문서 완료 자료를 보존하고 중단했으며 대기 중 WASM55개는 실행 전에 중단했다. 범위를 축소한 것이 아니라 알려진 미달 보정 뒤 최종 코드로 재실행하도록 순서를 정정한 것이다.

## 적용한 공통 결과

`leading_spaces.rs::LeadingSpaces`는 유효 표시 텍스트와 첫 실제 TAC·각주 위치에서 선두 소유를 한 번 계산한다. 겹쳐 쓰기 그룹은 여러 문자를 포갠 가시 개체이므로 그 내부를 줄 들여쓰기로 세지 않는다. 같은 소유 결과의 total은 분배 대상 계수에, 원본 런·조각의 교차 범위는 실제 방출에 전달한다.

선두는 extra_word_spacing을0으로 둔 자연 pen, 뒤 텍스트는 같은 배분 스타일로 이어 계산한다. 탭 뒤는 바뀐 pen에서 다시 계산하고 전체 뒤쪽을 일정 좌표만큼 빼지 않는다. 결과 문자 경계의 끝을 bbox·다음 런 전진에 전달하고 layout_positions로 replay·공개 charX가 같은 경계를 소비하게 한다. exact kerning의 기존 수용 조건은 유지하고 적용되지 않는 경우에도 새 자연 전진 결과를 버리지 않는다. 각주 앞/뒤 및 TAC 앞/뒤 실제 조각에도 원본 범위를 넘긴다. 탭 리더도 확정 경계가 있으면 재사용한다.

기존 분배 단위 검사는 기존 선두0 입력을 명시했으며 기대값을 바꾸지 않았다. 신규 합성 계약은 아직 review worktree 후보로 실행하고, 실제 문서의90% 미달 해소와 직접 판독 뒤 정식 회귀 추가를 판정한다. 새코드 검증은 아직 실행 전이다.

시작 시 일반 계정 디스크 여유6.1GiB를 확인해 실행 중 Cargo/Rust가 없는 상태에서 오래된 WASM debug 증분 버전3개와 종료된865MiB 임시 아카이브1개만 정리했다. 최신 WASM debug 증분, 모든 라이브러리·release·release-test·기준 입력·시각 증거는 보존했다.2.58GiB를 확보했고 정확한 목록은 ignored `stage1085-ended-cache-cleanup.json`에 있다.
