# Stage 327 — 첨자 오류에서 앞 항과 이후 입력의 경계

Issue: #7642

`script-failure-boundary`의 32개 수식을 한컴 일반 저장·Print로 출력했다.
수식 script의 저장 전후 보존과 전체 1쪽 출력을 확인했다. 입력·한컴 저장본·
Print PDF 및 해시는 진단 폴더에 함께 보존했다.

독립 Print는 다음을 구분한다.

- 앞 항 없는 `^x`·`_x`와 `{^x}`·`{_x}`는 출력하지 않고 이후 입력도 중단한다.
- `a {^} b`는 앞 항 `a`를 남기고 뒤 항을 중단한다.
- `a {x^} b`·`a {x_} b`는 `a`와 `x`를 남기고 뒤 항을 중단한다.
- `a {x^{}} b`·`a {x_{}} b`의 명시적 빈 그룹은 유효하여 뒤 항을 유지한다.
- 이중 marker와 서로의 marker를 피연산자로 삼는 경우도 앞 항을 보존하고 중단한다.
- 정상 음수 첨자는 유지한다. 구조 몸체 안의 같은 오류도 이후 입력을 중단한다.

문서 파서의 generic marker 오류는 기존 명령형 첨자 오류가 전체 수식을 비우는
계약과 구분한다. Stage 323에서 만든 중단 상태로 이미 읽은 앞 항·바깥 분수 등을
보존하는 방향을 검토한다. 명시적 빈 그룹을 누락 인자로 오판하지 않는다.
공개 호환 파서와 실제 문서 파서의 적용·비적용을 별도로 확인한다.

PDF glyph·좌표·script 대조는 ignored `stage327-script-failure-print-trace.json`에
보존했다. 현재 production 수정과 새 렌더링 회귀 추가는 아직 수행하지 않았다.
