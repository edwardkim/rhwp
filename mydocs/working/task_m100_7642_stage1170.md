# 단계 1170 독립 Print 입력의 공백 소유 회귀 정식화

Issue: #7642. 기준 devel은 `463c48cc228170b576c832591b76826116e86a49`, 검증 구현은 `fa56a97f683fb7ca690ae6a155bf1902bcfc9406`이다.

## 근거와 범위

단계 1093의 합성 HWPX를 내용 변경 없이 한컴 2020 MCP의 Print 경로로 출력한 6쪽을 사용한다. 수동 합성 입력임을 보존하며 일반 한컴 저장본으로 설명하지 않는다. 입력은 앞 공백 0·1·3개와 자간 0·음수의 Left/Justify 쌍 12문단이다. 기존 8회 반복 진단 입력의 점수를 대신 사용하지 않는다.

입력 SHA-256은 `cb7d4ae03e319c6f33b0432a118c2c25dbfee522a4bbb88bef8868aa480d899c`, 독립 PDF는 `fd7ae62cb38455e2d114d233290babd48a595bb36c0c8b8582b65d90ddbb84a4`다. PDF는 `pdf/issue7642-leading-tracking-contract/leading-tracking-contract-2020.pdf`에 한 번 보존하고 새 fixture에서 같은 바이트를 참조한다.

## 새 이름의 검사와 독립 기대값

- 6쪽에 각각 Left/Justify 원문 한 쌍이 있으며 모든 문자가 원래 문단·쪽에서 순서대로 보존된다. 원문 문자 범위, 줄의 진행과 누락·중복을 함께 확인한다.
- 선두 공백과 자동 줄바꿈에서 소비한 말미 공백은 Left와 같은 자연 전진을 유지하며 내부 단어 사이 공백만 배분한다. 공개 JSON의 소수 첫째 자리 직렬화 오차와 절대 위치 허용치를 구분한다.
- 2쪽의 첫 가시 `a` 원점은 독립 Print에서 두 정렬 모두 55.10205pt, 96dpi에서 약 73.4694px다. 해당 쪽 양쪽 98% 이상과 확대 판독을 확인한 경우에만 ±2px 검사로 보호하고 내용 관계 검사도 유지한다.

현재 ignored 후보를 새 기준 라이브러리에 직접 링크한 결과 3건 중 내용 보존 1건은 통과했다. 자연 말미 전진은 Left 약 6.6/Justify 약 6.2로 실패했고, 2쪽 Justify 원점은 약 76.1px로 독립 기대값에서 2px를 넘겨 실패했다. 빌드 오류가 아닌 의도한 assertion 실패다. 이 증거는 단계 1170의 link 명령·종료 코드와 로그에 보존한다.

## 정식 추가 전과 후의 검증

기존 Native 전쪽 최저 97.19000%와 fresh WASM 전쪽 최저 97.46868% 및 대표 영역 판독을 재사용하되, 검증용 Chrome을 명시한 새 fresh WASM 6쪽 결과를 먼저 확인한다. 필요한 양쪽 최저값·2쪽 98% 이상·같은 영역 판독 뒤에만 입력·새 이름의 정식 회귀를 추가한다. 같은 코드의 Native 라이브러리를 빌드해 수정 후 PASS를 확인한다. 기존 합성 Split 단위 검사에서 말미 구분자를 내부 슬롯으로 센 기대값도 독립 Print로 입증한 계약에 맞춘다.

새 정식 검사와 fixture는 문서별 선행 조건을 만족해도 전체 PR 완료를 뜻하지 않는다. 원본 HWP3 19쪽의 90% 미달, HWPX 25쪽·추적 변경 4쪽의 실제 줄바꿈 차이, 원래 전체 55문서와 대조군의 Native/fresh WASM 검증 및 전체 Rust/lint 게이트는 계속 해결한다. 별도 이슈로 넘긴 HML 수식 회귀는 재활성화하지 않는다.

## 정식 추가 직전 확인

지정한 일반 Chrome에서 같은 fresh WASM 패키지로 6쪽을 다시 렌더했다. 새 TSV의 전쪽 최저값은 97.46868%, 2쪽은 98.63457%다. Native는 전쪽 최저 97.19000%, 2쪽 98.59310%다. 새 review 1~6쪽의 앞 공백·줄 구성·가시 끝과 내부 간격을 직접 확인했고 입력/PDF SHA 및 6쪽 대응도 일치했다. 따라서 이 입력의 정식 fixture와 새 이름의 검사 3건을 추가한다. 기존 8회 반복 후보는 정식 fixture로 추가하지 않는다.

루트의 전체 fmt 첫 시도는 이전 자동 생성 suite가 이미 제거된 검사 파일을 참조해 실패했다. 이를 렌더링 결함이나 Rust 컴파일 실패로 세지 않는다. 검토 worktree에서 canonical `--prepare`를 먼저 실행하고 전체 fmt와 새 정식 검사 및 기존 Split 계약을 다시 실행한다. 파생 suite는 제출 변경에 포함하지 않는다. 수정 후 검사 통과는 아직 미확인이다.
