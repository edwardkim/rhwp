# Issue #7642: 남은 미달의 채우기·개체 앞 공백·PDF 래스터 원인 분석

## HWP3 원형 채우기의 전이 중심

- 부모 source `a36f3a3dc8ed39ce71dd172a1c33166e7ecdc141`, 고정 devel `2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`다. 원본·독립 Print는 단계 1378과 같다.
- 19쪽 Native 실루엣 88.58424%를 단순 글꼴 차이로 분류하지 않았다. 같은 고정 232/2px/색차32 식에서 미일치 픽셀 24203개 중 24196개가 본문 내부에 있고, 원형 채우기 띠에 집중된다. 외곽 4개 변과 ORACLE D/B 영문 줄의 직접 영역 진단은 각각 100%다. 이 영역 진단을 전쪽 통과로 대신하지 않는다.
- `stage1394-sample16-p19-unmatched.png`와 `stage1394-sample16-p19-localization.json`은 같은 원본 PNG의 불일치 위치를 보이는 진단이다. 마스크·측정 영역·최종 점수는 바꾸지 않았다.
- HWP3 gradient 구조는 시작/끝색·종류·각도·물리 중심 x/y·띠 개수만 저장한다. 파서가 존재하지 않는 HWP5 추가 전이 중심을 0으로 넣어 `expand_gradient_steps`의 유효한 0% 전이로 소비된다. 실제 layer의 앞쪽 띠 위치가 모두 0으로 접혀 중앙 색도 원래 색보다 옅어진다.
- 독립 PDF는 같은 원점의 동심 타원을 균등 띠로 칠한다. HWP3에 없는 전이 중심은 가운데 50%로 주입해야 한다. HWP5/HWPX의 명시적인 0%는 유지하며 공통 stop 함수의 0 의미를 바꾸지 않는다.
- 경로: HWP3 원시 gradient → shape_mapping의 GradientFill → layout/utils의 공통 띠 확장 → GradientFillInfo → Paint/Native Skia·fresh WASM Canvas다. 원본 64쪽과 중요 19쪽의 색·경계·배경·본문 보존, HWP5/HWPX peer와 별도 전이 중심 대조군을 확인한다.

## 배포 문서와 개체 앞 공백

- `samples/task1768/distribution_doc.hwpx`는 실제 HWP5다. 확장자만 맞춘 동일 바이트를 한컴 2020에서 Print한 독립 PDF를 사용한다.
- 3쪽 표 원점은 현재 x83.2 CSS px, 독립 Print는 약91.2다. 줄바꿈 시 개체 앞 마지막 공백이 일반 단어 앞 공백처럼 제거되는지 실제 프레임·줄 소유를 추적한다. 고정 8px 보정은 추가하지 않는다.
- 6쪽 독립 Print 통제 입력을 만들었지만 첫 HWPX 생성본에서 한컴이 원래 용지 여백 대신 기본 여백을 적용했다. 이 첫 통제군을 원본 배치의 올바른 반례로 승격하지 않는다. 저장본의 실제 속성을 대조해 통제군을 교정하고, 공백 0/1/2/3개·강제 개행·일반 텍스트의 결과로 규칙을 확인한다. 원본과 기존 PDF는 보존한다.

## PDF 래스터의 별도 결함 진단

- 배포 원본 PDF에는 파란 채우기 띠가 있다. 현행 `pdftoppm -thinlinemode shape`의 PNG는 그 띠를 흰색으로 덮는다. 같은 PDF·DPI의 Poppler 기본 none과 독립 MuPDF는 파란 띠를 보인다.
- 동일 Native PNG·동일 실루엣 식으로 배포 3쪽은 shape/solid 81.73836%, none 90.08061%, MuPDF 89.15529%다. HWP3 19쪽은 shape와 none 모두 88.58424%로 원형 채우기 미달은 그대로다. 점수를 위해 특정 문서의 옵션만 바꾸거나 실제 배치 차이를 면제하지 않는다.
- `stage1393-pdf-raster-diagnostic/receipt.json`에 PDF/PNG hash·모드별 실제 명령과 점수를 보존했다. 현행 지침은 shape를 명시하므로 진단 수치와 공식 TSV를 섞지 않는다. 래스터 경로를 교정하면 고정 devel과 후보 Native/fresh WASM 모두 같은 새 설정으로 전쪽을 다시 측정한다. 기존 증적은 덮어쓰지 않는다.
- 옵션은 [Poppler pdftoppm 원문](https://skia.googlesource.com/third_party/poppler/+/master/utils/pdftoppm.1)의 thin line 설명을 확인했다. 기본 none은 스냅을 하지 않고 shape/solid는 1px 미만 경계를 픽셀에 맞춘다. 수치 상승만을 수정·승인 근거로 삼지 않는다.

새 실물 회귀와 기대값 변경은 해당 원본의 전쪽 Native/fresh WASM 90% 및 확대 판독 이후에만 진행한다. 현재는 분석·보정 전이며 PR 준비 완료가 아니다.

## 독립 대조군과 수정 방향 확정

공백 통제군은 한컴이 저장한 정상 HWPX 구조를 재사용하고 원래 18mm 여백을 명시한 r2로 교정했다. 자동 줄바꿈의 공백 0/1/2/3개 모두 표가 같은 왼쪽 원점으로 가고, 강제 개행 뒤 3개 공백은 보존됐다. 현재 Native도 같은 관계다. 따라서 마지막 공백을 항상 표와 이월한다는 가설은 기각했다. 공백 분기를 임의로 바꾸지 않으며 원본 배포 ViewText의 실제 줄 구성·가용 폭 소비를 추적한다. 첫 대조군의 용지 기본값 문제와 이 결과를 구분한다.

원본 배포 ViewText를 제품의 공개 복호화 경로로 읽어 문단 47 원시 record를 확인했다. PARA_HEADER·TEXT·CHAR_SHAPE·CTRL_HEADER는 있지만 LINE_SEG record는 없다. 파서가 유효한 저장 줄을 삭제했다는 근거는 없으며 0 높이 stub 수용 조건도 바꾸지 않는다. 원장은 `stage1400-distribution-raw-host-records.json`이다.

원형 채우기의 두 번째 오류도 확인했다. 독립 Print의 동심원 바깥 반지름은 긴 축 절반이 아니라 **중심에서 가장 먼 모서리까지의 거리**다. 실제 19쪽과 별도 한컴 2020 Print 6쪽의 정사각형·가로/세로 직사각형·0/100% 중심에서 같은 식이 맞는다. 측정은 PDF의 타원 path에서 했고 구현 값을 기대값으로 재인용하지 않았다.

- 원형 통제군: `pdf/issue7642-radial-gradient-contract-20261016/radial-gradient-contract-r3.hwpx`와 동일 입력의 `radial-gradient-contract-r3-2020.pdf`. `stage1402-radial-mcp.json`에 Print mode0·한컴 버전·입력/출력 hash를 연결했다.
- 최초 통제군의 HWPX type 오타 CIRCLE은 공식 RADIAL로 교정했다. 색 없는 최초 출력은 원형 검증 증거로 쓰지 않는다.
- 독립 6쪽의 실제 반지름·pt 원점·96dpi 변환·차이는 `stage1402-radial-print-measurements.json`에 있다.
- 공통 radial_circle helper를 모서리 거리로 교정하고 SVG·Canvas·Native Skia가 그 결과를 소비하게 한다. Native Skia에 남아 있던 별도 긴 축 반경도 제거한다. 원뿔·사각의 기존 근사는 이번 원형 계약으로 바꾸지 않는다.
- Native/fresh WASM 전체 대조와 실제 Canvas·SVG 소비를 실행한 뒤에만 완료 여부와 회귀 추가를 판정한다. 색/농도·원형 띠·본문/테두리·다른 원본과 명시적인 전이 중심을 보호한다.

## 첫 Native 보정 검증

단계 1403의 고정 `target/pr-review`·빌드 잡 8·native-skia 빌드는 exit 0이다. 빌드 전후 생산 코드 SHA-256이 모두 같고 `cargo fmt --all -- --check`도 exit 0이다. 생산 원장은 ignored `stage1403-current-native.json`이며, 검증 명령·입력/PDF SHA·TSV는 `stage1405-gradient-native-qualification/receipt.json`에서 연결한다.

- 원본 HWP3 64쪽 전쪽 일치율 최저 **92.25853%**, 미달/누락 0쪽, 독립 Print와 전체 64쪽 일치다.
- 19쪽은 같은 96dpi·232/2px·색차32·PDF shape 래스터 조건에서 **88.58424% → 99.97506%**다. 새 review PNG를 실제 열어 채우기 띠와 본문의 대응을 확인했다. 글자 농도와 외곽선 잔여 차이는 별개이며 픽셀 완전 일치로 보고하지 않는다.
- 독립 원형 통제군 6쪽은 Native 모두 **100.00000%**다. 수정 전 같은 통제군은 정사각형 89.72476%, 중심이 옮겨진 가로 상자 67.81916%/67.65087% 등으로 원형 반경 결함을 드러냈다.
- HWP5/HWPX peer, fresh WASM 전쪽 및 실제 SVG 소비 경로의 검증은 아직 진행 중이다. fresh WASM은 같은 생산 파일 hash로 빌드하며, 그 검증을 마치기 전 새 실물 회귀를 추가하거나 PR 준비 완료로 판정하지 않는다.

원본 배포 문서의 남은 표 위치와 PDF 래스터 문제는 이 채우기 수정으로 해결됐다고 간주하지 않는다. 고정 devel 대비 전쪽 하락 검사와 남은 전체 회귀도 미완료다.
