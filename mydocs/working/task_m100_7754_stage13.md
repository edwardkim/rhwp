# 독립 기호 원본 복원과 실제 TTF 공급 조건 확인

#9293 머지 전 PR 제출을 보류하는 지시를 유지한다. 렌더러 코드와 보호 하한을 바꾸지 않고
글꼴 공급의 원인을 대조했다. 증거는 `mydocs/pr/assets/issues7754_7765/source44/`에 보존했다.

## 독립 한컴 Print의 기호 원본

별도로 작성한 한양중고딕 전체 표본이 Windows 한컴 2020 `11.0.0.9136`에서 성공했다.
실제 `pdf_print_method: 0`, `hancom2020_pdf_driver_one_up`을 확인했으며 7쪽의
11,187자 전체 순서와 Type3 글리프 집합을 검증했다. 글머리표 U+2022, 원 U+25CB,
화살표 U+279C의 원본 프로그램 SHA가 기존 기준 자료의 프로그램과 각각 일치한다.
대상 PDF와의 대조는 읽기 전용이며 글꼴 생성 입력은 이 별도의 전체 표본뿐이다.

이 독립 표본에서 14개의 비어 있지 않은 표준 기호·일반 문장부호를 private CFF로 옮겼다.
원본 전진과 윤곽을 그대로 사용하고 CFF xMin을 hmtx bearing에 기록했다. 위치·폭·획의
점수 보정은 하지 않았다. U+2027은 독립 Print에서도 빈 Type3 프로그램이어서 제외했고
가상의 점 윤곽이나 다른 문자 매핑을 만들지 않았다. 기존 공급 사다리가 이 문자를 담당한다.

새 family는 `RHWP Hancom Independent Symbols`다. 사라진 과거
`RHWPIndependentHFTSourceSymbols` 파일이나 그 SHA를 복구했다고 기록하지 않는다.
SPJGT를 원본 CFF로 유지하면서 빠진 기호만 이 독립 부분 공급으로 보완한다. 상용 글꼴
바이트는 Git에 넣지 않고 독립 PDF·입력·부분 글꼴은 제외된 private PDF 폴더에 보존했다.
생성 절차·Print 영수증·해시와 명시적 누락 목록은 공개 증거로 남겼다.

한양신명조의 별도 전체 표본 job은 실패했다. 실패 상태를 그대로 보존하며 그 job의 출력은
복원 근거로 사용하지 않았다. 성공한 한양중고딕 표본의 독립 근거만 사용했다.

화학 Native의 base·후보 전쪽 103쪽은 각각 최저 99.99%로 기존 보호 하한의 미달이 없다.
fresh WASM 전쪽에는 일부 0.01~0.06%p의 하한 미달이 남아 전체 완료로 판정하지 않는다.
60·61·72·74·91쪽의 PDF·Native·WASM을 같은 96 DPI의 4배 확대 화면에서 직접 대조했다.
화살표·글머리표·틸데·원의 공급 개선과 크기·기준선·주변 글자의 보존을 확인했다.

## 시행령의 원본 TTF와 공급 방식

시행령 기준 PDF의 따옴표는 H2MJSM TrueType 프로그램이다. 로컬 원본 TTF와 PDF의
U+201C·U+201D 윤곽 및 hmtx를 직접 대조해 일치를 확인했다. 휴먼명조의 HMKMM TTF도
기준 PDF의 독립 글리프와 윤곽·hmtx가 같다. 이름이 비슷한 HMFMMUEX TTC는 실제 face가
모음T·엑스포이므로 불일치 근거를 남기고 대체 공급으로 사용하지 않았다.

실제 원본 TTF의 프로그램 신원을 명시하자 WASM의 미달 8쪽이 모두 100.00%로 회복됐다.
Native에 남은 괄호 차이는 Palatino Bold의 글리프 불일치가 아니었다. 복사한 Windows
Palatino Bold의 괄호 윤곽·hmtx도 기준 PDF와 같다. 같은 정적 TTF를 명시적 custom 폰트로
넣는 경로와 Fontconfig의 system 폰트로 공급하는 경로의 출력 조건을 구분했다.

private Fontconfig에서 원본 Palatino를 공급하여 기존 system 경로를 재현한 결과,
4·5·8·24·28·45·46·63쪽의 base·후보가 Native·WASM 모두 100.00%다. 전역 설치나
렌더러 hinting·출력 좌표의 변경은 하지 않았다. 정본 manifest의 전쪽은 74쪽이다.
처음 전체 요청을 119쪽으로 잘못 지정한 실패와 정정·재실행은 stage14에 기록한다.

## Windows Arial의 실제 사용

Helvetica 스타일 보호 문서는 확보된 기존 목록에서 Arial이 빠진 WASM 실행만 98.89%였다.
승인받아 Windows에서 복사한 원본 Arial 4종을 실제로 공급하니 한 쪽 전체가 Native·WASM의
base·후보 네 실행 모두 100.00%로 회복됐다. 과거 파일 SHA와 같다고 표시하지 않고 실제
복사 SHA·기존 기록과 현재 공급을 구분한다. 화학 WASM의 나머지 차이도 같은 방식으로
실제 공급 프로그램을 확인하며 조사한다. 전체 보호·필수 편람 검증은 아직 진행 중이다.
