# Issue #7642: 정상 저장 본문의 어절 꼬리 캐시 재검토

## 독립 근거와 원인

부모는 `4b42375247864807db155e5d9388a7eda73f6ea2`, 고정 devel은
`2efefc6a1f9812a188e32c1cb283e9ef7962ea3e`다. 언어 원본과 Print는 단계 1383과 같다.
이전 Native 전범위 대조에서 언어 8쪽은 base 97.45733%, 후보 95.28261%다.

`stage1421-base-language-p8/`와 `stage1421-current-language-p8/`는 각각 고정 devel과
생산 코드 aaa63849e의 보존 fresh WASM으로 같은 원본 8쪽을 조회한 기록이다.
문단 177의 원문 317글자는 동일하며, 새 출력의 줄 수 감소와 양쪽 정렬 공백의 변화가 있다.
공백 분배를 제외한 자연 폭 차이는 마침표 7개·쉼표 5개의 언어 슬롯뿐이다.
독립 Print 첫 줄의 마침표도 한글 T4와 별도 영문 T3로 출력된다. 따라서 한글 슬롯으로
일괄 되돌려 점수를 맞추지 않는다. glyph 자체의 일치와 저장 줄 분할의 권위는 별개다.

`can_rejoin_stored_word_tail`은 같은 프레임이 더 적은 줄로 수용한다는 이유만으로
정상 저장 본문의 자동 줄 경계를 stale로 승격했다. 독립 Print는 해당 10개 저장 줄을
보존한다. 캐시 기하가 맞고 원문이 수정되지 않았으면 현재 자연 폭으로 더 적은 줄을
만들 수 있다는 사실만으로 본문 캐시를 무효화할 근거가 되지 않는다.

## 수정할 경로와 반례

공통 resolver의 기존 정책에서 본문은 `StoredRowMissPolicy::Reflow`, 정상 저장 셀은
`UnmodelledUnlessStale`를 전달한다. 어절 꼬리의 추가 재검토는 기존 셀 정책에 남기고,
본문의 기하 불일치·실제 stale·편집·명시적 재정렬·수식 재측정의 재조판은 유지한다.
문단 ID·문자열·글꼴 이름·고정 줄 수로 구현 분기를 추가하지 않는다.

생산 결과 → 소비 지점은 `stored_cell_reflow`의 stale 결정 → 공통 Frame resolver →
Reflowed의 줄·공백 기하 → 문단 측정 및 실제 body 배치다. 정상 본문은 stale를 추정해
Reflowed로 보내기 전에 원래 캐시 수용 경로를 유지한다.

별도 셀 반례는 #7701 검토 기록의 교육과정 원본 151쪽 `시연하/기`, 162쪽 `포/함)`이다.
독립 Print가 한 줄로 출력하므로 그 셀의 기존 정책과 공통 기하 전달을 보존한다.
해당 원본은 `mydocs/pr/assets/issue7445/education-curriculum-map/`의 보존 바이트를
진단 대조군으로만 사용한다. 이관된 회귀를 활성 검사로 복원하지 않는다.

## 검증 계획

1. 같은 고정 target·빌드 잡 8로 Native 생산물을 준비한다.
2. 언어 8쪽과 완료 10쪽을 먼저 실제 Print와 대조하고 원본 15쪽 전쪽 TSV를 산출한다.
   쪽수·원문 순서·누락·중복·단 소유와 저장 줄 시작점도 확인한다.
3. 사회 원본·분할 대조군 및 현재 남은 배포 문서는 정상/미해결 대조군으로 유지한다.
   이 수정으로 해결됐다고 가정하지 않는다.
4. 셀 반례의 동일 정책과 실제 줄 소속을 실행 대조한다. Native 경계가 맞은 뒤 같은
   생산 소스로 fresh WASM을 준비하고 관련 전쪽·확대 판독을 확인한다.
5. 전쪽 Native/fresh WASM 90%·직접 판독 후에만 새 이름의 정식 관계 회귀를 추가한다.
   완료 페이지의 98% 및 독립 좌표 조건을 충족한 경우에만 ±2px를 사용한다.

## 배포 문서 분석의 구분

`stage1419-public-frame-probe`는 원본을 바꾸지 않고 공개 셀 프레임 진입점에서 같은
물리 폭을 사용한 별도 진단이다. 원본 배포 문단은 공백 2개/1개로 나뉘지만 실제
inline plan은 공백 3개를 앞줄에서 소비한다. 이 진단을 최종 body 출력으로 보고하지 않는다.
한컴이 저장한 82개 선행 공백 대조군도 같은 원시 93 위치에서 다음 줄이 시작된다.
83개 선행 공백 경계의 별도 한컴 저장본에서는 raw 110(선행 구조 슬롯 16 제외 시 94)이며,
단순히 모든 첫 초과 공백에서 줄을 끝내는 수정은 그 반례를 깨뜨린다.
따라서 검증되지 않은 공백 분기를 이번 저장 본문 보정에 섞지 않는다.

저장본은 LineSeg 진단용이며 시각 판정 기준은 원본 대응 Print PDF 그대로다.
`stage1420-*`, `stage1423-*`에 SaveAs HWP job과 관측을 별도 기록했으며
SaveAs HWP를 Print PDF 생성 증거로 사용하지 않는다.
