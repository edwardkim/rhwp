## 독립 근거와 수정 순서

1. #7754의 실제 Hancom 저장본에서 8번 문단의 모든 원본 줄은 문단의 좌·우 여백을
   이미 제외한 상자다. 저장 시작·끝과 `ParagraphBox::body_for_style`의 양쪽 경계를
   대조한다. 그림 존재만으로 이 상자를 어울림 배제 줄로 바꿔 여백을 다시 적용하는
   소비 지점을 보정한다. 실제로 좁혀진 줄, 혼합 폭 줄, 셀·글상자 경로는 별도 계약을
   유지한다. cs 하나만 여백과 일치한다는 이유로 판정하지 않는다.
2. Enter 키 U+F03A0은 실제 공급한 같은 SFNT에 원 glyph와 전진폭이 있을 때 기존
   PUA 공급 경로를 사용한다. 원 프로그램이 없는 환경의 의미 대체는 유지한다.
   기존 기호의 공급 탐색 순서를 바꾸지 않는다.
3. 표제의 원본 자모는 그대로 보존한다. 기존 한양 PUA 표의 역관계와 실제 선택된
   원 글꼴의 cmap으로 조합 glyph를 사용할 수 있는지 별도로 조사한다. 제품명이나
   특정 문서 문자열을 치환하지 않는다. 측정과 paint가 같은 선택을 소비해야 한다.

## 기존 해결 이력과 실제 소비 연결

- #5677의 `60e4a4be49`는 빈 문단의 자기 여백을 외부 배제로 오인하는 문제를
  수정했다. #6706을 포함한 `4fddb1bb72`는 저장 TAC 배정이 인증한 프레임에서만
  같은 여백의 중복을 제거했다. 두 조건을 일반적으로 완화하지 않는다.
- #4690의 좁은 조각과 #1230의 실제 그림 배제는 문단 상자와 다른 저장 범위다.
  완전한 양쪽 경계 대조를 사용해 실제 배제와 문단 여백의 출처를 구분한다.
- 줄 구성의 `ParagraphBox` → `uses_stored_segment_geometry`의 상자 선택 →
  `effective_col_x/w` → `effective_margin_left/right` → 후속 wrap 오프셋과 최종
  bbox를 추적한다. 후속 오프셋이 같은 여백을 다시 소비하는지도 실제 출력으로 확인한다.
- PUA 공급은 `NativePuaFonts`의 cmap·전진폭 등록 → `NativePuaMetrics` →
  `expand_pua_render_text_in_style` 및 측정 → 출력 backend의 실제 glyph 선택을
  확인한다. 실제 글꼴 프로그램의 우선순위는 원 TTF → 검증된 TTC → OTF 순서를 유지한다.

## 검증 계획

먼저 첫 쪽과 실제 어울림 반례를 수정 전·후 Native와 fresh WASM으로 대조한다.
그 뒤 원본 24쪽과 암호 원본, 나머지 대상 원본 및 보호 문서의 전쪽 TSV를 확인한다.
새 회귀 등록은 실제 양쪽 raw 측정과 독립 Print 확대 판독 후 진행한다. 핵심 위치는
양쪽 최솟값 100% → 99%대 → 98%대 순서로 선정하고 관계 검사도 유지한다.
글꼴이 없는 회귀 환경에서도 조용히 건너뛰지 않는 검사를 작성한다.
최종 코드에서 필수 Rust·lint·WASM·브라우저·편람 게이트를 다시 완료한다.
현재 문서는 계획이며 아직 실행하지 않은 검증을 통과로 표시하지 않는다.

## 보정 커밋과 분할 프로그램의 추가 조사

여백·Enter 공급 보정을 `4230d331b3e715761224fd515b1fed7ce28ba318`에 커밋했다.
이 코드의 Native·fresh WASM 빌드는 진행 중이며, 첫 쪽과 #8399의 실제 어울림
A·D·E HWP/HWPX 6개를 빌드 후 자동 대조하도록 준비했다.

표제는 실제 4배 패널의 5개 출력을 직접 읽어 차이를 확인했다. 원본 글꼴의 첫
영문 조각 `ENGGT.otf`에는 자모·호환 음절이 없고 같은 family의 `HGGGT.otf`에는
U+F53A의 실제 윤곽과 1.0em 전진이 있다. 본문 `HGSMJ.otf`도 같은 음절을 제공한다.
원본 자모를 변경하지 않는 역매핑은 이미 `pua_glyph`에 있으나 Native는 첫 후보만
확인하고, Canvas의 단일 프로그램 coverage 역시 분할 프로그램의 소유를 확정하지
못한다. 원문·슬롯·선택 family의 실제 trace도 보존했다. 이 trace는 paint snapshot을
포함하지 않으므로 실제 backend 글리프의 증거로 승격하지 않았다.

다음 보정 초안은 실제 등록 프로그램을 같은 순서로 확인한다. 앞 프로그램에 원
자모가 있으면 기존 shaping을 유지하고, 그 전의 프로그램이 유일한 호환 음절을
공급하면 같은 hmtx와 glyph를 측정·Native·Canvas가 함께 소비하도록 한다.
TTF·TTC·OTF 우선순위를 재배열하거나 글꼴 이름만 보고 건너뛰지 않는다.
현재 초안은 `output/`에만 있으며 아직 제품 코드에 적용하거나 검증한 것이 아니다.

소스 33 Native의 10개 원본 583쪽 측정은 종료했다. 시장구조조사는 기준 최저
26.80%에서 후보 98.40%이며 모든 대상 원본의 Native 최저는 98% 이상이다.
이는 수정 전 Native의 수치 결과다. 첫 쪽의 직접 판독 미달, fresh WASM의 진행 중
범위와 암호 원본의 별도 검증을 이 숫자로 완료 처리하지 않는다.

## 소스 34의 후속 수치와 소스 35 구현

소스 34 Native 원본 24쪽은 전쪽 최저 99.22%이며 누락·98% 미만 쪽은 없다.
fresh WASM 첫 쪽은 98.07%에서 99.49%로 개선됐다. 전체 Native 자료와
완료한 WASM 집중 대조만 `source34/`에 보존한다. WASM 24쪽 전체를 실행한
것으로 기록하지 않는다.

독립 PDF의 첫 옛한글은 Type3 T2에서 U+F53A와 ZWSP 두 글자로 기록된 뒤
Hancom이 만든 래스터 이미지 Im3로 덮어 그려진다. 이 이미지는 원본 HWPX의
3개 BMP 자원이 아니다. 원 HGGGT의 PostScript 조회를 명시한 원인 분리 실험은
같은 옛한글 윤곽을 복원했다. 독립 PDF와의 잉크 경계는 세로 2px 차이가 남았다.
이 실험의 명시 글꼴 환경은 최종 선택 정책·시각 통과 자료로 사용하지 않는다.
원 글꼴 프로그램이나 추출한 glyph 명령은 커밋하지 않고 비교 패널과 메타데이터만
`source34/causal-glyph/`에 보존했다. 이 관측을 근거로 수치를 맞추는 y 보정은 넣지 않는다.

소스 35는 기존 한양 PUA 역매핑과 실제 등록 프로그램의 순서를 함께 사용한다.
앞 프로그램에 원 자모가 있으면 shaping을 보존하고, 그 전에 가시 호환 음절을
가진 프로그램이 있으면 그 프로그램의 hmtx와 표시 glyph를 측정·Native·Canvas가
공유한다. 원본 SFNT를 축약하기 전에 가시 윤곽을 확인해 빈 cmap 항목을 양수
coverage로 오인하지 않는다. 원문 자모·문자 주소와 원 TTF → 일치 TTC → OTF
순서는 유지한다. 목록처럼 원점 발행이 차단된 문단 상자도 폭 하나로 인증하지 않게 했다.
새 구현은 아직 제품 빌드·시각 검증 전이며 새 회귀도 이 상태에서 등록하지 않는다.

최신 Studio와 생산물로 검증하기 위해, 소스 33의 대기 중인 브라우저 큐는 종료했다.
완료된 Studio 2,822개·typecheck 증거는 보존했고 실제 실행 중인 자식 검사가 없는
것을 확인했다. 미실행 브라우저 항목은 `superseded-before-browser.json`에 명시했다.
