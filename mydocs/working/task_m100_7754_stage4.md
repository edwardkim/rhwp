## 독립 근거와 수정 순서

1. #7754의 실제 Hancom 저장본에서 8번 문단의 모든 원본 줄은 문단의 좌·우 여백을
   이미 제외한 상자다. 저장 시작·끝과 `ParagraphBox::body_for_style`의 양쪽 경계를
   대조한다. 그림 존재만으로 이 상자를 어울림 배제 줄로 바꿔 여백을 다시 적용하는
   소비 지점을 보정한다. 실제로 좁혀진 줄, 혼합 폭 줄, 셀·글상자 경로는 별도 계약을
   유지한다. cs 하나만 여백과 일치한다는 이유로 판정하지 않는다.
2. Enter 키 U+F03A0은 실제 공급한 같은 SFNT에 원 glyph와 전진폭이 있을 때 기존
   PUA 공급 경로를 사용한다. 원 프로그램이 없는 환경의 의미 대체는 유지한다.
   기존 기호의 공급 탐색 순서를 바꾸지 않는다.
3. 표제의 원본 자모는 그대로 보존한다. 기존 한양 PUA 표의 역관계와 실제 선택된
   원 글꼴의 cmap으로 조합 glyph를 사용할 수 있는지 별도로 조사한다. 제품명이나
   특정 문서 문자열을 치환하지 않는다. 측정과 paint가 같은 선택을 소비해야 한다.

## 기존 해결 이력과 실제 소비 연결

- #5677의 `60e4a4be49`는 빈 문단의 자기 여백을 외부 배제로 오인하는 문제를
  수정했다. #6706을 포함한 `4fddb1bb72`는 저장 TAC 배정이 인증한 프레임에서만
  같은 여백의 중복을 제거했다. 두 조건을 일반적으로 완화하지 않는다.
- #4690의 좁은 조각과 #1230의 실제 그림 배제는 문단 상자와 다른 저장 범위다.
  완전한 양쪽 경계 대조를 사용해 실제 배제와 문단 여백의 출처를 구분한다.
- 줄 구성의 `ParagraphBox` → `uses_stored_segment_geometry`의 상자 선택 →
  `effective_col_x/w` → `effective_margin_left/right` → 후속 wrap 오프셋과 최종
  bbox를 추적한다. 후속 오프셋이 같은 여백을 다시 소비하는지도 실제 출력으로 확인한다.
- PUA 공급은 `NativePuaFonts`의 cmap·전진폭 등록 → `NativePuaMetrics` →
  `expand_pua_render_text_in_style` 및 측정 → 출력 backend의 실제 glyph 선택을
  확인한다. 실제 글꼴 프로그램의 우선순위는 원 TTF → 검증된 TTC → OTF 순서를 유지한다.

## 검증 계획

먼저 첫 쪽과 실제 어울림 반례를 수정 전·후 Native와 fresh WASM으로 대조한다.
그 뒤 원본 24쪽과 암호 원본, 나머지 대상 원본 및 보호 문서의 전쪽 TSV를 확인한다.
새 회귀 등록은 실제 양쪽 raw 측정과 독립 Print 확대 판독 후 진행한다. 핵심 위치는
양쪽 최솟값 100% → 99%대 → 98%대 순서로 선정하고 관계 검사도 유지한다.
글꼴이 없는 회귀 환경에서도 조용히 건너뛰지 않는 검사를 작성한다.
최종 코드에서 필수 Rust·lint·WASM·브라우저·편람 게이트를 다시 완료한다.
현재 문서는 계획이며 아직 실행하지 않은 검증을 통과로 표시하지 않는다.
