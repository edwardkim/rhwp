## 결론

Q4-D1은 exact font registry의 불변 snapshot을 소유하고 `(charShapeId, languageIndex)` slot의 source
identity를 shape 직전에 재검증하는 `VerticalShapingContext`를 제품 module에 등록했다. context가 만드는
결과는 source handle·registry generation·동일 `Arc<[u8]>`·units-per-em을 인증한 dormant transaction이며,
layout·sidecar·paint·backend caller는 여전히 0이고 `product_published=false`다.

D0의 다섯 red 가운데 module registration과 exact-source-bound owner 두 항목만 green으로 전환됐다.
남은 D2 atomic layout commit, D3 vertical publication, D4 CanvasKit feature detection 세 항목은 의도한 red로
유지된다. 따라서 이 결과는 제품 activation이 아니라 다음 절편이 사용할 인증된 입력 권위만 연 것이다.

## 1. 구현 계약

1. `renderer::shaping_vertical`은 제품 module에 등록되지만 `#[allow(dead_code)]` 상태다.
2. `VerticalShapingContext`는 생성 시 exact registry를 소유해 이후 외부 registry 변경을 관찰하지 않는다.
3. `prepare_dormant`는 legacy fallback geometry를 먼저 검증하고, exact slot handle과 source를 다시 대사한 뒤
   Q4-C transaction을 만든다.
4. source certificate는 registry generation, exact slot, SHA-256·길이·face index handle, 동일 source bytes
   `Arc`, units-per-em만 소유한다.
5. Debug에는 raw text·font bytes·경로를 남기지 않는다. source 부재·identity mismatch·malformed face와
   Q4-C intent/run/variation/limit 실패는 typed reason과 원래 fallback geometry를 반환한다.
