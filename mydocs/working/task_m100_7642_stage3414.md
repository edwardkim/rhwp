## 수식 카탈로그의 독립 출력 문맥 재현

원래 259개 카탈로그의 한컴 2024 Print와 입력은 보존했다. Native 전체 66쪽 중
49·65·66쪽이 90% 미만이며 최저 58.25212%다. 기대값을 갱신하지 않는다.

`stage3390`의 같은 HWP 재인쇄도 49쪽의 같은 정렬을 보였다. 원본과 새 대조군의
EQEDIT 바이트가 같은 혼합 EQALIGN을 대조했다. 폭 교환, 번호 범주 비트,
DocInfo 교환, 저장 LineSeg 플래그, 개체 레코드 교환, 고유 z-order는 원인이 아니었다.
65개 정상 수식을 함께 둔 출력도 정상 정렬이므로 단순 개수 한계로 판정하지 않는다.

`stage3405/3408/3411`의 원본 레코드를 보존한 최소 대조는 다음을 재현했다.

| 함께 넣은 식 | 혼합 EQALIGN 두 번째 행 y 글자의 x(CSS px) |
| --- | ---: |
| 정상 MATRIX·PMATRIX·DMATRIX | 111.36014 |
| 인자 없는 EQALIGN 또는 PILE | 111.36014 |
| 정상 PILE 또는 & 없는 EQALIGN | 111.36014 |
| 인자 없는 MATRIX | 76.02548 |
| MATRIX{} | 76.02548 |

MATRIX를 혼합 EQALIGN 뒤에 넣어도 앞쪽 수식의 정렬이 달라졌다.
이는 전체 카탈로그에서 다른 수식의 한컴 Print 출력이 문맥에 따라 달라지는 실행 증거다.
일반 EQALIGN 배치를 무조건 왼쪽 정렬하는 수정의 근거로 사용하지 않는다.
65·66쪽의 중첩 구조 차이도 별도로 남아 있으며, 이 발견으로 원본의 일치나 회귀
적격성을 통과 처리하지 않는다. 원본·각 파생 입력·MCP job·실제 Print 모드·PDF 해시는
각 stage의 ignored output receipt에 있다. 정상 대조군 통과를 원본의 통과로 바꾸지 않는다.
