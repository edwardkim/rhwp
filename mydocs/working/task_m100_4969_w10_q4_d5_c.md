## 결론

Q4-D의 bounded HWP5 세로 표 셀 구현은 correctness, fail-closed 경계, 성능 정정, Native Skia fallback,
Docker/Node WASM, Studio actual CanvasKit 및 full nextest를 통과했다. D5 정정 뒤 9-process Rust 계측은 반복
source 준비 병목을 warm layout 약 598.64배, layer build 약 339.16배 줄였고, 최종 병합 head의 1회 canary도
같은 구조·resource·JSON/replay hash를 유지했다.

그러나 계획이 최종 `qualified-bounded-subset`의 hard gate로 지정한 same-tree causal WASM A/B size 비교는
완성하지 못했다. Q4-D 제품 checkpoint를 최신 tree에서 역적용하는 첫 단계가 문서와 Studio E2E에 충돌했고,
계획은 충돌 강제 해소와 과거 절대값 대체를 모두 금지한다. 따라서 구현 오류나 미해결 회귀 때문이 아니라
**인과적 WASM 크기 증적 미완료** 때문에 최종 분류는 `blocked`다.

이 결과를 `qualified-bounded-subset`으로 올리거나 Q4-E로 넘어가려면 메인테이너가 별도 수정 계획에서 causal
size hard gate의 충족 방법을 다시 정해야 한다. 현재 결과만으로 hard gate를 사후 완화하지 않는다.

## 2. 성능 정정과 최종 canary

D5-B 최초 계측이 드러낸 병목은 CanvasKit `drawGlyphs`가 아니라 같은 2.52 MiB exact source를 매 layout과
layer publication에서 다시 해시·parse·copy한 것이었다. registry 진입 시 immutable source identity를 한 번
준비하고, 인증된 `Arc`와 face/resource metadata를 layout→paint에 전달하도록 정정했다.

9-process p50 기준 결과는 다음과 같다.

이번에 제거한 반복 source 준비 병목과 구분한다.

## 3. WASM 크기 판정

현재 최종 head의 표준 Docker WASM은 9,894,929 bytes, SHA-256
`d7e4b1198ac17737aa6d423bcdb4ffe35e6083dfda02338d9bffc3503e590aee`다. 이는 현재 산출물의 절대 검증값일
뿐 Q4-D의 인과 delta가 아니다.

짝지은 A축을 만들기 위해 최신 tree의 disposable worktree에서 여섯 Q4-D 제품 checkpoint를 최신 것부터
역적용했다. 첫 `b1a33b6fc`부터 계획·결과 문서와 Studio #4969 E2E가 충돌했다. 계획에 따라 충돌을 강제로
풀지 않았고, revert를 abort한 뒤 worktree를 제거했다. 과거 D4 WASM 절대값도 대체값으로 사용하지 않았다.
따라서 causal size 상태는 `causal-size-unavailable`이며 `blocked` 분류의 유일한 미충족 hard gate다.
