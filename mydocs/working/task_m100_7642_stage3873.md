# #7642 본문 밖 용지 고정 표의 흐름 예약 보정

Issue: #7642

## 선행 분석과 독립 기대값

[앞 단계](task_m100_7642_stage3868.md)에서 #1950 원본과 독립 한컴 PDF 두 파일을
대조하고 Native/fresh WASM 모두의 1쪽→2쪽 회귀를 확인했다. 이슈·원 PR #1991과
통합 #1998은 탭 슬롯 단위를 다룬다. 그 수정을 유지하며, 현재 원본의 쪽수 회귀를
다른 변환 문서의 과거 빈 페이지 문제나 render-diff 오탐으로 분류하지 않는다.

`stage3869-issue1950-flow-trace/`의 실제 실행에서는 첫 문단 뒤 누적 높이가 base와
후보 모두 약 94.0px다. 첫 문단의 저장 줄은 1200+600 HWPUNIT이며 다음 문단은
1800에서 시작한다. 독립 PDF와 paint에서도 제목·다음 줄은 이 저장 줄 소속을 따른다.
본문 하단 밖의 `- 581-35 -` 표가 제목 문단에 달려 있는데, 예약은 그 표의 본체와
아래 바깥여백 4252 HWPUNIT를 본문에 더한다. 이는 실제 본문 점유와 다르다.
후보에서 원본 표 호스트 줄간격 500 HWPUNIT가 보존되면서 잘못된 누적량이 페이지
경계를 넘었고, 원래 첫 쪽에 속하는 `2 - 48` 문단이 둘째 쪽으로 밀렸다.

## 공통 규칙과 적용 범위

용지 기준 TopAndBottom 표의 **여백을 포함한 외곽 상자 전체가 본문 세로 영역 밖**에
있으면 본문을 배제할 띠가 없다. 표는 용지의 실제 원점에 보존하고 호스트 글줄만
본문 흐름에 계상한다. 본문 안에 있거나 경계를 걸치는 표·TAC·문단/쪽 기준 표는
이 판정을 적용하지 않는다. 캡션의 점유 경계는 이 변경에서 확인하지 않아 제외한다.
문서 ID·쪽수·여백 수치·한컴 제품으로 조건을 만들지 않는다.

## 생산과 소비 경로

- 측정: `MeasuredTable.total_height`와 선언 높이의 최댓값을 실제 표 높이의 보수적
  경계로 사용한다. 기존 본문·용지 좌표계는 `TypesetState::inline_flow_input`에서 읽는다.
- 원점: 기존 paint의 `absolute_table_vertical_geometry`가 계산하는 같은 정렬·오프셋·
  바깥여백 식으로 외곽 상자가 본문과 만나는지 확인한다.
- 확정: `controls::prepare_table_control` → `uses_decoration_placement`에서 분기를
  선택하고, 기존 `place_decoration_table`이 표를 방출한다. 호스트 글줄은 기존
  `place_decoration_host_text`가 한 번 방출·소비한다.
- 실제 paint: 용지 기준은 `table_layout::compute_table_y_position`의 동일 원점 helper를
  소비하며 문단 기준 push/clamp를 적용하지 않는다. 표 위치나 원본 줄간격을 바꾸지 않는다.

기존의 일반 흐름 분기가 표 본체·바깥여백을 호스트의 누적 높이에 더하는 일을 막는다.
출력을 숨기거나 최종 좌표를 clamp하지 않는다. 글자가 보이는지와 개체의 흐름 참여를
분리하며, 같은 호스트의 다른 정상 흐름 개체는 기존 경로를 유지한다.

## 검증 계획과 현재 한계

이 문서 작성 시 새 코드의 빌드·시각 검증은 아직 미완료다. 먼저 #1950 원본의
Native/fresh WASM 전체 쪽수·내용 보존·TSV·review/overlay를 확인한다. 본문 안과
경계에 걸치는 고정 표, 기존 장식 표·일반 표 경로를 대조하고 원래 작업 범위도 유지한다.
전쪽 90% 이상과 직접 판독을 확인하기 전에는 새 실물 배치 회귀를 추가하거나 골든을
갱신하지 않는다. 기존 1쪽 기대값을 그대로 유지하고 검출 여부를 재검증한다.

`cargo fmt --all`은 완료했다. 기존 `table_partial.rs`의 조건식 한 곳도 줄바꿈만
정리했으며 그 형식 변경은 동작 변경과 구분한다. 작업 중 미검증 상태는 PR 제출 허가가
아니다. 승인된 전체 범위의 필수 보정·검증을 완료하기 전에는 PR을 생성하지 않는다.
