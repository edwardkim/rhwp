## 별도 글꼴·래스터 진단

Windows `HDOTUM.TTF`는 기준 PDF의 한컴돋움 72개 글자 모두의 윤곽, fpgm/prep/cvt와 해당 쪽 616개 glyph occurrence의 명령이 일치했다. Linux 설치본은 윤곽 61/72와 일치하고 프로그램도 달랐다. 그러나 같은 Native code의 한 페이지 글꼴 공급 실험은 `98.08909 → 98.08674`로 점수를 개선하지 못했다. 따라서 글꼴 버전 차이를 해당 하락의 해결책으로 보고하지 않는다. Windows 휴먼명조 파일은 Linux 설치본과 byte-identical이다. 시스템 폰트 변경·설치나 폰트 파일 커밋은 하지 않았다.

별도 CanvasKit 진단의 regular fill / StrokeAndFill / fill 뒤 stroke 및 hinting None/Slight/Normal/Full도 대조했다. 합성 방식 하나를 추정해 실제 렌더러를 다시 변경하지 않았다. PDF의 Poppler thinlinemode shape/none은 시험지 해당 텍스트 영역에서 같은 결과였다. MuPDF와는 래스터 농도 차이가 있으나 기준 rasterizer·허용치·마스크는 바꾸지 않았다.
