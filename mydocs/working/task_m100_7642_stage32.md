# 이슈 #7642 — 미주 사이 간격의 소유와 물리 높이 예약

시작 커밋: `230222e08`(Stage31 세대 전달 구현). 회귀 실패는 모두 현재 브랜치에서 보정한다.
사용자의 이번 작업 지시는 기존 미달 입력의 별도 이슈 이관 절차보다 우선한다.
이번 검증의 110개 실패를 제거·이관하지 않고 원본 입력과 검사를 유지해 보정한다.

## 입력·독립 근거와 위반된 계약

대상은 실제 생성본 `samples/3-11월_실전_통합_2022.hwpx`와 그 한컴 2024 Print다.
17쪽 2024 조판 직접 비교도 30.90632%이며, 최초 큰 차이는 15쪽 단 경계에서 보인다.
미주 사이 간격은 직전 미주의 완성된 마지막 줄이 소유하는 물리 공간이다.
보이는 줄 간격을 바꾼 뒤 예산에서 같은 공간을 누락하면 다음 문항을 일찍 수용한다.

현재 `prepare_endnote_emit → apply_endnote_render_tail_spacing`은 직전 줄의
간격을 452에서 1984 HWPUNIT로 늘린다. 그러나 분할 누계는 종전 전진을 유지한다.
15쪽 두 경계에서 각각 약 20.427px가 빠져 문단 696의 누계 원점은 905.1,
실제 layout 원점은 945.9가 된다. 실제 끝은 본문 높이 1001.6을 넘는다.
이 값은 진단 관측이며 문서 ID·절대 좌표를 구현 조건이나 회귀 기대값에 사용하지 않는다.
`nov2022-p15-common-origin-divergence.json`과 debug log로 최초 차이와 소비를 연결했다.

원본 HWPX의 해당 미주 마지막 줄 저장 vpos는 20964다. 독립 한컴 2024 Save job
`dedf4679-c2df-4b76-bdd5-a679e364ca9c`의 정상 HWP는 같은 줄에 0 리셋을 기록했다.
원본 HWP 대조군도 0이다. Print는 이 줄을 다음 단에 배치한다. `ir-diff --summary`의
0건만으로 미주 저장 메타데이터까지 같다고 추정하지 않고 실제 원본 IR을 읽었다.
독립 저장본을 원본 개선으로 바꾸어 보고하지 않으며 기존 원본·Print 기준을 유지한다.

## 생산·측정·배치와 반례

`미주 모양의 최소 간격 + 기존 마지막 줄 간격 → 같은 현재 단의 완성된 tail 소유 확인 →
실제 줄 사본의 새 간격과 증가분 → 누적 예약·다음 미주 fit → 최종 같은 줄·다음 문항 원점`
을 연결한다. 저장 전진에도 같은 증가분이 포함되는 경로의 중복 계상을 확인한다.
현재 단에서 완성된 마지막 줄만 공간을 예약한다. 앞 단의 tail, 미완성 조각, 이미 충분한
간격, 미주 사이 0인 경계에는 새 예약을 더하지 않는다. 이월 뒤 기존 tail 간격을 새 단에
다시 청구하지 않는다. 수용 불가능한 마지막 줄은 내용 컷으로 이월하며 가리지 않는다.

Native 대상 15·17쪽과 원본 HWP 2020 대조를 먼저 수행하고 소유·내용 누락·중복을
직접 판독한다. 이후 관련 전쪽 Native/fresh WASM에서 90% 이상과 확대 판독을 충족한
범위의 회귀를 관계형으로 바꾼다. 테스트·golden·래칫 허용치부터 수정하지 않는다.


## 구현 연결과 검증 시작

상태 명령을 `apply_endnote_tail_spacing`으로 바꾸었다. 원문 간격과 새 간격의
차이, 완성된 마지막 줄의 현재 단 소유를 같은 곳에서 계산해 출력 줄 사본과
누적 높이에 반영한다. 뒤 미주의 저장 좌표는 원문 근거로 유지하며, 물리 간격의 추가 예약과 별개로
재해석하지 않는다. 앞 단·미완성 조각·빈 줄 메타데이터 누락은
현재 단에 예약하지 않는다. 값의 생산·측정·배치가 공통 공간을 소비하게 했다.
Native 새 빌드와 영향 쪽 Print 대조로 이 변경의 실제 적합성을 확인한다.

Stage31 fresh WASM wrapper는 exit 0, 총 15분 03초에 완료됐다. pkg와 Studio
public의 JS·WASM SHA-256도 각각 일치했다. 그 bundle은 `230222e08`의 세대 API와
Stage30 근호를 포함하며 지금 추가한 미주 간격 보정은 포함하지 않는다. 별도
`generation-fresh-wasm-package/`로 고정하고 실제 WASM 검증을 시작했다. 이후
간격 보정을 이 이전 bundle로 검증했다고 보고하지 않는다.

통과로 세지 않는다. 이 실행은 미주 첫 보정 코드에 대응한다. 기존 테스트·기대값은
그대로 두었으며 모든 실패를 현재 브랜치에서 계속 보정한다.

## 저장 좌표를 유지한 보정의 결과

두 번째 바이너리 SHA-256은
`c7b47dbf10ce98ec828fbfcb7af41a402d95631a254573075c0d4d6043932e16`이다.
build와 Native Clippy는 각각 exit 0이다. 대상 HWPX의 15쪽 63.57586%,
17쪽 44.09679%, HWP 대조군의 최저 95.73324%로 첫 보정과 같은 점수를 보였다.
출력 간격 예약은 수정됐지만 전체 분할 결함은 미충족이며, 회귀 기대값은 변경하지 않았다.
`endnote-tail-spacing-unmodified-vpos-focused-native/results.json`에 두 입력·기준 PDF의
해시, 세대, 명령과 결과를 보존했다. 최신 17쪽 review PNG도 사용자에게 표시했다.

추가 진단에서 문단 696의 누계 원점은 실제 원점과 같은 945.9가 됐다.
그러나 내용 높이 70.5와 전진 76.5가 잔여 55.6보다 큰 상태에서 전체 문단이 수용됐다.

전체 수용을 허용한다. 뒤 문단의 물리 점유·현재 단 경계를 대조하는 다음 단계가 필요하다.
진단의 18.0 전진은 한 줄 후보 측정이며 전체 문단의 76.5 전진과 구분한다.
측정 함수 자체가 전체 문단을 한 줄로 잘못 해석한다고 단정하지 않는다.

Stage31에서 생성한 Studio JS의 `setHangul2024Compat` export도 함께 보존한다.
이는 미주 보정 전 bundle이며 최종 fresh WASM 재빌드가 아직 필요하다.
