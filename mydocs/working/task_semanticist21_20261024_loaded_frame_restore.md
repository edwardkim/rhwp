# 로드 조판 상태 복원과 재조판 계보의 수명

## 문제와 독립 근거

현재 소스는 `291d189552`, 제품 증거는 Native176/fresh WASM049다. 이전 단계의
원본 전쪽 검증·완료 프레임 새 회귀와 편집 저장본의 실패를 구분한다.

- 원본 HWP/HWPX는 각각 115쪽이며 Native/fresh 전쪽 최저 90% 이상이다.
- 같은 원본에 56자를 넣었다가 삭제하면 표 JSON·구역 모델·DocInfo·저장 캐시 유효성
  상태가 원래와 같아진다. 그러나 live의 본문 소속과 HWP 저장 결과는 원본과 다르다.
- 같은 문서 모델을 새 파생 상태로 구성하면 양쪽 모두 원본 115쪽 내용과 일치한다.
  새 한컴 Print도 115쪽이다. HWP 재열기는 현재 116쪽이고 저장 vpos 3473개가 달라진다.
- 2817은 양쪽 구역·DocInfo·dirty/source-vpos guard의 복원을 확인했다. 실제 5줄로
  늘어난 중간 상태의 구역은 원본과 다르다. 전체 지문은 약 22ms이므로 입력마다
  반복해서 계산하지 않는다. 이 진단은 정식 회귀나 시각 gate의 대체물이 아니다.

원 계약은 `93144f844a`의 renderer 소유 계보, `7e3be0a3fb`의 같은 수직 프레임 보존,
#4167의 일반 타이핑 시 owner 전체 캐시 재검사 방지다. 실제 소비는
`text_reflowed_tables → compute_render_normalized의 원본/투영 표 등록 → 줄 컷과
행 프레임 선택 → HWP 저장 프레임 materialization`으로 연결된다. 수직 줄의 증감이
취소된 뒤에도 계보가 영구히 남으면 같은 원본에 두 가지 배치를 적용한다.

## 보정 규칙

로드 픽스업·첫 paginate가 끝난 상태의 구역·DocInfo와 저장 캐시 유효성을 한 번
기록한다. 원문 텍스트나 특정 문서 번호·좌표가 아닌 기존 모델 digest 계약을 재사용한다.
단순한 문자 수나 수직 높이의 일치만으로 원본 복원을 승인하지 않는다.

셀 텍스트 편집은 상수 비용의 문자 증감 힌트를 갱신한다. 문자를 줄이거나 교체해
로드 당시 문자 총량으로 돌아온 후보이고 실제 재조판 표식이 있을 때만 전체 구역·
DocInfo·저장 캐시 guard를 대조한다. 힌트는 해제 근거가 아니며 일치한 지문이 근거다.
스냅샷의 전체 파생 상태 재구성에서는 문자 증감 힌트를 다시 동기화한다.

정확히 복원된 구역의 역사적 재조판 표식만 해제한다. 셀 유닛·측정 캐시와 정규화
투영을 함께 무효화하고 현재 source에서 다시 만든다. 전체 모델을 교체하거나 저장
vpos를 임의로 덮어쓰지 않는다. 다른 편집·글꼴/스타일 변경이 남아 있으면 유지한다.

## 검증

실제 공개 API의 삽입·삭제·deferred·저장/재열기와 같은 source Print 대조를 묶는다.
원본·기존 55/200자 저장본·정상 대조군과 #7114/#7418/#7902/#7095 및 기존 실패를
함께 확인한다. 계획을 고정한 시점에는 구현 전이며 결과가 나오기 전에 완료나 새 회귀 자격을
판정하지 않는다. 정식 회귀 추가·변경은 동일 입력의 전쪽 Native/fresh 90%와 확대
판독 뒤에 한다. 기존 기대값은 바꾸지 않는다.

## Native177 원인 검증과 상속 계보 보존 보완

로드 완료 시 구역·DocInfo·저장 캐시 유효성 digest를 기록하고, 문자 증감 힌트를
갱신한다. 힌트가 로드 문자 총량으로 돌아온 삭제/교체이고 재조판 표식이 있을 때만
원본 동등성을 대조한다. 같은 source로 돌아오면 캐시와 투영을 무효화하고 구역을
재구성한다. 입력 IR·좌표·저장 vpos를 임의로 교체하지 않는다.

Native177은 종료 0·250.72초이며 실제 공개 API 14종 모두 live/재열기 쪽별 내용이
일치했다(2820). 문제의 HWP 115→116쪽과 HWPX 6쪽 소속 차이가 해소됐고, 삽입한
56자를 삭제한 양쪽 live는 원본 쪽별 내용과도 일치한다. 새 저장본의 한컴 Print를
다시 요청했다(2823). 아직 새 head의 전쪽 시각 완료나 정식 회귀 추가로 판정하지 않는다.

구현 검토에서 원래 문서로 복원한 사실과 별개로 복사·분할·스냅샷에서 명시적으로
상속한 admission 계보는 보존해야 함을 확인했다. Native178은 표식 집합이 수명과
원인을 함께 소유하도록 보완한다. 일반 insert/extend는 상속 계보로 기록하고, 셀
텍스트 편집이 새로 만든 표식만 복원 권한을 갖는다. remove/clear는 두 수명을 함께
종료하고, 알 수 없는 기존 표식에 셀 텍스트 편집을 더해도 복원 권한을 승격하지 않는다.

원 해결 PR #6666의 본문·검토·통합 comment를 읽고 실제 통합 #6694, 구현
`93144f844a`, merge `b6b9384ed9`를 대조했다(2824/2825). source IR에 렌더러
표식을 넣지 않고 live Box 수명·snapshot/undo/clone/split/join을 함께 보존하는 계약이다.
#4167 원 PR #4249와 실제 통합 #4265(`59b31e5ce1`)도 대조했다(2826/2827).
일반 타이핑/IME에서 셀 전체 재구성을 하지 않는 계약을 유지하며, 원본 지문 22ms를
매 글자 입력에 추가하지 않는다. Native178에서 API·기존 경계·수명·성능 검사를 묶는다.


## Native178 전쪽·live 검증과 원본 raw 봉인 복원

Native178은 14개 실제 API 시나리오의 live/저장 재열기 내용이 모두 일치했다(2830).
같은 저장 바이트의 새 한컴 Print는 양쪽 115쪽이다(2823). 원본·복원 저장본 네 입력
460쪽 Native 최저 raw는 95.77381%이며 쪽수도 모두 일치했다(2834). 이 결과는
정적 저장본 검증이며 실제 편집 세션의 PNG와 혼동하지 않는다.

실제 live Print PNG를 별도로 출력하니 HWPX는 115쪽 모두 정적 재열기 PNG와 바이트가
같지만 HWP는 8·15·103·104·105쪽이 달랐다(2835/2837). 원본 모델이 복원돼도
`raw_stream=None` 때문에 `Document::layout_profile().session_edited`가 유지되는
소비 경로를 확인했다. 원래 봉인된 raw 캐시의 소유권을 기존 무효화 지점에서 옮겨
보존하고, 전체 모델·DocInfo·저장 guard의 복원과 기존 raw 봉인의 모델/바이트 지문을
모두 확인한 경우에만 되돌린다. 재생성한 바이트나 임의 모델 표식으로 봉인을 대체하지 않는다.

매 입력에서 전체 구역 지문을 계산하지 않도록 편집 문단 텍스트의 BLAKE3를 XOR로
갱신한다. 문자 총량과 이 후보 힌트가 함께 복원될 때만 전체 모델 대조를 수행한다.
XOR는 순서·소유의 입증 수단이 아니며 최종 모델 대조를 생략하지 않는다. 줄 프레임
복원과 캐시 복원을 구분해, 같은 줄의 IME·일반 타이핑까지 `cellFlowChanged`로
승격하거나 셀 유닛 전체를 무효화하지 않는다. 캐시 복원 시 과거 focused PNG/tree
patch는 재사용하지 않는다. 실제 렌더는 현재 layout profile을 다시 소비한다.

Native179는 기존 14종에 deferred 복원·두 단계 삭제·같은 길이 IME 복원·같은 줄
삽입 취소를 형식별로 추가해 22종을 검증한다. 빌드와 후속 검증이 완료되기 전에는
이 보정의 시각 완료나 새로운 회귀 자격을 판정하지 않는다.

102쪽 표 아래 선은 95.77381% 통과와 별개로 직접 판독에서 차이가 남는다. 실제
호출의 8행×2열 자식 표 첫 컷은 0..1행이며 시작·끝 내부 컷은 없다. 현재 행 높이
37.29333px와 저장 첫 프레임 32.74667px를 구분한다(2841). 다음 쪽은 1..8행으로
이어지므로 빈 첫 행을 추가 소비하는 방식으로 보정하지 않는다. 이 보정은 계속 진행한다.
