# 증적 보고서 재검토 보정

Issue: #7449 · PR: #8178

## 원인과 보정 범위

검토 기준은 `8a478c7562354da86e3a1797c7b288bc656fdb74`다. 사용자가 재검토에서 확인한 네 항목의
보정을 요청했다. 기존 브랜치와 PR에서 결과 검증·관련 테스트·문서만 보정한다.

1. PNG 서명만 검사하여 잘린 파일도 verified가 됐다. 청크 구조·CRC·압축 스캔라인을 검사해 손상과 불완전을 거부한다.
2. 전체 error 필드와 pass가 모순되어도 성공했다. 오류가 있는 pass를 incomplete로 처리한다.
3. 후보 inventory의 해시만 맞으면 필수 파일이 없어도 성공했다. 실행기와 보고서가 같은 필수 파일 목록을 사용한다.
4. CodeQL #283은 테스트의 대소문자 구분 태그 정규식을 지적했다. 대소문자·혼합 태그를 검사하고 실제 HTML DOM에서도 능동 콘텐츠가 없는지 확인한다.

새 경계 검사를 보정 전 코드에서 실행해 실패 이유를 확인한 뒤 구현한다. 기존 32개 계약과 함께
재실행하며, 브라우저 검사는 보고서 HTML만 대상으로 한다. 합성 입력을 실제 확장 E2E 증거로 사용하지 않는다.
결과는 실행 뒤 아래에 기록한다.

## 실행 결과

- 새 경계 4개를 이전 코드에 먼저 적용: 기존 32 PASS / 새 4 FAIL / SKIP 0. 실패 원인은 각 결함의 assertion이었다.
- 보정 후 기존·신규 계약과 PNG 정상/오류 대조군: Node 24.19.0 및 CI와 같은 Node 22.23.4에서 각각 39 PASS / 0 FAIL / 0 SKIP.
- `RHWP_REPORT_BROWSER=/usr/bin/chromium node --test rhwp-chrome/e2e/report-browser.test.mjs`: 1 PASS / 0 FAIL / 0 SKIP, Chromium 151.
  공유/비공개 HTML의 script·이벤트 속성·능동 요소 없음, 코드 실행 없음, 정상 스크린샷 통과와 1200px/390px overflow 없음 확인.
- PNG는 Node 표준 라이브러리만 사용한다. 정상 팔레트·Adam7, CRC 손상, 잘린 파일, 잘못된 zlib·필터·스캔라인, 압축 해제 크기 제한을 검사했다.
- 후보 필수 파일 4개 각각의 누락과 재계산한 해시를 입력해 incomplete를 확인했다. 비어 있지 않은 오류 필드와 pass의 모순도 incomplete로 보존했다.
- 합성 5개 예제를 새로 생성해 pass/fail/error/not-run/incomplete 의미가 유지됨을 확인했다.
- CodeQL #283의 대소문자 구분 assertion을 보정하고 음성 대조와 DOM 검사를 추가했다. 실제 원격 경고 해제 여부는 push 뒤 별도 확인한다.
- 실제 확장 전체 E2E·스토어·문서 품질·사용자 수동 판정은 이번 계약/HTML 검사로 검증됐다고 기록하지 않는다.
