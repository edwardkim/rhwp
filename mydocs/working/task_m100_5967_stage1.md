### 왜 색 플래그가 자산마다 정확히 2바이트인가

코퍼스의 중첩 CFB 는 전건 엔트리 4개다 — Root Entry + `Contents` + `\x02OlePres000` +
`OOXMLChartContents`. CFB 이름 정렬(길이 먼저)로 midpoint BST 를 세우면 트리 root 는
`\x02OlePres000`(깊이 0), 좌우 자식이 `Contents`·`OOXMLChartContents`(깊이 1)다. `max_depth = 1`
이므로 자식 둘만 red 로 바뀐다 → 엔트리 1·3 의 `+0x43` 이 `01` → `00`, 2바이트.

### 왜 FAT 꼬리 값 `0x00` 이 미할당 슬롯을 유일하게 지목하는가

FAT 슬롯 값 `0` 은 "이 섹터 다음이 0번 섹터" 라는 뜻이다. 섹터 0 은 언제나 사슬의 **머리**
(여기서는 디렉터리 사슬 머리, `FAT[0] = ENDOFCHAIN`)이므로 어떤 사슬의 후속도 될 수 없다.
그러므로 커밋본에서 값이 `0` 인 슬롯은 곧 미할당 슬롯이고, 종전 라이터가 출력 버퍼의 기본값
`0` 을 그대로 둔 자리다. 분류기는 이 논거로 값 판정만으로 버킷 B 를 확정한다.

### MiniFAT 버킷은 죽은 가지가 아니다

`가로막대형_..._단일시리즈제목-점추가`(304B)와 `원형대원형-계열추가`(292B) 두 건에서 MiniFAT
미사용 슬롯이 실제로 잡힌다. 나머지는 스트림이 전부 미니 컷오프(4,096) 이상이라 ministream
자체가 없다(`+64 = 0`, `+60 = ENDOFCHAIN`).

## 3. 스트림은 동일하다

이슈 본문대로, hwpx 컨테이너 안에서 다른 엔트리는 `BinData/image1.OLE` 하나뿐이고 파일 크기도
양쪽 같다. 중첩 CFB 안 스트림 3종(`Contents`·`\x02OlePres000`·`OOXMLChartContents`)의 바이트는
바뀌지 않는다. 즉 **한컴이 판정한 내용은 그대로이고, 바뀐 것은 컨테이너 살림뿐이다.**

바이트 동일성은 라이터 판에 묶인 계약이라 회복할 수 없다(되돌리기는 `mini_cfb_strict_contract`
2건을 빨갛게 만든다). 대신 라이터 판을 넘어 성립하는 두 계약을 테스트로 세운다 —
