# #7642 Stage 179 — 공백으로 구분한 수식 항의 공통 파싱

Issue: #7642

## 독립 근거와 범위

Stage 178의 독립 한컴 Print에서 `a+b OVER c+d`는 공백 없는 양쪽 식을 각각 분자·분모로 묶는다. 공백을 넣은 `a + b OVER c + d`는 앞뒤 항을 분수 밖에 둔다. 네 공백 조합과 ATOP, 명시적 그룹·연쇄 OVER의 기준이 이미 `pdf/issue7642-operand-frame-diagnostic/`에 있다. 공식 수식 사양 1.1.2.1·1.1.2.5도 공백을 항 경계로 설명한다.

현재 try_consume_infix_over_atop은 이미 수집한 마지막 EqNode와 다음 parse_element를 소비한다. 문서의 parse_element가 논리 항 대신 개별 토큰만 반환하므로 붙은 덧셈의 소속을 잃는다. 각 그룹·행렬·PILE·CASES·EQALIGN의 같은 수집 경로에 문서 항 파싱을 공급한다. 글꼴 전환을 바꿀 수 있는 임의의 중괄호 삽입은 사용하지 않는다. 공개 EqParser::new/parser::parse의 LaTeX 호환 경로는 유지한다.

`문서 tokenizer → 문서 EqParser의 항 → OVER/ATOP 수집 → 측정 flow_metrics 및 인라인/표/떠 있는 수식 LayoutBox → Native/WASM paint`를 함께 연결한다. 실제 공백, 구조 종료, 명시적 그룹, 행/칸 구분은 보존한다. RM/IT의 빈 body 전환은 바깥 글줄에 남기고, 첨자와 NOT의 단일 글자 소비는 별도 원자 경로를 사용한다. 소괄호 인자 범위도 현재 닫힘 위치를 넘지 않는다.

## 검증 순서

실제 파서 소스의 사전 검사로 공백 네 조합·ATOP·명시적 그룹·연쇄·RM/IT·첨자·NOT·행/칸 경계를 비교한다. 사전 컴파일도 기본 작업공간 target/pr-review를 사용한다. 이후 구현을 묶어서 Native로 빌드해 18쪽 대조군과 원 카탈로그 전체를 다시 산출하고 직접 확대한다. 카탈로그 18쪽의 감소는 별도로 parent baseline/Frame 소비를 추적한다. 기존 golden이나 정식 회귀의 기대값을 먼저 갱신하지 않는다. 전체 90%·fresh WASM·전체 회귀·lint·PR/CI/후속 처리는 아직 미완료다.

## Native 빌드·전체 36쪽 재산출

코드 `785c2821c7276a506b635e16e6c5b53c3daf53ce`는 고정 target의 Native 빌드를 314.63초에 종료 코드 0으로 완료했다. 소스 해시 변화는 없었다. 분수·근호·PILE 대조군 18/18쪽의 최저값은 **99.06542%**, 미달·누락·쪽수 차이는 없다. 이전에 미달이던 1·3·4쪽은 각 100%, 8쪽은 99.06542%다. 실제 새 확대 그림에서 분자·분모의 소속과 바깥 항을 대조했으며, 가장자리의 raster 차이를 완전 동일로 보고하지 않는다. 증적은 `mydocs/pr/assets/issue7642-document-terms-20261013/README.md`에 연결했다.

원 카탈로그 18/18쪽은 2·3·4쪽이 개선되었지만 **5·6·13·14·16·17·18쪽이 미달**이고 최저 40.22286%다. 마지막 17·18쪽의 문단·줄 상자 31개는 직전 두 producer에서 동일했다. 18쪽 PDF에는 DMATRIX 근호 행이 먼저 있지만 Native에서는 이전 쪽에 있어, 기존 페이지 경계 차이를 수식 자체의 세부 차이와 분리하여 추적한다. 새 변경이 이 경계 회귀를 만들었다고 판정하지 않았으며 현재 보정 대상에서 제외하지 않는다.

fresh WASM 빌드 및 두 문서 전체 TSV를 이어서 실행한다. Native 통과를 WASM 통과나 전체 branch 완료로 승격하지 않는다. 정식 golden과 회귀 기대값은 이번 단계에서 변경하지 않았다.

## 같은 코드의 fresh WASM 완료

fresh WASM은 905.05초에 종료 코드 0으로 완료했고 source 해시가 동일했다. 루트 wrapper로 만든 pkg와 Studio의 JS/WASM SHA-256은 각각 동일하다. 분수·근호·PILE의 전체 18쪽 TSV는 Native와 같은 최저 99.06542%, 미달·누락·쪽수 차이 없음이다. 같은 원문의 Native/fresh WASM PNG 18쌍이 모두 byte 동일하여 위 대표 영역의 직접 판독에 연결한다. 원 카탈로그 18쪽도 재산출했고 최저 40.22286%, 미달 5·6·13·14·16·17·18쪽으로 Native와 같다.

이는 rebase 전 코드 `785c2821c7276a506b635e16e6c5b53c3daf53ce`의 증거다. 최신 upstream 변경을 반영한 head의 검증으로 대신하지 않는다. 최신 devel 동기화·rebase 뒤 영향 범위와 의존성 변경을 검증한다. 전체 목표는 계속 미완료다.
