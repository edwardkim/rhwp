# #7642 Stage 153 — 합성 글줄의 fit 간격과 작은 TAC 도형의 앵커

Issue: #7642

## 근거와 함께 수정할 경로

Stage 152 전체 64쪽은 compat 2024에서 미달 10쪽, 최저 27.23722%다.
문단 426은 독립 Print의 21쪽 첫 제목이나 Native 20쪽 꼬리에 배치됐다.
실행 로그는 현재 높이 947.1px, 앞 간격 15.1px, 줄 높이 17.3px를 보인다.
본문 예산은 971.3px이며 앞 간격과 줄을 함께 수용할 공간이 없다.
그러나 fit 높이는 17.3px로 축소됐고 실제 배치가 앞 간격을 더해 본문을 넘었다.

원인은 `format_paragraph_for_flow`의 `vpos_metric`이다.
원본에 없는 합성 줄도 비편집 단조 줄로 분류하여 span만으로 전체 fit을 잘랐다.
합성 줄에는 독립 저장 사다리가 없으므로 span 축소를 적용하지 않는다.
`para_has_no_stored_line_segs`의 공통 분류로 실제 재조판 간격과 줄 높이를 사용한다.
뒤 문단 440의 쪽 소속까지 독립 Print와 대조하며 단순 제목 표시로 완료하지 않는다.

39쪽 문단 628~630의 TAC 타원은 크기 804×740HU로 1300HU 글줄 안에 놓인다.
저장 기준선은 1105HU다. 현재 Native의 실제 타원 상자가 글줄 안에 있는데도
텍스트 문단의 원본 앞 간격 568HU를 끊고 있었다. 가시 본문·단일 유효 저장 줄과
캡션/내부 글상자 없는 TAC 도형의 상하 기준선 점유가 그 줄 안에 포함될 때만 앵커를 잇는다.
사용하는 도형 높이는 실제 배치와 같은 `flow_height_hu`이며 기준선 비율도 공통 계약을 따른다.

## 반례와 검증

합성·편집 저장 줄, 문단 수직 정렬 변경, 세로 오프셋, 커진/회전한 개체의 상하 점유,
캡션·글상자·그룹·표·수식 등 별도 높이 경로는 작은 TAC 텍스트 줄의 앵커로 추측하지 않는다.
기존 진짜 저장 줄의 span 판정은 유지하며 새 합성 줄의 간격을 잘라 fit시키지 않는다.

한 번의 Native 빌드로 대조군 9쪽, 전체 sample16 64쪽을 재검증한다.
20~24쪽 제목·본문의 소속과 39쪽 도형/텍스트/그림의 관계를 새 PNG에서 직접 확인한다.
전쪽 Native/fresh WASM 90% 및 확대 판독 전에는 새 회귀 검사와 PR 생성을 보류한다.

## 실행 결과 (2026-10-12)

Native 빌드는 종료 코드 0, 실행 전후 source 해시 일치다. 선행 9쪽은 모두 90% 이상
(최저 98.50071%)이다. 첫 실행의 탭·셀 순서 2문서는 Chrome WS 시작 대기 30초
초과로 PNG 산출에 실패했다. 각 실행의 종료를 확인한 뒤 같은 SVG·글꼴 바이트로
시작 대기 한도만 180초로 늘려 2개만 재실행했고 TSV 통과를 확인했다.
`receipt-first-attempt.json`과 재실행 명령·로그를 보존하며 환경 실패를 회귀로 세지 않는다.

Native 64/64쪽, PDF 64/64쪽을 확인했지만 전체 최저 37.23228%, 미달 11쪽
(22, 23, 24, 25, 26, 27, 35, 43, 45, 48, 49)이다. 제목 426은 21쪽에 복원됐고
뒤 문단 427도 같은 쪽 원본 위치로 이어진다. 39쪽 TAC 타원 줄도 원점/간격이 복원됐다.
그러나 원래 Print 21쪽 마지막 문단 439가 Native 22쪽 첫 문단으로 밀렸다.
실행 로그는 `cur=939.1`, `fit_h=28.7`, `avail=967.3`을 보이며 실제 본문은 971.3px다.
이 고정 4px 안전 여유 때문에 본문 안에 들어가는 줄을 다음 쪽으로 밀었다.
측정과 paint가 같은 재조판 줄 상자를 소비하는 경로의 실제 예산을 추가 확인한다.

확대 영역의 한점 리더 U+2024를 실제 Chrome CDP로 확인했다. 본문 “분석”·“설계”는
embedded 휴먼명조이고, 리더는 HCR Batang Regular다. 같은 family로 선언된
HCR Batang Bold 후보가 존재한다는 것만으로 실제 Bold 사용이라고 판정하지 않는다.
독립 Print의 보조 글꼴은 Haansoft Batang이다. 시스템에 공식 HBATANG.TTF가 등록돼 있고
U+2024는 baseline 위 244..368/1024em의 글리프다. HCR 대체의 baseline 근처 점과 다르다.
기호를 치환하거나 임의 좌표를 더하지 않고 실제 대체 글꼴 공급 경로를 보정할 근거다.

영수증·TSV·실행 로그는 ignored output의 `stage153-native-realign-build.json`,
`stage153-realign-preflight/receipt.json`, `stage153-sample16-whole-native/receipt.json`,
`stage153-flow.log`, `stage153-font-cdp-result.json`에 있다. 마지막 자료는 source SVG의
같은 CSS·글자 속성과 canonical driver의 projection/recovery를 사용한 실제 glyph 공급 진단이다.
전쪽 90%·Native/fresh WASM·확대 판독 전에는 새 회귀/기대값 변경·PR을 보류한다.
