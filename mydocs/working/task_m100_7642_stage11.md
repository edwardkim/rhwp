# 이슈 #7642 — 한컴 수식 글자와 구분자의 논리 전진폭

이전 단계: [수식 문단의 내어쓰기](task_m100_7642_stage10.md).
시작 head: `c70b06ffc`. 17쪽은 95.33926%지만 괄호/등호 및 수식 내부 간격 차이가 남는다.
전체 원본의 전수 비교와 관계형 회귀의 선행 조건을 유지한다.

## 독립 근거와 적용 범위

정상 `samples/hwpx/eq-002.hwpx`의 16개 수식만 바꾼 진단 대조군을 만들었다.
6/9/12/18pt에서 Roman E, Italic X, 명시적 작은 공백, 보통 LEFT/RIGHT 괄호를 비교한다.
오래된 크기/기준선/저장 LineSeg를 비우고 한컴 2020이 재생성한 저장본과 같은 저장본의
MCP Print를 읽는다. 실제 한컴은 `11.0.0.9136`, Print method 0 / one-up driver다.
job `c5dd6969-4a2b-4aeb-a23b-9eb6fcf0ad78`(저장)와
`fe4b18ec-9d06-44cd-ac27-92fa699e27ea`(Print)의 상태·해시는 ignored output에 있다.
수동 합성 대조군의 통과를 원본 통과로 기록하지 않는다.

재생성 논리 폭은 설치 HYhwpEQ의 hmtx(UPM 1024)를 75 HWPUNIT 격자로 반올림한
글자 전진폭과 대응한다. 작은 공백은 1/8 em이며 보통 괄호의 글리프 전진폭 밖에
추가 내부 여백을 예약하지 않는다. 9pt에서 E=600, X=675, X+작은 공백=787,
E LEFT(X` RIGHT)=2137 HWPUNIT이다. 괄호 두 개의 각 375와 문자/공백의 합과 일치한다.
여러 글자 크기에서 같은 계산을 확인한다. 이 값은 문서의 화면 px 위치가 아니다.

## 원인 경로와 보정 계획

`Equation.font_name/BaseUnit → EqLayout::for_equation → Text/Space/Paren의 논리 폭 →`
`Row의 자식 원점 → 공통 layout box → SVG/Canvas/Skia 표시`를 대조한다.
현재 HYhwpEQ 소문자 이탤릭에만 원본 전진폭을 쓰고 대문자/정체는 대체 글꼴 폭을 쓴다.
보통 괄호는 옛 Times 폭과 0.08em 내부 여백, 작은 공백은 0.17em을 추가해 저장 프레임과
표시 내용이 어긋난다. source font의 글자 메트릭과 명시 공백 계약을 공통 결과에 반영한다.
사설 글꼴 바이트/윤곽을 저장소에 추가하지 않는다. 다른 face와 큰 구분자의 별도 계약은
구분해 정상 대조군으로 확인한다. 위첨자의 추가 전진은 별도 크기·문자 대조군으로 확인하며
관측한 한 문자에만 조건을 더해 맞추지 않는다.

## 검증

먼저 같은 원본 17쪽과 같은 576dpi 영역을 다시 대조한다. 확인된 출력 보정 후에만 회귀를

PR 제출·전체 시각 개선 완료로 기록하지 않는다. TSV/JSON/로그는 ignored output에 보존한다.


## 공통 소비 지점 보정

괄호 폭을 바꾼 뒤 SVG/Canvas/Skia가 기존 `0.333em`을 다시 계산하면 오른쪽 원점이
다시 달라진다. 좌우 측정 폭을 `LayoutKind::Paren`에 보존해 이 backend들이 직접 소비하도록
했다. paint JSON에도 같은 폭을 전달하고 Studio CanvasKit의 일반 괄호 원점·기준선도 이
결과를 사용한다. 폭이 없는 옛 paint JSON은 SVG 대체 경로로 돌려 임의 재계산을 하지 않는다.
기존 golden dumper의 패턴은 새 필드를 수용하는 문법만 바꿨고 기대값은 갱신하지 않았다.

첫 stage11 진단 빌드는 남아 있는 괄호 폭 재계산을 발견해 exit 130으로 중단했다.
출력 공백 때문이 아니며 해당 source로 시각 검증을 수행하지 않았다. 소비 지점을 연결한
후 `--profile release-test`(같은 최적화, LTO 없음)의 Native 진단 빌드를 다시 시작했다.


Studio의 `./node_modules/.bin/tsc --noEmit`는 exit 0이다. 실행 로그는
`output/pr-review/issue7642/failed-inputs-20261008/stage11-studio-tsc.log`에 있다.
이는 최신 WASM이나 Studio 실제 화면의 시각 검증을 대체하지 않는다.

## 위첨자 전진의 적용·비적용 경계

6/9/12/18pt의 X와 9/18pt A/X/V/W 및 a/f/g/x 재생성에서 대문자 뒤 단일 위첨자는
글자 전진+첨자 전진에 0.15em을 예약하고 소문자는 추가 전진이 없음을 확인했다.
별도 반례에서 Roman X도 같은 대문자 간격이며 `X` 뒤 명시 공백이나 닫는 괄호 뒤에는
추가 전진이 없다. 다문자 XY는 마지막 대문자 경계에만 추가한다. 문자 이름 X를 분기하지
않고 AST의 끝 문자 종류로 적용한다. 아래첨자·복합 위아래첨자로 이 근거를 확대하지 않는다.
숫자 첨자의 논리 전진도 같은 HWPUNIT 격자를 소비해 부모 예약 폭과 실제 원점을 맞춘다.
MCP 저장본의 속성과 같은 저장본 Print에서 위치를 직접 대조하며 source/SHA/job/결과는
`font-advance-contract-counter/`의 `script-*`, `italic-*`, `boundary-*`에 보존한다.


## 연산자 간격의 독립 대조

9/18pt의 글자·숫자·괄호·분수 반례를 재생성했다. `+`/`×`는 원본 수학 글리프의
논리 전진폭에 양쪽 0.14em, `=`는 양쪽 0.21em을 예약한다. 줄 시작/끝의 바깥 여백과
앞 분수·닫는 괄호의 내부 점유 뒤 여백은 중복 예약하지 않는다. 9pt의 `1+1`은
450+675+252+450=1827, `1=1`은 450+675+378+450=1953이며 18pt에서도 같은 규칙이다.
분수 뒤 `+`의 왼쪽 여백을 생략하면 두 분수 1800+기호 675+오른쪽 126=2601,
줄 시작 `=1 over 2`는 675+오른쪽 189+분수 900=1764로 재생성 폭과 일치한다.

이 근거로 공통 Row에 glyph와 양쪽 예약 여백을 전달한다. 아직 측정하지 않은 다른
관계 기호를 같은 전진폭으로 대체하지 않는다. operator 저장 job은
`1e2f6a9e-0cf1-4a81-b0a1-316ef1fca32f`, Print job은
`924ceb1f-d875-477b-9bad-11675d40a26b`이며 모두 실제 2020 profile / 11.0.0.9136이다.
Print method 0 / one-up 실행 증거와 글리프 원점은 ignored `operator-*`에 보존했다.
현재 이 추가 보정의 Native 빌드가 진행 중이고 수정 후 시각 판정은 아직이다.


## 남은 첨자 경계와 기준선 보정

위첨자·아래첨자 뒤의 이항 연산자 앞은 0.20em이며 일반 글자 뒤 0.14em과 다르다.
9pt `a^2+a`는 첨자식 750 + 뒤 글자 450 + 기호 675 + 앞 180 + 뒤 126 = 2181이고,
아래첨자와 18pt에서도 같은 규칙이다. 닫는 괄호는 기존 여백 비예약 경계를 유지한다.
명시 작은 공백은 자기 전진을 보존한다. 두 원본 RHS 스크립트의 한컴 재생성 폭은
각각 8247/10995 HWPUNIT으로 원본과 같아 이 경계의 독립 대조군도 확보했다.

위첨자의 세로 기준선은 공개 표시 글꼴의 MATH 상수를 그대로 적용하던 경로에서 차이가
남는다. 기존 한컴 글자/위첨자 논리 프레임의 높이·기준선을 재사용해 단일 글자 줄의
위첨자 기준선 거리를 계산한다. 다른 크기를 추정하거나 원본의 y 좌표를 보정하지 않는다.
알려진 source face, 지원 프레임과 기본 첨자 크기에만 적용하고 복합 본체·크기 변경은
기존 구조 계약을 유지한다. 프레임은 출력 DPI에 맞춰 물리 단위로 변환한다.

보통/큰 괄호의 판정도 측정한 source 논리 높이를 사용한다. 공개 글꼴의 빈 높이 차이로
일반 괄호가 큰 path로 바뀌지 않도록 구분자 높이와 표시 방식을 공통 Paren 결과에 보존해
SVG/Canvas/Skia/Studio가 소비한다. 최신 Studio tsc는 exit 0이고 Native lint 확인 중이다.
단순 전체 점수와 최종 확대 판독의 통과 여부는 새 빌드 재출력 뒤 별도로 기록한다.

**미충족**이다. 수치 통과를 완료로 기록하지 않는다. 명령 연산자가 공통 여백 계산에서

보존했고 90% 미만으로 재검토가 필요하다. 전체 검증 통과를 뜻하지 않는다.

fresh WASM은 턴 중단으로 종료된 프로세스가 없음을 확인한 뒤 공용 절대 target

사용하며 Cargo를 병렬 실행하지 않는다. 최종 exit와 최신 WASM 시각 결과는 아직 미검증이다.
