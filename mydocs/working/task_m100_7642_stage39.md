# 이슈 #7642 — 미주 묶음 보정의 전쪽 교차 검증

생산 소스는 `f316ad1e66868ca9871502d0f9439886e21aebf5`다. Stage38 Native
바이너리와 커밋의 24개 소스 해시 및 Rust diff 해시가 일치함을 확인했다.
검사 제거·baseline 완화 없이 현재 브랜치에서 원본 출력 보정을 계속한다.

## 실행 순서

1. 진행 중인 새 소스의 focused Native 13·14·15·17·19·20쪽, HWP/2020 정상
   대조와 간격 없는 HWPX 14·15쪽의 최종 결과를 확인한다. 새 review PNG에서
   변경된 단 소속과 앞뒤 내용의 누락·중복·수식 모양·간격을 직접 판독한다.
2. 같은 frozen Native로 원본 2022 HWPX와 2024 Print의 전체 21쪽을 비교한다.
   미달 쪽·최저값·누락·쪽수를 TSV와 provenance에 기록한다.
3. 공용 target에서 root WASM wrapper로 새 web package를 빌드하고 소스 해시가
   빌드 전후 동일한지 확인한다. frozen package와 pkg/Studio JS·WASM의 해시를
   대조한다. 이 빌드가 종료하기 전에는 Rust 소스를 다시 수정하지 않는다.
4. 새 package로 동일한 원본·Print·조판 세대의 전체 WASM TSV를 산출한다.
   기존 Stage37 source `94ebd9c0a`의 실행은 변경 전 대조로만 사용한다.
5. 원본의 관련 모든 페이지 90% 이상 및 직접 확대 판독을 먼저 충족한 뒤 필요한
   회귀 검사를 소유·순서·보존·포함·겹침 관계로 바꾸고 실제 실행으로 통과를
   확인한다. 현재 전체 전환은 미완료이고 #1139 파일에 고정 px 검사가 남아 있다.
6. 요청 52개 원본과 나머지 실패 입력을 보정·검증한다. #1139의 직접 선언 입력
   18개 중 요청 목록 밖의 3개도 전체 파일 전환 범위에서 확인한다. 단순 숫자
   검색 결과를 관계형 전환 완료 판정으로 사용하지 않는다.

명령·해시·로그·TSV·중간 JSON·nextrun은 ignored output에 보존한다. 종료된
sweep의 재생성 가능한 대용량 SVG는 실행 완료와 사용 중 아님을 확인하고 해시
기록 후 정리한다. 입력·Print PDF·frozen 빌드·판독 PNG·TSV·JSON은 유지한다.
대표 PNG는 새 head의 실제 출력으로 생성해 표시한다. 전체 Rust 회귀·필수 lint·
fresh WASM·시각 검증 후 PR/CI/merge를 진행하며, code CI 종료 뒤 PR review와
오늘할일 trailing 기록을 커밋하는 기존 순서를 따른다.

## 현재 관측값

새 소스의 HWPX/2024 focused Native 6쪽은 exit 0, 선택 쪽 최저 95.75481%다.
13·14·15·17쪽은 98.03330 / 96.85306 / 95.75481 / 97.23218%,
19·20쪽은 97.67399 / 97.09636%다. 19·20쪽은 변경 전 62.18357 / 61.77429%에서
개선됐다. 전체 쪽수는 21/21이나 전쪽 측정과 새 fresh WASM 검증은 아직 진행 중이다.
새 19·20쪽 review PNG를 실제로 열고 사용자에게 표시했다. 선택 쪽 gate 통과를
전쪽 완료나 확대 판독 완료로 바꾸지 않는다.

20쪽 확대 판독에서 실제 수식 결함을 확인했다. 원본 본문 문단 404의 미주 문단
22, 가상 문단 951의 식은 `a \`not= \`0`이다. 한컴 Print의 `a ≠ 0`과 달리 RHWP는
등호와 그 위의 짧은 가로선으로 출력한다. `symbols.rs`는 `not`를 `StrikeThrough`로
해석하지만 SVG·Canvas·Skia의 장식 그리기는 해당 종류를 일반 가로선 fallback으로
처리한다. 장식 layout도 위쪽 장식의 높이를 일괄 추가한다. 생산된 장식 상자와
각 backend의 소비를 함께 보정하고 독립 Print에서 빗금·기준선·본문 간격을 다시
확인해야 한다. 97% 통과로 이 의미 차이를 면제하거나 회귀 기대값을 갱신하지 않는다.
원본 script·소유와 동일 영역의 확대 PNG/해시는 ignored output에 보존했다.

변경 전 source `94ebd9c0a`의 전쪽 fresh WASM과 HWP/2020 Native 대조도 종료됐다.
둘 다 21/21 측정, 누락 0, 19·20쪽 미달이며 각각 exit 1이다. 변경 전 WASM은
Native와 같은 62.18357 / 61.77429%, HWP/2020은 62.24026 / 61.94278%다.
이 결과는 새 소스의 통과 증거가 아니다. 종료된 실행의 재생성 가능한 SVG는
해시 기록 후 정리하고 판독 PNG·TSV·JSON·Print·frozen 빌드는 보존한다.

## 전쪽 Native 복구와 새 package 종료

진행 프로세스가 실제로 종료돼 Native 16쪽에서 중단됐음을 확인했다. 같은 frozen
소스·입력·PDF·SVG를 고정하고 완료된 PNG 16개는 보존한 채 나머지 5쪽만 같은
webfont rasterizer로 산출했다. `endnote-explicit-keep-native-recovery-provenance.json`에
21개 SVG/PNG 해시, 추가 raster 5개와 원 실행의 입력·빌드 출처를 연결했다.
전체 PNG 쌍 TSV는 exit 0, 21/21쪽, 최저 90.64221%, 미달·누락 0이다.
Native export와 PDF의 전체 쪽수도 별도로 21/21 확인했다. PNG 쌍 측정 자체의
gate는 `not_evaluated`이며 확대 판독에서 확인한 `not=` 결함이 남아 있다.

WASM 최적화도 종료된 PID와 `Terminated` 로그를 확인한 뒤 같은 소스·공용 캐시에서
재실행했다. 재실행은 exit 0, 544.46초로 완료됐고 소스 해시가 전후 일치한다.
새 frozen WASM SHA-256은 `2659d2fad218b7e0441680cd6e345046c48a23ee38dec780ccc64029095ec264`다.
JS/WASM은 루트 pkg와 Studio public의 해시도 일치한다. 이 frozen package의 전쪽
대조를 별도 프로세스로 시작했으며, 이후 소스 변경의 결과와 구분한다.

`not=`의 Print text trace는 등호 U+E047과 빗금 U+E054가 같은 원점에 표시됨을
입증한다. 한 글자 `≠`로 바꿔 동일한 표시라고 추정하지 않는다. 여러 크기의 재생성
자료에서도 빗금은 별도 glyph이며 크기와 대상에 따라 비율이 다르다. 4개 크기에서
부정 등호·부등호와 정상 기호를 비교하는 저장본 및 Print를 다음 단계의 독립 근거로
사용한다. 수동 진단 입력의 생성·저장 정보는 공개하며 원본의 일치로 대체하지 않는다.
