W9의 exact-source·common-layout·portable-replay 경계는 보존됐고 기존 공개 계약과 structured rejection
focused test는 모두 통과했다. W3의 기존 10,000-entry journal은 schema key만 읽었으며 direction, writing

  배포 archive에 원본 variable TTF가 별도 수록됨

## 6. source container 선택지와 권고

### A. 라이선스별 공식·파생 SFNT source를 분리해 추적 — 수정 권고

- Source Han Old Hangul은 OFL 원장과 기존 WOFF2를 input으로 고정하고 OTF로 결정적 lossless decompress한다.
  generator version, input/output SHA-256과 table equivalence를 기록해 `ttfs/opensource/`에 둔다.
- Happiness Sans는 수정 불가 정책 때문에 WOFF2를 변환하지 않는다. 공식 화면용 archive의
  `screen/otf/HappinessSansVF.ttf`를 byte 그대로 추출하고 동봉 license PDF와 archive/member hash를 보존한다.
- Happiness Sans는 OFL이 아니므로 `ttfs/opensource/`에 섞지 않는다. 별도
  `ttfs/redistributable/happiness-sans/` 경로와 source supply README를 추가하되, 공식 license의 추적·번들
  허용 범위를 메인테이너가 승인한 뒤에만 commit한다.
- 두 SFNT 모두 제품 WASM에 자동 embedding하지 않고 exact-source API·fixture·portable replay가 같은 bytes를
  사용한다.

장점은 runtime WOFF2 decoder와 WASM size·공격면을 추가하지 않고 native/WASM의 source bytes를 동일하게
만드는 것이다. 단점은 새 binary와 non-OFL 재배포 source용 디렉터리·원장을 관리해야 한다는 점이다.

### B. Rust/WASM runtime WOFF2 decoder 추가

제품이 assets WOFF2를 직접 shaping source로 사용할 수 있지만 dependency·WASM size·decompression 상한·malformed
font 공격면이 새로 생긴다. W10의 핵심 shaping보다 container decoder가 변경 이유가 되어 우선순위가 뒤집힌다.

### C. Noto TTF만으로 Q1·horizontal/vertical subset 진행

가장 작지만 variation과 old Hangul completion condition을 충족하지 못한다. 두 lane을 후속 issue로 넘기는
명시적 scope 축소 승인이 있을 때만 가능하다.

Q0 권고는 수정된 **A안**이다. 최초 A안처럼 Happiness WOFF2를 변환해 `ttfs/opensource/`에 넣는 방식은
라이선스 경계와 맞지 않아 폐기했다. binary 추출·생성·추적은 제품 mutation에 준하는 판단이므로 메인테이너
승인 전에는 실행하지 않는다.
