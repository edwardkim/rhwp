# #7642 완료한 일반 셀과 계속되는 병합 셀의 소유 분리

Issue: #7642. 수정 전 소스는 `f91ff1d1896a4c2dd3846beca01f86a04481afe0`이다.

## 독립 근거와 실제 소비 경로

#7028 원본의 9행 일반 셀은 첫 쪽에서 모든 내용 유닛을 소비한다. 그런데
일반 행의 마지막 물리 상자와 원시 행 높이를 뺀 약 9.8px를 다음 쪽의
빈 9행으로 다시 배치한다. 한컴 원본 Print는 다음 쪽을 10행부터 연다.
병합 셀은 원본 인덱스 6행부터 10행까지 계속되므로 그 내용·공간을 없애면 안 된다.

한컴 Print에서 관측한 글꼴 공급은 PDF 내장 글리프와 설치된 한컴바탕의
정규화된 윤곽을 대조해 확인했다. captured font environment로 대조해도
빈 완료 행과 뒤 행의 위치 차이는 남는다. 글꼴 차이로 면제하지 않는다.

생산·소비 경로는 `scan.split_end_cut/end_row_height_override` →
`emit_table_fragment`의 `complete_physical_end_cut` → 다음 행 높이 선택 →
`TableContinuationCursor::advance` → 다음 fragment의 예산·실제 배치다.
병합 셀의 `accepted_straddle_fragment_units` 및
`straddle_page_bands_after_fragment`는 내용 컷과 수용한 물리 공간을 별도로
보존한다. 일반 행을 다시 여는 것과 이 병합 셀 장부를 혼동하지 않는다.

## 수정 범위와 반례

일반 셀이 완료되고 병합 셀이 경계를 넘어 계속될 때, 원시 행 높이의
단순 차이를 일반 행의 새 소유 공간으로 만드는 마지막 fallback을 제외한다.
앞선 저장 프레임·물리 최소·그림 등의 실제 잔여 선택은 유지한다. 그 선택이
아무 높이도 소유하지 않을 때만 커서를 다음 원본 행으로 전진한다.
이미 수용한 앞 조각의 컷·높이·paint는 바꾸지 않으며 병합 셀의 원장은 유지한다.

불완료 일반 셀이 남은 56행, 독립된 큰 행 최소, 저장 쪽 프레임, 블록 컷,
#7518 마지막 행의 정상 분할은 적용되지 않아야 한다. 문서 ID·행 번호·특정
픽셀 높이로 분기하지 않는다. stage3007의 한컴 생성 대조군은 완료 일반 행을
다시 열지 않고 다음 행부터 시작하되 병합 셀의 남은 공간과 뒤 문단을 보존한다.
재조판 전용 물리 최소 경로는 이 fallback과 별도이므로 해당 진단 문서의
전체 일치를 이번 변경만으로 주장하지 않는다.

## 검증 상태

이 문서는 원인과 변경 범위를 기록한다. 원본·대조군의 Native 시각 출력,
기존 #7028 검사, 마지막 문단 소유·호스트 간격·정상 분할 대조군을 먼저
확인한다. 그 뒤 fresh WASM을 확인하며 전쪽 90% 이상과 직접 판독 전에는
새 회귀나 baseline을 추가·변경하지 않는다. 점수나 테스트 통과는 아직 미검증이다.

## 후보 실행과 가설 제한

`2071a756d1`의 stage3014 Native 빌드는 성공했다. stage3015의 원본 6쪽은
두 글꼴 조건 모두 이전과 byte-identical한 내용을 유지했지만 시각 미달은
개선되지 않았다. 기본 글꼴 최저 47.81438%, 관측된 Print 글꼴 최저
41.08081%다. stage3018에서 9행 2열은 여전히 1쪽 157.3px와 2쪽의 빈
9.8px 조각으로 남고, 셀별 내용의 변경·누락은 없다. 따라서 이 변경만으로
#7028을 고쳤다고 판단하지 않는다.

stage3021의 독립 대조군 6건 중 작은 최소 높이와 저장 빈 줄/재조판 줄이
섞인 `mixed-stored-6000.hwpx`는 Native 전쪽 최저 45.87609%에서 100%로
개선됐다. 나머지 다섯 건의 Native PNG는 전후 SHA-256이 같다. 특히
큰 최소 높이의 이어받기를 없애지는 않았다. 이들 중 기존 쪽수·점수 미달
문서는 계속 미달이며 통과 대조군으로 세지 않는다. 새 정식 테스트로
승격하려면 fresh WASM과 직접 판독도 필요하다.

원본에는 앞선 높이 선택이 먼저 값을 반환하므로 마지막 fallback만 고쳐서는
충분하지 않다. `RHWP_DIAG_ROW_TAIL`은 실제 재조판 잔여 분기의 full/used/tail,
종료 컷·완료 여부와 최종 override를 기록한다. Native에서 명시한 경우에만
동작하며 기본 출력·컷을 바꾸지 않는다. 저장 LineSeg가 하나 존재한다는
사실만으로 실제 `row_uses_reflow_physical_frame` 결과를 추정하지 않는다.

## 실제 재조판 잔여 분기의 보정

소스 `eef68a85a1`의 stage3030은 원본에서 실제로
`complete=true, crossing_span=true, reflow=true`이며 재조판 최소 높이 분기가
`full=167.146667, used=157.346667, tail=9.8`을 반환함을 확인했다.
관측한 Print 글꼴에서도 컷만 `[1,5,7]`로 바뀌고 같은 9.8px를 넘긴다.
따라서 원본을 저장 줄 경로로 가정한 해석을 폐기하고, 실제 재조판 잔여
생산 지점에 완료 컷의 소유 구분을 적용한다.

stage3035의 작은 재조판 대조군도 완료 컷 뒤 12px를 같은 방식으로 넘긴다.
큰 최소 높이 24000/36000HU 대조군은 `complete=false, cut=[]`의 다른
수용 경로를 사용하므로 이 조건을 적용하지 않는다. 해당 대조군의 기존
미달·쪽수 차이는 여전히 별도 미해결 범위다. #7518의 끝 행과 불완료
일반 내용의 컷, 실제 저장/그림 프레임·블록 컷도 유지한다.

보정한 소스의 원본 6쪽·독립 정상/반례·기존 보정 53쪽과 #7969 대조군을
다시 확인한다. Native 결과 전에는 효과를 선언하지 않고, fresh WASM과
90%·쪽수·직접 판독 전에는 회귀 기대값을 갱신하지 않는다.

## 새 base와의 추가 검토 항목

stage3033은 새 base `4296fa045d`와 `f91ff1d189`를 같은 조건에서
36개 문서/backend 조합, 52페이지에 대해 Decimal로 비교했다.
#7969의 양쪽 13문서는 0.01%p 이상 하락이 없다. 다만 호스트 간격 대조군
WASM 1쪽은 94.11347→94.09846으로 0.01501%p 하락해 재검토 상태다.
stage3034의 base/head review·overlay를 직접 대조했다. 제목 표 이중선의
선택된 bbox 16항목이 달라졌고, PDF path의 실제 굵기는 0.36pt(96dpi
0.48px)다. 현재 선 굵기를 단순히 과거의 더 굵은 값으로 돌리지 않으며,
원점·모서리 접합과 글자 가장자리의 차이를 추가 확인한다. 현재 90% 통과가
이 하락을 면제하지 않는다.

## 90% 미달·후퇴 후보의 기각과 원인 계층 재검토

`a56fa03d44`의 stage3036 Native 빌드는 성공했다. stage3037에서 완료 행의
빈 조각은 사라졌지만, 관측한 Print 글꼴의 전쪽 raw 값은
99.68890 / 50.92968 / 50.35633 / 47.59169 / 49.61106 / 41.78540%다.
수정 전 4쪽 98.47569%, 5쪽 97.60364%가 각각 47.59169%, 49.61106%로
후퇴했다. 따라서 마지막 fallback과 재조판 최소에서 완료 일반 행의 꼬리를
버리는 두 후보의 동작을 모두 철회한다. 앞의 작은 합성 대조군 개선은
원본의 후퇴를 정당화하지 않는다. 원본과 Print PDF·진단 산출물은 보존한다.

원본 10행 시작은 한컴 Print의 165.579px와 가깝게 이동했지만, 10행에서
시작하는 2행 병합 셀의 전체 높이는 계속 139.7px다. 원본 선언은 7940HU,
Print 경계는 165.579→271.383px다. 현재 측정 행 10/11은 약 3.7/136.0px로
이미 부풀어 있다. 이 요구 높이와 물리 공간을 해결하지 않고 내용 컷만
전진시킨 것은 잘못된 가정이었다.

HeightMeasurer의 병합 요구 산출과 LayoutEngine의 병합 요구 산출을
`RHWP_DIAG_ROWH`에서 함께 기록한다. 선언·텍스트·중첩/비인라인·그리기 요구와
배분 전 행 합을 대조해 생산 계층을 찾는다. 기존 줄/높이 계산이나 기대값은
바꾸지 않으며, Native 진단 선택 없이 기본 동작은 바뀌지 않는다. 90%·쪽수·
내용 보존·base 대비 하락이 남으므로 현재 PR 생성은 계속 보류한다.
