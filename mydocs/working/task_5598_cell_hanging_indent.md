# #5598 좁은 칸의 내어쓰기가 줄 상자를 무너뜨린다

## 목표

표 칸 안에서 줄바꿈된 다음 줄의 글자가 칸 오른쪽 밖으로 나가는 증상을 없앤다.

## 원인

문단 내어쓰기(`indent < 0`)는 이어지는 줄에 `|indent|` 만큼 좌여백을 더한다(정상 규약). 그런데 칸
안쪽 폭에 육박하는 내어쓰기가 오면 그 줄의 상자가 몇 px 로 무너진다.

재현(코퍼스 00539, `분류처우위원회 심의ㆍ의결` 칸):

| | 값 |
|---|---|
| 칸 안쪽 폭 | 107.7px |
| 문단 내어쓰기 | −7,832 HU = **−104.4px** |
| 둘째 줄 상자(수정 전) | x=193.3, **w=3.3** |
| `의결` 위치(수정 전) | x=229.3 — 칸 오른쪽 경계 **206.1 밖** |

계측(`RHWP_DBG_LINEBOX`)으로 확인한 값:

```
DBG_LINEBOX pi=0 line=0 x=88.8  w=107.7 cell=true stored=false colx=86.2 colw=113.1
DBG_LINEBOX pi=0 line=1 x=193.3 w=3.3   cell=true stored=false colx=86.2 colw=113.1
```

두 줄의 col 영역은 같고 저장 LINE_SEG 도 같다(`cs=200 sw=8076` = 107.7px). 즉 한글은 두 줄을 모두
칸 안쪽 폭으로 조판했고, 무너진 상자는 rhwp 가 내어쓰기를 그대로 적용해 만든 값이다.

## 변경

`src/renderer/layout/paragraph_layout.rs` — 이어지는 줄(`line_indent > 0`)에서 내어쓰기를 적용한
결과 줄 상자가 **한 글자(그 줄 최대 글꼴 크기)** 도 담지 못하면 내어쓰기를 접고 문단 좌여백을 쓴다.
첫 줄은 내어쓰기의 기준선이므로 손대지 않는다.

## 검증

| 항목 | 결과 |
|---|---|
| 재현 문서 00539 | 둘째 줄 상자 x=88.8 w=107.7 로 복귀, `의결` x=146.2 (칸 안), 가운데 정렬 회복 |
| 쪽수 회귀 (표본 1,000문서, rhwp 자체 조판) | **변화 0건** |
| 칸 밖 글자 셀 (표본 498문서·121,516칸) | 1,475 → **1,471** |

코퍼스 효과가 작은 것은 #5598 의 34.9% 가 여러 원인의 합이기 때문이다. 남은 최대 갈래는 별개다 —
예: 09200 은 폭 127.6px 칸에 448px 짜리 run 이 **줄바꿈 없이** 들어간다. 이 변경은 "내어쓰기가 줄
상자를 먹는" 갈래만 닫는다.
