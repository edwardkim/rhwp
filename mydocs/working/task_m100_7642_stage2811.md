# #7642 raster 합성 굵기와 정적 picture의 장치 상태 공유

Issue: #7642.

## 근거와 구현

[작업 계획](../plans/task_m100_7642_native_stroke_coverage_20261017.md)과
[독립 출력 진단](task_m100_7642_stage2807.md)의 범위에서 보정했다.
원문·기준 PDF·원 glyph·em 획·조판 좌표는 변경하지 않았다.

`render_page_to_canvas_with_options`의 최종 surface 종류를
`ReplayCacheContext::raster_target`으로 전달하고 cache seed에 포함했다.
`with_hint`는 이 값을 그대로 이어받는다. 정적 picture의 중간 Canvas를
최종 raster로 추정하지 않으며, 원래 current matrix를 기록하는 기존
경로와 그 matrix를 포함한 cache key를 유지했다. 큰 기존 renderer 모듈의
변경은 인자 전달 두 줄로 제한했다.

`SkiaTextReplay`가 이 상태를 실제 합성 굵기 path helper에 전달한다.
raster는 같은 glyph 원점의 fill과 stroke를 따로 소비한다. 최소 획은
현재 CTM의 역변환으로 얻은 두 장치 축 단위 중 작은 값으로 정했다.
PDFium Skia `SetupStrokePaint`의 소비 계약을 근거로 했으며, 특정 쪽의
픽셀 점수에서 역산하지 않았다. vector에는 이 최소 획을 적용하지 않고
원래 em 획을 남겨 출력 해상도에 따라 소비되게 했다.

모든 glyph path를 확인한 뒤 그린다는 기존 fallback 계약을 유지했다.
실제 Bold face·보통 글자·명시 outline은 원래 분기를 유지한다. shaping
span은 별도 경로여서 이번 변경으로 해당 범위의 일치까지 주장하지 않는다.

## 검증과 남은 범위

새 보정의 컴파일·실행·개선은 아직 미검증이다. 앞 source `145ea004`의
Native/fresh WASM 빌드 exit 0과 시각 결과를 이 변경의 통과로 재사용하지
않는다. 진행 중인 앞 source의 전체 검증은 그대로 수집한다. 공유 target의
Cargo 실행을 겹치거나 실행 중인 검증 worktree를 변경하지 않는다.

새 후보에서는 법령의 기준 하락 페이지와 시험지 대조군을 먼저 재출력하고,
vector PDF 원 획, 서로 다른 DPI·장평·회전과 raster/vector 순서 전환,
정적 picture cache hit/miss를 확인한다. 원본 전체의 Native/fresh WASM
90%·쪽수·확대 판독과 base 대비 하락 검증을 마친 뒤 실물 회귀를 추가한다.
새 회귀·golden·baseline은 아직 추가하거나 완화하지 않았다.

주의할 차이도 남겼다. PDFium AGG의 비등방 변환에서 최소 획을 계산하는
방식은 Skia 경로와 다르다. 현재 설치본의 동일 배율에서 관측한 획 포화만으로
비등방 변환의 동등성까지 단정하지 않으며, 해당 반례는 실행 전 미검증이다.
