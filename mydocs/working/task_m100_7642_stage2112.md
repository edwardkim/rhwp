## 실제 CanvasKit API 검증

Studio의 변경 helper를 설치된 실제 canvaskit-wasm과 CPU surface에서 직접 실행했다.
mock 응답이 아니라 실제 RGBA 그림·matrix·mipmap Image·drawImageRectOptions와
PNG를 사용했다. 64칸 중 한 칸이 검은 선인 독립 배열의 면적 평균을 기준으로 한다.
이는 수학적인 표본·자원 수명 계약이며 실물 문서의 px 위치 회귀가 아니다.

| 경로 | mipmap 생성 / 해제 | 실제 첫 RGBA |
|---|---|---|
|전체 source 1/16 축소|1 / 1|239,239,239,255|
|1:1|0 / 0|0,0,0,255|
|확대|0 / 0|0,0,0,255|
|잘린 source|0 / 0|255,255,255,255|
|장치 matrix 2배에서 축소|1 / 1|223,223,223,255|

5개 경로가 모두 통과했다. crop·1:1·확대에서 기존 경로를 유지하고 축소용 임시
Image를 해제함을 실제 API로 확인했다. 전체 Studio 페이지나 WebGL 경로를 실행한
결과로 승격하지 않으며 Native/fresh WASM의 전쪽 대조와 별도로 기록한다.
