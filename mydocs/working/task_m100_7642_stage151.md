# #7642 Stage 151 — 개체 저장 줄 뒤 간격과 쪽 리셋

Issue: #7642

## 독립 근거와 구현 범위

같은 원본 HWPX XML과 한컴 2024 MCP Print PDF에서 두 경계를 확인했다.
문단 131은 캡션 없는 글자취급 사각형 한 개가 저장 줄 하나를 점유한다.
저장 높이와 개체 높이는 7056HU이고 후속 문단 앞 간격은 568HU다.
도형의 크기는 고정돼 있으므로 저장 줄에 포함된 높이를 다시 더하지 않고
원본 줄 끝과 재작성 줄 끝의 앵커만 이어야 한다.

문단 631의 그림은 저장 시작 31196HU, 저장 끝 72240HU다.
문단 632의 “3. 사업현황”은 독립 Print PDF의 40쪽 첫 제목이며 원점 852HU다.
기존 리셋이 직전 마지막 줄의 시작만 읽어 큰 개체의 점유 끝을 놓쳤다.
현재 제목이 39쪽에 남고 40쪽 본문이 당겨진 것은 새로운 정상 기준이 아니다.

## 생산·소비 경로와 반례

`원본 줄 첫/끝 스냅샷 → 저장 개체 줄 소유 판정 → 원본/재작성 앵커 →
본문 예산과 저장 원점 하강의 쪽 경계 → HeightCursor의 fit/paint`를 잇는다.
줄 높이가 개체 높이와 바깥여백을 정확히 포함하고 가시 본문이 없는 단일 도형/그림만
저장 개체 줄 앵커로 사용한다. 합성·편집 줄, 여러 개체, 가시 본문 혼재, 캡션,
표·수식의 가변 높이 경로는 이 판정에 포함하지 않는다.

양수 저장 원점이 직전 저장 첫 원점보다 낮은 수치로 돌아가고 이전 끝에 새 줄을
이어 담을 공간이 없는 경우에만 새 본문 프레임을 보존한다. 다음 원점과 줄 높이는
본문에 들어가야 한다. 문서명·제목·고정 px 보정·기존 60000HU 임계로 판정하지 않는다.
단순한 원점 감소, 예산 내의 겹침, 합성/편집 줄은 반례다.
