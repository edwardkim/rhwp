# #7642 HY중고딕 가운뎃점 폭의 독립 확인과 보정

Issue: #7642.

## 관측과 원인

[보정 계획](../plans/task_m100_7642_hygothic_punctuation_20261017.md)에 따라 법령 61쪽의
원본 속성과 한컴 Print를 대조했다. 원본 셀의 첫 문단은 ‘13. 우선허용·’이고 저장
줄은 없다. RHWP의 공통 paint 생산 결과는 가운뎃점 폭 5.173px를 사용한다.
기존 Print의 같은 글자는 12.96pt 글자 크기에서 12.96pt를 전진한다.

공식 설치 `H2GTRM.TTF`의 UPM은 1024, `periodcentered`의 hmtx 전진도 1024다.
`quoteleft`, `quoteright`, `quotedblleft`, `quotedblright`도 각각 1024다.
프로그램 SHA는 `0b18f81f9d463f6c498853af3bdad577e9c881a5b59dc7ef4c43287588d696d5`다.
이는 글꼴 파일·윤곽선을 Git에 넣는 변경이 아니다.

`style_resolver`의 검증 face 목록은 과거 글꼴 파일이 없다는 이유로 HY중고딕을
제외했다. 이 때문에 명시적 TrueType 선택도 미검증 폭으로 취급되고, 공통 측정의
미검증 가운뎃점 0.3em 보정이 적용됐다. 이는 첫 문단을 한 줄에 담아 셀 높이와
후속 본문의 위치까지 바꾸는 원인이다. 임의로 셀 높이를 늘려 맞추지 않았다.

## 내어쓰기 통제와 실제 MCP Print

원본과 바이트가 같은 control, 문단 모양 26의 indent 필드만 0 또는 -7264 HU로
바꾼 입력을 출력했다. 변경은 같은 스타일의 모든 사용 위치에 적용된다.
세 Print 모두 첫 줄 ‘13. 우선허’와 다음 줄 ‘용·’를 유지했고, 바뀐 내어쓰기는
둘째 줄의 원점만 바꿨다. 따라서 첫 줄 끊음의 원인을 내어쓰기로 판정하지 않았다.
원본은 변경하지 않았고 control의 중복 HWP도 커밋하지 않는다.

세 작업은 모두 MCP의 start → status → download로 완료했다. engine 2020,
Hancom `11.0.0.9136`, `pdf_print_method=0`,
`pdf_output_mode=hancom2020_pdf_driver_one_up`, 전체 74쪽을 확인했다.
이는 HWPX 재저장이나 Save As PDF 결과가 아니다.

## 코드와 소비 경로

공식 프로그램으로 검증한 HY중고딕 TrueType을 기존 언어별 metric 신뢰 계약에
연결하고, 구두점 원 프로그램의 hmtx 값을 기존 검증 표에 추가했다.
명시적 TrueType 또는 기존 TTF 선언을 확인한 경로만 이를 사용한다. HFT와
미검증 대체 글꼴에 전각 폭을 일괄 적용하지 않는다. 문서 번호 분기는 없다.
공통 측정 결과를 컴포저의 금칙·줄 나눔, 셀 높이 측정, 실제 줄 배치와 양쪽
backend의 글자 원점이 소비한다. 가운뎃점의 줄머리 금칙도 유지했다.
