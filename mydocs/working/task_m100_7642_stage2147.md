# #7642 WMF 공통 Print surface의 구현 단계

[공통 surface 계획](../plans/task_m100_7642_wmf_surface_20261017.md)을 구현한다.
이 단계는 코드 연결이며 시각 개선·PR 준비 완료를 주장하지 않는다.

## 구현과 실제 소비

- `paint/metafile_surface.rs`: 2024 Print·RealPic·밝기/명암 0의 표준 WMF를
  SVG → crop/fill/변환을 반영한 전체 600DPI 자원 → resvg 최종 합성 → 예약
  흑백을 포함한 visible RGB 판정 → 전달색 → OutputDevice PNG로 내린다.
  DIB의 보간은 유지하며 벡터/문자는 해당 장치의 crisp 경로를 쓴다.
- 크기·입력·PNG cache에 상한을 둔다. premultiplied RGBA는 같은 buffer를
  unpremultiply해서 소비하고 alpha를 유지한다. 전체 크기의 복사 세 벌을 만들지 않는다.
  cache에는 원본·장치 가로/세로·명시 font 세대·실제로 선택한 프로그램의
  bytes/face fingerprint를 포함한다. 폰트 파일 경로만으로 신원을 정하지 않는다.
- `paint/metafile_fonts.rs`: 실제 SFNT/TTC face와 alias를 보유한다. 별도 alias
  등록이 앞선 binding을 없애지 않게 등록 family를 분리한다. 원본 프로그램은
  바꾸지 않는다. cmap으로 필요한 문자를 공급하지 못하면 빈 glyph PNG를 캐시하지 않는다.
- `DocumentCore`의 독립 paint font API는 실제 face 등록·교체 뒤 layer/JSON
  cache를 비운다. 저장 IR·줄 측정·쪽 배치와 HFT/exact slot API 의미는 바꾸지 않는다.
  WMF가 사용하는 내장 family는 본문 glyph slot의 사용 여부와 분리해 공급한다.
- `LayerBuilder`의 같은 resolved payload를 SVG·Native·Canvas2D·CanvasKit이
  소비한다. OutputDevice는 기존 계약에 따라 원본 bin key로 바이트를 재조회하지 않는다.
  실제 PNG의 내용 기반 image resource key를 사용한다.
- `MetafileFontSession`을 Studio `prepareCanvasMetrics` 앞에 연결했다. 저장된
  로컬 권한/host provider의 실제 bytes를 공급하며 새 권한 prompt를 만들지 않는다.
  CSS에만 존재하는 face를 공급 완료로 간주하지 않는다. SFNT가 없으면 기존 SVG
  경로를 보존한다. host font 세대와 비동기 문서 교체도 대조한다.

WMFC의 enhanced content, 기존 EMF 장치, 2020·Screen 및 지원 근거가 없는 효과는
기존 경로가 담당한다. 미달 정상 WMF 35쪽에는 대조군의 null-pen 사각형 조건이
직접 없었으므로 그 규칙을 이 구현의 원인 보정으로 끼워 넣지 않았다.

## 의존성과 사전 확인

resvg 0.47을 Native 기능에만 묶지 않고 공통 의존성으로 옮겼다. text/raster-images만
명시하고 WASM에는 fs·mmap을 요구하지 않는다. Native 시스템 글꼴은 기존 font_paths
규칙을 재사용한다. Cargo.lock 버전은 바꾸지 않았으며 THIRD_PARTY_LICENSES.md의
실제 사용 범위를 Native/WASM과 usvg 두 버전으로 맞췄다. 비공개 font bytes는 추가하지 않는다.

사전 작업 트리의 stage2143 Native check(exit 0), stage2144 Native check(exit 0),
stage2145 WASM32 check(exit 0), stage2146 Studio `tsc --noEmit`(exit 0)을 확인했다.
이후 alias·font source fingerprint·내장 font 공급·RGBA peak memory 보정을 함께 했으므로
해당 이전 실행을 최종 source의 검사로 재표기하지 않는다. 커밋된 source에서 다시 확인한다.

## 다음 검증과 기존 실행의 구분

진행 중인 stage2106은 고정 `aae3ea1b26` producer의 결과다. 새 Rust source의 결과가
아니며, guarded sweep script를 그 실행 중에 바꾸지 않는다. 새 Native를 빌드해 정상
저장본 18·35쪽과 관련 전쪽, 명시적 pen/bitmap palette 대조를 먼저 확인한다.
fresh WASM은 실제 메타파일 family도 수집·공급하도록 같은 API에 연결한 뒤 빌드·검증한다.
검증 전에는 새 WMF 회귀·정상 golden을 추가하지 않는다. 기존 미달·devel 대비 하락과
전체 Rust 실패를 해결하는 gate는 그대로다.

## 고정 Native의 첫 전쪽 결과

stage2149는 committed source `84fa650793b8a7677e77f970dc7f6d7ad956ec03`의
Native를 실제로 빌드하고 CLI artifact를 동결했다(exit 0, 289.37초).
공용 target 전환 뒤 library의 mtime만 갱신했으며 source 내용 SHA는 유지했다.
이후 현재 자동 sharding의 실제 target을 선택한 stage2156 기존 mask 계약은
2개 모두 PASS다. 앞선 stage2150의 오래된 suite 번호는 exit 4/실행 0개이며
테스트 실패나 통과로 세지 않는다. 해당 실패 로그도 보존했다.

stage2154 Native는 원본/PDF를 바꾸지 않고 정상 저장 HWPX·HWP를 전체 64쪽씩
새로 출력했다. `sample16-hwpx`, `additional-1`, `sample16-hwp5` 세 검증 항목의
전쪽 최저 raw는 모두 95.03221%다. 뒤 두 항목의 같은 입력 중복도 고유 문서
수가 늘어난 것으로 보고하지 않는다.

| 정상 HWPX의 실제 쪽 | 수정 전 Native | 수정 후 Native |
|---|---:|---:|
|18|75.39973%|96.83599%|
|35|80.95603%|98.51988%|

stage2157에 같은 페이지의 새 review·standalone overlay와 source/PNG 해시를
보존하고 직접 확인했다. WMF 그림의 큰 배경 차이가 줄었다. 본문 굵기·괘선 및
18쪽 그림 뒤 본문의 일부 수직 차이는 여전히 보이며, 페이지 점수로 면제하지 않는다.
이 직접 판독은 새 WMF의 완료·정상 golden·px 좌표 핀 추가 판정이 아니다.

새 Native 전쪽 queue와 stage2151 fresh WASM 빌드는 계속 진행한다. WASM의
실제 API/글꼴 공급·새 캡처가 없으므로 같은 점수나 전체 수용 판정을 복사하지 않는다.
stage2158에는 실제 emitted PNG 자원과 독립 PDF 자원의 geometry도 별도로 기록했다.
