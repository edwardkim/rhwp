# PR 9293 머지 대기와 로컬 통합 준비

사용자의 지시에 따라 #9293이 실제 머지되기 전에는 이번 작업의 원격 push·PR 제출과
통합 후속 처리를 진행하지 않는다. 주 작업 브랜치 `task/7754-nine-fidelity-devel`은 유지한다.

## 갱신된 선행 PR과 미리보기

#9293의 head가 승인받은 고지 보정 `83b671c2a63a87b0946d2d2aa3f512ecf38945d2`에서
`980516d956c3cfba7bdf0e22ddb3d10e04b12ea1`로 갱신됐다. 새 head는 최신 devel 동기화와
빈 CFF 가운뎃점의 다음 공급자 선택 보정을 포함한다. 앞서 기록한 83b671c의 CI 통과를
새 head의 결과로 표시하지 않으며 이 원격 PR에 추가 변경하지 않았다.

현재 후보 `914f408caafc3e6159e26880b8561ab8518aea7c`와 새 #9293 head의 읽기 전용
병합 시뮬레이션은 exit 0·충돌 0건이다. 결과 tree는
`d6e00190fb4822aae9dd127a117743046eeff659`다. 정식 작업 브랜치를 통합하지 않고,
별도 소유 sparse worktree의 로컬 미리보기 커밋
`c89b59865cfd64d40ee6f8d5e30667105c54d7d6`에서 Native·최적화 WASM을 순차 빌드한다.

미리보기는 원격으로 제출하지 않는다. 빌드 후 같은 입력·PDF·공급 조건의 집중 비교를
진행하며 미리보기의 병합된 프런트엔드 스크립트도 함께 사용한다. 기존 corpus는 절대 경로와
SHA로 고정한다. 실제 머지 뒤 최신 devel과 동기화하고 최종 head의 코드 동일성과 필요한
기능 보존·필수 검증을 확인하기 전에는 이 결과를 최종 PR 검증으로 승격하지 않는다.

로컬 PR 본문 초안은 `output/pr-review/issue7754-nine/pr-body-preparation.md`에 작성했다.
진행 중인 필수 보호 검증과 #9293 머지 조건을 제출 보류 사유로 명시했다.

## 추가 확인과 잘못 지정한 범위의 정정

Windows Arial 4종을 실제 공급한 Helvetica 스타일의 한 쪽 전체는 Native·WASM의 base·후보
네 실행이 모두 100.00%다. 과거 Arial의 파일 SHA를 복구했다고 주장하지 않는다.

시행령 전쪽 요청은 정본의 74쪽을 확인하지 않고 119쪽으로 잘못 지정했다. 64쪽의 부분
출력 뒤 다음 부분에서 실제 전체 74쪽을 벗어나 실패했다. 실패와 부분 결과를 보존했고
다음 요청은 manifest에서 페이지 수를 직접 읽어 전쪽을 산출하도록 정정했다.
8쪽의 집중 검증을 전쪽 통과로 취급하지 않는다. 실제 전체 측정에서 추가 헤드라인 차이도
확인되어 이를 해결한 것으로 기록하지 않는다. 잘못 지정한 범위나 서로 다른 시행의 쪽별
최댓값으로 보호 결과를 조합하지 않는다.

glyph identity 대조에서 Windows H2HDRM의 해당 글자는 기준 PDF와 윤곽·hmtx가 같았다.
이름이 같은 다른 로컬 버전과 다르다는 사실만으로 source 메트릭·원본 소유 계약까지
동일하다고 추정하지 않는다. 공급 방식과 프로그램 선언을 달리한 진단의 미달 기록도
보존하고 보호 하한은 그대로 유지한다.

전체 Rust 검증은 종료되어 Cargo/Rust 프로세스와 열린 파일 참조가 없고 lock이 해제된
debug 증분 캐시 네 세션만 정확한 경로로 정리해 859,570,176바이트를 확보했다.
새 빌드는 공유 `target/pr-review`에서 하나씩 실행한다. 다른 target 프로필·deps·실행 중인
시각 자료와 frozen producer는 유지한다.
