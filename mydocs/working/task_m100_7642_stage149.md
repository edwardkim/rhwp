# #7642 Stage 149 — 저장 원점의 연산 오차와 기본 대각선

Issue: #7642

## 구현 전 근거

Stage 148은 영월 셀의 잘림을 해소했다. Print 3쪽의 대각선 12개는 0.36pt이며,
한컴 정상 저장본의 해당 셀은 0.12mm다. HWP3 파서는 대각선을 0.1mm로 생성했고
Native SVG는 0.32px였다. 선 종류만 가진 HWP3의 기본 대각선 매핑을 0.12mm로 맞춘다.

sample16에서는 같은 저장 사다리의 `HeightCursor::vpos_adjust`를 호출해도 fit/paint의
순차 합산 순서가 다르다. 같은 물리 위치의 f64가 인접한 값이면
`raw_end_y >= y_offset`가 달라져 앞 간격 수용이 갈리고, 후속 배치도 더 내려갈 수 있다.
실측 로그의 pi123/124 위치와 원본 HWPUNIT으로 이 경계를 재계산했다. 문서 ID나 고정 px
여유를 넣지 않고 좌표 규모에 비례한 부동소수점 연산 오차만 비교에 반영한다.

## 생산·소비와 검증 범위

`vpos_corrected_end_y`는 Typeset과 Layout의 공통 원점 수용 함수다. 원점이나
줄 높이를 clamp하지 않고 동일 위치 비교의 연산 오차를 처리한다. 후속 원점·쪽 배정·
내용 순서는 실제 전체 출력으로 확인한다. 진단 로그는 수용 전·후 좌표를 충분한 정밀도로 남긴다.

영월 4쪽과 대조군 5쪽을 Native로 다시 출력하고 대각선·마지막 셀을 직접 판독한다.
sample16 전체 64쪽은 같은 독립 Print로 다시 비교한다. 선행 결과가 확인되면 같은 source의
fresh WASM을 빌드해 대응 범위를 확인한다. 미달 페이지·쪽수 불일치가 남으면 회귀 기대값을
변경하지 않는다. 새 관계형 회귀는 양쪽 전쪽 90%와 확대 판독 뒤 새 이름으로 추가한다.

## Native 선행 검증 결과

release-test Native 빌드와 9쪽 선행 검증이 exit 0으로 완료됐고, source 해시는 동일했다.
영월 전체 4쪽은 99.29000% / 100% / 99.68892% / 100%다. 탭·셀 순서·격자 대조군도
모두 90% 이상이며 최저 98.50071%다. 물리 대각선 12개는 이제 SVG에서 0.48px이며
독립 Print의 0.36pt와 같다. 같은 위치의 확대에서 마지막 셀 두 줄의 보존을 확인했다.
SVG와 PDF raster의 안티앨리어싱 차이는 남아 있다. 점수로 색상 일치를 주장하지 않는다.

sample16 실행 로그에서 pi124는 실제 배치 원점 비교가 같은 위치의 반올림 때문에
기각되던 경계를 이제 수용한다. 앞 간격 차감 전 첫 줄 원점은 같으며 원본 단위 1 HWPUNIT의
물리적 후방 이동은 별도 분석 대조군에서 계속 거부된다. 분석과 Rust 실행 로그는 구분했다.
이것으로 sample16 전체 문제가 해결됐다고 판정하지 않는다. 전체 64쪽 Native 비교는
이 기록 시점에 실행 중이고, fresh WASM·전체 회귀·55문서 853쪽은 남아 있다.

`git fetch upstream devel`을 수행했고 `upstream/devel`은
`bfa28a77a2714482f647ee6a7b9aa7f7876d8404`다. 현재 branch에 없는 upstream commit은 0개로
추가 동기화할 변경이 없다. 코드 검증 중 불필요한 rebase를 하지 않는다.
