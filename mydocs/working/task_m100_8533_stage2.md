# #8533 명시한 WASM 글꼴 프로그램의 측정 전 준비

일반 Native 자동 공급은 [1단계 기록](task_m100_8533_stage1.md)과 같은 Rust 소스다.
최소 글꼴 WASM 추가 검증에서 명시 환경의 실제 프로그램 준비 순서가 빠진 것을 확인하여
Visual Sweep의 JavaScript 소비 경계를 보완한다. 일반 WASM 자동 다운로드 기능을 추가하는 변경은 아니다.

## 확인한 경계

`applySweepFontEnvironment`의 자동 선택 분기는 프로그램을 먼저 로드한 뒤 환경을 적용했다.
명시 분기는 환경을 적용하고 바로 반환하여, 뒤따르는 Canvas 폭 측정 시점에 실제 프로그램이
준비되었다는 보장이 없었다. 명시 환경을 우선하는 것과 프로그램 로드를 생략하는 것은 다른 계약이다.

합성 호스트에서 실제 프로그램 준비 완료를 setter의 선행 조건으로 검사하면 보정 전 실패한다.
원본 요청에 없는 명시 주 프로그램과 슬롯별 글리프 대체도 공급 후보로 포함하고, 비동기 준비가
완료된 뒤 사용자의 환경을 그대로 적용하도록 보정했다. 준비 실패 시 환경을 적용하지 않는다.
자동 환경 생성기를 호출하여 사용자의 선택을 덮어쓰지 않는다.

이 단계에서 기존 자동 선택 분기 이후의 코드는 보정 전과 바이트가 동일했다. 이후 3단계가
목록·family 선택을 보완했으므로 현재 호스트 전체의 결과는 전쪽 재검증으로 별도 확인했다. Native·WASM 모듈의 Rust 코드와
WASM 번들은 변경하지 않는다. 보정 대상은 명시 환경을 사용하는 검증 호스트 경로다.

## 검증과 환경 구분

- 신규 준비 순서 검사: 보정 전 의도한 원인으로 FAIL, 보정 후 PASS.
- 명시 환경 우선·구 API의 명시 해제·공급 실패·실제 바이트 hash·자동 선택 정상 대조군을 유지한다.
- 개인 글꼴 파일 접근을 차단한 Chrome은 내부 프로세스 sandbox의 시작 제약을 별도로 확인했다.
  로컬 검증 wrapper에서 시작 인자를 조정하되 외부 파일 접근 차단은 유지했다.
- Python 준비 계획 11개와 실제 일반 Native 출력 영수증의 9개 프로그램이 달랐다.
  두 계획을 같은 공급 조건의 증거로 섞지 않는다. 최종 추가 WASM 검증에는 실제 Native 전쪽
  출력 영수증의 프로그램 파일·SHA와 환경을 확인하여 그대로 전달한다.
- 보정 전 같은 Native 영수증을 사용한 WASM 272쪽은 99.79836%였다. 이 수치는 보정 전의
  진단이다. 최신 전쪽 추가 검증은 383쪽·최저 94.37243%·220쪽이며, 272쪽은 100%다.
  일반 환경의 36문서·편람과는 구분하며 Canvas 간격 차이를 Native 완료 결과로 덮지 않는다.

최신 TSV·PNG는 [제출 증적 묶음](../pr/assets/issue8533/final-native-webfonts/README.md)에
환경을 구분하여 갱신한다. 로그와 임시 driver는 ignored output에 둔다. 최소 설치 VM이나 일반
WASM 자동 다운로드를 검증했다고 주장하지 않는다.
