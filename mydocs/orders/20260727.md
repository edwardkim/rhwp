## Issue #3474 — Studio HWP5 암호 문서 열기

[#3474](https://github.com/edwardkim/rhwp/issues/3474)의 범위를 HWP5 `EncryptVersion 4` 암호 문서로
한정해 Studio 열기 흐름을 보완했다.

- 일반 열기에서 비밀번호 필요 신호를 받으면 접근 가능한 한국어 암호 입력 대화상자를 열고, 취소·오답·손상 시
  기존 문서와 최근 문서 상태를 바꾸지 않는다. 정답 입력은 재시도·Enter 제출을 지원하며 비밀번호는 오류,
  저장소, 최근 문서, 문서 메타데이터에 남기지 않는다.
- 문서 교체를 원자화해 복호화·변환이 모두 성공한 뒤에만 기존 WASM 문서를 해제한다. 지원하지 않는 암호 방식과
  DRM·HWPX 흐름은 기존의 명시적 오류/일반 열기 동작을 유지한다.
- 실제 HWP5 암호 fixture를 사용하는 브라우저 E2E, Studio 단위 계약 시험, `npm test`, Studio build,
  E2E manifest 검사를 통과했다. UI 상태 전이 기능 검증이므로 렌더 배치 시각 sweep 대상은 아니다.
- `samples/HWP3-password-123456.hwp`는 향후 HWP3 복호화 회귀용 샘플로만 함께 보관한다. HWP3 복호화 알고리즘은
  별도 명세가 제공된 뒤 `src/parser/hwp3/`에서 구현하며, 이번 수용 범위·검증 주장에는 포함하지 않는다.

### 근인과 구조적 처방

`print-surface.ts` 가 `new URL('print.html', baseUrl)` 로 확장 루트 기준 파일을 열지만
`build.mjs` 가 복사하지 않았다. 확장은 `vite publicDir:false` 라 `public/` 자산을 개별
복사해야 하는데 `theme-init.js`·`favicon.ico`·아이콘 SVG 만 대상이었다.

더 근본적인 문제는 **`copy()` 가 원본 부재 시 경고만 내고 넘어가 누락이 빌드 성공으로
위장된 것**이다. 그래서 v0.8.0·v0.8.1 두 릴리즈를 그대로 통과했다. 런타임 필수 6종의 존재를
확인하고 없으면 `exit 1` 로 실패시키는 게이트를 추가했고, 원본을 임시 제거해 실제로
잡히는지(`MISSING: print.html` → exit 1) 실증했다.

기존 print 테스트 15개는 URL 계산·명령 계약만 검증해 이 결함을 잡지 못했다. **로직 테스트와
산출물 검증은 다른 층위**라는 점이 이번 사건의 교훈이다.
