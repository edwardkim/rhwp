# 2026-08-21 오늘할 일

## #4962 W3 실제 renderer 기반 font metric coverage 재계측

- 상위 로드맵 [#4960](https://github.com/edwardkim/rhwp/issues/4960)의 선행 작업인 W0·W1
  [#4939](https://github.com/edwardkim/rhwp/issues/4939)와 W2
  [#4961](https://github.com/edwardkim/rhwp/issues/4961)이 `devel`에 반영된 사실을 확인했다.
- 작업 기준은 `upstream/devel@fb434269eea237cc12053914560a2dbaf16270bf`이며, 로컬 `devel`,
  `origin/devel`, `upstream/devel`은 착수 시점에 일치했다. 작업 브랜치는
  `task_m100_4962`다.
- 기존 로컬 POC에는 전체·HWP·HWPX aggregate와 생성 source가 남아 있다. 실제 사용 font, 언어 slot,
  bold·italic, 장평·자간, 커닝, 문맥, 정렬, stored LineSeg 존재 여부, 문서·문단·run·문자 수와 고정
  frame 위험 통계는 새로 만들지 않고 W3 기준선으로 재사용한다.
- 기존 `metric mapped 91.16%`는 `layout_metric_face_name()`을 원시 font 이름에 직접 적용한 face-level
  수치다. 기존 aggregate에는 code point, `altType`, `substFont`, renderer 정규화 계보, 문자별 hit/miss,
  overlay·surrogate relation이 없어 W3의 7개 분류를 역산할 수 없다.
- 따라서 W3의 전수 작업 후보는 기존 계측 전체를 반복하는 것이 아니라, 기존 usage key와 합계에
  문자별 renderer decision만 보강하는 조건부 delta pass다. fresh layout과 backend snapshot은 별도
  cohort로 두며, 전수 적용 필요성과 비용은 pilot 결과를 보고 다시 승인받는다.
- W2 trace는 단일 page, 기본 1,024자·최대 4,096자이고 offset이 없다. raw trace를 page별로 저장하는
  방식 대신 기존 POC walker와 W2의 공통 decision을 결합한 streaming aggregate 경로를 검토한다.
- 로컬 private corpus의 10,000개 HWP/HWPX는 읽기 전용 입력이다.
  원문·본문·식별 파일 목록·절대 경로·raw trace는 저장소에 게시하지 않고 aggregate·비식별 결과와
  결정론적 aggregate hash만 남긴다.
- 메인테이너가 [수행계획서](../plans/task_m100_4962.md)를 승인했다. Stage 1에서는 기존 자산 동결,
  분류·분모·privacy 계약과 RED test까지만 수행한다. 별도 승인 전에는 private corpus 전수 실행을
  시작하지 않으며, W3 결과 승인 전에는 같은 이슈의 W4 조판 위험 순위 단계로 넘어가지 않는다.
- [Stage 1 기록](../working/task_m100_4962_stage1.md)을 완료했다. 기존 POC를 재생성하지 않고 비식별
  projection과 HWP+HWPX 가산성을 검증했으며, W1의 1,352개 candidate identity는 의미 변화 없이
  20개 boundary의 digest만 drift한 것으로 판정했다. 7개 분류·독립 분모·privacy·hash 계약 test는
  10/10 통과했다. Stage 2는 메인테이너 승인 대기다.
