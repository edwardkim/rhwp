## devel 브랜치 보호 변경 — `strict: false` (update branch 강제 해제)

콜레보레이터(jangster77·postmelee)가 **update branch 없이 merge** 할 수 있도록
devel 의 `required_status_checks.strict` 를 **true → false** 로 변경했다.

### 왜 admin 부여가 아니라 이 방법인가

개인 계정 저장소에는 "merge 규칙만 면제"하는 중간 등급이 없다. admin 을 주면 브랜치
보호 변경·저장소 삭제·Secrets·Actions 설정까지 전부 따라온다. **권한 등급을 올리지
않고 목적만 달성**하는 경로가 `strict: false` 다.

### 변경 범위 (검증 완료)

| 설정 | 이전 → 현재 |
|---|---|
| devel `strict` | true → **false** |
| contexts(`Build & Test`) · enforce_admins · reviews · force_push · deletions | **전부 불변** |
| **main `strict`** | **true 유지**(불변) |

### 유지되는 안전장치와 남는 위험

- `Build & Test` 필수 체크는 그대로 — **CI 통과 없이는 merge 불가**.
- 다만 체크는 PR 브랜치 기준이고 **base 가 그 뒤 앞서갔는지는 보지 않는다** →
  PR CI 가 검증하지 않은 조합이 devel 에 들어갈 수 있다(같은 파일을 여러 PR 이
  건드릴 때 실제 가능 — 오늘 typeset.rs 축이 그런 사례).
- 완화: devel push 시 CI 가 다시 돌아 **사후 검출**은 된다. 충돌 가능성이 큰 PR 은
  merge 전 update branch 를 **권고**로 남긴다.

되돌리려면 `strict: true` 한 줄. 변경 전 전체 설정 백업은 세션 scratchpad 에 보관했다
(`devel_protection_backup.json`).
