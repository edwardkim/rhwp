## 기여자 가이드 — Claude Code 활용 방식으로 작성

- 작업지시자 지시로, 기여자도 Claude 를 쓰는 점을 고려해 **그대로 복사해 실행할 수 있는 형태**로
  작성했다. [#2739 코멘트](https://github.com/edwardkim/rhwp/pull/2739)에 전문, #2746 에 참조 링크를 달았다.
- 구성: ①낡은 base 가 만드는 문제(충돌·커밋 얽힘, #2762 의 #2760 얹힘을 실제 사례로) ②지금 할
  리베이스 절차 ③앞으로는 로컬 `devel` 이 아니라 **`upstream/devel` 에서 직접 브랜치를 딸 것**
  ④Claude Code 세션 시작 시 지시할 6단계 블록.
- 6단계에는 `git fetch upstream devel` → 이슈 `state`·`assignees` 확인 → `git grep` 으로 이슈 주석
  확인 → `upstream/devel` 에서 브랜치 → 게이트 3종 → red→green 재현 후 PR 본문 기재를 담았다.
  rhwp 는 수정마다 근거 이슈를 `[#1234]` 주석으로 남기므로 `git grep` 한 줄이 중복을 가장 많이 막는다.

## IR 필드 전수 스윕 하네스 — 기존 게이트의 맹점 실증

- [#2763](https://github.com/edwardkim/rhwp/pull/2763)이 드러낸 사실: `serializer/body_text.rs:28` 이
  `raw_stream` 이 있으면 원본 바이트를 그대로 되돌려주므로, **편집하지 않은 문서의 HWP5 왕복은
  바이트 재생**이라 발산 0건이 나온다. 제품에서 한 글자만 고쳐도 `raw_stream = None` 으로
  무효화되고 레코드 재생성 경로를 타는데, 그 경로를 재현하니 **481행 발산**이 나왔다.
- 즉 **왕복 게이트가 초록인 이유는 무손실이라서가 아니라 그 필드를 보지 않아서**였다. 최근 30일
  왕복 1속성 소실 37건이 정확히 그 사각지대에 있었다.
- 하네스가 찾아낸 결함의 수정은 한 글자다(`false` → `is_last_text_char`). placeholder 가 문단의
  **마지막 문자**면 `next_offset` 이 없어 판정이 항상 실패했고, 그러면 공백을 리터럴로 쓰고 남은
  컨트롤을 뒤에 다시 방출하므로 재파싱 때 placeholder 가 하나 더 생겨 **저장할 때마다 공백이
  1개씩 무한히 늘었다**(수렴하지 않음). 쪽번호 자동번호가 든 머리말/꼬리말이 대표 사례다.
