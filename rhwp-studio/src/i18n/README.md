# 언어팩 (i18n)

편집기 UI 문자열을 로케일 파일로 분리해 한국어 외의 언어로도 표시한다.

## 무엇이 어디에 있나

```text
src/i18n/
  core.ts            조회와 폴백 — DOM 과 무관한 순수 로직
  resolve.ts         로케일 결정 (?lang= → localStorage → ko). 브라우저 언어는 기본으로 보지 않는다
  dom.ts             data-i18n* 표시가 붙은 요소 갱신
  index.ts           진입점. 카탈로그 등록·로케일 결정은 이 모듈을 읽는 순간 끝난다
  locales/ko.ts      원문 카탈로그 (생성물)
  locales/en.ts      영어 카탈로그 (생성물)
```

## 로케일은 왜 브라우저 언어를 따르지 않나

`navigator.language` 를 보면 영어 로케일 기계에서 편집기가 저절로 영어로 바뀐다. 고른 적 없는데
화면이 달라지는 것도 문제지만, 영어 라벨이 한국어보다 넓어 도구 모음이 늘어나면 편집 영역이 줄고
문서 쪽나눔까지 달라진다(실측). CI 러너는 대개 en-US 라 자동 감지를 켜 두면 레이아웃 e2e 가 흔들린다.
그래서 영어는 `?lang=en` 이나 저장된 선택으로 **고른 사람에게만** 보인다. `preferBrowserLanguage` 로 켤 수는 있다.

## 언어를 바꾸면 언제 적용되나 — 다음 실행부터

`setPreferredLocale('en')` 은 선택을 `localStorage['rhwp-locale']` 에 저장만 하고
`{ locale, appliesOnNextLaunch }` 를 돌려준다. 지금 화면과 로케일은 바꾸지 않는다.
언어 선택 UI 는 `appliesOnNextLaunch` 가 참이면 "다음 실행부터 적용됩니다" 를 알린다.

즉시 전환을 하지 않는 이유: 이미 열린 대화상자, 모듈을 읽을 때 번역해 둔 상수, 동적 메뉴와
상태 표시줄까지 **현재 앱 상태로** 다시 만들어야 안전하다. 정적 마크업만 다시 칠하면 상태 표시가
초기 문구로 돌아가고 대화상자에는 이전 언어가 남는다. 새로고침으로 적용한다면 미저장 문서 보호
흐름을 먼저 거쳐야 한다.

같은 이유로 정적 마크업 적용(`applyI18nToDom`)은 **요소가 아직 원문을 보이고 있을 때만** 바꾼다.
앱이 그 자리에 현재 상태(`구역: 2 / 3`, `수정`)를 써 넣었으면 건드리지 않는다.

## 규칙 셋

**기본 로케일은 `ko` 이고, `ko` 카탈로그는 원문을 그대로 담는다.**
폴백은 `현재 로케일 → ko → 키` 이므로, 번역이 하나도 없어도 화면은 도입 전과 같다.

**표시는 마크업에 붙는다.** `index.html` 의 요소에 `data-i18n="키"` 를 달면 그 요소의
**직계 텍스트 노드만** 바뀐다. `textContent` 를 덮지 않는 이유는 아이콘 span 과 단축키 표시를
지우지 않기 위해서다. 두 줄 라벨은 `data-i18n-lines` 로 줄을 `<br>` 로 재구성한다.
속성은 `data-i18n-title`, `data-i18n-placeholder`, `data-i18n-aria-label`, `data-i18n-value`.

**코드에서는 `t('키')`** 로 얻는다. 자리표시자는 이름을 쓴다: `t('msg.pages', { n: 3 })` → `{n}쪽`.

## 문자열을 옮길 때 조심할 것

- 비교식(`=== '없음'`), `case`, 선택자, 타입 리터럴의 문자열은 **옮기면 안 된다.**
  거기서 문자열은 화면이 아니라 값이다.
- 한 곳이 문자열을 만들고 다른 곳이 그 문자열과 **비교**하면, 앞만 옮겼을 때 뒤가 조용히 거짓이 된다.
  테스트가 한국어로 돌면 이 결함은 초록 화면 뒤에 숨는다. 짝을 함께 보라.
- 글꼴 이름(바탕·돋움·함초롬…)은 실제 글꼴 이름이라 옮기면 못 찾는다.
  글꼴 미리보기 견본은 여러 문자 체계를 보이려는 문자열이라 옮기면 뜻이 사라진다.

## 카탈로그를 고치려면

`locales/*.ts` 는 생성물이지만, 이 저장소에서 값을 직접 고쳐도 된다 — 키는 그대로 두고 값만 바꾸면 된다.
키를 새로 만들거나 지우는 일은 마크업·소스의 `data-i18n`·`t()` 와 함께 바꿔야 한다.

## 언어를 추가하려면

1. `locales/<코드>.ts` 를 만든다(`ko.ts` 와 같은 모양, 값만 그 언어로).
2. `core.ts` 의 `Locale` 과 `SUPPORTED` 에 코드를 더한다.
3. `index.ts` 에서 그 카탈로그를 `registerCatalog` 로 등록한다.

없는 키는 자동으로 원문(ko)으로 물러나므로, 일부만 번역한 상태로도 쓸 수 있다.

## 이 기능을 걷어내려면

이 폴더와 표시만 지우면 된다. 다른 코드에 남는 것은 없다.

```sh
rm -rf src/i18n tests/i18n-*.test.ts tests/support/i18n-text.ts
# index.html 의 data-i18n* 속성 제거 (원문 텍스트는 마크업에 그대로 있다)
# src/ui 의 t('키') 를 ko 카탈로그의 값으로 되돌림
# src/main.ts 의 initI18n() 호출 2줄 제거, src/engine/header-footer-mode.ts·src/view/canvas-view.ts 의 t() 되돌림
```

`index.html` 은 표시를 떼면 원문과 **바이트 단위로 같아진다.** 원문 텍스트를 마크업에서 지우지 않는
이유가 이것이다 — 스크립트가 로드되기 전 첫 페인트에도 한국어가 정상으로 보이고, 되돌리기도 쉽다.

## e2e 를 돌릴 때

e2e 는 한국어 라벨로 단추를 찾는다(`'확인'`, `'취소'`). 로케일은 `localStorage['rhwp-locale']` 에
남으므로, 개발자 브라우저에서 영어를 골라 둔 채 호스트 모드 e2e 를 돌리면 단추를 못 찾는다.
`?lang=ko` 를 URL 에 붙이거나 그 키를 지운 뒤 돌린다. 헤드리스 모드는 새 프로필이라 영향 없다.
