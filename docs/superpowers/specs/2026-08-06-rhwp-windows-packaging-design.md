# rhwp Windows 패키징 설계

- 날짜: 2026-08-06
- 상태: 승인 대기 (브레인스토밍 완료, 사용자 최종 리뷰 전)

## 배경과 목적

`rhwp`(https://github.com/edwardkim/rhwp)는 Rust + WebAssembly 기반 오픈소스 HWP/HWPX 뷰어·에디터다.
현재 배포 형태는 다음과 같다.

- CLI 바이너리(`rhwp.exe`) — GitHub Releases에서 Windows x86_64 zip으로 이미 배포 중 (`rhwp-v0.8.2-windows-x86_64.zip`, 설치 프로그램 없이 exe+README만 압축)
- `rhwp-studio` — Vite + WASM 기반 GUI 뷰어/에디터. 현재는 웹앱(PWA)으로만 존재하고, Tauri/Electron 같은 네이티브 데스크톱 셸은 없음
- 브라우저 확장(Chrome/Firefox/Safari), VS Code 확장은 별도 배포 채널로 존재

이 프로젝트의 목적은 `rhwp-studio`를 Windows 데스크톱 앱으로 패키징해 사내 직원들에게 배포하는 것이다.
일반 직원은 CLI를 사용하지 않으므로, GUI 뷰어/에디터를 앱 형태로 만드는 것이 목표다.

## 확정된 요구사항

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 앱 형태 | GUI 뷰어/에디터 앱 | CLI(`rhwp.exe`)는 이미 별도로 배포 중이므로 이번 범위에서 제외 |
| 배포 방식 | 수동 배포 (공유폴더/메일/사내 포털) | 중앙 배포(Intune/SCCM/GPO)는 사용하지 않음 |
| 코드사이닝 | 자체 서명(Self-signed) 인증서 | 상용 인증서 구매나 Microsoft Trusted Signing은 사용하지 않음 |
| 인증서 신뢰 배포 | 설치 과정에 포함 | 사내에 AD/GPO 일괄 배포 체계가 없으므로, 인증서 신뢰 등록을 설치 스크립트 안에 포함해 직원이 별도 조작 없이 진행되게 함 |
| 업데이트 방식 | 수동 재배포 | 새 버전이 나오면 새 설치 파일을 다시 공유. 앱 내 자동 업데이트 기능은 만들지 않음 |
| 파일 연결 | 설치 시 `.hwp`/`.hwpx` 연결 포함 | 강제 덮어쓰기가 아니라 설치 마법사에서 선택 가능한 체크박스로 제공 |

## 검토한 접근 방식

### 1. Tauri로 `rhwp-studio`를 감싸는 데스크톱 앱 (채택)

기존 `rhwp-studio`(Vite 프로젝트)의 빌드 산출물을 Tauri 셸로 감싼다. 새 프론트엔드를 만들 필요가 없고,
Windows 내장 WebView2를 재사용하므로 Electron 대비 설치 용량이 훨씬 작다. MSI/NSIS 설치 파일 생성이
가능하고 완전 오프라인으로 동작한다.

### 2. CLI 바이너리 단독 배포

이미 GitHub Releases에 존재하는 방식을 그대로 사용. 매우 가볍지만, 일반 직원이 터미널로 문서를 다루는
것은 비현실적이므로 이번 목적(GUI 뷰어 제공)에는 맞지 않는다. CLI는 이번 범위에서 다루지 않는다.

### 3. Electron/Nativefier로 외부 공개 데모(`edwardkim.github.io/rhwp`)를 감싸는 방식

몇 분 만에 실행 파일을 뽑을 수 있지만, 외부에서 호스팅하는 공개 데모 사이트에 의존하게 되어 가용성·
업데이트 시점·보안 정책을 회사가 통제할 수 없다. 사내 배포용으로는 부적합하다고 판단해 기각.

**결론:** 접근 방식 1(Tauri + 저장소 내 `rhwp-studio` 빌드 산출물)을 채택한다.

## 아키텍처

```
rhwp (기존 저장소)
├── rhwp-studio/          ← 기존 웹앱 (수정 최소화)
│   └── dist/              ← vite build 산출물 (HTML/JS/WASM)
└── rhwp-studio/src-tauri/ ← 신규: Tauri 셸 (Rust 프로젝트)
    ├── tauri.conf.json    ← 창 크기, 아이콘, 번들 설정
    ├── src/main.rs        ← 최소 진입점 (커스텀 백엔드 로직 없음)
    └── icons/
```

- Tauri는 Windows에서 OS 내장 WebView2를 사용하므로 Electron처럼 브라우저 엔진을 통째로 번들링하지
  않아도 된다 → 설치 용량이 Electron 대비 대폭 작음.
- 문서 열기/저장은 전부 클라이언트(WASM)에서 처리되는 기존 구조를 그대로 유지 — 네트워크 연결 없이
  완전 오프라인 동작.
- `vite-plugin-pwa`가 등록하는 서비스워커는 데스크톱 빌드에서는 불필요하고 캐시 충돌 위험이 있으므로,
  Tauri용 빌드에서는 비활성화한다.

## 구성요소 (설치 패키지 내용물)

NSIS 기반 설치 파일(`.exe`) 하나에 다음이 포함된다.

1. **rhwp-studio 앱 본체** — Tauri로 감싼 실행 파일. 기존 웹앱과 동일한 뷰어/에디터 UI.
2. **자체 서명 인증서 등록 스텝** — 설치 스크립트 안에서 인증서를 Windows "신뢰할 수 있는 게시자"
   저장소에 자동 등록 (관리자 권한 필요, UAC 프롬프트 1회). 직원이 별도 스크립트를 실행할 필요 없음.
3. **파일 연결(.hwp/.hwpx)** — 설치 시 레지스트리에 등록되어 탐색기 더블클릭으로 바로 열림. 기존에
   한글과컴퓨터 프로그램이 설치돼 있으면 그 연결을 덮어쓰게 되므로, "기본 프로그램으로 지정" 체크박스로
   선택하게 하고 강제 덮어쓰기는 하지 않는다.
4. **버전 표시** — 앱 정보 화면에 버전을 노출해, 직원이 자신이 설치한 버전을 확인할 수 있게 한다.

## 빌드·배포 파이프라인

릴리스마다 수동으로 실행하는 절차:

```
1. rhwp 저장소에서 wasm-pack build (기존 절차, pkg/ 생성)
2. rhwp-studio: npm run build (데스크톱 빌드에서는 PWA 플러그인 비활성화)
3. rhwp-studio/src-tauri: npm run tauri build
   → src-tauri/target/release/bundle/nsis/ 에 설치 파일(.exe) 생성
4. 생성된 설치 파일에 자체 서명 적용 (signtool)
5. SHA256 체크섬 생성 → 무결성 확인용으로 함께 배포
```

- CI 자동화는 이번 범위에서 제외한다(배포/업데이트가 수동이라는 결정과 일관됨). 필요하면 릴리스
  담당자가 로컬 또는 GitHub Actions를 수동 트리거하는 정도로 충분하다.
- 기존 CLI 릴리스(`rhwp-v*-windows-x86_64.zip`)와 혼동하지 않도록 산출물 파일명을 구분한다
  (예: `rhwp-studio-setup-v0.8.2.exe`).
- 서명에 쓰는 자체 서명 인증서의 개인키는 저장소에 커밋하지 않고, 릴리스 담당자 로컬 또는 사내 비밀
  저장소에 보관한다.

## 에러 처리 및 엣지 케이스

- **인증서 미신뢰 상태에서 실행**: 인증서 등록 스텝이 실패(UAC 거부 등)해도 앱 설치 자체는 계속
  진행되게 한다. 최초 실행 시 SmartScreen 경고가 뜨면 "추가 정보 → 실행"으로 우회할 수 있다는 안내를
  설치 완료 화면에 표시한다.
- **기존 한글과컴퓨터 프로그램과의 파일 연결 충돌**: 체크박스로 선택하게 하고(구성요소 3항), 언인스톨
  시에는 연결했던 확장자를 원래대로 복원하지 않는다(Windows 표준 동작 — 별도 복원 로직을 만들지 않음).
- **구버전이 이미 설치된 상태에서 재설치**: NSIS 설치 파일이 동일 설치 경로를 사용해 새 버전 설치 시
  자동으로 이전 버전을 덮어쓴다. 별도 언인스톨 안내 없이 새 설치 파일 실행만으로 업데이트된다.
- **WebView2 미설치 환경**: 최신 Windows 10/11은 기본 내장이지만, Tauri의 표준 옵션(설치 파일에
  WebView2 부트스트래퍼 포함)을 사용해 별도 안내 없이 자동 설치되게 한다.

## 테스트 계획

- **빌드 검증**: `npm run tauri build` 산출물을 Windows 환경(VM 또는 실제 PC)에서 설치·실행·제거까지
  한 사이클 확인.
- **핵심 기능 회귀**: 기존 `rhwp-studio`의 e2e 테스트(`npm run e2e:*`)는 브라우저 기준이므로 Tauri
  창에서 재실행하지 않는다. 대신 저장소 `samples/`의 실제 HWP/HWPX 샘플 파일을 열기/편집/저장하는
  수동 스모크 테스트로 대체한다.
- **설치 시나리오 테스트**: (1) 신규 설치, (2) 구버전 위 재설치(업그레이드), (3) 파일 연결 체크박스
  켠/끈 상태 각각, (4) 인증서 미신뢰 상태에서 SmartScreen 경고 우회 흐름.
- **직원 대상 파일럿**: 전사 배포 전 소수 인원(예: IT팀 또는 지원자) 대상으로 먼저 배포해 설치 안내문의
  이해도와 실제 설치 성공률을 확인한 뒤 전체 배포.
- CI 기반 자동 테스트는 범위에 넣지 않는다 — 배포/업데이트가 수동이라는 결정과 일관되게, 릴리스마다
  위 체크리스트를 수동으로 확인하는 정도로 충분하다고 판단했다.

## 범위 밖 (Out of scope)

- 앱 내 자동 업데이트 기능 (Tauri updater, 업데이트 서버/매니페스트 호스팅)
- 중앙 배포 체계 연동 (Intune, SCCM, GPO를 통한 일괄 설치/인증서 신뢰 배포)
- 상용 코드사이닝 인증서 또는 Microsoft Trusted Signing 도입
- CLI(`rhwp.exe`) 배포 변경 — 기존 방식 유지
- CI를 통한 Windows 설치 파일 자동 빌드/릴리스
