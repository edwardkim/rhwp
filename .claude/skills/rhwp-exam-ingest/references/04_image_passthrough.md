# 04 — 이미지 패스스루

PNG/JPG/WEBP 한 장(또는 여러 장)은 변환하지 않는다. 그 파일이 곧
Vision 입력이다. PDF helper 를 거치지 않는다.

## 언제

- 사용자가 "이 사진 시험지를 HWPX 로" 하고 `.png`/`.jpg` 를 첨부.
- 폰으로 찍은 책상 위 시험지.
- 이미 페이지별로 잘라 둔 `p1.png` `p2.png`.

## 절차

1. `check_deps.sh` — ImageMagick 은 crop 이 있을 때만 필수.
   텍스트만 옮기고 그림을 버리면 magick 없이도 진행 가능하다 (F02).
2. 파일을 Read tool 로 연다. 리사이즈 helper 를 만들지 않는다.
3. 너무 커서 모델이 거절하면, 기존 `magick` 으로 긴 변 2000px 리사이즈를
   **사용자 확인 후** 한 줄로 한다. 새 스크립트 금지.
4. 여러 장이면 정렬 키를 사용자에게 보여 준다.

```
p1.jpg, p2.jpg, p10.jpg  →  사전식이면 p10 이 p2 앞.
에이전트는 숫자 순(1,2,10)으로 읽고, 순서를 한 줄로 확인한다.
```

5. 문항 bbox 는 **그 이미지의 픽셀** 이다. PDF 포인트나 mm 가 아니다.
6. crop 출력만 `$MEDIA_DIR/img/` 로 보낸다. 원본 페이지는 media 에
   넣지 않는다 (시험지 전체 사진을 문항마다 박으면 안 된다).

## 패스스루가 아닌 것

| 입력 | 이유 |
| --- | --- |
| PDF | `pdf_to_pngs.sh` |
| DOCX 안의 그림 | `extract_docx.py` 가 이미 꺼냄. 그건 임베디드 추출 |
| MD 의 `![](fig.png)` | 05_md_image_refs — 경로 복사 규약 |
| TIFF 다중 페이지 | 이 helper 집합이 지원하지 않음. PDF 또는 PNG 시퀀스를 요청 |

## 사진 촬영 함정

- 기울기: 원근 보정 helper 는 없다. 심하면 재촬영 요청 (F10).
- 그림자·손가락: 문항 번호가 가려지면 그 문항을 건너뛰고 보고한다.
- 손글씨 답: ingest 에 넣지 않는다. 문제 지문만.
- 플래시 반사로 그래프 눈금이 사라짐: 그 그래프는 crop 하지 말고
  한계를 고지한다.

## 좌표계

`crop_image.sh` 의 `(x,y,w,h)` 는 패스스루 이미지의 좌상단 픽셀.
Vision 이 "대략 중간" 이라고만 하면 crop 하지 않는다. 숫자를 못 정하면
이미지 전체를 media 로 넣지 말고, 사용자에게 bbox 를 묻거나
텍스트만 진행한다.

픽스처: `fixtures/helpers/image_passthrough.json`.
