# 16. 커버리지는 표(코드)로만 늘어난다

자동 처리 비율을 올리는 유일한 방법은
`ROUTING_TABLE` 에 행을 추가하고 같은 PR 에서 핸들러와 게이트를 넣는 것이다.

## 허용되는 성장

1. 관측: 같은 needs-agent reason 이 두 번 (C13)
2. 정의: goal 문자열 + 필요 명령 + 검증 게이트
3. 구현: `goal_*` + docstring `needs:` + playbook §4 행
4. 시험: 픽스처 큐 + 계약 테스트에 그 goal 을 한 줄 더함

## 허용되지 않는 성장

- 프롬프트에 "요약 요청은 export-text 로 처리해"
- 유사도 / 임베딩 / LLM 분류기로 goal 을 메꿈
- 증상 문장 정규식으로 표 밖 문자열을 표 안으로 접기
- 핸들러는 있는데 playbook 표가 없음 (또는 반대)

## 지금 표에 없는 후보 (넣지 말 것 — 관측 전)

| 자주 오는 말 | 왜 아직 없는가 |
| --- | --- |
| 요약 | 검증 게이트가 "좋은 요약"이 아님. Strategist/doc-triage 층 |
| 번역 | 명령 없음 |
| 직인 | `insert-image` 좌표가 요청에 있어야 하고 표 설계가 안 끝남 |
| 메일머지 N행 | `batch fill` 은 존재하나 Chief 핸들러·게이트가 없음 |
| 한컴 대조 | 별도 스킬. 큐 goal 로 묶지 않음 |

후보를 이 장에 적는 것은 구현이 아니다. C13 이 두 번 울리기 전에는 행을
만들지 않는다.
