# 시각 검증: 실제 출력으로 주장 확인

정본은 [CONTRIBUTING.md](../../../../CONTRIBUTING.md)와
[시각 검증 정책](../../../../mydocs/manual/verification/visual_verification_governance.md)다.
메인터너의 증적 보관은
[visual_fixture_evidence.md](../../../../mydocs/manual/pr_review/visual_fixture_evidence.md)를 따른다.

## 비교할 것

조판 영향 변경은 Native/fresh WASM Visual Sweep과 검증 범위의 페이지별 TSV가 필수다.
**명령·저장 위치:** [「실루엣 보조값만 빠르게 TSV 산출」](../../../../mydocs/manual/verification/visual_sweep_guide.md#실루엣-보조값만-빠르게-tsv-산출)의 Native/fresh WASM 예제를 각각 실행한다.
편집 command·parser·model·serializer도 줄·높이·정렬·개체 배치·쪽 분할·인쇄 모양에 영향을 주면
적용한다. renderer 파일 무변경, SVG 자기 비교나 구조 회귀 통과는 면제 사유가 아니다.
한 페이지라도 **90% 미만** 또는 측정 불가이면 본인 branch에서 PDF/overlay 원인을 재검토·수정하고
새 head에서 재실행한다. 정확히 90%는 통과한다. 평균값·단순 글꼴 추정으로 면제하지 않는다.
올바른 공급으로 해결 불가능한 실제 글꼴 차이는 [예외 계약](../../../../mydocs/manual/verification/visual_sweep_guide.md#해결-불가능한-글꼴의-pr-제출-예외)의
증거와 `font_mismatch_exception`으로 90% 미만이어도 PR 제출이 가능하다. TSV 원값을 유지하고
측정 누락·쪽수 불일치·배치 차이는 면제하지 않는다.
쪽수·분할 변경은 전체 문서를 비교하고 다른 변경도 영향 페이지와 경계를 빠짐없이 포함한다.
TSV와 실행 로그는 ignored output에 보존하고 Git에 커밋하지 않으며 본문에 명령·출처·최저값·미달 쪽을 기록한다.

- 렌더링/레이아웃 변경은 동일한 입력의 기준 출력과 변경 전후 실제 출력을 비교한다.
- 입력과 대응하는 유효한 한컴 PDF는 기준으로 사용할 수 있다. 버전, 폰트, 출처와
  pdfinfo를 기록하고 대응 여부를 판단한다. PDF 버전 숫자만으로 폐기하거나 다시 출력하지 않는다.
- 페이지 번호만 맞추지 말고 실제 내용으로 페이지/영역을 대응시킨다.
- 대표 페이지와 문제가 드러나는 확대 영역을 직접 본다. 겹침, 누락, 줄바꿈, 차트 종류/축,
  정렬 등 변경이 해결한다고 주장한 내용을 확인한다.
- 90% 이상이어도 변경 영역·알려진 차이·사용자 지적 영역을 독립 Print PDF와 변경 전·후
  Native/fresh WASM의 같은 배율로 확대한다. 수식 모양·장평·정체/이탤릭·기준선·첨자·화살표·장식과
  관계 기호 양쪽·앞뒤 본문·보기 번호·탭·줄 사이 간격을 확인한다. 점수와 직접 판독을 구분하고
  확인된 결함은 출력 보정·재검증 후 완료·회귀 추가/변경 여부를 판정한다. 상세 절차는
  [90% 통과 후 확대 판독](../../../../mydocs/manual/pr_review/visual_fixture_evidence.md#90-통과-후-수식간격의-확대-판독)을 따른다.
- 페이지 수, 텍스트 해시, bbox, 픽셀 점수는 보조 증거이며 실제 출력 비교를 대신하지 않는다.
- 변경된 조건이 적용되면 안 되는 일반 객체와 혼재 사례에서도 부작용이 없는지 확인한다.

## 페이지별 TSV와 PR 재검토 필수 조건

조판·렌더링에 영향을 주는 변경은 **검증 대상 각 문서의 전체 페이지 TSV를 먼저 산출**한다.
`tolerant_content_match_percent`(2px 이웃 관용 내용 실루엣 일치율)를 페이지별로 확인하며,
**한 페이지라도 90% 미만이면 PR을 재검토한다.** 평균값이나 대표 페이지의 높은 점수로
미달 쪽을 상쇄하지 않는다. 정확히 90%는 통과한다.

`re_review_required` 상태에서는 새 PR 생성과 열린 PR의 승인·통합을 보류한다.
작성자는 원본·독립 한컴 Print PDF·overlay를 대조해 원인을 수정하고 새 head에서 다시 산출한다.
누락·측정 불가·전체 쪽수 불일치도 보류 조건이다. 모든 페이지가 90% 이상이어도
변경 영역의 수식·미세 간격을 확대 판독한 뒤 완료 여부를 판단한다.

전체 페이지 Native TSV와 fresh WASM TSV를 모두 `--page`·`--pages` 없이 산출·첨부하고,
대표 PNG 생성에만 쪽을 선택한다.
명령은 [TSV 산출 절차](../../../../mydocs/manual/verification/visual_sweep_guide.md#실루엣-보조값만-빠르게-tsv-산출)를 따른다.
정식 글꼴 예외는 같은 가이드의 [예외 계약](../../../../mydocs/manual/verification/visual_sweep_guide.md#해결-불가능한-글꼴의-pr-제출-예외)으로만 처리한다.

## 범위와 보관

파서 구조 보존만 주장하는 변경에 전체 출력의 픽셀 일치를 일괄 요구하지 않는다.
반대로 렌더링 개선을 주장하면서 구조 테스트만 통과한 결과를 시각 성공으로 기록하지 않는다.

기존의 유효한 기준 PDF를 재사용하고, 기준/입력의 식별 정보와 렌더 명령, 검증 SHA, 비교 범위를 기록한다.
보존용 대표 증거는 현재 역할의 증적 정책을 따른다.
로그, bbox HTML, 진단 JSON과 중간 이미지는 ignored output에 두며 무더기로 커밋하지 않는다.
## 일반 기여자의 버전별 PDF 제출

일반 기여자는 메인터너 MCP를 사용할 수 있다는 전제로 작업하지 않는다.
기준 PDF가 필요한 렌더링 검증에서는 본인의 한컴 오피스로 원본 HWP/HWPX를 열어
원본 저장 버전에 맞는 한컴에서 **파일 → 인쇄(Print) → PDF 출력**으로 만들고 PR 또는 관련 issue에
원본과 함께 첨부한다. PDF 저장/내보내기로 대신하지 않는다.
[인쇄 계약과 MCP 2020/2024 선택](../../../../mydocs/manual/mcp_hwp2024Convert_usage.md#기준-pdf-인쇄-계약)을 따른다.
편집 변경도 동일하게 편집한 저장본을 Print 출력한다. 기준 PDF 부족은 미검증이며 비해당이 아니다.

- 여러 한컴 버전의 동작을 주장하거나 비교 대상으로 삼으면 해당 버전별 PDF를 각각 제출한다.
  예를 들어 2020/2022/2024 비교라면 실제 각 제품에서 출력한 파일을 구분한다.
- 파일명은 `원본stem-2020.pdf`, `원본stem-2022.pdf`, `원본stem-2024.pdf`처럼
  실제 출력 제품 버전을 사용한다. 메인터너 MCP의 engine bucket을 직접 출력본에 적용하지 않는다.
- 한컴 제품 버전/빌드, OS, 폰트, 출력 방법과 대응 원본을 본문에 기록한다.
  PDF format version과 한컴 제품 버전을 혼동하지 않는다.
- 해당 원본과 버전의 유효한 첨부 PDF가 이미 있으면 재사용하며 동일 파일을 다시 만들지 않는다.
- 필요한 한컴 버전을 사용할 수 없으면 그 버전의 검증은 미완료로 기록한다.
  다른 버전 출력이나 파일명 변경으로 대신하지 않는다. 권한 있는 메인터너의 보완 검증은 별도 절차다.

저장소에 포함할 때는 CONTRIBUTING의 `pdf/{원본 stem}-{한컴버전}.pdf` 보존 규칙을 따른다.
비공개 자료를 공개 첨부하거나 MCP 인증 정보와 중간 산출물을 제출하지 않는다.

## 렌더링 회귀 신규 추가 조건

[회귀 추가 선행 조건](../../../../mydocs/manual/pr_review/visual_fixture_evidence.md#렌더링-회귀-테스트-신규-추가의-시각-검증-선행-조건)을 따른다.
관련 모든 페이지·fixture·Native/fresh WASM의 최저 일치율이 90% 미만이거나 측정 불가이면 새 회귀
테스트·fixture/golden을 추가하지 않는다. 쪽수 검사는 전체 페이지를 비교하고 실제 출력을 개선한 뒤
재검증한다. 평균값·글꼴 예외·CI 성공으로 면제하지 않으며 기존 검사는 자동 삭제하지 않는다.

## 실패한 기존 렌더링 회귀의 변경

**원 회귀의 원본 입력 출력 보정 → 버전에 맞는 독립 한컴 Print PDF와 Native/fresh WASM의 관련
모든 페이지에서 90% 이상 확인 → 독립 기대값에 따라 필요한 검사 변경** 순서로 진행한다.
쪽수 검사는 전체 페이지가 대상이며 미달·측정 불가이면 테스트·기대값·baseline 변경을 보류한다.
기존 px 고정 검사를 바꾸는 경우에도 이 선행 조건을 충족한 뒤 문단·줄·개체의 소유·순서·보존·
포함·겹침 관계로 검사한다. 절대 px 좌표·고정 px 영역으로 배치를 선택·고정하지 않는다.
원본과 실패 증거를 보존하고 글꼴 예외로 이 조건을 면제하지 않는다. 상세 절차는
[기존 기대값 재검토](../../../../mydocs/manual/pr_review/visual_fixture_evidence.md#기존-회귀-테스트의-기대값-재검토)를 따른다.
