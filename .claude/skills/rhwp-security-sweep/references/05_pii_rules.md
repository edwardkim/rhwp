# PII 보수 규칙 — ssn / card / phone / email

권위는 `mydocs/manual/cli_commands.md` 의 해당 절과 레시피 3·4·10 이다.
이 장은 기존 CLI 를 설명하고 소비 규칙을 고정한다. 새 명령·새 탐지 규칙을 발명하지 않는다.
## 원칙

마스킹은 되돌릴 수 없다. 오탐은 본문 훼손이다.

형태가 맞아도 검증을 통과하지 못하면 탐지하지 않는다.

이 장은 기존 `document_core::queries::pii_scan` 계약을 문서화한다. 규칙을 넓히지 않는다.

## ssn

형태: `######-#######` (하이픈 필수).

추가 검증: 생년월일 실재(윤년 포함) + 성별/세기 코드 1~8 + mod 11.

레시피 3: `900101-1234568` 탐지, `900101-1234567` 미탐(미끼).

하이픈 없는 13자열, 월 13, 2월 30, 성별 코드 0/9 는 탐지하지 않는다.

## card

형태: `4-4-4-4`(`-` 또는 공백), Amex `4-6-5`, 연속 15·16자리.

추가 검증: Luhn. 앞뒤가 숫자면 더 긴 토큰의 일부로 보고 버린다.

레시피 3: `4111-1111-1111-1111` 탐지, `1234-5678-9012-3456` 미탐.

13·14·19자리 카드는 v1 범위 밖.

## phone

형태: `01[016789]-3~4자리-4자리` 또는 `02-3~4자리-4자리`.

하이픈 필수. `01012345678` 은 잡지 않는다.

031·051 등 02 외 지역번호는 v1 범위 밖 — 문서번호와 구별 근거가 없다.

그 부류가 걱정이면 `search` 로 좁혀 사람이 확인한다.

## email

형태: 지역부@라벨(.라벨)+ .

라벨 2개 이상 + TLD 영문 2자 이상.

`hong@localhost` (라벨 1) · `hong@example.c` (TLD 1자) 는 거부.

레시피 3: `hong@example.com` 탐지.

## 범위 밖 (절대 여기서 발명하지 말 것)

- 이름, 주소, 사번, 여권, 계좌

- 그림·개체 안 텍스트 (본문 치환 경로 밖)

- 머리말/꼬리말·각주 필드 사각지대는 fields 재귀 한계와 같다

필요하면 `edit replace-text` 를 사람이 지목해서 쓴다. 탐지기를 느슨하게 만들지 않는다.

## 픽스처

기계 사례는 `fixtures/pii_cases.json` 이다. 각 행의 detect 값은 위 계약의 기대다.

테스트는 그 표를 읽고 스킬·레퍼런스가 같은 예외를 말하는지만 본다.

새 Luhn 구현을 테스트에 넣지 않는다.
