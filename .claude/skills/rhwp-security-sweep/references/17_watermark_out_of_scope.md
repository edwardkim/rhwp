# inspect watermark — 이 스킬의 비범위

권위는 `mydocs/manual/cli_commands.md` 의 해당 절과 레시피 3·4·10 이다.
이 장은 기존 CLI 를 설명하고 소비 규칙을 고정한다. 새 명령·새 탐지 규칙을 발명하지 않는다.
## 존재하는 명령

`inspect watermark <파일> [--json] [--kind hidden|homoglyph|whitespace|all]`

제로폭·동형자·비정상 공백 열처럼 은닉 추적 신호를 위치·개수와 함께 보고한다.

비트열로 해석 가능한 비가시 문자 열은 ASCII 후보도 함께 낸다.

## 왜 최소 경로에 넣지 않는가

이 이슈의 3축은 hidden-text / injection / unicode 다.

워터마크 축은 보고만 하고 **제거·우회 기능을 제공하지 않는다.**

에이전트가 '마크를 지워' 요청을 수행하면 범위 밖이다. 거부한다.

## 신호가 나와도

도구 실패가 아니다. 원본 보존·사람 검토·출처 확인을 위한 자료다.

exit 0 + 신호 = DATA. 3축과 같은 종료 코드 철학.

## unicode 와의 겹침

제로폭·동형자는 unicode 축과 개념이 겹친다.

배포 전 최소 경로는 unicode 로 화면-바이트 불일치를 묻는다.

추적 마크 분석이 별도 요청일 때만 watermark 를 언급한다.

## 하지 않는 것

- 워터마크 제거 명령 발명

- 우회·은닉 강화 조언

- gym 워터마크 과제 확장

## 사용자 발화 → 거절

| 발화 | 응답 |
|---|---|
| 워터마크 지워줘 | 제거 기능이 없다. inspect watermark 는 보고만 한다. |
| 추적 마크 우회해줘 | 거부. 이 스킬의 일이 아니다. |
| 숨은 마크 있나 | 3축 unicode/hidden 으로 화면-바이트·은닉을 먼저 묻는다. watermark 는 별도 보고. |

## 3축과의 경계

배포 전 게이트는 hidden + injection + unicode + redact dry-run 이다.
watermark 신호를 게이트 술어에 넣지 않는다. 넣으면 제거 없는 축이 배포를
영구히 막거나, 반대로 우회 유혹을 만든다.
