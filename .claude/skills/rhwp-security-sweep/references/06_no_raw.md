# 자동화 기본값 — --no-raw

권위는 `mydocs/manual/cli_commands.md` 의 해당 절과 레시피 3·4·10 이다.
이 장은 기존 CLI 를 설명하고 소비 규칙을 고정한다. 새 명령·새 탐지 규칙을 발명하지 않는다.
## 문제

`findings[].raw` 는 원문 개인정보 그 자체다.

감사를 위해 기본 봉투에 실렸지만, 로그·이슈·채팅에 그대로 붙이면 유출 경로가 된다.

마스킹하려던 값이 점검 로그에 남는 사고다.

## 두 기본값

| 소비자 | 기본 | 이유 |

|---|---|---|

| CLI 계약 | raw 포함 | 기존 스크립트·사람 검토를 깨지 않음 |

| 이 스킬의 자동화 | `--no-raw` | 봉투가 파이프로 흘러감 |

에이전트는 스킬 기본을 따른다. CLI 플래그 기본을 바꾸라는 요청이 아니다.

새 플래그를 만들지 않는다.

## 계약

`--no-raw` 를 주면 `findings[].raw` 필드 자체가 빠진다. `null` 이 아니다.

`noRaw: true` 가 명시된다. `kind`/`masked`/`section`/`paragraph`/`page`/`charOffset` 은 남는다.

위치·건수 검토는 그대로 되고 원문은 없다.

## 로그 게이트

자동화 스크립트는 dry-run 봉투를 붙이기 전에 다음을 확인한다.

```bash

rhwp edit redact 초안.hwp --dry-run --no-raw --json \

  | jq -e '.noRaw == true and (any(.findings[]; has("raw")) | not)'

```

실패하면 그 봉투를 이슈 본문에 붙이지 않는다.

## 사람이 원문이 필요할 때

로컬 터미널에서 `--no-raw` 없이 dry-run 할 수 있다.

그 출력은 채팅·티켓·CI 로그로 복사하지 않는다.

`--no-raw` 는 봉투에서 원문을 빼는 옵션이지 문서 마스킹 범위를 바꾸지 않는다.

## 금지

- raw 가 있는 봉투를 `gh issue comment` 에 붙이기

- raw 를 파일 이름·커밋 메시지에 넣기

- raw 를 다음 도구 인자로 넣기
