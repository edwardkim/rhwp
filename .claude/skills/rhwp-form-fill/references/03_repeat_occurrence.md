# 03 — 반복 필드 `이름[순번]`

규제영향분석서·사업계획서·평가표는 `성명`·`날짜`·`피규제집단명` 처럼 **같은
이름**이 여러 번 나온다. `samples/80168_regulatory_analysis.hwp` 는 누름틀
1,070개에 고유 이름이 151개이고 `피규제집단명` 이 14번이다.

이름만 주면 **첫 매치만** 바뀐다. 그 사실을 `ambiguous` 로 알려주지 않으면
에이전트는 14개 중 1개만 채워진 문서를 완성본으로 제출한다. 제출 실패는
문서가 깨져서가 아니라 빈칸이 남아서 일어난다.

계약: #3476, `tests/edit_field_occurrence_contract.rs`.

## 문법

```
{"피규제집단명[0]":"…","피규제집단명[13]":"…"}
```

- 순번은 **0 기준**
- 순서는 `fields --json` 목록에서 그 이름이 나오는 순서
- 범위를 벗어나면 `notFound` 에 그 키가 실린다 (`이름[14]` on 14개)
- 음수·공백·`이름[]` 를 해석하는 확장 문법은 없다

순번 없는 키:

- 첫 매치를 채운다 (종전 동작)
- 같은 이름이 여러 곳이면 `ambiguous: [{name, matched, total}]`

`ambiguous` 가 비어 있지 않으면 **아직 끝난 게 아니다.**

## 조사

```bash
rhwp fields 분석서.hwp --json | jq -r '.fields[] | .name' | sort | uniq -c | sort -rn
```

`field-01.hwp` 의 `목차1` 은 5회다. 단건으로 `"목차1":"가"` 만 주면
occurrence 0 만 바뀌고 ambiguous 가 남는다.

올바른 키:

```json
{
  "목차1[0]": "배경",
  "목차1[1]": "목적",
  "목차1[2]": "범위",
  "목차1[3]": "일정",
  "목차1[4]": "예산"
}
```

고유 이름(`회사명`)은 인덱스가 필요 없다. `회사명[0]` 도 동작하지만
필수는 아니다.

## 판정 루프

```
1. fields --json 으로 이름별 횟수
2. 2회 이상인 이름은 전부 이름[0]…이름[n-1] 키를 준비
3. --dry-run
4. ambiguous 가 남아 있으면 빠진 순번을 추가
5. notFound 의 이름[k] 는 k 가 범위 밖 — 횟수를 다시 센다
6. 실행 --verify
7. 산출물을 fields 로 읽어 그 이름의 value 배열이 요청과 같은지 대조
```

7번의 재독은 occurrence 계약이 하는 일이다. 보고의 `filled[].occurrence`
만 믿지 않는다.

## 하지 말 것

| 유혹 | 왜 안 되나 |
| --- | --- |
| `성명1` `성명2` 키를 발명 | 문서 이름이 `성명` 이면 notFound |
| 1 기준 (`성명[1]` = 첫 칸) | 첫 칸은 `[0]` |
| 없는 순번에 맞춰 필드를 삽입 | 이 스킬은 누름틀을 만들지 않음 |
| 14칸을 `replace-text` 로 | 첫 본문 출현만 바뀌거나 과치환 |
| gym 과제로 14칸을 새로 채점 | 이 이슈 범위 밖 |

## 혼합 키

한 객체에 고유 키와 인덱스 키를 같이 넣는다.

```json
{
  "작성자": "홍길동",
  "날짜": "2026. 8. 18.",
  "성명[0]": "김가온",
  "성명[1]": "이서연"
}
```

`날짜` 가 문서에 3개면 이 객체는 첫 날짜만 채우고 ambiguous 를 남긴다.
날짜도 반복이면 `날짜[0]`… 로 고친다.

## 선택 표본이 없을 때

규제영향분석서 파일은 저장소에 없을 수 있다. 그때는 `field-01.hwp` 의
`목차1` ×5 로 같은 문법을 연습한다. 스킬이 샘플 바이너리를 생성하지
않는다.
