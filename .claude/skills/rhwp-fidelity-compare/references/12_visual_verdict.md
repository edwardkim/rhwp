# 12 — 최종 시각 판정은 유지자

`visual_verification_governance.md` 가 권위다. 이 장은 그 문서를
fidelity_compare 산출에 적용한다. 거버넌스를 이 폴더에 복사해
다시 쓰지 않는다.

핵심 문장:

> 자동 도구는 보조, 판정은 사람. **최종 시각 판정 권위는
> 작업지시자(한컴 2020/2022 편집기·PDF 정답지)** 이며 어떤 도구
> 통과도 이를 대체하지 않는다 (자기검증 ≠ 한컴 호환).

## 이 하네스가 말해도 되는 것

- "p12 가 픽셀 랭킹 1위 (4.82%) 다"
- "text-report 가 p18 소실 24자, p19 과잉 24자라 owner 이동 후보다"
- "시트를 `/tmp/.../cmp-p012.png` 에 남겼다"
- "glyph-risk 에 U+F02B1 이 있다"
- "run-state complete, provenance 는 한컴 2022 파일-PDF"

## 이 하네스가 말하면 안 되는 것

- "한컴과 동일하다 / 통과다 / merge 해도 된다"
- "diff% < 2 이므로 회귀 없다"
- "text-report 가 0 이므로 시각적으로 같다"
- "유지자 확인 없이 이슈를 Closed 로 바꾼다"
- "이 도구 통과가 한컴 호환 증명이다"

자기 라운드트립 `render-diff` PASS 도 한컴 호환이 아니다.
거버넌스가 이미 "자기검증 ≠ 한컴 호환" 이라고 쓴다.

## PR 에 붙일 때

렌더링 코어를 고친 PR 이 이 하네스를 돌렸다면:

1. provenance 블록
2. 범위와 모드 (`plan 0-34`, pixel 또는 text-only)
3. 상위 쪽 목록 + 시트 경로 (커밋한다면 거버넌스 파일명)
4. "후보이며 유지자 판정 대기" 한 문장
5. OVL 이 필요하면 거버넌스 도구 매핑의 다른 줄
   (`scripts/visual_sweep.py`, OVR) — 이 스킬이 그 도구를 재문서화하지 않음

도구/문서/CI 전용 PR (이 스킬 PR 이 그 유형) 은 시각 검증이
필수 가 아니다. 거버넌스 표: "도구 자체 스모크로 대체".

## 선택적 적용

거버넌스 원칙 1: 기계적 전수 금지. 215쪽 전수 시트를 모든 문서 PR 에
요구하지 않는다. 텍스트 전수 + 상위 쪽 시트 가 보통의 정직한 범위다.

원인·페이지가 이미 정해진 renderer PR 은 bug-hunter 가 아니라
거버넌스(이 문서의 상위) 가 지배한다. 이 하네스는 그때도 **후보
원장** 만 제공한다.

## 에이전트 점검표

- [ ] 판정 문장에 "후보" 또는 "유지자 대기" 가 있는가
- [ ] 절대 임계로 CI 를 빨강으로 만들지 않았는가
- [ ] 거버넌스 파일을 이 스킬이 수정하지 않았는가
- [ ] 시트를 작업지시자가 열 수 있는 경로로 남겼는가
