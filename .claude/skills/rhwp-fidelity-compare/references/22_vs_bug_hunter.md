# 22 — bug-hunter 여정과 다른 축

bug-hunter 는 **실사례 사용자 여정** 을 처음부터 끝까지 실행하고
한컴 공식 출력·법정 서식·제출 요건의 정답지와 대조해 결함을 찾는다.
방법론 스킬이다. 이 스킬은 그 여정의 **한 도구** 다.

거버넌스 표:

| 시작 조건 | 지배 절차 | fidelity_compare 역할 |
| --- | --- | --- |
| 기준 PDF 와 rhwp 가 다르다는 실제 결함, 원인 미확정 | bug-hunter | 쪽 랭킹·텍스트 원장으로 범위를 좁힘 |
| 원인·페이지가 확정된 renderer PR | 거버넌스 | 발동 쪽 시트 |
| 도구·문서 전용 | 직접 검증 | 보통 실행하지 않음 |

## 이 스킬이 하는 일 / 안 하는 일

한다:

- 공식 PDF 가 있을 때 하네스를 올바른 플래그로 호출
- 원장을 후보로 읽기
- provenance 를 남기기
- 여정이 필요하면 **bug-hunter 스킬로 인계**

안 한다 (F08):

- bug-hunter SKILL / playbook 을 이 폴더에서 재작성
- 여정 단계(접수→정답지→재현→원인→패치)를 여기 정지 표에 복제
- "버그 헌팅 스킬 고도화" 이슈를 이 PR 에 섞기

## 인계 문장

```
한컴 2022 PDF 대조 원장을 /tmp/rhwp-fidelity-issue-3738 에 남겼습니다.
p18→p19 text-owner-shift 와 page-count SVG+2 가 후보입니다.
원인·범위가 미확정이므로 bug-hunter 여정으로 넘깁니다.
이 스킬은 여정 문서를 수정하지 않았습니다.
```

원장 경로와 상위 쪽만 넘긴다. playbook 을 요약하며 잘못 적지 않는다.

## 무작위 스윕과의 차이

사용자가 "그냥 전체 샘플을 돌려 버그를 찾아" 라고 하면 이 스킬도
bug-hunter 도 **무작위 스윕이 목표라고 하지 않는다.** 등록 키 전수는
후보 수집이다. 법정 서식 여정이 필요하면 hunter 로 넘긴다.

gym 스윕은 둘 다 금지 (F06).
