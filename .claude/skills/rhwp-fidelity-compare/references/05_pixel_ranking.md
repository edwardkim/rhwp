# 05 — 픽셀 diff% 랭킹 (최악 쪽 우선)

`report.tsv` 는 시트 모드에서 `page`, `diff%`, `note` 세 열이고,
**diff% 내림차순** 으로 정렬된다. 가장 다른 쪽이 첫 행이다.

이 숫자는 **후보 검출** 이다. 보편적 절대 판정이 아니다. README 가
같은 문장을 이미 쓴다.

## 헤더와 정렬

```
page	diff%	note
12	4.82	-
7	3.91	-
28	3.40	-
```

`--text-only` 면 모든 행이 `not-run` 이고 요청 쪽 순서다. 랭킹이 없다.
텍스트 후보와 픽셀 랭킹을 한 파일에서 기대한 에이전트는 F02 를 다시 읽는다.

stdout 은 상위 8 쪽만 찍는다.

```
diff 랭킹(top 8):
  p12: 4.82%
  p7: 3.91%
```

8 위 밖을 보려면 TSV 를 연다. 요약만 보고 "나머지는 같다"고 하지 말 것.

## 왜 절대값이 아닌가

자간·힌팅·서브픽셀이 쪽 전체에 깔리면 구조가 같아도 수 퍼센트가 나온다.
`math` 실측은 수식 렌더가 강한데도 6~11% 였다. 그 구간을 "수식이 깨졌다"로
읽으면 오진이다. **순위 + 사람 감사** 가 한 쌍이다 (F03, F05).

같은 문서의 쪽 사이 비교가 의미 있다. p12 가 4.8% 이고 p1 이 1.0% 이면
p12 시트를 먼저 연다. 다른 문서의 4.8% 와 숫자로 겨루지 않는다.

## 음수·실패 행

SVG 가 없으면 `diff%` 가 `-1.0` 이고 note 가 `rhwp SVG 없음` 이다.
정렬이 이 행을 맨 위로 올린다. 그건 "가장 다른 쪽"이 아니라 **실행
실패** 다. `run-state.tsv` 의 missing 과 맞춰 읽고, 랭킹에서 제외한 뒤
남은 쪽만 본다 (F12).

`비교 시트 PNG 실패` 도 점수가 신뢰되지 않는다.

## 읽는 절차

1. `run-state` complete 확인
2. 두부 시트 여부 (F14) — 오염이면 랭킹 폐기
3. `-1.0` / 실패 행 격리
4. 상위 3~8 쪽 시트를 연다
5. 구조 차이만 이슈 초안
6. 프린지·폰트만이면 기록하고 승격하지 않음
7. 유지자에게 시트와 provenance 를 넘김 (F05)

## 게이트로 쓰지 말 것

```
# 금지 — 절대 임계로 CI 빨강
awk -F'\t' 'NR>1 && $2+0 > 2.0 { exit 1 }' report.tsv
```

이런 게이트는 자간 프린지에 항상 걸린다. 이 스킬은 merge gate 를
발명하지 않는다. visual-regression 의 `geom_inventory.tsv` status 열과
축이 다르다.

허용되는 기계 사용:

- 상위 N 쪽 목록을 사람 큐로 만들기
- 같은 `--out-dir` 전후 랭킹이 **같은 쪽** 을 가리키는지 보기
- missing 행이 생겼는지 보기

## 레시피 — 상위 쪽만 다시 시트

```bash
# TSV 에서 1-based page 를 읽는다
cut -f1 /tmp/rhwp-fidelity-plan/report.tsv | tail -n +2 | head -3
# 예: 12, 7, 28 → 0-based 11, 6, 27
venv/bin/python tools/fidelity_compare/fidelity_compare.py plan 11 11 \
  --out-dir /tmp/rhwp-fidelity-plan-p12
```

한 쪽씩 돌리면 시트가 섞이지 않는다. 범위를 넓히면 그 구간만 다시
정렬된다.
