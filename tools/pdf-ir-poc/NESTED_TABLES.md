# 상태머신과 중첩 표 인식 POC

## 범위

2026-10-14, `poc/pdf-ir`의 로컬 실험이다. 제품 parser/renderer와 Cargo workspace는
변경하지 않는다. 기존 기본 표 인식 EFSM을 유지하고, 중첩 격자의 위상 검증과 셀 합성,
내용 소유권을 확장한다. PDF에는 작성 당시의 표 객체가 없을 수 있으므로 결과는 추론이다.

## 기본 표 상태머신

`Searching → Candidate → Validating → GeometryConfirmed → RecognizingCells → Complete`.
격자·소유권·계층 검증이 실패하면 `Deferred`로 보류한다. 완료 뒤 자식이 보류되면
`HoldSubtree`로 연결된 가족 전체를 보류한다. 표 안 문단은 별도 EFSM과 context를 사용한다.
자식 표는 부모 셀 문단 인식의 장애물이며 그 앞뒤 문장을 하나의 문단으로 합치지 않는다.

## Algebraic Topology 적용

1. 축 방향 실선의 연결 성분에서 닫힌 외곽·분할·병합 셀을 구성한다. 선이 없는 곳을 임의로
   메우지 않는다. 각 셀 둘레가 실제 원본 획으로 덮여 있는지도 확인한다.
2. 교점/분할점을 0-cell, 경계의 기본 구간을 1-cell, 직사각형 셀을 2-cell로 만든다.
3. `F2` 계수에서 `C2 --d2--> C1 --d1--> C0`를 계산한다. 각 면의 경계에 `d1`을 적용한
   결과가 0인지 검사한다. `d2` rank는 sparse XOR 소거로 계산한다.
4. 연결 성분과 rank로 Betti 수를 계산하여 채워진 표 복합체의 `(b0,b1,b2)=(1,0,0)`를
   확인한다. 괘선 그래프의 cycle rank와 채워진 복합체의 `b1`은 다르다.
   정상 격자의 여러 순환은 셀 면으로 채워지므로 복합체의 구멍이 아니다.

이는 유한 셀 복합체의 정합성 검사다. 닫힌 다이어그램도 같은 위상을 가질 수 있으므로
호몰로지만으로 문서의 의미가 표임을 증명하지 않는다. 분할선·행/열/병합 조건도 필요하다.
셀 체인과 호몰로지의 수학적 근거는 [Hatcher, Algebraic Topology 제2장](https://pi.math.cornell.edu/~hatcher/AT/ATchapters.html)을 따른다.

## Operad 관점의 셀 합성

표를 순서 있는 셀 슬롯들의 연산, 자식 표를 해당 슬롯에 대입되는 연산으로 취급한다.
자식 격자는 검증된 부모 표의 **단일 셀 내부**에 엄격히 포함되어야 한다.
가장 가까운 부모를 선택하고, 슬롯 번호와 정규화된 affine embedding `(x,y,width,height)`를 기록한다.
3단계 중첩도 동일 규칙을 재귀적으로 적용한다. 형제 표는 서로 겹치지 않아야 한다.

단위 정사각형 embedding의 합성 `A(B(u))`를 구현하여 항등과 결합 법칙을 검사한다.
이는 [May, Multicategories Associated to Operads](https://www.math.uchicago.edu/~may/PAPERS/MultCat1.pdf)의
합성 관점에서 착안한 **제약된 공간 대입 모델**이다. 일반 operad의 모든 공리·대칭 작용이나
operadic homology를 구현한 것으로 주장하지 않는다. 포함 관계만으로 표 후보를 생성하지 않는다.

셀 경계 접촉·교차, 부모 슬롯 불명확, 비층상 교차는 보류한다. 부모와 연결된 획의 중첩 격자는
현재 연결 성분 검출기가 분리하지 못할 수 있으므로 지원하지 않는다. 작은 좌표 차이를 clamp하여
억지로 슬롯에 넣지 않는다. `EPS=0.5pt`는 기존 괘선 정규화 허용치다.

## 소유권과 출력 계약

- text/image는 가장 깊은 단일 셀에만 배정한다. 부모에는 자식 표 참조만 남긴다.
- 자식 격자의 분할선을 가로지르는 내용은 부모 셀로 우회 배정하지 않고 모호성으로 남긴다.
- 페이지/표/셀 context가 각 계층에서 분리되며 max_context_depth를 초과하면 가족을 보류한다.
- 보고서의 부모 선언을 신뢰하지 않고 recognition에서 셀 기하를 다시 대조한다.
- `--tables`는 확인된 가족을 실제 `Table → Cell → Paragraph → Table`로 재귀 생성한다.
  한 가족의 자식 생성이 실패하면 부모와 모든 자식의 객체화를 취소하고 원본 배치형
  글상자·그림·괘선 및 스타일 풀을 복구한다. 인식 성공과 한컴 조판 성공은 별도 판정이다.
- 기존 단일 표 객체화와 한컴에서 확인한 B본은 변경하지 않는다.

제한: 괘선 512개, 기본 tile 4096개, 표 후보 128개, 합성 깊이 16, 체인 incidence 65536개,
XOR 소거 작업 200만 개로 제한한다. recognition의 context 제한은 별도로 적용한다.
이는 parser 내부 할당·압축 폭탄·CPU 격리까지 보장하지 않는다.

## 검증

`tests/nested_tables.rs`의 합성 기하 입력으로 3단계 중첩, 형제, 병합 셀, 내용 단일 소유권,
그림 소유권, 경계 교차, 잘못된 부모, 깊이 초과, 위상적 구멍/비연결/중복 면, 자원 제한을 검사한다.
`fixtures/nested-grid.content`는 독립적으로 작성한 3단계 PDF paint program이다. 생성기는
stream length와 xref를 실제 byte 길이로 계산한다. Native/fresh WASM에서 같은 PDF를 추출하고
인식 보고서를 대조하며, 보류된 HWPX가 배치형 B 출력과 동일한지 확인한다.
이 자료는 합성 계약이지 한컴에서 작성·인쇄한 중첩 표의 대체 증거가 아니다.

  --target-dir target/pr-review --example nested_probe -- \

전쪽 인식 진단과 전쪽 HWPX 변환을 구분한다. 페이지별 미지원 오류를 결과에 남기며
성공 페이지만 전체 문서의 통과 증거로 삼지 않는다. 검증 결과와 미검증 범위는 README에 기록한다.

## 중첩 객체화 단계 (2026-10-14)

이전 인식 단계는 `c0dd49e28`에 로컬 체크포인트로 커밋했다. 메인테이너가 이전 배치형
샘플의 원본 유사 조판을 확인한 뒤 실제 중첩 표 객체화 구현을 승인했다.
그 확인을 아래 새 HWPX의 한컴 통과로 승격하지 않는다.

- 부모 셀의 호스트 Paragraph에 인라인 자식 Table을 재귀적으로 넣는다. 자식 앞의 세로
  간격은 직전 문단의 후행 간격 또는 첫 셀의 상단 padding으로 표현한다.
- 가로 인셋은 PDF의 `child.x - parentCell.x`를 TAC `outer_margin_left`로 저장한다.
  `paragraph_layout.rs`의 TAC 표 paint에서 `x + tac_table_om.0`로 소비된다.
  빈 호스트의 문단 margin이 실제 paint에서 생략될 수 있으므로 문단 margin과 이중 기록하지 않는다.
- 측정과 배치는 같은 호스트 LineSeg의 점유 높이와 자식 Table 크기를 소비한다.
  부모 셀의 text/image/child 항목은 PDF의 세로 순서로 정렬하며 겹치는 흐름은 보류한다.
- 중첩 가족의 확정 문단은 PDF 줄 단위로 보존한다. 미확정 문단은 원본 span 글상자를
  셀의 각 줄 프레임에 상대 배치한다. 큰 글자 간격을 임의의 한 칸 공백으로 합치지 않는다.
  상대 오프셋은 HWPUNIT 좌표의 차로 계산한다. 작성 당시 문단 의미·편집 흐름 전체 복원은 주장하지 않는다.
- 셀의 좌/우/상/하 변별 원본 선의 연속 범위·색·굵기를 BorderFill에 연결한다.
  HWP 굵기 단계로 양자화하며, 동일한 한 변 안에서 서로 다른 스타일이 섞이면 보류한다.
- 성공한 Table에 속한 괘선·원본 글상자만 소비한다. 미인식 표의 괘선은 계속 도형으로 남는다.

표 외곽·제목·본문·내부 표 영역을 원본 PDF와 직접 대조했다. 글꼴/간격 차이와 미인식 표는 남아 있다.

## 한컴 재조판 비교본 (2026-10-14)

확인된 출력 속성: 미확정 문단의 span 글상자가 셀 안 문단 기준(`PARA`)인데도
`flowWithText=0`이었다. 줄 높이도 PDF의 명시적 높이와 별도로 `PERCENT=100`으로
표현되어 한컴이 글꼴/객체 메트릭으로 다시 계산할 수 있었다. 첫 텍스트 줄의 위 간격은
문단 앞 간격과 저장 LineSeg 위치에 동시에 표현되었다. 이는 재조판에 취약한 생성 입력이며,
각 속성이 한컴 실패에 기여한 정도는 한컴 비교 실행 전에는 확정하지 않는다.

POC의 중첩 가족에만 아래 보정을 적용했다. 제품 renderer/serializer는 변경하지 않았다.

- 셀 안 글상자와 inline 자식 표/그림은 `flowWithText=1`로 본문 연동한다.
- PDF에서 추출한 줄/객체 높이를 `FIXED` 줄 간격으로 표현한다. IR의 2배 단위와
  HWPX `HwpUnitChar` case의 물리 단위 변환은 기존 serializer 계약을 따른다.
- 첫 내용의 위 인셋은 셀 padding 한 곳에 저장하고 문단 앞 간격/저장 vpos에 중복하지 않는다.
- HWPX 재열기에서 앵커 연동, 좌표, 셀 padding 보존을 기존 왕복 검사에 추가했다.

새 비교본: `output/poc/pdf-ir-20261014/nested-tables-hancom-v1/`.
`real7-structured-page/compiled.hwpx`, `real8-structured-page/compiled.hwpx`를 사용한다.
이전 실패본과 한컴 통과 B본은 보존했다. 63개 검사, Native/WASM Clippy, fresh WASM을
통과했고 선택한 7쪽/8쪽 실루엣은 각각 97.12586%/96.60277%다. Native/WASM PNG는 동일하다.
직접 원본 PDF와 대조해 표 소속과 본문 배치는 유지되지만 글꼴/세부 간격 차이가 남음을 확인했다.
새 비교본의 한컴 Print 조판은 아래 MCP 검사에서 **불합격**으로 확인됐다.
한컴 편집 후 저장/재열기는 미검증이다.

### R3 결과 (2026-10-14)

R2를 `6faf10987`에 커밋한 뒤 한컴 재조판 계약을 보정했다.
빈 호스트의 떠 있는 글상자 대신 PDF의 각 줄을 실제 셀 Paragraph/Run으로 만든다.

자리표 폭 0은 rhwp에서는 TabDef로 재계산되지만 한컴에서는 공백이 사라지므로 사용하지 않는다.

핵심 결함은 **PDF 물리 좌표를 문단 IR의 단위 비트에 잘못 넣었던 것**이다.
`hu(2 × points)`를 반올림하면 홀수가 될 수 있다. 문단 여백의 홀수 IR 값은
HWPUNIT의 소수 정밀도가 아니라 CHAR 단위 플래그로 직렬화된다.
생성하는 물리 간격은 `2 × hu(points)`로 변환해 이 플래그를 만들지 않는다.
제품 serializer는 변경하지 않았으며 기존 B본/단일 표 출력 경로는 유지했다.

한컴 저장 HWP에서 `<표 5>`의 호스트 줄 시작은 수정 전 4674에서 수정 후 1894 HWPUNIT으로
변했다. 앞 캡션의 `spacing_after`는 잘못된 CHAR 표현 1391에서 물리 표현 1390으로 바뀐다.
차이는 단순 0.01pt 반올림 오차가 아니라 실제 줄 시작의 **27.8pt 차이**다.
독립 한컴 Print에서 8쪽 하단 누락도 해소됐다.
셀 padding, 줄 상자, inter-item gap은 같은 PDF 점유 상자의 원점/끝점을 사용한다.

폭 없는 탭 후보는 86.92926%, 실제 저장 폭을 넣은 후보는 **92.76461%**다.
