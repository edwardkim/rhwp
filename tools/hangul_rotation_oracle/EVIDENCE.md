# 측정 결과 — `flip` bit19 는 회전 표식이 아니다

## 장비

| 항목 | 값 |
|---|---|
| OS | Windows (win32) |
| 한글 | COM `HWPFrame.HwpObject` Version **13, 0, 0, 645** (한글 2024) |
| Python | 3.11.9 + pywin32 |
| rhwp | devel `f6a6bee8f` 에서 `cargo build --release --bin rhwp` |

## 물음

rhwp 의 `refresh_picture_rotation_layout_for_save` 는 회전이 바뀌면 각도와 무관하게
`rotate_image = true` 와 `flip |= 0x0008_0000`(bit19) 을 세운다. 회전을 0 으로 되돌려도
남는다. bit19 가 "지금 회전돼 있음" 을 뜻한다면 0 에서 내려야 하고, 아니라면 회전을 근거로
건드리는 것 자체가 틀렸다.

## (1) 전수 조사 — `--survey`

`samples/**/*.hwp` 529개, 변환 정보를 가진 개체 **5660건**(회전≠0 569건, 회전=0 5091건).

| 비트 | 회전&켜짐 | 회전&꺼짐 | 평평&켜짐 | 평평&꺼짐 | 판정 |
|---|---|---|---|---|---|
| bit0 `0x00000001` | 5 | 564 | 11 | 5080 | 무관 |
| bit1 `0x00000002` | 2 | 567 | 6 | 5085 | 무관 |
| bit16 `0x00010000` | 9 | 560 | 1937 | 3154 | 무관 |
| bit17 `0x00020000` | 8 | 561 | 1261 | 3830 | 무관 |
| **bit19 `0x00080000`** | **10** | **559** | **4416** | **675** | **무관** |
| bit24 `0x01000000` | 0 | 569 | 898 | 4193 | 비회전에서만(부분) |
| bit25 `0x02000000` | 7 | 562 | 0 | 5091 | 회전에서만(부분) |
| bit26 `0x04000000` | 7 | 562 | 1825 | 3266 | 무관 |
| bit27 `0x08000000` | 0 | 569 | 6 | 5085 | 비회전에서만(부분) |
| bit29 `0x20000000` | 7 | 562 | 2270 | 2821 | 무관 |

회전 상태와 정확히 일치하는 비트는 **없다**. bit19 는 회전 개체 569건 중 **559건에서 꺼져**
있고, 비회전 개체 5091건 중 **4416건에서 켜져** 있다 — 회전과 오히려 반대 방향이다.

한 파일 안의 대조도 같다. `samples/ta-pic-001-r.hwp` 는 한컴이 만든 문서이고 그림이 둘인데:

```
변환: 뒤집기=(false,false), 회전=34, flip=0x26080000, rotateImage=false
변환: 뒤집기=(false,false), 회전=0,  flip=0x24080000, rotateImage=false
```

회전 34° 그림과 회전 0° 그림이 **둘 다 bit19 가 켜져** 있다. 차이는 bit25 다.

## (2) 한글 재저장 — `--resave`

`samples/ta-pic-001-r.hwp` 를 한글 2024 로 열어 그대로 저장.

| 그림 | 한글 전 | 한글 후 | 판정 |
|---|---|---|---|
| 0 (34°) | `flip=0x26080000` rotateImage=0 | `flip=0x26090000` rotateImage=0 | flip bit16 꺼짐→켜짐 |
| 1 (0°) | `flip=0x24080000` rotateImage=0 | `flip=0x24090000` rotateImage=0 | flip bit16 꺼짐→켜짐 |

- 한글은 **회전 0 그림의 bit19 를 그대로 켜 둔다.** 회전을 근거로 내리지 않는다.
- 한글은 **34° 회전 그림의 `rotateimage` 를 0 으로 둔다.** 회전을 근거로 세우지 않는다.
- 한글이 저장에서 건드리는 것은 bit16 이고, 회전 여부와 무관하게 양쪽 모두 세운다.

## 결론

bit19 도 `rotate_image` 도 회전 상태의 함수가 아니다. 따라서
`refresh_picture_rotation_layout_for_save` 의 두 줄

```rust
pic.shape_attr.rotate_image = true;
pic.shape_attr.flip |= 0x0008_0000;
```

은 어느 방향으로도 정당화되지 않는다 — **회전 0 에서 내리는 것도 틀리고, 회전 변경 시
세우는 것도 틀리다.** 파싱된 값을 보존해야 한다.
