# 커진 표 다음 저장 줄의 흐름

`native-8-0.hwpx`는 기존 공개 합성 빈 문서에서 만든 한 칸 표와 `Footer` 입력이다. 사용자 양식이나 파생 내용은 포함하지 않는다. 기준 파일 한 개만 보관하며 `tests/cases/stored_table_text_tail.rs`가 메모리에서 다음 조건을 만든 뒤 실제 HWPX 로딩 경로로 검사한다.

- 셀 문단 수 `2`/`8`: 기준 XML의 앞 두 문단만 남기거나 여덟 문단을 유지한다. 두 문단은 선언 높이 6000 HWPUNIT 안에 들어가며, 여덟 문단은 실제 표가 커진다.
- 저장 줄 사이 간격 `0`/`600`: 다음 줄의 세로 위치를 `7000 + gap`으로 바꾼다. 96 dpi에서 두 결과의 문구 위치 차이는 8px이어야 한다.
- `native`/`pure`: HWP5 계보 마커를 유지하거나 ZIP에서 제거한 뒤 파싱한다. 파싱 후 프로파일도 확인한다.
- 문단 뒤 간격 `0`/`600`/`1200`: 로딩한 문서의 호스트 문단만 별도 스타일로 분리해 값을 바꾼다. 같은 문단의 Footer 위치는 변하지 않아야 한다.
- 같은 문단의 사각형과 다음 문단: 테스트 코드에서 사각형 제어와 그 8-unit 위치를 추가한다. 실제 페이지 항목에 표·도형·부분 문단이 존재하는지 확인하고, 문단 뒤 간격을 늘려도 Footer·도형은 그대로이며 다음 문단만 8/16px 내려가는지 검사한다. 문단의 끝은 마지막 글줄뿐 아니라 표와 도형을 모두 포함한다.

표가 커지지 않는 `2` 입력도 표 아래 간격을 정확히 검사한다. 표 소속 줄의 세로 위치는 1000 HU, 줄 높이와 표 높이는 모두 6000 HU, 줄간격과 표 위아래 바깥여백은 0이다. 다음 줄은 `7000 + gap` HU이므로 표 하단과 다음 문구의 간격은 `(7000 + gap) - 1000 - 6000`, 즉 0/600 HU(0/8px)여야 한다. 이 기대값은 엔진의 수정 결과가 아닌 입력의 저장 줄 정보에서 정한다. 표 앞 빈 줄의 1000 HU(13.33px)를 표 뒤 간격에 더하지 않는다. 줄 위치·높이·줄간격은 [한컴의 문단 레이아웃 구조 설명](https://tech.hancom.com/python-hwp-parsing-2/)의 구분을 따른다.

이 입력은 표 뒤 글줄이 실제 점유 높이를 이어받는 기하 계약이다. 수동 저장 메타데이터를 포함하므로 한컴이 저장한 문서 또는 한컴 출력 오라클로 취급하지 않는다. 실제 비공개 HWP와 대응 PDF는 로컬에서 별도로 검증한다.
