# issue 6860 — 자리차지 표의 앵커 줄

## 무엇을 잠그나

자리차지(`TopAndBottom`, `vertRelTo=PARA`) 표를 앵커한 호스트 문단이 **자기 글자를 두 줄
이상 가질 때**, 그 줄이 표보다 위에 남는지를 잠근다.

## 원본에서의 증상

원본 `3067979_[붙임 2] 도로안전시설 설치 및 관리 지침- 조명시설편.hwpx` 88쪽(쪽번호
`- 82 -`)에서 호스트 두 줄이 마지막 표 조각 뒤로 밀려 본문 하단 밖에 그려졌다.

```text
  용지 793.7 × 1122.5px · 본문 75.6 .. 1084.7

  [수정 전] 88쪽   y=1064.2 / 1085.5 / 1106.9   ← 뒤 두 줄이 본문 14.1px·35.5px 밖,
                                                  꼬리말 쪽번호와 겹침
  [정답]   87쪽   표 위                          ← 한글 저장 lineseg 가 그렇게 적어 두었다
```

## 정답지 — 한글 자신의 저장 기하

원본 문단 1523 의 `hp:linesegarray` 가 두 줄을 표보다 위에 적어 두었다.

```text
  문단 1522 (직전)   vertpos = 29132
  문단 1523 줄0     vertpos = 30732   vertsize = 1000   textpos = 0
  문단 1523 줄1     vertpos = 32332   vertsize = 1000   textpos = 56
  ── 표 밴드 (33332 … 74427) ──
  문단 1524 (다음)   vertpos = 74427
```

표는 `vertOffset=1256` 이고 제어 문자가 텍스트 맨 끝이라 **앵커 줄은 줄1** 이다.

```text
  앵커 줄 기준(정답)  표 상단 32332 + 1256 = 33588  ≥  줄1 끝 33332
  첫 줄 기준(결함)    표 상단 30732 + 1256 = 31988  <   줄1 시작 32332
```

## 이 fixture 의 정본

`pdf/3067979-road-lighting-photometric-appendix-2020.pdf` (engine 2020 — 저장 제품이
`hancom-office-2020` 이라 규약 §3.5.1 의 2020 버킷).

```text
  1쪽  y = 179.8   '도로조명계산 시뮬레이션 시 사용되는 조명기구의 측광데이터 파일 포맷은 …'
       y = 201.2   '으며, 이 중 국제적으로 많이 통용되는 IES 파일 포맷의 각 항목별 해석은 …'
       y ≈ 247.1 부터 표
  2쪽  표 이어짐만 — 호스트 글자 없음
  총 2쪽
```

절단본이라 **절대 y 는 정본과 다르다** — rhwp 는 저장 lineseg 의 `vertpos` 를 따르고
한글은 절단된 문서를 새로 조판하기 때문이다. 이 fixture 가 잠그는 것은 절대 좌표가 아니라
**차례**(호스트 두 줄 → 캡션 → 표)와 **쪽 귀속**(표가 시작하는 쪽, 마지막 조각 뒤 아님)이다.

## 만든 방법

구역0 최상위 `hp:p` 1,747개 중 `0`(`secPr` 보유) · `1521` · `1522` · `1523` · `1524` 만
남기고 `BinData/` 56개를 스텁으로 치환했다. 2,502,806 → 26,868 바이트(93배 축소)이고
결함 좌표(표 561.4/512.3, 이어짐 75.6/989.3, 호스트 1064.2/1085.5/1106.9)는 원본과 같다.
