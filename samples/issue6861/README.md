## 형상

바깥 표(1열 2행) 안에 6열 중첩 표가 둘 들어 있다. 중첩 표가 부모 셀보다 **30.15px 넓게**
저장돼 있고(선언 50,170HU vs 셀 안폭 47,909HU), 한/글은 그대로 넘겨 그린다.

## 회귀 계약 — 갈림은 **저장 줄 폭**이 준다

`#5587` 은 "부모 셀보다 넓게 저장된 중첩 표는 한글도 부모 경계에서 자른다"로 정리하고
Hancom PDF 로 잠갔다. 이 문서는 **정반대**다. 두 문서를 가르는 것은 호스트 문단의
`LINE_SEG.segment_width` 다.

```text
  3194097   sw 50,440 >= 중첩 50,170   → 한글이 자리를 잡아 줬다 → 넘겨 그린다
  #5587     sw 34,160 <  중첩 35,144   → 안 잡아 줬다           → 부모 경계에서 자른다
```

문턱 상수가 없다 — 두 값 모두 문서가 주는 HWPUNIT 정수다.

⚠ 상한은 **용지**다. 사다리가 자리를 잡아 줬어도 용지 밖까지 열지 않는다.

```text
  상한 없음      1480000-201200206 이 용지 밖 2 → 9 (회귀)
  상한 = 본문     이 축이 통째로 닫힌다 (이 문서 본문 우단이 720.0 이다)
  상한 = 용지     대상 문서만 열리고 회귀 0
```

## 음성 대조

`#5587` 의 `samples/basic/issue1994_behindtext_table_20200830.hwp` 를 그대로 쓴다 —
새 fixture 를 늘리지 않는다. 그 문서는 사다리가 자리를 안 잡아 줘 부모 clip 을 유지해야
하고, 시험이 한컴 정답지 경계(512.2px)를 함께 잠근다.

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
