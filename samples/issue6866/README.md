## 형상

12쪽 표 칸의 작은 화살표 그림 하나만 `hp:rotationInfo/@angle="270"` 이고, 같은 문서의
나머지 그림 15장은 전부 `angle="0"` 이다 — **문서 안에 통제군이 있다.**

```xml
<hp:rotationInfo angle="270" centerX="1100" centerY="2015" rotateimage="1"/>
<hp:sz width="2196" height="4030"/>     <!-- 29.3px × 53.7px — 이미 "회전 후" 상자 -->
```

## 회귀 계약

`hp:sz` 는 **회전을 반영한 최종 상자**다. 렌더 노드의 상자도 그대로여야 한다.

```text
                            노드 상자(px)
  수정 전     53.7 × 29.3     ← 눕혀졌다
  수정 후     29.3 × 53.7
  선언 hp:sz  29.3 × 53.7
```

### 근인

페인터는 `ShapeTransform::effective_image_bbox` 로 90/270° 회전 그림의 bbox 가로세로를
**먼저 뒤집은 뒤** 회전을 건다(이중회전 방지). 즉 페인터는 노드 상자가 **회전 후** 상자
라고 전제한다. 그런데 `layout_picture` 는 회전 프레임 그림에서 노드에
`current_*`(= 회전 **전** 비트맵, 53.7×29.3)를 실었다 — 그 전제가 깨져 뒤집기가 한 번 더
걸렸다. 두 상자는 중심이 같으므로, 노드에 `frame`(= 선언 상자)을 실으면 페인터의
뒤집기가 정확히 회전 전 상자를 만들고 회전이 다시 선언 상자로 돌려놓는다.

## 정본 대조

engine 2020 정본 12쪽의 배치 행렬을 콘텐츠 스트림에서 직접 읽었다.

```text
  Im42   a=21.95  b=0.00  c=0.00  d=40.28  e=270.93  f=154.87
         └ 회전 행렬이 **없다** — 21.95×40.28pt = 29.3×53.7px 세로 상자
```

한/글은 회전을 비트맵에 구워 넣고 상자는 선언 그대로 쓴다. 그 비트맵(98×109)도 화살표가
오른쪽을 향하며, rhwp 가 `rotate(270)` 로 만드는 결과와 방향이 같다.

## 코퍼스

10,000건 A/B 에서 `layout-anomaly` 다섯 지표 변화 **0건**이다.

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
