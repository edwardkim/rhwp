**정책연구 활용결과 보고서**(해양수산부)의 원본 바이트를 등록했다. 비공개 PC 경로
또는 환경 변수가 없어 검사를 건너뛰는 방식은 사용하지 않는다.

- 파일: [1192000-202100017-policy-research-report.hwp](1192000-202100017-policy-research-report.hwp)
- SHA-256: `fd0b95cb4239b08e2ab9130b6b697af56dda379f1c9029dbf5f5a0b97af5ceee`
- 크기: 90112바이트
- 저장 제품: `hancom-office-2018`, `10.0.0.10376`
- 기준 엔진: **`2020`** (저장 제품이 `hancom-office-2018` 이므로
  [시각·fixture 증적](../../mydocs/manual/pr_review/visual_fixture_evidence.md) §3.5.1
  에 따라 `hwp2024Convert` MCP 의 `engine: 2020`). 초판은 `2024` 로 적었다 —
  PR #6801 지적.
  ⚠ 그 기준 PDF 는 아직 없다(작업 PC 에 MCP `.env.local` 부재). 다만 **이 축은
  출력 불변**이라 기준 PDF 대조가 판정을 주지 않는다 — 1쪽 SVG 는 수정 전후
  320,055 bytes / 같은 SHA-256 이다.
- 참고 증적: 한/글 2024 PDF 와 **공백 제거 592자로 완전히 일치**한다 — 수정 전후 모두.
  **출력 결함이 아니라 렌더 트리 계약 결함**이다.
- 회귀 계약: 오른쪽/가운데 탭이 다음 블록을 재배치할 때, 그 **끝 탭 런의 advance 와
  bbox·장식 상자·탭 리더가 재배치가 정한 같은 `x` 를 쓴다.** 폭은 다음 런의 시작
  x 까지만 줄어들고 그보다 더 줄지 않으므로 **진짜 glyph 겹침은 그대로 계수된다.**
  탭 뒤에 가시문자가 있는 런은 대상이 아니다.

⚠ 이 결함이 중요한 이유는 `text_overlap_baseline` 래칫이 가짜 겹침을 세어 **진짜
글자겹침을 가리기** 때문이다. 실측: `3070000-202200004` 글자겹침 **230 → 132**.

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
