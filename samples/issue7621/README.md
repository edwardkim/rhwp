# Issue #7621 자리 차지 표 다음 글자 문단 대조군

두 HWP는 `devel` `d9749c5a1`의 web WASM으로 `generate.mjs`를 실행해 만든 **생성 대조군**입니다. 한컴 저장본이 아닙니다. 같은 패키지로 다시 실행하면 바이트가 같습니다.

- `b-text-after-float.hwp`: 앞 문단 · 자리 차지 표 문단 · **글자 문단** · 뒤 문단.
- `control-float.hwp`: 같은 구성에서 표 문단 다음 문단이 **빈 문단**인 정상 대조군.

표는 2×2, 비TAC, `TopAndBottom`, 세로 문단 기준 오프셋 0, 바깥 여백 283HU, 쪽 나눔 None입니다. 표 문단 줄은 native 생성 그대로 폭 0 앵커 줄(`vpos 1600, lh 1000, ls 600, sw 0`)이고, 다음 문단 vpos는 3200입니다. 한컴 저장본의 폭 0 앵커 줄은 다음 vpos − 현 vpos가 개체 높이인데(#7470), 이 생성본은 `lh + ls`라서 #6147 저장 사다리와 같은 모양이 됩니다.

기준 PDF는 `pdf/issue7621/`에 있습니다. 한컴독스 웹서비스 6.3.6(2026-09-17), 편집기 "한컴오피스 Web v2 한글" 빌드 `20260812021742`에서 파일 → 인쇄 시 서버가 만든 인쇄용 PDF(`webhwp/handler/download/…?fileExt=pdf&preview=true`, Producer cairo 1.15.12)를 브라우저 인쇄 전에 받은 것입니다. 한/글 데스크톱 Print 출력은 확인하지 않았습니다.

한컴 인쇄에서 두 문서 모두 표 괘선은 157–191px, 표 문단 다음 문단은 표 아랫변 + 바깥 여백 아래(글자 잉크 195px)에서 시작합니다(96dpi). 입력과 PDF의 SHA-256은 `MANIFEST.json`에 고정했습니다. 생성 대조군의 통과를 한컴 저장본 일반의 시각 일치로 보고하지 않습니다.
