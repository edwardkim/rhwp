## 형상 — 표 뒤 간격을 두 번 준다

4쪽은 자리차지 표 두 장을 품은 한 문단(`pi=30`)으로 시작해, 빈 문단(`pi=31`)과 출처
줄(`pi=32`)로 끝난다.

```text
  용지 793.7 × 1122.5px · 본문 113.4 .. 1020.5

  pi=30 seg0   vpos 0      lh 45.3     ← 앵커 줄 사다리는 첫 TAC 표(41.5px)만 덮는다
  표1(TAC)                 113.4 .. 154.9
  표2(비-TAC 자리차지)      156.8 .. 977.4
  pi=31 저장 vpos 64803  →   977.4     ← 사다리가 표 하단을 그대로 지목한다
  pi=32 저장 vpos 66723  →  1003.0
```

`seg.line_spacing`(1120HU = 14.9px)을 표 하단에 또 더하면 뒤가 통째로 밀린다.

```text
             pi=31      출처 줄            본문 하단 1020.5
  수정 전     992.3   1017.9 .. 1033.9    13.4px 넘음 ✗
  수정 후     977.4   1003.0 .. 1019.0    안 ✓
  정본(2020)          1000.6 .. 1019.8
```

⚠ **표는 무죄다.** 표 하단은 정본과 1.1px 안이고 이 수정이 건드리지 않는다. 어긋난
축은 표 **뒤**의 간격 하나다.

## 회귀 계약

표 아래 간격은 host 앵커 줄의 후행 `line_spacing` 인데, 앵커 줄 사다리가 뒤따르는
비-TAC 표를 덮지 않는 문단에서는 표 하단이 **이미** 사다리가 지목한 다음 문단 자리다.
그때는 간격을 더하지 않는다. 판별은 문서가 준다 — 다음 문단의 저장 `vpos` 를 이 문단의
사다리 기준점으로 환산해 현재 흐름 위치와 견주고, **사다리가 표 하단 이하를 지목할
때만** 거둔다(더 아래를 지목하면 종전대로 더한다).

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
