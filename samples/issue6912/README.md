# issue 6912 — 세로 가운데 정렬 칸의 자리차지 개체 띠

## 무엇을 잠그나

세로 가운데(`subList vertAlign="CENTER"`) 정렬 칸 안에 자리차지
(`textWrap="TOP_AND_BOTTOM"`, `vertRelTo="PARA"`) 개체가 있을 때, 그 개체가 먹는 띠를
칸의 콘텐츠 높이로 세는지를 잠근다. 안 세면 글자 없는 한 줄이 칸 한가운데로 내려가고
개체가 그 줄을 따라간다.

## 원본에서의 증상

원본 `156564340_085 [특허청] “소송 대신 합의” 지식재산 분쟁조정 신청 ‘쑥’.hwpx`
**4쪽**의 안내 포스터가 칸 바닥과 쪽 아래를 넘어 잘렸다.

```text
  정본  x=100.6  y=128.3  w=601.9  h=843.7     (칸 윗변 116.8 기준 +11.5px)
  rhwp  x=100.7  y=541.5  w=602.4  h=844.7     (칸 윗변 109.4 기준 +432.1px)
                          ~~~~~~~ 자기 칸 기준 +420.6px
```

## 근인 — 계산이 아니라 저장 흐름 **신뢰 규칙**

재조판 스택은 개체 띠를 이미 세고 있었다(`13.33 + 854.4 = 867.7px`). 그런데
`#1486`(악보 셀) 계약이 "TopAndBottom 은 저장 vpos 에 흡수된다"를 **전제로** 깔고
그 개체를 `non_flow_object_extent` 에서 빼 두어, 저장 `LINE_SEG` extent
`13.33px` 가 콘텐츠 높이를 통째로 대신했다.

이 문서의 앵커 줄은 `vertpos=0` — **흡수가 일어나지 않았다.** `hp:rect` 를
`textWrap="SQUARE"` 로만 바꾸면(같은 크기·같은 오프셋) 개체가 곧바로 칸 상단
`+11.6px` 로 돌아온다. Square 는 그 신뢰 규칙의 배제 목록에 있기 때문이다 —
갈린 것은 개체가 아니라 **신뢰 규칙의 배제 목록**이다.

## 정답지 — 한/글 자신의 저장값

한/글은 자리차지 개체의 띠를 **행 높이에 넣는다.** 그래서 가운데 정렬이 옮길 여백이
남지 않는다.

```text
  tc  cellSz  height =   282   = cellMargin.top 141 + bottom 141   → 글 내용 높이 0
  tbl sz      height = 64362   = 63356(개체 높이) + 724(vertOffset) + 282
```

```text
  검산: cellMargin.top 141HU(1.88px) + vertOffset 724HU(9.65px) = 11.53px
        정본 실측 128.3 - 116.8 = 11.5px                              ✔
```

반대로 띠를 안 세면 13.33px 짜리 빈 줄 하나만 남아

```text
  (inner_height 854.4 - 13.33) / 2 = 420.5px   ← 관측 어긋남 420.6px 과 일치
```

## 이 fixture 의 유래

원본 919,682B 에서 두 가지를 줄였다.

1. 구역0 최상위 `hp:p` 61개 중 **0**(`secPr` 보유)과 **59**(결함 문단)만 남겼다.
2. `hp:ole` 을 **배치 속성이 완전히 같은 `hp:rect`** 로 바꾸고
   `BinData/ole5.ole`(12,618,756B)과 `content.hpf` 의 그 항목을 지웠다.

`sz`(45183×63356)와 `pos`(`treatAsChar=0`, `TOP_AND_BOTTOM`, `vertRelTo=PARA`,
`horzRelTo=COLUMN`, `vertOffset=724`, `horzOffset=1088`), `outMargin`(0)은 원본 OLE 값
그대로다. 결함 좌표도 그대로다 — 절단본 2쪽의 rhwp 값이 원본 4쪽과 같은
`x=100.7 y=541.5 w=602.4 h=844.7` 이다.

> ⚠ **`hp:pic` 으로 바꾸면 재현되지 않는다.** 같은 `sz`·`pos` 를 줘도 그림은
> 칸 상단(`y=121.0`)에 놓인다 — 그림은 이 문단 앵커를 따라가지 않는 별개 배치
> 갈래다. 재현에는 `hp:rect`(= OLE 와 같은 `Control::Shape` 갈래)를 써야 한다.
