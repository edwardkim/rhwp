# #6797 정식 회귀 입력

[이슈 #6797](https://github.com/edwardkim/rhwp/issues/6797)에서 식별한 공개 문서
**사회성 뛰어난 돼지로 농장 수익 높인다**(농촌진흥청 농식품 브리핑)의 원본 바이트를
등록했다. 비공개 PC 경로 또는 환경 변수가 없어 검사를 건너뛰는 방식은 사용하지 않는다.

- 파일: [156160455-social-pig-farm-income.hwp](156160455-social-pig-farm-income.hwp)
- SHA-256: `1b99b763aac36a14a9f463e35ee894a23eb1083780040eab5e0f02a481c694b8`
- 크기: 458752바이트
- 저장 제품: `hancom-office-2010`, `8.5.8.1522`
- 기준 엔진: **`2020`** (저장 제품이 `hancom-office-2010` 이므로
  [시각·fixture 증적](../../mydocs/manual/pr_review/visual_fixture_evidence.md) §3.5.1
  에 따라 `hwp2024Convert` MCP 의 `engine: 2020`).
  ⚠⚠ **engine 2020 기준 PDF 는 아직 없다** — 이 작업 PC 에는 그 MCP 의
  `.env.local`(endpoint·token)이 없어 산출하지 못했다. (초판에 적은 "기준 엔진 없음"은
  정책과 맞지 않았다 — PR #6798 지적.)
- ⚠ **쪽수·글자 수로는 판정하지 않는다.** 2010 저장본이라 한/글 2024 와 드리프트가
  있다. 이 축의 판정은 **저장 사다리**가 준다 — `pi=71` 의 `vpos=16306` 은 단 기준
  217.4px, 절대 **296.77px** 로 앞 표(`pi=70`)가 만든 밴드의 바닥(296.8)과 같다.
  겹침 자체가 버전과 무관한 결함이다.
- 회귀 계약: **빈 host 의 표 항목**은, 저장 사다리가 그 문단을 앞 문단 자리차지 밴드의
  **바닥 아래**에 두었을 때 그 저장 위치로 비켜 간다. host 에 보이는 글이 있으면 그
  줄이 스냅을 지므로 손대지 않는다(`synam-001 pi=229`: 저장 930.16 = 밴드 바닥 930.2,
  그러나 host 줄이 있어 불변). **크기 문턱이 없다.**

⚠ 이 문서에 남는 `overflow` 8건은 이 축과 무관한 별개 형상이다(수정 전후 동일).

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
