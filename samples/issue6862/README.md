- 출처: 해양경찰청 과학수사 기본규칙 `[별지 11] 선박충돌재현시스템 분석결과보고서`
- 저장 제품: `hancom-office-2020`, `11.0.0.3524` → 기준 엔진 **`2020`**
- 기준 PDF: `pdf/2249811-vessel-collision-analysis-form-2020.pdf` — **1쪽**

## 형상

1쪽 전체가 표이고, 빈 누름틀 안내문(빨간 기울임)이 **전부 표 칸 안**이다.
글리프 238개가 대상이다.

## 회귀 계약 — 두 갈래

### ① 정렬 앵커를 시작점으로 쓰면 안 된다

빈 누름틀 줄은 글자 폭이 0 이라 `find_x_for_char` 가 돌려주는 것은 **정렬 앵커**
(가운데 정렬이면 줄 중앙)다. 안내문을 거기서 오른쪽으로 그리면 통째로 자기 폭의
절반만큼 밀린다.

```text
  칸 286.9..670.1  중앙 478.5   안내문 폭 668.0
    종전 시작 478.5           = 중앙 (폭을 안 뺐다)
    정상 시작 478.5 − 334.0   = 144.5
```

줄에 보이는 글자가 있으면 그 앵커는 실제 글자 자리이므로 건드리지 않는다.

### ② 칸 안에서도 접는다

`#6111` 이 본문 안내문 접기를 넣으면서 셀은 *"가용 폭 기준이 다르므로 종전대로 한 줄"*
로 남겼다. 그 기준은 이미 손에 있다 — **이 줄의 상자**(`line_node.bbox`)가 칸 안여백까지
반영한 텍스트 상자다.

⚠ 본문 갈래는 종전 기준(`current_body_area`)을 그대로 둔다 — `#6111` 의 확정 핀이
그 값으로 잠겨 있다.

## 실측

```text
                 안내문 글리프 x        용지(793.7) 밖   안내문 줄 수
  수정 전     178.8 .. 1139.8              41              9
  수정 후     178.8 ..  656.0               0             15
```

수정 후 안내문은 전부 자기 칸 안에 있다(시험이 칸별로 대조한다).

## ⚠ 이 축은 `layout-anomaly` 가 보지 못한다

안내문 노드는 `with_editor_only` 라 기하 이상탐지 대상이 아니다. 용지를 352.8px
넘겨도 다섯 지표가 전부 침묵한다 — 코퍼스 A/B 로는 이 결함도, 이 수정도 안 보인다.

## ⚠ 인쇄·PDF 에는 원래 안 나온다

engine 2020 정본에 **빨간 글씨가 하나도 없다.** 한컴은 빈 누름틀 안내문을 인쇄·PDF 로
내보내지 않고, rhwp 도 같은 규약이다(`RenderProfile::shows_editor_visuals()` 가
`Screen`·`FastPreview` 에서만 참). 즉 이것은 **편집 화면 정합** 축이고, 기준 PDF 는
형상 확인용이지 판정을 주지 않는다.

새 sample이 기존 코퍼스 래칫에 주는 영향은 통합 검증에서 실측한다. 알려지지 않은
회귀를 숨기려고 기존 문서 기준선을 올리거나 보안 탐지 신호를 포괄적으로 무시하지 않는다.
