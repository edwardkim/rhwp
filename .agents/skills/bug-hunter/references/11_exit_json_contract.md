# 11 — 종료 코드와 JSON 계약

playbook 예시 5: 매니페스트만 보고 호출하는 에이전트가 지뢰를
밟지 않는가. 정답 기준은 자기서술이 실제와 같고, 종료 코드·JSON
봉투가 계약대로인 것이다.

권위: [`cli_commands.md`](../../../../mydocs/manual/cli_commands.md)
종료 코드 표 (#2707). 이 장이 숫자를 바꾸지 않는다.

## 공통 (요약 — 정본은 매뉴얼)

| 코드 | 뜻 | 예 |
| --- | --- | --- |
| 0 | 성공 (텍스트 모드 비교는 차이가 있어도 0 인 명령이 있음) | 정상 info |
| 1 | 읽기·실행 실패 | 파일 없음 |
| 2 | 사용법 | 인자 없음, 페이지 범위 초과 |
| 3 | 검증·판정 실패 | `ir-diff --json` 차이, `--verify` 실패 |
| 4 | 일부 게이트 (`--verify-pages`) | 페이지 검증 단절 |

텍스트 모드와 `--json` 모드의 종료 코드가 다를 수 있다.
`ir-diff` 텍스트는 차이가 있어도 0, `--json` 은 차이 = 3.
사람 모드 숫자를 JSON 계약으로 읽지 않는다.

## 기계 판정

1. `capabilities` 와 `--help` 와 실제 하위명령 존재
2. 인자 순서·미지 옵션·경계값
3. `--json` 이 약속한 키 (`schemaVersion` 등)
4. 실패 경로의 stdout 이 비는지 (export-svg 규약)
5. `search --limit` 가 총량을 숨기지 않는지 (#3353)

불일치 → C05, `issueReady=true`. 정답지는 매뉴얼 문장이다.
