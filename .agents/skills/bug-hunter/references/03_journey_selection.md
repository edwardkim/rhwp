# 03 — 여정 선택

playbook: "사용자 가치 순서에 따라 실사례 여정 하나를 선택한다.
없으면 실제 정부 양식, 법정 서식, 실제 공고 등 정답지가 존재하는
여정을 정의한다."

## 고르는 순서

1. playbook 예시 1–7 중 아직 이 작업에서 안 돈 것
2. playbook "여정 카탈로그 (다음 후보)"
3. 지금 인터넷에 배포 중인 실물 정부/법정 서식 (정답지가 있는 것)
4. samples/ 는 **이미 고쳐진 문서에 치우쳐** 있다. 새 결함이 덜 나온다

금지: 무작위 파일 스윕으로 "안 죽는다"를 확인하고 끝내기 (F01).
그것은 견고성 확인이지 실효 버그 헌팅이 아니다.

## 정답지가 있는 여정만

| 종류 | 정답지 | 예 |
| --- | --- | --- |
| 정부 실공고 양식 | 제출 요건 문구 + 재독 값 | K-Startup 사업계획서 |
| 한컴 공식 출력 | 해당 환경 PDF + provenance | plan/math/leet |
| 법정 서식 | 편람 별지 | 일반/간이기안문 |
| 인터넷 배포 실물 | 원본 ZIP 이름 집합 | 서울시 공개 결재문서 |
| CLI 계약 | cli_commands.md · capabilities | 종료 코드 #2707 |

정답지를 만들 수 없으면 여정으로 올리지 않는다. 자기 일관성만
필요하면 [06_self_consistency_limit.md](06_self_consistency_limit.md).

## 한 번에 하나

동시에 여러 여정을 돌리지 않는다. 한 여정을 최종 산출물까지 닫고
격차를 이슈화한 뒤에 다음으로 간다. 배치 스윕은 이웃
`rhwp-bulk-pipeline` 이고, 실패한 한 건을 여기로 승격한다.
