# 14 — 실제 접수·로그인·실명인증 금지

playbook 예시 1: 완전 가상 데이터로 채운다. **실제 접수는 하지
않는다.** 가상 데이터로 실존 프로그램 접수는 허위 신청이고
로그인·실명인증은 자동화 밖이다. "제출 직전 완성 파일"까지가
정당한 경계.

정지 **F13**. 시도 자체를 거부한다. 우회 스크립트도 작성하지 않는다.

## 허용

- 가상 상호: `(주)시연용가상기업`
- 사업자번호·주민번호·계좌: 전부 0 또는 문서화한 가상 패턴
- 공고 페이지를 **읽기** (양식 다운로드)
- `export-pdf` 로 제출용 파일 생성
- 제출 요건 문구를 인용해 스타일/칸을 대조

## 금지

- 실제 포털 로그인
- 공동인증서·간편인증·실명인증 자동화
- 가상 데이터로 실존 공고에 제출
- 타인 개인정보로 채움
- 접수 번호·영수증을 성공 기준으로 삼기

## 경계 문장 (그대로)

```
검증 범위는 가상 데이터로 문서를 작성하고 제출 직전 산출물을
만드는 것까지다. 실제 서비스 접수, 로그인, 실명인증은 수행하지
않았다.
```

이 문장이 없는 양식 여정 로그는 불완전하다.

## PII 여정 (카탈로그)

개인정보 탐지→마스킹은 `inspect` / `edit redact --dry-run` 등
**기존** 명령으로 문서 안에서만 한다. 외부 시스템에 올리지 않는다.
