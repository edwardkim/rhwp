# 20 질문 설계

엔진은 질문을 똑똑하게 만들지 않는다. 키워드를 문서에 그대로 던진다.
질문 설계가 에이전트의 전략 판단이다.

## 좋은 질문

- 문서에 있을 법한 **어휘**를 키워드로 가진다.
- 한 질문이 한 결정에 대응한다 (기능 / 예산 / 배점).
- 전망이 아니라 관측을 묻는다 ("얼마로 적혀 있나", "무엇을 필수로 했나").

## 나쁜 질문

- "우리가 이길까" — 코퍼스가 답하지 않음. 0건 또는 전망 유혹.
- 키워드가 목표 문장 전체 — 매치 0, 또는 무관한 장문 히트.
- 키워드가 한 글자 — 절단·노이즈.
- 영어만 / 한글만 한쪽에 치우침. 공고가 혼용이면 둘 다.

## 절차

1. objective 를 결정 포인트로 분해한다 (보통 3~7개).
2. 각 포인트마다 문서 장르에 맞는 키워드 2~4개를 고른다.
   공고: 필수기능, 총사업비, 수행기간, 배점.
   분기: 수주액, MM, 리스크.
3. 동의어를 같은 질문의 keywords 에 넣는다 (총사업비/사업비/백만원).
4. 엔진을 돌린다.
5. 0건이면 키워드를 바꾸고 재실행한다. 전망으로 메우지 않는다.
6. 절단이면 키워드를 더 구체화하거나 limit 를 올린다.

## 예: 수주 목표

objective: `2026년 스마트시티 데이터 플랫폼 정부과제 수주`

| id | text | keywords |
| --- | --- | --- |
| Q1 | 필수 기능 | 필수기능, 데이터 플랫폼, 표준 API |
| Q2 | 예산·기간 | 총사업비, 수행기간, 백만원 |
| Q3 | 평가 배점 | 기술평가, 가격평가, 배점 |

"수주 확률 70%" 질문은 만들지 않는다.

이 장이 스킬 본문의 끝이다. 예제와 픽스처로 내려간다.
